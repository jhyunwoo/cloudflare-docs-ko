IP 검증 방법은 봇이 요청을 보낼 수 있는 IP 주소를 모두 식별하는 것을 목표로 합니다. IP 검증은 검증방법으로만 사용됩니다.[검증된 봇](/bots/concepts/bot/verified-bots/).

Cloudflare는 두 가지 방법으로 이것을 달성 할 수 있습니다.

- **봇 소유자가 제공하는 IP 목록 사용**: 봇 소유자는 IP 범위의 공개 목록을 호스트 할 수 있습니다 (예 :[Googlebot의 목록](https://developers.google.com/static/search/apis/ipranges/googlebot.json)). Cloudflare fetches는 유효성을 위해 이 목록을 직접 사용합니다.
- **도메인 기반 역 DNS 사용**: 봇 소유자는 자신의 봇 요청이 시작된 도메인(또는 도메인)을 제공 할 수 있습니다. Cloudflare는 봇의 사용자 에이전트와 요청에 따라 관찰된 IP 주소를 수집하고 역 DNS 조회를 수행합니다. IP의 반전 DNS가 제공 된 도메인 중 하나에 해결되면, Cloudflare는 유효하고 저장합니다.

## IP 목록

공용 IP 목록을 사용하여 봇을 확인하려면 다음을 제공해야합니다.

- IP 주소의 고정 및 제한 설정, 이는 공개적으로 접근 가능한 일반 텍스트를 통해 확인 될 수있다,`JSON`, 또는`CSV`.
- IP 주소는 bot 소유자에 의해 단독으로 사용.
- 사용자 시약 일치 패턴.

## 반전 DNS

역 DNS를 사용하여 봇을 확인하려면 다음을 제공해야합니다.

- DNS 레코드를 검증하는 도메인 suffixes 목록.
- IP 주소는 PTR 레코드가 올바르게 설정되어야 합니다.
- 사용자 시약 일치 패턴.

## Generic 사용자 시약

일반적인 사용자 시약과 일치하는 사용자 시약 패턴은 Verified Bots API에 의해 거부됩니다. 인증된 Bot 양식에 매우 공통된 사용자 시약 패턴을 추가할 때, 사용자 시약을 수정하기 전에 사용자 시약을 수정할 수 있는 오류 메시지가 발생할 수 있습니다.

일반 사용자 시약은 다음과 같습니다:

- `Dart`
- `Go-http-client`
- `GuzzleHttp`
- `Google Chrome`
- `Mozilla Firefox`
- `Safari`
- `Nessus`
- `Websocket++`
- `cloudflare-go`
- `fasthttp`
- `got`
- `nginx-ssl early hints`
- `node`
- `node-fetch`
- `okhttp`
- `python-requests`
- `uTorrent`
