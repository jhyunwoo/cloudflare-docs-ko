탐지 ID는 인간 교통을 가진 overlap 없이 예측할 수 있는 bot 행동을 검출하기 위하여 이용된 정체되는 규칙입니다. 검색 ID는 정확한 참조[제품정보](/bots/concepts/bot-detection-engines/)헤리티지, 검증된 봇 탐지, 또는 anomaly 탐지에서 할 수있는 봇을 식별하는 데 사용됩니다. 예를 들어, 검색 ID는 브라우저의 예상보다 다른 주문에서 헤더를 보내면 식별 할 수 있습니다.

우리의 허리즘 중 하나에 문제가있는 경우, 검출 ID는 고객 구성 가능한 허리학을 사용하여 영역에서 시행하는 것을 결정할 수 있습니다. 다른 봇에 대한 독특한 행동을 선택할 수 있습니다. :::참조
요청은 여러 탐지 ID를 트리거 할 수 있습니다.
주요 특징

사용 가능`cf.bot_management.detection_ids`같은 도구의 필드:

- [주문 규칙](/waf/custom-rules/)
- [고급 비율 제한](/waf/rate-limiting-rules/)
- [Transform 규칙](/rules/transform/)
- [작업자](/workers/)(아)`request.cf.botManagement.detectionIds`)

Bot 탐지 ID 및 꼬리표는 또한에서 유효합니다[봇 분석](/bots/bot-analytics/)·[보안 Analytics](/waf/analytics/security-analytics/).

:::카ution\[베타 탐지]

그것은 가능하지만, uncommon, you to have beta detection IDs on the Cloudflare\`대시보드 that are not active collecting data on your zone.

## 검색 태그

검색 태그는 'Cloudflare'가 봇을 지문으로 인식 한 시간에 검출 ID와 관련된 범주를 나타냅니다. 예를 들어, 검색 태그가 있다면`go`, 즉 Cloudflare는 Go 프로그래밍 언어 봇에서 그 탐지 ID로부터 트래픽을 관찰했다.

:::참조

검색 태그는 Security Analytics에서 사용할 수 있지만 Security Events에 없습니다.

## 사용 사례

### 특정 검출 ID와 일치하는 블록 요청

```js
any(cf.bot_management.detection_ids[*] eq 3355446)
and not cf.bot_management.verified_bot
and http.request.uri.path eq "/login"
and http.request.method eq "POST"
```

### 특정 검출 ID 없이 Bot 관리 실행

```js
cf.bot_management.score lt 30
and not cf.bot_management.verified_bot
and http.request.uri.path eq "/login"
and http.request.method eq "POST"
and not any(cf.bot_management.detection_ids[*] in {3355446 12577893})
```

## Logpush를 통해 Bot 탐지 ID

기존의 Logpush 작업을 만들거나 편집 할 수 있습니다. 기존의 Logpush 작업은 각 요청에 대한 ID의 배열을 제공 할 수있는 새로운 봇 탐지 ID 필드를 포함 할 수 있습니다. 더 보기`BotDetectionIDs`필드는 HTTP 요청 데이터 세트의 일부로 사용할 수 있으며 Logpush API 또는 'Cloudflare 대시보드\`를 통해 새로운 기존 작업에 추가 할 수 있습니다. 탐지 ID를 발견하는 1 차적인 방법입니다.
