앞으로 실행할 계획 작업 - 현재 초인지 여부, 특정 날짜 / 시간, 또는 반복 cron 일정. 계획된 작업은 에이전트를 다시 시작하고 SQLite에 persisted.

Scheduled task can do nothing a request or message from the user can: make request, query databases, send email, read and write state. 일정한 작업은 에이전트에 대한 일반적인 방법을 호출 할 수 있습니다.

## 제품정보

스케줄링 시스템은 4개의 모드를 지원합니다:

| 주요 특징     | 옵션 정보                               | 사용 사례     |
| --------- | ----------------------------------- | --------- |
| **관련 상품** | `this.schedule(60, ...)`            | 60 초에서 실행 |
| **일정표**   | `this.schedule(new Date(...), ...)` | 특정 시간에 실행 |
| **한국어**   | `this.schedule("0 8 * * *", ...)`   | 자주 묻는 질문  |
| **회사연혁**  | `this.scheduleEvery(30, ...)`       | 30 초마다 실행 |

후드 아래에, scheduling 용도[튼튼한 목표 경보](/durable-objects/api/alarms/)적절한 시간에 에이전트를 깨어. 작업은 SQLite 테이블에 저장되며 순서대로 실행됩니다.

## 빠른 시작

<TypeScriptExample>
  ```ts
  import { Agent } from "agents";

  export class ReminderAgent extends Agent {
  	async onRequest(request: Request) {
  		const url = new URL(request.url);

  		//30 초에 있는 계획
  		await this.schedule(30, "sendReminder", {
  			message: "Check your email",
  		});

  		//특정 시간에 일정
  		await this.schedule(new Date("2025-02-01T09:00:00Z"), "sendReminder", {
  			message: "Monthly report due",
  		});

  		//일정 회수 (8am에서 매일)
  		await this.schedule("0 8 * * *", "dailyDigest", {
  			userId: url.searchParams.get("userId"),
  		});

  		return new Response("Scheduled!");
  	}

  	async sendReminder(payload: { message: string }) {
  		console.log(`Reminder: ${payload.message}`);
  		//알림, 이메일 등 발송
  	}

  	async dailyDigest(payload: { userId: string }) {
  		console.log(`Sending daily digest to ${payload.userId}`);
  		//생성하고 digest를 보냅니다
  	}
  }
  ```
</TypeScriptExample>

## 스케줄링 모드

### 지연된 실행

지연 후 실행할 작업을 일정할 수 있는 번호를 전달합니다.**지원하다**:

<TypeScriptExample>
  ```ts
  //10 초에서 실행
  await this.schedule(10, "processTask", { taskId: "123" });

  //5 분에서 실행 (300 초)
  await this.schedule(300, "sendFollowUp", { email: "user@example.com" });

  //1 시간에서 실행
  await this.schedule(3600, "checkStatus", { orderId: "abc" });
  ```
</TypeScriptExample>

**사용 사례:**

- 급속한 사건을 위임
- 지연 알림 ("당신은 당신의 카트에 항목을 왼쪽")
- backoff를 가진 Retry
- 비율 제한

### 계획된 실행

패스워드`Date`특정 시간에 작업을 일정하려면:

<TypeScriptExample>
  ```ts
  //noon에서 내일 실행
  const tomorrow = new Date();
  tomorrow.setDate(tomorrow.getDate() + 1);
  tomorrow.setHours(12, 0, 0, 0);
  await this.schedule(tomorrow, "sendReminder", { message: "Meeting time!" });

  //특정 타임스탬프에서 실행
  await this.schedule(new Date("2025-06-15T14:30:00Z"), "triggerEvent", {
  	eventId: "conference-2025",
  });

  //날짜 수학을 사용하여 2 시간에서 실행
  const twoHoursFromNow = new Date(Date.now() + 2 * 60 * 60 * 1000);
  await this.schedule(twoHoursFromNow, "checkIn", {});
  ```
</TypeScriptExample>

**사용 사례:**

- 약속 알림
- Deadline 알림
- 계획된 내용 출판
- 시간 기반 방아쇠

### (크론)

recurring 일정에 대 한 cron 표현 문자열을 전달:

<TypeScriptExample>
  ```ts
  //매일 오전 8시
  await this.schedule("0 8 * * *", "dailyReport", {});

  //매시간
  await this.schedule("0 * * * *", "hourlyCheck", {});

  //매주 월요일 9:00 AM
  await this.schedule("0 9 * * 1", "weeklySync", {});

  //각 15 분
  await this.schedule("*/15 * * * *", "pollForUpdates", {});

  //매월 첫째 날
  await this.schedule("0 0 1 * *", "monthlyCleanup", {});
  ```
</TypeScriptExample>

**Cron 구문:** `minute hour day month weekday`

| 제품정보   | 제품정보        | 특수 문자           |
| ------ | ----------- | --------------- |
| 이름 \*  | 0-59        | `*` `,` `-` `/` |
| 시간 :   | 0-23        | `*` `,` `-` `/` |
| 달의 날   | 1-31        | `*` `,` `-` `/` |
| 월 \~ 월 | 1-12        | `*` `,` `-` `/` |
| 주간의 날  | 0-6 (0=일요일) | `*` `,` `-` `/` |

**일반적인 본:**

<TypeScriptExample>
  ```ts
  "* * * * *"; //각 분
  "*/5 * * * *"; //각 5 분
  "0 * * * *"; //각 시간 (시간에)
  "0 0 * * *"; //매일 밤
  "0 8 * * 1-5"; //평일 오전 8시
  "0 0 * * 0"; //매주 일요일
  "0 0 1 * *"; //매월 첫째
  ```
</TypeScriptExample>

**사용 사례:**

- 매일/주간 보고
- 정기휴일
- 외부 서비스 오염
- 건강 검사
- 구독 갱신

### 회사연혁

제품 정보`scheduleEvery()`고정 간격에서 작업을 실행하기 (초). cron과는 달리, 간격은 분 정밀도와 arbitrary 내구를 지원합니다:

<TypeScriptExample>
  ```ts
  //30 초마다 오염
  await this.scheduleEvery(30, "poll", { source: "api" });

  //45 초마다 건강 검사
  await this.scheduleEvery(45, "healthCheck", {});

  //90 초마다 동기화 (1.5 분 - 크론에서 표현할 수 없습니다)
  await this.scheduleEvery(90, "syncData", { destination: "warehouse" });
  ```
</TypeScriptExample>

**크론의 주요 차이점:**

| 제품 정보      | 한국어                | 회사연혁        |
| ---------- | ------------------ | ----------- |
| 최소한도 과립상   | 1 분                | 1 초         |
| 중재 간격      | 없음 (근접 cron 패턴)    | 이름 \*       |
| 고정 일정      | 예 (예 : "8am에서 매일") | 없음 (시작에 관계) |
| Overlap 예방 | 이름 \*              | 예 (붙박이)     |

**Overlap 예방:**

콜백이 간격보다 더 길어지면 다음 실행이 건너 뛰고 있습니다. 이것은 runaway 자원 사용법을 막습니다:

<TypeScriptExample>
  ```ts
  class PollingAgent extends Agent {
  	async poll() {
  		//45 초가 걸리면 간격이 30 초입니다.
  		//다음 설문 조사는 건너 뛰고 있습니다 (경보 기록)
  		const data = await slowExternalApi();
  		await this.processData(data);
  	}
  }

  //30초 간격 설정
  await this.scheduleEvery(30, "poll", {});
  ```
</TypeScriptExample>

Skip가 발생하면 로그에 경고를 볼 수 있습니다.

```txt
Skipping interval schedule abc123: previous execution still running
```

**오류 탄력:**

콜백이 오류를 발생하면 간격이 계속됩니다. 즉, 실행은 실패합니다.

<TypeScriptExample>
  ```ts
  class SyncAgent extends Agent {
  	async syncData() {
  		//이 던지는 경우에도 간격은 실행 유지
  		const response = await fetch("https://api.example.com/data");
  		if (!response.ok) throw new Error("Sync failed");
  		//· ...
  	}
  }
  ```
</TypeScriptExample>

**사용 사례:**

- 분 오염 (모두 10, 30, 45 초)
- Cron에 지도하지 않는 간격 (90 초마다 7 분마다)
- 정확한 제어를 가진 Rate-limited API polling
- 실시간 데이터 동기화

## 자주 묻는 질문

### 자주 묻는 질문

ID로 예약된 작업을 검색:

<TypeScriptExample>

  ```ts
  const schedule = this.getSchedule(scheduleId);

  if (schedule) {
  	console.log(
  		`Task ${schedule.id} will run at ${new Date(schedule.time * 1000)}`,

  	console.log(`Type: ${schedule.type}`); //"스케이드" | "레이드" | "크론" | "interval"
  } else {
  	console.log("Schedule not found");
  }
  ```
</TypeScriptExample>

### 일정표

Query는 선택 필터와 작업 예정:

<TypeScriptExample>
  ```ts
  //자주 묻는 질문

  //단지 cron 작업

  ```
</TypeScriptExample>

### 자주 묻는 질문

실행하기 전에 예정된 작업을 제거:

<TypeScriptExample>
  ```ts
  const cancelled = await this.cancelSchedule(scheduleId);

  if (cancelled) {
  	console.log("Schedule cancelled successfully");
  } else {
  	console.log("Schedule not found (may have already executed)");
  }
  ```
</TypeScriptExample>

**예: 취소 가능한 알림**

<TypeScriptExample>
  ```ts
  class ReminderAgent extends Agent {
  	async setReminder(userId: string, message: string, delaySeconds: number) {
  		const schedule = await this.schedule(delaySeconds, "sendReminder", {
  			userId,
  			message,
  		});

  		//일정 ID를 저장하여 나중에 취소할 수 있습니다.
  		this.sql`
        INSERT INTO user_reminders (user_id, schedule_id, message)
        VALUES (${userId}, ${schedule.id}, ${message})
      `;

  		return schedule.id;
  	}

  	async cancelReminder(scheduleId: string) {
  		const cancelled = await this.cancelSchedule(scheduleId);

  		if (cancelled) {
  			this.sql`DELETE FROM user_reminders WHERE schedule_id = ${scheduleId}`;
  		}

  		return cancelled;
  	}

  	async sendReminder(payload: { userId: string; message: string }) {
  		//알림 보내기

  		//기록 정리
  		this.sql`DELETE FROM user_reminders WHERE user_id = ${payload.userId}`;
  	}
  }
  ```
</TypeScriptExample>

## 일정 객체

일정을 작성하거나 검색할 때, 당신은 얻을`Schedule`객체:

```ts
type Schedule<T> = {
	id: string; //고유 식별자
	callback: string; //호출 방법 이름
	payload: T; //콜백에 전달된 데이터
	time: number; //다음 실행의 유닉스 타임스탬프 (둘째)
} & (
	| { type: "scheduled" } //특정 날짜에 한 번
	| { type: "delayed"; delayInSeconds: number } //지연 후에 1 시간
	| { type: "cron"; cron: string } //Recurring (크론 표현)
	| { type: "interval"; intervalSeconds: number } //반복 (fixed 간격)
);
```

**예:**

<TypeScriptExample>
  ```ts
  const schedule = await this.schedule(60, "myTask", { foo: "bar" });

  console.log(schedule);
  //이름 *
  //id: "abc123xyz",
  //콜백: "myTask",
  //{ foo : "bar" },
  //시간: 1706745600,
  //유형: "delayed",
  //지연InSeconds: 60
  //이름 *
  ```
</TypeScriptExample>

## 패턴

### 콜백에서 냉각

동적 반복 일정을 위해, 콜백 내에서 다음 실행을 계획:

<TypeScriptExample>
  ```ts
  class PollingAgent extends Agent {
  	async startPolling(intervalSeconds: number) {
  		await this.schedule(intervalSeconds, "poll", { interval: intervalSeconds });
  	}

  	async poll(payload: { interval: number }) {
  		try {
  			const data = await fetch("https://api.example.com/updates");
  			await this.processUpdates(await data.json());
  		} catch (error) {
  			console.error("Polling failed:", error);
  		}

  		//다음 설문 조사 일정 (수업 / 실패)
  		await this.schedule(payload.interval, "poll", payload);
  	}

  	async stopPolling() {
  		//모든 투표 일정 취소
  		const schedules = this.getSchedules({ type: "delayed" });
  		for (const schedule of schedules) {
  			if (schedule.callback === "poll") {
  				await this.cancelSchedule(schedule.id);
  			}
  		}
  	}
  }
  ```
</TypeScriptExample>

### 노출 backoff retry

<TypeScriptExample>
  ```ts
  class RetryAgent extends Agent {
  	async attemptTask(payload: {
  		taskId: string;
  		attempt: number;
  		maxAttempts: number;
  	}) {
  		try {
  			await this.doWork(payload.taskId);
  			console.log(
  				`Task ${payload.taskId} succeeded on attempt ${payload.attempt}`,
  			);
  		} catch (error) {
  			if (payload.attempt >= payload.maxAttempts) {
  				console.error(
  					`Task ${payload.taskId} failed after ${payload.maxAttempts} attempts`,
  				);
  				return;
  			}

  			//노출 백오프: 2^attempt 초 (2s, 4s, 8s, 16s...)
  			const delaySeconds = Math.pow(2, payload.attempt);

  			await this.schedule(delaySeconds, "attemptTask", {
  				...payload,
  				attempt: payload.attempt + 1,
  			});

  			console.log(`Retrying task ${payload.taskId} in ${delaySeconds}s`);
  		}
  	}

  	async doWork(taskId: string) {
  		//당신의 실제적인 일은 여기
  	}
  }
  ```
</TypeScriptExample>

### 자기 파괴 대리인

안전하게 전화할 수 있습니다.`this.destroy()`예정된 콜백 안에:

<TypeScriptExample>
  ```ts
  class TemporaryAgent extends Agent {
  	async onStart() {
  		//24 시간에 자기 파괴
  		await this.schedule(24 * 60 * 60, "cleanup", {});
  	}

  	async cleanup() {
  		//최종 정리
  		console.log("Agent lifetime expired, cleaning up...");

  		//예약된 콜백으로 전화하는 것이 안전합니다.
  		await this.destroy();
  	}
  }
  ```
</TypeScriptExample>

:::참조

시간 :`destroy()`예정된 작업 내에서 호출됩니다. Agent SDK는 예정된 콜백을 성공적으로 완료하기 위해 파괴를 방어합니다. 에이전트 인스턴스는 콜백 종료 후 즉시 evicted됩니다.

:::

## AI 보조 스케줄링

SDK는 AI로 자연 언어 스케줄링 요청을 파싱하기위한 유틸리티가 포함되어 있습니다.

### `getSchedulePrompt()`

자연 언어를 스케줄링 매개 변수로 파싱하기위한 시스템 프롬프트를 반환:

<TypeScriptExample>
  ```ts
  import { getSchedulePrompt, scheduleSchema } from "agents";
  import { generateObject } from "ai";
  import { openai } from "@ai-sdk/openai";

  class SmartScheduler extends Agent {
  	async parseScheduleRequest(userInput: string) {
  		const result = await generateObject({
  			model: openai("gpt-4o"),
  			system: getSchedulePrompt({ date: new Date() }),
  			prompt: userInput,
  			schema: scheduleSchema,
  		});

  		return result.object;
  	}

  	async handleUserRequest(input: string) {
  		//Parse: "내가 3pm에서 엄마를 호출하는 것은"
  		const parsed = await this.parseScheduleRequest(input);

  		//파일 형식
  		//설명: "콜 엄마",
  		//현재 위치:
  		//유형: "scheduled",
  		//날짜: "2025-01-30T15:00:00Z"
  		//이름 *
  		//이름 *

  		if (parsed.when.type === "scheduled" && parsed.when.date) {
  			await this.schedule(new Date(parsed.when.date), "sendReminder", {
  				message: parsed.description,
  			});
  		} else if (parsed.when.type === "delayed" && parsed.when.delayInSeconds) {
  			await this.schedule(parsed.when.delayInSeconds, "sendReminder", {
  				message: parsed.description,
  			});
  		} else if (parsed.when.type === "cron" && parsed.when.cron) {
  			await this.schedule(parsed.when.cron, "sendReminder", {
  				message: parsed.description,
  			});
  		}
  	}

  	async sendReminder(payload: { message: string }) {
  		console.log(`Reminder: ${payload.message}`);
  	}
  }
  ```
</TypeScriptExample>

### `scheduleSchema`

Zod schema for validating parsed 스케줄링 데이터. Discriminated 조합을 사용하여`when.type`이렇게 각 변종은 단지 그것을 필요로 하는 분야를 포함합니다:

<TypeScriptExample>
  ```ts
  import { scheduleSchema } from "agents";

  //schema는 차별적인 조합입니다:
  //이름 *
  //설명: 문자열,
  //현재 위치:
  //| { type: "scheduled", 날짜: string } // ISO 8601 날짜 문자열
  //| { type: "delayed", 지연InSeconds: 번호 }
  //| { 타입: "cron", cron: string }
  //| { 타입: "no-schedule"}
  //이름 *
  ```
</TypeScriptExample>

:::참조
날짜는 ISO 8601 문자열로 반환됩니다 (not)`Date`객체) Zod v3 및 v4 JSON schema 생성과 호환.

## 'Workflows' 대 Queue 대 일정

| 제품 정보       | 이름 \*     | 관련 기사  | Workflows\`에 대해서 |
| ----------- | --------- | ------ | ---------------- |
| **시간 :**    | 즉시 (FIFO) | 미래 시간  | 미래 시간            |
| **회사연혁**    | 회사연혁      | 예정된 시간 | 멀티 스텝            |
| **이름 \***   | 내장형       | 내장형    | 제품정보             |
| **이름 \***   | 사이트맵      | 사이트맵   | Workflow 엔진      |
| **관련 상품**   | 이름 \*     | 예 (크론) | 없습니다.            |
| **복합 논리**   | 이름 \*     | 이름 \*  | 이름 \*            |
| **인간적인 승인** | 이름 \*     | 이름 \*  | 이름 \*            |

현재 위치:

- 응답을 차단하지 않고 배경 처리가 필요합니다.
- 작업은 ASAP을 실행해야하지만 블록을 차단할 필요가 없습니다.
- 주문 문제 (FIFO)

Scheduling을 사용할 때:

- 작업은 특정 시간에 실행해야합니다
- 구직 (cron)
- 지연된 실행 (debouncing, retries)

Workflows를 사용할 때:

- Multi-step 프로세스
- backoff를 가진 자동적인 retries
- 인간-in-the-loop 승인
- 긴 실행 작업 (분에서 시간)

## API 참고 자료

### `schedule()`

```ts
async schedule<T>(
  when: Date | string | number,
  callback: keyof this,
  payload?: T,
  options?: { retry?: RetryOptions }
): Promise<Schedule<T>>
```

미래의 실행에 대한 작업 계획.

**모수:**

- `when`- 실행할 때:`number`(두번째 지연),`Date`(특정 시간), 또는`string`(크론 표현)
- `callback`- 호출하는 방법의 이름
- `payload`- 콜백에 전달하는 데이터 (JP JSON-serializable)
- `options.retry`- 옵션 재량 설정. 더 알아보기[이름 \*](/agents/api-reference/retries/)상세 정보

**반환:**·`Schedule`작업 세부 사항과 객체

:::카트로션

존재하지 않는 방법에 대한 콜백을 설정하는 작업은 예외를 던집니다. 이름의 방법을 확인`callback`인수가 존재합니다.`Agent`수업.

:::

### `scheduleEvery()`

```ts
async scheduleEvery<T>(
  intervalSeconds: number,
  callback: keyof this,
  payload?: T,
  options?: { retry?: RetryOptions }
): Promise<Schedule<T>>
```

고정 간격에서 반복적으로 실행하는 작업 일정.

**모수:**

- `intervalSeconds`- 실행 중 초 수 (0보다 더 큰)
- `callback`- 호출하는 방법의 이름
- `payload`- 콜백에 전달하는 데이터 (JP JSON-serializable)
- `options.retry`- 옵션 재량 설정. 더 알아보기[이름 \*](/agents/api-reference/retries/)상세 정보

**반환:**·`Schedule`객체와`type: "interval"`

**공급 능력:**

- 첫 번째 실행 후 발생`intervalSeconds`(즉시)
- 콜백이 여전히 실행될 때 다음 실행이 발생하면 건너뛰는 (overlap 예방)
- 콜백이 오류를 발생하면 간격이 계속됩니다.
- 이름 \*`cancelSchedule(id)`전체 간격을 중지

### `getSchedule()`

```ts
getSchedule<T>(id: string): Schedule<T> | undefined
```

ID로 예약된 작업을 가져옵니다. 기타 제품`undefined`찾을 수 없습니다. 이 방법은 비동기입니다.

```ts
getSchedules<T>(criteria?: {
  id?: string;
  type?: "scheduled" | "delayed" | "cron" | "interval";
  timeRange?: { start?: Date; end?: Date };
}): Schedule<T>[]
```

표준에 맞는 일정한 작업을 가져옵니다. 이 방법은 비동기입니다.

### `cancelSchedule()`

```ts
async cancelSchedule(id: string): Promise<boolean>
```

자주 묻는 질문 기타 제품`true`취소하는 경우`false`찾을 수 없습니다.

### `keepAlive()`

```ts
async keepAlive(): Promise<() => void>
```

30초의 심박수 일정을 만들기 위해 Inactivity로 인해 발생하는 튼튼한 개체를 방지합니다. 호출 할 때 심박수를 취소하는 disposer 함수를 반환합니다. disposer는 idempotent입니다 - 여러 번 호출은 안전합니다.

항상 작업을 수행 할 때 disposer 호출 - 그렇지 않으면 심벌은 무한하게 계속.

<TypeScriptExample>
  ```ts
  const dispose = await this.keepAlive();
  try {
  	//중단되지 않은 긴 실행 작업
  	const result = await longRunningComputation();
  	await sendResults(result);
  } finally {
  	dispose();
  }
  ```
</TypeScriptExample>

### `keepAliveWhile()`

```ts
async keepAliveWhile<T>(fn: () => Promise<T>): Promise<T>
```

튼튼한 개체를 유지하기 위해 async 함수를 실행합니다. Heartbeat는 함수가 실행되기 전에 자동으로 시작되며 완료되면 중지됩니다. (그런 것은 성공하거나 던지기). 함수에 의해 반환된 값을 반환합니다.

이용하시는 것이 좋습니다.`keepAlive`— 그것은 정리를 보장합니다.

<TypeScriptExample>
  ```ts
  const result = await this.keepAliveWhile(async () => {
  	const data = await longRunningComputation();
  	return data;
  });
  ```
</TypeScriptExample>

## 기업생활

Durable Objects는 inactivity(일반적으로 70-140초, 들어오지 않는 요청, WebSocket 메시지, 알람)의 기간 후 evicted입니다. 긴 실행 작업 동안 - 스트리밍 LLM 응답, 외부 API를 기다리고, 멀티 단계 계산을 실행 - 에이전트는 중간 기쁨을 evicted 할 수 있습니다.

`keepAlive()`30초의 심박수 일정을 작성하여 이것을 방지합니다. 내부 heartbeat 콜백은 no-op입니다 - 알람 발사 자체는 inactivity 타이머를 재설정하는 것입니다. 스케줄링 시스템을 사용했기 때문에:

- Heartbeat는 자신의 일정과 충돌하지 않습니다 (싱글 알람 슬롯을 통해 스케줄링 시스템 다중화)
- Heartbeat는에서 보여줍니다`getSchedules()`당신이 그것을 검사하는 경우에
- 다중 동시`keepAlive()`각 호출은 자신의 일정을 얻을, 그래서 그들은 서로 방해하지 않습니다

### 다중 동시 호출기

각 각`keepAlive()`호출은 독립적 인 disposer를 반환 :

<TypeScriptExample>
  ```ts
  const dispose1 = await this.keepAlive();
  const dispose2 = await this.keepAlive();

  //둘 다 heartbeats는 활동적입니다
  dispose1(); //첫 번째 심벌을 취소
  //에이전트는 여전히 dispose2의 심박수를 통해 살아

  dispose2(); //지금 대리인은 idle를 갈 수 있습니다
  ```
</TypeScriptExample>

### AIChatAgent 정보

`AIChatAgent`자동 호출`keepAlive()`스트리밍 응답 중. 사용할 때 자신을 추가 할 필요가 없습니다.`AIChatAgent`— 모든 LLM 스트림은 기본적으로 idle eviction에서 보호됩니다.

## 제한 사항

- **최대 작업:**&#x53;QLite 저장에 의해 제한 (각 작업은 행입니다). 실제 한계는 대리인 당 수천의 10s입니다.
- **작업 크기:**&#xAC01; 작업 (Payload 포함) 최대 2MB 수 있습니다.
- **최소 지연:**&#x30; 초 (다음 경보 진드기에 실행)
- **Cron 정밀도:**&#xBD84; 수준 (초)
- **공급 능력:**&#x32;단계
- **Cron 작업:**&#xC2E4;행 후, 자동으로 다음 발생을 위해 재개
- **Interval 작업:**&#xC2E4;행 후, 재개`now + intervalSeconds`; 아직도 달리는 경우에 건너뛰기
