Agents SDK는 비동기 실행을 위한 작업을 스케줄할 수 있는 내장 큐 시스템을 제공합니다. 이 배경 처리를 위해 유용합니다, 지연된 가동, 그리고 즉시 실행을 필요로 하지 않는 workload 관리.

## 제품정보

큐 시스템은 기초에 내장`Agent`수업. 작업은 SQLite 테이블에 저장되며 FIFO (First In, First Out) 주문에서 자동으로 처리됩니다.

## `QueueItem`제품정보

```ts
type QueueItem<T> = {
	id: string; //queued 작업에 대한 고유 식별자
	payload: T; //콜백 기능에 전달하는 데이터
	callback: keyof Agent; //호출 방법의 이름
	created_at: number; //작업이 생성되었을 때 Timestamp
};
```

## 핵심 방법

### `queue()`

미래의 실행을 위해 큐에 작업을 추가합니다.

```ts
async queue<T>(callback: keyof this, payload: T): Promise<string>
```

**모수:**

- `callback`- 작업 처리시 호출하는 방법의 이름
- `payload`- 콜백 메소드에 전달하는 데이터

**반환:**&#xD034;즈 작업의 독특한 ID

**예:**

<TypeScriptExample>
  ```ts
  class MyAgent extends Agent {
  	async processEmail(data: { email: string; subject: string }) {
  		//이메일
  		console.log(`Processing email: ${data.subject}`);
  	}

  	async onMessage(message: string) {
  		//이메일 처리 작업
  		const taskId = await this.queue("processEmail", {
  			email: "user@example.com",
  			subject: "Welcome!",
  		});

  		console.log(`Queued task with ID: ${taskId}`);
  	}
  }
  ```
</TypeScriptExample>

### `dequeue()`

ID로 큐에서 특정 작업을 제거합니다. 이 방법은 비동기입니다.

```ts
dequeue(id: string): void
```

**모수:**

- `id`- 제거하기 위해 작업의 ID

**예:**

<TypeScriptExample>
  ```ts
  //특정 작업을 제거
  agent.dequeue("abc123def");
  ```
</TypeScriptExample>

### `dequeueAll()`

큐에서 모든 작업을 제거. 이 방법은 비동기입니다.

```ts
dequeueAll(): void
```

**예:**

<TypeScriptExample>
  ```ts
  //전체 큐를 취소
  agent.dequeueAll();
  ```
</TypeScriptExample>

### `dequeueAllByCallback()`

특정 콜백 메소드와 일치하는 모든 작업을 제거합니다. 이 방법은 비동기입니다.

```ts
dequeueAllByCallback(callback: string): void
```

**모수:**

- `callback`- 콜백 방법의 이름

**예:**

<TypeScriptExample>
  ```ts
  //모든 이메일 처리 작업을 제거
  agent.dequeueAllByCallback("processEmail");
  ```
</TypeScriptExample>

### `getQueue()`

ID로 특정한 할당 작업을 검색합니다. 이 방법은 비동기입니다.

```ts
getQueue<T>(id: string): QueueItem<T> | undefined
```

**모수:**

- `id`- 작업의 ID는 검색

**반환:**&#xB354; 보기`QueueItem`패딩 페이로드 또는`undefined`찾을 수 없음

페이로드는 반환되기 전에 JSON에서 자동으로 파싱됩니다.

**예:**

<TypeScriptExample>
  ```ts
  const task = agent.getQueue("abc123def");
  if (task) {
  	console.log(`Task callback: ${task.callback}`);
  	console.log(`Task payload:`, task.payload);
  }
  ```
</TypeScriptExample>

### `getQueues()`

특정 키 값 쌍과 일치하는 모든 누적 작업을 검색합니다. 이 방법은 비동기입니다.

```ts
getQueues<T>(key: string, value: string): QueueItem<T>[]
```

**모수:**

- `key`- payload에 의해 필터의 열쇠
- `value`- 일치 값

**반환:**&#xC77C;치의 배열`QueueItem`기타 제품

이 방법은 모든 큐 항목을 태우고 각 페이로드를 파싱하여 메모리에 필터링하고 지정된 키가 값을 일치하면 검사합니다.

**예:**

<TypeScriptExample>
  ```ts
  //특정 사용자에 대한 모든 작업을 찾기
  const userTasks = agent.getQueues("userId", "12345");
  ```
</TypeScriptExample>

## queue 처리 작업

1. **인증 및 인증**: 호출시`queue()`, the method validates that the callback 존재s as a function on the agent.
2. **자동 처리**: queuing 후, 시스템은 자동으로 큐를 플러시하려고합니다.
3. **FIFO 주문**: 작업이 생성 된 순서로 처리됩니다 (`created_at`타임스탬프).
4. **Context 보전**: 각 누적 작업은 동일한 에이전트 컨텍스트 (연결, 요청, 이메일)로 실행됩니다.
5. **자동 dequeue**: 성공적으로 실행된 작업은 queue에서 자동으로 제거됩니다.
6. **오류 처리**: 콜백 방법이 실행 시간에 존재하지 않는 경우, 오류가 로그되고 작업이 건너 뛰는 것입니다.
7. **이름 \***: 작업이 저장됩니다.`cf_agents_queues`SQL 테이블과 생존 에이전트 재시작.

## Queue 콜백 방법

할당 된 작업에 대한 콜백 방법을 정의 할 때, 그들은이 서명을 따라야한다 :

```ts
async callbackMethod(payload: unknown, queueItem: QueueItem): Promise<void>
```

**예:**

<TypeScriptExample>
  ```ts
  class MyAgent extends Agent {
  	async sendNotification(
  		payload: { userId: string; message: string },
  		queueItem: QueueItem<{ userId: string; message: string }>,
  	) {
  		console.log(`Processing task ${queueItem.id}`);
  		console.log(
  			`Sending notification to user ${payload.userId}: ${payload.message}`,
  		);

  		//당신의 알림 논리 여기
  		await this.notificationService.send(payload.userId, payload.message);
  	}

  	async onUserSignup(userData: any) {
  		//자주 묻는 질문
  		await this.queue("sendNotification", {
  			userId: userData.id,
  			message: "Welcome to our platform!",
  		});
  	}
  }
  ```
</TypeScriptExample>

## 사용 사례

### 배경 처리

<TypeScriptExample>
  ```ts
  class DataProcessor extends Agent {
  	async processLargeDataset(data: { datasetId: string; userId: string }) {
  		const results = await this.heavyComputation(data.datasetId);
  		await this.notifyUser(data.userId, results);
  	}

  	async onDataUpload(uploadData: any) {
  		//비동기적으로 하는 대신 처리
  		await this.queue("processLargeDataset", {
  			datasetId: uploadData.id,
  			userId: uploadData.userId,
  		});

  		return { message: "Data upload received, processing started" };
  	}
  }
  ```
</TypeScriptExample>

### 일괄 작업

<TypeScriptExample>
  ```ts
  class BatchProcessor extends Agent {
  	async processBatch(data: { items: any[]; batchId: string }) {
  		for (const item of data.items) {
  			await this.processItem(item);
  		}
  		console.log(`Completed batch ${data.batchId}`);
  	}

  	async onLargeRequest(items: any[]) {
  		//작은 배치로 큰 요청을 분할
  		const batchSize = 10;
  		for (let i = 0; i < items.length; i += batchSize) {
  			const batch = items.slice(i, i + batchSize);
  			await this.queue("processBatch", {
  				items: batch,
  				batchId: `batch-${i / batchSize + 1}`,
  			});
  		}
  	}
  }
  ```
</TypeScriptExample>

## 오류 처리

<TypeScriptExample>
  ```ts
  class RobustAgent extends Agent {
  	async reliableTask(payload: any, queueItem: QueueItem) {
  		try {
  			await this.doSomethingRisky(payload);
  		} catch (error) {
  			console.error(`Task ${queueItem.id} failed:`, error);

  			//retry 논리를 가진 선택적인 requeue
  			if (payload.retryCount < 3) {
  				await this.queue("reliableTask", {
  					...payload,
  					retryCount: (payload.retryCount || 0) + 1,
  				});
  			}
  		}
  	}
  }
  ```
</TypeScriptExample>

## 좋은 관행

1. **작은 payloads 유지**: Payloads는 JSON-serialized이며 데이터베이스에 저장됩니다.
2. **Idempotent 운영**: 디자인 콜백 메서드는 리트리에 안전합니다.
3. **오류 처리**: 콜백 메소드에서 적절한 오류 처리가 포함되어 있습니다.
4. **관련 기사**: queue 처리를 추적하기 위해 로깅을 사용합니다.
5. **회사 소개**: 일반 청소 완료 또는 필요한 경우 실패 작업.

## 다른 기능과 통합

queue 시스템은 다른 Agent SDK 기능과 함께 작동합니다.

- **국가 관리**: Queued 콜백 내의 출입 에이전트 상태.
- **관련 기사**: 결합[`schedule()`](/agents/api-reference/schedule-tasks/)시간 기반 queue 처리를 위해.
- **사이트맵**: Queued 작업은 원래 요청 컨텍스트를 유지합니다.
- **관련 기사**: 다른 에이전트 데이터와 동일한 데이터베이스를 사용합니다.

## 제한 사항

- 작업은 순차적으로 처리되며 평행하지 않습니다.
- 우선 시스템 없음 (FIFO 전용).
- Queue 처리는 에이전트 실행 중 발생, 별도의 배경 작업.

:::참조
Queue 작업은 exponential backoff와 내장 된 저장소를 지원합니다. 패스워드`{ retry: { maxAttempts, baseDelayMs, maxDelayMs } }`세 번째 인수로`queue()`. 참고[이름 \*](/agents/api-reference/retries/)상세 정보
