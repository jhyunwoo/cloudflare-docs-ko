에이전트는 'Cloudflare\`를 사용하여 수신 및 프로세스 이메일을받을 수 있습니다.[이메일 Routing](/email-routing/email-workers/). 이 가이드는 에이전트에 인바운드 메일을 경로를 처리하고 안전하게 replies.

## 자주 묻는 질문

1. 설정된 도메인[Cloudflare 이메일 루팅](/email-routing/).
2. 메일을 수신하도록 설정된 이메일 작업자.
3. 이메일 처리 에이전트.

## 빠른 시작

<TypeScriptExample>
  ```ts
  import { Agent, routeAgentEmail } from "agents";
  import { createAddressBasedEmailResolver, type AgentEmail } from "agents/email";

  //이메일 처리
  export class EmailAgent extends Agent {
  	async onEmail(email: AgentEmail) {
  		console.log("Received email from:", email.from);
  		console.log("Subject:", email.headers.get("subject"));

  		//자주 묻는 질문
  		await this.replyToEmail(email, {
  			fromName: "My Agent",
  			body: "Thanks for your email!",
  		});
  	}
  }

  //귀하의 에이전트에 경로
  export default {
  	async email(message, env) {
  		await routeAgentEmail(message, env, {
  			resolver: createAddressBasedEmailResolver("EmailAgent"),
  		});
  	},
  } satisfies ExportedHandler<Env>;
  ```
</TypeScriptExample>

## 해결사

Resolvers는 에이전트 인스턴스가 수신된 이메일임을 결정합니다. 사용 사례와 일치하는 해결자를 선택하십시오.

### `createAddressBasedEmailResolver`

인바운드 메일에 대한 추천. 수신자 주소에 근거한 노선 이메일.

<TypeScriptExample>
  ```ts
  import { createAddressBasedEmailResolver } from "agents/email";

  const resolver = createAddressBasedEmailResolver("EmailAgent");
  ```
</TypeScriptExample>

**여정 논리:**

| 자주 묻는 질문                                | 에이전트 이름             | 에이전트 ID   |
| --------------------------------------- | ------------------- | --------- |
| `support@example.com`                   | `EmailAgent`(과태)    | `support` |
| `sales@example.com`                     | `EmailAgent`(과태)    | `sales`   |
| `NotificationAgent+user123@example.com` | `NotificationAgent` | `user123` |

하위주소 형식 (`agent+id@domain`)는 단일 이메일 도메인에서 다른 에이전트 네임스페이스 및 인스턴스로 라우팅할 수 있습니다.

### `createSecureReplyEmailResolver`

응답을 위해 서명 확인과 흐름. 수신된 이메일은 아웃바운드 이메일에 대한 인증된 답변이며, arbitrary 에이전트 인스턴스에 대한 routing 이메일에서 공격자를 방지합니다.

<TypeScriptExample>
  ```ts
  import { createSecureReplyEmailResolver } from "agents/email";

  const resolver = createSecureReplyEmailResolver(env.EMAIL_SECRET);
  ```
</TypeScriptExample>

에이전트가 이메일을 보낼 때`replyToEmail()`·`secret`, 그것은 타임스탬프를 가진 여정 우두머리를 서명합니다. 답변이 돌아올 때, 이 해결자는 서명을 검증하고 여정 전에 만료되지 않은 검사를 확인합니다.

**옵션 :**

<TypeScriptExample>
  ```ts
  const resolver = createSecureReplyEmailResolver(env.EMAIL_SECRET, {
  	//초 (기본값: 30일)
  	maxAge: 7 * 24 * 60 * 60, //7 일

  	//logging/debugging 서명 실패를 위한 콜백
  	onInvalidSignature: (email, reason) => {
  		console.warn(`Invalid signature from ${email.from}: ${reason}`);
  		//이유는 다음과 같습니다: "missing headers", "expired", "invalid", "malformed timestamp"
  	},
  });
  ```
</TypeScriptExample>

**사용시:**&#xC5D0;이전트가 이메일 대화를 시작하면 동일한 에이전트 인스턴스로 돌아갈 수 있습니다.

### `createCatchAllEmailResolver`

단 하나 조밀도 여정을 위해. 수신자 주소에 관계없이 특정 에이전트 인스턴스에 대한 모든 이메일.

<TypeScriptExample>
  ```ts
  import { createCatchAllEmailResolver } from "agents/email";

  const resolver = createCatchAllEmailResolver("EmailAgent", "default");
  ```
</TypeScriptExample>

**사용시:**&#xBAA8;든 이메일을 처리하는 단일 에이전트 인스턴스가있을 때 (예를 들어, 공유 inbox).

### 해결사 결합

다른 시나리오를 처리 할 해결자를 결합 할 수 있습니다 :

<TypeScriptExample>
  ```ts
  export default {
  	async email(message, env) {
  		const secureReplyResolver = createSecureReplyEmailResolver(
  			env.EMAIL_SECRET,
  		);
  		const addressResolver = createAddressBasedEmailResolver("EmailAgent");

  		await routeAgentEmail(message, env, {
  			resolver: async (email, env) => {
  				//첫 번째,이 서명 된 응답인지 확인
  				const replyRouting = await secureReplyResolver(email, env);
  				if (replyRouting) return replyRouting;

  				//그렇지 않으면, 수신자 주소를 기준으로 경로
  				return addressResolver(email, env);
  			},

  			//어떤 라우팅 규칙과 일치하지 않는 이메일 처리
  			onNoRoute: (email) => {
  				console.warn(`No route found for email from ${email.from}`);
  				email.setReject("Unknown recipient");
  			},
  		});
  	},
  } satisfies ExportedHandler<Env>;
  ```
</TypeScriptExample>

## 귀하의 에이전트에서 이메일 처리

### Agent이메일 인터페이스

당신의 대리인의 때`onEmail`메소드는 호출, 그것은 수신`AgentEmail`객체:

```ts
type AgentEmail = {
	from: string; //Sender의 이메일 주소
	to: string; //Recipient의 이메일 주소
	headers: Headers; //이메일 헤더 (subject, message-id 등)
	rawSize: number; //바이트의 원시 이메일의 크기

	getRaw(): Promise<Uint8Array>; //전체 원시 이메일 내용 얻기
	reply(options): Promise<void>; //자주 묻는 질문
	forward(rcptTo, headers?): Promise<void>; //이메일 발송
	setReject(reason): void; //이메일 주소
};
```

### 연락처

도서관 사용[최근 포스트](https://www.npmjs.com/package/postal-mime)이메일:

<TypeScriptExample>
  ```ts
  import PostalMime from "postal-mime";

  class MyAgent extends Agent {
  	async onEmail(email: AgentEmail) {
  		const raw = await email.getRaw();
  		const parsed = await PostalMime.parse(raw);

  		console.log("Subject:", parsed.subject);
  		console.log("Text body:", parsed.text);
  		console.log("HTML body:", parsed.html);
  		console.log("Attachments:", parsed.attachments);
  	}
  }
  ```
</TypeScriptExample>

### 자동 리턴 이메일 탐지

제품 정보`isAutoReplyEmail()`전자 메일을 감지하고 메일 루프를 방지하기 위해 :

<TypeScriptExample>
  ```ts
  import { isAutoReplyEmail } from "agents/email";
  import PostalMime from "postal-mime";

  class MyAgent extends Agent {
  	async onEmail(email: AgentEmail) {
  		const raw = await email.getRaw();
  		const parsed = await PostalMime.parse(raw);

  		//중복 응답을 보낼 수 있도록 자동 리턴 이메일을 감지
  		if (isAutoReplyEmail(parsed.headers)) {
  			console.log("Skipping auto-reply email");
  			return;
  		}

  		//이메일 처리
  	}
  }
  ```
</TypeScriptExample>

표준 RFC 3834 헤더에 대한이 체크 (`Auto-Submitted`, `X-Auto-Response-Suppress`, `Precedence`) 그것은 전자 메일을 나타냅니다 자동 반환.

### 자주 묻는 질문

제품 정보`this.replyToEmail()`답장을 보내려면:

<TypeScriptExample>
  ```ts
  class MyAgent extends Agent {
  	async onEmail(email: AgentEmail) {
  		await this.replyToEmail(email, {
  			fromName: "Support Bot", //sender를 위한 표시 이름
  			subject: "Re: Your inquiry", //선택 사항, 기본값은 "Re:"
  			body: "Thanks for contacting us!", //이메일 body
  			contentType: "text/plain", //선택 사항, 기본적으로 "text/plain"
  			headers: {
  				//옵션 사용자 정의 헤더
  				"X-Custom-Header": "value",
  			},
  			secret: this.env.EMAIL_SECRET, //선택 사항, 보안 회신을위한 표지판 헤더
  		});
  	}
  }
  ```
</TypeScriptExample>

## 안전한 대답 routing

에이전트가 이메일을 보내고 답장을 기대할 때, 위조 헤더에서 공격자를 방지하기 위해 안전한 응답 룰렛을 사용하여 임의 에이전트 인스턴스에 이메일을 전달합니다.

### 어떻게 작동합니까?

1. **아웃바운드:**&#xC804;화 번호`replyToEmail()`한국어`secret`, 대리인은 routing 우두머리를 서명합니다 (`X-Agent-Name`, `X-Agent-ID`) HMAC-SHA256를 사용하여.
2. **상행:** `createSecureReplyEmailResolver`routing 전에 서명을 지정합니다.
3. **공급 능력:**&#xC774;메일이 안전한 해결자를 통해 경로를 갖는 경우,`replyToEmail()`비밀을 요구합니다 (또는 명시된`null`선택하기).

### 설치하기

1. 당신의 비밀을 추가`wrangler.jsonc`:

   <WranglerConfig>
     ```jsonc
     {
     	"vars": {
     		"EMAIL_SECRET": "change-me-in-production",
     	},
     }
     ```
   </WranglerConfig>

   생산을 위해, 대신에 Wrangler secrets를 사용하십시오:

   ```sh
   npx wrangler secret put EMAIL_SECRET
   ```

2. 결합된 결말 본을 사용하십시오:

   <TypeScriptExample>
     ```ts
     export default {
     	async email(message, env) {
     		const secureReplyResolver = createSecureReplyEmailResolver(
     			env.EMAIL_SECRET,
     		);
     		const addressResolver = createAddressBasedEmailResolver("EmailAgent");

     		await routeAgentEmail(message, env, {
     			resolver: async (email, env) => {
     				const replyRouting = await secureReplyResolver(email, env);
     				if (replyRouting) return replyRouting;
     				return addressResolver(email, env);
     			},
     		});
     	},
     } satisfies ExportedHandler<Env>;
     ```
   </TypeScriptExample>

3. 이메일:

   <TypeScriptExample>
     ```ts
     class MyAgent extends Agent {
     	async onEmail(email: AgentEmail) {
     		await this.replyToEmail(email, {
     			fromName: "My Agent",
     			body: "Thanks for your email!",
     			secret: this.env.EMAIL_SECRET, //routing 헤더를 서명
     		});
     	}
     }
     ```
   </TypeScriptExample>

### 인력 행동

이메일이 via`createSecureReplyEmailResolver`·`replyToEmail()`방법 서명 시행:

| `secret`제품정보    | 채용 정보                             |
| --------------- | --------------------------------- |
| `"my-secret"`   | 헤더(secure)                        |
| `undefined`(필수) | **비밀번호**- 비밀 또는 명시 옵트 아웃을 제공해야합니다 |
| `null`          | 허용하지만 권장되지 않음 - 명시적으로 서명 중 선택     |

## 완전한 예

안전한 대답 여정을 가진 완전한 이메일 대리인은 여기 있습니다:

<TypeScriptExample>
  ```ts
  import { Agent, routeAgentEmail } from "agents";
  import {
  	createAddressBasedEmailResolver,
  	createSecureReplyEmailResolver,
  	type AgentEmail,
  } from "agents/email";
  import PostalMime from "postal-mime";

  interface Env {
  	EmailAgent: DurableObjectNamespace;
  	EMAIL_SECRET: string;
  }

  export class EmailAgent extends Agent {
  	async onEmail(email: AgentEmail) {
  		const raw = await email.getRaw();
  		const parsed = await PostalMime.parse(raw);

  		console.log(`Email from ${email.from}: ${parsed.subject}`);

  		//이메일 주소
  		const emails = this.state.emails || [];
  		emails.push({
  			from: email.from,
  			subject: parsed.subject,
  			receivedAt: new Date().toISOString(),
  		});
  		this.setState({ ...this.state, emails });

  		//서명된 우두머리로 자동 반환
  		await this.replyToEmail(email, {
  			fromName: "Support Bot",
  			body: `Thanks for your email! We received: "${parsed.subject}"`,
  			secret: this.env.EMAIL_SECRET,
  		});
  	}
  }

  export default {
  	async email(message, env: Env) {
  		const secureReplyResolver = createSecureReplyEmailResolver(
  			env.EMAIL_SECRET,
  			{
  				maxAge: 7 * 24 * 60 * 60, //7 일
  				onInvalidSignature: (email, reason) => {
  					console.warn(`Invalid signature from ${email.from}: ${reason}`);
  				},
  			},
  		);
  		const addressResolver = createAddressBasedEmailResolver("EmailAgent");

  		await routeAgentEmail(message, env, {
  			resolver: async (email, env) => {
  				//안전한 대답 여정을 첫째로 시도하십시오
  				const replyRouting = await secureReplyResolver(email, env);
  				if (replyRouting) return replyRouting;
  				//주소 기반 라우팅으로 돌아가기
  				return addressResolver(email, env);
  			},
  			onNoRoute: (email) => {
  				console.warn(`No route found for email from ${email.from}`);
  				email.setReject("Unknown recipient");
  			},
  		});
  	},
  } satisfies ExportedHandler<Env>;
  ```
</TypeScriptExample>

## API 참고 자료

### `routeAgentEmail`

```ts
function routeAgentEmail<Env>(
	email: ForwardableEmailMessage,
	env: Env,
	options: {
		resolver: EmailResolver;
		onNoRoute?: (email: ForwardableEmailMessage) => void | Promise<void>;
	},
): Promise<void>;
```

해결자의 결정에 따라 적절한 에이전트로 들어오는 이메일.

| 옵션 정보       | 이름 \*                                                                                     |
| ----------- | ----------------------------------------------------------------------------------------- |
| `resolver`  | 이메일 경로를 결정하는 기능                                                                           |
| `onNoRoute` | 옵션 콜백은 정보가 발견되지 않을 때 호출됩니다. 이메일을 거부하거나 사용자 정의 취급을 수행합니다. 제공되지 않은 경우, 경고가 기록되고 이메일이 삭제됩니다. |

### `createSecureReplyEmailResolver`

```ts
function createSecureReplyEmailResolver(
	secret: string,
	options?: {
		maxAge?: number;
		onInvalidSignature?: (
			email: ForwardableEmailMessage,
			reason: SignatureFailureReason,
		) => void;
	},
): EmailResolver;

type SignatureFailureReason =
	| "missing_headers"
	| "expired"
	| "invalid"
	| "malformed_timestamp";
```

이메일 routing에 대한 해결사 서명 검증을 받았습니다.

| 옵션 정보                | 이름 \*                                |
| -------------------- | ------------------------------------ |
| `secret`             | HMAC 검증에 대한 비밀 키 (Sign에 사용되는 키와 일치)  |
| `maxAge`             | 초에 있는 서명의 최대 나이 (과태: 30 일/2592000 초) |
| `onInvalidSignature` | 서명 검증이 실패할 때 로깅에 대한 옵션 콜백            |

### `signAgentHeaders`

```ts
function signAgentHeaders(
	secret: string,
	agentName: string,
	agentId: string,
): Promise<Record<string, string>>;
```

수동으로 서명 대리인 routing 우두머리. 객체를 반환합니다.`X-Agent-Name`, `X-Agent-ID`, `X-Agent-Sig`·`X-Agent-Sig-Ts`머리.

외부 서비스를 통해 이메일을 보낼 때 유용한 보안 답변을 유지하면서. 서명은 타임스탬프를 포함하고 기본적으로 30 일 동안 유효합니다.
