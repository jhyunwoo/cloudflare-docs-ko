회사연혁[Cloudflare작업 흐름](/workflows/)에이전트가 실시간 통신을 처리하면서 내구성, 다중 단계 배경 처리를 위한 에이전트.

:::노트\[Agents vs. Workflows]

에이전트는 실시간 통신 및 상태 관리에서 발췌. Workflows는 자동적인 retries, 실패 회복 및 외부 사건을 기다리는 튼튼한 실행에 발췌합니다.

채팅, 메시징 및 빠른 API 통화를 위해 혼자 에이전트를 사용합니다. 긴 실행 작업 (30 초 이상), 다중 단계 파이프라인 및 인간의 승인 흐름에 대 한 에이전트 + 작업 흐름을 사용 합니다.

:::

## 빠른 시작

### 1. 워크 플로우 정의

지원하다`AgentWorkflow`시작 에이전트에 대한 유형 접근 :

<TypeScriptExample>
  ```ts
  import { AgentWorkflow } from "agents/workflows";
  import type { AgentWorkflowEvent, AgentWorkflowStep } from "agents/workflows";
  import type { MyAgent } from "./agent";

  type TaskParams = { taskId: string; data: string };

  export class ProcessingWorkflow extends AgentWorkflow<MyAgent, TaskParams> {
  	async run(event: AgentWorkflowEvent<TaskParams>, step: AgentWorkflowStep) {
  		const params = event.payload;

  		const result = await step.do("process-data", async () => {
  			return processData(params.data);
  		});

  		//Non-durable: 진행 보고 (회전에 may 반복)
  		await this.reportProgress({
  			step: "process",
  			status: "complete",
  			percent: 0.5,
  		});

  		//WebSocket 클라이언트를 연결하는 방송
  		this.broadcastToClients({ type: "update", taskId: params.taskId });

  		await step.do("save-results", async () => {
  			//RPC를 통해 에이전트 방법 호출
  			await this.agent.saveResult(params.taskId, result);
  		});

  		//내구재: idempotent는, retry에 반복하지 않을 것입니다
  		await step.reportComplete(result);
  		return result;
  	}
  }
  ```
</TypeScriptExample>

### 2. 에이전트에서 Workflow 시작

제품 정보`runWorkflow()`시작 및 트랙 워크플로우:

<TypeScriptExample>
  ```ts
  import { Agent } from "agents";

  export class MyAgent extends Agent {
  	async startTask(taskId: string, data: string) {
  		const instanceId = await this.runWorkflow("PROCESSING_WORKFLOW", {
  			taskId,
  			data,
  		});
  		return { instanceId };
  	}

  	async onWorkflowProgress(
  		workflowName: string,
  		instanceId: string,
  		progress: unknown,
  	) {
  		this.broadcast(JSON.stringify({ type: "workflow-progress", progress }));
  	}

  	async onWorkflowComplete(
  		workflowName: string,
  		instanceId: string,
  		result?: unknown,
  	) {
  		console.log(`Workflow completed:`, result);
  	}

  	async saveResult(taskId: string, result: unknown) {
  		this
  			.sql`INSERT INTO results (task_id, data) VALUES (${taskId}, ${JSON.stringify(result)})`;
  	}
  }
  ```
</TypeScriptExample>

## AgentWorkflow 클래스

에이전트와 통합하는 Workflows의 기본 클래스.

### 유형 모수

| 제품 설명          | 이름 \*                               |
| -------------- | ----------------------------------- |
| `AgentType`    | 유형 RPC를 위한 대리인 종류 유형                |
| `Params`       | 워크플로우에 전달된 매개변수                     |
| `ProgressType` | 진행 보고를 위한 유형 (과태에`DefaultProgress`) |
| `Env`          | 환경 유형 (과태에`Cloudflare.Env`)         |

### 제품 정보

| 회사 정보          | 제품정보  | 이름 \*                       |
| -------------- | ----- | --------------------------- |
| `agent`        | 사이트맵  | Agent 메소드 호출을 위한 Typed stub |
| `instanceId`   | 이름 \* | 워크플로우 인스턴스 ID               |
| `workflowName` | 이름 \* | 작업 흐름 바인딩 이름                |
| `env`          | 지원하다  | 환경 바인딩                      |

### 인스턴스 방법 (non-durable)

이 방법은 retry에 반복 할 수 있습니다. 경량, 빈번한 업데이트를 위한 사용.

#### reportProgress(승인)

에이전트로 진행 상황을 보고합니다. 트리거`onWorkflowProgress`콜백.

<TypeScriptExample>
  ```ts
  await this.reportProgress({
  	step: "processing",
  	status: "running",
  	percent: 0.5,
  });
  ```
</TypeScriptExample>

#### BroadcastToClients(메시지)

에이전트에 연결된 모든 WebSocket 클라이언트에게 메시지를 방송합니다.

<TypeScriptExample>
  ```ts
  this.broadcastToClients({ type: "update", data: result });
  ```
</TypeScriptExample>

#### waitForApproval(단계, 옵션?)

승인 이벤트를 기다립니다. 한국어`WorkflowRejectedError`거부하는 경우.

<TypeScriptExample>
  ```ts
  const approval = await this.waitForApproval<{ approvedBy: string }>(step, {
  	timeout: "7 days",
  });
  ```
</TypeScriptExample>

### 단계 방법 (durable)

이 방법은 idempotent이고 재발행에 반복하지 않습니다. persist를 해야 하는 상태 변경에 대 한 사용.

| 제품 설명                           | 이름 \*                         |
| ------------------------------- | ----------------------------- |
| `step.reportComplete(result?)`  | 성공 사례                         |
| `step.reportError(error)`       | 오류 신고                         |
| `step.sendEvent(event)`         | 에이전트에 맞춤 이벤트 보내기              |
| `step.updateAgentState(state)`  | 에이전트 상태 교체 (고객에게 브로드캐스트)      |
| `step.mergeAgentState(partial)` | 에이전트 상태에 Merge (고객에게 브로드 캐스트) |
| `step.resetAgentState()`        | 초기 상태 재설정                     |

### DefaultProgress 유형

```ts
type DefaultProgress = {
	step?: string;
	status?: "pending" | "running" | "complete" | "error";
	message?: string;
	percent?: number;
	[key: string]: unknown;
};
```

## Agent 워크플로 방법

사용방법`Agent`Workflow 관리 클래스.

### runWorkflow(workflowName, params, 옵션?)

작업 흐름 인스턴스를 시작하고 에이전트 데이터베이스에서 추적합니다.

**모수:**

| 제품 설명                  | 제품정보  | 이름 \*                              |
| ---------------------- | ----- | ---------------------------------- |
| `workflowName`         | 이름 \* | Workflow 바인딩 이름`env`               |
| `params`               | 기타 제품 | 작업 흐름에 전달하는 매개 변수                  |
| `options.id`           | 이름 \* | 사용자 정의 워크플로우 ID (제공되지 않은 경우 자동 생성) |
| `options.metadata`     | 기타 제품 | 쿼리에 저장 된 Metadata (작업 흐름에 전달되지 않음) |
| `options.agentBinding` | 이름 \* | 에이전트 바인딩 이름 (제공하지 않는 경우 자동 감지)     |

**반환:** `Promise<string>`- 워크 플로우 인스턴스 ID

<TypeScriptExample>
  ```ts
  const instanceId = await this.runWorkflow(
  	"MY_WORKFLOW",
  	{ taskId: "123" },
  	{
  		metadata: { userId: "user-456", priority: "high" },
  	},
  );
  ```
</TypeScriptExample>

### Workflows(criteria?)를 얻으세요.

Query는 커서 기반 pagination과 워크플로를 추적했습니다. 구매하기`WorkflowPage`워크플로우, 총 수, 다음 페이지의 커서.

<TypeScriptExample>
  ```ts
  //작업 흐름을 실행 (기본 제한은 50, 최대 100)
  const { workflows, total } = this.getWorkflows({ status: "running" });

  //메타데이터에 의한 필터
  const { workflows: userWorkflows } = this.getWorkflows({
  	metadata: { userId: "user-456" },
  });

  //cursor의 질
  const page1 = this.getWorkflows({
  	status: ["complete", "errored"],
  	limit: 20,
  	orderBy: "desc",
  });

  console.log(`Showing ${page1.workflows.length} of ${page1.total} workflows`);

  //다음 페이지를 cursor
  if (page1.nextCursor) {
  	const page2 = this.getWorkflows({
  		status: ["complete", "errored"],
  		limit: 20,
  		orderBy: "desc",
  		cursor: page1.nextCursor,
  	});
  }
  ```
</TypeScriptExample>

더 보기`WorkflowPage`유형:

```ts
type WorkflowPage = {
	workflows: WorkflowInfo[];
	total: number; //Total matching 워크플로우
	nextCursor: string | null; //더 많은 페이지가 없을 때 null
};
```

### deleteWorkflow(변수) 아이)

단일 워크플로우 인스턴스 추적 기록 삭제. 기타 제품`true`삭제 된 경우`false`찾을 수 없습니다.

### deleteWorkflows(criteria?)를 삭제합니다.

작업 흐름 인스턴스 추적 기록 일치 기준.

<TypeScriptExample>
  ```ts
  //완료된 작업 흐름 인스턴스를 7일 이상 삭제
  this.deleteWorkflows({
  	status: "complete",
  	createdBefore: new Date(Date.now() - 7 * 24 * 60 * 60 * 1000),
  });

  //모든 오류 및 종료 워크플로우 삭제
  this.deleteWorkflows({
  	status: ["errored", "terminated"],
  });
  ```
</TypeScriptExample>

## Lifecycle 콜백

에이전트에서 작업 흐름 이벤트를 처리하는 방법에 대한 추가:

| 콜백                   | 매개 변수                                    | 이름 \*               |
| -------------------- | ---------------------------------------- | ------------------- |
| `onWorkflowProgress` | `workflowName`, `instanceId`, `progress` | 워크플로우가 진행될 때 호출     |
| `onWorkflowComplete` | `workflowName`, `instanceId`, `result?`  | 작업 흐름이 완료되면 호출      |
| `onWorkflowError`    | `workflowName`, `instanceId`, `error`    | 워크플로우 오류가 있을 때 호출   |
| `onWorkflowEvent`    | `workflowName`, `instanceId`, `event`    | 작업 흐름이 이벤트를 보낼 때 호출 |
| `onWorkflowCallback` | `callback: WorkflowCallback`             | 모든 콜백 유형에 대한 호출     |

<TypeScriptExample>
  ```ts
  class MyAgent extends Agent {
  	async onWorkflowProgress(
  		workflowName: string,
  		instanceId: string,
  		progress: unknown,
  	) {
  		this.broadcast(
  			JSON.stringify({ type: "progress", workflowName, instanceId, progress }),
  		);
  	}

  	async onWorkflowComplete(
  		workflowName: string,
  		instanceId: string,
  		result?: unknown,
  	) {
  		console.log(`${workflowName}/${instanceId} completed`);
  	}

  	async onWorkflowError(
  		workflowName: string,
  		instanceId: string,
  		error: string,
  	) {
  		console.error(`${workflowName}/${instanceId} failed:`, error);
  	}
  }
  ```
</TypeScriptExample>

## Workflow 추적

Workflows 시작`runWorkflow()`에이전트의 내부 데이터베이스에서 자동으로 추적됩니다. 위에서 설명한 방법을 사용하여 쿼리, 필터 및 워크플로를 관리할 수 있습니다.`getWorkflow()`, `getWorkflows()`, `deleteWorkflow()`, 등).

### 상태 값

| 주요연혁         | 이름 \*          |
| ------------ | -------------- |
| `queued`     | 시작하기           |
| `running`    | 현재 실행          |
| `paused`     | 사용자에 의해 Paused |
| `waiting`    | 행사 일정          |
| `complete`   | 성공적으로 완료       |
| `errored`    | 오류로 실패         |
| `terminated` | 수동으로 종료        |

사용 방법`metadata`옵션 정보`runWorkflow()`쿼리 가능한 정보 저장 (사용자 ID 또는 작업 유형과 같은) 나중에 필터링 할 수 있습니다`getWorkflows()`.

## 이름 \*

### 인간-in-the-loop 승인

<TypeScriptExample>
  ```ts
  import { AgentWorkflow } from "agents/workflows";
  import type { AgentWorkflowEvent, AgentWorkflowStep } from "agents/workflows";

  export class ApprovalWorkflow extends AgentWorkflow<MyAgent, RequestParams> {
  	async run(event: AgentWorkflowEvent<RequestParams>, step: AgentWorkflowStep) {
  		const request = await step.do("prepare", async () => {
  			return { ...event.payload, preparedAt: Date.now() };
  		});

  		await this.reportProgress({
  			step: "approval",
  			status: "pending",
  			message: "Awaiting approval",
  		});

  		//일러스트 WorkflowRejectedError가 거부되면
  		const approval = await this.waitForApproval<{ approvedBy: string }>(step, {
  			timeout: "7 days",
  		});

  		console.log("Approved by:", approval?.approvedBy);

  		const result = await step.do("execute", async () => {
  			return executeRequest(request);
  		});

  		await step.reportComplete(result);
  		return result;
  	}
  }

  class MyAgent extends Agent {
  	async handleApproval(instanceId: string, userId: string) {
  		await this.approveWorkflow(instanceId, {
  			reason: "Approved by admin",
  			metadata: { approvedBy: userId },
  		});
  	}

  	async handleRejection(instanceId: string, reason: string) {
  		await this.rejectWorkflow(instanceId, { reason });
  	}
  }
  ```
</TypeScriptExample>

### backoff를 가진 Retry

<TypeScriptExample>
  ```ts
  import { AgentWorkflow } from "agents/workflows";
  import type { AgentWorkflowEvent, AgentWorkflowStep } from "agents/workflows";

  export class ResilientWorkflow extends AgentWorkflow<MyAgent, TaskParams> {
  	async run(event: AgentWorkflowEvent<TaskParams>, step: AgentWorkflowStep) {
  		const result = await step.do(
  			"call-api",
  			{
  				retries: { limit: 5, delay: "10 seconds", backoff: "exponential" },
  				timeout: "5 minutes",
  			},
  			async () => {
  				const response = await fetch("https://api.example.com/process", {
  					method: "POST",
  					body: JSON.stringify(event.payload),
  				});
  				if (!response.ok) throw new Error(`API error: ${response.status}`);
  				return response.json();
  			},
  		);

  		await step.reportComplete(result);
  		return result;
  	}
  }
  ```
</TypeScriptExample>

### 국가 동기화

Workflows는 Agent state를 크게 업데이트할 수 있습니다.`step`, 모든 연결된 클라이언트에 자동으로 방송:

<TypeScriptExample>
  ```ts
  import { AgentWorkflow } from "agents/workflows";
  import type { AgentWorkflowEvent, AgentWorkflowStep } from "agents/workflows";

  export class StatefulWorkflow extends AgentWorkflow<MyAgent, TaskParams> {
  	async run(event: AgentWorkflowEvent<TaskParams>, step: AgentWorkflowStep) {
  		//전체 국가를 대체 (durable, 클라이언트에 방송)
  		await step.updateAgentState({
  			currentTask: {
  				id: event.payload.taskId,
  				status: "processing",
  				startedAt: Date.now(),
  			},
  		});

  		const result = await step.do("process", async () =>
  			processTask(event.payload),
  		);

  		//Merge 부분 상태 (durable, 기존 필드 유지)
  		await step.mergeAgentState({
  			currentTask: { status: "complete", result, completedAt: Date.now() },
  		});

  		await step.reportComplete(result);
  		return result;
  	}
  }
  ```
</TypeScriptExample>

### 주문 진행 유형

도메인 별보고에 대한 사용자 정의 진행 유형 정의 :

<TypeScriptExample>
  ```ts
  import { AgentWorkflow } from "agents/workflows";
  import type { AgentWorkflowEvent, AgentWorkflowStep } from "agents/workflows";

  //데이터 파이프라인에 대한 사용자 정의 진행 유형
  type PipelineProgress = {
  	stage: "extract" | "transform" | "load";
  	recordsProcessed: number;
  	totalRecords: number;
  	currentTable?: string;
  };

  //사용자 정의 진행 유형 (3rd 유형 매개 변수)
  export class ETLWorkflow extends AgentWorkflow<
  	MyAgent,
  	ETLParams,
  	PipelineProgress
  > {
  	async run(event: AgentWorkflowEvent<ETLParams>, step: AgentWorkflowStep) {
  		await this.reportProgress({
  			stage: "extract",
  			recordsProcessed: 0,
  			totalRecords: 1000,
  			currentTable: "users",
  		});

  		//... 처리
  	}
  }

  //에이전트는 typed 진행을받습니다.
  class MyAgent extends Agent {
  	async onWorkflowProgress(
  		workflowName: string,
  		instanceId: string,
  		progress: unknown,
  	) {
  		const p = progress as PipelineProgress;
  		console.log(`Stage: ${p.stage}, ${p.recordsProcessed}/${p.totalRecords}`);
  	}
  }
  ```
</TypeScriptExample>

### Cleanup 전략

내부의`cf_agents_workflows`테이블은 언바운드를 성장할 수 있으므로 보존 정책을 구현하십시오.

<TypeScriptExample>
  ```ts
  class MyAgent extends Agent {
  	//선택권 1: 완료에 삭제
  	async onWorkflowComplete(
  		workflowName: string,
  		instanceId: string,
  		result?: unknown,
  	) {
  		//프로세스 결과 첫째, 다음 삭제
  		this.deleteWorkflow(instanceId);
  	}

  	//선택권 2: 계획된 정리 (최근 역사)
  	async cleanupOldWorkflows() {
  		this.deleteWorkflows({
  			status: ["complete", "errored"],
  			createdBefore: new Date(Date.now() - 7 * 24 * 60 * 60 * 1000),
  		});
  	}

  	//선택권 3: 수락/auditing를 위한 모든 역사 유지
  	//deleteWorkflows()를 호출하지 마십시오. - 필요에 따라 과거 데이터 쿼리
  }
  ```
</TypeScriptExample>

## 양방향 통신

### 작업 흐름 에 Agent

<TypeScriptExample>
  ```ts
  //직접 RPC 통화 (타입)
  await this.agent.updateTaskStatus(taskId, "processing");
  const data = await this.agent.getData(taskId);

  //Non-durable callbacks (재고에 대한 무적 반복, 빈번한 업데이트 사용)
  await this.reportProgress({ step: "process", percent: 0.5 });
  this.broadcastToClients({ type: "update", data });

  //단계 (idempotent를 통해 튼튼한 콜백은, retry에 반복하지 않습니다)
  await step.reportComplete(result);
  await step.reportError("Something went wrong");
  await step.sendEvent({ type: "custom", data: {} });

  //단계 (고객에게 broadcasts)를 통해 튼튼한 국가 동기화
  await step.updateAgentState({ status: "processing" });
  await step.mergeAgentState({ progress: 0.5 });
  ```
</TypeScriptExample>

## 좋은 관행

1. **작업 흐름 유지**— 논리 작업 당 하나의 워크플로
2. **의미있는 단계 이름**- 디버깅 및 관찰성에 대한 도움말
3. **자주 묻는 질문**— 사용자가 알 수 있도록
4. **처리 오류가 완전히**— 사용`reportError()`시작하기
5. **완료된 워크플로우 청소**— 추적 테이블에 대한 보존 정책을 구현
6. **처리 작업 흐름 바인딩 이름**— 사용`migrateWorkflowBinding()`작업 흐름을 renaming 할 때`wrangler.jsonc`

## 제한 사항

| 옵션 정보     | 지원하다                            |
| --------- | ------------------------------- |
| 최대 단계     | 작업 흐름당 10,000 / 구성 가능 최대 25,000 |
| 국가 크기     | 작업 흐름 당 10MB                    |
| 이벤트 대기 시간 | 최대 1 년                          |
| 단계 실행 시간  | 단계 당 30 분                       |

Workflows는 WebSocket 연결을 직접 열 수 없습니다. 제품 정보`broadcastToClients()`에이전트를 통해 연결된 클라이언트와 통신합니다.
