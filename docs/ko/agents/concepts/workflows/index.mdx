## Workflows란 무엇인가요?

[Cloudflare Workflows](/workflows/)는 실패를 견디고, 자동 재시도하고, 외부 이벤트를 기다려야 하는 작업을 위해 durable한 multi-step execution을 제공합니다. Agents와 통합하면, Workflows는 장기 실행되는 백그라운드 처리를 담당하고 Agents는 실시간 커뮤니케이션을 담당합니다.

### Agents vs. Workflows

Agents와 Workflows는 서로 보완적인 강점을 가집니다.

| Capability              | Agents                     | Workflows                      |
| ----------------------- | -------------------------- | ------------------------------ |
| Execution model         | Can run indefinitely       | Run to completion              |
| Real-time communication | WebSockets, HTTP streaming | Not supported                  |
| State persistence       | Built-in SQL database      | Step-level persistence         |
| Failure handling        | Application-defined        | Automatic retries and recovery |
| External events         | Direct handling            | Pause and wait for events      |
| User interaction        | Direct (chat, UI)          | Through Agent callbacks        |

Agents는 반복하고, 분기하고, 사용자와 직접 상호작용할 수 있습니다. Workflows는 단계별로 순차 실행되며, 전달이 보장되고, 승인이나 외부 데이터를 기다리며 며칠간 일시 중지할 수도 있습니다.

### 각각 언제 사용할까

**Agents만 사용할 때:**

- 채팅 및 메시징 애플리케이션
- 빠른 API 호출과 응답
- 실시간 협업 기능
- 30초 이하 작업

**Agents와 Workflows를 함께 사용할 때:**

- 데이터 처리 파이프라인
- 보고서 생성
- human-in-the-loop 승인 흐름
- 전달 보장이 필요한 작업
- 재시도 요구사항이 있는 multi-step operations

**Workflows만 사용할 때:**

- 사용자 승인 유무와 관계없는 백그라운드 작업
- 예약된 데이터 동기화
- 이벤트 기반 처리 파이프라인

## Agents와 Workflows는 어떻게 통신하나요?

`agents/workflows`에서 가져오는 `AgentWorkflow` 클래스는 Workflows와 그것을 시작한 Agent 사이의 양방향 통신을 제공합니다.

### Workflow to Agent

Workflows는 여러 방법으로 Agents와 통신할 수 있습니다.

- **RPC calls**: `this.agent`를 통해 완전한 타입 안정성으로 Agent 메서드를 직접 호출
- **Progress reporting**: `this.reportProgress()`로 진행 상황을 보내고 Agent callbacks를 트리거
- **State updates**: `step.updateAgentState()` 또는 `step.mergeAgentState()`로 Agent state를 수정하고 연결된 클라이언트에 브로드캐스트
- **Client broadcasts**: `this.broadcastToClients()`로 모든 WebSocket clients에 메시지 전송

<TypeScriptExample>

```ts
// Inside a workflow's run() method
await this.agent.updateTaskStatus(taskId, "processing"); // RPC call
await this.reportProgress({ step: "process", percent: 0.5 }); // Progress (non-durable)
this.broadcastToClients({ type: "update", taskId }); // Broadcast (non-durable)
await step.mergeAgentState({ taskProgress: 0.5 }); // State update (durable)
```

</TypeScriptExample>

### Agent to Workflow

Agents는 실행 중인 Workflows와 다음 방식으로 상호작용할 수 있습니다.

- **Starting workflows**: `runWorkflow()`로 새 workflow instances 시작
- **Sending events**: `sendWorkflowEvent()`로 이벤트 전송
- **Approval/rejection**: `approveWorkflow()` / `rejectWorkflow()`로 승인 요청 응답
- **Workflow control**: pause, resume, terminate, restart
- **Status queries**: `getWorkflow()` / `getWorkflows()`로 workflow 진행 상태 조회

## Durable vs. non-durable operations

workflow를 효과적으로 사용하려면 durability를 이해하는 것이 중요합니다.

### Non-durable (재시도 시 반복될 수 있음)

이 동작들은 가볍고 자주 업데이트하기에 적합하지만, workflow가 재시도되면 여러 번 실행될 수 있습니다.

- `this.reportProgress()` — 진행 상황 보고
- `this.broadcastToClients()` — WebSocket 브로드캐스트
- `this.agent`에 대한 직접 RPC 호출

### Durable (idempotent, 반복되지 않음)

이 동작들은 `step` 파라미터를 사용하며 정확히 한 번 실행됩니다.

- `step.do()` — durable step 실행
- `step.reportComplete()` / `step.reportError()` — 완료 보고
- `step.sendEvent()` — 사용자 지정 이벤트
- `step.updateAgentState()` / `step.mergeAgentState()` — 상태 동기화

## Durability guarantees

Workflows는 step 기반 실행을 통해 durability를 제공합니다.

1. **Step completion is permanent** — 한 step이 완료되면 workflow가 재시작되어도 다시 실행되지 않습니다
2. **Automatic retries** — 실패한 step은 설정 가능한 backoff로 재시도됩니다
3. **Event persistence** — Workflows는 최대 1년까지 이벤트를 기다릴 수 있습니다
4. **State recovery** — workflow 상태는 인프라 장애 이후에도 유지됩니다

이 durability 모델 덕분에 Workflows는 다단계 데이터 처리나 여러 시스템에 걸친 트랜잭션처럼 부분 완료 상태를 반드시 보존해야 하는 작업에 적합합니다.

## Workflow tracking

Agent가 `runWorkflow()`를 사용해 workflow를 시작하면, 해당 workflow는 자동으로 Agent의 내부 database에 추적됩니다. 이를 통해 다음이 가능해집니다.

- cursor 기반 pagination과 함께 ID, 이름, metadata로 workflow 상태 조회
- lifecycle callbacks(`onWorkflowProgress`, `onWorkflowComplete`, `onWorkflowError`)를 통한 진행 상황 모니터링
- workflow 제어: pause, resume, terminate, restart
- `deleteWorkflow()` / `deleteWorkflows()`로 완료된 workflow 기록 정리
- metadata를 통해 workflow를 사용자나 세션과 연결

## 일반적인 패턴

### 진행 상황이 있는 백그라운드 처리

Agent가 요청을 받고, 무거운 처리를 위해 Workflow를 시작한 뒤, Workflow가 각 step을 실행할 때 연결된 클라이언트에 진행 상황을 브로드캐스트합니다.

<TypeScriptExample>

```ts
// Workflow reports progress after each item
for (let i = 0; i < items.length; i++) {
	await step.do(`process-${i}`, async () => processItem(items[i]));
	await this.reportProgress({
		step: `process-${i}`,
		percent: (i + 1) / items.length,
		message: `Processed ${i + 1}/${items.length}`,
	});
}
```

</TypeScriptExample>

### Human-in-the-loop approval

Workflow가 요청을 준비한 뒤 `waitForApproval()`로 승인을 기다리며 멈추고, Agent는 `approveWorkflow()` / `rejectWorkflow()`를 통해 사용자가 승인 또는 거절할 수 있는 UI를 제공합니다. Workflow는 결정에 따라 재개되거나 `WorkflowRejectedError`를 던집니다.

### 복원력 있는 외부 API 호출

Workflow는 재시도 로직이 포함된 durable steps 안에서 외부 API 호출을 감쌉니다. API가 실패하거나 workflow가 재시작되더라도 완료된 호출은 반복되지 않고, 실패한 호출은 자동으로 재시도됩니다.

<TypeScriptExample>

```ts
const result = await step.do(
	"call-api",
	{
		retries: { limit: 5, delay: "10 seconds", backoff: "exponential" },
		timeout: "5 minutes",
	},
	async () => {
		const response = await fetch("https://api.example.com/process");
		if (!response.ok) throw new Error(`API error: ${response.status}`);
		return response.json();
	},
);
```

</TypeScriptExample>

### 상태 동기화

Workflow는 중요한 시점마다 `step.updateAgentState()` 또는 `step.mergeAgentState()`를 사용해 Agent state를 업데이트합니다. 이 상태 변화는 연결된 모든 클라이언트에 브로드캐스트되어, polling 없이도 UI가 동기화됩니다.
