Agents를 작성하고, 배포하고, 실행할 때 적용되는 한도는 아래와 같습니다.

많은 한도는 Workers scripts와 Durable Objects에 적용되는 한도를 그대로 상속하며, 자세한 내용은 [Workers limits](/workers/platform/limits/) 문서를 참고하세요.

| Feature                                     | Limit                                                                     |
| ------------------------------------------- | ------------------------------------------------------------------------- |
| Max concurrent (running) Agents per account | Tens of millions+ [^1]                                                    |
| Max definitions per account                 | ~250,000+ [^2]                                                            |
| Max state stored per unique Agent           | 1 GB                                                                      |
| Max compute time per Agent                  | 30 seconds (refreshed per HTTP request / incoming WebSocket message) [^3] |
| Duration (wall clock) per step [^3]         | Unlimited (for example, waiting on a database call or an LLM response)    |

---

[^1]: 네, 정말입니다. 각 Agent는 [고유한 Durable Object](/durable-objects/concepts/what-are-durable-objects/)(actor)에 매핑되므로, 동시에 수천만 개 이상의 Agents를 실행할 수 있습니다.

[^2]: account당 [최대 500개 scripts](/workers/platform/limits/)를 배포할 수 있지만, 각 script(프로젝트)는 여러 Agents를 정의할 수 있습니다. 배포된 각 script는 [Workers Paid Plan](/workers/platform/pricing/#workers)에서 최대 10 MB까지 가능합니다.

[^3]: Agent당 compute(CPU) time은 30초로 제한되지만, Agent가 새 HTTP 요청을 받거나, [scheduled task](/agents/api-reference/schedule-tasks/)를 실행하거나, 새로운 WebSocket 메시지를 받을 때마다 이 시간이 새로 갱신됩니다.
