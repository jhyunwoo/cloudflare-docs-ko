Cloudflare에서 [Model Context Protocol (MCP)](https://modelcontextprotocol.io/) 서버를 빌드하고 배포할 수 있습니다.

## Model Context Protocol (MCP)이란?

[Model Context Protocol (MCP)](https://modelcontextprotocol.io)는 AI 시스템을 외부 애플리케이션과 연결하는 개방형 표준입니다. MCP를 AI 애플리케이션을 위한 USB-C 포트라고 생각해 보세요. USB-C가 다양한 액세서리에 기기를 연결하는 표준화된 방법을 제공하듯, MCP는 AI agents를 다양한 서비스에 연결하는 표준화된 방법을 제공합니다.

### MCP 용어

- **MCP Hosts**: 외부 기능에 접근해야 하는 AI assistants([Claude](https://claude.ai), [Cursor](https://cursor.com) 등), AI agents, 또는 애플리케이션
- **MCP Clients**: MCP hosts 안에 내장되어 MCP servers에 연결하고 도구를 호출하는 clients. 각 MCP client instance는 하나의 MCP server와 단일 연결을 가집니다.
- **MCP Servers**: MCP clients가 사용할 수 있는 [tools](/agents/model-context-protocol/tools/), [prompts](https://modelcontextprotocol.io/docs/concepts/prompts), [resources](https://modelcontextprotocol.io/docs/concepts/resources)를 노출하는 애플리케이션

### Remote vs. local MCP connections

MCP 표준은 두 가지 동작 모드를 지원합니다.

- **Remote MCP connections**: MCP clients는 인터넷을 통해 MCP servers에 연결하며, [Streamable HTTP](/agents/model-context-protocol/transport/)로 연결을 수립하고 [OAuth](/agents/model-context-protocol/authorization/)를 사용해 사용자의 account 리소스에 대한 접근 권한을 MCP client에 부여합니다.
- **Local MCP connections**: MCP clients는 같은 머신에서 [stdio](https://spec.modelcontextprotocol.io/specification/draft/basic/transports/#stdio)를 로컬 transport 방법으로 사용해 MCP servers에 연결합니다.

### 모범 사례

- **Tool design**: MCP server를 전체 API schema의 래퍼처럼 취급하지 마세요. 대신 특정 사용자 목표와 신뢰할 수 있는 결과에 최적화된 tools를 만드세요. 특히 context window가 작거나 latency budget이 빡빡한 agents에게는, 잘 설계된 적은 수의 tools가 지나치게 세분화된 많은 tools보다 더 좋은 성능을 냅니다.
- **Scoped permissions**: 권한 범위가 좁은 집중형 MCP servers를 여러 개 배포하면 과도한 권한 부여 위험을 줄이고, 각 server가 무엇을 할 수 있는지 관리하고 감사하기 쉬워집니다.
- **Tool descriptions**: 자세한 parameter descriptions는 agents가 도구를 올바르게 사용하는 데 도움이 됩니다. 어떤 값이 기대되는지, 동작에 어떤 영향을 주는지, 어떤 제약이 있는지를 설명하면 오류를 줄이고 신뢰성을 높일 수 있습니다.
- **Evaluation tests**: 평가 테스트(evals)를 사용해 agent가 도구를 올바르게 사용하는 능력을 측정하세요. server나 tool descriptions를 업데이트한 뒤에는 반드시 다시 실행해 회귀를 조기에 잡고 개선을 추적하세요.
