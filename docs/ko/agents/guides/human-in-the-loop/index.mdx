Human-in-the-loop (HITL) 패턴은 일시 중지 실행을 허용하고 진행하기 전에 인간의 승인, 확인 또는 입력을 기다립니다. 에이전트 시스템의 준수, 안전 및 oversight에 필수적입니다.

## 왜 인간에서 루프?

- **견적 요청**: 규제 요건은 특정 행동에 대한 인적 승인
- **제품정보**: High-stakes 운영 (지불, 삭제, 외부 통신)은 oversight가 필요합니다.
- **품질 관리**: Human review catches 오류 AI가 놓칠 수 있음
- **지원하다**: 사용자가 중요한 작업을 수행 할 때 더 자신감이 느껴집니다.

### 일반적인 사용 사례

| 사용 사례    | 이름 \*              |
| -------- | ------------------ |
| 금융 승인    | Expense 보고서, 결제 처리 |
| 관련 상품    | 출판, 이메일 발송         |
| 데이터 작업   | 대량 deletions, 수출   |
| AI 도구 실행 | 실행하기 전에 도구 호출 확인   |
| 오시는 길    | 권한 부여, 역할 변경       |

## 패턴 선택

Cloudflare는 인간의 반복에 대한 두 가지 주요 패턴을 제공합니다:

| 제품 정보           | 제품 정보               | 키 API               |
| --------------- | ------------------- | ------------------- |
| **Workflow 승인** | 다단계 과정, 튼튼한 승인 문    | `waitForApproval()` |
| **MCP 분석**      | MCP 서버 요청 구조 사용자 입력 | `elicitInput()`     |

결정 가이드:

- 제품 정보**Workflow 승인**시간, 일, 또는 주를 기다릴 수 있는 승인 문을 가진 튼튼한, 다단계 과정이 필요할 때
- 제품 정보**MCP 분석**MCP 서버를 구축 할 때 도구 실행 중에 사용자에서 추가 구조 입력을 요청해야

## Workflow 기반 승인

내구성, 다단계 프로세스를 위해, 사용[Cloudflare작업 흐름](/workflows/)이름 \*`waitForApproval()`방법. 작업 흐름은 인간적인 승인 또는 거부 될 때까지 일시 중지합니다.

### 기본 패턴

<TypeScriptExample>
  ```ts
  import { Agent } from "agents";
  import { AgentWorkflow } from "agents/workflows";
  import type { AgentWorkflowEvent, AgentWorkflowStep } from "agents/workflows";

  type ExpenseParams = {
  	amount: number;
  	description: string;
  	requestedBy: string;
  };

  export class ExpenseWorkflow extends AgentWorkflow<
  	ExpenseAgent,
  	ExpenseParams
  > {
  	async run(event: AgentWorkflowEvent<ExpenseParams>, step: AgentWorkflowStep) {
  		const expense = event.payload;

  		//1 단계 : 비용 검증
  		const validated = await step.do("validate", async () => {
  			if (expense.amount <= 0) {
  				throw new Error("Invalid expense amount");
  			}
  			return { ...expense, validatedAt: Date.now() };
  		});

  		//2 단계 : 우리가 승인을 기다리고있는 보고서
  		await this.reportProgress({
  			step: "approval",
  			status: "pending",
  			message: `Awaiting approval for $${expense.amount}`,
  		});

  		//단계 3: 인간 승인 대기 (작업 흐름을 일시 중지)
  		const approval = await this.waitForApproval<{ approvedBy: string }>(step, {
  			timeout: "7 days",
  		});

  		console.log(`Approved by: ${approval?.approvedBy}`);

  		//4 단계 : 승인 된 비용 처리
  		const result = await step.do("process", async () => {
  			return { expenseId: crypto.randomUUID(), ...validated };
  		});

  		await step.reportComplete(result);
  		return result;
  	}
  }
  ```
</TypeScriptExample>

### 승인 방법

에이전트는 approve 또는 reject 대기 흐름을 제공:

<TypeScriptExample>
  ```ts
  import { Agent, callable } from "agents";

  type PendingApproval = {
  	workflowId: string;
  	amount: number;
  	description: string;
  	requestedBy: string;
  	requestedAt: number;
  };

  type ExpenseState = {
  	pendingApprovals: PendingApproval[];
  };

  export class ExpenseAgent extends Agent<Env, ExpenseState> {
  	initialState: ExpenseState = {
  		pendingApprovals: [],
  	};

  	//대기 흐름을 Approve
  	@callable()
  	async approve(workflowId: string, approvedBy: string): Promise<void> {
  		await this.approveWorkflow(workflowId, {
  			reason: "Expense approved",
  			metadata: { approvedBy, approvedAt: Date.now() },
  		});

  		//업데이트 상태는 승인을 반영
  		this.setState({
  			...this.state,
  			pendingApprovals: this.state.pendingApprovals.filter(
  				(p) => p.workflowId !== workflowId,
  			),
  		});
  	}

  	//대기 흐름을 거부
  	@callable()
  	async reject(workflowId: string, reason: string): Promise<void> {
  		await this.rejectWorkflow(workflowId, { reason });

  		this.setState({
  			...this.state,
  			pendingApprovals: this.state.pendingApprovals.filter(
  				(p) => p.workflowId !== workflowId,
  			),
  		});
  	}

  	//워크플로우 진행을 추적하여 pending 승인을 업데이트합니다.
  	async onWorkflowProgress(
  		workflowName: string,
  		workflowId: string,
  		progress: unknown,
  	): Promise<void> {
  		const p = progress as { step: string; status: string; message?: string };

  		if (p.step === "approval" && p.status === "pending") {
  			//UI 디스플레이에 대한 승인 목록 추가
  			this.setState({
  				...this.state,
  				pendingApprovals: [
  					...this.state.pendingApprovals,
  					{
  						workflowId,
  						amount: 0, //패러다임웍스
  						description: p.message || "",
  						requestedBy: "user",
  						requestedAt: Date.now(),
  					},
  				],
  			});
  		}
  	}
  }
  ```
</TypeScriptExample>

### Timeout 처리

timeouts를 설정하여 워크플로우를 대기 중시적으로 방지합니다.

<TypeScriptExample>
  ```ts
  const approval = await this.waitForApproval<{ approvedBy: string }>(step, {
  	timeout: "7 days", //또한 지원: "1 시간", "30 분", 등.
  });

  if (!approval) {
  	//Timeout 만료 - 에스칼레이트 또는 자동 거부
  	await step.reportError("Approval timeout - escalating to manager");
  	throw new Error("Approval timeout");
  }
  ```
</TypeScriptExample>

### 스케줄링과 확장

제품 정보`schedule()`에스컬레이션 알림 설정:

<TypeScriptExample>
  ```ts
  import { Agent, callable } from "agents";

  class ExpenseAgent extends Agent<Env, ExpenseState> {
  	@callable()
  	async submitForApproval(expense: ExpenseParams): Promise<string> {
  		//승인 워크플로우 시작
  		const workflowId = await this.runWorkflow("EXPENSE_WORKFLOW", expense);

  		//4 시간 후에 일정 알림
  		await this.schedule(Date.now() + 4 * 60 * 60 * 1000, "sendReminder", {
  			workflowId,
  		});

  		//24 시간 후에 일정 에스컬레이션
  		await this.schedule(Date.now() + 24 * 60 * 60 * 1000, "escalateApproval", {
  			workflowId,
  		});

  		return workflowId;
  	}

  	async sendReminder(payload: { workflowId: string }) {
  		const workflow = this.getWorkflow(payload.workflowId);
  		if (workflow?.status === "waiting") {
  			//알림 설정
  			console.log("Reminder: approval still pending");
  		}
  	}

  	async escalateApproval(payload: { workflowId: string }) {
  		const workflow = this.getWorkflow(payload.workflowId);
  		if (workflow?.status === "waiting") {
  			//관리자에게 확장
  			console.log("Escalating to manager");
  		}
  	}
  }
  ```
</TypeScriptExample>

### SQL을 가진 감사 길

제품 정보`this.sql`immutable 감사 흔적을 유지하기 위해:

<TypeScriptExample>
  ```ts
  import { Agent, callable } from "agents";

  class ExpenseAgent extends Agent<Env, ExpenseState> {
  	async onStart() {
  		//감사 표
  		this.sql`
        CREATE TABLE IF NOT EXISTS approval_audit (
          id INTEGER PRIMARY KEY AUTOINCREMENT,
          workflow_id TEXT NOT NULL,
          decision TEXT NOT NULL CHECK(decision IN ('approved', 'rejected')),
          decided_by TEXT NOT NULL,
          decided_at INTEGER NOT NULL,
          reason TEXT
        )
      `;
  	}

  	@callable()
  	async approve(
  		workflowId: string,
  		userId: string,
  		reason?: string,
  	): Promise<void> {
  		//SQL에 대한 결정을 기록 (immutable Audit log)
  		this.sql`
        INSERT INTO approval_audit (workflow_id, decision, decided_by, decided_at, reason)
        VALUES (${workflowId}, 'approved', ${userId}, ${Date.now()}, ${reason || null})
      `;

  		//승인 방법
  		await this.approveWorkflow(workflowId, {
  			reason: reason || "Approved",
  			metadata: { approvedBy: userId },
  		});
  	}
  }
  ```
</TypeScriptExample>

## MCP 분석

MCP 서버 구축`McpAgent`, 도구 실행 중에 추가 사용자 입력을 요청할 수 있습니다.**한국어**. MCP 클라이언트는 JSON Schema를 기반으로 한 양식을 렌더링하고 사용자의 응답을 반환합니다.

### 기본 패턴

<TypeScriptExample>
  ```ts
  import { McpAgent } from "agents/mcp";
  import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
  import { z } from "zod";

  type State = { counter: number };

  export class CounterMCP extends McpAgent<Env, State, {}> {
  	server = new McpServer({
  		name: "counter-server",
  		version: "1.0.0",
  	});

  	initialState: State = { counter: 0 };

  	async init() {
  		this.server.tool(
  			"increase-counter",
  			"Increase the counter by a user-specified amount",
  			{ confirm: z.boolean().describe("Do you want to increase the counter?") },
  			async ({ confirm }, extra) => {
  				if (!confirm) {
  					return { content: [{ type: "text", text: "Cancelled." }] };
  				}

  				//사용자에서 추가 입력 요청
  				const userInput = await this.server.server.elicitInput(
  					{
  						message: "By how much do you want to increase the counter?",
  						requestedSchema: {
  							type: "object",
  							properties: {
  								amount: {
  									type: "number",
  									title: "Amount",
  									description: "The amount to increase the counter by",
  								},
  							},
  							required: ["amount"],
  						},
  					},
  					{ relatedRequestId: extra.requestId },
  				);

  				//자주 묻는 질문
  				if (userInput.action !== "accept" || !userInput.content) {
  					return { content: [{ type: "text", text: "Cancelled." }] };
  				}

  				//입력을 사용하십시오
  				const amount = Number(userInput.content.amount);
  				this.setState({
  					...this.state,
  					counter: this.state.counter + amount,
  				});

  				return {
  					content: [
  						{
  							type: "text",
  							text: `Counter increased by ${amount}, now at ${this.state.counter}`,
  						},
  					],
  				};
  			},
  		);
  	}
  }
  ```
</TypeScriptExample>

## Elicitation vs 워크플로우 승인

| 이름 \*     | MCP 교육            | Workflow 승인           |
| --------- | ----------------- | --------------------- |
| **사이트맵**  | MCP 서버 도구 실행      | Multi-step 워크플로우 프로세스 |
| **이름 \*** | Immediate (도구 호출) | 시간/일/주를 기다릴 수 있습니다    |
| **기본 정보** | JSON Schema 기반 양식 | 주문 UI를 통해 에이전트 상태     |
| **주요 특징** | MCP 세션 상태         | 튼튼한 작업 흐름 상태          |
| **사용 사례** | 도구 중 대화 형 입력      | 파이프라인의 승인 문           |

## Multi-approver 패턴

여러 approvers를 필요로 하는 과민한 가동을 위해:

<TypeScriptExample>
  ```ts
  import { Agent, callable } from "agents";

  type MultiApproval = {
  	workflowId: string;
  	requiredApprovals: number;
  	currentApprovals: Array<{ userId: string; approvedAt: number }>;
  	rejections: Array<{ userId: string; rejectedAt: number; reason: string }>;
  };

  type State = {
  	pendingMultiApprovals: MultiApproval[];
  };

  class MultiApprovalAgent extends Agent<Env, State> {
  	@callable()
  	async approveMulti(workflowId: string, userId: string): Promise<boolean> {
  		const approval = this.state.pendingMultiApprovals.find(
  			(p) => p.workflowId === workflowId,
  		);
  		if (!approval) throw new Error("Approval not found");

  		//사용자가 이미 승인되면 확인
  		if (approval.currentApprovals.some((a) => a.userId === userId)) {
  			throw new Error("Already approved by this user");
  		}

  		//이 사용자의 승인 추가
  		approval.currentApprovals.push({ userId, approvedAt: Date.now() });

  		//우리는 충분한 승인을 가지고 있는지 확인
  		if (approval.currentApprovals.length >= approval.requiredApprovals) {
  			//승인 된 작업을 실행
  			await this.approveWorkflow(workflowId, {
  				metadata: { approvers: approval.currentApprovals },
  			});
  			return true;
  		}

  		this.setState({ ...this.state });
  		return false; //아직 더 많은 승인을 기다리고 있습니다.
  	}
  }
  ```
</TypeScriptExample>

## 좋은 관행

1. **명확한 승인 기준 정의**— 의미있는 결과와 행동에 대한 확인 필요 (지불, 이메일, 데이터 변경)
2. **자세히 알아보기**- 모든 인수를 포함한 모든 작업을 정확히 표시하십시오.
3. **Timeouts 구현**— 사용`schedule()`적당한 기간 후에 escalate 또는 자동 거절
4. **감사의 길 유지**— 사용`this.sql`준수에 대한 모든 승인 결정을 기록하기
5. **핸들 연결 방울**- 에이전트 상태의 종료 승인 저장 그래서 그들은 단선을 생존
6. **화려한 degradation**- 승인이 거부되면 fallback 동작 제공
