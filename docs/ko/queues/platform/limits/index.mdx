다음 제한은 Workers 유료 및 WorkersXQ 예외로 무료 계획**메시지 Retention**Workers 무료 플랜을 위한 24 시간에 비 구성이 가능한 .
주요 특징

| 제품 정보                                            | 지원하다                                                                                |
| ------------------------------------------------ | ----------------------------------------------------------------------------------- |
| Queues                                           | 계정 당 10,000                                                                         |
| 이름 \*                                            | 전화 번호: +86 592 512 9455<sup>1</sup>                                                 |
| 이름 \*                                            | 100                                                                                 |
| 최대 소비자 배치 크기                                     | 100 메시지                                                                             |
| 최대 메시지`sendBatch`이름 \*                           | 100 (총 256KB)                                                                       |
| 지원하다 Batch 대기 시간                                 | 60 초                                                                                |
| Per-queue 메시지 처리량                                | 초당 5,000 메시지<sup>2</sup>                                                            |
| 공지사항<sup>3</sup>                                 | [최대 14일 구성 가능](/queues/configuration/configure-queues/#queue-configuration).        |
| Perqueue backlog 크기<sup>4</sup>                  | 25GB 이상                                                                             |
| Concurrent 소비자 봉사                                | 250 <sup>푸시 기반 전용</sup>                                                             |
| 소비자 기간 (벽 시계 시간)                                 | 15 분<sup>5</sup>                                                                    |
| [소비자 CPU 시간](/workers/platform/limits/#cpu-time) | [5 분으로 구성 가능](/queues/platform/limits/#increasing-queue-consumer-worker-cpu-limits) |
| `visibilityTimeout`(pull 기반 큐)                   | 12시간                                                                                |
| `delaySeconds`(송신 또는 재발송시)                       | 24시간                                                                                |

<sup>1</sup>1 KB는 1000 바이트로 측정됩니다. 메시지는 최대 \~100 바이트의 내부 메타데이터를 포함할 수 있습니다.

<sup>2</sup>최대 메시지 처리량을 초과하면`send()`·`sendBatch()`예외를 던지는 방법`Too Many Requests`생산자가 한계의 밑에 떨어질 때까지 오류.

<sup>3</sup>최대 메시지 유지에 도달하는 큐의 메시지는 큐에서 삭제됩니다. Queues는 이 한계에 도달하지 않은 동일한 큐에 메시지 삭제하지 않습니다.

<sup>4</sup>이 한계에 도달하는 개인 큐는 받게됩니다`Storage Limit Exceeded`호출시 오류`send()`또는`sendBatch()`큐에.

<sup>5</sup>더 알아보기[Workers 제한](/workers/platform/limits/#cpu-time).

### Queue 소비자 노동자 CPU 한계 증가

[큐 소비자 Workers](/queues/reference/how-queues-works/#consumers)Worker 스크립트이며, 동일하게 공유합니다.[CPU 제한 당](/workers/platform/limits/#worker-limits)어떤 Workers로. CPU 시간이 활동적인 처리 시간이라고 주의하십시오: 네트워크 요구, 저장 통화, 또는 다른 일반적인 I/O에 기다리지 않는 시간.

기본적으로 소비자 노동자 인 직업 당 최대 CPU 시간은 30 초에 놓이고, 그러나 조정해서 증가될 수 있습니다`limits.cpu_ms`Wrangler 윤곽에서:

<WranglerConfig>
  ```jsonc
  {
    //당신의 윤곽의 ...rest...
    "limits": {
      "cpu_ms": 300000, //300,000 밀리 초 = 5 분
    },
    //당신의 윤곽의 ...rest...
  }
  ```
</WranglerConfig>

CPU 시간과 한계에 대해 자세히 알아 보려면,[Workers 문서 검토](/workers/platform/limits/#cpu-time).
