Cloudflare Queues는 통합됩니다[Cloudflare Workers](/workers). 메시지를 보내고 수신하려면 노동자를 사용해야합니다.

Queue에 메시지를 보낼 수있는 노동자는 프로듀서 노동자이며, Queue에서 메시지를받을 수있는 노동자는 소비자 노동자입니다. 같은 노동자가 생산자와 소비자가 될 수 있습니다.

앞으로는 HTTP 엔드포인트와 같은 다른 API를 지원하거나 메시지를 수신할 것으로 기대합니다. 버그 또는 요청 기능을 보고하려면[Cloudflare 커뮤니티 포럼](https://community.cloudflare.com/c/developers/workers/40). 의견을 주기 위하여, 갑니다[`#queues`](https://discord.cloudflare.com)Discord 채널.

## 회사 소개

이 API는 제작자 노동자가 Queue에 메시지를 보낼 수 있도록 허용합니다.

Queue에 단일 메시지 작성의 예 :

    interface Env {
      readonly MY_QUEUE: Queue;
    }

    export default {
      async fetch(req, env, ctx): Promise<Response> {
        await env.MY_QUEUE.send({
          url: req.url,
          method: req.method,
          headers: Object.fromEntries(req.headers),
        });
        return new Response("Sent!");
      },
    } satisfies ExportedHandler<Env>;
    ```

    from pyodide.ffi import to_js
    from workers import Response, WorkerEntrypoint

    class Default(WorkerEntrypoint):
        async def fetch(self, request):
            await self.env.MY_QUEUE.send(to_js({
                "url": request.url,
                "method": request.method,
                "headers": dict(request.headers),
            }))
            return Response("Sent!")
    ```

### `Queue`

제작자가 Queue에 메시지를 보낼 수있는 바인딩.

```ts
interface Queue<Body = unknown> {
  send(body: Body, options?: QueueSendOptions): Promise<void>;
  sendBatch(messages: Iterable<MessageSendRequest<Body>>, options?: QueueSendBatchOptions): Promise<void>;
}
```

- `send(bodyunknown, options?{ contentType?: QueuesContentType })` <Type text="Promise<void>" />

  - Queue에 메시지를 보냅니다. 몸은 지원되는 어떤 유형일 수 있습니다[구조화된 clone 알고리즘](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Structured_clone_algorithm#supported_types)그것의 크기로 긴, 128 KB 보다는 더 적은입니다.
  - 약속이 해결될 때, 메시지는 디스크에 기록될 수 있습니다.

- `sendBatch(messagesIterable<MessageSendRequest<unknown>>, options?QueueSendBatchOptions)` <Type text="Promise<void>" />

  - Queue에 메시지의 배치를 보냅니다. 제공된 각 항목[제품 정보](https://www.typescriptlang.org/docs/handbook/iterators-and-generators.html)지원해야 함[구조화된 clone 알고리즘](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Structured_clone_algorithm#supported_types). 배치는 각 128 KB에 한정된 품목이 128 KB로 제한되더라도, 배열의 총 크기는 256 KB를 초과할 수 없습니다.
  - 선택 사항`options`매개변수는 조정을 적용하기 위하여 사용될 수 있습니다 (와 같은`delaySeconds`) 배치에 있는 모든 메시지에. 이름 \*[QueueSendBatch옵션](#queuesendbatchoptions).
  - 약속이 해결되면 메시지가 디스크에 기록되도록 확인됩니다.

### `MessageSendRequest`

메시지 배치 전송에 사용되는 래퍼 유형.

```ts
interface MessageSendRequest<Body = unknown> {
  body: Body;
  contentType?: QueueContentType;
  delaySeconds?: number;
}
```

- <code>뚱 베어</code> <Type text="unknown" />

  - 메시지의 몸.
  - 몸은 지원되는 어떤 유형일 수 있습니다[구조화된 clone 알고리즘](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Structured_clone_algorithm#supported_types)그것의 크기로 긴, 128 KB 보다는 더 적은입니다.

- <code>내용 유형</code> <Type text="QueueContentType" />

  - 메시지의 명시적 내용 유형 그래서 제대로 미리보기 할 수 있습니다[dashboard의 메시지 목록](/queues/examples/list-messages-from-dash/)이름 \* 옵션 인수.
  - 이름 \*[Queues콘텐츠](#queuescontenttype)가능한 값.

- <code>지연Seconds</code> <Type text="number" />

  - 몇 초에서[메시지 지연](/queues/configuration/batching-retries/)소비자에게 전달되기 전에 큐 내에서.
  - 0 및 86400 (24 시간) 사이의 정수가 있어야합니다.

### `QueueSendOptions`

큐에 메시지를 보낼 때 적용되는 옵션 구성.

- <code>내용 유형</code> <Type text="QueuesContentType" />

  - 메시지의 명시적 내용 유형 그래서 제대로 미리보기 할 수 있습니다[dashboard의 메시지 목록](/queues/examples/list-messages-from-dash/)이름 \* 옵션 인수.
  - 현재,이 옵션은 내부 사용을 위한 것입니다. 미래에`contentType`명시적으로 문자 메시지를 직렬화하기 위해 대안 소비자 유형에 의해 사용되므로 원하는 유형에서 소비 될 수 있습니다.
  - 이름 \*[Queues콘텐츠](#queuescontenttype)가능한 값.

- <code>지연Seconds</code> <Type text="number" />

  - 몇 초에서[메시지 지연](/queues/configuration/batching-retries/)소비자에게 전달되기 전에 큐 내에서.
  - 0 및 86400 (24 시간) 사이의 정수가 있어야합니다. 이 값을 0으로 설정하면 queue 레벨에서 글로벌 (기본값) 지연이 있는 경우에도 지연되는 메시지를 명시적으로 방지합니다.

### `QueueSendBatchOptions`

큐에 메시지의 배치를 보낼 때 적용되는 옵션 구성.

- <code>지연Seconds</code> <Type text="number" />

  - 몇 초에서[지연 메시지](/queues/configuration/batching-retries/)소비자에게 전달되기 전에 큐 내에서.
  - 긍정적 인 정수이어야합니다.

### `QueuesContentType`

유효한 메시지 내용 유형을 포함하는 조합 유형.

```ts
//기본: json
type QueuesContentType = "text" | "bytes" | "json" | "v8";
```

- 제품 정보`"json"`JSON-serialized 할 수있는 JavaScript 객체를 보내려면. 이 내용 유형은 미리 볼 수 있습니다[Cloudflare dashboard](https://dash.cloudflare.com)·`json`content type은 기본값입니다.
- 제품 정보`"text"`제품정보`String`. 이 내용 유형은 미리 볼 수 있습니다[dashboard의 메시지 목록](/queues/examples/list-messages-from-dash/)이름 \*
- 제품 정보`"bytes"`제품정보`ArrayBuffer`. 이 내용 유형은 미리 볼 수 없습니다[Cloudflare dashboard](https://dash.cloudflare.com)Base64 인코딩으로 표시됩니다.
- 제품 정보`"v8"`JSON-serialized 할 수없는 JavaScript 객체를 보내려면 지원됩니다.[구조화된 clone](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Structured_clone_algorithm#supported_types)(예를 들어`Date`·`Map`). 이 콘텐츠 유형은 미리 볼 수 없습니다[Cloudflare dashboard](https://dash.cloudflare.com)Base64 인코딩으로 표시됩니다.

:::참조

Queues에 대한 기본 내용 유형 변경`json`(에서)`v8`) 어떤 Workers를 위한 잡아당기기 근거한 소비자와 겸용성을 개량하기 위하여[호환성 날짜](/workers/configuration/compatibility-flags/#queues-send-messages-in-json-format)후에`2024-03-18`.

:::

잘못된 콘텐츠 유형 또는 지정된 콘텐츠 유형이 메시지 내용의 유형과 일치하지 않는 경우, 전송 작업은 오류로 실패합니다.

## 제품정보

이 API는 소비자 근로자가 Queue에서 메시지를 소비하도록 허용합니다.

소비자 노동자를 정의하기 위해, 추가`queue()`노동자의 기본 수출에 기능. 이것은 Queue에서 메시지를 수신 할 수 있습니다.

기본적으로 배치의 모든 메시지는 다음과 같은 조건이 충족되기 때문에 곧 인정됩니다.

1. 더 보기`queue()`함수가 반환되었습니다.
2. 만약에`queue()`함수는 약속을 반환했습니다, 약속은 해결했습니다.
3. 모든 약속은`waitUntil()`해결되었습니다.

만약에`queue()`기능 던지기, 또는 약속은 그것 또는 약속의 무엇이든에 의해 반환합니다`waitUntil()`거절된, 그 후에 전체 배치는 실패로 간주되고 소비자의 재량 조정에 따라 retried.

:::참조

`waitUntil()`queue 핸들러가 완료된 후 해결된 작업 (로깅 또는 메트릭 호출과 같은)을 실행하는 유일한 지원 방법입니다. queue 핸들러가 완료하지 않을 때 해결되지 않은 약속은 실행 완료되지 않을 수 있습니다.

:::

더 보기`env`·`ctx`분야는[Workers 문서](/workers/reference/migrate-to-module-workers/).

또는 대안으로, queue 소비자는 (deprecated) 서비스 노동자 문법을 사용하여 쓸 수 있습니다:

```js
addEventListener('queue', (event) => {
	event.waitUntil(handleMessages(event));
});
```

서비스 노동자 syntax에서,`event`동일한 필드와 방법을 제공`MessageBatch`아래에 정의된 것과 같이, 더하여[`waitUntil()`](https://developer.mozilla.org/en-US/docs/Web/API/ExtendableEvent/waitUntil).

:::참조

메시지를 통해 iterates 할 수 있는 큐 핸들러에서 비동기 작업을 수행 할 때, 당신의 메시지를 통해 iterating의 비동기 버전을 사용합니다. 예를 들어,`for (const m of batch.messages)`또는`await Promise.all(batch.messages.map(work))`비동기 통화의 결과를 기다리고 있습니다.`batch.messages.forEach()`아니다.

:::

### `MessageBatch`

소비자 노동자에게 보내지는 메시지의 배치.

```ts
interface MessageBatch<Body = unknown> {
  readonly queue: string;
  readonly messages: readonly Message<Body>[];
  ackAll(): void;
  retryAll(options?: QueueRetryOptions): void;
}
```

- <code>이름 \*</code> <Type text="string" />

  - 이 배치에 속하는 Queue의 이름.

- <code>이름 \*</code> <Type text="Message[]" />

  - 일괄 처리에 메시지의 배열. 메시지의 주문은 가장 좋은 노력입니다 -- 그들이 출판 된 순서와 정확히 동일하게 보장하지. 보장된 FIFO 주문에 관심이 있다면, 제발[Queues 팀에 이메일을 보내십시오](mailto:queues@cloudflare.com).

- <code>모든()</code> <Type text="void" />

  - 모든 메시지를 성공적으로 전달하고, 당신의 여부에 관계없이`queue()`소비자 핸들러는 성공적으로 또는 아닙니다.

- <code>retryAll (옵션?: QueueRetryOptions)</code> <Type text="void" />

  - 다음 일괄 처리에 기여할 모든 메시지 표시.
  - 옵션 지원`options`객체.

### `Message`

소비자 노동자에게 보내는 메시지.

```ts
interface Message<Body = unknown> {
  readonly id: string;
  readonly timestamp: Date;
  readonly body: Body;
	readonly attempts: number;
  ack(): void;
  retry(options?: QueueRetryOptions): void;
}
```

- <code>이름 \*</code> <Type text="string" />

  - 메시지에 대한 독특한 시스템 생성 ID.

- <code>타임 스탬프</code> <Type text="Date" />

  - 메시지를 보낼 때 타임스탬프.

- <code>뚱 베어</code> <Type text="unknown" />

  - 메시지의 몸.
  - 몸은 지원되는 어떤 유형일 수 있습니다[구조화된 clone 알고리즘](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Structured_clone_algorithm#supported_types)그것의 크기로 긴, 128 KB 보다는 더 적은입니다.

- <code>다운로드</code> <Type text="number" />

  - 소비자의 수는이 메시지를 처리하려고했습니다. 1. 시작

- <code>태그()</code> <Type text="void" />

  - 메시지가 성공적으로 전달되고 있는지 여부에 관계없이`queue()`소비자 핸들러는 성공적으로 또는 아닙니다.

- <code>retry(옵션?: QueueRetryOptions)</code> <Type text="void" />

  - 다음 배치에서 재생되는 메시지를 표시합니다.
  - 옵션 지원`options`객체.

### `QueueRetryOptions`

메시지 또는 재try에 대한 메시지의 배치를 표시 할 때 옵션 구성.

```ts
interface QueueRetryOptions {
  delaySeconds?: number;
}
```

- <code>지연Seconds</code> <Type text="number" />

  - 몇 초에서[메시지 지연](/queues/configuration/batching-retries/)소비자에게 전달되기 전에 큐 내에서.
  - 긍정적 인 정수이어야합니다.
