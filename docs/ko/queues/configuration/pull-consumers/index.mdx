풀 기반 소비자는 Cloudflare QXQXQXQXWorkers 이외의 모든 환경 및 / 또는 프로그래밍 언어에서 HTTP를 통해 큐를 끌어낼 수 있습니다. 풀 기반 소비자는 메시지 소비 비율이 업스트림 인프라 또는 장기간 작업에 의해 제한 될 때 유용 할 수 있습니다.

## 푸시 또는 풀 소비자 사이에서 선택하는 방법

푸시 기반 소비자 또는 풀 기반 소비자를 구성하는 것은 queues를 사용하는 방법에 따라 달라집니다.

- **시작하기[푸시 기반 소비자](/queues/reference/how-queues-works/#consumers)get started에 가장 쉬운 방법이고 큐에서 소모합니다**. 푸시 기반 소비자는 Workers에서 실행되며 기본적으로 큐에 기록되어있는 것처럼 자동 스케일 업 및 소모 메시지입니다.
- QXQX0156XQQ QXWorkers, 그리고/또는 빠른 메시지가 소모되는지 주의깊게 통제할 필요가 있는 경우에 끌어 근거한 소비자를 이용하십시오. 해당 이용 후기에 달린 코멘트가 없습니다.

언제든지 큐에 새로운 소비자를 제거하고 첨부 할 수 있습니다. 요구 사항이 변경되면 풀 기반 소비자로 전환 할 수 있습니다.

:::note\[API Bearer 토큰을 검색]

풀 기반 소비자를 구성하려면, 생성[API 토큰](/fundamentals/api/get-started/create-token/)둘 다`queues#read`·`queues#write`이름 \* 소비자는 메시지를 인정하는 큐에 쓸 수 있어야 합니다.

:::

풀 기반 소비자를 구성하고 큐에서 메시지를 수신하려면 다음을해야합니다.

1. queue를 위한 HTTP 잡아당기기.
2. HTTP 클라이언트의 유효한 인증 토큰을 만듭니다.
3. 큐에서 메시지 배치를 잡아.
4. 일괄 처리 내에서 Acknowledge 및/또는 retry 메시지.

## 1. HTTP 풀 사용

HTTP Pull을 활성화하거나 푸시 기반에서 큐를 변경할 수 있습니다.[Wrangler 구성 파일](/workers/wrangler/configuration/)·`wrangler`CLI, 또는[Cloudflare dashboard](https://dash.cloudflare.com/).

### Wrangler 구성 파일

HTTP 소비자는 설정할 수 있습니다.[Wrangler 구성 파일](/workers/wrangler/configuration/)으로 설정`type = "http_pull"`소비자 윤곽에서:

<WranglerConfig>
  ```jsonc
  {
  	"queues": {
  		"consumers": [
  			{
  				//견적 요청
  				"queue": "QUEUE-NAME",
  				"type": "http_pull",
  				//옵션 정보
  				"visibility_timeout_ms": 5000,
  				"max_retries": 5,
  				"dead_letter_queue": "SOME-OTHER-QUEUE"
  			}
  		]
  	}
  }
  ```
</WranglerConfig>

뚱 베어`type`속성은 기본적으로 queue를 밀어 기반합니다.

### wrangler 클립

기존의 큐에 기반한 소비자를 사용할 수 있습니다.`wrangler queues consumer http`sub-commands와 큐 이름을 제공합니다.

```sh
npx wrangler queues consumer http add $QUEUE-NAME
```

기존의 푸시 기반 소비자가 있다면 먼저 제거해야합니다.`wrangler`전화를 시도하면 오류를 반환합니다.`consumer http add`기존의 소비자 구성과 큐에:

```sh
wrangler queues consumer worker remove $QUEUE-NAME $SCRIPT_NAME
```

:::참조

Worker 소비자를 제거하면`wrangler`그러나 삭제하지 마십시오`[[queues.consumer]]`설정에서[Wrangler 구성 파일](/workers/wrangler/configuration/), 당신의 노동자의 후속 배포 그들은 충돌 소비자 구성을 추가하려고 할 때 실패합니다.

소비자 구성을 먼저 제거하십시오.

:::

## 2. 소비자 인증

HTTP Pull 소비자는 요구합니다[API 토큰](/fundamentals/api/get-started/create-token/)이름 \*`com.cloudflare.api.account.queues_read`·`com.cloudflare.api.account.queues_write`이름 \*

모두 읽&#xAE30;*·*&#xC791;성은 수신된 메시지를 인정하기 위해 큐 국가로 작성해야 하는 풀 기반 소비자로 요구됩니다. 메시지를 변환하는 방법

API 토큰은 Bearer 토큰으로 표시됩니다.`Authorization`형식의 HTTP 요청 헤더`Authorization: Bearer $YOUR_TOKEN_HERE`. 다음 예제는 API 토큰을 사용하여 전달하는 방법을 보여줍니다.`curl`HTTP 클라이언트:

```bash
curl "https://api.cloudflare.com/client/v4/accounts/${CF_ACCOUNT_ID}/queues/${QUEUE_ID}/messages/pull" \
--header "Authorization: Bearer ${QUEUES_TOKEN}" \
--header "Content-Type: application/json" \
--data '{ "visibility_timeout": 10000, "batch_size": 2 }'
```

단일 큐에 대해 여러 동시 풀 기반 소비자를 인증하고 실행할 수 있습니다.

### API 토큰 만들기

API 토큰을 만들려면:

1. 로그인하기[QXQX0165XQQdashboard](https://dash.cloudflare.com).

3. 제품정보**토큰 만들기**.
4. 페이지 하단에 스크롤하고 선택**사용자 정의 토큰 만들기**.
5. 토큰에게 이름을 부여합니다. 예를 들어,`queue-pull-token`.
6. 이름 \***제출**단면도, 선택**계좌정보**그리고 그때**Queues**. 선택해 주세요**제품정보**(읽기 + 쓰기).
7. (선택 사항) 선택**모든 계정**(과태) 또는 토큰을 범위에 특정 계정.
8. 제품정보**자주 묻는 질문**그리고 그때**토큰 만들기**.

토큰을 기억해야 합니다: 한번만 표시될 것입니다.

메시지를 풀려면 HTTP POST 요청을[Queues 등급 API](/api/resources/queues/subresources/messages/methods/pull/)선택적으로 지정하는 JSON 인코딩된 몸으로`visibility_timeout`·`batch_size`, 또는 빈 JSON 객체 (`{}`):

각 메시지 객체에는 다섯 개의 필드가 있습니다.

1. `body`- 이것은 base64 인코딩 될 수있다[content-type 메시지가 게시되었습니다.](#content-types).
2. `id`- 메시지에 대한 독특하고 읽기 전용 ephemeral 식별자.
3. `timestamp_ms`- 메시지가 milliseconds에서 큐에 게시되었을 때[유닉스](https://en.wikipedia.org/wiki/Unix_time). 이 메시지를 어떻게 이전하는지 결정할 수 있습니다.
4. `attempts`- 메시지가 얼마나 많은 시간 동안 전체에서 배달하려고 시도했습니다. 이 값에 도달하면`max_retries`, 메시지는 재 배달되지 않으며 영구적으로 큐에서 삭제됩니다.
5. `lease_id`- 메시지의 인코딩된 임대 ID. 더 보기`lease_id`명시적으로 인정하거나 메시지를 재발하는 데 사용됩니다.

더 보기`lease_id`귀하의 풀 소비자가 명시적으로 일부, 아무도 또는 배치의 모든 메시지 또는 복원에 표시 할 수 있습니다. 메시지가 인식되지 않거나 소비자의 재량에 표시되지 않은 경우 한 번 재 납품에 표시 될 것입니다.`visibility_timeout`오시는 길 ·`lease_id`이 타임아웃은 더 이상 유효하지 않습니다.

모두 구성할 수 있습니다.`batch_size`·`visibility_timeout`큐에서 당기는 경우:

- `batch_size`(기본값에서 5; 최대 100) - 얼마나 많은 메시지는 각 잡아당기기에 있는 소비자에 반환됩니다.
- `visibility_timeout`(기본 30 초; 최대 12 시간) - 소비자가 자신의 배치에 따라 명시적으로 승인 된 메시지를 명시적으로 정의하는 방법을 정의`lease_id`. 이 타임아웃이 만료되면, 메시지가 다시 재발견을 위해 unacknowledged와 queued를 가정합니다.

### Concurrent 소비자

동시에 동일한 큐에서 당기는 여러 HTTP 클라이언트가있을 수 있습니다. 각 클라이언트는 메시지의 고유 한 배치를 받고 그 메시지에 "lease"를 유지`visibility_timeout`만료, 또는 그 메시지가 다시 표시 될 때까지.

retry에 표시된 메시지는 큐에 다시 넣고 어떤 소비자에게 전달 될 수 있습니다. 이름 \**아니다.*&#xC18C;비자가 정체성을 갖지 못하고, 큐에 메시지를 처리하기 위해 느린 소비자를 방지하기 위해 특정 소비자에게 묶어.

다중 소비자는 여러 업스트림 리소스 (예를 들어, GPU 인프라)가있는 경우 유용 할 수 있습니다.[백로그](/queues/observability/metrics/)큐, 및 / 또는 비용의.

## 4. Acknowledge 메시지

소비자에 의해 당겨지는 메시지는 retry를 위해 인정되거나 표시될 필요가 있습니다.

수신 및 / 또는 표시 메시지가 검색되면 HTTP를`POST`지원하다`/ack`당 당신의 큐의 끝점[Queues 등급 API](/api/resources/queues/subresources/messages/methods/ack/)배열을 제공함으로써`lease_id`인정 및 / 또는 재시험 대상 :

<Tabs syncKey="workersExamples">
  <TypeScriptExample filename="index.ts" omitTabs={true}>
    ```ts
    //POST /accounts/${CF ACCOUNT ID}/queues/${QUEUE ID}/messages/ack 와 임대 ids
    let resp = await fetch(
    	`https://api.cloudflare.com/client/v4/accounts/${CF_ACCOUNT_ID}/queues/${QUEUE_ID}/messages/ack`,
    	{
    		method: "POST",
    		headers: {
    			"content-type": "application/json",
    			authorization: `Bearer ${QUEUES_API_TOKEN}`,
    		},
    		//리트리에 메시지가 없으면 빈 배열을 지정할 수 있습니다. - retries: []
    		body: JSON.stringify({
    			acks: [
    				{ lease_id: "lease_id1" },
    				{ lease_id: "lease_id2" },
    				{ lease_id: "etc" },
    			],
    			retries: [{ lease_id: "lease_id4" }],
    		}),
    	},
    );
    ```
  </TypeScriptExample>

  <TabItem label="모델 번호: Python" icon="seti:python">

선택적으로 몇 초의 번호를 지정할 수 있습니다. retry에 표시할 때 메시지가 지연될 수 있습니다.`{ lease_id: string, delay_seconds: number }`객체의`retries`배열:

```json
{
	"acks": [
		{ "lease_id": "lease_id1" },
		{ "lease_id": "lease_id2" },
		{ "lease_id": "lease_id3" }
	],
	"retries": [{ "lease_id": "lease_id4", "delay_seconds": 600 }]
}
```

다음:

- 모든 것을 제공해야`lease_id`요청에 따라`/ack`소비자의 메시지를 처리하는 경우 endpoint. 메시지를 인정하지 않는 경우, re-delivery (queue에서 다시 입력)에 표시됩니다.
- 당신은 선택적으로 메시지를 검색 할 수 있습니다: 예를 들어, 오류가 메시지 또는 당신은 업스트림 자원 압력을 처리하는 경우. retry에 대 한 메시지를 표시 하는 Explicitly 즉시 큐에 다시 배치 됩니다., 대신에 (주로 긴)`visibility_timeout`오시는 길
- 여러 통화를 할 수 있습니다.`/ack`메시지의 배치를 통해 진행 상황을 확인하지만, 필요한 API 통화의 수를 줄이기 위해 그룹화 인식을 권장합니다.

Queues는 ID를 임대 할 때 허용됩니다. 소비자가 임대 ID로 메시지를 인정하는 경우*후에*가시적인 timeout는 도달됩니다, Queues는 아직도 그 acknowledgment를 받아들입니다. 메시지가 intervening 기간 동안 다른 소비자에게 전달되면 오류없이 메시지를 인식 할 수 있습니다.

## 내용 유형

:::카트로션

당기한 소비자를 큐에 붙일 때, 당신은 그 메시지를 보내야 합니다`text`, `bytes`또는`json` [내용 유형](/queues/configuration/javascript-apis/#queuescontenttype).

기본 내용 유형은`json`.

Pull-based 소비자는 해독할 수 없습니다`v8`Workers 런타임에 따라 내용 유형입니다.

:::

외부 소비자가 있는 큐에 게시할 때, 특정 콘텐츠 유형이 JSON 객체 내에서 안전하게 직렬화되도록 할 수있는 방식으로 인코딩 될 수 있다는 것을 인식해야합니다.

둘 다를 위해`json`·`bytes`내용 유형, 이것은 그들이 base64 인코딩 될 것이라는 것을 의미합니다 ([RFC 4648년](https://datatracker.ietf.org/doc/html/rfc4648)). 더 보기`text`타입은 일반 UTF-8 인코딩 문자열로 전송됩니다.

당신의 소비자는 해독할 필요가 있습니다`json`·`bytes`데이터에서 작동하기 전에 유형.
