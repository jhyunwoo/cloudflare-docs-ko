Queues 지원 로컬 개발 워크플로우 사용[Wrangler](/workers/wrangler/install-and-update/), Workers를 위한 명령 선 공용영역. Wrangler는 CloudflareXQ로 Queues의 동일한 버전을 전 세계적으로 실행합니다.

## 자주 묻는 질문

QueuesXQ로 로컬 개발하려면 다음이 필요합니다.

- [Wrangler의 v3.1.0](https://blog.cloudflare.com/wrangler3/)또는 나중에.

- Node.js 버전의`18.0.0`또는 나중에. Node 버전 관리자를 사용하여 고려하십시오.[볼트](https://volta.sh/)또는[사이트맵](https://github.com/nvm-sh/nvm)권한 문제를 방지하고 노드 버전을 변경합니다.

- Queues 및 / 또는 Cloudflare WorkersXQ에 새로운 경우, 참조[Queues 튜토리얼](/queues/get-started/)설치하기`wrangler`첫 번째 Queue를 배포합니다.

## 현지 개발 세션 시작

터미널을 열고 다음 명령을 실행하여 로컬 개발 세션을 시작합니다.

```sh
npx wrangler@latest dev
```

```sh output
------------------
Your Worker and resources are simulated locally via Miniflare. For more information, see: https://developers.cloudflare.com/workers/testing/local-development.

Your worker has access to the following bindings:
- Queues: <QUEUE-NAME>
```

로컬 개발 세션은 생산 환경 Queues를 미러링하는 독립, 로컬 전용 환경을 만들기 때문에 Workers*이전 다음*당신은 생산에 배치합니다.

더 알아보기[`wrangler dev`관련 기사](/workers/wrangler/commands/#dev)로컬 개발 세션을 구성하는 방법에 대해 자세히 알아보세요.

## 제조 업체 및 소비자 Workers

Wrangler는 단일 명령과 동시에 여러 WorkersXQ를 실행하는 것을 지원합니다. 당신의 건축술이 생산자와 소비자를 명백한 Workers로 분리하는 경우에, 당신은 국부적으로 전체 메시지를 시험하기 위하여 이 기능을 이용할 수 있습니다.

:::카트로션
여러 WorkersXQ를 한 번에 실행하는 지원 Wrangler 명령은 실험적이고, 우리가 경험에서 일하기 때문에 변화하는 주제입니다. 버그로 실행하거나 피드백을 가지고 있다면,[근로자 sdk 저장소에 문제가 열립니다.](https://github.com/cloudflare/workers-sdk/issues/new)
:::

예를 들어, 프로젝트가 다음과 같은 디렉토리 구조를 가지고 있다면:

```
producer-worker/
├── wrangler.jsonc
├── index.ts
└── consumer-worker/
    ├── wrangler.jsonc
    └── index.ts
```

다음 명령을 사용하여 두 명의 근로자를위한 개발 서버를 시작할 수 있습니다.

```sh
npx wrangler@latest dev -c wrangler.jsonc -c consumer-worker/wrangler.jsonc --persist-to .wrangler/state
```

프로듀서 노동자가 큐에 메시지를 보낼 때 소비자 노동자는 자동으로 그들을 처리하기 위해 호출됩니다.
:::참조
[소비자 concurrency](/queues/configuration/consumer-concurrency/)로컬로 실행하는 동안 지원되지 않습니다.

## Known 문제

- Queues는 Wrangler 먼 형태를 지원하지 않습니다 (`wrangler dev --remote`).
