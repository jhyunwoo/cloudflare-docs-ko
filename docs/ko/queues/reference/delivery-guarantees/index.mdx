납품은 강하게 메시징 체계가 그것 과정의 납품을 실행하는 방법을 정의합니다.

메시지 전달에 대한 더 강한 보증으로, 시스템은 더 많은 체크 및 acknowledgments를 수행 할 필요가 메시지가 전달되었거나 메시지를 보장하기 위해 상태를 유지해야합니다. 메시지가 지정된 번호 만 전달됩니다. 이 시스템의 대기 시간을 증가시키고 시스템의 전체 처리량을 감소시킵니다. 각 메시지는 추가 내부 인식을 요구할 수 있으며, 추가 왕복의 해당 수를 고려할 수 있습니다.

- **Queues는 제공합니다*적어도 한 번*기본값으로 배송**신뢰성을 최적화하기 위해.
- 이것은 메시지가 적어도 한 번 배달되도록 보장되고 드문 경우, 한 번 이상 배달 될 수있다.
- 응용 프로그램의 대다수를 위해, 이것은 어떤 메시지와 minimizing end-to-end latency를 잃지 않고, 정확히 한 번 배달은 어떤 메시징 시스템에서 추가 오버 헤드를 incurs.

같은 메시지를 처리하는 경우 한 번 이상 unintended 행동을 소개 할 것이며, 쿼리에 메시지를 작성할 때 고유 ID를 생성하고 데이터베이스 삽입의 기본 키와 / 또는 처리 후 메시지를 삭제하는 데 idempotency 키로 사용. 예를 들어, 업스트림 이메일 API 또는 지불 API의 ID로이 idempotency 키를 사용하여 해당 서비스를 거부 할 수 있습니다, 응용 프로그램에 추가 상태를 수행하지 않고.
