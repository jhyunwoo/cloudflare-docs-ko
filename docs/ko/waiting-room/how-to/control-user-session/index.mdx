이 설정을 조정해 사용자가 대기실을 떠난 뒤에도 사이트 내 자리를 얼마나 오래 유지할 수 있을지 제어합니다.

## Session duration

사이트에 들어온 사용자는 대기실이 적용되는 모든 URL에 대해 **session duration** 분마다 한 번 이상 HTTP 요청을 보내는 한 활성 상태로 간주됩니다. 각 새 요청은 사용자의 활성 유지 시간을 **session duration**만큼 다시 시작합니다.

## 세션 갱신 비활성화로 탐색 시간 제한하기

dashboard에서 Disable Session Renewal 옆의 확인란을 선택하면 각 사용자가 사이트에 머무를 수 있는 시간을 한 번의 session duration으로 제한할 수 있습니다. 사용자가 사이트에서 **session duration**분 동안 활성 상태를 유지한 뒤에도 대기열이 활성화되어 있으면, 해당 사용자는 대기열의 맨 뒤로 이동합니다. **session duration**이 끝났을 때 대기열이 활성화되어 있지 않으면, 이 사용자는 새 Waiting Room 쿠키를 받고 다시 새 사용자로 계산됩니다.

## origin 명령을 사용해 사용자 세션 철회하기

사용자가 특정 작업을 수행할 때 세션을 종료하려면, origin 응답의 HTTP 헤더를 통해 Waiting Room에 명령을 보낼 수 있습니다. 이 명령은 현재 응답과 연결된 사용자의 세션을 철회하라고 Waiting Room에 지시합니다. 이를 통해 자리가 더 동적으로 열리고 대기열 처리량이 증가할 수 있습니다.

Cloudflare Dashboard에서 이 기능을 활성화하려면 Allow session termination via origin commands 옆 확인란을 선택하세요.
[Cloudflare API](/api/resources/waiting_rooms/methods/update/)를 통해 활성화하려면 `enabled_origin_commands` 속성을 업데이트하여 활성화된 origin 명령 목록에 `”revoke”` 값을 포함시키세요.

그런 다음 현재 요청과 연결된 사용자 세션을 철회하는 origin 명령을 반환하려면, origin 응답에 `Cf-Waiting-Room-Command: revoke` HTTP 헤더를 추가하세요.

철회된 세션 수를 얻으려면 GraphQL API를 통해 [Waiting Room analytics](/waiting-room/waiting-room-analytics/#graphql-analytics) 데이터에서 `sessionsRevoked` 메트릭을 조회할 수 있습니다.
