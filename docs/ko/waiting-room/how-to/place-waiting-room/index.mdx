[대기실을 구성](/waiting-room/how-to/create-waiting-room/)할 때는 대기실이 어떤 페이지를 보호할지 지정해야 합니다.

대기실의 configuration settings에는 최소 하나의 hostname과 path가 필요합니다. path 뒤에는 암묵적인 와일드카드가 붙기 때문에, 해당 대기실은 모든 하위 경로에도 적용됩니다. 대기열이 활성화되어 있으면 이 hostname과 path 조합에 포함되는 모든 URL에서 새 사용자는 대기열에 들어갑니다. 대기실이 여러 개라면 가장 구체적인 하위 경로를 가진 대기실이 우선합니다.

## 여러 호스트명과 경로에 적용

Advanced Waiting Room 고객은 단일 대기실을 여러 호스트명과 경로에 적용할 수 있습니다. UI에서 이렇게 하려면 첫 번째 hostname과 path를 추가한 뒤 **Add Hostname and Path**를 선택하고, 대기실이 적용될 다음 hostname과 path 조합을 입력하세요. 하나의 대기실에 여러 hostname과 path를 추가하는 경우에는 Custom cookie 필드를 채워 고유한 Waiting Room 쿠키도 만들어야 합니다. API를 통해 여러 hostname과 path를 추가하려면 `additional_routes` 필드를 사용하고, `cookie_suffix` 필드로 쿠키 접미사를 사용자 지정하세요.

다른 대기실에 이미 구성된 hostname과 path 조합은 추가할 수 없습니다. hostname은 대기실이 구성된 zone에 속해야 합니다.

다음 조건을 만족하면 하나의 대기실을 여러 custom hostname에 적용할 수 있습니다.

- custom hostname들 사이의 apex domain이 동일해야 합니다.
- 각 custom hostname이 SSL for SaaS 설정에서 [명시적으로 구성](#custom-hostnames)되어 있어야 합니다.

## 커스텀 호스트명

커스텀 호스트명에 대기실을 배포하려면, 와일드카드가 아닌 custom hostname이 SSL for SaaS에서 [구성되어 활성 상태](/cloudflare-for-platforms/cloudflare-for-saas/domain-support/create-custom-hostnames/)여야 합니다. 그런 다음 Waiting Room을 [생성](/waiting-room/how-to/create-waiting-room/)하고, 같은 apex domain을 가진 [여러 호스트명](#apply-to-multiple-hostnames-and-paths)에 선택적으로 적용할 수 있습니다.

즉, `hello.example.com`에 대기실을 두고 싶다면 `hello.example.com`이 활성 custom hostname이어야 합니다. SSL for SaaS 설정에서 `example.com`을 custom hostname으로 구성하고 해당 custom hostname에 대해 와일드카드를 활성화했더라도, `example.com`만 설정된 상태로는 `hello.example.com`에 대기실을 만들 수 없습니다.

## 대기실 적용 범위에서 예외 만들기

대기실에 설정한 경로 아래의 특정 하위 경로나 쿼리 문자열에는 대기실을 적용하지 않으려면, [Waiting Room 우회 규칙](/waiting-room/additional-options/waiting-room-rules/bypass-rules/#common-use-cases)을 만들어 해당 사이트 영역에서 트래픽이 대기열에 들어가지 않도록 할 수 있습니다.
