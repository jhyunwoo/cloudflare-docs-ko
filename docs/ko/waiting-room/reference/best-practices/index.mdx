잠재적인 문제를 피하고 방문자 경험을 개선하려면 다음 모범 사례를 따르세요.

## Total active users

[구성 설정](/waiting-room/reference/configuration-settings/)에서 **Total active users**를 지정할 때는 origin의 트래픽 수용량의 `75%`로 설정하세요.

## Page path

[구성 설정](/waiting-room/reference/configuration-settings/)에서 대기실 **Path**를 설정할 때는 가능한 하위 경로도 고려하세요. 대기실은 모든 하위 경로에 활성화되므로, 예상보다 더 많은 트래픽을 대기실로 보내게 될 수 있습니다.

또한 여러 개의 대기실이 있는 경우 가장 구체적인 하위 경로를 가진 대기실이 우선합니다.

## Update during active queueing

### Waiting room template

사용자가 대기 중일 때 업데이트된 정보나 기대 시간을 제공하고 싶다면 Cloudflare는 [대기실 템플릿](/waiting-room/how-to/customize-waiting-room/)을 업데이트할 것을 권장합니다. 모든 변경 사항은 거의 실시간으로 사용자에게 표시됩니다.

### Configuration settings

사용자가 실제로 대기 중인 동안에는 꼭 필요한 경우에만 [구성 설정](/waiting-room/reference/configuration-settings/)을 변경하세요. 이러한 변경은 최종 사용자에게 표시되는 예상 대기 시간에 영향을 주어 혼란을 일으킬 수 있습니다.

## Waiting Room and SEO

SEO 크롤러는 대기열이 활성화된 동안 대기열에 들어갈 수 있습니다. 이렇게 되면 사이트 검색 결과와 SEO에 영향을 줄 수 있습니다. 이를 방지하려면 Waiting Room 대시보드 또는 API에서 SEO Crawler Bypassing을 활성화할 수 있습니다. SEO Crawler Bypassing은 Bot Management로 검증된 신뢰할 수 있는 SEO 크롤러가 절대 대기실에 들어가지 않도록 보장합니다. 이들이 대기하지 않음으로써 사이트를 계속 크롤링할 수 있어 주요 검색 엔진에서의 SEO와 검색 결과를 유지하는 데 도움이 됩니다.

이 기능을 활성화하면 검증된 크롤러가 대기실을 완전히 우회한다는 점을 이해한 것으로 간주됩니다. 이 트래픽에는 어떤 대기실 설정이나 기능도 적용되지 않습니다.
