Waiting Room Bypass Rule은 Cloudflare의 Ruleset Engine 위에 구축되고 Waiting Room API를 통해 관리되는 Waiting Room Rule 유형입니다. Waiting Room Bypass Rule을 사용하면 대기실이 적용되지 않기를 원하는 특정 트래픽 또는 사이트/애플리케이션 영역을 지정할 수 있습니다. 각 우회 규칙은 정밀한 제어를 위해 개별 대기실 수준에서 생성되고 관리됩니다.

우회 규칙을 적용할 위치를 지정하려면 Cloudflare Ruleset Engine에서 사용할 수 있는 [fields](/ruleset-engine/rules-language/fields/reference/)로 [커스텀 로직](/ruleset-engine/rules-language/)을 작성하세요. 단, 다음은 제외됩니다.

- `cf.threat_score` 및 `cf.bot_management`로 시작하는 필드
- HTTP response 필드

우회 규칙 표현식에 일치하는 모든 트래픽에는 대기실이 적용되지 않으며 active users로 집계되지 않는다는 점에 유의하세요. Event pre-queueing, Reject queueing method, Queue-all을 포함하되 이에 국한되지 않는 어떠한 Waiting Room 기능도 이 트래픽에는 적용되지 않습니다. 따라서 Bypass Waiting Room 규칙을 만들고 활성화할 때는 신중해야 합니다. origin을 압도하거나 큰 트래픽 급증을 일으키지 않을 것이라고 확신하는 트래픽에 대해서만 우회 규칙을 사용하세요.

:::note
일부 고객만 Waiting Room 규칙을 생성할 수 있습니다. 자세한 내용은 [요금제](/waiting-room/plans/) 페이지를 참고하세요.
:::

## Common Use Cases

* **Path/URL Exclusion**: 대기실이 해당 경로에 적용되지 않기를 원하는 경우, 대기실을 구성한 경로 아래의 특정 경로나 URL을 우회합니다.
* **Administrative Bypass**: 일반적으로 IP 주소로 식별되는 내부 사이트 관리자가 항상 대기실을 우회하도록 허용합니다.
* **Geo-targeting**: 특정 국가를 대기열 대상에서 제외합니다.
* **Query String Exclusion**: 대기실이 구성된 경로 아래에서 특정 query string을 제외합니다.
* **파일 확장자 제외**: 대기실 HTML 템플릿을 제대로 렌더링하기 위해 사용하는 `.js` 같은 특정 파일 확장자에 대기실이 적용되지 않도록 합니다.

### 하위 요청에 대한 참고

제외하려는 query string 또는 path와 함께, 하위 요청이 접근할 수 있는 path나 파일 형식도 표현식에 포함해야 합니다. 그래야 해당 자산이나 path에도 대기실이 적용되지 않습니다. 그렇지 않으면 이러한 하위 요청은 여전히 대기실 범위 안에 있기 때문에 대기실 쿠키를 받게 됩니다.

이는 이미지, JavaScript 파일, CSS 파일 등 무엇이든 될 수 있습니다. 또한 요청이 `.js`, `.css`, `.png` 등으로 끝나는 경우 대기실을 우회하도록 규칙을 구성하면, 해당 자산이 저장된 각 path를 일일이 수동 구성하지 않아도 됩니다.

예시 조건: `ends_with(http.request.uri.path, ".js")`

## 대시보드에서 Waiting Room 우회 규칙 만들기

새 우회 규칙을 만들려면 다음과 같이 하세요.

1. Cloudflare 대시보드에서 **Waiting Room** 페이지로 이동합니다.

   <DashButton url="/?to=/:account/:zone/traffic/waiting-rooms" />

2. 대기실을 펼친 다음 **Manage rules**를 선택합니다.
3. **Create new bypass rule**를 선택합니다.
4. **Rule name**에 규칙을 설명하는 이름을 입력합니다.
5. **When incoming requests match** 아래에서 규칙 표현식을 정의합니다. **Field** 드롭다운 목록을 사용해 HTTP 속성을 선택하세요. 각 요청에 대해 **Field**로 고른 속성 값이, **Operator**에서 선택한 연산자를 사용해 **Value**에 지정한 값과 비교됩니다.
6. **Then** 아래에서는 Bypass Waiting Room 작업이 자동으로 선택됩니다. 저장하기 전에 표현식을 검토하고, 표현식에 일치하는 트래픽이 실제로 대기실을 적용하지 않으려는 트래픽인지 확인하세요.
7. 규칙을 저장하고 배포하려면 **Save and Deploy**를 선택합니다. 아직 배포할 준비가 되지 않았다면 **Save as Draft**를 선택합니다.

### Operators and grouping symbols

* Comparison operators는 표현식이 true를 반환하기 위해 표현식에 정의된 값이 실제 HTTP 요청 값과 어떤 관계여야 하는지 지정합니다.
* Logical operators는 두 표현식을 결합해 복합 표현식을 만들고, 연산자 우선순위를 사용해 표현식 평가 방식을 결정합니다.
* Grouping symbols는 표현식을 정리하고, 연산자 우선순위를 강제하며, 표현식을 중첩하는 데 사용됩니다.

예시와 사용법은 Rules language 문서의 [Operators and grouping symbols](/ruleset-engine/rules-language/operators/)를 참고하세요.

## Waiting Room API를 통한 규칙 관리

대기실의 우회 규칙은 [Waiting Room API](/api/resources/waiting_rooms/subresources/rules/methods/get/)를 통해 관리, 삭제, 생성할 수 있습니다. 우회 규칙은 `bypass_waiting_room` 작업을 사용하는 Waiting Room Rule입니다.

API를 통해 Bypass Waiting Room Rule을 만들 때는 다음을 확인하세요.

* 규칙을 적용할 대상 대기실을 이미 만들고 저장했습니다.
* 어떤 트래픽이 대기실을 우회해야 하는지를 나타내는 표현식을 정의했습니다.
* 규칙 action을 `bypass_waiting_room`으로 설정했습니다.

다음 엔드포인트를 Waiting Room API 경로로 Cloudflare API 기본 URL 뒤에 붙여 Waiting Room Rule을 만듭니다. 새 Waiting Room 규칙은 기존 규칙 뒤에 추가됩니다.

```txt
POST zones/{zone_id}/waiting_rooms/{room_id}/rules
```

다음 필수 및 선택 파라미터로 우회 규칙을 구성하세요.

* **Description** (optional) - 우회 규칙의 목적을 기록하기 쉽도록 설명을 추가합니다.
* **Expression** (required) - 어떤 트래픽에 우회 규칙을 적용할지 나타내는 규칙 표현식을 정의합니다.
* **Action** (required) - 표현식이 true로 평가될 때 수행할 작업을 정의합니다. `bypass_waiting_room`으로 설정하세요.
* **Enabled** (optional) - 기본값은 true입니다. 규칙을 배포하고 싶지 않다면 false로 설정해야 합니다.

### API Examples


<Details header="대기실 아래의 특정 경로와 그 모든 하위 경로 우회">

대기실이 `example.com/`에 구성되어 있고 `example.com/bypassme` 및 그 모든 하위 경로를 방문하는 트래픽을 모두 우회시키고 싶다고 가정해 봅시다. 이 예시에서는 해당 경로에서 로드되는 모든 자산이 제대로 표시되도록 `js`, `css`, `png` 하위 요청도 함께 대기실을 우회하게 하고자 합니다. 이 예시에서는 `js`, `css`, `png`로 끝나는 모든 요청이 하위 경로와 무관하게 대기실을 우회한다는 점에 유의하세요. 이것이 의도한 사용 사례가 아니라면, 사이트 구조와 요구사항에 맞게 표현식을 조정하세요.

<APIRequest
  path="/zones/{zone_id}/waiting_rooms/{waiting_room_id}/rules"
  method="POST"
  json={{
    description: "subpath bypass",
    expression: "starts_with(http.request.uri.path, \"/bypassme\") or ends_with(http.request.uri.path, \".js\") or ends_with(http.request.uri.path, \".css\") or ends_with(http.request.uri.path, \".png\")",
    action: "bypass_waiting_room"
  }}
/>

</Details>


<Details header="정의된 IP 목록이 대기실을 우회하도록 허용">

<APIRequest

  method="POST"
  json={{
    description: "ip list bypass",
    expression: "ip.src in $bypass_ip_list",
    action: "bypass_waiting_room"

</Details>

### 우회 규칙 관리를 위한 기타 API 옵션

Waiting Room API를 통해 Waiting Room rules API 호출을 사용하면 다음 작업도 수행할 수 있습니다.

* **List Waiting Room Rules**: 대기실의 규칙 목록을 조회합니다.
* **Replace Waiting Room Rules**: 대기실의 모든 규칙을 교체합니다.
* **Patch Waiting Room Rules**: 대기실의 규칙을 업데이트합니다.
* **Delete Waiting Room Rules**: 대기실의 규칙을 삭제합니다.
