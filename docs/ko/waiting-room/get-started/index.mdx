## 시작하기 전에

이 튜토리얼을 시작하기 전에 다음을 확인하세요.

- Waiting Room의 [소개](/waiting-room/about/) 페이지를 검토했습니다.
- 자동 페이지 새로고침에 필요하므로, [rate limiting rules](/waf/rate-limiting-rules/)이 최소 20초마다 1회 이상의 요청을 허용하도록 검토했습니다.

---

## 1단계 — 대기실 계획하기

대기실을 만들기 전에 어떻게 표시하고 동작하게 할지 생각해 보세요.

### 위치

어떤 페이지를 대기실로 보호할 것인가요? 페이지당 대기실은 하나만 가질 수 있으므로, 웹사이트에서 트래픽이 많이 몰리는 영역을 식별해야 합니다.

[configuration settings](/waiting-room/reference/configuration-settings/)에서 `hostname`과 `path`를 설정해 페이지의 URL을 지정합니다.

Advanced Waiting Room 고객은 같은 zone에 대해 [여러 hostname 및 path 조합을 지정](/waiting-room/how-to/place-waiting-room/)할 수도 있습니다.

### 접근 방식

트래픽이 많은 페이지로 방문자를 보내는 방법은 다음과 같습니다.

- 직접(URL 사용)
- 간접적으로([redirect](/rules/url-forwarding/bulk-redirects/) 사용)

### 대기열 활성화

[대기실을 활성화](#step-3--activate-your-waiting-room)할 때 다음 중 무엇을 선택할지 정합니다.

- 제품 출시나 기타 시간 기반 이벤트에 대비해 [**모든 방문자**](#queue-all-visitors)를 대기열에 넣을지
- `Total active users` 및 `New users per minute`에 정의된 임계값에 도달할 때만 [**일부 방문자**](#queue-some-visitors)를 대기열에 넣을지

## 2단계 — 대기실 만들기

다음 방법으로 대기실을 만듭니다.

- [dashboard](/waiting-room/how-to/create-waiting-room/) 사용
- [API](/waiting-room/how-to/create-waiting-room/) 사용

### 모양(선택 사항)

일부 고객은 페이지의 HTML 및 CSS를 편집하여 대기실의 [디자인을 사용자 지정](/waiting-room/how-to/customize-waiting-room/)할 수 있습니다.

이 기능을 사용할 수 있다면 페이지를 어떻게 보이게 할지 생각해 보세요.

### 모바일 애플리케이션 트래픽에 대비해 대기실 준비하기

모바일 앱이나 웹 앱처럼 브라우저가 아닌 환경의 트래픽을 관리해야 한다면, API 엔드포인트를 통해 소비할 수 있는 [JSON 친화적 대기실](/waiting-room/how-to/json-response/)을 사용하세요. 모바일 앱이나 웹 앱이 대기실로 보호되는 리소스에 의존하는 경우, 해당 클라이언트가 Waiting Room을 적절히 처리하도록 업데이트해야 한다는 점에 유의하세요.
