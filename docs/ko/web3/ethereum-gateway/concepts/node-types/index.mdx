널리 알려진 Ethereum node 유형은 세 가지입니다: Full node, Archive node, Light node.

## Full nodes

Full node는 블록체인의 모든 데이터를 저장하고 블록 검증에 참여합니다. 블록체인을 검증한다는 것은 새 블록을 추적하고 상태 변화를 계산하고 유지하는 일을 포함합니다. 네트워크와 완전히 동기화된 full node는 Ethereum 블록체인 데이터를 모두 조회할 수 있습니다.

## Light nodes

Light node는 full node보다 훨씬 작으며 같은 방식으로 블록 검증에 참여하지 않습니다. 이 node는 Ethereum network를 조회할 수 있지만 체인의 상태를 저장하지는 않습니다. 이 제한 때문에 정확한 체인 데이터를 얻기 위해 full node와의 peering에 의존합니다.

## Archive nodes

Archive node는 블록체인의 과거 상태를 추가로 저장하는 full node입니다. full node도 과거 상태를 계산할 수는 있지만, archive node는 정보를 로컬 저장소에 바로 보유하고 있어 이러한 요청에 대해 더 나은 성능을 제공합니다.

## Cloudflare의 노드

Cloudflare의 Ethereum Gateway는 full node와 archive node에 대한 접근을 제공합니다.

archive node는 block number parameter가 가장 최근 128블록 이전이거나 기본 block parameter가 “earliest”로 설정된 경우, 다음 [RPC state methods](https://ethereum.org/en/developers/docs/apis/json-rpc/#state_methods)에 대한 요청을 처리합니다.

* [eth\_getBalance](https://ethereum.org/en/developers/docs/apis/json-rpc/#eth_getbalance)
* [eth\_getCode](https://ethereum.org/en/developers/docs/apis/json-rpc/#eth_getcode)
* [eth\_getTransactionCount](https://ethereum.org/en/developers/docs/apis/json-rpc/#eth_gettransactioncount)
* [eth\_getStorageAt](https://ethereum.org/en/developers/docs/apis/json-rpc/#eth_getstorageat)
* [eth\_call](https://ethereum.org/en/developers/docs/apis/json-rpc/#eth_call)
