게이트웨이를 [생성](/web3/how-to/manage-gateways/#create-a-gateway)하면 Cloudflare는 Cloudflare 계정에 필요한 [DNS 레코드](/web3/reference/gateway-dns-records/)를 자동으로 생성하고 추가합니다.

게이트웨이에 연결된 호스트명이 요청을 받으면, 해당 DNS 레코드는 이 요청을 Cloudflare Workers 스크립트로 라우팅합니다.

![Cloudflare's Web3 gateways provide HTTP-accessible interfaces to the IPFS and Ethereum networks. For more details, continue reading.](~/assets/images/web3/web3-gateway-flow-diagram.png)

## 읽기 작업

Worker로 향하는 API 호출이 읽기 작업이고 요청된 콘텐츠가 캐시되어 있다면, Workers 스크립트는 HTTP를 통해 클라이언트에 요청된 정보를 응답합니다.

요청된 콘텐츠가 캐시되어 있지 않다면, 먼저 Cloudflare IPFS 또는 Ethereum 노드에 API 호출을 보내 콘텐츠를 가져오고, 이후 요청을 위해 edge에 캐시한 뒤, HTTP 응답으로 클라이언트에 반환합니다.

## 쓰기 작업

*[Ethereum](/web3/how-to/use-ethereum-gateway/)과 같은 EVM 기반 체인용 게이트웨이에서만 사용할 수 있습니다.*

게이트웨이에 대한 API 호출이 쓰기 작업이면, 게이트웨이는 Cloudflare 노드 중 하나로 API 호출을 보내고, 트랜잭션은 로컬 mempool에 배치된 뒤 피어들에게 전파됩니다.

트랜잭션 ID가 게이트웨이에 반환되고, 다시 HTTP 응답을 통해 클라이언트에 전달됩니다. 검증자들은 mempool에서 트랜잭션을 가져와 블록에 넣어 실행합니다. 블록체인에 추가할 새 블록이 검증되고, 합의가 이루어지면 블록이 블록체인과 네트워크 전체에 전파됩니다.
