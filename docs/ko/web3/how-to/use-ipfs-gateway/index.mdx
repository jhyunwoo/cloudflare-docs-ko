IPFS gateway를 만들었다면, 즉 `target`을 **IPFS**로 하여 [새 게이트웨이를 생성](/web3/how-to/manage-gateways/#create-a-gateway)했다면, URL을 사용해 IPFS network에서 데이터를 가져올 수 있습니다.

## 네트워크에서 읽기

Cloudflare의 IPFS Gateway를 통해 콘텐츠에 접근할 때마다 URL에는 두 부분이 필요합니다. 게이트웨이 호스트명과 요청 경로입니다.

### 게이트웨이 호스트명

게이트웨이 호스트명은 [게이트웨이를 생성](/web3/how-to/manage-gateways/#create-a-gateway)할 때 입력한 **Hostname** 값입니다.

### 요청 경로

요청 경로는 제공하려는 콘텐츠 유형에 따라 달라집니다.

요청 경로가 `/ipfs/<CID_HASH>`이면, 이는 바로 뒤에 오는 Content Identifier(CID)에 해당하는 콘텐츠를 원한다는 뜻입니다. 콘텐츠가 CID로 주소 지정되므로, 게이트웨이 응답은 불변(immutable)이며 절대 바뀌지 않습니다. 예를 들어 `https://cloudflare-ipfs.com/ipfs/QmXoypizjW3WknFiJnKLwHCnL72vedxjQkDDP1mXWo6uco/wiki/`는 Wikipedia 미러이자 불변 `/ipfs/` 링크입니다.

요청 경로가 `/ipns/<DOMAIN>`이면, 게이트웨이에 특정 도메인과 연결된 CID를 DNS에서 조회한 뒤 그 CID가 가리키는 콘텐츠를 제공하라는 의미입니다. DNS는 시간이 지남에 따라 바뀔 수 있기 때문에 게이트웨이 응답도 바뀔 수 있습니다. 예를 들어 `https://cloudflare-ipfs.com/ipns/ipfs.tech/`는 IPFS의 마케팅 사이트이며, `ipfs.tech` 도메인에 연결된 [DNSLink record](/web3/ipfs-gateway/concepts/dnslink/)를 수정하면 언제든지 변경할 수 있습니다.

## 네트워크에 쓰기

Cloudflare의 IPFS Gateway는 현재 읽기 전용 접근만 지원합니다.
