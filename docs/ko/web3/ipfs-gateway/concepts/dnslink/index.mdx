DNSLink record로 게이트웨이를 설정하면, 해당 게이트웨이는 특정 콘텐츠 조각(특정 Content Identifier(CID) 또는 Interplanetary Name Service(IPNS) 호스트명)에만 제한됩니다.

DNSLink가 있는 게이트웨이, 즉 *restricted gateway*는 IPFS 네트워크에 호스팅된 어떤 콘텐츠든 접근할 수 있게 해 주는 [universal gateway](/web3/ipfs-gateway/concepts/universal-gateway/)와 다릅니다.

## 이것이란 무엇인가요?

[IPFS](/web3/ipfs-gateway/concepts/ipfs/)로 무엇이든 가져오면, 해당 항목은 `bafybeiaysi4s6lnjev27ln5icwm6tueaw2vdykrtjkwiphwekaywqhcjze`와 비슷한 고유한 콘텐츠 식별자([CID](https://docs.ipfs.io/concepts/glossary/#cid))를 갖게 됩니다.

이처럼 긴 CID는 IPFS에 호스팅된 웹사이트(`https://cf-ipfs.com/ipfs/bafybeiaysi4s6lnjev27ln5icwm6tueaw2vdykrtjkwiphwekaywqhcjze`)를 다른 사람이 접근하게 만들고 싶을 때 문제가 될 수 있습니다. 이는 일반 웹사이트에서 최종 사용자가 도메인 이름(`google.com`) 대신 IP 주소(`192.0.2.1`)를 기억하기 어려운 것과 비슷한 문제입니다.

이 문제는 DNS record를 통해 같은 방식으로 해결됩니다. IPFS에 호스팅된 웹사이트를 더 쉽게 접근 가능하게 만들려면 웹사이트 전체를 하나의 디렉터리에 넣고, 그 CID에 대한 **DNSLink** record를 생성하면 됩니다. 이후 최종 사용자는 `https://cf-ipfs.com/ipns/en.wikipedia-on-ipfs.org/` 같은 Universal Gateway URL로 요청할 수 있고, 그 요청은 백그라운드에서 올바른 CID로 변환됩니다.

DNSLink record는 콘텐츠 유지보수에도 도움을 줍니다. 웹사이트의 새 버전을 게시할 준비가 되면 DNSLink DNS record를 새 CID로 업데이트하면 되고, 게이트웨이는 자동으로 새 버전을 제공하기 시작합니다.

:::note

추가 세부 사항은 공식 [IPFS documentation](https://docs.ipfs.tech/concepts/dnslink/)을 참고하세요.
:::

## Cloudflare에서는 어떻게 사용되나요?

[IPFS gateway를 생성](/web3/how-to/manage-gateways/#create-a-gateway)할 때 DNSLink를 지정할 수 있으며, 이 값은 이미 IPFS에 호스팅된 웹사이트로 사용자를 보내는 커스텀 호스트명 역할을 합니다.

기본 DNSLink 경로는 `/ipns/onboarding.ipfs.cloudflare.com`입니다. 웹사이트를 자체 IPFS node나 pinning service에 호스팅된 다른 콘텐츠 폴더에 넣고 싶다면 그 값을 직접 지정해야 합니다.

예를 들어 `www.example.com`의 기본 DNSLink record는 다음과 같습니다.

| Record type | Name | Content |
| --- | --- | --- |
| TXT | `_dnslink.www.example.com` | `dnslink=/ipns/onboarding.ipfs.cloudflare.com` |

IPFS gateway가 생성하는 DNS record에 대한 자세한 내용은 [Gateway DNS records](/web3/reference/gateway-dns-records/)를 참고하세요.
