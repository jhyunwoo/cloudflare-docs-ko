반드시 필요한 것은 아니지만, 다른 도메인으로 연결하는 경우를 제외하면 IPFS에 호스팅된 웹사이트는 상대 링크만 사용할 것을 강력히 권장합니다. 데이터는 궁극적으로 동일하더라도 여러 방식으로 접근될 수 있기 때문입니다.

* 커스텀 도메인에서: `https://ipfs.tech/index.html`
* gateway에서: `https://cloudflare-ipfs.com/ipns/ipfs.tech/index.html`
* 불변 hash로: `https://cloudflare-ipfs.com/ipfs/QmNksJqvwHzNtAtYZVqFZFfdCVciY4ojTU2oFZQSFG9U7B/index.html`

웹 애플리케이션 내부에서 상대 링크만 사용하면 이 모든 방식이 동시에 지원되며, 사용자에게 가장 큰 유연성을 제공합니다. 이미 상대 링크를 사용하고 있지 않다면 이를 전환하는 정확한 방법은 사용하는 프레임워크에 따라 달라집니다.

## Angular, React, Vue

이 인기 있는 JavaScript 프레임워크들은 [Pinata](https://pinata.cloud/)의 [블로그 게시물](https://medium.com/pinata/how-to-easily-host-a-website-on-ipfs-9d842b5d6a01)에서 다루고 있습니다. 작은 설정 변경만으로 해결할 수 있습니다.

## Gatsby

Gatsby는 React 기반 JavaScript 프레임워크입니다. 링크를 상대 경로로 만들어 주는 [plugin](https://www.gatsbyjs.org/packages/gatsby-plugin-ipfs/)이 있습니다.

## Jekyll

`_includes/base.html` 파일을 만들고 다음 내용을 추가하세요.

```
{% assign base = '' %}
{% assign depth = page.url | split: '/' | size | minus: 1 %}
{% if    depth <= 1 %}{% assign base = '.' %}
{% elsif depth == 2 %}{% assign base = '..' %}
{% elsif depth == 3 %}{% assign base = '../..' %}
{% elsif depth == 4 %}{% assign base = '../../..' %}{% endif %}
```

이 스니펫은 현재 페이지에서 웹사이트 루트까지의 상대 경로를 계산합니다. 루트에 링크해야 하는 페이지 상단에는 다음을 추가하세요.

```
{%- include base.html -%}
```

이 스니펫은 또한 모든 링크 앞에 `{{base}}`를 붙이는 데 사용됩니다. 예를 들어 `href="/css/main.css"`는 `href="{{base}}/css/main.css"`로 바꾸게 됩니다.

## Generic

다른 프레임워크를 사용하거나 프레임워크를 사용하지 않은 경우에는 [make-relative](https://github.com/tmcw/make-relative)라는 스크립트가 있어 웹사이트의 HTML을 파싱하고 링크와 이미지를 자동으로 상대 경로로 다시 작성해 줍니다.
