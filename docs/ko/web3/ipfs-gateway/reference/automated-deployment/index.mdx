정적 사이트는 자동 배포하기 쉽습니다. 사이트 코드는 보통 Git 저장소에 있고, [Travis CI](https://travis-ci.org/) 같은 Continuous Integration 서비스와 연결된 저장소에 최신 커밋을 push하거나, 서버상의 저장소에 직접 push한 뒤 post-receive hook을 활성화해 배포합니다. 어느 방식이든 사이트의 프로덕션 버전이 빌드된 뒤 Apache 또는 NGINX 인스턴스의 serving path에 복사됩니다.

IPFS는 보통 이러한 시스템에 잘 들어맞습니다. 즉, 웹사이트의 프로덕션 버전을 HTTP 서버의 serving path에 복사하는 대신 같은 파일을 IPFS node에 업로드하고 새 hash로 DNS record를 업데이트하면 됩니다. 이를 돕는 여러 도구가 있습니다.

* [ipfs-deploy](https://github.com/agentofuser/ipfs-deploy)는 third-party pinning provider에 데이터를 업로드하고 Cloudflare가 관리하는 DNS record를 자동으로 업데이트하는 데 도움을 줍니다.
* [dnslink-cloudflare](https://github.com/ipfs-shipyard/dnslink-cloudflare)는 DNSLink record를 프로그래밍 방식으로 업데이트하는 스크립트입니다. 이는 최상위 hash만 출력하는 `ipfs add`의 `-Q` 플래그와 함께 실행할 수 있습니다.
* [Fission's IPFS support](https://guide.fission.codes/developers/custom-domains/using-cloudflare-ipfs-gateway)는 Cloudflare가 관리하는 DNS와 gateway를 사용하면서 CLI 또는 GitHub Actions에서 Fission의 IPFS 앱 퍼블리싱 시스템을 사용할 수 있게 해 줍니다.
