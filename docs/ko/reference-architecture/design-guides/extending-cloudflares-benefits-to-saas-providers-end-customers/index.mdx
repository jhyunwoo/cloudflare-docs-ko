## 제품정보

Software-as-a-service (SaaS) 응용 프로그램을 개발하는 주요 측면은 인터넷에 직면하는 잠재적 인 공격에 대한 다양한 보안을 보장합니다. Cloudflare의 네트워크 및 보안 서비스는 고객의 SaaS 애플리케이션을 사용하여 고객을 보호하는 데 사용될 수 있으며, 공급 업체에 대한 위험이 줄어듭니다.[관련 제품](https://radar.cloudflare.com/reports/ddos).

이 디자인 가이드는 Cloudflare를 활용하여 보안, 성능 및 Cloudflare의 네트워크에 대한 Cloudflare의 네트워크의 준수 혜택을 확장 할 수 있습니다.

다음 다이어그램은 다음과 같은 서비스의 사용을 시각화 :

- Data Localization Suite (특히,[지역 서비스](/data-localization/regional-services/))
- [SaaS를 위한 Cloudflare](/cloudflare-for-platforms/cloudflare-for-saas/)
- [모델 번호: Cloudflare 연락처](/cloudflare-one/networks/connectors/cloudflare-tunnel/)웹 응용 프로그램을 안전하게 노출 (with[공유 hostnames](/cloudflare-one/networks/connectors/cloudflare-tunnel/routing-to-tunnel/)·[개인 네트워크](/cloudflare-one/networks/connectors/cloudflare-tunnel/private-net/))
- Load Balancers는 트래픽을 관리하고 신뢰성과 성능을 보장하며 글로벌 트래픽 관리(GTM) 구현[개인 네트워크 부하 Balancing](/load-balancing/private-network/).

이 설정은 최소 가동 시간, SSL/TLS 인증서의 자동 갱신을 보장해야하는 SaaS 제공 업체에 이상적입니다. 효율적으로 건강 엔드 포인트에 트래픽을 배포하고 준수 및 성능 최적화를위한 지역 교통 관리.

이 문서는 공급자의 애플리케이션 DNS가 Cloudflare를 기본 및 권한 DNS 공급자로 등록하고 관리한다는 것을 가정합니다. 이 작업을 설정하는 방법에 대한 세부 정보를 찾을 수 있습니다.[Cloudflare DNS 영역 설정 가이드](/dns/zone-setups/full-setup/).

이 솔루션은 자체 영역에서 하위 도메인을 지원하며 고객에게 자신의 도메인 이름 (vanity 또는 사용자 정의 도메인)을 귀하의 서비스를 사용할 수 있습니다. 예를 들어, 각 고객을 위해 사용자 정의 hostname을 만들 수 있습니다.`mycustomer.myappexample.com`또한 자신의 도메인을 사용할 수 있도록,`app.mycustomerexample.com`당신의 서비스에 그들의 tenant에 점. 각 하위 도메인 (`mycustomer.myappexample.com`) 주요 도메인에 생성 할 수 있습니다 (`myappexample.com`)를 통해[모델 번호: Cloudflare](/dns/manage-dns-records/how-to/create-dns-records/#create-dns-records)고객이 서비스에 계정을 만들 때 DNS 레코드의 생성을 쉽게 자동화 할 수 있습니다.

## SaaS 예제에 대한 Cloudflare

Cloudflare를 사용하는 주요 목적은 애플리케이션의 사용자 정의 호스트 이름에 대한 모든 요청이 Cloudflare의 보안 및 성능 서비스를 통해 먼저 트래픽의 보안 제어 및 라우팅 또는로드 균형을 적용하도록 설계되었습니다. 원래 서버가 자주 공개적으로 액세스 할 필요가 있기 때문에 Cloudflare와 Origin 서버가 중요합니다. 근원 서버에 대한 종합적인 지도를 위해, Cloudflare의 문서를 참조하십시오:[당신의 근원 서버를 보호하십시오](/fundamentals/security/protect-your-origin-server/).

아래의 다이어그램은 이 목표를 달성하는 가장 간단한 접근 방식을 설명하여 더 복잡한 구성으로 이어졌습니다.

### 표준 fallback 근원 체제

SaaS 설정을 위한 이 표준 Cloudflare는 대부분의 공급자를 위해 실행하기 위하여 가장 통용되고 가장 쉽습니다. 일반적으로, 이 공급자는 SaaS 회사이며, 이는 서비스 솔루션으로 소프트웨어를 개발 및 제공. 이 설정은 Cloudflare에 직접 요청하는 단일 DNS 레코드 만 필요합니다. 그러면 A 레코드를 사용하여 응용 프로그램에 트래픽을 프록시합니다.

![그림 1: 표준 fallback 근원 체제.](~/assets/images/reference-architecture/extending-cloudflares-benefits-to-saas-providers-end-customers/standard-fallback-origin-setup.svg "Figure 1: Standard fallback origin setup.")

1. 사용자 지정 hostname(`custom.example.com`)은 공급자의 fallback origin을 가리키는 CNAME 레코드로 구성됩니다. fallback origin은 사용자 지정 hostname으로 요청이 들어왔을 때 Cloudflare가 기본적으로 트래픽을 전달하는 서버 또는 서버 집합입니다. 이 DNS 레코드는 Cloudflare 내부에서 관리될 필요는 없으며, 공급자가 제공하는 Cloudflare 호스팅 레코드(`fallback.myappexample.com`)를 가리키기만 하면 됩니다.
2. Fallback Origin은 Origin 서버의 공개 IP 주소에 대한 A 레코드로 설정됩니다. Cloudflare는 기본적으로 이 근원 서버에 주문 hostnames에 전송된 교통을 경로를 것입니다.

Origin 서버는 사용자 정의 도메인의 세부 정보를 수신합니다.[호스트 헤더 또는 SNI](/cloudflare-for-platforms/cloudflare-for-saas/reference/connection-details/). 이것은 원시 서버를 사용하여 요청을 지시하는 응용 프로그램을 결정합니다. 이 방법은 custom hostnames (예를 들면,`app.mycustomerexample.com`)와 허영 도메인 (예를 들면,`customer1.myappexample.com`). 응용 프로그램에 대한 모든 요청은 이제 Cloudflare 네트워크를 통해 경로를 따라, 다음을 포함한 모든 요청에 대한 보안 및 성능 서비스를 활용할 수 있습니다.

### 지역 서비스로 표준 fallback Origin 설정

이 접근법은 Cloudflare의 사용을 소개합니다[지역 서비스](/data-localization/regional-services/)TLS 종료 및 HTTP 처리를 지역화에 대한 해결책은 특정 지리적 위치에 서비스 프로세스 데이터를 결정하는 모든 준수 규정을 확인합니다. 이 서버는 선택된 영역 내에서만 처리됩니다.

![Figure 2: 지역 서비스로 표준 fallback Origin 설정.](~/assets/images/reference-architecture/extending-cloudflares-benefits-to-saas-providers-end-customers/standard-fallback-origin-setup-regional-services.svg "Figure 2: Standard fallback origin setup with regional services.")

1. 사용자 정의 hostname (`custom.example.com`) CNAME 레코드로 구성하여 지역화 된 SaaS 호스트 이름 (`eu-customers.myappexample.com`). 이 구성은 TLS 종료를 포함한 모든 처리가 지정된 지리적 영역 내에서만 발생합니다.
2. 지역화된 SaaS hostname은 CNAME 레코드로 설정되어 표준 트래픽을 전달합니다.[회사 소개](/cloudflare-for-platforms/cloudflare-for-saas/start/getting-started/#1-create-fallback-origin)SaaS 공급자의 (`fallback.myappexample.com`).
3. fallback 근원은 근원 서버의 공중 IP 주소에 점을 점하는 A 기록으로 설치됩니다. Cloudflare는 기본적으로 이 근원 서버에 주문 hostnames에 전송된 교통을 경로를 것입니다.

### 모델 번호: Cloudflare 지역 서비스로 fallback Origin 설정

향상된 보안을 위해 일반 IP를 통해 인터넷에 직접 애플리케이션 서버를 탐색하는 것보다 SaaS 공급자는 사용할 수 있습니다.[모델 번호: Cloudflare 연락처](/cloudflare-one/networks/connectors/cloudflare-tunnel/). 이 갱도는 Cloudflare의 가장 가까운 자료 센터에 당신의 네트워크를 연결하고, SaaS 신청을 통해 접근될 수 있습니다[공유 hostnames](/cloudflare-one/networks/connectors/cloudflare-tunnel/routing-to-tunnel/). 결과적으로, Cloudflare는 당신의 신청 네트워크로 공중 인터넷에서 최종 사용자를 위한 유일한 입장 점이 됩니다.

![그림 3: Cloudflare 갱도는 지역 서비스를 가진 Fallback 근원 체제로.](~/assets/images/reference-architecture/extending-cloudflares-benefits-to-saas-providers-end-customers/cloudflare-tunnel-fallback-origin-setup-regional-services.svg "Figure 3: Cloudflare Tunnel as Fallback Origin Setup with Regional Services.")

1. 사용자 정의 hostname (`custom.example.com`) CNAME 레코드로 구성하여 지역화 된 SaaS 호스트 이름 (`eu-customers.myappexample.com`). 이 구성은 TLS 종료를 포함한 모든 처리가 지정된 지리적 영역 내에서만 발생합니다.
2. 지역화된 SaaS hostname은 CNAME 레코드로 설정되어 표준 트래픽을 전달합니다.[회사 소개](/cloudflare-for-platforms/cloudflare-for-saas/start/getting-started/#1-create-fallback-origin)SaaS 공급자의 (`fallback.myappexample.com`).
3. fallback 기원은 CNAME DNS 레코드입니다.[공유 hostname](/cloudflare-one/networks/connectors/cloudflare-tunnel/routing-to-tunnel/)Cloudflare 갱도에 의해 드러내는. 이 공개 hostname은 애플리케이션에 대한 트래픽을 경로로 구성해야 합니다. 예를 들어,`localhost:8080`.

이 설정은 granular load balancing이 필요없는 SaaS 공급자에 이상적입니다.[Geo 기반 트래픽 스티어링](/load-balancing/understand-basics/traffic-steering/)다수 근원 서버의 맞은편에. 그것은 또한 간단한 테스트 및 개발 환경에 적합, 어디[당신의 근원 서버 보호](/fundamentals/security/protect-your-origin-server/)Cloudflare 터널을 통해서만 요청할 수 있습니다. 그러나, 글로벌 및 지역 수준에서 균형 잡힌 부하를 요구하는 분산 응용 프로그램에 대한, 우리는 사용하는 것이 좋습니다[Cloudflare의 짐 균형](/load-balancing/)글로벌 네트워크 로드 밸런싱 기능으로

### Global Traffic Management (GTM) & Private Network Load Balancing as custom Origin 설정

Cloudflare는 적재 균형을 잡는 기능의 강력한 세트를 제안합니다. 이러한 SaaS 애플리케이션이 호스팅되는 다른 소스 서버로 신뢰할 수 있는 스티어 트래픽을 신뢰할 수 있게 해 줍니다. 이 설정은 여러 서버에서 트래픽을 배포하고 Cloudflare 터널을 통해 요청을 허용하여 보안을 향상시킵니다.

![Figure 4: Global Traffic Management (GTM) & Private Network Load Balancing as custom Origin 설정.](~/assets/images/reference-architecture/extending-cloudflares-benefits-to-saas-providers-end-customers/gtm-ltm-custom-origin-setup.svg "Figure 4: Global Traffic Management (GTM) & Private Network Load Balancing as custom origin setup.")

1. 사용자 정의 hostname (`custom.example.com`)는 Cloudflare에 점유하는 CNAME 기록으로 형성됩니다[지역화된 Load Balancer](/data-localization/how-to/load-balancing/) (`eu-lb.myappexample.com`). TLS termination을 포함한 모든 처리가 지정된 지역 내에서 이루어집니다. 또한 SaaS 공급자는 Load Balancer를 설정해야 합니다.[주문 근원](/cloudflare-for-platforms/cloudflare-for-saas/start/advanced-settings/custom-origin/)사용자 지정 hostname에 대 한.
2. 지역 짐 밸런서는 설정[주변 명소 보기](/load-balancing/pools/)여러 다운스트림 서버에서 요청을 배포합니다. 각 풀은 구성할 수 있습니다.[공유 hostnames](/cloudflare-one/networks/connectors/cloudflare-tunnel/routing-to-tunnel/)글로벌 트래픽 관리(GTM) 또는[개인 네트워크](/cloudflare-one/networks/connectors/cloudflare-tunnel/private-net/)Private Network Load Balancing과의 주소. 위의 다이어그램에서 우리는 두 가지 옵션을 사용합니다.
   - Origin 풀 1 사용[모델 번호: Cloudflare 터널 hostname](/cloudflare-one/networks/connectors/cloudflare-tunnel/routing-to-tunnel/dns/) (`<UUID>.cfargotunnel.com`) 그 요청을 처리하기위한 endpoint 또는 Origin 서버로.
     공개 호스트명을 사용할 때, 설정해야 합니다.[HTTP 호스트 헤더 값](/load-balancing/additional-options/override-http-host-headers/)public hostname 구성 및 노출에 일치[Cloudflare 갱도](/cloudflare-one/networks/connectors/cloudflare-tunnel/). 이것은 근원 서버가 들어오는 요구에 정확하게 갈 수 있다는 것을 보증합니다.
   - Origin Pool 2는 개인 IP 주소 또는 개인 네트워크 (즉,`10.0.0.5`) SaaS 공급자의 내부 네트워크 내에서, SaaS 애플리케이션이 되다. 이 풀은 지정된 곳에서 작동하도록 구성되어야 합니다.[가상 네트워크](/cloudflare-one/networks/connectors/cloudflare-tunnel/private-net/cloudflared/tunnel-virtual-networks/)요청의 적절한 여정을 보장합니다.
3. 모델 번호: Cloudflare 터널은 모두 노출[공유 hostnames](/cloudflare-one/networks/connectors/cloudflare-tunnel/routing-to-tunnel/)GTM와 함께[개인 네트워크](/cloudflare-one/networks/connectors/cloudflare-tunnel/private-net/)(private IPs) 개인 네트워크 부하 균형.

응용 프로그램 제공 및 확장성에 향상된 과립을 위해, 그것은 일반적으로 공공 호스트 이름보다 개인 네트워크를 사용하는 것이 좋습니다. 개인 네트워크는 Cloudflare를 활성화하고 정확하게 호스트 헤더를 Origin 서버에 전달합니다. 대비, 공개 호스트명을 사용할 때, 공급자는 구성해야 합니다.[헤더 값](/load-balancing/additional-options/override-http-host-headers/)load balancer endpoint 당 1개의 public hostname에 제한되는 load balancer에, 잠재적으로 융통성을 제한하는.

Zero Trust의 인식[터널 제한](/cloudflare-one/account-limits/#cloudflare-tunnel)SaaS를 위한 Cloudflare[연결 요청 세부사항](/cloudflare-for-platforms/cloudflare-for-saas/reference/connection-details/), 그리고 주문 근원[SNI 명세](/cloudflare-for-platforms/cloudflare-for-saas/start/advanced-settings/custom-origin/#sni-rewrites). Cloudflare Load Balancer에 대한 자세한 내용은 리뷰를 참조하십시오.[참고 자료 건축](/reference-architecture/architectures/load-balancing/).
