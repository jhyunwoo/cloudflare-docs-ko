## 제품정보

보호 DNS 서비스는 DNS 쿼리를 분석하고 악성 웹 사이트 및 기타 유해한 온라인 콘텐츠에 대한 액세스를 차단하는 보안 서비스입니다. 기술이 공공 부문 운영을 위해 점점 더 중요 해지고, 정부 부서는 이러한 사이버 보안 서비스를 bolster 사건 감지 및 응답에 채택하고 더 탄력있는 기업 네트워크를 구축 할 수 있습니다. 전통적으로, 이 유형의 솔루션을 배치하는 것은 필수 비용으로 온프레미스 하드웨어를 요구하는 레거시 시스템의 신뢰성 때문에 상당한 도전. 이것은 배포 및 관리가 어렵고 확장성과 가용성을 가진 포스트 배포 투쟁을 소개합니다.

오늘 이러한 제한은 클라우드 기반 솔루션을 통해 해결 될 수 있습니다.[Cloudflare 게이트웨이](/cloudflare-one/traffic-policies/), 우리의 안전한 웹 출입구 서비스. 모델 번호: Cloudflare Gateway의 DNS 필터링 기능은 관리자가 향상된 보안을 제공합니다. Cloudflare에 의해 역행된 정책을 쉽게 창조하십시오[광범위한 위협 인텔리전스](https://www.cloudflare.com/en-gb/security/), 정부 기관은 효과적으로 잠재적으로 액세스에서 최종 사용자를 보호 할 수 있습니다[유해 도메인](/cloudflare-one/traffic-policies/domain-categories/#security-categories). 또한, 대행사는 이러한 방어력을 강화할 수 있습니다.[자신의 위협 인텔리전스 데이터를 통합](https://developers.cloudflare.com/security-center/indicator-feeds/)정책에.

마지막으로, Cloudflare Gateway는 가용성, 성능 및 확장성에 대한 우려를 제거하여 내장되어 있습니다.[Cloudflare의 1.1.1.1 공개 DNS 해결자](/1.1.1.1/), 중 하나[빠른 속도](https://www.dnsperf.com/#!dns-providers)세계에서 가장 널리 사용되는 DNS 해커.

## 제품정보

Cloudflare는 가동 가능한 DNS 배치 모형을, 위치와 관계없이 각 사용자를 위한 튼튼한 보호를 전달합니다. 서비스 지원 사무실 기반 및 원격 사용자 모두, 다양한 운영 요구 사항을 해결하기 위해 필요한 적응성 제공.

### Office 또는 사이트 기반 사용자

IT 관리자는 Cloudflare에 공개 DNS 요청을 전달하고 구성 된 DNS 필터링 정책에 따라 로그인합니다. DNS 포워더는 원격 사이트에서 배포되는 라우터와 같은 기관의 개인 DNS 인프라 또는 네트워킹 기기가 될 수 있으며 로컬 DNS 서버로 구성됩니다.

![그림 1: DNS 요청은 다양한 방법을 통해 Cloudflare에 전달될 수 있습니다.](~/assets/images/reference-architecture/gateway-for-protective-dns/gateway-for-protective-dns-image-01.svg "Figure 1: DNS requests can be forwarded to Cloudflare via a variety of different methods.")

정부 부서 및 기관에서 시작된 쿼리를 구별하기 위해, 관리자는 Cloudflare 대시보드의 위치를 구성합니다. DNS 위치가 생성될 때 게이트웨이는 TLS/HTTPS(DoT/DoH) 호스트명을 통해 IPv4/IPv6 주소와 DNS를 할당합니다. 이러한 IP 주소와 호스트명은 관리자가 DNS 쿼리를 해결하는 데 사용됩니다. 차례로, 관리자는 DNS 서버의 공개 IP 주소를 가진 위치 객체를 구성하고, Cloudflare를 사용하여 해당 위치로 쿼리를 정확하게 준수합니다.

DNS 필터링은 관리자가 연결된 도메인을 감지하기 위해 설정된 정책을 통해 시행됩니다.[보안 위험](/cloudflare-one/traffic-policies/domain-categories/#security-categories). Cloudflare 지속적으로 높은 위험 도메인의 목록을 업데이트[강력한 위협 인텔리전스](https://www.cloudflare.com/security/). DNS 쿼리가 떠난 도메인을 일치할 때, DNS 정책에서 지정된 해당 동작이 실행됩니다. 이 작업은 '[제품정보](/cloudflare-one/traffic-policies/dns-policies/#block)Gateway가 응답하는 곳`0.0.0.0`IPv4 쿼리 또는`::`IPv6 쿼리를 위해, 또는 표시[Cloudflare에 의해 호스팅되는 주문 구획 페이지](/cloudflare-one/reusable-components/custom-pages/gateway-block-page/). 대안으로,[관련 제품](/cloudflare-one/traffic-policies/dns-policies/#override)활동 또는[블록 페이지 URL 리디렉션](/cloudflare-one/reusable-components/custom-pages/gateway-block-page/#redirect-to-a-block-page)정부 기관에서 호스팅 한 블록 페이지로 DNS 쿼리를 리디렉션 할 수 있습니다.

Cloudflare의 자신의 위협 인텔리전스는 기관 또는 제삼자 근원에 의해 제공된 위협 인텔리전스 자료와 이음새가 없는 통합될 수 있습니다. 이 설정에서 기관 또는 제 3 자 단체는[위협 공급 업체](/security-center/indicator-feeds/)Cloudflare에. IT 관리자는 Cloudflare의 보안 위험 범주와 통합 및 향상된 보안 자세 (아래 다이어그램 참조)에 대한 기관에 의해 소스 데이터로 결합 DNS 정책을 만들 수 있습니다. 또한,[publicly 유효한 주문 지시자 급식](/security-center/indicator-feeds/#publicly-available-feeds)공급자 관계를 수립하고 보안 역량을 확장하는 데 필요한 필요 없이 해당 공공 및 민간 부문 조직에 접근할 수 있습니다.

![Figure 2 : 사용자 정의 위협 인텔 피드의 사용을 보여주는 DNS 정책.](~/assets/images/reference-architecture/gateway-for-protective-dns/gateway-for-protective-dns-image-02.svg "Figure 2: Example DNS policy showing the use of a custom threat intel feed.")

### 원격 사용자

기관 네트워크에 연결되지 않은 사용자의 경우, HTTPS를 통해 DNS를 사용하여 Cloudflare에 DNS 요청을 리디렉션할 수 있습니다 ([사이트맵](/cloudflare-one/networks/resolvers-and-proxies/dns/dns-over-https/)) 제공된 호스트명[이름 \*](/cloudflare-one/networks/resolvers-and-proxies/dns/locations/). 이것은 요구합니다[각 장치의 구성](/cloudflare-one/networks/resolvers-and-proxies/dns/dns-over-https/#filter-doh-requests-by-location)기존 관리 솔루션을 사용하여 수행 할 수 있습니다. 이 접근법은 통합에 의해 강화될 수 있습니다[사용자별 인증 토큰](/cloudflare-one/networks/resolvers-and-proxies/dns/dns-over-https/#filter-doh-requests-by-user). 이 토큰은 Cloudflare를 사용하여 개별 사용자에게 DNS 쿼리를 속성하고 사용자 별 정책의 응용 프로그램을 촉진합니다.

고급 정체 기반 DNS 정책을 위해 Cloudflare의 장치 에이전트가 배포 될 수 있습니다. 이 설정에서, 사용자는 장치 에이전트를 통해 인증[Cloudflare와 통합된 ID 공급자](/cloudflare-one/integrations/identity-providers/). 대리인은 그 때 안으로 형성됩니다[DNS만 모드](/cloudflare-one/team-and-resources/devices/warp/configure-warp/warp-modes/#dns-only-mode), 장치의 모든 공공 DNS 쿼리가 Cloudflare로 전달된다는 것을 보증합니다. 이 쿼리는 장치에서 사용자 ID를 포함, ID 기반 정책 시행을 가능하게.

![그림 3: 원격 사용자가 Cloudflare를 통해 보호에 대 한 DNS 요청을 리디렉션 하는 방법을 보여주는.](~/assets/images/reference-architecture/gateway-for-protective-dns/gateway-for-protective-dns-image-03.svg "Figure 3: Showing how remote users can also redirect DNS requests for protection via Cloudflare.")

다음 정책은 Identity 공급자로부터 그룹 정보를 어떻게 특정 보호 DNS 정책을 적용하기 위해 사용될 수 있는지 보여줍니다.

![그림 4 : 장치 에이전트와 사용자를위한 DNS 정책의 예. 본 방침은 정체성 공급자로부터 그룹 정보를 사용하므로 사용자의 특정 청중에 적용됩니다.](~/assets/images/reference-architecture/gateway-for-protective-dns/gateway-for-protective-dns-image-04.svg "Figure 4: An example of a DNS policy for users with the device agent. The policy uses group information from the identity provider so that it applies to a specific audience of users.")

장치 대리인은 호환이 됩니다[데스크탑 및 모바일 운영 시스템](/cloudflare-one/team-and-resources/devices/warp/download-warp/), 관리 및 관리되지 않은 장치 모두에 대한 솔루션을 만들기. 이 다양성은 DNS 보안 서비스를 확장 할 수 있습니다. 예를 들어, high-risk 개인의 개인 기기에 위치 또는 장치와 관계없이 보호의 일관성을 보장합니다. 관리된 IT 장치를 위해, 우리의 대리인은 지원합니다[관리 도구](/cloudflare-one/team-and-resources/devices/warp/deployment/mdm-deployment/), 배포 및 업그레이드의 용이.

## 추가 기능

모델 번호: Cloudflare Gateway는 보호 DNS를 넘어가는 종합적인 서비스를 제공합니다.[보안 웹 게이트웨이](https://www.cloudflare.com/learning/access-management/what-is-a-secure-web-gateway/). 그것은 HTTP 검사를 지원하고, 사용자 소통량에 더 깊은 가시성을 제공하고, 사용자가 사용할 수있는 위협 보호 및 데이터 보안 기능의 범위를 확장합니다.

HTTP 트래픽을 검사 할 때 Cloudflare는 데이터 센터의 HTTPS 요청을 해독, 검사 및 재 암호화하여 방해를 방지합니다. 모델 번호: Cloudflare 게이트웨이는 나머지와 모든 캐시 디스크에서 캐시 콘텐츠를 저장합니다. 또한 TLS decryption이 있는 서버의 지리적 영역을 구성할 수 있습니다.[지역 서비스](/data-localization/regional-services/)Cloudflare에서[데이터 로컬라이제이션 스위트](/data-localization/)(DLS) 및 조직은 장치 또는에 Cloudflare 인증서를 추가 할 수있는 능력을 가지고[자신의 인증서 사용](/cloudflare-one/team-and-resources/devices/user-side-certificates/custom-certificate/)(BYOPKI) 사용자 트래픽 해독 및 검사.

### 위협 보호

언제 Cloudflare Gateway는 HTTP 검사를 수행하고 DNS 보안을 넘어 보호 기능을 확장하여 사용자가 인터넷을 검색 할 수 있도록 추가 기능을 제공합니다.

- **안티 바이러스 스캐닝 (AV) :**&#xC0AC;용자는 인터넷에서 파일을 다운로드하거나 업로드할 때 보호됩니다.[파일이 스캔됨](/cloudflare-one/traffic-policies/http-policies/antivirus-scanning/)악의적인 내용을 감지하는 실시간.
- **모래로 덮기:**&#xC774;전에 본 파일에 대해서는 Cloudflare 게이트웨이[분석을위한 안전한 sandbox 환경에서 quarantine](/cloudflare-one/traffic-policies/http-policies/file-sandboxing/). 이 sandbox에서, Cloudflare는 파일의 행동을 모니터링하고 알려진 악성 코드 패턴에 대해 비교합니다. 파일은 악성 콘텐츠가 감지되지 않은 경우 사용자에게만 공개됩니다.
- **원격 브라우저 고립 (RBI):** [고립 정책](/cloudflare-one/remote-browser-isolation/)잠재적 위험 웹 사이트에 액세스 할 때 사용자를 보호 할 수 있습니다. 예를 들어,[사용자가 고립 정책을 트리거하는 새로 본 도메인을 방문하는 경우](/cloudflare-one/remote-browser-isolation/isolation-policies/), 웹 사이트의 활성 콘텐츠는 가장 가까운 Cloudflare 데이터 센터에서 호스팅되는 안전한 격리 된 브라우저에서 실행됩니다. 이것은 제로 데이 공격과 악성 코드가 사용자에 영향을 미칠 수 있기 전에 mitigated 것을 보장합니다. 이 원격 브라우징 경험은 원활하고 투명하며 사용자가 선호하는 브라우저와 워크플로우를 계속 사용할 수 있습니다. 모든 브라우저 탭과 창은 자동으로 격리되고 세션은 닫힐 때 삭제됩니다.

### 데이터 보호

위협 보호 외에도 Cloudflare Gateway는 HTTP 검사 중에 강력한 데이터 보호 정책을 구현할 수 있습니다.

- **파일 업로드 컨트롤:**&#xAD00;리자는 모니터링 및 정책 시행[파일 제한](/cloudflare-one/traffic-policies/http-policies/#download-and-upload-file-types)인터넷에, 민감한 데이터의 inadvertent 공유를 방지.
- **데이터 손실 방지 (DLP):** [DLP 정책](/cloudflare-one/data-loss-prevention/)기밀 또는 분류 된 정보의 무단 공유를 식별하고 차단할 수 있습니다. 더 자세한 내용을 보려면[transit에서 데이터 확보](/reference-architecture/diagrams/security/securing-data-in-transit/).
- **원격 브라우저 고립 (RBI):**&#xC704;협 보호를 넘어,[관련기관](/cloudflare-one/remote-browser-isolation/)시행일자[사용자 행동 제한](/cloudflare-one/remote-browser-isolation/isolation-policies/#policy-settings)검색 결과를 찾을 수 없음 한국어 사전에 온라인 구직 추가 정보, 참조[사용중인 데이터 확보](/reference-architecture/diagrams/security/securing-data-in-use/).

## 보안 웹 게이트웨이로 Cloudflare 게이트웨이 채택

확장 Cloudflare 보호 DNS 서비스의 게이트웨이는 전체 기능을 갖춘 보안 웹 게이트웨이가 바로 프로세스입니다. Cloudflare의 대시보드를 사용하여, IT 관리자는 구성할 것입니다[HTTP 정책](/cloudflare-one/traffic-policies/http-policies/)기존 DNS 정책 외에. 이 HTTP 정책은 추가 보호, 즉, 안티 바이러스 스캐닝, 샌드 박스, 원격 브라우저 고립 (RBI) 및 데이터 손실 방지 (DLP)을 가능하게합니다.

사용자의 관점에서 원격 Workers는 동일한 장치 대리인을 사용하여 계속할 것입니다. 이러한 향상된 보호를 활용하려면 장치 에이전트 모드를 전환해야 합니다.[교통 및 DNS 모드](/cloudflare-one/team-and-resources/devices/warp/configure-warp/warp-modes/#traffic-and-dns-mode-default). 이 형태는 또한 장치 관리를 사용하여 대리인을 배치하기 위하여 강제될 수 있습니다.

사무실 및 사이트 기반 사용자의 경우, 네트워크 어플라이언스는 설정할 수 있습니다.[Cloudflare에 IPsec 또는 GRE 갱도](/cloudflare-wan/). 이 설정은 Cloudflare 게이트웨이를 통해 모든 인터넷 바운드 트래픽을 우회하여 보안 정책이 인터넷에 접근하기 전에 적용됩니다. 대안으로,[프록시 자동 구성 파일 (PAC)](/cloudflare-one/networks/resolvers-and-proxies/proxy-endpoints/)Cloudflare를 향한 DNS 및 HTTP/S 트래픽을 전달할 수 있습니다.
