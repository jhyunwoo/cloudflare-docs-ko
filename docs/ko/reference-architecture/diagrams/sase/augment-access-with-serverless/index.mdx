## 제품정보

Zero Trust Network Access (ZTNA) 서비스를 사용하여 회사는 사용자가 개인적으로 호스팅 된 Wiki 서버 또는 소스 코드 저장소와 같은 보호 된 리소스에 액세스 할 수 있는지 결정하는 정책을 구축합니다. Policies는 일반적으로 그룹 회원, 인증 방법, 장치 보안 자세를 사용하여 사용자가 리소스에 액세스 할 수 있습니다.

보안 액세스는 평가에 대한 정책 엔진에 사용할 수있는 속성의 범위를 요구합니다. Cloudflare의 ZTNA 서비스로,[오시는 길](/cloudflare-one/access-controls/policies/), 액세스 결정에 필요한 데이터의 일부를 제공하는 또 다른 API에 대한 외부 요청을 포함 할 수 있습니다.

예를 들어, 하드 토큰을 필요로하는 자격 증명으로 인증 된 그룹 "Engineers"의 모든 구성원을 해당하는 정책이있을 수 있습니다. 자체 호스팅 소스 코드 저장소에 액세스 할 수 있습니다. 그러나 보안 훈련을 완료 한 엔지니어만 할 수 있습니다. 그 데이터는 다른 시스템에서 사용할 수 있으므로 Cloudflare를 사용하면 정책 검사의 일부로서 전화가 사용 가능[모델 번호: Workers](https://workers.cloudflare.com/)이 사용자가 보안 훈련을 통과했는지 결정하는 교육 시스템에.

또한 한 번 인증 및 정책 검사는 성공적인 Cloudflare는 보호 된 기원에 트래픽을 전달합니다. 원본이 있어야한다는 점에 중요합니다. 수신 요청이 Cloudflare에서 illegitimate 액세스 방지를 위해 인증된다는 것을 확인하십시오. Cloudflare는 요청이 성공적으로 정정되었는지 증명하기 위해 원래의 트래픽에 JWT 토큰을 삽입하고, 기원은 이 데이터를 저자화 논리의 일부로 사용할 수 있습니다.

이러한 유형의 사용 사례를 통합하려면 Cloudflare는[전체 개발 플랫폼](/workers/)당신이 디자인하고 당신의 자신의 사업 논리를 실행할 수 있는 곳에. 이것은 당신이 더 적은 시간을 보내고 함께 솔루션을 만들고 더 많은 시간을 통합 완료.

이 문서는 Cloudflare를 강화하는 해결책 둘 다 결합하는 방법 이용 약관[인증 및 인증](https://www.cloudflare.com/learning/access-management/what-is-access-control/).

## 사용 사례

- **주문 승인 논리**: Workers를 사용하여 외부 평가에 접근하십시오 (예를 들면, 당신의 자신의 구현을 사용하여[오픈 정책 에이전트 aka OPA](https://www.openpolicyagent.org/integrations/cloudflare-worker/)])
- **제품정보[JSON 웹 토큰 (JWT)](/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/validating-json/)**: Cloudflare의 자체 인증 JWT 자료를 사용하여, 예를 들어, 수신 요청의 일부로 자세 세부 정보를 추가합니다.
- **Zero-trust로 보호되는 Serverless 증강 앱**: 네이티브 ZTNA 기능에서 혜택을 받을 수 있는 Serverless 애플리케이션을 구축할 수 있음

## 시작하기

조직이 자신의 맞춤형 비즈니스 논리를 실행할 수 있는지 다음 개요를 통해 거의 모든 요구 사항을 충족시키기 위해 맞춤 인증 및 인증 프로세스를 맞춤화 할 수 있습니다. 아래 각 사용 케이스는 위의 다이어그램의 단계에 나타납니다.

### 1. 당신의 자신의 규칙을 사용하여 주문 승인 과정

정책 평가 중[외부 평가](/cloudflare-one/access-controls/policies/external-evaluation/)규칙은 액세스 정책 평가에서 자신의 코드를 실행할 수 있습니다. 이 예제에서 Cloudflare Workers에 의해 노출 된 API는 요청을 만드는 사용자에 대한 데이터를받습니다. 중요한 부분은 사용자 이름입니다.

코드는 일반적으로 호출 할 수[관련 기사](/d1/)또는 다른 API는 전달된 사용자가 응용 프로그램에 액세스하는 경우를 평가합니다. 외부 평가 규칙은 전화가 True 또는 False 중 하나를 반환하고, 이것은 접근을 결정하는 정책과 결합됩니다.

<LinkCard title="더 알아보기" description="Cloudflare의 외부 평가 기능을 가진 외부 허가" href="/cloudflare-one/access-controls/policies/external-evaluation/" />

### 2. 분석 및 인증 자료 검증 (JWT)

사용자가 성공적으로 인증하고 보호 응용 프로그램에 액세스 할 수있는 권한이있을 때 Cloudflare 삽입[JSON 웹 토큰 (JWT)](/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/validating-json/)HTTP 트래픽으로 인해 기원에 전송. 이 토큰은 안전한 처리를 통해 맞춤형 비즈니스 로직을 확장하는 귀중한 자산 역할을 합니다. JWT의 형식은 현명하고 오히려 경량이며 기원에 대한 요청에 대한 과부하를 방지합니다.

원래에 보낸 JWT의 예입니다 (사용[사이트맵](http://jwt.io)JWT의 내용을 읽으려면

```json title="JWT content"
{
	"aud": ["264063895705477af73bfbaed1bf401981f4812eefcdb9fea33f5e10e666e282"],
	"email": "john.doe@cloudflare.com",
	"exp": 1728551137,
	"iat": 1728464737,
	"nbf": 1728464737,
	"iss": "https://myorg.cloudflareaccess.com",
	"type": "app",
	"identity_nonce": "IA0hPRvwILtbUXSQ",
	"sub": "ce40d564-c72f-475f-a9b8-f395f19ad986",
	"device_id": "8469d7c4-83a9-11ee-b559-76e6e80876db",
	"country": "FR"
}
```

Cloudflare는 특정한 노출합니다[끝점](/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/validating-json/#_top)유효한 사람을 허용하고 Cloudflare 서명한 JWT를 확장하십시오.

Cloudflare의 Workers는 들어오는 JSON Web Tokens (JWTs)와 상호 작용을 위한 중대한 후보자, 어떤 추가 지연든지 소개 없이 serverless 플랫폼 안에 직접 추가 처리를 가능하게 합니다.

<LinkCard title="더 알아보기" description="Cloudflare 액세스 JWT를 검증하고 시각화하는 방법" href="/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/application-token/#user-identity" />

### 3. 추가 인증 세부 사항이있는 인증 자료 (JWT) 배치

일부 상황에서는 보호 대상 응용 프로그램에 추가 처리를 수행하기 위해이 JWT에 정교한 것이 좋습니다 (예를 들어, 장치를 추가[posture 세부사항](/cloudflare-one/reusable-components/posture-checks/)수신 요청의 일부로).

다음 예에서, 우리는 노출 된 응용 프로그램이 장치의 방화벽 및 디스크 암호화의 상태인지 확인하려면 (WARP 클라이언트가 수집 할 수있는 이러한 신호를 클라이언트 시스템에 설치해야합니다).

![Figure 2: posture 세부사항을 포함하여 수정된 근원 요구](~/assets/images/reference-architecture/augment-access-with-serverless/diagram2.svg "Figure 2: Modified origin request including posture details")
