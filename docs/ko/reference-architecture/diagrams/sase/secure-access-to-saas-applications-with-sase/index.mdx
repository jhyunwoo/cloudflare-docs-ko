## 제품정보

SaaS 애플리케이션은 오늘날의 비즈니스 운영에 필수적인 도구가 되었습니다. SaaS 애플리케이션이 IT 및 인프라 부담을 줄이면서 전통적인 아키텍처가 해결하는 새로운 보안 문제를 소개합니다. 오늘 많은 회사들은 경로를 통해 구현[Zero Trust 건축](https://zerotrustroadmap.org/), 몹시 보안 응용 프로그램에 ID, 장치 및 네트워크 정보를 결합합니다.

그러나 SaaS 애플리케이션은 보안 방식으로 데이터 저장과 같은 자체 플랫폼에 보안을 집중하고 애플리케이션 취약점으로 인해 애플리케이션이 고객 데이터를 폭발하지 않도록 합니다. 이 문서는 Cloudflare의 Secure Access Service Edge (SASE) 플랫폼을 사용하여 SaaS 애플리케이션의 제한을 해결하는 방법을 커버하는 것입니다. 특정 Zero Trust 네트워크 액세스 (ZTNA) 및 보안 웹 게이트웨이 (SWG) 서비스, 기존 정체성 및 장치 보안 공급 업체에 통합과 결합.

## SaaS는 이미 안전하지 않습니다?

SaaS 애플리케이션을 위한 SASE를 구현하는 구체적인 논의하기 전에, 우리는 요청해야 합니다: SaaS는 이미 안전하지 않습니까? Salesforce, ServiceNow, Microsoft 등과 같은 주요 공급자는 Single Sign On (SSO), SSL/TLS, 모든 응용 통신, 데이터 암호화 및 종합 감사 로그에 대한 ID 제공 업체와 통합을 포함하여 강력한 보안 기능을 구현했습니다. 불행히도, SaaS 공급 업체는 그들의 응용 프로그램에 전체 보안 플랫폼을 재 구축하려고하지 않습니다, 그래서 그들은 현대 Zero Trust 아키텍처에 필요한 많은 기능을 제공 할 수 없습니다.

SaaS 애플리케이션은 연결 장치의 보안 자세를 평가할 수 없습니다. 유효한 자격 증명을 가진 손상된 노트북은 안전하게 관리된, 기업 장치에 동일하. SaaS 애플리케이션에서 데이터를 다운로드할 때, 기기가 안전하게 다운로드되는지 여부를 파악할 수 없습니다. SaaS 애플리케이션의 전형적인 인증은 사용자를 ID 서비스로 리디렉션함으로써 외부화되므로 SaaS 애플리케이션은 사용자 인증 및 모든 신뢰가 정체성 공급자에 배치되는 방법을 의미하지 않습니다.

이러한 보안 문제는 가난한 네트워크 액세스 제어에 의해 합성됩니다 - 대부분의 SaaS 응용 프로그램은 어떤 인터넷 소스에서 연결을 허용하지만 때때로 그들은 하나 이상의 물리적 사무실과 관련 될 수있는 IP 주소의 특정 세트에서만 액세스 할 수 있습니다. 그러나 이러한 재정적인 네트워크 제어는 집에서 일하는 원격 사용자에 대한 확장 또는 액세스가 필요한 파트너 및 계약자.

Cloudflare의 SASE 플랫폼은 SaaS 애플리케이션을 확보하기 위해 더 많은 Zero Trust orientated 접근법을 가져올 수있는 능력을 제공합니다. 중앙화된 정책은 장치 자세, 정체성 특성 및 과립상 네트워크 위치에 근거하여 1개 또는 많은 SaaS 신청에 적용될 수 있습니다. Cloudflare는 새로운 기업 네트워크가되고, Cloudflare에 연결되는 그 사용자에게 인터넷 기반 SaaS 애플리케이션에 접근할 수 있습니다. 필수 클라우드의 새로운 기업 네트워크입니다.

## Cloudflare로 접근

아래 다이어그램은 Cloudflare가 SaaS 응용 프로그램에 액세스 할 수있는 사용자, 장치 및 네트워크 사이에 앉아있는 방법을 보여줍니다. 보안 기능을 proving 두 가지 주요 서비스:

- [Zero Trust 네트워크 접근](/cloudflare-one/access-controls/policies/). Cloudflare는 정체 프록시가 될 수 있으므로 다양한 정체 공급자와 단일 SaaS 애플리케이션에 쉽게 인증할 수 있습니다. 이 서비스는 또한 장치 자세 및 네트워크 위치에 따라 액세스 평가 기능을 통합합니다.
- [보안 웹 게이트웨이](/cloudflare-one/traffic-policies/). SaaS 애플리케이션에 액세스하는 모든 트래픽이 게이트웨이를 통해 흐르면 HTTPS 연결은 Cloudflare에서 종결되며 SaaS 애플리케이션에서 데이터 흐름을 검사할 수 있습니다. 이것은 당신이 insecure 위치에 수출되는에서 민감한 자료를 막을 수 있습니다.

![그림 1 : Cloudflare 네트워크 및 관련 정책을 통과 한 트래픽 만 SaaS 응용 프로그램에 액세스 할 수 있습니다.](~/assets/images/reference-architecture/secure-access-to-saas-applications-with-sase/figure1.svg "Figure 1: Only traffic that has passed the Cloudflare network and relevant policies is authorized to access the SaaS application.")

위의 다이어그램은 ZNTA 서비스가 인증 및 보안 웹 게이트웨이 필터를 SaaS 응용 프로그램에서 인바운드 및 아웃바운드 트래픽을 모두 보장하는 Cloudflare에 대한 트래픽이 다양한 방법을 보여줍니다.

1. SaaS 응용 프로그램에 대한 초기 요청은 SSO 흐름의 일부로 Cloudflare로 리디렉션됩니다. ZTNA 서비스는 기존 ID 공급자에 대한 사용자를 인증합니다.
2. 사용자, 인증 또는 아닙니다, 트래픽이 Cloudflare에서 소스되지 않은 경우 SaaS 응용 프로그램에 대한 액세스를 거부합니다.
3. SaaS 응용 프로그램은 Cloudflare 서버에서 실행되는 브라우저가 브라우저 고립을 사용할 수 있으며 렌더링 된 페이지의 결과는 사용자의 로컬 브라우저에 안전하게 전달됩니다.
4. 관리된 장치는 안전한 갱도를 사용하여 Cloudflare에 연결되고 그러므로 장치에서 SaaS 신청에 모든 커뮤니케이션은 거르고 확보됩니다.
   1. Cloudflare 대리인 장치 자세는 또한 이 장치에서 교통을 허가하기 위하여 통합될 수 있습니다.
5. 로컬 네트워크에 연결된 장치는 모든 인터넷 트래픽이 Cloudflare로 향하도록, Cloudflare와의 안전한 IPsec 터널을 통해 라우팅됩니다. 이 방식은 네트워크에서 SaaS 애플리케이션으로 가는 모든 트래픽이 필터링되고 보호되도록 보장합니다.
6. 트래픽은 보안 웹 게이트웨이를 통과하여 DNS 및 HTTP 정책이 트래픽에 적용될 수 있습니다.
   1. HTTP 정책은 DLP 프로파일을 사용하여 SaaS 응용 프로그램을 업로드하고 다운로드 한 데이터의 검사를 허용합니다.
7. 특정 IP를 가진 교통 egresses Cloudflare. SaaS 응용 프로그램은 그 주소에서 오는 모든 트래픽을 허용하도록 구성된다.

:::note\[XDR 플랫폼 통합]
Crowdstrike, Sentinel One 또는 Microsoft Intune과 같은 XDR 플랫폼과 통합 할 때 Cloudflare가 XDR 시스템 및 장치 자세 정보의 사용자와 정체성을 일치하기 때문에 Cloudflare가 인증 된 사용자에 대해도 사용할 수 있습니다.

## 예시정책

다음은 Cloudflare를 사용하여 Salesforce에 대한 액세스를 확보 할 수있는 방법을 보여주는 정책의 예입니다.

첫 번째 단계는 사용[Cloudflare Gateway의 IP 정책](/cloudflare-one/traffic-policies/egress-policies/). 게이트웨이를 통해 트래픽을 필터링하는 사용자들에게 특정 IP를 구매하고 할당할 수 있습니다. 그런 다음 Salesforce에서 액세스가 egress 정책에 일치하는 소스 IP와 트래픽을 허용한다는 것을 시행합니다. 이 조합은 Salesforce에 접근을 얻는 유일한 방법은 Cloudflare를 통해 입니다.

| Egress 정책                   |                |
| :-------------------------- | :------------- |
| **이름 \***                   |                |
| 사용자 그룹 이름                   | 모든 직원          |
| **Egress IP 선택**            |                |
| 전용 Cloudflare Egress IPs 사용 | `203.0.113.88` |

이것은 Salesforce에 대한 액세스를 확보하는 것이 중요하지 않지만 사용 중에 콘텐츠를 적절하게 보호하는 것이 중요합니다. 이제 Sales 또는 Executives 그룹의 구성원에 대한 액세스를 제한하는 액세스 정책을 검토하십시오. Crowdstrike 통합을 사용하여 사용자는 회사 관리 장치에 있습니다.

| 정책 이름           | 신뢰할 수있는 장치에 계정 임원 |
| :-------------- | :---------------- |
| - 연혁            | 지원하다              |
| **이름 \***       |                   |
| 그룹 멤버           | 판매, 임원            |
| **이름 \***       |                   |
| 인증 방법           | MFA - 멀티 팩터 인증    |
| 오시는 길           | 이름 \*             |
| Crowdstrike 서비스 | 전체 점수 80          |

이 두 번째 정책은 모든 직원에 적용하지만 액세스 권한을 부여하기 전에 몇 가지 단계를 적용하려고합니다.

| 정책 이름             | 신뢰할 수있는 장치의 직원                 |
| :---------------- | :----------------------------- |
| - 연혁              | 지원하다                           |
| **이름 \***         |                                |
| 그룹 멤버             | 모든 직원                          |
| **이름 \***         |                                |
| 인증 방법             | MFA - 멀티 팩터 인증                 |
| 오시는 길             | 이름 \*                          |
| Crowdstrike 서비스   | 전체 점수 80                       |
| **추가 설정**         |                                |
| 회사 소개             | 이름 \*                          |
| 임시 인증             | 이름 \*                          |
| approvers의 이메일 주소 | `salesforce-admin@company.com` |

이 두 번째 정책에 임시 인증을 추가하려고합니다. 즉, Cloudflare가 들어오는 요청이 Sales 또는 Executives 부서 외부에서 있다는 것을 결정하면 관리자는 명시적으로 임시 액세스를 부여해야합니다. 컨텍스트에서, 이 정책은 영업 부서 외부 직원을위한 Salesforce에 대한 액세스를 확보하기 위해 사용될 수있다, 고객 정보는 민감하고 기밀 할 수있다.

이 접근법은 몇몇 이유를 위해 중요합니다:

- 잠재적으로 위험한 액세스 시도에 대한 인간의 oversight를 허용, 손상 또는 insecure 장치를 통해 무단 액세스의 가능성을 감소.
- 그것은 합법적 인 사용자에 대한 유연성을 제공합니다 응용 프로그램에 액세스 할 때 장치가 가장 높은 보안 표준을 충족하는 실패. 이 기능은 사용자가 기기에서 좋은 보안 관행을 유지하도록 권장합니다.
- 또한, 모든 사용자 트래픽이 Cloudflare를 통해 경로를 통과했기 때문에 웹 트래픽 정책을 통해 추가 보안 조치를 시행 할 수 있습니다.

Cloudflare의 SASE 플랫폼은 SaaS 응용 프로그램에 액세스하기위한 보안 정책을 중앙화 할 수 있습니다. 또한 장치 자세 및 네트워크 속성을 활용할 수 있도록 보안을 향상시킵니다. SaaS 애플리케이션이 기본적으로 Cloudflare에 내장된 새로운 기업 네트워크를 통해 접근할 수 있는 방식으로 구성할 수 있습니다.
