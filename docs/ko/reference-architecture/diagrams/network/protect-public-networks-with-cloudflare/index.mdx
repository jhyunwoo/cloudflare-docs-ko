## 제품정보

네트워크 보안 팀은 DDoS 공격, 악성 코드, 랜섬웨어, 피싱 및 민감한 정보의 누출과 같은 외부 및 내부 위협에 대한 공공 직면 네트워크를 보호하기 위해 네트워크의 둘레에 다양한 네트워크 방화벽 또는 보안 기기를 사용했습니다. 그러나 이러한 방화벽 및 보안 기기는 종종 비싸고 복잡한 구성 및 관리, 큰 공격을 처리하기 어렵고, 신속하게 업그레이드 및 패치를 통합하여 새로 발견 된 위협과 취약성을 방어합니다.

[Cloudflare 마술 이동](/magic-transit/), [Cloudflare 네트워크 방화벽](/cloudflare-network-firewall/)·[Cloudflare 게이트웨이](/cloudflare-one/traffic-policies/)기본적으로 실행되는 서비스[Cloudflare의 대규모 글로벌 네트워크](https://www.cloudflare.com/network/)위의 모든 단점에 대한 해결책을 제공합니다. 이 서비스는 온라인, 자동, 확장 가능한 네트워크 보호를 제공합니다. 모든 인터넷 네트워크에 대한 네트워크 보호, 성능이 느리지 않고, 클라우드에서 온 프레미스 여부, 또는 두 가지 조합 (그, 하이브리드 아키텍처).

- [매직 트레인](https://www.cloudflare.com/network-services/products/magic-transit/)네트워크층 DDoS 공격에 대한 즉각적인 탐지 및 완화를 제공합니다.
- [Cloudflare 네트워크 방화벽](/cloudflare-network-firewall/)Magic Transit에 의해 보호되는 네트워크에서 트래픽을 필터링하는 데 사용할 수있는 클라우드 기반 네트워크 방화벽 서비스입니다. 기능도 지원[Intrusion 검출](/cloudflare-network-firewall/about/ids/)(IDS)와[패킷 캡처](/cloudflare-network-firewall/packet-captures/).
- [오시는 길](https://www.cloudflare.com/zero-trust/products/gateway/)보안 웹 게이트웨이 (SWG) 서비스는 DNS, 네트워크 및 HTTP 기반을 적용하면서 Cloudflare의 글로벌 네트워크를 통해이 트래픽을 프록시하여 네트워크에서 발생하는 인터넷 경계 트래픽을 검사하고 제어 할 수 있습니다[회사연혁](/cloudflare-one/traffic-policies/).

Magic Transit, Cloudflare Network Firewall 및 Gateway 작업 및 다양한 사용 사례를 위해 설계 될 수있는 방법에 대한 자세한 내용은 문서의 끝에서 링크 된 리소스에서 찾을 수 있습니다. 이 문서는 Cloudflare Magic Transit, Cloudflare 네트워크 방화벽 및 Cloudflare 네트워크 인프라를 보호하는 게이트웨이 서비스.

건축과 어떻게 작동하는지 설명하기 위해 다음과 같은 다이어그램은 공개 직면 네트워크의 세트와 함께 예를 나타냅니다. 이 네트워크는 5개의 명백한 위치에 배치됩니다, 온프레미스 둘 다 및 다수 공중 구름의 맞은편에.

```
AWS VPC: 192.0.2.0/24
GCP VPC: 198.51.100.0/24
Azure vNet: 203.0.113.0/26
On-premises data center 1: 203.0.113.64/26
On-premises data center 2: 203.0.113.128/25
```

## inbound 네트워크 트래픽 보호

아래 참고 자료 아키텍처 다이어그램은 Cloudflare Magic Transit과 Cloudflare 네트워크 방화벽이 인터넷에서 시작되는 인바운드 트래픽에서 공공 네트워크를 보호하는 데 사용할 수 있습니다.

![Figure 1: 인터넷에서 시작되는 inbound 트래픽에서 공공 네트워크를 보호합니다.](~/assets/images/reference-architecture/protect-public-networks-with-cloudflare/figure-1.svg "Figure 1: Protect the public networks from inbound traffic originating from the Internet.")

*참고: 이 이미지의 라벨은 이전 제품 이름을 반영할 수 있습니다.*

1. Border Gateway Protocol 사용[사이트맵](https://www.cloudflare.com/learning/security/glossary/what-is-bgp/))와[IP 정보](https://www.cloudflare.com/learning/cdn/glossary/anycast-network/)Cloudflare는 Cloudflare의 세계적인 자료 센터 전부에서 인터넷에 고객의 보호한 IP 접두사를 광고합니다. 이러한 보호 IP 접두사는 항상 트래픽의 소스에 가장 가까운 Cloudflare 데이터 센터에 갈 것이다 인터넷 트래픽.

   동시에, 온프레미스 네트워크(s) 및 클라우드 공급자 네트워크(s)는 각각의 on-premises 국경 라우터 및 클라우드 경계 라우터에서 동일한 정확한 접두사를 광고 중지할 것입니다. 이 모든 인터넷 트래픽은 Magic Transit 보호 IP 접두사는 Cloudflare 네트워크를 통해 추적됩니다.

   대신 인터넷에 국경 라우터에서 덜 특정 IP 접두사를 광고 할 수 있습니다. 이 방법, 매직 트랜지션 서비스 실패와 달리, 트래픽은 인터넷에서 네트워크 위치에 직접 다시 추적 할 수 있습니다.

2. 인터넷에서 시작되는 트래픽은 보호 된 IP 접두사에 운명은 글로벌 Cloudflare 네트워크로 나뉩니다.

3. 모든 DDoS 공격 트래픽은 고급 및 자동화를 사용하여 모든 Cloudflare 데이터 센터에서 mitigated 인라인입니다.[DDoS 완화](/ddos-protection/)기술.

4. DDoS 완화를 통과하는 트래픽은 포함되는 추가 방화벽 필터링에 적용됩니다.[Cloudflare 네트워크 방화벽](/cloudflare-network-firewall/)서비스.

5. 깨끗한, 필터링 트래픽은 개인을 통해 보호 된 네트워크로 경로를[Cloudflare 네트워크 상호 연결](/network-interconnect/)(CNI) 연결, 또는 GRE 또는 IPsec 터널을 사용하여 공공 인터넷. Magic Transit IP 터널에 대한 자세한 내용이 있습니다.[Magic Transit Tunnels 및 캡슐화 문서](/magic-transit/reference/gre-ipsec-tunnels/).

6. 서버 반환 트래픽은 Cloudflare 네트워크를 통해 인터넷에 도달[매직 트레인 Egress](/magic-transit/reference/egress/). 그것은 동일한 CNIs 또는 GRE, IPsec 갱도를 통해 Cloudflare 네트워크에 통과될 수 있습니다, 당신의 위치에 정책 근거한 여정 (PBR)와 같은 여정 기술을 사용하여 진입 소통량 traversed.

7. Magic Transit Egress 트래픽은 Cloudflare 네트워크 방화벽 필터링 대상입니다.

## 아웃바운드 네트워크 트래픽 보호

아래의 참고 자료 아키텍처 다이어그램 Cloudflare 서비스 - Magic Transit (Egress), Cloudflare 네트워크 방화벽 및 Cloudflare Gateway는 공공 네트워크에서 시작되는 아웃바운드 인터넷 트래픽을 보호하는 데 사용할 수 있습니다.

![그림 2 : 공공 네트워크에서 시작되는 아웃바운드 인터넷 트래픽을 보호합니다.](~/assets/images/reference-architecture/protect-public-networks-with-cloudflare/figure-2.svg "Figure 2: Protect outbound Internet traffic originating from the public networks.")

*참고: 이 이미지의 라벨은 이전 제품 이름을 반영할 수 있습니다.*

1. 공공 네트워크에서 Cloudflare로 시작하는 각 사이트 네트워크 경로 아웃바운드 인터넷 트래픽, 동일한 CNIs 및 IP 터널을 통해. 본 사이트는 정책 기반 라우팅 (PBR)과 같은 당신의 선택의 라우팅 기술을 통해 사이트에서 수행 할 수 있습니다.
2. Cloudflare 네트워크에 입력하면, 아웃바운드 인터넷 트래픽은 Cloudflare 네트워크 방화벽을 통해 첫 번째 경로입니다. 어떤 구성 네트워크 방화벽 정책에 따라.
3. 아웃바운드 인터넷 트래픽은 연속적으로 전송됩니다[Cloudflare 게이트웨이](/cloudflare-one/traffic-policies/), 각종 우리의 안전한 웹 출입구 서비스[회사연혁](/cloudflare-one/traffic-policies/)아웃바운드 트래픽에 대한 보안 및 제어 조치의 포괄적 인 세트를 시행하고 네트워크의 최대 보호를 보장합니다.
4. 한 번의 트래픽은 검사, Gateway 프록시는 인터넷의 대상에 아웃바운드 트래픽. 아웃바운드 트래픽의 소스 IP 주소는 게이트웨이 서비스와 관련된 Cloudflare 소유 IP 주소입니다.
5. 인터넷에서 트래픽을 반환, Cloudflare의 IP 주소 게이트웨이 서비스에 연결, Cloudflare의 글로벌 네트워크로 경로.
6. 교통은 Gateway 정책에 대해 검사됩니다.
7. 게이트웨이 검사를 통과하는 트래픽은 Cloudflare 네트워크 방화벽으로 더 많은 패킷 필터링을 우회합니다.
8. Cloudflare 네트워크 방화벽 필터링을 통과하는 트래픽은 Cloudflare에서 인터넷에 CNIs 또는 IP 터널을 통해 네트워크 위치에 전달됩니다.
