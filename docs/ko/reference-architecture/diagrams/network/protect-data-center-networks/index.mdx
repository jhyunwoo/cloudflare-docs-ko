## 제품정보

네트워크 보안 팀은 예를 들어, DDoS 공격, 악성 코드, 랜섬웨어, 피싱, 민감한 정보의 누출을 위해 외부 및 내부 위협에 대한 데이터 센터 네트워크를 보호하기 위해 둘레에 다양한 네트워크 방화벽 또는 보안 기기를 사용했습니다. 또한, 동일한 또는 추가 방화벽 또는 보안 기기가 배포됩니다.[프로젝트](https://en.wikipedia.org/wiki/DMZ_\(computing\))또는 데이터 센터 네트워크의 핵심 층은 다양한 데이터 센터 사이트 (WAN)를 통해 여러 데이터 센터 사이트 간의 내부 개인 네트워크 트래픽을 제어하고 보안합니다.

그러나 이러한 방화벽 및 보안 기기는 종종 비싸고 복잡한 구성 및 관리, 큰 공격을 처리하기 어렵고 새로 발견 된 위협과 취약성을 방어하기 위해 업그레이드 및 패치가 필요합니다.

[Cloudflare 마술 이동](/magic-transit/), [Cloudflare 대만](/cloudflare-wan/)(이전 매직 WAN),[Cloudflare 네트워크 방화벽](/cloudflare-network-firewall/)·[Cloudflare 게이트웨이](/cloudflare-one/traffic-policies/)기본적으로 실행되는 서비스[Cloudflare의 대규모 글로벌 네트워크](https://www.cloudflare.com/network/)위의 모든 단점에 대한 해결책을 제공합니다. 이 서비스는 단일 클라우드 네트워크 플랫폼에서 데이터 센터 네트워크에 대한 온라인, 확장 및 수행 글로벌 보호를 제공합니다.

- [매직 트레인](https://www.cloudflare.com/network-services/products/magic-transit/)네트워크층 DDoS 공격에 대한 즉각적인 탐지 및 완화를 제공합니다.
- [Cloudflare 대만](https://www.cloudflare.com/network-services/products/magic-wan/)개인, 엔터프라이즈 네트워크간에 하이브리드/멀티 클라우드 보안 연결을 제공합니다.
- [Cloudflare 네트워크 방화벽](/cloudflare-network-firewall/)Magic Transit에 의해 보호되는 네트워크에서 트래픽을 필터링하는 데 사용할 수있는 클라우드 기반 네트워크 방화벽 서비스입니다. 기능도 지원[Intrusion 검출](/cloudflare-network-firewall/about/ids/)(IDS)와[패킷 캡처](/cloudflare-network-firewall/packet-captures/).
- [오시는 길](https://www.cloudflare.com/zero-trust/products/gateway/)보안 웹 게이트웨이 (SWG) 서비스는 네트워크에서 시작되는 인터넷 바운드 트래픽을 검사하고 제어 할 수있는 보안 웹 게이트웨이 (SWG) 서비스뿐만 아니라 Cloudflare의 글로벌 네트워크를 통해 이러한 트래픽을 프록시하여 DNS, 네트워크 및 HTTP 기반[회사연혁](/cloudflare-one/traffic-policies/).

이 문서는 Cloudflare WAN, Cloudflare Network Firewall, Cloudflare Gateway 서비스를 사용하는 레퍼런스 아키텍처에 초점을 맞춥니다. 이 서비스들은 데이터 센터 네트워크의 외부 및 내부 통신을 보호하는 데 사용할 수 있습니다. Cloudflare WAN, Cloudflare Network Firewall, Cloudflare Gateway의 세부 기능으로는 다양한 사용 사례를 구현할 수 있으며, 문서 끝의 연결된 리소스에서 더 자세한 내용을 확인할 수 있습니다.

건축과 어떻게 작동하는지 설명하기 위해 다음과 같은 다이어그램은 인터넷 또는 개인, 내부 직면에 대한 사용자와 연결하는 공공장소 네트워크의 세트와 예를 시각화합니다. 기업 내에서 통신에 사용됩니다. 이 네트워크는 두 개의 온프레미스 위치에 배치됩니다. 공용 네트워크의 접두사는 Cloudflare Magic Transit에 의해 보호됩니다.

| 데이터 센터 1                 | 데이터 센터 2                 |
| :----------------------- | :----------------------- |
| 공공 네트워크:`192.0.2.0/24`   | 공공 네트워크:`203.0.113.0/24` |
| 개인 네트워크:`192.168.1.0/24` | 개인 네트워크:`172.16.2.0/24`  |

각 자료 센터에 가장자리 대패 (s)는 2개의 직접을 통해 Cloudflare 네트워크에 연결됩니다[Cloudflare 네트워크 상호 연결](/network-interconnect/)(CNI) 연결, 직접, 네트워크와 Cloudflare 네트워크 사이의 개인 연결. 직접 CNI 연결 중 하나는 공용 네트워크 트래픽을 운반하는 것입니다, 반면 다른 개인 네트워크 트래픽을 운반하는 것입니다. 선택적으로, 당신은 하나의 CNI 연결에 공공 및 개인 네트워크 트래픽을 수행 할 수 있지만 많은 조직은 보안 연습에 별도의 연결에 외부 및 내부 네트워크 트래픽을 수송하고자합니다.

- 데이터 센터 1, CNI 연결 1은 공공 네트워크 트래픽을 운송하는 데 사용되며 연결 2은 개인 네트워크 트래픽을 수송하는 데 사용됩니다.
- 데이터 센터 2를 위해, CNI 연결 3는 대중 교통 네트워크 트래픽을 수송하기 위하여 이용되고 연결 4는 개인적인 네트워크 트래픽을 수송하기 위하여 이용됩니다.

## 네트워크에 inbound 트래픽을 보호합니다.

아래 참고 자료 아키텍처 다이어그램은 Cloudflare Magic Transit 및 Cloudflare 네트워크 방화벽이 인터넷에서 시작되는 인바운드 트래픽에서 데이터 센터의 공개 네트워킹 네트워크를 보호하기 위해 사용될 수 있습니다.

![그림 1. Inbound 트래픽에서 공공 네트워크 보호.](~/assets/images/reference-architecture/protect-data-center-networks/figure1.svg "Figure 1. Protect Public-facing Networks from Inbound Traffic.")

*참고: 이 이미지의 라벨은 이전 제품 이름을 반영할 수 있습니다.*

1. Border Gateway Protocol 사용[사이트맵](https://www.cloudflare.com/learning/security/glossary/what-is-bgp/))와[IP 정보](https://www.cloudflare.com/learning/cdn/glossary/anycast-network/), Cloudflare는 고객의 보호한 IP prefixes를 전부에서 인터넷에 광고합니다[Cloudflare의 글로벌 데이터 센터](https://www.cloudflare.com/network/). 동시에, on-premises 네트워크 (s)는 그들의 각각 on-premises 국경 대패에서 동일한 정확한 접두사를 광고할 것입니다. 이 모든 트래픽이 Cloudflare를 통해 전달되기 전에 Magic Transit DDoS 보호 및 정책 시행을 보장합니다. 이러한 보호 IP 접두사는 항상 트래픽의 소스에 가장 가까운 Cloudflare 데이터 센터에 갈 것이다 인터넷 트래픽.
   선택적으로, 당신은 국경 대패에서 인터넷에 더 적은 특정한 IP 접두사를 광고할 수 있었습니다. 이 방법, 매직 트랜지션 서비스 실패와 달리, 트래픽은 인터넷에서 네트워크 위치에 직접 다시 추적 할 수 있습니다.
2. 인터넷에서 시작되는 트래픽은 보호 된 IP 접두사에 운명은 글로벌 Cloudflare 네트워크로 나뉩니다.
3. 모든 DDoS 공격 트래픽은 모든 Cloudflare 데이터 센터에서 소스에 근접하여 고급 및 자동화를 사용하여 전환 된 인라인입니다.[DDoS 완화](/ddos-protection/)기술.
4. DDoS 완화를 통과하는 트래픽은 추가 방화벽 필터링에 적용[Cloudflare 네트워크 방화벽](/cloudflare-network-firewall/).
5. Clean, 필터링된 트래픽은 직접 보호된 네트워크로 전환됩니다.[Cloudflare 네트워크 상호 연결](/network-interconnect/)(CNI) 연결.
6. 서버 반환 트래픽을 클라이언트로 경로를 두 가지 방법이 있습니다. 한 가지 방법은 데이터 센터와 인터넷에 기본적으로 Cloudflare 네트워크를 우회하는 것입니다. 이 방법은 Direct Server Return (DSR)라고 합니다. 네트워크 보안 및 트래픽 필터링에 문제가 발생할 수 있는 양방향 트래픽에 대한 비대칭 라우팅 결과 네트워크 경로의 상태 방화벽 또는 NAT 장치, 데이터 센터 또는 데이터 센터와 인터넷 사이 다른 부분을 통해. Caution는 네트워크에서 이러한 문제가 존재하지 않는 것을 보장하는 데 필요합니다.
   다른 방법은 [Magic Transit Egress](/magic-transit/reference/egress/)를 사용해, 클라이언트에서 서버로 가는 트래픽을 운반하는 동일한 연결을 통해 서버 반환 트래픽도 Cloudflare 네트워크로 대칭 라우팅하는 것입니다. 이 방법은 위 다이어그램에 묘사되어 있으며, 서버 반환 트래픽은 사이트에서 정책 기반 라우팅(PBR) 같은 라우팅 기법을 사용해, Cloudflare에서 데이터 센터로 공용 네트워크 트래픽을 전달하는 것과 동일한 CNI를 통해 Cloudflare 네트워크로 라우팅됩니다.
7. Magic Transit Egress 트래픽은 Cloudflare 네트워크 방화벽 필터링 대상입니다.

## 공용 네트워크에서 인터넷 액세스를 보호

아래의 참고 자료 아키텍처 다이어그램 Cloudflare 서비스 - Magic Transit (Egress), Cloudflare 네트워크 방화벽 및 Cloudflare Gateway는 데이터 센터의 공공 네트워크 (즉, 공용 IP 주소를 가진 서버)에서 시작되는 아웃바운드 인터넷 트래픽을 보호하는 데 사용될 수 있습니다.

![그림 2. 공공장소 네트워크에서 아웃바운드 트래픽을 보호합니다.](~/assets/images/reference-architecture/protect-data-center-networks/figure2.svg "Figure 2. Protect outbound traffic from public-facing networks.")

*참고: 이 이미지의 라벨은 이전 제품 이름을 반영할 수 있습니다.*

1. 각 사이트 네트워크는 공공 네트워크에서 Cloudflare로 시작하는 아웃바운드 인터넷 트래픽을 우회합니다. 본 사이트는 정책 기반 라우팅 (PBR)과 같은 당신의 선택의 라우팅 기술을 통해 사이트에서 수행 할 수 있습니다.
2. Cloudflare 네트워크에 입력하면, 아웃바운드 인터넷 트래픽은 Cloudflare 네트워크 방화벽을 통해 첫 번째 경로입니다. 어떤 구성 네트워크 방화벽 정책에 따라.
3. 아웃바운드 인터넷 트래픽은 연속적으로 전송됩니다[Cloudflare 게이트웨이](/cloudflare-one/traffic-policies/), 각종 우리의 안전한 웹 출입구 서비스[회사연혁](/cloudflare-one/traffic-policies/)아웃바운드 트래픽에 대한 보안 및 제어 조치의 포괄적 인 세트를 시행하고 네트워크의 최대 보호를 보장합니다. 예를 들어 Gateway DNS 및 HTTP 정책은 의심스러운 인터넷 사이트와 악성 코드 또는 기타 악의 콘텐츠를 다운로드하여 서버가 차단하도록 구성 될 수 있습니다.
4. 한 번의 트래픽은 검사, Gateway 프록시는 인터넷의 대상에 아웃바운드 트래픽. 아웃바운드 트래픽의 소스 IP 주소는 게이트웨이 서비스와 관련된 Cloudflare 소유 IP 주소이며, 구매하고 설정할 수 있습니다.[IP 등급](/cloudflare-one/traffic-policies/egress-policies/dedicated-egress-ips/)
5. 인터넷에서 트래픽을 반환, Cloudflare의 IP 주소 게이트웨이 서비스에 연결, Cloudflare의 글로벌 네트워크로 경로.
6. 교통은 Gateway 정책에 대해 검사됩니다.
7. 게이트웨이 검사를 통과하는 트래픽은 Cloudflare 네트워크 방화벽으로 더 많은 패킷 필터링합니다.
8. Cloudflare 네트워크 방화벽 필터링을 통과하는 트래픽은 Cloudflare에서 네트워크 위치에 전달되는 CNIs를 통해 네트워크 트래픽.

## 사이트 - 사이트, 간 데이터 센터, 개인 네트워크 트래픽 보호

참고 자료 아키텍처는 아래의 Cloudflare 서비스 - Cloudflare WAN, Cloudflare 네트워크 방화벽 및 Cloudflare Gateway — 사이트 현장을 보호하는 데 사용할 수 있습니다, 개인 네트워크 사이의 간 데이터 센터 트래픽.

**사이트 Private Network 트래픽 연결**

먼저, Cloudflare에 사이트 전용 네트워크 트래픽을 주제로하지 않는 사용 사례를 검사하십시오. Gateway 프록시 방화벽 서비스 및 Cloudflare WAN 서비스를 사용하여 경로.

![그림 3.1. 사설망간 상호 데이터 센터 비 게이트웨이 추진 트래픽을 보호합니다.](~/assets/images/reference-architecture/protect-data-center-networks/figure3.1.svg "Figure 3.1. Protect inter-data center non-gateway-proxied traffic between private networks.")

*참고: 이 이미지의 라벨은 이전 제품 이름을 반영할 수 있습니다.*

1. 해당 CNI 연결을 통해 Cloudflare WAN에 다른 데이터 센터 위치에 따라 사이트 사이트 전용 네트워크 트래픽을 경로. 본 사이트는 정책 기반 라우팅 (PBR)과 같은 당신의 선택의 라우팅 기술을 통해 사이트에서 수행 할 수 있습니다.
2. Cloudflare 네트워크를 입력하면 트래픽은 Cloudflare 네트워크 방화벽을 통해 경로화됩니다.
3. Cloudflare 네트워크 방화벽은 구성된 네트워크 방화벽 정책에 트래픽을 나타냅니다.
4. Cloudflare 네트워크 방화벽 규칙을 지우는 교통은 Cloudflare 게이트웨이 서비스에 의해 더 번영되지 않으며 해당 CNI를 통해 목적지 네트워크로 돌아갑니다.

**Site to Site Private Network 트래픽 with Application Level 보안 제어**

특정 개인 네트워크 트래픽에 미세 곡물 제어 및 보안에 대한 응용 프로그램 수준 정책을 적용하려는 경우 Cloudflare WAN 및 Cloudflare 게이트웨이 서비스를 통해 경로 및 프록시를 선택할 수 있습니다. 다음 다이어그램은 이러한 사용 사례의 아키텍처와 패킷 흐름을 보여줍니다.

![그림 3.2 : 그림 3.2. 개인 네트워크 간의 상호 데이터 센터 게이트웨이 보호 트래픽을 보호합니다.](~/assets/images/reference-architecture/protect-data-center-networks/figure3.2.svg "Figure 3.2. Protect inter-data center gateway-proxied traffic between private networks.")

*참고: 이 이미지의 라벨은 이전 제품 이름을 반영할 수 있습니다.*

1. 각 사이트 경로 개인 네트워크 트래픽은 해당 CNI 연결을 통해 Cloudflare WAN에 다른 데이터 센터 위치에 종료. 본 사이트는 정책 기반 라우팅 (PBR)과 같은 당신의 선택의 라우팅 기술을 통해 사이트에서 수행 할 수 있습니다.
2. Cloudflare 네트워크에 입력하면 트래픽은 Cloudflare 네트워크 방화벽을 통해 경로로 변환됩니다.
3. Cloudflare 네트워크 방호벽을 삭제한 후에, 교통은 연속적으로[Cloudflare 게이트웨이](/cloudflare-one/traffic-policies/), 우리의 안전한 웹 출입구 서비스.
4. 모델 번호: Cloudflare Gateway는 구성된 L3-7의 트래픽을 나타냅니다.[회사연혁](/cloudflare-one/traffic-policies/)보안 및 제어 조치의 포괄적 인 세트를 시행하고 네트워크의 최대 보호를 보장합니다. 일단 트래픽이 검사되면 Gateway는 트래픽을 목적지 개인 네트워크로 프록시합니다. proxied 트래픽의 소스 IP 주소는 게이트웨이 서비스와 관련된 Cloudflare 소유 IP 주소입니다.
5. proxied 트래픽, 에 루트 목적지 개인 네트워크, Cloudflare 네트워크 방화벽을 통해 더 많은 패킷 필터링을 위해 다시 한 번 경로.
6. Cloudflare 네트워크 방화벽 필터링을 전달하는 트래픽은 Cloudflare에서 개인 네트워크 트래픽을 전송하는 해당 CNIs를 통해 네트워크 위치에 전달됩니다.

## 개인 네트워크에서 아웃바운드 인터넷 트래픽 보호

아래의 참고 자료 아키텍처 다이어그램 Cloudflare 서비스 - Cloudflare WAN, Cloudflare 네트워크 방화벽 및 Cloudflare Gateway - 데이터 센터의 개인 네트워크에서 시작되는 아웃바운드 인터넷 트래픽을 보호하는 데 사용할 수 있습니다. 개인 네트워크의 서버에 제공된 사용 사례와 보호는 공용 네트워크에서 인터넷 액세스를 보호하는 이전 섹션에서 설명된 것과 매우 유사합니다. 차이점은 서버가 개인 IP 주소를 가지고 있으며 Cloudflare WAN 서비스는이 섹션에서 사용되며, 서버가 공용 IP 주소와 Magic Transit 서버로 할당되는 이전 섹션과 반대하는 것과 같습니다.

![그림 4. 개인 네트워크에서 아웃바운드 트래픽을 보호합니다.](~/assets/images/reference-architecture/protect-data-center-networks/figure4.svg "Figure 4. Protect outbound traffic from private networks.")

*참고: 이 이미지의 라벨은 이전 제품 이름을 반영할 수 있습니다.*

1. 해당 CNI 연결을 통해 Cloudflare WAN에 개인 네트워크에서 시작되는 각 사이트 경로 아웃바운드 인터넷 트래픽. 본 사이트는 정책 기반 라우팅 (PBR)과 같은 당신의 선택의 라우팅 기술을 통해 사이트에서 수행 할 수 있습니다.
2. Cloudflare 네트워크에 입력하면, 아웃바운드 인터넷 트래픽은 Cloudflare 네트워크 방화벽을 통해 첫 번째 경로입니다. 어떤 구성 네트워크 방화벽 정책에 따라.
3. Cloudflare 네트워크 방화벽을 명확하게 하는 트래픽은 나중에 전송됩니다[Cloudflare 게이트웨이](/cloudflare-one/traffic-policies/), 어떤 형성된 L3-7가 있는 우리의 안전한 웹 출입구 서비스[회사연혁](/cloudflare-one/traffic-policies/)아웃바운드 트래픽에 대한 보안 및 제어 조치의 포괄적 인 세트를 시행하고 네트워크의 최대 보호를 보장합니다.
4. 한 번의 트래픽은 검사, Gateway 프록시는 인터넷의 대상에 아웃바운드 트래픽. 아웃바운드 트래픽의 소스 IP 주소는 게이트웨이 서비스와 관련된 Cloudflare 소유 IP 주소입니다.
5. 인터넷에서 트래픽을 반환, Cloudflare의 IP 주소 게이트웨이 서비스에 연결, Cloudflare의 글로벌 네트워크로 경로.
6. 교통은 Gateway 정책에 대해 검사됩니다.
7. 게이트웨이 검사를 통과하는 트래픽은 Cloudflare 네트워크 방화벽으로 더 많은 패킷 필터링합니다.
8. Cloudflare 네트워크 방화벽 필터링 통과 트래픽은 Cloudflare에서 개인 네트워크 트래픽을 전송하는 CNIs를 통해 네트워크 위치에 전달됩니다.
