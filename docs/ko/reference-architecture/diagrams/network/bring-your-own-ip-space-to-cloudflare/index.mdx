## 제품정보

Cloudflare는 우리의 고객의 디지털 자산에 안전 그리고 성과를 가져옵니다. 그러나 프록시 서비스의 특성 중 하나는 Cloudflare (DNS 쿼리 또는 요청 SaaS 제공 업체, 예를 들어)에가는 웹에 대한 상호 작용이 Cloudflare IP 공간에서 오는 세계로 나타날 것입니다. 이것은 몇몇 기업을 위한 도전을 창조할 수 있습니다.

예를 들어, 파트너 또는 기타 B2B 관계는 다양한 거래에서 검증 및 분석을위한 고객에 의해 소유 된 공공 IP 공간을 사용할 수 있습니다. 그들은 공개 hostname에 대한 해결 된 주소를 볼 수 있습니다 (예를 들어,`www.example.com`)는 고객에 의해 소유되기 위하여 알려지는 특정한 범위 또는 주소를 일치하기 위하여 IP를 예상합니다.

[자신의 IP를 가져 오기 (BYOIP)](/byoip/)기업이 Cloudflare에 IP 공간을 가져갈 수 있도록 Cloudflare 플랫폼의 보안 및 성능을 얻고 여전히 자신의 공공 IP 공간을 통해 세계의 나머지에 나타납니다. 이 참고 자료 건축 도표는 다른 방법을 강조합니다 고객은 Cloudflare 네트워크에 그들의 IP 공간을 가져올 수 있고 달성되는 이익.

## BYOIP 시나리오 하나 - Cloudflare 프록시 서비스

DNS 쿼리가 Cloudflare proxied hostname로 만들 때 기본 동작은 Cloudflare의 하나가 반환됩니다[기본 anycast IP 주소](https://www.cloudflare.com/ips/). 트래픽은 가속, 보호, 그리고, Cloudflare 캐시에 의해 제공되지 않는 경우, 고객의 기원 서버로 보내.

아래 다이어그램에서 기본 동작 대신, 트래픽은 Cloudflare의 애플리케이션 서비스 플랫폼을 통해 프록시되지만 DNS 쿼리는 Cloudflare의 anycast 네트워크에서 혜택을하면서 고객이 소유 한 IP 주소를 반환합니다.

이 예제에서 사용되는 두 가지 다른 네트워크 범위가 있습니다.

- `152.3.15.0/24`- Cloudflare 네트워크와 관련되는 고객 소유 IP 범위.
- `152.3.14.0/24`- 고객 소유 IP 범위는 원래 네트워크와 관련 될 것입니다.

![그림 1: Cloudflare는 고객 IP 범위를 발표하고 원래 서버 IP에 프록시.](~/assets/images/reference-architecture/bring-your-own-ip-space-to-cloudflare/figure1.svg "Figure 1: Cloudflare announces customer IP range and proxies it to the origin server IP.")

1. Cloudflare는 고객의 공간의 주소로 DNS 쿼리에 응답하기 위해, 기관 (LOA)의 편지는 Cloudflare에 고객이 제공해야하므로 주소가 제공되고 광고 될 수 있습니다. 이 주소 공간 (예에서,`152.3.15.0/24`)는 Cloudflare의 윤곽을 위해 전념하고 고객 환경 안에 어디에서든지 사용해서는 안됩니다.
2. 원래 서버의 Cloudflare DNS 구성`www.abc.com`IP 주소로 구성`152.3.14.10/32`.
3. DNS 쿼리`www.abc.com`이름 \*
4. Cloudflare는 이전에 고객에 의해 제공된 BYOIP 공간에서 형성된 고객의 공간에서 주소를 반환합니다. 이 경우, 응답이었다`152.2.15.200`, 이는 부분의`/24`연락처`152.2.15.0/24`.
5. eyeball는 요구에 응합니다`152.2.15.200`그것은 Cloudflare로  routed.
6. Cloudflare 프록시 연결, SNI 사용 (`www.abc.com`) 실제적인 근원 IP를 결정하기 위하여,`152.3.14.10`. 요청은 Cloudflare의 프록시 서비스를 통해 DDoS 보호, 웹 애플리케이션 방화벽 및 Bot 관리와 같은 경로로 처리됩니다.
7. 성공적인 요청은 근원으로 보내집니다 (현금에 의해 봉사하지 않는 경우에)`152.3.14.10`Cloudflare 네트워크의 소스 IP로.

## BYOIP 시나리오 2 - 네트워크 DDoS 보호

Cloudflare는 공공 웹 사이트 및 API를 보호하는 그것의 DDoS 완화 서비스를 위해 잘 알려져 있습니다. 동일한 기술은 또한 전체 네트워크를 보호하기 위해 사용될 수 있습니다. Cloudflare의[매직 트레인](/magic-transit/)서비스는 클라우드 기반 네트워크 DDoS 완화 서비스를 제공합니다.

![그림 2 : DDoS 공격에 대한 보호는 Cloudflare 터널 네트워크 앞에 BYOIP 범위의 앞에 배치 될 수 있습니다.](~/assets/images/reference-architecture/bring-your-own-ip-space-to-cloudflare/figure2.svg "Figure 2: Protection against DDoS attacks can be placed in front of the BYOIP range in front of your Cloudflare tunneled network.")

1. Cloudflare를 위한 순서에서는 고객 네트워크 접두사, 기관 (LOA)의 편지가 Cloudflare에 고객에 의해 제공되어야 합니다, 그래서 네트워크 접두사는 제공되고 광고될 수 있다 그래야.
2. 일단 제공되면, Cloudflare는 Cloudflare 네트워크에 그 네트워크에 대 한 트래픽을 끌어 인터넷에 고객 접두사를 광고 합니다.
3. 모든 트래픽은 Cloudflare로 전환됩니다.
4. DDoS 트래픽은 Cloudflare에 의해 이동되고 합법적인 교통은 고객 네트워크로 돌아갑니다[터널](/cloudflare-wan/), 또는 통해[Cloudflare 네트워크 상호 연결](/network-interconnect/)(CNI) 고객의 환경에 경사.

Magic Transit 기능에 대한 자세한 내용은 다음을 참조하십시오.[마술 이동 참고 자료 회사연혁](/reference-architecture/architectures/magic-transit/).
