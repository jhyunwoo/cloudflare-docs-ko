## 제품정보

A/B 테스트, 또한 분할 테스트로 알려져, 웹 개발의 영역에서 근본적인 기술이다, iteratively 정제 팀과 그들의 디지털 경험을 최적화 할 수. A/B 테스트는 웹 페이지 또는 앱 기능의 두 가지 버전을 비교하여 변환, 참여, 사용자 만족과 같은 미리 정의 된 목표를 달성하는 데 더 나은 수행을 결정합니다.

프로세스는 일반적으로 두 가지 변형의 생성으로 시작합니다 : 제어 (A) 및 변형 (B). 이 변형은 테스트 된 특정 요소를 제외하고 동일합니다. 헤드 라인, 버튼 색상, 레이아웃 또는 사용자 인터페이스 또는 사용자 경험의 다른 구성 요소. 예를 들어, 팀은 두 개의 다른 통화 행동 버튼 색상을 테스트하여 더 많은 클릭을 생성 할 수 있습니다.

변형이 준비되면, 그들은 무작위 방식으로 사용자에게 노출됩니다. 이 임의화는 변종 사이의 성능에 대한 차이는 사용자 인구 통계 또는 행동과 같은 외부 요인보다 오히려 테스트되는 변화에 영향을 미칠 수 있음을 보장합니다.

사용자는 다른 변종과 상호 작용하고, 그들의 행동과 행동은 predefined 목표에 대한 각 변종의 성능을 측정하기 위해 추적되고 분석됩니다. click-through rate, conversion rate, bounce rate, join metrics와 같은 Key metrics는 원하는 결과를 달성하는 데 더 효과적인 변형을 결정하기 위해 모니터링됩니다.

A/B 테스트는 지속적으로 최적화 및 디지털 경험을 개선하기위한 강력한 도구이며, 팀에게 제목의 의견이나 가정보다 실제 사용자 피드백을 기반으로하는 데이터 중심 결정을 할 수 있습니다. 웹 사이트 또는 응용 프로그램의 다른 요소를 체계적으로 테스트하고 정제함으로써 조직은 사용자 만족, 증가 변환을 강화하고 궁극적으로 경쟁적인 온라인 환경에서 비즈니스 목표를 달성 할 수 있습니다.

Cloudflare의 저편성, 완전히 serverless compute 플랫폼,[모델 번호: Workers](/workers/)서버 측 구현을 사용하여 A/B 테스트를 가능하게 하는 강력한 기능을 제공합니다. 도움으로[Workers KV](/kv/), 이 해결책은 아주 쉽게 구성할 수 있습니다.

## Workers를 사용하는 A/B 테스트

![그림 1: Workers를 사용하여 A/B 테스트](~/assets/images/reference-architecture/a-b-testing-workers/a-b-testing-workers.svg "Figure 1: A/B testing using Workers")

이 아키텍처는 동일한-URL A/B 테스트 엔드포인트를 보여줍니다. A/B 테스트 로직 및 구성은 서버 측에 배치되므로 클라이언트는 A/B 테스트 사용을 위해 변경 사항을 구현할 필요가 없습니다.

1. **회사 소개**: 서버로 요청을 보냅니다. 데스크톱 또는 모바일 브라우저 또는 네이티브 또는 모바일 앱을 통해 할 수 있습니다.
2. **제품 설명**: Workers를 사용하여 처리 수신 요청. 현재 설정 읽기[모델 번호: KV](/kv/)사용 방법[`get()`](/kv/api/read-key-value-pairs/)방법. A/B 서비스 구성에 유연한 업데이트를 할 수 있습니다.
3. **회사 소개**: 요청 헤더에 이미 기존 쿠키를 확인한다. 그룹 할당에 대한 쿠키가 설정되지 않은 경우, 무작위로 그룹을 할당합니다. 쿠키가 설정되면 쿠키 헤더에서 할당된 그룹을 추출합니다. 제어 endpoint (A) 또는 변형 endpoints (B) 구성 및 할당 된 그룹에 따라 요청을 보냅니다.
4. **관련 기사**: 근원에서 응답을 반환합니다. 또한, 쿠키가 이전에 설정되지 않은 경우, 세션 친화에 대한 각각의 할당 된 그룹과 쿠키를 설정합니다.

Workers와 Workers KV를 사용해 서로 다른 origin 웹 서버로 요청을 라우팅하는 방법에 대한 코드 스니펫과 예제가 필요하다면, Workers KV 예제의 [웹 서버 간 라우팅](/kv/examples/routing-with-workers-kv/)을 참고하세요.
