## 제품정보

사용자 생성된 콘텐츠 (UGC)는 현대 응용 프로그램의 필수 측면입니다. 이 문서는 프로필 사진, 문서 및 비디오뿐만 아니라 이미지, 요약 또는 구조화 된 데이터를 생성하는 AI 모델이 포함되어 있습니다. 따라서, 신청은 믿을 수 있고, 확장할 수 있고, 이 내용을 저장하고 접근하기를 위한 비용 효과적인 해결책.

모델 번호: Cloudflare[모델 번호: R2](/r2/)S3-compatible object storage with zero egress Fee, 콘텐츠 업로드 및 배송 처리에 이상적입니다. Cloudflare로 결합하는[모델 번호: Workers](/workers/)그리고 Cloudflare의 글로벌 네트워크, 그것은 UGC를 소화하고 관리하기 위한 빠르고 안전한, 비용 효과적인 워크플로우를 가능하게 합니다.

이 참고 자료 건축은 성과, 안전 및 비용 효율성을 위해 낙관된 2개의 일반적인 UGC 워크플로우를 탐구합니다:

1. **로그인 URL을 통해 R2에 보안 사용자 업로드:**&#xD30C;일을 업로드 할 수 있도록 허용 (파일 이미지, 문서 등) 효율적이고 안전하게 백엔드 시스템을로드하지 않고.
2. **R2에서 저장된 AI-Generated 내용:**&#x57;orkers AI 또는 외부 AI 서비스에 의해 생성된 저장 내용은, inference 결과를 미래 사용을 위해 persistently 유효합니다.

## 사용 사례

### 사용 케이스 1: 보안 사용자 로그인 URL을 통해 R2에 업로드

사용자 생성 된 콘텐츠는 일반적으로 프로파일 그림, 이력서, 풍부한 미디어 및 문서를 포함하여 파일 업로드를 시작합니다. 응용 프로그램은 보안을 검증하고 이 업로드를 저장해야하며 대기 시간, 높은 비용 및 불필요한 복잡성을 방지합니다.

이 건축물에서 우리는**모델 번호: R2**1 차적인 저장 층 및 a로**작업자**업로드 액세스를 제어합니다. 파일은 사용자의 브라우저 또는 장치에서 직접 업로드됩니다 R2 서명 URL을 사용하여, 이는 사용자의 권한 및 업로드 의도를 검증 한 후 노동자에 의해 생성됩니다.

이 접근법은 애플리케이션 백엔드 또는 Worker를 통해 큰 파일을 라우팅하고, 대기 시간과 운영 비용을 줄이며, 액세스 및 보안을 통해 꽉 제어를 보장합니다.

그리고 R2가 기본적으로 Cloudflare의 글로벌 네트워크와 통합되어 있기 때문에, R2에 저장된 파일은 세계에서 어느 곳에서나 낮은 지연으로 접근할 수 있습니다.**egress 수수료 없음**, 심지어 응용 프로그램 규모.

![사용 케이스 1: 보안 사용자 로그인 URL을 통해 R2에 업로드](~/assets/images/reference-architecture/storing-user-generated-content/uploads-to-r2-via-signed-urls.svg "Use Case 1: Secure User Uploads to R2 via Signed URLs")

**어떻게 작동합니까?**

1. **사용자는 frontend에서 업로드:**&#xC571;은 파일 세부 정보를 수집합니다 (예 : 크기, 이름) 업로드 프로세스를 시작하기 위해 백엔드 API (a Cloudflare Worker)를 호출합니다.
2. **Worker는 사용자를 인증하고 요청을 검증합니다.**&#x57;orker는 사용자가 로그인되었는지 확인하며, 업로드 권한을 가지고 있으며, 파일이 허용한 제한 내에서 있음(예를 들어, 최대 10MB, 허용된 MIME 유형).
3. **노동자는 R2에 서명한 PUT URL을 반환합니다:**&#xC11C;명된 URL은 R2에 직접 업로드할 수 있습니다. 제한된 시간 동안 특정 키 또는 네임스페이스에서. 작업자가 큰 파일을 직접 처리 할 필요가 없습니다.
4. **R2에 파일을 직접 업로드:**&#xD30C;일은 클라이언트에서 R2로 직접 스트리밍됩니다.
5. **(선택 사항) 방아쇠 포스트 업로드 워크 플로우 :**&#x52;2 제안[이벤트 알림](/r2/buckets/event-notifications/)R2 버킷의 데이터가 새 업로드처럼 변경 될 때 큐에 메시지를 보낼 수 있습니다. 예제 포스트 처리 :
   - 스캔, 온건한, 또는 파일을 변환.
   - metadata 쓰기 (예를 들면,`user_id`, `file_path`, `timestamp`)에[모델 번호: D1](/d1/), Cloudflare의 serverless SQL 데이타베이스.
   - 사용자를 통지하거나 대시보드/UI를 업데이트하십시오.

클라이언트에서 R2에 직접 업로드 데이터에 대한 자세한 내용은 문서 참조[할당된 URL](/r2/api/s3/presigned-urls/).

### 사용 케이스 2: R2에서 저장되는 AI-Generated 내용

많은 현대 신청은 제품 설명, 단면도 그림, 오디오 클립 및 더 많은 것을 포함할 수 있는 AI 생성한 내용을 이용합니다. 이 콘텐츠는 사용자 행동 또는 예정된 이벤트에 대한 응답으로 생성될 때, 즉시 저장되어야 하며, 스케일로 저장되어야 합니다.

이 건축물은 고용[모델 번호: Workers AI](/workers-ai/)가장자리에 inference를 실행하고 다음 단일 노동자 안에 Cloudflare R2에서 직접 생성 된 출력을 저장합니다.

![사용 케이스 2: R2에서 저장되는 AI-Generated 내용](~/assets/images/reference-architecture/storing-user-generated-content/ai-generated-content-in-r2.svg "Use Case 2: AI-Generated Content Stored in R2")

**어떻게 작동합니까?**

1. **사용자는 콘텐츠 생성을 시작:**&#x66;rontend는 Cloudflare에 요청을 보냅니다 AI 모델을 사용하여 콘텐츠를 생성하는 작업자 (예를 들어, "이 제품에 대한 썸네일 이미지를 수집합니다.")
2. **노동자는 Workers AI를 지시합니다:**&#xB178;동자는 Workers AI에 배치된 모형에 사용자 입력을 전달합니다.
3. **생성된 산출은 노동자에 돌려보냅니다:**&#xC751;답은 일반 텍스트, Base64 이미지, 바이너리 버퍼 또는 모델 유형에 따라 다른 구조 데이터가 될 수 있습니다.
4. **노동자는 직접 R2에 산출을 업로드합니다:**&#xC11C;명된 URL 또는 클라이언트 업로드가 필요하지 않습니다. 노동자는 보안을 수행, 인증`PUT`지정된 물통에 출력을 저장하는 요청.
5. **Worker는 성공과 metadata를 frontend로 반환합니다.**&#xD074;라이언트는 저장된 파일에 참고 자료를 받습니다 ( 경로와 같은 목표 열쇠, 또는 필요하다면 서명한 다운로드 URL).

더 알아보기[R2에서 사용 Workers](/r2/api/workers/workers-api-usage/)Cloudflare Workers를 통해 R2 물통에 접근에 정보 더를 위해.

## 제품정보

저장하기**Cloudflare R2에 있는 사용자 생성한 내용**, 신청 이익:

- 높은 확장 가능한 스토리지 백엔드
- Cloudflare의 가장자리 컴퓨팅을 통해 빠른 액세스
- 0 egress 수수료로 예상 비용
- 효율성 극대화를 위한 원활한 AI + UGC 워크플로우

이 건축은 그 내용을 저장하고, 가공하고, 배달합니다**빠르고, 안전하고, 비용 효율적인**.
