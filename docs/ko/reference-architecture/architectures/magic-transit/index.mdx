## Magic Transit이란?

DDoS 공격으로부터 네트워크 인프라 보호는 강점과 속도의 독특한 조합을 요구합니다. Volumetric 공격은 쉽게 압도적 인 하드웨어 상자와 대역폭 기반 인터넷 링크를 할 수 있습니다. 대부분의 클라우드 기반 솔루션은 네트워크 성능에 크게 영향을 미치는 중앙화된 스크랩 센터에 트래픽을 리디렉션합니다.

Cloudflare Magic Transit은 온프레미스, 클라우드 및 하이브리드 네트워크에 대한 DDoS 보호 및 트래픽 가속을 제공합니다. 데이터 센터로[수백 도시](https://www.cloudflare.com/network/)그리고 대량의 Tbps의 수백을 제공, 매직 트랜지션을 감지하고 mitigate 공격은 평균적으로 3 초 미만의 근원에 가깝습니다 — 모두 대중적인 인터넷보다 트래픽을 빠르게 올리는 동안.

![그림 1: 마술 transit 개요](~/assets/images/reference-architecture/magic-transit-ref-arch-diagrams/magic-transit-ref-arch-1.png "Figure 1: Magic transit overview")

높은 수준에서 Magic Transit은 다음과 같이 작동합니다.

- **연결:**&#x42;order Gateway Protocol (BGP) 경로는 인터넷에 발표, 그리고 Cloudflare anycast 네트워크, 고객 트래픽은 소스에 가까운 Cloudflare 데이터 센터에서 파생됩니다.

- **보호하고 과정:**&#xBAA8;든 고객 트래픽은 공격을 위해 검사됩니다. 고급 및 자동화 된 완화 기술은 공격을 감지하여 즉시 적용됩니다. load balancing, next-generation Firewall, content caching, serverless compute 등의 추가 기능도 서비스로 제공됩니다.

- **가속:**&#xAE68;끗한 트래픽은 최적의 처리량을 위한 Cloudflare의 저경도 네트워크 링크에 경로를 두고 IP 터널(GRE 또는 IPsec) 또는 프라이빗 네트워크 인터커넥트(PNI)을 통해 전달됩니다. Magic Transit은 Cloudflare의 터널 엔드포인트에 대한 모든 서버가 동일한 터널에 대한 캡슐화 및 탈수 패킷을 사용할 수 있다는 것을 의미한다. 터널 및 캡슐화에 대한 자세한 내용은 참조[GRE 및 IPsec 터널](/magic-transit/reference/gre-ipsec-tunnels/).

### Baking는 anycast를 사용하여 네트워크에 의존합니다.

Magic Transit은 네트워크 터널 엔드포인트의 끝을 위한 IP 주소를 사용하므로 고객의 네트워크에서 Cloudflare로 구성된 단일 터널은 모든 Cloudflare 글로벌 데이터 센터에 연결됩니다.[중국 네트워크](/china-network/)). 이것은 라우터에 변형을 추가하지 않습니다. 라우터의 관점에서 단일 터널은 단일 IP 엔드 포인트입니다.

터널 엔드 포인트가 기술적으로 IP 주소에 바인딩되어 있기 때문에이 작품은 특정 장치에 바인딩되지 않습니다. 외부 우두머리를 벗을 수 있는 어떤 장치든지 그 후에 안 소포를 갱도에 보내진 어떤 소포를 취급할 수 있습니다.

네트워크 부족이나 다른 문제의 경우 터널은 자동으로 실패했습니다. 고객의 네트워크 성능에 영향을 미치지 않습니다.

## Magic Transit에 대한 배포 아키텍처

### 기본 설정 (ingress 만, 직접 서버 반환)

기본적으로, Ingress 방향의 Magic Transit 프로세스 트래픽 (인터넷에서 고객 네트워크). 클라이언트로 돌아가 서버 반환 트래픽은 가장자리 라우터의 기본 라우팅 테이블을 기반으로 인터넷 / ISP에 업링크를 통해 고객의 DC 가장자리 라우터에 의해 전달됩니다. 이 서버 반환 트래픽은 터널을 통해 Cloudflare를 통해 전달되지 않습니다. Direct Server Return (DSR)라고 합니다.

그림 2의 네트워크 다이어그램은 Magic Transit 설정과 Magic Transit-protected 트래픽의 엔드 투 엔드 패킷 흐름을 보여줍니다. 이 설정의 터널은 캡슐화를위한 GRE를 사용합니다.

![그림 2: 참고 자료 기본 DSR 선택권을 가진 마술 이동 anycast 갱도 (GRE)의 윤곽](~/assets/images/reference-architecture/magic-transit-ref-arch-diagrams/magic-transit-ref-arch-2.png "Figure 2: Reference Configuration of Magic Transit anycast Tunnel (GRE) With Default DSR Option")

- Cloudflare는 갱도 종점의 Cloudflare 끝을 위한 anycast IP 주소의 쌍을 가진 고객을 제공합니다. 이들은 Cloudflare 소유 주소 공간에서 공개적으로 routable IP 주소입니다. anycast IP 주소의 쌍은 네트워크 중복을위한 두 개의 터널을 구성하는 데 사용할 수 있지만 기본 구성에만 필요합니다. 위의 구성은 터널 엔드 포인트 주소의 Cloudflare 끝과 함께 단일 터널을 보여줍니다 192.0.2.1.

- anycast GRE 터널의 고객 끝은 공개적으로 routable 주소이어야합니다. 일반적으로 고객의 가장자리 라우터에 WAN 인터페이스의 IP 주소입니다. 이 예제에서 192.0.2.153입니다.

- 터널 인터페이스의 IP 주소는 RFC 1918 개인 주소입니다. 이 주소는 특정 Magic Transit 서비스 인스턴스 내에서 "현지적으로 뜻깊은"일 뿐입니다. 따라서 고객은 동일한 Magic Transit 서비스 인스턴스 내에서 구성 된 다른 터널의 사람들로 인해 원하는 RFC 1918 주소를 선택할 수 있습니다.

- 가장 좋은 연습으로 터널은 포인트 투 포인트 연결이며, 31 subnet은 주어진 터널에 필요한 2 IP 주소를 할당하는 것이 충분합니다. 위 예에서 10.10.10.0/31 서브넷이 선택되어, 터널 인터페이스의 Cloudflare 끝은 10.10.10.0/31이고, 고객은 DC 가장자리 대패 측은 10.10.1/31입니다.

- 터널이 구성되면, 경로는 Magic Transit 서비스 인스턴스에서 올바른 터널에 주어진 고객 접두사에 전달된 트래픽을 전달합니다.

- 트래픽은 고객 접두사 203.0.113.0/24에 중단되어 터널 인터페이스의 Cloudflare 네트워크의 관점에서 Cloudflare 네트워크의 끝 (즉, 고객의 끝)이 10.10.10.1이다.

- 이 주어진 직접 서버 반환 (DSR) 설정, 서버 반환 트래픽은 기본 경로 (IP 경로 0/0) 고객 가장자리 라우터에 구성 및 그것의 업 링크 피어에 전송 (즉, 고객의 ISP의 라우터), 인터넷에 클라이언트로 다시 경로. 이 반환 트래픽은 Cloudflare 네트워크를 가로지르지 않습니다.

**참고 :**&#xAC00;장 작은 IP 접두사 크기 (즉, 가장 긴 IP 서브넷 마스크와 함께) 대부분의 ISP는 서로의 BGP 광고에서 허용됩니다 /24; 예를 들어 x.x.x.0/24 또는 y.y.0/23 괜찮지만 z.z.0/25은 아닙니다. 따라서, 가장 작은 IP 접두사 크기 Cloudflare 마술 이동은 고객 대신에 광고할 수 있습니다 /24입니다.

### 활성화된 egress 옵션으로 Magic Transit

Magic Transit이 Egress 옵션으로 배포되면 Cloudflare 네트워크를 통해 고객의 네트워크 흐름에서 egress 트래픽이 가능합니다. 이 배포 옵션은 Cloudflare 네트워크를 통해 클라이언트 서버 및 서버 리턴 트래픽 흐름 모두 트래픽 흐름에 대한 심리학을 제공합니다. 이 구현은 Cloudflare 네트워크에 의해 감당하여 서버 수익 트래픽에 대한 보안 및 신뢰성을 제공합니다.

다음 네트워크 다이어그램은 Magic Transit Egress 옵션이 활성화 될 때 최종 클라이언트와 고객 네트워크 사이의 엔드 투 엔드 패킷 흐름을 보여줍니다.

![그림 3: Egress 선택권을 가진 마술 이동 Enabled](~/assets/images/reference-architecture/magic-transit-ref-arch-diagrams/magic-transit-ref-arch-3.png "Figure 3: Magic Transit With Egress Option Enabled")

- ingress 트래픽 흐름은 위의 기본 설정 사용 사례와 동일합니다.

- Magic Transit에 의해 수신되고 처리되는 egress 트래픽의 경우, 트래픽의 소스 IP 주소는 Magic Transit-protected IP 접두사 범위에 있어야하며, 대상 IP 주소는 공공 인터넷 routable, 즉. 비-RFC 1918 주소가 필요합니다.

그것은 자신의 공공 IP 주소를 가지고 고객을 위해 그 가치가있다 ([BYOIP의 특징](/byoip/)) 클라우드 호스팅 서비스에 대한, Magic Transit Egress 옵션은 클라우드 제공 업체와 BYOIP 서비스를 구입하고 구현하기 위해 필요성을 제거하여 추가 가치를 제공 할 수 있으며 클라우드 요금 및 운영 비용을 절감합니다.

이를 달성하기 위해 IP 터널은 클라우드 제공 업체의 VPC와 Cloudflare 네트워크 사이에 설정되어 있습니다. Magic Transit Egress 옵션으로, 클라이언트 서버 트래픽의 두 방향은이 터널을 통해 흐릅니다. 터널링 패킷의 BYOIP 주소는 외부 터널 엔드포인트 IP 주소와 터널 헤더 뒤에 숨겨져 VPC와 Cloudflare 네트워크 사이의 하위 클라우드 공급자 네트워크 요소에 "접근"을 만듭니다.

### Cloudflare 네트워크 연결 (CNI)에 마술 이동

[Cloudflare 네트워크 상호 연결 (CNI)](/network-interconnect/)고객은 Cloudflare에 네트워크 인프라를 직접 연결할 수 있습니다 – 공공 인터넷을 우회하여 더 신뢰할 수 있고, 실행 및 안전한 경험을 제공합니다.

- CNI는 층 2 연결의 세트로 교차 연결 공급자에 의해 제공되고, Cloudflare는 각 연결을 위한 Cloudflare의 자신의 인터넷 룰렛 IP 주소 구획에서 IP 주소의 쌍을 알립니다.

- Cloudflare는 고객이 이러한 링크를 구성하고 CNI를 내장하는 동안 링크 위에 BGP 피어링 세션을 수립하기 위해 협조합니다.

- BGP 세션이 Cloudflare 네트워크와 CNI, Cloudflare 소유의 접두사를 통해 연결되는 고객 가장자리 대패 사이 위로 이 CNI 연결에 광고될 것입니다.

그림 4는 CNI를 통해 Magic Transit에 대한 참고 자료 구성 및 관련 패킷 흐름을 보여줍니다.

**참고 :**&#xC774; 예제는 Egress 옵션이 활성화되지 않고 기본적으로 Magic Transit 서비스가 표시됩니다. Magic Transit Direct Server Return mode(i.e. Ingress only)의 이전 섹션에서 설명된대로, 서버 반환 트래픽은 공용 인터넷을 통해 ISP를 통해 클라이언트에게 고객 가장자리 라우터에 의해 전달됩니다.

![그림 4: CNI (과태 DSR 선택권)에 마술 이동의 참고 자료 윤곽](~/assets/images/reference-architecture/magic-transit-ref-arch-diagrams/magic-transit-ref-arch-4.png "Figure 4: Reference Configuration of Magic Transit Over CNI (Default DSR Option)")

Magic Transit Egress 옵션이 활성화되고 활용되면 서버 반환 트래픽은 Cloudflare 네트워크를 통해 클라이언트로 돌아올 수 있으며, CNI 연결을 구성하는 IP 터널을 통해 전송할 수 있습니다. 그림 5 같은 예제를 보여줍니다.

### Magic Transit 보호 공공 클라우드 호스팅 서비스

Magic Transit은 온프레미스 및 클라우드에서 호스팅되는 서비스를 보호합니다. 이 사용 사례는 클라우드 호스팅 배포에 대한 구성을 설명합니다.

![그림 6 : Magic Transit (Egress Option Enabled)을 통한 멀티 클라우드 기반 서비스를 보호합니다.](~/assets/images/reference-architecture/magic-transit-ref-arch-diagrams/magic-transit-ref-arch-6.png "Figure 6: Protect Multi-Cloud-Based Services With Magic Transit (Egress Option Enabled)")

- 이 예에서 주어진 고객은 두 개의 클라우드 VPC 배포가 서로 다른 클라우드 제공 업체에서 확산되고 두 개의 다른 지리적 영역에서 있습니다.

- 이 예에서 고객은 24 또는 더 큰 접두사는 여러 개의 작은 (즉, 더 긴 서브넷 마스크 길이) 접두사 (예 : /26)로 분할되며 다른 위치에 다양한 VPC에 할당됩니다. VPC의 각에 Cloudflare 네트워크에서 터널을 설치하면 고객은 Magic Transit 구성에서 각각 VPC로 트래픽을 경로로 구성 할 수 있습니다. 이러한 구성은 API 또는 UI 대시보드를 통해 만들 수 있습니다.

Magic Transit Egress 옵션과 함께, 고객은 각 클라우드 공급자의 BYOIP 서비스를 우회할 수 있으며, 관련 수수료 및 구성 및 운영 복잡성을 우회하여 egress 트래픽 (즉, 서버 반환 또는 서버로 인터넷 트래픽을 보호하는)을 통해 Cloudflare 글로벌 네트워크에서 Magic Transit 터널을 통해 우회할 수 있습니다.

### 마술 이동과 Cloudflare WAN

Cloudflare Magic Transit 서비스는 Cloudflare Magic Transit Service를 사용하여 Cloudflare Magic Transit Service를 사용하여 기업 (i.e. north-south Internet-routable traffic)의 외부 포장 서비스를 보호하고 routing 트래픽 외에도 내부 트래픽 (e.g. RFC 1918 개인 주소)을 보호하고 엔터프라이즈의 모든 사이트를 상호 연결하여[Cloudflare 대만](/cloudflare-wan/)(이전 매직 WAN).

Cloudflare WAN은 Cloudflare 네트워크와 레거시 WAN 아키텍처를 대체하여 글로벌 연결, 클라우드 기반 보안, 성능 및 하나의 간단한 사용자 인터페이스를 통해 제어합니다.

Cloudflare Magic Transit과 Cloudflare WAN 서비스는 전체 기업을 위한 전체적인, 안전한, 믿을 수 있는, 및 실행하는 세계적인 네트워크 A 서비스 해결책을, 보호하고 북-south 뿐 아니라 동쪽 서쪽 교통을 가속하는 제공합니다.

둘 다 서비스는 동일한 서비스 인스턴스에서 배치될 수 있습니다, 또는, 외부의 관리 그리고 소통량 교류를 지키기 위하여 선호하는 고객을 위해, 인터넷 직면 네트워크 및 내부 법인 네트워크는 완전히 분리된, 다른 서비스 인스턴스 마술 이동 및 Cloudflare WAN을 위해 배치될 수 있습니다.

- 예를 들어, GRE 터널은 Cloudflare 글로벌 anycast 네트워크에서 고객의 다양한 사이트를 연결하는 데 사용됩니다. Magic Transit Service 인스턴스의 Cloudflare anycast IP 주소는 192.0.2.1이며 Cloudflare WAN 서비스 인스턴스는 192.0.2.2입니다. Magic Transit 서비스는 Egress 옵션으로 제공됩니다.

### Cloudflare 네트워크 방화벽: 기업 네트워크에 도달하기 전에 통제 및 필터 원치 않는 트래픽

Magic Transit은 DDoS 공격으로부터 고객의 서비스를 보호합니다. 많은 네트워크 관리자는 다른 원치 않는 또는 잠재적으로 악의적인 트래픽을 제어하고 차단할 수 있습니다.[Cloudflare 네트워크 방화벽](/cloudflare-network-firewall/)본사, 지사 및 가상 개인 클라우드를 포함한 전체 고객 WAN에 걸쳐 일관된 네트워크 보안 정책을 시행하고, 고객이 글로벌 초에서 고급 필터링 규칙을 배포 할 수 있습니다. 일반적인 대시보드.

Cloudflare 네트워크 방화벽은 Magic Transit의 일부로 배포 및 구성됩니다. Cloudflare 가장자리 데이터 센터를 통해 흐르는 모든 진입 트래픽은 Magic Transit에 의해 보호되며 Cloudflare 네트워크 방화벽에 의해 필터링 될 수 있습니다.

![그림 8: Cloudflare 네트워크 방화벽 차단 Unwanted 과 malicious 트래픽 에 Internet Edge](~/assets/images/reference-architecture/magic-transit-ref-arch-diagrams/magic-transit-ref-arch-8.png "Figure 8: Cloudflare Network Firewall Blocks Unwanted and Malicious Traffic at the Internet Edge")

*참고: 이 이미지의 라벨은 이전 제품 이름을 반영할 수 있습니다.*

Cloudflare 네트워크 방화벽 규칙에서는, 관리자는 전형적인 5tuple (source/destination IP, 근원/destination 항구, 의정서) 정보에 IP 소포 우두머리에서 실행된 IP 소포 길이 IP 우두머리 길이, TTL, 등과 같은 다른 소포 정보도 일치할 수 있습니다. 또한, Cloudflare 데이터 센터 / colo의 이름과 같은 지리적 정보, 지역 및 국가 데이터 센터는 네트워크 방화벽 규칙 (geo-blocking) 구성에 사용될 수 있습니다.

Cloudflare 네트워크 방화벽 및 그 구성에 대한 자세한 내용은 참조[Magic Firewall 소개](https://blog.cloudflare.com/introducing-magic-firewall/)·[Cloudflare 네트워크 방화벽 문서](/cloudflare-network-firewall/).

## 항상 주문한 배포에 주의

클라우드 DDoS 완화 서비스 제공 업체는 공격이 감지 될 때만 모든 시간 ( 항상 배포 모델) 또는 다시 루트 트래픽을 모니터링 할 수 있습니다 (주문형). 이 결정은 응답 시간 및 시간 청구에 영향을 미칩니다. 일부 경우에, 그것은 또한 대기 시간에 대 한 repercussions가 있다.

On-demand 배포 모델에서 inbound 트래픽은 네트워크 가장자리에서 모니터링하고 측정하여 Volumetric 공격을 감지합니다. 정상적인 가동 도중, 또는 “peacetime,” 모든 교통은 어떤 지연 또는 리디렉션 없이 신청과 인프라를 직접 도달합니다. 트래픽은 활성 DDoS 공격의 경우에만 클라우드 스크러빙 제공 업체로 전환됩니다. 많은 경우, 고객은 교통을 리디렉션하기 위해 서비스 제공 업체를 호출해야합니다, 응답 시간을 증가.

항상 모드는 공격의 이벤트에서 아무것도 할 필요가 없습니다 DDoS 완화에 대한 손 떨어져 접근입니다. 조직의 트래픽은 항상 보안 검사를위한 클라우드 제공 업체의 데이터 센터를 통해 경로화됩니다. 이 감지에서 완화로 시간을 최소화하고 서비스 중단이 없습니다.

모든 접근 및 배포 옵션 중, 항상 방법은 가장 포괄적 인 보호를 제공합니다.

그러나, 공급자에 따라, DDoS 완화 공급자의 클라우드를 통해 모든 트래픽을 디버깅하는 것은 비즈니스 크리티컬 애플리케이션에 대한 하위 최적화 된 대기 시간을 추가 할 수 있습니다. Cloudflare는 고객이 공격의 결과로 대기권을 침해하지 않도록 설계되어 있습니다. - 항상 배포합니다. 가장자리에 교통을 분석하는 것은 성능에 영향을 미치지 않고 규모로 시작하는 유일한 방법입니다.

이것은 anycast를 통해 트래픽을 섭취하기 때문에 트래픽은 검사를위한 가장 가까운 Cloudflare 데이터 센터에 불과합니다. 데이터 센터[전세계 수백 도시](https://www.cloudflare.com/network/), 그것은 짧은 거리 될 가능성이. 이것은 trombone 효력을 삭제합니다.

많은 경우에,[트래픽은 Cloudflare에 노선이 있을 때 더 빠릅니다](https://www.cloudflare.com/static/360e550c8890054d5e5835efb9fb8dd1/Magic_Transit_protects_networks_while_also_improving_performance__1_.pdf)공공 인터넷 이상. 우리는 고객이 포괄적 인 보안을 달성하기 위해 성능을 희생하지 않아야합니다.

## 제품정보

Cloudflare는 온-프레미스, 클라우드 호스팅 및 하이브리드 엔터프라이즈 네트워크를 연결하는 종합 네트워크 서비스를 제공합니다. Cloudflare는 고객의 독특한 건축물에 맞게 다양한 연결 및 배포 옵션을 제공합니다.

- Cloudflare Magic Transit은 DDoS 공격에 대한 조직을 보호하기 위해 Cloudflare 글로벌 네트워크의 힘을 사용하는 클라우드 기반 네트워크 보안 솔루션입니다.

- Magic Transit은 온프레미스 방화벽을 차단하고 확장하는 네트워크 보안 as-a-service를 배포하는 데 도움이 되는 내장 네트워크 방화벽을 갖추고 있습니다.

- Cloudflare WAN을 사용하여 외부 운전 서비스에 대한 보호 및 라우팅 트래픽뿐만 아니라, 고객은 동서 “인트라 인스톨” 내부 트래픽을 연결하고 보호 할 수 있습니다.

Magic Transit, Cloudflare WAN, 또는 Cloudflare 네트워크 방화벽에 대해 자세히 알고 싶다면[데모 문의](https://www.cloudflare.com/magic-transit/).
