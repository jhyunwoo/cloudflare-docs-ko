## 제품정보

Cloudflare의 통합 One and SentinelOne은 엔드포인트 보호를 결합하는 종합 보안 솔루션으로 조직을 제공합니다.[Zero Trust 네트워크 접근](https://www.cloudflare.com/learning/security/glossary/what-is-zero-trust/). 이 통합은 조직이 장치 보안 자세를 기반으로 액세스 결정을 내릴 수 있으며, 그뿐만 아니라 건강하고 준수 장치가 보호 된 리소스에 액세스 할 수 있도록합니다. 이 참고 자료 아키텍처는 조직이 보안 자세를 강화하기 위해이 통합을 구현하고 활용할 수있는 방법을 설명합니다. 통합은 조직 또는 기관의 Zero Trust Architecture Maturity Model을 개발하는 데 도움이 될 수 있으며, 결국 모든 조직의 목표를 달성하거나 최적화 할 수 있습니다.[CISA의 Zero Trust의 5 기둥.](https://www.cisa.gov/sites/default/files/2023-04/CISA_Zero_Trust_Maturity_Model_Version_2_508c.pdf)

## 이 문서는 누구입니까?

이 참고 자료 아키텍처는 Cloudflare 및 SentinelOne을 사용하여 Zero Trust 보안 모델을 구현하거나 계획하는 IT 및 보안 전문가를 위해 설계되었습니다. 통합 설정, 구성 옵션 및 일반적인 배포 시나리오에 대한 자세한 지침을 제공합니다. 이러한 기술에 대한 강력한 기본 이해를 구축하기 위해, 우리는 플랫폼의 핵심 문서를 검토하는 것이 좋습니다.

Cloudflare의 SentinelOne 통합의 더 강한 이해를 위한 추천된 자원:

- [SentinelOne 장치 자세 통합](/cloudflare-one/integrations/service-providers/sentinelone/)

## 통합 개요

모델 번호: Cloudflare One은 애플리케이션 및 리소스에 대한 장치 기반 액세스 정책을 시행하기 위해 SentinelOne과 통합 할 수 있습니다. 통합은 일련 번호를 기반으로 장치를 식별하는 서비스 투 서비스 자세 검사를 통해 작동합니다. 이 조직은 관리 및 보안 장치가 민감한 리소스에 액세스 할 수 있도록합니다.

## 기술부품

### SentinelOne 부품

SentinelOne 플랫폼은 중요한 엔드포인트 보안 기능을 제공합니다.

SentinelOne 에이전트는 모든 관리 장치에 배포하고 실시간 보안 모니터링 및 위협 탐지를 제공합니다. 주요 자세 데이터 포인트 포함:

- 장치 감염 상태
- 탐지되는 행위의 수
- 에이전트 활동 상태
- Network 연결 상태
- 에이전트의 운영 상태

SentinelOne Management Console은 Cloudflare와의 통합을 위해 필요한 API를 포함한 중앙 제어 및 가시성을 제공합니다.

### Cloudflare 성분

Cloudflare의 Zero Trust 인프라는 정책 시행 층을 제공합니다:

WARP 클라이언트는 관리된 장치에 SentinelOne 대리인 안쪽에 배치되어야 합니다. 이 클라이언트는 Cloudflare의 네트워크에 안전한 연결을 만들고 장치 자세 검사를 가능하게 합니다.

Cloudflare 대시보드는을 위한 윤곽 공용영역을 제공합니다:

- Service Provider 통합 설정
- 장치 자세 정책
- 장치 자세 검사를 통합하는 접근 정책

## 건축설계

### 인증 및 인증 흐름

![그림 1: SentinelOne는 허가 교류의 부분으로 Cloudflare 정책에서 사용됩니다.](~/assets/images/reference-architecture/cloudflare-sase-with-sentinelone/figure1.svg "Figure 1: SentinelOne is used in Cloudflare policies as part of authorization flow.")

사용자가 보호 된 리소스에 액세스하려고 할 때 다음 순서가 발생합니다.

1. 사용자의 장치는 WARP 클라이언트를 통해 Cloudflare의 네트워크에 연결합니다.
2. Cloudflare는 장치의 안전 자세를 검사하기 위하여 SentinelOne API를 쿼리합니다.
3. SentinelOne 플랫폼은 감염 상태, 위협 및 대리인 건강을 포함하여 현재 장치 상태를 반환합니다.
4. Cloudflare는 구성 된 정책에 대한이 정보를 평가합니다.
5. 액세스는 정책 평가를 기반으로 부여 또는 거부됩니다.

### 통합 설정

통합은 특정 구성 단계가 필요합니다.

첫째, 서비스 계정은 적절한 권한을 가진 SentinelOne에서 생성해야합니다. API 토큰을 생성하고 인스턴스의 REST API URL을 표기합니다.

다음, SentinelOne은 Cloudflare Zero Trust 대시보드QX에서 서비스 제공 업체로 구성해야합니다. 다음을 포함합니다:

- API 토큰 및 REST API URL 제공
- 적절한 오염 빈도 설정
- 적절한 통신을 보장하기 위해 연결 테스트

마지막으로, 장치 자세 검사는 액세스에 대한 보안 요구 사항을 정의하도록 구성해야합니다. 자세한 설정 지침은 참조[SentinelOne 장치 자세 통합](/cloudflare-one/integrations/service-providers/sentinelone/).

## 보안 기능

### Device posture 인증

통합은 여러 속성을 통해 강력한 장치 보안 검증을 가능하게 합니다.

감염 상태 모니터링은 손상된 장치가 민감한 리소스에 액세스 할 수 없다는 것을 보장합니다. Active Threat Detection은 지속적인 보안 사고를 방지합니다. Agent Health Monitoring은 보안 스택이 기능적이고 올바르게 구성된다는 것을 확인합니다.

### 사용자 위험 감지

SentinelOne은[엔드포인트 탐지 및 응답 (EDR)](https://www.sentinelone.com/cybersecurity-101/endpoint-security/what-is-endpoint-detection-and-response-edr/)사용자의 위험 점수를 결정하는 데 도움이되는 신호. 보안 위험이 발생할 수 있는 사용자를 식별하고 관리할 수 있습니다.

## 핵심 건축

![그림 2: SentinelOne와 Cloudflare Zero Trust 기술적인 건축술.](~/assets/images/reference-architecture/cloudflare-sase-with-sentinelone/figure2.svg "Figure 2: SentinelOne and Cloudflare Zero Trust technical architecture.")

통합 아키텍처는 관리형 엔드포인트 장치 수준에서 시작되며, 두 가지 중요한 구성 요소가 협동합니다. SentinelOne 대리인은 1 차적인 안전 힘으로, 지속적으로 위협을 위한 장치를 감시하고, 장치 건강을 평가하고, 순간 안전 상태 갱신을 제공합니다. Cloudflare WARP 클라이언트가 보안 연결을 설정하고 Cloudflare의 Zero Trust 인프라와 함께 장치의 상호 작용을 관리합니다. 이러한 구성 요소는 endpoint 보안 및 보안 네트워크 액세스를 보장하기 위해 tandem에서 작동합니다.

사용자가 보호 된 리소스에 액세스하려고 할 때, 아키텍처는 정교한 검증 프로세스를 시작합니다. WARP 클라이언트는 첫번째 모든 커뮤니케이션을 위한 암호화된 수로를 창조하는 Cloudflare의 세계적인 네트워크에 안전한 갱도를 설치합니다. 이 연결은 장치와 보호된 자원 사이 모든 트래픽이 안전하게 유지되고 보안 정책을 통해 제대로 평가될 수 있다는 것을 보증합니다.

### Cloudflare Zero Trust 플랫폼 가동

건축의 중심에는 Cloudflare Zero Trust 플랫폼, 콘서트에서 일하는 3개의 주요 엔진으로 이루어져 있습니다. 더 보기**장치 Posture 엔진**첫 번째 방어선 역할을 담당하고 있는 SentinelOne 플랫폼은 디바이스의 보안 상태를 확인하기 위한 것입니다. 감염 상태, 활성 위협, 에이전트 건강 및 네트워크 연결 상태를 포함하여 여러 속성을 확인합니다. 이 정보는 액세스 결정의 기초를 형성합니다.

더 보기**Access Policy 엔진**그런 다음이 장치 자세 정보를 가지고 액세스 결정을 내릴 다른 컨텍스트 요소와 결합합니다. 장치 보안 상태, 사용자 정체성, 위치 및 기타 위험 요인과 같은 기준을 포함 할 수있는 사전 정의 정책을 평가합니다. 이 엔진은 모든 보안 요구 사항을 충족하는 유일한 장치 만 보호 리소스에 액세스 할 수 있습니다.

더 보기**보안 웹 게이트웨이**모든 트래픽을 필터링하여 보호의 또 다른 층을 추가하고, 악의적인 사이트에 접근을 방지하고, 데이터 손실 방지 정책을 해제합니다. 이 성분은 접근이 부여된 후에 조차, 모든 교통은 지속적으로 감시되고 보호됩니다.

### SentinelOne 플랫폼 통합

SentinelOne 플랫폼은 세 가지 주요 구성 요소를 통해이 아키텍처에서 중요한 역할을합니다. 더 보기**관리 콘솔**모든 엔드포인트를 통해 중앙제어를 제공하므로 보안팀이 정책, 모니터링 장치 상태 및 보안 이벤트에 대응할 수 있습니다. 더 보기**API 서비스**구성 요소는 Cloudflare와 실시간 통신을 촉진하여 관리되는 장치에 대한 중요한 보안 정보를 제공합니다.

더 보기**보안 Analytics**구성 요소는 모든 엔드 포인트에서 보안 원격 측정을 지속적으로 처리하고 위협을 식별하고 위험을 평가하고 상세한 보안 통찰력을 제공합니다. 이 정보는 Cloudflare로 흐릅니다**API 서비스**, 최신 보안 인텔리전스를 기반으로 동적 액세스 결정 활성화.

### 인증 및 액세스 흐름

사용자가 보호 된 리소스에 액세스 할 때, 아키텍처는 특정 흐름을 따릅니다.

첫째, 장치의 보안 상태가 평가됩니다.**SentinelOne 에이전트**SentinelOne 플랫폼에 대한 상세한 건강 및 보안 정보를보고하는 . 동시에,**Cloudflare WARP 클라이언트**Cloudflare의 Zero Trust 플랫폼에 접근 요청을 개시합니다.

다음 것, Cloudflare의**장치 Posture 엔진**SentinelOne 플랫폼을 통해 쿼리**API 서비스**장치의 보안 상태를 확인합니다. 이 체크에는 현재 보안 미터, 위협 상태 및 규정 준수 정보가 포함됩니다. 더 보기**Access Policy 엔진**정의된 보안 정책에 대한 이 정보를 평가합니다.

모든 보안 요구 사항이 충족되면 WARP 클라이언트가 설치된 보안 터널을 통해 액세스가 부여됩니다. 세션을 통해 지속적인 모니터링은 장치 보안 상태의 변경 사항이 즉시 액세스 권한을 유발할 수 있음을 보장합니다.

### 보안 및 모니터링 기능

건축은 다수 기계장치를 통해서 포괄적인 안전을 제공합니다. 엔드포인트 수준에서 SentinelOne 에이전트는 고급 위협 탐지 및 응답 기능을 제공합니다. 더 보기**보안 Analytics**구성 요소는 실시간 보안 원격 측정, 위협 및 보안 문제의 빠른 식별을 가능하게합니다.

Cloudflare의**보안 웹 게이트웨이**네트워크 수준의 보호를 제공, 트래픽 필터링 및 악의적 자원에 액세스 방지. 이 구성 요소는 함께 작동**Access Policy 엔진**모든 트래픽을 보장하기 위해 내부 및 외부 리소스 모두 보안 요구 사항을 충족합니다.

## 작업 혜택

이 통합된 건축은 몇몇 중요한 가동 이익을 전달합니다. Zero Trust 액세스 제어를 구현하는 조직을 활성화하여 모든 액세스 요청이 현재 보안 상태를 기반으로 확인됩니다. SentinelOne과 Cloudflare의 통합은 네트워크 수준 접근 제한을 가진 endpoint 보호를 결합하는 이음새가 없는 안전 시행을 제공합니다.

이 아키텍처는 동적 정책 시행을 지원하며 장치 보안 상태의 변경은 자동으로 액세스 제한을 유발할 수 있습니다. 이 손상되거나 비 고분고분한 장치가 민감한 자원에서 빨리 격리될 수 있다는 것을 보증합니다, 조직적인 안전을 유지하십시오.

## 배포 고려사항

### 네트워크 아키텍처

이 통합을 구현할 때 네트워크 아키텍처를 고려해야 합니다. 주요 요인은 다음을 포함합니다:

- 다른 네트워크를 통한 endpoints 배포
- 자세 검사를 위한 대역폭과 대기권 필요조건
- 기존 보안 도구 및 워크플로우 통합

Cloudflare의 통합 One and SentinelOne은 성공적인 구현을 보장하기 위해 많은 계획이 필요합니다. 그것의 기초에, 조직은 SentinelOne 대리인 및 Cloudflare WARP 클라이언트가 자세 검사에 주제일 것이다 모든 장치에 배치된 그들의 환경을 준비해야 합니다. 이 기초 단계는 보안 모니터링 및 보안 네트워크 연결 모두 추가 보안 제어를 구축하기 전에 장소에 있습니다.

통합을 구현할 때, 조직은 SentinelOne이 장치 보안 정보의 신뢰할 수있는 소스 역할을하는 서비스 제공 업체 관계로 접근해야합니다. 이 관계는 안전한 API 커뮤니케이션을 통해서 설치되고, 주의깊은 관심은 플랫폼 사이 연결의 적절한 자격 관리 그리고 일정한 검증에 지불했습니다. 통합은 Cloudflare를 사용하여 실시간 장치 보안 상태를 제공하는 SentinelOne의 능력에 의존하여 액세스 결정을 내립니다.

### 정책 디자인

효과적인 정책 디자인은 보안과 유용성을 위해 중요합니다. 정책 구현을 고려:

- 기본적인 위생 필요조건과 점차적인 증가 안전 필요조건으로 시작하십시오
- 다른 사용자 역할 및 액세스 요구를위한 계정
- 탁월한 상황에 대한 fallback 옵션 포함

정책 구성은 배포의 또 다른 중요한 측면을 나타냅니다. 조직은 SentinelOne의 상세한 장치 자세 정보를 활용하여 nuanced Access 정책을 만들 수 있습니다. 이 정책은 장치 감염 상태, 활성 위협 및 에이전트 건강과 같은 여러 요인에 걸릴 수 있습니다. 이러한 다양한 속성을 모니터링함으로써 조직은 보안 요구 사항을 충족하는 유일한 장치만 보호 리소스에 액세스 할 수 있습니다.

일반 테스트 및 모니터링 통합의 효율성을 유지에 중요한 역할을합니다. Cloudflare의 로깅 및 테스트 기능을 통해 조직은 자세 검사가 의도적이고 정책이 올바르게 시행된다는 것을 확인할 수 있습니다. 이 지속적인 검증은 통합의 보안 혜택을 지속적으로 실현하는 데 도움이됩니다.
