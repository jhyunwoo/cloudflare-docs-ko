## 새로운 epoch를 게시

아래 예제를 참조하여 서명을 요청하여 새로운 epoch를 게시합니다.

이 API를 통해 인증[사이트맵](https://www.cloudflare.com/learning/access-management/what-is-mutual-tls/), 그래서 단지 로그 소유자는 새로운 epochs를 게시 할 수 있습니다.

```sh
curl 'https://plexi.key-transparency.cloudflare.com/namespaces/{namespace}/audits' \
      --header 'Content-Type: application/json' \
      --data '{"epoch": 1, "digest": "1111111111111111111111111111111111111111111111111111111111111111"}'
{
  "namespace": "your.new.log.com",
  "timestamp": 1717084639921,
  "epoch": 1,
  "digest": "1111111111111111111111111111111111111111111111111111111111111111",
  "signature": "f6a51443bb6703813b330959d9d97471bc06464142165e59733fa102a18b052782a5307d59c31b8b13c1af7dfff6f6e7bf44e880d44e26e96c50a72f72a30c07",
  "key_id": 74,
}
```

### 옵션 정보

- 이름 \*`root`namespace에 정의되어, 첫번째 epoch는 (number와 digest) 일치해야합니다.
- Epochs는 증가해야 합니다. 두번째 epoch는 2, 3입니다 3, 등입니다.
- Epochs는 독특하고 digest가 있어야 합니다.
- Epochs는 재발행할 수 없습니다.
- Digest는 32 바이트 문자열 hex 인코딩되어야 합니다 (길이 64).

namespace가 비활성화되면 다음 오류를받습니다.

```txt
HTTP 400 Bad Request
Namespace is disabled and read-only.
```
