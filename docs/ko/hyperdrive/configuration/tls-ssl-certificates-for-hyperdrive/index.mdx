Hyperdrive는 데이터베이스에 연결되는 추가 방법을 제공합니다. Hyperdrive 지원:

1. **서버 인증서**TLS (SSL) 모드와 같은`verify-ca`·`verify-full`증가된 보안. 구성될 때, Hyperdrive는 예상되는 증명서 권위 (CA)에 의해 man-in-the-middle 공격을 피하기 위하여 서명되었습니다.
2. **고객 인증서**Hyperdrive를 위해 사용자 이름/password를 넘어서는 credentials를 가진 당신의 데이타베이스에 자신을 정정하기 위하여. 제대로 클라이언트 인증서를 사용하려면 데이터베이스는 Hyperdrive와 같은 클라이언트가 제공 한 클라이언트 인증서를 확인하도록 구성해야하며 데이터베이스에 액세스 할 수 있습니다.

Hyperdrive는 보안 요구 사항 및 데이터베이스 구성에 따라 서버 인증서, 클라이언트 인증서 만 사용하도록 구성 할 수 있습니다.

:::참조

서버 인증서 및 클라이언트 인증서에 대한 지원은 MySQL (beta)에서 사용할 수 없습니다. 서버 인증서 및 클라이언트 인증서에 대한 지원은 로컬 개발에서만 사용할 수 있습니다.`npx wrangler dev --remote`Workers와 HyperdriveXQ를 로컬 디버깅과 함께 Cloudflare의 네트워크를 실행합니다.

:::

## 서버 인증서 (TLS/SSL 모드)

Hyperdrive는 3개의 일반적인 암호화를 지원합니다[TLS/SSL 모드](https://www.postgresql.org/docs/current/libpq-ssl.html)데이터베이스에 연결하기:

- `require`(과태): TLS는 암호화된 연결성 및 서버 인증서가 검증됩니다 (WebPKI 기반).
- `verify-ca`: Hyperdrive는 데이터베이스 서버가 예상되는 루트 인증서 기관 또는 중간 인증서 기관에 의해 서명되었는지 확인하여 신뢰할 수 있습니다.
- `verify-full`: 식별`verify-ca`, 그러나 Hyperdrive는 또한 증명서에 존재하는 주제 대안 이름 (SAN) 일치하기 위하여 데이타베이스 hostname를 요구합니다.

기본적으로 모든 Hyperdrive 구성은 SSL/TLS로 암호화됩니다 (`require`). 이 데이터베이스가 암호화된 연결을 허용하도록 구성해야 합니다(SSL/TLS).

Hyperdrive를 구성할 수 있습니다.`verify-ca`·`verify-full`더 엄격한 보안 구성을 위해 서버 인증서의 추가 검증 확인을 제공합니다. 이것은 man-in-the-middle 공격에 대 한 감시.

서버의 인증서를 확인하려면 Hyperdrive를 구성하려면 Hyperdrive를 루트 인증서 권위 (CA) 또는 데이터베이스의 인증서에 서명하기 위해 사용되는 중간 인증서를 제공해야합니다.

### 단계 1: 루트 인증서 권한을 업로드 (CA) 인증서

Wrangler를 사용하여 루트 인증서 기관 (CA) 인증서를 업로드 할 수 있습니다.

```bash
#Wrangler 4.9.0 이상
npx wrangler cert upload certificate-authority --ca-cert \<ROUTE_TO_CA_PEM_FILE\>.pem --name \<CUSTOM_NAME_FOR_CA_CERT\>

---

Uploading CA Certificate tmp-cert...
Success! Uploaded CA Certificate <CUSTOM_NAME_FOR_CA_CERT>
ID: <YOUR_ID_FOR_THE_CA_CERTIFICATE>
...
```

:::참조

특정 지역에는 CA 인증서 번들을 사용해야 합니다. CA 인증서 번들을 사용하여 각 지역의 인증서를 포함하는 CA 인증서의 글로벌 번들와 같은 CA 인증서 번들을 사용할 수 없습니다.

:::

### 단계 2: CA 인증서 및 SSL 모드를 사용하여 Hyperdrive 구성 만들기

CA 인증서가 생성되면 Hyperdrive 구성을 대시보드 또는 Wrangler를 사용하여 새로 생성 된 인증서로 만들 수 있습니다. SSL 모드를 지정해야 합니다.`verify-ca`또는`verify-full`이용하기

<Tabs>
  <TabItem label="Wrangler">

    ```bash
    npx wrangler hyperdrive create <NAME_OF_HYPERDRIVE_CONFIG> --connection-string="postgres://user:password@HOSTNAME_OR_IP_ADDRESS:PORT/database_name" --ca-certificate-id <YOUR_CA_CERT_ID> --sslmode verify-full
    ```
  </TabItem>

Hyperdrive 윤곽을 창조할 때, Hyperdrive는 제공한 credentials를 가진 데이타베이스에 연결할 것을 시도할 것입니다. 명령이 성공적인 결과를 제공하는 경우, 데이터베이스 서버에서 제공되는 인증서를 확인하려면 Hyperdrive 구성을 올바르게 구성해야 합니다.

:::참조

Hyperdrive는 구성을 만들기 전에 올바른 확인하기 위해 제공된 자격 증명을 사용하여 데이터베이스에 연결하려고합니다. 연결 시도 할 때 오류가 발생하면 Hyperdrive의 참조[문제 해결 문서](/hyperdrive/observability/troubleshooting/)가능한 원인을 디버그합니다.

:::

## 고객 인증서

데이터베이스를 구성할 수 있습니다.[클라이언트가 제공하는 인증서 확인](https://www.postgresql.org/docs/current/libpq-ssl.html#LIBPQ-SSL-CLIENTCERT), 이 경우에, Hyperdrive. 클라이언트를 인증하기 위한 추가적인 요소(사용자 이름과 암호 이외에) 역할을 합니다.

클라이언트 인증서를 확인할 수 있는 데이터베이스 서버의 경우, Hyperdrive는 인증서 파일을 제공하도록 구성해야 합니다 (`client-cert.pem`) 그리고 인증서가 생성 된 개인 키 (`private-key.pem`).

### 단계 1: 클라이언트 인증서 업로드 (mTLS 인증서)

HyperdriveXQXQXQXQXQXQXQXQ에 의해 사용 될 클라이언트 인증서를 업로드:

```bash
#Wrangler 4.9.0 이상
npx wrangler cert upload mtls-certificate --cert client-cert.pem --key client-key.pem --name <CUSTOM_NAME_FOR_CLIENT_CERTIFICATE>

---

Uploading client certificate <CUSTOM_NAME_FOR_CLIENT_CERTIFICATE>...
Success! Uploaded client certificate <CUSTOM_NAME_FOR_CLIENT_CERTIFICATE>
ID: <YOUR_ID_FOR_THE_CLIENT_CERTIFICATE_PAIR>
...
```

### 2 단계 : Hyperdrive 구성

대시보드 또는 WranglerXQ를 사용하여 새로 만들어진 클라이언트 인증서 번들을 사용하여 HyperdriveXQXQXQXQXQXQXQ를 만들 수 있습니다.

<Tabs>
  <TabItem label="모델 번호: Wrangler">
    Wrangler를 사용하여 터미널에서 다음 명령을 입력하여 클라이언트 인증서 쌍을 사용하여 Hyperdrive 구성을 만듭니다.

    ```bash
    npx wrangler hyperdrive create <NAME_OF_HYPERDRIVE_CONFIG> --connection-string="postgres://user:password@HOSTNAME_OR_IP_ADDRESS:PORT/database_name" --mtls-certificate-id <YOUR_CLIENT_CERT_PAIR_ID>
    ```
  </TabItem>

  <TabItem label="대시보드">
    대시보드에서 서버 인증서로 Hyperdrive 구성을 만들려면이 단계를 따르십시오.

    1. Cloudflare 대시보드에서, 가십시오**모델 번호: Hyperdrive**사이트 맵

       <DashButton url="/?to=/:account/workers/hyperdrive" />
    2. 제품정보**설정 만들기**.
    3. 제품정보**고객 인증서**.
    4. SSL 클라이언트 인증서 및 개인 키 쌍을 선택 Hyperdrive 데이터베이스 서버와 연결 설정 중 사용.
  </TabItem>
</Tabs>

Hyperdrive가 데이터베이스에 연결되면 데이터베이스 서버에 개인 키와 서명 한 클라이언트 인증서를 제공 할 것입니다. 이것은 데이터베이스 서버가 클라이언트가이 경우 Hyperdrive에서 클라이언트가 개인 키와 클라이언트 인증서를 모두 가지고 있는지 확인합니다. 클라이언트 인증서를 사용하여 데이터베이스에 추가 인증 레이어를 추가하여 Hyperdrive만 연결할 수 있습니다.

:::참조

Hyperdrive는 구성을 만들기 전에 올바른 확인하기 위해 제공된 자격 증명을 사용하여 데이터베이스에 연결하려고합니다. 연결 시도 할 때 오류가 발생하면 Hyperdrive의 참조[문제 해결 문서](/hyperdrive/observability/troubleshooting/)가능한 원인을 디버그합니다.
