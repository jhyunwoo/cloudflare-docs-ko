Query rewriting은 AI Search 파이프라인에서 선택적 단계이며, 원래 사용자 쿼리를 더 효과적인 검색 쿼리로 변환하여 검색 품질을 향상시킬 수 있습니다.

원본 사용자 입력을 직접 삽입하는 대신, AI Search는 시스템 프롬프트에 근거를 둔 쿼리를 다시 쓰기 위해 큰 언어 모델을 사용할 수 있습니다. rewritten 쿼리는 벡터 검색을 수행하는 데 사용됩니다.

## 왜 쿼리 rewriting 사용?

사용자의 질문에 대한 말은 문서가 작성된 방법을 일치하지 않을 수 있습니다. Query rewriting 도움 bridge 이 gap 로:

- Rephrasing informal 또는 vague 쿼리는 정확하고, 정보 밀도 용어
- synonyms 또는 관련 키워드 추가
- Removing 필러 단어 또는 관련 세부 사항
- Incorporating 도메인 별 용어

이것은 최종 생성된 응답의 정확도를 개량하는 더 관련 벡터 경기에 지도합니다.

## 이름 \*

**본래 질문:** `how do i make this work when my api call keeps failing?`

**Rewritten 쿼리:** `API call failure troubleshooting authentication headers rate limiting network timeout 500 error`

이 예제에서, 원본 쿼리는 대화 및 vague입니다. rewritten 버전은 핵심 문제 (API 호출 실패)를 추출하고 관련 기술 용어와 가능성이 원인으로 확장합니다. 이 용어는 문서 또는 로그에 나타나기 위해 훨씬 더 가능성이 있으며, 벡터 검색 중에 semantic matching을 개선합니다.

## 어떻게 작동합니까?

쿼리 rewriting이 활성화되면, AI Search는 다음을 수행합니다.

1. 이름 \***원본 사용자 쿼리**그리고**rewrite 체계 신속한**구성 LLM
2. 수상내역**rewritten 쿼리**모델에서
3. 선택한 embedding 모델을 사용하여 rewritten 쿼리를 구현
4. AI 검색 Vectorize 인덱스에서 벡터 검색 수행

이 단계에서 모델 행동을 안내하는 방법에 대한 자세한 내용은[시스템 프롬프트](/ai-search/configuration/system-prompt/)문서.

:::참조
모든 AI 검색 요청을 통해 경로[AI 게이트웨이](/ai-gateway/)로그인 설정 중에 AI Gateway를 선택하지 않으면 AI Search는 인스턴스의 기본 게이트웨이를 만듭니다. 검색할 수 있는 쿼리를 다시 작성, embeddings, text generation, and other model call in the AI Gateway logs for monitoring and debugging.
