웹 사이트 데이터 소스를 사용하면 페이지가 크롤링, 저장 및 색인 할 수 있도록 도메인을 연결할 수 있습니다.

동일한 Cloudflare 계정에 내장된 crawl 도메인만 사용할 수 있습니다. 더 알아보기[도메인 등록](/fundamentals/manage-domains/add-site/)Cloudflare 계정에 도메인 추가에 대한 자세한 내용은.

:::caution\[Bot 보호는 크롤러를 막을지도 모릅니다]
CloudflareXQ 제품을 사용하여 제어 또는 봇 트래픽을 제한하는 경우[Bot 관리](/bots/), [웹 응용 프로그램 방화벽 (WAF)](/waf/), 또는[모델 번호: Turnstile](/turnstile/), 같은 규칙은 AI 검색 크롤러에 적용됩니다. 설정에서 AI Search crawler에 대한 예외 또는 허용 목록을 구성해야합니다.
주요 특징

## 웹 사이트 크롤러 작업

도메인을 연결할 때, 크롤러는 웹 사이트의 사이트 맵을 참조하여 해당 페이지를 방문하십시오.

1. 크롤러 첫번째 체크`robots.txt`관련 사이트
2. 없음`robots.txt`에서 사이트 맵에 대한 크롤러 검사`/sitemap.xml`.
3. 사이트 맵을 사용할 수 없다면 도메인은 크롤링 할 수 없습니다.

### 회사연혁

사이트 맵이 포함된 경우`<priority>`속성, AI Search는 모든 사이트 맵을 읽고 각 페이지의 우선 순위를 기준으로 페이지의 인덱스 페이지는 페이지에 있습니다.

없음`<priority>`지정된 페이지는 sitemaps가 목록에 나열된 순서로 인덱스됩니다.`robots.txt`정상에서 바닥에.

AI 검색 지원`.gz`압축 사이트 맵. 모두 보기`robots.txt`사이트 맵은 부분 URL을 사용할 수 있습니다.

## 경로 필터링

URL 경로에 대한 규칙을 제외하고, defining에 의해 색인을 얻을 수있는 페이지를 제어 할 수 있습니다. 사이트의 특정 섹션에 인덱스를 제한하거나 검색 할 수없는 콘텐츠를 제외합니다.

:::참조
Path filtering match against the full URL, including the 계획, hostname, 그리고 subdomains. 예를 들어, 페이지`https://www.example.com/blog/post`같은 패턴을 요구합니다.`**/blog/**`채팅하기 사용 방법`/blog/**`혼자 호스트 이름에 계정이 없기 때문에 일치하지 않습니다.
주요 특징

예를 들어, 초안을 제외하고는 블로그 게시물 만 색인합니다.

- **포함 :** `**/blog/**`
- **제외 :** `**/blog/drafts/**`

더 알아보기[경로 필터링](/ai-search/configuration/path-filtering/)패턴 문법, 필터링 행동, 그리고 더 많은 예제.

## robots.txt 및 sitemap에 대한 모범 사례

설정하기`robots.txt`사이트 맵 에 도움 AI Search crawl 당신의 사이트 효율적.

### 로봇.txt

AI Search 크롤러는 사용자 대리인을 사용합니다`Cloudflare-AI-Search`. 너의`robots.txt`파일은 참고 자료 귀하의 사이트 맵을 확인하고 크롤러를 허용한다 :

```txt title="robots.txt"
User-agent: *
Allow: /

Sitemap: https://example.com/sitemap.xml
```

여러 사이트 맵을 나열하거나 사이트 맵 인덱스 파일을 사용할 수 있습니다.

```txt title="robots.txt"
User-agent: *
Allow: /

Sitemap: https://example.com/sitemap.xml
Sitemap: https://example.com/blog-sitemap.xml
Sitemap: https://example.com/sitemap.xml.gz
```

다른 모든 크롤러를 차단하지만 AI 검색만 허용:

```txt title="robots.txt"
User-agent: *
Disallow: /

User-agent: Cloudflare-AI-Search
Allow: /

Sitemap: https://example.com/sitemap.xml
```

### 사이트 맵

사이트 맵을 구축하여 AI를 검색하는 정보를 효율적으로 크롤링해야합니다.

```xml title="sitemap.xml"
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://example.com/important-page</loc>
    <lastmod>2026-01-15</lastmod>
    <changefreq>weekly</changefreq>
    <priority>1.0</priority>
  </url>
  <url>
    <loc>https://example.com/other-page</loc>
    <lastmod>2026-01-10</lastmod>
    <changefreq>monthly</changefreq>
    <priority>0.5</priority>
  </url>
</urlset>
```

이 속성을 사용하여 crawling 동작을 제어하십시오.

| 사이트 맵          | 제품정보              | Recommend                                                                                   |
| -------------- | ----------------- | ------------------------------------------------------------------------------------------- |
| `<loc>`        | 페이지의 URL          | 견적 요청 전체 또는 부분 URL을 사용하십시오.                                                                 |
| `<lastmod>`    | 마지막 수정일           | 변경 감지를 가능하게 합니다. AI Search re-crawls 페이지 이 날짜가 변경 될 때.                                      |
| `<changefreq>` | 예상된 변화 빈도         | 사용시`<lastmod>`없습니다. 가치:`always`, `hourly`, `daily`, `weekly`, `monthly`, `yearly`, `never`. |
| `<priority>`   | 상대적 중요성 (0.0-1.0) | 중요한 페이지에 더 높은 값을 설정합니다. AI Search는 우선순위에 있는 페이지를 색인합니다.                                     |

당신은 또한 다른 번들에 사이트맵 인덱스를 사용할 수 있습니다, 도메인 특정 사이트 맵:

```xml title="sitemap-index.xml"
<?xml version="1.0" encoding="UTF-8"?>
<sitemapindex xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <sitemap>
    <loc>https://www.example.com/sitemap-blog.xml</loc>
    <lastmod>2024-08-15T10:00:00+00:00</lastmod>
  </sitemap>
  <sitemap>
    <loc>https://www.example.com/sitemap-docs.xml</loc>
    <lastmod>2024-08-10T12:00:00+00:00</lastmod>
  </sitemap>
</sitemapindex>
```

사이트 맵을 파싱 할 때, AI Search는 모든 어린이 사이트 맵을 수집하고, 그 결과, 사이트 맵에서 모든 관련 URL을 수집합니다.

### Recommend

- **이름 \*`<lastmod>`**&#xBAA8;든 URL에서 동기화 중에 효율적인 변경 감지를 가능하게합니다.
- **설치하기`<priority>`**&#x49;ndexing 순서를 통제하기 위하여. 더 높은 우선 순위를 가진 Pages는 첫번째 색인을 붙입니다.
- **제품 정보`<changefreq>`**&#xD604;재 위치`<lastmod>`없습니다.
- **sitemap 인덱스 파일**다수 sitemaps를 가진 큰 위치를 위해.
- **큰 사이트 맵 압축**이름 \*`.gz`대역폭을 줄이기 위한 형식.
- **50MB 이하 사이트 맵 유지**파일 당 50,000 URL (표준 사이트 맵 제한).

## 옵션 선택

Onboarding 또는 인스턴스 설정에서 옵션을 설정할 수 있습니다.**Parser 옵션**.

### 특정 사이트 맵

기본적으로 AI Search crawls all sitemaps 나열`robots.txt`그들이 나타나는 순서에서 (아래로). 모든 것을 색인하기 위해 크롤러를 원하지 않는 경우, 페이지가 크롤링되는 한계에 단일 사이트 맵 URL을 지정할 수 있습니다. 최대 5개의 특정 사이트 맵을 추가할 수 있습니다.

### 연출 형태

당신은 방법을 선택할 수 있습니다 페이지는 크롤링 중 파쇄:

- **정적 위치**: 각 페이지의 원본 HTML을 다운로드합니다.
- **사이트 맵**: 헤드리스 브라우저를 가진 페이지로드하고 동적 JavaScript 콘텐츠를 포함하여 완전히 렌더링 된 버전을 다운로드합니다. 주의사항[브라우저 렌더링](/browser-rendering/pricing/)제한 및 청구 신청.

## 액세스 보호 콘텐츠에 대한 추가 헤더

웹 사이트가 인증 뒤에 페이지를 가지고 있거나 로그인 된 사용자 만 볼 수 있다면, 이 보호 된 콘텐츠에 액세스하기 위해 AI 검색 크롤러를 허용하기 위해 사용자 정의 HTTP 헤더를 구성 할 수 있습니다. 요청 AI 검색에 최대 5개의 사용자 지정 HTTP 헤더를 추가할 수 있습니다.

### Cloudflare에 의해 보호되는 위치에 접근 제한 오시는 길

AI Search to crawl 사이트 보호[Cloudflare 오시는 길](/cloudflare-one/access-controls/), 당신은 서비스 토큰 자격 증명을 만들고 사용자 정의 헤더로 구성해야합니다.

서비스 토큰 우회 사용자 인증, 그래서 귀하의 액세스 정책은 인덱스를 원하는 콘텐츠를 적절하게 구성. 서비스 토큰은 AI 검색 크롤러가 서비스 Auth 정책에 의해 덮여 모든 콘텐츠를 액세스 할 수 있습니다.

  6. 제품정보**웹 사이트**데이터 소스로.

## 제품 정보

설정 중 AI Search는 계정의 전용 R2 버킷을 작성하여 HTML 파일로 다운로드 된 페이지를 저장합니다. 이 물통은 자동적으로 관리되고 크롤러에 의해 발견된 내용만을 위해 사용됩니다. 이 물통에 직접 추가하는 어떤 파일 또는 물체는 색인되지 않을 것입니다.

:::참조
우리는 그것이 색인을 고주파로 변환시키고 내용이 제대로 업데이트되지 않을 수 있기 때문에 물통을 수정하지 않는 것이 좋습니다.

## 동기화 및 업데이트

예정된 또는 수동 도중[sync 작업](/ai-search/configuration/indexing/), 크롤러는 변경을 위해 검사할 것입니다`<lastmod>`사이트 맵에 속성. 마지막으로 동기화 날짜 이후에 발생하는 날짜로 변경 된 경우, 그 페이지는 크롤링 될 것입니다, 업데이트 된 버전은 R2 물통에 저장되며, 자동으로 검색 결과가 항상 최신 콘텐츠를 반영합니다.

만약에`<lastmod>`속성은 정의되지 않습니다, AI Search 용도`<changefreq>`URL을 re-crawl하는 방법을 결정하는 속성. 없음`<lastmod>`이름 \*`<changefreq>`정의, AI Search는 매일 한 번에 자동 크롤러 각 링크.

## 제한 사항

일반 AI 검색[제한 사항](/ai-search/platform/limits-pricing/)웹 사이트 데이터 소스를 사용할 때 적용하십시오.

크롤러는 AI Search 인스턴스를 위해 지원되는 최대 객체 제한까지만 다운로드하고 색인 페이지를 색인합니다. 그 제한이 도달될 때까지 방문한 페이지의 첫 세트를 처리합니다. 또한 다운로드 된 모든 파일이 있지만 파일 크기 제한을 초과하지 않습니다.
