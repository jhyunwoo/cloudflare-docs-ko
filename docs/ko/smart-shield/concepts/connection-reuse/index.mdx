Smart Shield는 Cloudflare의 최적화된 인프라를 활용해 [상위 티어](/smart-shield/configuration/smart-tiered-cache/)에서 들어오는 여러 요청을 오리진으로 향하는 단일 연결로 묶습니다. 즉, 오리진으로 향하는 전체 연결 수가 평균적으로 30% 감소합니다. 자세한 내용은 [블로그 게시물](https://blog.cloudflare.com/introducing-observatory-and-smart-shield/#protecting-and-accelerating-origins-with-smart-connection-reuse)을 참고하세요.

## 연결 재사용 소개

HTTP/1.1에 의해 구현되는 연결 재사용은 하나의 동일한 연결(하나의 소스 IP:포트와 하나의 대상 IP:포트 사이)을 통해 여러 요청이 전달되는 방식을 뜻합니다. 오늘날에는 단순한 웹사이트에서도 흔히 사용됩니다.

예를 들어 `shop.example.com`에 대한 연결이 시작되면 CSS, 이미지 파일, 광고 등 여러 임베드된 하위 리소스가 요청될 수 있습니다. 이로 인해 웹사이트 하나를 로드하는 데만 수백 개의 요청이 발생할 수 있습니다. 요청 하나당 연결 하나를 사용하는 대신, 하나의 연결이 여러 요청에 사용됩니다.

HTTP/2에서는 요청 대상이 서로 다른 도메인이라도 동일한 연결을 사용할 수 있습니다. 이를 연결 병합(connection coalescing)이라고도 합니다.

예를 들어 `shop.example.com`에 대해 시작된 연결은 `blog.example.com`에 대한 요청에도 사용할 수 있습니다. 단, 요청의 대상 IP:포트가 동일하고 서버 TLS 인증서가 두 호스트명 모두에 대해 권한을 갖고 있어야 합니다.

## 송신 IP 할당

연결 재사용과 연결 병합은 [Dedicated CDN Egress IPs](/smart-shield/configuration/dedicated-egress-ips/)를 할당할 때도 고려됩니다.
