Cloudflare는 Cloudflare로 보안 관련 분야에 대한 몇 가지 업데이트를 배포합니다. 이 업데이트는 다음과 같은 datasets에 영향을 줄 것입니다.

- [HTTP 요청](/logs/logpush/logpush-job/datasets/zone/http_requests/)
- [방화벽 이벤트](/logs/logpush/logpush-job/datasets/zone/firewall_events/)

## - 연혁

고객의 기존에 미치는 영향 최소화<GlossaryTooltip term="SIEM">사이트맵</GlossaryTooltip>구성, 이러한 업데이트는 다음과 같은 타임 라인에 따라 두 단계에서 발생합니다.

### 단계 1 (2 월 1, 2023)

로그 필드를 추가하려면 Cloudflare는 점차 데이터셋을 로그에 추가합니다.

로그인 필드를 위해 Cloudflare는 다음과 같습니다.

- **새 필드 추가**단계 2에 제거 될 필드와 동일한 데이터 (이 문서에서 이전 필드로 삭제). 이 새로운 필드는 점차적으로 사용할 수 있습니다. 자세한 내용은 다음 섹션을 참조하십시오.
- **이전 필드의 결정 발표.**&#x43;loudflare는 8월 1, 2023에 로그 데이터셋에서 이러한 필드를 제거합니다.

제거되는 로그 필드를 위해, Cloudflare는 deprecated로 그들을 announcing. 로그 데이터 세트의 제거는 8 월 1, 2023에 발생합니다.

이 Cloudflare 이외에 로그 변경, Cloudflare 또한 다음에 새로운 보안 관련 필드 추가[GraphQL 데이터셋](/analytics/graphql-api/features/data-sets/):

- `httpRequestsAdaptive `
- `httpRequestsAdaptiveGroups`
- `firewallEventsAdaptive`
- `firewallEventsAdaptiveGroups`
- `firewallEventsAdaptiveByTimeGroups`

### 단계 2 (8 월 1, 2023)

Cloudflare는 Cloudflare 로그 데이터셋에서 오래된 필드를 제거합니다. 8 월 1, 2023에서 앞으로는 새로운 필드 만 사용할 수 있습니다.

로그 필드가 제거되면 Cloudflare는 Cloudflare 로그 데이터셋에서 제거됩니다. 8 월 1, 2023 이후,이 필드는 더 이상 사용할 수 없습니다.

## 회사 소개

다음과 같은 개념은 검토 된 필드 설명에서 아래에 사용됩니다.

- **종료 활동:**&#xB2E4;음 작업 중 하나 :

  - `block`
  - `js_challenge`
  - `managed_challenge`
  - `challenge` (*대화 도전*)

이러한 행동에 대한 자세한 내용은 참조[관련 기사](/ruleset-engine/rules-language/actions/)규칙 언어 문서에 참고 자료.

- **보안 규칙:**&#xB2E4;음 규칙 유형 중 하나 :

  - [WAF 관리 규칙](/waf/managed-rules/)
  - [WAF 사용자 정의 규칙](/waf/custom-rules/)
  - [WAF 비율 제한 규칙](/waf/rate-limiting-rules/)

## HTTP 요청 dataset 변경

다음 필드는 이름이 변경됩니다.[HTTP 요청](/logs/logpush/logpush-job/datasets/zone/http_requests/)2단계 전략에 따른 dataset[계정 정보](#timeline):

| 새 필드 이름                   | 제품정보   | 이름 \*                            | 올드 필드 이름<br />(8월 1일, 2023) |
| ------------------------- | ------ | -------------------------------- | --------------------------- |
| `SecurityRuleID`          | 스트레이트  | 보안 규칙의 규칙 ID는 용어를 트리거, 어떤 경우.    | `WAFRuleID`                 |
| `SecurityRuleDescription` | 스트레이트  | 보안 규칙의 규칙 설명은 용어 행동을 트리거, 어떤 경우. | `WAFRuleMessage`            |
| `SecurityAction`          | 스트레이트  | 보안 규칙의 규칙 행동은 용어 행동을 트리거, 어떤 경우. | `WAFAction`                 |
| `SecurityRuleIDs`         | 문자열 배열 | 요청을 일치하는 보안 규칙 ID의 배열.           | `FirewallMatchesRuleIDs`    |
| `SecurityActions`         | 문자열 배열 | Cloudflare 보안 제품의 배열은 요청에 수행.    | `FirewallMatchesActions`    |
| `SecuritySources`         | 문자열 배열 | 일치하는 Cloudflare 보안 제품의 배열.       | `FirewallMatchesSources`    |

다음 필드는 이제 deprecated이며 8 월 1, 2023에서 HTTP 요청 데이터 세트에서 제거됩니다.

| Deprecated 필드 이름      | 지원하다                                     |
| --------------------- | ---------------------------------------- |
| `WAFProfile`          | WAF의 이전 버전에서 사용하는 관리 규칙 (지금 deprecated). |
| `EdgeRateLimitAction` | 제한 규칙의 이전 버전에서 사용 (지금 deprecated).       |
| `EdgeRateLimitID`     | 제한 규칙의 이전 버전에서 사용 (지금 deprecated).       |
| `SecurityLevel`       | 사이트맵                                     |

## GraphQL 데이터셋 변경

Cloudflare는 다음 필드를 추가합니다.`httpRequestsAdaptive `·`httpRequestsAdaptiveGroups `데이터 세트:

| 필드 이름            | 제품정보  | 이름 \*                      |
| ---------------- | ----- | -------------------------- |
| `securityAction` | 스트레이트 | 보안 규칙의 동작은 용어를 트리거, 어떤 경우. |
| `securitySource` | 스트레이트 | 보안 규칙의 소스는 용어를 트리거, 어떤 경우. |

Cloudflare는 또한 뒤에 오는 분야를 추가할 것입니다`firewallEventsAdaptive`, `firewallEventsAdaptiveGroups`·`firewallEventsAdaptiveByTimeGroups`데이터 세트:

| 필드 이름         | 제품정보  | 이름 \*               |
| ------------- | ----- | ------------------- |
| `description` | 스트레이트 | 규칙의 설명은 요청에 의해 방아쇠. |

이 새로운 필드는 점차적으로 사용할 수 있습니다.

사용 가능한 데이터셋에 대한 자세한 내용은 참조[GraphQL 데이터셋](/analytics/graphql-api/features/data-sets/).

## Logpush 작업 및 SIEM 시스템 업데이트

Cloudflare는 이름 필드를 사용하는 기존의 Logpush 작업을 업데이트하지 않습니다. 아래의 지침에 따라 작업을 업데이트해야합니다.

Logpush 작업을 업데이트 한 후 로그 필드 변경을 반영하기 위해 SIEM 시스템에 외부 필터 또는 보고서를 업데이트해야합니다.

### 대시보드에서 Logpush 작업을 업데이트

1. Cloudflare 대시보드에서, 갑니다**다운로드**사이트 맵

   <DashButton url="/?to=/:account/:zone/analytics/logs" />

2. 제품정보**제품정보**편집하려는 Logpush 작업 옆에.

3. 이름 \***데이터 필드 선택**, 당신의 일에 있는 분야를 새롭게 합니다. 새로운 보안 로그 필드를 사용할 수 있습니다.**주요사업**.

4. 제품정보**비밀번호**.

### API를 통해 Logpush 작업 업데이트

자주 묻는 질문[output options 업데이트](/logs/logpush/examples/example-logpush-curl/#optional---update-output_options)Logpush 작업에 필드를 업데이트합니다.

### Terraform을 통해 Logpush 작업 업데이트

이미 Terraform을 통해 Logpush 일자리를 관리하는 경우, 업데이트`logpull_options`현재 위치[`cloudflare_logpush_job`](https://registry.terraform.io/providers/cloudflare/cloudflare/latest/docs/resources/logpush_job)Terraform 자원. 예를 들면:

```diff
  resource "cloudflare_logpush_job" "example_job" {
    enabled             = true
    zone_id             = "<ZONE_ID>"
    name                = "My-logpush-job"
-   logpull_options     = "fields=RayID,ClientIP,EdgeStartTimestamp,WAFAction,WAFProfile&timestamps=rfc3339"
+   logpull_options     = "fields=RayID,ClientIP,EdgeStartTimestamp,SecurityAction&timestamps=rfc3339"
    destination_conf = "r2://cloudflare-logs/http_requests/date={DATE}?account-id=${var.account_id}&access-key-id=${cloudflare_api_token.logpush_r2_token.id}&secret-access-key=${sha256(cloudflare_api_token.logpush_r2_token.value)}"
    dataset             = "http_requests"
  }
```
