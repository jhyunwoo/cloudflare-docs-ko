### 1. 작업 만들기

일을 만들려면,`POST`다음 필드에 Logpush 작업 엔드 포인트에 요청:

- **이름 \***(optional) - 도메인 이름을 작업 이름으로 사용하십시오.
- **대상 conf**- 엔드포인트 URL, 채널 ID, insecure-skip-verify 플래그, 소스 유형, 아래에 문자열 형식의 권한 헤더로 구성된 로그 대상.

  - **\<SPLUNK ENDPOINT URL>**: 포트가 있는 Splunk raw HTTP Event Collector URL. 예를 들면:`splunk.cf-analytics.com:8088/services/collector/raw`.
    - Cloudflare는 Splunk 엔드포인트를 기대합니다.`/services/collector/raw`Logpush 작업을 설정하고 설정하는 동안.
    - 당신은 Splunk에서 HEC를 활성화해야합니다. 더 알아보기[Splunk Analytics 통합](/analytics/analytics-integrations/splunk/)Splunk에서 HEC를 설정하는 방법에 대한 정보.
    - API 요청이 504 오류로 실패했을 때 잘못된 URL을 추가할 수 있습니다. Splunk Cloud 엔드 포인트 URL은 일반적으로 포함`http-inputs-`또는 호스트 이름 앞에 유사한 텍스트.
  - **\<SPLUNK CHANNEL ID>에 대하여**: 독특한 채널 ID. 생성 할 수있는 임의 GUID입니다 :
    - 온라인 도구를 사용하여[GUID 발전기](https://www.guidgenerator.com/).
    - 명령행을 사용하여. 예를 들면:`python -c 'import uuid; print(uuid.uuid4())'`.
  - **\<INSECURE SKIP VERIFY>**: Boolean 가치. Cloudflare는 이 값을 조정하는 것을 추천합니다`false`. 이 값을 설정`true`사용과 동일`-k`옵션과`curl`Splunk 예제와 같이**아니다.**&#xC790;주 묻는 질문 이 값을 설정`true`HEC가 자기 서명 인증서를 사용할 때.

  :::참조
  Cloudflare는 높게 이 가치를 조정하는 것을 추천합니다`false`. 참조[로그인 FAQ](/logs/faq/logpush/)더 많은 정보.
  주요 특징

  - **\<SOURCE TYPE>**: Splunk 소스 유형. 예를 들면:`cloudflare:json`.
  - **\<SPLUNK AUTH TOKEN>에 대하여**: URL 인코딩 된 Splunk Authorization 토큰은 단어로 접목해야합니다.`Splunk`. 예를 들면:`Splunk e6d94e8c-5792-4ad1-be3c-29bcaee0197d`.

```bash
"splunk://<SPLUNK_ENDPOINT_URL>?channel=<SPLUNK_CHANNEL_ID>&insecure-skip-verify=<INSECURE_SKIP_VERIFY>&sourcetype=<SOURCE_TYPE>&header_Authorization=<SPLUNK_AUTH_TOKEN>"
```

- **데이터셋**- 수신하려는 로그의 범주. 더 알아보기[데이터셋](/logs/logpush/logpush-job/datasets/)지원된 datasets의 전체 목록을 위해.

- **output 옵션**(선택 사항) - 필드, 샘플 속도 및 타임스탬프 형식을 구성하려면, 참조[로그 출력 옵션](/logs/logpush/logpush-job/log-output-options/). 타임스탬프를 위해, Cloudflare는 사용을 추천합니다`timestamps=rfc3339`.

## 문제 해결 Splunk 목적지

### 유효성 검사

Splunk 작업을 설정하면서 검증 오류를 받으면 다음을 확인하십시오.

- **엔드포인트 URL**: Cloudflare는 HTTPS를 통해 Splunk HEC raw endpoint를 지원합니다. 엔드포인트 URL을 검증하고 포트가 포함되어 있습니다 (일반적으로`:8088`).
- **인증 토큰**: Splunk 인증 토큰은 URL 인코딩 및 접두사`Splunk`. 예를 들면, 사용`%20`토큰의 공간.
- **인증서 구성**: Splunk 또는 타사 인증서에 의해 생성 된 인증서가 있어야합니다.**이름 \***&#xD544;드는 Splunk 서버의 도메인 이름과 일치합니다. 그렇지 않으면 다음과 같은 오류를 볼 수 있습니다.`x509: certificate is valid for SplunkServerDefaultCert, not <YOUR_INSTANCE>.splunkcloud.com`.

### insecure-skip-verify에 대한 이해

더 보기`insecure-skip-verify`모수, 설정할 때`true`, Splunk에 insecure 연결을 만듭니다. 이것은 사용과 동일`-k`옵션과`curl`·**옵션 정보**.

**왜 이 매개 변수가 존재할까요?**: Splunk 또는 타사 인증서에 의해 생성 된 인증서가 있어야합니다.**이름 \***&#xD544;드는 Splunk 서버의 도메인 이름과 일치합니다. 그들은 일치하지 않을 경우 (특히 시작에 Splunk에 의해 생성 된 기본 인증서), 푸시는 인증서가 고정되지 않는 한 실패합니다. 이 매개 변수는 서버 구성을 변경할 수 없습니다 Splunk Cloud 인스턴스와 같은 인증서에 액세스하거나 수정할 수없는 희귀 시나리오에 존재합니다.

:::카트로션
Cloudflare는 높게 조정을 추천합니다`insecure-skip-verify`으로`false`. 이만 설정`true`HEC가 자기 서명 인증서를 사용하고 인증서를 수정하면 안됩니다.
주요 특징

### 설정하기 전에 HEC 검증

Logpush 작업을 만들기 전에 Splunk HEC가 테스트 이벤트를 게시하여 올바르게 작동한다는 것을 확인합니다.`curl`없음`-k`플래그와 함께`insecure-skip-verify=false`:

```bash
curl "https://<SPLUNK_ENDPOINT_URL>?channel=<SPLUNK_CHANNEL_ID>&insecure-skip-verify=false&sourcetype=<SOURCE_TYPE>" \
--header "Authorization: Splunk <SPLUNK_AUTH_TOKEN>" \
--data '{"BotScore":99,"BotScoreSrc":"Machine Learning","CacheCacheStatus":"miss","CacheResponseBytes":2478}'
```

예상된 응답:

```json
{"text":"Success","code":0}
```

### 네트워크 포트 요구 사항

Cloudflare는 HEC 네트워크 포트가 구성되도록 기대합니다.`:443`또는`:8088`. 다른 항구는 지원되지 않습니다.

### Cloudflare Splunk 앱 통합

Logpush와 통합[Splunk를 위한 Cloudflare 앱](https://splunkbase.splunk.com/app/4501/). 당신이 로그를 사용하여 긴`cloudflare:json`소스 유형, Cloudflare Splunk App을 사용하여 로그를 분석하고 시각화 할 수 있습니다.

자세한 설정 지침은 참조[Splunk Analytics 통합](/analytics/analytics-integrations/splunk/).
