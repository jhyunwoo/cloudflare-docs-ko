9. 제품정보**제출하기**일단 당신이 당신의 logpush 일을 구성하고 있습니다.

## API를 통해 관리

IBM 클라우드 로그 작업을 설정하려면:

1. 적절한 엔드포인트 URL 및 인증 매개 변수로 작업을 만듭니다.
2. 로그를 푸는 작업을 활성화합니다.

:::주\[주]
Log Share 권한이 활성화되기 전에 Logpush 작업을 읽거나 구성하려고 시도합니다. 더 많은 정보를 원하시면[역할 섹션](/logs/logpush/permissions/#roles).
:::

### 1. 작업 만들기

일을 만들려면,`POST`다음 필드에 Logpush 작업 엔드 포인트에 요청:

- **이름 \***(optional) - 도메인 이름을 작업 이름으로 사용하십시오.
- **output 옵션**(선택) - 이 매개 변수는 원하는 출력 형식과 구조를 정의하는 데 사용됩니다. 아래는 구성 필드입니다:
  - 출력 type
  - 타임스탬프 format
  - batch prefix 및 일괄 처리 suffix
  - record prefix 및 레코드 suffix
  - 기록 delimiter
- **대상 conf**- Instance ID, Region 및[IBM API 키](https://cloud.ibm.com/docs/account?topic=account-iamtoken_from_apikey)아래 문자열 형식에서.

`ibmcl://<INSTANCE_ID>.ingress.<REGION>.logs.cloud.ibm.com/logs/v1/singles?ibm_api_key=<IBM_API_KEY>`

- **최대 upload records**(선택 사항) - 일괄 처리 당 로그 라인의 최대 번호. 1,000개 이상의 라인이 있어야 합니다. 배치 당 최소 로그 라인을 지정하는 방법이 없습니다. 로그 파일이 지정된 것보다 많은 몇 줄을 포함 할 수 있음을 의미합니다.
- **최대 upload bytes**(선택 사항) - 로그의 일괄 처리를위한 최대 압축 파일 크기. 우리는 IBM의 한계에 따라 업로드 당 2 MB의 기본값을 권장합니다, 우리의 시스템은이 목적지에 시행됩니다. 최소 파일 크기를 설정할 수 없기 때문에 로그 파일이 지정된 일괄 크기보다 작을 수 있습니다.
- **데이터셋**- 수신하려는 로그의 범주. 더 알아보기[데이터셋](/logs/logpush/logpush-job/datasets/)지원된 datasets의 전체 목록을 위해.

cURL을 사용한 예시 요청:

<APIRequest
  method="POST"
  path="/zones/{zone_id}/logpush/jobs"
  json={{
  	name: "<DOMAIN_NAME>",
  	output_options: {
  		output_type: "ndjson",
  		timestamp_format: "rfc3339",
  		batch_prefix: "[",
  		batch_suffix: "]",
  		record_prefix:
  			'{"applicationName":"ibm-platform-log","subsystemName":"internet-svcs:logpush","text":{',
  		record_suffix: "}}",
  		record_delimiter: ",",
  	},
  	destination_conf:
  		"ibmcl://<INSTANCE_ID>.ingress.<REGION>.logs.cloud.ibm.com/logs/v1/singles?ibm_api_key=<IBM_API_KEY>",
  	max_upload_bytes: 2000000,
  	dataset: "http_requests",
  	enabled: true,
  }}
/>
