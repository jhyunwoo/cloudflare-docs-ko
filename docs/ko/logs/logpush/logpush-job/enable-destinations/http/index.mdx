모델 번호: Cloudflare Logpush는 이제 configurable HTTP 엔드포인트에 로그를 보낼 수있는 능력을 지원합니다.

Logpush를 HTTP 엔드포인트로 사용할 때, Cloudflare 고객은 푸시 로그의 자신의 인증을 수행 할 것으로 예상됩니다. 예를 들어, 고객은 URL 또는 Logpush 대상의 HTTP 헤더에 비밀 토큰을 지정할 수 있습니다.

## API를 통해 관리

Logpush 작업을 만들려면,`POST`요청하기[Logpush 작업 작성 엔드 포인트 URL](/logs/logpush/logpush-job/api-configuration/)적당한 모수로.

지원된 모수는 다음과 같이 입니다:

- 다른 출처에서 변하지 않는 필드:
  - **데이터셋**(필수): 예를 들어,`http_requests`.
  - **이름 \***(선택): 도메인 이름을 작업 이름으로 사용하는 것이 좋습니다.
  - **output 옵션**(선택): Refer에[로그 출력 옵션](/logs/logpush/logpush-job/log-output-options/)필드, 샘플 속도 및 타임스탬프 형식을 구성합니다.
- 유일한 분야:
  - **대상 conf**: 로그를 보내는 곳. 이것은 endpoint URL과 HTTP 헤더로 사용됩니다.
    - 이름 \*`"header_*"`URL 매개 변수는 요청 헤더를 설정하는 데 사용됩니다.
      - HTTPS 엔드 포인트는 어떤과 충돌 사용자 정의 URL 매개 변수를 가질 수 없습니다`"header_*"`URL 매개 변수 설정.
      - 이 매개 변수는 제대로 URL 인코딩해야합니다 (그는, 사용`"%20"`whitespace를 위해), 그렇지 않으면 몇몇 특별한 특성은 잘못된 잘못될지도 모릅니다.
    - `destination_conf`더 많은 URL 매개 변수가 특수에`"header_*"`모수.
      - URL 인코딩 특수 문자는 업로드 할 때 인코딩됩니다.
    - 예:`https://logs.example.com?header_Authorization=Basic%20REDACTED&tags=host:theburritobot.com,dataset:http_requests`
  - **최대 upload bytes**(선택): 로그의 배치의 최대 압축 파일 크기. 이 조정 가치는 5 MB와 1개 GB 사이에서 있어야 합니다. 최소 파일 크기를 설정할 수 없습니다. 즉, 로그 파일이 일괄 크기보다 훨씬 작을 수 있음을 의미합니다.
  - **최대 upload records**(선택): 일괄 처리 당 로그 라인의 최대 번호. 이 설정은 1,000과 1,000,000 줄 사이이어야 합니다. 일괄 처리 당 최소 로그 라인을 지정할 수 없습니다. 이 로그 파일이이보다 많은 몇 줄을 포함 할 수 있음을 의미합니다.

:::주\[주]

더 보기`ownership_challenge`매개변수는 Logpush 작업을 HTTP 엔드포인트로 만들 필요가 없습니다. 해당 이용 후기에 달린 코멘트가 없습니다.`test.txt.gz`내용으로`{"content":"tests"}`압축, 그렇지 않으면 오류를 반환합니다.`error validating destination: error writing object: error uploading`.

  	max_upload_records: 1000,
  	dataset: "http_requests",
  	enabled: true,
  }}
