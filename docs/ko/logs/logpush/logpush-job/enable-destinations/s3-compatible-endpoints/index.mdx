## API를 통해 관리

S3-compatible 엔드포인트를 설정하려면:

1. 적절한 엔드포인트 URL 및 인증 매개 변수로 작업을 만듭니다.
2. 로그를 푸는 작업을 활성화합니다.

:::주\[주]

Amazon S3에 Logpush 작업과는 달리 S3-compatible API와 소유권이 없습니다.

:::

<Render file="enable-read-permissions" product="logs" />

### 1. 작업 만들기

일을 만들려면,`POST`다음 필드에 Logpush 작업 엔드 포인트에 요청:

- **이름 \***(optional) - 도메인 이름을 작업 이름으로 사용하십시오.
- **대상 conf**- 엔드포인트 이름, 버킷 이름, 버킷 경로, 지역, 액세스 키 ID 및 다음 문자열 형식의 secret-access-key로 구성된 로그 대상:

```bash
"s3://<BUCKET_NAME>/<BUCKET_PATH>?region=<REGION>&access-key-id=<ACCESS_KEY_ID>&secret-access-key=<SECRET_ACCESS_KEY>&endpoint=<ENDPOINT_URL>"
```

:::주\[주]

`<ENDPOINT_URL>`버킷 이름이나 경로없이 URL입니다. 예를 들면:`endpoint=sfo2.digitaloceanspaces.com`.

:::

- **데이터셋**- 수신하려는 로그의 범주. 더 알아보기[데이터셋](/logs/logpush/logpush-job/datasets/)지원된 datasets의 전체 목록을 위해.
- **output 옵션**(선택 사항) - 필드, 샘플 속도 및 타임스탬프 형식을 구성하려면, 참조[로그 출력 옵션](/logs/logpush/logpush-job/log-output-options/).

cURL을 사용한 예시 요청:

### 2. 직업 (업데이트)

일을 할 수 있도록,`PUT`Logpush 작업 엔드 포인트에 요청. URL에서 이전 단계에서 반환된 작업 ID를 사용하고 전송합니다.`{"enabled": true}`요청 몸에서.

cURL을 사용한 예시 요청:

```bash
curl --request PUT \
https://api.cloudflare.com/client/v4/zones/{zone_id}/logpush/jobs/{job_id} \
--header "X-Auth-Email: <EMAIL>" \
--header "X-Auth-Key: <API_KEY>" \
--header "Content-Type: application/json" \
--data '{
  "enabled": true
}'
```
