## API를 통해 관리

Datadog Logpush 작업을 설정하려면:

1. 적절한 엔드포인트 URL 및 인증 매개 변수로 작업을 만듭니다.
2. 로그를 푸는 작업을 활성화합니다.

:::주\[주]

AWS S3, GCS, 또는 Azure를 위한 Logpush 작업을 구성하는 것은 Datadog에 Logpush를 구성할 때 소유권이 없습니다.

:::

### 1. 작업 만들기

일을 만들려면,`POST`다음 필드에 Logpush 작업 엔드 포인트에 요청:

- **이름 \***(optional) - 도메인 이름을 작업 이름으로 사용하십시오.

- **대상 conf**- endpoint URL, authorization 헤더 및 Datadog가 문자열 형식으로 지원되는 0 이상의 옵션 매개 변수로 구성된 로그 대상.

  - `<DATADOG_ENDPOINT_URL>`: Datadog HTTP 로그 입구 endpoint, 어느 쪽이든 할 수 있습니다. 당신은 차이를 찾을 수 있습니다[데이터 독 API 참고 자료](https://docs.datadoghq.com/api/latest/logs/).

  <Tabs>
    <TabItem label="v1의">
      [모델 번호: https://http-intake.logs.datadoghq.com/v1/input\`](https://http-intake.logs.datadoghq.com/v1/input`)
    </TabItem>

    <TabItem label="사이트맵">
      `https://http-intake.logs.datadoghq.com/api/v2/logs`
    </TabItem>
  </Tabs>

- `<DATADOG_API_KEY>`: Datadog API 토큰은 다음과 같이 재생될 수 있습니다.[이 단계](https://docs.datadoghq.com/account_management/api-app-keys/#add-an-api-key-or-client-token). 예를 들면,`20e6d94e8c57924ad1be3c29bcaee0197d`.

- `ddsource`: 세트`cloudflare`.

- `service`, `host`, `ddtags`: Datadog에 의해 허용되는 선택적인 모수.

```bash
"datadog://<DATADOG_ENDPOINT_URL>?header_DD-API-KEY=<DATADOG_API_KEY>&ddsource=cloudflare&service=<SERVICE>&host=<HOST>&ddtags=<TAGS>"
```

- **데이터셋**- 수신하려는 로그의 범주. 더 알아보기[데이터셋](/logs/logpush/logpush-job/datasets/)지원된 datasets의 전체 목록을 위해.
- **output 옵션**(선택 사항) - 필드, 샘플 속도 및 타임스탬프 형식을 구성하려면, 참조[로그 출력 옵션](/logs/logpush/logpush-job/log-output-options/).

## 제한 사항

다음 Logpush 전송 제한을 참고하십시오.[Datadog 문서](https://docs.datadoghq.com/api/latest/logs/).

HTTP를 통해 Datadog 플랫폼에 로그인하십시오. HTTP 요청 당 제한은 다음과 같습니다.

- 페이로드 당 최대 함량 크기 (압축) : 5 MB
- 단일 로그의 최대 크기: 1 MB
- 배열에 여러 로그를 보내는 경우 최대 배열 크기: 1,000 항목

:::카트로션\[Warning]

위 제한은 기본적으로 hardcoded입니다. Logpush 구성 값을 사용하여 이러한 제한을 무시 할 수 없습니다,`max_upload_records`또는`max_upload_bytes`.

이러한 제한은 Datadog에서 고 트래픽 이벤트를 따르는 것으로 눈에 띄는 로그 ingestion 지연이 발생할 수 있습니다. Logpush는 unsent 로그를 삭제하지 않습니다. 그래서 모든 로그는 Datadog에 업로드됩니다.
