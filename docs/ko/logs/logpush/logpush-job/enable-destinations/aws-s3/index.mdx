## S3 버킷에 액세스하고

Cloudflare는 Amazon Identity와 Access Management(IAM)을 사용하여 S3 Bucket에 액세스할 수 있습니다. Cloudflare IAM 사용자 필요`PutObject`버킷의 허가.

로그는 S3 액세스 제어 목록 (ACL)을 사용하여 gzipped 개체로 그 물통으로 작성됩니다
`Bucket-owner-full-control`이름 \*

illustrative 목적을 위해, 당신이 물통에 로그를 저장하고 싶은 상상`burritobot`, 에서`logs`디렉토리. S3 URL은 그런 다음`s3://burritobot/logs`.

<Render file="enable-read-permissions" product="logs" />

<br />

Amazon S3에 Logpush를 활성화하려면:

1. S3 버킷을 만듭니다. 더 알아보기[Amazon의 지시](https://docs.aws.amazon.com/AmazonS3/latest/gsg/CreatingABucket.html).

   :::주\[주]
   중국 지역에서 버킷 ( Buckets)`cn-north-1`, `cn-northwest-1`)는 현재 지원되지 않습니다.
   주요 특징

2. 아래 정책 편집 및 붙여넣기**사이트맵** > **제품정보** > **제출** > **버킷 정책**, 교체`Resource`자신의 물통 경로와 값. 더 보기`AWS` `Principal`Cloudflare가 소유하고 변경되지 않아야합니다.

```json
{
	"Id": "<POLICY_ID>",
	"Version": "2012-10-17",
	"Statement": [
		{
			"Sid": "Stmt1506627150918",
			"Action": ["s3:PutObject"],
			"Effect": "Allow",
			"Resource": "arn:aws:s3:::burritobot/logs/*",
			"Principal": {
				"AWS": ["arn:aws:iam::391854517948:user/cloudflare-logpush"]
			}
		}
	]
}
```

:::주\[주]

Logpush는 S3에 대한 멀티 파트 업로드를 사용합니다. Aborted uploads은 버킷에 남아있는 불완전한 파일에서 발생합니다. 스토리지 비용을 최소화하기 위해 Amazon은 Lifecycle 규칙을 구성하는 것이 좋습니다.`AbortIncompleteMultipartUpload`활동. 더 알아보기[multipart 업로드를 사용하여 객체 업로드 및 복사](https://docs.aws.amazon.com/AmazonS3/latest/dev/mpuoverview.html#mpu-abort-incomplete-mpu-lifecycle-config).

:::
