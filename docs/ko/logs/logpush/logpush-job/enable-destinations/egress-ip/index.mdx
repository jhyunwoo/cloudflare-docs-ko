이 가이드 커버[전용 CDN Egress IPs](/smart-shield/configuration/dedicated-egress-ips/)Logpush 구성 및 테스트 지침은 고정, 전용 egress IP로 로그 전달을 가능하게합니다.

## 자주 묻는 질문

전용 egress IP를 사용하여 Logpush를 사용하려면 필요한 것입니다.[Smart Shield 고급](/smart-shield/get-started/#smart-shield-advanced)Dedicated CDN Egress IPs (이전 Aegis로 알려져 있음). Dedicated CDN Egress IPs 풀은 영역과 관련이 있으며 계정과는 없습니다. 전용 IP로 Logpush를 사용하려면 트래픽은 단일 영역으로 전환해야합니다.

일반적인 접근법은 Cloudflare 지역을 통해 Logpush 작업 프록시 Logpush 데이터를 Dedicated CDN Egress IPs를 사용하여 원하는 목적지에 데이터를 보낼 수 있습니다. 이 방법 당신의 목적지는 프록시 영역의 헌신적 인 egress IPs를 허용해야합니다.

우선 순위로, 당신은 전용 영역을 만들거나 기존 영역을 사용합니다. 기존 구역을 사용하는 경우, Zone의 egress가 Dedicated CDN Egress IPs에 제한 될 것이라는 점을 인식해야합니다. 그 지역을 사용하는 모든 서비스가 영향을받지 않습니다.

생산 시스템의 영향을 피하기 위해 별도의 전용 구역을 사용하는 것이 좋습니다. 새로운 영역을 만들려면, 따르십시오[계정 만들기](/registrar/get-started/register-domain/)Cloudflare로 새로운 도메인을 등록하려면.

다음 예제는 logpush 및 Dedicated CDN Egress IPs를 HTTPS 목적지 프록시로 설정하는 방법을 보여줍니다. 그러나 프록시는 모든 목적지가 HTTP 프로토콜 underneath를 사용하여 지원되는 Logpush 대상을 위해 작동해야합니다.

## 1. Provision 전용 egress IP 풀

1. Cloudflare 계정 팀과 함께 구매[전용 CDN Egress IPs](/smart-shield/configuration/dedicated-egress-ips/)당신의 지역을 위해.

2. (선택하지만 권장) PDX-B에서 두 개의 IP를 요청하고 SJC-A에서 하나 - 지역 전체에 적용을 보장하기 위해.

3. 한 번에 풀 ID를 확인합니다.

## 2. 영역 구성

1. 등록 또는 전용 egress IPs 풀에 대한 기존 영역을 사용합니다.
2. 계정 팀에 연락하여 전용 egress IPs 풀 ID를 받으세요.
3. 더 보기`PATCH`요청하기[편집 영역 설정](/api/resources/zones/subresources/settings/methods/edit/)엔드포인트:

- 이름 \*`aegis`URL에서 설정 ID로.
- 요청 몸에서, 설정`enabled`으로`true`이전 단계에서 ID를 사용`pool_id`.

<APIRequest
  path="/zones/{zone_id}/settings/{setting_id}"
  method="PATCH"
  json={{
  	  "id": "aegis",
  		"value": {
  			"enabled": true,
  			"pool_id": "<YOUR_EGRESS_POOL_ID>",
  			},
  }}
  parameters={{
  setting_id: "aegis",
}}
/>

## 3. 프록시 영역 설정

1. 영역에서 DNS 레코드 (CNAME 또는 A/AAAA)를 추가하십시오.**제품정보**HTTP 대상 엔드포인트로.

![Cloudflare 대시보드에서 DNS 레코드를 작성하여 HTTP 대상 엔드포인트 정의](~/assets/images/logs/endpoint.png)

2. 필요한 경우, 구성[기본 규칙](/rules/origin-rules/)사용자 정의 포트를 지정합니다. 이것은 목적지가 아닌 표준 포트에 트래픽을 허용하는 경우 유용합니다. 예를 들어`12345`. 구성할 수 있습니다`logpush.yourdestinationendpoint.com`(포트를 지정하지 않고, Cloudflare로 기본적으로 HTTP/HTTPS 포트에서만 프록시 트래픽) 프록시로`yourdestinationendpoint.com:12345`.

## 4. Logpush 구성

1. 다음 세부 사항으로 Logpush 작업을 작성:

- 대상: HTTP
- 엔드포인트: 도메인/경로 설정을 입력합니다. Cloudflare 대시보드는 목적지를 자동으로 검증합니다. 이 경우 DNS 레코드 섹션에 있는 서버 이름 `logpush.yourdestionationendpoint.com`을 사용합니다.

![Cloudflare 대시보드에서 Logpush 작업을 만들 때 대상 정보를 입력](~/assets/images/logs/destination-details.png)

- 구성: dataset, job name, filter, 필드를 선택합니다. 더 알아보기[Logpush 문서](/logs/logpush/)더 많은 정보.

2. 로그가 수신되면 목적지를 확인합니다.

## 5. 프록시 영역 엔드포인트 보안

프록시 영역 hostname은 공개적으로 resolvable이지만, 보안 컨트롤을 적용할 수 있는 Cloudflare의 가장자리를 통과합니다. 당신의 endpoint를 보호하기 위해 다음과 같은 모범 사례를 사용합니다.

### WAF 유효성을 가진 비밀 우두머리를 추가하십시오

Logpush 작업에 HTTP 헤더로 비밀 토큰을 추가하면 WAF 규칙을 사용하여 요청을 차단합니다. 이것은 대부분의 배포에 대한 권장된 접근법입니다.

**비밀 헤더로 Logpush 구성**

어떤 URL 매개 변수 시작`header_`요청에 HTTP 헤더가 됩니다. Logpush 작업을 생성하거나 업데이트하면 목적지 URL에 비밀 헤더를 추가하십시오.

```txt
https://logpush.yourdestinationendpoint.com?header_X-Logpush-Secret=YOUR_RANDOM_SECRET_TOKEN
```

강력한 무작위 토큰 생성`openssl rand -hex 32`.

**WAF 사용자 정의 규칙 만들기**

프록시 영역에서 이동**보안 보안** > **모델 번호: WAF** > **주문 규칙**올바른 비밀 헤더없이 요청을 차단하는 규칙을 만듭니다.

- **표현:**
  ```txt
  (http.host eq "logpush.yourdestinationendpoint.com" and all(http.request.headers["x-logpush-secret"][*] ne "YOUR_RANDOM_SECRET_TOKEN"))
  ```
- **활동 :**&#xC81C;품정보

### ASN 기반 필터링 추가

깊이에 방어를 위해 Cloudflare의 ASNs에서 트래픽을 허용하는 규칙을 추가하십시오. Logpush 트래픽은 Cloudflare의 네트워크 (ASN 13335, 132892, 또는 202623)에서 유래합니다.

- **표현:**
  ```txt
  (http.host eq "logpush.yourdestinationendpoint.com" and not ip.geoip.asnum in {13335 132892 202623})
  ```
- **활동 :**&#xC81C;품정보

:::참조
혼자 필터링 ASN는 다른 Cloudflare 고객 트래픽이 이러한 ASNs에서 시작되기 때문에 충분합니다. 항상 비밀 헤더 검증과 결합.

### 높은 보안 환경을 위한 Access Service Token 사용

더 강한 인증, 사용[Cloudflare 액세스 서비스 토큰](/cloudflare-one/access-controls/service-credentials/service-tokens/)기계에 기계 입증을 위해. Zero Trust 대시보드에서 서비스 토큰을 만들고, 액세스 헤더와 Logpush를 구성합니다.

```txt
https://logpush.yourdestinationendpoint.com?header_CF-Access-Client-Id=YOUR_CLIENT_ID&header_CF-Access-Client-Secret=YOUR_CLIENT_SECRET
```

### 보안 설정 확인

WAF 규칙이 승인 된 요청을 차단하는 테스트 :

```bash
$ curl https://logpush.yourdestinationendpoint.com
#예상 : 오류 코드 : 1020

$ curl -H "X-Logpush-Secret: wrong-token" https://logpush.yourdestinationendpoint.com
#예상 : 오류 코드 : 1020
```

체크 Cloudflare Logpush 트래픽을 확인하기 위해 프록시 영역에 대한 분석은 흐름 및 WAF 이벤트를 모니터링하여 무단 요청을 차단합니다.
