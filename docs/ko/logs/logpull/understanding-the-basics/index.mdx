## 접근 패턴

기본 접근 패턴은*분 M을 위해 지역 Z에 대한 모든 로그를 제공합니다*약 1분*사이트맵*로그 항목이 Cloudflare의 로그 집계 시스템에 디스크에 기록 된 시간을 나타냅니다.

시작하려면 각 분마다 쿼리를 실행하십시오. 응답이 너무 작으면 5 분까지 이동하면 대부분의 영역에 적합합니다. 응답이 너무 크면 15 초로 내려갑니다.

지역이 너무 많은 로그를 가지고 있다면 1 분 이상 로그의 1 분을 읽으려면 2 명의 근로자가 매 2 분마다 로그의 1 분을 요청하면됩니다.

API로 리턴된 데이터는 반복 통화로 변경되지 않습니다. 응답에 있는 메시지의 순서는 다를지도 모릅니다, 그러나 메시지의 수 그리고 내용은 항상 응답 부호로 주어진 조회를 위해 동일일 것입니다`200`응답 몸을 읽는 오류가 없습니다.

우리의 로그 처리 시스템은 일괄 처리에 데이터, 분 당 1 백만 개 이상의 요청을 가진 대부분의 영역은 "empty"분이 있습니다. 상태에 대한 응답의 분 결과`200`그러나 몸에 있는 자료 없음. 이것은 그 분에 대한 Cloudflare에 의해 발음되지 않은 요청이 없다는 것을 의미하지 않습니다. 그것은 단지 우리의 시스템은 그 분에 그 영역에 대한 로그의 배치를 처리하지 않았다.

## 반환된 데이터의 순서

더 보기`logs/received`API 엔드포인트는 수신된 시간에 의해 데이터를 노출합니다. 이 이벤트는 Cloudflare에서 디스크에 기록되었습니다. 로그 집계 시스템.

로그 생성 시간 대신에 로그 집계 시간을 주문 (빠른) 로그 파이프라인 대기 시간 및 결정적인 로그 당. Functionally, 로그 파일 또는 읽기를 꼬리와 유사합니다.*RSS 피드*(chunks에서 금지).

주어진 시간 범위에 대한 로그를 얻기 위해, 당신은 각 연속 분 (또는 다른 시간 범위)에 대한 하나의 호출을 발급 할 수 있습니다. 로그 라인은 수신된 시간에 의해 배치되고 사용할 수 있기 때문에 늦은 도착 데이터가 없습니다. 주어진 분을 위한 응답은 결코 변화하지 않을 것입니다. 당신은 우리의 집계 시스템에 통합으로 로그를받을 주어진 시간 범위를 반복적으로 오염하지 않습니다.

## 데이터의 형식은 반환

Logpull API는 NDJSON 형식의 데이터를 반환합니다. 각 로그 라인은 유효 JSON 객체입니다. Google BigQuery 및 AWS Kinesis와 같은 주요 분석 도구는이 형식을 요구합니다.

log data를 log line당 1개의 array 엘리먼트로 JSON 배열으로 설정하려면, use`jq`도구. 기본적으로 API 응답을 파이프*사이트맵*사용 방법*인기 카테고리*(또는 단순히)*₢ 킹*) 깃발:

`<API request data> | jq -s`

더 알아보기[다운로드 jq](https://jqlang.github.io/jq/download/)더 많은 정보를 얻기 및 설치`jq`.
