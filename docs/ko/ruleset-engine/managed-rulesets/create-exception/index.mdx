제품 정보[옵션 정보](/waf/managed-rules/waf-exceptions/)규칙의 일부 관리 규칙의 실행을 건너.

예외 구성에는[이름 \*](/ruleset-engine/rules-language/expressions/)그것은 건너뛰기 조건을 정의, 규칙 또는 관리 규칙은 그 조건에서 건너뛰기.

Terraform을 사용하는 경우, 참조[예외 설정](/terraform/additional-configurations/waf-managed-rulesets/#configure-exceptions)Terraform 문서에서.

Cloudflare 대시보드를 사용하는 경우, 참조[대시보드XQ에서 예외 추가](/waf/managed-rules/waf-exceptions/define-dashboard/).

:::참조
현재, 만[Cloudflare 웹 응용 프로그램 방화벽 (WAF)](/waf/managed-rules/waf-exceptions/)관리된 규칙 예외를 지원합니다.
주요 특징

## 예외의 종류

예외는 다음과 같은 행동 중 하나가 될 수 있습니다 (최고에서 가장 낮은 우선 순위):

- [항목에 남아있는 규칙을 건너](#skip-all-remaining-rules)
- [하나 이상의 관리 규칙을 건너](#skip-one-or-more-managed-rulesets)
- [관리 규칙의 하나 이상의 규칙을 건너](#skip-one-or-more-rules-of-managed-rulesets)

주어진 맥락에서 예외를 정의 - 영역 수준 또는 계정 수준 - 그들은 그 맥락에만 적용. 예를 들어, 계정 수준에서 모든 나머지 규칙을 건너는 예외를 정의하면 지역 수준에서 항목 점 규칙에 정의 된 규칙은 여전히 평가됩니다.

Cloudflare는 여러 예외의 표현에 대한 일치가 있다면 가장 높은 우선 순위와 예외를 고려할 것입니다.

예외는 해당 후 관리된 규칙을 실행하는 규칙에만 적용됩니다. 항목 포인트 규칙의 규칙의 끝에서 예외를 추가하면 아무것도 건너 뛸 것입니다.

:::caution\[계정 예외에 대한 추가적인 요구]
계정 수준에서 항목 포인트 규칙에 대한 규칙은 엔터프라이즈 영역에서만 적용됩니다. 또한 예외(또는 건너뛰기 규칙)가 포함되어 있습니다. 계정 수준에서 예외를 추가할 때, 당신은 규칙 표현에서 모든 사용자 정의 조건을 둘러싸고 표현을 종료하기 위해 모체를 사용해야합니다`and cf.zone.plan eq "ENT"`, 또는 다른 API 가동은 실패할 것입니다.
주요 특징

### 자주 묻는 질문

자주 묻는 질문[관련 항목](/ruleset-engine/about/rulesets/#entry-point-ruleset), 규칙을 만듭니다`skip`활동 및 포함`"ruleset": "current"`내 계정`action_parameters`객체.

규칙 정의의 예:

```json
{
	"expression": "<RULE_EXPRESSION>",
	"action": "skip",
	"action_parameters": {
		"ruleset": "current"
	}
}
```

모든 나머지 규칙을 건너는 것은 현재 상황에 대한 규칙에 영향을 미칩니다 (계정 또는 영역). 예를 들어, 규칙을 추가`skip`계정 수준의 단계 항목 포인트 규칙에 행동은 영역 수준의 단계 항목 포인트 규칙에 정의 된 규칙에 영향을 미치지 않습니다 - 이러한 영역 수준의 규칙은 여전히 평가됩니다.

전체 예제의 경우, 참조[WAF 문서](/waf/managed-rules/waf-exceptions/define-api/#skip-all-remaining-rules).

### 하나 이상의 관리 규칙을 건너

하나 이상의 관리 규칙을 건너려면 규칙을 작성하십시오.`skip`활동 포함`rulesets`현장에`action_parameters`객체. 더 보기`rulesets`필드는 건너뛰고 싶은 관리 규칙 ID 목록을 포함해야 합니다.

규칙 정의의 예:

```json
{
	"expression": "<RULE_EXPRESSION>",
	"action": "skip",
	"action_parameters": {
		"rulesets": ["<MANAGED_RULESET_1_ID>", "<MANAGED_RULESET_2_ID>"]
	}
}
```

전체 예제의 경우, 참조[WAF 문서](/waf/managed-rules/waf-exceptions/define-api/#skip-the-cloudflare-managed-ruleset).

### 관리 규칙의 하나 이상의 규칙을 건너

관리 규칙의 하나 이상의 규칙을 건너려면 규칙을 작성하십시오.`skip`활동 포함`rules`객체의`action_parameters`객체. 더 보기`rules`객체는 키로 하나 이상의 관리된 규칙 ID를 포함해야 하며, 각 키의 값으로 관리된 규칙을 건너는 규칙의 목록입니다.

규칙 정의의 예는 규칙을 건너`A`·`B`관리 규칙`1`, 규칙`X`관리 규칙`2`:

```json
{
	"expression": "<RULE_EXPRESSION>",
	"action": "skip",
	"action_parameters": {
		"rules": {
			"<MANAGED_RULESET_1_ID>": ["<RULE_A_ID>", "<RULE_B_ID>"],
			"<MANAGED_RULESET_2_ID>": ["<RULE_X_ID>"]
		}
	}
}
```

규칙은`rules`객체는 지정된 관리 규칙에 속해야 합니다. 그렇지 않으면 오류가 발생합니다.

전체 예제의 경우, 참조[WAF 문서](/waf/managed-rules/waf-exceptions/define-api/#skip-one-or-more-rules-of-waf-managed-rulesets).

## 추가 노트

- 예외에는 우선 순위가 있습니다.[관련 기사](/ruleset-engine/managed-rulesets/override-managed-ruleset/).
- 나머지 모든 규칙을 건너는 예외를 정의하는 경우, 그 규칙의 표현은 평가되지 않습니다.
- 관리 규칙의 규칙을 건너 뛰는 예외를 정의하는 경우, 관리 규칙을 실행하는 규칙의 표현은 평가되고 관리되는 규칙 규칙은 해당 특정 규칙을 제외하고 실행됩니다.
