규칙 언어는 두 종류의 표현을 지원합니다: 간단하고 화합물.

## 간단한 표현

**간단한 표현**HTTP 요청에서 표현된 값에 값을 비교합니다. 예를 들어,이 간단한 표현은 Microsoft Exchange Autodiscover 요청을 일치시킵니다.

```txt
http.request.uri.path matches "/autodiscover\.(xml|src)$"
```

간단한 표현에는 다음과 같은 문법이 있습니다.

```txt
<field> <comparison_operator> <value>
```

위치:

- [제품정보](/ruleset-engine/rules-language/fields/)HTTP 요청과 관련된 속성을 지정합니다.

- [비교 연산자](/ruleset-engine/rules-language/operators/#comparison-operators)실제 요청 데이터를 반환하는 방법을 정의합니다.`true`.

- [제품정보](/ruleset-engine/rules-language/values/)필드와 관련된 데이터를 나타냅니다. 규칙을 평가할 때, Cloudflare는 요청에서 얻은 실제 데이터와 이러한 값을 비교합니다.

## 화합물 표현

**화합물 표현**제품 정보[논리 연산자](/ruleset-engine/rules-language/operators/#logical-operators)등`and`두 개 이상의 표현을 단일 표현으로 결합합니다.

예를 들어, 이 표현은`and`작업자 대상 요청`www.example.com`포트 80 또는 443에 있지 않습니다.

```txt
http.host eq "www.example.com" and not cf.edge.server_port in {80 443}
```

화합물 표현에는 다음과 같은 일반적인 구문이 있습니다.

```txt
<expression> <logical_operator> <expression>
```

화합물 표현은 정교한, 고도의 대상 규칙을 생성 할 수 있습니다.
