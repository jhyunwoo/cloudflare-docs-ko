HTTP 요청이 Cloudflare 글로벌 네트워크에 도달 할 때 Cloudflare는 필드 값 쌍의 테이블을 작성하여 표현식을 일치시킵니다. 이 테이블은 현재 요청이 처리되기 때문에 오랫동안 존재합니다.

규칙 언어의 표정표를 팝업하는 값은 다양한 소스에서 그려집니다.

- **Primitive 속성**요청에서 직접 획득 (`http.request.uri.path`예를 들어).
- **잘못된 값**변형, 구성, 또는 기본 조작의 제품입니다. 예를 들어, 변환`lower(http.request.uri.path)`값 변환`http.request.uri.path`더 낮은 케이스.
- **Computed 값**검색, 계산, 또는 기타 정보의 제품입니다. 예를 들어, Cloudflare는 역동적으로 공격 점수를 계산하기 위해 기계 학습 프로세스를 사용하며,`cf.waf.score*`사이트 맵

이 값 외에, 표현도 리터값을 포함할 수 있습니다. 이 표현식에 통합된 정적, 알려진 값은 요청/response 필드의 값과 어떤 변형 없이 비교할 수 있습니다.

규칙 표현의 값으로 작업할 때, 다음 섹션에서 정보를 염두에 두십시오.

## 문자열 값과 일반 표현

문자열은 특정한 delimiters에 의해 동봉된 바이트의 순서입니다.

Cloudflare 규칙은 정규 표현식을 포함하여 리터 문자열을 지정하기위한 두 가지 형식을 지원합니다.[문학 문자열 인용](#quoted-string-syntax)·[원시 문자열](#raw-string-syntax). 이 체재에는 다른 delimiters 및 escaping 기계장치가 있습니다.

두 문자열 형식 중 하나를 사용하여 정규 표현식을 표현할 수 있습니다. 그러나 Cloudflare는 당신이 이용하는 것을 추천합니다[원시 문자열 구문](#raw-string-syntax)인용된 문자열 구문은 복잡한 escaping 규칙을 가지고 있고 철저하게 시험되지 않는 경우에 예상치 못한 행동에 지도할 수 있습니다.

Rust 정규 표현식 엔진을 사용하여 정규 표현식 일치가 수행됩니다.

### 인용 문자열 구문

인용된 문자열 문법을 사용할 때, 문자열 리터럴은 delimited by`"`(더블 인용) 문자. 이 형식은 특별한 문자를 탈출해야`"`·`\`이름 \*`\"`·`\\`각각.

인용된 문자열 구문에는 다음과 같은 추가 escaping 요구 사항이 있습니다.

- 오른쪽의 정규 표현식을 지정할 때[regex 연산자](/ruleset-engine/rules-language/operators/#comparison-operators) (`matches`또는`~`), 문자열은 regex escaping 규칙을 사용하여 파싱됩니다.
- 다른 연산자와 같은 표현의 오른쪽에 사용될 때, 또는[기능 모수](/ruleset-engine/rules-language/functions/), 문자열은 기본 escaping 규칙을 사용하여 파싱된다.

```txt title="Examples"
# Test if URI path contains 'a"b'
http.request.uri.path matches "a\"b"

# Test if URI path contains 'a"#b'
http.request.uri.path matches "a\"#b"

# Replace 'a' with '\' (backslash)
regex_replace(http.host, "a", "\\")
```

:::카트로션

어떤 상황에서 당신은 문자열을 두 배로해야합니다 — 예를 들어, 사용할 때[`regex_replace()`](/ruleset-engine/rules-language/functions/#regex_replace)backslash와 일치하는 정규 표현 함수 ()`\`).

이 경우, 함수 매개 변수로 문자열에 의해 필요한 기본 escaping을 수행해야합니다 (사용`\\`각각`\`문자) 또한 regex escaping (사용`\\`각각`\`문자), backslash는 정규 표현식의 특별한 의미를 가지고 있기 때문에.

따라서, backslash를 대체하기 위해 (`\`)와`a`문자 사용`regex_replace()`다음과 같은 표현식을 사용할 수 있습니다:

```txt
regex_replace(http.host, "\\\\", "a")
```

이 상황을 피하기 위해 Cloudflare는 당신이 사용하는 것을 추천합니다[원시 문자열 구문](#raw-string-syntax)정규 표현식을 지정합니다.

:::

### Raw 문자열 구문

문자열을 지정하려면 (또는 정규 표현식) 원시 문자열 구문을 사용하여 특별한 delimiters를 사용합니다.

- 초기 delimiter 구성`r`문자, 선택적으로 하나 이상의`#`문자 (최대 255), 다음`"`(두 배 인용) 특성.
- ending delimiter는`"`(double Quote) 문자는 같은 숫자로 나뉩니다.`#`초기 delimiter로 문자(0에서 255).

원시 문자열에는 특수 문자가 없습니다. 따라서 모든 문자는 엔딩 delimiter로 해석됩니다. (그는 탈출 순서가 없습니다).

인용된 문자열 구문과는 달리, 원시 문자열 구문은 항상 사용 중인 컨텍스트에 관계없이 (예를 들어, 정규 표현식과 같이)[regex 연산자](/ruleset-engine/rules-language/operators/#comparison-operators)또는 매개 변수로[기능 호출](/ruleset-engine/rules-language/functions/)).

```txt title="Examples"
# Test if URI path contains 'a"b'
http.request.uri.path matches r#"a"b"#

# Test if URI path contains 'a"#b'
http.request.uri.path matches r##"a"#b"##

# Replace '\' (backslash) with 'a'
# You must still escape the '\' character in the following raw string because it has a special meaning in regular expressions
regex_replace(http.host, r"\\", "a")

# Test if URI path ends with '/api/login.aspx'
# You must still escape the '.' character in the following raw string because it has a special meaning in regular expressions ("any character")
http.request.uri.path matches r"/api/login\.aspx$"
```

### 문자열 비교의 경우 감도

표현의 문자열 리터럴 값의 평가는 case-sensitive이며, 다음과 같은 옵션 중 하나를 고려하여 표현의 자본 변형을 캡처합니다.

- 사용 방법[`wildcard`](/ruleset-engine/rules-language/operators/#wildcard-matching)연산자, 즉 case-insensitive, 문자열 리터럴 일치.
- 사용 방법[`lower()`](/ruleset-engine/rules-language/functions/#lower)문자열을 비교하기 전에 lowcase로 변환하는 함수.
- 사용 방법[`matches`](/ruleset-engine/rules-language/operators/#regular-expression-matching)연산자 (Business and Enterprise plans에서만 사용 가능) 다른 변형과 일치하는 정규 표현식.
- 여러 하위 압축을 씁니다.[`eq`](/ruleset-engine/rules-language/operators/#comparison-operators)또는[`contains`](/ruleset-engine/rules-language/operators/#comparison-operators)연산자, 함께 가입[`or`](/ruleset-engine/rules-language/operators/#supported-logical-operators)연산자, 문자열 리터럴의 다른 변형을 캡처 (예를 들어,`<field> eq "a" or <field> eq "A"`).

### 정규 표현식 한계

Cloudflare는 일반 표현에 관한 몇 가지 제한이 있습니다. 그 제한 중 하나는 각 규칙은 도메인의 계획에 관계없이 64 정규 표현 (regexes)의 최대를 지원한다는 것입니다.

규칙에서 일반 표현의 수를 줄이기위한 다음 전략을 사용할 수 있습니다.

- 사용 방법[`contains`](/ruleset-engine/rules-language/operators/#comparison-operators)회사 소개
- 사용 방법[`wildcard`](/ruleset-engine/rules-language/operators/#wildcard-matching) / [`strict wildcard`](/ruleset-engine/rules-language/operators/#wildcard-matching)작업자.
- 사용 방법[`starts_with()`](/ruleset-engine/rules-language/functions/#starts_with)·[`ends_with()`](/ruleset-engine/rules-language/functions/#ends_with)기능.

## Boolean 값

boolean 필드를 사용하는 간단한 표현은 연산자 표기 또는 값이 필요하지 않습니다. 자신에 필드를 삽입 할 필요가 있습니다.`ssl`아래 예제.

```sql
ssl
```

이 간단한 표현은 다음과 같은 요청을 일치시킵니다.`ssl`분야는`true`.

자주 묻는 질문`ssl`이름 \*`false`, boolean 사용`not`운영자 :

```sql
not ssl
```

## 기타 제품

Cloudflare 규칙 언어 포함[주요연혁](/ruleset-engine/rules-language/fields/)이름 \*`Array`유형과[제품정보](/ruleset-engine/rules-language/functions/)이름 \*`Array`인수 및 반환 값.

제곱 브래킷 사이 인덱스(non-negative value)를 사용하여 개별 배열 요소에 액세스할 수 있습니다.`[]`). 배열 인덱스 시작`0`(제로).

특별한 표기`[*]`각 배열 요소에 대한 평가 될 표현을 지정할 때 (like)[`map`높은 주문 기능](https://wikipedia.org/wiki/Map_\(higher-order_function\))). 이 특별한 색인 표기는 배열을 풀고, 모든 요소에 대한 엔클링 기능을 개별적으로 호출하고, 모든 개별 반환 값을 포함하는 새로운 배열을 반환합니다.

### 이름 \*

자주 묻는 질문`http.request.headers.names`유형과 분야`Array<String>`다음 예제에서:

- 배열에 있는 첫번째 성분을 얻으십시오:<br />
  `http.request.headers.names[0]`

- 첫 번째 배열 요소가 동일하면 확인`Content-Type`(필요한 케이스):<br />
  `http.request.headers.names[0] == "Content-Type"`

- 어떤 배열 요소가 동등한지 확인`Content-Type`(필요한 케이스):<br />
  `any(http.request.headers.names[*] == "Content-Type")`

- 어떤 배열 요소가 동등한지 확인`Content-Type`, 케이스를 무시:<br />
  `any(lower(http.request.headers.names[*])[*] == "content-type")`

마지막 예에서,`lower()`함수는`[*]`함수는 각 배열 요소에 대해 평가됩니다. 이 기능, 따라 사용`[*]`, 입력 배열의 각 성분이 Lowercase로 변환되는 새로운 배열을 반환합니다. 그런 다음 문자열 비교 사용`[*]`적용된 배열을 변환`lower()`각 헤더 이름은 boolean 값의 배열에 있습니다. 마지막으로,`any()`이 배열 요소의 적어도 하나가 사실이라면 true로 평가합니다.

## 지도 보기

지도, 또한 associative 배열이라고 불린, 열쇠가 있어야 하는 열쇠 가치 쌍의 수집을 저장하는 자료 구조입니다`String`그리고 값은 어떤 유형 (예를 들면, a`String`또는 값의 배열). 지도의 모든 값은 동일한 유형이 있어야 합니다.

Cloudflare 규칙 언어는 몇몇을 포함합니다[주요연혁](/ruleset-engine/rules-language/fields/)이름 \*`Map`데이터 유형. 맵 필드의 유형 표기, 예를 들어`Map<Array<String>>`, 키와 관련된 값의 데이터 유형을 나타냅니다 (안`Array`이름 \*`String`요소). 이것은 당신이 키의 값을 접근 할 때`"foo"`당신은 하나의 배열을 얻을 것이다`String`요소 또는[누락된 값](#notes-1).

지도의 값에 액세스하려면 스퀘어 브래킷 사이의 키를 입력하십시오 (`[]`):

```txt
<MAP_FIELD>[<KEY>]
```

값이 있는지도를 위해`Array`유형, 당신은 직접 사용할 수 없습니다[채용 정보](/ruleset-engine/rules-language/operators/)얻은 (array) 값으로, 이 연산자가 직접 배열을 지원하지 않기 때문에. 배열의 항목에 연산자를 사용하려면 특별한 표기를 사용하십시오.`[*]`표현을 지정할 때. 이 특별한 색인 표기는 배열을 풀고, 모든 요소에 대한 엔클링 기능을 개별적으로 호출하고, 모든 개별 반환 값을 포함하는 새로운 배열을 반환합니다.

### 이름 \*

다음 예제를 기반으로[`http.request.headers`](/ruleset-engine/rules-language/fields/reference/http.request.headers/)데이터 유형의 필드`Map<Array<String>>`, 어디 배열 요소의`String`데이터 유형.

수신 HTTP 요청이 단일에 포함 된 경우`Accept: application/json`HTTP 헤더, 다음과 같은 표현은 다음과 같은 값으로 평가됩니다:

```txt
http.request.headers["accept"]     # ==> ["application/json"]
http.request.headers["accept"][0]  # ==> "application/json"

any(http.request.headers["accept"][*] == "application/json") # ==> true
any(http.request.headers["accept"][*] == "text/plain")       # ==> false
```

다음 예제를 기반으로[`http.request.uri.args`](/ruleset-engine/rules-language/fields/reference/http.request.uri.args/)데이터 유형의 필드`Map<Array<String>>`, 어디 배열 요소의`String`데이터 유형.

HTTP 요청이 포함된 경우 3`filter`URI 인수`waf`, `botm`·`cdn`, 다음과 같은 표현은 표시된 값으로 평가됩니다:

```txt
# Example request URL:
# https://example.com/?filter=waf&filter=botm&filter=cdn

http.request.uri.args["filter"]          # ==> ["waf", "botm", "cdn"]

len(http.request.uri.args["filter"][1])  # ==> 4

# Check if the length of all 'filter' values is always 3 or 4
all(len(http.request.uri.args["filter"][*])[*] in {3 4})      # ==> true

# Check if the length of 'filter' values (if any) is never 3 or 4
all(not len(http.request.uri.args["filter"][*])[*] in {3 4})  # ==> false

# Check if the http.request.uri.args map contains a "filter" key
len(http.request.uri.args["filter"]) >= 0     # ==> true

# Check if the http.request.uri.args map does not contain an "order" key
not len(http.request.uri.args["order"]) >= 0  # ==> true
```

더 많은 정보`any()`, `all()`, `len()`, 및 다른 유효한 기능, 참조[제품정보](/ruleset-engine/rules-language/functions/).

## 이름 \*

목록은 아이템의 그룹을 만들 수 있으며, 이름, 표현에 따라 집단적으로 나타납니다. 각 목록 유형은 특정한 자료 유형의 품목을 지원합니다. 목록의 모든 항목은 동일한 데이터 유형이 있어야합니다. 사용 가능한 목록 유형에 대한 자세한 내용은 참조[이름 \*](/waf/tools/lists/#supported-lists).

규칙 표현의 목록을 참조하려면 사용`$<list_name>`그리고 지정`in` [회사연혁](/ruleset-engine/rules-language/operators/). 목록의 한 값 만 표현의 왼쪽 측면과 일치해야합니다 (예를 들어`in`연산자) 간단한 표현을 위해 평가하는`true`. 일치하지 않은 경우, 표현은 평가됩니다`false`.

IP 주소에서 다음과 같은 예식 필터 요청[IP 목록](/waf/tools/lists/custom-lists/#ip-lists)이름 \*`office_network`:

```sql
(ip.src in $office_network)
```

목록 이름은 더 낮은 케이스 문자, 숫자, 그리고 밑줄만 포함할 수 있습니다 (`_`) 문자. 작성 및 관리 목록에 대한 안내는 참조[이름 \*](/waf/tools/lists/).

### Inline 목록

Inline lists를 사용하면 간단한 표현의 값 목록을 직접 포함 할 수 있습니다.`in`회사 소개

인라인 목록의 요소는 문자열, 정수 또는 IP 주소/범위일 수 있습니다. 인라인 목록의 모든 요소는 동일한 데이터 유형이 있어야하며 리터 값이어야합니다. 인라인 목록 요소를 지정하려면 개별적으로 입력하여 공간을 분리합니다. 인라인 목록은 중복 값을 포함 할 수 있습니다.

또한 일부 데이터 유형에 대해서는 다음과 같이 범위를 사용할 수 있습니다.

- integer 값의 경우, 형식의 범위를 입력`<start_value>..<end_value>`. 인라인 목록은 정수 범위와 정수 값을 모두 포함 할 수 있습니다.
- IP 주소를 위해, 당신은 입력할 수 있습니다:

  - Explicit IP는 형태에 배열합니다`<start_address>..<end_address>`(예:`198.51.100.3..198.51.100.7`).
  - CIDR 범위 (예를 들면,`192.0.2.0/24`또는`2001:0db8::/32`).

  인라인 목록은 명시된 IP 범위, CIDR 범위 및 개별 IP 주소를 포함할 수 있습니다.

```sql title="Examples"
http.host in {"example.com" "example.net"}

ip.src in {198.51.100.1 198.51.100.3..198.51.100.7 192.0.2.0/24 2001:0db8::/32}

tcp.dstport in {8000..8009 8080..8089}
```
