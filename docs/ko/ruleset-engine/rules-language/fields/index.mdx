Cloudflare 규칙 언어는 다음과 같은 다른 유형의 필드를 지원합니다:

- 요청 필드는 요청 헤더, URI 구성 요소 및 요청 바디에 대한 특정 필드를 포함하여 수신 요청의 기본 속성을 나타냅니다.
- 계산 또는 파생 된 값을 나타내는 동적 필드, 일반적으로 HTTP 요청에 대한 위협 인텔리전스 관련.
- 수신 응답의 기본 속성을 나타내는 응답 필드.
- 나중에 평가에 대한 원래 요청 값을 보존하는 Raw 필드.

더 알아보기[필드 참고 자료](/ruleset-engine/rules-language/fields/reference/)사용 가능한 필드의 목록입니다.

## Wireshark 디스플레이 필드의 차이점

Cloudflare 규칙 언어에 의해 지원되는 대부분의 분야는 동일한 naming 규칙을 이용합니다[Wireshark 디스플레이 필드](https://www.wireshark.org/docs/wsug_html_chunked/ChWorkBuildDisplayFilterSection.html). 그러나, Cloudflare와 Wireshark 사이 몇몇 미묘한 다름이 있습니다:

- Wireshark 지원[CIDR (클래스리스 인터 도어 루팅) 표기](https://en.wikipedia.org/wiki/Classless_Inter-Domain_Routing)IP 주소를 표현하기 위해 equality 비교 범위 (`ip.src == 1.2.3.0/24`예를 들어). Cloudflare는 아닙니다.

  CIDR 표기를 사용하여 다양한 주소를 평가하기 위해[`in`](/ruleset-engine/rules-language/operators/#comparison-operators)이 예에서 비교 연산자:`ip.src in {1.2.3.0/24 4.5.6.0/24}`.

- Wireshark에서`ssl`여러 가지 방법으로 비교할 수 있는 다양한 유형의 수백 가지를 포함하는 프로토콜 필드입니다. 그러나 규칙 언어에서[`ssl`](/ruleset-engine/rules-language/fields/reference/ssl/)클라이언트에서 Cloudflare에 연결 여부를 나타내는 단일 Boolean 필드입니다.

- Cloudflare 규칙 언어는 지원하지 않습니다.`slice`회사 소개
