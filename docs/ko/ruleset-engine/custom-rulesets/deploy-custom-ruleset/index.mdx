사용자 정의 규칙을 배포하려면 규칙을 추가하십시오.`execute`단계의 규칙의 목록에 작용[관련 항목](/ruleset-engine/about/rulesets/#entry-point-ruleset)계정 또는 영역 수준에서. 새로운 규칙의 표현은 사용자 정의 규칙이 실행될 때 정의됩니다.

동일한 범위의 항목 포인트 규칙에 사용자 정의 규칙 만 배치 할 수 있습니다. 예를 들어, 계정 수준에서 정의된 사용자 정의 규칙은 계정 수준에서만 배포할 수 있습니다.

## 시작하기 전에

1. 이름 얻기[단계별](/ruleset-engine/reference/phases-list/)사용자 정의 규칙을 배포하고 싶은 곳.
2. [사용자 정의 규칙 만들기](/ruleset-engine/custom-rulesets/create-custom-ruleset/)새로운 사용자 정의 규칙의 ID를 유지.
3. [규칙은 이미 단계 항목 포인트 규칙에 제시](/ruleset-engine/basic-operations/view-rulesets/#view-the-rules-included-in-a-ruleset). 당신은 포함해야`PUT`계속하려면 모든 기존 규칙을 요청하십시오.

## 예제 A - 계정 수준 배치

다음 것`PUT`request adds a 규칙 that performs a custom ruleet when the zone name match`example.com`.

내 계정`PUT`요청, 당신은 유지하려는 모든 기존 규칙의 ID를 포함해야합니다. 응답은 업데이트 후 단계 항목 포인트 규칙의 모든 규칙을 포함합니다.

<APIRequest
  path="/accounts/{account_id}/rulesets/phases/{ruleset_phase}/entrypoint"
  method="PUT"
  parameters={{
  	ruleset_phase: "http_request_firewall_custom",
  }}
  json={{
  	rules: [
  		{
  			action: "execute",
  			description: "Execute custom ruleset",
  			expression: '(cf.zone.name == "example.com") and cf.zone.plan eq "ENT"',
  			action_parameters: {
  				id: "<CUSTOM_RULESET_ID>",
  			},
  		},
  		{
  			id: "<EXISTING_PHASE_RULE_ID_1>",
  		},
  		{
  			id: "<EXISTING_PHASE_RULE_ID_2>",
  		},
  	],
  }}
/>

## 예제 B - Zone-level 배포

다음 것`PUT`요청은 ID와 사용자 정의 규칙을 실행하는 영역 수준의 항목 포인트 규칙에 규칙을 추가`"<CUSTOM_RULESET_ID>"`요청 대상`/login`URI 경로.

당신은 포함해야`PUT`유지하려는 모든 기존 규칙의 ID를 요청합니다. 응답은 업데이트 후 단계 항목 포인트 규칙의 모든 규칙을 포함합니다.

<APIRequest
  path="/zones/{zone_id}/rulesets/phases/{ruleset_phase}/entrypoint"
  method="PUT"
  parameters={{
  	ruleset_phase: "http_request_firewall_custom",
  }}
  json={{
  	rules: [
  		{
  			action: "execute",
  			description: "Execute custom ruleset (zone)",
  			expression: '(http.request.uri.path eq "/login")',
  			action_parameters: {
  				id: "<CUSTOM_RULESET_ID>",
  			},
  		},
  		{
  			id: "<EXISTING_PHASE_RULE_ID_1>",
  		},
  	],
  }}
/>
