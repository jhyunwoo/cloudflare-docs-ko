규칙은 필터와 필터와 일치하는 들어오는 요청에 수행 할 작업을 정의합니다.

- 법칙[이름 \*](/ruleset-engine/rules-language/expressions/), 또한 필터 표현을 호출, 규칙의 범위를 정의.
- 법칙[이름 \*](/ruleset-engine/rules-language/actions/)표현의 일치가 있을 때 무슨 일이 일어나는지 정의합니다.

규칙 표현은 정의된다[언어 선택](/ruleset-engine/rules-language/).

예를 들어, 4 가지 규칙 (R1, R2, R3 및 R4)과 다음 규칙을 고려하십시오. 주어진 수신 요청의 경우, 첫 번째 두 가지 규칙의 표현은 요청 속성에 일치합니다. 따라서, 이러한 규칙의 행동은 실행 (*계정 관리*·*로그인*, 각각). 첫 번째 규칙의 동작은 관리 규칙을 실행, 이는 관리 규칙에 모든 규칙이 평가된다. 두 번째 규칙의 행동은 현재 단계와 관련된 이벤트를 기록합니다. 규칙 3과 4의 표현에 대한 일치는 없습니다, 그래서 그들의 행동은 실행되지 않습니다. 규칙이 요청을 차단하지 않기 때문에 다음 단계로 진행합니다.

![규칙 실행 시나리오의 예. 첫 번째 규칙이 관리 된 규칙을 실행하는 4 가지 규칙을 무시합니다.](~/assets/images/ruleset-engine/rulesets-rules-example.png)

규칙은 특정 Cloudflare 제품을 통해 추가 기능을 가질 수 있습니다. 규칙 표현을 위해 더 많은 필드를 가질 수 있습니다, 다른 작업을 수행, 또는 주어진 단계에서 추가 동작을 구성.

## 규칙 평가

규칙을 평가할 때, Cloudflare는 요청/response 속성 또는 파생된 값의 값을 비교합니다.[주요연혁](/ruleset-engine/rules-language/fields/)) 규칙의 필터 표현에 정의 된 사람들.

전체 표현이 평가되면`true`, 규칙 일치가 있고 Cloudflare는 트리거합니다[이름 \*](/ruleset-engine/rules-language/actions/)규칙에서 구성. 표현이 평가되면`false`, 규칙은 일치하지 않으며 구성 된 행동은 적용되지 않습니다.

이용 시`true`규칙 필터 표현으로, 이것은 "모든 들어오는 요청에 규칙을 적용"을 현재[단계별](/ruleset-engine/about/phases/)지역 또는 계정 일 수 있는 수준.

:::주\[주]

- boolean 값에 대한 규칙 필터 표현이 있어야 합니다 (either`true`또는`false`).
- 특정 CloudflareXQ 제품의 규칙과 같은[Transform 규칙](/rules/transform/), 동적 값을 지정하는 데 사용되는 다른 표현이 포함될 수 있습니다. 이 표현은 불린 값에 대한 평가가 없습니다.

### 규칙 평가 중 필드 값

주어진 요청 / 응답에 대한 규칙을 평가하는 동안, 모든 요청 및 응답의 값[주요연혁](/ruleset-engine/rules-language/fields/)각 단계 안에 immutable 입니다. 그러나 필드 값은 단계 사이에 변경 될 수 있습니다.

예를 들면:

- 이름 \*[URL rewrite 규칙](/rules/transform/url-rewrite/)#1 URI 경로 또는 요청의 쿼리 문자열을 업데이트, URL 다시 쓰기 규칙 #2 고려으로 이러한 이전 변경을하지 않습니다.
- 이름 \*[요청 헤더 변형 규칙](/rules/transform/request-header-modification/)#1 HTTP 요청 헤더의 값을 설정, 요청 헤더 변형 규칙 #2 이 새로운 값을 읽거나 평가 할 수 없습니다.
- URL rewrite 규칙이 요청의 URI 경로 또는 쿼리 문자열을 업데이트하는 경우,`http.request.uri`, `http.request.uri.*`·`http.request.full_uri`필드는 단계에 다른 값이 있습니다.`http_request_transform`단계 (URL Rewrite 규칙이 실행되는 경우).

:::참조
나중에 평가 된 규칙의 원래 필드 값을 사용하려면 원 필드를 사용할 수 있습니다 (예를 들어,`raw.http.request.uri.path`) 그들의 표현에서. 이 특수 필드는 전체 요청 평가 워크플로우에서 immutable입니다. 원료 분야의 목록은, 참고합니다[필드 참고 자료](/ruleset-engine/rules-language/fields/reference/?field-category=Raw+fields).
:::
