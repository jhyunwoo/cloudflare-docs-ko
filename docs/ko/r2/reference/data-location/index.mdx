R2에 저장된 데이터의 위치를 어떻게 결정하고 당신의 물통에 있는 물체가 저장되는 물리적 위치를 통제하는 다른 유효한 입력에 관하여.

## 자동 (추천)

새 버킷을 만들 때 데이터 위치는 기본적으로 자동 설정됩니다. 현재이 옵션은 콜러의 위치에 근거를 둔 버킷 요청을 만드는 가장 가까운 가능한 지역에 버킷 위치를 선택합니다.

## 위치 힌트

위치 힌트는 선택적 매개 변수입니다. 버킷 생성 중에 데이터를 기대하는 기본 지리적 위치를 나타냅니다.

오시는 길 힌트는 버킷의 데이터에 액세스 할 때 좋은 선택이 될 수 있으며 버킷 요청이 시작되는 것보다 다른 위치에서 올 수 있습니다. 힌트를 염두에두고, 힌트는 최고의 노력과 보증이 아니라, 그들은 정기적으로 업데이트 된 내용을 사용자에게 더 가까이 배치하여 성능을 최적화하는 방법으로 사용해야합니다.

### Cloudflare dashboard

당신은 자동으로 당신의 위치에 근거를 둔 가장 가까운 유효한 지역에 당신의 물통을 창조하거나 목록에서 특정한 위치를 선택할 수 있습니다.

1. Cloudflare dashboard에서,**R2 객체 저장**사이트 맵

   <DashButton url="/?to=/:account/r2/overview" />
2. 제품정보**버킷 만들기**.
3. 물통의 이름을 입력하십시오.
4. 이름 \***제품정보**, 휴가*이름 \**&#xC790;동 선택 또는 목록에서 지역을 선택하십시오.
5. 제품정보**버킷 만들기**버킷 생성 프로세스를 완료하기 위해.

### S3 API를 통해 힌트 설정

위치 힌트를 통해 설정할 수 있습니다.`LocationConstraint`S3 API를 사용하는 매개변수:

```js
await S3.send(
	new CreateBucketCommand({
		Bucket: "YOUR_BUCKET_NAME",
		CreateBucketConfiguration: {
			LocationConstraint: "WNAM",
		},
	}),
);
```

더 알아보기[이름 \*](/r2/examples/)다른 S3 SDK에서 추가 예제를 위해.

### 자주 묻는 질문

위치 힌트는 주어진 이름을 가진 물통을 처음으로 명예를 줍니다. 같은 이름으로 버킷을 삭제하고 다시 작성하면 원래 버킷의 위치가 사용됩니다.

## 관할 구역

관할구역 내에는 관할구역이 있습니다.

데이터가 저장되고 처리될 때 관할 구역 내에서 데이터 잔고 요구 사항을 충족하기 위해 필요한 관할 구역 내에서 보관하고 처리할 때 관할 구역 내에서 보관할 수 있습니다.[GDPR](https://gdpr-info.eu/)또는[파일 형식](https://blog.cloudflare.com/cloudflare-achieves-fedramp-authorization/).

### Cloudflare dashboard

1. Cloudflare dashboard에서, 가십시오**R2 객체 저장**사이트 맵

   <DashButton url="/?to=/:account/r2/overview" />
2. 제품정보**버킷 만들기**.
3. 물통의 이름을 입력하십시오.
4. 이름 \***제품정보**, 선택**관할 구역**목록에서 관할권을 선택하십시오.
5. 제품정보**버킷 만들기**버킷 생성 프로세스를 완료하기 위해.

### Workers의 관할권을 사용하여

R2 버킷에 액세스하려면 관할권에 속합니다.[모델 번호: Workers](/workers/), 당신은 관할 구역을 지정해야 할뿐만 아니라 물통 이름의 일부[관련 제품](/r2/api/workers/workers-api-usage/#3-bind-your-bucket-to-a-worker)내 계정[Wrangler 구성 파일](/workers/wrangler/configuration/):

<WranglerConfig>
  ```jsonc
  {
  	"r2_buckets": [
  		{
  			"bindings": [
  				{
  					"binding": "MY_BUCKET",
  					"bucket_name": "<YOUR_BUCKET_NAME>",
  					"jurisdiction": "<JURISDICTION>"
  				}
  			]
  		}
  	]
  }
  ```
</WranglerConfig>

더 많은 정보를 얻기 위해, 참조[R2XQ를 Workers에서 사용하십시오](/r2/api/workers/workers-api-usage/).

### S3 API로 관할권을 사용

S3 API 또는 기존 S3-compatible SDK로 정의된 관할권에 속한 R2 리소스와 상호 작용할 때, 지정해야 합니다.[회사연혁](#available-jurisdictions)S3 엔드포인트에서:

`https://<ACCOUNT_ID>.<JURISDICTION>.r2.cloudflarestorage.com`

관할 구역 별 엔드포인트를 사용할 수 있습니다.[지원된 S3 API 가동](/r2/api/s3/api/). 관할 구역 엔드포인트를 사용할 때 해당 관할 구역 이외의 R2 리소스에 액세스할 수 없습니다.

아래 예제는 R2 버킷을 만드는 방법을 보여줍니다.`eu`관할구역[`@aws-sdk/client-s3`](https://www.npmjs.com/package/@aws-sdk/client-s3)JavaScript를 위한 포장.

```js
import { S3Client, CreateBucketCommand } from "@aws-sdk/client-s3";
const S3 = new S3Client({
	endpoint: "https://<account_id>.eu.r2.cloudflarestorage.com",
	credentials: {
		accessKeyId: "<access_key_id",
		secretAccessKey: "<access_key_secret>",
	},
	region: "auto",
});
await S3.send(
	new CreateBucketCommand({
		Bucket: "YOUR_BUCKET_NAME",
	}),
);
```

더 알아보기[이름 \*](/r2/examples/)다른 S3 SDK에서 추가 예제를 위해.

### 제한 사항

다음 서비스는 지정된 관할 구역으로 R2 리소스와 상호 작용하지 않습니다.

- [슈퍼 Slurper](/r2/data-migration/) (*현재 위치*)
- [다운로드](/logs/logpush/logpush-job/enable-destinations/r2/). 이 한계에 workaround로, 당신은 위로 설정할 수 있습니다[S3-compatible endpoint를 사용하는 Logpush 작업](/data-localization/how-to/r2/#send-logs-to-r2-via-s3-compatible-endpoint)R2 버킷을 선택의 관할 구역에 저장하십시오.

R2 버킷이 생성되면 관할권이 변경 될 수 없습니다.
