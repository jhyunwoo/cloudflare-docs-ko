R2는 Workers의 정상에 건축되고 Unicode를 기본적으로 지원합니다. 자주 보이는 Unicode의 한 nuance는 문제입니다[파일명 상호 운용성](https://en.wikipedia.org/wiki/Filename#Encoding_indication_interoperability)이름 \*[Unicode 주식](https://en.wikipedia.org/wiki/Unicode_equivalence).

사용자의 피드백에 따라 기본 저장하기 전에 NFC-normalize 키 이름을 선택했습니다. 즉,`Héllo`·`Héllo`예를 들면, R2에 있는 동일한 목표 그러나 다른 저장 공급자에 있는 다른 목표입니다. 그러나`Héllo`·`Héllo`다른 문자 바이트 순서가 될 수 있습니다, 그들은 동일하게 렌더링됩니다.

R2는 전시를 위한 기호화를 그러나 보존합니다. 개체를 나열하면 업로드 된 마지막 인코딩을 다시 얻을 수 있습니다.

고려해야 할 몇 가지 플랫폼 별 차이점이 있습니다.

- Windows 및 macOS 파일명은 R2 및 Linux가 아닌 경우 불균형입니다.
- Unicode에 대한 Windows 콘솔 지원은 오류가 발생 할 수 있습니다. 자주 묻는 질문`chcp 65001`command-line 도구를 사용하거나 객체 이름이 잘못 될 경우 Cygwin을 사용하십시오.
- Linux는 파일명이 바이트 스트림이기 때문에 unicode-equivalent는 구별된 파일을 허용합니다. Linux의 유니코드-equivalent 파일명은 R2 객체와 동일합니다.

만약 당신이 unicode equivalence를 우회할 수 있고 byte-centric 키 이름을 사용 하 여 귀하의 Cloudflare 계정 팀에 게 연락할 수 있는 중요 한 경우.
