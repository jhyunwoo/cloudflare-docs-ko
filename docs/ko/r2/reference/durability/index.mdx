R2는 연례 내구성의 99.999999999% (eleven 9s)를 제공하기 위하여 디자인됩니다. 이것은 당신이 R2XQ에 10,000,000의 목표를 저장하는 경우에, 당신은 평균에 10,000 년마다 목표를 잃을 것으로 예상할 수 있습니다.

## R2는 eleven-nines 내구성을 달성합니다

R2의 내구성은 중복과 데이터 보호의 다수 층에 건설됩니다:

- **이름 \***: 객체를 업로드하면 R2는 전체 복제 및/또는 지우기 코딩을 통해 그 객체의 여러 "copies"를 저장합니다. 모든 개별 디스크의 전체 또는 부분 고장이 데이터 손실에서 발생하지 않도록 보장합니다. Erasure 코딩은 여러 디스크에 걸쳐 객체의 부품을 배포하고, 일부 디스크가 실패하더라도, 객체는 여전히 사용 가능한 부품의 하위 세트에서 재구성 될 수있다, 하드웨어 고장 또는 데이터 센터에 물리적 영향을 방지 (예 : 화재 또는 홍수와 같은) 데이터 손실.

- **하드웨어 중복**: 스토리지 클러스터는 지리적 영역 내에서 여러 데이터 센터를 통해 배포된 하드웨어로 구성되어 있습니다. 이 물리적 배포는 전원 부족, 네트워크 중단, 또는 단일 시설에서 하드웨어 고장과 같은 현지화 된 실패를 보장한다. 데이터 손실이 발생하지 않습니다.

- **동시 쓰기**: R2 반환`HTTP 200 (OK)`API를 통해 쓰기 또는 그렇지 않으면 데이터가 디스크에 침투되었을 때만 성공을 나타냅니다. 내구성을 보장하는 비동기 복제에 의존하지 않습니다. 이것은 R2의 일관성 보증과 변화가 지속되는 메타데이터 및 스토리지 인프라 없이 성공적인 API 응답을 수신하는 클라이언트의 기회를 부여하는 것입니다.

### 관련 기사

- 내구성은 데이터 가용성을 보장하지 않습니다. 데이터 손실의 likelihood의 측정입니다.
- R2는 가용성을 제공합니다[99.9%의 SLA](https://www.cloudflare.com/r2-service-level-agreement/)
- 내구성은 의도적 또는 사고를 방지하지 않습니다. 제품 정보[물통 자물쇠](/r2/buckets/bucket-locks/)및 / 또는 양동이-scoped[API 토큰](/r2/api/tokens/)데이터에 대한 제한 접근.
- 내구성은 또한 구별됩니다[이름 \*](/r2/reference/consistency/), 읽는 방법을 설명하고 쓰기는 시스템의 상태 (예 : eventual 견실함 대 강한 견실함)에서 반영됩니다.
