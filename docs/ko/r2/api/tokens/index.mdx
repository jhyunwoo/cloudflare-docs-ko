기존 S3- 호환 SDK 또는 XML API를 사용하여 액세스 키 역할을 하는 API 토큰을 생성할 수 있습니다.

:::참조
이 페이지에는 API 토큰 생성에 대한 지침이 포함되어 있습니다.*제품 정보*R2를 위해. 이것은 다른 서비스에 대한 API 토큰 생성과 다릅니다.[API 토큰 만들기](/fundamentals/api/get-started/create-token/).
:::

API 토큰을 생성하기 전에 R2XQ를 구입해야합니다.

API 토큰을 만들려면:

1. Cloudflare dashboard에서, 가십시오**R2 객체 저장**사이트 맵

   <DashButton url="/?to=/:account/r2/overview" />
2. 제품정보**R2 관리 API 토큰**.
3. 하나를 만들려면:
   - **계정 API 토큰 만들기**- 이 토큰은 Cloudflare 계정 자체에 연결되며 모든 권한 시스템 또는 사용자에 의해 사용할 수 있습니다. Super Administrator 역할에 대한 사용자 만 볼 수 있고 만들 수 있습니다. 이 토큰은 수동으로 변경 될 때까지 유효합니다.
   - **사용자 API 토큰 만들기**- 이 토큰은 개별 Cloudflare 사용자에 연결됩니다. 개인 허가를 상속하고 사용자가 계정에서 제거되면 비활성화됩니다.
4. 이름 \***제출**, 토큰에 대한 권한 유형 선택. 더 알아보기[제출](#permissions)각 옵션에 대한 정보.
5. (선택) 선택하면**개체 읽기 및 쓰기**또는**객체 읽기**권한, 당신은 당신의 토큰을 물통의 세트에 배열할 수 있습니다.
6. 제품정보**계정 API 토큰 만들기**또는**사용자 API 토큰 만들기**.

토큰이 성공적으로 생성 된 후 리뷰를 검토하십시오.**비밀 액세스 키**·**액세스 키 ID**가치. 이들은 종종 Client Secret 및 Client ID라고 할 수 있습니다.

:::카트로션

액세스 할 수 없습니다**비밀 액세스 키**이 단계 후에 다시. 그들을 잃을 피하기 위해 두 값을 복사하고 기록합니다.

:::

구성해야 할 수도 있습니다.`endpoint`S3 클라이언트에서`https://<ACCOUNT_ID>.r2.cloudflarestorage.com`.

내 계정[Cloudflare dashboard의 계정 ID](/fundamentals/account/find-account-and-zone-ids/).

관할 구역으로 만든 물통은 관할 구역 별 엔드포인트를 통해 접근해야 합니다.

- 유럽 연합 (EU):`https://<ACCOUNT_ID>.eu.r2.cloudflarestorage.com`
- 파일 형식:`https://<ACCOUNT_ID>.fedramp.r2.cloudflarestorage.com`

:::카트로션

관할 구역 끝점을 통해서만 접근할 수 있습니다. 대부분의 S3 클라이언트는 여러 가지 구성할 수 없습니다.`endpoints`, 그래서 당신은 일반적으로 관할 당 하나의 클라이언트를 초기화해야합니다.

:::

## API를 통해 API 토큰 만들기

API를 통해 API 토큰을 생성하고 해당 액세스 키 ID 및 비밀 액세스 키 값을 생성하는 데 사용할 수 있습니다. get started에, 참고하십시오[API를 통해 API 토큰 만들기](/fundamentals/api/how-to/create-via-api/). R2를 위한 특성은 아래에 있습니다.

### 오시는 길

액세스 정책은 토큰을 액세스 할 수있는 리소스를 지정하고 권한이 있습니다.

#### 지원하다

R2를 위한 2개의 관련 자원 유형이 있습니다:`Account`·`Bucket`. 계정 리소스 유형에 대한 자세한 내용은 참조[계좌정보](/fundamentals/api/how-to/create-via-api/#account).

##### 제품정보

계정에서 R2 물통 또는 모든 물통의 세트를 포함하십시오.

특정한 물통은 다음과 같이 대표됩니다:

```json
"com.cloudflare.edge.r2.bucket.<ACCOUNT_ID>_<JURISDICTION>_<BUCKET_NAME>": "*"
```

- `ACCOUNT_ID`: 참고[지역 및 계정 ID 찾기](/fundamentals/account/find-account-and-zone-ids/#find-account-id-workers-and-pages).
- `JURISDICTION`: 한국어[회사연혁](/r2/reference/data-location/#available-jurisdictions)R2 양동이 생활. 특정 관할권에서 생성되지 않는 물통을 위해 이 가치는 일 것입니다`default`.
- `BUCKET_NAME`: 액세스 정책의 양동이의 이름은 적용됩니다.

계정의 모든 버킷은 다음과 같습니다.

```json
"com.cloudflare.api.account.<ACCOUNT_ID>": {
  "com.cloudflare.edge.r2.bucket.*": "*"
}
```

- `ACCOUNT_ID`: 참고[지역 및 계정 ID 찾기](/fundamentals/account/find-account-and-zone-ids/#find-account-id-workers-and-pages).

### API 토큰에서 S3 API 자격 취득

액세스 키 ID 및 비밀 액세스 키 값을 응답에서 얻을 수 있습니다[토큰 만들기](/api/resources/user/subresources/tokens/methods/create/)API:

- 액세스 키 ID :`id`API 토큰의.
- 비밀 액세스 키: API 토큰의 SHA-256 해시`value`.

더 알아보기[auth 토큰을 사용하여 R2 API에 대한 인증](/r2/examples/authenticate-r2-auth-tokens/)JavaScript, Python 및 Go 예제를 가진 튜토리얼을 위해.

## 임시 접근 자격

물통을 위한 임시 credentials 또는 물통 안에 prefix/object를 창조하는 경우에, 당신은 사용할 수 있습니다[temp-access-credentials 엔드포인트](/api/resources/r2/subresources/temporary_credentials/methods/create/)API에서. 당신은 기존의 R2 토큰이 부모 액세스 키 ID로 전달해야합니다. 같은 자격 변수를 설정하여 S3-compatible 요청에 대한 API 결과에서 자격 증명을 사용할 수 있습니다.

```
AWS_ACCESS_KEY_ID = <accessKeyId>
AWS_SECRET_ACCESS_KEY = <secretAccessKey>
AWS_SESSION_TOKEN = <sessionToken>
```

:::참조

임시 액세스 키는 부모 액세스 키보다 높은 권한을 가질 수 없습니다. e.g. 부모 키가 설정되면`Object Read Write`, 임시 접근 열쇠는 단지 가지고 있을 수 있었습니다`Object Read Write`또는`Object Read Only`이름 \*

:::
