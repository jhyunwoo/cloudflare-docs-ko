이 가이드를 따르면, 응용 프로그램이 멀티 파트 업로드를 수행 할 수있는 작업자를 만들 것입니다.
이 예제 worker는 worker에 인증을 추가할 수 있는 자신의 사용 사례에 대한 기초로 제공 할 수 있거나 각 부분을 업로드 할 때 추가 유효성 논리를 추가 할 수 있습니다.
이 가이드에는 이 작업자에게 파일을 업로드하는 Python 응용 프로그램이 포함되어 있습니다.

이 가이드는 당신이 설정 한 가정[R2 바인딩](/workers/runtime-apis/bindings/)당신의 노동자를 위해. 더 알아보기[R2를 Workers에서 사용하십시오](/r2/api/workers/workers-api-usage)R2 바인딩을 설정하는 방법에 대한 지침.

## multipart API를 사용하여 작업자

다음 예제 Worker는 Worker를 통해 Multipart API를 사용할 수 있는 HTTP API를 노출합니다.

이 예에서 각 요청은 HTTP 방법과 행동 요청 매개 변수를 기반으로합니다. 작업자가 더 복잡해지면 서버가 없는 웹 프레임워크를 활용해야 합니다.[호노](https://honojs.dev/)당신을 위한 여정을 취급하기 위하여.

다음 예제 Worker는 각 요청에 대한 응답에서 multipart 업로드의 상태에 대한 새로운 정보를 포함합니다. multipart 업로드를 만드는 요청을 위해,`uploadId`반환합니다. 요청에 대한 업로드 부분, 부품 번호 및`etag`반환합니다. 차례로, 클라이언트는이 상태의 추적을 유지하고, 다음 요청에서 uploadId를 포함,`etag`복수 업로드를 완료할 때 각 부분의 부품 번호.

프로젝트의 다음 코드를 추가`index.js`파일 및 교체`MY_BUCKET`당신의 물통의 이름으로:

```js
interface Env {
  MY_BUCKET: R2Bucket;
}

export default {
  async fetch(
    request,
    env,
    ctx
  ): Promise<Response> {
    const bucket = env.MY_BUCKET;

    const url = new URL(request.url);
    const key = url.pathname.slice(1);
    const action = url.searchParams.get("action");

    if (action === null) {
      return new Response("Missing action type", { status: 400 });
    }

    //HTTP 방법 및 행동 유형에 따라 요청을 루트
    switch (request.method) {
      case "POST":
        switch (action) {
          case "mpu-create": {
            const multipartUpload = await bucket.createMultipartUpload(key);
            return new Response(
              JSON.stringify({
                key: multipartUpload.key,
                uploadId: multipartUpload.uploadId,
              })
            );
          }
          case "mpu-complete": {
            const uploadId = url.searchParams.get("uploadId");
            if (uploadId === null) {
              return new Response("Missing uploadId", { status: 400 });
            }

            const multipartUpload = env.MY_BUCKET.resumeMultipartUpload(
              key,
              uploadId
            );

            interface completeBody {
              parts: R2UploadedPart[];
            }
            const completeBody: completeBody = await request.json();
            if (completeBody === null) {
              return new Response("Missing or incomplete body", {
                status: 400,
              });
            }

            //Multipart 업로드가 더 이상 존재하지 않는 경우 오류 처리
            try {
              const object = await multipartUpload.complete(completeBody.parts);
              return new Response(null, {
                headers: {
                  etag: object.httpEtag,
                },
              });
            } catch (error: any) {
              return new Response(error.message, { status: 400 });
            }
          }
          default:
            return new Response(`Unknown action ${action} for POST`, {
              status: 400,
            });
        }
      case "PUT":
        switch (action) {
          case "mpu-uploadpart": {
            const uploadId = url.searchParams.get("uploadId");
            const partNumberString = url.searchParams.get("partNumber");
            if (partNumberString === null || uploadId === null) {
              return new Response("Missing partNumber or uploadId", {
                status: 400,
              });
            }
            if (request.body === null) {
              return new Response("Missing request body", { status: 400 });
            }

            const partNumber = parseInt(partNumberString);
            const multipartUpload = env.MY_BUCKET.resumeMultipartUpload(
              key,
              uploadId
            );
            try {
              const uploadedPart: R2UploadedPart =
                await multipartUpload.uploadPart(partNumber, request.body);
              return new Response(JSON.stringify(uploadedPart));
            } catch (error: any) {
              return new Response(error.message, { status: 400 });
            }
          }
          default:
            return new Response(`Unknown action ${action} for PUT`, {
              status: 400,
            });
        }
      case "GET":
        if (action !== "get") {
          return new Response(`Unknown action ${action} for GET`, {
            status: 400,
          });
        }
        const object = await env.MY_BUCKET.get(key);
        if (object === null) {
          return new Response("Object Not Found", { status: 404 });
        }
        const headers = new Headers();
        object.writeHttpMetadata(headers);
        headers.set("etag", object.httpEtag);
        return new Response(object.body, { headers });
      case "DELETE":
        switch (action) {
          case "mpu-abort": {
            const uploadId = url.searchParams.get("uploadId");
            if (uploadId === null) {
              return new Response("Missing uploadId", { status: 400 });
            }
            const multipartUpload = env.MY_BUCKET.resumeMultipartUpload(
              key,
              uploadId
            );

            try {
              multipartUpload.abort();
            } catch (error: any) {
              return new Response(error.message, { status: 400 });
            }
            return new Response(null, { status: 204 });
          }
          case "delete": {
            await env.MY_BUCKET.delete(key);
            return new Response(null, { status: 204 });
          }
          default:
            return new Response(`Unknown action ${action} for DELETE`, {
              status: 400,
            });
        }
      default:
        return new Response("Method Not Allowed", {
          status: 405,
          headers: { Allow: "PUT, POST, GET, DELETE" },
        });
    }
  },
} satisfies ExportedHandler<Env>;
```

위의 코드로 작업자를 업데이트 한 후, 실행`npx wrangler deploy`.

이제는 복수의 업로드를 수행하기 위해이 노동자를 사용할 수 있습니다. 기존 애플리케이션에서 이 Worker에 요청을 보내거나 이 Worker를 통해 파일을 업로드할 수 있는 스크립트를 사용할 수 있습니다.

다음 섹션은 선택 사항이며 작업자에게 선택된 파일을 업로드하는 Python 스크립트의 예를 보여줍니다.

## 작업자 (선택 사항)로 복수 업로드

이 예제 응용 프로그램은 여러 부분에서 작업자에게 로컬 파일을 업로드합니다. 그것은 Python의 붙박이를 사용합니다`ThreadPoolExecutor`업로드 속도를 높이는 작업자에게 부품의 업로드를 평행시킵니다. Worker에 HTTP 요청은[이름 \*](https://pypi.org/project/requests/)도서관.

이 방법으로 멀티 파트 API를 활용하면 작업자를 사용하여 파일을 더 크게 업로드 할 수 있습니다.[Workers 요청 신체 크기 제한](/workers/platform/limits#request-limits). 개별 부품의 업로드는 여전히 이 한계에 따라 달라질 수 있습니다.

이름의 파일에 다음 코드를 저장`mpuscript.py`당신의 국부적으로 기계에. 수정하기`worker_endpoint variable`당신의 노동자가 배치되는 곳에. 이 스크립트를 실행할 때 인수로 업로드하려는 파일을 전달하십시오.`python3 mpuscript.py myfile`. 이 파일을 업로드`myfile`당신의 기계에서 노동자를 통해서 당신의 물통에.

```python
import math
import os
import requests
from requests.adapters import HTTPAdapter, Retry
import sys
import concurrent.futures

#파일로 업로드하기
filename = sys.argv[1]
#우리의 노동자를위한 엔드 포인트, 당신이 노동자를 배치하는 곳을 변경
worker_endpoint = "https://myworker.myzone.workers.dev/"
#부분 크기를 10MB로 구성합니다. 5MB는 마지막 부분을 제외하고 최소 부분 크기입니다.
partsize = 10 * 1024 * 1024


def upload_file(worker_endpoint, filename, partsize):
    url = f"{worker_endpoint}{filename}"

    #Multipart 업로드
    uploadId = requests.post(url, params={"action": "mpu-create"}).json()["uploadId"]

    part_count = math.ceil(os.stat(filename).st_size / partsize)
    #최대 25개의 동시 업로드를 위한 executor를 만듭니다.
    executor = concurrent.futures.ThreadPoolExecutor(25)
    #각 부분을 업로드하기 위해 executor에 작업 제출
    futures = [
        executor.submit(upload_part, filename, partsize, url, uploadId, index)
        for index in range(part_count)
    ]
    concurrent.futures.wait(futures)
    #미래에서 부품을 얻을
    uploaded_parts = [future.result() for future in futures]

    #multipart 업로드 완료
    response = requests.post(
        url,
        params={"action": "mpu-complete", "uploadId": uploadId},
        json={"parts": uploaded_parts},
    )
    if response.status_code == 200:
        print("🎉 successfully completed multipart upload")
    else:
        print(response.text)


def upload_part(filename, partsize, url, uploadId, index):
    #rb 모드에서 파일을 엽니 다, utf-8에 시도하는 것보다 원시 바이트로 치료
    with open(filename, "rb") as file:
        file.seek(partsize * index)
        part = file.read(partsize)

    #부품 업로드시 Retry 정책이 실패합니다.
    s = requests.Session()
    retries = Retry(total=3, status_forcelist=[400, 500, 502, 503, 504])
    s.mount("https://", HTTPAdapter(max_retries=retries))

    return s.put(
        url,
        params={
            "action": "mpu-uploadpart",
            "uploadId": uploadId,
            "partNumber": str(index + 1),
        },
        data=part,
    ).json()


upload_file(worker_endpoint, filename, partsize)
```

## 국가 관리

multipart uploads의 본질은 쉽게 Workers의 사용 모델에지도하지 않습니다. 정상적인 multipart 올려주기에서는, multipart 올려주기는 클라이언트 신청의 1개의 지속적인 실행에서 보통 실행됩니다. 이것은 노동자의 여러 발명품에 종종 완료 될 노동자의 멀티 파트 업로드와 다릅니다. 이것은 국가 관리 더 도전합니다.

이를 극복하기 위해 multipart 업로드와 관련된 국가, 즉`uploadId`업로드 된 부품은 노동자 밖에 어딘가의 트랙을 유지해야합니다.

이 가이드에 설명 된 예 노동자 및 Python 응용 프로그램에서 멀티 파트 업로드의 상태는 각 요청에 포함 된 필요한 상태와 함께 노동자에 요청을 보내는 클라이언트 응용 프로그램에 추적됩니다. 클라이언트 애플리케이션의 multipart 상태의 유지 트랙은 최대의 유연성을 가능하게하고 각 부분의 병렬 및 무상화 된 업로드를 허용합니다.

클라이언트의이 상태의 추적을 유지하면, 대안 디자인은 고려 될 수있다. 예를 들면, 당신은 추적할 수 있었습니다`uploadId`그리고 그 부속은 튼튼한 목표 또는 다른 데이타베이스에서 업로드되었습니다.
