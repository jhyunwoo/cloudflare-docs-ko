R2는 기본적인 S3 API의 정상에 몇몇 연장을 실행합니다. 이 페이지는 이러한 추가 기능, 사용 가능한 기능을 설명합니다. 이 페이지에 설명 된 기능 중 일부는 사용자 정의 헤더를 설정해야합니다. 그렇게 할 수있는 방법에 대한 예제, 참조[사용자 정의 헤더 구성](/r2/examples/aws/custom-header).

## Unicode를 사용하여 확장 된 메타 데이터

더 보기[Workers R2 API](/r2/api/workers/workers-api-reference/)추가 인코딩 또는 디코딩을 요구하지 않고 기본적으로 키와 값의 유니코드를 지원합니다.`customMetadata`이름 \* 이 필드 맵`x-amz-meta-`- R2 S3-compatible API 엔드포인트 안에 사용된 예비적인 우두머리.

HTTP 헤더 이름과 값은 유니코드 문자 라이브러리의 작은 하위 설정인 ASCII 문자만 포함될 수 있습니다. 쉽게 사용자를 수용하려면 R2는 준수[RFC 2047년](https://datatracker.ietf.org/doc/html/rfc2047)그리고 자동적으로 모든 것을 삭제합니다`x-amz-meta-*`저장하기 전에 헤더 값. retrieval에, unicode를 가진 어떤 metadata 가치는 응답을 렌더링하기 전에 RFC 2047 암호로 고쳐. 메타데이터 값의 길이 제한은 디코딩 유니코드 값에 적용됩니다.

:::카ution\[메타데이터 가변]

Workers 및 S3 API 엔드포인트를 사용하여 동일한 데이터를 액세스 할 때 마음에 들지 마십시오. R2 메타데이터 키가 유니코드를 포함하면 S3 API 및 S3 API를 통해 액세스 할 때 스트립화됩니다.`x-amz-missing-meta`헤더는 omitted 키의 숫자로 설정된다.
주요 특징

이 헤더 맵`httpMetadata`현장에[R2 바인딩](/workers/runtime-apis/bindings/):

| HTTP 헤더               | 재산 이름                             |
| --------------------- | --------------------------------- |
| `Content-Encoding`    | `httpMetadata.contentEncoding`    |
| `Content-Type`        | `httpMetadata.contentType`        |
| `Content-Language`    | `httpMetadata.contentLanguage`    |
| `Content-Disposition` | `httpMetadata.contentDisposition` |
| `Cache-Control`       | `httpMetadata.cacheControl`       |
| `Expires`             | `httpMetadata.expires`            |
|                       |                                   |

오브젝트 키 이름에서 Unicode를 사용하는 경우, 참조[Unicode 상호 운용성](/r2/reference/unicode-interoperability/).

## Auto-creating Buckets를 업로드

수요에 버킷을 만들면 대상 버킷이 존재하는 가정과 함께 업로드 할 수 있습니다. 이 상황에서, 당신이받은 경우`NoSuchBucket`오류, 아마 문제`CreateBucket`가동. 그러나이 접근법에 따라 문제가 발생할 수 있습니다. 신체가 이미 부분적으로 소비 된 경우 업로드는 낙태해야합니다. 이 문제점에 일반적인 해결책은, 다른 목표 저장 공급자에 의해, 이용하기 위한 것입니다[HTTP: HTTP`100`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status/100)몸이 전송되는지 여부를 감지하는 응답, 또는 물통이 업로드를 복원하기 전에 생성되어야하는 경우. 그러나, Cloudflare는 HTTP를 지원하지 않습니다`100`응답. HTTP의 경우`100`응답은 지원되었습니다, 당신은 아직도 관여된 둥근 여행 때문에 추가 대기 시간이 있을 것입니다.

스트리밍 바디로 업로드를 지원하려면 아직 존재하지 않을 수 있는 버킷으로 업로드 작업`PutObject`또는`CreateMultipartUpload`헤더를 지정할 수 있습니다.`NoSuchBucket`오류가 반환되지 않습니다. 물통이 업로드 당시 존재하지 않는 경우, 다음과 같이 즉시 복제됩니다.`CreateBucket`요구 사항:

```txt
PUT / HTTP/1.1
Host: bucket.account.r2.cloudflarestorage.com
<CreateBucketConfiguration xmlns="http://s3.amazonaws.com/doc/2006-03-01/">
   <LocationConstraint>auto</LocationConstraint>
</CreateBucketConfiguration>
```

이것은 당신이 양동이의 이름을 모르는 때문에 수요에 물통을 창조하는 경우에만 유용합니다 또는 시간의 앞에 선호한 접근 위치. 예를 들어, 고객 중 하나당 1개의 버킷이 있고 버킷은 버킷에 첫 번째 업로드에 생성되어 계정 등록 중에 없습니다. 이 경우,[`ListBuckets`이름 \*](#listbuckets)1,000개 이상의 물통을 가진 계정을 지원하는 , 또한 유용할지도 모릅니다.

## 팟캐스트

### 상태 작업`PutObject`

`PutObject`지원하다[상태 업로드](https://developer.mozilla.org/en-US/docs/Web/HTTP/Conditional_requests)을 통해[`If-Match`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/If-Match), [`If-None-Match`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/If-None-Match), [`If-Modified-Since`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/If-Modified-Since)·[`If-Unmodified-Since`](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/If-Unmodified-Since)머리. 이 헤더는 원인`PutObject`rejected에 가동`412 PreconditionFailed`지정된 조건과 일치하지 않는 객체의 선행 상태일 때 오류 코드.

## 비밀번호

### MERGE 메타데이터 지시어

더 보기`x-amz-metadata-directive`지원하다`MERGE`값, 표준 이외에`COPY`·`REPLACE`옵션. 사용될 때,`MERGE`의 조합은`COPY`·`REPLACE`, 어느 것`COPY`소스 객체의 모든 메타 데이터 키와`REPLACE`새 값과 요청에 지정되는 것들. 사용할 수 없습니다.`MERGE`소스에서 기존 메타데이터 키를 제거하기 위해 — use`REPLACE`대신.

## `ListBuckets`

`ListBuckets`모든 동일한 검색 매개 변수를 지원`ListObjectsV2`일부 고객이 1,000 개 이상의 물통을 가질 수 있기 때문에 R2XQ에서. 도구로 만들기 때문에 기존 S3 라이브러리와 마찬가지로 이러한 검색 매개 변수를 설정하는 방법을 노출 할 수 없습니다. 이러한 값은 헤더를 통해 전송 될 수도 있습니다. headers의 값은 검색 매개 변수에 대해 우선합니다.

| 검색 매개 변수             | HTTP 헤더                 | 이름 \*                                       |
| -------------------- | ----------------------- | ------------------------------------------- |
| `prefix`             | `cf-prefix`             | 이 접두사를 가진 물통을 보여주십시오.                       |
| `start-after`        | `cf-start-after`        | 이름이 계정에서 lexicographically 나타나는 물통을 보여주십시오. |
| `continuation-token` | `cf-continuation-token` | 이전에 반환 된 continuation 토큰에서 목록.              |

### 상태 작업`CopyObject`대상 객체의 경우

:::참조

이 기능은 현재 베타입니다. 피드백이 있다면, 우리에게 연락[Cloudflare 개발자 Discord](https://discord.cloudflare.com)#r2-storage 채널에서 스레드를 열거나[커뮤니티 포럼](https://community.cloudflare.com/c/developers/storage/81).
:::

`CopyObject`이미 소스 객체에 의존하는 조건을 지원합니다.`x-amz-copy-source-if-...`S3 API 준수의 일부로 우두머리. 이 외에도 R2는 R2의 특정 세트를 지원합니다.`CopyObject`대상 객체의 상태일 수 있는 작업:

- `cf-copy-destination-if-match`
- `cf-copy-destination-if-none-match`
- `cf-copy-destination-if-modified-since`
- `cf-copy-destination-if-unmodified-since`

이 우두머리는 유사한 지명한 상태 우두머리에 akin를 일합니다`PutObject`. 지정된 조건과 일치하지 않는 대상 객체의 우선 상태일 때`CopyObject`가동은 rejected`412 PreconditionFailed`오류 코드.

#### 비분명 관계`x-amz-copy-source-if`

더 보기`x-amz-copy-source-if-...`헤더는 복사 작업에 대한 소스 객체가 선택될 때 체크해야 하며,`cf-copy-destination-if-...`headers는 개체가 물통 상태에 투입될 때 검사될 것입니다.
그러나, 소스 객체가 복사를 위해 선택되고, 목적지 객체가 물통 상태에 투입되면 시간에 포인트는 반드시 동일하지 않습니다. 즉,`cf-copy-destination-if-...`헤더는 관계에서 원자가 아닙니다.`x-amz-copy-source-if...`머리.
