Rclone는 클라우드 스토리지에서 파일을 관리하는 명령줄 도구입니다. 당신은 R2 concurrently에 개체를 업로드하기 위해 혼자를 사용할 수 있습니다.

## rclone 구성

이름 \*[`rclone`](https://rclone.org/install/)설치, 실행할 수 있습니다[`rclone config`](https://rclone.org/s3/)새로운 S3 스토리지 공급자를 구성합니다. 당신은 새로운 공급자 세부사항을 위한 질문의 시리즈로 신속한 할 것입니다.

:::주최\[추천]
그것은 당신이 독특한 공급자 이름을 선택 하 고 그 다음 신속 하 게 모든 기본 답변에 의존 하는 것이 좋습니다.

이것은 만들 것입니다`rclone`구성 파일, 다음 아래에 주어진 preset 구성으로 수정할 수 있습니다.
주요 특징

<Steps>
  1. 선택하여 새로운 리모트 만들기`n`.
  2. 새로운 리모트의 이름을 선택하십시오. 예를 들어, 사용`r2`.
  3. 선택하기`Amazon S3 Compliant Storage Providers`저장 유형.
  4. 제품정보`Cloudflare R2 storage`회사 소개
  5. AWS credentials를 수동으로 입력하고 싶을지 여부를 선택하거나 런타임 환경에서 얻을 수 있습니다.
  6. AWS 액세스 키 ID를 입력하십시오.
  7. AWS 비밀 액세스 키 입력 (password).
  8. (선택 사항)에 연결하는 지역을 선택하십시오.
  9. S3 API 엔드포인트를 선택하십시오.
</Steps>

:::참조
실행 중`rclone`v1.59 이상 ([rclone 다운로드](https://beta.rclone.org/)). v1.59 이전에 버전이 반환될 수 있습니다.`HTTP 401: Unauthorized`오류, 이전 버전의`rclone`모든 경우에 S3 명세에 엄격히 일치하지 마십시오.
주요 특징

### 기존 rclone 구성 편집

이미 설정한 경우`rclone`과거에, 당신은 실행할 수 있습니다`rclone config file`당신의 위치 인쇄하기`rclone`구성 파일:

```sh
rclone config file
#구성 파일에 저장됩니다:
#~/.config/rclone/rclone.conf 설정
```

그런 다음 편집기를 사용하십시오 (`nano`또는`vim`, 예를 들면) 추가하거나 새로운 공급자를 편집합니다. 이 예제는 새로운 것을 가정`r2`공급자:

```toml
[r2]
type = s3
provider = Cloudflare
access_key_id = abc123
secret_access_key = xyz456
endpoint = https://<accountid>.r2.cloudflarestorage.com
acl = private
```

:::참조

토큰을 사용하는 경우[Object-level 권한](/r2/api/tokens/#permissions), 당신은 추가해야 할 것입니다`no_check_bucket = true`오류를 방지하기 위해 구성.
주요 특징

새로운 것을 사용할 수 있습니다.`rclone`정상적인 작업 흐름을 위한 공급자.

## 물통 & 물체 목록

더 보기[rclone 나무](https://rclone.org/commands/rclone_tree/)명령은 리모트의 내용을 목록으로 만들 수 있습니다, 이 경우 Cloudflare R2.

```sh
rclone tree r2:
#·
#├── 사용자 업로드
#파일 형식
#└─ my-bucket 이름
#다운로드
#todos.txt에 대해

rclone tree r2:my-bucket-name
#·
#다운로드
#todos.txt에 대해
```

## 업로드 및 검색 개체

더 보기[rclone 사본](https://rclone.org/commands/rclone_copy/)명령은 R2 Bucket 및 vice versa에 오브젝트를 업로드하는 데 사용할 수 있습니다 - 이것은 R2 지원되는 5 TB 최대 객체 크기까지 파일을 업로드 할 수 있습니다.

```sh
#개.txt를 사용자 업로드 버킷
rclone copy dog.txt r2:user-uploads/
rclone tree r2:user-uploads
#·
#파일 형식
#└ - 개.txt

#사용자 업로드 버킷에서 dog.txt 다운로드
rclone copy r2:user-uploads/dog.txt .
```

### multipart 업로드 부분 크기에 대한 메모

multipart uploads의 경우, 부품 크기가 크게 사용 된 클래스 A 작업의 수에 영향을 미칠 수 있습니다, 이는 얼마나 많은 충전 될 수 있습니다.
모든 부품 업로드는 별도의 작업으로 계산되므로 더 큰 부품 크기는 몇 가지 작업을 사용할 수 있지만 업로드가 실패한 경우 재발 할 수 있습니다. 또한 multipart 업로드는 항상 단일로 적어도 3 번을 소비하려고 고려`PutObject`적어도 1을 포함하기 때문에`CreateMultipartUpload`, `UploadPart` & `CompleteMultipartUpload`작업.

Balancing 부품 크기는 사용 사례에 크게 의존하지만, 이러한 요소는 청구서를 최소화 할 수 있으므로 고려해야 할 가치가 있습니다.

rclone의 multipart 업로드 부분 크기를 구성할 수 있습니다.`--s3-chunk-size`CLI 인수. 또한 조정해야 할 수도 있음`--s3-upload-cutoff`rclone가 multipart uploads을 사용하는 것을 보장하는 인수. 둘 다 구성 파일에서 설정할 수 있습니다. 일반적으로,`--s3-upload-cutoff`보다 더 적은`--s3-chunk-size`.

```sh
rclone copy long-video.mp4 r2:user-uploads/ --s3-upload-cutoff=100M --s3-chunk-size=100M
```

## 사전 서명된 URL 생성

당신은 또한 당신이 일시적으로 파일을 공유 할 수있는 사전 서명 된 링크 생성 할 수 있습니다[rclone 링크](https://rclone.org/commands/rclone_link/)명령.

```sh
#--expire 플래그를 전달할 수 있습니다. --unlink 플래그는 R2에 의해 지원되지 않습니다.
rclone link r2:my-bucket-name/cat.png --expire 3600
#모델 번호: https://<accountid>.r2.cloudflarestorage.com/my-bucket-name/cat.png?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Credential=<credential>&X-Amz-Date=<timestamp>&X-Amz-Expires=3600&X-Amz-SignedHeaders=host&X-Amz-Signature=<signature>
```
