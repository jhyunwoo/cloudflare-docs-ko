주요 특징

R2 Data Catalog는 관리[아파치 Iceberg](https://iceberg.apache.org/)R2 버킷에 직접 내장 된 데이터 카탈로그. 그것은 표준 Iceberg REST 카탈로그 인터페이스를 노출, 그래서 당신은 이미 사용하는 엔진을 연결할 수 있습니다[스파크](/r2/data-catalog/config-examples/spark-scala/), [스노우레이크](/r2/data-catalog/config-examples/snowflake/)·[프로젝트](/r2/data-catalog/config-examples/pyiceberg/).

R2 데이터 카탈로그는 로그 분석, 비즈니스 인텔리전스 및 데이터 파이프라인을 포함한 다양한 분석 워크로드에 대한 데이터 창고 또는 호수에 R2 버킷을 쉽게 설정할 수 있습니다. R2의 Zero-egress 수수료 모델은 데이터 사용자 및 소비자가 다른 클라우드, 데이터 플랫폼 또는 지역으로부터 데이터를 액세스 및 분석 할 수 있음을 의미합니다.

## Apache Iceberg는 무엇입니까?

[아파치 Iceberg](https://iceberg.apache.org/)Object Storage에 저장되는 대규모 분석 데이터셋을 처리하도록 설계된 오픈 테이블 형식입니다. 주요 특징은 다음을 포함합니다:

- ACID 거래 - 신뢰할 수있는, 동시 읽음 및 전체 데이터 무결성로 작성합니다.
- 최적화 된 메타 데이터 - 빠른 쿼리에 대한 색인 된 메타 데이터를 사용하여 비용으로 전체 테이블 검사를 피합니다.
- Full schema 진화 - 데이터를 rewriting 없이 추가, 복제, 삭제할 수 있습니다.

Iceberg는 이미[널리 지원](https://iceberg.apache.org/vendors/)Apache Spark, Trino, Snowflake, DuckDB 및 ClickHouse와 같은 엔진으로 빠르게 성장하는 커뮤니티가 있습니다.

## 왜 데이터 카탈로그가 필요합니까?

Iceberg 데이터와 metadata 파일이 객체 저장소에서 직접 살고 있지만 (like)[모델 번호: R2](https://developers.cloudflare.com/r2/)), 테이블과 포인터의 목록은 현재 메타데이터가 데이터 카탈로그에 의해 중앙으로 추적되어야 합니다.

데이터 카탈로그를 라이브러리의 색인 시스템으로 생각하십시오. 책 (당신의 자료)는 물리적으로 선반 (보통 저장)에 걸쳐 배포, 인덱스는 어떤 책 존재, 그들의 위치 및 최신 버전에 대한 진실의 단일 소스를 제공합니다. 이 색인 없이, 독자 (query 엔진)는 책을 검색하는 시간을 낭비할 것입니다, outdated 버전에 접근할지도 모릅니다, 또는 그(것)들을 unfindable 만드는 방법에 있는 실수로 shelve 새로운 책.

마찬가지로, 데이터 카탈로그는 일관성 있고, 여러 쿼리 엔진을 안전하게 읽고 충돌이나 데이터 손상없이 동일한 테이블에 쓰기 할 수 있습니다.
