Super Slurper와 Sippy의 조합을 사용하여 최소한의 다운타임으로 모든 객체를 효과적으로 마이그레이션할 수 있습니다.

### 소스 버킷이 적극적으로 읽기 / 쓰기

1. Sippy를 사용 하 여 시작 R2 물통 당신의 응용 프로그램에.
   - 이전 버킷에서 R2 버킷에서 응용 프로그램에 의해 요청 될 때이 사본 개체.
   - 새로운 업로드는 R2 버킷으로 이동합니다.
2. Super Slurper를 사용하여 R2 버킷에 남아있는 개체를 복사하기 위해 One-off 마이그레이션을 트리거하십시오.
   - 내 계정**목적지 R2 물통** > **파일을 덮어?**, 선택 "Skip 기존".

### 소스 버킷이 자주 읽지 않을 때

1. R2 물통에 모든 목표를 복사하기 위해 슈퍼 슬러퍼를 사용합니다.
   - Super Slurper가 복사 한 개체를 나열한 후 업로드 된 경우 일부 개체를 건너 뛸 수 있습니다.
2. R2 물통에 Sippy를 사용하골, 그 후에 당신의 신청에 있는 R2Q 물통을 사용하여 시작하십시오.
   - 새로운 업로드는 R2 버킷으로 이동합니다.
   - Super Slurper를 복사하는 동안 업로드 된 개체는 응용 프로그램에 의해 요청 될 때 대상 (Sippy)에 복사됩니다.

### Slurper 데이터 마이그레이션 성능 최적화

계정의 경우 주어진 시간에 세 개의 동시 Slurper 마이그레이션 작업을 실행할 수 있으며, 각 Slurper 마이그레이션 작업은 초당 요청의 설정 금액을 처리 할 수 있습니다.

전반적인 처리량과 신뢰성을 증가시키기 위해, 우리는 당신의 이동을 더 작게 나누기를 추천합니다, 접두사 (또는 물통 subpath) 선택권을 사용하여 동시 일.

마이그레이션 작업을 만들 때:

1. 오시는 길**소스 버킷**단계.
2. 이름 \***정의 규칙**, 에서**물통 subpath**, prefix에 의해 데이터를 분할하는 subpaths를 지정합니다.
3. 데이터 마이그레이션 설정 완료.

예를 들어 소스 버킷을 공급합니다.

<FileTree>
  - 이름 \*
    - 2024
      - 파일1.jpg
      - 파일2.jpg
    - 2023
      - 파일3.jpg
    - 2019
      - 파일4.jpg
</FileTree>

다음과 같은 접두사를 가진 별도의 작업을 만들 수 있습니다:

- `/photos/2024`모든 2024 파일을 마이그레이션
- `/photos/202`2023 및 2024의 모든 파일을 마이그레이션

각 접두사는 독립적 인 마이그레이션 작업으로 실행되며 Slurper가 병렬로 데이터를 전송할 수 있습니다. 이것은 총 이동 속도를 개량하고 1개의 일에 있는 실패는 다른 사람을 방해하지 않습니다.
