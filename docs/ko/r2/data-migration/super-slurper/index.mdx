Super Slurper는 다른 클라우드 제공 업체에서 R2 버킷까지 신속하게 물건을 복사 할 수 있습니다.

마이그레이션 작업:

- R2에 migrated 개체에 복사하여 소스 버킷에서 사용자 정의 객체 메타 데이터를 보존합니다.
- 소스 버킷에서 어떤 개체를 삭제하지 마십시오.
- TLS 암호화를 사용하여 안전한 개인 객체 전송을 위해 HTTPS 연결.

## Super Slurper를 사용할 때

Super Slurper를 사용하여 전략의 일부로 클라우드 스토리지 버킷이 1 TB 미만으로 구성되는 경우 좋은 선택입니다. 1 TB보다 더 큰 개체는 건너뛰고 별도로 복사해야합니다.

위의 기준을 충족하지 않는 이전 사용 사례를 들어, 우리는 같은 도구를 사용하는 것이 좋습니다[뚱 베어](/r2/examples/rclone/).

## R2에 데이터를 마이그레이션하는 Super Slurper 사용

1. Cloudflare dashboard에서, 가십시오**R2 데이터 마이그레이션**사이트 맵

   <DashButton url="/?to=/:account/r2/slurper" />
2. 제품정보**Migrate 파일**.
3. 소스 클라우드 스토리지 공급자를 선택하면 데이터를 마이그레이션할 수 있습니다.
4. 소스 버킷 이름 및 관련 자격 증명 및 선택 입력**이름 \***.
5. R2 버킷 이름과 관련된 자격 증명을 입력하고 선택**이름 \***.
6. 마이그레이션의 세부 사항을 검토 한 후, 선택**Migrate 파일**.

마이그레이션을 선택할 때 언제든지 마이그레이션 작업을 확인할 수 있습니다.**데이터 마이그레이션**사이트 맵

### 소스 버킷 옵션

#### (선택) 물통 잠수함

이 설정은 개체가 복사 될 소스 버킷 내의 접두사를 지정합니다.

### 대상 R2 버킷 옵션

#### 파일을 덮어?

이 설정은 R2 버킷의 기존 객체의 경로와 일치하는 소스 저장 버킷에서 복사되는 객체가 일어나는 것을 결정합니다. 두 가지 옵션이 있습니다:

- (기본값)
- 팟캐스트

## 클라우드 스토리지 제공

Cloudflare는 현재 뒤에 오는 구름 목표 저장 공급자에서 R2에 자료 복사를 지원합니다:

- 아마존 S3
- Cloudflare R2
- Google 클라우드 스토리지 (GCS)
- 모든 S3- 호환 스토리지 제공 업체

### S3 호환 스토리지 제공 업체 테스트

뒤에 오는 S3-compatible 저장 공급자는 Super Slurper와 일하기 위하여 시험되고 확인되었습니다:

- 백조 B2
- DigitalOcean 공간
- Scaleway 개체 저장
- Wasabi Cloud 개체 저장

Super Slurper는 모든 S3-compatible 스토리지 제공 업체에서 전송을 지원해야하지만 나열된 것들은 명시적으로 테스트되었습니다.

## 저장 공급자를 위한 credentials 만들기

### 아마존 S3

Amazon S3의 개체를 복사하려면 Super Slurper는 S3 버킷에 액세스 권한을 요구합니다. AWS Identity 및 Access Management (IAM) 사용자 자격 증명을 올바른 권한으로 사용할 수 있지만, CloudflareXQXQ는 사용자가 좁은 권한으로 만들 것을 권장합니다.

올바른 권한을 가진 자격 증명을 만들려면:

1. AWS IAM 계정으로 로그인하세요.
2. 다음 형식으로 정책을 작성하고 교체하십시오.`<BUCKET_NAME>`에 액세스 권한을 부여하고 싶은 물통:

```json
{
	"Version": "2012-10-17",
	"Statement": [
		{
			"Effect": "Allow",
			"Action": ["s3:Get*", "s3:List*"],
			"Resource": ["arn:aws:s3:::<BUCKET_NAME>", "arn:aws:s3:::<BUCKET_NAME>/*"]
		}
	]
}
```

3. 새로운 사용자를 만들고 만든 정책을 사용자에 첨부합니다.

이제 소스 버킷을 정의 할 때 Access Key ID 및 Secret Access Key를 모두 사용할 수 있습니다.

### Google 클라우드 스토리지

Google Cloud Storage (GCS)에서 개체를 복사하려면 Super Slurper는 GCS 버킷에 액세스 권한을 요구합니다. Google Cloud predefined를 사용할 수 있습니다.`Storage Admin`역할, 그러나 Cloudflare는 허가의 더 좁은 세트를 가진 주문 역할을 하는 것을 추천합니다.

필요한 권한을 가진 사용자 정의 역할 만들기:

1. Google Cloud 콘솔에 로그인하십시오.
2. 오시는 길**IAM 및 관리자** > **제품정보**.
3. 자주 묻는 질문`Storage Object Viewer`역할 및 선택**이 역할에서 역할 만들기**.
4. 이름의 새로운 역할을합니다.
5. 제품정보**자주 묻는 질문**그리고 추가`storage.buckets.get`이름 \*
6. 제품정보**이름 \***.

사용자 정의 역할로 자격 증명을 만들려면:

1. Google Cloud 콘솔에 로그인하십시오.
2. 오시는 길**IAM 및 관리자** > **서비스 계정**.
3. 사용자 정의 역할로 서비스 계정을 만드십시오.
4. 오시는 길**주요 특징**당신이 만든 서비스 계정 탭.
5. 제품정보**키 추가** > **새로운 키 만들기**JSON 키 파일을 다운로드합니다.

Super Slurper를 사용할 때이 JSON 키 파일을 사용할 수 있습니다.

### Archive 저장 교실

AWS S3로 저장되는 목표[아카이브 스토리지 클래스](https://aws.amazon.com/s3/storage-classes/#Archive)별도의 복사 및 복사가 필요합니다. 특정한:

- S3 Glacier tiers (Gigcier Instant Retrieval 포함되지 않음)를 사용하여 저장 된 파일이 이동 로그에 기록됩니다.
- S3 Intelligent Tiering을 사용하여 저장 된 파일과 Deep Archive tier에 배치하면 마이그레이션 로그에 기록됩니다.
