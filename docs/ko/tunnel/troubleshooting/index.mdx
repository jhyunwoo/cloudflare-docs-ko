## 연결 오류

시간 :`cloudflared`Cloudflare 네트워크에 도달 할 수 없습니다, 그것은[로그아웃](/tunnel/monitoring/#logs)문제가 DNS 해상도, QUIC (UDP) 또는 TCP 연결을 나타내는 특정 오류 메시지.

### DNS 해결책 실패

#### `edge discovery: error looking up Cloudflare edge IPs`

```txt
ERR edge discovery: error looking up Cloudflare edge IPs: the DNS query failed
    error="lookup _v2-origintunneld._tcp.argotunnel.com on 172.19.64.1:53: no such host"
```

이 오류는 기계에 구성 된 DNS 해결자는 SRV 레코드를 해결할 수 없습니다.`cloudflared`자주 묻는 질문[모델 번호: Cloudflare 터널 대상 IP](/tunnel/configuration/#firewall-rules). 일반적인 원인은 SRV 레코드를 스트립 또는 블록하는 기업 DNS 해커 및 압축 SRV 레코드를 반환 DNS 해커를 포함한다.

**진단하기:**

에 의해`cloudflared`주인 기계, 뛰기:

```sh
dig SRV _v2-origintunneld._tcp.argotunnel.com
```

자주 묻는 질문`SERVFAIL`, `NXDOMAIN`, 또는 빈 대답, Cloudflare의 공중 결실에 대하여 시험:

```sh
dig SRV _v2-origintunneld._tcp.argotunnel.com @1.1.1.1
```

**해결하기:**

- 이름 \*`1.1.1.1`결과를 반환하지만 로컬 해설자는 사용하지 않습니다, 호스트를 구성[Cloudflare DNS (1.1.1.1)](/1.1.1.1/setup/)또는 또 다른 공개적인 해결자.
- 결과를 반환하지 않는 경우, 방화벽은 아웃바운드 DNS 쿼리를 차단할 가능성이 있습니다 (UDP 포트`53`). 네트워크 관리자와 함께 DNS 트래픽을 허용.

#### `DNS query failed ... i/o timeout`

```txt {3}
ERR edge discovery: error looking up Cloudflare edge IPs: the DNS query failed
    error="lookup _v2-origintunneld._tcp.argotunnel.com on 127.0.0.11:53:
    read udp 127.0.0.1:53467->127.0.0.11:53: i/o timeout"
```

이 변형은 DNS 쿼리를 의미합니다.`cloudflared`차단되거나 완전히 떨어졌다 - 해결자는 결코 응답하지 않습니다. 내부 DNS 해결자 (Docker, Kubernetes)의 컨테이너 환경에서는 일반적입니다.`127.0.0.11`)는 unachable 또는 misconfigured입니다.

**해결하기:**

- Docker에서 컨테이너의 DNS 구성을 확인합니다 (`/etc/resolv.conf`). 해결자를 무시할 수 있습니다.`--dns 1.1.1.1`컨테이너를 실행할 때.
- 쿠버네티스에서는`kube-dns`또는`CoreDNS`서비스는 pod에서 실행되고 접근 가능합니다.
- 에 의해`cloudflared`호스트는 해결자가 나열된 것을 확인합니다.`/etc/resolv.conf`답변 및 답변

### QUIC 핸즈크 타임아웃

#### `Failed to dial a quic connection`

```txt
ERR Failed to dial a quic connection error="failed to dial to edge with quic:
    timeout: handshake did not complete in time" connIndex=0 ip=198.41.192.227
INF Retrying connection in up to 2s connIndex=0 ip=198.41.192.227
```

이 오류는`cloudflared`해결하기[모델 번호: Cloudflare 터널 대상 IP](/tunnel/configuration/#firewall-rules)그러나 UDP 항구에 QUIC Handhake를 완료할 수 없습니다`7844`. 네트워크 또는 방화벽은 CloudflareXQ에 아웃바운드 UDP 트래픽을 차단하고 있습니다.

`cloudflared`exponential 백오프 (2, 4, 8, 16, 32, 64 초까지)를 가진 화물. retries를 배출 한 후 TCP에서 HTTP / 2로 돌아갑니다.

```txt
INF Switching to fallback protocol http2 connIndex=0
```

가을이 실패하면, 당신은 볼 것이다[TCP 연결 timeout](#tcp-connection-timeout)오류.

**진단하기:**

에 의해`cloudflared`host machine – 품질 협력 업체 중국에서`7844`:

```sh
nc -uvz -w 3 198.41.192.227 7844
```

기타 제품`198.41.192.227`IP와 함께[오류 메시지](#failed-to-dial-a-quic-connection). 포트가 방화벽에 의해 닫히거나 차단되면 명령이 반환됩니다.`Connection refused`또는 시간.

**해결하기:**

- 포트에 아웃바운드 UDP 트래픽 허용`7844`방화벽 또는 보안 그룹에. 더 알아보기[IP 및 포트의 전체 목록](/tunnel/configuration/#firewall-rules).
- UDP를 열 수 없는 경우,`cloudflared`TCP를 자동적으로 HTTP/2로 돌아갑니다. HTTP / 2를 강제 할 수 있습니다.`--protocol http2` [run 매개 변수](/tunnel/configuration/#run-parameters), 그러나 QUIC는 더 나은 성과를 위해 추천됩니다.

### TCP 연결 timeout

#### `DialContext error: dial tcp ... i/o timeout`

```txt
ERR Unable to establish connection with Cloudflare edge
    error="DialContext error: dial tcp 198.41.200.43:7844: i/o timeout" connIndex=0
ERR Serve tunnel error
    error="DialContext error: dial tcp 198.41.200.43:7844: i/o timeout" connIndex=0
```

이 오류는`cloudflared`TCP 포트에 Cloudflare에 도달 할 수 없습니다`7844`. 당신이 또한 볼 경우[QUIC 핸즈크 타임아웃](#failed-to-dial-a-quic-connection)위, UDP 및 TCP 모두 차단됩니다 - 터널은 모두 연결할 수 없습니다.

**진단하기:**

빠른 테스트로, 실행:

```sh
curl -v https://region1.v2.argotunnel.com:7844
```

연결이 걸린 경우, 트래픽은 호스트와 Cloudflare 사이에서 떨어질 것입니다.

시험하기`cloudflared`항구에 연결할 수 있습니다`7844`, 실행:

```sh
nc -vz -w 3 198.41.200.43 7844
```

기타 제품`198.41.200.43`IP와 함께[오류 메시지](#dialcontext-error-dial-tcp--io-timeout). 포트가 방화벽에 의해 닫히거나 차단되면 명령이 반환됩니다.`Connection refused`또는 시간.

**해결하기:**

- 포트에 아웃바운드 TCP 트래픽 허용`7844`이름 \*[모델 번호: Cloudflare 터널 IP 범위](/tunnel/configuration/#firewall-rules).
- 당신의 환경 구획 항구`7844`완전히 (UDP와 TCP), 갱도는 기능을 할 수 없습니다. 네트워크 관리자와 함께 이 포트에 아웃바운드 트래픽을 허용.
