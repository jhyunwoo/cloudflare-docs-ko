Data Localization Suite 기능을 배포할 때 일부 동굴과 제한이 있습니다.

Cloudflare는 이 제안을 개량하고 간격을 채우기 위하여 열심히 일하고 있습니다. 특정 기능 요청이있는 경우, 연락처[계정 팀](/support/contacting-cloudflare-support/).

## 핵심 관리

Geo Key Manager 또는 Keyless SSL을 사용할 때 일부 caveats가 적용될 수 있습니다.

서버에서 키 서버로의 원격 절차 호출은 핸디케이크에 대기 시간을 추가 할 수 있습니다, 연결을 느리게. 추가 대기 시간 비용은 서버에서 키 서버로의 왕복 시간에 해당합니다. 키 서버가 세계의 다른 측면에 있다면 두 번째로 될 수 있습니다. Luckily,이 대기 비용 만 서버에 연결 첫 번째 시간에 적용. Handhake가 완료되면 키 서버는 관여하지 않습니다. 또한, TLS Session Resumption와의 연결은 개인 키가 필요하지 않습니다. Hence, latency는 초기 연결에만 추가됩니다.

어떻게 작동하나요?[블로그 게시물](https://blog.cloudflare.com/geo-key-manager-how-it-works/).

## 지역 서비스

지역 서비스를 사용할 때 일부 동굴과 제한이 적용될 수 있습니다.

제품별 동굴의 경우, 참조[Cloudflare 제품 호환성](/data-localization/compatibility/)사이트 맵

다음 기능 및 프로토콜은 지역 서비스에서 지원되지 않으며 지역화 된 호스트 이름에서 작동하지 않을 수 있습니다.

- [ICMP를](https://www.cloudflare.com/learning/ddos/glossary/internet-control-message-protocol-icmp/)
- [암호화된 클라이언트 Hello (ECH)](/ssl/edge-certificates/ech/)
- [오렌지 - 오렌지 (O2O)](/cloudflare-for-platforms/cloudflare-for-saas/saas-customers/how-it-works/)
- [양파 (Tor)](/network/onion-routing/)

Regional Services는 스펙트럼을 배경으로 활용합니다.[스펙트럼 제한](/spectrum/reference/limitations/)신청하기

지역 서비스는 적용되지 않습니다.[구독하기](/workers/platform/limits/#subrequests). 지역 서비스는 호스트 이름의 IP에서 작동합니다. 자주 묻는 질문[다운로드](/learning-paths/application-security/default-traffic-security/dnssec/)및/또는[HTTPS에서 DNS](/1.1.1.1/encryption/dns-over-https/)DNS 응답이 안전하고 정확하다는 것을 보장하기 위해.

## 고객 메타데이터 경계

Metadata Boundary를 사용할 때 특정 제한 및 동굴이 있습니다.

Zone Analytics & Logs UI Tabs의 가장 구체적으로는 EU에 고객 메타데이터 경계를 구성할 때 빈으로 표시됩니다. UI를 사용하는 것이 좋습니다.[보안 Analytics](/waf/analytics/security-analytics/)대신, 또는[HTTP 요청](/logs/logpush/logpush-job/datasets/zone/http_requests/)로그를 통해[다운로드](/logs/logpush/).

고객 Metadata Boundary를 EU로 구성하려면 계정 내 모든 영역에 대한 Log Retention을 비활성화해야합니다. Log Retention는 유산 기능입니다.[로그인](/logs/logpull/).

제품별 동굴의 경우, 참조[Cloudflare 제품 호환성](/data-localization/compatibility/)사이트 맵
