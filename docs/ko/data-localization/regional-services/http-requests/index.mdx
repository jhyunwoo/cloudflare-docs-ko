Cloudflare는 세계에서 가장 큰 글로벌 anycast 네트워크 중 하나이며, 현재 모든 데이터 센터 위치는 접근 가능[네트워크 맵](https://www.cloudflare.com/network/).

Cloudflare 데이터 센터 내에서 Cloudflare 네트워크와 고객의 기원 사이에 트래픽이 암호화됩니다. 고객이 선택할 수있는 유연성이 있습니다.[암호화 모드](/ssl/origin-configuration/ssl-modes/)이름 \*[Cipher 스위트](/ssl/edge-certificates/additional-options/cipher-suites/)그들은 사용을 원한다.

또한 Cloudflare 데이터 센터 내에서 모든 요청 및 응답 처리는 인체 접근을 방지하기 위해 사용되는 기계 검사와 메모리에서 발생합니다. 고객에 의해 구성 된 캐싱 또는 캐시 규칙에 대한 자격이 된 콘텐츠를 제외하고 디스크에 기록되지 않습니다. 또한 모든 캐시 디스크는 나머지에서 암호화됩니다.

![HTTP 요청 흐름](~/assets/images/data-localization/http-requests-flow.png)

높은 수준에서 최종 사용자의 장치가 Cloudflare 데이터 센터에 연결하면 다음과 같은 방법으로 요청이 처리됩니다.

1. 사이버 공격에 사용할 수있는 특정 유형은 즉시 주소 정보를 기반으로 떨어졌다 (레이어 3 / 네트워크 층).

2. 다음으로 암호화된 요청은 고객의 선택된 비즈니스 논리를 사용하여 해독되고 검사됩니다. 예를 들어 제품 구성 규칙, WAF 사용자 정의 규칙, 제한 규칙, 다음을 포함합니다.[교통수단](https://blog.cloudflare.com/traffic-sequence-which-product-runs-first/)그리고 단계. 이 프로세스는 레이어 7 / 애플리케이션 레이어 DDoS 공격, 자동화된 봇 트래픽, 자격 증명 필링 및 SQL 주입을 포함한 다양한 종류의 사이버 공격 및 악의적 트래픽을 탐지 및 예방할 수 있습니다.

3. 검사된 요구는 그 때 캐시 단위에 통과됩니다. 캐시가 내용의 캐쉬드 사본과 요청을 수행 할 수 있다면, 그렇게; 그렇지 않다면 고객의 기원 서버에 요청을 전달합니다. Cloudflare 데이터 센터와 Origin 서버 간의 트래픽은 다른 암호화 모드를 사용하기로 결정한 경우 암호화됩니다.

4. 응답이 고객의 기원 서버에서 제공 될 때, 정적 및 자격이 된 콘텐츠는 암호화 된 디스크에 캐시됩니다. 응답은 인터넷을 통해 사용자에게 비즈니스 논리를 통해 다시 간다.

기본적으로 Cloudflare는 모든 데이터 센터에서 전 세계적으로 TLS 종료를 수행합니다. 인터넷 엔드 사용자는 Cloudflare 뒤에 웹 사이트 또는 응용 프로그램에 연결됩니다. 그러나, 고객은 처리 및 TLS 종료가 발생하는 지역 서비스를 지정할 수 있습니다.
