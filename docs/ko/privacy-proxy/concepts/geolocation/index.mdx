개인 정보 보호 프록시는 실제 IP 주소를 폭발하지 않고 사용자의 지리적 위치를 보존합니다. 개인정보를 유지하면서 위치 기반 서비스를 올바르게 수행하십시오.

## 왜 위치가 중요합니까?

많은 온라인 서비스는 IP 주소를 사용하여 사용자 위치를 결정합니다.

- 검색 엔진은 로컬 관련 결과를 반환합니다.
- 콘텐츠 제공 업체는 지역 라이센스 제한을 적용합니다.
- 전자 상거래 사이트는 지역 가격 및 배송 옵션을 보여줍니다.
- 뉴스 사이트 디스플레이 지역 별 콘텐츠.

전통적인 VPN 및 프록시는 종종 사용자의 실제 위치에서 데이터 센터에서 트래픽 출구로 인해 이러한 서비스를 중단합니다. Privacy Proxy는 사용자의 지리적 지역과 일치하는 egress IP 주소를 선택하여 이것을 해결합니다.

## Geolocation 작업

Privacy Proxy는 정확한 좌표를 표시하지 않고 위치를 보존하기 위해 geohashes를 사용합니다.

### Geohash 인코딩

·[프로젝트](https://en.wikipedia.org/wiki/Geohash)위도와 경도의 컴팩트한 표현입니다. Geohashes는 더 긴 문자열이 더 정확한 위치를 나타내는 계층 인코딩을 사용합니다.

| Geohash 길이 | 오시는 길 |
| ---------- | ----- |
| 1개의 특성     | 24시간  |
| 2개의 특성     | 24시간  |
| 3개의 특성     | 24시간  |
| 4개의 특성     | 24시간  |
| 5개의 특성     | 24시간  |

개인 정보 보호 프록시는 감소-precision geohashes (일반적으로 4 \~ 5 문자)를 사용하여 사용자가 정확한 위치를 지정하지 않고 도시 또는 지역에 위치합니다.

### Egress IP 선택

클라이언트가 개인 정보 보호 프록시에 연결하면:

1. 클라이언트 (또는 더블 홉 배포에 처음 프록시) 사용자의 대략적인 위치를 결정합니다.
2. 클라이언트는 geohash를 보냅니다`sec-ch-geohash`헤더.
3. Privacy Proxy는 geohash를 검증하고 해당 지리적 지역에 등록된 풀에서 egress IP 주소를 선택합니다.
4. 대상 서버는 egress IP를보고 올바른 영역으로 사용자를 찾습니다.

### Geohash 헤더 형식

더 보기`sec-ch-geohash`헤더에는 geohash 및 국가 코드가 포함되어 있습니다.

```http
sec-ch-geohash: xn76c-JP
```

형식은`<geohash>-<country_code>`. 국가 코드는 geohashes 경간 국가 국경을 해결하는 가장자리 사례를 해결하는 데 도움이됩니다.

## Geolocation 정확도

Cloudflare는 전 세계 수백개의 도시에 있는 egress IP 수영장을 유지합니다. 당신은 Geolocation 데이터베이스와 egress IPs를 등록할 때, 그들은 특정 위치에 맵.

개인 정보 보호 프록시 달성 :

- **도시 수준 정확도**기본적으로, 그래서 사용자는 로컬 관련 검색 결과를 얻을.
- **국가 수준 정확도**도시 수준이 유효하지 않은 경우 fallback로.

사용자는 정확한 위치 공유를 선호하는 경우에 coarser geolocation (국가 및 시간대 전용)를 선택할 수 있습니다.

### 피자 시험

지리적 위치 정확도를 확인하는 간단한 방법은 프록시를 통해 "pizza near me"를 검색하는 것입니다. 결과가 멀지 않은 데이터 센터보다 사용자의 실제 도시의 피자 장소를 표시하면 지리적 위치가 올바르게 작동됩니다.

## IPv6 및 위치 정밀도

개인 정보 보호 프록시는 IPv6에 더 나은 위치 정밀도를 달성합니다. 소스 서버가 IPv6 (AAAA DNS 레코드)를 지원한다면 프록시는 IPv4 상당수보다 더 큰 지리적 정밀도로 등록되는 IPv6 egress 주소를 선호합니다.

사용자를 위한 지리적 위치 정확도를 극대화하려면, 귀하의 서비스가 IPv6에 도달 할 수 있도록 합니다.

## Geolocation 에 더블 홉 배포

내 계정[Double-hop 배포](/privacy-proxy/concepts/deployment-models/#double-hop), Proxy A (당신이 작동 하는)는 Geohash를 결정 하 고 전달에 대 한 책임:

1. 다운로드 클라이언트의 IP 주소를 찾습니다.
2. 프록시 A는 적절한 정밀도로 geohash에 위치를 변환합니다.
3. 다운로드 Proxy B에 전달된 CONNECT 요청에서 지오 해시가 포함되어 있습니다.
4. 프록시 B (Cloudflare)는 geohash에 근거한 egress IP를 선정합니다.

geohash는 암호로 보호됩니다. 클라이언트를 spoofing에서 위치.
