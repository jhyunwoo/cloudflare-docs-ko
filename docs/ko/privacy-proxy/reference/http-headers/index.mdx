이 문서는 인증, 지리적 위치 및 관측 가능성에 대한 개인 프록시에 의해 사용되는 HTTP 헤더를 문서화합니다.

## 요청 헤더

Clients는 다음 헤더를 포함합니다.

### `Proxy-Authorization`

프록시에 클라이언트를 지정합니다. 모든 요청에 대한 요구.

사전 공유 키 형식 :

```http
Proxy-Authorization: Preshared <key>
```

Privacy Pass 토큰 체재:

```http
Proxy-Authorization: PrivateToken token=<base64-encoded-token>
```

| 제품 설명                    | 이름 \*                    |
| ------------------------ | ------------------------ |
| `<key>`                  | Cloudflare               |
| `<base64-encoded-token>` | base64-encoded 개인용 패스 토큰 |

### `sec-ch-geohash`

고객의 IP 선택에 대한 지리적 위치를 지정합니다. 선택적이지만 정확한 위치 변경을 권장합니다.

```http
sec-ch-geohash: <geohash>-<country_code>
```

| 제품 설명            | 이름 \*                                                            |
| ---------------- | ---------------------------------------------------------------- |
| `<geohash>`      | ·[프로젝트](https://en.wikipedia.org/wiki/Geohash)문자열 (일반적으로 4-8 문자) |
| `<country_code>` | ISO 3166-1 알파-2 국가 코드                                            |

```http title="Example"
sec-ch-geohash: u4pruydqqvj-GB
```

이 예제는 영국의 위치를 지정합니다.

***

## 응답 헤더

Privacy Proxy는 응답에 다음 헤더를 포함합니다.

### `Server-Timing`

프록시 처리에 대한 타이밍 정보를 제공합니다. 프록시에 의해 도입 된 대기 시간을 측정하기 위해 이것을 사용합니다.

```http
Server-Timing: proxy;dur=<milliseconds>
```

| 제품 설명            | 이름 \*        |
| ---------------- | ------------ |
| `<milliseconds>` | 밀리 초에서 처리 시간 |

```http title="Example"
Server-Timing: proxy;dur=8.2
```

***

## `CONNECT`요청 형식

전체장편`CONNECT`개인 정보 보호 프록시는 다음과 같습니다 :

```http
CONNECT example.com:443 HTTP/2
Host: example.com
Proxy-Authorization: Preshared abc123xyz
sec-ch-geohash: 9q8yy-US
```

프록시는 성공 또는 실패를 나타내는 상태 코드로 응답합니다.

| 주요연혁                      | 이름 \*                   |
| ------------------------- | ----------------------- |
| `200 OK`                  | 성공적으로 설치되는 갱도           |
| `403 Forbidden`           | 인증 실패                   |
| `502 Bad Gateway`         | 대상에 연결할 수 없습니다.         |
| `503 Service Unavailable` | Proxy는 일시적으로 사용할 수 없습니다 |
