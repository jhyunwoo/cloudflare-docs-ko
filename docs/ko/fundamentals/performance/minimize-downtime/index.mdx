인터넷 애플리케이션의 라우팅을 변경할 때는 인증서 발급, 잘못된 설정, 원본 서버의 제한 등으로 인해 다운타임이 발생할 가능성이 항상 있습니다. 서비스 전환 시 다운타임을 피하려면 가장 일반적인 구성을 검토하는 것이 중요합니다.

## DNS 레코드 업데이트 및 검토

도메인을 Cloudflare에서 활성화하기 전에(정확한 단계는 [DNS 설정](/dns/zone-setups/)에 따라 다름) Cloudflare 계정의 DNS 레코드를 검토하세요.

### 먼저 프록시되지 않은 레코드로 시작

새 도메인의 경우 모든 DNS 레코드의 [프록시 상태](/dns/proxy-status/)가 **DNS-only**인지 확인하세요.

이 설정은 활성 에지 인증서가 없거나 Cloudflare IP 주소를 허용하기 전에 Cloudflare가 트래픽을 프록시하지 않도록 해 줍니다.

### 레코드 정확성 확인

도메인을 활성화하기 전에 DNS 레코드의 정확성을 확인하는 데 충분한 시간을 들이세요. 특히 다음 항목을 주의 깊게 확인하세요.

- [영역 apex 레코드 (`example.com`)](/dns/manage-dns-records/how-to/create-zone-apex/)
- [하위 도메인 레코드 (`www.example.com` 또는 `blog.example.com`)](/dns/manage-dns-records/how-to/create-subdomain/)
- [이메일 레코드](/dns/manage-dns-records/how-to/email-records/)

도메인을 온보딩한 후 활성화하기 전 사이에 권한 DNS 공급자에 DNS 레코드를 추가했다면, Cloudflare에도 해당 레코드를 추가해야 할 수 있습니다.

## 도메인 활성화

도메인의 [DNS 설정](/dns/zone-setups/)을 완료하여 [도메인 상태](/dns/zone-setups/reference/domain-status/)를 **Active**로 변경하세요.

- [전체 설정](/dns/zone-setups/full-setup/setup/): 등록기관에서 권한 네임서버를 업데이트하고, 해당 변경이 인증될 때까지 기다립니다.
- [부분 설정](/dns/zone-setups/partial-setup/setup/): 권한 DNS에 검증용 TXT 레코드를 추가하고, 해당 변경이 인증될 때까지 기다립니다.

## SSL/TLS 에지 인증서 확인

트래픽을 Cloudflare를 통해 프록시하기 전에 Cloudflare가 도메인에 대해 활성 **Edge Certificate**를 가지고 있는지 [확인](/ssl/reference/certificate-statuses/#monitor-certificate-statuses)하세요.

시점과 인증서 권장 사항에 대한 자세한 내용은 [인증서 발급](/ssl/edge-certificates/universal-ssl/enable-universal-ssl/#full-dns-setup)을 참고하세요.

## 선택 사항 - 구성 테스트

로컬 머신을 사용하거나 개발용 도메인 또는 하위 도메인에서 트래픽을 프록시하여 구성을 테스트할 수 있습니다.

문제가 발생한다면 원본 서버에서 [Cloudflare IP 주소를 허용](/fundamentals/concepts/cloudflare-ip-addresses/)했는지 확인해야 합니다.

## 프록시 상태 업데이트

SSL/TLS 에지 인증서가 활성 상태이고 Cloudflare IP 주소를 허용했음을 확인한 후, 적절한 DNS 레코드의 [프록시 상태](/dns/proxy-status/)를 **Proxied**로 변경하세요.
