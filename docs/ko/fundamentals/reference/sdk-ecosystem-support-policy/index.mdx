## 라이프사이클

코드 저장소에 별도 명시가 없는 한, Cloudflare는 라이브러리 또는 도구의 최신 메이저 버전에 대해서만 적극적인 지원을 제공합니다. 이 정책의 예외는 중요한 보안 수정이며, 취약점, 영향도, 필요한 완화 조치를 고려해 사안별로 검토됩니다.

Cloudflare는 세 가지 주요 개발 단계를 제공합니다. 얼리 액세스, 적극 지원, 수명 종료입니다.

:::note

이러한 라이프사이클 단계는 Cloudflare 제품마다 다른 용어로 불릴 수 있지만, 기본 원칙은 동일합니다.
:::

### 얼리 액세스

이 단계에서 Cloudflare는 일반 사용을 위해 릴리스하기 전에 피드백을 받고자 하는 SDK 변경 사항을 제공합니다. 얼리 액세스에는 예고 없이 변경될 수 있는 기능에 대한 경고 라벨이나 주의 사항이 포함되는 경우가 많습니다. 일반적으로 얼리 액세스 SDK는 명시적으로 언급되지 않는 한 프로덕션 시스템에 적합하지 않습니다.

### 적극 지원

적극 지원 단계에서는 라이브러리 또는 도구에 대해 계획된 변경 사항과 지원이 제공됩니다.

### 수명 종료

수명 종료 단계에서는 라이브러리 또는 도구의 새 메이저 버전이 릴리스되고, Cloudflare는 이전 메이저 버전에 대해 더 이상 개선이나 버그 수정이 제공되지 않는다고 표시합니다. 수명 종료 버전을 계속 실행할 경우 지원은 매우 제한적입니다.

![모든 라이프사이클 단계와 상호 관계](~/assets/images/fundamentals/support-policy.png "모든 라이프사이클 단계와 상호 관계")

## 이전 버전 또는 수명 종료 버전

Cloudflare는 모든 이전 버전의 라이브러리나 도구를 지원할 수는 없지만, 직접 지원 없이도 계속 사용할 수 있도록 해당 버전을 제거하지는 않습니다.

## 버전 관리

SDK 에코시스템은 시맨틱 버전 관리를 따르며, 버전은 다음과 같이 정의됩니다.

* 하위 호환되지 않는 변경이 있을 때 MAJOR 버전
* 하위 호환 방식으로 기능이 추가될 때 MINOR 버전
* 개선 없이 하위 호환 버그 수정만 있을 때 PATCH 버전

:::caution

Cloudflare는 최근 [OpenAPI를 사용해 라이브러리를 자동 생성하는 방식](https://blog.cloudflare.com/lessons-from-building-an-automated-sdk-pipeline)으로 전환했기 때문에, 라이브러리에 대한 엄격한 버전 관리 요구 사항을 완화했습니다(Terraform은 변경되지 않음). 서비스 소유자가 스키마를 안정화하고 사용성 개선을 반복하는 과정에서, 메서드/구조체/타입 이름 변경 형태의 호환성 깨짐이 마이너 릴리스에도 포함될 *수 있습니다*.

이 방식이 사용 사례에 적합하지 않다면, 검증된 버전에 고정하거나 라이브러리의 이전 메이저 버전을 사용하십시오.
:::

필요에 따라 애플리케이션의 패키지 매니저 버전 설정이 올바르게 구성되어 있는지 확인해야 합니다. 최소한 자동 메이저 업그레이드가 발생하지 않도록 현재 사용 중인 라이브러리 또는 도구의 현재 메이저 버전으로 설치를 제한하십시오.

## 마이그레이션

가능한 경우 Cloudflare는 주요 버전 업그레이드를 수행할 때 중단을 줄이기 위해 codemod를 활용한 자동화 접근 방식을 제공합니다. 이러한 마이그레이션 도구 사용 방법은 각 라이브러리 또는 도구별 릴리스 노트를 검토하십시오.

자동 마이그레이션 접근 방식과 함께, 수동으로 변경해야 하는 경우를 대비해 어떤 변경이 있었는지에 대한 문서도 제공합니다.
