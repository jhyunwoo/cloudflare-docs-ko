HTTP/HTTPS 트래픽이 [Cloudflare를 통해 프록시](/fundamentals/concepts/how-cloudflare-works/#cloudflare-as-a-reverse-proxy)될 때는 보통 두 개의 [TCP 연결](/fundamentals/reference/tcp-connections/)이 설정됩니다. 첫 번째는 요청 클라이언트와 Cloudflare 간의 연결이고, 두 번째는 Cloudflare와 원본 서버 간의 연결입니다. 각 연결에는 자체 TCP 및 HTTP 제한이 있으며, 아래에 문서화되어 있습니다.

## 구성 가능한 제한

일부 TCP 연결은 Enterprise 고객을 위해 사용자 지정할 수 있습니다. 자세한 내용은 계정 팀에 문의하십시오.

## Keep-Alive

Cloudflare는 전 세계 네트워크에서 사이트 원본 서버로 고객 트래픽을 프록시할 때 성능을 높이고 반복되는 TCP 연결 비용을 줄이기 위해 keep-alive 연결을 유지합니다.

원본에서 HTTP keep-alive 연결이 활성화되어 있는지 확인하십시오. Cloudflare는 마지막 HTTP 요청 이후 `Proxy Idle Timeout` 제한까지 열린 TCP 연결을 재사용합니다. 원본 웹 서버는 너무 많은 TCP 연결이 열려 있으면 이를 닫습니다. HTTP keep-alive는 Cloudflare를 통해 프록시된 요청에서 연결 재설정을 피하는 데 도움이 됩니다.

## 요청 제한

URL은 16 KB 제한이 있습니다. 요청 헤더 총합은 128 KB 제한이 있습니다.

## 응답 제한

응답 헤더 총합은 128 KB 제한을 따릅니다.

## 캐시 제한

최대 업로드 크기와 캐시 가능한 파일 크기 제한에 대한 자세한 내용은 [캐시 문서](/cache/concepts/default-cache-behavior/#customization-options-and-limits)를 참조하십시오.
