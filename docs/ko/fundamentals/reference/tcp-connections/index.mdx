다음 섹션에서는 Cloudflare가 애니캐스트 라우팅으로 트래픽을 효율적으로 전달하고 사용자와 원본 서버 사이의 중개자 역할을 수행하는 방식을 설명합니다. 이어서 성능 최적화를 위한 TCP 연결과 keep-alive를 다루고, 마지막으로 TCP 연결 속도를 높여주는 프로토콜 확장인 TCP Fast Open(TFO)을 설명합니다.

## Cloudflare가 사용자를 원본에 연결하는 방법

사용자는 자신의 장치에서 Cloudflare 글로벌 네트워크로 요청을 보내 Cloudflare에 연결합니다. Cloudflare는 사용자와 원본 사이의 중개자로 동작하며 원본 서버에 연결합니다.

```mermaid

accTitle: Connections with Cloudflare
A[Visitor] <-- Connection --> B[Cloudflare global network] <-- Connection --> C[Origin server]
```

<br/>

사용자 트래픽은 [애니캐스트](https://www.cloudflare.com/learning/cdn/glossary/anycast-network/) 라우팅 덕분에 가장 짧은 [Border Gateway Protocol](https://www.cloudflare.com/learning/security/glossary/what-is-bgp/) (BGP) 경로를 기준으로 가장 가까운 Cloudflare 데이터 센터로 라우팅됩니다. 이후 Cloudflare가 요청을 처리합니다. 요청이 Cloudflare 데이터 센터에서 직접 제공되지 않는 경우 Cloudflare는 요청을 전달하기 위해 원본 서버에 연결을 엽니다.

## TCP 연결과 keep-alive

HTTP(Hypertext Transfer Protocol)는 TCP 위에서 동작하는 [Layer 7](https://en.wikipedia.org/wiki/OSI_model) 애플리케이션 프로토콜입니다. 기본적으로 HTTP는 각 요청-응답 주기마다 새 TCP 연결을 열기 때문에, 반복적인 연결 설정과 해제로 인해 성능 오버헤드가 발생할 수 있습니다.

Keep-Alive는 TCP와 HTTP를 잇는 메커니즘으로, 하나의 TCP 연결을 여러 HTTP 요청과 응답에 걸쳐 열어 둘 수 있게 합니다. 이를 통해 각 웹 리소스마다 새 TCP 연결을 설정하는 데 따르는 연결 오버헤드와 지연 시간을 줄일 수 있습니다. Keep-Alive는 기존 연결의 재사용을 촉진하고, 네트워크 트래픽을 줄이며, 사용자 경험을 향상해 웹 애플리케이션의 효율성과 응답성을 높입니다.

TCP 연결은 HTTP 요청이 끝난 후에도 계속 유지될 수 있습니다. 그러나 리소스를 효율적으로 관리하기 위해 일반적으로 유휴 연결은 일정 시간 비활성 상태가 지속되면 종료됩니다. 연결 재사용을 높이고 연결 오버헤드를 최소화하기 위해 keep-alive가 사용됩니다. 이러한 메커니즘은 네트워크 리소스를 절약하면서 웹 애플리케이션의 성능과 안정성을 함께 최적화합니다.

사용자나 원본 중 하나라도 두 번의 keep-alive에 응답하지 않으면 Cloudflare는 TCP Reset(RST) 패킷을 보내 연결을 종료합니다.

사용자와의 연결에서 Cloudflare의 기본 유휴 타임아웃은 400초입니다. 400초가 지나면 Cloudflare는 75초마다 keep-alive probe를 보내기 시작합니다. 9번 연속으로 응답이 없으면 Cloudflare는 RST 패킷을 보내 연결을 종료합니다.

:::note


keep-alive가 존재하더라도 Cloudflare가 연결 유지를 보장할 수는 없습니다. 유휴 상태 외에도 용량 밸런싱, 데이터 센터 유지보수, 노드 재시작 등 연결이 끊어질 수 있는 다른 이유가 있기 때문입니다. 이를 고려하여 애플리케이션은 연결 끊김을 우아하게 처리할 수 있도록 설계되어야 합니다.


:::

사용자와 Cloudflare 간, 그리고 Cloudflare와 원본 간의 TCP 연결 설정은 Enterprise 고객을 위해 사용자 지정할 수 있습니다. 자세한 내용은 계정 팀에 문의하십시오.

## TCP Fast Open (TFO)

[TCP Fast Open](https://en.wikipedia.org/wiki/TCP_Fast_Open)(TFO)은 데이터 전송 전에 별도의 핸드셰이크를 요구하는 대신 초기 SYN 패킷에서 데이터를 전송할 수 있게 해 TCP 연결 수립 속도를 크게 향상시킬 수 있는 프로토콜 확장입니다. TFO는 지연 시간을 줄이고, 특히 고지연 네트워크에서 웹사이트와 애플리케이션 성능을 향상시킬 수 있습니다. Cloudflare는 사용자 연결에서 TFO를 지원합니다.

클라이언트가 Cloudflare로 보호되는 웹 서버에 연결을 시작하면, 연결 요청을 위해 TCP SYN 패킷을 보냅니다. 리버스 프록시로 동작하는 Cloudflare는 SYN 패킷을 가로채고, 연결을 설정하기 위해 SYN-ACK 패킷으로 응답합니다. TFO가 활성화되면 Cloudflare는 SYN-ACK 패킷 안에 초기 데이터(예: HTTP 요청 데이터)도 함께 전송할 수 있어, 데이터 전송을 위한 추가 왕복이 필요 없어집니다. 클라이언트는 데이터를 포함한 SYN-ACK 패킷을 받은 뒤 ACK 패킷으로 확인합니다. 이 과정을 통해 연결 설정이 빨라집니다.
