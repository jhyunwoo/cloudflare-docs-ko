Cloudflare가 기본적으로 어떤 네트워크 포트를 프록시하는지와, 추가 포트에 대해 Cloudflare 프록시를 활성화하는 방법을 알아보십시오.

## Cloudflare 프록시와 호환되는 네트워크 포트

기본적으로 Cloudflare는 아래 나열된 HTTP/HTTPS 포트로 향하는 트래픽을 프록시합니다.

## 추가 포트에 대해 Cloudflare 프록시를 활성화하는 방법

도메인 트래픽이 위 목록에 없는 다른 포트로 향하는 경우, 예를 들어 22번 포트에서 들어오는 연결을 수신하는 SSH 서버가 있다면 다음 중 하나를 수행하십시오.

- Cloudflare DNS 앱에서 서브도메인을 [회색 구름(Gray-clouded)](/dns/proxy-status/) 상태로 변경하여 Cloudflare 네트워크를 우회하고 원본에 직접 연결합니다.
- 서버를 실행하는 호스트 이름에 대해 [Spectrum 애플리케이션](/spectrum/get-started/)을 구성합니다. Spectrum은 모든 포트를 지원합니다. 모든 TCP 및 UDP 포트에 대한 Spectrum은 Enterprise 플랜에서만 사용할 수 있습니다. Cloudflare 플랜에 대해 더 알고 싶다면 Cloudflare 계정 팀에 문의하십시오.

## 추가 포트의 트래픽을 차단하는 방법

Cloudflare 유료 플랜에서 80 및 443 이외의 포트 트래픽을 차단하려면 다음 중 하나를 수행하십시오.

- [WAF 관리형 규칙(이전 버전)](/waf/reference/legacy/old-waf-managed-rules/)을 사용하는 경우 규칙 ID `100015`(`Anomaly:Port - Non Standard Port (not 80 or 443)`)를 활성화합니다.
- 새 [Cloudflare Web Application Firewall (WAF)](/waf/)을 사용하는 경우 기본적으로 비활성화된 규칙 ID <RuleID id="8e361ee4328f4a3caf6caf3e664ed6fe" /> (`Anomaly:Port - Non Standard Port (not 80 or 443)`)를 활성화합니다. 이 규칙은 Cloudflare Managed Ruleset의 일부입니다.

80 및 443 포트만 다음과 호환됩니다.

- **China Network**가 활성화된 도메인에 대해 China 데이터 센터 내부의 HTTP/HTTPS 트래픽

<Render file="open-ports-blocked-traffic" product="waf" /> <br />

WAF의 [Cloudflare Managed Ruleset](/waf/managed-rules/reference/cloudflare-managed-ruleset/)에는 애플리케이션 계층([OSI 모델](https://www.cloudflare.com/learning/ddos/glossary/open-systems-interconnection-model-osi/)의 7계층)에서 트래픽을 차단하는 규칙이 포함되어 있으며, 비표준 포트를 사용하는 HTTP/HTTPS 요청이 원본 서버에 도달하지 못하게 합니다.

:::note

[Cloudflare Access](/cloudflare-one/)는 URL의 포트 번호를 지원하지 않습니다. Cloudflare Access로 보호되는 URL 요청에서는 포트 번호가 제거됩니다.

:::
