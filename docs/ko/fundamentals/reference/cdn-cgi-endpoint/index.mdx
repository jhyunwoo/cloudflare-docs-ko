[도메인을 Cloudflare에 추가](/fundamentals/manage-domains/add-site/)하면 Cloudflare는 해당 도메인에 `/cdn-cgi/` 엔드포인트(`www.example.com/cdn-cgi/`)를 추가합니다.

이 엔드포인트는 Cloudflare가 관리하고 제공합니다. 수정하거나 사용자 정의할 수 없습니다. 모든 Cloudflare 제품이 이 엔드포인트를 사용하는 것은 아니지만, 일부 제품은 URL에서 이 엔드포인트를 사용합니다.

다음은 몇 가지 예시입니다(이에 국한되지 않음).

* 문제 해결에 도움이 되는 [요청을 처리한 Cloudflare 데이터 센터 식별](/support/troubleshooting/general-troubleshooting/gathering-information-for-troubleshooting-sites/#identify-the-cloudflare-data-center-serving-your-request) (`https://<YOUR_DOMAIN>/cdn-cgi/trace`)
* Cloudflare 봇 제품에서 사용하는 [JavaScript 탐지](/bots/additional-configurations/javascript-detections/) (`example.com/cdn-cgi/challenge-platform/`)
* 이미지에 사용하는 새 URL의 [이미지 변환](/images/transform-images) (`example.com/cdn-cgi/image/`)
* 악성 봇으로부터 이메일 주소를 숨기는 데 사용하는 [이메일 주소 난독화](/waf/tools/scrape-shield/email-address-obfuscation/) (`example.com/cdn-cgi/l/email-protection`)
* Cloudflare를 통해 프록시되는 웹사이트의 [웹 분석](/web-analytics/get-started/#sites-proxied-through-cloudflare) (`example.com/cdn-cgi/rum`). 이 엔드포인트는 `204` HTTP 상태 코드를 반환합니다.
* [Speed Brain](/speed/optimization/content/speed-brain/)은 웹 페이지 응답에 `Speculation-Rules`라는 HTTP 헤더를 추가합니다. 이 헤더에는 브라우저에 향후 예상 탐색에 대한 prefetch 요청을 시작하도록 지시하는, 선호되는 Speculation-Rules 구성을 호스팅하는 URL이 포함됩니다.

## 권장 제외 항목

### 보안 스캐너에서 제외

일부 스캐너는 특정 `/cdn-cgi/` 엔드포인트에 [HSTS 설정](/ssl/edge-certificates/additional-options/http-strict-transport-security/)이 적용되지 않았거나 유사한 이유로 오류를 표시할 수 있습니다. 이 엔드포인트는 Cloudflare가 관리하므로 해당 오류는 무시해도 되며 걱정할 필요가 없습니다.

스캐너 오류를 방지하려면 보안 스캔에서 `/cdn-cgi/` 엔드포인트를 제외하십시오.

### robots.txt에서 사용 금지

`/cdn-cgi/`는 다양한 웹 크롤러에서 문제를 일으킬 수도 있습니다.

검색 엔진 크롤러는 [이 엔드포인트를 크롤링할 때 오류](/support/troubleshooting/general-troubleshooting/troubleshooting-crawl-errors/)를 만날 수 있으며, 이러한 오류는 사이트 순위에 영향을 주지는 않지만 웹마스터 대시보드에는 표시될 수 있습니다.

SEO 크롤러나 기타 웹 크롤러도 이 엔드포인트를 사이트 콘텐츠의 일부로 오해하여 크롤링할 수 있습니다.

모범 사례로 `robots.txt` 파일에 `Disallow: /cdn-cgi/`를 추가하십시오.
