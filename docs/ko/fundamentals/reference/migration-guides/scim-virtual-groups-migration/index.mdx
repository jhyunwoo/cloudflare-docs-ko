Cloudflare의 첫 번째 SCIM 통합 버전에서는 IdP에서 일반적으로 `CF-<accountID>-<Role Name>` 패턴으로 식별되는 *Virtual Groups*라는 개념이 도입되었습니다. Virtual Groups는 그룹 기반 액세스 제어의 초기 구현으로, IdP 그룹을 계정 멤버십에 매핑하기 위해 SCIM이 자동 생성하는 자리 표시자 역할을 했습니다.

고객은 IdP 내에서 이러한 그룹에 멤버를 추가하거나 제거할 수 있었지만, Virtual Groups에는 중요한 제한이 있었습니다.
- IdP에서 이름을 바꾸거나 삭제할 수 없었습니다.
- Cloudflare 내에서 관리할 수 없었습니다.
- 기능적으로는 Virtual Group을 관리하는 일이 사용자 동기화 후 각 멤버의 정책을 개별적으로 편집하는 것과 동일했습니다.

[User Groups](/changelog/2025-06-23-user-groups-ga/)가 GA로 출시되면서 Virtual Groups는 이제 더 이상 사용되지 않습니다. 고객은 정책을 보다 유연하고 확장성 있게 할당하고 관리할 수 있는 [User Groups](/fundamentals/manage-members/user-groups/)로 마이그레이션해야 합니다. Cloudflare 대시보드와의 SCIM 동기화를 유지하려면 **SCIM User Groups**로의 마이그레이션을 강력히 권장합니다.

IdP에서 `CF-<accountID>-<Role Name>` Virtual Group에 연결된 그룹을 Cloudflare로 한 번도 동기화한 적이 없다면 별도 조치가 필요하지 않습니다.

## 마이그레이션 단계

1. Cloudflare에서 프로비저닝한 [Account Owned Token](/fundamentals/account/account-security/scim-setup/)을 사용하여 IdP에서 **새 SCIM 통합**을 만듭니다.
2. 내부 프로세스에 맞는 이름 규칙을 따라 IdP의 **새 애플리케이션에 사용자와 그룹을 할당**합니다.
3. **그룹을 Cloudflare로 동기화**하고, Cloudflare 대시보드의 **User Groups** 창에 표시되는지 확인합니다.
4. 새 User Groups에 **권한 정책을 연결**하여, 멤버가 그룹에 할당되었을 때 올바른 액세스 권한을 상속받도록 합니다.
5. **사용자를 새 그룹으로 점진적으로 마이그레이션**하면서, Cloudflare 대시보드로 사용자와 그룹이 동기화되는지 테스트합니다.
6. `CF-<accountID>-<Role Name>` 패턴을 따르는 SCIM v1 Virtual Groups와 IdP 매핑을 제거하여 **레거시 리소스를 정리**합니다.
