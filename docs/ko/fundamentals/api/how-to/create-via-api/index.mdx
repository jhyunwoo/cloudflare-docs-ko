API를 통해 즉시 새 API 토큰을 생성할 수 있습니다. 이를 위해서는 먼저 후속 토큰을 생성할 수 있는 API 토큰을 Cloudflare 대시보드에서 만들어야 합니다.

:::note

토큰을 생성하려면 API 토큰 템플릿 [**Create additional tokens**](/fundamentals/api/reference/template/)를 사용해야 합니다. **API Tokens::Edit** 옵션은 다른 어떤 템플릿이나 Custom Token builder에서도 사용할 수 없습니다.
:::

## 초기 토큰 생성

API를 통해 토큰을 만들기 전에 먼저 Cloudflare 대시보드에서 [초기 토큰을 생성](/fundamentals/api/get-started/create-token/)해야 합니다.

<Render file="new-token-warning" product="fundamentals" />

### 권장 사항

Cloudflare는 이 템플릿을 사용할 때 토큰에 다른 권한을 부여하지 않을 것을 강력히 권장합니다. 새 토큰은 사용자의 모든 리소스에 접근할 수 있는 토큰을 생성할 수 있으므로 반드시 안전하게 보호하세요.

Cloudflare는 또한 토큰이 손상되었을 때 악용 가능성을 줄이기 위해 클라이언트 IP 주소 필터링이나 TTL로 토큰 사용을 제한할 것을 권장합니다. 자세한 내용은 [토큰 사용 제한](/fundamentals/api/how-to/restrict-tokens/)을 참조하세요.

## API로 API 토큰 만들기

API와 함께 사용할 사용자 소유 토큰 또는 계정 소유 토큰을 만들 수 있습니다. 자세한 내용은 [user owned token](/api/resources/user/subresources/tokens/methods/create/) 또는 [account owned token](/api/resources/accounts/subresources/tokens/methods/create/) API 스키마 문서를 참조하세요.

토큰을 만들려면:

1. 정책을 정의합니다.
2. 제한 사항을 정의합니다.
3. 토큰을 생성합니다.

### 1. 접근 정책 정의

접근 정책은 토큰이 어떤 리소스에 대해 동작할 수 있는지와 해당 리소스에 대해 어떤 권한을 가지는지를 정의합니다. 이 과정은 [Cloudflare 대시보드에서 토큰을 만드는 방법](/fundamentals/api/get-started/create-token/)과 유사합니다.

각 토큰에는 여러 정책을 포함할 수 있습니다.

```json
[
	{
		"id": "f267e341f3dd4697bd3b9f71dd96247f",
		"effect": "allow",
		"resources": {
			"com.cloudflare.api.account.zone.eb78d65290b24279ba6f44721b3ea3c4": "*",
			"com.cloudflare.api.account.zone.22b1de5f1c0e4b3ea97bb1e963b06a43": "*"
		},
		"permission_groups": [
			{
				"id": "c8fed203ed3043cba015a93ad1616f1f",
				"name": "Zone Read"
			},
			{
				"id": "82e64a83756745bbbb1c9c2701bf816b",
				"name": "DNS Read"
			}
		]
	}
]
```

| 필드                | 설명                                                                                                                                                                                                                                     |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`                | 생성 후 정책에 대해 만들어지는 고유한 읽기 전용 식별자입니다.                                                                                                                                                                           |
| `effect`            | 이 정책이 접근을 허용할지 거부할지 정의합니다. 정책을 하나만 만들 경우 `allow`를 사용하세요. 정책 평가 순서는 다음과 같습니다. 1. 명시적 `DENY` 정책 2. 명시적 `ALLOW` 정책 3. 암시적 `DENY ALL` |
| `resources`         | 구성 가능하도록 허용된 리소스를 정의합니다.                                                                                                                                                                                              |
| `permission_groups` | 정책이 포함된 리소스에 부여하는 권한을 정의합니다.                                                                                                                                                                                       |

#### 리소스

API 토큰 정책은 `User`, `Account`, `Zone` 세 가지 리소스 유형을 지원합니다.

:::note

각 객체의 ID는 적절한 `GET <object>` API를 호출해 가져오세요. 자세한 내용은 [User](/api/resources/user/methods/get/), [Account](/api/resources/accounts/methods/list/), [Zone](/api/resources/zones/methods/list/) 문서를 참조하세요.
:::

##### Account

토큰 정책에 단일 계정 또는 모든 계정을 포함할 수 있습니다.

- **단일 계정**은 `"com.cloudflare.api.account.<ACCOUNT_ID>": "*"`로 표기합니다.
- **모든 계정**은 `"com.cloudflare.api.account.*": "*"`로 표기합니다.

##### Zone

토큰 정책에 **단일 zone**, **계정 내 모든 zone**, 또는 **모든 계정의 모든 zone**을 포함할 수 있습니다.

- **단일 zone**은 `"com.cloudflare.api.account.zone.<ZONE_ID>": "*"`로 표기합니다.
- **계정 내 모든 zone**은 `"com.cloudflare.api.account.<ACCOUNT_ID>": {"com.cloudflare.api.account.zone.*": "*"}`로 표기합니다.
- **모든 계정의 모든 zone**은 `"com.cloudflare.api.account.zone.*": "*"`로 표기합니다.

##### User

사용자 리소스의 경우 자신만 참조할 수 있으며 `"com.cloudflare.api.user.<USER_TAG>": "*"`로 표기합니다.

#### 권한 그룹

API 토큰에 권한 그룹을 추가하려면 해당 `id` 값을 지정하세요. Cloudflare API와 상호작용할 때는 `name`보다 `id`를 키로 사용하는 것을 권장합니다. 권한 `name`은 표시용이며 변경될 수 있습니다. 권한 그룹은 특정 리소스(user, account, zone)에 범위가 지정되므로, 정책의 권한 그룹은 해당 범위의 리소스 유형에만 적용됩니다.

사용 가능한 모든 권한 그룹과 ID를 가져오려면 [List permission groups](/api/resources/user/subresources/tokens/subresources/permission_groups/methods/list/) 엔드포인트를 사용하세요.

<APIRequest path="/user/tokens/permission_groups" method="GET" />

```json output

  "result": [
    {
      "id": "19637fbb73d242c0a92845d8db0b95b1",
      "name": "AI Crawl Control Read",

      "scopes": [

}
```

### 2. 제한 사항 정의

토큰 사용 방식에 대한 제한을 설정합니다. API 토큰은 클라이언트 IP 주소 필터링과 TTL 제한을 지원합니다. 자세한 내용은 [토큰 사용 제한](/fundamentals/api/how-to/restrict-tokens/)을 참조하세요.

TTL을 정의할 때는 `not_before`로 토큰이 활성화되기 시작하는 시간을, `expires_on`으로 만료 시간을 설정할 수 있습니다. 두 필드 모두 `"2018-07-01T05:20:00Z"` 형식의 UTC 타임스탬프를 사용합니다.

클라이언트 IP 주소 필터로 토큰 사용을 제한하려면 다음 객체를 사용하세요.

```json
{
	"request.ip": {
		"in": ["199.27.128.0/21", "2400:cb00::/32"],
		"not_in": ["199.27.128.0/21", "2400:cb00::/32"]
	}
}
```

`in` 및 `not_in` 객체의 각 매개변수는 CIDR 표기법이어야 합니다. 예를 들어 단일 IP 주소를 지정하려면 `192.168.0.1/32`를 사용하세요.

### 3. 토큰 생성

앞서 정의한 정보를 조합해 다음 예시처럼 토큰을 생성합니다.

<Tabs>
  <TabItem label="Account token">
```bash
curl "https://api.cloudflare.com/client/v4/accounts/{account_id}/tokens" \
--header "Authorization: Bearer <API_TOKEN>" \
--header "Content-Type: application/json" \
--data '{
  "name": "readonly token",
  "policies": [
    {
      "effect": "allow",
      "resources": {
        "com.cloudflare.api.account.zone.eb78d65290b24279ba6f44721b3ea3c4": "*",
        "com.cloudflare.api.account.zone.22b1de5f1c0e4b3ea97bb1e963b06a43": "*"
      },
      "permission_groups": [
        {
          "id": "c8fed203ed3043cba015a93ad1616f1f",
          "name": "Zone Read"
        },
        {
          "id": "82e64a83756745bbbb1c9c2701bf816b",
          "name": "DNS Read"
        }
      ]
    }
  ],
  "not_before": "2020-04-01T05:20:00Z",
  "expires_on": "2020-04-10T00:00:00Z",
  "condition": {
    "request.ip": {
      "in": [
        "199.27.128.0/21",
        "2400:cb00::/32"
      ],
      "not_in": [
        "199.27.128.1/32"
      ]
    }
  }
}'
```
