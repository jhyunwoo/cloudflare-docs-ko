템플릿 URL을 사용하면 미리 구성된 권한으로 Cloudflare API 토큰을 생성할 수 있습니다. 템플릿 URL을 사용하면 대시보드에서 권한을 수동으로 선택하지 않고도 사용자와 토큰 요구 사항을 공유할 수 있습니다.

템플릿 URL은 쿼리 매개변수를 사용해 Cloudflare 대시보드의 API 토큰 생성 페이지를 미리 채웁니다. 사용자가 템플릿 URL을 열면 대시보드가 지정된 권한과 설정을 자동으로 구성합니다.

Cloudflare는 [사용자 API 토큰](#user-token-url-format)과 [계정 API 토큰](#account-token-url-format) 모두에 대해 템플릿 URL을 지원합니다. 이 두 토큰 유형의 차이에 대한 자세한 내용은 [계정 API 토큰](/fundamentals/api/get-started/account-owned-tokens/)을 참조하세요.

:::note

템플릿 URL은 토큰 생성 양식만 미리 채웁니다. 사용자는 여전히 대시보드에서 토큰 생성 과정을 완료해야 합니다.

:::

## 사용자 토큰 URL 형식

사용자 토큰 템플릿 URL은 사용자 프로필 수준(`/profile/api-tokens`)에서 토큰 생성 양식을 엽니다. 이렇게 만든 토큰은 사용자 소유입니다.

기본 템플릿 URL 구조는 다음과 같습니다.

```txt
https://dash.cloudflare.com/profile/api-tokens?permissionGroupKeys=[ENCODED_PERMISSIONS]&accountId=*&zoneId=all&name=[TOKEN_NAME]
```

### URL 구성 요소

| 매개변수              | 필수 | 설명                                   |
| --------------------- | ---- | -------------------------------------- |
| `permissionGroupKeys` | 예   | URL 인코딩된 권한 객체의 JSON 배열     |
| `accountId`           | 예   | 계정 범위(`*`는 모든 계정)             |
| `zoneId`              | 예   | zone 범위(`all`은 모든 zone)           |
| `name`                | 아니오 | 미리 채워진 토큰 이름                |

## 계정 토큰 URL 형식

계정 토큰 템플릿 URL은 계정 수준에서 토큰 생성 양식을 엽니다. 이렇게 만든 토큰은 계정 소유(서비스 주체 토큰)이며 특정 사용자에게 연결되지 않습니다. 계정 토큰을 만들려면 Super Administrator 또는 Administrator 권한이 필요합니다.

기본 템플릿 URL 구조는 다음과 같습니다.

```txt
https://dash.cloudflare.com/?to=/:account/api-tokens&permissionGroupKeys=[ENCODED_PERMISSIONS]&name=[TOKEN_NAME]
```

`:account` 세그먼트는 자리표시자입니다. 사용자가 URL을 열었을 때 둘 이상의 계정에 접근할 수 있다면 대시보드에서 계정을 선택하라는 메시지를 표시합니다.

### URL 구성 요소

| 매개변수              | 필수 | 설명                               |
| --------------------- | ---- | ---------------------------------- |
| `permissionGroupKeys` | 예   | URL 인코딩된 권한 객체의 JSON 배열 |
| `name`                | 아니오 | 미리 채워진 토큰 이름            |

:::note

계정 토큰 템플릿 URL은 `accountId` 또는 `zoneId` 매개변수를 사용하지 않습니다. 계정 토큰의 리소스 범위는 대시보드에서 토큰 생성 중에 구성합니다.

:::

## 권한 형식

사용자 토큰과 계정 토큰 템플릿 URL은 모두 동일한 권한 인코딩 형식을 사용합니다. 권한은 다음 구조를 가진 JSON 배열로 인코딩됩니다.

```json
[{ "key": "permission_name", "type": "read|edit|revoke|run|purge" }]
```

### 권한 유형

| 유형      | 설명                                  |
| --------- | ------------------------------------- |
| `read`    | 읽기 전용 접근                        |
| `edit`    | 전체 접근(생성, 읽기, 업데이트, 삭제) |
| `revoke`  | 취소 권한                             |
| `run`     | 실행 권한                             |
| `purge`   | 제거 권한                             |

## 사용자 지정 템플릿 만들기

### 1. 필요한 권한 식별

사용 사례에 필요한 권한을 나열합니다. [권한 참조](#permission-reference) 표를 참조하세요.

### 2. 권한 JSON 만들기

권한을 JSON 배열 형식으로 작성합니다.

```json
[
	{ "key": "zone_dns", "type": "edit" },
	{ "key": "analytics", "type": "read" }
]
```

### 3. JSON URL 인코딩

URL 인코더를 사용해 JSON 문자열을 변환합니다.

```text
%5B%7B%22key%22%3A%22zone_dns%22%2C%22type%22%3A%22edit%22%7D%2C%7B%22key%22%3A%22analytics%22%2C%22type%22%3A%22read%22%7D%5D
```

### 4. 전체 URL 구성

**사용자 토큰**의 경우, 모든 구성 요소를 결합해 최종 템플릿 URL을 만듭니다.

```txt
https://dash.cloudflare.com/profile/api-tokens?permissionGroupKeys=[ENCODED_JSON]&accountId=*&zoneId=all&name=Custom%20Token
```

**계정 토큰**의 경우 대신 계정 수준 경로를 사용합니다.

```txt
https://dash.cloudflare.com/?to=/:account/api-tokens&permissionGroupKeys=[ENCODED_JSON]&name=Custom%20Token
```

## 권한 참조

사용자 지정 템플릿에 사용할 권한 키를 찾으려면 이 표를 사용하세요.

### 계정 권한

| 권한 키               | 설명              | 일반적인 사용 사례     |
| --------------------- | ----------------- | ---------------------- |
| `account_analytics`   | 계정 분석         | 보고, 모니터링         |
| `account_api_tokens`  | API 토큰 관리     | 토큰 자동화            |
| `account_settings`    | 계정 구성         | 계정 관리              |
| `billing`             | 청구 정보         | 비용 추적, 청구        |
| `workers_scripts`     | Workers 스크립트  | 서버리스 함수          |
| `workers_kv`          | Workers KV 저장소 | 데이터 저장            |
| `workers_routes`      | Workers 라우트    | 트래픽 라우팅          |

### Zone 권한

| 권한 키              | 설명          | 일반적인 사용 사례   |
| -------------------- | ------------- | -------------------- |
| `zone_dns`           | DNS 레코드    | 도메인 관리          |
| `zone`               | Zone 관리     | 도메인 구성          |
| `analytics`          | Zone 분석     | 성능 모니터링        |
| `firewall_services`  | 방화벽 규칙   | 보안 관리            |
| `page_rules`         | Page Rules    | 트래픽 제어          |
| `cache_purge`        | 캐시 제거     | 콘텐츠 업데이트      |

### Access 권한

| 권한 키               | 설명                 | 일반적인 사용 사례      |
| --------------------- | -------------------- | ----------------------- |
| `access`              | Access 애플리케이션  | Zero Trust 앱           |
| `access_acct`         | Access 조직          | ID 관리                 |
| `access_audit_log`    | Access 감사 로그     | 규정 준수, 보안         |
| `access_custom_page`  | 사용자 지정 페이지   | 브랜딩, 사용자 경험     |

## 모범 사례

템플릿 URL을 만들고 공유할 때 다음 지침을 따르세요.

- 최소 권한 원칙: 사용 사례에 필요한 최소한의 권한만 요청하세요. 이렇게 하면 토큰이 손상되었을 때의 보안 위험을 줄일 수 있습니다.
- 설명적인 토큰 이름 사용: 사용자가 토큰의 목적을 이해할 수 있도록 템플릿 URL에 명확하고 설명적인 이름을 포함하세요.
- 토큰 사용 문서화: 각 토큰이 무엇에 사용되는지, 더 이상 필요 없을 때 어떻게 폐기하는지에 대해 명확하게 문서화하세요.
- 정기적인 토큰 교체: 사용자가 정기적으로 토큰을 교체하고 권한을 검토하도록 권장하세요.
- 공유 전 테스트: 템플릿 URL을 사용자와 공유하기 전에 항상 스테이징 환경에서 테스트하세요.

## 문제 해결

일반적인 문제와 해결 방법 목록을 검토하세요.

| 문제                              | 해결 방법                                      |
| --------------------------------- | --------------------------------------------- |
| URL이 권한을 미리 채우지 않음     | JSON이 올바르게 URL 인코딩되었는지 확인       |
| 권한이 누락됨                     | 참조 표의 권한 키를 확인                      |
| 토큰 이름이 표시되지 않음         | name 매개변수가 URL 인코딩되었는지 확인       |
| Access denied 오류                | 사용자가 계정에서 필요한 권한을 가지고 있는지 확인 |

또한 템플릿 URL을 공유하기 전에 다음 체크리스트를 검토하세요.

- 모든 권한 키가 올바름
- JSON 구문이 유효함
- URL 인코딩이 올바름
- 토큰 이름이 설명적임
- 권한이 최소 권한 원칙을 따름
