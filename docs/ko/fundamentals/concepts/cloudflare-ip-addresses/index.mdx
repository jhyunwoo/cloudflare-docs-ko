Cloudflare는 모든 프록시된 호스트 이름이 공유하는 여러 [IP 주소 범위](https://www.cloudflare.com/ips/)를 보유하고 있습니다.

이 IP 주소들은 함께 [애니캐스트 네트워크](https://www.cloudflare.com/learning/cdn/glossary/anycast-network/)의 기반을 이루며, 다양한 에지 네트워크 서버에 트래픽을 분산하는 데 도움을 줍니다.

:::note

Cloudflare는 여러 제품과 서비스에 대해 다른 IP 범위도 사용하지만, 해당 주소들은 원본에 연결하지 않습니다.

:::

## Cloudflare IP 주소 허용

[프록시된 DNS 레코드](/dns/proxy-status/)로 향하는 모든 트래픽은 원본 서버에 도달하기 전에 Cloudflare를 통과합니다. 즉, 원본 서버는 더 이상 개별 방문자 IP 주소에서 직접 트래픽을 받지 않고, 모든 프록시된 호스트 이름이 공유하는 [Cloudflare IP 주소](https://www.cloudflare.com/ips)에서 트래픽을 받게 됩니다.

이 설정은 원본 서버가 Cloudflare IP 주소에서 오는 연결을 차단하거나 속도 제한할 경우 문제를 일으킬 수 있습니다. 모든 방문자 트래픽이 Cloudflare IP 주소에서 오는 것처럼 보이기 때문에, 실수로라도 이 IP를 차단하면 방문자 트래픽이 애플리케이션에 도달하지 못하게 됩니다.

또한 원본 서버에서 이러한 요청을 <GlossaryTooltip term="rate limiting">속도 제한</GlossaryTooltip>하거나 차단하지 않도록 하려면 Cloudflare IP 허용이 필요할 수 있습니다.

[Magic Transit](/magic-transit/) 고객의 경우 Cloudflare는 트래픽을 프록시하지 않고 라우팅합니다. Cloudflare가 IP 프리픽스를 광고하기 시작하면 네트워크를 대상으로 하는 IP 패킷을 수락하고 처리한 뒤, 이 패킷을 원본 인프라로 전달합니다.

## 원본 서버 구성

### Cloudflare IP 주소 허용 목록 추가

Cloudflare IP 주소가 의도치 않게 차단되지 않도록 원본 웹 서버에서도 Cloudflare IP 주소를 허용하는 것이 좋습니다.

[.htaccess 파일](https://httpd.apache.org/docs/trunk/mod/mod_authz_core.html#require)이나 [iptables](https://www.linode.com/docs/security/firewalls/control-network-traffic-with-iptables/#block-or-allow-traffic-by-port-number-to-create-an-iptables-firewall)를 사용하여 이러한 IP 주소를 명시적으로 허용할 수 있습니다.

다음 예제는 iptables 규칙을 사용해 Cloudflare IP 주소 범위를 허용하는 방법을 보여줍니다. 아래의 `$ip`를 [Cloudflare IP 주소 범위](https://www.cloudflare.com/ips) 중 하나로 바꾸세요.

```bash
# IPv4 주소용
$ iptables -I INPUT -p tcp -m multiport --dports http,https -s $ip -j ACCEPT

# IPv6 주소용
$ ip6tables -I INPUT -p tcp -m multiport --dports http,https -s $ip -j ACCEPT
```

보다 구체적인 안내가 필요하면 호스팅 제공업체나 웹사이트 관리자에게 문의하세요.

### 다른 IP 주소 차단(권장)

모범 사례로 Cloudflare IP 주소 또는 신뢰하는 파트너, 공급업체, 애플리케이션의 IP 주소에서 오지 않는 모든 트래픽을 명시적으로 차단하는 것도 권장합니다.

예를 들어 다음 명령으로 [iptables를 업데이트](https://www.linode.com/docs/guides/control-network-traffic-with-iptables/#block-or-allow-traffic-by-port-number-to-create-an-iptables-firewall)할 수 있습니다.

```sh
# IPv4 주소용
iptables -A INPUT -p tcp -m multiport --dports http,https -j DROP
# IPv6 주소용
ip6tables -A INPUT -p tcp -m multiport --dports http,https -j DROP
```

보다 구체적인 안내가 필요하면 호스팅 제공업체나 웹사이트 관리자에게 문의하세요.

## 외부 도구 검토

Cloudflare IP 주소가 의도치 않게 차단되지 않도록 다음 사항을 확인하면서 외부 도구를 검토하세요.

* WordPress용 플러그인 같은 보안 플러그인이 Cloudflare IP 주소를 허용하는지 확인합니다.
* [ModSecurity](https://github.com/SpiderLabs/ModSecurity) 플러그인이 최신 상태인지 확인합니다.

### 추가 권장 사항

#### 추가 보호

원본 서버 보안 강화에 대한 추가 권장 사항은 [원본 서버 보호](/fundamentals/security/protect-your-origin-server/) 가이드를 참고하세요.

### Cloudflare IP 주소 사용자 지정

모든 프록시된 호스트 이름이 공유하는 Cloudflare IP 주소를 사용하고 싶지 않은 Enterprise 고객에게는 두 가지 대안이 있습니다.

* [**Bring Your Own IP (BYOIP)**](/byoip/): Cloudflare가 고객의 IP(임대 또는 소유한 IP 주소 범위)를 모든 [로케이션](https://www.cloudflare.com/network/)에서 광고합니다.
* **정적 IP 주소**: Cloudflare가 도메인에 정적 IP 주소를 설정합니다. 자세한 내용은 계정 팀에 문의하세요.

Business 및 Enterprise 고객은 [Custom SSL 인증서 업로드](/ssl/edge-certificates/custom-certificates/)를 통해 도메인이 다른 Cloudflare 고객 도메인과 공유하는 Cloudflare IP 수를 줄일 수도 있습니다.

### IP 범위 업데이트

Cloudflare의 IP 범위는 자주 바뀌지 않습니다. 변경이 발생하면 프로덕션에 적용되기 전에 [IP 범위 목록](https://www.cloudflare.com/en-in/ips/)에 먼저 추가됩니다. Cloudflare API를 사용해 구성을 프로그래밍 방식으로 최신 상태로 유지할 수도 있습니다.
