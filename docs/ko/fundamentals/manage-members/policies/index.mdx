정책은 특정 사용자가 계정이나 도메인에 대해 어떤 접근 권한을 가지는지 정의하며, 다음 세 부분으로 구성됩니다.

1. actor(사용자)
2. `ResourceGroup`(범위)
3. `PermissionGroup`(역할)

계정 멤버는 가장 적절한 접근 수준을 표현하기 위해 이러한 정책을 하나 이상 가질 수 있습니다. 멤버의 실효 권한은 직접 할당되었든 그룹 멤버십을 통해 상속되었든, 자신에게 할당된 모든 정책의 합집합입니다.

Cloudflare 역할 시스템의 사용성과 유연성을 높이기 위해 API가 변경되어 이러한 기본 데이터 원칙을 노출하고 사용자가 직접 상호작용할 수 있게 되었습니다.

예를 들어 하나의 계정 안에 프로덕션 도메인과 스테이징 도메인이 모두 있고, 어떤 사용자는 계정 전체를 볼 수 있어야 하면서도 프로덕션 도메인의 캐시를 비우고 스테이징 도메인은 구성할 수 있어야 한다면, 여러 정책을 할당하고 scope를 사용해 접근을 제어할 수 있습니다.

## 정책 관리

모든 계정에는 멤버에 접근할 수 있는 표준 API 엔드포인트 집합이 있으며, 최근에는 `resourceGroups`와 `PermissionGroups` 목록이 추가되어 기능이 향상되었습니다.

* `resourceGroup`은 정책이 적용되는 범위의 고유 식별자입니다.
* `permissionGroup`은 특정 정책에 할당된 역할 집합의 고유 식별자입니다.

자세한 내용은 [API 문서](/api/)를 참고하세요.

## 실효 권한 보기

Cloudflare는 멤버에게 권한을 직접 할당하는 방식과 [User Groups](/fundamentals/manage-members/user-groups/)를 통한 할당 방식을 모두 지원합니다. 멤버의 실효 권한은 누적식이며, 멤버에게 직접 부여된 모든 권한과 멤버가 속한 그룹을 통해 상속된 권한의 합집합입니다.

:::note
멤버의 전체 접근 권한을 이해하려면 **Members** 보기와 **User Groups** 보기를 모두 확인하세요.

- **Members** 보기에는 사용자에게 명시적으로 할당된 권한만 표시됩니다.
- [User Groups](/fundamentals/manage-members/user-groups/)를 통해 상속된 권한은 Members 페이지에 표시되지 않습니다. 이를 보려면 Groups 탭으로 이동해 사용자가 속한 그룹을 찾고, 각 그룹에 할당된 정책을 검토하세요.

Cloudflare는 향후 업데이트에서 이 보기를 통합하기 위해 적극적으로 개선 작업을 진행하고 있습니다.
:::
