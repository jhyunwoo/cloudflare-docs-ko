Cloudflare는 사용자 지정 이메일 도메인으로 로그인하는 모든 고객에게 SSO(단일 로그인)를 제공합니다. Cloudflare SSO 커넥터를 만들면 원하는 ID 공급자(IdP)를 사용해 Cloudflare 대시보드에 대한 SSO를 강제할 수 있습니다. SSO는 해당 이메일 도메인의 모든 사용자에게 적용됩니다.

## 사용 가능 여부

Cloudflare Dashboard SSO는 모든 플랜에서 무료로 사용할 수 있습니다.

<FeatureTable id="account.single_sign_on" />

## 사전 준비

1. 이메일 도메인을 직접 제어하고, 이를 검증하기 위한 TXT 레코드를 추가할 수 있어야 합니다.
   - `@gmail.com`과 같은 공용 이메일 제공업체는 허용되지 않습니다.
   - 해당 이메일 도메인을 사용하는 모든 사용자는 조직의 직원이어야 합니다. 예를 들어 `@harvard.edu` 같은 대학 도메인은 학생 이메일을 포함하므로 허용되지 않습니다.

2. Super Administrator여야 하며 Cloudflare API에 접근할 수 있어야 합니다.

3. 어떤 구독 등급이든(Free 포함) Cloudflare Zero Trust 조직이 생성되어 있어야 합니다. 설정 방법은 [Cloudflare Zero Trust 조직 만들기](/cloudflare-one/setup/#create-a-zero-trust-organization)를 참고하세요.

## 1. IdP 설정

[상세 안내](/cloudflare-one/integrations/identity-providers/)에 따라 Cloudflare Zero Trust에 IdP를 추가하세요.

IdP를 구성한 뒤에는 반드시 [IdP를 테스트](/cloudflare-one/integrations/identity-providers/#test-idps-in-cloudflare-one)하세요.

## 2. SSO용 Cloudflare 도메인 등록

:::caution
`SSO Connector Edit` 역할이 있는 [Account API 토큰](/fundamentals/api/get-started/create-token/)을 만들어 안전하게 보관해야 합니다. 이는 나중에 IdP 구성 변경 등으로 실수로 잠겨 버렸을 때 API를 통해 SSO를 비활성화할 수 있는 백업 수단이 됩니다.
:::

<Tabs syncKey="dashPlusAPI">
<TabItem label="Dashboard">

1. Cloudflare One에서 IdP 구성을 마쳤다면 **Members** 페이지로 이동해 SSO 커넥터를 관리합니다.

<DashButton url="/?to=/:account/members" />

2. 1단계가 성공했다면 새 SSO 도메인을 추가하는 버튼이 표시됩니다. 이 버튼을 선택해 새 SSO 도메인 추가 절차를 시작합니다.

![SSO 커넥터 생성 모달 스크린샷](~/assets/images/fundamentals/members/sso/create_modal.png)

3. 이메일 도메인을 입력하고 **Create**를 선택해 검증 단계로 이동합니다.

:::note
`.edu`와 같은 일부 최상위 도메인은 SSO 도메인으로 사용할 수 없습니다.
:::

</TabItem>
<TabItem label="API">

이미 `SSO Connector Edit` 권한이 있는 사용자 또는 계정 API 토큰을 `CLOUDFLARE_API_TOKEN` 환경 변수로 설정한 명령줄 터미널에서, 다음 명령을 실행해 SSO 커넥터를 만듭니다. `{account_id}`는 계정 ID로, `{domain}`은 이메일 도메인으로 바꾸세요.

```bash title="cURL command"
curl "https://api.cloudflare.com/client/v4/accounts/{account_id}/sso_connectors" \
  --request POST \
  --header "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
  --json '{"email_domain":"{domain}"}'
```

## 3. 도메인 소유권 검증

<Tabs syncKey="dashPlusAPI">
<TabItem label="Dashboard">

DNS 레코드를 바로 변경할 수 없다면 나중에 검증하는 옵션을 사용할 수 있습니다. 검증 프로세스는 목록에서 해당 커넥터의 작업 메뉴를 통해 수동으로 시작할 수 있습니다.

![SSO 커넥터 검증 모달 스크린샷](~/assets/images/fundamentals/members/sso/verify_modal.png)

검증 코드를 복사한 뒤, 그 값을 사용해 DNS 구성에 TXT 레코드를 만드세요. 레코드에는 `cloudflare_dashboard_sso=` 접두사를 포함한 전체 텍스트가 모두 들어가야 합니다.

Cloudflare는 이 DNS 레코드를 찾을 때까지 또는 이틀 안에 시간 초과가 발생할 때까지 자동으로 폴링합니다.

시간 초과로 검증에 실패했다면 목록에서 해당 커넥터의 작업 메뉴에서 **Begin verification**을 선택해 폴링을 수동으로 다시 시작할 수 있습니다.

</TabItem>
<TabItem label="API">

검증 코드(예: `cloudflare_dashboard_sso=1111111`)를 복사한 뒤, 그 값을 사용해 DNS 구성에 `TXT` 레코드를 만드세요. DNS 레코드가 올바르게 설정되었는지 테스트하려면 `dig` 명령으로 이메일 도메인을 조회할 수 있습니다.

```sh
dig cool.cats TXT +short
```

```sh output
"cloudflare_dashboard_sso=111111111"
```

`TXT` 레코드에는 숫자 코드와 함께 `cloudflare_dashboard_sso=` 접두사가 반드시 포함되어야 합니다.

Cloudflare는 이 DNS 레코드를 찾을 때까지 또는 이틀 안에 시간 초과가 발생할 때까지 자동으로 폴링합니다. 시간 초과로 검증에 실패했다면 아래 명령으로 폴링을 수동으로 다시 시작할 수 있습니다.

```bash title="cURL command"
curl "https://api.cloudflare.com/client/v4/accounts/{account_id}/sso_connectors/{sso_connector_id}/begin_verification" \
  --request POST \
  --header "Authorization: Bearer $CLOUDFLARE_API_TOKEN"
```

</TabItem>
</Tabs>

검증 프로세스가 완료되거나 시간 초과되면 검증 결과에 대한 이메일 알림을 받게 됩니다.

## 4. 대시보드 SSO 활성화

:::caution
이메일 도메인(예: `@mycompany.com`)에 대해 Cloudflare Dashboard SSO를 활성화하면, 해당 도메인을 사용하는 모든 사용자에게 전역적으로 적용됩니다. 그 사용자가 어떤 계정에 접근할 수 있는지와 관계없이, 모두 지정한 ID 공급자를 통해 인증해야 합니다. 여기에는 해당 도메인이 SSO용으로 구성되기 전에 Cloudflare에 등록된 사용자도 포함됩니다.
:::

검증 프로세스가 완료되어 도메인 소유권이 성공적으로 확인되면 커넥터를 활성화할 수 있습니다.

이미 다른 계정의 활성 커넥터와 연결된 도메인은 이전 계정에서 비활성화되기 전까지 새 계정에서 활성화할 수 없습니다.

<Tabs syncKey="dashPlusAPI">
<TabItem label="Dashboard">

목록에서 해당 커넥터의 Actions 메뉴에서 **Enable**을 선택해 커넥터를 활성화합니다.

![SSO 커넥터 활성화 버튼 스크린샷](~/assets/images/fundamentals/members/sso/verified_domain.png)

</TabItem>
<TabItem label="API">

아래 명령을 실행해 커넥터를 활성화하세요. 다시 말해 `{account_id}`는 계정 ID로 바꾸고, 추가로 `{sso_connector_id}`는 이전 호출 응답의 `id` 필드에서 얻은 값으로 바꿔야 합니다.

```bash title="cURL command"
curl "https://api.cloudflare.com/client/v4/accounts/{account_id}/sso_connectors/{sso_connector_id}" \
  --request PATCH \
  --header "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
  --json '{"enabled": true}'
```

</TabItem>
</Tabs>

## 제한 사항

Cloudflare dashboard SSO는 다음을 지원하지 않습니다.

- `example+2@domain.com` 같은 plus addressing 이메일을 사용하는 사용자. 이런 사용자가 조직에 추가되어 있다면 SSO로 로그인할 수 없습니다.
- SSO 도메인 정책과 일치하지 않는 별도의 이메일 기반 정책을 Zero Trust SSO 애플리케이션에 추가하는 것
- 여러 개의 Zero Trust 도메인 정책. 다른 도메인 정책이 필요하다면 다른 SSO 커넥터를 만들 수 있으며, 그러면 SSO 애플리케이션에 새 도메인용 두 번째 정책이 생성됩니다.
- 자동 생성된 Zero Trust `allow email domain` 정책 삭제. 이 정책을 삭제하면 조직 관리자들이 Cloudflare 대시보드에 접근할 수 없게 됩니다.

## IdP 시작형 SSO

Cloudflare dashboard SSO는 ID 공급자(IdP)에서 시작하는 로그인을 지원하며, 구성은 사용하는 ID 공급자에서 가능합니다.

현재 단계별 가이드는 Okta에 대해 제공되며, 사용자 지정 SSO 엔드포인트를 지원하는 다른 ID 공급자에서도 유사하게 구성할 수 있습니다.

### Okta

Cloudflare Zero Trust와 Okta를 사용해 ID 공급자(IdP) 시작형 SSO 세션을 구성합니다.

<a id="prerequisites-1"></a>
#### 사전 준비

1. [Cloudflare One](https://one.dash.cloudflare.com/)에서 **Access controls** > **Applications**로 이동한 뒤 **SSO App**을 선택합니다.
2. **Configure**를 선택해 애플리케이션 설정에 접근합니다.
3. **Basic Information** 섹션에서 **SSO Endpoint URL**과 **Access Entity ID or Issuer**를 복사합니다. 이 값은 IdP 설정에 필요합니다.

#### Okta를 IdP로 구성

1. [Okta Admin Dashboard](https://login.okta.com/)에 로그인한 뒤 **Applications** > **Applications**로 이동합니다.
2. **Create App Integration**을 선택해 IdP 시작형 SSO 흐름을 처리할 새 SAML 통합을 시작합니다.
3. 팝업에서 **SAML 2.0**을 선택한 뒤 **Next**를 선택합니다.
4. 앱 이름을 입력하고 **Next**를 선택합니다.
5. **Single Sign-On URL** 필드에 [앞에서 복사한](/fundamentals/manage-members/dashboard-sso/#prerequisites-1) **SSO Endpoint URL**을 붙여넣습니다.
6. **Audience URI (SP Entity ID)** 필드에 [앞에서 복사한](/fundamentals/manage-members/dashboard-sso/#prerequisites-1) **Access Entity ID or Issuer**를 붙여넣습니다.
7. **Name ID Format**을 **EmailAddress**로 설정합니다.
8. **Application Username**을 **Email**로 설정합니다.
9. **Next** > **Finish**를 선택해 통합을 저장합니다.
10. Okta User Dashboard에서 새 앱 타일을 찾아 선택해 SSO 흐름을 검증합니다.

**(선택 사항) Instant Auth로 단일 IdP 로그인 강제**

Cloudflare SSO에 하나의 IdP(예: Okta)만 사용하고, 사용자가 ID 공급자 선택 프롬프트를 건너뛰도록 하려면 다음을 수행하세요.

1. [Cloudflare One](https://one.dash.cloudflare.com/)에서 **Access controls** > **Applications**로 이동한 뒤 **SSO App**을 선택합니다.
2. **Login methods**로 이동합니다.
3. **Accept all available identity providers**를 비활성화하고 로그인 방법으로 Okta만 선택되어 있는지 확인합니다.
4. **Instant Auth**를 활성화해 사용자가 ID 공급자 선택을 건너뛸 수 있게 합니다.

## 대시보드 SSO 우회

이 섹션에서는 SSO로 로그인할 수 없을 때 Cloudflare 대시보드 접근 권한을 복구하는 방법을 설명합니다.

### 옵션 1: 백업 IdP 추가

SSO IdP 제공업체에 문제가 있는 경우 API를 사용해 대체 IdP를 추가할 수 있습니다. 다음 예시는 [Cloudflare One-time PIN](/cloudflare-one/integrations/identity-providers/one-time-pin/)을 로그인 방법으로 추가하는 방법을 보여줍니다.

1. [One-time PIN 로그인 추가](/api/resources/zero_trust/subresources/identity_providers/methods/create/):

   <APIRequest
   	path="/accounts/{account_id}/access/identity_providers"
   	method="POST"
   	json={{
   		type: "onetimepin",
   		config: {},
   	}}
   />

2. `dash_sso` Access 애플리케이션의 `id`를 [조회](/api/resources/zero_trust/subresources/access/subresources/applications/methods/list/)합니다. 올바른 애플리케이션을 빠르게 찾으려면 [`jq`](https://jqlang.github.io/jq/download/)를 사용할 수 있습니다.

   ```bash title="cURL command"
   curl "https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/access/apps" \
     --header "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
     | jq '.result[] | select(.type == "dash_sso")'
   ```

   ```json output {2}
   {
   	"id": "3537a672-e4d8-4d89-aab9-26cb622918a1",
   	"uid": "3537a672-e4d8-4d89-aab9-26cb622918a1",
   	"type": "dash_sso",
   	"name": "SSO App"
   	// ...
   }
   ```

3. 위에서 얻은 `id`를 사용해 [**SSO App**을 업데이트](/api/resources/zero_trust/subresources/access/subresources/applications/methods/update/)하여 모든 ID 공급자를 허용하도록 합니다. 기존 구성을 덮어쓰지 않으려면 PUT 요청 본문에 이전 GET 요청에서 반환된 모든 필드를 포함해야 합니다.

   <APIRequest
   	path="/accounts/{account_id}/access/apps/{app_id}"
   	method="PUT"
   	parameters={{ app_id: "3537a672-e4d8-4d89-aab9-26cb622918a1" }}
   	json={{
   		id: "3537a672-e4d8-4d89-aab9-26cb622918a1",
   		uid: "3537a672-e4d8-4d89-aab9-26cb622918a1",
   		type: "dash_sso",
   		name: "SSO App",
   		allowed_idps: [],
   		// ... (other existing properties)
   	}}
   	code={{
   		mark: [9],
   	}}
   />

이제 사용자는 one-time PIN으로 로그인할 수 있습니다.

### 옵션 2: 대시보드 SSO 비활성화

:::caution
SSO를 비활성화하기 전에 Cloudflare 사용자 이메일에 접근할 수 있는지 확인하세요. 그래야 Cloudflare 대시보드에서 로그아웃되더라도 비밀번호를 재설정할 수 있습니다.
:::

<Tabs syncKey="dashPlusAPI">
<TabItem label="Dashboard">

1. **Members** 페이지로 이동합니다.

<DashButton url="/?to=/:account/members" />

2. **Settings**로 이동합니다.
3. 목록에서 SSO 커넥터의 작업 메뉴를 열고 **Disable**을 선택합니다.

4. 커넥터의 도메인을 입력하고 확인을 클릭해 비활성화를 완료합니다.

</TabItem>
<TabItem label="API">

아래 API 호출은 계정에 대한 SSO 강제를 비활성화합니다. 이 작업은 `SSO connectors edit` 역할이 있는 API 토큰 또는 Super Administrator만 수행할 수 있습니다.

1. SSO 커넥터 `id`를 조회합니다.

   ```bash title="cURL command"
   curl "https://api.cloudflare.com/client/v4/accounts/{account_id}/sso_connectors" \
     --request GET \
     --header "Authorization: Bearer $CLOUDFLARE_API_TOKEN"
   ```

   ```json output
   {
   	"result": [
   		{
   			"id": "d616ac82cc7f87153112d75a711c5c3c",
   			"email_domain": "cool.cats",

   			// ...
   		}
   	],
   	"success": true,
   	"errors": [],
   	"messages": []
   }
   ```

2. SSO 커넥터를 비활성화합니다.

   ```bash title="cURL command"
   curl "https://api.cloudflare.com/client/v4/accounts/{account_id}/sso_connectors/{connector_id}" \
     --request PATCH \
     --header "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
     --json '{
       "enabled": false
     }'
   ```

   ```json output
   {
   	"result": [
   		{
   			"id": "d616ac82cc7f87153112d75a711c5c3c",
   			"email_domain": "cool.cats",
   			"enabled": false
   			// ...
   		}
   	],
   	"success": true,
   	"errors": [],
   	"messages": []
   }
   ```

</TabItem>
</Tabs>

이제 사용자는 Cloudflare 계정 이메일과 비밀번호로 로그인할 수 있습니다. 사용자가 비밀번호를 모른다면 로그인 페이지의 [비밀번호를 잊으셨나요](/fundamentals/user-profiles/change-password-or-email/#forgot-your-password) 절차를 사용해 새 비밀번호를 만들 수 있습니다.

## Zero Trust 팀 이름 변경

SSO 커넥터가 생성된 상태에서는 <GlossaryTooltip term="team name">팀 이름</GlossaryTooltip>을 변경할 수 없습니다. 팀 이름을 바꾸려면 모든 SSO 커넥터를 비활성화하고 삭제해야 합니다.

<Tabs syncKey="dashPlusAPI">
<TabItem label="Dashboard">

1. **Members** 페이지로 이동합니다.

<DashButton url="/?to=/:account/members" />

2. **Settings**로 이동합니다.
3. 모든 SSO 커넥터를 비활성화합니다.
4. 모든 SSO 커넥터를 삭제합니다.

</TabItem>
<TabItem label="API">

1. 계정의 모든 SSO 커넥터를 가져옵니다.

   ```bash title="cURL command"
   curl "https://api.cloudflare.com/client/v4/accounts/{account_id}/sso_connectors" \
     --request GET \
     --header "Authorization: Bearer $CLOUDFLARE_API_TOKEN"
   ```

2. 이전 단계에서 얻은 각 커넥터의 `id`를 사용해 활성 SSO 커넥터를 비활성화합니다.

   ```bash title="cURL command"
   curl "https://api.cloudflare.com/client/v4/accounts/{account_id}/sso_connectors/{connector_id}" \
     --request PATCH \
     --header "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
     --json '{
       "enabled": false
     }'
   ```

3. 이전 단계에서 얻은 각 커넥터의 `id`를 사용해 모든 SSO 커넥터를 삭제합니다.

   ```bash title="cURL command"
   curl "https://api.cloudflare.com/client/v4/accounts/{account_id}/sso_connectors/{connector_id}" \
     --request DELETE \
     --header "Authorization: Bearer $CLOUDFLARE_API_TOKEN"
   ```

</TabItem>
</Tabs>

4. [Cloudflare One](https://one.dash.cloudflare.com/)에서 **Reusable components** > **Custom pages**로 이동합니다.
5. **Team domain** 아래에서 **Edit**를 선택해 새 팀 이름을 입력하고 **Save**를 선택합니다.
6. ID 공급자에서 새 팀 이름으로 Cloudflare 통합을 업데이트합니다. 예를 들어 SAML IdP를 사용 중이라면 Single Sign-on URL과 Entity ID를 `https://<new-team-name>.cloudflareaccess.com/cdn-cgi/access/callback`으로 업데이트해야 합니다.
7. [SSO용 Cloudflare 도메인 등록](/fundamentals/manage-members/dashboard-sso/#2-register-your-domain-with-cloudflare-for-sso)의 단계에 따라 삭제한 SSO 커넥터를 다시 만듭니다.
8. 커넥터를 다시 만든 뒤 검증 및 활성화 단계를 수행합니다.
