시간열을 위치, 기간 등으로 비교할 때 [min-max](/radar/concepts/normalization)를 사용해 값을 정규화하는 엔드포인트에서는 반드시 같은 요청 안에서 비교해야 합니다. 이는 여러 개의 series를 요청하는 방식으로 수행합니다. 그러면 모든 값이 동일한 최소값과 최대값을 사용해 정규화되므로 서로 안전하게 비교할 수 있습니다.

[NetFlows](/radar/investigate/netflows) 값은 [min0-max](/radar/concepts/normalization)로 정규화되므로, 여기서는 이를 예시로 사용하겠습니다. 자세한 내용은 [Get NetFlow time series](/api/resources/radar/subresources/netflows/methods/timeseries/) 엔드포인트를 참고하세요.

## 위치 비교

다음 예제에서는 미국과 포르투갈이라는 두 서로 다른 위치의 트래픽 변화를 비교합니다. 예제에서는 최근 7일 동안의 [alpha-2 코드](https://en.wikipedia.org/wiki/ISO_3166-1_alpha-2#Officially_assigned_code_elements)를 사용합니다.

```bash
curl "https://api.cloudflare.com/client/v4/radar/netflows/timeseries?name=us_data&dateRange=7d&location=US&name=pt_data&dateRange=7d&location=PT&format=json" \
--header "Authorization: Bearer <API_TOKEN>"
```

위 예제에서는 두 개의 timeseries를 요청하고 있습니다. 첫 번째 series는 다음 파라미터를 가집니다.

`name=us_data&dateRange=7d&location=US`

두 번째 series는 다음 파라미터를 가집니다.

`name=pt_data&dateRange=7d&location=PT`

이 파라미터들은 모두 배열이며, 배열 내 위치가 해당 필터가 어느 series에 속하는지를 결정합니다. 사용 가능한 파라미터에 대한 자세한 내용은 [NetFlow 엔드포인트](/api/resources/radar/subresources/netflows/methods/timeseries/)를 참고하세요.

응답은 아래처럼 간략히 줄여 보여 주는 형태로, 제공된 `name` 속성을 사용해 타임스탬프와 해당 값을 감쌉니다. 이 데이터를 차트로 그려 보면, Cloudflare가 포르투갈보다 미국에서 훨씬 더 적은 트래픽을 수신한 것이 아니라 훨씬 더 많은 트래픽을 수신했다는 점이 분명해집니다.

```json
{
  "success": true,
  "errors": [],
  "result": {
    "us_data": {
      "timestamps": [ "2022-10-26T17:00:00Z", "2022-11-02T15:00:00Z" ],
      "values": [ "0.871752", "1" ]
    },
    "pt_data": {
      "timestamps": [ "2022-10-26T17:00:00Z", "2022-11-02T15:00:00Z" ],
      "values": [ "0.020457", "0.012313" ]
    },
    "meta": {
      "dateRange": {
        "startTime": "2022-10-26T17:00:00Z",
        "endTime": "2022-11-02T17:00:00Z"
      },
      "aggInterval": "ONE_HOUR",
			// ...
    }
  }
}
```

비교는 `min-max`를 사용하는 엔드포인트에만 한정되지 않고, 대부분의 엔드포인트에서 수행할 수 있습니다.

## 기간 비교

다음 예제에서는 `7d`와 `7dControl` 단축 표기를 사용해 미국의 서로 다른 기간을 비교합니다. 각각 최근 7일과 그 직전의 7일을 의미하므로, 다시 말해 이번 주와 지난주를 비교하는 셈입니다.

```bash
curl "https://api.cloudflare.com/client/v4/radar/netflows/timeseries?name=this_week&dateRange=7d&location=US&name=previous_week&dateRange=7dControl&location=US&format=json" \
--header "Authorization: Bearer <API_TOKEN>"
```

첫 번째 series는 다음 파라미터를 가집니다.

`name=this_week&dateRange=7d&location=US`

두 번째 series는 다음 파라미터를 가집니다.

`name=previous_week&dateRange=7dControl&location=US`

이제 `result` 속성에서 다음과 유사한 결과를 얻을 수 있습니다.

```json
{
  "this_week": {
    "timestamps": [ "2022-10-27T13:00:00Z", "2022-10-27T14:00:00Z", "...", "2022-11-03T12:00:00Z" ],
    "values": [ "0.794321", "1", "...", "0.718433"]
  },
  "previous_week": {
    "timestamps": [ "2022-10-20T13:00:00Z", "2022-10-20T14:00:00Z", "...", "2022-10-27T12:00:00Z" ],
    "values": [ "0.774392", "0.835071", "...", "0.720181"]
  }
}
```

이 정보를 살펴보면 최대값이 `2022-10-27T14:00:00Z`에 도달했음을 알 수 있습니다. 모든 Radar 타임스탬프는 협정 세계시(UTC)를 사용합니다. 또한 이 요청이 실행된 시점에 `7d`와 `7dControl` 단축 기간이 실제로 어떤 범위로 해석되었는지도 확인할 수 있습니다.

### 특정 타임스탬프 사용

특정 타임스탬프를 직접 지정해서 요청할 수도 있습니다. 다음 예제에서는 장애가 있었던 2022년 1월과 10월의 [Tonga](https://blog.cloudflare.com/tonga-internet-outage/) 관련 데이터를 비교합니다.

```bash
curl "https://api.cloudflare.com/client/v4/radar/netflows/timeseries?name=tonga&dateStart=2022-10-15T02%3A00%3A00Z&dateEnd=2022-10-15T05%3A00%3A00Z&location=TO&name=tonga_outage&dateStart=2022-01-15T02%3A00%3A00Z&dateEnd=2022-01-15T05%3A00%3A00Z&location=TO&format=json&aggInterval=1h" \
--header "Authorization: Bearer <API_TOKEN>"
```

첫 번째 series는 다음 파라미터를 가집니다(URL 인코딩됨).

`name=tonga&dateStart=2022-10-15T02%3A00%3A00Z&dateEnd=2022-10-15T05%3A00%3A00Z%&location=TO`

두 번째 series는 다음 파라미터를 가집니다.

`name=tonga_outage&dateStart=2022-01-15T02%3A00%3A00Z&&dateEnd=2022-01-15T05%3A00%3A00Z&location=TO`

위 예제에서는 결과를 이 페이지에 표시할 수 있도록 [집계 간격](/radar/concepts/aggregation-intervals)으로 1시간(`aggInterval=1h`)을 요청했습니다. `format`과 `aggInterval`은 [API reference](/api/resources/radar/subresources/netflows/methods/timeseries/)에 명시된 대로 배열이 아니며, 요청에 포함된 모든 series에 전역으로 적용됩니다.

`result` 속성은 다음과 같은 응답을 반환해야 합니다.

```json
{
	"tonga": {
		"timestamps": ["2022-10-15T02:00:00Z", "2022-10-15T03:00:00Z", "2022-10-15T04:00:00Z", "2022-10-15T05:00:00Z"],
		"values": ["1.0", "0.832473", "0.820083", "0.79408"]
	},
	"tonga_outage": {
		"timestamps": ["2022-01-15T02:00:00Z", "2022-01-15T03:00:00Z", "2022-01-15T04:00:00Z", "2022-01-15T05:00:00Z"],
		"values": ["0.354105", "0.357287", "0.181811", "0.044198"]
	}
}
```

이 결과는 장애 기간 동안 트래픽이 거의 0에 가깝게 떨어졌음을 보여 줍니다. 이를 차트로 그리고 더 분명히 보기 위해 종료 날짜를 1월 18일로 설정하면 다음과 같은 형태가 됩니다.
