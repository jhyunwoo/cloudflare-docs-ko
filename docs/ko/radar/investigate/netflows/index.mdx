[NetFlows](https://en.wikipedia.org/wiki/NetFlow)는 Cloudflare edge router에서 수집한 최종 사용자 네트워크 트래픽 데이터를 보여줍니다. NetFlows 데이터는 [Internet traffic change](https://radar.cloudflare.com/) 차트에도 사용됩니다.

NetFlows에는 Cloudflare [CDN](https://www.cloudflare.com/en-gb/learning/cdn/what-is-a-cdn/)이 제공하는 웹사이트 트래픽뿐 아니라, Cloudflare router를 지나는 모든 유형의 트래픽이 포함됩니다.

## 엔드포인트 목록

### 시계열

#### 예시: product로 필터링

위치나 날짜 범위에 따라 시계열을 비교하는 것 외에도([Make comparisons](/radar/get-started/making-comparisons/) 참고), `product` 필터를 사용해 `ALL` 트래픽과 `HTTP` 트래픽만 따로 비교할 수 있습니다. 이 endpoint에 대한 자세한 내용은 [API reference](/api/resources/radar/subresources/netflows/methods/timeseries/)를 참고하세요.

:::note[NetFlow products]

`HTTP` 트래픽에는 Cloudflare zone으로 향하는 웹 트래픽만 포함되며, `ALL`에는 [Spectrum](/spectrum/), [Magic Transit](/magic-transit/), [1.1.1.1](/1.1.1.1/) 같은 다른 모든 서비스로 향하는 트래픽도 포함됩니다.
:::

다음 예제에서는 두 [autonomous systems](https://www.cloudflare.com/en-gb/learning/network-layer/what-is-an-autonomous-system/)의 `ALL` 및 `HTTP` 트래픽을 모두 살펴봅니다. 먼저 포르투갈의 로컬 Internet Service Provider (ISP)인 [AS3243](https://radar.cloudflare.com/as3243)를 살펴보겠습니다. 전체 트래픽에 대한 매개변수는 `name=AS3243_all&product=ALL&dateRange=1d&asn=3243`이고, HTTP 트래픽만 보려면 `name=AS3243_http&product=HTTP&dateRange=1d&asn=3243`입니다.

```bash
curl "https://api.cloudflare.com/client/v4/radar/netflows/timeseries?name=meo_all&product=ALL&dateRange=1d&asn=3243&name=meo_http&product=HTTP&dateRange=1d&asn=3243&format=json&aggInterval=1h" \
--header "Authorization: Bearer <API_TOKEN>"
```

응답을 축약하면 다음과 같습니다.

```json
{
  "success": true,
  "errors": [],
  "result": {
		"AS3243_all": {
			"timestamps": ["2022-11-08T14:00:00Z", "2022-11-08T15:00:00Z", "..."],
			"values": ["0.565885", "0.586434", "..."]
		},
		"AS3243_http": {
			"timestamps": ["2022-11-08T14:00:00Z", "2022-11-08T15:00:00Z", "..."],
			"values": ["0.548564", "0.568329", "..."]
		}
	}
}
```

`HTTP` 트래픽 값은 `ALL` 트래픽 값과 비슷합니다. 이는 Cloudflare가 이 AS로부터 받는 대부분의 트래픽이 Cloudflare [CDN](https://www.cloudflare.com/en-gb/learning/cdn/what-is-a-cdn/) 제품이 제공하는 웹사이트 트래픽임을 의미합니다.

다음 예제에서는 ISP가 아닌 다른 autonomous system인 [AS174](https://radar.cloudflare.com/as174)를 살펴보겠습니다.

```bash
curl "https://api.cloudflare.com/client/v4/radar/netflows/timeseries?name=AS174_all&product=ALL&dateRange=1d&asn=174&name=AS174_http&product=HTTP&dateRange=1d&asn=174&format=json&aggInterval=1h" \
--header "Authorization: Bearer <API_TOKEN>"
```

축약된 응답은 다음과 같습니다.

```json
{
  "success": true,
  "errors": [],
  "result": {
		"AS174_all": {
			"timestamps": ["2022-11-08T14:00:00Z", "2022-11-08T15:00:00Z", "..."],
			"values": ["0.917348", "1.0", "..."]
		},
		"AS174_http": {
			"timestamps": ["2022-11-08T14:00:00Z", "2022-11-08T15:00:00Z", "..."],
			"values": ["0.381777", "0.408091", "..."]
		}
	}
}
```

여기서는 다른 유형의 트래픽에 비해 `HTTP` 트래픽이 더 적습니다. 이 AS는 최종 사용자에게 서비스를 제공하는 ISP가 아니기 때문에 자연스러운 결과입니다.

이 예제에서는 각 AS에서 `HTTP`가 트래픽의 대다수를 차지하는지 여부만 관심이 있으므로 두 개의 개별 요청을 보냈습니다. 하지만 예를 들어 누가 더 많은 트래픽을 보유하는지처럼 실제로 트래픽 값을 [compare](/radar/get-started/making-comparisons/)하려면, 모든 series를 포함한 단일 요청을 보내야 합니다. 예를 들면 다음과 같습니다.

```bash
curl "https://api.cloudflare.com/client/v4/radar/netflows/timeseries?name=AS174_all&product=ALL&dateRange=1d&asn=174&name=AS174_http&product=HTTP&dateRange=1d&asn=174&name=AS3243_all&product=ALL&dateRange=1d&asn=3243&name=AS3243_http&product=HTTP&dateRange=1d&asn=3243&format=json&aggInterval=1h" \
--header "Authorization: Bearer <API_TOKEN>"
```

이 경우 응답은 다음과 비슷합니다.

```json
{
  "success": true,
  "errors": [],
  "result": {
		"AS174_all": {
			"timestamps": ["2022-11-08T14:00:00Z", "2022-11-08T15:00:00Z", "..."],
			"values": ["0.917348", "1.0", "..."]
		},
		"AS174_http": {
			"timestamps": ["2022-11-08T14:00:00Z", "2022-11-08T15:00:00Z", "..."],
			"values": ["0.381777", "0.408091", "..."]
		},
		"AS3243_all": {
			"timestamps": ["2022-11-08T14:00:00Z", "2022-11-08T15:00:00Z", "..."],
			"values": ["0.317136", "0.328652", "..."]
		},
		"AS3243_http": {
			"timestamps": ["2022-11-08T14:00:00Z", "2022-11-08T15:00:00Z", "..."],
			"values": ["0.307429", "0.318505", "..."]
		}
	}
}
```

이 응답은 Cloudflare가 AS3243보다 AS174로부터 더 많은 트래픽을 받는다는 점을 보여줍니다.
