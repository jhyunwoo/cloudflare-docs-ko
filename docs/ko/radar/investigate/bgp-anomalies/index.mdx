Cloudflare Radar의 BGP 이상 징후 탐지 결과에 접근하려면 먼저 `Account:Radar` 권한이 포함된 API token을 만들어야 합니다. 아래 예시는 모두 무료 등급 Cloudflare 계정에서도 동작합니다.

## BGP hijack event 검색

다음 예시에서는 `AS64512`(예시 ASN)에서 발생했거나 `AS64512`에 영향을 미친 가장 최근의 BGP origin hijack을 조회하기 위해 [BGP hijack events API][hijack-api-doc]를 호출합니다.

```bash
curl "https://api.cloudflare.com/client/v4/radar/bgp/hijacks/events?invlovedAsn=64512&format=json&per_page=10" \
--header "Authorization: Bearer <API_TOKEN>"
```

결과는 `AS64512`에 영향을 주는 가장 최근 10개의 BGP hijack event를 보여줍니다.

```json
{
  "success": true,
  "errors": [],
  "result": {
    "asn_info": [
      {
        "asn": 64512,
        "org_name": "XXXXX",
        "country_code": "XX"
      },
      ...
    ],
    "events": [
      {
        "duration": 0,
        "event_type": 0,
        "hijack_msgs_count": 1,
        "hijacker_asn": 64512,
        "id": 1234,
        "is_stale": false,
        "max_hijack_ts": "2023-04-27T14:01:55.952",
        "max_msg_ts": "2023-04-27T14:01:55.952",
        "min_hijack_ts": "2023-04-27T14:01:55.952",
        "on_going_count": 1,
        "peer_asns": [
          8455
        ],
        "peer_ip_count": 1,
        "prefixes": [
          "192.0.2.0/24"
        ],
        "tags": [
          {
            "name": "irr_new_origin_invalid",
            "score": 4
          },
          {
            "name": "irr_old_origin_valid",
            "score": 0
          },
          ...
        ],
        "victim_asns": [
          64513
        ],
        "confidence_score": 4
      },
    ],
    "total_monitors": 163
  },
  ...
}
```

응답을 통해 각 event에 대해 다음 정보를 확인할 수 있습니다.

- `hijack_msg_count`: 모든 peer에서 관측된 잠재적 BGP hijack 메시지 수
- `peer_asns`: hijack 메시지를 관측한 route collector peer의 AS 번호
- `prefixes`: 영향을 받은 prefix
- `hijacker_asn` 및 `victim_asns`: 잠재적 hijacker ASN과 피해 ASN
- `confidence_score`: 이 event가 hijack일 가능성에 대해 시스템이 얼마나 확신하는지를 나타내는 정량 점수
  - 1-3: 낮은 확신
  - 4-7: 중간 확신
  - 8-above: 높은 확신
- `tags`: event에 대해 수집된 근거. 각 `tag`에는 전체 confidence score에 영향을 주는 점수도 연결됩니다.
  - 양수 점수는 해당 event가 hijack일 _가능성이 더 높음_ 을 뜻합니다.
  - 음수 점수는 해당 event가 hijack일 _가능성이 더 낮음_ 을 뜻합니다.

사용자는 `minConfidence=8` 파라미터를 추가해 낮은 확신의 event를 제외할 수 있습니다. 그러면 `confidence_score`가 `8` 이상인 event만 반환됩니다.

```bash
curl "https://api.cloudflare.com/client/v4/radar/bgp/hijacks/events?invlovedAsn=64512&format=json&per_page=10&minConfidence=8" \
--header "Authorization: Bearer <API_TOKEN>"
```

## BGP route leak event 검색

BGP route leak는 Cloudflare Radar가 탐지하는 또 다른 유형의 BGP 이상 징후입니다. 현재는 특히 `provider-customer-provider` 유형의 route leak 탐지에 집중하고 있습니다. 설계와 방법론에 대한 자세한 내용은 [블로그 글][route-leak-blog-post]을 참고하세요.

[route-leak-blog-post]: https://blog.cloudflare.com/route-leak-detection-with-cloudflare-radar/

다음 예시에서는 `AS64512`에 영향을 미치는 가장 최근의 BGP route leak event를 조회하기 위해 [BGP route leak events API][route-leak-api-doc]를 호출합니다.

```bash
curl "https://api.cloudflare.com/client/v4/radar/bgp/leaks/events?invlovedAsn=64512&format=json&per_page=10" \
--header "Authorization: Bearer <API_TOKEN>"
```

결과는 `AS64512`에 영향을 주는 가장 최근 10개의 BGP route leak event를 보여줍니다.

```json
{
  "success": true,
  "errors": [],
  "result": {
    "asn_info": [
      {
        "asn": 64512,
        "org_name": "XXXXXXX",
        "country_code": "XX"
      },
      ...
    ],
    "events": [
      {
        "detected_ts": "2023-04-21T23:10:06",
        "finished": false,
        "id": 1234,
        "leak_asn": 64512,
        "leak_count": 14,
        "leak_seg": [
          64514,
          64512,
          64513
        ],
        "leak_type": 1,
        "max_ts": "2023-04-21T23:10:56",
        "min_ts": "2023-04-21T23:09:46",
        "origin_count": 1,
        "peer_count": 13,
        "prefix_count": 1
      },
      ...
    ]
  },
  ...
}
```

응답을 통해 각 event에 대해 다음 정보를 확인할 수 있습니다.

- `leak_asn`: 누출을 일으킨 것으로 추정되는 AS
- `leak_seg`: 누출로 보이는 관측된 AS 경로 세그먼트
- `min_ts` 및 `max_ts`: 누출 announcement의 가장 이른 시각과 가장 늦은 시각
- `leak_count`: 관측된 BGP route leak announcement 총수
- `peer_count`: 누출을 관측한 route collector peer 수
- `prefix_count` 및 `origin_count`: 누출의 영향을 받은 prefix와 origin AS 수

## BGP hijack 경고 보내기

이 예시에서는 특정 ASN과 관련된 BGP hijack에 대해 webhook(Google Hangouts, Discord, Telegram 등)이나 email을 사용해 알림을 보내는 Cloudflare Workers 앱을 구축하는 방법을 보여줍니다.

플랫폼으로는 Cloudflare Workers를 사용하고, Cron Triggers로 새 알림을 주기적으로 확인합니다.

이 앱은 다음 작업을 수행해야 합니다.

- 주어진 API token으로 Cloudflare API를 호출합니다.
- Cloudflare KV를 조회해 어떤 event가 새로운지 확인합니다.
- 새 hijack에 대한 메시지를 구성하고 webhook trigger를 통해 경고를 보냅니다.

### Worker 앱 설정

먼저 Cloudflare Worker 앱을 설정합니다.

첫 단계로 로컬 디렉터리에 새 Workers 앱을 생성합니다.

<PackageManagers type="create" pkg="cloudflare@latest" args={"hijack-alerts"} />

<Render
	file="c3-post-run-steps"
	product="workers"
	params={{
		category: "hello-world",
		type: "Worker only",
		lang: "JavaScript",
	}}
/>

Worker 개발을 시작하려면 새 프로젝트 디렉터리로 `cd` 이동합니다.

```sh
cd hijack-alerts
```

Wrangler 파일에서 기본 확인 주기(한 시간에 한 번)를 원하는 값으로 바꿉니다. 아래는 5분마다 스크립트를 실행하도록 workers를 설정하는 예시입니다.

<WranglerConfig>

```jsonc
{
	"$schema": "./node_modules/wrangler/config-schema.json",
	"name": "hijack-alerts",
	"main": "src/index.js",
	"compatibility_date": "$today",
	"triggers": {
		"crons": [
			"*/5 * * * *"
		]
	}
}
```

</WranglerConfig>

이 예시에서는 최신으로 확인한 event ID를 저장해 어떤 event가 새로운지 알기 위해 Cloudflare KV도 사용합니다. KV를 생성한 후 `wrangler.jsonc` 파일로 돌아가 아래 섹션을 추가하세요.

<WranglerConfig>

```jsonc
{
	"kv_namespaces": [
		{
			"binding": "HIJACKS_KV",
			"id": "KV_ID_FOR_PRODUCTION",
			"preview_id": "TEMPORARY_KV_FOR_DEV_ENVIRONMENT"
		}
	]
}
```

</WranglerConfig>

### 새로 탐지된 BGP hijack 조회

먼저 API 호출 함수를 작성합니다.

다음 `apiFetch(env, paramsStr)`는 요청 파라미터 문자열을 받아 적절한 헤더를 구성한 뒤 Cloudflare API BGP hijacks 엔드포인트를 호출합니다.

```javascript
async function apiFetch(env, paramsStr) {
	const config = {
		headers: {
			Authorization: `Bearer ${env.CF_API_TOKEN}`,
		},
	};
	const res = await fetch(
		`https://api.cloudflare.com/client/v4/radar/bgp/hijacks/events?${paramsStr}`,
		config,
	);

	if (!res.ok) {
		console.log(JSON.stringify(res));
		return null;
	}
	return await res.json();
}
```

`env` 파라미터는 호출자에게서 전달되므로 직접 구성할 필요가 없습니다. `paramsStr`은 쿼리 URL에 들어갈 query parameter 문자열입니다.

이제 메인 cron trigger 함수에서 query parameter를 구성하고 API fetch 함수를 호출해야 합니다. 기본 cron trigger worker 스크립트는 다음과 같이 정의됩니다.

```javascript

export default {
    async scheduled(controller, env, ctx) {
    ...
    }
}
```

이 예시에서는 `env` 변수로 TOKEN, 관심 ASN, Cloudflare KV binding 같은 런타임 변수를 가져옵니다. 여기서는 `controller`와 `ctx` 변수를 사용하지 않습니다.

먼저 어떤 event가 새 event인지 알아야 합니다. 여기서는 앱이 아직 처리하지 않은 event를 새 event로 정의합니다. 앞서 만든 Cloudflare KV 버킷(`HIJACKS_KV`)을 사용해 가장 최근에 처리한 event ID를 저장하고 불러옵니다.

```javascript
let kv_latest_id = parseInt(await env.HIJACKS_KV.get("latest_id"));
const first_batch = isNaN(kv_latest_id);
```

가장 최근 event를 확인하는 메인 루프는 다음과 같습니다. 일부 검증 코드는 생략했습니다.

```javascript
let new_events = [];
let page = 1;
while (true) {
	// 이벤트 조회
	const query_params = `per_page=10&page=${page}&involvedAsn=${env.TARGET_ASN}&sortBy=ID&sortOrder=DESC`;
	const data = await apiFetch(env, query_params);

	// 첫 번째 배치라면 KV 값만 저장
	if (first_batch) {
		await env.HIJACKS_KV.put("latest_id", events[0].id.toString());
		return;
	}

	// 일부 검증은 생략
	// ...

	let reached_last = false;
	for (const event of data.result.events) {
		if (event.id <= kv_latest_id) {
			// 최신 이벤트에 도달함
			reached_last = true;
			break;
		}
		new_events.push(event);
	}
	if (reached_last) {
		break;
	}
	page += 1;
}
```

이제 새로 탐지된 event가 `new_events` 변수에 모두 저장되었으므로, 경고를 보낼 수 있습니다.

```javascript
// ID 오름차순으로 이벤트 정렬
new_events.sort((a, b) => a.id - b.id);
const kv_latest_id = new_events[new_events.length - 1].id;
// 새 이벤트 전송
for (const event of new_events) {
	await send_alert(env, event);
}
// latest_id KV 값 갱신
await env.HIJACKS_KV.put("latest_id", kv_latest_id.toString());
```

### webhook으로 알림 보내기

`send_alert` 함수는 경고 메시지를 구성하고 webhook을 사용해 알림을 전송합니다. 여기서는 Google Hangouts webhook을 사용하는 일반 텍스트 메시지 템플릿 예시를 보여줍니다. 사용자는 자신의 플랫폼과 필요에 맞게 메시지와 webhook 사용 방식을 자유롭게 조정할 수 있습니다.

```javascript
async function send_hangout_alert(env, event) {
	const webhook_url = `${env.WEBHOOK_URL}&threadKey=bgp-hijacks-event-${event.id}`;

	const data = JSON.stringify({
		text: `Detected BGP hijack event (${event.id}):
Detected time: *${event.min_hijack_ts} UTC*
Detected ASN: *${event.hijacker_asn}*
Expected ASN(s): *${event.victim_asns.join(" ")}*
Prefixes: *${event.prefixes.join(" ")}*
Tags: *${event.tags.map((tag) => tag.name).join(" ")}*
Peer Count: *${event.peer_ip_count}*
`,
	});
	await fetch(webhook_url, {
		method: "POST",
		headers: {
			"Content-Type": "application/json; charset=UTF-8",
		},
		body: data,
	});
}
```

webhook은 비밀 정보로 취급되므로 `wrangler secret put WEBHOOK_URL` 명령으로 환경에 설정해야 합니다.

마지막 단계는 `npx wrangler deploy` 명령으로 애플리케이션을 배포하는 것입니다. 그러면 앱이 Cloudflare 계정에서 실행되고 5분마다 트리거됩니다.

### Workers에서 email 알림 보내기

도메인에 [Email Routing][email-routing]이 활성화되어 있다면 Workers에서 직접 email 알림도 보낼 수 있습니다. 자세한 내용은 [Workers에서 email 보내기][email-workers-tutorial]를 참고하세요.

이 알림이 동작하려면 [Wrangler configuration file][wrangler-send-email]에 적절한 email binding을 설정해야 합니다.

<WranglerConfig>

```jsonc
{
	"send_email": [
		{
			"type": "send_email",
			"name": "SEND_EMAIL_BINDING",
			"destination_address": "<YOUR_EMAIL>@example.com"
		}
	]
}
```

</WranglerConfig>

그다음 구성한 destination address로 경고 email을 보내는 함수를 만들 수 있습니다.

```javascript
async function send_email_alert(hijacker, prefixes, victims) {
	const msg = createMimeMessage();
	msg.setSender({
		name: "BGP Hijack Alerter",
		addr: "<YOUR_APP>@<YOUR_APP_DOMAIN>",
	});
	msg.setRecipient("<YOUR_EMAIL>@example.com");
	msg.setSubject("BGP hijack alert");
	msg.addMessage({
		contentType: "text/plain",
		data: `BGP hijack detected:
    Detected origin: ${hijacker}
    Expected origins: ${victims.join(" ")}
    Prefixes: ${prefixes.join(" ")}
    `,
	});

	var message = new EmailMessage(
		"<YOUR_APP>@<YOUR_APP_DOMAIN>",
		"<YOUR_EMAIL>@example.com",
		msg.asRaw(),
	);
	try {
		await env.SEND_EMAIL_BINDING.send(message);
	} catch (e) {
		return new Response(e.message);
	}
}
```
