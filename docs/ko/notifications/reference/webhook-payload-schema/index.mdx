당신은[일반 webhook 구성](/notifications/get-started/configure-webhooks/#generic-webhooks)Cloudflare는 각 통보를 위한 당신의 지정된 URL에 JSON payload를 보냅니다. 이 문서는 그 페이로드의 구조입니다.

## Payload 구조

모든 일반 웹훅 알림이 schema를 따르십시오 :

```json
{
	"name": "string",
	"text": "string",
	"data": {},
	"ts": 1136214245,
	"account_id": "string",
	"policy_id": "string",
	"policy_name": "string",
	"alert_type": "string",
	"alert_correlation_id": "string",
	"alert_event": "string"
}
```

### 현장 설명

| 제품정보                   | 제품정보  | 이름 \*                                                       |
| ---------------------- | ----- | ----------------------------------------------------------- |
| `name`                 | 이름 \* | 알림 정책의 이름.                                                  |
| `text`                 | 이름 \* | 간헐적인 가치를 가진 알림의 인간 읽기 쉬운 묘사.                                |
| `data`                 | 기타 제품 | 경고 별 데이터. 구조가 변화합니다.`alert_type`.                           |
| `ts`                   | 뚱 베어  | 알림이 생성되었을 때 unix 타임스탬프 (seconds since epoch, UTC).          |
| `account_id`           | 이름 \* | 이 웹훅이 불화 된 계정 ID.                                           |
| `policy_id`            | 이름 \* | 이 웹훅을 트리거하는 알림 정책의 UUID.                                    |
| `policy_name`          | 이름 \* | 알림 정책의 이름.                                                  |
| `alert_type`           | 이름 \* | 경고 유형에 대한 독특한 식별자 (예를 들어,`http_alert_origin_error`).        |
| `alert_correlation_id` | 이름 \* | UUID 그룹 관련 경고를 함께합니다.                                       |
| `alert_event`          | 이름 \* | 이벤트 상태 등`ALERT_STATE_EVENT_START`또는`ALERT_STATE_EVENT_END`. |

:::참조
더 보기`account_id`, `policy_id`·`alert_type`필드는 alert type과 context에 따라 모든 알림에 표시되지 않을 수 있습니다.

## 웹훅 페이로드

당신은 사용할 수 있습니다`cf-webhook-auth`웹훅이 Cloudflare에서 있는지 확인하는 헤더. Cloudflare는 웹훅을 비밀로 구성할 때 모든 요청에서 비밀 값으로 이 헤더를 포함합니다. 이 헤더가 누락되거나 구성 된 비밀과 일치하지 않는 모든 요청을 거부합니다.
