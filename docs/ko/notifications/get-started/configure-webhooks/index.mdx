## 일반적인 webhooks

Cloudflare의 현재 유효한 webhooks에 의해 덮지 않는 서비스를 이용하는 경우에, 당신은 할 수 있습니다[자주 묻는 질문](#configure-webhooks), 그리고 유효한 webhook URL을 입력하십시오.

항상 일반 webhooks에 대한 비밀을 사용하는 것이 좋습니다. Cloudflare는 당신의 비밀을 안으로 보낼 것입니다`cf-webhook-auth`모든 요청의 헤더. 이 헤더가 존재하지 않는다면 지정된 값이 아닌 웹훅을 거부해야합니다.

선택 후**저장 및 테스트**, 웹훅은 이제 정책에 첨부 할 수있는 목적지로 구성해야합니다.

Cloudflare가 웹훅을 보낼 때 다음 스키마가 있습니다.

```json title="Example schema"
{
	"text": "Hello World! This is a test message sent from https://cloudflare.com. If you can see this, your webhook is configured properly."
}
```

다른 경고 유형에 대한 전체 페이로드 구조 및 예의 경우, 참조[webhook 페이로드 스키마 참고 자료](/notifications/reference/webhook-payload-schema/).

### 일반적인 webhooks의 제한

Cloudflare 일반적인 webhook 통보는 항구 80 또는 443에 대중적으로 resolvable IP 주소로만 파견될 것입니다.

개인 IP 주소 또는 다른 포트에서 일반 웹훅 알림을 받고 싶다면, 수신하고 알림을 전달할 수 있습니다.[모델 번호: Workers](/workers/)또는 설정[Cloudflare 갱도](/cloudflare-one/networks/connectors/cloudflare-tunnel/)연결 된 응용 프로그램에 대한 경로.

### Workers를 가진 일반적인 webhooks를 사용하십시오

Cloudflare Workers를 사용하여 일반적인 웹훅을 사용하여 웹훅을 수락하는 모든 서비스에 대한 알림을 제공 할 수 있습니다.

Cloudflare에는 있습니다[예제 도구](https://github.com/cloudflare/cf-webhook-relay/)당신이 사용할 수있는 방법을 이해하는 데 도움이[모델 번호: Workers](/workers/)그리고 일반적인 webhooks. 예를 들어, Rocket에 전달되기 위해 일반적인 webhook 응답을 변환합니다. 채팅. 제공된 코드는 크게 귀하의 필요에 맞는 예를 적용하는 과정에서 당신을 안내하는 것입니다.

### 비밀의 구성

Google Chat, Slack, Discord 또는 Feishu webhook을 만들 때 비밀은 URL의 일부입니다. URL에서 비밀을 제거하고 명시적으로 값을 설정할 수 있습니다.`secret`Cloudflare를 자동적으로 추출하는 보다는 오히려.

URL이 Cloudflare에 의해 수정되지 않기 때문에 Terraform을 사용하여 웹훅 인프라를 정의 할 때 유용합니다.

```tf title="Terraform example"
resource "cloudflare_notification_policy_webhooks" "example" {
  account_id = "<ACCOUNT_ID>"
  name       = "Slack Webhook"
  url        = "https://hooks.slack.com/services/T00000000/B00000000"
  secret     = "<secret>"
}
```
