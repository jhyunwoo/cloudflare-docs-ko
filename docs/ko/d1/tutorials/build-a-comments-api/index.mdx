SQL 파일을 통과 할 수 있습니다 - 단일 명령에서 초기 데이터 묘기를 위해 완벽합니다. 이름 \*`schemas/schema.sql`새로운 것`comments`당신의 프로젝트를 위한 테이블:

```sql
DROP TABLE IF EXISTS comments;
CREATE TABLE IF NOT EXISTS comments (
  id integer PRIMARY KEY AUTOINCREMENT,
  author text NOT NULL,
  body text NOT NULL,
  post_slug text NOT NULL
);
```

```sh

```

## 5. SQL 실행

초기 단계에서 SQL 데이터베이스를 생성하고 초기 데이터로 변환합니다. 이제 Workers 기능에 대한 경로를 추가하여 해당 데이터베이스에서 데이터를 검색합니다. 이전 단계에서 Wrangler 구성을 기반으로 D1 데이터베이스가 이제 액세스 할 수 있습니다.`DB`바인딩. 코드에서 SQL 문장을 준비하고, 예를 들어, 주석을 검색하기 위해 바인딩을 사용합니다.

```js
app.get("/api/posts/:slug/comments", async (c) => {
	const { slug } = c.req.param();
	const { results } = await c.env.DB.prepare(
		`
    select * from comments where post_slug = ?
  `,
	)
		.bind(slug)
		.run();
	return c.json(results);
});
```

위 코드의 사용`prepare`, `bind`·`run`D1 바인딩의 기능은 SQL 선언을 준비하고 실행합니다. 더 알아보기[D1 Workers 바인딩 API](/d1/worker-api/)사용 가능한 모든 방법 목록.

이 기능에서, 당신은 받아들입니다`slug`URL 쿼리 매개 변수를 설정하고 일치하는 모든 코멘트를 선택 새로운 SQL 문 설정`post_slug`쿼리 매개 변수에 값. JSON 응답으로 돌아갈 수 있습니다.

## 6. 삽입 자료

이전 단계 보조금은 데이터에 대한 읽기 전용 액세스. 데이터를 데이터베이스에 삽입하여 새로운 의견을 작성하려면 다른 엔드포인트를 정의하십시오.`src/worker.js`:

```js
app.post("/api/posts/:slug/comments", async (c) => {
	const { slug } = c.req.param();
	const { author, body } = await c.req.json();

	if (!author) return c.text("Missing author value for new comment");
	if (!body) return c.text("Missing body value for new comment");

	const { success } = await c.env.DB.prepare(
		`
    insert into comments (author, body, post_slug) values (?, ?, ?)
  `,
	)
		.bind(author, body, slug)
		.run();

	if (success) {
		c.status(201);
		return c.text("Created");
	} else {
		c.status(500);
		return c.text("Something went wrong");
	}
});
```

## 7. Hono 응용 프로그램을 배포

WranglerXQ를 사용하여 프로젝트를 Cloudflare 네트워크에 구축하고 배포합니다.

실행하기`wrangler whoami`Cloudflare 계정에 로그인했는지 확인하십시오. 로그인하지 않은 경우 Wrangler는 로그인하여 로컬 머신에서 자동으로 인증된 요청을 만들 수 있는 API 키를 생성합니다.

로그인한 후 Wrangler 파일이 아래와 같이 구성되어 있음을 확인합니다. 변경할 수 있습니다.`name`당신의 선택의 프로젝트 이름에 분야:

<WranglerConfig>
  ```jsonc
  {
  	"$schema": "./node_modules/wrangler/config-schema.json",
  	"name": "d1-example",
  	"main": "src/worker.js",
  	"compatibility_date": "$today",
  	"d1_databases": [
  		{
  			"binding": "DB", //env.DB에 있는 당신의 노동자에서 유효한
  			"database_name": "<YOUR_DATABASE_NAME>",
  			"database_id": "<YOUR_DATABASE_UUID>"
  		}
  	]
  }
  ```
</WranglerConfig>

지금, 실행`npx wrangler deploy`Cloudflare에 프로젝트를 배포합니다.

```sh
npx wrangler deploy
```

성공적으로 배포되면 API를 테스트하여`GET`관련 게시물에 대한 의견을 검색 할 수 있습니다. 아직 게시물이 없기 때문에이 응답은 비어있을 것입니다. 그러나 여전히 D1 데이터베이스에 대한 요청을 만들 것입니다. 이는 응용 프로그램이 올바르게 배포되었는지 확인하는 데 사용할 수 있습니다.

## 8. 선택적 frontend를 가진 시험

이 응용 프로그램은 API 백엔드, 만들기 및 보기 코멘트를 위한 프런트 엔드 UI와 함께 최고의 서비스를 제공합니다. prebuild front-end UI와 함께 이 백엔드를 테스트하려면, 예제 UI를 참조[example-frontend 디렉토리](https://github.com/cloudflare/workers-sdk/tree/main/templates/worker-d1-api/example-frontend). 확실히,[`loadComments`·`submitComment`제품정보](https://github.com/cloudflare/workers-sdk/tree/main/templates/worker-d1-api/example-frontend/src/views/PostView.vue#L57-L82)이 사이트의 배포 된 버전에 대한 요청을 작성, 의미 당신은 프론트엔드를 취할 수 있고이 튜토리얼에서 코드베이스의 배포 된 버전과 URL을 대체 할 수 있습니다 자신의 데이터를 사용합니다.

프론트엔드에서 이 API를 해석하면 특정 Cross-Origin Resource Sharing(또는*사이트맵*) 귀하의 백엔드 API의 헤더. Hono는 Cross-Origin Resource Sharing을 지원할 수 있습니다. 구매하기`cors`모듈과 API에 미들웨어로 추가`src/worker.js`:

```typescript null {5}
import { Hono } from "hono";
import { cors } from "hono/cors";

const app = new Hono();
app.use("/api/*", cors());
```

이제 요청을 할 때`/api/*`, Hono는 자동적으로 생성하고 당신의 API에서 응답에 CORS 우두머리를 추가할 것입니다, 과실 없이 상호 작용하는 front-end UIs를 허용하.
