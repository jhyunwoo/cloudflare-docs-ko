[D1 읽기 복제](/d1/best-practices/read-replication/)D1 데이터베이스를 여러 영역으로 복제할 수 있는 기능입니다. 이 전자 상거래 웹 사이트에 유용합니다, 그것은 읽는 latencies를 감소시키고 읽는 처리량을 개량하기 때문에. 이 튜토리얼에서 D1는 전자 상거래 웹 사이트에 대한 복제를 읽는 방법을 배울 것입니다.

이 튜토리얼은 소설 전자 상거래 웹 사이트를 사용하지만, 원칙은 뉴스 웹 사이트, 소셜 미디어 플랫폼, 또는 마케팅 웹 사이트와 같은 낮은 읽기 latencies 및 scaling 읽기를 필요로하는 모든 사용 케이스에 적용 할 수 있습니다.

## 단계 4: API 경로 만들기

업데이트`src/index.ts`Hono 라이브러리를 가져오고 API 경로를 만듭니다.

```ts
import { Hono } from "hono";
//쿠키에 db 세션 북마크 설정
import { getCookie, setCookie } from "hono/cookie";

const app = new Hono<{ Bindings: Env }>();

//모든 제품
app.get("/api/products", async (c) => {
	return c.json({ message: "get list of products" });
});

//단일 제품 얻기
app.get("/api/products/:id", async (c) => {
	return c.json({ message: "get a single product" });
});

//제품 업데이트
app.post("/api/product", async (c) => {
	return c.json({ message: "create or update a product" });
});

export default app;
```

위 코드는 세 가지 API 경로를 만듭니다.

- `GET /api/products`: 제품의 목록을 반환합니다.
- `GET /api/products/:id`: 단일 제품을 반환합니다.
- `POST /api/product`: 제품 생성 또는 업데이트.

그러나 API 경로는 D1 데이터베이스에 아직 연결되지 않습니다. 다음 단계에서 D1 데이터베이스에서 제품 테이블을 만들고 D1 데이터베이스에 연결하는 API 경로를 업데이트합니다.

## 5 단계 : 로컬 D1 데이터베이스 스키마 만들기

다음 명령을 실행하여 D1 데이터베이스에서 제품 테이블을 만듭니다.

```sh
npx wrangler d1 execute fast-commerce --command "CREATE TABLE IF NOT EXISTS products (id INTEGER PRIMARY KEY, name TEXT NOT NULL, description TEXT, price DECIMAL(10, 2) NOT NULL, inventory INTEGER NOT NULL DEFAULT 0, category TEXT NOT NULL, created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP, last_updated TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP)"
```

다음, 다음 명령을 실행하여 제품 테이블에 인덱스를 생성:

```sh
npx wrangler d1 execute fast-commerce --command "CREATE INDEX IF NOT EXISTS idx_products_id ON products (id)"
```

개발 목적으로 다음 명령을 실행하여 로컬 D1 데이터베이스에 삽입문을 실행할 수 있습니다.

```sh
npx wrangler d1 execute fast-commerce --command "INSERT INTO products (id, name, description, price, inventory, category) VALUES (1, 'Fast Ergonomic Chair', 'A comfortable chair for your home or office', 100.00, 10, 'Furniture'), (2, 'Fast Organic Cotton T-shirt', 'A comfortable t-shirt for your home or office', 20.00, 100, 'Clothing'), (3, 'Fast Wooden Desk', 'A wooden desk for your home or office', 150.00, 5, 'Furniture'), (4, 'Fast Leather Sofa', 'A leather sofa for your home or office', 300.00, 3, 'Furniture'), (5, 'Fast Organic Cotton T-shirt', 'A comfortable t-shirt for your home or office', 20.00, 100, 'Clothing')"
```

## 단계 6: retry 논리 추가

응용 프로그램을 더 탄력적으로 만들려면 API 경로에 재스트 논리를 추가 할 수 있습니다. 새 파일 만들기`retry.ts`내 계정`src`디렉토리.

```ts
export interface RetryConfig {
	maxRetries: number;
	initialDelay: number;
	maxDelay: number;
	backoffFactor: number;
}

const shouldRetry = (error: unknown): boolean => {
	const errMsg = error instanceof Error ? error.message : String(error);
	return (
		errMsg.includes("Network connection lost") ||
		errMsg.includes("storage caused object to be reset") ||
		errMsg.includes("reset because its code was updated")
	);
};

//잠을 위한 Helper 기능
const sleep = (ms: number): Promise<void> => {
	return new Promise((resolve) => setTimeout(resolve, ms));
};

export const defaultRetryConfig: RetryConfig = {
	maxRetries: 3,
	initialDelay: 100,
	maxDelay: 1000,
	backoffFactor: 2,
};

export async function withRetry<T>(
	operation: () => Promise<T>,
	config: Partial<RetryConfig> = defaultRetryConfig,
): Promise<T> {
	const maxRetries = config.maxRetries ?? defaultRetryConfig.maxRetries;
	const initialDelay = config.initialDelay ?? defaultRetryConfig.initialDelay;
	const maxDelay = config.maxDelay ?? defaultRetryConfig.maxDelay;
	const backoffFactor =
		config.backoffFactor ?? defaultRetryConfig.backoffFactor;

	let lastError: Error | unknown;
	let delay = initialDelay;

	for (let attempt = 0; attempt <= maxRetries; attempt++) {
		try {
			const result = await operation();
			return result;
		} catch (error) {
			lastError = error;

			if (!shouldRetry(error) || attempt === maxRetries) {
				throw error;
			}

			//동기화 retries를 방지하는 임의성을 추가하십시오
			//지연과 지연 사이의 임의 지연을 기대*2
			await sleep(delay * (1 + Math.random()));

			//exponential backoff와 다음 지연 계산
			delay = Math.min(delay * backoffFactor, maxDelay);
		}
	}

	throw lastError;
}
```

더 보기`withRetry`함수는 exponential backoff를 가진 주어진 가동을 retries 하는 실용 함수입니다. 구성 객체를 인수로 움직입니다. 즉, retries, 초기 지연, 최대 지연 및 backoff 요소를 사용자 정의 할 수 있습니다. 네트워크 연결 손실, 저장 재설정, 또는 코드 업데이트로 인해 오류가 발생하면 작동을 재개합니다.

:::카트로션

distrubed 체계에서는, retry 기계장치는 특정 위험이 있을 수 있습니다. 기사 읽기[Distributed Systems의 Retry Strategies : 식별 및 주소 키 Pitfalls](https://www.computer.org/publications/tech-news/trends/retry-strategies-avoiding-pitfalls)회복 메커니즘의 위험에 대해 자세히 알아 보려면 및 그들을 피하는 방법.

Retries는 때때로 자료 inconsistency에 지도할 수 있습니다. retry 논리를 주의 깊게 취급해야합니다.

:::

## 단계 7: API 경로 업데이트

D1 데이터베이스에 연결하는 API 경로 업데이트.

### 1. POST /api / 제품

```ts
app.post("/api/product", async (c) => {
	const product = await c.req.json();

	if (!product) {
		return c.json({ message: "No data passed" }, 400);
	}

	const db = c.env.DB;
	const session = db.withSession("first-primary");

	const { id } = product;

	try {
		return await withRetry(async () => {
			//상품이 존재하는 경우 확인
			const { results } = await session
				.prepare("SELECT * FROM products where id = ?")
				.bind(id)
				.run();
			if (results.length === 0) {
				const fields = [...Object.keys(product)];
				const values = [...Object.values(product)];
				//제품 삽입
				await session
					.prepare(
						`INSERT INTO products (${fields.join(", ")}) VALUES (${fields.map(() => "?").join(", ")})`,
					)
					.bind(...values)
					.run();
				const latestBookmark = session.getBookmark();
				latestBookmark &&
					setCookie(c, "product_bookmark", latestBookmark, {
						maxAge: 60 * 60, //1시간
					});
				return c.json({ message: "Product inserted" });
			}

			//제품 업데이트
			const updates = Object.entries(product)
				.filter(([_, value]) => value !== undefined)
				.map(([key, _]) => `${key} = ?`)
				.join(", ");

			if (!updates) {
				throw new Error("No valid fields to update");
			}

			const values = Object.entries(product)
				.filter(([_, value]) => value !== undefined)
				.map(([_, value]) => value);

			await session
				.prepare(`UPDATE products SET ${updates} WHERE id = ?`)
				.bind(...[...values, id])
				.run();
			const latestBookmark = session.getBookmark();
			latestBookmark &&
				setCookie(c, "product_bookmark", latestBookmark, {
					maxAge: 60 * 60, //1시간
				});
			return c.json({ message: "Product updated" });
		});
	} catch (e) {
		console.error(e);
		return c.json({ message: "Error upserting product" }, 500);
	}
});
```

위 코드에서:

- 요청 몸에서 제품 데이터를 얻습니다.
- 그런 다음 제품이 데이터베이스에 존재하는지 확인하십시오.
  - 그것이 작동하는 경우에, 당신은 제품을 새롭게 합니다.
  - 그렇지 않으면 제품을 삽입합니다.
- 당신은 쿠키에 책갈피를 설정한다.
- 마지막으로 응답을 반환합니다.

최신 데이터로 세션을 시작하려면 사용`first-primary`제약. 당신이 사용하더라도`first-unconstrained`constraint 또는 bookmark를 통과, 쓰기 요청은 항상 기본 데이터베이스로 이동합니다.

쿠키에 설정된 책갈피는 새로운 세션이 제공된 책갈피로 최소한의 데이터베이스 버전을 읽는 것을 보장하기 위해 사용될 수 있습니다.

외부 플랫폼을 사용하여 제품을 관리하려면, 이 API를 외부 플랫폼에 연결할 수 있습니다. 이 API를 외부 플랫폼에서 생성하거나 업데이트 할 때 D1 데이터베이스는 자동으로 제품 세부 정보를 업데이트합니다.

### 2. GET /api / 제품

```ts
app.get("/api/products", async (c) => {
	const db = c.env.DB;

	//쿠키에서 bookmark 받기
	const bookmark = getCookie(c, "product_bookmark") || "first-unconstrained";

	const session = db.withSession(bookmark);

	try {
		return await withRetry(async () => {
			const { results } = await session.prepare("SELECT * FROM products").run();

			const latestBookmark = session.getBookmark();

			//쿠키에 책갈피 설정
			latestBookmark &&
				setCookie(c, "product_bookmark", latestBookmark, {
					maxAge: 60 * 60, //1시간
				});

			return c.json(results);
		});
	} catch (e) {
		console.error(e);
		return c.json([]);
	}
});
```

위 코드에서:

- 당신은 쿠키에서 데이터베이스 세션 북마크를 얻을.
  - 책갈피가 설정되지 않은 경우, 사용`first-unconstrained`제약.
- 당신은 책갈피와 데이터베이스 세션을 만들.
- 당신은 데이터베이스에서 모든 제품을 꺼내 최신 bookmark를 얻을.
- 당신은 쿠키에이 책갈피를 설정한다.
- 마지막으로 결과를 반환합니다.

npm run dev

\`\`로 이동[모델 번호: http://localhost:8787](http://localhost:8787). 당신은 제품 목록으로 보아야 합니다. 제품 상세보기를 클릭.

curl -X POST http://localhost:8787/api/product \
     -H "Content-Type: application/json" \

## 단계 9: 응용 프로그램을 배포

이전 단계에서 사용되는 데이터베이스가 로컬이기 때문에 원격 데이터베이스에서 제품 테이블을 만들 필요가 있습니다. 다음 D1 명령을 실행하여 원격 데이터베이스에서 제품 테이블을 만듭니다.

```sh
npx wrangler d1 execute fast-commerce --remote --command "CREATE TABLE IF NOT EXISTS products (id INTEGER PRIMARY KEY, name TEXT NOT NULL, description TEXT, price DECIMAL(10, 2) NOT NULL, inventory INTEGER NOT NULL DEFAULT 0, category TEXT NOT NULL, created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP, last_updated TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP)"
```

다음, 다음 명령을 실행하여 제품 테이블에 인덱스를 생성:

```sh
npx wrangler d1 execute fast-commerce --remote --command "CREATE INDEX IF NOT EXISTS idx_products_id ON products (id)"
```

선택적으로, 다음 명령을 실행하여 원격 데이터베이스에 제품을 삽입 할 수 있습니다.

```sh
npx wrangler d1 execute fast-commerce --remote --command "INSERT INTO products (id, name, description, price, inventory, category) VALUES (1, 'Fast Ergonomic Chair', 'A comfortable chair for your home or office', 100.00, 10, 'Furniture'), (2, 'Fast Organic Cotton T-shirt', 'A comfortable t-shirt for your home or office', 20.00, 100, 'Clothing'), (3, 'Fast Wooden Desk', 'A wooden desk for your home or office', 150.00, 5, 'Furniture'), (4, 'Fast Leather Sofa', 'A leather sofa for your home or office', 300.00, 3, 'Furniture'), (5, 'Fast Organic Cotton T-shirt', 'A comfortable t-shirt for your home or office', 20.00, 100, 'Clothing')"
```

이제 다음 명령을 사용하여 응용 프로그램을 배포 할 수 있습니다.

```sh
npm run deploy
```

이것은 Workers 및 D1 데이터베이스에 응용 프로그램을 배포합니다. 사용자 요청이 모든 지역에서 응용 프로그램을 요청하면 데이터베이스가 복제 된 가장 가까운 지역에 요청이 리디렉션됩니다.
