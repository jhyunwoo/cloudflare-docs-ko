D1는 데이터베이스를 쿼리 할 때 예외 및 로그 오류를 캡처 할 수 있습니다. D1를 디버깅하려면, 같은 도구를 사용할 수 있습니다.[디버깅 Workers](/workers/observability/).

D1의[`stmt.`](/d1/worker-api/prepared-statements/)·[`db.`](/d1/worker-api/d1-database/)자주 묻는 질문[오류 객체](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Error)오류가 발생했을 때. 예외를 캡처하려면 로그인`e.message`가치.

예를 들어, 아래 코드는 잘못된 키워드로 쿼리가 있습니다.`INSERTZ`대신에`INSERT`:

```js
try {
    //이것은 의도적 인 말입니다.
    await db.exec("INSERTZ INTO my_table (name, employees) VALUES ()");
} catch (e: any) {
    console.error({
        message: e.message
    });
}
```

위의 코드는 다음과 같은 오류 메시지를 던졌습니다.

```json
{
	"message": "D1_EXEC_ERROR: Error in line 1: INSERTZ INTO my_table (name, employees) VALUES (): sql error: near \"INSERTZ\": syntax error in INSERTZ INTO my_table (name, employees) VALUES () at offset 0"
}
```

:::참조
시작하기[`wrangler` 3.1.1](https://github.com/cloudflare/workers-sdk/releases/tag/wrangler%403.1.1), D1 JavaScript 오류 사용[이름 \*](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Error/cause)상세한 오류 메시지.

이전 버전의 사용시 이러한 오류를 검사하기 위해`wrangler`로그인`error?.cause?.message`.
:::

## 오류 목록

D1는 다음과 같은 오류 일정을 반환합니다. 확장 (detailed) 오류 메시지 :

| 오류 메시지               | 이름 \*                                                                      | 자주 묻는 질문                    |
| -------------------- | -------------------------------------------------------------------------- | --------------------------- |
| `D1_ERROR`           | 특정 D1 오류의 접두사.                                                             | 아래의 "D1 ERRORs 목록"을 참조하십시오. |
| `D1_EXEC_ERROR`      | 줄 x의 Exec 오류: y 오류.                                                        |                             |
| `D1_TYPE_ERROR`      | 열과 값 사이의 유형에 잡힌 경우 반환됩니다. 일반적인 원인은 공급`undefined`대신 변수 (unsupported)`null`. | 값과 열 일치의 유형을 보장합니다.         |
| `D1_COLUMN_NOTFOUND` | 찾을 수 없습니다.                                                                 | 데이터베이스에 존재하는 열을 선택합니다.      |

## 자동 retries

D1는 읽기 전용 쿼리를 감지하고 두 개의 레트리를 자동으로 시도하여 복원 가능한 오류로 실패의 경우 쿼리를 실행합니다.

D1는 리트리 시도가 데이터베이스 쓰기를 일으키지 않다는 것을 보증합니다, 측 효력에서 자동적인 retries 안전을 만들기, 읽기 전용 탐지를 통해 수정 미끄러짐을 일으키는 경우에 조차. D1는 각 질의 실행 후에 수정을 위해 이것을 달성하고, 어떤 쓰기가 retry 시도 때문에 일어났는 경우에, 조회는 뒤 구르고 있습니다.

:::참조
읽기 전용 쿼리 만 (다음 SQLite 키워드 만 포함 된 쿼리 :`SELECT`, `EXPLAIN`, `WITH`)는 retried. 자주 묻는 질문[SQLite 키워드](https://sqlite.org/lang_keywords.html)그것은 데이터베이스 쓰기로 이동하지 않습니다.

## 문제 보고

- 버그 또는 요청 기능을 보고하려면[Cloudflare 커뮤니티 포럼](https://community.cloudflare.com/c/developers/d1/85).
- 피드백을 제공하기 위해, 이동[모델 번호: D1 Discord 채널](https://discord.com/invite/cloudflaredev).
- Wrangler에 문제가 있는 경우, 보고서 문제[Wrangler GitHub 저장소](https://github.com/cloudflare/workers-sdk/issues/new/choose).

다음과 같은 버그 보고서를 포함해야 합니다:

- 데이터베이스의 ID. 제품 정보`wrangler d1 list`ID에 데이터베이스 이름과 일치합니다.
- 문제가 발생할 때 쿼리 (또는 쿼리) ran. 개인 식별 정보를 보장 (PII).
- 쿼리를 만드는 노동자 코드, 어떤 호출을 포함`bind()`사용 방법[모델 번호: Workers 바인딩 API](/d1/worker-api/).
- 전체 오류 텍스트, 내용 포함[`error.cause.message`](#handle-errors).
