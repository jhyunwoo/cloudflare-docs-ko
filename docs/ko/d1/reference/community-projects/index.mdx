Cloudflare 개발자 커뮤니티 및 더 넓은 개발자 생태계의 구성원은 ORMs (Object Relational Mapper) 라이브러리, 쿼리 빌더 및 CLI 도구와 같은 Tooling 및/또는 기여했습니다. D1XQ.

:::참조

커뮤니티 프로젝트는 QXQX0660XQQ D1 팀에 의해 유지되지 않습니다. 그들은 프로젝트 저자에 의해 관리되고 업데이트됩니다.

:::

## 프로젝트

### 스탄도 ORM

Sutando는 Node.js를 위해 디자인된 ORM입니다. Sutando로, 데이터베이스의 각 테이블에는 CRUD(Create, Read, Update, Delete) 작업을 처리하는 대응 모델이 있습니다.

- [프로젝트](https://github.com/sutandojs/sutando)
- [Sutando ORM 예제가있는 D1](https://github.com/sutandojs/sutando-examples/tree/main/typescript/rest-hono-cf-d1)

### knex 클라우드 플레어 d1

knex-cloudflare-d1는 Knex.js를 위한 Cloudflare D1 방언입니다. Knex.js에서 제공하는 공식 방언이 아닙니다.

- [프로젝트](https://github.com/kiddyuchina/knex-cloudflare-d1)

### 프리즈마 ORM

[프리즈마 ORM](https://www.prisma.io/orm)차세대 JavaScript 및 TypeScript ORM은 직관적 인 데이터 모델, 자동화 된 마이그레이션, 유형 안전 및 자동 컴파일 덕분에 데이터베이스와 작업 할 때 개발자 경험의 새로운 수준을 잠금 해제합니다.

- [다운로드](/d1/tutorials/d1-and-prisma-orm/)
- [사이트맵](https://www.prisma.io/docs/orm/prisma-client/deployment/edge/deploy-to-cloudflare#d1)

### D1 어댑터 Kysely ORM

Kysely는 Type-safe 및 Autocompletion-friendly typescript SQL 쿼리 빌더입니다. 이 어댑터를 사용하면 친숙한 Kysely 인터페이스와 D1와 상호 작용할 수 있습니다.

- [프로젝트](https://github.com/koskimas/kysely)
- [D1 접합기](https://github.com/aidenwallis/kysely-d1)

### 깃털-kysely

더 보기`feathers-kysely`데이터베이스 어댑터는 FeathersJS Query Syntax 표준을 따르고 모든 프레임 워크와 함께 작동합니다. 그것은 Kysely를 위한 D1 접합기에 건축되고 클라이언트 신청에서 직접 쿼리를 전달합니다. FeathersJS 쿼리 구문은 MongoDB의 구문의 하위 세트이므로 이전에 SQL 경험없이 Cloudflare QXD1XQXQXQ를 사용하는 MongoDB 사용자를위한 훌륭한 도구입니다.

- [깃털-kysely 에 npm](https://www.npmjs.com/package/feathers-kysely)
- [GitHub에서 공유하기](https://github.com/marshallswain/feathers-kysely)

### 건조 ORM

Drizzle은 Node, Bun 및 Deno에서 실행되는 머리와 함께 헤드리스 TypeScript ORM입니다. Drizzle ORM은 Edge에 살고 있으며 JavaScript ORM도 있습니다. 자동 SQL 마이그레이션 세대에 대한 drizzle-kit CLI 동반자로 제공됩니다. Drizzle은 TypeScript에 정의된 유형에 따라 D1 스키마를 자동으로 생성하고 데이터베이스를 직접 쿼리할 수 있는 API를 노출시킵니다.

- [사이트맵](https://orm.drizzle.team/docs)
- [프로젝트](https://github.com/drizzle-team/drizzle-orm)
- [D1 예](https://orm.drizzle.team/docs/connect-cloudflare-d1)

### 채용정보

`workers-qb`간단한 표준화된 인터페이스를 제공하는 Zero-dependency 쿼리 빌더로서, 기존의 ORM을 통해 원시 쿼리를 사용하여 이점과 속도를 유지하고 있습니다. ORM-like 기능을 제공하지 않는 동안,`workers-qb`직접 SQL 액세스를 위해 코드에서 데이터베이스와 상호 작용하는 것이 더 쉽습니다.

- [프로젝트](https://github.com/G4brym/workers-qb)
- [회사연혁](https://workers-qb.massadas.com/)

### d1 콘솔

대신 실행`wrangler d1 execute`데이터베이스와 상호 작용할 때마다 터미널에서 명령하면 D1와 상호 작용할 수 있습니다.`d1-console`. Discord Community Champion에 의해 생성해, 이것은 명령 역사를 얻는 다 선 쿼리를 실행하는 이점을 주고, 청결한 체재한 테이블 산출을 전망합니다.

- [프로젝트](https://github.com/isaac-mcfadyen/d1-console)

### 사이트맵

`L1`어떤 Cloudflare를 가져오는 포장입니다 Cloudflare API를 통해 PHP 및 Laravel에 대한 Worker 생태계 바인딩. 그것은 PDO, KV 및 QueuesXQ를 통해 D1XQ와 상호 작용을 제공하고, 앞으로 추가하는 더 많은 서비스와 더불어, CloudflareXQ와 진짜 바람을 가진 PHP 통합을 만들기.

- [프로젝트](https://github.com/renoki-co/l1)
- [관련 상품](https://packagist.org/packages/renoki-co/l1)

### 직원 디렉토리 - D1 기반 데모

Staff Directory는 D1를 사용하여 데모 프로젝트입니다.[호노X](https://github.com/honojs/honox)·[Cloudflare Pages](/pages/). 그것은 D1를 사용하여 직원 데이터를 저장하고 D1XQ의 정상에 건설된 풀스택 응용 프로그램의 예입니다.

- [프로젝트](https://github.com/lauragift21/staff-directory)
- [D1 기능](https://github.com/lauragift21/staff-directory/blob/main/app/db.ts)

### 프로젝트

`NuxtHub`Cloudflare 구성 없이 Nuxt 애플리케이션에 작업자 바인딩. 그것은 레버리지[Wrangler 플랫폼 프록시](/workers/wrangler/api/#getplatformproxy)생산의 개발 및 직접적인 바인딩에서 상호 작용[모델 번호: D1](/d1/), [모델 번호: KV](/kv/)·[R2](/r2/)서버 composables로 (`hubDatabase()`, `hubKV()`·`hubBlob()`).

`NuxtHub`또한 원격 D1 데이터베이스를 사용하여 개발하는 방법을 제공합니다`npx nuxt dev --remote`명령.

- [프로젝트](https://github.com/nuxt-hub/core)
- [회사연혁](https://hub.nuxt.com)
- [이름 \*](https://github.com/Atinux/nuxt-todos-edge)
