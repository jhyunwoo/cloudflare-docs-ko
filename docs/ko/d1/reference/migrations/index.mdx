Database 마이그레이션은 데이터베이스를 버전화하는 방법입니다. 각 이동은 저장됩니다`.sql`파일 형식`migrations`폴더. 더 보기`migrations`폴더는 첫 번째 마이그레이션을 만들 때 프로젝트 디렉토리에서 생성됩니다. 데이터베이스 개발 전반에 걸쳐 저장 및 트랙 변경이 가능합니다.

## 주요 특징

현재 마이그레이션 시스템은 간단하면서도 효과적입니다. 현재 구현으로, 당신은 할 수 있습니다:

- [이름 \*](/workers/wrangler/commands/#d1-migrations-create)빈 이동 파일.
- [이름 \*](/workers/wrangler/commands/#d1-migrations-list)승인 된 마이그레이션.
- [지원하다](/workers/wrangler/commands/#d1-migrations-apply)나머지 마이그레이션.

모든 마이그레이션 파일`migrations`폴더에는 파일명에 지정된 버전 번호가 있습니다. 파일은 순차적 순서로 나열됩니다. 모든 마이그레이션 파일은 실행할 쿼리를 지정할 수 있는 SQL 파일입니다.

:::note\[Binding name vs Database 이름]
마이그레이션 스크립트를 실행하면 바인딩 이름 또는 데이터베이스 이름을 사용할 수 있습니다.

그러나, 바인딩 이름은 변경할 수 있습니다, 데이터베이스 이름은 할 수 없습니다. 따라서 잘못된 바인딩에 실수로 마이그레이션을 방지하기 위해 D1 마이그레이션에 대한 데이터베이스 이름을 사용할 수 있습니다.

## Wrangler 주문화

기본적으로 마이그레이션은`migrations/`Worker 프로젝트 디렉토리에 폴더. 마이그레이션은 적용된 마이그레이션의 기록을 유지한다.`d1_migrations`데이터베이스에서 찾을 수 있습니다.

이 위치와 테이블 이름은 Wrangler 파일에서, D1 바인딩 안쪽에 주문을 받아서 만들어질 수 있습니다.

<WranglerConfig>
  ```jsonc
  {
  	"d1_databases": [
  		{
  			"binding": "<BINDING_NAME>", //i.e. "DB"로 설정하면 `env.DB`에서 작업자에서 사용할 수 있습니다.
  			"database_name": "<DATABASE_NAME>",
  			"database_id": "<UUID>",
  			"preview_database_id": "<UUID>",
  			"migrations_table": "<d1_migrations>", //적용된 마이그레이션 테이블 이름을 변경하는 이 값을 사용자 지정
  			"migrations_dir": "<FOLDER_NAME>" //사용자 지정 마이그레이션 디렉토리
  		}
  	]
  }
  ```
</WranglerConfig>

## 외국 키 제약

이동을 신청할 때, 일시적으로 비활성화해야 할 수 있습니다.[외국 키 제약](/d1/sql-api/foreign-keys/). 이렇게하려면, 전화`PRAGMA defer_foreign_keys = true`외국 키를 위반하는 변경 전에.

더 알아보기[외국 키 문서](/d1/sql-api/foreign-keys/)외국 키와 D1로 작업하는 방법에 대해 자세히 알아보세요.
