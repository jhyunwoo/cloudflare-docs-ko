| 제품 정보                                                                                         | 지원하다                             |
| --------------------------------------------------------------------------------------------- | -------------------------------- |
| 계정 당 데이터베이스                                                                                   | 50,000 (Workers 유료)[^1]/ 10 (무료) |
| 최대 데이터베이스 크기                                                                                  | 10 GB (Workers 유료) / 500 MB (무료) |
| 계정 당 최대 저장                                                                                    | 1 TB (Workers 유료)[^2]/ 5 GB (무료) |
| [시간 여행](/d1/reference/time-travel/)기간 (점 시간 회복)                                               | 30 일 (Workers 유료) / 7 일 (무료)     |
| 최대 시간 여행 복원 작업                                                                                | 10 분 당 복원 (데이터베이스당)              |
| 작업자 직업 당 쿼리 (read)[subrequest 제한](/workers/platform/limits/#how-many-subrequests-can-i-make)) | 1000 (Workers 유료) / 50 (무료)      |
| 테이블 당 열의 최대 수                                                                                 | 100                              |
| 테이블 당 행 수                                                                                     | 무제한 (per-database 저장 한계 제외)      |
| 최대 문자열,`BLOB`또는 테이블 행 크기                                                                      | 2,000,000 바이트 (2 MB)             |
| 최대 SQL 문 길이                                                                                   | 100,000 바이트 (100 KB)             |
| 쿼리 당 최대 경계 매개 변수                                                                              | 100                              |
| SQL 함수당 최대 인수                                                                                 | 32                               |
| 최대 문자(바이트)`LIKE`또는`GLOB`이름 \*                                                                 | 50 바이트                           |
| Workers 스크립트 당 최대 바인딩                                                                         | 약 5,000[^3]                      |
| 최대 SQL 쿼리 기간                                                                                  | 30 초[^4]                         |
| 최대 파일 가져 오기 (`d1 execute`) 크기                                                                 | 5개 GB[^5]                        |

:::note\[배치 제한]
개별 쿼리에 대한 제한 (위 나열) 배치 문 내에서 포함 된 각 개별 진술에 적용. 예를 들어, 100 KB의 최대 SQL 문 길이는 내부 각 문에 적용됩니다.`db.batch()`.
:::

[^1]: 계정 당 데이터베이스의 최대 수는 Workers Paid 및 엔터프라이즈 계획에 따라 수백만 대의 데이터베이스 (또는 더 많은)에 대한 지원으로 증가 할 수 있습니다. 이 페이지에 한도 증가에 대한 지도를 참조하십시오.

[^2]: 계정 당 최대 저장은 Workers Paid 및 Enterprise 계획에 따라 증가 할 수 있습니다. 이 페이지에 한도 증가에 대한 지도를 참조하십시오.

[^3]: 단일 노동자 스크립트는 스크립트 메타 데이터의 1MB까지 가질 수 있습니다. 바인딩은 D1 데이터베이스, KV 네임스페이스와 같은 리소스에 바인딩으로 정의됩니다.[환경변수](/workers/configuration/environment-variables/), 또는 비밀. 각 리소스 바인딩은 약 150 바이트이지만 환경 변수와 비밀은 제공 값의 크기에 의해 제어됩니다. 환경 변수를 초과하면 단일 작업자 스크립트에 \~5,000 D1 데이터베이스를 바인딩할 수 있습니다.

[^4]: Cloudflare API 요청은 30초 내에 해결해야 합니다. 따라서, 이 기간 제한은 또한 전체 배치 호출에 적용합니다.

[^5]: 수입된 파일은 R2에 업로드됩니다. 더 알아보기[R2 업로드 제한](/r2/platform/limits).

Cloudflare는 또한 다른 저장 해결책을 제안합니다[Workers KV](/kv/api/), [모델 번호: Durable Objects](/durable-objects/)·[모델 번호: R2](/r2/get-started/). 각 제품은 다른 이점 및 한계가 있습니다. 더 알아보기[데이터 또는 저장 제품 선택](/workers/platform/storage-options/)저장 옵션이 사용 사례에 적합한지 검토하십시오.
