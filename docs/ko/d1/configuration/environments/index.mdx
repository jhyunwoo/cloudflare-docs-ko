[환경분야](/workers/wrangler/environments/)코드가 실행되는 다른 컨텍스트입니다. Cloudflare Developer Platform은 다른 환경을 만들고 관리할 수 있습니다. 환경을 통해 여러 이름으로 동일한 프로젝트를 여러 곳으로 배포할 수 있습니다.

다른 환경에 대한 다른 D1 데이터베이스를 지정하려면 Wrangler 파일에 다음 구문을 사용하십시오.

<WranglerConfig>
  ```jsonc
  {
  	"env": {
  		//이것은 staging 환경입니다
  		"staging": {
  			"d1_databases": [
  				{
  					"binding": "<BINDING_NAME_1>",
  					"database_name": "<DATABASE_NAME_1>",
  					"database_id": "<UUID1>"
  				}
  			]
  		},
  		//이것은 생산 환경입니다
  		"production": {
  			"d1_databases": [
  				{
  					"binding": "<BINDING_NAME_2>",
  					"database_name": "<DATABASE_NAME_2>",
  					"database_id": "<UUID2>"
  				}
  			]
  		}
  	}
  }
  ```
</WranglerConfig>

위의 코드에서,`staging`환경은 다른 데이터베이스를 사용합니다 (`DATABASE_NAME_1`) 보다는`production`환경 (`DATABASE_NAME_2`).

## Wrangler 파일의 해부학

다른 환경에 대한 D1 데이터베이스를 지정해야 하는 경우,[Wrangler 구성 파일](/workers/wrangler/configuration/)다음과 같은 바인딩을 포함 할 수 있습니다 :

<WranglerConfig>
  ```jsonc
  {
  	"production": {
  		"d1_databases": [
  			{
  				"binding": "DB",
  				"database_name": "DATABASE_NAME",
  				"database_id": "DATABASE_ID"
  			}
  		]
  	}
  }
  ```
</WranglerConfig>

위 윤곽에서:

- `[[production.d1_databases]]`객체 생성`production`시설 안내`d1_databases`, 어디`d1_databases`객체의 배열입니다. 여러 D1 바인딩을 만들 수 있으므로 하나의 데이터베이스가 있습니다.
- 양식의 선 아래 모든 속성`<key> = <value>`객체의 속성은`d1_databases`배열.

따라서 위의 바인딩은 다음과 같습니다.

```json
{
  "production": {
    "d1_databases": [
      {
        "binding": "DB",
        "database_name": "DATABASE_NAME",
        "database_id": "DATABASE_ID"
      }
    ]
  }
}
```

  ```jsonc
      ]
  ```

```json
    "staging": {
      "d1_databases": [
        {
          "binding": "BINDING_NAME_1",
          "database_id": "UUID_1",

        }
      ]
    }
  }
}
```
