응용 프로그램을 구축하는 경우[Cloudflare Workers](/workers/), 당신은 당신의 SaaS 지역을 위한 근원으로 노동자를 사용할 수 있습니다 (또한 당신의 fallback 근원으로 알려지는).

## 사용자 정의 호스트 이름 트래픽은 당신의 노동자에 도달

고객이 SaaS 영역에 도메인을 지적할 때 (예를 들어,`mystore.customer.com`이름에`service.saasprovider.com`), 그들의 교통은 당신의 Cloudflare 지역을 입력합니다. 영역에서 구성 된 모든 노동자 경로는이 들어오는 트래픽과 일치합니다.

예:

- SaaS 영역:`saasprovider.com`
- 당신의 fallback 근원:`service.saasprovider.com`
- 고객의 주문 이름:`mystore.customer.com`(CNAME을 통해 영역으로 지정)
- 노동자 노선:`*/*`

자주 묻는 질문`mystore.customer.com`, 당신의 지역을 통해 요구하는 Cloudflare 노선. 더 보기`*/*`노선 패턴은 사용자 정의 호스트 이름과 같은 트래픽을 포함하여 모든 트래픽을 입력`mystore.customer.com`.

:::참조
각 사용자 지정 호스트 이름에 대한 개별 노동자 경로를 추가 할 필요가 없습니다. 와일드 카드 루트 패턴 (Bildcard route pattern)`*/*`) 자동적으로 당신의 지역에 들어가는 모든 소통량을, 고객 허영 영역에서 소통량 포함하.
주요 특징

## 당신의 fallback 근원으로 노동자를 설치하십시오

1. SaaS 영역에서,[생성 및 설정 fallback 기원](/cloudflare-for-platforms/cloudflare-for-saas/start/getting-started/#1-create-fallback-origin). fallback 근원은 단지 있습니다[잘못된 DNS 기록](/dns/manage-dns-records/how-to/create-dns-records/#originless-setups):
   - **이름 \***: `service.example.com AAAA 100::`

2. 같은 영역에서, 탐색**Workers 오시는 길**.

3. 이름 \***경로 추가**.

4. 작업자에게 트래픽을 보내는 경로 구성. 당신의 필요에 따라 다음 옵션 중 하나를 선택하십시오.
   - **노동자에게 모든 교통을**(최대 SaaS 애플리케이션에 대한 권장):

     - **오시는 길**: `*/*`
     - **작업자**: SaaS 애플리케이션에 사용되는 Worker를 선택합니다.

     이 패턴은 사용자 정의 hostnames (예를 들면,)에서 요청을 포함하여 작업자에게 영역을 입력하는 모든 트래픽을 경로`mystore.customer.com`) 자신의 하위 도메인에 요청 (예를 들어,`app.saasprovider.com`).

   - **모든 경로는 노동자에게 특정 경로**:

     - **오시는 길**: `*/*`
     - **작업자**: SaaS 애플리케이션에 사용되는 Worker를 선택합니다.
     - 영역의 자신의 호스트 이름에 대한 두 번째 경로 추가**작업자**설정하기**이름 \***&#xADF8;들을 제외하고.

     예를 들어, 영역이 있다면`saasprovider.com`그리고 당신은`api.saasprovider.com`Worker를 우회하여 추가 경로 생성`api.saasprovider.com/*`작업자가 할당되지 않습니다. 더 구체적인 루트는 Wildcard 노선을 통해 선행합니다.

   - **경로 단지 사용자 정의 hostname 트래픽에 노동자**:

   - **오시는 길**: `vanity.customer.com`

   - **작업자**: SaaS 애플리케이션에 사용되는 Worker를 선택합니다.

5. 이름 \***제품 정보**.

***

:::caution\[지역 이름 제한]
