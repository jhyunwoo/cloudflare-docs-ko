SaaS 공급자로서, 원하는 것, 또는 호스트명을 관리하는 여러 영역이 있습니다. 각 지역에는 다른 윤곽 또는 근원이 있고, 뿐 아니라 다양한 제품에 correlate 할 수 있습니다. 특정 기능을 활성화하거나 비활성화 할 수있는 영역 사이의 사용자 정의 호스트 이름을 변경할 수 있습니다. Cloudflare는 아래 단계를 통해 동일한 계정 내에서 마이그레이션 할 수 있습니다.

***

## 이름 \*

사용자 정의 hostname이 CNAME 레코드를 사용한다면, 새로운 영역에 사용자 정의 hostname을 추가하고[DNS 레코드 업데이트](/dns/manage-dns-records/how-to/create-dns-records/#edit-dns-records)새로운 영역으로 포인트.

:::참조

DNS 대상을 변경하지 않고 사용자 정의 호스트 이름을 마이그레이션하려는 경우, 사용[apex 프록시](/cloudflare-for-platforms/cloudflare-for-saas/start/advanced-settings/apex-proxying/).

:::

1. [사용자 정의 hostname 추가](/cloudflare-for-platforms/cloudflare-for-saas/start/getting-started/)새로운 영역으로.

2. 고객에게[DNS 레코드 변경](/dns/manage-dns-records/how-to/create-dns-records/#edit-dns-records)그래서 그것은 새로운 영역에 포인트.

3. custom hostname은 새로운 영역에서 유효하다는 것을 확인합니다.

4. Cloudflare를 통해 자동으로 검증된 인증서를 기다립니다.[Domain Control Validation (DCV)를 사용하여 검증](/ssl/edge-certificates/changing-dcv-method/methods/#perform-dcv).

5. 이전 영역에서 사용자 정의 호스트 이름을 제거.

이 단계가 완료되면, 사용자 정의 hostname의 트래픽은 두 번째 SaaS 영역으로 경로를 변경하고 구성을 사용합니다.

## 이름 \*

제품정보[Apex 프록시](/cloudflare-for-platforms/cloudflare-for-saas/start/advanced-settings/apex-proxying/)또는[BYOIP의 특징](/byoip/), 당신은 당신의 끝 고객에서 활동 없이 주문 hostname를 migrate 할 수 있습니다.

1. Apex 프록시 IP가 SaaS 영역 모두에 할당 된 계정 팀과 검증.

2. [사용자 정의 hostname 추가](/cloudflare-for-platforms/cloudflare-for-saas/start/getting-started/)새로운 영역으로.

3. custom hostname은 새로운 영역에서 유효하다는 것을 확인합니다.

4. Cloudflare를 통해 자동으로 검증할 수 있는 인증서를 기다립니다.[DCV를 사용하는 검증](/ssl/edge-certificates/changing-dcv-method/methods/#perform-dcv).

5. 이전 영역에서 사용자 정의 호스트 이름을 제거.

:::참조

가장 최근에 편집 된 사용자 정의 hostname은 활성 될 것입니다. 예를 들어,`example.com`현재 위치`SaaS Zone 1`. 그것은 추가됩니다`SaaS Zone 2`. 최근에 활성화되었기 때문에`SaaS Zone 2`, 그것은 어디 활성화 될 것입니다. 그러나, 편집이 example.com에 만든 경우`SaaS Zone 1`, 대신 해당 영역에서 다시 활성화됩니다`SaaS Zone 2`.

:::

## Wildcard 인증서

와일드 카드 인증서에 의존하는 사용자 정의 호스트 이름을 마이그레이션하는 경우, CloudflareXQ는 자동으로 도메인 제어 검증 (DCV)을 완료 할 수 없습니다.

1. [사용자 정의 hostname 추가](/cloudflare-for-platforms/cloudflare-for-saas/start/getting-started/)새로운 영역으로.

2. 고객에게[DNS 레코드 변경](/dns/manage-dns-records/how-to/create-dns-records/#edit-dns-records)그래서 그것은 새로운 영역에 포인트.

3. [인증서 검증](/ssl/edge-certificates/changing-dcv-method/methods/#perform-dcv)DCV를 통해 새로운 영역에.

사용자 정의 hostname은 오래된 영역에서 인증서가 여전히 활성화되는 경우에도 새로운 영역에 활성화 할 수 있습니다. 이것은 마이그레이션 중에 유효한 인증서가 존재합니다. 그러나, 그것은 가능한 한 빨리 새로운 영역에 인증서를 검증하는 것이 중요합니다.

:::참조

사용자 정의 hostname이 마이그레이션 후 성공적으로 활성화되었는지 확인합니다.[**사용자 이름**](https://dash.cloudflare.com/?to=/:account/:zone/ssl-tls/custom-hostnames)사이트 맵

:::
