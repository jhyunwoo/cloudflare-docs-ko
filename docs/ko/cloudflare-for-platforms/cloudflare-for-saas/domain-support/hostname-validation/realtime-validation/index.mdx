실시간 유효성 검사 방법을 사용할 때 Cloudflare는 고객의 호스트명을 지정할 때 고객의 호스트명을 지정합니다.[DNS 라우팅 기록](/cloudflare-for-platforms/cloudflare-for-saas/start/getting-started/#3-have-customer-create-cname-record)자신의 권위 있는 DNS에.

## 사용시

실시간 유효성 검사 방법은 추가적인 행동을 요구하지 않기 때문에 고객의 부담을 덜어줍니다.

그러나 Cloudflare가 DNS 레코드를 초과하는 데 몇 초가 걸립니다. 이 다운타임도 증가할 수 있습니다.[유효성 검사](/cloudflare-for-platforms/cloudflare-for-saas/domain-support/hostname-validation/backoff-schedule/)- 고객이 DNS 라우팅 레코드를 추가 할 때 추가 시간이 걸립니다.

이 가동 시간을 극소화하기 위하여, 당신은 지속적으로 no-change를 보낼 수 있습니다[`PATCH`이름 \*](/api/resources/custom_hostnames/methods/edit/)특정 사용자 정의 호스트 이름에 대한 유효성 검사 ( validation backoff schedule을 재설정).

다운타임의 기회를 피하기 위해, 사용[사전 검증 방법](/cloudflare-for-platforms/cloudflare-for-saas/domain-support/hostname-validation/pre-validation/)

## 이름 \*

실시간 유효성 검사는 고객이 추가할 때 자동으로 발생합니다.[DNS 라우팅 기록](/cloudflare-for-platforms/cloudflare-for-saas/start/getting-started/#3-have-customer-create-cname-record).

정확한 기록은 SaaS 설정을 위한 Cloudflare에 달려 있습니다.
