## 어떻게 작동합니까?

O2O가 활성화되면 트래픽 경로에 대한 자세한 내용은 참조[O2O는 어떻게 작동합니까?](/cloudflare-for-platforms/cloudflare-for-saas/saas-customers/how-it-works/).

## 이름 \*

고객은 어떤 Cloudflare 지역 계획든지에 O2O를 활성화할 수 있습니다. Cloudflare 지원은 기업 고객을 위해만 유효합니다.

Cloudflare 영역 내에서 특정 호스트 이름을 위해 O2O를 활성화하려면[지원하다](/dns/manage-dns-records/how-to/create-dns-records/#create-dns-records)견적 요청`CNAME`Render 사이트 이름과 함께 DNS 레코드. Render의 도메인 추가 설정은 다른 유효성 검사 단계를 통해 이동합니다.

| 제품정보    | 이름 \*             | 제품정보                                           | 프록시 상태 |
| ------- | ----------------- | ---------------------------------------------- | ------ |
| `CNAME` | `<YOUR_HOSTNAME>` | `<RENDER_SUBDOMAIN>`(예:`example.onrender.com`) | 견적 요청  |

:::참조

Render 설정에 대한 자세한 내용은 참조[관련 기사](https://render.com/docs/configure-cloudflare-dns).

도메인을 활성화할 수 없는 경우[DNS 레코드](/dns/proxy-status/), 당신의 Cloudflare 계정 팀 또는 당신의 렌더링 지원 팀에 도달.

:::

### wildcard subdomains에 대한 추가 요구 사항

O2O가 활성화되어 렌더링 서비스에 와일드카드 서브도메인을 추가하면 해당 루트 도메인이 Render로 전달됩니다. 루트 도메인이 다른 곳에서 경로가 있다면, 와일드카드 라우팅은 실패합니다.

루트 도메인이 Render 옆에 어딘가에 경로를 필요로한다면, 야생 카드 대신 개인 하위 도메인을 추가하십시오.

### SSL 오류 해결

SSL 오류가 발생하면 확인`CAA`이름 \*
