Workers 플랫폼은 최종 사용자에게 데이터를 공유하는 데 사용할 수있는 로그 및 분석 기능을 제공합니다.

## 로그인

플랫폼에 대한 Workers와 로그에 액세스하는 방법을 알아보세요.

### Workers Trace 이벤트 Logpush

Workers Trace 이벤트 로그는 Workers 실행 로그를 얻기 위해 사용됩니다. 더 알아보기[다운로드](/workers/observability/logs/logpush/)더 많은 정보.

Logpush는 전체 파견 네임스페이스 또는 단일 사용자 작업자에게 사용할 수 있습니다. 모든 사용자 WorkersXQ에 대한 로그를 캡처하려면

1. 이름 \*[Logpush 작업](/workers/observability/logs/logpush/#create-a-logpush-job).
2. 이름 \*[로그인](/workers/observability/logs/logpush/#enable-logging-on-your-worker)당신의 파견 노동자에.

당신의 파견 노동자에 기록하는 것은 파견 노동자 둘 다를 위한 통나무를 모으고 파견 namespace에 있는 어떤 사용자 WorkersXQ를 위해 기록합니다. 로그는 모든 새로운 WorkersXQ를 위해 자동으로 수집됩니다. 전체 파견 네임스페이스보다는 개별 사용자 작업자에게 로깅을 할 수 있도록, 사용자 작업자의 1단계와 2단계를 실행합니다.

모든 로그는 계정의 설정이있는 Logpush 작업에 전달됩니다. Logpush 필터는 사용할 수 있습니다`Outcome`또는`Script Name`특정 값을 제외하거나 다른 목적지에 로그를 보냅니다.

### 꼬리 Workers

·[꼬리 노동자](/workers/observability/logs/tail-workers/)다른 WorkersXQ의 실행에 대한 정보를 수신 (제작자 Workers), HTTP 상태와 같은 데이터 전달`console.log()`또는 부정한 예외.

제품 정보[꼬리 Workers](/workers/observability/logs/tail-workers/)Logpush 대신 로그를 포맷하기 전에 과립 제어를 원하면 목적지로 전송됩니다.[진단 채널 사건](/workers/runtime-apis/nodejs/diagnostics-channel), 또는 실시간 로그를 원하는 경우.

당신의 파견 노동자에 꼬리 노동자를 추가하는 것은 파견 노동자 둘 다를 위한 통나무를 모으고 파견 네임스페이스에 있는 어떤 사용자 WorkersXQ를 위해 기록합니다. Logs는 모든 새로운 WorkersXQ에 대한 자동 수집됩니다. 전체 파견 네임스페이스보다는 개별 사용자 작업자에게 로깅을 할 수 있도록[Tail Worker 구성](/workers/observability/logs/tail-workers/#configure-tail-workers)사용자 작업자에 직접.

## 회사 소개

플랫폼 분석을위한 WorkersXQ를 검토 할 수있는 두 가지 방법이 있습니다.

### 모델 번호: Workers Analytics 엔진

[Workers Analytics 엔진](/analytics/analytics-engine/)Workers와 함께 사용할 수 있습니다. Workers invocation 또는 사용자 정의 이벤트와 관련된 이벤트를 노출 할 수 있습니다. 플랫폼은 스크립트 태그에 의해 작성 / query 이벤트를 작성하여 사용자의 사용량에 집계를 얻을 수 있습니다.

### GraphQL 분석 API

Cloudflare의 사용[GraphQL 분석 API](/analytics/graphql-api)Dispatch Namespaces와 관련된 메트릭을 얻을 수 있습니다. 사용 방법`dispatchNamespaceName`차원에서`workersInvocationsAdaptive`node to query usage by namespace.
