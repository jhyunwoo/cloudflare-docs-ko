사용 가능[동적 파견](/cloudflare-for-platforms/workers-for-platforms/configuration/dynamic-dispatch/)Workers는 전통적인 타격 없이 WorkersXQXQXQ에 허영 도메인의 수백만을 통과하기 위하여 또는 subdomain를 WorkersXQXQ[경로 제한](/workers/platform/limits/#number-of-routes-per-zone). 이 호스트명은 관리 도메인의 하위 도메인(e.g.`customer1.saas.com`) 또는 당신의 최종 고객에 의해 통제되는 허영 도메인 (e.g.`mystore.com`)를 통해 관리될 수 있는[사용자 정의 hostnames](/cloudflare-for-platforms/cloudflare-for-saas/domain-support/).

## (추천) 파견 노동자와 Wildcard 노선

wildcard 구성[오시는 길](/workers/configuration/routing/routes/) (`*/*`) 귀하의 SaaS 도메인에 (사용자 지정 호스트 이름을 구성 하는 도메인) 당신의 동적 파견 노동자에 포인트. 이렇게 하면:

- **하위 도메인과 허영 도메인 모두 지원**: 핸들`customer1.myplatform.com`(subdomain) 및`shop.customer.com`(custom hostname)과 같은 라우팅 논리.
- **제한을 피하십시오**: 모든 도메인에 대한 개별 경로를 생성하는 대신, 당신은 충돌을 일으킬 수[노선 제한](/workers/platform/limits/#number-of-routes-per-zone), 당신은 코드 및 개인 Workers에 도메인의 프록시 수백만에 routing 논리를 처리 할 수 있습니다.
- **Programmatically 통제 routing 논리**: hostname을 기반으로하는 route 요청에 대한 사용자 정의 코드를 작성,[메타데이터](/cloudflare-for-platforms/cloudflare-for-saas/domain-support/custom-metadata/), 경로, 또는 다른 어떤 재산.

:::참조
이 모든 트래픽을 전송하는 도메인에 전송 노동자.
주요 특징

파견 노동자에게 라우팅에서 특정 호스트 이름을 제외하면 다음을 할 수 있습니다.

- 노동자 명세없이 경로 추가하여 파견자 노동자 (예를 들면, 예를 들면,`saas.com`, `api.saas.com`등)
- 지원하다[관련 도메인](/dns/zone-setups/subdomain-setup/)(예:`customers.saas.com`) 사용자 정의 호스트 이름 및 파견 노동자 관리는 그 도메인에 대한 트래픽의 나머지를 분리.

### 설치하기

hostname routing을 와일드 카드 루트로 설정하려면:

1. **사용자 지정 hostnames 구성**: 도메인 및 사용자 정의 호스트 이름 설정[SaaS를 위한 Cloudflare](/cloudflare-for-platforms/cloudflare-for-saas/)
2. **fallback 근원을 놓으십시오**: 설정[fallback 근원 서버](/cloudflare-for-platforms/cloudflare-for-saas/start/getting-started/#1-create-fallback-origin), 이것은 모든 사용자 정의 hostnames이 경로가 될 곳이다. 별도의 원산지로 경로를 원하면 사용할 수 있습니다.[사용자 정의 Origin 서버](/cloudflare-for-platforms/cloudflare-for-saas/start/advanced-settings/custom-origin/). 요청은 기원에 도달하기 전에 노동자를 통해 경로. 노동자가 근원이면 그 후에 가을에 대한 더미 DNS 레코드를 배치하십시오 (예 :`A 192.0.2.0`).
3. **DNS 구성**: Point DNS 레코드 (subdomains 또는 custom hostname)[CNAME 레코드 에 saas 도메인](/cloudflare-for-platforms/cloudflare-for-saas/start/getting-started/#3-have-customer-create-cname-record). 고객이 apex hostname(e.g.를 프록시해야 하는 경우`example.com`) CNAME 레코드를 사용할 수 없으며 체크 아웃[Apex 프록시](/cloudflare-for-platforms/cloudflare-for-saas/start/advanced-settings/apex-proxying/).
4. **Wildcard 노선 만들기**: 추가`*/*`플랫폼 도메인 (e.g. saas.com)에 대한 경로와 당신의 파견 노동자와 연관.
5. **파견 논리**: 당신의 파견 노동자에 논리를 추가하여 호스트 이름에 따라 노선을 경로를 입력하고, 저장된 맵핑을 찾습니다[Workers KV](/kv/)또는 사용[메타데이터](/cloudflare-for-platforms/cloudflare-for-saas/domain-support/custom-metadata/)custom hostnames에 붙어 있습니다.

:::참조
사용자 정의 메타 데이터를 기반으로 요청을 경로로 계획하면 하위 도메인 (e.g.)을 만들 필요가 있습니다.`customer1.saas.com`) custom hostnames로. DNS 레코드가 사용자 정의 메타 데이터를 지원하지 않기 때문에.
주요 특징

#### 예제 파견 노동자

```js
export default {
	async fetch(request, env) {
		const hostname = new URL(request.url).hostname;

		//routing 결정을 위한 custom hostname metadata를 얻으십시오
		const hostnameData = await env.KV.get(`hostname:${hostname}`, {
			type: "json",
		});

		if (!hostnameData?.workerName) {
			return new Response("Hostname not configured", { status: 404 });
		}

		//적합한 사용자 작업자 경로
		const userWorker = env.DISPATCHER.get(hostnameData.workerName);
		return await userWorker.fetch(request);
	},
};
```

## Subdomain 여정

하위 도메인 레코드를 경로를 찾고 있다면 (예를 들어.`customer1.saas.com`), 더 구체적인 노선을 사용할 수 있습니다 (`*.saas.com/*`) 당신의 파견 노동자에 노선 요구에.

### 설치하기

subdomain 여정을 설정하려면:

1. 오렌지 클라우드 와일드 카드 DNS 레코드 만들기:`*.saas.com`그것은 근원에 점. 노동자가 기원이라면 dummy DNS 값을 사용할 수 있습니다 (예를 들어,`A 192.0.2.0`).
2. 와일드 카드 노선을 설정:`*.saas.com/*`당신의 파견 노동자에 포위
3. 파견 노동자에 논리를 추가하여 Subdomain 요청을 올바른 노동자로 경로하십시오.

#### subdomain 파견 노동자

```js
export default {
	async fetch(request, env) {
		const url = new URL(request.url);
		const subdomain = url.hostname.split(".")[0];

		//하위 도메인에 근거한 노선
		if (subdomain && subdomain !== "saas") {
			const userWorker = env.DISPATCHER.get(subdomain);
			return await userWorker.fetch(request);
		}

		return new Response("Invalid subdomain", { status: 400 });
	},
};
```

### 오렌지 - 오렌지 (o2o) Behavior

고객이 Cloudflare를 사용하고 CNAME을 통해 SaaS 도메인에 사용자 정의 도메인을 지적합니다.`mystore.com` → `saas.com`), 노동자 여정 행동은 고객의 DNS 레코드가 proxied (오렌지 클라우드) 또는 DNS 전용 (회색 클라우드)인지 여부에 따라 달라집니다. 더 알아보기[Orange-to-Orange 설정](/cloudflare-for-platforms/cloudflare-for-saas/saas-customers/how-it-works/#with-o2o)

특정 호스트 루트를 사용할 때 의도적인 행동을 일으킬 수 있습니다:

- CNAME 대상을 기반으로 룰렛하는 경우 (`saas.com`), 주문 hostname의 DNS 레코드는 worker에 대 한 오렌지 클라우드 있어야 invoked.
- 사용자 지정 호스트 이름에 따라 라우팅이 있다면 (`mystore.com`), 고객의 기록은 노동자를 위해 invoked 있어야 합니다.

고객의 DNS 프록시 설정을 통해 제어하지 않을 수 있으므로, 우리는 사용하는 것이 좋습니다.`*/*`routing logic을 보장하는 와일드 카드 경로는 DNS가 구성되는 방법에 관계없이 항상 예상대로 작동합니다.

| `*/*`(추천)      | ✅                            | ✅                          |
