동일한 GraphQL Analytics API 쿼리를 여러 번 실행했을 때 결과가 조금씩 다르다면, 이는 Adaptive Bit Rate(ABR) 샘플링 때문입니다. ABR은 쿼리 복잡도와 실행 시점에 따라 데이터 해상도를 동적으로 조정하므로, 같은 쿼리라도 실행마다 약간의 차이가 생길 수 있습니다.

변동을 줄이려면 더 짧은 기간(월 단위 대신 일 단위 또는 주 단위)을 쿼리하고, 집계 데이터세트(`Groups` 접미사가 붙은 노드)를 사용하며, 데이터 품질을 이해하기 위해 신뢰 구간을 요청하세요. 자세한 내용은 [샘플링](/analytics/graphql-api/sampling/)을 참고하세요.

## 샘플링이란 무엇인가요?

Cloudflare의 데이터 파이프라인은 글로벌 네트워크 전반에서 초당 7억 건이 넘는 이벤트를 처리합니다. 모든 쿼리에 대해 이 모든 데이터를 실시간으로 처리하는 것은 비용과 시간 측면에서 비현실적입니다.

샘플링은 모든 개별 데이터 포인트 대신 일부 데이터만 분석하는 방식입니다. Cloudflare는 대규모 데이터세트를 다룰 때도 쿼리가 빠르게 완료되도록 Adaptive Bit Rate(ABR) 샘플링을 사용합니다.

ABR은 데이터를 여러 해상도로 저장합니다.

- **100%** — 전체 데이터(더 작은 데이터세트에 사용)
- **10%** — 10% 샘플(중간 해상도)
- **1%** — 1% 샘플(더 낮은 해상도)

쿼리를 실행하면 ABR은 쿼리 복잡도, 요청한 기간 범위, 검색할 행 수, 현재 시스템 부하를 바탕으로 최적의 해상도를 동적으로 선택합니다.

## 쿼리 실행마다 결과가 왜 달라지나요?

결과는 여러 이유로 달라질 수 있습니다.

- **동적 해상도 선택** — ABR은 시스템 상태에 따라 서로 다른 실행에서 서로 다른 샘플링 해상도를 선택할 수 있습니다.
- **긴 기간 범위** — 30일 전체를 한 번에 조회하면 더 공격적인 샘플링이 유발되는 비용 높은 작업이 됩니다.
- **높은 쿼리 복잡도** — 필터나 집계가 많은 복잡한 쿼리는 다르게 샘플링될 수 있습니다.
- **시스템 부하** — 트래픽이 많은 시간대에는 공정한 리소스 분배를 위해 더 공격적인 샘플링이 적용될 수 있습니다.

예를 들어 동일한 30일 쿼리를 두 번 실행했을 때 한 번은 3,500개 객체가, 다른 한 번은 3,600개 객체가 반환될 수 있습니다. 이는 서로 다른 샘플링 해상도가 사용되었음을 뜻합니다.

## 샘플링된 데이터를 신뢰할 수 있나요?

네. 샘플링된 데이터는 매우 신뢰할 수 있으며, 전체 데이터세트에서 도출된 결과만큼 믿을 수 있는 인사이트를 제공합니다. Cloudflare의 샘플링 기법은 전체 데이터세트의 핵심 특성을 포착합니다.

집계 메트릭(총합, 평균, 백분위수)은 샘플 크기를 기반으로 외삽되므로, 보고된 메트릭은 전체 데이터세트를 정확하게 대표합니다. 수천 개 행을 기반으로 한 결과는 대표성이 높을 가능성이 큽니다.

:::note
샘플링은 발생 빈도가 극히 낮은 매우 희귀한 이벤트를 포착하지 못할 수 있습니다.
:::

## 쿼리 결과의 변동을 어떻게 줄일 수 있나요?

### 더 짧은 기간 범위를 쿼리하기

한 번에 한 달 전체를 쿼리하는 대신, 더 작은 간격(일 단위 또는 주 단위)으로 나누어 쿼리하세요.

이전(변동성 높음):

```graphql
datetime_geq: "2024-09-01T00:00:00Z"
datetime_lt: "2024-10-01T00:00:00Z"
```

이후(더 일관적임):

```graphql
datetime_geq: "2024-09-01T00:00:00Z"
datetime_lt: "2024-09-02T00:00:00Z"
```

그런 다음 클라이언트 측에서 결과를 집계하세요. 더 작은 시간 창은 공격적인 샘플링 임계값을 유발할 가능성이 더 낮습니다.

### 집계 데이터세트 사용하기

원시 적응형 데이터세트보다 `Groups` 접미사가 붙은 데이터 노드를 우선 사용하세요. 집계 데이터는 사전 처리되어 있어 샘플링 변동성의 영향을 덜 받습니다.

예를 들어 원시 이벤트 데이터 대신 `httpRequestsAdaptiveGroups`를 사용하세요.

### 명시적 정렬 추가하기

항상 쿼리에 `orderBy`를 포함하여 일관된 결과 순서를 보장하세요.

```graphql
orderBy: [datetime_ASC]
```

### 신뢰 구간 사용하기

적응형 데이터세트에서는 데이터 품질을 이해하고 샘플링을 검증하기 위해 [신뢰 구간](/analytics/graphql-api/features/confidence-intervals/)을 요청하세요.

```graphql
confidence(level: 0.95) {
  count {
    estimate
    lower
    upper
    sampleSize
  }
}
```

더 높은 `sampleSize`는 더 신뢰할 수 있는 결과를 의미합니다.

## 빠른 참조

| 문제 | 완화 방법 |
| --- | --- |
| 실행마다 결과가 달라짐 | 더 짧은 기간 범위(월 대신 일/주 단위)로 쿼리 |
| 큰 쿼리에서 공격적인 샘플링 | 쿼리를 더 작은 시간 간격으로 나누고 클라이언트 측에서 집계 |
| 일관된 정렬이 필요함 | 모든 쿼리에 `orderBy` 절 추가 |
| 데이터 품질을 검증해야 함 | `confidence` 구간을 요청해 샘플 크기와 정확도 확인 |
| 원시 적응형 데이터 사용 중 | 집계 데이터세트(`Groups` 접미사가 붙은 노드)로 전환 |
