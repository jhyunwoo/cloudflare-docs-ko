Cloudflare는 분석 기능을 모든 제품의 보편적인 구성 요소로 만들기 위해, 고객이 Cloudflare 위의 인터넷 자산에서 인사이트를 얻고 접근할 수 있는 여러 방법을 구현해 왔으며 지금도 계속 발전시키고 있습니다.

Cloudflare 계정과 관련된 메타데이터를 개괄적으로 보여 주는 루트 수준 분석, 특정 자산 및 제품과 관련된 분석, 그리고 Cloudflare 대시보드에서 제공되는 분석 및 로그 정보를 시각화하는 방식을 더 세밀하게 제어할 수 있는 GraphQL API에 접근할 수 있습니다.

이 주제에 대한 자세한 내용은 [분석 유형](/analytics/types-of-analytics/)을 참고하세요.

## Cloudflare가 분석 데이터를 수집하고 처리하는 방법

Cloudflare Analytics가 수집하고 처리하는 기본 데이터세트는 다음과 같은 특성을 공유합니다.

* 모든 메트릭은 Cloudflare DNS 앱의 DNS 레코드 설정에 따라 Cloudflare 네트워크를 통해 프록시된(오렌지 클라우드 처리된) 트래픽을 반영합니다. [CNAME 설정](/dns/zone-setups/partial-setup/)의 경우 Cloudflare는 DNS 메트릭을 제공할 수 없습니다.
* Cloudflare는 프록시되지 않은 DNS 레코드의 트래픽은 집계하지 않습니다. 그러나 사이트가 Cloudflare를 통해 프록시되지 않더라도 Cloudflare가 권한 있는 DNS 서버라면 DNS 메트릭은 수집할 수 있습니다.
* Cloudflare는 [특정 포트](/fundamentals/reference/network-ports/)를 대상으로 하는 트래픽 정보만 프록시할 수 있습니다.
* 원래 국가를 판별할 때 Cloudflare는 각 요청에 연관된 IP 주소를 사용합니다. [Cloudflare IP Geolocation 구성](/network/ip-geolocation/)에 대해 알아보세요.

## 겉보기 데이터 차이

Cloudflare 메트릭이 Google Analytics나 웹 서버 로그처럼 동일한 사이트에 대한 다른 분석 소스의 데이터와 완전히 일치하지 않을 수 있습니다.

Cloudflare가 요청에 대해 고유 IP 주소를 식별하면 해당 요청을 방문으로 간주합니다. 따라서 Cloudflare Analytics가 표시하는 방문자 수는 다른 분석 서비스가 보고하는 수보다 더 높을 가능성이 있습니다.

예를 들어 Google Analytics와 다른 웹 기반 분석 프로그램은 방문자를 추적하기 위해 웹 브라우저에서 JavaScript를 사용합니다. 따라서 위협, 봇, 자동화된 크롤러 요청은 일반적으로 JavaScript를 실행하지 않으므로 Google Analytics에는 기록되지 않습니다. 또한 브라우저에서 JavaScript를 비활성화한 방문자나 페이지가 완전히 로드되기 전에 떠난 방문자도 이런 서비스에서는 추적되지 않습니다.

마지막으로 Cloudflare Analytics 앱의 고유 방문자 데이터가 검색 분석의 고유 페이지뷰보다 더 클 가능성이 높습니다. 페이지뷰는 누군가 웹 브라우저를 통해 페이지에 방문하고 전체 페이지를 로드했을 때를 반영합니다. 하지만 봇, 플러그인, API 같은 다른 사이트나 서비스가 사이트의 일부 콘텐츠만 소비하고 전체 페이지를 로드하지 않는 경우, Cloudflare에서는 이를 고유 방문자로 집계하지만 페이지뷰로는 집계하지 않습니다.

## 메트릭이 누락되는 경우

다음과 같은 이유로 Cloudflare Analytics에서 메트릭이 보이지 않을 수 있습니다.

* Cloudflare에 가입한 지 얼마 되지 않은 경우입니다. 무료 Cloudflare 플랜의 도메인 메트릭은 24시간 지연됩니다.
* Cloudflare에 직접 가입한 경우, 등록기관에서 네임서버가 아직 Cloudflare를 가리키지 않을 수 있습니다. 등록기관의 네임서버 업데이트에는 24~72시간이 걸릴 수 있습니다. Cloudflare를 가리키는 네임서버를 감지하기 전까지는 메트릭 수집이 시작되지 않습니다.
* Cloudflare [호스팅 파트너 옵션](https://www.cloudflare.com/partners/)을 통해 가입한 경우, 설정이 올바르지 않을 수 있습니다. 지원이 필요하면 호스팅 파트너에 문의하세요.
* 광고 차단용 브라우저 확장 프로그램 일부가 분석 로딩을 막을 수 있습니다. 이 문제를 해결하려면 광고 차단 확장을 비활성화하거나 `cloudflare.com`을 허용 목록에 추가하세요.

:::note
호스팅 파트너를 통한 활성화는 `www` 레코드의 [CNAME 설정](/dns/zone-setups/partial-setup/)을 통해 작동합니다. 실제 트래픽 대부분이 `domain.com`으로 간다면 `domain.com`에서 `www.domain.com`으로 [트래픽을 전달](/rules/url-forwarding/bulk-redirects/)하세요.
:::

## **Overview** 페이지의 분석 데이터가 **View More Analytics** 아래 데이터와 일치하지 않는 이유는 무엇인가요?

Overview 페이지는 하위 요청을 포함한 모든 트래픽을 기반으로 분석을 표시합니다. 하지만 **Analytics & Logs** > **HTTP Traffic**으로 이동하면 메트릭(`Requests`, `Data`, `Visits` 등)은 최종 사용자 트래픽만 표시하도록 필터링됩니다(즉, `requestSource = eyeball`).

그 결과 하위 요청은 **HTTP Traffic** 보기에서 제외되며, 이 때문에 **Overview**와 대시보드의 다른 분석 섹션에 표시되는 수치 간 차이가 생길 수 있습니다.
