이 튜토리얼은 [Cloudflare App for Splunk](https://splunkbase.splunk.com/app/4501/)를 사용해 [Cloudflare Logs](https://www.cloudflare.com/products/cloudflare-logs/)를 분석하는 방법을 설명합니다.

## 사전 요구 사항

Cloudflare 로그 데이터를 Splunk로 보내기 전에 다음을 확인하세요.

- 기존 Splunk Enterprise 또는 Cloud 계정이 있어야 합니다.
- Cloudflare Enterprise 계정이 있어야 합니다.
- Cloudflare App에 대한 [Splunk 문서](https://splunkbase.splunk.com/app/4501/)를 참고합니다.

## 작업 1 - Cloudflare App for Splunk 설치 및 구성

[Cloudflare App for Splunk](https://splunkbase.splunk.com/app/4501/)를 설치하려면 다음 단계를 따르세요.

1. Splunk 인스턴스에 로그인합니다.
2. **Apps** > **Find More Apps**에서 _Cloudflare App for Splunk_ 를 검색합니다.
3. **Install**을 클릭합니다.

![Splunk website with Apps menu expanded and Search & Reporting menu item along with Cloudflare App for Splunk](~/assets/images/fundamentals/splunk/screenshots/splunk-cloudflare-app-for-splunk.png)

4. Splunk 인스턴스를 재시작하고 다시 엽니다.

5. Cloudflare App for Splunk에서 `cloudflare:json` source type을 편집합니다. 편집 방법은 다음과 같습니다.
   1. **Settings** 드롭다운을 클릭하고 **Source types**를 선택합니다.
   2. **Show only popular** 체크를 해제한 뒤 _cloudflare_ 를 검색합니다.
   3. **Edit**를 클릭하고 Regex 식을 `([\r\n]+)`로 변경합니다.
   4. 변경 사항을 저장합니다.

6. HTTP Event 로그를 저장할 인덱스를 Splunk에 생성합니다. 인덱스 생성 방법은 다음과 같습니다.
   1. **Settings** 드롭다운을 클릭한 뒤 **Indexes**를 선택해 설정 화면을 엽니다.
   2. **New Index**를 선택합니다. **Indexes** 페이지에서는 기존 인덱스의 상태도 볼 수 있어 라이선스 용량을 곧 소진할지 확인할 수 있습니다.
   3. Cloudflare App이 기본적으로 사용하는 인덱스인 **cloudflare**라는 이름을 지정합니다.

7. Splunk에서 HTTP Event Collector(HEC)를 설정합니다. HEC 생성 방법은 다음과 같습니다.
   1. **Settings** 드롭다운을 클릭하고 **Data inputs**를 선택합니다.
   2. **+Add new**를 클릭하고 마법사를 따라갑니다. 요청되면 다음 정보를 입력합니다.
      - Name: Cloudflare
      - Source Type: Select > "cloudflare:json"
      - App Context: Cloudflare App for Splunk (cloudflare)
      - Index: cloudflare
   3. 마법사 마지막에 **Token Value**가 표시됩니다. 이 토큰은 Cloudflare Logpush 작업이 Splunk 인스턴스로 데이터를 보낼 수 있도록 인증합니다. 지금 복사하지 못해도 Splunk에서 언제든 값을 다시 확인할 수 있습니다.

8. Splunk가 자체 서명 인증서를 사용하는지 확인합니다. 이 정보는 Logpush 작업 생성 시 필요합니다.

9. 데이터를 전송할 엔드포인트를 확인합니다. 엔드포인트는 다음 형식이어야 합니다.

```sql
"<protocol>://input-<host>:<port>/<endpoint>" or "<protocol>://http-inputs-<host>:<port>/<endpoint>"
```

각 항목의 의미는 다음과 같습니다.

- `protocol`: HTTP 또는 HTTPS
- `input`: self-service 또는 managed cloud 플랜에 따라 `input` 또는 `http-inputs`
- `host`: Splunk 인스턴스의 호스트명. 가장 쉬운 방법은 Splunk 로그인 시 사용한 URL을 확인하는 것입니다.
- `port`: 443 또는 8088
- `endpoint`: services/collector/raw

예: `https://prd-p-0qk3h.splunkcloud.com:8088/services/collector/raw`. 자세한 내용과 예시는 [Splunk Documentation](https://docs.splunk.com/Documentation/SplunkCloud/latest/Data/UsetheHTTPEventCollector)를 참고하세요.

**설치 후 참고 사항**

초기 구성 이후 **Settings** 드롭다운에서 **Advanced search**로 이동해 **Search macros**를 선택하면 **Index Name**을 변경할 수 있습니다.

![Splunk interface highlighting Apps menu and Manage Apps option along with Enable Acceleration checkbox](~/assets/images/fundamentals/splunk/screenshots/splunk-settings-advanced-search-search-macros.png)

Cloudflare App for Splunk에는 사용자 지정 Cloudflare Data Model이 포함되어 있으며 가속 기간은 1일이지만 기본적으로 가속은 비활성화되어 있습니다. [Data Model acceleration](https://docs.splunk.com/Documentation/Splunk/latest/Knowledge/Acceleratedatamodels)을 활성화하려면 Splunk 환경에 부정적 영향이 없도록 1일 또는 7일만 가속하는 것을 권장합니다.

초기 구성 이후 가속을 켜거나 끄려면 **Apps** 드롭다운에서 **Manage Apps** > **Cloudflare Set Up**을 클릭해 앱 설정 페이지로 이동하세요.

![Splunk Advanced Search page highlighted Search macros and Advanced search](~/assets/images/fundamentals/splunk/screenshots/splunk-apps-manage-apps-cloudflare-set-up-enable-data-model-acceleration.png)

**Settings** > **Data models**로 이동해 Data Model을 수동 구성할 수도 있습니다. Data model acceleration에 대한 자세한 내용은 [Splunk documentation](https://docs.splunk.com/Documentation/Splunk/latest/Knowledge/Acceleratedatamodels)를 참고하세요.

## 작업 2 - API 호출로 Logpush 작업 생성

[Enable Logpush to Splunk](/logs/logpush/logpush-job/enable-destinations/splunk/)의 안내에 따라 Logpush 작업을 생성합니다. API 호출은 Logpush 작업을 생성하지만 활성화하지는 않습니다.

[Enable Logpush to Splunk](/logs/logpush/logpush-job/enable-destinations/splunk/) 안내에 따라 Cloudflare 대시보드 또는 API를 통해 Logpush 작업을 활성화합니다. 대시보드에서 활성화하려면 다음을 따르세요.

1. Cloudflare 대시보드에서 **Analytics & Logs** > **Logs**를 선택합니다.
2. **Edit**를 선택하고 아래 Dashboard 섹션에서 참조하는 필드를 선택하여 모든 표와 그래프가 완전히 채워지도록 합니다.
3. Edit 링크 옆의 스위치를 켜서 Logpush 작업을 활성화합니다. 데이터가 채워지기까지 몇 분이 걸립니다.

데이터 수신 여부를 확인하려면 Splunk에서 `index=cloudflare`를 검색하세요.

## 작업 3 - 대시보드 보기

아래 나열된 열세(13) 개 대시보드로 Cloudflare 로그를 분석할 수 있습니다.

이 대시보드의 필터를 사용하면 날짜와 시간, 디바이스 유형, 국가, user agent, 클라이언트 IP, 호스트명 등을 기준으로 분석 범위를 좁혀 디버깅과 추적에 도움을 받을 수 있습니다.

### 대시보드 소개

아래에서 설명하는 대시보드는 Cloudflare App for Splunk의 일부로 제공됩니다.

#### Cloudflare - Snapshot

_Web Traffic Overview_ 및 _Web Traffic Types_: Cloudflare 네트워크 상의 웹사이트와 애플리케이션에서 가장 중요한 메트릭의 개요를 제공합니다.
![Splunk dashboard with Web Traffic Overview metrics](~/assets/images/fundamentals/splunk/dashboards/splunk-cloudflare-snapshot-dashboard.png)

#### Cloudflare - Reliability

_Summary_ 및 _Detailed_: 웹사이트와 애플리케이션의 가용성에 대한 인사이트를 제공합니다. 메트릭에는 원본 응답 오류 비율, 시간 경과에 따른 원본 응답 상태, 시간 경과에 따른 3xx/4xx/5xx 오류 비율 등이 포함됩니다.
![Splunk dashboard with a high level summary of Reliability metrics](~/assets/images/fundamentals/splunk/dashboards/splunk-cloudflare-reliability-summary-dashboard.png)

![Splunk dashboard with a detailed summary of Reliability metrics](~/assets/images/fundamentals/splunk/dashboards/splunk-cloudflare-reliability-detailed-dashboard.png)

#### Cloudflare - Security

_Overview_: 차단된 위협 수, 시간 경과에 따른 위협, 상위 위협 국가 등을 포함하여 웹사이트와 애플리케이션에 대한 위협 인사이트를 제공합니다.
![Splunk dashboard with an overview of Security metrics](~/assets/images/fundamentals/splunk/dashboards/splunk-cloudflare-security-overview.png)

_WAF_: SQL 인젝션, XSS 등 Web Application Firewall의 위협 식별 및 완화 이벤트에 대한 인사이트를 제공합니다. 이 데이터를 사용해 명백한 위협을 겨냥하도록 방화벽을 세밀하게 조정하고 오탐을 방지할 수 있습니다.
![Splunk dashboard with an overview of Security metrics for WAF](~/assets/images/fundamentals/splunk/dashboards/splunk-cloudflare-security-waf-dashboard.png)

_Rate Limiting_: 서비스 거부 공격, 무차별 대입 로그인 시도 및 웹사이트나 애플리케이션을 노리는 기타 남용 행위에 대한 속도 제한 보호 인사이트를 제공합니다.
![Splunk dashboard with an overview of Security metrics for Rate Limiting](~/assets/images/fundamentals/splunk/dashboards/splunk-cloudflare-security-rate-limiting-dashboard.png)

_Bots Summary_ 및 _Bots Detailed_: 콘텐츠 스크래핑, 결제 사기, 스팸 등록 및 기타 악의적 활동을 방지하기 위해 웹사이트의 봇 활동을 조사할 수 있습니다.
![Splunk dashboard with a high level summary of Security metrics for Bots](~/assets/images/fundamentals/splunk/dashboards/splunk-cloudflare-security-bot-summary-dashboard.png)

![Splunk dashboard with a detailed summary of Security metrics for Bots](~/assets/images/fundamentals/splunk/dashboards/splunk-cloudflare-security-bots-detailed-dashboard.png)

#### Cloudflare - Performance

_Requests and Cache_ 및 _Bandwidth_: 성능 문제와 캐시 구성 오류를 식별하고 해결합니다. 메트릭에는 총/캐시된 대역폭, 절약된 대역폭, 총 요청 수, 캐시 비율, 상위 비캐시 요청 등이 포함됩니다.
![Splunk dashboard with Performance metrics for Requests and Cache](~/assets/images/fundamentals/splunk/dashboards/splunk-cloudflare-performance-requests-and-cache-dashboard.png)

![Splunk dashboard with Performance metrics for Bandwidth](~/assets/images/fundamentals/splunk/dashboards/splunk-cloudflare-performance-bandwidth-dashboard.png)

_Hostname, Content Type, Request Methods, Connection Type_: 가장 인기 있는 호스트명, 가장 많이 요청되는 콘텐츠 유형, 요청 메서드 분포, 연결 유형에 대한 인사이트를 제공합니다.

![Splunk dashboard with Cloudflare Performance metrics including for Hostname, Content Type, Request Methods, Connection Type](~/assets/images/fundamentals/splunk/dashboards/splunk-cloudflare-performance-hostname-dashboard.png)

_Static vs. Dynamic Content_: 가장 느린 URL을 포함하여 정적 및 동적 콘텐츠의 성능에 대한 인사이트를 제공합니다.
![Splunk dashboard with Cloudflare Performance metrics for Static vs. Dynamic Content](~/assets/images/fundamentals/splunk/dashboards/splunk-cloudflare-performance-static-vs-dynamic-dashboard.png)

### 필터

모든 대시보드에는 다음 예시와 같이 전체 대시보드에 적용할 수 있는 필터 세트가 있습니다. 필터는 대시보드 전체에 적용됩니다.

![Available dashboard filters from the Splunk dashboard](~/assets/images/fundamentals/splunk/screenshots/splunk-filters.png)

필터를 사용해 데이터를 세밀한 수준까지 드릴다운해 확인할 수 있습니다. 필터에는 클라이언트 국가, 클라이언트 디바이스 유형, 클라이언트 IP, 클라이언트 요청 호스트, 클라이언트 요청 URI, 클라이언트 요청 user agent, 엣지 응답 상태, 원본 IP, 원본 응답 상태가 포함됩니다.

기본 시간 간격은 24시간으로 설정됩니다. 정확한 계산을 위해서는 Worker 하위 요청(**WorkerSubrequest** = _false_)과 purge 요청(**ClientRequestMethod**가 _PURGE_ 가 아님)을 필터에서 제외해야 합니다.

사용 가능한 필터:

- Time Range (EdgeStartTimestamp)

- Client Country

- Client Device type

- Client IP

- Client Request Host

- Client Request URI

- Client Request User Agent

- Edge response status

- Origin IP

- Origin Response Status

- RayID

- Worker Subrequest

- Client Request Method

## 디버깅 팁

### 불완전한 대시보드

Splunk용 Cloudflare App은 아래에 나열된 Cloudflare Enterprise Logs 필드 데이터를 사용합니다. 활성화한 필드에 따라 일부 대시보드는 완전히 채워지지 않을 수 있습니다.

그런 경우 각 대시보드 아래의 Cloudflare App 필터를 확인하고 테스트하세요(이 필터는 모든 대시보드에서 동일합니다). 로그에 이미 포함된 데이터 필드가 있는 경우라도 필요 없는 필터는 삭제할 수 있습니다.

또한 Cloudflare Logs에서 수신되는 필드 목록을 **Splunk** > **Settings** > **Data Model** > **Cloudflare**에 나열된 필드와 비교해 볼 수 있습니다.

- ClientASN

- ClientIP

- ClientRequestProtocol

- ClientRequestReferer

- ClientRequestURI

- ClientRequestUserAgent

- ClientSSLCipher

- ClientSSLProtocol

- ClientSrcPort

- EdgeColoCode

- EdgeColoID

- EdgeEndTimestamp

- EdgePathingOp

- EdgePathingSrc

- EdgePathingStatus

- EdgeRequestHost

- EdgeResponseBytes
