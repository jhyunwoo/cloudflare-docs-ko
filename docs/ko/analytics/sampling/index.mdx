[샘플링](https://en.wikipedia.org/wiki/Sampling_(statistics))은 개별 데이터 포인트를 모두 처리하는 대신 데이터의 일부만 분석하는 기법입니다. Cloudflare Analytics에서 샘플링은 높은 정확성과 신뢰성을 유지하면서 효율적인 성능과 확장성을 보장합니다. 이 문서는 샘플링이 어떻게 작동하는지, 왜 사용하는지, 그리고 다양한 Cloudflare 도구 전반의 분석에 어떤 영향을 주는지에 대한 종합적인 개요를 제공합니다.

## 샘플링 작동 방식

대규모 데이터세트를 다룰 때도 쿼리가 빠르게 완료되도록 [Adaptive Bit Rate (ABR)](https://blog.cloudflare.com/explaining-cloudflares-abr-analytics/)라는 샘플링 방식을 사용합니다. ABR은 쿼리 복잡도와 실행 시간에 따라 조회되는 데이터의 상세 수준을 동적으로 조정합니다. 이 접근 방식은 크거나 복잡한 쿼리가 계산 리소스를 과도하게 점유해 더 작은 쿼리를 지연시키거나 차단하지 않도록 하여 공정성을 보장합니다. 리소스를 더 균등하게 분배함으로써 ABR은 데이터세트 크기와 상관없이 모든 사용자가 일관된 성능을 경험하도록 돕습니다.

이를 위해 데이터는 서로 다른 샘플링 비율을 나타내는 여러 해상도(100%, 10%, 1%)로 저장됩니다. 쿼리가 실행되면 ABR은 쿼리 복잡도와 조회할 행 수를 바탕으로 가장 적절한 해상도를 선택합니다. 데이터 해상도를 동적으로 조정함으로써 ABR은 성능을 최적화하고 지연을 방지합니다. 이 점은 대규모 데이터세트를 다룰 때 시간 초과, 오류, 높은 비용을 겪는 시스템과 차별화됩니다.

## 샘플링이 적용되는 이유

Cloudflare의 데이터 파이프라인은 전 세계 네트워크 전반에서 [초당 7억 건이 넘는 이벤트](https://blog.cloudflare.com/how-we-make-sense-of-too-much-data)를 처리하며, 그 규모는 계속 증가하고 있습니다. 이 모든 데이터를 실시간으로 처리하고 저장하는 일은 비용과 시간 측면에서 매우 비효율적입니다. Cloudflare Analytics는 정교하게 설계된 샘플링 방식을 활용하여 정확하고 실행 가능한 데이터를 제공하며, 정밀도와 성능의 균형을 맞춥니다.

샘플링은 다음을 가능하게 합니다.

- **확장성**: 인사이트를 손상시키지 않으면서 처리되는 데이터 양을 줄입니다.
- **성능**: 분석 쿼리 실행 속도를 높입니다.
- **비용 효율성**: 리소스 사용량과 저장소 요구량을 최소화합니다.

## 샘플링된 데이터를 신뢰할 수 있나요?

샘플링된 데이터는 매우 신뢰할 수 있으며, 전체 데이터세트에서 도출한 결과만큼 믿을 수 있는 인사이트를 제공할 수 있습니다. Cloudflare는 전체 데이터세트의 핵심 특성을 포착하도록 샘플링 기법을 설계하여, 신뢰할 수 있는 결과를 제공합니다.

샘플링은 다른 분야에서도 비슷하게 사용됩니다. 예를 들면 다음과 같습니다.

- Google 지도: 온라인 지도가 축소 시 저해상도 이미지를, 확대 시 고해상도 이미지를 표시해 전체 픽셀 수를 비교적 일정하게 유지하는 것처럼, Cloudflare Analytics도 데이터세트 크기와 상관없이 일관되고 정확한 결과를 반환하도록 샘플링 비율을 동적으로 조정합니다.
- 여론 조사: 여론 조사 기관이 전체 인구 중 일부를 표본으로 삼아 선거 결과를 예측하듯, Cloudflare도 데이터의 일부를 샘플링하여 시스템 전체 수준의 정확한 인사이트를 제공합니다.
- 영화 프레임: 초당 60프레임 대신 30프레임으로 영화를 보더라도 전체 경험이 크게 달라지지 않는 것처럼, 더 적은 데이터 포인트를 분석해도 분석 데이터세트의 동일한 패턴과 추세를 파악할 수 있습니다.

현재는 ABR 쿼리 결과의 정확한 해상도를 검증하기가 다소 어려울 수 있다는 점을 알고 있습니다. 하지만 일반적으로는 읽은 행 수를 확인하면 됩니다. 더 많은 행을 읽을수록 결과 해상도는 더 높아집니다. 예를 들어 수천 개 행을 기반으로 한 결과는 대표성이 높을 가능성이 크지만, 몇 개 행만 기반으로 한 결과는 그만큼 신뢰하기 어려울 수 있습니다.

가까운 미래에는 쿼리 결과와 함께 신뢰 구간도 제공하여, 결과가 얼마나 정확한지 정확히 확인할 수 있도록 할 예정입니다.

## 추가 고려 사항

**샘플링이 발생하는 시점**
- 샘플링은 일반적으로 전체 데이터 분석이 비현실적인 매우 높은 트래픽 데이터세트에 적용됩니다.
- 더 작은 데이터세트의 경우에는 샘플링 없이 전체 데이터를 분석하는 경우가 많습니다.

**샘플링 비율**
- 샘플링 비율은 데이터세트와 제품에 따라 달라집니다.
- Cloudflare는 쿼리 전반에서 정확도를 유지하기 위해 단일 데이터세트 내에서 샘플링 비율이 일관되도록 보장합니다.

**메트릭에 미치는 영향**
- 샘플링은 처리되는 데이터 양을 줄이지만, 총합, 평균, 백분위수 같은 집계 메트릭은 샘플 크기를 기반으로 외삽됩니다. 이를 통해 보고되는 메트릭이 전체 데이터세트를 정확히 대표하도록 합니다.

**제한 사항**
- 샘플링은 발생 빈도가 매우 낮은 극히 드문 이벤트를 포착하지 못할 수 있습니다.

**분석 인터페이스에서의 샘플링**
- GraphQL API: 샘플링 메타데이터가 쿼리 응답에 포함됩니다. 자세한 내용은 [GraphQL Analytics API](/analytics/graphql-api/sampling/)의 샘플링 문서를 참고하세요.
- Workers Analytics Engine: 자세한 내용은 [Workers Analytics Engine](/analytics/analytics-engine/sampling/) 문서를 참고하세요.
- Dashboard Analytics: 시각화에 샘플링된 데이터가 사용된 경우, 샘플링 비율을 나타내는 아이콘을 표시합니다.
