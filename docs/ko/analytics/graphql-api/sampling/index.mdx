Cloudflare에서 샘플링이 어떻게 작동하는지 자세히 알아보려면 [Understanding sampling in Cloudflare Analytics](/analytics/sampling/)를 참고하세요.

## 개요

드문 경우이지만 Cloudflare 대시보드와 GraphQL Analytics API에서 제공하는 분석은 **샘플**(데이터세트의 일부)을 기반으로 합니다. 이 경우 Cloudflare Analytics는 샘플 값에서 계산한 추정치를 반환합니다. 예를 들어 공격 중 샘플링 비율이 10%이고 5,000개의 이벤트가 샘플링되었다면, Cloudflare는 총 이벤트 수를 50,000개(5,000 × 10)로 추정해 Analytics에 보고합니다.

## 샘플링된 데이터세트

Cloudflare GraphQL API는 적응형 샘플링으로 구동되는 데이터세트를 제공합니다. 이러한 노드 이름에는 **Adaptive**가 포함되며 [introspection][1]을 통해 확인할 수 있습니다.

샘플링된 데이터의 존재 여부는 Cloudflare 대시보드와 API의 데이터세트 설명에도 표시됩니다.

## 샘플링을 적용하는 이유

Analytics는 요청된 데이터를 적절한 상세 수준으로 가능한 한 빠르게 제공하도록 설계되었습니다. 샘플링을 사용하면 Cloudflare는 공격 중 갑자기 급증하는 Firewall 이벤트처럼 데이터세트 규모가 빠르고 예측 불가능하게 커질 때에도 몇 초 안에 분석 결과를 제공할 수 있습니다. 또한 기초 데이터량이 매우 크기 때문에 샘플에서 추정한 값은 여전히 통계적으로 유의미하며, 높은 신뢰도로 샘플링된 데이터를 사용할 수 있습니다. 샘플링이 없다면 쿼리 응답에 몇 분 이상 걸릴 수 있으며, 이는 완화 조치를 검증할 때 너무 긴 대기 시간일 수 있습니다.

## 샘플링 유형

### 적응형 샘플링

Cloudflare는 거의 항상 **적응형 샘플링**을 사용합니다. 즉, 샘플 비율이 수집되거나 조회되는 데이터량에 따라 변동합니다. 레코드 수가 비교적 적으면 샘플링을 사용하지 않습니다. 하지만 레코드 양이 커질수록 점점 더 낮은 샘플 비율이 적용됩니다. Security Events(Firewall Events라고도 함)와 Security Event Log가 이 모델을 따릅니다. 적응형 샘플링을 사용하는 데이터 노드는 `firewallEventsAdaptive`처럼 노드 이름의 `Adaptive` 접미사로 쉽게 식별할 수 있습니다.

### 고정 샘플링

다음 데이터 노드는 샘플 비율이 변하지 않는 고정 샘플링을 기반으로 합니다.

| Data set                                                                                                                                       |   Rate | Notes                                                                                                                                                                                                |
| :--------------------------------------------------------------------------------------------------------------------------------------------- | -----: | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Firewall Rules Preview<br /><p><b>Nodes:</b><br />`firewallRulePreviewGroups`</p>                                                              |     1% | 주의해서 사용하세요. 1% 샘플 비율은 특정 임계값보다 작은 데이터세트에 대해 정확한 추정치를 제공하지 않으며, Cloudflare 대시보드는 이를 명시적으로 알리지만 API는 그렇지 않습니다. |
| Network Analytics<br /><p><b>Nodes:</b><br />`ipFlows1mGroups`<br />`ipFlows1hGroups`<br />`ipFlows1dGroups`<br />`ipFlows1mAttacksGroups`</p> | 0.012% | 샘플링 비율은 패킷 수 기준입니다(8,192개 패킷마다 1개).                                                                                                                                                |

## 원시 데이터 접근

샘플링은 주로 적응형으로 동작하며 정확한 추정치를 제공하도록 자동 조정되므로, 샘플링 비율을 직접 제어할 수는 없습니다. Enterprise 고객은 Cloudflare Logs를 통해 원시 데이터에 접근할 수 있습니다.
