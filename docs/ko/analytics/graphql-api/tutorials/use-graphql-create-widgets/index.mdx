쿼리를 만들고 테스트할 때는 다음 워크플로를 사용하세요.

- Cloudflare Analytics GraphQL API에 인증하기 위해 [GraphiQL](https://www.gatsbyjs.com/docs/how-to/querying-data/running-queries-with-graphiql/) 앱을 설치하고 구성합니다. Cloudflare는 토큰 인증을 권장합니다. 자세한 내용은 [Analytics API 토큰 구성](/analytics/graphql-api/getting-started/authentication/api-token-auth/)을 참조하세요.
- GraphiQL에서 쿼리를 작성합니다. GraphQL 클라이언트의 내장 문서을 사용해 사용 가능한 노드를 탐색할 수 있습니다. 쿼리에 대한 자세한 내용은 [Querying basics](/analytics/graphql-api/getting-started/querying-basics/)를 참조하세요.
- GraphiQL에서 실행하거나 GraphQL API 엔드포인트로 보내는 cURL 요청의 payload로 전달하여 쿼리를 테스트합니다.
- 애플리케이션에서 이 쿼리를 사용해 대시보드 위젯에 데이터를 제공합니다.

## 매개변수와 필터

이 예제들은 조회하려는 Cloudflare 계정의 account ID를 사용합니다. 이를 변수(`accountTag`)로 정의하고 쿼리에서 참조할 수 있습니다.

쿼리는 또한 조회하려는 시간 간격을 지정하기 위해 필터를 사용합니다. 필터는 시작 시간과 종료 시간을 사용해 시간 간격을 정의합니다. 어떤 기간을 조회하느냐에 따라 시작 및 종료 시간을 지정하는 속성이 달라집니다. 필터에 대한 자세한 내용은 [Filtering](/analytics/graphql-api/features/filtering/)을 참조하세요.

다음 예제는 날짜가 `date_geq` 이상이고 `date_leq` 이하인 데이터를 조회합니다.

```json title="계정 및 쿼리 시간 간격 설정"
{
	"accountTag": "{account-id}",
	"filter": {
		"AND": [{ "date_geq": "2020-01-19" }, { "date_leq": "2020-01-20" }]
	}
}
```

이 표는 특정 시간 선택에 대해 데이터를 조회할 때 사용해야 하는 Network Analytics 데이터셋(노드)과 `datetimeDimension`을 보여줍니다.

집계된 데이터 보기가 필요할 때는 `Groups` 쿼리 노드를 사용하세요. 예를 들어 `ipFlows1mAttacksGroups` 데이터셋은 공격 활동의 분 단위 롤업 보고서를 나타냅니다. 자세한 내용은 [Datasets](/analytics/graphql-api/features/data-sets/)를 참조하세요.

## 시계열 그래프

Network Analytics의 시계열 그래프를 만들려면 다음 쿼리를 사용하세요.

```graphql graphql-api-explorer title="시계열 그래프"
query ipFlowTimeseries(
	$accountTag: string
	$filter: AccountIpFlows1mGroupsFilter_InputObject
) {
	viewer {
		accounts(filter: { accountTag: $accountTag }) {
			ipFlows1mGroups(
				limit: 1000
				filter: $filter
				orderBy: datetimeMinute_ASC
			) {
				dimensions {
					timestamp: datetimeMinute
					attackMitigationType
					attackId
				}
				sum {
					bits
					packets
				}
			}
		}
	}
}
```

## 활동 로그

이 쿼리는 IP flow에서 공격 트래픽의 분 단위 롤업을 요약한 활동 로그를 반환합니다. 쿼리는 `dimensions` 객체에 나열된 필드를 기준으로 데이터를 그룹화합니다.

```graphql graphql-api-explorer title="활동 로그 쿼리"
query ipFlowEventLog(
	$accountTag: string
	$filter: AccountIpFlows1mAttacksGroupsFilter_InputObject
) {
	viewer {
		accounts(filter: { accountTag: $accountTag }) {
			ipFlows1mAttacksGroups(
				limit: 10
				filter: $filter
				orderBy: [min_datetimeMinute_ASC]
			) {
				dimensions {
					attackId
					attackDestinationIP
					attackDestinationPort
					attackMitigationType
					attackSourcePort
					attackType
				}
				avg {
					bitsPerSecond
					packetsPerSecond
				}
				min {
					datetimeMinute
					bitsPerSecond
					packetsPerSecond
				}
				max {
					datetimeMinute
					bitsPerSecond
					packetsPerSecond
				}
				sum {
					bits
					packets
				}
			}
		}
	}
}
```

## 상위 N 카드 - 소스

이 쿼리는 상위 소스 IP에 대한 데이터를 반환합니다.
`limit` 매개변수는 각 노드에서 반환되는 레코드 수를 제어합니다. 다음 코드에서 강조된 줄이 `limit`을 설정하는 부분입니다.

```graphql graphql-api-explorer title="상위 N 카드 쿼리" {9,22,35,47,60,72}
query GetTopNBySource(
    $accountTag: string
    $filter: AccountIpFlows1mGroupsFilter_InputObject
    $portFilter: AccountIpFlows1mGroupsFilter_InputObject
  ) {
    viewer {
      accounts(filter: { accountTag: $accountTag }) {
        topNPorts: ipFlows1mGroups(
        limit: 5
        filter: $portFilter
        orderBy: [sum_(bits/packets)_DESC]
      ) {
        sum {
          count: (bits/packets)
        }
        dimensions {
          metric: sourcePort
          ipProtocol
        }
      }
      topNASN: ipFlows1mGroups(
        limit: 5
        filter: $filter
        orderBy: [sum_(bits/packets)_DESC]
      ) {
        sum {
          count: (bits/packets)
        }
        dimensions {
          metric: sourceIPAsn
          description: sourceIPASNDescription
        }
      }
        topNIPs: ipFlows1mGroups(
        limit: 5
        filter: $filter
        orderBy: [sum_(bits/packets)_DESC]
      ) {
        sum {
          count: (bits/packets)
        }
        dimensions {
          metric: sourceIP
        }
      }
        topNColos: ipFlows1mGroups(
          limit: 10
          filter: $filter
          orderBy: [sum_(bits/packets)_DESC]
        ) {
          sum {
            count: (bits/packets)
          }
          dimensions {
            metric: coloCity
            coloCode
          }
        }
        topNCountries: ipFlows1mGroups(
          limit: 10
          filter: $filter
          orderBy: [sum_(bits/packets)_DESC]
        ) {
          sum {
            count: (bits/packets)
          }
          dimensions {
            metric: coloCountry
          }
        }
        topNIPVersions: ipFlows1mGroups(
          limit: 2
          filter: $filter
          orderBy: [sum_(bits/packets)_DESC]
        ) {
          sum {
            count: (bits/packets)
          }
          dimensions {
            metric: ipVersion
          }
        }
      }
    }
  }

```

## TCP 플래그

이 쿼리는 IP flow의 분 단위 롤업에서 TCP 패킷 수를 추출하고 TCP 플래그 값별로 결과를 그룹화합니다. `limit: 8`을 사용해 상위 8개 결과를 표시하고, 내림차순으로 보여 줍니다.

TCP 데이터만 보려면 필터에 다음 줄을 추가하세요.

```json
{ "ipProtocol": "TCP" }
```

```graphql graphql-api-explorer title="TCP 플래그 쿼리"
query GetTCPFlags(
    $accountTag: string
    $filter: AccountIpFlows1mGroupsFilter_InputObject
  ) {
    viewer {
      accounts(filter: { accountTag: $accountTag }) {
        tcpFlags: ipFlows1mGroups(
          filter: $filter
          limit: 8
          orderBy: [sum_(bits/packets)_DESC]
        ) {
          sum {
            count: (bits/packets)
          }
          dimensions {
            tcpFlags
          }
        }
      }
    }
  }
```

## 경영진 요약

경영진 요약 쿼리는 전체 활동을 요약하므로 선택한 시간 간격으로만 필터링하고 analytics에 적용된 다른 필터는 무시합니다.
검토하려는 시간 간격과 계정이 보고 있는 트래픽 종류에 따라 서로 다른 쿼리를 사용하세요.

시간 간격이 예를 들어 3월 25일 09:00부터 3월 25일 17:00까지처럼 절대값이라면, 그 시간 범위의 공격을 조회하는 쿼리를 실행하세요. 시간 간격에 맞는 [적절한 query node](#매개변수와-필터), 예를 들어 `ipFlows1dGroups`를 사용합니다.

```graphql graphql-api-explorer title="GetPreviousAttacks query - 이전 공격 가져오기"
query GetPreviousAttacks($accountTag: string, $filter: filter) {
  viewer {
    accounts(filter: {accountTag: $accountTag}) {
      ${queryNode}(limit: 1000, filter: $filter) {
        dimensions {
          attackId
        }
        sum {
          packets
          bits
        }
      }
    }
  }
}
```

시간 간격이 현재 시각 기준 상대값, 예를 들어 최근 24시간 또는 최근 30분이라면 `ipFlows1mGroup` 노드에 쿼리하여 지난 5분 동안 공격이 있었는지 확인합니다. 최근 5분 이내의 공격은 진행 중인 것으로 분류되며 Activity Log에는 `Present`가 표시됩니다.
쿼리 응답에는 진행 중인 공격의 `attackID` 값이 나열됩니다.

```graphql graphql-api-explorer title="GetOngoingAttackIds query - 진행 중인 공격 확인"
query GetOngoingAttackIds($accountTag: string, $filter: filter) {
	viewer {
		accounts(filter: { accountTag: $accountTag }) {
			ipFlows1mGroups(limit: 1000, filter: $filter) {
				dimensions {
					attackId
				}
			}
		}
	}
}
```

진행 중인 공격이 있다면, 이전 쿼리에서 받은 `attackID` 값으로 필터링하여 `ipFlows1mAttacksGroups` 노드를 조회합니다. 아래 쿼리는 최대 비트율과 패킷율을 반환합니다.

```graphql graphql-api-explorer title="GetOngoingAttacks query - 진행 중인 공격 데이터 가져오기"
query GetOngoingAttacks($accountTag: string, $filter: filter) {
	viewer {
		accounts(filter: { accountTag: $accountTag }) {
			ipFlows1mAttacksGroups(limit: 1000, filter: $filter) {
				dimensions {
					attackId
				}
				max {
					bitsPerSecond
					packetsPerSecond
				}
			}
		}
	}
}
```

진행 중인 공격이 없다면 `GetPreviousAttacks` 쿼리를 사용해 절대 시간 간격 내의 공격 데이터를 표시하세요.
