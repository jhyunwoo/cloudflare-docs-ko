## Aggregated roll-ups와 Adaptive Bit Rate

Network Analytics v1(NAv1)에서는 데이터가 1분 롤업 테이블로 집계된 다음 1시간 롤업, 마지막으로 1일 롤업으로 집계됩니다. 사용자는 지난 30일의 고해상도 트래픽 및 공격 데이터를 보려면 `ipFlows1mGroups` 노드를, 과거 데이터를 보려면 `ipFlows1hGroups` 또는 `ipFlows1dGroups` 노드를 쿼리할 수 있습니다. 하지만 이 노드들을 통해 제공되는 데이터는 집계 데이터이므로 결과의 정확도와 카디널리티가 제한됩니다. 예를 들어 짧은 트래픽 급증은 롤업에서 샘플이 집계되기 때문에 이 노드들로 얻은 데이터에서는 보이지 않습니다.

반면 Network Analytics v2(NAv2)는 [Adaptive Bit Rate (ABR)](/analytics/network-analytics/understand/concepts/#adaptive-bit-rate-sampling) 샘플링을 사용합니다. 이는 사용자가 쿼리 시간 범위에 따라 노드를 선택할 필요가 없다는 뜻입니다. 또한 과거 데이터를 조회할 때도 카디널리티와 정확도가 유지됩니다. 쿼리 크기에 따라 ABR 메커니즘이 최적의 샘플링 비율을 선택하고, 각 노드 뒤에 캡슐화된 샘플 테이블 중 하나에서 응답을 가져옵니다.

## 샘플링 개선

Network Analytics v2는 더 나은 샘플링 비율과 [Edge Sample Enrichment](/analytics/network-analytics/understand/concepts/#edge-sample-enrichment) 덕분에 더 정확한 데이터를 제공합니다. NAv1은 1/8,192 패킷(즉, 8,192개 패킷당 1개)을 샘플링하는 반면, NAv2의 샘플 비율은 완화 서비스에 따라 달라집니다. 예를 들면 다음과 같습니다.

- `dosd`의 샘플 비율은 패킷 볼륨에 따라 1/100에서 1/10,000 packets 사이로 동적으로 바뀝니다.
- Cloudflare Network Firewall 이벤트의 샘플 비율은 패킷 수에 따라 1/100에서 1/1,000,000 packets 사이로 동적으로 바뀝니다.
- `flowtrackd`의 샘플 비율은 1/10,000 packets입니다.

NAv2 데이터 파이프라인은 NAv1에 비해 회복력도 더 뛰어납니다. NAv1은 Core Sample Enrichment를 사용하며, 여기서는 원시 패킷 샘플이 Cloudflare의 모든 엣지 데이터 센터에서 Core 데이터 센터로 전송됩니다. Core 데이터 센터에서 패킷 샘플은 추가 데이터베이스와 대조되어 관련 고객 계정 ID, 공격 ID, 공격 유형 및 기타 메타데이터가 주입됩니다. 그 후 패킷 샘플이 저장소에 삽입됩니다. 이 방식의 주요 단점 중 하나는 정보를 대조하는 과정에서 샘플 정체가 발생할 수 있어, 드물게 일시적인 데이터 지연이 생길 수 있다는 점입니다.

이러한 잠재적인 데이터 지연을 없애기 위해 NAv2는 Edge Sample Enrichment에 의존하는 새로운 데이터 로깅 파이프라인을 사용합니다. 패킷 샘플 보강과 상호 참조를 엣지 데이터 센터에 위임함으로써 데이터 파이프라인의 회복력과 혼잡 허용성을 높입니다. 이 방식을 사용하면 보강된 패킷 샘플이 도착하는 즉시 Cloudflare의 코어 데이터 센터에 저장됩니다.
