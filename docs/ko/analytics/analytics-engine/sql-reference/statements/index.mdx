## SHOW TABLES 구문

`SHOW TABLES`는 계정의 테이블 목록을 조회하는 데 사용할 수 있습니다. 테이블 이름은 Workers 바인딩을 구성할 때 `dataset`으로 지정한 이름입니다. 자세한 내용은 [Workers Analytics Engine 시작하기](/analytics/analytics-engine/get-started/)를 참고하세요. 테이블은 Worker에서 이벤트 데이터를 기록하면 자동으로 생성됩니다.

```sql
SHOW TABLES
[FORMAT <format>]
```

사용 가능한 `FORMAT` 옵션은 [FORMAT 절](#format-clause)을 참고하세요.

## SHOW TIMEZONES 구문

`SHOW TIMEZONES`는 SQL API가 지원하는 모든 타임존 목록을 조회하는 데 사용할 수 있습니다. 일반적으로 많이 쓰는 타임존은 대부분 지원됩니다.

```sql
SHOW TIMEZONES
[FORMAT <format>]
```

## SHOW TIMEZONE 구문

`SHOW TIMEZONE`은 SQL API가 현재 사용하는 기본 타임존을 반환합니다. 항상 `Etc/UTC`여야 합니다.

```sql
SHOW TIMEZONE
[FORMAT <format>]
```

## SELECT 구문

`SELECT`는 테이블을 조회하는 데 사용합니다.

사용법:

```sql
SELECT <expression_list>
[FROM <table>|(<subquery>)]
[WHERE <expression>]
[GROUP BY <expression>, ...]
[HAVING <expression>]
[ORDER BY <expression_list>]
[LIMIT <n>|ALL]
[FORMAT <format>]
```

아래에서 각 절의 문법을 확인할 수 있습니다. 예제 쿼리는 [SQL API](/analytics/analytics-engine/sql-api/) 문서를 참고하세요.

### SELECT 절

`SELECT` 절은 결과에 포함할 열 목록을 지정합니다.
열은 `AS` 키워드를 사용해 별칭을 지정할 수 있습니다.

사용법:

```sql
SELECT <expression> [AS <alias>], ...
```

예시:

```sql
-- 이름 있는 열 반환
SELECT blob2, double3

-- 모든 열 반환
SELECT *

-- 열에 더 설명적인 이름의 별칭 부여
SELECT
    blob2 AS probe_name,
    double3 AS temperature
```

지원되는 함수와 [연산자](/analytics/analytics-engine/sql-reference/operators/)를 사용하는 식도 열 이름 대신 사용할 수 있습니다.

```sql
SELECT
    blob2 AS probe_name,
    double3 AS temp_c,
    double3*1.8+32 AS temp_f -- 값 계산

SELECT
    blob2 AS probe_name,
    if(double3 <= 0, 'FREEZING', 'NOT FREEZING') AS description -- 함수 사용

SELECT
    blob2 AS probe_name,
    avg(double3) AS avg_temp -- 집계 함수
```

### FROM 절

`FROM`은 쿼리에서 데이터를 가져올 원본을 지정하는 데 사용합니다.

사용법:

```sql
FROM <table_name>|(subquery)
```

예시:

```sql
-- "temperatures"라는 workers 데이터셋에 기록된 데이터 조회
FROM temperatures

-- 테이블을 조작하기 위해 서브쿼리 사용
FROM (
    SELECT
        blob1 AS probe_name,
        count() as num_readings
    FROM
        temperatures
    GROUP BY
        probe_name
)
```

쿼리는 하나의 테이블에 대해서만 동작할 수 있습니다. `UNION`, `JOIN` 등은 현재 지원되지 않습니다.

### WHERE 절

`WHERE`는 그룹화와 집계 이전에 반환할 행을 필터링하는 데 사용합니다.

사용법:

```sql
WHERE <condition>
```

`<condition>`에는 불리언으로 평가되는 어떤 식이든 사용할 수 있습니다.

[비교 연산자](/analytics/analytics-engine/sql-reference/operators/#comparison-operators)로 값을 비교할 수 있고, [불리언 연산자](/analytics/analytics-engine/sql-reference/operators/#boolean-operators)로 조건을 조합할 수 있습니다.

함수와 [연산자](/analytics/analytics-engine/sql-reference/operators/#supported-operators)를 포함한 식도 지원됩니다.

그룹화와 집계 이후의 결과를 필터링하려면 대신 [`HAVING` 절](#having-clause)을 사용하세요.

예시:

```sql
-- 단순 비교
WHERE blob1 = 'test'
WHERE double1 = 4

-- 부등식
WHERE double1 > 4

-- 연산자 사용(지원되는 연산자 목록은 아래 참고)
WHERE double1 + double2 > 4
WHERE blob1 = 'test1' OR blob2 = 'test2'

-- 부등식, 함수, 연산자를 사용한 식
WHERE if(unit = 'f', (temp-32)/1.8, temp) <= 0
```

### GROUP BY 절

집계 함수를 사용할 때 `GROUP BY`는 집계를 수행할 그룹을 지정합니다.

사용법:

```sql
GROUP BY <expression>, ...
```

예를 들어 온도 측정값 테이블이 있다고 가정하면:

```sql
-- 각 프로브의 평균 온도 반환
SELECT
    blob1 AS probe_name,
    avg(double1) AS average_temp
FROM temperature_readings
GROUP BY probe_name
```

일반적으로 `<expression>`은 열 이름이면 충분하지만, 복잡한 식을 넣는 것도 가능합니다. 쉼표로 구분해 여러 식 또는 열 이름을 제공할 수 있습니다.

### HAVING 절 <Badge text="New" variant="tip" size="small" />

`HAVING`은 그룹화와 집계 이후의 결과를 필터링하는 데 사용합니다.

사용법:

```sql
HAVING <condition>
```

`<condition>`에는 불리언으로 평가되는 어떤 식이든 사용할 수 있으며, 집계 함수나 그룹화된 열을 참조할 수 있습니다.

`WHERE`가 그룹화 전에 행을 필터링하는 것과 달리, `HAVING`은 집계 후 그룹을 필터링합니다. 즉, 집계 값 기준으로 필터링할 수 있습니다.

[비교 연산자](/analytics/analytics-engine/sql-reference/operators/#comparison-operators)로 값을 비교할 수 있고, [불리언 연산자](/analytics/analytics-engine/sql-reference/operators/#boolean-operators)로 조건을 조합할 수 있습니다.

예시:

```sql
-- 평균이 10보다 큰 그룹 필터링
SELECT
    blob1 AS probe_name,
    avg(double1) AS average_temp
FROM temperature_readings
GROUP BY probe_name
HAVING average_temp > 10

-- 측정값이 100개보다 많은 그룹 필터링
SELECT
    blob1 AS probe_name,
    count() AS num_readings
FROM temperature_readings
GROUP BY probe_name
HAVING num_readings > 100

-- 여러 조건 조합
SELECT
    blob1 AS city,
    avg(double1) AS avg_temp,
    count() AS readings
FROM weather_data
GROUP BY city
HAVING avg_temp > 20 AND readings >= 50
```

### ORDER BY 절

`ORDER BY`는 행이 반환되는 순서를 제어하는 데 사용할 수 있습니다.

사용법:

```sql
ORDER BY <expression> [ASC|DESC], ...
```

`<expression>`은 단순한 열 이름일 수도 있습니다.

`ASC` 또는 `DESC`는 정렬 방향이 오름차순인지 내림차순인지 결정합니다. `ASC`가 기본값이며 생략할 수 있습니다.

예시:

```sql
-- double2, double3 순으로 둘 다 오름차순 정렬
ORDER BY double2, double3

-- double2는 오름차순, double3는 내림차순 정렬
ORDER BY double2, double3 DESC
```

### LIMIT 절

`LIMIT`는 반환할 최대 행 수를 지정합니다.

사용법:

```sql
LIMIT <n>|ALL
```

반환할 최대 행 수를 지정하거나, 제한이 없으면 `ALL`을 사용합니다.

예를 들면:

```sql
LIMIT 10 -- 최대 10행 반환
```

### OFFSET 절

`OFFSET`은 쿼리 결과에서 건너뛸 행 수를 지정합니다.

사용법:

```sql
OFFSET <n>
```

예를 들면:

```sql
OFFSET 10 -- 처음 10개 결과 행 건너뛰기
```

### FORMAT 절

`FORMAT`은 반환되는 데이터의 인코딩 방식을 제어합니다.

사용법:

```sql
FORMAT [JSON|JSONEachRow|TabSeparated]
```

FORMAT 절을 포함하지 않으면 기본 형식인 `JSON`이 사용됩니다.

형식을 지정해 기본값을 덮어쓸 수 있습니다. 예를 들면:

```sql
FORMAT JSONEachRow
```

다음 형식이 지원됩니다.

#### JSON

데이터는 스키마 정보를 포함한 단일 JSON 객체로 반환됩니다.

```json
{
    "meta": [
        {
            "name": "<column 1 name>",
            "type": "<column 1 type>"
        },
        {
            "name": "<column 2 name>",
            "type": "<column 2 type>"
        },
        ...
    ],
    "data": [
        {
            "<column 1 name>": "<column 1 value>",
            "<column 2 name>": "<column 2 value>",
            ...
        },
        {
            "<column 1 name>": "<column 1 value>",
            "<column 2 name>": "<column 2 value>",
            ...
        },
        ...
    ],
    "rows": 10
}
```

#### JSONEachRow

데이터는 행마다 별도의 JSON 객체로 반환됩니다. 행은 줄바꿈으로 구분되며, 헤더 줄이나 스키마 데이터는 없습니다.

```json
{"<column 1 name>": "<column 1 value>", "<column 2 name>": "<column 2 value>"}
{"<column 1 name>": "<column 1 value>", "<column 2 name>": "<column 2 value>"}
...
```

#### TabSeparated

데이터는 줄바꿈으로 구분된 행으로 반환됩니다. 열은 탭으로 구분되며 헤더는 없습니다.

```txt
column 1 value  column 2 value
column 1 value  column 2 value
...
```
