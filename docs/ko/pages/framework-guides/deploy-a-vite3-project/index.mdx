[뚱 베어](https://vitejs.dev)앞엔드 개발자를 위한 차세대 빌드 도구입니다. 이름 \*[Vite 3의 출시](https://vitejs.dev/blog/announcing-vite3.html), 개발자는 새로운 명령 줄 (CLI) 개선, 스타터 템플릿 및 사용을 만들 수 있습니다[더 보기](https://github.com/vitejs/vite/blob/main/packages/vite/CHANGELOG.md#300-2022-07-13)프론트 엔드 응용 프로그램을 구축하는 데 도움이됩니다.

Cloudflare Pages는 Vite 3 프로젝트를 위한 기본 지원이 있습니다. 블로그 게시물에 Refer[Pages 빌드 프로세스 개선](https://blog.cloudflare.com/cloudflare-pages-build-improvements/)Vite 3 및 Cloudflare PagesXQXQXQ를 사용하여 초기화를 포함하여, 당신의 신청의 건축 장식새김을 낙관하기 위하여 정보 더.

이 가이드에서 Vite 3을 사용하여 새로운 프로젝트를 시작하는 방법을 배우고 Cloudflare PagesXQ에 배포합니다.

<PackageManagers type="create" pkg="vite@latest" />

```sh output
✔ Project name: … vite-on-pages
✔ Select a framework: › vue
✔ Select a variant: › vue

Scaffolding project in ~/src/vite-on-pages...

Done. Now run:

  cd vite-on-pages
  npm install
  npm run dev
```

이제 새로운 GitHub 저장소를 만들고 코드를 사용하여 밀어[GitHub의`gh`명령행 (CLI)](https://cli.github.com):

```sh
git init
```

```sh output
Initialized empty Git repository in ~/vite-vue3-on-pages/.git/
```

```sh
git add .
git commit -m "Initial commit"                                           vite-vue3-on-pages/git/main +
```

```sh output
[main (root-commit) dad4177] Initial commit
 14 files changed, 1452 insertions(+)
```

```sh
gh repo create
```

```sh output
✓ Created repository kristianfreeman/vite-vue3-on-pages on GitHub
✓ Added remote git@github.com:kristianfreeman/vite-vue3-on-pages.git
```

```sh
git push
```

Pages에 사이트를 배포하려면:

1. Cloudflare QX대시보드에서, 가십시오**Workers & Pages**사이트 맵

   <DashButton url="/?to=/:account/workers-and-pages" />
2. 제품정보**회사연혁** > **모델 번호: Pages** > **기존 Git 저장소에서 가져 오기**.
3. 새로운 GitHub 저장소를 선택하십시오.
4. 내 계정**빌드 및 배포 설정**, 세트`npm run build`으로**명령 실행**·`dist`으로**출력 디렉토리**.

설정 완료 후, 선택**저장 및 배포**.

진행중인 첫 번째 배포 파이프라인을 볼 수 있습니다. Pages는 모든 의존성을 설치하고 프로젝트를 지정합니다. 프로젝트를 배포 한 후, 그것은 사용할 수 있습니다`<YOUR_PROJECT_NAME>.pages.dev`하위 도메인. 프로젝트의 하위 도메인 찾기**Workers & Pages**> Pages 프로젝트 선택 >**계정 만들기**.

Cloudflare Pages는 자동적으로 당신의 프로젝트를 재건하고 각 새로운 강요된 투입에 그것을 배치할 것입니다.

또한 액세스 할 수 있습니다.[관련 기사](/pages/configuration/preview-deployments/)풀 요청에 대한 빌드 및 배포 프로세스를 반복하는 ,. 이 작업을 통해 실제 URL로 변경할 수 있습니다.
