Cloudflare는 Cloudflare PagesXQ에 어떤 정적 HTML 웹사이트를 배치하는 것을 지원합니다. 프레임 워크 또는 정적 사이트 생성기를 사용하지 않고 웹 사이트를 관리하거나 프레임 워크가 나열되지 않은 경우[Framework 가이드](/pages/framework-guides/), 당신은 여전히이 가이드를 사용하여 배포 할 수 있습니다.

## Cloudflare Pages

<Render file="deploy-to-pages-steps-no-preset" product="pages" />

<div>
  | 구성 옵션       | 제품정보               |
  | ----------- | ------------------ |
  | 생산 지점       | `main`             |
  | 명령을 빌드 (옵션) | `exit 0`           |
  | 출력 디렉토리     | `<YOUR_BUILD_DIR>` |
</div>

많은 프레임 워크 가이드와 달리, 빌드 명령과 사이트 출력 디렉토리를 구축 완전히 사용자 정의 할 것입니다. 미리 설치하지 않고 사이트를 구축 할 필요가 없습니다, 사용`exit 0`이름 \***명령 실행**. Cloudflare는 사용을 추천합니다`exit 0`이름 \***명령 실행**Pages 기능과 같은 기능에 접근하십시오. 더 보기**출력 디렉토리**당신의 응용 프로그램의 콘텐츠가 삶의 곳입니다.

사이트를 구성하면 첫 번째 배포를 시작할 수 있습니다. 사용자 정의 빌드 명령 (제공되는 경우) 실행되며 Pages는 정적 사이트를 배포합니다.

:::참조

Cloudflare PagesXQ에 첫 번째 사이트를 배포하는 완벽한 가이드를 위해, 참조[자주 묻는 질문](/pages/get-started/).

:::

사이트를 배포 한 후, 프로젝트에 대한 독특한 하위 도메인을 받게됩니다.`*.pages.dev`. Cloudflare Pages는 자동적으로 당신의 프로젝트를 재건하고 그것을 배치할 것입니다. 당신은 또한 접근을 얻을 것이다[관련 기사](/pages/configuration/preview-deployments/)새로운 풀 요청에, 그래서 당신은 생산에 배치하기 전에 사이트로 변경 사항을 볼 수 있습니다.

<Details header="*.pages.dev에 404 오류가 있습니까?">
  당신이 얻는 경우에`404`자주 묻는 질문`*.pages.dev`웹 사이트가 최상위 파일이 있는지 확인하십시오.`index.html`. 이`index.html`Pages는 지정된 페이지 없이 당신의 apex에 봉사할 것입니다.
</Details>
