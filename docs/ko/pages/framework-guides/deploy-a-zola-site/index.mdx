[인기 카테고리](https://www.getzola.org/)모든 내장과 단일 바이너리의 빠른 정적 사이트 발전기입니다. 이 가이드에서 새로운 Zola 응용 프로그램을 만들고 Cloudflare Pages를 사용하여 배포합니다. 당신은 사용할 것이다`zola`새로운 Zola 사이트를 만들려면 CLI.

## Zola 설치

첫 번째,[설치하기](https://www.getzola.org/documentation/getting-started/installation/)이름 \*`zola`아래 운영 체제의 특정 지침을 사용하여 CLI :

### 맥 OS (Homebrew)

패키지 관리자를 사용하는 경우[홈 양조장](https://brew.sh), 실행`brew install`Zola를 설치하려면 터미널에서 명령:

```sh
brew install zola
```

### 윈도우 (Chocolatey)

패키지 관리자를 사용하는 경우[스낵 바](https://chocolatey.org/), 실행`choco install`Zola를 설치하려면 터미널에서 명령:

```sh
choco install zola
```

### Windows (스코프)

패키지 관리자를 사용하는 경우[사이트맵](https://scoop.sh/), 실행`scoop install`Zola를 설치하려면 터미널에서 명령:

```sh
scoop install zola
```

### 리눅스 (pkg)

Linux distro의 패키지 관리자는 Zola를 포함 할 수 있습니다. 이 경우 Distro의 패키지 관리자를 사용하여 직접 설치할 수 있습니다 -- 예를 들어, 사용`pkg`, 당신의 맨끝에 있는 뒤에 오는 명령을 실행하십시오:

```sh
pkg install zola
```

패키지 관리자가 Zola를 포함하지 않거나 직접 릴리스를 다운로드하려는 경우, 참조[**제품 설명**](/pages/framework-guides/deploy-a-zola-site/#manual-installation)아래에 단면도.

### 수동 설치

Zola GitHub 저장소에는 다양한 운영 체제를 위한 Zola 명령줄 도구의 사전 제작 버전이 포함되어 있습니다.[공지사항](https://github.com/getzola/zola/releases).

이 릴리스를 설치하는 데 더 많은 지침을 들어, 참조[Zola의 설치 가이드](https://www.getzola.org/documentation/getting-started/installation/).

## 새로운 프로젝트 만들기

Zola 설치, 실행하여 새로운 프로젝트를 만들`zola init`기본 템플릿을 사용하여 터미널에서 명령:

```sh
zola init my-zola-project
```

계속하기`zola init`, 당신은 3개의 질문으로 신속한 할 것입니다:

1. 사이트의 URL은 무엇입니까? ([모델 번호: https://example.com](https://example.com)):
   지금 이 공백을 떠날 수 있습니다.

2. Sass 컴파일을 활성화 하시겠습니까? \[Y/n]: Y

3. 문법 강조를 활성화하려면? \[y/N]: y

4. 내용의 검색 인덱스를 만들려면? \[y/N]: y

## Cloudflare Pages

<PagesBuildPreset framework="zola" />

윤곽의 밑에, 확인하십시오**환경 변수 (advanced)**&#xC9C0;정하기`ZOLA_VERSION`.

예를 들어,`ZOLA_VERSION`: `0.17.2`.

사이트를 구성하면 첫 번째 배포를 시작할 수 있습니다. 당신은 Cloudflare Pages 설치를 참조하십시오`zola`, 당신의 프로젝트 의존성 및 사이트를 구축하기 전에, 배포하기 전에.

:::참조

Cloudflare QXPages에 첫 번째 사이트를 배포하는 완벽한 가이드를 위해, 참조[자주 묻는 질문](/pages/get-started/).

:::

사이트를 배포 한 후, 프로젝트에 대한 독특한 하위 도메인을 받게됩니다.`*.pages.dev`.

이제 하위 도메인을 추가 할 수 있습니다.`base_url`내 계정`config.toml`파일.

예를 들면:

```yaml
#사이트의 URL은
base_url = "https://my-zola-project.pages.dev"
```

Zola 사이트, Cloudflare PagesXQ에 새 코드를 자동 재구성하고 배포합니다. 당신은 또한 접근을 얻을 것이다[관련 기사](/pages/configuration/preview-deployments/)새로운 풀 요청에, 그래서 당신은 생산에 배치하기 전에 사이트로 변경 사항을 볼 수 있습니다.

### 관리 미리보기 배포

Cloudflare QXPagesXQ와 함께 일할 때, 당신은 당신의 주요 분지에 merging의 앞에 시험 변화를 위한 시사 배치를 이용할지도 모릅니다. 그러나 이러한 미리보기 배포는 다른 URL을 사용합니다 (like)`https://your-branch-name.my-zola-project.pages.dev`), 당신의 자산 선적으로 문제를 일으킬 수 있는`base_url`하드 코딩.

이 문제를 해결하려면 Cloudflare QXPages 구성에서 동적 설정 환경에 따라 기본 URL을 설정하십시오.

```sh
if [ "$CF_PAGES_BRANCH" = "main" ]; then zola build; else zola build --base-url $CF_PAGES_URL; fi
```

이 명령은:

- 더 보기`base_url`설정하기`config.toml`건물의 경우`main`주요사업
- 미리보기 배포 URL (자동 제공 Cloudflare Pages`$CF_PAGES_URL`) 다른 모든 분지
