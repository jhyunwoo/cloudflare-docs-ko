SvelteKit는 현대 웹 응용 프로그램을 구축하기위한 공식 프레임 워크입니다[스벨트](https://svelte.dev), 점점 인기 있는 오픈 소스 도구 사용자 인터페이스를 만들기. 대부분의 프레임 워크와는 달리, SvelteKit는 Svelte를 사용하며, 컴포넌트 코드를 효율적인 JavaScriptXQ로 변환하는 컴파일러는 SvelteKit를 사용하여 애플리케이션 상태 변경으로 수술적으로 업데이트할 수 있습니다.

이 가이드에서, 당신은 새로운 SvelteKit 응용 프로그램을 만들고 Cloudflare QXPages를 사용하여 그것을 배치합니다.
이용안내[`SvelteKit`](https://kit.svelte.dev/), 모든 크기의 웹 응용 프로그램을 구축하기위한 공식 Svelte 프레임 워크.

## 새 프로젝트 설정

사용 방법[`create-cloudflare`](https://www.npmjs.com/package/create-cloudflare)CLI (C3)는 새로운 프로젝트를 설정합니다. C3는 새로운 프로젝트 디렉토리를 만들고, SvelteKit의 공식 설정 도구를 시작하며 즉시 배포 할 수있는 옵션을 제공합니다.

이용안내`create-cloudflare`새로운 SvelteKit 프로젝트를 만들려면 다음 명령을 실행하십시오.

<PackageManagers type="create" pkg="cloudflare@latest" args="my-svelte-app --framework=svelte --platform=pages" />

SvelteKit는 주문화 선택을 위해 당신을 선행할 것입니다. 템플릿 옵션의 경우 Application/project 옵션 중 하나를 선택하십시오. 나머지 답변은이 가이드의 나머지에 영향을 미치지 않습니다. 프로젝트에 맞는 옵션을 선택하세요.

`create-cloudflare`그러면 의존성을 설치합니다.[모델 번호: Wrangler](/workers/wrangler/install-and-update/#check-your-wrangler-version)CLI와 SvelteKit`@sveltejs/adapter-cloudflare`어댑터 및 설정 질문.

프로젝트 의존도를 설치 한 후 응용 프로그램을 시작하십시오.

```sh
npm run dev
```

## SvelteKit Cloudflare 윤곽

SvelteKitXQXQXQXQQXQXPages를 사용하기 위하여, 당신은 추가할 필요가 있습니다[Cloudflare 접합기](https://kit.svelte.dev/docs/adapter-cloudflare)당신의 신청에.

<Render file="c3-adapter" product="pages" />

1. Cloudflare 설치 실행하여 어댑터`npm i --save-dev @sveltejs/adapter-cloudflare`당신의 맨끝에서.
2. 어댑터 포함`svelte.config.js`:

```diff
- import adapter from '@sveltejs/adapter-auto';
+ import adapter from '@sveltejs/adapter-cloudflare';

/** @type {import('@sveltejs/kit').Config} */
const config = {
  kit: {
    adapter: adapter(),
    // ... truncated ...
  }
};

export default config;
```

3. (TypeScript를 사용하는 경우) 환경 변수에 대한 지원 포함. 더 보기`env`KV 네임스페이스 및 기타 저장 객체를 포함하는 객체는 SvelteKit로 전달되며 컨텍스트 및 캐시와 함께 플랫폼 속성을 통해 Hooks 및 endpoints에 액세스할 수 있습니다. 예를 들면:

```diff
declare namespace App {
    interface Locals {}

+   interface Platform {
+       env: {
+           COUNTER: DurableObjectNamespace;
+       };
+       context: {
+           waitUntil(promise: Promise<any>): void;
+       };
+       caches: CacheStorage & { default: Cache }
+   }

    interface Session {}

    interface Stuff {}
}

```

4. 추가된 KV 또는 튼튼한 목표를 접근하십시오 (또는 일반적으로 무엇이든[관련 제품](/pages/functions/bindings/)) 당신의 endpoint에`env`:

```js
export async function post(context) {
	const counter = context.platform.env.COUNTER.idFromName("A");
}
```

:::참조

Cloudflare 어댑터 외에도 프로젝트에 사용할 수있는 다른 어댑터를 검토하십시오.

- [`@sveltejs/adapter-auto`](https://www.npmjs.com/package/@sveltejs/adapter-auto)

  SvelteKit의 기본 어댑터는 현재 환경에 어댑터를 자동으로 선택합니다. 이 어댑터를 사용하는 경우,[구성이 필요](https://kit.svelte.dev/docs/adapter-auto). 그러나, 기본 어댑터는 애플리케이션이 배포되기 때문에 로컬 개발에 대한 몇 가지 단점을 소개합니다.

이 문제를 해결하려면`CF_PAGES`어댑터가 QXSvelteKitXQ 플랫폼을 감지 할 수 있도록 SvelteKitXQ에 가변. 예를 들어, 로컬로 응용 프로그램을 구축 할 때:`CF_PAGES=1 vite build`.

- [`@sveltejs/adapter-static`](https://www.npmjs.com/package/@sveltejs/adapter-static)클라이언트 측 정적 자산 (서버 측 렌더링 없음)을 생산하고 Cloudflare PagesXQ와 호환됩니다.
  자주 묻는 질문[SvelteKit 문서](https://kit.svelte.dev/docs/adapter-static)어댑터를 설정하는 방법에 대한 지침. 이 어댑터를 사용하기로 결정하면 빌드 디렉토리, 대신`.svelte-kit/cloudflare`,이`build`. 당신은 또한 당신의 Cloudflare Pages 신청의 구조 디렉토리를 그러므로 구성해야 합니다.

:::

## 기능 설정

SvelteKit에서 기능은 엔드포인트로 작성됩니다. 기능에 포함`/functions`프로젝트의 루트에 디렉토리는 배포에 포함되지 않습니다, 이는 단일 컴파일`_worker.js`파일.

Pages 기능과 같은 기능을 가지고[`onRequests`](/pages/functions/api-reference/#onrequests), 당신은 SvelteKitXQ에 있는 표준 요구 Handlers를 쓸 필요가 있습니다. 예를 들어, 다음 TypeScript 파일은 다음과 같습니다.`onRequestGet`:

```ts
import type { RequestHandler } from "./$types";

export const GET = (({ url }) => {
	return new Response(String(Math.random()));
}) satisfies RequestHandler;
```

:::노트\[SvelteKit API 루트]

SvelteKit API 루트에 대한 자세한 내용은 참조[SvelteKit 문서](https://kit.svelte.dev/docs/routing#server).
:::
