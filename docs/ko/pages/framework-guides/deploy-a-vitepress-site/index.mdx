[VitePress 정보](https://vitepress.dev/)한국어[static 위치 발전기](https://en.wikipedia.org/wiki/Static_site_generator)(SSG) 빠른 구축을 위해 설계, 콘텐츠 중심 웹 사이트. VitePress는 소스 콘텐츠를 작성했습니다.[옵션 정보](https://en.wikipedia.org/wiki/Markdown), 테마에 적용, 쉽게 어디에서 배포 할 수있는 정적 HTML 페이지를 생성.

이 가이드에서 새로운 VitePress 프로젝트를 만들고 Cloudflare QXQXPagesXQ를 사용하여 배포합니다.

## 새로운 프로젝트를 설정

VitePress는 기본 프로젝트를 비계하는 데 도움이 될 명령 줄 설정 마법사로 배송합니다.

터미널에서 다음 명령을 실행하여 새로운 VitePress 프로젝트를 만듭니다.

<PackageManagers type="dlx" pkg="vitepress@latest" args="init" />

다른 질문 중, 설정 마법사가 새 프로젝트를 저장하기 위해 디렉토리에 묻습니다, 확인
프로젝트의 디렉토리에 설치 한 다음 설치`vitepress`다음 명령에 의존:

<PackageManagers pkg="vitepress@latest" dev />

:::참조

오류가 발생하면 로컬 머신이 충족되도록하십시오.[VitePress에 대한 문의](https://vitepress.dev/guide/getting-started#prerequisites).

:::

마지막으로 만들기`.gitignore`다음 내용으로 파일:

```
node_modules
.vitepress/cache
.vitepress/dist
```

이 단계는 불필요한 파일이 프로젝트의 git 저장소에 포함되어 있지 않다는 것을 확인합니다 (우리는 다음을 설정할 것입니다).

## Cloudflare Pages

<Render file="deploy-to-pages-steps-with-preset" product="pages" params={{ name: "VitePress" }} />

<PagesBuildPreset framework="vitepress" />

사이트를 구성하면 첫 번째 배포를 시작할 수 있습니다. Cloudflare Pages는 설치될 것입니다`vitepress`, 당신의 프로젝트 의존성, 및 그것을 배치하기 전에 사이트를 구축.

:::참조

QXQX0854XQ QXQXPagesXQ에 첫 번째 사이트를 배포하는 완벽한 가이드를 위해, 참조[자주 묻는 질문](/pages/get-started/).

:::

사이트를 배포 한 후, 프로젝트에 대한 독특한 하위 도메인을 받게됩니다.`*.pages.dev`. 당신이 투입하고 당신의 VitePress 프로젝트에 새로운 코드를 밀어 때마다, Cloudflare QXPagesXQ는 자동적으로 당신의 프로젝트를 재건하고 그것을 배치할 것입니다. 당신은 또한 접근을 얻을 것이다[관련 기사](/pages/configuration/preview-deployments/)새로운 풀 요청에 따라 사이트가 생산에 배포하기 전에 어떻게 변경 사항을 미리 볼 수 있습니다.
