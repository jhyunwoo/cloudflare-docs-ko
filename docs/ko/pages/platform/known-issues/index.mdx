다음은 Cloudflare Pages와 함께 알려진 버그와 문제입니다:

## 빌드 및 배포

- GitHub 및 GitLab은 현재 자동 CI/CD 빌드를 지원하는 플랫폼입니다.[연락처](/pages/get-started/direct-upload/)자신의 빌드 플랫폼을 통합하거나 로컬 컴퓨터에서 업로드 할 수 있습니다.

- Incremental 빌드는 현재 Cloudflare PagesXQ에서 지원되지 않습니다.

- 다운로드`/functions`대시보드의 직접 업로드 옵션을 통해 디렉토리가 작동하지 않습니다 (refer to[직접 업로드 기능 사용](/pages/get-started/direct-upload/#functions)).

- 옥수수 속/ forked repositories의 PR은 미리보기를 만들지 않습니다. 미래에 대한 지원.

## Git 구성

- Git 통합을 사용하여 배포하면 나중에 직접 업로드 할 수 없습니다. 그러나 이미 Git-integrated 프로젝트를 사용한다면 매번 배포를 트리거 할 필요가 없습니다.[disable/pause 자동적인 배치](/pages/configuration/git-integration/#disable-automatic-deployments). 대안으로, 당신은 당신의 Pages 프로젝트를 삭제할 수 있고 당신이 그것을 새롭게 하는 필요로 하는 경우에 다른 저장소에 새로운 1개의 지적을 창조할 수 있습니다.

## 구성

- `*.pages.dev`하위 도메인은 현재 변경할 수 없습니다. 변경해야 하는 경우`*.pages.dev`subdomain, 프로젝트를 삭제하고 새로운 것을 만듭니다.

- Hugo는 이전 버전을 자동으로 실행합니다. Hugo의 최신 버전을 실행하려면 (예를 들어,`0.101.0`), 당신은 환경 변수를 설정해야합니다. 설치하기`HUGO_VERSION`으로`0.101.0`또는 당신의 선택의 후고 버전.

- 기본적으로 Cloudflare는 Node를 사용합니다.`12.18.0`Pages 구조 환경에서. 새로운 Node 버전을 사용해야 하는 경우, 참조[구성 페이지](/pages/configuration/build-configuration/)구성 옵션에 대한.

- Netlify에서 마이그레이션하는 경우 Cloudflare는 Netlify의 양식 기능을 지원하지 않습니다.[모델 번호: Pages 제품정보](/pages/functions/)Netlify의 Serverless Functions와 동일하게 사용할 수 있습니다.

## 사용자 정의 도메인

- 그것은 현재 사용자 정의 도메인을 추가 할 수 없습니다

  - a wildcard, 예를 들어,`*.domain.com`.
  - Worker는 이미 그 도메인에 옮겼습니다.

- 현재 CloudflareXQ로 사용자 정의 도메인을 추가 할 수 없습니다 액세스 정책은 이미 그 도메인에서 활성화.

- Cloudflare의 로드밸런서는 작동하지 않습니다.`*.pages.dev`프로젝트;`Error 1000: DNS points to prohibited IP`나타날 것이다.

- 사용자 정의 도메인을 추가 할 때 도메인은 Cloudflare가 해당 호스트 이름에 SSL 인증서에 대한 요청을 유효하게 할 수 있는지 확인하지 않습니다. 유효한 SSL을 위해, Cloudflare 액세스 또는 Cloudflare Worker는 유효 경로에 요청할 수 있습니다.`http://{domain_name}/.well-known/acme-challenge/*`.

- [고급 인증서](/ssl/edge-certificates/advanced-certificate-manager/)Cloudflare QXPagesXCloudflareXQXQ로 SaaS의 QXQXQXQ로 사용할 수 없습니다.[증명서 우선권](/ssl/reference/certificate-and-hostname-priority/).

## 모델 번호: Pages 제품정보

- [제품정보](/pages/functions/)현재 추가/제거 polyfills를 지원하지 않습니다, 그래서 당신의 번들러 (예를 들면, webpack)는 달릴지도 모릅니다.

- `passThroughOnException()`현재 진보된 형태 Pages 기능을 위해 유효하지 않습니다 (PagesXQ 기능 사용`_worker.js`파일).

- `passThroughOnException()`현재 Workers에 있는 것과 같이 탄력이 없습니다. 우리는 현재 Pages 기능 코드에[다운로드](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/try...catch)블록 및 fallback 호출`env.ASSETS.fetch()`. 이것은 어떤 중요한 실패든지 (cpu 시간 초과 또는 기억과 같은) 아직도 오류를 던질지도 모릅니다.

## 높은 배포로 프로젝트를 삭제

Pages 프로젝트를 삭제할 수 없습니다. Cloudflare 팀은 이 문제를 추적하고 있습니다.

Pages 프로젝트에서 모든 배포를 삭제하려면 다음 단계를 검토하십시오. 배포를 삭제한 후 Pages 프로젝트를 삭제할 수 있습니다.

1. 다운로드`delete-all-deployments.zip`다음 링크로 이동하여 파일:[모델 번호: https://pub-505c82ba1c844ba788b97b1ed9415e75.r2.dev/delete-all-deployments.zip](https://pub-505c82ba1c844ba788b97b1ed9415e75.r2.dev/delete-all-deployments.zip).
2. 추출 물`delete-all-deployments.zip`파일.
3. 당신의 맨끝을 열고`cd`이름 \*`delete-all-deployments`디렉토리.
4. 내 계정`delete-all-deployments`디렉토리, run`npm install`의존성을 설치합니다.
5. 다음과 같은 명령을 검토하여 진행하려는 삭제를 결정하십시오.

- 실시간 생산 배포를 제외하고 모든 배포를 삭제하려면 (예를 들면[aliased 배포](https://developers.cloudflare.com/pages/configuration/preview-deployments/#preview-aliases)):

```sh
CF_API_TOKEN=<YOUR_CF_API_TOKEN> CF_ACCOUNT_ID=<ACCOUNT_ID> CF_PAGES_PROJECT_NAME=<PROJECT_NAME> npm start
```

- 실시간 생산 배포를 제외하고 모든 배포를 삭제하려면 (포함[aliased 배포](https://developers.cloudflare.com/pages/configuration/preview-deployments/#preview-aliases)예를 들면,`staging.example.pages.dev`):

```sh
CF_API_TOKEN=<YOUR_CF_API_TOKEN> CF_ACCOUNT_ID=<ACCOUNT_ID> CF_PAGES_PROJECT_NAME=<PROJECT_NAME> CF_DELETE_ALIASED_DEPLOYMENTS=true npm start
```

Cloudflare API 토큰을 찾으려면 로그인[Cloudflare대시보드](https://dash.cloudflare.com), 화면 오른쪽 상단의 사용자 아이콘을 선택 > 이동**내 프로필** > **API 토큰**.

토큰이 필요합니다.`Cloudflare Pages Edit`이름 \*

계정 ID 찾기, 참조[지역 및 계정 ID 찾기](/fundamentals/account/find-account-and-zone-ids/).
