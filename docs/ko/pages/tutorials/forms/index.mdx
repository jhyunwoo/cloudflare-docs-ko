## 제품정보

웹에서 양식은 사용자와 웹 문서 간의 상호 작용의 일반적인 점입니다. 사용자가 데이터를 입력하고 일반적으로 데이터를 서버에 제출할 수 있습니다. 양식은 적어도 하나의 양식 입력으로 구성되어 있으며 텍스트 필드에서 드롭다운을 체크 박스와 더 많은 수 있습니다.

각 입력은 지명되어야 합니다 – 사용[`name`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input#attr-name)속성 – 그래서 입력의 값은 서버에서 수신 할 때 식별 가능한 이름이 있습니다. 또한 HTML5의 발전과 함께, 형태 요소는 자동 형태 검증을 선택하기 위해 추가 속성을 선언 할 수 있습니다. 유효한 유효성 검사는 입력 유형에 따라 다릅니다; 예를 들면, 이메일 (via)를 받아들이는 원본 입력[`type=email`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input#input_types)) 값은 유효한 이메일 주소, 숫자 입력 (via를 통해 보이는 것을 지킬 수 있습니다`type=number`)는 integers 또는 decimal 값 ( 허용되는 경우)만 허용되며 일반적인 텍스트 입력은 사용자 정의를 정의 할 수 있습니다.[`pattern`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input#attr-pattern)수 있습니다. 그러나 모든 입력은 값이 아닌지 선언 할 수 있습니다.[`required`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input#attr-required).

아래는 몇 가지 입력과 검증 규칙이 정의된 HTML5 양식입니다.

```html
<form method="POST" action="/api/submit">
	<input type="text" name="fullname" pattern="[A-Za-z]+" required />
	<input type="email" name="email" required />
	<input type="number" name="age" min="18" required />

	<button type="submit">Submit</button>
</form>
```

HTML5 양식이 정의 된 검증 규칙을 가지고 있다면 브라우저는 사용자가 양식을 제출하려고 시도 할 때 모든 규칙을 자동으로 확인할 수 있습니다. 오류가 발생하면 제출이 방지되고 브라우저는 오류 메시지(s)를 수정할 수 있습니다. 더 보기`<form>`계정 만들기`POST`데이터에`/submit`탁월한 검증 오류가 없을 때 endpoint. 이 전체 프로세스는 HTML5에 기본이며, 적절한 형태와 입력 속성이 존재하도록 요구합니다. - JavaScript는 필요하지 않습니다.

형태 성분은 또한 있을지도 모릅니다[`<label>`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/label)그들과 관련된 요소는 명확하게 각 입력을 설명 할 수 있습니다. 이것은 시각적 명확성, 물론, HTML 마크 업이 더 잘 정의되어 있기 때문에 더 많은 액세스 가능한 사용자 경험을 허용합니다. 이 분야에서 직접 이익을 얻을 수있는 기술; 예를 들어, 화면 리더는 다음과 같이 발표 할 수 있습니다`<input>`초점. 그리고 때`<label>`클릭, 할당 된 양식 입력 대신 초점을 맞추고, 입력에 대한 활성화 영역을 증가.

이를 가능하게 하기 위해, 당신은 창조해야 합니다`<label>`각 입력에 대한 요소와 각 할당`<input>`요소 및 고유`id`속성 값. 더 보기`<label>`자주 묻는 질문[`for`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/label#attr-for)입력의 고유성을 반영한 속성`id`가치. 이전 스니펫이 다음을 생성해야합니다 :

```html
<form method="POST" action="/api/submit">
	<label for="i-fullname">Full Name</label>
	<input
		id="i-fullname"
		type="text"
		name="fullname"
		pattern="[A-Za-z]+"
		required
	/>

	<label for="i-email">Email Address</label>
	<input id="i-email" type="email" name="email" required />

	<label for="i-age">Your Age</label>
	<input id="i-age" type="number" name="age" min="18" required />

	<button type="submit">Submit</button>
</form>
```

:::참조

내 계정`for`·`id`값은 위의 값을 정확히 일치하지 않습니다. 당신은 어떤 사용할 수 있습니다`id`HTML 문서에 독특합니다. ·`<label>`연결 가능`<input>`만약에`for`·`id`속성 일치.

:::

현재 위치`<form>`유효한 데이터로 제출되어 서버로 전송됩니다. 이 데이터가 양식 자체의 속성을 선언하여 전송되는 방법을 사용자 정의 할 수 있습니다. 이 세부 사항을 제공하지 않는 경우,`<form>`현재 URL 주소로 데이터를 얻을 것이다, 이는 거의 원하는 행동이다. 이 문제를 해결하려면 최소한으로 정의해야합니다.[`action`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/form#attr-action)대상 URL 주소를 가진 속성, 하지만 선언[`method`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/form#attr-method)기본적으로 redeclaring 경우에도 종종 권장됩니다.`GET`가치.

기본적으로 HTML 양식은 자신의 내용을 보냅니다.`application/x-www-form-urlencoded`MIME 유형. 이 값은 반영됩니다.`Content-Type`HTTP 헤더, 수신 서버는 데이터 내용을 파싱하는 방법을 결정해야합니다. MIME 유형을 통해 사용자 정의 할 수 있습니다.[`enctype`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/form#attr-enctype)이름 \* 예를 들어, 파일을 수락하기 위해 (via`type=file`), 당신은 변화해야 합니다`enctype`이름 \*`multipart/form-data`가치:

```html
<form method="POST" action="/api/submit" enctype="multipart/form-data">
	<label for="i-fullname">Full Name</label>
	<input
		id="i-fullname"
		type="text"
		name="fullname"
		pattern="[A-Za-z]+"
		required
	/>

	<label for="i-email">Email Address</label>
	<input id="i-email" type="email" name="email" required />

	<label for="i-age">Your Age</label>
	<input id="i-age" type="number" name="age" min="18" required />

	<label for="i-avatar">Profile Picture</label>
	<input id="i-avatar" type="file" name="avatar" required />

	<button type="submit">Submit</button>
</form>
```

그 때문에`enctype`변경된 브라우저는 서버로 데이터를 전송하는 방법을 변경합니다. 더 보기`Content-Type`HTTP 헤더는 새로운 접근 방식을 반영하고 HTTP 요청의 몸은 새로운 MIME 유형에 따릅니다. 수신 서버는 새로운 형식을 수용하고 요청 파싱 방법을 조정해야합니다.

### 작업자

HTML 양식은 배포 완료 및 준비. 사용자가 이 양식을 제출할 때 모든 데이터가 전송됩니다.`POST`요청하기`/api/submit`URL. 이 양식의`method`·`action`이름 \* 그러나 현재 요청 핸들러가 없습니다.`/api/submit`이름 \* 지금 만들겠습니다.

Cloudflare Pages는 제안합니다[제품정보](/pages/functions/)동적 동작을 위해 WorkersXQ를 정의하고 배포할 수 있는 기능.

기능에 연결됩니다`functions`디렉토리 및 편리한 구성 URL 요청 핸들러 관계`functions`파일 구조. 예를 들어,`functions/about.js`파일에 맵`/about`URL 및`functions/hello/[name].js`핸들링`/hello/:name`URL 패턴, 어디`:name`어떤 일치 URL 세그먼트입니다. 더 알아보기[기능 라우팅](/pages/functions/routing/)더 많은 정보를 위한 문서.

핸들러를 정의하려면`/api/submit`, 당신은 창조해야 합니다`functions/api/submit.js`파일. 즉,`functions`·`public`감독은 다음과 같은 총 프로젝트 구조와 함께 siblings이어야한다.

```txt
├── functions
│   └── api
│       └── submit.js
└── public
    └── index.html
```

더 보기`<form>`공지사항`POST`요청, 즉,`functions/api/submit.js`파일 수출 필요`onRequestPost`핸들:

```js
/** 이름
* POST /api/submit*/
export async function onRequestPost(context) {
	//TODO : 양식 제출 처리
}
```

더 보기`context`매개 변수는 잠재적 인 관심의 여러 값으로 채워진 객체입니다. 이 예제의 경우, 당신은 단지 필요[`Request`](/workers/runtime-apis/request/)접근할 수 있는 객체`context.request`주요.

언급했듯이,`<form>`기본값으로`application/x-www-form-urlencoded`제출할 때 MIME 유형. 그리고, 더 진보된 시나리오를 위해,`enctype="multipart/form-data"`속성이 필요합니다. 다행히, 둘 다 MIME 유형은 파종되고 대우될 수 있습니다[`FormData`](https://developer.mozilla.org/en-US/docs/Web/API/FormData). 이것은 WorkersXQ를 포함하는 PagesXQ를 가진다는 것을 의미합니다 Functions – 네이티브를 사용할 수 있습니다.[`Request.formData`](https://developer.mozilla.org/en-US/docs/Web/API/Request/formData)파서.

illustrative 목적을 위해, 예를 들면 신청의 모양 핸들러는 주어진 모든 가치로 대답할 것입니다. ·`Response`항상 핸들러에 의해 반환되어야한다.

```js
/** 이름
* POST /api/submit*/
export async function onRequestPost(context) {
	try {
		let input = await context.request.formData();
		let pretty = JSON.stringify([...input], null, 2);
		return new Response(pretty, {
			headers: {
				"Content-Type": "application/json;charset=utf-8",
			},
		});
	} catch (err) {
		return new Response("Error parsing JSON content", { status: 400 });
	}
}
```

이 핸들러와 함께, 예제는 이제 완전히 기능입니다. 제출이 수신되면 Worker는 JSON 목록에 응답합니다.`FormData`키 값 쌍.

그러나, key-value 쌍 대신 JSON 객체로 회신하려는 경우 ( Array of Array), 그런 다음 수동으로 수행해야합니다. 최근 JavaScript 추가[`Object.fromEntries`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Object/fromEntries)관련 기사 이것은 어떤 경우에 잘 작동합니다; 그러나, 예`<form>`다음을 포함합니다`movies`여러 값을 허용하는 체크리스트. 사용 방법`Object.fromEntries`, 생성 된 객체는 단지 하나의 유지`movies`값, 나머지를 무시. 이를 피하기 위해, 당신은 당신의 자신의 쓰기해야`FormData`으로`Object`대신 유틸리티:

```js
/** 이름
* POST /api/submit*/
export async function onRequestPost(context) {
	try {
		let input = await context.request.formData();

		//FormData를 JSON으로 변환
		//참고: 키 당 여러 값을 허용
		let output = {};
		for (let [key, value] of input) {
			let tmp = output[key];
			if (tmp === undefined) {
				output[key] = value;
			} else {
				output[key] = [].concat(tmp, value);
			}
		}

		let pretty = JSON.stringify(output, null, 2);
		return new Response(pretty, {
			headers: {
				"Content-Type": "application/json;charset=utf-8",
			},
		});
	} catch (err) {
		return new Response("Error parsing JSON content", { status: 400 });
	}
}
```

최종 snippet (above)는 Worker가 모든 값을 유지하고 JSON 응답을 정확한 표현으로 돌려줍니다.`<form>`제출.
