### 구성 설정

응용 프로그램에 구성 된 Sanity를 사용하면 블로그를 렌더링하기 시작할 수 있습니다. Sanity API에서 데이터를 끌어 놓고 렌더링하는 몇 페이지가 설정됩니다. Nuxt에 익숙하지 않은 경우, 당신이 검토하는 것이 좋습니다[Nuxt 가이드](https://nuxtjs.org/guide)Nuxt와 함께 건물 응용 프로그램에 대한 몇 가지 기본 개념을 가르칠 것입니다.

### 인덱스 페이지 설정

시작하려면`index`페이지를 방문 할 때 렌더링됩니다 (`/`). 내 계정`pages/index.vue`:

```html title="pages/index.vue"
<template>
	<div class="container">
		<div>
			<h1 class="title">My Blog</h1>
		</div>
		<div class="posts">
			<div v-for="post in posts" :key="post._id">
				<h2><a v-bind:href="post.slug.current" v-text="post.title" /></h2>
			</div>
		</div>
	</div>
</template>

<script>
	import { groq } from "@nuxtjs/sanity";

	export default {
		async asyncData({ $sanity }) {
			const query = groq`*[_type == "post"]`;
			const posts = await $sanity.fetch(query);
			return { posts };
		},
	};
</script>

<style>
	.container {
		margin: 2rem;
		min-height: 100vh;
	}
	.posts {
		margin: 2rem 0;
	}
</style>
```

Vue SFCs 또는*단일 파일 구성 요소*, JavaScript, HTML 및 CSS를 단일 파일로 결합 할 수있는 독특한 VueXQ 기능입니다. 내 계정`pages/index.vue`·`template`태그는 Vue 구성 요소를 나타냅니다.

중요하게,`v-for`Vue에 대해 HTML을 렌더링하는 지시어로 사용됩니다.`post`배열에서`posts`:

```html title="Inspecting the v-for directive"
<div v-for="post in posts" :key="post._id">
	<h2><a v-bind:href="post.slug.current" v-text="post.title" /></h2>
</div>
```

그에 대해`posts`배열,`asyncData`함수는 Nuxt에 의해 제공되며 비동기 호출(예, 네트워크 요청)에 의해 페이지의 데이터를 전달합니다.

더 보기`$sanity`객체는 Nuxt 및 Sanity.js 통합에 의해 제공되며 Sanity dataset에 요청할 수 있습니다. 자주 묻는 질문`$sanity.fetch`, 그리고 쿼리를 전달, 당신은 우리의 Sanity dataset에서 특정 데이터를 검색할 수 있으며, 페이지의 데이터로 반환합니다.

이전에 Sanity를 사용하지 않은 경우 GROQ와 비교할 수 없습니다. GRaph는 데이터셋과 상호작용할 수 있는 Sanity가 제공하는 Query 언어입니다. GROQ는 데이터셋을 원하는 데이터인 Sanity API를 말할 수 있는 강력한 언어입니다. 우리의 첫 번째 쿼리에 대해 Sanity가 dataset에서 모든 개체를 검색하는 것을 말합니다.`_type`가치의`post`:

```js title="A basic GROQ query"
const query = groq`*[_type == "post"]`;
const posts = await $sanity.fetch(query);
```

### 블로그 포스트 페이지를 설정

제품 정보`index`페이지는 우리의 dataset에서 각 블로그 게시물에 대한 링크를 렌더링합니다.`slug`블로그 게시물의 URL을 설정하는 값. 예를 들어, "Hello World"라는 블로그 게시물을 만들고 슬러그를 설정하면`hello-world`, 나의 Nuxt 신청은 페이지에 요구에 응할 수 있어야 합니다`/hello-world`, Sanity에서 해당 블로그 게시물을 검색합니다.

Nuxt는 페이지의 이러한 종류에 대한 내장 지원을 가지고 있으며, 새 파일을 만들 수 있습니다.`pages`형식에서`_slug.vue`. 에서`asyncData`페이지의 기능, 다음을 사용할 수 있습니다`params`참고 자료에 인수 슬러그:

```html title="pages/_slug.vue"
<script>
	export default {
		async asyncData({ params, $sanity }) {
			console.log(params); // { slug: "hello-world" }
		},
	};
</script>
```

마음으로, 당신은 구축 할 수`pages/_slug.vue`자주 묻는 질문`slug`값, 일치하는 블로그 게시물을 찾기 위해 Sanity에 쿼리를 만들고 렌더링`post`블로그 게시물의 제목 :

```html title="pages/_slug.vue"
<template>
	<div class="container">
		<div v-if="post">
			<h1 class="title" v-text="post.title" />
			<div class="content"></div>
		</div>
		<h4><a href="/">← Go back</a></h4>
	</div>
</template>

<script>
	import { groq } from "@nuxtjs/sanity";

	export default {
		async asyncData({ params, $sanity }) {
			const query = groq`*[_type == "post" && slug.current == "${params.slug}"][0]`;
			const post = await $sanity.fetch(query);
			return { post };
		},
	};
</script>

<style>
	.container {
		margin: 2rem;
		min-height: 100vh;
	}

	.content {
		margin: 2rem 0;
		max-width: 38rem;
	}

	p {
		margin: 1rem 0;
	}
</style>
```

방문할 때, 예를 들어,`/hello-world`, Nuxt는 들어오는 slug를 가지고 갈 것입니다`hello-world`, 그리고 어떤 목표든지를 위한 Sanity에 GROQ 조회를 만드십시오`_type`이름 \*`post`, 뿐만 아니라 슬러그는 가치를 일치`/hello-world`. 그 세트에서, 당신은 배열에 있는 첫번째 목표를 얻을 수 있습니다 ( 배열 색인 통신수를 사용하여 당신은 JavaScript에서 찾아낼 것입니다 –`[0]`) 그리고 그것으로 설정하십시오`post`당신의 페이지 자료.

### 블로그 게시물에 대한 렌더링 내용

당신은 렌더링`post`블로그에 대한 제목, 하지만 당신은 여전히 블로그 게시물의 내용을 누락. 이것을 렌더링하려면, 가져오기[`sanity-blocks-vue-component`](https://github.com/rdunk/sanity-blocks-vue-component)Sanity의 패키지[휴대용 텍스트](https://www.sanity.io/docs/presenting-block-text)형식과 렌더링 Vue 구성 요소.

첫째로, npm 포장을 설치하십시오:

<PackageManagers pkg="sanity-blocks-vue-component" />

패키지가 설치되면 생성`plugins/sanity-blocks.js`구성 요소를 가져오고 Vue 구성품으로 등록하십시오`block-content`:

```js title="plugins/sanity-blocks.js"
import Vue from "vue";
import BlockContent from "sanity-blocks-vue-component";
Vue.component("block-content", BlockContent);
```

Nuxt 설정에서`nuxt.config.js`, 파일의 일부로 가져 오기`plugins`이름:

```js title="nuxt.config.js"
{
	plugins: ["@/plugins/sanity-blocks.js"];
}
```

내 계정`pages/_slug.vue`, 당신은 지금 사용할 수 있습니다`<block-content>`콘텐츠를 렌더링하는 구성 요소. 이것은 사용자 정의 HTML 구성 요소의 형식을 가지고, 세 가지 인수를 가지고:`:blocks`렌더링하는 것을 나타냅니다 (우리의 경우,`child`), `v-for`, 어디의 iterator를 받아`child`에서 (우리의 경우,`post.body`·`:key`VueXQ를 돕는,[상태 렌더링의 추적](https://vuejs.org/v2/guide/list.html#Maintaining-State)각 게시물에 대한 독특한 가치를 제공함으로써: 즉,`_id`가치.

```html title="pages/_slug.vue" {6}
<template>
	<div class="container">
		<div v-if="post">
			<h1 class="title" v-text="post.title" />
			<div class="content">
				<block-content
					:blocks="child"
					v-for="child in post.body"
					:key="child._id"
				/>
			</div>
		</div>
		<h4><a href="/">← Go back</a></h4>
	</div>
</template>

<script>
	import { groq } from "@nuxtjs/sanity";

	export default {
		async asyncData({ params, $sanity }) {
			const query = groq`*[_type == "post" && slug.current == "${params.slug}"][0]`;
			const post = await $sanity.fetch(query);
			return { post };
		},
	};
</script>

<style>
	.container {
		margin: 2rem;
		min-height: 100vh;
	}

	.content {
		margin: 2rem 0;
		max-width: 38rem;
	}

	p {
		margin: 1rem 0;
	}
</style>
```

내 계정`pages/index.vue`, 당신은 사용할 수 있습니다`block-content`블로그 게시물 콘텐츠에 첫 번째 블록을 복용 하 고 그것을 렌더링 하는 콘텐츠의 요약을 렌더링 하는 구성 요소:

## Cloudflare Pages로 발행

QXQX2613XQQQXQXPagesXQ는 2단계 과정입니다: 첫째로, GitHub에 프로젝트를 밀어넣고, QXQX2614XQQQXPagesQX대시보드XQ에 따라 새로운 프로젝트를 설치했습니다. Pages는 게시할 때마다 사이트의 새로운 버전을 배포하고 새로운 풀 요청을 열 때마다 미리보기 배포를 설정할 것입니다.

GitHub에 프로젝트를 푸시하려면,[새로운 저장소 만들기](https://repo.new), GitHub에 로컬 Git 저장소를 밀어하는 지침을 따르십시오.

GitHub에 프로젝트를 푸시한 후, Pages:

1. Cloudflare QX대시보드에서, 가십시오**Workers & Pages**사이트 맵

   <DashButton url="/?to=/:account/workers-and-pages" />
2. 제품정보**회사연혁** > **모델 번호: Pages** > **기존 Git 저장소 가져 오기**.
3. 만든 새로운 GitHub 저장소를 선택하고 선택**설정 시작**.
4. 내 계정**빌드 및 배포 설정**단면도, 밑에**설정 설정** > **프레임 워크**, 선택*사이트맵*. Pages는 당신을 위한 정확한 분야를 자동적으로 놓을 것입니다.

사이트가 배포되었을 때, 당신은 생산에서 볼 수있는 독특한 URL을 받게됩니다.

Sanity.io 데이터 변경 시 자동으로 프로젝트를 배포할 수 있도록[배포 후크](/pages/configuration/deploy-hooks/). 새 배포 후크 URL 만들기**Pages 프로젝트** > **계정 설정**. Sanity 프로젝트의 설정 페이지에서**웹훅**섹션을 추가하고 아래에서 볼 때 Deploy Hook URL을 추가하십시오.

![Sanity의 대시보드에 Deploy Hook URL 추가](~/assets/images/pages/tutorials/hooks.png)

이제 Sanity.io 데이터셋으로 변경할 때 Sanity는 새로운 Cloudflare QXPagesXQ 배포를 시작할 수 있는 고유의 Deploy Hook URL에 대한 요청을 만들 것입니다. 이 작업을 수행하면 Pages 응용 프로그램은 새로운 블로그 게시물을 추가하거나 기존 하나를 편집 할 때 최신 상태로 유지됩니다.
