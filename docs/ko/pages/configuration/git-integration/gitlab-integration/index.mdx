당신은 GitLab 저장소에 각 Cloudflare Pages 프로젝트를 연결할 수 있고, CloudflareXQ는 분기에 변화를 밀어 때마다 코드를 자동으로 배치합니다.

## 주요 특징

자동 배포를 넘어 Cloudflare GitLab 통합은 GitLab에서 직접 모니터링, 관리 및 미리보기 배포를 할 수 있으므로 워크플로를 떠나지 않고 알려줍니다.

### 회사 소개

Pages는 기본적으로 당신의 설정에[생산 환경](/pages/configuration/branch-build-controls/#production-branch-control)첫 번째 푸시 지점으로. 기본 지점 이외의 지점(e.g.`main`) 당신의 프로젝트의 생산 분지를 대표합니다, 그 후에 갈**계정 설정** > **회사연혁** > **지점제어**, 생산 지점을 클릭하여 변경**생산 지점**드롭다운 메뉴와 다른 지점을 선택하십시오.

당신은 또한 사용할 수 있습니다[관련 기사](/pages/configuration/preview-deployments/)생산 지점을 merging하기 전에 프로젝트의 미리보기 버전, 생산에 배포합니다. Pages를 사용하면 미리보기 지점을 자동으로 사용하여 구성 할 수 있습니다.[Branch 구축 제어](/pages/configuration/branch-build-controls/). 구성하려면, 이동**계정 설정** > **회사연혁** > **지점제어**옵션 선택**미리보기 지점**. 사용[**회사 소개**](/pages/configuration/branch-build-controls/)자동 미리보기 배포에서 포함하거나 제외하려는 지점을 지정합니다.

### 커밋 메시지를 통해 특정 빌드를 건너

어떤 구성이 필요 없이, 당신은 광고 hoc 기반에 배포를 건너 뛸 수 있습니다. 추가하기`[CI Skip]`, `[CI-Skip]`, `[Skip CI]`, `[Skip-CI]`, 또는`[CF-Pages-Skip]`커밋 메시지의 접두사로 플래그, Pages는 배포가 중단됩니다. 접두사는 과민하지 않습니다.

### 실행 및 미리보기 URL

저장소에 연결된 하나의 또는 여러 프로젝트가 있다면 (즉,.[모노레포](/workers/ci-cd/builds/advanced-setups/#monorepos)), 당신은 GitLab에서 각 구조의 상태를 검사할 수 있습니다[GitLab 커밋 상태](https://docs.gitlab.com/ee/user/project/merge_requests/status_checks.html).

커밋과 같은 상태 아이콘을 선택하여 상태를 볼 수 있습니다.**제품정보** > **파이프 라인**GitLab 저장소 내에서. 아래 예에서 체크 실행 결과를 볼 수있는 녹색 체크 마크를 선택할 수 있습니다.

![GitLab 상태](~/assets/images/workers/platform/ci-cd/gl-status-checks.png)

체크 실행은 저장소에서 다음과 같이 나타납니다. 상태 중 하나를 선택할 수 있습니다.[URL 보기](/pages/configuration/preview-deployments/)그 배포.

![GitLab Commit 상태](~/assets/images/pages/configuration/glcommitstatus.png)

어떤 이유로 빌드 건너뛰기 (즉, CI Skip, 빌드 시계 경로, 또는 지점 배포 제어), 체크 run/commit 상태는 표시되지 않습니다.

## 자주 묻는 질문

Cloudflare WorkersXQXQ를 Cloudflare QXQXPages 앱을 사용하여 GitLab의 회사 또는 측 프로젝트에서 프로젝트를 배포할 수 있습니다.

### 회사연혁

Cloudflare PagesXQXQ를 GitHub 및 GitLab의 회사 또는 사이드 프로젝트에 배포할 수 있습니다.

CloudflareQXQXPagesXQ를 승인하면 GitLab 계정에 액세스할 수 있습니다. CloudflareQXQXPagesXQ를 조직, 그룹 및 네임스페이스에 액세스할 수 있습니다. 이 조직과 그룹에 대한 액세스를 관리하는 것은 GitLab에 의해 처리됩니다.

### 자주 묻는 질문

Cloudflare QXWorkersXQ를 제거할 수 있습니다.[관련 문의](https://gitlab.com/-/profile/applications)GitLab에 대해 Cloudflare WorkersXQ라는 응용 프로그램을 찾아 선택**다운로드**접근을 취소하는 버튼.

GitLab 응용 프로그램 Cloudflare Workers는 Workers 및 Pages 프로젝트 사이에 공유되며 GitLab에 액세스하는 것은 WorkersXQ 및 PagesXQXQ를 위해 새로운 빌드를 비활성화 할 수 있지만 이전 배포가 CloudflareXQXQXQXQXQXQXQXQXQXQXQXQXQXQXQXQXQX

### Cloudflare GitLab 앱 설치

Git 통합 관련 문제가 발생하면 잠재적 인 문제 해결 단계는 Cloudflare QXQXQXPages 설치와 관련된 GitHub 또는 GitLab 응용 프로그램을 제거하고 재설치하려고합니다.

1. GitLab의 응용 프로그램 설정 페이지로 이동:[모델 번호: https://gitlab.com/-/profile/applications](https://gitlab.com/-/profile/applications)
2. 선택하기**다운로드**당신의 Cloudflare QXPages 임명에 단추는 그것이 존재하는 경우에.
3. 바로가기**Workers & Pages**개요 페이지`https://dash.cloudflare.com/[YOUR_ACCOUNT_ID]/workers-and-pages`. 선택**회사연혁** > **Pages** > **Git에 연결**.
4. 선택하기**프로젝트**상단에 탭, 선&#xD0DD;**+ 계정 추가**버튼, 추가하려는 GitLab 계정을 선택하고, 다음을 선택합니다.**이름 \***&#x6D;odal에 "Cloudflare QXPagesXQ를 사용하여 계정을 사용합니까?
5. 계정 목록에서 GitLab 계정 또는 조직으로 프로젝트 페이지로 리디렉션됩니다.
6. 이전에 깨진 프로젝트로 새로운 배포를 만들려면.
