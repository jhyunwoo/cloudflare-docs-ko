Pages 프로젝트를 배포할 때, 사용자 정의 도메인(또는 하위 도메인)을 귀하의 사이트에 할당할 수 있습니다.

## 사용자 정의 도메인 추가

<Render file="custom-domain-steps" product="pages" />

### 사용자 정의 apex 도메인 추가

apex 도메인에 배포하는 경우 (예를 들어,`example.com`), 당신은 Cloudflare 지역으로 당신의 위치를 추가할 필요가 있을 것입니다[네임서버를 구성](#configure-nameservers).

#### nameservers 구성

apex 도메인을 사용하려면 (예를 들어,`example.com`) 당신의 Pages 프로젝트로,[Cloudflare의 네임서버를 설정](/dns/zone-setups/full-setup/setup/). 만약 네임서버가 Cloudflare, CloudflareXQ에 성공하면 CNAME 레코드를 만들 수 있습니다.

### 사용자 지정 subdomain 추가

하위 도메인에 배포하는 경우 Cloudflare Zone이 될 사이트에 필요하지 않습니다. 당신은 필요[CNAME 레코드 추가](#add-a-custom-cname-record)귀하의 Cloudflare Pages 사이트에 도메인을 지적합니다. Pages 프로젝트를 사용자 정의 apex 도메인에 배포하려면 사용자 정의 도메인은 Cloudflare 계정의 영역이어야하며 Pages 프로젝트를 만들었습니다.

:::참조

영역이 엔터프라이즈 플랜에 있다면, 당신이 확인[지역 파악을 해제](/fundamentals/account/account-security/zone-holds/#release-zone-holds)사용자 정의 도메인을 추가하기 전에. 영역 파악은 활성화에서 사용자 정의 하위 도메인을 방지 할 것입니다.

:::

#### 사용자 정의 CNAME 레코드 추가

nameservers를 CloudflareXQ로 바꾸려면, Cloudflare QXPagesXQ로 하위 도메인을 사용하는 사용자 정의 CNAME 레코드를 작성해야 합니다. DNS 공급자에 로그인 한 후 원하는 하위 도메인에 CNAME 레코드를 추가하십시오. 예를 들어,`shop.example.com`. 이 기록은 당신의 관례 Pages subdomain에, 예를 들면, 점해야 합니다`<YOUR_SITE>.pages.dev`.

| 제품정보    | 이름 \*              | 이름 \*                   |
| ------- | ------------------ | ----------------------- |
| `CNAME` | `shop.example.com` | `<YOUR_SITE>.pages.dev` |

사이트가 이미 Cloudflare 영역으로 관리되는 경우, CNAME 레코드는 DNS 레코드를 확인한 후 자동으로 추가됩니다.

:::참조

사용자 정의 도메인이 성공적으로 추가되도록하려면, you should go through[사용자 정의 도메인 추가](#add-a-custom-domain)위에서 설명한 과정. Cloudflare QXQXPagesQ 사이트에 대한 사용자 정의 CNAME 레코드를 수동으로 추가 - 먼저 Cloudflare QXQXQX0170XQQ QX대시보드XQ - CNAME 레코드 주소에서 해결하는 도메인에 실패하고 표시[`522`오류 수정](/support/troubleshooting/http-status-codes/cloudflare-5xx-errors/error-522/).

:::

## 사용자 정의 도메인 삭제

Pages 프로젝트에서 사용자 정의 도메인을 detach하려면 영역의 DNS 레코드를 수정해야합니다.

<Steps>
  1. 오시는 길**DNS 기록**Cloudflare 대시보드에서 웹 사이트에 대한 페이지.

     <DashButton url="/?to=/:account/:zone/dns/records" />

  2. Pages 프로젝트의 CNAME 레코드를 찾습니다.

  3. 제품정보**제품정보**.

  4. 제품정보**이름 \***.

  5. Cloudflare 대시보드에서, 갑니다**Workers & Pages**사이트 맵

     <DashButton url="/?to=/:account/workers-and-pages" />

  6. Pages 프로젝트를 선택하십시오.

  7. 오시는 길**주문 영역**.

  8. 선택하기**세 도트 아이콘**사용자 정의 도메인 옆에 >**도메인 제거**.
</Steps>

이 단계를 완료한 후 Pages 프로젝트는 단지 접근할 수 있을 것입니다`*.pages.dev`프로젝트를 만들 때 선택된 subdomain.

## 접근성 준수`*.pages.dev`이름 \*

귀하의 프로젝트에 대한 액세스를 비활성화하려면`*.pages.dev`하위 도메인:

<Steps>
  1. 사용 Cloudflare 당신의 미리보기에 액세스 (`*.{project}.pages.dev`). 더 알아보기[사용자 지정 미리보기 배포 액세스](/pages/configuration/preview-deployments/#customize-preview-deployments-access).

  2. 관련 기사`*.pages.dev`귀하의 생산 Pages 프로젝트와 관련된 URL은 사용자 정의 도메인에. 계정 레벨을 사용할 수 있습니다.[대량 Redirect](/rules/url-forwarding/bulk-redirects/)를 리디렉션하는 기능`*.pages.dev`사용자 정의 도메인에 URL.
</Steps>

## 알려진 문제

### CAA 기록

인증 기관 인증 (CAA) 레코드는 특정 인증서 권한 (CA)에 인증서 발급을 제한 할 수 있습니다.

이 문제를 일으킬 수 있습니다.[사용자 정의 도메인](/pages/configuration/custom-domains/)Pages 프로젝트에 CAA 레코드가 있는 경우 Cloudflare를 허용하여 사용자 정의 도메인의 인증서를 발급할 수 있습니다.

이 문제를 해결하려면 필요한 CAA 레코드를 추가하여 Cloudflare를 허용하여 사용자 정의 도메인에 대한 인증서를 발급합니다.

```
example.com.            300     IN      CAA     0 issue "letsencrypt.org"
example.com.            300     IN      CAA     0 issue "pki.goog; cansignhttpexchanges=yes"
example.com.            300     IN      CAA     0 issue "ssl.com"
example.com.            300     IN      CAA     0 issuewild "letsencrypt.org"
example.com.            300     IN      CAA     0 issuewild "pki.goog; cansignhttpexchanges=yes"
example.com.            300     IN      CAA     0 issuewild "ssl.com"
```

더 알아보기[인증 기관 인증 (CAA) FAQ](/ssl/faq/#caa-records)더 많은 정보.

### Pages에서 DNS 항목을 변경하고 다시

사용자 정의 도메인이 설정되면 DNS 항목을 변경하면 다른 점으로 (예를 들어, 당신의 기원), 사용자 정의 도메인은 비활성화됩니다. DNS 항목을 변경하면 사용자 정의 도메인에서 다시 포인트로 변경하면 DNS 항목을 사용하여 웹 사이트를 방문하면 다시 활성화 될 때까지 오류가 발생합니다. Pages 프로젝트에서 즉시 트래픽을 리디렉션하려는 경우 일시적으로 DNS 항목을 변경하는 것이 좋습니다.[근원 규칙](/rules/origin-rules/)또는[관련 규칙](/rules/url-forwarding/single-redirects/create-dashboard/)대신.
