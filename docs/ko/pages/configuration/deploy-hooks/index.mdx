Deploy Hooks를 사용하면 소스 저장소에서 커밋을 넘어 이벤트 소스를 사용하여 배포할 수 있습니다. 각 이벤트 소스는 새로운 배포를 시작하려면 HTTP POST 요청을 수신하는 고유의 URL을 얻을 수 있습니다. 이 기능은 Pages를 새로운 워크플로우로 통합할 수 있습니다. 예를 들면, 당신은 할 수 있습니다:

- Headless CMS가 변경할 때마다 자동으로 새로운 빌드를 배포합니다.
- 완전한 주문을 받아서 만들어진 CI/CD 파이프라인을 실행하고, 원한 조건 하에서 단지 배치
- CRON 트리거가 고정 된 타임 라인에 웹 사이트를 업데이트 할 예정

Deploy Hook을 만들려면:

1. Cloudflare 대시보드에서, 가십시오**Workers & Pages**사이트 맵

   <DashButton url="/?to=/:account/workers-and-pages" />
2. Pages 프로젝트를 선택하십시오.
3. 오시는 길**계정 설정** > **회사연혁**선택하기**배포 Hook**설정 시작.

![Cloudflare 대시보드](~/assets/images/pages/platform/deploy-hooks-add.png)

## 필요한 모수

Deploy Hook을 구성하려면 두 가지 키 매개 변수를 입력해야합니다.

1. **배포 후크 이름:**&#x44;eploy Hook에 대한 독특한 식별자 (예를 들어,`contentful-site`)
2. **구축 지점:**&#xC800;장소는 Deploy Hook을 빌드해야 합니다.

![Cloudflare QXQX0239XQ](~/assets/images/pages/platform/deploy-hooks-configure.png)

## Deploy Hook 사용

구성이 완료되면 Deploy Hook의 고유 URL을 사용할 준비가되어 있습니다. URL과 POST 요청을 복사할 수 있습니다.

![Deploy Hook의 새로 생성 된 고유 URL 검토](~/assets/images/pages/platform/deploy-hooks-details.png)

요청은 Deploy Hook에 전송되며 새로운 빌드가 트리거됩니다. 자주 묻는 질문**이름 \***&#xBC30;포 로그의 열은 배포가 Deploy Hook에 의해 트리거되었습니다.

![배포가 Deploy Hook에 의해 트리거 된 검토](~/assets/images/pages/platform/deploy-hooks-deployment-logs.png)

## 보안 고려 사항

계정 만들기 Hook은 프로젝트에 고유하게 연결되며 추가 인증을 필요로하지 않습니다. 이 작업은 완벽한 유연성을 허용합니다. 이러한 URL을 동일한 방식으로 보호하는 것이 중요합니다. 당신은 모든 독점적 인 정보 또는 응용 프로그램 비밀을 보호 할 것입니다.

Deploy Hook의 무단 사용을 의심한다면 Deploy Hook을 삭제하고 새로운 것을 생성해야합니다.

각 CMS 공급자는 다르고 Pages' Deploy 걸이와 통합하는 다른 통로를 제안할 것입니다. 다음 섹션에는 인기 CMS 플랫폼의 선택 번호에 대한 단계별 지침이 포함되어 있습니다.
