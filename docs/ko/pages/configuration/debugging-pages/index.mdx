Pages 프로젝트를 설정할 때, 사이트를 성공적으로 배포하는 것을 막는 다양한 오류가 발생할 수 있습니다. 이 가이드는 일반적인 오류 및 솔루션의 개요를 제공합니다.

## 빌드 로그 확인

Pages 빌드 로그에서 오류를 확인할 수 있습니다. 빌드 로그에 액세스하려면:

1. Cloudflare 대시보드에서, 갑니다**Workers & Pages**사이트 맵

   <DashButton url="/?to=/:account/workers-and-pages" />

2. Pages 프로젝트를 선택하십시오.

3. 오시는 길**계정 만들기** > **자주 묻는 질문** > **로그인**.

![Cloudflare 대시보드에 로그인 후 위의 지시에 따라 빌드 로그에 액세스하십시오.](~/assets/images/pages/platform/pages-build-log.png)

빌드 로그의 가능한 오류는 다음과 같은 섹션에 포함되어 있습니다.

### 초기 구축 환경

이 단계에 있는 가능한 과실은 Git 통합 도중 improper 임명에 기인될 수 있었습니다.

GitHub에서 이것을 수정하려면:

1. GitHub 계정으로 로그인하세요.
2. 오시는 길**계정 설정**사용자 아이콘에서 > 찾기**이름 \***&#xD1B5;합 아래.
3. 제품정보**Cloudflare Pages** > **설정하기**> 스크롤 다운 및 선택**다운로드**.
4. Cloudflare 대시보드에 GitHub 사용자/편성 재조합.

GitLab에서 이것을 수정하려면:

1. GitLab 계정으로 로그인하세요.
2. 오시는 길**사이트맵**사용자 아이콘에서 >**이름 \***.
3. 제품정보**CloudflarePages**> 스크롤 다운 및 선택**다운로드**.

당신이의 역할이 필요한 인식**회사 소개**또는 성공적으로 저장소를 연결하려면 빌드가 실패합니다.

### Cloning git 저장소

이 단계에서 가능한 오류는 Git Large File Storage (LFS)의 부족으로 발생할 수 있습니다. LFS 사용 확인[프로젝트](https://docs.github.com/en/billing/managing-billing-for-git-large-file-storage/viewing-your-git-large-file-storage-usage)·[프로젝트](https://docs.gitlab.com/ee/topics/git/lfs/)문서.

하위 모듈 구성을 검토해야합니다.`.gitmodules`루트 디렉토리에 파일. 이 파일은 모두 포함해야`path`·`url`호텔 위치

유효한 구성의 예:

```js
[submodule "example"]
	path = example/path
	url = git://github.com/example/repo.git
```

잘못된 구성의 예 :

```js
[submodule "example"]
	path = example/path
```

또는

```js
[submodule "example"]
        url = git://github.com/example/repo.git
```

### 회사연혁

이 단계에서 가능한 오류는 Pages 프로젝트에서 잘못된 설정으로 발생할 수 있습니다. 빌드 명령, 출력 폴더 및 환경 변수를 incorrect 구성에 검토하십시오.

:::참조

GitHub 또는 GitLab과 통합되어 있는 Pages 프로젝트의 커밋 메시지의 일부로서 이모티콘이나 특수 문자가 없는지 확인하십시오. 프로젝트 구축 시 잠재적으로 문제가 발생할 수 있습니다.

:::

### Cloudflare의 글로벌 네트워크 배포

이 단계에 있는 가능한 과실은 incorrect Pages 기능 구성에 의해 초래될 수 있었습니다. 더 알아보기[제품정보](/pages/functions/)Functions 설정에 대한 자세한 내용은 문서.

함수를 사용하지 않거나 함수 구성이 오류를 포함하지 않다는 것을 검토 한 경우, 검토[Cloudflare 회사연혁](https://www.cloudflarestatus.com/)Cloudflare 네트워크 문제에 대한 빌드 실패를 일으킬 수 있습니다.

## 차이점`pages.dev`및 사용자 정의 영역

사용자 정의 도메인이 CloudflareXQ를 통해 proxied (orange-clouded) 인 경우, 캐싱과 같은 영역의 설정이 적용됩니다.

새로운 내용으로 문제가 발생하면,**이름 \*** > **페이지 규칙**Cloudflare 대시보드 및 페이지 규칙에 대한 확인**캐시 모든 것**지원하다 현재 Pages는 자체 캐시를 처리합니다.

사용자 정의 도메인에 오류를 경험하고 있지만 당신의 위에`pages.dev`도메인, 이동**DNS 보호** > **이름 \***&#x43;loudflare 대시보드에서 당신의 프로젝트에 대한 DNS 레코드를 설정**DNS 전용**(회색 구름). 오류가 발생하면 영역의 구성을 검토합니다.

## 도메인 인증

이름 \*[사용자 정의 도메인](/pages/configuration/custom-domains/)에서 이동하지 않았다**인증 및 인증**Cloudflare 대시보드의 단계는, 뒤에 오는 디버깅 단계 참고합니다.

### HTTP 유효성 검사

Pages는 HTTP 유효성을 사용하며 유효 기간 동안 HTTP 엔드포인트를 명중해야 합니다. 다른 Cloudflare 제품이 방법에 있는 경우에 (와 같은)[오시는 길](/cloudflare-one/access-controls/policies/), [로그인](/rules/url-forwarding/), [일러스트](/workers/), 등), 검증 완료할 수 없습니다.

확인하려면, 실행`curl`귀하의 도메인 타격에 대한 명령`/.well-known/acme-challenge/randomstring`. 예를 들면:

```sh
curl -I https://example.com/.well-known/acme-challenge/randomstring
```

```sh output

HTTP/2 302
date: Mon, 03 Apr 2023 08:37:39 GMT
location: https://example.cloudflareaccess.com/cdn-cgi/access/login/example.com?kid=...&redirect_url=%2F.well-known%2Facme-challenge%2F...
access-control-allow-credentials: true
cache-control: private, max-age=0, no-store, no-cache, must-revalidate, post-check=0, pre-check=0
server: cloudflare
cf-ray: 7b1ffdaa8ad60693-MAN
```

위의 예에서 Cloudflare로 리디렉션됩니다. 오시는 길`Location`헤더). 이 경우 도메인이 확인 될 때까지 도메인에 액세스 할 필요가 있습니다. 도메인이 확인되면 액세스가 재 활성화 될 수 있습니다.

Redirect Rules 또는 Worker 예제에 대한 동일한 종류의 작업을 수행해야합니다.

### Missing CAA 레코드

HTTP 유효성을 차단하지 않으면 인증 기관 인증 (CAA) 레코드가 누락 될 수 있습니다. 이것은 당신이 비활성화 한 경우 가능성이[범용 SSL](/ssl/edge-certificates/universal-ssl/)또는 외부 공급자를 사용하십시오.

확인하려면, 실행`dig`사용자 정의 도메인의 apex (또는 영역, 이 경우[subdomain 영역](/dns/zone-setups/subdomain-setup/)). 예를 들면:

```sh
dig CAA example.com
```

```sh output

; <<>> DiG 9.10.6 <<>> CAA example.com
;; global options: +cmd
;; Got answer:
;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 59018
;; flags: qr rd ra; QUERY: 1, ANSWER: 1, AUTHORITY: 0, ADDITIONAL: 1

;; OPT PSEUDOSECTION:
; EDNS: version: 0, flags:; udp: 4096
;; QUESTION SECTION:
;example.com.		IN	CAA

;; ANSWER SECTION:
example.com.	300	IN	CAA	0 issue "amazon.com"

;; Query time: 92 msec
;; SERVER: 127.0.2.2#53(127.0.2.2)
;; WHEN: Mon Apr 03 10:15:51 BST 2023
;; MSG SIZE  rcvd: 76
```

위의 예에서 ceritficates를 발행하기 위해 Amazon을 허용하는 단일 CAA 레코드 만 있습니다.

이 문제를 해결하려면 인증서 저자 (CA) Cloudflare는 인증서를 발급하는 다음 CAA 레코드를 추가해야합니다.

```
example.com.            300     IN      CAA     0 issue "letsencrypt.org"
example.com.            300     IN      CAA     0 issue "pki.goog; cansignhttpexchanges=yes"
example.com.            300     IN      CAA     0 issue "ssl.com"
example.com.            300     IN      CAA     0 issuewild "letsencrypt.org"
example.com.            300     IN      CAA     0 issuewild "pki.goog; cansignhttpexchanges=yes"
example.com.            300     IN      CAA     0 issuewild "ssl.com"
```

### 지역 보유

·[지역 파악](/fundamentals/account/account-security/zone-holds/)Pages는 영역 파악의 호스트 이름에 대한 사용자 지정 도메인을 추가하는 것을 방지합니다.

영역 파악을 가진 hostname에 대한 사용자 정의 도메인을 추가하려면, 일시적으로[지역 파악을 해제](/fundamentals/account/account-security/zone-holds/#release-zone-holds)사용자 정의 도메인 설정 과정에서.

사용자 정의 도메인이 성공적으로 완료되면, 당신은 할 수 있습니다[지역 파악](/fundamentals/account/account-security/zone-holds/#enable-zone-holds).

:::caution\[문제가 발생]

위의 단계를 수행 한 경우 도메인은 여전히 15 분 후에 확인됩니다.[공지사항](https://discord.cloudflare.com)지원 또는 우리의 지원 팀을 위해[지원 포털](https://dash.cloudflare.com/?to=/:account/support).

:::

### 뚱 베어`index.html`뿌리에`pages.dev`사이트 맵

당신이 볼 경우`404`루트의 오류`pages.dev`URL (`example.pages.dev`), 당신은 가능성이 누락`index.html`프로젝트의 파일.

다운로드`index.html`이 문제를 해결하기 위해 파일.
