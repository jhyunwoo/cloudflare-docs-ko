Cloudflare QX대시보드 또는[Wrangler 클립](/workers/wrangler/commands/#deployment-tail).

로그는 Pages의 동작을 테스트하고 모니터링 할 수있는 강력한 디버깅 도구입니다 일단 그들은 배치 된 기능. Pages 프로젝트의 모든 배포에 사용할 수 있습니다.

로그는 이벤트에 대한 자세한 정보를 제공하고 통찰력을 제공 할 수 있습니다 :

- 당신의 기능에 성공적인 실패한 요구.
- 당신의 기능에 의해 던지는 예외.
- 제품 정보`console.log`s는 당신의 기능 안에 선언했습니다.
- 쉽게 재현 할 수없는 생산 문제.
- 당신의 응용 프로그램에 들어오는 요청의 실시간보기.

로깅 세션을 시작하는 두 가지 방법이 있습니다.

1. 지원하다`wrangler pages deployment tail` [당신의 맨끝에서](/pages/functions/debugging-and-logging/#view-logs-with-wrangler).
2. 사용 방법[Cloudflare 대시보드](/pages/functions/debugging-and-logging/#view-logs-in-the-cloudflare-dashboard).

## 사용자 정의 로그 추가

사용자 정의 로그는`console.log()`함수 안에서 자신을 추가할 수 있는 문. 이러한 기능을 포함 하는 배포에 대 한 로그를 스트리밍할 때, 문 모두에서 나타납니다`wrangler pages deployment tail`그리고 대시보드 산출.

아래는 사용자의 예입니다.`console.log`Pages 기능 안쪽에 문:

```js
export async function onRequest(context) {
	console.log(
		`[LOGGING FROM /hello]: Request came from ${context.request.url}`,
	);

	return new Response("Hello, world!");
}
```

위의 코드를 배포 한 후, 실행`wrangler pages deployment tail`당신의 맨끝에서. 그런 다음 기능에 대한 경로에 액세스하십시오. 당신의 맨끝은 표시합니다:

![Run wrangler 페이지 배포 꼬리](~/assets/images/pages/platform/functions/wrangler-custom-logs.png)

대시보드는 전시할 것입니다:

![대시보드에서 사용자 정의 로그에 액세스하려면 위의 단계를 따르십시오.](~/assets/images/pages/platform/functions/dash-custom-logs.png)

## Wrangler로 로그보기

`wrangler pages deployment tail`개발자가 livestream logs를 특정 프로젝트 및 배포할 수 있습니다.

시작하기, 실행`wrangler pages deployment tail`Pages 프로젝트 디렉토리. 이것은 당신의 국부적으로 맨끝에 있는 당신의 신청에 어떤 들어오는 요구든지 로그인할 것입니다.

각 출력`wrangler pages deployment tail`log는 구조화된 JSON 객체입니다:

```js
{
  "outcome": "ok",
  "scriptName": null,
  "exceptions": [
    {
      "stack": "    at src/routes/index.tsx17:4\n    at new Promise (<anonymous>)\n",
      "name": "Error",
      "message": "An error has occurred",
      "timestamp": 1668542036110
    }
  ],
  "logs": [],
  "eventTimestamp": 1668542036104,
  "event": {
    "request": {
      "url": "https://pages-fns.pages.dev",
      "method": "GET",
      "headers": {},
      "cf": {}
    },
    "response": {
      "status": 200
    }
  },
  "id": 0
}
```

`wrangler pages deployment tail`로깅 세션을 사용자 정의 할 수 있습니다. 더 알아보기[`wrangler pages deployment tail`관련 기사](/workers/wrangler/commands/#deployment-tail)유효한 윤곽 선택권을 위해.

## Cloudflare 대시보드에서 로그 보기

로그인하기`production`또는`preview`어떤 배포와 관련된 환경:

1. Cloudflare 대시보드에서, 가십시오**Workers & Pages**사이트 맵

   <DashButton url="/?to=/:account/workers-and-pages" />
2. Pages 프로젝트를 선택하면 로그를 볼 수 있습니다.**자주 묻는 질문** > **제품정보**.

로깅은 모든 고객에게 제공됩니다 (무료, 유료, 기업).

## 제한 사항

다음과 같은 제한은 Functions 로그에 적용됩니다.

- 로그는 저장되지 않습니다. 스트림을 언제 볼 수 있지만, 그들은 지속되지 않습니다.
- 로그는 초당 함수의 요청이 지난 5 분 동안 100 이상이면 표시되지 않습니다.
- 로그인[모델 번호: Durable Objects](/pages/functions/bindings/#durable-objects)Cloudflare QX대시보드XQ에서 표시할 것이다 당신 기능.
- 최대 10 클라이언트는 한 번에 배포 로그를 볼 수 있습니다. 대시보드 세션 또는`wrangler pages deployment tail`전화.

## 소스 맵

무해한 예외를 디버깅하면 찾을 수 있습니다.[스택 추적](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Error/stack)로그에는 생성 된 JavaScript 파일에 줄 번호가 포함되어 있습니다. Pages의 지원 사용[소스 맵](https://web.dev/articles/source-maps)원본 소스 코드의 라인 번호와 기호와 일치하는 스택 추적을 얻을 수 있습니다.

:::참조

Fullstack 응용 프로그램을 개발할 때, 많은 빌드 도구 (Pages 기능 및 대부분의 풀랙 프레임 워크에 대한 wrangler 포함)는 클라이언트와 서버 모두에 대한 소스 맵을 생성하고 빌드 단계는 서버 소스 맵을 방출하거나 클라이언트 소스 맵을 제거하기 위해 추가 빌드 단계를 사용합니다. 공공 소스 맵은 사용자에 응용 프로그램의 소스 코드를 노출 할 수 있습니다.

:::

더 알아보기[소스 맵 및 스택 추적](/pages/functions/source-maps/)심층적인 설명.
