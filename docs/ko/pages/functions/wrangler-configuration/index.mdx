모델 번호: Pages 기능은 두 가지 방법으로 구성 할 수 있습니다.[Cloudflare대시보드](https://dash.cloudflare.com)또는 Wrangler 구성 파일, 개발 및 배포 설정을 사용자 정의하는 데 사용되는 파일[모델 번호: Workers](/workers/)Pages 기능.

이 페이지는 Wrangler 구성 파일을 통해 Pages 프로젝트를 구성하는 방법에 QXQXQXQXQXQXQXQXQXQXQXQ 프로젝트 역할을 합니다.

WranglerXQ 구성 파일을 사용하는 경우 파일에 파일을 처리해야합니다.[진실의 근원](/pages/functions/wrangler-configuration/#source-of-truth)Pages 프로젝트 구성을 위해.

Wrangler 구성 파일을 사용하여 Pages 프로젝트를 구성할 수 있습니다.

- **소스 컨트롤에 설정 파일을 저장:**&#xB2F9;신의 코드의 나머지와 함께 저장소에 구성을 유지.
- **코드 편집기를 통해 구성 편집:**&#xC778;터페이스 사이에 다시 전환 할 필요가 제거.
- **환경 전반에 걸쳐 공유되는 구성을 작성:**&#xAC19;은 구성 정의[관련 제품](/pages/functions/bindings/)로컬 개발, 미리보기 및 생산에 대한 하나의 파일.
- **더 나은 접근 제한을 지킵니다:**&#xD504;로젝트 저장소의 구성 파일을 사용함으로써 QXQX1717XQX대시보드XQ에 액세스하지 않고 변경할 수 있는 권한을 제어할 수 있습니다.

## 제품 정보

### V2 구축 시스템

모델 번호: Pages Wrangler 윤곽 파일을 통해 기능 구성은 요구합니다[V2 구축 시스템](/pages/configuration/build-image/#v2-build-system)또는 나중에. V1에서 업데이트하려면, 참조[V2 구축 시스템 마이그레이션 지침](/pages/configuration/build-image/#v1-to-v2-migration).

### 모델 번호: Wrangler

Wrangler 버전 3.45.0 이상이 있어야 하며 WranglerXQ 구성 파일을 Pages 프로젝트의 구성에 사용해야 합니다. Wrangler 버전을 확인하려면 Wrangler를 업데이트하거나 WranglerXQ를 설치하십시오.[설치/업데이트 Wrangler](/workers/wrangler/install-and-update/).

## 대시보드 설정에서 마이그레이션

Pages 프로젝트에 대한 마이그레이션 지침은 WranglerXQ 파일이 현재 기존 QXQX1733XWrangler 파일과 함께 QXQXQ 프로젝트에 대한 것보다 다릅니다. 생산에 오류를 방지하기 위해 신중하게 상황을 기반으로 지침을 읽으십시오.

### 기존 Wrangler 파일 프로젝트

Wrangler 구성 파일을 사용하여 미리보기 및 생산 구성을 정의 할 수 있으므로 파일을 정의 할 수있었습니다.[관련 제품](/pages/functions/bindings/)로컬 개발에서 Pages 프로젝트에 사용할 수 있어야 합니다.

로컬 개발을 위한 Wrangler 구성 파일을 사용하고 있다면 이미 Pages 프로젝트에서 파일을 가질 수 있습니다.

<WranglerConfig>
  ```jsonc
  {
  	"kv_namespaces": [
  		{
  			"binding": "KV",
  			"id": "<NAMESPACE_ID>"
  		}
  	]
  }
  ```
</WranglerConfig>

Wrangler 파일을 기존 WranglerX1740XQXQ 프로젝트 구성을 사용하려면 다음을해야합니다.

1. 추가하기`pages_build_output_dir`당신의 가치와 열쇠[출력 디렉토리](/pages/configuration/build-configuration/#build-commands-and-directories)(예:`pages_build_output_dir = "./dist"`.)
2. 기존의 WranglerXQ 구성을 검토하여 배포하기 전에 원하는 프로젝트 구성과 정렬해야합니다.

당신이 추가하는 경우`pages_build_output_dir`WranglerXQ 구성 파일에 대한 키와 Pages 프로젝트 배포, PagesQXQ는 로컬 사용으로 정의 된 구성을 사용할 것입니다. 이는 비 생산이 매우 가능성이 높습니다. WranglerXQ 구성 파일이 생산용으로 준비되도록 confident 때까지 배포하지 마십시오.

:::caution\[Overwriting 구성]

(주)[`wrangler pages download config`](/pages/functions/wrangler-configuration/#projects-without-existing-wranglertoml-file)Cloudflare 대시보드 구성을 기반으로 생성 된 WranglerXQ 파일로 기존 WranglerXQXQXQ 파일을 덮을 것입니다. 로컬 개발을 위해 사용하고 Cloudflare QX대시보드XQ에서 당겨진 구성으로 시작하면이 명령을 실행하십시오.

:::

Wrangler 파일을 계속 사용할 수 있습니다.`pages_build_output_dir`키. 추가하지 않는 경우`pages_build_output_dir`키와 실행`wrangler pages deploy`, 당신은 당신이 필드가 누락되어있는 경고 메시지를 볼 수 있으며, 파일은 로컬 개발에만 사용됩니다.

### 기존 Wrangler 파일없이 프로젝트

QXQX1756XQ QX대시보드를 통해 설정된 구성을 가진 기존 PagesXQXQ 프로젝트를 가지고 있고 프로젝트에서 기존 WranglerXQXWranglerXQXQ 파일을 가지고 있지 않는 경우에, 실행하십시오`wrangler pages download config`Pages 프로젝트 디렉토리의 명령. 더 보기`wrangler pages download config`명령은 기존의 Cloudflare 대시보드 구성을 다운로드하고 WranglerXQ 파일을 Pages 프로젝트 디렉토리에 생성합니다.

### "최신"로 설정된 호환성 날짜 처리

Cloudflare 대시보드에서 미리보기 배포에 대한 호환성 날짜를 "최근"로 설정할 수 있습니다. 이 프로젝트는 항상 최신 호환성 날짜를 사용하여 명시적으로 설정해야합니다.

프로젝트에서 Wrangler 설정 파일을 다운로드하면 "최신"를 사용하여`wrangler pages download`명령, Wrangler 구성 파일은 구성 파일을 다운로드 한 시간에 사용할 수있는 최신 호환성 날짜가 있습니다. Wrangler는 대시보드와 같은 "최신"기능을 지원하지 않습니다. 호환성 날짜는 Wrangler 구성 파일을 사용할 때 명시적으로 설정해야합니다.

더 알아보기[이 가이드](/workers/configuration/compatibility-dates/)어떤 호환성 날짜와 그들이 일하는 방법에 대한 자세한 내용은.

## Pages 기능 및 Workers

사용중인 경우[Workers](/workers), 당신은 이미 익숙할 수 있습니다[Wrangler 구성 파일](/workers/wrangler/configuration/). PagesXQ로 이 파일을 사용할 때 몇 가지 주요 차이점이 있습니다. 기능 프로젝트:

- 구성 분야**정확히 일치하지 마십시오**Pages 기능 사이 Wrangler 파일과 WorkersXQ 동등한 것. 예를 들면, 윤곽 열쇠는 좋아합니다`main`Workers특히 Pages 기능 WranglerXQ 구성 파일에 적용되지 않는 ,. Workers에 의해 지원되는 몇몇 기능[모듈 aliasing](/workers/wrangler/configuration/#module-aliasing)Cloudflare Pages 프로젝트에서 아직 사용될 수 없습니다.
- Pages' WranglerXQ 윤곽 파일은 새로운 열쇠를 소개합니다,`pages_build_output_dir`Pages 프로젝트에만 사용됩니다.
- 의 개념[제품정보](/pages/functions/wrangler-configuration/#configure-environments)그리고 이 파일에 있는 구성 상속**아니다.**&#x57;orkers와 동일.
- 이 파일은[진실의 근원](/pages/functions/wrangler-configuration/#source-of-truth)사용할 때, 당신이 의미**대시보드XQ에서 동일한 필드를 편집 할 수 없습니다**이 파일을 사용하면 됩니다.

## 환경 설정

Wrangler 구성 파일로 로컬 환경, 미리보기 배포 및 생산 전반에 신속하게 구성할 수 있습니다.

### 지역 개발

Wrangler 구성 파일은 로컬로 사용될 때 사용`wrangler pages dev`. 이것은 당신이 Cloudflare QX대시보드XQ에 로그인할 필요가 없는 윤곽 변화를 빨리 시험할 수 있다는 것을 의미합니다. 예를 들어 다음과 같은 구성 파일에 Refer:

<WranglerConfig>
  ```jsonc
  {
  	"$schema": "./node_modules/wrangler/config-schema.json",
  	"name": "my-pages-app",
  	"pages_build_output_dir": "./dist",
  	"compatibility_date": "$today",
  	"compatibility_flags": [
  		"nodejs_compat"
  	],
  	"kv_namespaces": [
  		{
  			"binding": "KV",
  			"id": "<NAMESPACE_ID>"
  		}
  	]
  }
  ```
</WranglerConfig>

이 Wrangler 구성 파일 추가`nodejs_compat`호환성 깃발과 KV 네임스페이스는 Pages 프로젝트에 바인딩합니다. (주)`wrangler pages dev`Pages 프로젝트 디렉토리에 이 Wrangler 구성 파일이 적용됩니다`nodejs_compat`로컬라이제이션 플래그 및 노출`KV`Pages에 바인딩 기능 코드 at`context.env.KV`.

:::참조

구성 키의 전체 목록의 경우, 참조[상속 키](#inheritable-keys)·[비 inheritable 열쇠](#non-inheritable-keys).

:::

### 생산 및 미리보기 배포

프로젝트를 배포 할 준비가되면 Wrangler 파일을 포함하는 새로운 배포를 만들기 위해 생산 및 미리보기 배포 구성을 설정할 수 있습니다.

:::참조

다음 명령의 경우 git을 사용하여 설정된 지점을 기억하는 것이 중요합니다.[생산 지점](/pages/configuration/branch-build-controls/#production-branch-control)물론,[미리보기 지점 설정](/pages/configuration/branch-build-controls/#preview-branch-control).

:::

생산에 대한 구성으로 위의 예제를 사용하려면 새로운 생산 배포를 사용합니다.

```sh
npx wrangler pages deploy
```

또는 더 구체적으로:

```sh
npx wrangler pages deploy --branch <PRODUCTION BRANCH>
```

미리보기 배포에 대한 구성을 배포하려면 위의 같은 명령을 실행할 수 있습니다.[관련 기사](/pages/configuration/branch-build-controls/#preview-branch-control). 이 설정은 모든 미리보기 배포, 뿐만 아니라 특정 지점에서 배포합니다. Pages는 현재 분지 기반 구성을 지원하지 않습니다.

:::참조

더 보기`--branch`깃발은 선택적입니다`wrangler pages deploy`. git 통합을 사용하는 경우, Wrangler는 현재 저장소에서 분기를 삽입하고 명령에 임의로 추가합니다.

:::

### 환경특성

로컬, 미리보기 배포 및 생산을 통해 다른 구성을 사용할 수 있는 시간이 있습니다. 생산 및 미리보기 배포에 대한 override 구성이 가능합니다.`[env.production]`또는`[env.preview]`.

:::참조

이름 \*[Workers 환경분야](/workers/wrangler/configuration/#environments), `production`·`preview`사용할 수있는 유일한 두 가지 옵션`[env.<ENVIRONMENT>]`.

:::

다음 WranglerXQ 구성 파일에 대한 예를 들면 override 미리보기 설정 구성:

<WranglerConfig>
  ```jsonc
  {
  	"$schema": "./node_modules/wrangler/config-schema.json",
  	"name": "my-pages-site",
  	"pages_build_output_dir": "./dist",
  	"kv_namespaces": [
  		{
  			"binding": "KV",
  			"id": "<NAMESPACE_ID>"
  		}
  	],
  	"vars": {
  		"API_KEY": "1234567asdf"
  	},
  	"env": {
  		"preview": {
  			"kv_namespaces": [
  				{
  					"binding": "KV",
  					"id": "<PREVIEW_NAMESPACE_ID>"
  				}
  			],
  			"vars": {
  				"API_KEY": "8901234bfgd"
  			}
  		}
  	}
  }
  ```
</WranglerConfig>

이 파일을 통해 배포하는 경우`wrangler pages deploy`, `name`, `pages_build_output_dir`, `kv_namespaces`·`vars`현지 및 생산에 대한 구성을 적용 할 수 있지만`env.preview`더 많은 것`kv_namespaces`·`vars`미리보기 배포.

구성 값이 로컬 및 미리보기에 적용되었는지 원한다면, 오버라이드 생산, 파일이 다음과 같이 보일 것입니다:

<WranglerConfig>
  ```jsonc
  {
  	"$schema": "./node_modules/wrangler/config-schema.json",
  	"name": "my-pages-site",
  	"pages_build_output_dir": "./dist",
  	"kv_namespaces": [
  		{
  			"binding": "KV",
  			"id": "<NAMESPACE_ID>"
  		}
  	],
  	"vars": {
  		"API_KEY": "1234567asdf"
  	},
  	"env": {
  		"production": {
  			"kv_namespaces": [
  				{
  					"binding": "KV",
  					"id": "<PRODUCTION_NAMESPACE_ID>"
  				}
  			],
  			"vars": {
  				"API_KEY": "8901234bfgd"
  			}
  		}
  	}
  }
  ```
</WranglerConfig>

## 공급 능력

Inheritable 키는 최고 수준의 구성이며 환경 별 구성으로 상속 (또는 overridden)을 상속 할 수 있습니다.

- `name` <Type text="string" /> <MetaInfo text="required" />
  - Pages 프로젝트의 이름. 알파벳 및 dashes 만.

- `pages_build_output_dir` <Type text="string" /> <MetaInfo text="required" />
  - 프로젝트의 빌드 출력 폴더에 경로. 예를 들면:`./dist`.

- `compatibility_date` <Type text="string" /> <MetaInfo text="required" />
  - 양식의 날짜`yyyy-mm-dd`Workers 런타임의 버전을 결정하는 데 사용될 것입니다. 더 알아보기[호환성 날짜](/workers/configuration/compatibility-dates/).

- `compatibility_flags`string\[] 옵션
  - Workers 런타임의 다가오는 기능에서 기능을 가능하게 하는 깃발의 명부는, 보통 함께 사용했습니다`compatibility_date`. 참고[호환성 날짜](/workers/configuration/compatibility-dates/).

- `send_metrics` <Type text="boolean" /> <MetaInfo text="optional" />
  - Wrangler는 이 프로젝트를 위해 CloudflareXQ에 사용법 자료를 보내야 합니다. 기본 설정`true`. 당신은 우리의 이것에 관하여 더 많은 것을 배울 수 있습니다[데이터 정책](https://github.com/cloudflare/workers-sdk/tree/main/packages/wrangler/telemetry.md).

- `limits`옵션 제한
  - 런타임에서 실행할 수 있는 제한이 있습니다. 더 알아보기[제한 사항](#limits).

- `placement`선택 사항
  - 어떻게 Pages 기능은 둥근 지구 시간을 극소화하기 위하여 있어야 합니다. 더 알아보기[스마트 배치](/workers/configuration/placement/).

- `upload_source_maps`한국어
  - 시간 :`upload_source_maps`설정`true`, Wrangler는 당신의 Pages 프로젝트의 어떤 서버 측 근원 지도든지 기록에 있는 정확한 더미 추적을 주기 위하여 업로드할 것입니다.

## 비 inheritable 열쇠

비 inheritable 열쇠는 최고 수준에 구성할 수 있습니다, 그러나, 어떤 비 inheritable 열쇠가 어떤 환경을 위해 overridden인 경우에 (예를 들면,`[[env.production.kv_namespaces]]`), 모든 non-inheritable 열쇠는 또한 환경 윤곽과 overridden에서 지정되어야 합니다.

예를 들어,이 구성은 작동하지 않습니다.

<WranglerConfig>
  ```jsonc
  {
  	"$schema": "./node_modules/wrangler/config-schema.json",
  	"name": "my-pages-site",
  	"pages_build_output_dir": "./dist",
  	"kv_namespaces": [
  		{
  			"binding": "KV",
  			"id": "<NAMESPACE_ID>"
  		}
  	],
  	"vars": {
  		"API_KEY": "1234567asdf"
  	},
  	"env": {
  		"production": {
  			"vars": {
  				"API_KEY": "8901234bfgd"
  			}
  		}
  	}
  }
  ```
</WranglerConfig>

`[[env.production.vars]]`override에 설정`[vars]`. 이것 때문에`[[kv_namespaces]]`또한 정의에 의해 overridden`[[env.production.kv_namespaces]]`.

이것은 로컬 개발을 위해 작동하지만 배포하려고 할 때 유효하지 않습니다.

## 진실의 근원

Pages 기능 프로젝트에서 사용될 때, 당신의 Wrangler 파일은 진실의 근원입니다. Cloudflare대시보드로 로그인하면 동일한 필드를 편집 할 수 없습니다.

설정에 대한 Wrangler 구성 파일을 사용하지 않으려면 안전하게 삭제하고 새로운 배포를 만들 수 있습니다. 마지막 배포에서 구성 값은 여전히 적용되며 대시보드에서 편집할 수 있습니다.
