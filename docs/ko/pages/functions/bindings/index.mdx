## KV 네임스페이스

[Workers KV](/kv/concepts/kv-namespaces/)Cloudflare의 열쇠 가치 저장 해결책입니다.

PagesQX1090XQXQ 기능, 당신은 안으로 KV namespace 바인딩을 구성할 수 있습니다[Wrangler 구성 파일](/pages/functions/wrangler-configuration/#kv-namespaces)또는 Cloudflare 대시보드.

Cloudflare QXQX대시보드XQXQXQ를 통해 KV 네임스페이스 바인딩을 구성하려면:

1. Cloudflare 대시보드에서, 가십시오**Workers & Pages**사이트 맵

   <DashButton url="/?to=/:account/workers-and-pages" />
2. Pages 프로젝트를 선택하십시오.
3. 오시는 길**계정 설정** > **회사 소개** > **더 보기** > **KV 네임스페이스**.
4. 아래에 이름을 바인딩하십시오**변수 이름**.
5. 이름 \***KV 네임스페이스**, 원하는 네임스페이스를 선택합니다.
6. Redeploy 효력을 가지고 가는 바인딩을 위한 당신의 프로젝트.

아래는 기능에서 KVXQ를 사용하는 방법의 예입니다. 다음 예제에서 KV 네임스페이스 바인딩은 호출됩니다.`TODO_LIST`그리고 당신은 당신의 기능 부호에 있는 바인딩에 접근할 수 있습니다`context.env`:

<Tabs>
  <TabItem label="모델 번호: JavaScript" icon="seti:javascript">
    ```js
    export async function onRequest(context) {
    	const task = await context.env.TODO_LIST.get("Task:123");
    	return new Response(task);
    }
    ```
  </TabItem>

  <TabItem label="모델 번호: TypeScript" icon="seti:typescript">
    ```ts
    interface Env {
    	TODO_LIST: KVNamespace;
    }

    export const onRequest: PagesFunction<Env> = async (context) => {
    	const task = await context.env.TODO_LIST.get("Task:123");
    	return new Response(task);
    };
    ```
  </TabItem>
</Tabs>

### 로컬로 KV 네임스페이스와 상호 작용

KV 네임스페이스와 상호 작용할 수 있습니다.

- Pages 프로젝트의 Wrangler 파일을 구성하고 실행[`npx wrangler pages dev`](/workers/wrangler/commands/#dev-1).
- 패스 인수를`wrangler pages dev`직접.

KV 네임스페이스는 로컬로 Wrangler CLI에 대한 인수를 전달함으로써 상호 작용하기 위해 추가`-k <BINDING_NAME>`또는`--kv=<BINDING_NAME>`이름 \*`wrangler pages dev`명령. 예를 들어, KV 네임스페이스가 기능에 따라 달라집니다.`TODO_LIST`바인딩, 실행하여 로컬 개발의 KV 네임스페이스에 접근:

```sh
npx wrangler pages dev <OUTPUT_DIR> --kv=TODO_LIST
```

## Durable Objects

[Durable Objects](/durable-objects/)(DO)는 Cloudflare는 WebSockets와 취급 국가와 같은 힘 기능에 강한 일관된 자료 상점입니다.

<Render file="do-note" product="pages" />

Pages 기능에 튼튼한 목표를 묶기 위하여, 당신은 안으로 튼튼한 목표 바인딩을 구성할 수 있습니다[Wrangler 구성 파일](/pages/functions/wrangler-configuration/#kv-namespaces)또는 Cloudflare 대시보드.

Cloudflare 대시보드를 통해 튼튼한 목표 바인딩을 구성하려면:

1. Cloudflare 대시보드에서, 가십시오**Workers & Pages**사이트 맵

   <DashButton url="/?to=/:account/workers-and-pages" />
2. Pages 프로젝트를 선택하십시오.
3. 오시는 길**계정 설정** > **회사 소개** > **더 보기** > **튼튼한 목표**.
4. 아래에 이름을 바인딩하십시오**변수 이름**.
5. 이름 \***튼튼한 목표 namespace**, 원하는 네임스페이스를 선택합니다.
6. Redeploy 효력을 가지고 가는 바인딩을 위한 당신의 프로젝트.

아래는 기능에서 Durable Objects를 사용하는 방법의 예입니다. 다음 예제에서, 당신의 DO 바인딩은 호출됩니다`DURABLE_OBJECT`그리고 당신은 당신의 기능 부호에 있는 바인딩에 접근할 수 있습니다`context.env`:

<Tabs>

    	return stub.fetch(context.request);
    }
    ```
  </TabItem>

  <TabItem label="모델 번호: TypeScript" icon="seti:typescript">

    	const stub = context.env.DURABLE_OBJECT.get(id);

### Locally 당신의 튼튼한 목표 namespaces를 가진 Interact

두 가지 방법 중 하나에서 로컬로 튼튼한 개체 바인딩과 상호 작용할 수 있습니다.

- Pages 프로젝트의 Wrangler 파일을 구성하고 실행[`npx wrangler pages dev`](/workers/wrangler/commands/#dev-1).
- 패스 인수를`wrangler pages dev`직접.

로컬로 개발하는 동안, 튼튼한 Object namespace와 상호 작용하는 동안, 실행`wrangler dev`Worker의 디렉토리에서 튼튼한 개체를 수출합니다. 다른 터미널에서 실행`wrangler pages dev`Pages 프로젝트 디렉토리.

Wrangler CLI, append를 통해 로컬로 튼튼한 오브젝트 네임스페이스와 상호 작용하기`--do <BINDING_NAME>=<CLASS_NAME>@<SCRIPT_NAME>`으로`wrangler pages dev`. `CLASS_NAME`튼튼한 개체 클래스 이름을 표시하고`SCRIPT_NAME`당신의 노동자의 이름.

예를 들어, 노동자가 호출되면`do-worker`그리고 그것은 튼튼한 개체 클래스를 선언`DurableObjectExample`, 실행해서 이 튼튼한 목표 접근`npx wrangler dev`내 계정`do-worker`디렉토리. 동시에 실행`npx wrangler pages dev <OUTPUT_DIR> --do MY_DO=DurableObjectExample@do-worker`Pages의 프로젝트 디렉토리. 자주 묻는 질문`MY_DO`기능 코드를 사용하여 바인딩`context.env`(예:`context.env.MY_DO`).

## R2 물통

[모델 번호: R2](/r2/)Cloudflare의 blob 스토리지 솔루션으로 개발자는 egress 수수료없이 많은 양의 비구조 데이터를 저장할 수 있습니다.

R2 버킷을 Pages 기능에 바인딩하려면 R2 버킷 바인딩을 구성할 수 있습니다.[Wrangler 구성 파일](/pages/functions/wrangler-configuration/#r2-buckets)또는 Cloudflare 대시보드.

Cloudflare QX대시보드XQXQXQ를 통해 R2 물통 바인딩을 구성하기 위하여:

1. Cloudflare QX대시보드에서, 가십시오**Workers & Pages**사이트 맵

   <DashButton url="/?to=/:account/workers-and-pages" />
2. Pages 프로젝트를 선택하십시오.
3. 오시는 길**계정 설정** > **회사 소개** > **더 보기** > **R2 물통**.
4. 아래에 이름을 바인딩하십시오**변수 이름**.
5. 이름 \***R2 물통**, 원하는 R2 물통을 선택하십시오.
6. Redeploy 효력을 가지고 가는 바인딩을 위한 당신의 프로젝트.

아래는 기능에서 R2 물통을 사용하는 방법의 예입니다. 뒤에 오는 예에서, 당신의 R2 물통 바인딩은 불립니다`BUCKET`그리고 당신은 당신의 기능 부호에 있는 바인딩에 접근할 수 있습니다`context.env`:

<Tabs>
  <TabItem label="모델 번호: JavaScript" icon="seti:javascript">

    	const obj = await context.env.BUCKET.get("some-key");
    	if (obj === null) {
    		return new Response("Not found", { status: 404 });
    	}
    	return new Response(obj.body);
    }
    ```
  </TabItem>

  <TabItem label="모델 번호: TypeScript" icon="seti:typescript">
    ```ts

    	BUCKET: R2Bucket;
    }

    export const onRequest: PagesFunction<Env> = async (context) => {
    	const obj = await context.env.BUCKET.get("some-key");
    	if (obj === null) {
    		return new Response("Not found", { status: 404 });
    	}
    	return new Response(obj.body);
    };
    ```
  </TabItem>
</Tabs>

### 로컬로 R2 버킷과 상호 작용

R2 버킷과 상호 작용할 수 있습니다.

- Pages 프로젝트의 Wrangler 파일을 구성하고 실행[`npx wrangler pages dev`](/workers/wrangler/commands/#dev-1).
- 패스 인수를`wrangler pages dev`직접.

:::참조

기본적으로 Wrangler는 로컬 저장소에 데이터를 자동으로 생성합니다. 더 많은 정보를 원하시면, 참조[지역 개발](/workers/development-testing/).

:::

Wrangler CLI를 통해 로컬로 Wrangler 버킷과 상호 작용하려면 추가`--r2=<BINDING_NAME>`이름 \*`wrangler pages dev`명령. R2 물통이 당신의 기능에 묶는 경우에`BUCKET`묶음, 이 R2 버킷을 로컬 개발에서 실행:

```sh
npx wrangler pages dev <OUTPUT_DIR> --r2=BUCKET
```

이 바인딩을 사용하여 Interact`context.env`(예:`context.env.BUCKET`.)

### 서비스 바인딩을 현지으로

두 가지 방법 중 하나에서 로컬로 서비스 바인딩과 상호 작용할 수 있습니다.

- Pages 프로젝트의 Wrangler 파일을 구성하고 실행[`npx wrangler pages dev`](/workers/wrangler/commands/#dev-1).
- 패스 인수를`wrangler pages dev`직접.

자주 묻는 질문[서비스 바인딩](/workers/runtime-apis/bindings/service-bindings/)로컬로 개발하는 동안, 당신이 묶고 싶은 노동자를 실행`wrangler dev`그리고 평행한에서, 뛰기`wrangler pages dev`이름 \*`--service <BINDING_NAME>=<SCRIPT_NAME>`이름 \*`SCRIPT_NAME`노동자의 이름을 나타냅니다. 예를 들어, 노동자가 호출되면`my-worker`, 이 노동자와 연결하여 그것을 통해 실행`npx wrangler dev`(Worker의 디렉토리에서) 따라`npx wrangler pages dev <OUTPUT_DIR> --service MY_SERVICE=my-worker`(Pages' 디렉토리에서). 이 바인딩을 사용하여 Interact`context.env`(예:`context.env.MY_SERVICE`).

당신은 Cloudflare QXQXQX대시보드를 통해 서비스 바인딩을 설치하면, 당신은 부를 필요가 있을 것입니다`wrangler pages dev`이름 \*`--service <BINDING_NAME>=<SCRIPT_NAME>`이름 \*`BINDING_NAME`서비스 바인딩의 이름은이고`SCRIPT_NAME`노동자의 이름입니다.

예를 들어, 로컬로 개발하기 위해 노동자가 호출되면`my-worker`, 실행`npx wrangler dev`내 계정`my-worker`디렉토리. 다른 맨끝에서, 또한 달리십시오`npx wrangler pages dev <OUTPUT_DIR> --service MY_SERVICE=my-worker`Pages 프로젝트 디렉토리. 이 서비스 바인딩을 사용하여 Interact`context.env`(예:`context.env.MY_SERVICE`).

Wrangler는 또한 Pages 프로젝트를 실행하고 하나의 명령과 동일한 dev 세션에서 Workers를 바인딩합니다. 그것을 밖으로 시도하려면, Wrangler에 다중 C 플래그를 통과, 다음과 같이:`wrangler pages dev -c wrangler.jsonc -c ../other-worker/wrangler.jsonc`. 첫 번째 인수는 PagesXQ 구성 파일에 해당해야하며, 이후 구성은 Pages 프로젝트의 서비스 바인딩을 통해 접근할 수 있습니다.

:::카트로션

하나의 Wrangler 명령을 가진 동일한 dev 세션에서 여러 WorkersXQX1303XQXQ를 실행하는 지원은 실험적이고, 우리가 경험에서 일하는 것처럼 변경할 수 있습니다. 버그로 실행하거나 피드백을 가지고 있다면,[근로자 sdk 저장소에 문제가 열립니다.](https://github.com/cloudflare/workers-sdk/issues/new)

1. Cloudflare 대시보드에서, 가십시오**Workers & Pages**사이트 맵

   <DashButton url="/?to=/:account/workers-and-pages" />
2. Pages 프로젝트를 선택하십시오.
3. 오시는 길**계정 설정** > **회사 소개** > **더 보기** > **Analytics 엔진**.
4. 아래에 이름을 바인딩하십시오**변수 이름**.
5. 이름 \***데이터셋**, 원하는 dataset를 입력합니다.
6. Redeploy 효력을 가지고 가는 바인딩을 위한 당신의 프로젝트.

아래에서 Analytics Engine 바인딩을 사용하는 방법은 다음과 같습니다. 다음 예제에서 바인딩은 호출됩니다.`ANALYTICS_ENGINE`그리고 당신은 당신의 기능 부호에 있는 바인딩에 접근할 수 있습니다`context.env`:

### Analytics Engine 바인딩을 현지으로 통합

로컬로 Analytics Engine 바인딩을 사용할 수 없습니다.

## 환경 변수

이름 \*[환경 변수](/workers/configuration/environment-variables/)당신의 기능에 의해 접근될 수 있는 주사된 가치입니다. 환경 변수는 텍스트 문자열 또는 JSON 값을 Pages 기능에 첨부할 수 있는 바인딩 유형입니다. 일반 텍스트로 저장됩니다. Cloudflare QX대시보드XQ에서 직접 환경 변수를 설정하여 실행 시간과 빌드 시간에서 생산 및 미리보기 환경을 제공합니다.

Pages 프로젝트에 환경 변수를 추가하려면, 당신은 사용할 수 있습니다[Wrangler 구성 파일](/pages/functions/wrangler-configuration/#environment-variables)또는 Cloudflare 대시보드.

QXQX1380XQ 대시보드를 통해 환경 변수를 구성하려면:

1. Cloudflare QX대시보드에서, 가십시오**Workers & Pages**사이트 맵

   <DashButton url="/?to=/:account/workers-and-pages" />
2. Pages 프로젝트 선택
3. 오시는 길**계정 설정** > **변수 및 비밀** > **더 보기** .
4. 변수 이름과 값을 설정한 후, 선택**제품 정보**.

아래는 함수의 환경 변수를 사용하는 방법의 예입니다. 이 예제의 환경 변수는`ENVIRONMENT`환경 변수에 접근할 수 있습니다.`context.env`:

### 환경 변수를 로컬로

두 가지 방법 중 하나에서 로컬로 환경 변수와 상호 작용할 수 있습니다.

- Pages 프로젝트의 Wrangler 파일을 구성하고 실행`npx wrangler pages dev`.
- 패스 인수를[`wrangler pages dev`](/workers/wrangler/commands/#dev-1)직접.

Wrangler CLI를 통해 로컬로 환경 변수와 상호 작용하려면 추가`--binding=<ENVIRONMENT_VARIABLE_NAME>=<ENVIRONMENT_VARIABLE_VALUE>`이름 \*`wrangler pages dev`명령:

```sh
npx wrangler pages dev --binding=<ENVIRONMENT_VARIABLE_NAME>=<ENVIRONMENT_VARIABLE_VALUE>
```

## 계정 관리

비밀은 Pages 기능에 암호화 된 텍스트 값을 첨부 할 수있는 바인딩의 유형입니다. 설정한 후 비밀을 볼 수 없으며, 실제 비밀만 접근할 수 있습니다.`context.env`. 비밀은 API 키와 auth 토큰과 같은 민감한 정보를 저장하는 데 사용됩니다.

Pages 프로젝트에 비밀을 추가하려면:

1. Cloudflare QX대시보드에서, 갑니다**Workers & Pages**사이트 맵

   <DashButton url="/?to=/:account/workers-and-pages" />
2. Pages 프로젝트 선택
3. 오시는 길**계정 설정** > **변수 및 비밀** > **더 보기**.
4. 변수 이름과 값을 설정합니다.
5. 제품정보**공유하기**비밀을 만듭니다.
6. 제품정보**제품 정보**.

당신은 환경 변수와 같은 방법을 사용합니다. Wrangler 또는 Cloudflare QXQX대시보드XQ로 비밀을 설정할 때, 그 비밀을 사용하는 배포 전에 수행해야합니다. 더 많은 지도를 위해, 참고하십시오[환경 변수](#environment-variables).
