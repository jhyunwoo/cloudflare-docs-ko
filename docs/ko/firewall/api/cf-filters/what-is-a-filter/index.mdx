필터는 말하기의 방법입니다:

```txt
if (traffic matches certain criteria) then...
```

필터는 반환할 표현이 포함되어 있습니다.`true`또는`false`'Cloudflare'를 통해 트래픽을 평가할 때.

필터 표현은 인간과 기계 읽기 가능, 그리고 당신은 당신이 검출하고 행동에 흥미있는 교통에 정확하게 일치하기 위하여 복잡한 논리를 구성할 수 있습니다.

필터 객체는 일반적으로 다음과 같습니다.

```json
{
  "id": "<FILTER_ID>",
  "expression": "(http.request.uri.path ~ \"^.*wp-login.php$\" or http.request.uri.path ~ \"^.*xmlrpc.php$\") and ip.src ne 93.184.216.34",
  "description": "WordPress login paths via the login page or mobile RPC endpoint"
}
```

이 예제 필터에서 지정된 표현은 다음과 같습니다.

```txt
(http.request.uri.path ~ "^.*wp-login.php$" or http.request.uri.path ~ "^.*xmlrpc.php$") and ip.src ne 93.184.216.34
```

이 필터 표현에는`(this or that) and not this`디자인되는 구조:

- 두 WordPress 경로 캡처는 강제 암호 공격을 위반 할 수 있습니다, 및
- IP 주소에서 오는 트래픽 제외`93.184.216.34`.

사무실의 IP임을 상상해보십시오. 이 표현은 사용 될 수있는 필터를 보여줍니다 ( 방화벽 규칙에서) 사무실 네트워크 밖에 액세스 할 때 WordPress 로그인에 액세스 차단.

규칙 표현에 대한 자세한 내용은 참조[회사 소개](/ruleset-engine/rules-language/expressions/)규칙 언어 문서에서.
