## 다중 규칙 업데이트

이 예제는 단일 API 호출을 사용하여 여러 방화벽 규칙을 업데이트합니다.

JSON 객체 배열에서 최대 25개의 규칙을 포함할 수 있습니다 (`-d`flag) 배치로 업데이트합니다. 일괄 처리는 거래로 처리됩니다.

```bash title="Request"
curl --request PUT \
"https://api.cloudflare.com/client/v4/zones/{zone_id}/firewall/rules" \
--header "X-Auth-Email: <EMAIL>" \
--header "X-Auth-Key: <API_KEY>" \
--header "Content-Type: application/json" \
--data '[
  {
    "id": "<RULE_ID>",
    "paused": false,
    "description": "Challenge site",
    "action": "challenge",
    "priority": null,
    "filter": {
      "id": "<FILTER_ID>",
      "expression": "not http.request.uri.path matches \"^/api/.*$\"",
      "paused": false,
      "description": "not /api"
    }
  }
]'
```

:::참조

`PUT`지정된 필터를 업데이트하지 않습니다. 필터 ID에서만 볼 수 있습니다 (`<FILTER_ID>`) 새로운 필터로 규칙을 업데이트합니다.

필터를 업데이트하려면[필터 API](/firewall/api/cf-filters/).

:::

```json title="Response"
{
	"result": [
		{
			"id": "<RULE_ID>",
			"paused": false,
			"description": "Challenge site",
			"action": "challenge",
			"priority": null,
			"filter": {
				"id": "<FILTER_ID>",
				"expression": "not http.request.uri.path matches \"^/api/.*$\"",
				"paused": false,
				"description": "not /api"
			}
		}
	],
	"success": true,
	"errors": [],
	"messages": []
}
```

## 단일 규칙 업데이트

이 예제는 방화벽 규칙을 ID로 업데이트`{rule_id}`.

요청 본문에 다음 필드를 포함해야 합니다:

- `id`
- `action`
- `filter.id`

다른 모든 분야는 선택적입니다.

```bash title="Request"
curl --request PUT \
"https://api.cloudflare.com/client/v4/zones/{zone_id}/firewall/rules/{rule_id}" \
--header "X-Auth-Email: <EMAIL>" \
--header "X-Auth-Key: <API_KEY>" \
--header "Content-Type: application/json" \
--data '{
  "id": "<RULE_ID>",
  "paused": false,
  "description": "Do not challenge login from office IPv6",
  "action": "allow",
  "priority": null,
  "filter": {
    "id": "<FILTER_ID>",
    "expression": "ip.src in {2400:cb00::/32 2803:f800::/32 2c0f:f248::/32 2a06:98c0::/29} and (http.request.uri.path ~ \"^.*/wp-login.php$\" or http.request.uri.path ~ \"^.*/xmlrpc.php$\")",
    "paused": false,
    "description": "Login from office"
  }
}'
```

```json title="Response"
{
	"result": {
		"id": "<RULE_ID>",
		"paused": false,
		"description": "Do not challenge login from office IPv6",
		"action": "allow",
		"priority": null,
		"filter": {
			"id": "<FILTER_ID>",
			"expression": "ip.src in {2400:cb00::/32 2803:f800::/32 2c0f:f248::/32 2a06:98c0::/29} and (http.request.uri.path ~ \"^.*/wp-login.php$\" or http.request.uri.path ~ \"^.*/xmlrpc.php$\")",
			"paused": false,
			"description": "Login from office"
		}
	},
	"success": true,
	"errors": [],
	"messages": []
}
```

:::참조

`PUT`요청에 명시되지 않은 필드를 덮어쓰기.

예를 들어, 요청 omits 경우`description`, 이전에 존재하는 것`description`가치는 지워질 것입니다.

기존의 가치를 보존하기 위해`GET`요청 및 응답에 따라 필드 (및 해당 값)을 결정하여`PUT`이름 \*

:::
