## Firewall 규칙 예제 JSON 응답

JSON 응답[방화벽 규칙 API](/api/resources/firewall/subresources/rules/methods/list/)이 구조가 있다:

```json
{
	"id": "772bf1026a72c400ea576db1ffa16407",
	"filter": {
		"id": "6f58318e7fa2477a23112e8118c66f61",
		"expression": "http.request.uri.path ~ \"^.*/wp-login.php$\" or http.request.uri.path ~ \"^.*/xmlrpc.php$\"",
		"paused": false,
		"description": "WordPress login paths",
		"ref": ""
	},
	"action": "challenge",
	"priority": 1000,
	"paused": false,
	"description": "Protect blog login page",
	"ref": ""
}
```

이 테이블은 객체 속성을 요약합니다:

## 우선 충돌 방지

Priority는 방화벽 규칙을 구성하는 핵심 역할을 합니다. Cloudflare 필터를 사용하면 다음과 같은 분쟁 규칙을 구성 할 수 있습니다.

- 사무실 IP 범위에서 요청을 허용하고,
- 특정 사용자 에이전트와 블록 요청.

사용자 에이전트를 사용하여 사무실 IP 범위에서 요청은 모두 규칙을 트리거하지만, 우리는 허용하고 요청을 차단 할 수 없습니다. 이 문제를 해결하기 위해 방화벽 규칙은 행동과 우선 순위에 따라 엄격한 주문을 따릅니다.

Cloudflare는 우선순위 1이 우선순위와 규칙을 우선순위로 지정합니다. 같은 우선의 규칙을 위해, Cloudflare는 그들에 따라 행동을 주문[우선순위](/firewall/cf-firewall-rules/actions/#supported-actions). 위의 예에서, 우선이 설정되지 않는 경우, 규칙`allow request from the office IP range`신청하기*지원하다*행동은 보다 높은 precedence*제품정보*.

무인 행동의 위험을 줄이기 위해 잠재적으로 분쟁 규칙에 대한 원하는 우선 순위를 명시적으로 지정하는 것이 가장 좋습니다.
