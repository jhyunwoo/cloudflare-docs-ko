에 2021-04-08, Cloudflare 발표[URL 정상화](/rules/normalization/), HTTP 요청 URI 경로를 정상화하여 영역을 보호하는 기능.

악성 사용자는 방화벽 시스템 및 원산지 시스템에 의해 다르게 해석 될 수있는 특정 URI를 만들 수 있습니다. 사용 가능**수신 URL을 정상화**URI 경로에 필터링하는 모든 규칙은 이 악의적 인 사용자에 대한 보호의 추가 레이어를 제공하는 대문 양식의 URL을 받게됩니다.

Cloudflare는 이 변화에 영향을 미칠 수 있는 사람들을 제외하고 모든 Cloudflare 영역에 대해 점차적으로 URL 정상화를 가능하게 합니다. 우리는 URL 정상화 기술을 사용할 때 더 이상 일치하지 않을 HTTP 필드의 패턴을 찾고 모든 방화벽 규칙을 분석하여 영향을받는 영역을 결정했습니다.

이 필드는 다음과 같습니다:

- `http.request.uri.path`
- `http.request.full_uri`
- `http.request.uri`

Cloudflare는 기존 방화벽 규칙의 동작을 방지하기 위해 이러한 변화에 영향을 미칠 영역에서 URL 정상화가 자동으로 활성화되지 않았습니다.

## 왜 URL 정상화는 중요합니다

Cloudflare는 당신이 활성화 할 수있는 강력 추천**수신 URL을 정상화**내 계정**이름 \*** > **제품정보** > **URL 정상화**영역의 보안 자세를 강화하기 위해. 성공적인 공격의 더 큰 위험에서 영역을 떠나지 마십시오. 맛있는 파티는 규칙이 회계하지 않는 방식으로 URL을 만들 수 있습니다.

예를 들어, 방화벽 규칙과 같은 표현`http.request.uri.path contains "/login"`악의 행위가 인코딩 된 경우 우회 할 수 있습니다.`l`문자로`%6C`. 이 시나리오에서 URL 정상화가 비활성화되어 트래픽은 방화벽 규칙에 의해 일치하지 않습니다.

더 알아보기[URL 정상화가 작동하는 방법](/rules/normalization/how-it-works/)더 많은 정보 및 추가 예제.

***

## 자주 묻는 질문

그것은 당신이 추천:

1. URL 정상화 변화에 영향을 미치는 방화벽 규칙을 업데이트하십시오.
2. URL 정상화 활성화.

이 단계는 영역 (s)에 더 강한 안전 자세를 지킬 것입니다.

### 1. 검토 및 업데이트 방화벽 규칙

URL 정상화를 활성화하기 전에, 당신은 당신의 지역 (들)에 영향을 미치는 방화벽 규칙을 검토하고 다음 접근법 중 하나를 가지고:

- 이 방화벽 규칙을 편집하여 더 이상 방아쇠가 정상화되지 않는 부분을 제거하십시오. — 예를 들어, 어떤 규칙은`//`또는`../`URL 경로. Administrators 이전에는 제한된 URL 정상화를 수행하기 위해 이러한 규칙을 만들었습니다. 이 규칙은 이제 안전하게 비활성화하고 삭제 될 수 있습니다.

- 이 방화벽 규칙과 비정상화 된 URI 경로로 방문자를 식별하려면 원래 (또는 원시) 비정상화 된 필드를 사용하여 업데이트해야합니다. 이 필드는 다음과 같습니다:
  - `raw.http.request.uri.path`
  - `raw.http.request.full_uri`
  - `raw.http.request.uri`

### 2. Enable URL 정상화

영향을받는 방화벽 규칙을 업데이트하면 URL 정상화가 활성화됩니다.**이름 \*** > **제품정보** > **URL 정상화**.

Cloudflare 사용자는 있어야 합니다.[방화벽 역할](/fundamentals/manage-members/roles/)또는 '대시보드'의 URL 정상화 설정에 액세스하는 관리자 역할 중 하나입니다.

***
