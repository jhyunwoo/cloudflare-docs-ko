이 페이지는 유효한 관리된 Transforms를 목록으로 만듭니다. HTTP 요청 헤더 또는 응답 헤더를 수정할 수 있습니다.

## 중요한 말

- Managed Transform이 웹 사이트에 문제가 발생할 수 있습니다. 당신은 노후화 환경에서 어떤 변화를 테스트해야합니다. 만약 당신이 undesired 또는 예상치 못한 행동을 감지하면, 관리 된 변환을 해제하고 자신의 변형 규칙을 사용하여 부분 구현을 만듭니다.

- HTTP 헤더의 이름은 case-insensitive입니다. Cloudflare는 이 페이지에서 제시된 것과 다른 자본화를 사용할 수 있습니다. 원래 서버가 이름의 정확한 자본화에 관계없이 HTTP 요청 헤더를 처리 할 수 있는지 확인하십시오.

## HTTP 요청 헤더

### 자주 묻는 질문

HTTP 헤더를 입력하여 방문자의 IP 주소에 대한 위치 정보를 입력합니다.

- `cf-ipcity`: 방문자의 도시 (값에서[`ip.src.city`](/ruleset-engine/rules-language/fields/reference/ip.src.city/)분야).
- `cf-ipcountry`: 방문자의 국가 (값에서[`ip.src.country`](/ruleset-engine/rules-language/fields/reference/ip.src.country/)분야).
- `cf-ipcontinent`: 방문자의 대륙 (값에서[`ip.src.continent`](/ruleset-engine/rules-language/fields/reference/ip.src.continent/)분야).
- `cf-iplongitude`: 방문자의 경도 (값에서[`ip.src.lon`](/ruleset-engine/rules-language/fields/reference/ip.src.lon/)분야).
- `cf-iplatitude`: 방문자의 위도 (값에서[`ip.src.lat`](/ruleset-engine/rules-language/fields/reference/ip.src.lat/)분야).
- `cf-region`: 방문자의 지역 (값에서[`ip.src.region`](/ruleset-engine/rules-language/fields/reference/ip.src.region/)분야).
- `cf-region-code`: 방문자의 지역 코드 (값에서[`ip.src.region_code`](/ruleset-engine/rules-language/fields/reference/ip.src.region_code/)분야).
- `cf-metro-code`: 방문자의 지하철 코드 (값에서[`ip.src.metro_code`](/ruleset-engine/rules-language/fields/reference/ip.src.metro_code/)분야).
- `cf-postal-code`: 방문자의 우편 번호 (값에서[`ip.src.postal_code`](/ruleset-engine/rules-language/fields/reference/ip.src.postal_code/)분야).
- `cf-timezone`: 방문자의 시간대의 이름 (값에서[`ip.src.timezone.name`](/ruleset-engine/rules-language/fields/reference/ip.src.timezone.name/)분야).

:::참조
관련 기사[IP 위치](/network/ip-geolocation/)전송하기`cf-ipcountry`HTTP 헤더에서 소스 서버까지**자주 묻는 질문**설정한다.
주요 특징

#### non-ASCII 헤더 값의 인코딩

Cloudflare는 항상 HTTP 요청 및 응답 헤더 값에서 UTF-8에 비 ASCII 문자를 변환합니다. 이 위치 헤더에 적용**자주 묻는 질문**관리 변환.

### IP 헤더를 제거

HTTP 헤더를 제거하면 방문자의 IP 주소를 입력합니다. 다음 HTTP 요청 헤더를 처리:

- `cf-connecting-ip`
- `x-forwarded-for`(참고)[이름 \*](#visitor-ip-address-in-the-x-forwarded-for-http-header)아래)
- `true-client-ip`

이 Managed Transform은 사용할 수 없습니다.[**"True-Client-IP" 헤더 추가**](#add-true-client-ip-header)지원하다

#### 방문자 IP 주소`x-forwarded-for`HTTP 헤더

제품정보`x-forwarded-for`HTTP 요청 헤더, 활성화**IP 헤더를 제거**CloudflareXQ가 적어도 다른 CDN (content 납품 네트워크)에 의해 proxied 요청을받을 때 헤더 값에서 방문자 IP 만 제거됩니다. 이 경우, Cloudflare는 마지막 프록시의 IP 주소를 유지합니다.

예를 들어, 들어오는 요청은 두 개의 CDN (으)로 예상됩니다.`CDN_1`·`CDN_2`) Cloudflare 네트워크에 도달하기 전에. 더 보기`x-forwarded-for`헤더는 다음과 같습니다:<br />
`x-forwarded-for: <VISITOR_IP>, <THIRD_PARTY_CDN_1_IP>, <THIRD_PARTY_CDN_2_IP>`

이름 \***IP 헤더를 제거**지원하다`x-forwarded-for`헤더는 원래 서버로 전송됩니다:<br />
`x-forwarded-for: <THIRD_PARTY_CDN_2_IP>`

### 누출된 자격 검사를 추가

추가하기`Exposed-Credential-Check`WAFXQ는 들어오는 요구에 있는 새겨진 credentials를 검출합니다.

헤더는 이러한 값을 가질 수 있습니다:

| 헤더 + 값                        | 이름 \*                              | 적용분야      |
| ----------------------------- | ---------------------------------- | --------- |
| `Exposed-Credential-Check: 1` | 이전 누출된 사용자 및 암호 감지                 | Pro 플랜 이상 |
| `Exposed-Credential-Check: 2` | 이전 누출된 사용자의 검색                     | 기업 계획     |
| `Exposed-Credential-Check: 3` | 이전에 유출된 사용자 이름과 암호의 유사한 조합은 검출했습니다 | 기업 계획     |
| `Exposed-Credential-Check: 4` | 이전 누출된 암호 검출                       | 모든 계획     |

이 관리된 헤더를 다음과 같이 받게 됩니다:

- 더 보기[누출 검출](/waf/detections/leaked-credentials/)WAF는 켜집니다.
- 더 보기**유출된 Credentials 체크 Header 추가**관리된 변환은 켜집니다.
- Cloudflare 계획은 자격 증명 탐지의 유형을 지원합니다. 예를 들어, 무료 계획은 암호가 이전에 유출 된 경우만 알 수 있습니다. 이 상황에서 Cloudflare는 추가할 것입니다`Exposed-Credential-Check: 4`요청에 헤더.

### 악성행위 탐지 헤더 추가

추가하기`Malicious-Uploads-Detection`header가 악성코드에 업로드된 내용의 결과를 나타내는 것을 요청합니다.

헤더는 다음과 같은 값 중 하나를 가질 수 있습니다:

| 헤더 + 값                           | 이름 \*                                                                                                                                                                           |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Malicious-Uploads-Detection: 1` | 이 요청은 적어도 하나의 악의적인 내용 객체를 포함합니다 ([`cf.waf.content_scan.has_malicious_obj`](/ruleset-engine/rules-language/fields/reference/cf.waf.content_scan.has_malicious_obj/)이름 \*`true`). |
| `Malicious-Uploads-Detection: 2` | 파일 스캐너는 요청에서 감지 된 모든 콘텐츠 개체를 스캔 할 수 없습니다 ([`cf.waf.content_scan.has_failed`](/ruleset-engine/rules-language/fields/reference/cf.waf.content_scan.has_failed/)이름 \*`true`).      |
| `Malicious-Uploads-Detection: 3` | 요청은 적어도 하나의 내용 객체를 포함합니다 ([`cf.waf.content_scan.has_obj`](/ruleset-engine/rules-language/fields/reference/cf.waf.content_scan.has_obj/)이름 \*`true`).                            |

더 많은 정보를 원하시면, 참조[악성행위 탐지](/waf/detections/malicious-uploads/).

## HTTP 응답 헤더

### "X-Powered-By" 헤더 제거

제거하기`X-Powered-By`HTTP 응답 헤더는 요청을 처리하는 Origin 서버에서 응용 프로그램에 대한 정보를 제공합니다.

### 보안 헤더 추가

:::참조
다음 보안 헤더를 추가하면 리소스를 차단하거나 인증서 오류를 트리거와 같은 웹 사이트에 영향을 미칠 수 있습니다. 어떤 문제가 발견되면, 가능한 원인을 고립시키기 위해 관리 된 변형을 비활성화하십시오.
주요 특징

여러 보안 관련 HTTP 응답 헤더를 추가합니다. 추가 응답 헤더와 값은 다음과 같습니다.

- `x-content-type-options: nosniff`
- `x-xss-protection: 1; mode=block`
- `x-frame-options: SAMEORIGIN`
- `referrer-policy: same-origin`
- `expect-ct: max-age=86400, enforce`

보호 증가,[HTTP Strict Transport 보안 활성화 (HSTS)](/ssl/edge-certificates/additional-options/http-strict-transport-security/)웹 사이트.
