더 알아보기[규칙 예제 갤러리](/rules/transform/examples/?operation=Request+modification)규칙 정의의 예입니다.

규칙을 만들려면:

<Steps>
  1. Cloudflare 대시보드에서 규칙에 가십시오**제품정보**사이트 맵

     <DashButton url="/?to=/:account/:zone/rules/overview" />

  2. 제품정보**규칙 만들기** > **Header Transform 규칙 요청**.

  3. (선택 사항) 일반적인 사용 사례를 해결하는 규칙 템플릿 중 하나를 선택하십시오. 그런 다음, 검토 및 제안 된 규칙 구성을 조정합니다.

  4. 규칙에 대한 설명 이름 입력**규칙 이름**.

  5. 이름 \***수신 요청 일치**, 당신이 모든 들어오는 요청에 규칙을 적용하려는 경우 선택 또는 사용자 정의 필터 표현과 일치하는 요청 만.

  6. (선택) 사용자 정의 표현을 정의하려면 Expression Builder를 사용 (하나 이상의 값을 지정)**제품정보**, **회사연혁**·**제품정보**) 또는 수동으로 Expression Editor를 사용하여 표현을 입력합니다. 더 많은 정보를 원하시면, 참조[대시보드](/ruleset-engine/rules-language/expressions/edit-expressions/).

     :::참조
     자주 묻는 질문[유효한 분야 및 기능](/rules/transform/request-header-modification/reference/fields-functions/).
     :::

  7. 제품 정보**요청 헤더를 수정**, 다음 옵션 중 하나를 선택:
     - *설정 static*— HTTP 요청 헤더의 값을 정적 문자열 값으로 설정합니다. 같은 이름과 기존 헤더의 값을 덮거나 존재하지 않는 경우 새로운 헤더를 추가합니다.
     - *동적 설정*- 제공된 표현에 따라 HTTP 요청 헤더의 값을 설정합니다. 같은 이름과 기존 헤더의 값을 덮거나 존재하지 않는 경우 새로운 헤더를 추가합니다.
     - *기타 제품*- 제공된 이름과 HTTP 요청 헤더 제거, 그것이 존재하는 경우.

  8. HTTP 요청 헤더의 이름을 입력하여 수정**헤더 이름**정적 값이나 표현**제품정보**, 당신이 헤더 값을 설정하는 경우.

  9. 동일한 규칙에 다른 HTTP 요청 헤더를 수정하려면, 선택**새 헤더 설정**. 단일 규칙에서 최대 30 HTTP 요청 헤더를 수정할 수 있습니다.

     다음 예제에는 세 개의 헤더의 수정이 포함됩니다.

     ![세 가지 요청 헤더 수정을 수행하는 예 구성 : 동적 헤더 값을 설정하고 정적 헤더 값을 설정하고 기존 헤더를 제거하십시오.](~/assets/images/rules/transform/request-header-modification-example.png)

  10. 규칙을 저장하고 배포하려면, 선택**계정 만들기**. 규칙을 배포 할 준비가 없다면, 선택**Draft로 저장**.

      <Render file="rules-creation-dash-dns-popup" product="rules" />
</Steps>
