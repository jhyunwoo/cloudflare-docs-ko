정적 및 동적 URL 리깅에는 다른 매개 변수가 있습니다.

- 정적 URL rewrite는 대상 URL의 정적값을 요구합니다.
- 동적 URL rewrite는, 평가할 때, 대상 URL을 정의한다.

와일드 카드 패턴과 URL 리깅은 Cloudflare 대시보드에서 간단한 인터페이스로 동적 URL 리깅을 만들기 위해[wildcard 일치 및 교체](#wildcard-matching-and-replacement).

URL rewrite (combined)의 모든 매개 변수 값의 최대 길이는 4,096 문자입니다. 예를 들어, 2,048 문자와 URI 경로에 대한 정적 값 (또는 표현)을 제공 할 수 있으며 쿼리 문자열에 대한 정적 값 (또는 표현)을 2,048 문자.

## API 정보

### 정적 URL rewrites

전체 구문`action_parameters`URI 경로와 쿼리 문자열을 모두 다시 작성하는 정적 URL 리깅 규칙 필드는 다음과 같습니다.

```json
"action_parameters": {
  "uri": {
    "path": {
      "value": "<URI_PATH_VALUE>"
    },
    "query": {
      "value": "<QUERY_STRING_VALUE>"
    }
  }
}
```

URI 경로 또는 쿼리 문자열을 rewriting만 있다면, omit`query`또는`path`모수, 각각.

### 동적 URL rewrite

전체 구문`action_parameters`URI 경로와 쿼리 문자열을 모두 다시 작성하는 동적 URL 리깅 규칙 필드는 다음과 같습니다.

```json
"action_parameters": {
  "uri": {
    "path": {
      "expression": "<URI_PATH_EXPRESSION>"
    },
    "query": {
      "expression": "<QUERY_STRING_EXPRESSION>"
    }
  }
}
```

URI 경로 또는 쿼리 문자열을 rewriting만 있다면, omit`query`또는`path`모수, 각각.

#### Wildcard 매칭 및 교체

동적 URL 리깅 규칙의 구문은 URI 경로와 와일드 카드 매칭 및 교체에 따라 쿼리 문자열을 두는 규칙을 다음과 같습니다.

```json
{
	"expression": "(http.request.full_uri wildcard r\"<REQUEST_URL>\")",
	"action_parameters": {
		"uri": {
			"path": {
				"expression": "wildcard_replace(http.request.uri.path, r\"<PATH_TARGET_PATH>\", r\"<PATH_REWRITE_TO>\")"
			},
			"query": {
				"expression": "wildcard_replace(http.request.uri.query, r\"<QUERY_TARGET_QUERY>\", r\"<QUERY_REWRITE_TO>\")"
			}
		}
	},
	"action": "rewrite"
	// ...
}
```

더 보기`<REQUEST_URL>`, `<PATH_TARGET_PATH>`, `<PATH_REWRITE_TO>`, `<QUERY_TARGET_QUERY>`·`<QUERY_REWRITE_TO>`Value placeholders는 Cloudflare 대시보드XQ에서 사용할 수있는 필드에 해당합니다.**Wildcard 패턴**옵션. 더 많은 정보를 원하시면, 참조[Wildcard 패턴 매개 변수](/rules/transform/url-rewrite/create-dashboard/#wildcard-pattern-parameters).

:::참조
더 보기`http.request.uri.query`필드는 포함되지 않습니다.`?`처음부터 delimiter, 즉,`<QUERY_TARGET_QUERY>`값은 초기에 일치하려고하지 않아야합니다.`?`.
:::

### 다른 URL은 동일한 규칙에서 유형을 다시 씁니다

동일한 규칙은 URI 경로와 쿼리 문자열에 대한 URL rewrites의 다른 유형이 있을 수 있습니다. 예를 들어, 단일 규칙은 수행 할 수 있습니다**뚱 베어**URL URI 경로와 a를 다시 쓰기**제품 정보**쿼리 문자열을 다시 작성합니다. 그러한 규칙의 구문은 다음과 같습니다.

```json
"action_parameters": {
  "uri": {
    "path": {
      "expression": "<URI_PATH_EXPRESSION>"
    },
    "query": {
      "value": "<QUERY_STRING_VALUE>"
    }
  }
}
```
