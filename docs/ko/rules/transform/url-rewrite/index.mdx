다른 작업을 통해 요청의 URL을 조작 할 수 있습니다, 즉, 다시 쓰기 및 리디렉션 :

- **URL 재 작성**: 소스 URL을 타겟 URL로 변환하는 서버 측 작동. 웹 서버가 완전히 요청을 처리하기 전에 발생합니다. 웹 사이트 방문자가 볼 수 없습니다. 브라우저에 표시된 URL이 변경되지 않습니다. URL Rewrite 규칙을 구성하여 웹 서버에 도달하지 않고 Cloudflare 글로벌 네트워크에 재쓰기합니다.

- **URL 리디렉션**: 대상 URL로 소스 URL을 변환하는 클라이언트 측 작동. 웹 서버가 초기 URL을로드 한 후 발생합니다. 이 경우 웹 사이트 방문자는 리디렉션이 발생할 때 URL을 변경할 수 있습니다. 더 알아보기[회사 소개](/rules/url-forwarding/)configuring redirects에 대해 자세히 알아보세요.

URL rewrite 규칙을 사용하여 브라우저의 다른 URL을 표시하면서 URL의 내용을 반환합니다. URI 경로, 쿼리 문자열 또는 둘 다를 다시 작성할 수 있습니다.

:::카트로션

URL rewrite 규칙을 사용하여 hostname을 다시 작성할 수 없습니다. hostname을 다시 작성하려면[이름 \*](/rules/origin-rules/features/#dns-record).

## 정적 및 동적 리깅

URL Rewrite 규칙은 정적 또는 동적 리깅을 수행 할 수 있습니다 :

- **정체되는 rewrite**: 정적 문자열을 사용하여 요청 URL (path 또는 쿼리 문자열)의 주어진 부분을 대체합니다.
- **동적 rewrite**: 결과 경로 또는 쿼리 문자열을 정의하기 위해 다시 쓰기 표현을 사용하는 고급 시나리오를 지원합니다.

URL Rewrite 규칙 만들기[대시보드](/rules/transform/url-rewrite/create-dashboard/), [Cloudflare API를 통해](/rules/transform/url-rewrite/create-api/), 또는[Terraform 사용](/terraform/additional-configurations/transform-rules/#create-a-url-rewrite-rule).

## 사용자 정의 경로의 Serve 이미지

Cloudflare를 사용하는 경우 이미지, URL Rewrite 규칙을 사용하여 사용자 정의 경로에서 이미지를 제공 할 수 있습니다. 더 많은 정보를 원하시면, 참조[사용자 정의 영역에서 이미지](/images/manage-images/serve-images/serve-from-custom-domains/).

## 중요한 말

- URL rewrite 규칙은 순서에서 실행되고, 나중에 규칙은 이전 규칙에 의해 행해질 수 있습니다.

- 요청 및 응답 필드의 값은 각 영역 내에서 immutable 입니다.[단계별](/ruleset-engine/about/phases/), 등`http_request_transform`URL rewrite 규칙을 정의하는 단계. 이것은 나중에 URL을 다시 작성 규칙이 이전 URL에 의해 수행 된 변경에 따라 일치하지 않는다는 것을 의미한다 규칙. 더 알아보기[규칙 평가 중 필드 값](/ruleset-engine/about/rules/#field-values-during-rule-evaluation)더 많은 정보.
