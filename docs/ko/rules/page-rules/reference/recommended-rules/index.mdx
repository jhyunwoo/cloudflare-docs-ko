Cloudflare 페이지 규칙은 보안 및 향상된 사이트 성능으로 도메인의 사용자 경험을 향상시키기 위해 소스 서버의 신뢰성과 최소화 대역폭 사용량을 늘리고 있습니다.

<Render file="page-rules-migration" product="rules" />

모든 규칙이 모든 사람에게 맞지 않을 것을 염두에 두지 마십시오. 그러나 이것은 대중의 일부입니다.

- 301/302 전송 URL
- 특정 경로의 캐시 수준
- Edge Cache TTL, 항상 온라인 및 브라우저 캐시 TTL

### 301/302 전송 URL

:::참조
자주 묻는 질문[단일 Redirects](/rules/url-forwarding/single-redirects/)또는[대량 Redirects](/rules/url-forwarding/bulk-redirects/)사용, 유지 보수 및 비용의 용이로 인해 다른 URL로 트래픽을 전달하거나 리디렉션합니다. Dynamic 또는 Bulk Redirects가 사용 사례를 충족하지 않으면 페이지 규칙만 사용해야합니다.
주요 특징

전달 URL을 사용하는 두 가지 일반적인 예는 다음과 같습니다.

- 당신의 도메인의 canonical 버전으로 루트 정의.
- URL을 기억하기 쉬운 특정 페이지로 이동합니다.

이 예제 페이지 규칙 구성은 도메인의 운수 버전으로 루트를 정의합니다.

<Example>
  - **URL이 일치하면**: `*www.example.com/*`
  - **설치하기**: *전송 URL* | **상태 코드 선택**: *301 영구 Redirect*
  - **대상 URL을 입력**: `https://example.com/$2`
</Example>

이 예제는 URL을 기억하기 쉬운 특정 페이지로 방문자를 리디렉션 :

<Example>
  - **URL이 일치하면**: `*www.example.com/fb*`
  - **설치하기**: *전송 URL* | **상태 코드 선택**: *302 임시 간접*
  - **대상 URL을 입력**: `https://www.facebook.com/username`
</Example>

### 특정 경로의 캐시 수준

웹 사이트의 특정 섹션은 로그인 또는 관리자 섹션과 같은 다른 보안 및 성능 요구 사항이 있습니다. 일반적인 공개 호스팅 페이지보다.

다음 예제 페이지 규칙 구성은 특정 경로를 대상으로 요청 시 캐시를 우회합니다.

<Example>
  - **URL이 일치하면**: `example.com/user*`
  - **설치하기**: *캐시 레벨* | **제품정보**: *비밀번호*
</Example>

### 가장자리 캐시 TTL 및 브라우저 캐시 TTL

도메인의 특정 리소스는 종종 변경되지 않습니다. 이러한 리소스를 위해 공격적인 캐싱 옵션을 활용하면 서버 및 대역폭 활용에 부하를 크게 줄일 수 있습니다.

#### 이름 \*

다음 예에서 페이지 규칙 구성, 대상은 이미지 자산의 대부분을 보유하는 폴더뿐만 아니라 멀티미디어의 다른 유형입니다.

<Example>
  - **URL이 일치하면**: `example.com/sites/default/files*`
  - **설치하기**: *브라우저 캐시 TTL* | **제품정보**: *당일*
  - **설치하기**: *캐시 레벨 |* **제품정보**: *캐시 모든 것*
  - **설치하기**: *가장자리 캐시 TTL |* **제품정보**: *7 일*
</Example>

다음 예제 페이지 규칙 구성은 매우 자주 변경하지 않는 중요한 페이지에 대한 독특한 규칙을 적용합니다.

<Example>
  - **URL이 일치하면**: `example.com/terms-of-service`
  - **설치하기**: *브라우저 캐시 TTL* | **제품정보**: *당일*
  - **설치하기**: *항상 온라인 |* **제품정보**: *이름 \**
  - **설치하기**: *캐시 레벨* | **제품정보**: *캐시 모든 것*
  - **설치하기**: *가장자리 캐시 TTL* | **제품정보**: *1 개월*
</Example>
