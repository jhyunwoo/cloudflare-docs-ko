## 쿠키 설정에서 우회 Cache

이 조정은 사업과 기업 고객에게 유효합니다.

더 보기**Bypass 캐시 에 Cookie**설정은 다음과 같이 기본 정규식 (regex)을 지원합니다.

- 파이프 연산자 (represented by`|`) 여러 쿠키를 사용하여 일치*이름 \**&#x62;oolean 논리. 예를 들어,`bypass=.*|PHPSESSID=.*`쿠키가 호출되면 캐시를 우회합니다.`bypass`또는`PHPSESSID`쿠키의 값에 관계없이 설정되었습니다.
- 와일드 카드 연산자 (represented by`.*`), 그러한 규칙 값의`t.*st=`라는 두 개의 쿠키와 일치합니다.`test`그리고 하나 호출`teeest`.

제한은 다음과 같습니다:

- 쿠키 regex 당 150자
- 쿠키 regex 당 12 와일드 카드
- 각 1개의 와일드카드`|`쿠키 regex에서

설정 방법 알아보기**Bypass 캐시 에 Cookie**캐시 규칙으로, 참조[Bypass 캐시 에 Cookie](/cache/how-to/cache-rules/examples/bypass-cache-on-cookie/).

:::참조

이 설정과 기업 전용을 모두 추가하면*쿠키 정책*동일한 페이지 규칙에 설정,*쿠키 정책*계속*Bypass 캐시 에 Cookie*.

:::

## 지역명은 슬래시로 끝나야 합니다.

페이지 규칙을 저장할 때, Cloudflare는 현재 영역 이름의 각 발생 후에 슬래시가 있다는 것을 보증할 것입니다**URL이 일치하면**이름 \* 예를 들어, 현재 영역 이름이 있는 경우`example.com`, 다음:

- `example.com`저장될 것입니다`example.com/`
- `example.com/path/example.com`저장될 것입니다`example.com/path/example.com/`

주의사항`example.com/some-path/cloudflare.com`저장될 것입니다*없음*마지막 슬래시, 영역 이름 이후는 아니다`cloudflare.com`.

## 페이지 규칙에 의해 지원되는 네트워크 포트

포트를 지정하면**URL이 일치하면**페이지 규칙의 필드, 그것은 다음 중 하나이어야한다 :

- HTTP/HTTPS 포트 중 하나[Cloudflare의 프록시와 호환](/fundamentals/reference/network-ports/#network-ports-compatible-with-cloudflares-proxy).
- 사용자 정의 포트[Cloudflare 스펙트럼](/spectrum/)HTTPS 신청.

## WorkersXQ로 페이지 규칙 사용하기

현재 요청의 URL이 페이지 규칙과 일치하면[Workers 주문 노선](/workers/configuration/routing/routes/), 몇몇 Pages 규칙 설정은 적용되지 않습니다. 더 자세한 내용은 참조[페이지 규칙](/workers/configuration/workers-with-page-rules/).

## 페이지 규칙은 case-insensitive입니다

아래 입력된 패턴**URL이 일치하면**위와 더 낮은 케이스 차이를 고려하지 않을 것 —`example.com/path`, `example.com/Path`·`example.com/PATH`같은 방법을 트리거 할 것입니다.

케이스 감도를 고려해야 할 규칙이 있으면 대안을 사용할 수 있습니다.[이름 \*](/rules/)대신 옵션.
