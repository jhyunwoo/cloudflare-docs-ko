## 왜 페이지 규칙은 작동하지?

페이지 규칙이 작동하지 않는 가장 일반적인 이유 - URL 전달과 같은 - 당신이 만든 페이지 규칙은 Cloudflare에 의해 발음되지 않는 기록에 있다는 것입니다[DNS 설정](/dns/manage-dns-records/how-to/create-dns-records/).

하위 도메인을 리디렉션하는 페이지 규칙이있는 예를 고려하십시오 (`subdomain.yoursitename.com`) 당신의 apex 도메인으로 돌아 가기 (`yoursitename.com`). 하위 도메인 레코드의 DNS 설정에서 proxied를 기록하지 않은 경우, Cloudflare의 프록시는 레코드를 실행하지 않으며 페이지 규칙은 서버로 직접 이동하기 때문에 작동하지 않습니다.

## 오류 500 (내부 서버 오류)

### 뿌리 원인

페이지 규칙에 구성 문제로 인해 발생할 수 있습니다. 두 개의 와일드 카드를 사용하는 페이지 규칙을 만들 때, 같은*전송 URL*규칙, 두 번째 와일드 카드를 언급하는 규칙을 만들 수 있습니다`$2`회사연혁 아래 예제 참조 :

![예제 페이지 규칙 구성 두 와일드 카드. 전달 URL은 두 번째로 일치하는 콘텐츠로 대체되는 $2 placeholder를 포함합니다.](~/assets/images/support/page-rule-create.png)

동일한 규칙을 업데이트하면 와일드 카드 중 하나를 제거 할 수 있습니다.**URL이 일치하면**필드를 저장합니다. 아래 예제 참조 :

![단일 와일드 카드가있는 잘못된 페이지 규칙 구성, 그러나 여전히 운송 URL에 $ 2 위 홀더를 사용합니다. 이 설정은](~/assets/images/support/page-rule-update.png)

그렇다면,`$2`placeholder 참고 자료 더 이상 존재하지 않는 와일드 카드, 그리고 같은,`Error 500 (Internal server error)`URL이 페이지 규칙을 트리거 할 때 던져집니다.

### 제품 설명

페이지 규칙을 업데이트하고 참고 자료`$2`두 번째 와일드 카드에. 하나의 와일드 카드가 있다면, 당신은 단지 사용할 수 있습니다`$1`.
