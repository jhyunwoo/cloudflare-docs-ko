## 시작하기 전에

몇 페이지 규칙의 행동을 이해하는 것이 중요합니다.

### 페이지 규칙은 DNS 레코드를 요구합니다

페이지 규칙은[뚱 베어](/dns/proxy-status/)귀하의 페이지 규칙에 대한 DNS 기록. 페이지 규칙은 DNS에 존재하지 않는 호스트 이름에 적용되지 않거나 CloudflareXQ로 지시되지 않습니다.

레코드 유형에 따라 대상에 다른 값을 사용할 수 있습니다. 이 중 하나가 동일한 결과를 달성하고 당신은 단지 하나를 만들 필요가:

```
www.example.com  A      192.0.2.1
www.example.com  AAAA   2001:DB8::1
www.example.com  CNAME  domain.example
```

Cloudflare는 IP 주소 또는 도메인 이름을 사용하여 외국 인프라로 트래픽을 전송하는 것이 좋습니다.

예약된 IP 주소 또는 최상위 도메인에 대한 자세한 내용은 다음 RFC를 참조하시기 바랍니다:

- [RFC 5737년](https://datatracker.ietf.org/doc/html/rfc5737)
- [RFC 3849년](https://datatracker.ietf.org/doc/html/rfc3849)
- [RFC 2606년](https://datatracker.ietf.org/doc/html/rfc2606)

### 우선순위 사정

가장 높은 우선 순위 일치 페이지 규칙은 요청에 영향을줍니다.

페이지 규칙은 Cloudflare 대시보드에서 가장 높은 우선권 규칙과 더불어 CloudflareXQXQ의 후손 순서로 전진됩니다. 이 이유를 들어, Cloudflare는 대부분의 특정에서 가장 특정한 규칙을 주문하는 것이 좋습니다.

페이지 규칙은 다음과 같은 형식을 기반으로 URL 패턴 일치 (5 세그먼트의 약속) :

```txt
<SCHEME>://<HOSTNAME>:<PORT>/<PATH>?<QUERY_STRING>
```

모든 세그먼트와 예 URL은 다음과 같습니다.

```txt
https://www.example.com:443/image.png?parameter1=value1
```

더 보기`<SCHEME>`·`<PORT>`세그먼트는 선택적입니다. omitted 경우,`<SCHEME>`모두 일치`http://`·`https://`프로토콜. 없음`<PORT>`지정된 규칙은 모든 포트와 일치합니다.

### Disabled 페이지 규칙

페이지 규칙이 비활성화되면 행동이 트리거되지 않습니다. 그러나 규칙은 다음과 같습니다.

- 아직도 Cloudflare 대시보드XQ에 나타납니다.
- 편집 할 수 있습니다.
- 도메인에 허용된 규칙의 수에 대한 조사.
