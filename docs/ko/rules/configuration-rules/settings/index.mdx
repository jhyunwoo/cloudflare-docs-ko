## 자동 HTTPS 리깅

[자동 HTTPS 리깅](/ssl/edge-certificates/additional-options/automatic-https-rewrites/)최종 사용자를보고 방지`Mixed content`URL을 rewriting에 의한 오류`http`으로`https`HTTPS로 제공 할 수있는 웹 사이트에서 리소스 또는 링크.

이 설정을 사용하여 일치 요청에 대한 자동 HTTPS 리깅을 켜거나 해제합니다.

<Details header="API 정보">
  API 구성 속성 이름:`"automatic_https_rewrites"`(불린).

  ```json title="API configuration example"
  "action_parameters": {
    "automatic_https_rewrites": true
  }
  ```

</Details>

## 바디 버퍼링

요청 바디 버퍼링 설정을 사용하여 일치하는 요청에 대한 요청 바디 버퍼링 모드를 구성합니다.

- **제품 정보**(과태): Cloudflare 제품을 허용하여 귀하의 영역에서 활성화된 기능을 위해 필요한 경우 요청 몸의 접두사를 검사합니다.
- **한국어**: 당신의 근원 서버에 요청을 보내기 전에 전체 요청 몸을 버퍼.
- **이름 \***: 엄밀하게 버퍼링 없음. 요청 몸은 검사없이 원래 서버로 직접 흐릅니다.

이 조정은 Cloudflare's를 달리는 지역에 단지 효력을 가지고 갑니다[최신 CDN 프록시](https://blog.cloudflare.com/20-percent-internet-upgrade/). 기업 고객은 그들의 지역에 최신 프록시를 가능하게 하는 그들의 계정 팀을 접촉할 수 있습니다.

:::카트로션
요청 체 버퍼링 설정**이름 \***&#xC2E0;체 검사가 필요한 기능을 깰 수 있습니다. 특히 Web Application Firewall (WAF) 및 기타 보안 기능의 효과에 영향을 줄 수 있습니다.
주요 특징

<Details header="API 정보">
  API 구성 속성 이름:`"request_body_buffering"`(문자).

  API 값:`"standard"`, `"full"`, `"none"`.

  ```json title="API configuration example"
  "action_parameters": {
    "request_body_buffering": "full"
  }
  ```

  <Render file="configuration-rule-link-to-examples" product="rules" />
</Details>
