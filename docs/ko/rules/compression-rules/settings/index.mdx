압축 규칙은 뒤에 오는 단면도에서 커버된 윤곽 조정을 지원합니다.

## Dashboard 설정

### Enable Zstandard (Zstd) 압축<Badge text="Beta" variant="caution" size="small" />

Zstandard를 선호하는 압축 알고리즘으로 설정합니다. 지원되지 않은 경우, 자동으로 Brotli, Gzip 또는 uncompressed 데이터로 돌아갑니다.

### Enable Brotli와 Gzip 압축

Cloudflare의 기본 압축 설정 활성화. Brotli는 선호하는 압축 알고리즘입니다. 그것은 자동으로 Gzip 또는 압축 된 데이터로 돌아갑니다.

### 압축 해제

일치하는 요청에 대한 압축 해제. 또한 Cloudflare의 비활성화[기본 압축 동작](/speed/optimization/content/compression/).

### 제품 정보

압축 알고리즘에 대한 사용자 정의 주문.

허용된 값은 다음과 같습니다:

- **사이트맵**: 웹 사이트 방문자가 지원하는 경우 Gzip 압축 알고리즘을 사용합니다.
- **뚱 베어**: 웹 사이트 방문자가 지원하는 경우 Brotli 압축 알고리즘을 사용합니다.
- **사이트맵**: Zstandard (Zstd) 압축 알고리즘을 사용하여 웹 사이트 방문자에 의해 지원되는 경우.
- **자동차**: 웹 사이트 방문자가 지원하는 알고리즘에 따라 응답을 압축합니다. Cloudflare는 앞으로 변화할지도 모르다 압축 알고리즘을 위한 p참고 자료의 순서를 정의할 것입니다. 같은 행동이 있습니다.**Enable 압축**옵션.
- **기본 정보**: Cloudflare의 사용[기본 압축 동작](/speed/optimization/content/compression/)응답 내용 유형에 달려 있는 ,.

만 지정하면*사이트맵*, *뚱 베어*, 또는*사이트맵*그리고 알고리즘 일치는 없다, 응답은 압축이 없다. fallback 압축 메커니즘을 구성하려면 추가*자동차*이름 \*

:::참조
압축 적용*기본 정보*옵션은 수신 요청과 일치하는 구성 된 압축 규칙을 고려해야합니다.

## API 설정 설정

지원되는 구성 객체`compress_response`동작에는 다음과 같은 형식이 있습니다:

```json
"action_parameters": {
  "algorithms": [
    { "name": "<VALUE1>" },
    { "name": "<VALUE2>" },
    // ...
  ]
}
```

더 보기`algorithms`목록은 적어도 1개의 품목을 포함해야 합니다.

지원되는 알고리즘 값은:

- `gzip`: 웹 사이트 방문자가 지원하는 경우 Gzip 압축 알고리즘을 사용합니다.
- `brotli`: 웹 사이트 방문자가 지원하는 경우 Brotli 압축 알고리즘을 사용합니다.
- `zstd`: Zstandard 압축 알고리즘을 사용하여 웹 사이트 방문자에 의해 지원되는 경우.
- `none`: 압축 알고리즘을 사용하지 마십시오.
- `auto`: 웹 사이트 방문자가 지원하는 알고리즘에 따라 응답을 압축합니다. Cloudflare는 앞으로 변화할지도 모르다 압축 알고리즘을 위한 p참고 자료의 순서를 정의할 것입니다.
- `default`: Cloudflare의 사용[기본 압축 동작](/speed/optimization/content/compression/#compression-between-cloudflare-and-website-visitors)응답 내용 유형에 달려 있는 ,.

당신이 포함 하는 경우`none`, `default`, 또는`auto`목록에서, 그것은 목록에서 마지막 값이어야한다.

지정할 때`gzip`, `brotli`, 또는`zstd`알고리즘, 알고리즘이 일치하지 않으면 응답은 압축이 없습니다. fallback 압축 메커니즘을 구성하려면 추가`auto`이름 \*

API 예제의 경우, 참조[본문 바로가기](/rules/compression-rules/examples/).
