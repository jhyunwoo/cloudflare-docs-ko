다음 섹션은 Origin 규칙에서 사용할 수있는 설정을 설명합니다.

## 호스트 헤더

HTTP를 다시 작성할 수 있습니다.`Host`수신 요청 헤더.

이 기능에 대한 일반적인 사용 사례는 콘텐츠가 타사 서버에서 호스팅 될 때만 허용됩니다.`Host`자신의 서버 이름을 가진 헤더. 이 상황에서, 당신은 업데이트해야합니다`Host`HTTP 헤더 수신 요청`Host: example.com`으로`Host: thirdpartyserver.example.net`.

:::주\[주]

- 대부분의 상황에서 HTTP를 재 작성할 때`Host`header 당신은 또한 구성해야[DNS 레코드 override](#dns-record)·`Host`헤더 오버라이드는 헤더 값을 업데이트합니다. DNS 레코드 오버라이드는 요청의 리락을 처리합니다.

- 기본 규칙`Host`헤더 오버라이드는 Server Name Indication (SNI) 값을 동일한 값으로 업데이트합니다. SNI 값을 다른 설정하려면`Host`헤더 값, 추가[SNI 오버라이드](#server-name-indication-sni)동일한 근원 규칙에서 또는 이 목적을 위한 분리되는 근원 규칙을 창조하십시오.

- CloudflareXQ를 통해 균형 잡힌 부하를 설정하면 HTTP를 override 할 수 있습니다.`Host`원산지 또는 주어진 모니터에 대한 헤더, 참조[HTTP 보안 호스트 헤더](/load-balancing/additional-options/override-http-host-headers/)Load Balancing 문서에서 더 많은 정보를 제공합니다.

- 근원 규칙이 override에 형성될 때`Host`핸들링 요청 헤더[작업자](/workers/), 이 override는 evaluating 때 계정으로 가지고 있지 않습니다[Workers 노선](/workers/configuration/routing/routes/).

:::

## 서버 이름 표시 (SNI)

서버 이름 표시 (SNI)를 override 할 수 있습니다.[^1]요청 값. 더 많은 정보를 원하시면, 참조[SNI (서버 이름 표시)는 무엇입니까?](https://www.cloudflare.com/learning/ssl/what-is-sni/)학습 센터에서.

:::주\[주]

- 새로운 SNI 값은 동일한 Cloudflare 계정에서 유효한 호스트 이름이어야 합니다 (다른 영역에서 가능).
- 현재 SNI를 overriding 할 때 정적 값을 사용할 수 있습니다.
- SNI override는 전진합니다[SNI는 주문 근원의 재쓰기](/cloudflare-for-platforms/cloudflare-for-saas/start/advanced-settings/custom-origin/#sni-rewrites)SaaS를 위한 Cloudflare를 사용할 때.

:::

[^1]: SNI는 서버가 단일 IP 주소를 사용하여 여러 웹 사이트에 여러 TLS 인증서를 호스팅 할 수 있습니다. SNI는 TLS Handhake의 웹 사이트 hostname을 추가하여 공유 IP를 사용할 때 웹 사이트가 존재하는 서버에 알려줍니다.

## DNS 기록

수신 요청의 해결된 호스트명을 무시할 수 있습니다. 이 기능은 또한 override를 해결로 알려져 있습니다.

일반적인 사용 사례는 URI에서 응용 프로그램을 제공 할 때 (예를 들어,`mydomain.com/app`). 이 경우,`app`다른 서버 또는 제3자에 의해 호스팅 될 수 있습니다. DNS 레코드 오버라이드는 이 엔드포인트를 제3자 애플리케이션의 서버로 리디렉션할 수 있습니다.

:::참조

- 동일한 CloudflareXQ 계정에 호스트명인 DNS 레코드 오버라이드에서 유효한 호스트명을 지정해야 합니다. (다른 영역에서 가능). 당신은 할 수[DNS 레코드 구성](/dns/manage-dns-records/how-to/create-dns-records#create-dns-records)(아)`CNAME`, `A`, 또는`AAAA`레코드)는 Cloudflare 또는 아닙니다.

- 대부분의 상황에서 DNS 레코드를 구성 할 때도 구성해야합니다.[`Host`머리 오버라이드](#host-header). DNS 기록 override는 요청의 rerouting를 취급합니다;`Host`header override 업데이트`Host`HTTP 헤더 값 요청. 정의하기`Host`헤더 오버라이드는 Server Name Indication (SNI) 값을 동일한 값으로 업데이트합니다. SNI 값을 다른 설정하려면`Host`헤더 값, 추가[SNI 오버라이드](#server-name-indication-sni)동일한 근원 규칙에서 또는 이 목적을 위한 분리되는 근원 규칙을 창조하십시오.

:::

## 항만 항구

요청의 대상 포트를 무시할 수 있습니다.

포트 오버라이드를 구성할 때 다른 포트에 들어오는 요청을 리디렉션할 수 있습니다. 예를 들어, 요청에 대한 목적지 포트를 override 할 수 있습니다.`mydomain.com`포트 9000 (포트 9000)에서 실행되는 응용 프로그램에 의해 제공됩니다.`mydomain.com:9000`).

대상 항구는 1과 65,535 사이이어야 합니다.
