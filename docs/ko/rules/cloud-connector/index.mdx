클라우드 커넥터<ProductAvailabilityText product="cloud-connector" />웹 사이트에서 들어오는 트래픽을 정의 할 수 있습니다.[CloudflareR2](/r2/)AWS, Google Cloud 및 Azure와 같은 객체 저장 또는 외부 공급자. Cloud Connector를 사용하면 CloudflareXQ를 웹 트래픽의 제어 센터를 만들 수 있으며, 추가 규칙을 구성하지 않고 공공 클라우드 제공 업체에서 트래픽을 포함.

## 어떻게 작동합니까?

먼저 Cloud Connector 규칙을 구성합니다.

- 클라우드 공급자 및 지원되는 클라우드 서비스는 트래픽을 수락합니다.
- 그 클라우드 서비스로 가는 교통.

그런 다음 Cloudflare는 만들 것입니다[필요한 구성](#applied-configurations)그래서 콘텐츠는 클라우드 커넥터 규칙과 일치하는 요청에 액세스 할 수 있습니다. 당신의 물체 저장 물통은 구름 연결관을 위해 작동해야 합니다.

Cloud Connector 규칙은 요청 평가 워크플로에서 마지막으로 평가됩니다. 규칙 일치가있을 때 다른 규칙이 동일한 설정을 변경할 때, 클라우드 커넥터 규칙은 다른 규칙에 승리합니다.

## 적용 구성

Cloud Connector는 클라우드 공급자에 따라 다음과 같은 구성을 자동으로 수행합니다.

- 수정하기`Host`헤더.
- 물통 관련 교통을 위한 SSL/TLS를 조정하십시오 ([AWS S3 웹 사이트 엔드포인트](/rules/cloud-connector/providers/#ssl-connections-to-aws-s3-endpoints)만).

:::note\[추가 구성요소]

Cloud Connector는 다음 구성을 적용하지 않습니다.

- **Cache 콘텐츠는 storage Bucket에서 제공**: 사용자 정의 캐시 동작을 정의하기 위해 - 반환 객체와 같은 경우[긴 시간](/cache/how-to/cache-rules/settings/#edge-ttl)— 당신은 만들 필요가[캐시 규칙](/cache/how-to/cache-rules/). 예를 들면 규칙 윤곽을 위해, 참고하십시오[캐시 레벨 (Cache Everything)](/cache/how-to/cache-rules/examples/cache-everything/).

- **URL을 다시 작성**: 웹 사이트 방문자가 리소스를 얻고 저장 물통에서 사용되는 폴더 구조가 무엇인지에서 URL 구조를 조정하기 위해, 당신은 만들 필요가있다[URL 재 작성](/rules/transform/url-rewrite/). 예를 들어 URL을 다시 작성하여 제거 할 수 있습니다.`/files`URI 경로의 접두사 요청을 객체 저장 물통에 올리기 전에. 예를 들어, 참조[물체 저장 물통을 위한 경로를 씁니다](/rules/transform/examples/rewrite-path-object-storage/).

:::
