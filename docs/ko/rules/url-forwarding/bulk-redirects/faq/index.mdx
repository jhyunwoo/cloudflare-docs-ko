아래에서 Bulk Redirects에 대한 가장 일반적으로 묻는 질문에 대한 답변을 찾을 수 있습니다.

대량 Redirects와 관련된 오류를 해결하려면:

- 더 알아보기[문제 해결 Cloudflare 10XXX 오류](/support/troubleshooting/http-status-codes/cloudflare-10xxx-errors/)런타임 오류에 대한 자세한 내용은.
- 제품 정보[Cloudflare 추적](/rules/trace-request/)규칙이 특정 URL을 트리거하는 경우를 결정합니다.

## 동일한 소스 URL이 두 개의 다른 대량 Redirect 목록에 나타나는 경우 어떻게됩니까?

이 상황에서 Cloudflare는 트리거의 첫 번째 규칙을 리디렉션하는 URL을 사용합니다. 벌크 리디렉트 규칙의 순서에 따라 결정됩니다. 각 벌크 리디렉트 목록에서`http_request_redirect`단계 항목 포인트 규칙.

## 다음 오류를 해결할 수 있는 방법: "이 계정은 같은 hostname/path에서 URL 일치하는 항목의 수에 제한을 도달했습니다"?

Bulk Redirect List에 아이템을 추가할 때 이 오류를 얻을 수 있습니다.

같은 소스 호스트 이름 (다른 경로) 또는 동일한 소스 경로 (다른 호스트 이름)와 같은 소스 경로로 리디렉션할 수 있습니다. 그러나 모든 목록에서 동일한 호스트 이름과 경로로 최대 16 소스 URL을 가질 수 있습니다. 대량 Redirect 규칙 또는 아닙니다.

이 오류를 받으면 소스 호스트 이름과 경로가 사용되지 않는 대량 리디렉션 목록이 있고, 목록에서 이러한 항목을 제거하십시오.

## 얼마나 많은 URL 리디렉션은 단일 대량 리디렉션 목록에있을 수 있습니까?

각 계정은 Cloudflare 계획에 따라 모든 목록에서 리디렉션되는 최대 URL이 있습니다. 원하는 경우, 단일 대량 리디렉션 목록에서 모든 URL 리디렉션을 사용할 수 있지만 다른 URL 리디렉션을 다른 목록에서 만들 수 없습니다. 더 알아보기[적용분야](/rules/url-forwarding/#availability)더 많은 정보.

## URL의 비정상화 된 버전에 근거를 둔 방법은 무엇입니까?

사용 방법`raw.http.request.full_uri`규칙 표현과 키에서 모두 필드, 대신 기본 필드`http.request.full_uri`. 이것은 계정으로 URL의 원시 버전을 취할 것입니다, 즉, URL은 Cloudflare 글로벌 네트워크에 수신<GlossaryTooltip term="URL normalization">일반화</GlossaryTooltip>. 참고[대량 Redirects 개념](/rules/url-forwarding/bulk-redirects/concepts/#bulk-redirect-rules)사용자 정의 규칙 표현과 사용자 정의 키를 사용하여 더 많은 정보를 제공합니다.

## Bulk Redirects는 페이지 규칙에 대한 우선 순위를 가지고 있습니까?

예. Bulk Redirects는 페이지 규칙이 리디렉션을 통해 미리 취합니다. 규칙 제품의 실행 순서에 대한 자세한 내용은 참조[실행 순서](/rules/url-forwarding/#execution-order).

## 하나의 API 호출에서 전체 대량 리디렉션 목록을 추적 할 수 있습니까?

이름 \*[대량 Redirect 목록](/rules/url-forwarding/bulk-redirects/concepts/#bulk-redirect-lists)500,001 이상의 항목이 포함되어 있으며 단일 API 통화의 전체 목록을 추적 할 수 없습니다. 대신 여러 통화를해야합니다.[자주 묻는 질문](/api/resources/rules/subresources/lists/subresources/items/methods/delete/)API 엔드 포인트, 요청에 따라 최대 100,000 항목 삭제.

예를 들어, 1,000,000 항목으로 목록을 삭제하려면 적어도 10 API 요청을 발급해야합니다.
