URL 리디렉션에는 소스 URL, 대상 URL, 상태 코드 및 URL 일치 행동 및 실행 행동에 영향을 미치는 몇 가지 추가 매개 변수가 있습니다.

## 소스 URL

API 필드:`source_url` <Type text="String" />

수신 요청 URL이 적용되는 리디렉션에 일치해야 하는 URL 문자열. 이 속성은 필수입니다. 소스 URL의 최대 길이는 32 KB입니다.

값은 유효 URL이어야하지만 URL 계획은 필요하지 않습니다 (예를 들어,`https`); 계획이 omitted 때, 리디렉션은 둘 다에 적용합니다`http`·`https`URL 계획.

대량 간접 목록은 정확한 동일한 소스 URL로 여러 URL을 리디렉션할 수 없습니다.
정확한 행동[URL 매칭 알고리즘](/rules/url-forwarding/bulk-redirects/how-it-works/#url-matching-algorithm)리다이렉트의 소스 URL과 들어오는 요청과 일치하면 값에 따라 달라집니다.[**하위 도메인 포함**](#include-subdomains)·[**Subpath 일치**](#subpath-matching)모수.

지원된 URL 구성 요소에 대한 자세한 내용은 참조[대량 Redirects에서 URL 구성품 지원](/rules/url-forwarding/bulk-redirects/reference/url-components/).

## 대상 URL

API 필드:`target_url` <Type text="String" />

클라이언트가 URL을 리디렉션할 때 리디렉션될 URL입니다. 이 속성은 필수입니다. 대상 URL의 최대 길이는 32 KB입니다.

값은 유효한 URL이어야 합니다. 최종 대상 URL은 값에 따라 달라집니다.[**자주 묻는 질문**](#preserve-query-string)·[**예약 경로 suffix**](#preserve-path-suffix)모수.

지원된 URL 구성 요소에 대한 자세한 내용은 참조[대량 Redirects에서 URL 구성품 지원](/rules/url-forwarding/bulk-redirects/reference/url-components/).

## Subpath 일치

API 필드:`subpath_matching` <Type text="Boolean" /> <MetaInfo text="default: false" />

이름 \*`true`, 현재 리디렉션은 현재 URL 리디렉션에 대한 일치가 있는 경우, 요청 URL에 하위 경로 매칭 알고리즘을 적용합니다.

예를 들어, URL 리디렉션`/my-folder/`으로`/other-folder/`이름 \***Subpath 일치**활성화는 또한 요청을 리디렉션합니다.`/my-folder/item`으로`/other-folder/item`. 그러나, 리다이렉션은 포함`item`부분 때[**예약 경로 suffix**](#preserve-path-suffix)이름 \*`true`.

더 많은 정보를 원하시면, 참조[리디렉션의 소스 URL 일치](/rules/url-forwarding/bulk-redirects/how-it-works/#matching-the-source-url-of-redirects).

## 하위 도메인 포함

API 필드:`include_subdomains` <Type text="Boolean" /> <MetaInfo text="default: false" />

이름 \*`true`, 소스 URL 호스트 이름도 하위 도메인에 적용 할 것이다 - 리디렉션은 소스 URL의 도메인 부분의 왼쪽에 모든 하위 도메인에 일치, 뿐만 아니라 지정된 도메인.

예를 들어 소스 URL과 리디렉션을 정의합니다.`http://example.com/about`소스 URL과 요청에 적용`http://a.example.com/about`또는`http://a.b.example.com/about`.

더 많은 정보를 원하시면, 참조[리디렉션의 소스 URL 일치](/rules/url-forwarding/bulk-redirects/how-it-works/#matching-the-source-url-of-redirects).

## 자주 묻는 질문

API 필드:`preserve_query_string` <Type text="Boolean" /> <MetaInfo text="default: false" />

이름 \*`true`, 리디렉션 URL은 원래 요청의 쿼리 문자열을 유지한다.

예를 들어, URL 리디렉션`/my-folder/`으로`/other-folder/`이름 \***자주 묻는 질문**활성화는 요청을 리디렉션합니다.`/my-folder/?name=value`으로`/other-folder/?name=value`. 만약**자주 묻는 질문**비활성화, 요청은 에서 리디렉션됩니다`/my-folder/?name=value`으로`/other-folder/`.

## 예약 경로 suffix

API 필드:`preserve_path_suffix` <Type text="Boolean" /> <MetaInfo text="default: true" />

적용 가능한 경우에만[**Subpath 일치**](#subpath-matching)지원하다 이름 \*`true`, 리디렉션 URL이 소스 URL의 나머지 (비 일치) 경로 요소를 포함한다는 것을 정의, 어떤 경우.

예를 들어 둘 때**Subpath 일치**·**예약 경로 suffix**활성화, URL에서 리디렉션`/my-folder/`으로`/another-folder/`자주 묻는 질문`/my-folder/foo`으로`/another-folder/foo`. 만약**예약 경로 suffix**여전히 URL 리디렉션을 일치하지만, 그것은에서 리디렉션됩니다`/my-folder/foo`으로`/another-folder/`.

## 상태 코드

API 필드:`status_code` <Type text="Integer" /> <MetaInfo text="default: 301" />

HTTP 상태 코드는 리디렉션할 때 클라이언트로 반환됩니다.

값은 다음과 같습니다.

- `301`(정상적으로 이동)
- `302`(일부로도 알려져 있음)
- `307`(온도 리디렉션)
- `308`(원래 리디렉션)
