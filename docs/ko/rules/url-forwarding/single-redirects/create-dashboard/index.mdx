<Steps>
  1. Cloudflare 대시보드에서 규칙에 가십시오**제품정보**사이트 맵

     <DashButton url="/?to=/:account/:zone/rules/overview" />

  2. 제품정보**규칙 만들기** > **Redirect 규칙**.

  3. (선택 사항) 일반적인 사용 사례를 해결하는 규칙 템플릿 중 하나를 선택하십시오. 그런 다음, 검토 및 제안 된 규칙 구성을 조정합니다.

  4. 규칙에 대한 설명 이름 입력**규칙 이름**.

  5. 이름 \***수신 요청 일치**, 다음 옵션 중 하나를 선택:
     - **Wildcard 패턴**: 규칙은 와일드카드 패턴과 일치하는 트래픽에만 적용됩니다.
       - **URL 요청**: 입력[wildcard 패턴](/ruleset-engine/rules-language/operators/#wildcard-matching)asterisk 사용`*`) 다수 요구에 응하는 특성. 예를 들어,`http*://*.example.com/files/*`.
       - **다음 것**: 정의[URL 리디렉션 설정](/rules/url-forwarding/single-redirects/settings/)포함 :
         - **대상 URL**: 정적일 수 있는 대상 URL을 입력합니다.`https://example.com`) 또는 동적인 (예를 들면,`https://example.com/${1}/files/${2}`). 제품 정보[wildcard 교체](/ruleset-engine/rules-language/functions/#wildcard_replace)등`${1}`·`${2}`동적 대상 URL을 정의합니다.
         - **상태 코드**: 리디렉션의 상태 코드를 선택 (예를 들어,`301`).
         - **자주 묻는 질문**: 원래 요청에서 쿼리 문자열을 유지 여부를 선택하십시오.
     - **모든 수신 요청**: 규칙은 모든 교통에 적용됩니다.
       - **다음 것**: 정의[URL 리디렉션 설정](/rules/url-forwarding/single-redirects/settings/)모든 수신 요청을 위해.
     - **사용자 정의 필터 표현**: 규칙은 사용자 정의 표현과 일치하는 트래픽에만 적용됩니다. 수정하기[규칙 표현](/ruleset-engine/rules-language/expressions/edit-expressions/)요청이 리디렉션되어야 하는 구성.
       - **다음 것**: 정의[URL 리디렉션 설정](/rules/url-forwarding/single-redirects/settings/)사용자 정의 규칙 표현과 일치하는 요청에 대한.

  6. 규칙을 저장하고 배포하려면, 선택**계정 만들기**. 규칙을 배포 할 준비가 없다면, 선택**Draft로 저장**.

     <Render file="rules-creation-dash-dns-popup" product="rules" />
</Steps>
