migration는 class name에서 runtime state로 매핑 프로세스입니다. 이 과정은 Workers 런타임에 변화를 전달하고 그 변경 사항을 처리하는 방법에 대한 지침과 실행 시간을 제공합니다.

마이그레이션을 적용하려면:

1. 아래 설명대로 Wrangler 구성 파일을 편집하십시오.
2. 작업자 배치`npx wrangler deploy`.

당신은 마이그레이션 프로세스를 시작해야:

- 새로운 기능<GlossaryTooltip term="Durable Object class">튼튼한 목표 종류</GlossaryTooltip>.
- 튼튼한 개체 클래스 이름을 지정합니다.
- 튼튼한 개체 클래스를 삭제합니다.
- 기존 Durable Objects 클래스를 전송합니다.

:::참조

기존의 튼튼한 개체 클래스에 대한 코드를 업데이트는 마이그레이션이 필요하지 않습니다. 기존의 튼튼한 개체 클래스의 코드를 업데이트하려면 실행[`npx wrangler deploy`](/workers/wrangler/commands/#deploy). 이 코드가 영구 저장과 어떻게 상호 작용하는지에 대한 변경도 사실입니다. 이름 \*[글로벌 독창성](/durable-objects/platform/known-issues/#global-uniqueness), 당신은 같은 저장과 상호 작용하는 오래된 새로운 부호에 관하여 고민할 필요가 없습니다. 그러나 새로운 코드가 기존 저장 된 데이터와 호환되는 것을 보장하는 책임입니다.

:::

## 회사연혁

가장 일반적인 마이그레이션은 새로운 클래스 마이그레이션입니다, 이는 새로운 내구성 개체 클래스가 업로드 된 실행 시간을 알려줍니다. 이것은 첫 번째 튼튼한 개체 클래스를 만들 때 필요한 마이그레이션입니다.

생성 마이그레이션을 적용하려면:

<Steps>
  1. Wrangler 구성 파일에 다음 줄을 추가하십시오:

     <WranglerConfig>
       ```jsonc
       {
         "migrations": [
           {
             "tag": "<v1>", //마이그레이션 식별자. 각 마이그레이션 항목에 고유해야합니다
             "new_sqlite_classes": [ //새로운 클래스의 배열
               "<NewDurableObjectClass>"
             ]
           }
         ]
       }
       ```
     </WranglerConfig>

     생성 마이그레이션 포함:

     - ·`tag`마이그레이션을 식별합니다.
     - 한국어`new_sqlite_classes`새로운 튼튼한 개체 클래스를 포함하는 ,.

  2. 참고 자료 당신의 노동자 부호에 있는 튼튼한 목표 종류의 정확한 이름을 지키십시오.

  3. Worker를 배포합니다.
</Steps>

<Details header="migration 예제 만들기">
  새로운 튼튼한 개체 바인딩을 만들려면`DURABLE_OBJECT_A`, 당신의 Wrangler 윤곽 파일은 다음과 같이 보입니다:

  <WranglerConfig>
    ```jsonc
    {
    	//새로운 튼튼한 개체 클래스 만들기
    	"durable_objects": {
    		"bindings": [
    			{
    				"name": "DURABLE_OBJECT_A",
    				"class_name": "DurableObjectAClass"
    			}
    		]
    	},
    	//Create migration에 대해 아래 라인을 추가하십시오.
    	"migrations": [
    		{
    			"tag": "v1",
    			"new_sqlite_classes": [
    				"DurableObjectAClass"
    			]
    		}
    	]
    }
    ```
  </WranglerConfig>
</Details>

## 관련 기사

삭제 마이그레이션을 실행하면 모든 Durable Objects를 삭제할 수 있습니다.

- 먼저 Durable Objects에 의존하지 않는 것을 보장하지 않고 클래스에서 삭제 마이그레이션을 실행하지 마십시오, 즉, 먼저 노동자에서 바인딩을 제거.
- 삭제하기 전에 다른 위치에 중요한 자료를 복사하십시오.
- 이름을 변경하거나 전송 한 클래스에서 삭제 마이그레이션을 실행할 필요가 없습니다.

삭제 된 마이그레이션을 적용하려면:

<Steps>
  1. Wrangler 설정 파일에서 삭제하려면 클래스에 대한 바인딩을 제거하십시오.

  2. 참고 자료s를 제거하여 작업자의 코드를 삭제합니다.

  3. Wrangler 구성 파일에 다음 줄을 추가하십시오.

     <WranglerConfig>
       ```jsonc
       {
         "migrations": [
           {
             "tag": "<v2>", //마이그레이션 식별자. 각 마이그레이션 항목에 고유해야합니다
             "deleted_classes": [ //삭제 된 클래스 이름의 배열
               "<ClassToDelete>"
             ]
           }
         ]
       }
       ```
     </WranglerConfig>

     삭제 마이그레이션 포함:

     - ·`tag`마이그레이션을 식별합니다.
     - 한국어`deleted_classes`삭제 된 튼튼한 개체 클래스를 포함하는 ,.

  4. Worker를 배포합니다.
</Steps>

<Details header="마이그레이션 예제">
  튼튼한 개체 바인딩을 삭제하려면`DEPRECATED_OBJECT`, 당신의 WranglerXQ 윤곽 파일은 다음과 같이 보입니다:

  <WranglerConfig>
    ```jsonc
    {
    	//DeprecatedObjectClass DO에 대한 바인딩 제거
    	//{"durable objects": {"bindings": [
    	//이름 *
    	//"이름": "DEPRECATED OBJECT",
    	//"class name": "DeprecatedObjectClass"
    	//이름 *
    	//₢ 킹
    	"migrations": [
    		{
    			"tag": "v3", //각 항목에 고유해야합니다
    			"deleted_classes": [ //삭제 된 클래스의 배열
    				"DeprecatedObjectClass"
    			]
    		}
    	]
    }
    ```
  </WranglerConfig>
</Details>

## 이름 migration

이름 마이그레이션은 동일한 노동자 부호 파일에 있는 2개의 튼튼한 목표 종류 사이 저장한 Durable Objects를 이동하기 위하여 이용됩니다.

이름 마이그레이션을 적용하려면:

<Steps>
  1. 다음 방법으로 Wrangler 구성 파일을 편집하여 새로운 클래스 이름에 이전 클래스 이름을 업데이트하십시오.

     <WranglerConfig>
       ```jsonc
       {
       	"durable_objects": {
       		"bindings": [
       			{
       				"name": "<MY_DURABLE_OBJECT>",
       				"class_name": "<UpdatedDurableObject>" //새 클래스 이름에 클래스 이름을 업데이트
       			}
       		]
       	},
       	"migrations": [
       		{
       			"tag": "<v3>", //마이그레이션 식별자. 각 마이그레이션 항목에 고유해야합니다
       			"renamed_classes": [ //rename 지시어의 배열
       				{
       					"from": "<OldDurableObject>",
       					"to": "<UpdatedDurableObject>"
       				}
       			]
       		}
       	]
       }
       ```
     </WranglerConfig>

     이름 마이그레이션 포함:

     - ·`tag`마이그레이션을 식별합니다.
     - 더 보기`renamed_classes`배열, 물체 포함`from`·`to`이름 \*
       - `from`속성은 오래된 튼튼한 개체 클래스 이름입니다.
       - `to`속성은 renamed 튼튼한 개체 클래스 이름입니다.

  2. 당신의 노동자 부호에 있는 새로운 튼튼한 목표 종류 이름.

  3. Worker를 배포합니다.
</Steps>

<Details header="Rename 마이그레이션 예제">
  튼튼한 개체 클래스 이름을 변경하려면`OldName`으로`UpdatedName`, 당신의 Wrangler 윤곽 파일은 다음과 같이 보입니다:

  <WranglerConfig>
    ```jsonc
    {
    	//`DeprecatedClass`를 삭제하기 전에 `DeprecatedClass`XQ에 대한 바인딩을 제거합니다.
    	//새로운 클래스 이름 `UpdatedName`에 `DurableObjectExample`XQ에 대한 바인딩을 업데이트하십시오.
    	"durable_objects": {
    		"bindings": [
    			{
    				"name": "MY_DURABLE_OBJECT",
    				"class_name": "UpdatedName"
    			}
    		]
    	},
    	//관련 수업
    	"migrations": [
    		{
    			"tag": "v3",
    			"renamed_classes": [ //rename 지시어의 배열
    				{
    					"from": "OldName",
    					"to": "UpdatedName"
    				}
    			]
    		}
    	]
    }
    ```
  </WranglerConfig>
</Details>

## 이동 migration

전송 마이그레이션은 다른 노동자 코드 파일에서 두 개의 튼튼한 개체 클래스 사이에 저장 Durable Objects를 전송하는 데 사용됩니다.

동일한 작업자 코드 파일에 2개의 튼튼한 목표 종류 사이 저장한 Durable Objects를 이동하고 싶은 경우에, 사용[이름 migrations](#rename-migration)대신.

:::참조
실행하지 마십시오[회사연혁](#create-migration)전송 마이그레이션을 실행하기 전에 대상 클래스. Transfer migration는 목적지 클래스를 만들 것입니다.
주요 특징

전송 마이그레이션을 적용하려면:

<Steps>
  1. 다음 방법으로 Wrangler 구성 파일을 편집하십시오.

     <WranglerConfig>
       ```jsonc
       {
         "durable_objects": {
           "bindings": [
             {
               "name": "<MY_DURABLE_OBJECT>",
               "class_name": "<DestinationDurableObjectClass>"
             }
           ]
         },
         "migrations": [
           {
             "tag": "<v4>", //마이그레이션 식별자. 각 마이그레이션 항목에 고유해야합니다
             "transferred_classes": [
               {
                 "from": "<SourceDurableObjectClass>",
                 "from_script": "<SourceWorkerScript>",
                 "to": "<DestinationDurableObjectClass>"
               }
             ]
           }
         ]
       }
       ```
     </WranglerConfig>

     전송 마이그레이션 포함:

     - ·`tag`마이그레이션을 식별합니다.
     - 더 보기`transferred_class`배열, 물체 포함`from`, `from_script`·`to`이름 \*
       - `from`속성은 source 튼튼한 Object 클래스의 이름입니다.
       - `from_script`속성은 소스 Worker 스크립트의 이름입니다.
       - `to`속성은 목적지 튼튼한 개체 클래스의 이름입니다.

  2. 참고 자료의 새로운 이름, 당신의 노동자 부호에 있는 목적지 튼튼한 목표 종류.

  3. Worker를 배포합니다.
</Steps>

<Details header="이동 이동 예">
  당신은 저장한 Durable Objects를 안으로 이동할 수 있습니다`DurableObjectExample`으로`TransferredClass`Worker 스크립트에서`OldWorkerScript`. 당신의 새로운 노동자 부호 (destination 노동자 부호)를 위한 WranglerXQ 윤곽 파일의 윤곽은 이것 같이 보일 것입니다:

  <WranglerConfig>
    ```jsonc
    {
    	//대상 노동자
    	"durable_objects": {
    		"bindings": [
    			{
    				"name": "MY_DURABLE_OBJECT",
    				"class_name": "TransferredClass"
    			}
    		]
    	},
    	//전송 클래스
    	"migrations": [
    		{
    			"tag": "v4",
    			"transferred_classes": [
    				{
    					"from": "DurableObjectExample",
    					"from_script": "OldWorkerScript",
    					"to": "TransferredClass"
    				}
    			]
    		}
    	]
    }
    ```
  </WranglerConfig>
</Details>

## 마이그레이션 Wrangler 구성

- Migrations는 수행`[[migrations]]`설정 키에서`wrangler.toml`파일 또는`migration`당신의 열쇠`wrangler.jsonc`파일.

- 마이그레이션 태그가 필요합니다.`tag`각 마이그레이션 항목에 속성.

- 마이그레이션 태그는 고유 한 이름 처럼 처리 하 고 이미 적용 되었다 어떤 마이그레이션을 결정 하는 데 사용. 주어진 노동자 코드가 마이그레이션 태그를 설정하면, 모든 미래의 노동자 코드 배포는 마이그레이션 태그를 포함해야합니다.

- 마이그레이션 목록은 Wrangler 구성 파일에서 키로 지정된 테이블의 주문 배열입니다.

- 각 환경에 대한 마이그레이션을 정의 할 수 있습니다.
  - 최고 수준의 마이그레이션은 최고 수준의 지정`migrations`WranglerXQ 윤곽 파일에 있는 열쇠.
  - 환경 수준의 마이그레이션은 지정된`migrations`키 내부`env`WranglerXQ 구성 파일의 키 (`[env.<environment_name>.migrations]`).
    - Wrangler 파일 보기:
    ```jsonc title="wrangler.jsonc"
    {
    //top-level 기본 마이그레이션
    "migrations": [{ ... }],
    "env": {
    "staging": {
      //staging를 위한 이동 override
      "migrations": [{...}]
      }
     }
    }
    ```
  - 이동이 최고 수준에서만 지정되는 경우에, 그러나 환경 수준에, 환경은 정상 수준 이동을 상속할 것입니다.
  - 상위 수준에서 환경 수준의 과급 마이그레이션에 대한 마이그레이션.

- 모든 마이그레이션은 배포에 적용됩니다. 각 이동은 한 번만 적용될 수 있습니다[환경분야](/durable-objects/reference/environments/).

- 목록의 각 마이그레이션은 여러 지침을 가질 수 있으며, 여러 마이그레이션은 복잡한 프로젝트로 지정될 수 있습니다.

:::카ution\[중요]

- 대상 클래스 (Durable Objects를 저장하는 클래스는 Rename 또는 Transfer 마이그레이션을 위해 전송되어야합니다.

- Rename 또는 Transfer migration를 실행하기 전에 목적지 튼튼한 개체 클래스를 만들 필요가 없습니다. 이동은 목적지 클래스를 만들 것입니다.

- Rename 또는 Transfer 마이그레이션 후, 목적지에 요청 튼튼한 개체 클래스는 소스에 액세스 할 것입니다 내구성 개체의 저장 데이터.

- 마이그레이션 후, 원래의 튼튼한 개체 클래스에 기존 바인딩 (예를 들어, 다른 Workers에서) 자동으로 업데이트 된 목적지 클래스로 전달됩니다. 그러나, 어떤 Workers 업데이트 된 튼튼한 개체 클래스에 바인딩 구성을 업데이트해야합니다`wrangler`다음 배포에 대한 구성 파일.
  주요 특징

:::참조
주의사항`.toml`파일은 인라인 테이블에 라인 브레이크를 허용하지 않습니다 (the`{key = "value"}`구문), 그러나 주위 인라인 배열에 있는 선 틈은 수락가능합니다.
주요 특징

기존의 SQLite 저장소 백엔드를 활성화할 수 없으므로 튼튼한 개체 클래스를 배치합니다.`new_sqlite_classes`나중에 마이그레이션은 오류로 실패합니다. SQLite 저장소 백엔드에 배포된 클래스의 자동 마이그레이션은 미래에 사용할 수 있습니다.

:::카ution\[중요]
튼튼한 개체 마이그레이션은 원자 작업이며 점차 배포 될 수 없습니다. 개발자에게 초기 피드백을 제공하려면 새로운 마이그레이션 버전이 업로드 될 수 없습니다. 더 알아보기[Durable Objects에 대한 Gradual 배포](/workers/configuration/versions-and-deployments/gradual-deployments/#gradual-deployments-for-durable-objects)더 많은 정보.
