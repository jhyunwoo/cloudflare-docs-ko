## 관할권에 Durable Objects 제한

관할구역<GlossaryTooltip term="Durable Object">Durable Objects</GlossaryTooltip>지역 내의 데이터만 실행하고 저장하여 지역 규정 준수[GDPR](https://gdpr-info.eu/)또는[파일 형식](https://blog.cloudflare.com/cloudflare-achieves-fedramp-authorization/).

Workers는 여전히 세계에서 어느 곳에서나 관할권에 Durable Objects에 접근할지도 모릅니다. 이 관할 구역은 튼튼한 개체 자체가 실행되고 persists 데이터 만 제어합니다. 자주 묻는 질문[지역 서비스](/data-localization/regional-services/)Cloudflare는 요청에 응답합니다.

:::노트\[로깅]

·[`DurableObjectId`](/durable-objects/api/id)청구 및 디버깅 목적으로 지정된 관할 구역 밖에 기록될 것입니다.

:::

Durable Objects는 특정 관할권에 제한될 수 있습니다[`DurableObjectNamespace`](/durable-objects/api/namespace/)관할권에 제한. 모든 것[튼튼한 개체 ID 방법](/durable-objects/api/id/)관할권에 제한되는 네임스페이스 내에서 ID를 유효하다.

```js
const euSubnamespace = env.MY_DURABLE_OBJECT.jurisdiction("eu");
const euId = euSubnamespace.newUniqueId();
```

- 같은 이름이 다른 ID를 다른 관할 구역에서 표현할 수 있습니다.

  ```js
  const euId1 = env.MY_DURABLE_OBJECT.idFromName("my-name");
  const euId2 = env.MY_DURABLE_OBJECT.jurisdiction("eu").idFromName("my-name");
  console.assert(!euId1.equal(euId2), "This should always be true");
  ```

- 귀하는 귀하의 관할권이 있는 경우 오류로 실행됩니다.[`DurableObjectNamespace`](/durable-objects/api/namespace/)그리고 관할권[`DurableObjectId`](/durable-objects/api/id)다른 것.

- 오류로 실행되지 않습니다.[`DurableObjectNamespace`](/durable-objects/api/namespace/)관할권과 관련이 없습니다.

- 모든 것[튼튼한 개체 ID 방법](/durable-objects/api/id/)관할권에 제한되는 네임스페이스 내에서 ID를 유효하다.

  ```js
  const euSubnamespace = env.MY_DURABLE_OBJECT.jurisdiction("eu");
  const euId = euSubnamespace.idFromName(name);
  const stub = env.MY_DURABLE_OBJECT.get(euId);
  ```

:::카트로션\[사용]`DurableObjectNamespace.jurisdiction`]

관할권을 지정할 때, Cloudflare는 먼저 관할권에 제한되는 네임스페이스를 만듭니다.`const euSubnamespace = env.MY_DURABLE_OBJECT.jurisdiction("eu")`.

관할권을 지정할 수도 있습니다.[`DurableObjectId`](/durable-objects/api/id)관할권 제한, 사용`const euId = env.MY_DURABLE_OBJECT.newUniqueId({ jurisdiction: "eu" })`.

**그러나 Cloudflare는 이 접근법을 추천하지 않습니다.**
:::

## 위치 hint 제공

Durable Objects, 어떤 stateful API와 같이, 요구가 튼튼한 목표, 또는 국가가 있는 자료 센터에 전달되어야 하는 대로 수시로 응답 대기권을 추가할 것입니다.

Durable Objects는 현재 생성한 후에 위치를 변경하지 않습니다<sup>1</sup>. 기본적으로, 튼튼한 목표는 자료 센터에서 처음에 가까운 순간적으로 입니다`get()`요청이 이루어집니다. 이 같은 데이터 센터에 있을 수 없습니다.`get()`요청은, 하지만 대부분의 경우, 그것은 가까운 근접 될 것입니다.

:::caution\[Durable Objects에 대한 정보 요청]

첫 번째 클라이언트 요청 이전에 Durable ObjectsXQ를 사전 작성하는 데 부정적인 영향을 줄 수 있거나 첫 번째 클라이언트 요청이 대부분의 요청이 제공되지 않은 경우. 그것은 실제 생산 교통에 응답에 Durable Objects를 창조하는 대기권에 더 낫습니다 또는 명시한 위치 hints를 제공합니다.

:::

위치 힌트는 튼튼한 개체가 처음에 관계없이 위치 지정하는 메커니즘입니다.`get()`자주 묻는 질문

수동으로 다른 위치에 있는 Durable Objects를 창조하기 위하여는, 선택을 제공합니다`locationHint`매개 변수`get()`. 첫 번째 호출만`get()`특정 개체는 힌트를 존중합니다.

```js
let durableObjectStub = OBJECT_NAMESPACE.get(id, { locationHint: "enam" });
```

:::카트로션

힌트는 최고의 노력이며 보증이 아닙니다. 관할 구역과는 달리, Durable Objects는 반드시 힌트 위치에 즉각적으로 처리되지 않을 것입니다, 그러나 힌트 위치에 있는 대기권을 극소화하기 위하여 선택된 자료 센터에서 즉시.
