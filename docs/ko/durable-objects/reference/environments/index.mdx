환경은 특정 의존성 및 구성으로 코드를 실행하는 고립 된 공간을 제공합니다. 이것은 호환성 테스트 또는 버전 관리와 같은 다수 이유를 위해 유용합니다. 다른 환경은 코드 배포시 오류의 위험을 줄이기 위해 일관성있는 코드, 테스트 및 생산 분리를 도울 수 있습니다.

## Wrangler 환경

[모델 번호: Wrangler](/workers/wrangler/install-and-update/)서로 다른 구성으로 동일한 Worker 응용 프로그램을 배포 할 수 있습니다.[환경분야](/workers/wrangler/environments/).

Wrangler환경을 사용하는 경우, 지정해야 합니다.[튼튼한 목표 바인딩](/workers/runtime-apis/bindings/)당신은 per-environment 기초에 사용을 원합니다.

튼튼한 목표 바인딩은 상속되지 않습니다. 예를 들어, 이름을 지정할 수 있습니다.`staging`아래에로:

<WranglerConfig>
  ```jsonc
  {
  	"env": {
  		"staging": {
  			"durable_objects": {
  				"bindings": [
  					{
  						"name": "EXAMPLE_CLASS",
  						"class_name": "DurableObjectExample"
  					}
  				]
  			}
  		}
  	}
  }
  ```
</WranglerConfig>

Wrangler가 추가되기 때문에[환경 이름](/workers/wrangler/environments/)게시 할 때 최고 수준의 이름에, 지명 된 노동자`worker-name`위의 예는 다음과 같습니다.

<WranglerConfig>
  ```jsonc
  {
  	"env": {
  		"staging": {
  			"durable_objects": {
  				"bindings": [
  					{
  						"name": "EXAMPLE_CLASS",
  						"class_name": "DurableObjectExample",
  						"script_name": "worker-name-staging"
  					}
  				]
  			}
  		}
  	}
  }
  ```
</WranglerConfig>

`"EXAMPLE_CLASS"`노후화 환경에서는 최고 수준과 비교된 다른 노동자 부호 이름에 경계합니다`"EXAMPLE_CLASS"`바인딩은, 그러므로 다른 persistent 저장을 가진 다른 Durable ObjectsXQ에 접근할 것입니다.

top-level 바인딩과 동일한 개체에 액세스하는 환경 별 바인딩을 원한다면, 명시적으로 사용하는 최상위 작업자 코드 이름을 지정하십시오.`script_name`:

<WranglerConfig>
  ```jsonc
  {
  	"env": {
  		"another": {
  			"durable_objects": {
  				"bindings": [
  					{
  						"name": "EXAMPLE_CLASS",
  						"class_name": "DurableObjectExample",
  						"script_name": "worker-name"
  					}
  				]
  			}
  		}
  	}
  }
  ```
</WranglerConfig>

### Migration 환경

각 환경에 대한 견고한 오브젝트 마이그레이션을 정의 할 수 있습니다. 상위 수준에서 환경 수준의 과급 마이그레이션에 대한 마이그레이션.

더 많은 정보를 원하시면, 참조[마이그레이션 Wrangler 제품 설명](/durable-objects/reference/durable-objects-migrations/#migration-wrangler-configuration).

## 지역 개발

로컬 개발 세션은 생산 환경을 미러링하는 독립적이고 로컬 전용 환경을 만들고, 생산 환경에 배포하기 전에 작업자와 Durable ObjectsXQXQ를 테스트 할 수 있습니다.

기존의 튼튼한 개체 바인딩`DB`로컬에서 실행할 때 작업자에게 사용할 수 있습니다.

Workers에 Refer[지역 개발](/workers/development-testing/bindings-per-env/).

## 원격 개발

KV-backed Durable ObjectsXQ는 대시보드 운동장을 사용하여 먼 발달을 지원합니다. 대시보드 놀이터는 비주얼 스튜디오 코드의 브라우저 버전을 사용하며 브라우저에서 작업자에게 신속하게 그것을 제공 할 수 있습니다.

원격 개발 시작:

1. Cloudflare 대시보드에서, 가십시오**Workers & Pages**사이트 맵

   <DashButton url="/?to=/:account/workers-and-pages" />
2. 기존 노동자를 선택하십시오.
3. 선택하기**비밀번호**화면의 오른쪽 상단에 위치한 아이콘.

:::카트로션
원격 개발은 KV-backed Durable Objects에서만 유효합니다. SQLite-backed Durable Objects는 원격 개발을 지원하지 않습니다.
