Durable Objects는 노동자의 특별한 종류입니다, 그래서[모델 번호: Workers 제한 사항](/workers/platform/limits/)Workers 계획에 따라 적용하십시오. 또한, Durable Objects는 이 페이지에 목록으로 만들어진 특정한 한계가 있습니다.

## SQLite 백업 Durable Objects 일반 제한

| 제품 정보               | 지원하다                                                                         |
| ------------------- | ---------------------------------------------------------------------------- |
| 개체 수                | 무제한 ( 계정 또는 주어진 클래스의)                                                        |
| 최대 튼튼한 개체 클래스 (계정당) | 500 (Workers 유료) / 100 (무료)[^1]                                              |
| 계정 당 저장             | 무제한 (Workers 유료) / 5GB (무료)[^2]                                              |
| 수업당 저장              | 제한 없음[^3]                                                                    |
| 튼튼한 목표 당 저장         | 10개 GB[^3]                                                                   |
| 키 크기                | 결합된 열쇠와 가치는 2 MB를 초과할 수 없습니다                                                 |
| 가치 크기               | 결합된 열쇠와 가치는 2 MB를 초과할 수 없습니다                                                 |
| WebSocket 메시지 크기    | 32 MiB (받은 메시지 만)                                                            |
| 요구에 의하여 CPU         | 30 초 (과태) / 구성 가능한 5 분[활동적인 CPU 시간](/workers/platform/limits/#cpu-time) [^4] |

[^1]: Workers에 식별[스크립트 제한](/workers/platform/limits/).

[^2]: Durable Objects는 기가 바이트에 근거를 둔 계산서 및 측정 저장 둘 다<br />(1 GB = 1,000,000,000 바이트) 과 gibibyte (GiB).<br />

[^3]: Workers 무료 계획에 대한 계정은 5 GB 총 Durable Objects 저장에 제한됩니다.

[^4]: 각 수신 HTTP 요청 또는 WebSocket*이름 \**&#xB098;머지 사용 가능한 CPU 시간을 30 초로 재설정합니다. 이것은 각 들어오는 네트워크 요구 후에 compute의 30 초까지 소비하는 튼튼한 목표가, 타이머를 다시 놓는 각 새로운 네트워크 요구와 더불어 허용합니다. 들어오는 네트워크 요청에 비해 30 초 이상 소비하는 경우, 개별 내구성 개체가 evicted 및 재설정되는 고도화 된 기회가 있습니다. 요청에 따라 CPU 시간[증가할 수 있습니다.](/durable-objects/platform/limits/#can-i-increase-durable-objects-cpu-limit).

### SQL 저장 한계

튼튼한 개체 클래스에 대해[SQLite 저장](/durable-objects/api/sqlite-storage-api/)이 SQL 한계는 적용합니다:

| 사이트맵                          | 지원하다              |
| ----------------------------- | ----------------- |
| 테이블 당 열의 최대 수                 | 100               |
| 테이블 당 행 수                     | 무제한 (당사 저장 제한 제외) |
| 최대 문자열,`BLOB`또는 테이블 행 크기      | 2개 MB             |
| 최대 SQL 문 길이                   | 100개 KB           |
| 쿼리 당 최대 경계 매개 변수              | 100               |
| SQL 함수당 최대 인수                 | 32                |
| 최대 문자(바이트)`LIKE`또는`GLOB`이름 \* | 50 바이트            |

## 열쇠 가치는 Durable Objects 일반적인 한계를 역행시켰습니다

| 제품 정보               | key-value 저장 backend를 가진 종류를 위한 한계      |
| ------------------- | --------------------------------------- |
| 개체 수                | 무제한 ( 계정 또는 주어진 클래스의)                   |
| 최대 튼튼한 개체 클래스 (계정당) | 500 (Workers 유료) / 100 (무료)[^5]         |
| 계정 당 저장             | 50 GB (Cloudflare에 접촉해서 올려질 수 있습니다)[^6] |
| 수업당 저장              | 제한 없음                                   |
| 튼튼한 목표 당 저장         | 제한 없음                                   |
| 키 크기                | 2 KiB (2048 바이트)                        |
| 가치 크기               | 128 KiB (131072 바이트)                    |
| WebSocket 메시지 크기    | 32 MiB (받은 메시지 만)                       |
| 요구에 의하여 CPU         | 30s (WebSocket 메시지 포함)[^7]              |

[^5]: Workers에 식별[스크립트 제한](/workers/platform/limits/).

[^6]: Durable Objects는 기가 바이트에 근거를 둔 계산서 및 측정 저장 둘 다<br />(1 GB = 1,000,000,000 바이트) 과 gibibyte (GiB).<br />

[^7]: 각 수신 HTTP 요청 또는 WebSocket*이름 \**&#xB098;머지 사용 가능한 CPU 시간을 30 초로 재설정합니다. 이것은 각 들어오는 네트워크 요구 후에 compute의 30 초까지 소비하는 튼튼한 목표가, 타이머를 다시 놓는 각 새로운 네트워크 요구와 더불어 허용합니다. 들어오는 네트워크 요청에 비해 30 초 이상 소비하는 경우, 개별 내구성 개체가 evicted 및 재설정되는 고도화 된 기회가 있습니다. 요청에 따라 CPU 시간[증가할 수 있습니다.](/durable-objects/platform/limits/#can-i-increase-durable-objects-cpu-limit).
