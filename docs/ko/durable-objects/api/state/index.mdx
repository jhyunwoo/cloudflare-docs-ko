### `blockConcurrencyWhile`

`blockConcurrencyWhile`콜백이 완료 될 때까지 다른 이벤트를 차단하면서 async 콜백을 실행합니다. 이 방법은 주문 및 동시 요청을 방지합니다. 콜백 자체의 일부로 명시되지 않은 모든 이벤트는 차단됩니다. 콜백이 완료되면 다른 모든 이벤트가 전달됩니다.

- `blockConcurrencyWhile`일반적으로 어떤 요청이 전달되기 전에 발생하기 위해 내구성 개체 클래스의 생성자 내에서 사용됩니다.
- 또 다른 사용 사례는 executing`async`현재 상태에 기반을 둔 작업 내구성 개체 및 사용`blockConcurrencyWhile`이벤트 루프를 산출하는 동안 변화에서 그 상태를 방지하기 위해.
- 콜백이 예외를 던지면 객체가 종료되고 재설정됩니다. 이 객체는 예기치 않은 상태에 갇힐 수 없다는 것을 보증합니다.
- 이 행동을 방지하려면 콜백의 몸을 닫습니다.`try...catch`예외를 끊을 수 없습니다.

mitigate deadlocks 호출을 실행할 때 적용된 30 초 timeout이 있습니다. 이 타임 아웃이 초과되면, 튼튼한 개체가 재설정됩니다. 콜백을 가지고있는 가장 좋은 연습은 전반적인 요청 처리량을 내구성 객체로 향상시킬 수 있기 때문에 약간의 작업입니다.

:::노트\[사용시`blockConcurrencyWhile`]

제품 정보`blockConcurrencyWhile`어떤 요청이 처리되기 전에 schema migrations 또는 initialize 상태를 실행하는 constructor. 이것은 당신의 튼튼한 목표를 완전히 취급하기 전에 준비합니다.

자주 묻는 질문(FAQ)`blockConcurrencyWhile`. SQLite 저장 가동은 동시이고 사건 반복을 산출하지 않습니다, 그래서 그들은 그것 없이 atomically 실행합니다. 비동기 KV 저장 가동을 위해, 입력 문은 이미 저장 통화 도중 interleaving에서 다른 요구를 방지합니다.

【특전】`blockConcurrencyWhile`외부 async 호출을 만드는 경우의 구성자 외부 (예 :`fetch()`) 및 이벤트 루프 수율 동안 국가 변경을 허용 할 수 없습니다.

:::

### `acceptWebSocket`

`acceptWebSocket`의 일부[웹소켓 Hibernation API](/durable-objects/best-practices/websockets/#websocket-hibernation-api)WebSockets가 연결되는 동안 비용을 절약하기 위해 메모리에서 제거 할 수있는 튼튼한 개체를 허용합니다.

`acceptWebSocket`WebSockets 의 설정에 WebSockets 을 추가합니다. 호출되면, 어떤 들어오는 메시지는 튼튼한 개체의 호출에 의해 전달됩니다`webSocketMessage`핸들러 및`webSocketClose`연결될 것입니다. 호출 후`acceptWebSocket`WebSocket은 받아들여지고 있습니다.`send`·`close`사용 방법.

더 보기[웹소켓 Hibernation API](/durable-objects/best-practices/websockets/#websocket-hibernation-api)표준의 장소[웹소켓 API](/workers/runtime-apis/websockets/). 그러므로,`ws.accept`별도로 호출되지 않은`ws.addEventListener`대신 튼튼한 개체에 전달 될 것 처럼 이벤트를받지 않습니다.

WebSocket Hibernation API는 최대 32,768 WebSocket 연결을 허용하지만 주어진 워크로드의 CPU 및 메모리 사용은 동시 연결의 실용적인 수를 제한 할 수 있습니다.

#### 매개 변수

- 자주 묻는 질문`WebSocket`이름 \*`ws`.
- 선택 사항`Array<string>`관련 태그. 태그를 통해 WebSockets 검색에 사용할 수 있습니다[`DurableObjectState::getWebSockets`](/durable-objects/api/state/#getwebsockets). 각 태그는 최대 256 문자이며 WebSocket과 관련된 대부분의 10 태그에있을 수 있습니다.

#### 반환 값

### `setWebSocketAutoResponse`

`setWebSocketAutoResponse`의 일부[웹소켓 Hibernation API](/durable-objects/best-practices/websockets/#websocket-hibernation-api)WebSockets가 연결되는 동안 비용을 절약하기 위해 메모리에서 제거 할 수있는 튼튼한 개체를 허용합니다.

`setWebSocketAutoResponse`자동 응답을 설정, 자동 응답, 모든 WebSockets에 제공된 요청에 대한 내구성 개체에 첨부. 요청이 제공 된 요청을 일치하면 자동 응답은 납세 및 침수 청구 기간에 웹 소켓없이 반환됩니다.

`setWebSocketAutoResponse`WebSockets를 하이킹없이 처리 할 수 있기 때문에 정적 핑 / 탁구 메시지를 위해 서버를 설정하는 일반적인 대안입니다.

#### 매개 변수

- 선택 사항`WebSocketRequestResponsePair(request string, response string)`WebSocket이 허용하는 경우[`DurableObjectState::acceptWebSocket`](/durable-objects/api/state/#acceptwebsocket)제공된 요청을 받을 때 제공된 응답에 자동적으로 대답하십시오. 두 요청 및 응답은 각각 2,048 문자로 제한됩니다. 매개 변수가 omitted 경우, 이전에 설정된 자동 응답 구성이 제거됩니다.[`DurableObjectState::getWebSocketAutoResponseTimestamp`](/durable-objects/api/state/#getwebsocketautoresponsetimestamp)자동 응답이 전송 된 마지막 타임스탬프를 반영합니다.

#### 반환 값
