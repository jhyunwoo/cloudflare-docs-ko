## Durable Objects 하이라이트

Durable Objects는 분배된 Stateful 확장 가능한 신청을 위한 중대한 적합을 만드는 재산이 있습니다.

**Serverless compute, 제로 인프라 관리**

- Durable Objects는 Workers런타임의 위에 건축됩니다, 그래서 그들은 정확하게 동일한 부호 (JavaScript 및 WASM) 및 유사한 기억 및 CPU 한계를 지원합니다.
- 각 튼튼한 목표는[첫 번째 액세스에서 implicitly 만든](/durable-objects/api/namespace/#get). 사용자 응용 프로그램은 그들의 수명주기와 관련이 없으며, 그들을 만들거나 파괴하지 않습니다. Durable Objects는 건강한 서버 중 migrate, 그러므로 신청은 그(것)들을 관리하는 것에 대해 걱정할 필요가 없습니다.
- 각 튼튼한 목표는 요구가 처리되고, 몇몇 초 동안 hibernating의 앞에 idle를 위해 살아있고, 신청이 할 수 있는 것을 허용하[악용 in-memory 캐싱](/durable-objects/reference/in-memory-state/)많은 연속 요청을 처리하고 성능 향상.

**compute로 colocated 저장**

- 각 내구재 목표에는 그것의 소유가 있습니다[튼튼한, 거래, 그리고 강하게 일관된 저장](/durable-objects/api/sqlite-storage-api/)(최대 10 GB[^1]), 요청에 따라 persisted, 그리고 그 객체 내에서만 접근.

**단일 스레드 concurrency**

- 각 각[튼튼한 Object 인스턴스에는 식별자가 있습니다.](/durable-objects/api/id/), 무작위로 생성하는 또는 사용자 생성하는, 내구재 목표가 특정한 활동 또는 요구를 취급해야 하는 세계적인 주소를 허용하는.
- Durable Objects는 웹 브라우저에서 실행되는 코드와 같은 단일 스레드 및 협력적 멀티 태깅입니다. 안전과 정정이 달성되는 방법에 대한 자세한 내용은 블로그 게시물 참조["Durable Objects: 쉬운, 빠른, 정확한 — 3개를 선택하십시오"](https://blog.cloudflare.com/durable-objects-easy-fast-correct-choose-three/).

**Cloudflare의 글로벌 네트워크를 통해 탄성 수평 스케일링**

- Durable Objects는 전 세계 퍼지고, 당신은 할 수 있습니다[각 인스턴스가 어디에 있는지 선택적으로 영향](/durable-objects/reference/data-location/#provide-a-location-hint). Durable Objects는 아직 각 Cloudflare 자료 센터에서 유효하지 않습니다; 참조[어디에.durableobjects.live](https://where.durableobjects.live/)사업소개
- 각 튼튼한 목표 유형 (or["Namespace 바인딩"](/durable-objects/api/namespace/)Cloudflare 용어)는 실제 논리를 구현하는 JavaScript 클래스에 해당합니다. Durable Objects가 각 네임스페이스에 생성될 수 있는 방법에 대한 하드 한계가 없습니다.
- Durable Objects 가늠자는 당신의 신청으로 신축성있게 목표의 수백만을 창조합니다. 인프라를 관리하거나 용량에 앞서 계획할 필요가 없습니다.

## Durable Objects 특징

### In-memory 상태

각 내구재 목표에는 그것의 소유가 있습니다[in-memory 상태](/durable-objects/reference/in-memory-state/). 신청은 중요한 정보 in-memory를 지키기에 의하여 그들의 신청의 성과를 낙관하기 위하여 이 in-memory 국가를 이용할 수 있습니다, 전부에 튼튼한 저장에 접근하는 필요를 피하는.

In-memory 상태에 대한 유용한 사례는 저장하기 전에 일괄 처리 및 집계 정보를 포함하거나 특정 기준을 충족하는 즉시 거부 / 처리 수신 요청을 위해 더 많은 정보를 포함합니다.

In-memory 상태는 몇몇 시간 동안 idle이기 후에 튼튼한 목표 hibernates 때 재시동합니다. 따라서, 그것은 내구성 객체가 다른 요청을받을 때 그 데이터가 나중에 필요할 경우 내구성 스토리지에 어떤 in-memory 데이터를 persist하는 것이 중요합니다.

### 저장 API

더 보기[튼튼한 목표 저장 API](/durable-objects/api/sqlite-storage-api/)Durable Objects를 사용하여 빠르고, 거래, 강력하고 일관된 스토리지에 액세스할 수 있습니다. 튼튼한 개체의 첨부 스토리지는 고유 한 인스턴스에 개인이며 다른 개체에 의해 액세스 할 수 없습니다.

스토리지 API의 두 가지 맛,[키 값 (KV) API](/durable-objects/api/legacy-kv-storage-api/)한국어[SQL API를](/durable-objects/api/sqlite-storage-api/).

사용시[Durable Objects 스토리지 백엔드의 새로운 SQLite](/durable-objects/reference/durable-objects-migrations/#enable-sqlite-storage-backend-on-new-durable-object-class-migration), 당신은 API 둘 다에 접근이 있습니다. 그러나 이전 저장소를 사용하면 키 값 API에 액세스 할 수 있습니다.

### 경보 API

Durable Objects는 제공합니다[경보 API](/durable-objects/api/alarms/)당신은 미래의 시간에 woken 할 수있는 튼튼한 개체를 일정 할 수 있습니다. 특정 작업 주기적으로 할 때 유용합니다, 또는 시간에 특정 지점에서, 수동으로 자신의 작업 스케줄링 러너와 같은 인프라를 관리하지 않고.

in-memory state와 튼튼한 스토리지 API를 결합하여 쿼리, 워크플로우 또는 고급 데이터 파이프라인과 같은 일괄 및 집계 응용 프로그램을 구축할 수 있습니다.

### 웹소켓

WebSockets는 클라이언트와 서버 간의 양방향, 실시간 통신을 가능하게 하는 오랜 TCP 연결입니다. WebSocket 세션이 긴 수명이기 때문에 일반적으로 Durable Objects를 사용하여 클라이언트 또는 서버 연결을 수락합니다.

Durable Objects는 QXQX0316XQ QXWorkersXWorkers, 단일 내구성 오브젝트 인스턴스가 채팅 룸 또는 멀티 플레이어 게임 참가자와 같은 여러 클라이언트와 WebSockets와 평행으로 사용될 수 있기 때문에 Durable ObjectsXQXQXQXQ는 단일 지점 조정을 제공합니다.

Durable Objects 지원[WebSocket 표준 API](/durable-objects/best-practices/websockets/#websocket-standard-api), 뿐 아니라[웹소켓 Hibernation API](/durable-objects/best-practices/websockets/#websocket-hibernation-api)WebStandard WebSocket API를 확장하여, Inactivity 기간 동안 청구 수수료가 부과되지 않습니다.

### 사이트맵

Durable Objects 지원 Workers[원격 관리 (RPC)](/workers/runtime-apis/rpc/)JavaScript-native 메소드와 객체를 사용하여 Workers 및 Durable ObjectsXQ와 통신할 수 있습니다.

통신을 위한 RPC 사용은 신청 발달을 더 쉽고 간단한 이유에 관하여, 그리고 능률 더 만듭니다.

## Actor 프로그래밍 모델

Durable Objects에 대해 설명하고 생각하는 또 다른 방법은 렌즈를 통해[Actor 프로그래밍 모델](https://en.wikipedia.org/wiki/Actor_model). 런타임 또는 라이브러리 프레임워크를 통해 프로그래밍 언어 수준에서 지원하는 Actor 모델의 몇 가지 인기있는 예가 있습니다.[한국어](https://www.erlang.org/), [언어 선택](https://elixir-lang.org/), [아카](https://akka.io/), 또는[.NET에 대한 Microsoft Orleans](https://learn.microsoft.com/en-us/dotnet/orleans/overview).

Actor 모델은 모든 운송 프로토콜의 위에 구현 될 수있는 RPC 통화 (또는 메시지 전송)를 사용하여 배우 간의 통신을 초래하여 분산 시스템에서 많은 문제를 단순화하고, 여러 프로세스 / 스레드가 동일한 데이터 in-memory에 액세스 할 때 경주 조건과 같은 공유 메모리를 통해 concurrency 할 때 얻을 수 concurrency pitfalls의 대부분을 피합니다.

각 튼튼한 개체 인스턴스는 Actor 인스턴스로 볼 수 있으며, 메시지 수신 (HTTP/RPC 요청 수신), 첨부 된 내구성 스토리지 또는 메모리 상태를 사용하여 자신의 단일 스레드 컨텍스트에서 일부 로직을 실행하고, 마지막으로 외부 세계에 메시지를 전송 (HTTP/RPC 요청 또는 응답), 심지어 다른 튼튼한 개체 인스턴스.

각 튼튼한 목표에는 점에 있는 특정 기능이 있습니다[그것을 할 수있는 방법](/durable-objects/platform/limits/#how-much-work-can-a-single-durable-object-do)응용 프로그램의 영향을 받아야하는 ,[완전히 플랫폼의 장점을 가지고 아키텍처](/reference-architecture/diagrams/storage/durable-object-control-data-plane-pattern/).

Durable Objects는 기본적으로 Cloudflare의 인프라로 통합되어 Cloudflare의 네트워크 전체를 분산시키는 분산된 최신 애플리케이션을 구축하는 궁극적인 서버리스 플랫폼을 제공합니다.
