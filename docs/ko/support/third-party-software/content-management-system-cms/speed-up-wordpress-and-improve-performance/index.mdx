Cloudflare의 CDN 서비스는 우리의 거대한 세계적인 네트워크의 맞은편에 당신의 내용을 캐시할 수 있습니다, 그러나 성과는 당신의 방문자에 가까운 이동하는 정체되는 파일에 관하여 다만 아닙니다. Cloudflare는 CDN, CloudflareXQ의 최적화 기능을 제공하므로 전통적인 CDN이 할 수있는 것보다 WordPress 사이트의 성능을 향상시킬 수 있습니다.

### Caching 익명 페이지 조회

![익명 페이지의 캐시 규칙 만들기.](~/assets/images/support/hc-import-screen_shot_2017_03_09_at_16_54_36_1_.png)

Cloudflare의 "[Bypass 캐시 에 Cookie](/cache/how-to/cache-rules/examples/bypass-cache-on-cookie/)"기능은 CloudflareXQ에 의해 완전히 캐시 된 페이지를 기록 할 수 있습니다. 이것은 서버가 HTML이 효과적으로 정적 인 페이지를 재생하지 않고 시간 및 리소스를 저장할 수 있다는 것을 의미합니다. 동적 행동과 방해하지 않는 것은 WordPress 대시보드XQXQXQ에 사용자가 로그 인 한 후, Edge 캐시는 우회됩니다.

### Optimise 이미지

이미지는 페이지 짐 시간에 믿을 수 없을 것입니다; 다행히, Cloudflare는 극적으로 이미지 짐 시간을 개량할 수 있습니다. QXQX0002XQQ 대시보드에서 이러한 기능을 찾을 수 있습니다.**제품 정보** > **계정 설정** > **이미지 최적화**.

사용 후[**담당자: Ms.**](/images/polish/), 당신은 극적으로 이미지를 압축하고 metadata를 벗기는 이미지와 웹 페이지 짐 시간을 개량할 수 있습니다. Lossless는 대부분의 메타 데이터를 스트립합니다 (`EXIF`data, 예를 들어) 하지만 이미지 세부 사항을 변경하지 않습니다. Lossy는 대부분의 메타 데이터를 스트립하고 약 48 %의 이미지를 압축합니다.

### HTTP/2 사용

**HTTP / 2의**Multiplexing, Header Compression 등 다양한 성능 기능을 제공합니다. WordPress 사이트에서 HTTP / 2를 활성화하려면 사이트가 HTTPS로로드된다는 것을 확인하십시오.

이름 \***SSL 활성화**또한 사용자가 HTTP / 2 이상 로드 할 수 있도록 HTTPS 버전으로 리디렉션됩니다. 이 작업을 수행 할 수 있습니다*항상 HTTPS를 사용* **페이지 규칙**:

![Wordpress 웹 사이트를 보장하기 위해 페이지 규칙을 작성하면 HTTP / 2개](~/assets/images/support/hc-import-screen_shot_2016_09_30_at_15_34_14.png)

Cloudflare의**WordPress 플러그인**필요한 자산을 HTTP / 2 Server Push를 사용하여 사용자에게 밀어 낼 수 있으므로 CSS 및 JavaScriptXQ를로드해야합니다. 더 알아보기[WordPress에서 HTTP / 2 서버 푸시를 활성화하는 방법](https://developers.cloudflare.com/support/third-party-software/content-management-system-cms/how-do-i-enable-http2-server-push-in-wordpress/)설정에 대한 튜토리얼.

### Minify 자산

Grunt 또는 Gulp를 빌드 프로세스의 일부로 사용하는 경우 빌드에서 축소를 구현할 수 있습니다.

HTTP / 2 다중화 요청으로 인해 CSS 또는 JavaScript 파일을 concatenating 또는이 작업을 수행 할 수있는 서버에서 아무것도 설치에 대해 조언합니다.
