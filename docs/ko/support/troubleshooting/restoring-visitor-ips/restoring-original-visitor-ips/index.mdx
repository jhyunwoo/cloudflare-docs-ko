## 아파치 모듈 mod remoteip

Cloudflare 더 이상 업데이트 및 지원*mod cloudflare는*그러나 Apache 웹 서버를 사용하여 운영 체제와 같은 경우**우분투 서버 18.04**·**데비안 9 스트레치**, 당신은 사용할 수 있습니다*아파치 모듈 mod remoteip*방문자의 원래 IP 주소를 로그.

**이 모듈은 외부 파티에 의해 만들어졌으며 플러그인과 관련된 문제에 대한 기술 지원을 제공하지 않습니다.**

설치하기*아파치 모듈 mod remoteip*Apache 웹 서버에서:

1. 이름 \**아파치 모듈 mod remoteip*다음 명령을 발급함으로써:

```sh
sudo a2enmod remoteip
```

2. 사이트 구성 업데이트*RemoteIPHeader CF 연결 IP*, 예를들면`/etc/apache2/sites-available/000-default.conf`

```
ServerAdmin webmaster@localhost
DocumentRoot /var/www/html
ServerName remoteip.andy.support
RemoteIPHeader CF-Connecting-IP
ErrorLog ${APACHE_LOG_DIR}/error.log
CustomLog ${APACHE_LOG_DIR}/access.log combined
```

3. 결합된 업데이트*로그인*이름 \*`apache.conf`, 교체*100%년*이름 \**%a에서* `/etc/apache2/apache2.conf.`예를 들어, 현재*로그인*다음과 같이

```
LogFormat "%h %l %u %t \"%r\" %>s %O \"%{Referer}i\" \"%{User-Agent}i\"" combined
```

업데이트*로그인*다음으로:

```
LogFormat "%a %l %u %t \"%r\" %>s %O \"%{Referer}i\" \"%{User-Agent}i\"" combined
```

4. 신뢰할 수있는 프록시 주소를 정의`/etc/apache2/conf-available/remoteip.conf`다음 코드를 입력하고[Cloudflare의 IP](https://www.cloudflare.com/ips/):

```
RemoteIPHeader CF-Connecting-IP
RemoteIPTrustedProxy 192.0.2.1 (example IP address)
RemoteIPTrustedProxy 192.0.2.2 (example IP address)
(repeat for all Cloudflare IPs listed at https://www.cloudflare.com/ips/)
```

5. Apache 설정 활성화:

```sh
sudo a2enconf remoteip
```

```sh output
Enabling conf remoteip.
To activate the new configuration, you need to run:
service apache2 reload
```

6. Apache 설정 테스트:

```sh
sudo apache2ctl configtest
```

```sh output
Syntax OK
```

7. 아파치 재시작:

```sh
sudo systemctl restart apache2
```

### 설치하기

Apache 웹 서버를 사용하는 경우 mod cloudflare를 다운로드할 수 있습니다.[프로젝트](https://github.com/cloudflare/mod_cloudflare).

#### 소스 웹 서버에 코드를 추가

mod cloudflare를 설치할 수 없는 경우, 또는 콘텐츠 관리 시스템 플랫폼에서 사용 가능한 Cloudflare 플러그인이 없는 경우, 원본 방문자 IP를 복원할 수 있는 경우, 이 코드를 원래 웹 서버로 추가하거나 이전하기 전에`<body>`원본 방문자 IP를 필요로하는 페이지에 태그:

```php
<?php if (isset($_SERVER['HTTP_CF_CONNECTING_IP'])) $_SERVER['REMOTE_ADDR'] = $_SERVER['HTTP_CF_CONNECTING_IP'];?>
```

이 명령은 필요한 스크립트에 사용할 수있는 IP 주소를 만들 것입니다. 실제 서버 로그에 IP를 저장하지 않습니다.

### 제거하기

#### 아파치

제거하기*mod cloudflare는*, 아파치 설정 줄을 읽어야 합니다.*mod cloudflare는*.

이것은 리눅스 배포에 따라 다르지만 대부분의 사람들이 볼 경우`in /etc/apache2`, 당신은 선을 찾기 위해 검색 할 수 있어야합니다 :

`LoadModule cloudflare_module`

이 줄을 읽거나 제거하면 apache를 재시작하고*mod cloudflare는*갔다.

Ubuntu 또는 Debian을 실행하면 볼 수 있습니다.

`file/etc/apache2/mods-enabled/cloudflare.load`

이 파일을 삭제*mod cloudflare는*아파치를 다시 시작한다.

#### 사이트맵

*mod cloudflare는*Nginx는 필요하지 않습니다. 사용 방법[`ngx_http_realip_module`NGINX 모듈](http://nginx.org/en/docs/http/ngx_http_realip_module.html)그리고 설정 파라미터는[웹 서버 지침](https://developers.cloudflare.com/support/troubleshooting/restoring-visitor-ips/restoring-original-visitor-ips/#web-server-instructions)대신.

   - 빨간 모자/Fedora/Debian/Ubuntu:`apxs -a -i -c mod_cloudflare.c`
4. Restart와 확인 모듈은 활성:
   - 빨간 모자/Fedora`service httpd restart; httpd -M|grep cloudflare`

```
IfModule cloudflare_module
CloudFlareRemoteIPHeader X-Forwarded-For
CloudFlareRemoteIPTrustedProxy [insert your load balancer’s IP address]
DenyAllButCloudFlare
/IfModule
```

### 사이트맵

Lighttpd가 자동으로 액세스 로그 및 응용 프로그램에 대한 서버 IP를 다시 작성하려면 아래 두 가지 솔루션 중 하나를 따를 수 있습니다.

1. 자주 묻는 질문**엠에디터 매크로 참조:lighttpd.conf**파일 및 추가*mod extforward 지시어*이름 \**서버.modules*이름 \* 그것은 온다**후에** *아파치 모듈 mod accesslog*액세스 로그에서 실제 IP 표시
2. 다음 코드를 추가하십시오.**엠에디터 매크로 참조:lighttpd.conf**서버 모듈 목록 후에 파일을 다시 시작 Lighttpd

```
$HTTP["remoteip"] == "192.2.0.1 (example IP address)"
{
extforward.forwarder = ( "all" => "trust" )
extforward.headers = ("CF-Connecting-IP")
}
```

:::참조

소스가 IPv6로 인터넷에 연결하면
**$HTTP\["remoteip"]**&#xB9AC;모트 IP 일치를 위해 요구되는 ,
범위는 IPv6가 활성화되면 작동하지 않습니다. 위의 방법을 사용하여
IP 범위를 전달하려고 할 때 작동하지 않습니다. 다음 줄을 추가하여
lighttpd.conf의 대안 솔루션:
`extforward.forwarder = ( "all" => "trust" ) extforward.headers = ("CF-Connecting-IP")`

### 톰캣 7


이처럼 보이는 로그에서 어떤 결과가:

### 언어 선택

호스팅 제어판 VestaCP를 사용하는 경우 서버에서 Nginx와 Apache 둘 다 있습니다. 요청은 Apache로 이동하기 전에 Nginx를 통해 proxied.

이 Nginx 프록시 때문에 실제로 Nginx를 구성하는 지침을 따라 실제 방문자 IP 주소를 반환해야합니다.[아파치 모듈 mod remoteip](https://httpd.apache.org/docs/2.4/mod/mod_remoteip.html)아파치는 Nginx 서버가 일부 요청을 비활성화하지 않는 한 필요하지 않습니다. 더 보기[아파치 모듈 mod remoteip](https://httpd.apache.org/docs/2.4/mod/mod_remoteip.html)Apache는 Nginx 서버 구성과 충돌하지 않습니다.

### 다운로드

X FORWARDED FOR 헤더에서 원래 클라이언트 IP를 추출하려면 HAProxy의 다음 구성을 사용해야합니다.

1. 텍스트 파일 만들기`CF_ips.lst`모든 IP 범위를 포함[모델 번호: https://www.cloudflare.com/en-gb/ips/](https://www.cloudflare.com/en-gb/ips/)
2. 비활성화`option forwardfor`HAProxy에서

HAProxy 설정:

```
acl from_cf src -f /path/to/CF_ips.lst
acl cf_ip_hdr req.hdr(CF-Connecting-IP) -m found
http-request set-header X-Forwarded-For %[req.hdr(CF-Connecting-IP)] if from_cf cf_ip_hdr
```

### Envoy 게이트웨이

Envoy Gateway에 대한 원래 클라이언트 IP를 추출하려면, 설정[고객 교통 정책](https://gateway.envoyproxy.io/latest/tasks/traffic/client-traffic-policy/#configure-client-ip-detection)사용자 정의[`CF-Connecting-IP`기타 제품](/fundamentals/reference/http-headers/#cf-connecting-ip).

```txt title="Truncated Client Traffic Policy example"
clientIPDetection:
    customHeader:
        name: CF-Connecting-IP
        failClosed: true
```

더 자세한 내용은 참조[주문 헤더 원본 IP 탐지 연장](https://www.envoyproxy.io/docs/envoy/latest/api-v3/extensions/http/original_ip_detection/custom_header/v3/custom_header.proto).

### 카테고리

응용 프로그램을 실행하는 경우[카테고리](https://caddyserver.com/)그것은에 의존`X-Forwarded-For`헤더, Cloudflare의 헤더를 override하는 Caddy를 구성할 수 있습니다.[CF-Connecting-IP 헤더](/fundamentals/reference/http-headers/#cf-connecting-ip).

그것은 당신이 또한 트래픽을 받아 들인 것을 조언합니다[Cloudflare의 IP 주소](https://www.cloudflare.com/ips/); 그렇지 않으면, 우두머리는 spoofed 일 수 있었습니다. 즉, 두 번째 예에서, 우리는 Caddy 구성의 일부로 이것을 처리합니다. 또는 방화벽 수준에서 이것을 처리 할 수 있습니다. 일반적으로 자동화가 쉽습니다. 이미 방화벽 또는 다른 측정이 있는 경우, Caddyfile은 다음과 같이 보일 수 있습니다.

```txt title="Caddyfile"
https://example.com {
    reverse_proxy localhost:8080 {
				# Sets X-Forwarded-For as the value Cloudflare gives us for CF-Connecting-IP.
				header_up X-Forwarded-For {http.request.header.CF-Connecting-IP}
		}
}
```

Caddy를 선택하면 트래픽 만 허용[Cloudflare의 IP 주소](https://www.cloudflare.com/ips/), 당신은 이 것 같이 윤곽을 사용할 수 있습니다:

```txt title="Caddyfile"
https://example.com {
    # Restrict access to Cloudflare IPs (https://www.cloudflare.com/ips/)
    @cloudflare {
        remote_ip 173.245.48.0/20 103.21.244.0/22 103.22.200.0/22 103.31.4.0/22 141.101.64.0/18 108.162.192.0/18 190.93.240.0/20 188.114.96.0/20 197.234.240.0/22 198.41.128.0/17 162.158.0.0/15 104.16.0.0/13 104.24.0.0/14 172.64.0.0/13 131.0.72.0/22 2400:cb00::/32 2606:4700::/32 2803:f800::/32 2405:b500::/32 2405:8100::/32 2a06:98c0::/29 2c0f:f248::/32
    }

    # Process requests from Cloudflare IPs
    handle @cloudflare {
        reverse_proxy localhost:8080 {
            # Sets X-Forwarded-For as the value Cloudflare gives us for CF-Connecting-IP.
            header_up X-Forwarded-For {http.request.header.CF-Connecting-IP}
        }
    }

    # Deny requests from non-Cloudflare IPs
    handle {
        respond "Access Denied" 403
    }
}
```
