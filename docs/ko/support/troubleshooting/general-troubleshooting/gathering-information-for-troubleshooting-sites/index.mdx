## 브라우저 기반 문제 해결

이 도구는 웹 브라우저에서 직접 캡처 정보를 캡처하고 페이지로드 및 렌더링과 진단 문제에 유용합니다.

### HAR 파일을 생성

:::tip\[이용시]
당신이 경험할 때 HAR 파일을 사용하십시오**시각적 문제, 깨진 페이지 요소, 느린 페이지로드, 또는 HTTP 요청의 전체 순서를 캡처해야합니다**당신의 브라우저에 의해. 이것은 종종 첫 번째 것은 Cloudflare 지원 요청됩니다.
주요 특징

HTTP Archive (HAR)는 요청 및 응답 헤더, 신체 콘텐츠 및 페이지로드 시간을 포함한 모든 웹 브라우저 요청을 기록합니다. Incognito Mode 또는 Private Browsing window를 사용해야 합니다.

:::카트로션

HAR 파일은 비밀번호, 결제와 같은 민감한 정보를 포함 할 수 있습니다.
정보 및 개인 키.

민감한 정보를 제거[HAR 소독기](https://har-sanitizer.pages.dev/).

보안상의 이유로 Cloudflare 지원은 ZIP, GZIP, TAR 등과 같은 압축 파일을 열 수 없습니다.
주요 특징

일부 브라우저는 브라우저 확장을 요구하거나 HAR를 생성 할 수 없습니다. 브라우저 확장을 설치할 때 확장 업체의 지시를 따르십시오.

### 수출 콘솔 로그

:::tip\[이용시]
경험할 때 콘솔 로그 사용**JavaScript 오류, CORS 문제 또는 요청이 브라우저에 의해 차단되거나 취소 될 때**. HAR 파일에 나타나지 않을 수 있는 브라우저 측 오류를 캡처합니다.
주요 특징

요청시 특정 상황에서는 브라우저에 의해 발행되거나 취소되지 않습니다 (예를 들면, 때문에[사이트맵](https://developer.mozilla.org/en-US/docs/Glossary/CORS)), 우리는 JS 콘솔 로그 출력을 얻을 필요가, HAR 파일 이외에, 루트 원인을 식별.

#### 크롬에서

1. 오시는 길**회사 소개**DevTools 바에서 탭.
2. 콘솔 설정으로 이동하고 선택**공지사항**.
3. 콘솔을 열고 문제를 reproduce하는 단계를 수행하십시오.
4. 모든 항목에 마우스 오른쪽 버튼**회사 소개**탭 및 선택**구매하기**로그 파일.
5. 지원 티켓에 로그 파일을 첨부합니다.

![Chrome의 개발자 도구에서 콘솔 탭을 찾는 방법.](~/assets/images/support/console_snapshot.png)

#### Firefox에서

1. 오시는 길**회사 소개**웹 개발자 도구 모음에서 탭.
2. 콘솔 설정으로 이동하고 선택**Persist 로그인**·**쇼 Timestamps**.
3. 콘솔을 열고 문제를 reproduce하는 단계를 수행하십시오.
4. 오른쪽 클릭,**모두 보기**메시지 및**파일로 내보내기 Visible Messages**.
5. 지원 티켓에 로그 파일을 첨부합니다.

#### Microsoft Edge에서

1. 오시는 길**회사 소개**개발자 도구 모음에서 탭.
2. 콘솔 설정으로 이동하고 선택**공지사항**.
3. 콘솔을 열고 문제를 reproduce하는 단계를 수행하십시오.
4. 오른쪽에서 아이템을 클릭**회사 소개**탭 및 선택**구매하기**로그 파일.
5. 지원 티켓에 로그 파일을 첨부합니다.

#### Safari에서

1. 오시는 길**회사 소개**웹 검사기 바에서 탭.
2. Tick 상자**공지사항**.
3. 콘솔을 열고 문제를 reproduce하는 단계를 수행하십시오.
4. 모든 메시지, 오른쪽 클릭 및 선택**선택 사항**로그 파일에.
5. 지원 티켓에 로그 파일을 첨부합니다.

### NetLog 덤프 캡처

:::tip\[이용시]
경험할 때 NetLog 덤프를 사용하십시오.**프로토콜 수준 오류**등`ERR_QUIC_PROTOCOL_ERROR`또는`ERR_HTTP2_PROTOCOL_ERROR`. 이것은 HAR 파일 캡처를 넘어가는 상세한 네트워크 수준 디버깅 정보를 제공합니다.
주요 특징

몇 가지 경우, 프로토콜과 관련된 문제 해결 문제 (errors such as`ERR_QUIC_PROTOCOL_ERROR`, `ERR_HTTP2_PROTOCOL_ERROR`, 등.) 우리의 지원 팀은 당신에게 제공할 것을 요구할지도 모릅니다[NetLog 덤프](https://www.chromium.org/for-testers/providing-network-details/).

:::카트로션

Google Chrome, Opera 또는 Microsoft Edge 브라우저에서 NetLog 만 생성 할 수 있습니다.
주요 특징

1. 새 탭을 열고 사용중인 브라우저에 따라 다음을 입력하십시오.

- `chrome://net-export`
- `edge://net-export`
- `opera://net-export`

2. 자주 묻는 질문**Disk 로깅 시작**버튼.
3. 다른 탭에서 네트워크 문제를 해결합니다.
   (대)`chrome://net-export/`, `edge://net-export/`또는`opera://net-export`탭은 다른 로깅을 자동적으로 유지해야합니다.
4. 이름 \***관련 링크**버튼.
5. 지원 티켓에 로그 파일을 첨부합니다.

## 명령행 문제 해결

이 도구는 터미널 또는 명령 프롬프트에서 실행되며 브라우저 오버 헤드없이 연결, 성능 및 서버 응답을 테스트하는 데 유용합니다.

### Cloudflare 데이터 센터를 식별

:::tip\[이용시]
당신이 필요로 할 때 이것을 사용하십시오**Cloudflare 포인트 (PoP)가 요청하는 것을 결정합니다.**. 지역 문제 해결 또는 트래픽 라우팅 확인이 도움이 됩니다.
주요 특징

[데이터 센터 지도](https://www.cloudflare.com/network-map)본문 바로가기[Cloudflare 상태 페이지](https://www.cloudflarestatus.com/), 대륙에 의해 분류.
데이터 센터 이름에 있는 3-letter 부호는 입니다[IATA 코드](http://en.wikipedia.org/wiki/IATA_airport_code)가장 가까운 주요 국제 공항.
Cloudflare 데이터 센터는 브라우저에 대한 요청을 방문:
`http://``_www.example.com_``/cdn-cgi/trace.`

기타 제품`www.example.com`도메인 및 호스트 이름. 이름 \*`colo`산출에서 분야.

### 컬을 가진 문제 해결 요구

:::tip\[이용시]
당신이 필요로 할 때 컬을 사용하십시오**브라우저 방해없이 HTTP 요청 테스트**, 측정 성능 메트릭, HTTP 헤더를 확인, 또는 문제가 Cloudflare 또는 원산지 서버에서 시작했는지 결정.
주요 특징

[컬럼](https://curl.se/)HTTP/HTTPS 요청을 전송하는 명령줄 도구이며 문제 해결에 유용합니다.

- HTTP/HTTPS 성능
- HTTP 오류 응답
- HTTP 헤더
- API를
- Server/Proxy 응답 비교
- SSL 인증서

:::참조

Windows를 사용하는 경우 Windows에서 컬을 사용하는 방법에 대한 자세한 내용을 찾을 수 있습니다.[Windows에서 API 호출 만들기
](/fundamentals/api/how-to/make-api-calls/#making-api-calls-on-windows)기사.
주요 특징

다음 명령을 실행하여 표준 HTTP GET 요청을 웹 사이트 (replace`www.example.com`호스트 이름:

```
curl -svo /dev/null http://www.example.com/
```

이 예제 curl 명령은 HTTP 응답과 요청 헤더를 상세히 표시하지만 페이지 본문 출력을 무시합니다. 컬 산출은 HTTP 응답을 확인하고 Cloudflare가 현재 위치에 대한 프록시 트래픽을 확인합니다.

:::참조

자주 묻는 질문[curl 명령 옵션](https://curl.se/docs/manpage.html)추가 기능.
주요 특징

HTTP 오류, 성능, 캐싱 및 SSL/TLS 인증서의 문제 해결에 대한 팁 아래 섹션을보십시오:

#### HTTP 오류

### CF-RAY 헤더를 로그에 추가

:::tip\[이용시]
당신이 필요로 할 때 이것을 사용하십시오**Cloudflare의 로그와 특정 요청을 correlate**문제 해결. CF-RAY 헤더는 Cloudflare의 네트워크를 통해 각 요청을 고유하게 식별하고 지원 조사에 필수적입니다.
주요 특징

더 보기**CF 레이**헤더는 Cloudflare의 네트워크를 통해 웹 사이트 요청을 추적합니다. 제품정보**CF 레이**CloudflareXQ 지원에 웹 요청의 문제 해결. 또한 추가할 수 있습니다.**CF 레이**웹 서버의 브랜드에 대응하는 아래 스니펫로 웹 서버 구성을 편집하여 로그에:

#### Apache 웹 서버에서 추가`%{CF-Ray}i`LogFormat 정보

```
LogFormat "%h %l %u %t \"%r\" %>s %b \"%{Referer}i\" \"%{User-agent}i\" %{CF-Ray}i" cf_custom
```

#### Nginx 웹 서버에서 log format에 '$http cf ray' 추가

```
log_format cf_custom '$remote_addr - $remote_user [$time_local] '
'"$request" $status $body_bytes_sent '
'"$http_referer" "$http_user_agent" '
'$http_cf_ray';
```

### MTR 실행

:::tip\[이용시]
당신이 필요로 할 때 사용 MTR**traceroute 보다는 더 상세한 네트워크 진단은 제공합니다**. MTR은 traceroute와 ping을 결합하여 각 홉에서 실시간 대기 시간 및 패킷 손실을 보여주며 간헐적인 네트워크 문제를 쉽게 식별할 수 있습니다.
주요 특징

My Traceroute (MTR)는[제품정보](https://www.cloudflare.com/learning/network-layer/what-is-mtr/)traceroute와 ping을 결합하여 네트워크 연결성 및 속도를 테스트하는 다른 일반적인 방법인 네트워크 경로의 건강을 측정합니다. 네트워크 경로에 따라 홉 외에도 MTR은 목적지에 따라 지연 및 패킷 손실에 대한 정보를 지속적으로 업데이트합니다. 이것은 네트워크 문제를 해결하는 데 도움이됩니다. 실시간 경로에 따라 일어나는 것을 볼 수 있습니다.

MTR은 트레잇 루트와 유사한 방식으로 네트워크 경로를 발견하여 정기적으로 패킷을 전송하여 네트워크의 건강과 속도를 업데이트하는 정보를 수집합니다.

traceroute와 같이, MTR는 나가는 소포를 위한 ICMP 또는 UDP를 사용할 수 있습니다 그러나 반환 (유형 11를 위한 ICMP에 의존합니다: 시간 초과하는) 소포.

:::참조

MacOS 사용자를 위해, MTR는 설치될 수 있습니다[홈 양조장](https://formulae.brew.sh/formula/mtr)·
Windows 사용자를 위해, 보기[계정 관리](https://github.com/White-Tiger/WinMTR/releases).
:::

#### 어떻게 MTR을 사용하여 네트워크 경로 보고서를 생성합니까?

**NIX 기반 기계에 MTR 사용**

일반적으로, 우리는 다음과 같이 MTR를 이용합니다:

```sh
mtr -rw <dest_hostname> e.g.: mtr -rw one.one.one.one
```

또는 대상 IP:

```sh
mtr -rw <dest_IP> e.g.: mtr -rw 1.1.1.1
```

TCP 포트

```sh
mtr -P <tcp port> -T <destination ip>
```

이 문서를 참조하시기 바랍니다, 이는 MTR 분석에 대해 더 많은 설명:[MTR을 읽는 방법](https://www.cloudflare.com/en-gb/learning/network-layer/what-is-mtr/).

### Packet 캡처 실행

:::tip\[이용시]
경험할 때 패킷 캡처 사용**연결 재설정, 패킷 손실, SSL 핸즈크 실패, 또는 520, 524 및 525 같은 HTTP 오류**. 이 문제는 층 3/4에서 발생하고 깊은 패킷 레벨 분석을 필요로 HTTP 로그에 나타나지 않습니다.
주요 특징

레이어 3/4에서 발생하는 문제는 Cloudflare의 로깅 시스템에 도달하기 전에 발생하므로 HTTP 로그에 표시하지 않습니다. 따라서 연결 리셋, 패킷 손실 또는 SSL 핸디케이크 실패와 관련된 문제 해결은 패킷 수준에서 깊은 조사없이 까다로울 수 있습니다.

CloudflareXQ에 의해 생성된 몇몇 HTTP 과실[50대](/support/troubleshooting/http-status-codes/cloudflare-5xx-errors/error-520/), [524년대](/support/troubleshooting/http-status-codes/cloudflare-5xx-errors/error-524/)·[525년대](/support/troubleshooting/http-status-codes/cloudflare-5xx-errors/error-525/), 층 3/4에 underlying 문제점을 보여주고, 더 조사를 위한 소포 붙잡음을 요구할지도 모릅니다.

**패킷 캡처를 실행하는 방법**

:::카트로션

자주 묻는 질문
패킷 캡처 실행, 그것은 기록 될 것입니다.
주요 특징

Cloudflare 제안[채용정보](https://www.wireshark.org/download.html)패킷 캡처를 실행합니다. 사용법*뚱 베어*명령 줄, 참조[이름 \*](https://www.wireshark.org/docs/wsug_html_chunked/AppToolstcpdump.html)기사.

1. 모든 프로그램/브라우저 탭을 닫아 배경에 데이터를 전송할 수 있는 많은 디스플레이 필터를 사용 하 여 나중에.
2. Wireshark 캡처 필터 생성 (refer to[이름 \*](https://wiki.wireshark.org/CaptureFilters)더 많은 정보를 위한 기사).
3. 적절한 인터페이스를 선택하십시오 (예 : Wi-Fi : en0). 어떤 인터페이스를 사용할지 모르겠다면, Wireshark는 각 인터페이스의 I/O 그래프를 제공합니다.
4. 왼쪽 상단의 파란색 상어 핀 아이콘을 클릭하여 패킷 캡처를 시작합니다.
5. 캡처를 실행하는 동안 문제를 해결합니다.
6. 왼쪽 상단 모서리에 빨간색 광장 아이콘을 클릭하여 패킷 캡처를 중지하십시오.
7. 구매하기`.pcap`파일 및 지원 티켓에 첨부합니다.
