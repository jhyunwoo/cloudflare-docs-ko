## 429 너무 많은 요청

더 보기`429 Too Many Requests`상태 코드는 클라이언트가 서버의 비율 제한 규칙에 의해 결정된대로 지정된 시간의 지정된 양에 너무 많은 요청을 보냈습니다. 서버는 포함될 수 있습니다`Retry-After`클라이언트가 다시 시도 할 때 지정하는 응답의 헤더.

더 자세한 내용은 참조[RFC 6585년](https://tools.ietf.org/html/rfc6585).

### 일반적인 사용 사례

Servers는 시스템의 과도한 API 요청을 방지하기 위해이 상태 코드를 사용합니다. 예를 들어 짧은 시간 프레임 내에서 반복 된 API 호출을 만드는 고객은 429 응답을 유발할 수 있습니다. 웹 사이트 또는 서비스는 트래픽 스파이크를 관리하거나, 일시적으로 사용자가 과도한 요청을 차단하는 비율 제한을 부과 할 수 있습니다.

#### R2는 공공 물통을 관리했습니다

Cloudflare는 R2를 위한 요구에 제한하는 비율을 관리한 공중 물통을 통해 접근했습니다`r2.dev`. 이것은 대중적인 물통의 남용 그리고 overuse에서 고객을 보호합니다. 자주 묻는 질문[관리된 공중 물통에 제한 비율`r2.dev`](/r2/platform/limits/#rate-limiting-on-managed-public-buckets-through-r2dev).
