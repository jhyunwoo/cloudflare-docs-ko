## 499 클라이언트 닫기 요청

더 보기`HTTP 499`응답 코드는 일반적으로 클라이언트가 서버의 연결을 종료하면 응답 할 수 있습니다.

### 일반적인 사용 사례

예제의`499`응답 코드는 클라이언트가 밖으로 시간을 보내고 서버가 처리하기 전에 연결을 닫는 상황, 큰 파일 업로드 또는 긴 실행 요청에 따라. TCP three-way Handhake의 문제로 인해 발생할 수 있습니다. 클라이언트가 타임 아웃 설정 때문에 연결이 조기에 종료됩니다.

### Cloudflare-특징 정보

더 보기`499 Client Closed Request`상태 코드는 nginx에 적합하며 클라이언트가 요청을 처리하면서 연결을 닫는 것을 나타냅니다. 서버는 응답 상태 코드를 전송하여 서버를 방지합니다. 이 상태 코드는[Cloudflare 로그](/logs/)Enterprise 고객을 위한 상태 코드 분석.

:::참조
Cloudflare는 nginx에 내장되어 있기 때문에, 499 HTTP 코드는 Cloudflare 로그 및 Cloudflare 이전에 클라이언트에 의해 종결된 연결을 위한 분석에서 기록됩니다. 고객의 로그에 이러한 항목을 볼 것으로 예상됩니다.
주요 특징

더 많은 컨텍스트를 제공하기 위해 TCP 연결은 Cloudflare와 웹 사이트 소스 서버 사이에 설치되어야 합니다 (HTTP와 같은) 통신을 시작합니다. TCP는 연결을 설정하기 위해 three-way handhake를 사용합니다.

- **사이트맵**: Cloudflare는 SYN 패킷을 Origin 서버에 보냅니다.
- **사이트맵**: Origin 서버는 SYN+ACK 패킷으로 응답합니다.
- **사이트맵**: Cloudflare는 원래 서버로 ACK 패킷을 다시 보냅니다.

이 시점에서 연결이 설치되고 CloudflareXQ와 Origin 서버 모두 통신 할 수 있습니다. 그러나, 근원 서버가 19 초 안에 CloudflareXCloudflareXQXQXQXQXQ retries에 다시 SYN+ACK를 보내지 않는 경우에, 다른 15-second timeout와 더불어.

클라이언트 측 timeout 설정에 따라 다음 시나리오가 발생할 수 있습니다.

- **짧은 클라이언트 타임 아웃 (38 초 미만)**: 클라이언트가 더 짧은 타임 아웃을 가지고 있다면 Cloudflare가 처리 완료하기 전에 연결을 포기하고 A`499`응답 부호는 기록될 것입니다.
- **성공적인 연결 (38 초 이상)**: 클라이언트가 더 긴 타임 아웃과 TCP 연결이 성공적으로 설치되면 HTTP 트랜잭션은 일반적으로 진행되며 Cloudflare는 표준 상태 코드를 반환합니다 (`HTTP 200`).
- **Handshake 실패**: 클라이언트가 더 긴 타임 아웃을 가지고 있지만 Cloudflare는 원래 서버로 TCP 핸디크를 설정할 수 없습니다, CloudflareXQ는 반환됩니다`HTTP 522`상태 코드.
