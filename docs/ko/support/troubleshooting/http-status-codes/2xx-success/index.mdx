2xx 상태 코드는 성공을 나타냅니다, 클라이언트 요청이 수신 된 의미, 이해, 서버에서 허용.

## 200 OK

200 응답은 요청이 성공했는지 나타냅니다.

### 일반적인 사용 사례

200 응답은 다음과 같은 시나리오에서 일반적으로 사용됩니다.

- 요청 사항 : 관련 헤더와 함께 웹 페이지, 이미지, 또는 API 데이터와 같은 요청 된 리소스를 반환합니다.
- HEAD 요청: 메타데이터와 같은 요청된 리소스에 해당하는 헤더만 검색합니다. 예를 들어, 파일 크기 또는 마지막 수정 날짜.
- POST 요청: 양식 제출과 같은 제출 된 데이터의 성공적인 처리 확인, 종종 응답 몸에서 결과에 대한 세부 사항.

200 응답은 이상적으로 payload를 포함해야하지만 필요하지 않습니다. Occasionally, 근원 서버는 0개의 내용 길이를 가진 200의 응답을 돌려보낼지도 모릅니다. 그러나 RFC 표준을 따르는 204 응답은 그런 경우에 추천됩니다 (CONNECT 방법을 제외하고).

### Cloudflare-특징 정보

기본적으로 200 응답은 프록시 서버 및 브라우저에서 캐시할 수 있습니다. 특정한 경우[캐시 컨트롤](/cache/concepts/customize-cache/)정의되지 않음[정적 자원](/cache/concepts/default-cache-behavior/)200 응답으로 Cloudflare의 가장자리에 2 시간 동안 캐시됩니다.

## 201 작성

201 응답은 한 개 이상의 새로운 자원의 성공적인 창조를 나타냅니다. 서버는 일반적으로 새로 만들어진 리소스의 위치를 포함합니다.`Location`헤더 또는 요청 URI.

### 일반적인 사용 사례

POST 요청에 대한 응답에 새로운 리소스를 만듭니다. 예를 들어, 새로운 사용자, 기사, 또는 기록 생성.

### Cloudflare-특징 정보

Cloudflare는 수정 없이 201의 응답을 전달합니다.

더 많은 정보를 원하시면,[RFC 7231의](https://tools.ietf.org/html/rfc7231#section-7.2)validator 헤더에 대한 자세한 내용은 다음과 같습니다.**기타**·**최근 수정**201 응답에서.

## 203 비주의 정보

203 응답은 요청이 성공되었지만 응답은 원래 서버에서 직접 오지 않았습니다. 응답은 프록시 또는 중간 서버로 전달되었습니다.

### 일반적인 사용 사례

Servers는 이 응답을 사용하여 리소스가 프록시 서버에 의해 캐시 된 클라이언트에게 알려줍니다.

### Cloudflare-특징 정보

Cloudflare는 203 응답을 캐시하지 않습니다. Cloudflare가 203 응답을 처리하는 방법에 대한 자세한 내용은 참조[Cloudflare HTTP 헤더](/fundamentals/reference/http-headers/).

## 204 내용 없음

204 응답은 요청이 성공적으로 처리되었는지 나타냅니다, 그러나 응답에서 반환하는 내용이 없습니다.

### 일반적인 사용 사례

이 응답은 종종 서버에서 문서 편집기의 저장 작업이 성공적으로 완료되었는지 나타냅니다.

### Cloudflare-특징 정보

204 응답은 HTTP 표준에 의해 지정 된 대로, 페이로드를 포함하지 않으며 Cloudflare는 이러한 응답을 캐시하지 않습니다.

## 205 재설정 콘텐츠

205 응답은 클라이언트가 요청 후 이전 상태로 반환합니다.

### 일반적인 사용 사례

이 응답은 사용자가 양식 또는 기타 데이터를 제출 한 후 발생하며 고객이 페이지를 새로 고침하거나 새 제출을 허용합니다.

### Cloudflare-특징 정보

205 응답은 어떤 페이로드와 Cloudflare를 포함하지 않아 이러한 응답을 캐시하지 않습니다.

## 206 부분적인 내용

206 응답은 요청이 부분적으로 성공한다는 것을 의미하며, 종종 더 작은 펑크에 큰 파일을 봉사하는 데 사용됩니다.

### 일반적인 사용 사례

이 응답은 종종 클라이언트가 분할 또는 중단 된 다운로드가 필요할 수있는 더 큰 파일을 처리 할 때 지연을 줄일 수 있습니다. 예를 들어, 스트리밍 비디오 또는 서빙 파일 범위에 대한 진보적 인 로딩.

206 응답은 다음을 포함합니다:

- Partial payload를 포함`Content-Range`요청된 범위와 응답에서 제공되는 데이터를 지정하는 헤더.
- Multipart payload 그 omits 그만큼`Content-Range`최고 수준의 헤더는 있지만 포함`Content-Type`·`Content-Range`multipart 응답 몸의 각 부분을 위한 우두머리.

더 자세한 내용은 참조[RFC 7233의 단면도 4.1](https://tools.ietf.org/html/rfc7233#page-10).

### Cloudflare-특징 정보

Cloudflare는 범위 요구에 대한 206 응답을 처리하지만,[캐싱 행동](/cache/concepts/default-cache-behavior/)파일 유형 및 원산지 설정에 따라 달라질 수 있습니다.
