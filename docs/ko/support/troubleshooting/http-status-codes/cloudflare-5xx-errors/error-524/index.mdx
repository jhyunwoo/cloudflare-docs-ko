## 오류 524 : 타임 아웃이 발생했습니다.

오류 수정`524`Cloudflare는 원래 웹 서버에 성공적으로 연결되었지만, 기원은 기본 120 초 전에 HTTP 응답을 제공하지 않았다[프록시 읽기 Timeout](/fundamentals/reference/connection-limits/).

### 일반적인 원인

서버가 너무 오래 걸릴 경우 발생할 수 있습니다. 예를 들어, 큰 데이터 쿼리, 또는 서버가 리소스에 대한 struggling이기 때문에, 시간에 어떤 데이터를 반환 할 수 없습니다.
오류`524`웹 서버가 (ACK) 연결이 설치 된 후 리소스 요청을 인정하는 경우 발생하지만 적시 응답을 보내지 않습니다 ([프록시 읽기 Timeout](/fundamentals/reference/connection-limits/)지연, 기본적으로 120 초).

오류 수정`524`CloudflareXQ가 데이터를 작성하기 위해 원래 웹 서버에 연결되었지만 30 초 전에 작성하지 않았습니다.[프록시 쓰기 Timeout](/fundamentals/reference/connection-limits/)(또는 6.5 초의 경우[모델 번호: Cloudflare 제품정보](/images/)). 이 타임아웃은 조정될 수 없습니다.

### 당신의 근원에 해결책

여기에 우리가이 문제에 대해 일하는 것이 좋습니다 :

- [호스팅 공급자에게 연락하기](/support/troubleshooting/http-status-codes/cloudflare-5xx-errors/#required-error-details-for-hosting-provider)웹 서버에서 다음과 같은 일반적인 원인을 제외하려면:
  - 웹 서버의 긴 실행 과정.
  - 과부하된 근원 웹 서버.

- 이 오류를 피하기 위해 큰 HTTP 프로세스의 상태 오염을 구현합니다.

:::참조

웹 서버에서 요청 응답 시간을 기록하면 리소스가 느립니다.
호스팅 제공 업체 또는 사이트 관리자에 문의하여 로그 형식을 조정하거나 웹 서버의 브랜드에 대한 관련 로깅 문서를 검색[아파치](http://httpd.apache.org/docs/current/mod/mod_log_config.html)또는[사이트맵](http://nginx.org/en/docs/http/ngx_http_log_module.html#log_format).
:::

### Cloudflare에 해결책

다음은 CloudflareQ 측에 걸릴 수있는 다른 작업입니다 :

- 120 초 이상 완료하는 HTTP 요청을 정기적으로 실행하면 (예를 들어, 큰 데이터 내보내기), 그 프로세스를 이전[subdomain (DNS 전용, 회색 클라우드)](/dns/proxy-status/#dns-only-records)Cloudflare**DNS 보호**앱.
- 기업 고객은 증가할 수 있습니다`524`최대 6,000 초:
  - 콘텐츠를 캐시 할 수 있다면, 만들 수 있습니다.[캐시 규칙](/cache/how-to/cache-rules/settings/#proxy-read-timeout-enterprise-only)이름 \*`Proxy Read Timeout`설정. 내용이 트리거 될 규칙에 대해 캐시 할 필요가 있지만, 캐시 할 필요가 없습니다.
  - 당신은 증가할 수 있습니다`proxy_read_timeout`전체 영역 설정[편집 영역 설정 API endpoint](/api/resources/zones/subresources/settings/methods/edit/).

:::참조

당신은 당신이 설정 한 타임 아웃 사이 1 초 차이를 관찰 할 수 있습니다 및 실제 시간에 오류`524`반환합니다. 이것은 예상된다, 그것은 우리의 프록시 구현에 현재 작업 때문에 -[핑라](https://blog.cloudflare.com/how-we-built-pingora-the-proxy-that-connects-cloudflare-to-the-internet/)·
운동으로, 당신은 단순히 1 초에 타임 아웃을 설정할 수 있습니다 (121 초 대신 120 초, 예를 들어).
