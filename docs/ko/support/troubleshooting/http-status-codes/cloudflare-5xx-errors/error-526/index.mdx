## 오류 526 : 잘못된 SSL 인증서

이 오류는 Cloudflare가 원래 서버에서 SSL 인증서를 확인 할 수 없다는 것을 나타냅니다. 보안 연결을 설정에서 방지합니다.

### 일반적인 원인

이 오류는 이러한 두 가지 조건이 true일 때 발생합니다.

- Cloudflare는 원래 웹 서버에서 SSL 인증서를 유효하지 않습니다.
- [*전체 SSL (Strict)*](/ssl/origin-configuration/ssl-modes/full-strict/) **사이트맵**설정은**제품정보**Cloudflare의 탭**사이트맵**앱.

#### 제품 설명

이 문제를 해결하거나 해결하기위한 몇 가지 옵션이 있습니다 :

- 잠재적인 빠른 고침을 위해, 세트**사이트맵**으로*한국어*대신에*풀 (strict)*&#xB0B4; 계정**제품정보**Cloudflare의 탭**사이트맵**도메인의 앱.

- 자체 서명된 SSL 인증서를 추가하십시오.[회사 소개](/ssl/origin-configuration/custom-origin-trust-store/). 이것은 CloudflareXQ 가장자리가 유효한 것과 같이 당신의 각자 서명한 SSL 증명서를 인식하기 위하여 허용합니다.

- 지원하다[Cloudflare 근원 CA 증명서](/ssl/origin-configuration/origin-ca/)당신의 근원에.

- 서버 관리자 또는 호스팅 제공 업체가 웹 서버의 SSL 인증서를 검토하고 확인하려면 :

  - 인증서는 만료되지 않습니다.
  - 인증은 개정되지 않습니다.
  - 증명서는 서명됩니다[인증 기관](https://en.wikipedia.org/wiki/Certificate_authority)(자가 위탁되지 않음).
  - 요청 또는 대상 도메인 이름 및 호스트 이름은 인증서의**이름 \***&#xB610;는**제목 내용**.
  - 당신의 근원 웹 서버는 항구 SSL 항구에 연결을 받아들입니다`443`.
  - [임시 일시 정지 Cloudflare](/fundamentals/manage-domains/pause-cloudflare/)그리고 방문[모델 번호: https://www.sslshopper.com/ssl-checker.html#hostname=www.example.com](https://www.sslshopper.com/ssl-checker.html#hostname=www.example.com)(장소)`www.example.com`호스트 이름과 도메인으로 인해 문제가 발생하지 않도록 SSL 인증서:

  ![오류없이 SSL 인증서를 보여주는 화면.](~/assets/images/support/hc-import-troubleshooting_5xx_errors_sslshopper_output.png)

### Zero Trust의 오류 526

사용 방법[Cloudflare 게이트웨이](/cloudflare-one/traffic-policies/)HTTP 오류`526`반환 될 수 있습니다[다음 사례](/cloudflare-one/faq/troubleshooting/#i-see-error-526-when-browsing-to-a-website):

- **위탁되지 않은 인증서는 Gateway의 기원에서 제시됩니다.**&#xAC8C;이트웨이는 이러한 조건이 true인 경우 인증서가 위탁되지 않습니다.
  - 서버 인증서 발급자는 알 수 없거나 서비스에 의해 신뢰할 수 없습니다.
  - 서버 인증서가 개정되고 CRL 체크가 실패합니다.
  - 서버 인증서에 대한 인증서 체인에 적어도 하나의 만료 된 인증서가 있습니다.
  - 인증서의 일반적인 이름은 도달하려고하는 URL과 일치하지 않습니다.
  - 인증서의 일반적인 이름은 잘못된 문자 (fromscores와 같은)를 포함합니다. Gateway 사용[보링SSL](https://csrc.nist.gov/projects/cryptographic-module-validation-program/validated-modules/search?SearchMode=Basic\&Vendor=Google\&CertificateStatus=Active\&ValidationYear=0)인증서를 검증합니다. 크롬의[검증 논리](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/net/cert/x509_certificate.cc#429)웹 사이트가 WARPXQ를 해제 할 때로드 할 수있는 비 RFC 1305 호환 인증서를 허용합니다.

- **Gateway의 연결은 insecure입니다.**&#x47;ateway는 다음과 같은 원산지를 신뢰하지 않습니다.
  - RC4, RC4-MD5 또는 3DES와 같은 insecure cipher 스위트 만 제공하십시오. 당신은 사용할 수 있습니다[SSL 서버 테스트 도구](https://www.ssllabs.com/ssltest/index.html)ciphers가 근원에 의해 지원되는 것을 확인하기 위하여.
  - 지원하지 않음[FIPS-compliant 수석](/cloudflare-one/traffic-policies/http-policies/tls-decryption/#cipher-suites)(당신이 활성화한 경우[FIPS 준수 모드](/cloudflare-one/traffic-policies/http-policies/tls-decryption/#fips-compliance)). 페이지를로드하려면 FIPS 모드를 비활성화하거나이 호스트에 대한 검사 정책을 만들 수 있습니다 (이 기원에 대한 FIPS 준수를 비활성화하는 효과).
  - HTTP에 모든 HTTPS 요청을 다시 시작합니다.

### Workers의 오류 526

Workers는 CloudflareXQ에 의해 발음되지 않는 CloudflareQXQ가 항상 사용하는 어떤 hostname든지에 subrequest&#x73;**[풀 (strict)](/ssl/origin-configuration/ssl-modes/full-strict/)**&#x57;orkers 영역 구성에 관계없이 SSL 모드.

#### 제품 설명

- SSL 인증서가 원본에서 설정된 것을 확인합니다.

- 자체 서명된 SSL 인증서를 추가하십시오.[회사 소개](/ssl/origin-configuration/custom-origin-trust-store/)그리고 활성화[`cots_on_external_fetch`호환성 깃발](/workers/configuration/compatibility-flags/#do-not-use-the-custom-origin-trust-store-for-external-subrequests)당신의 노동자의 윤곽에서.
  이 플래그는 사용 가능[회사 소개](/ssl/origin-configuration/custom-origin-trust-store/)Cloudflare Worker에서 외부 (회색) 잠수함 만들기.
