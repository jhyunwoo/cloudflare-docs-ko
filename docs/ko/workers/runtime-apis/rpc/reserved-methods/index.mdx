몇몇 방법 이름은 예약되거나 특별한 semantics가 있습니다.

## 특수 방법

뒤로 겸용성을 위해, 장시간 때`WorkerEntrypoint`또는`DurableObject`, 뒤에 오는 방법 이름은 특별한 semantics가 있습니다. 이 글은*아니다.*&#xC2E0;청하기`RpcTarget`. 에`RpcTarget`, 이 방법은 다른 어떤 RPC 방법 같이 작동합니다.

### `fetch()`

더 보기`fetch()`메소드는 특별히 처리됩니다. HTTP 요청을 처리하는 데만 사용될 수 있습니다. —[회사 소개](/workers/runtime-apis/handlers/fetch/).

당신은 구현할 수 있습니다`fetch()`클래스의 방법`WorkerEntrypoint`— 하지만 타입의 1개의 매개변수만 허용해야 합니다.[`Request`](https://developer.mozilla.org/en-US/docs/Web/API/Request), 인스턴스를 반환해야 합니다.[`Response`](https://developer.mozilla.org/en-US/docs/Web/API/Response), 또는[회사 소개](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Promise)하나.

클라이언트 측에,`fetch()`서비스 바인딩 또는 튼튼한 목표 stub는 표준 세계적인 같이 작동합니다`fetch()`. 즉, 호출기는 1개 또는 2개의 모수를 통행할지도 모릅니다`fetch()`. 콜러가 단순히 단일을 통과하지 않는 경우`Request`객체, 다음 새로운`Request`불확실하게 건설되고, 그것의 constructor에 모수를 통과하고, 그 요구는 실제로 서버로 보내지는 무슨입니다.

일부 속성`Request`행동을 제어`fetch()`클라이언트 측에 실제로 서버로 보내지 않습니다. 예를 들어, 속성`redirect: "auto"`(기본값) instructs`fetch()`서버가 리디렉션 응답을 반환하면 자동으로 수행되어야하며, HTTP 요청에서 공개 인터넷에 결과를 나타냅니다. 다시, 이 행동은 Fetch API 표준에 따라 입니다. 짧은,`fetch()`RPC semantics가 없습니다. Fetch API semantics가 있습니다.

### `connect()`

더 보기`connect()`방법의`WorkerEntrypoint`클래스는 작업자에게 소켓 같은 연결을 열어줍니다. 이것은 현재 구현되거나 지원되지 않습니다. — 당신이 할 수 있지만[Worker에서 TCP 소켓을 엽니다.](/workers/runtime-apis/tcp-sockets/)또는 TCP 소켓을 통해 데이터베이스에 직접 연결[모델 번호: Hyperdrive](/hyperdrive/get-started/).

## 방법 이름

다음 방법 (또는 속성) 이름은 RPC 유형에 RPC 방법으로 사용할 수 없습니다 (포함`WorkerEntrypoint`, `DurableObject`·`RpcTarget`):

- `dup`: 이 스텁을 duplicating 할 수 있습니다. 더 알아보기[RPC 수명주기](/workers/runtime-apis/rpc/lifecycle)더 자세히 알아보기`dup()`.
- `constructor`: 이 이름은 JavaScript 클래스의 특별한 의미를 가지고 있습니다. 그것은 방법으로 호출되지 않습니다, 그래서 그것은 RPC에 허용되지 않습니다.

다음과 같은 방법은 멸균됩니다.`WorkerEntrypoint`·`DurableObject`, 그러나 허용`RpcTarget`. 이 방법은 역사적으로 Durable Objects에 특별한 의미를 가지고 있으며 특정 시스템 생성 된 이벤트를 처리하는 데 사용됩니다.

- `alarm`
- `webSocketMessage`
- `webSocketClose`
- `webSocketError`
