더 보기`Response`인터페이스는 HTTP 응답을 나타내며 Fetch API의 일부입니다.

***

## 회사연혁

```js
let response = new Response(body, init);
```

### 매개 변수

- `body`옵션 정보

  - 응답에 대한 신체 텍스트를 정의하는 객체. 수 있습니다`null`또는 다음 유형 중 하나 :

    - 버퍼소스
    - 양식데이터
    - 읽을 수 있는Stream
    - URL검색Params
    - 미국VString

- `init`옵션 정보

  - 이름 \*`options`응답에 적용 할 수있는 사용자 정의 설정을 포함.

유효한 옵션`options`객체는 다음과 같습니다:

- `cf`한국어
  - Cloudflare-specific 정보가 포함된 객체. 이 객체는 Fetch API 표준의 일부가 아니며 Cloudflare Workers에서만 사용할 수 있습니다. 이 필드는 정보 목적으로 응답자의 소비자가 사용되며 Workers 행동에 영향을 미치지 않습니다.
- `encodeBody`이름 \*
  - Workers는에 따라 자료를 압축해야 합니다`content-encoding`전송 할 때 헤더, 이미 압축 된 데이터 제공, 이 속성은 설정해야`"manual"`, 그렇지 않으면 기본값은`"automatic"`.
- `headers`본사 | ByteString
  - 어떤 헤더가 귀하의 응답에 추가하려면[`Headers`](/workers/runtime-apis/request/#parameters)객체 또는 객체의 리터럴[`ByteString`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/String)키 값 쌍.
- `status`뚱 베어
  - 응답의 상태 코드 등`200`.
- `statusText`이름 \*
  - 상태 코드와 관련된 상태 메시지와 같은,`OK`.
- `webSocket`웹소켓 | null
  - 이것은 성공적인 WebSocket Handhake 응답에서 존재합니다. 예를 들어, 클라이언트가 WebSocket 업그레이드 요청을 소스에 보내고 Worker는 요청을 가로 질러 소스에 전달하고 성공적인 WebSocket 업그레이드 응답을 통해 원래의 replies를 전달합니다. Worker는`response.webSocket`. 이것은 Worker를 통해 WebSocket 연결 proxied를 설치합니다. WebSocket 연결을 통해 데이터 흐름을 차단할 수 없습니다.

## 제품 정보

- `response.body`읽기 쉬운 스트림
  - 본문내용 바로가기
- `response.bodyUsed`한국어
  - 몸이 응답에서 사용되었는지 나타내는 불린.
- `response.headers`기타 제품
  - 응답을위한 헤더.
- `response.ok`한국어
  - 응답이 성공했는지 나타내는 불린 (범위의 통계)`200`-`299`).
- `response.redirected`한국어
  - 응답이 리디렉션의 결과로 나타내는 불린. 그렇다면 URL 목록은 1 개 이상의 항목이 있습니다.
- `response.status`뚱 베어
  - 응답의 상태 코드 (예를 들어,`200`성공을 나타냅니다.
- `response.statusText`이름 \*
  - 상태 코드에 해당하는 상태 메시지 (예를 들어,`OK`제품 정보`200`).
- `response.url`이름 \*
  - 응답의 URL. 값은 리디렉션 후에 얻어진 마지막 URL입니다.
- `response.webSocket`웹소켓?
  - 이것은 성공적인 WebSocket Handhake 응답에서 존재합니다. 예를 들어, 클라이언트가 WebSocket 업그레이드 요청을 소스에 보내고 Worker는 요청을 가로 질러 소스에 전달하고 성공적인 WebSocket 업그레이드 응답을 통해 원래의 replies를 전달합니다. Worker는`response.webSocket`. 이것은 Worker를 통해 WebSocket 연결 proxied를 설치합니다. WebSocket 연결을 통해 데이터 흐름을 차단할 수 없습니다.

## 제품 설명

### Instance 방법

- `clone()`: 응답

  - 창조의 클론[`Response`](#response)객체.

- `json()`: 응답

  - JSON 직렬 페이로드로 새로운 응답을 만듭니다.

- `redirect()`: 응답

  - 다른 URL로 새로운 응답을 만듭니다.

### 추가 인스턴스 방법

`Response`구현[`Body`](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch#body)혼합의[페치 API](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API), 그러므로`Response`예를 들어 다음과 같은 방법이 있습니다.

- <code>arrayBuffer()</code>: 프로\<miseArrayBuffer>

  - 한국어[`Response`](#response)스트림, 완료하기 위해 그것을 읽고, 해결 약속을 반환[`ArrayBuffer`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/ArrayBuffer).

- <code>형식자료()</code>: Pro\<구성자료>

  - 한국어[`Response`](#response)스트림, 완료에 그것을 읽고, 해결 약속을 반환[`FormData`](https://developer.mozilla.org/en-US/docs/Web/API/FormData)객체.

- <code>제이슨()</code>: 프로미스\<JSON>

  - 한국어[`Response`](#response)스트림, 완료에 그것을 읽고, 몸 텍스트를 파싱의 결과로 해결 약속을 반환[`JSON`](https://developer.mozilla.org/en-US/docs/Web/).

- <code>텍스트()</code>: 프로미스\<USVString>

  - 한국어[`Response`](#response)스트림, 완료에 그것을 읽고, 해결 약속을 반환[`USVString`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/String)(텍스트).

### 설정하기`Content-Length`기타 제품

더 보기`Content-Length`헤더는 모든 데이터 소스를 기반으로 런타임에 의해 자동으로 설정됩니다.`Response`이름 \* 사용자 코드에 의해 수동으로 설정`Headers`무시됩니다. 에 있다`Content-Length`지정된 특정 값으로 헤더,`body`이름 \*`Response`한국어`FixedLengthStream`또는 고정 길이 값은 문자열 또는`TypedArray`.

·`FixedLengthStream`정체성`TransformStream`그것은 단지 고정 된 바이트 수를 허용한다.

```js
  const { writable, readable } = new FixedLengthStream(11);

  const enc = new TextEncoder();
  const writer = writable.getWriter();
  writer.write(enc.encode("hello world"));
  writer.end();

  return new Response(readable);
```

다른 유형의 사용`ReadableStream`응답의 몸으로 chunked 인코딩에서 사용 됩니다.

## 기타

Workers 구현`Response`인터페이스는 웹 표준에 몇 가지 확장을 포함합니다.`Response`API. 이러한 차이는 의도적이고 Workers 런타임에 따라 추가 기능을 제공합니다.

:::노트\[TypeScript 사용자]
Workers 유형 정의 (에서`@cloudflare/workers-types`또는 생성[`wrangler types`](/workers/wrangler/commands/#types)) 정의`Response`Workers-specific 속성을 포함하는 유형`cf`·`webSocket`. 이 유형은 표준과 직접 호환되지 않습니다`Response`유형에서`lib.dom.d.ts`. Workers 유형과 표준 웹 유형 둘 다를 사용하는 부호로 일하는 경우에, 당신은 유형 assertions를 사용할 필요가 있을지도 모릅니다.
주요 특징

### 더 보기`cf`이름 \*

Workers 옵션 추가`cf`호텔 위치`Response`객체. 이 숙박 시설은`ResponseInit`옵션 및 응답의 소비자에 의해 정보 목적으로 사용됩니다. Workers 행동에 영향을 미치지 않습니다.

### 더 보기`webSocket`이름 \*

Workers 추가`webSocket`호텔 위치`Response`WebSocket 연결을 지원하는 객체. 이 속성은 성공적인 WebSocket Handhake 응답에 있습니다. 더 알아보기[웹소켓](/workers/runtime-apis/websockets/)더 많은 정보.

### 더 보기`encodeBody`옵션 정보

Workers는 추가합니다`encodeBody`옵션 정보`ResponseInit`응답 몸이 압축되는 방법을 제어합니다. 설정하기`"manual"`자동 압축을 방지하기 위해 사전 압축 데이터를 제공 할 때.

### 더 보기`headers`이름 \*

더 보기`headers`속성은 Workers-specific 반환[`Headers`](/workers/runtime-apis/headers/)같은 추가 방법을 포함 하는 개체`getAll()`제품 정보`Set-Cookie`머리. 더 알아보기[관련 문서](/workers/runtime-apis/headers/#differences)Workers`Headers`구현은 웹 표준과 다릅니다.
