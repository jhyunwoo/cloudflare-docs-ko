## 이름 \*

모든 HTTP 요청 및 응답 헤더를 통해 사용할 수 있습니다[헤더 API](https://developer.mozilla.org/en-US/docs/Web/API/Headers).

헤더 이름은 여러 값을 소유할 때, 그 값은 단일, comma-delimited string 값으로 concatenated 됩니다. 즉,`Headers.get`항상 문자열을 반환하거나`null`가치. 이 모든 헤더 이름에 적용됩니다.`Set-Cookie`, 필요한`Headers.getAll`. 아래 문서[기타](#differences).

```js
let headers = new Headers();

headers.get('x-foo'); //=> 오류

headers.set('x-foo', '123');
headers.get('x-foo'); //=> "123"'실제 이름입

headers.set('x-foo', 'hello');
headers.get('x-foo'); //=> "안녕하세요"

headers.append('x-foo', 'world');
headers.get('x-foo'); //=> "hello, 세계"
```

## 기타

Workers 구현`Headers`API는 여러 가지 방법으로 웹 표준과 다릅니다. 이러한 차이는 의도적이며 Workers 런타임의 서버 측 성격을 반영합니다.

:::노트\[TypeScript 사용자]
Workers 유형 정의 (에서`@cloudflare/workers-types`또는 생성[`wrangler types`](/workers/wrangler/commands/#types)) 정의`Headers`Workers-specific 메소드를 포함하는 유형`getAll()`. 이 유형은 표준과 직접 호환되지 않습니다`Headers`유형에서`lib.dom.d.ts`. Workers 유형과 표준 웹 유형 둘 다를 사용하는 부호로 일하는 경우에, 당신은 유형 assertions를 사용할 필요가 있을지도 모릅니다.
주요 특징

### `getAll()`제품 설명

사실에도 불구하고`Headers.getAll`방법은 웹 브라우저에서 사용되지 않았습니다. Workers는 여전히이 방법을 제공합니다.`Set-Cookie`헤더. 이것은 쿠키가 종종 날짜 문자열을 포함하기 때문에, commas 포함. 여러 값을 파싱할 수 있습니다.`Set-Cookie`더 열심히.

어떤 시도를 사용`Headers.getAll`다른 헤더 이름은 오류를 던질 것입니다. 간단한 역사`Headers.getAll`이용 가능[GitHub 문제](https://github.com/whatwg/fetch/issues/973).

### `Set-Cookie`제품정보

이름 \*[RFC 6265 시리즈](https://www.rfc-editor.org/rfc/rfc6265)다수 접히는 prohibiting`Set-Cookie`헤더는 단일 헤더로,`Headers.append`메소드를 설정할 수 있습니다.`Set-Cookie`응답 헤더 대신 기존 헤더에 값을 appending.

```js
const headers = new Headers();

headers.append("Set-Cookie", "cookie1=value_for_cookie_1; Path=/; HttpOnly;");
headers.append("Set-Cookie", "cookie2=value_for_cookie_2; Path=/; HttpOnly;");

console.log(headers.getAll("Set-Cookie"));
//배열(2) [ Cookies1=value for cookie 1; Path=/; HttpOnly;, cookie2=value for cookie 2; Path=/; HttpOnly; ]
```

문서화 된 Cloudflare 요청 헤더의 목록은 참조[Cloudflare HTTP 헤더](/fundamentals/reference/http-headers/).
