:::note\[Dynamic Worker 로딩은 닫힌 베타]

Worker Loader API는 Wrangler 및 workerd와 현지 개발에서 사용할 수 있습니다. 그러나 CloudflareXQXQXQ에 동적 Workers를 실행하려면 반드시 해야 합니다.[닫힌 베타에 가입](https://forms.gle/MoeDxE9wNiqdf8ri9).

:::

노동자 장전기 바인딩은 당신이 런타임에 arbitrary 부호를 포함하는 추가 Workers를 적재하는 것을 허용합니다.

isolate는 경량 용기와 같습니다.[Workers 플랫폼은 컨테이너 또는 VMs 대신 격리합니다.](/workers/reference/how-workers-works/), 그래서 모든 노동자는 이미 고립에서 실행합니다. 하지만, Worker Loader 바인딩을 사용하면 Worker가 추가 isolates를 만들 수 있습니다.

Isolates는 컨테이너보다 훨씬 저렴합니다. 당신은 밀리 초에 isolate를 시작할 수 있으며 코드의 스니펫을 실행하고 즉시 멀리 던질 수 있습니다. 당신이 콘테이너로 할 필요가 있기 때문에 풀리는 고립에 관하여 고민하거나 이미 온난한 isolates를 재사용하는 것을 시도할 필요가 없습니다.

Worker Loaders도 가능**회사 소개**코드의, 당신은 엄격하게 코드를 할 수있는 것을 제한 할 수있는 의미. 특히:

- Worker가 만든 모든 네트워크 요청을 차단할 수 있습니다.
- 사용자 정의 바인딩을 사용하여 sandboxed Worker를 제공 할 수 있습니다 특정 리소스를 나타냅니다.

적절한 sandboxing 구성으로, 당신은 안전하게 동적 isolate에 신뢰하지 않는 코드를 실행할 수 있습니다.

## 비밀번호

Dynamic Worker Loaders의 기본 사용 사례[비밀번호](/agents/api-reference/codemode/)내 계정[에이전트 SDK](/agents/). Codemode는 TypeScript API를 입력하고 LLM을 단일 "쓰기 코드"공구로 변환합니다. 생성 된 코드는 격리 된 노동자 샌드 박스에서 실행되며 AI 에이전트 체인 다중 도구가 하나의 실행에서 호출하고 모델을 통해 왕복을 줄일 수 있습니다.

Codemode는 표준 AI SDK 도구와 함께 작동합니다.[사이트맵](/agents/model-context-protocol/)도구.

## 기본 사용

Worker Loader는 단 하나 방법의 바인딩입니다,`get()`isolate를로드합니다. 예제 사용:

```js
let id = "foo";

//주어진 ID와 isolate를 얻을, 그런 isolate가 아직 존재하지 않는 경우 만들기.
let worker = env.LOADER.get(id, async () => {
	//isolate가 이미 존재하지 않는 경우, 이 콜백은 fetch로 호출됩니다.
	//isolate의 노동자 코드.

	return {
		compatibilityDate: "2025-06-01",

		//worker의 코드를 지정합니다 (module 파일).
		mainModule: "foo.js",
		modules: {
			"foo.js":
				"export default {\n" +
				"  fetch(req, env, ctx) { return new Response('Hello'); }\n" +
				"}\n",
		},

		//동적 노동자의 환경을 지정합니다 (`env`). 이것은 지정됩니다
		//JavaScript 객체로, 정확히 당신이 그것에 나타나는 것처럼
		//아이 노동자. 그것은 기본적인 serializable 유형 뿐 아니라 포함할 수 있습니다
		//서비스 바인딩 (아래 참조).
		env: {
			SOME_ENV_VAR: 123,
		},

		//`fetch()`를 사용하여 인터넷에 이야기하는 노동자를 차단하거나
		//`connect()`, `globalOutbound`를 `null`XQ로 설정하십시오. 당신은 또한 이것을 설정할 수 있습니다
		//모든 서비스 바인딩에, 호출을 방해하고 리디렉션
		//그 바인딩에.
		globalOutbound: null,
	};
});

//이제 노동자의 입장을 얻을 수 있으며 요청을 보내주십시오.
let defaultEntrypoint = worker.getEntrypoint();
await defaultEntrypoint.fetch("http://example.com");

//non-default 엔트리포인트를 얻을 수 있으며, 지정할 수 있습니다.
//`ctx.props` 값은 엔트리포인트로 전달됩니다.
let someEntrypoint = worker.getEntrypoint("SomeEntrypointClass", {
	props: { someProp: 123 },
});
```

## API 참조

### `get`

<code>
  태그(id)<Type text="string" />, getCodeCallback{" "}

  <Type text="() => Promise<WorkerCode>" />

  ): <Type text="WorkerStub" />
</code>

주어진 ID를 가진 노동자를 적재하고, 돌려보내는`WorkerStub`작업자에게는 사용할 수 있습니다.

편리함에 따라, 로더는 격리의 캐싱을 구현합니다. 새로운 ID가 처음으로 볼 때, 새로운 고립은 적재됩니다. 그러나, isolate는 동안 기억에 따뜻하게 될 수있다. Loader가 동일한 ID를 요청하는 경우, 기존 isolate는 다시 돌아올 수 있으므로 새로운 것을 만들 수 있습니다. 그러나 보증이 없습니다 : 같은 ID와 나중에 호출은 스크래치에서 새로운 격리를 시작할 수 있습니다.

시스템을 결정하면 새로운 고립을 시작해야하며 이미 코드 캐시의 사본이 없습니다.`codeCallback`Worker의 코드를 얻을 수 있습니다. 이것은 async 콜백입니다, 그래서 응용 프로그램은 원하는 경우 원격 저장소에서 코드를로드 할 수 있습니다. 콜백 반환 a`WorkerCode`객체 (아래로 호출 됨).

캐싱 때문에 콜백은 항상 동일한 ID를 호출 할 때 정확히 동일한 내용을 반환한다는 것을 보증해야합니다. 내용이 변경되는 경우, 새로운 ID를 사용해야 합니다. 그러나 내용이 변경되지 않은 경우, 캐싱의 장점을 얻기 위해 동일한 ID를 재사용하는 것이 가장 좋습니다. 만약에`WorkerCode`다른 매번, 당신은 무작위 ID를 통과할 수 있습니다.

예를 들어, 양식의 ID를 사용할 수 있습니다.`<worker-name>:<version-number>`, 버전 번호가 매번 코드를 변경합니다. 또는 코드와 구성의 해시를 기준으로 ID를 계산할 수 있으므로 새 ID에서 변경 결과를 변경할 수 있습니다.

`get()`계정 만들기`WorkerStub`적재한 노동자에 요구에 보낼 수 있는 ,. stub가 비동기적으로 반환되는 것을 참고하십시오. 노동자가 아직 로드되지 않은 경우, stub에 요청이 전달되기 전에 적재하기 위해 노동자를 기다립니다. 로드가 실패하면, 요청은 예외를 던집니다.

두 가지 요청이 같은 고립 될 것이라고 보장되지 않습니다. 같은 경우도`WorkerStub`여러 요청을 만들려면 다른 고립에서 실행할 수 있습니다. 콜백에 전달`loader.get()`한 번 이상 호출 될 수 있습니다 (일부 그것은 한 번 이상 호출 될 수 있음).

### `WorkerCode`

이것은 곁에 반환된 구조입니다`getCodeCallback`노동자를 대표합니다.

#### <code>호환성Date<Type text="string" /></code>

더 보기[호환성 날짜](/workers/configuration/compatibility-dates/)노동자를 위해. 이것은 같은 의미를 가지고`compatibility_date`Wrangler config 파일에서 설정.

#### <code>호환성 언어 선택<Type text="string[]" /> <MetaInfo text="Optional" /></code>

옵션 목록[모델 번호: compatibility flags](/workers/configuration/compatibility-flags)호환성 날짜를 augmenting. 이것은 같은 의미가 있습니다.`compatibility_flags`Wrangler config 파일에서 설정.

#### <code>관련 상품<Type text="boolean" /> <MetaInfo text="Optional" /></code>

진정한 경우 compatibility flags를 실험하면`compatibilityFlags`. 이것을 놓기 위하여, 장전기를 부르는 노동자는 겸용성 깃발이 있어야 합니다`"experimental"`세트. Experimental 플래그는 생산에서 사용할 수 없습니다.

#### <code>메인 모듈<Type text="string" /></code>

노동자의 주요 단위의 이름. 모듈 중 하나가 있어야 합니다.`modules`.

#### <code>모듈<Type text="Record<string, string | Module>" /></code>

dictionary object mapping module name to their string 내용. 모듈 내용이 일반 문자열이라면, 모듈 이름은 형식을 나타내는 파일 확장자가 있어야 합니다.`.js`또는`.py`.

모듈의 내용도 객체로 지정할 수 있으며, 이름과 독립적으로 지정할 수 있습니다. 허용된 객체는:

- `{js: string}`: A JavaScript 모듈, ES 모듈을 사용하여 가져 오기 및 내보내기.
- `{cjs: string}`: CommonJS 모듈`require()`수입에 대한 구문.
- `{py: string}`: 아[Python 단위](/workers/languages/python/), 그러나 밑에 경고를 보십시오.
- `{text: string}`: importable string 값입니다.
- `{data: ArrayBuffer}`: 수입`ArrayBuffer`가치.
- `{json: object}`: 수입 객체. 값은 JSON-serializable이어야 합니다. 그러나 값은 파삭한 객체로 제공되며 파삭한 객체로 전달됩니다. 실제로 JSON serialization을 볼 수 없습니다.

#### <code>글로벌Outbound<Type text="ServiceStub | null" />옵션 정보</code>

동적 작업자가 네트워크에 액세스 할 수 있는지 제어합니다. 글로벌`fetch()`·`connect()`함수 (HTTP 요청 및 TCP 연결을 위해 각각)는 worker를 격리하거나 리디렉션할 수 있습니다.

이름 \*`globalOutbound`기본적으로 부모의 네트워크 액세스를 상속하는 것은 아닙니다. 일반적으로 동적 작업자가 공용 인터넷에 대한 전체 액세스가있을 것입니다.

이름 \*`globalOutbound`이름 \*`null`, 그 후에 동적인 노동자는 네트워크에서 완전히 차단될 것입니다. 모두 보기`fetch()`·`connect()`예외를 던질 것입니다.

`globalOutbound`또한 부모 노동자의 서비스 바인딩을 포함하여 어떤 서비스 의무든지에 놓일 수 있습니다`env`뿐만 아니라[루프백 바인딩에서`ctx.exports`](/workers/runtime-apis/context/#exports).

사용 방법`ctx.exports`특히 유용합니다. 특정 샌드 박스에 바인딩을 더 사용자 정의 할 수 있습니다.`ctx.props`그것은 그것을 다시 통과해야합니다. 더 보기`props`특정 동적 작업자를 식별 할 수있는 정보를 포함 할 수 있습니다.

예를 들면:

```js
import { WorkerEntrypoint } from "cloudflare:workers";

export class Greeter extends WorkerEntrypoint {
	fetch(request) {
		return new Response(`Hello, ${this.ctx.props.name}!`);
	}
}

export default {
	async fetch(request, env, ctx) {
		let worker = env.LOADER.get("alice", () => {
			return {
				//모든 요청을 보내려면 worker의 글로벌 아웃 바운드를 다시 시작합니다.
				//`Greeter` 클래스에 `ctx.props.name`에 채우기
				//"Alice"라는 이름으로 항상 "Hello, Alice!"에 응답합니다.
				globalOutbound: ctx.exports.Greeter({ props: { name: "Alice" } }),

				//... 코드 ...
			};
		});

		return worker.getEntrypoint().fetch(request);
	},
};
```

#### <code>뚱 베어<Type text="object" /></code>

동적 작업자에게 제공하는 환경 객체.

이것을 사용하여, 당신은 노동자에 관례 바인딩을 제공할 수 있습니다.

`env`일련되고 역동적 인 노동자로 이동, 그것은 값으로 직접 사용됩니다`env`있습니다. 그것은 포함할지도 모릅니다:

- [구조화된 clonable 유형](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Structured_clone_algorithm).
- [서비스 바인딩](/workers/runtime-apis/bindings/service-bindings), 등[루프백 바인딩에서`ctx.exports`](/workers/runtime-apis/context/#exports).

두 번째 포인트는 사용자 정의 바인딩을 만드는 열쇠입니다: 당신은 모든 중재 API와 바인딩을 정의 할 수 있습니다, defining a[`WorkerEntrypoint`한국어](/workers/runtime-apis/bindings/service-bindings/rpc)RPC API를 구현하고 서비스 바인딩으로 동적 작업자에게 제공합니다.

또한, 사용`ctx.exports`루프백 바인딩, 당신은 더 특정 동적 노동자에 대한 바인딩을 사용자 정의 할 수 있습니다 설정`ctx.props`견적 요청`globalOutbound`, 위.

```js
import { WorkerEntrypoint } from "cloudflare:workers";

//동적 노동자에 의해 호출 할 수있는 바인딩을 구현합니다.
export class Greeter extends WorkerEntrypoint {
	greet() {
		return `Hello, ${this.ctx.props.name}!`;
	}
}

export default {
	async fetch(request, env, ctx) {
		let worker = env.LOADER.get("alice", () => {
			return {
				env: {
					//호출 할 수있는 방법 그리스 ()가있는 바인딩
					//감사합니다. 바인딩은 노동자의 이름을 알고 있습니다.
					GREETER: ctx.exports.Greeter({ props: { name: "Alice" } }),
				},

				//... 코드 ...
			};
		});

		return worker.getEntrypoint().fetch(request);
	},
};
```

#### <code>기타 제품<Type text="ServiceStub[]" />옵션 정보</code>

하나 이상의 지정할 수 있습니다.[꼬리 Workers](/workers/observability/logs/tail-workers/)콘솔 로그, 오류 및 동적 부하 작업자의 실행에 대한 기타 세부 사항을 관찰 할 수 있습니다. 꼬리 이벤트는 역동적으로 로드 된 노동자에 요청 완료시 꼬리 노동자에 전달됩니다. 항상, 당신은 당신의 부모 노동자에 있는 대안 입장으로 꼬리 노동자를 실행할 수 있습니다, 그것을 사용하여 참조`ctx.exports`:

```js
import { WorkerEntrypoint } from "cloudflare:workers";

export default {
	async fetch(request, env, ctx) {
		let worker = env.LOADER.get("alice", () => {
			return {
				//로그, 오류 등을 `LogTailer`로 전송합니다. 우리는 `name`를 안으로 통과합니다
				//`ctx.props` 그래서 `LogTailer`는 어떤 생성 로그를 알고.
				//(`props`에서 원하는 모든 것을 통과 할 수 있습니다.)
				tails: [ctx.exports.LogTailer({ props: { name: "alice" } })],

				//... 코드 ...
			};
		});

		return worker.getEntrypoint().fetch(request);
	},
};

export class LogTailer extends WorkerEntrypoint {
	async tail(events) {
		let name = this.ctx.props.name;

		//우리의 로그 엔드 포인트에 로그를 전송, 노동자 이름을 지정
		//URL.
		//
		//`events`는 항상 이 시나리오에서 크기 1의 배열일 것입니다,
		//Dynamically-loaded Worker에 전달된 이벤트를 설명합니다.
		await fetch(`https://example.com/submit-logs/${name}`, {
			method: "POST",
			body: JSON.stringify(events),
		});
	}
}
```
