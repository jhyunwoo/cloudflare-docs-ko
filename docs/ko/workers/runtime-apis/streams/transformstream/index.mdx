## 이름 \*

변환 스트림은 한 쌍의 스트림으로 이루어져 있습니다 : writable 스트림, 그것의 writable 측면으로 알려진, 그리고 읽을 수있는 스트림, 그것의 읽기 쉬운 측면으로 알려져. 읽을 수 있는 측에서 독서를 위해 유효한 새로운 자료에 있는 writable 측 결과에 씁니다.

Workers는 현재 정체성 변환 스트림을 구현하고 있으며, 어떤 변화없이 읽을 수있는 측면에 대한 모든 펑크를 전달합니다.

***

## 회사연혁

```js
let { readable, writable } = new TransformStream();
```

- `TransformStream()`관련 링크

  - 새로운 ID 변환 스트림을 반환합니다.

## 제품 정보

- `readable`읽을 수 있는Stream
  - 예를 들어`ReadableStream`.
- `writable`WritableStream의 장점
  - 예를 들어`WritableStream`.

***

## `IdentityTransformStream`

현재 구현`TransformStream`Workers 플랫폼은 현재 호환되지 않습니다[스트림 표준](https://streams.spec.whatwg.org/#transform-stream)그리고 우리는 곧 규격에 맞게 구현에 변경 될 것입니다. 이렇게 하기를 위한 준비에서는, 우리는 소개했습니다`IdentityTransformStream`현재의 동작을 구현하는 클래스`TransformStream`수업. 스트림의 이 유형은 바이트 데이터의 모든 펑크를 전달합니다 (형에서`TypedArray`s)는 어떤 변화 없이 그것의 읽을 수 있는 측에 그것의 writable 측에 기록했습니다.

더 보기`IdentityTransformStream`readable 측 지원[자신의 버퍼 (BYOB)를 가져옵니다](https://developer.mozilla.org/en-US/docs/Web/API/ReadableStreamBYOBReader).

### 회사연혁

```js
let { readable, writable } = new IdentityTransformStream();
```

- `IdentityTransformStream()`IdentityTransformStream의 장점

  - 새로운 ID 변환 스트림을 반환합니다.

### 제품 정보

- `readable`읽을 수 있는Stream
  - 예를 들어`ReadableStream`.
- `writable`WritableStream의 장점
  - 예를 들어`WritableStream`.

***

## `FixedLengthStream`

더 보기`FixedLengthStream`특수화`IdentityTransformStream`스트림이 통과 할 바이트의 총 수를 제한합니다. 그것은 사용시 주로 유용합니다.`FixedLengthStream`생산하기`Response`또는`Request`, 스트림의 고정 길이 사용 될 것 이다`Content-Length`다른 어떤 스트림을 사용할 때 chunked 인코딩을 사용하지 않는 한 헤더 값. 오류가 너무 많은 경우 발생하거나 스트림을 통해 몇 바이트가 작성됩니다.

### 회사연혁

```js
let { readable, writable } = new FixedLengthStream(1000);
```

- `FixedLengthStream(length)`고정 길이스트림

  - 새로운 ID 변환 스트림을 반환합니다.
  - `length`아마`number`또는`bigint`최대 값으로`2^53 - 1`.

### 제품 정보

- `readable`읽을 수 있는Stream
  - 예를 들어`ReadableStream`.
- `writable`WritableStream의 장점
  - 예를 들어`WritableStream`.
