## 이름 \*

더 보기[메시지Channel API](https://developer.mozilla.org/en-US/docs/Web/API/MessageChannel)응용 프로그램의 다른 부분 사이에 통신 채널을 만들 수있는 방법을 제공합니다.

Workers 런타임은 최소 구현을 제공합니다.`MessageChannel`API는
현재 단일 Worker 인스턴스와 함께 사용하도록 제한됩니다. 이것은 당신이 사용할 수 있다는 것을 의미합니다`MessageChannel`당신의 노동자의 다른 부속 사이 메시지를 보낼 것이다, 그러나 다른 Workers의 맞은편에 아닙니다.

```js
const { port1, port2 } = new MessageChannel();

port2.onmessage = (event) => {
	console.log('Received message:', event.data);
};

port2.postMessage('Hello from port2!');
```

어떤 값으로 사용할 수 있습니다`structuredClone(...)`API는 항구에 보내질 수 있습니다.

## 기타

몇 가지 주요 제한이 있습니다.`MessageChannel`Workers에 있는 API:

- 전송 목록은 현재 지원되지 않습니다. 이것은 당신이 이동할 수 없다는 것을 의미합니다
  물체의 소유권`ArrayBuffer`또는`MessagePort`항구 사이.
- 더 보기`MessagePort`아직 serializable 없습니다. 이것은 당신이 보낼 수없는 것을 의미합니다`MessagePort`기타 제품
  한국어`postMessage`방법 또는 JSRPC 통화를 통해.
- 더 보기`'messageerror'`이벤트는 부분적으로 지원됩니다. 만약에`'onmessage'`핸들러는
  오류,`'messageerror'`이벤트는 트리거됩니다, 그러나, 거기 있을 때 트리거되지 않을 것입니다
  errors serializing or deserializing 메시지 데이터입니다. 대신 오류가 발생하면
  이름 \*`postMessage`방법은 전송 포트에 호출됩니다.
- 더 보기`'close'`이벤트는 포트 중 하나가 닫을 때 두 포트에 방출되지만
  노동자가 종결 될 때 방출되지 않거나 포트 중 하나가 수집 된 쓰레기입니다.
