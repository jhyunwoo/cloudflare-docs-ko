[웹 조립](https://webassembly.org/)(약어 Wasm) 같은 언어를 컴파일 할 수 있습니다[Rust](/workers/languages/rust/), 이동, 또는 C는 다양한 환경에서 실행할 수있는 바이너리 형식으로, 포함[웹 브라우저](https://developer.mozilla.org/en-US/docs/WebAssembly#browser_compatibility), Cloudflare Workers 및 다른 웹 조립 가동 시간.

WebAssembly를 사용할 수 있습니다.

- JavaScript 이외의 언어로 작성된 코드를 실행`WebAssembly.instantiate()`·
  :::참조
  `WebAssembly.instantiate()`사전 컴파일된 모듈만 지원[웹 표준 문서](/workers/runtime-apis/web-standards/#javascript-standards).
  :::

- 전체 Cloudflare 쓰기 Rust, Workers' JavaScript Rust 코드에서 직접 사용할 수 있는 API.

## 지원된 제안

WebAssembly는 표준의 급속한 진화 세트, 와[많은 제안 된 API](https://webassembly.org/roadmap/)개발의 다양한 단계에 있습니다. 일반적으로 Workers는 Google Chrome에서 사용할 수있는 기능의 동일한 세트를 지원합니다.

### 사이트맵

SIMD는 Workers에서 지원됩니다. WebAssembly의 SIMD 사용에 대한 자세한 내용은 참조[WebAssembly SIMD를 가진 빠르고, 평행한 신청](https://v8.dev/features/simd).

### 회사 소개

스레드는 Workers에서 할 수 없습니다. 각 노동자는 단일 스레드에서 실행, 그리고[웹 노동자](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API)API는 지원되지 않습니다.

## Binary 크기

WebAssembly에 부합하는 것은 추가 런타임 의존성을 포함해야 합니다. 결과적으로, Workers를 사용하는 것은 일반적으로 JavaScript에 기록된 동등한 노동자 보다는 더 크다. 더 큰 노동자는, 더 긴 그것은 당신의 노동자를 시작할지도 모릅니다. 더 알아보기[Worker 시작 시간](https://developers.cloudflare.com/workers/platform/limits/#worker-startup-time)더 많은 정보. 우리는 같은 도구를 사용하는 것이 좋습니다[`wasm-opt`](https://github.com/brson/wasm-opt-rs)Wasm 바이너리의 크기를 최적화합니다.

## WebAssembly 시스템 인터페이스 (WASI)

더 보기[WebAssembly 시스템 인터페이스](https://wasi.dev/)(약어 WASI)는 WebAssembly에 대한 모듈 형 시스템 인터페이스로 네트워킹, 파일 시스템 액세스 등을 위해 시스템 통화의 집합을 표준화합니다. WebAssembly System Interface에 따라 호스트 환경 및 운영 체제에서 동일하게 동작할 수 있습니다.

WASI는 Wasm보다 훨씬 빠르게 진화하는 표준입니다. WASI 지원은 Cloudflare Workers에 실험적이며, 일부 syscall 만 구현됩니다. 우리를 따르라[WASI의 오픈 소스 구현](https://github.com/cloudflare/workers-wasi)·[Workers에 대한 블로그 게시물](https://blog.cloudflare.com/announcing-wasi-on-workers/)사용 중지.
