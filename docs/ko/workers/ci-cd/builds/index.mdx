Cloudflare[Git 통합](/workers/ci-cd/builds/git-integration/)새로운 또는 기존 Worker를 GitHub 또는 GitLab 저장소에 연결할 수 있도록 자동화된 빌드 및 배포를 제공합니다.

## 시작하기

### 새로운 노동자를 연결

새로운 노동자를 만들고 GitHub 또는 GitLab 저장소에 연결하십시오.

1. Cloudflare dashboard에서, 가십시오**Workers & Pages**사이트 맵

   <DashButton url="/?to=/:account/workers-and-pages" />

2. 제품정보**회사연혁**.

3. 제품정보**시작하기**이름 \***저장소 가져오기**.

4. 이름 \***저장소 가져오기**, 선택**Git 계정**.

5. 목록에서 가져올 저장소를 선택합니다. 검색 바를 사용하여 결과를 축소 할 수 있습니다.

6. 프로젝트 구성 및 선택**저장 및 배포**.

7. 제공된 작업자 미리보기[`workers.dev`](/workers/configuration/routing/workers-dev/)하위 도메인.

### 기존 Worker 연결

기존 Worker를 GitHub 또는 GitLab 저장소에 연결하려면:

1. Cloudflare QXdashboard에서, 갑니다**Workers & Pages**사이트 맵

   <DashButton url="/?to=/:account/workers-and-pages" />

2. 저장소에 연결하려는 노동자를 선택하십시오.

3. 제품정보**계정 설정**그리고 그때**회사연혁**.

4. 제품정보**연결하기**작업자에 저장소를 연결하고 구성하기 위해 프롬프트를 따르십시오.[설정 설정](/workers/ci-cd/builds/configuration/).

5. Git 저장소에 커밋을 밀어서 빌드를 트리거하고 작업자에게 배포합니다.

:::카트로션

Workers 프로젝트에 저장소를 연결하면 Cloudflare QXQXQXdashboard에 있는 노동자 이름은 일치해야 합니다`name`지정된 루트 디렉토리의 Wrangler 구성 파일 또는 빌드가 실패합니다. 이 저장소에서 배포 된 노동자가 Cloudflare dashboard에 등록 된 노동자와 일관성을 보장합니다. 자주 묻는 질문[Workers 이름 필요조건](/workers/ci-cd/builds/troubleshoot/#workers-name-requirement).

:::

## 자동 프로젝트 구성

Wrangler 구성 파일이 없는 저장소를 연결할 때,[자동 설정](/workers/framework-guides/automatic-configuration/)프레임 워크를 감지하고 생성[연락처](/workers/ci-cd/builds/automatic-prs/)Cloudflare WorkersXQ에 대한 프로젝트를 구성합니다.

1. Autoconfig는 프레임워크를 감지하고 필요한 구성을 생성합니다.
2. 필요한 구성 변경으로 저장소에서 풀 요청이 생성됩니다.
3. 미리보기 배포가 생성되므로 merging 전에 테스트 할 수 있습니다.
4. PR을 병합하면 프로젝트가 배포 준비됩니다.

지원된 프레임워크에 대한 세부 사항 및 파일이 생성된 것, 참조[기존 프로젝트 배포](/workers/framework-guides/automatic-configuration/). 생성된 PR에 대한 자세한 내용은 참조[자동적인 잡아당기기 요구](/workers/ci-cd/builds/automatic-prs/).

## 빌드 및 미리보기 URL

빌드의 상태와 빌드 로그를 navigating로 모니터링 할 수 있습니다.**회사연혁**아래에서**계정 만들기**작업자의 탭.

빌드가 성공하면, 선택하여 빌드 세부 사항을 볼 수 있습니다.**뷰 빌더**관련 새로운[이름 \*](/workers/configuration/versions-and-deployments/)버전 역사에서 생성. 또한 찾을 수 있습니다[URL 보기](/workers/configuration/previews/)버전 ID에 의해 생성.

:::note\[건축, 버전, 배포]

빌드가 성공하면 버전으로 업로드됩니다. 빌드가 배치하는 경우 (예를 들어,`wrangler deploy`배포 명령으로 설정), 업로드 된 버전은 자동으로 Active Deployment에 홍보됩니다.

:::

## 연락처

GitHub 또는 GitLab 저장소에서 작업자를 분리하려면:

1. Cloudflare dashboard에서, 가십시오**Workers & Pages**사이트 맵

   <DashButton url="/?to=/:account/workers-and-pages" />

2. 저장소에서 분리하려는 노동자를 선택하십시오.

3. 제품정보**계정 설정**그리고 그때**회사연혁**.

4. 제품정보**연결하기**.

노동자를 위해 다른 저장소로 전환하려면 먼저 빌드를 비활성화해야합니다. 새로운 저장소를 선택하려면 다시 연결하십시오.

자동 배포를 비활성화하려면 자동으로 실행하고 저장할 수 있습니다.[이름 \*](/workers/configuration/versions-and-deployments/)(Active 배포를 홍보하지 않고), 배포 명령을 업데이트:`npx wrangler versions upload`.
