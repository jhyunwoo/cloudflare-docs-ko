Cloudflare는 당신의 CloudflareXQ에 당신의 GitLab 저장소 연결을 지원합니다 Worker, 자동으로 코드를 배포합니다.

## 주요 특징

자동 빌드 및 배포를 넘어 Cloudflare GitLab 통합은 GitLab에서 직접 빌드를 모니터링하고 워크플로를 떠나지 않고 알려줍니다.

### Merge 요청 코멘트

커밋이 병합 요청에 따라 Cloudflare는 자동으로 빌드 상태와 병합 요청에 대한 의견을 게시합니다.

![GitLab 병합 요청 코멘트](~/assets/images/workers/platform/ci-cd/gitlab-pull-request-comment.png)

·[URL 보기](/workers/configuration/previews/)수행 할 모든 빌드에 제공 될 것입니다`wrangler versions upload`. 그것은 당신이 당신의 노동자의 업데이트 된 버전과 함께 코드 변경을 비교할 수 있기 때문에 당신의 풀 요청을 검토 할 때 특히 유용합니다.

:::note\[GitLab Merge 기존 연결에 대한 요청 이벤트]
새로운 GitLab 연결은 자동으로 병합 요청 이벤트를 수신하도록 구성되어 있습니다. 기존의 연결을 위해서는 수동으로 활성화해야 합니다.`Merge request events`프로젝트의 설정의 Webhooks 탭에서. GitLab의 설명서를 따라갈 수 있습니다.[웹훅 관리](https://docs.gitlab.com/user/project/integrations/webhooks/#manage-webhooks).
:::

### Commit 상태

저장소에 연결되는 1개 또는 다수 Workers가 있는 경우에 (i.e. a[모노레포](/workers/ci-cd/builds/advanced-setups/#monorepos)), 당신은 GitLab에서 각 구조의 상태를 검사할 수 있습니다[GitLab 커밋 상태](https://docs.gitlab.com/ee/user/project/merge_requests/status_checks.html).

커밋과 같은 상태 아이콘을 선택하여 상태를 볼 수 있습니다.**제품정보** > **파이프 라인**GitLab 저장소 내에서. 아래 예에서 녹색 체크 마크를 선택하여 체크 실행 결과를 볼 수 있습니다.

![GitLab 상태](~/assets/images/workers/platform/ci-cd/gl-status-checks.png)

체크 실행은 저장소에서 다음과 같이 나타납니다. Cloudflare 대시보드에서 빌드를 볼 수 있습니다.

![GitLab Commit 상태](~/assets/images/workers/platform/ci-cd/gl-commit-status.png)

사용시 주의사항[시계 경로 구축](/workers/ci-cd/builds/build-watch-paths/), 빌드를 트리거하는 유일한 프로젝트는 커밋 상태를 생성합니다.

### Cloudflare GitLab 앱 설치

1. GitLab의 응용 프로그램 설정 페이지로 이동:[https://gitlab.com/-/profile/applications](https://gitlab.com/-/profile/applications)
2. Cloudflare QXWorkersXQ 설치에 "Revoke"버튼을 클릭하십시오.
3. 바로가기[**Workers & Pages**모델 번호: overview](https://dash.cloudflare.com)사이트 맵 제품정보**회사연혁** > **모델 번호: Pages** > **Git에 연결**.
4. 선택하&#xAE30;**+ 계정 추가**버튼, 추가하려는 GitLab 계정을 선택하고, 다음을 선택합니다.**설치 및 권한**.
5. 계정 목록에서 GitLab 계정 또는 조직으로 프로젝트 페이지를 리디렉션해야합니다.
6. 이전에 깨진 프로젝트로 새로운 배포를 만들려면.
