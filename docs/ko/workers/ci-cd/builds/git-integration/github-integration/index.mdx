Cloudflare는 GitHub 저장소를 CloudflareXQ에 연결하는 것을 지원합니다 Worker, 자동으로 코드를 배포합니다.

## 주요 특징

자동 빌드 및 배포를 넘어 Cloudflare GitHub 통합은 GitHub에서 직접 빌드를 모니터링하고 워크플로를 남기지 않고 알려줍니다.

### Pull 요청 코멘트

커밋이 풀 요청에 따라 Cloudflare는 자동으로 빌드의 상태와 풀 요청에 대한 의견을 게시합니다.

![GitHub pull request 댓글](~/assets/images/workers/platform/ci-cd/github-pull-request-comment.png)

·[URL 보기](/workers/configuration/previews/)수행 할 모든 빌드에 제공 될 것입니다`wrangler versions upload`. 그것은 당신이 당신의 노동자의 업데이트 된 버전과 함께 코드 변경을 비교할 수 있기 때문에 당신의 풀 요청을 검토 할 때 특히 유용합니다.

코멘트 역사는 PR이 열리면서도 빌드가 완료되었습니다.

![GitHub Pull 요청 의견 역사](~/assets/images/workers/platform/ci-cd/github-pull-request-comment-history.png)

### 자주 묻는 질문

저장소에 연결되는 1개 또는 다수 Workers가 있는 경우에 (i.e. a[모노레포](/workers/ci-cd/builds/advanced-setups/#monorepos)) GitHub에서 각 빌드의 상태를 확인할 수 있습니다.[GitHub 체크 실행](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/collaborating-on-repositories-with-code-quality-features/about-status-checks#checks).

GitHub 저장소 내에서 커밋하는 상태 아이콘을 선택하여 체크를 볼 수 있습니다. 아래 예에서 체크 실행 결과를 볼 수있는 녹색 체크 마크를 선택할 수 있습니다.

![GitHub 상태](~/assets/images/workers/platform/ci-cd/gh-status-check-runs.png)

체크 실행은 저장소에서 다음과 같이 나타납니다. 선택할 수 있습니다.**이름 \***&#xAC01; 검사와 관련된 빌드 (Build ID) 및 프로젝트 (Script)를 볼 수 있습니다.

![GitHub 체크 실행](~/assets/images/workers/platform/ci-cd/workers-builds-gh-check-runs.png)

사용시 주의사항[시계 경로 구축](/workers/ci-cd/builds/build-watch-paths/), 빌드를 트리거하는 유일한 프로젝트는 체크 실행을 생성합니다.

## 자주 묻는 질문

프로젝트는 GitHub에서 Cloudflare WorkersXQ에 배포할 수 있습니다.[Cloudflare Workers & PagesXQ GitHub 앱](https://github.com/apps/cloudflare-workers-and-pages).

### 회사연혁

Cloudflare QXWorkers를 승인하면 GitHub 계정에 액세스할 수 있으며 GitHub에 속한 개인 계정 또는 조직에 액세스할 수 있습니다.

조직에 Cloudflare Workers 설치를 추가하려면 사용자 계정이 소유자이어야하며 조직 내에서 적절한 역할을해야합니다 (예 : GitHub Apps Manager 역할). 이 역할에 대한 더 많은 정보는 위에 볼 수 있습니다[GitHub의 문서](https://docs.github.com/en/organizations/managing-peoples-access-to-your-organization-with-roles/roles-in-an-organization#github-app-managers).

:::caution\[GitHub 보안 고려사항]

GitHub 계정은 하나의 Cloudflare 계정으로만 해당해야 합니다. CloudflareXQ를 조직의 GitHub로 설정하면 CloudflareXQ는 PagesXQ로 구축하려는 저장소의 범위를 제한하는 것이 좋습니다. 이 권한을 수정하려면, 이동[회사연혁](https://github.com/settings/installations)GitHub에서 선택**Switch 설정**GitHub 조직 설정에 액세스하십시오. 다음, 선택**CloudflareWorkers & Pages**> 용**Repository 접근**, 선택**자주 묻는 질문**> 저장소를 선택하십시오.

:::

### 자주 묻는 질문

GitHub 저장소 또는 계정에 액세스하여 QXQX0116XQQWorkersXQ를 제거할 수 있습니다.[회사연혁](https://github.com/settings/installations)GitHub에서 (당신이 조직에 있다면, GitHub 조직 설정에 액세스하기 위해 Switch 설정 컨텍스트를 선택합니다). GitHub 앱은 Cloudflare Workers 및 PagesXQ라는 이름이며 Workers 및 Pages 프로젝트 사이에 공유됩니다.

#### GitHub 저장소에 Cloudflare 액세스 제거

개인 GitHub 저장소에 액세스하려면 탐색할 수 있습니다.**Repository 접근**. 선택**자주 묻는 질문**옵션 및 Cloudflare와 같은 저장소를 재구성하여 액세스 할 수 있습니다.

![GitHub 저장소 액세스](~/assets/images/workers/platform/ci-cd/github-repository-access.png)

#### 전체 GitHub 계정에 Cloudflare 액세스 제거

Cloudflare QXWorkers 및 Pages 액세스를 전체 Git 계정에 제거하려면 탐색 할 수 있습니다.**제거 "Cloudflare Workers 및 Pages"**, 다음 선택**다운로드**. Cloudflare Workers 및 Pages 앱에 대한 액세스를 제거하면 CloudflareXQ의 액세스가 수정됩니다.*모든 저장소*GitHub 계정에서. 자동 빌드 및 배포만 비활성화하려면[Disable 구조](/workers/ci-cd/builds/#disconnecting-builds)이름 \*

GitHub에 액세스 제거는 Workers 및 Pages 프로젝트에 대한 새로운 빌드를 비활성화 할 수 있지만 이전 배포는 Cloudflare WorkersXQ에 의해 계속 호스팅됩니다.

### Cloudflare GitHub 앱 설치

Git 통합 관련 문제가 발생하면 잠재적 인 문제 해결 단계는 Cloudflare QXQXPages 설치와 관련된 GitHub 또는 GitLab 응용 프로그램을 제거하고 재설치하려고합니다. 각 Git 공급자를 위한 과정은 아래에 제공됩니다.

1. GitHub의 설치 설정 페이지로 이동:
   - 바로가기**설정 > 회사연혁**Workers 또는 Pages 프로젝트 및 선택을위한**계정 관리**Git 저장소 아래.
   - 대안으로, Cloudflare QXWorkers 및 Pages 설치 및 선택이 링크를 방문**설정하기**:

|          |                                                                                    |
| -------- | ---------------------------------------------------------------------------------- |
| **한국어**  | `https://github.com/settings/installations`                                        |
| **회사연혁** | `https://github.com/organizations/<YOUR_ORGANIZATION_NAME>/settings/installations` |

2. Cloudflare QXWorkers 및 QXQX0146XQQ GitHub 앱 설정 페이지에서 탐색**제거 "Cloudflare Workers 및 Pages"**&#xC120;택하기**다운로드**.
3. 바로가기[**Workers & Pages**모델 번호: overview](https://dash.cloudflare.com)사이트 맵 제품정보**회사연혁** > **모델 번호: Pages** > **Git에 연결**.
4. 선택하&#xAE30;**+ 계정 추가**버튼, 추가하려는 GitHub 계정을 선택하고, 다음 선택**설치 및 권한**.
5. 계정 목록에서 GitHub 계정 또는 조직으로 프로젝트 페이지를 리디렉션해야합니다.
6. 이전에 깨진 프로젝트로 새로운 배포를 만들려면.
