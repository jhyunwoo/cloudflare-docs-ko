Git 저장소를 작업자에게 연결하면 작업자를 구축하고 배포할 필요가 있는 구성을 사용자 정의할 수 있습니다.

## Workers 빌드 작업

커밋이 연결 저장소에 푸시되면 Workers 빌드는 두 단계 프로세스를 실행:

1. **명령 실행** *(선택)*- 프로젝트를 컴파일 (예를 들면,`npm run build`Next.js 또는 AstroXQ와 같은 기구를 위해)
2. **배포 명령**- Cloudflare (기본값에서`npx wrangler deploy`)

미리보기 빌드 (생산 지점 이외의 다른 지점을 할당), 배포 명령은 대체됩니다**미리보기 배치 명령**(과태에`npx wrangler versions upload`), 그것은 생산에 승진 없이 미리보기 버전을 창조합니다.

### 배포 명령

당신은 당신의 선택의 패키지 관리자를 사용하여 배포 명령을 실행할 수 있습니다.

Wrangler 배포 명령을 스크립트에 추가하면`package.json`, 다음 배포 명령으로 설정하여 실행할 수 있습니다. 예를 들어,`npm run deploy`.

다른 배포 명령의 예는 다음과 같습니다.

| 예제 명령                                    | 이름 \*                                                                                                                                                                                                        |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `npx wrangler deploy --assets ./public/` | 지정된 디렉토리에서 정적 자산과 함께 작업자를 배포합니다. 대안으로, 당신은 사용할 수 있습니다[자산 바인딩](/workers/static-assets/binding/).                                                                                                              |
| `npx wrangler deploy --env staging`      | 당신이 있는 경우에[Wrangler 환경](/workers/ci-cd/builds/advanced-setups/#wrangler-environments)작업자, 당신은 환경 플래그와 함께 배포 명령을 설정해야합니다. 더 자세한 내용을 보려면[고급 설정](/workers/ci-cd/builds/advanced-setups/#wrangler-environments). |

### Non-production 분기 배포 명령

non-production 분기 배포 명령은 활성화되었을 때만 적용 가능합니다.[비생산점 구축](/workers/ci-cd/builds/build-branches/#configure-non-production-branch-builds).

그것은 기본적으로`npx wrangler versions upload`, 생성[URL 보기](/workers/configuration/previews/). 빌드 및 배포 명령처럼, 그것은 대신 아무것도 실행할 수 있습니다.

다른 비 생산 지점 배포 명령의 예는 다음과 같습니다.

| 예제 명령                                        | 이름 \*                                                                                                                                                                                                             |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `yarn exec wrangler versions upload`         | WranglerXQ를 실행하는 데 사용되는 패키지 관리자를 사용자 정의 할 수 있습니다.                                                                                                                                                                 |
| `npx wrangler versions upload --env staging` | 당신이 있는 경우에[Wrangler 환경](/workers/ci-cd/builds/advanced-setups/#wrangler-environments)작업자, 당신은 환경 플래그와 비 생산 지점 배치 명령을 설정해야합니다. 더 자세한 내용을 보려면[고급 설정](/workers/ci-cd/builds/advanced-setups/#wrangler-environments). |

### 새로운 프로젝트에 대한 자동 구성

저장소가 WranglerXQ 구성 파일이 없는 경우, 배포 명령(`wrangler deploy`) 트리거[자동 프로젝트 구성](/workers/framework-guides/automatic-configuration/). 이것은 당신의 기구를 검출하고, 필요한 윤곽을 창조하고, 엽니다[연락처](/workers/ci-cd/builds/automatic-prs/)리뷰에 대해 PR을 병합하면 프로젝트가 구성되고 미래 빌드는 일반적으로 배치됩니다.

### API 토큰

Workers의 API 토큰 빌드는 Workers에 부여된 액세스 권한을 정의하여 계정의 리소스와 상호 작용합니다. 현재 사용자 토큰만 지원됩니다. 계정 소유 토큰 지원이 곧 제공됩니다.

당신이 선택할 때**새로운 토큰 만들기**, 새로운 API 토큰은 다음과 같은 권한으로 자동으로 생성됩니다.

- **계정:**&#xACC4;정 설정 (읽기), Workers 스크립트 (edit), Workers KVQ 저장 (edit), WorkersQR2QXQ 저장 (edit)
- **지역:**&#xBAA8;델 번호: Workers 계정의 모든 영역에 대한 경로 (edit)
- **사용자:**&#xC0AC;용자 정보 (읽기), 회원 (읽기)

이 API 토큰의 권한을 navigating로 구성할 수 있습니다.**내 프로필** > **API 토큰**사용자 토큰

일관된 액세스 권한을 유지하기 위해 작업자의 모든 업로드 및 배포에 걸쳐 동일한 API 토큰을 지속적으로 사용할 것을 권장합니다.

### 기본 변수

다음과 같은 시스템 환경 변수는 기본적으로 주사됩니다 (그러나 overridden 일 수 있습니다):

| 환경 변수                   | 잘못된 값                           | 사용 사례                                           |
| ----------------------- | ------------------------------- | ----------------------------------------------- |
| `CI`                    | `true`                          | CI versus 로컬에서 실행할 때 빌드 동작 변경                   |
| `WORKERS_CI`            | `1`                             | Workers에서 실행할 때 빌드 동작 변경 로컬로 versus 구축          |
| `WORKERS_CI_BUILD_UUID` | `<build-uuid-of-current-build>` | 사용자 정의 워크플로우에 따라 빌드 UUID 전달                     |
| `WORKERS_CI_COMMIT_SHA` | `<sha1-hash-of-current-commit>` | 현재 커밋 ID를 오류 보고, 예를 들어, Sentry                  |
| `WORKERS_CI_BRANCH`     | `<branch-name-from-push-event`  | 분기에 따라 사용자 정의 빌드, 예를 들어, 디버그 로깅을 해제`production` |
