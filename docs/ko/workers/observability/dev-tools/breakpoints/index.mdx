## Breakpoints를 통해 디버그

Wrangler 또는 Vite를 사용하는 노동자를 로컬로 개발할 때, 당신은 당신의 노동자에 있는 Breakpoints를 통해 디버그 할 수 있습니다. Breakpoints는 작업자의 실행에 주어진 시점에서 무슨 일이 일어나는지를 검토 할 수있는 능력을 제공합니다. Breakpoint 기능은 DevTools와 VS Code 모두에 존재합니다.

Chrome의 DevTools를 통해 Breakpoint 디버깅에 대한 자세한 내용은 참조[Chrome의 breakpoints 기사](https://developer.chrome.com/docs/devtools/javascript/breakpoints/).

### VSCode 디버그 터미널

VSCode의 내장 사용[JavaScript 디버그 터미널](https://code.visualstudio.com/docs/nodejs/nodejs-debugging#_javascript-debug-terminal), 당신이해야 할 모든 것은 JS 디버그 맨끝을 엽니다 (`Cmd + Shift + P`그리고 그 후에 유형`javascript debug`) 및 실행`wrangler dev`(주)`vite dev`) debug 맨끝 안에. VSCode는 자동적으로 실행하는 노동자에 연결됩니다 (단 하나에 다수 WorkersXQ를 달리는 경우에 조차!)는 디버깅 세션을 시작합니다.

### 설정 VS breakpoints를 사용하는 코드`launch.json`이름 \*

작업자 프로젝트에서 Breakpoint 디버깅을 위한 VS Code를 설정하려면:

1. 이름 \*`.vscode`프로젝트의 루트 폴더에 폴더가 존재하지 않는 경우.
2. 그 폴더 내에서, 생성`launch.json`다음 내용으로 파일:

```json
{
	"configurations": [
		{
			"name": "Wrangler",
			"type": "node",
			"request": "attach",
			"port": 9229,
			"cwd": "/",
			"resolveSourceMapLocations": null,
			"attachExistingChildren": false,
			"autoAttachChildProcesses": false,
			"sourceMaps": true // works with or without this line
		}
	]
}
```

3. VS Code에서 프로젝트를 열고, VS Code에서 새로운 터미널 창을 열고, 실행`npx wrangler dev`로컬 dev 서버를 시작합니다.

4. 맨 위로**실행 및 디버그**패널, 구성을 선택할 수있는 옵션을 볼 수 있습니다. 제품 정보**모델 번호: Wrangler**, 재생 아이콘을 선택합니다.**Wrangler: 원격 프로세스 \[0]**&#xC67C;쪽에 통화 스택 패널에서 표시해야합니다.

5. 바로가기`.js`또는`.ts`프로젝트의 파일과 적어도 하나의 Breakpoint를 추가합니다.

6. 브라우저를 열고 Worker의 로컬 URL로 이동 (기본값)`http://127.0.0.1:8787`). Breakpoint는 히트해야하며 지정된 줄에서 코드에 대한 세부 정보를 검토 할 수 있어야합니다.

:::카트로션

Breakpoint 디버깅`wrangler dev`이름 \*`--remote`Worker CPU 시간 확장 및 사용 제한에 대한 계산 실제 자원에 대한 테스트 이후 추가 비용. 이용에 좋습니다.`wrangler dev`없음`--remote`옵션. 로컬로 개발할 수 있습니다.

사용 안 함`--remote`, 디버거로 코드 축소를 사용할 수 없습니다 휴식 지점에서 중지 될 때 vars 찾을 수 없습니다. 수정되지 않음`true`Wrangler 설정 파일에서.

:::

:::참조

더 보기`.vscode/launch.json`파일은 단일 작업 공간에만 적용됩니다. 선호하는 경우, 위의 실행 구성을 사용자 설정에 추가 할 수 있습니다 (당신)[공식 VS Code 문서](https://code.visualstudio.com/docs/editor/debugging#_global-launch-configuration)) 모든 작업 공간에 사용할 수 있습니다.

:::
