Workers 오류 및 예외 검토.

## Workers에 의해 생성된 오류 페이지

작업자가 생산에서 실행되면 응답을 반환하는 오류가 발생하면 클라이언트는 다음과 같이 정의된 오류 코드와 오류 페이지를 받게됩니다.

| 오류 코드   | 이름 \*                                                                                                                                                                                           |
| ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `1101`  | 노동자는 JavaScript 예외를 threw.                                                                                                                                                                      |
| `1102`  | 노동자 초과[CPU 시간 제한](/workers/platform/limits/#cpu-time).                                                                                                                                          |
| `1103`  | 이 노동자의 소유자는 접촉해야[Cloudflare 지원](/support/contacting-cloudflare-support/)                                                                                                                        |
| `1015`  | 노동자는[파열률 제한](/workers/platform/limits/#burst-rate).                                                                                                                                             |
| `1019`  | 채용공고[루프 제한](#loop-limit).                                                                                                                                                                       |
| `1021`  | Worker는 호스트가 접근할 수 없습니다.                                                                                                                                                                        |
| `1022`  | Cloudflare는 노동자에게 요청을 경로를 실패했습니다.                                                                                                                                                               |
| `1024`  | 노동자는 Cloudflare-owned IP 주소로 하위 요청을 만들 수 없습니다.                                                                                                                                                  |
| `1027`  | Worker는 자유로운 층을 초과했습니다[일일 요청 제한](/workers/platform/limits/#daily-request).                                                                                                                      |
| `1042`  | 노동자는 같은 지역에 또 다른 노동자에서 태워 시도, 이는 단지[지원되는](/workers/runtime-apis/fetch/)현재 위치[`global_fetch_strictly_public`호환성 깃발](/workers/configuration/compatibility-flags/#global-fetch-strictly-public)사용. |
| `10162` | 모듈은 지원되지 않는 Content-Type을 가지고 있습니다.                                                                                                                                                             |

이름 \*`11xx`오류는 일반적으로 Workers 런타임 자체로 문제를 나타냅니다. 더 알아보기[본문 바로가기](https://www.cloudflarestatus.com)오류가 발생하면 됩니다.

오류에`11xx`범위는 또한 관련일 수 있습니다[뚱 베어](/rules/snippets/).

### 루프 제한

노동자는 스스로 또는 다른 노동자에게 16 시간 이상 호출할 수 없습니다. Workers,[`CF-EW-Via`](/fundamentals/reference/http-headers/#cf-ew-via)header의 값은 많은 주장이 남아있는 것을 나타내는 정수입니다. 매번 노동자는 부유 한, 정수는 1에 의해 줄 것이다. 카운트가 0에 도달하면[`1019`](#error-pages-generated-by-workers)오류가 반환됩니다.

### "스크립트는 응답을 생성하지 않습니다" 오류

일부 요청은 1101 오류를 반환 할 수 있습니다.`The script will never generate a response`오류 메시지. Workers 런타임이 요청이 실행되지 않은 모든 코드를 감지하고 이벤트가 이벤트 루프에 남아있는 경우 응답이 반환되지 않았습니다.

#### 원인 1 : 해결되지 않은 약속

이것은 결코 해결되지 않았거나 거부되지 않는 Promise에 의존하여 가장 일반적으로 발생합니다. 응답을 반환해야합니다. 디버그로, 응답을 차단하는 코드 또는 의존성 코드 내에서 Promises를 찾습니다.

브라우저 및 기타 JavaScript 런타임에서 동일한 코드는 무한하게, 버그와 메모리 누출을 모두 선도합니다. Workers 런타임은 디버그를 돕기 위해 명시된 오류를 발생시킵니다.

아래 예에서 응답은 결코 일어나지 않는 약속에 의존합니다. 자주 묻는 질문`resolve`콜백은 문제를 해결합니다.

```js null {9}
export default {
	fetch(req) {
		let response = new Response("Example response");
		let { promise, resolve } = Promise.withResolvers();

		//약속이 해결되지 않은 경우, Workers 실행 시간은
		//이것을 인식하고 오류를 던져.

		//setTimeout(해결, 0)

		return promise.then(() => response);
	},
};
```

이를 방지할 수 있습니다.[`no-floating-promises`eslint 규칙](https://typescript-eslint.io/rules/no-floating-promises/)Promise가 생성되고 제대로 처리되지 않을 때보고있는 .

#### 원인 2: 결코 닫히지 않는 WebSocket 연결

WebSocket이 서버 측 연결을 닫는 적절한 코드를 누락하면 Workers 런타임이 종료됩니다.`script will never generate a response`오류. 아래 예제에서,`'close'`클라이언트의 이벤트는 호출하여 제대로 처리되지 않습니다.`server.close()`, 과실은 던진다. 이를 피하기 위해 WebSocket의 서버 측 연결이 사건 청취자 또는 기타 서버 측 논리를 통해 제대로 닫힙니다.

```js null {10}
async function handleRequest(request) {
	let webSocketPair = new WebSocketPair();
	let [client, server] = Object.values(webSocketPair);
	server.accept();

	server.addEventListener("close", () => {
		//이 누락된 선은 WebSocket 연결이 무한하게 유지될 것입니다
		//그리고 "스크립트는 응답을 생성하지 않을 것" 오류
		//서버.close();
	});

	return new Response(null, {
		status: 101,
		webSocket: client,
	});
}
```

### "Illegal invocation" 오류

오류 메시지`TypeError: Illegal invocation: function called with incorrect this reference`주입의 근원일 수 있습니다.

이것은 일반적으로 호출 기능 호출에 의해 발생`this`, 하지만 값의`this`잃었다.

예를 들어, 주어진`obj`객체와`obj.foo()`논리가 의존하는 방법`this`, 방법을 통해 실행`obj.foo();`확인하기`this`제대로 references`obj`객체. 그러나, 변수에 메소드를 할당, e.g.`const func = obj.foo;`그런 변수를 호출, e.g.`func();`현재 위치`this`이름 \*`undefined`. 이 때문에`this`방법은 독립 함수로 호출될 때 손실됩니다. JavaScript의 표준 동작입니다.

연습에서, 이것은 종종 런타임 제공 자바 스크립트 개체를 파괴 할 때 볼 수 있습니다.`this`, 등`ctx`.

다음 코드는 오류가 발생합니다.

```js
export default {
	async fetch(request, env, ctx) {
		//ctx의 파괴는 waitUntil이 '이' reference
		const { waitUntil } = ctx;
		//waitUntil 오류, 그것으로 '이'
		waitUntil(somePromise);

		return fetch(request);
	},
};
```

오류를 피하기 위해 원래 상황에 대한 함수를 수정하거나 재 바인딩하지 마십시오.

다음 코드는 제대로 실행됩니다:

```js
export default {
	async fetch(request, env, ctx) {
		//ctx의 메소드를 직접 호출하는 것은 오류를 피합니다.
		ctx.waitUntil(somePromise);

		//적용을 통해 ctx에 대안으로 재 바인딩, 전화, 또는 바인딩 오류를 방지
		const { waitUntil } = ctx;
		waitUntil.apply(ctx, [somePromise]);
		waitUntil.call(ctx, somePromise);
		const reboundWaitUntil = waitUntil.bind(ctx);
		reboundWaitUntil(somePromise);

		return fetch(request);
	},
};
```

### 다른 요청을 대신하여 I/O를 수행할 수 없습니다.

```
Uncaught (in promise) Error: Cannot perform I/O on behalf of a different request. I/O objects (such as streams, request/response bodies, and others) created in the context of one request handler cannot be accessed from a different request's handler.
```

이 오류는 입력 / 출력 (I / O) 개체 ( 스트림, 요청, 또는 응답과 같은)을 공유하려고 할 때 발생합니다. 다른 직업의 맥락에서 작업자의 한 주장.

Cloudflare Workers에서, 각 invocation는 자주적으로 취급되고 그것의 자신의 실행 상황에 있습니다. 이 디자인은 하나의 요청에 따라 최적의 성능과 보안을 보장합니다. 다른 직업 사이 I/O 개체를 공유하려고 할 때, 당신은이 고립을 깰. 이 객체는 특정 요청에 연결되기 때문에 다른 요청의 핸들러에서 액세스 할 수 없으며 오류로 이동합니다.

이 오류는 I / O 객체를 캐시하려고 할 때 가장 일반적으로 발생합니다.[제품 정보](/workers/runtime-apis/request/)글로벌 범위에서, 그리고 그 후속 요청에 액세스. 예를 들어, 노동자를 만들고 로컬 개발에서 다음 코드를 실행하고, 빠른 성공에 직장인에게 두 가지 요청을 만들면, 이 오류를 재현 할 수 있습니다.

```js
let cachedResponse = null;

export default {
	async fetch(request, env, ctx) {
		if (cachedResponse) {
			return cachedResponse;
		}
		cachedResponse = new Response("Hello, world!");
		await new Promise((resolve) => setTimeout(resolve, 5000)); //5s의 수면은이 특정 오류 사례를 보여줍니다.
		return cachedResponse;
	},
};
```

I/O 객체 자체가 아닌 글로벌 범위의 데이터만 저장하여 이것을 수정할 수 있습니다.

```js
let cachedData = null;

export default {
	async fetch(request, env, ctx) {
		if (cachedData) {
			return new Response(cachedData);
		}
		const response = new Response("Hello, world!");
		cachedData = await response.text();
		return new Response(cachedData, response);
	},
};
```

요청을 통해 상태를 공유해야하는 경우, 고려[모델 번호: Durable Objects](/durable-objects/). 당신이 요구의 맞은편에 자료를 캐시해야 하는 경우에, 사용 고려하십시오[Workers KV](/kv/).

### 유효성 검사 (10021)

10021 오류 코드에는 노동자를 배포하려고 할 때 발생하는 모든 오류가 포함되어 있으며 Cloudflare 그런 다음 최고 수준의 범위를로드하고 실행하려고 시도합니다 (작업자의 앞에 일어나는 것을 모두)[회사 소개](/workers/runtime-apis/handlers/)을 호출합니다. 예를 들어, 잘못된 JavaScript를 사용하여 깨진 작업자를 배포하려고하면`SyntaxError`— Cloudflare는 당신의 노동자를 배치하지 않을 것입니다.

이것은 당신이 당신의 노동자의 최고 수준 범위에서 일하고 있다는 것을 의미합니다[시작 시간 제한 (1s)](/workers/platform/limits/#worker-startup-time)CPU 시간의.

이것은 당신이 당신의 노동자의 최고 수준 범위에서 일하고 있다는 것을 의미합니다[메모리 제한 (128 MB)](/workers/platform/limits/#memory)기억의.

## Workers와 디버그 예외 로그인

[Workers 로그인](/workers/observability/logs/workers-logs)Workers를 디버깅하기위한 강력한 도구입니다. 작업자가 생성한 모든 역사적인 로그를 보여줍니다. 실행 중에 발생하는 모든 uncaught 예외를 포함하여.

Workers 로그, 다음 필터를 사용할 수 있습니다:`$metadata.error EXISTS`. 이것은 그들과 관련된 오류가 있는 모든 로그를 보여줍니다. 필터도 할 수 있습니다.`$workers.outcome`오류로 인한 요청을 찾을 수 있습니다. 예를 들어, 필터링 할 수 있습니다.`$workers.outcome = "exception"`모든 요청을 찾을 수 없습니다.

가능한 모든 결과를 찾을 수 있습니다.[Workers Trace 이벤트](/logs/logpush/logpush-job/datasets/account/workers_trace_events/#outcome)모델 번호: reference.

## Debug 예외에서`Wrangler`

wrangler 사용을 통해 작업자를 디버깅`wrangler tail`예외를 검사하고 수정합니다.

예외는 아래에 표시됩니다`exceptions`JSON의 필드는 반환된`wrangler tail`. 오류가 발생되는 예외를 확인한 후, 수정을 가진 코드를 redeploy하고, 수정을 확인하는 로그를 계속합니다.

## 제3자 로깅 서비스 설정

Worker는 공용 인터넷에서 HTTP 서비스에 HTTP 요청을 할 수 있습니다. 같은 서비스를 사용할 수 있습니다.[회사 소개](https://sentry.io)작업자의 오류 로그를 수집하기 위해 HTTP 요청을 사용하여 오류를보고합니다. 서비스 API 문서에 대한 자세한 내용은 어떤 종류의 요청을 참조하십시오.

외부 로깅 전략을 사용할 때 탁월한 비동기 작업이 클라이언트에게 주요 응답 몸을 보내는 작업자 마무리로 취소된다는 것을 기억하십시오. 로깅 subrequest가 완료되었는지 확인하려면, 요청이 약속합니다.[`event.waitUntil()`](https://developer.mozilla.org/en-US/docs/Web/API/ExtendableEvent/waitUntil). 예를 들면:

<Tabs>
  <TabItem label="모듈 Worker" icon="seti:javascript">
    ```js
    export default {
    	async fetch(request, env, ctx) {
    		function postLog(data) {
    			return fetch("https://log-service.example.com/", {
    				method: "POST",
    				body: data,
    			});
    		}

    		//ctx.waitUntil() 없이 `postLog` 함수는 완료할 수 없습니다.
    		ctx.waitUntil(postLog(stack));
    		return fetch(request);
    	},
    };
    ```
  </TabItem>

  <TabItem label="서비스 노동자" icon="seti:javascript">
    :::카트로션\[서비스 Workers는 deprecated]

    서비스 Workers는, 아직도 지원됩니다. 자주 묻는 질문[단위 Workers](/workers/reference/migrate-to-module-workers/)대신. 새로운 기능은 서비스 WorkersXQ를 위해 지원되지 않을지도 모릅니다.

    :::

    ```js
    addEventListener("fetch", (event) => {
    	event.respondWith(handleEvent(event));
    });

    async function handleEvent(event) {
    	//· ...

    	//event.waitUntil() 없이 `postLog` 함수는 완료할 수 없습니다.
    	event.waitUntil(postLog(stack));
    	return fetch(event.request);
    }

    function postLog(data) {
    	return fetch("https://log-service.example.com/", {
    		method: "POST",
    		body: data,
    	});
    }
    ```
  </TabItem>
</Tabs>

## 오류 발생

이름 \*[`event.passThroughOnException`](/workers/runtime-apis/context/#passthroughonexception), Workers 신청은 노동자의 실행 도중 예외가 던지는 경우에 당신의 근원에 요구할 것입니다. Workers로 로깅, 추적 또는 다른 기능을 추가 할 수 있습니다.

<Tabs>
  <TabItem label="모듈 Worker" icon="seti:javascript">
    ```js
    export default {
    	async fetch(request, env, ctx) {
    		ctx.passThroughOnException();
    		//오류가 발생하지 않은 경우, 원래 응답을 반환합니다.
    		return fetch(request);
    	},
    };
    ```
  </TabItem>

  <TabItem label="서비스 노동자" icon="seti:javascript">
    :::카트로션\[서비스 Workers는 deprecated]

    서비스 Workers는, 아직도 지원됩니다. 자주 묻는 질문[단위 Workers](/workers/reference/migrate-to-module-workers/)대신. 새로운 기능은 서비스 WorkersXQ를 위해 지원되지 않을지도 모릅니다.

    :::

    ```js
    addEventListener("fetch", (event) => {
    	event.passThroughOnException();
    	event.respondWith(handleRequest(event.request));
    });

    async function handleRequest(request) {
    	//오류가 발생하지 않은 경우, 원래 응답을 반환합니다.
    	//· ...
    	return fetch(request);
    }
    ```
  </TabItem>
</Tabs>
