모델 번호: Workers Logs는 Cloudflare WorkersXQ에서 방출된 기록 데이터 수집, 저장, 필터 및 분석합니다. 데이터는 Cloudflare 계정으로 작성되며 dashboardXQ에서 각 WorkersXQ에 쿼리할 수 있습니다. 모든 새로 만들어진 Workers는 기본적으로 사용할 수 있는 관찰성 설정으로 제공됩니다.

로그인[비밀번호](/workers/observability/logs/workers-logs/#invocation-logs), [사용자 정의 로그](/workers/observability/logs/workers-logs/#custom-logs), 오류 및 uncaught 예외.

![Workers 로그 대시보드를 보여주는 예](~/assets/images/workers-observability/wobs_workers_events_122.png)

제3자에게 로그를 보내려면 사용[Workers Logpush의](/workers/observability/logs/logpush/)또는[꼬리 Workers](/workers/observability/logs/tail-workers/).

## 유효한 Workers 로그인

:::note\[Wrangler 버전]
최소 필요한 Wrangler 버전: 3.78.6. 실행하여 버전 확인`wrangler --version`. Wrangler를 업데이트하려면, 참조[설치/업데이트 Wrangler](/workers/wrangler/install-and-update/).
:::

Workers 로그에 로그를 쓰기 위해 작업자의 관찰성 설정을 추가해야합니다. 노동자의 Wrangler 파일에 뒤에 오는 조정을 추가하고 당신의 노동자를 redeploy.

<WranglerConfig>
  ```jsonc
  {
    "observability": {
      "enabled": true,
      "head_sampling_rate": 1 //옵션. 기본값 = 1.
    }
  }
  ```
</WranglerConfig>

[헤드 기반 샘플링](/workers/observability/logs/workers-logs/#head-based-sampling)Workers 요청의 비율을 설정할 수 있습니다.

### 환경과 연계

[환경분야](/workers/wrangler/environments/)다른 구성과 동일한 Worker 응용 프로그램을 배포 할 수 있습니다. 예를 들어, 다른 구성을 할 수 있습니다.`head_sampling_rate`staging와 생산에. 환경의 관측을 구성하려면`staging`: 1. 아래의 구성 추가`[env.staging]`

<WranglerConfig>
  ```jsonc
  {
    "env": {
      "staging": {
        "observability": {
          "enabled": true,
          "head_sampling_rate": 1 //옵션 정보
        }
      }
    }
  }
  ```
</WranglerConfig>

2. 작업자 배치`npx wrangler deploy -e staging`
3. 각 환경을 위해 1과 2를 반복하십시오.

## 최고의 연습

### 구조화된 JSON 객체

QXQX0376XQ 로그에서 가장 많은 것을 얻으려면 JSON 형식으로 로그인하는 것이 좋습니다. Workers 자동적으로 필드를 추출하고 데이터베이스에서 지능적으로 색인합니다. 이 구조화된 로깅 기술의 이점은 무제한 cardinality를 가진 분야를 위한 어떤 차원든지에 쉽게 세그먼트 자료를 허용하는 방법에 있습니다. 다음 시나리오를 고려:

| 채용정보 | 비밀번호                                                       | 이벤트 로그 (Partial)                              |
| ---- | ---------------------------------------------------------- | --------------------------------------------- |
| 1    | `console.log("user_id: " + 123)`                           | `{message: "user_id: 123"}`                   |
| 2    | `console.log({user_id: 123})`                              | `{user_id: 123}`                              |
| 3    | `console.log({user_id: 123, user_email: "a@example.com"})` | `{user_id: 123, user_email: "a@example.com"}` |

이 예제의 차이는 더 빠른 쿼리를 활성화하기 위해 로그를 색인하는 방법에 있습니다. 시나리오 1에서,`user_id`메시지 안에 내장되어 있습니다. 특정 user id와 관련된 모든 로그를 찾으려면 텍스트 일치를 실행해야합니다. 시나리오 2 및 3에서 로그는 키에 대해 필터링 할 수 있습니다.`user_id`·`user_email`.

## 주요 특징

### 회사 소개

각 Workers invocation는 요청, 응답 및 관련 메타데이터와 같은 세부 정보가 포함 된 단일 invocation 로그를 반환합니다. 이 호출 로그는 필드에 의해 식별 될 수있다`$cloudflare.$metadata.type = "cf-worker-event"`. 각 invocation 로그는 Cloudflare에 사용할 수있는 정보와 invocation의 맥락에 풍부합니다.

Workers 로그 UI에서, 로그는 로컬 타임 스탬프와 메시지로 표시됩니다. 메시지는 invocation 핸들러에 의존합니다. 예를 들어, Fetch 요청은 요청 방법 및 요청 URL을 설명하는 메시지가 있으며, cron 이벤트는 cron으로 표시됩니다. 아래는 invocation 메시지와 함께 invocation Handlers의 목록입니다.

Invocation 로그는 wrangler에서 비활성화 할 수 있습니다.`invocation_logs = false`구성.

### 사용자 정의 로그

기본적으로 Worker가 방출됩니다.[비밀번호](/workers/observability/logs/workers-logs/#invocation-logs)요청에 대한 세부 사항, 응답 및 관련 메타 데이터.

코드를 통해 사용자 정의 로그를 추가 할 수 있습니다. 이름 \*`console.log`노동자 내에서 진술은 Workers 로그에서 볼 수 있습니다. 다음 예제는 사용자 정의를 보여줍니다.`console.log`Worker 요청 핸들러 안에.

<Tabs>

    ```js
    	async fetch(request) {
    		const { cf } = request;
    		const { city, country } = cf;

    		console.log(`Request came from city: ${city} in country: ${country}`);

    		return new Response("Hello worker!", {
    			headers: { "content-type": "text/plain" },
    		});
    	},
    };
    ```
  </TabItem>

  <TabItem label="서비스 노동자" icon="seti:javascript">
    :::카트로션\[서비스 Workers는 deprecated]

    서비스 Workers는, 아직도 지원됩니다. 자주 묻는 질문[단위 Workers](/workers/reference/migrate-to-module-workers/)대신. 새로운 기능은 서비스 WorkersXQ를 위해 지원되지 않을지도 모릅니다.

    :::

    ```js
    	event.respondWith(handleRequest(event.request));

    /** 이름

    	const { cf } = request;
    ```

### 헤드 기반 샘플링

헤드 기반 샘플링은 Cloudflare Worker에 들어오는 요청의 비율을 기록할 수 있습니다. 특히 높은-traffic 응용 프로그램에 대한, 이것은 로그 볼륨을 줄이고 비용을 관리하는 데 도움이, 여전히 응용 프로그램의 성능에 의미있는 통찰력을 제공. 헤드 기반 샘플링 속도를 구성할 때 로그를 얻는 요청의 비율을 제어할 수 있습니다. 요청의 상황에 따라 모든 로그가 수집됩니다.

헤드 기반 샘플링을 활성화하려면 설정`head_sampling_rate`관찰성 구성 내에서. 유효한 범위는 0에서 1이고, 0는 100개의 요구가 기록되고, 1는 각 요구가 기록됩니다. 이름 \*`head_sampling_rate`지정되지 않습니다, 그것은 1 (100%)의 기본 값으로 구성됩니다. 아래 예제에서,`head_sampling_rate`0.01로 설정되어 각 백개의 요청 중 하나가 기록됩니다.

<WranglerConfig>
  ```jsonc
  {
  	"observability": {
  		"enabled": true,
  		"head_sampling_rate": 0.01 //1% 표본 추출 비율
  	}
  }
  ```
</WranglerConfig>
