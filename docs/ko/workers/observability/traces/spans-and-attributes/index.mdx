Cloudflare Workers는 자동적인 추적 계기를 제공합니다**상자에서**- 코드 변경 또는 SDK가 필요하지 않습니다.

## 현재 지원된 스팬과 속성

### 모든 스팬에서 사용 가능

- `cloud.provider`- 항상 설정`cloudflare`
- `cloud.platform`- 항상 설정`cloudflare.workers`
- `faas.name`- 노동자의 이름
- `faas.invocation_id`- 이 특정 Worker invocation에 대한 고유 식별자
- `faas.version`- 작업자의 배포판 태그
- `faas.invoked_region`- 노동자가 잘못되었다 지역
- `service.name`- 노동자의 이름
- `cloudflare.colo`- Cloudflare 데이터 센터의 3-letter IATA 공항 코드 요청 (예 :`SFO`, `LHR`)
- `cloudflare.script_name`- 노동자의 이름
- `cloudflare.script_tags`- 당신의 Worker 배포와 관련된 태그
- `cloudflare.script_version.id`- 배포 된 노동자의 버전 식별자
- `cloudflare.invocation.sequence.number`- 모든 방출 된 스팬에 추가 된 카운터와 로그인하여 타임 스탬프가 동일 할 때 방출 된 것을 구별 할 수 있습니다.
- `telemetry.sdk.language`- 사용 된 프로그래밍 언어, 설정`javascript`
- `telemetry.sdk.name`- telemetry SDK 이름, 설정`cloudflare`

***

### 모든 루트 스팬에서 사용 가능

- `faas.trigger`- 당신의 노동자가 (e.g.,에 의해 호출 된 트리거`http`, `cron`, `queue`, `email`)
- `cloudflare.ray_id`- 아[고유 식별자](/fundamentals/reference/cloudflare-ray-id/)Cloudflare
- `cloudflare.handler_type`- 요청을 처리하는 핸들러의 유형 (예 :`fetch`, `scheduled`, `queue`, `email`, `alarm`)
- `cloudflare.entrypoint`- 당신의 노동자 (예를 들어, 당신의 튼튼한 목표의 이름)에 invoked 된 항목
- `cloudflare.execution_model`- 노동자의 실행 모델 (예 :,`stateless`, `stateful`Durable Objects를 위해)
- `cloudflare.outcome`- 노동자 직업의 결과 (예 :,`ok`, `exception`, `exceededCpu`, `exceededMemory`)
- `cloudflare.cpu_time_ms`- 노동자 invocation에 의해 사용되는 CPU 시간, 밀리 초
- `cloudflare.wall_time_ms`- 노동자 invocation에 의해 사용되는 벽 시간, 밀리 초
