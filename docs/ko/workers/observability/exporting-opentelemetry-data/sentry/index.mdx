Sentry는 개발자가 식별 및 디버그 성능 문제 및 오류를 식별하는 소프트웨어 모니터링 도구입니다. End-to-end 분산 tracing에서 성능 모니터링, Sentry는 문제를 진단하고 시스템 및 서비스 전반에 걸쳐 응용 프로그램 코드 건강에 대해 지속적으로 배울 수있는 코드 수준 관측 기능을 제공합니다. Cloudflare WorkersXQ 신청 telemetry를 발송해서, 당신은 할 수 있습니다:

- Query 로그 및 추적 Sentry
- Workers

![Timeline에 표시된 타이밍 정보와 Sentry 추적보기](~/assets/images/workers-observability/sentry-example.png)

이 가이드는 CloudflareXQ에서 Sentry에 OpenTelemetry-compliant 추적 및 로그를 내보내기 통해 당신을 걸 것입니다 작업자 신청

## 자주 묻는 질문

시작하기 전에, 당신은 가지고:

- 로그인[계정 관리](https://sentry.io/signup/)(무료 계층 가능)
- 모니터링 할 작업자 배치

## 단계 1: Sentry 프로젝트를 만들기

이미 데이터를 전송하기 위해 Sentry 프로젝트가 없다면 Cloudflare QXQXQXQXWorkers 응용 telemetry를 보내려면 하나를 만들 필요가 있습니다.

1. 로그인[계정 관리](https://sentry.io/)
2. Insights로 이동 > 네비게이션 사이드바의 프로젝트는 프로젝트 목록을 엽니다.
3. 이름 \*[**새로운 프로젝트**](https://sentry.io/orgredirect/organizations/:orgslug/insights/projects/new/)
4. 프로젝트 작성 양식을 작성하고 클릭**프로젝트**프로세스를 완료합니다.

## 단계 2: 당신의 Sentry OTLP 엔드포인트를 얻으십시오

Sentry는 추적 및 로그에 대한 별도의 OTLP 엔드포인트를 제공합니다.

- **팟캐스트**: `https://{HOST}/api/{PROJECT_ID}/integration/otlp/v1/traces`
- **로그인**: `https://{HOST}/api/{PROJECT_ID}/integration/otlp/v1/logs`

프로젝트 설정에서 OTLP 엔드포인트를 찾을 수 있습니다.

1. 오시는 길[설정 > 프로젝트](https://sentry.io/orgredirect/organizations/:orgslug/settings/projects/)Sentry의 페이지.
2. 목록에서 프로젝트를 선택하고 프로젝트 이름을 클릭하여 프로젝트 설정을 엽니다.
3. "SDK Setup"이 프로젝트의 하위 페이지에 "Client Keys (DSN)"로 이동합니다.

Sentry 프로젝트의 OTLP 로그와 OTLP 추적 엔드포인트뿐만 아니라 엔드포인트에 대한 인증 헤더를 찾을 수 있습니다. 엔드포인트 및 인증 헤더를 복사해야 합니다.

Sentry의 OTLP 엔드포인트를 사용하는 방법에 대한 자세한 내용은 참조[Sentry의 OTLP 문서](https://docs.sentry.io/concepts/otlp/).

## 단계 3: Cloudflare dashboard

QXQX0607XQ QXdashboard의 목적지를 설정하려면 Cloudflare 계정의 이동[모델 번호: Workers 옵션 정보](https://dash.cloudflare.com/?to=/:account/workers-and-pages/observability/pipelines)이름 \* 다음을 클릭합니다**자주 묻는 질문**추적 또는 로그 대상을 구성합니다.

### 교통 안내

추적 대상을 구성하려면 클릭**자주 묻는 질문**그리고 다음을 구성:

- **대상 이름**: `sentry-traces`(또는 원고 이름)
- **여행 정보**: 선택**팟캐스트**
- **OTLP 엔드포인트**: Sentry OTLP 추적 엔드포인트 (예:`https://{HOST}/api/{PROJECT_ID}/integration/otlp/v1/traces`)
- **공급 업체**: Sentry 인증 헤더 추가:
  - 헤더 이름:`x-sentry-auth`
  - 공급 능력:`sentry sentry_key={SENTRY_PUBLIC_KEY}`이름 \*`{SENTRY_PUBLIC_KEY}`Sentry 프로젝트의 공개 키입니다.

### 자주 묻는 질문

로그인 상태를 설정하려면 클릭**자주 묻는 질문**그리고 다음을 구성:

- **대상 이름**: `sentry-logs`(또는 원고 이름)
- **여행 정보**: 선택**로그인**
- **OTLP 엔드포인트**: Sentry OTLP 로그 엔드포인트 (예:`https://{HOST}/api/{PROJECT_ID}/integration/otlp/v1/logs`)
- **공급 업체**: Sentry 인증 헤더 추가:
  - 헤더 이름:`x-sentry-auth`
  - 공급 능력:`sentry sentry_key={SENTRY_PUBLIC_KEY}`이름 \*`{SENTRY_PUBLIC_KEY}`Sentry 프로젝트의 공개 키입니다.

## 단계 4: 노동자를 구성

QXQX0610XQ dashboardXQX0609XQXQ에서 생성된 목적지로, 원격 측정 수출을 가능하게 하기 위하여 노동자의 윤곽을 새롭게 합니다.

<WranglerConfig>
  ```json
  {
    "observability": {
      "traces": {
        "enabled": true,
        // Must match the destination name in the dashboard
        "destinations": ["sentry-traces"]
      },
      "logs": {
        "enabled": true,
        // Must match the destination name in the dashboard
        "destinations": ["sentry-logs"]
      }
    }
  }
  ```
</WranglerConfig>

구성을 업데이트 한 후, 효과에 대한 변경 사항에 대한 작업자를 배치하십시오.

:::참조
