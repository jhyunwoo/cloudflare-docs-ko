복잡한 응용 프로그램을 구축 할 때 개발 중에 여러 Workers를 실행 할 수 있습니다. 이 가이드는 여러 Workers를 로컬로 실행하고 각 접근 방식을 사용할 때 다른 접근 방식을 다룹니다.

## 단일 dev 명령

:::참조
우리는 대부분의 개발 작업 흐름에 대한 기본으로이 접근을 권장합니다. 그것은 바인딩과 최고의 호환성을 보장합니다.
주요 특징

여러 WorkersXQ를 실행할 수 있습니다.

**Wrangler 사용하기**

<PackageManagers type="exec" pkg="wrangler" args="dev -c ./app/wrangler.jsonc -c ./api/wrangler.jsonc" />

첫번째 설정 (`./app/wrangler.jsonc`)에 드러낸 1 차적인 노동자로 대우됩니다`http://localhost:8787`. 추가 설정 (e.g.`./api/wrangler.jsonc`) 보조 Workers로, 1 차적인 노동자에서 서비스 바인딩 또는 꼬리 소비자를 통해 유효한 달리십시오.

**Vite 플러그인 사용**

설정하기`auxiliaryWorkers`당신의 Vite 윤곽에서:

```js title="vite.config.js"
import { defineConfig } from "vite";
import { cloudflare } from "@cloudflare/vite-plugin";

export default defineConfig({
  plugins: [
    cloudflare({
      configPath: "./app/wrangler.jsonc",
      auxiliaryWorkers: [
        {
          configPath: "./api/wrangler.jsonc",
        },
      ],
    }),
  ],
});
```

다음 실행:

<PackageManagers type="exec" pkg="vite" args="dev" />

**이 접근을 사용할 때:**

- 개발의 가장 간단한 설정
- Workers는 동일한 신청 또는 codebase의 부분입니다
- 다른 Worker에서 튼튼한 Object namespace에 액세스해야 합니다.`script_name`생산자와 소비자 Workers가 분리되는 Workers가 있는 , 또는 체제 QueuesXQ.

## 다중 dev 명령

별도의 dev 명령에서 각 Worker를 실행할 수 있습니다. 각 터미널과 구성으로 각.

<PackageManagers comment="Terminal 1" type="exec" pkg="wrangler" args="dev -c ./app/wrangler.jsonc" />

<PackageManagers comment="Terminal 2" type="exec" pkg="wrangler" args="dev -c ./api/wrangler.jsonc" />

이 Workers는 다른 dev 명령에서 실행되지만 서비스 바인딩 또는 꼬리 소비자를 통해 서로 통신 할 수 있습니다.**그들이 시작하기에 관계없이`wrangler dev`또는`vite dev`**.

:::참조
당신은 또한 두 가지 접근법을 결합 할 수 있습니다 — 예를 들어, 함께 Workers의 그룹을 실행`vite dev`이름 \*`auxiliaryWorkers`, 다른 노동자를 따로따로 달리는 동안`wrangler dev`. 이것은 단 하나 dev 명령의 밑에 달리는 단단하게 결합된 WorkersXQXQ를 유지하고, 독립 또는 분리되는 것을 WorkersXQXQ를 공유하는 것을 허용합니다.
주요 특징

**이 접근을 사용할 때:**

- 각 근로자는 개발 중에 자신의 로컬 URL에 접근 할 수 있기를 원합니다. 기본 노동자는 단일 dev 명령을 사용할 때 노출됩니다.
- 각 노동자는 자체 빌드 설정 또는 툴링을 가지고 있습니다. 예를 들어, 다른 하나는 바닐라 Wrangler 프로젝트입니다.
- WorkersXQXQXQXQ를 실행하고 개발할 수 있는 유연성을 필요하거나 config를 통합

이 설정은 특히 더 큰 프로젝트에 유용합니다. 각 팀은 Workers의 하위 세트를 유지합니다. 단일 dev 명령에서 모든 것을 실행하면 항상 실제가 아닌 중요한 재 구축 또는 통합이 필요할 수 있습니다.
