:::참조
이 기능은 Wrangler v3.98.0 이상을 요구합니다.
주요 특징

다른 노동자와 같이,[도메인의 경로에 실행할 자산을 가진 Worker를 구성할 수 있습니다.](/workers/configuration/routing/routes/)·
Worker에 정의 된 자산은 원하는 경로에 미러 디렉토리 구조에서 배열해야합니다.

예를 들어, 자산을`example.com/blog/*`, 만들기`blog`자산 디렉토리에 디렉토리.

<FileTree>
  - 뚱 베어
    - 블로그
      - 프로젝트
      - 이름 \*
        - 포스트1.html
        - 포스트2.html
</FileTree>

한국어[Wrangler 구성 파일](/workers/wrangler/configuration/)이렇게:

<WranglerConfig>
  ```jsonc
  {
  	"$schema": "./node_modules/wrangler/config-schema.json",
  	"name": "assets-on-a-path-example",
  	"main": "src/index.js",
  	"route": "example.com/blog/*",
  	"assets": {
  		"directory": "dist"
  	}
  }
  ```
</WranglerConfig>

이 예제에서, 요청`example.com/blog/`봉사할 것`index.html`파일 및 요청`example.com/blog/posts/post1`봉사할 것`post1.html`파일.

구성 된 경로 밖에서 파일을 가지고 있다면, 그것은 제공되지 않습니다, 그것은의 일부가 아닌`assets.not_found_handling`제품 정보[단일 페이지 응용](/workers/static-assets/routing/single-page-application/)또는[관례 404 페이지](/workers/static-assets/routing/static-site-generation/). 예를 들면, 당신이 있는 경우에`home.html`자산 디렉토리의 루트에 파일, 요청시 제공되지 않습니다`example.com/blog/home`. 그러나, 필요한 경우, 이 파일은 여전히 수동으로 위에 fetched 할 수 있습니다[연결하기](/workers/static-assets/binding/#binding).
