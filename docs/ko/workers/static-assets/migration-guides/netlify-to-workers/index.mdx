이 튜토리얼에서 Netlify 응용 프로그램을 Cloudflare QXWorkersXQ로 마이그레이션하는 방법을 배울 수 있습니다.

CloudflareXQX0752XQXQ에 호스트하려는 Netlify에 배포된 기존 프로젝트가 이미 있어야 합니다. 특정 기능은 Cloudflare Workers에 의해 지원되지 않습니다. 자주 묻는 질문[Workers 호환성 모체](/workers/static-assets/migration-guides/migrate-from-pages/#compatibility-matrix)지원되는 것에 대한 자세한 내용은.

## 프레임 워크

수요 렌더링에 Next.js, AstroXQXQXQ와 같은 일부 프레임 워크는 CloudflareQXQXQXQ에 마이그레이션하기위한 특정 가이드가 있습니다. 우리를 따르라[프레임 워크 가이드](/workers/framework-guides/)더 많은 정보. 프레임 워크가 있다면**Workers에 기존 프로젝트를 배포**가이드, 특정 지침에 대한 가이드를 따르십시오. 그렇지 않으면 아래 단계를 계속합니다.

## 빌드 명령을 찾아서 디렉토리를 빌드하십시오.

QXQX0759XQQ Workers에 응용 프로그램을 이동하려면 빌드 명령과 빌드 디렉토리를 알아야합니다. Cloudflare Workers는 이 정보를 사용하여 응용 프로그램을 구축하고 배포합니다. 아래 Netlify 대시보드에서 이러한 값을 찾는 방법을 다룹니다.

Netlify 대시보드에서 Workers에 마이그레이션하려는 프로젝트를 찾을 수 있습니다. 오시는 길**프로젝트 구성**특정 프로젝트에 대한 메뉴, 다음으로 이동**빌드 및 배치**메뉴 항목. 당신은 찾을 수**설정 설정**카드 포함**명령 실행**·**관련 링크**이름 \* Cloudflare WorkersXQ에 배포를 위해 이러한 저장하십시오. 아래 이미지에서,**명령을 실행**이름 \*`npm run build`, 그리고**출력 디렉토리**이름 \*`.next`.

![Build Command 및 게시 디렉토리 필드 찾기](~/assets/images/workers/migrations/netlify-build-command.png)

## wrangler 파일 만들기

프로젝트의 뿌리에서, 생성`wrangler.jsonc`또는`wrangler.toml`파일 (`wrangler.jsonc`권장). 파일이란 어떤 유형의 응용 프로그램에 따라 달라집니다. 배포: 구동되는 응용 프로그램[정체되는 위치 발생 (SSG)](/workers/static-assets/routing/static-site-generation/), 또는[단일 페이지 응용 프로그램 (SPA)](/workers/static-assets/routing/single-page-application/).

각 경우, 업데이트해야합니다.`<your-project-name>`프로젝트의 이름과 값`<your-build-directory>`Netlify에서 빌드 디렉토리와 값.

한국어**사이트 맵**, 당신은 당신의 wrangler 파일에 뒤에 추가해야 할 것입니다.

<WranglerConfig>
  ```jsonc
  {
  	"name": "<your-project-name>",
  	"compatibility_date": "$today",
  	"assets": {
  		"directory": "<your-build-directory>",
  	},
  }
  ```
</WranglerConfig>

한국어**단일 페이지 신청**, 당신은 당신의 Wrangler 윤곽 파일에 뒤에 추가할 필요가 있을 것입니다, 포함되는`not_found_handling`이름 \*

<WranglerConfig>
  ```jsonc
  {
  	"name": "<your-project-name>",
  	"compatibility_date": "$today",
  	"assets": {
  		"directory": "<your-build-directory>",
  		"not_found_handling": "single-page-application",
  	},
  }
  ```
</WranglerConfig>

일부 프레임 워크는 Cloudflare Workers에 마이그레이션하기위한 특정 가이드를 제공합니다. 견적 요청[프레임 워크 가이드](/workers/framework-guides/)더 많은 정보. 프레임 워크가 "WorkersXQ" 가이드에 기존 프로젝트를 완료하면 자세한 지침을 따르십시오.

## 새로운 Workers 프로젝트 만들기

응용 프로그램은 Cloudflare Workers에 내장 및 배포 할 수있는 적절한 구성이 있습니다.

더 보기[새로운 노동자를 연결](/workers/ci-cd/builds/#connect-a-new-worker)가이드는 GitHub 프로젝트를 Cloudflare WorkersXQ에 연결하는 방법을 안내합니다. 구성 단계에서 빌드 명령은 Netlify에서 찾을 수있는 명령과 동일합니다. 또한, 배포 명령은 기본값이어야한다.`npx wrangler deploy`.

## 사용자 정의 도메인 추가

Workers Custom Domains는 계정의 영역으로 구성되는 도메인만 지원합니다. Cloudflare는 DNS 및 트래픽을 포함한 도메인(예: example.com)을 말합니다.

자주 묻는 질문[Workers 프로젝트에 대한 사용자 정의 도메인 추가](/workers/configuration/routing/custom-domains/#add-a-custom-domain). 도메인의 영역 만들기에 추가 정보를 찾을 수 있습니다.

## Netlify 앱 삭제

사용자 정의 도메인이 설정되고 Cloudflare Workers에 요청을 전송하면 Netlify 응용 프로그램을 안전하게 삭제할 수 있습니다.

## 문제 해결

추가 마이그레이션 지침을 위해, 검토[Cloudflare Pages를 WorkersXQ 마이그레이션 가이드](/workers/static-assets/migration-guides/migrate-from-pages/). 특정하지 않는 동안, 그것은 도움이 될 수있는 몇 가지 추가 단계를 다룹니다.
