프론트 엔드 정적 자산과 백엔드 API, 서버 사이드 렌더링 페이지(SSR)을 포함한 전체 스택 애플리케이션을 배포할 수 있습니다.[Cloudflare Workers](/workers/static-assets/).

Pages와 같은 Workers의 정적 자산은 무료이며,[Pages 기능](#pages-functions)직업은 Workers로 동일한 비율에 위탁됩니다, 그래서 당신은 예상할 수 있습니다[비슷한 비용 구조](/workers/platform/pricing/#workers).

Pages와는 달리, Workers는 그것에 유효한 특징의 명백하게 더 넓은 세트가 있습니다, (Durable Objects, Cron Triggers 및 더 포괄적인 관찰 가능성). 전체 목록에서 찾을 수 있습니다[이 페이지의 하단](#compatibility-matrix).

## 관련 기사

Cloudflare QXPages에서 QXQX0707XQ QXQXQXWorkersXQ는 수시로 straightforward 과정입니다. 다음은 가장 일반적인 단계 중 일부는 프로젝트를 마이그레이션해야합니다.

### 프레임 워크

Pages 프로젝트가 사용하는 경우[인기 프레임](/workers/framework-guides/), 대부분의 기구는 이미 Cloudflare WorkersXQ를 위해 유효한 접합기가 있습니다. WorkersXQX0713XQXQXWorkersXQXQXPagesXQXQXPagesXQXQXQXQXQXQXQXQXPagesXQXQXQXQ-특정 어댑터를 전환하여 제공한 모든 지침을 따르십시오.

### 프로젝트 구성

프로젝트가 이미 하나가 없는 경우, 생성[Wrangler 구성 파일](/workers/wrangler/configuration/)(이더`wrangler.jsonc`, `wrangler.json`또는`wrangler.toml`) 프로젝트의 뿌리에. 두 가지 필수 필드는:

- [`name`](/workers/wrangler/configuration/#inheritable-keys)

  배포하려는 Worker의 이름으로 설정합니다. 이것은 기존 Pages 프로젝트 이름과 동일 할 수 있으므로 Workers의 이름 제한 (예를들면 최대 길이)에 따릅니다.

- [`compatibility_date`](/workers/configuration/compatibility-dates/).

  이미 사용중인 경우[모델 번호: Pages 제품정보](/pages/functions/wrangler-configuration/#inheritable-keys), 같은 날짜로 설정한다. 그렇지 않으면 현재 날짜로 설정합니다.

#### 출력 디렉토리

이전에는 PagesXQ에 대한 "build output directory"를 구성 할 곳 (하나님)[Wrangler 구성 파일](/pages/functions/wrangler-configuration/#inheritable-keys)또는[Cloudflare dashboard](/pages/configuration/build-configuration/#build-commands-and-directories)), 당신은 지금 설정해야합니다[`assets.directory`](/workers/static-assets/binding/#directory)Worker 프로젝트의 가치.

시작하기**CloudflarePages**:

<WranglerConfig>
  ```json
  {
  	"name": "my-pages-project",
  	"pages_build_output_dir": "./dist/client/"
  }
  ```
</WranglerConfig>

지금, 와**Cloudflare Workers**:

<WranglerConfig>
  ```json
  {
  	"name": "my-worker",
  	"compatibility_date": "$today",
  	"assets": {
  		"directory": "./dist/client/"
  	}
  }
  ```
</WranglerConfig>

:::참조

작업자가 자산과 노동자 스크립트를 포함하지 않으면 제거해야합니다.`"binding": "ASSETS"`구성 파일에서 필드, 이 때문에 단지 유효하다면 노동자 스크립트에 의해 표시된 경우`"main"`호텔 위치 이름 \*[자산 바인딩](#assets-binding)아래에 단면도.

:::

#### 봉사 활동

Pages는 자동으로 배포되는 프로젝트의 유형을 결정하려고합니다. 견적 요청`404.html`·`index.html`프로젝트가 가능성이 있는지 여부에 대한 신호로 파일[단일 페이지 응용 프로그램 (SPA)](/pages/configuration/serving-pages/#single-page-application-spa-rendering)또는 만약[관례 봉사 404 페이지](/pages/configuration/serving-pages/#not-found-behavior).

Workers에서 사고를 방지하기 위해이 행동은 명시되고[수동 설정](/workers/static-assets/routing/).

단일 페이지 신청 (SPA)를 위해:

<WranglerConfig>
  ```json
  {
  	"name": "my-worker",
  	"compatibility_date": "$today",
  	"assets": {
  		"directory": "./dist/client/",
  		"not_found_handling": "single-page-application"
  	}
  }
  ```
</WranglerConfig>

관례 404 페이지를 위해:

<WranglerConfig>
  ```json
  {
  	"name": "my-worker",
  	"compatibility_date": "$today",
  	"assets": {
  		"directory": "./dist/client/",
  		"not_found_handling": "404-page"
  	}
  }
  ```
</WranglerConfig>

##### 자산을 무시

Pages는 자동적으로 몇몇 파일 및 폴더를 제외하고와 같은 정체되는 자산으로 업로드될 것입니다`node_modules`, `.DS_Store`·`.git`. 당신이 또한 Workers에 이 파일을 업로드하지 않는 경우에, 당신은 창조할 수 있습니다[`.assetsignore`이름 \*](/workers/static-assets/binding/#ignoring-assets)프로젝트의 정적 자산 디렉토리에.

```txt title="dist/client/.assetsignore"
**/node_modules
**/.DS_Store
**/.git
```

#### Pages 기능

##### 풀 스택 프레임

전체 스택 프레임 워크를 사용하는 경우[모델 번호: Pages 제품정보](/pages/functions/), 당신을 지킵니다[당신의 프레임을 업데이트](#frameworks)대상 Workers 대신 Pages.

##### 모델 번호: Pages "advanced mode"기능`_worker.js`이름 \*

Pages 기능을 사용하는 경우["advanced 모드"`_worker.js`이름 \*](/pages/functions/advanced-mode/), 먼저 이 스크립트가 정적 자산으로 업로드 되지 않도록 해야 합니다. 하나 이동`_worker.js`정적 자산 디렉토리에서 (권장), 또는 생성[이름 \*`.assetsignore`이름 \*](/workers/static-assets/binding/#ignoring-assets)정적 자산 디렉토리에 포함`_worker.js`그것 안에.

```txt title="dist/client/.assetsignore"
_worker.js
```

그런 다음 구성 파일을 업데이트하십시오.`main`이 Worker 스크립트의 위치로 가려면 필드:

<WranglerConfig>
  ```json
  {
  	"name": "my-worker",
  	"compatibility_date": "$today",
  	"main": "./dist/client/_worker.js", // or some other location if you moved the script out of the static asset directory
  	"assets": {
  		"directory": "./dist/client/"
  	}
  }
  ```
</WranglerConfig>

##### 모델 번호: Pages 기능과 기능`functions/`파일 형식

이용안내**모델 번호: Pages 기능과 기능[폴더의`functions/`](/pages/functions/)**, 당신은 먼저이 기능을 단일 노동자 스크립트로 컴파일해야합니다[`wrangler pages functions build`](/workers/wrangler/commands/#functions-build)명령.

<PackageManagers type="exec" pkg="wrangler" args={"pages functions build --outdir=./dist/worker/"} />

이 명령은 언제든지 실행할 수 있지만 파일 기반 라우팅을 계속 사용하려면 다른 프레임워크를 사용하는 것이 좋습니다.[호노X](https://github.com/honojs/honox)인기있는 옵션입니다.

Worker 스크립트가 컴파일되면 구성 파일을 업데이트할 수 있습니다.`main`위치에 가리키는 필드는 다음과 같습니다.

<WranglerConfig>
  ```json
  {
  	"name": "my-worker",
  	"compatibility_date": "$today",
  	"main": "./dist/worker/index.js",
  	"assets": {
  		"directory": "./dist/client/"
  	}
  }
  ```
</WranglerConfig>

##### `_routes.json`Pages 기능 미들웨어

당신이 승인 한 경우[한국어`_routes.json`이름 \*](/pages/functions/routing/#create-a-_routesjson-file)Pages 프로젝트에서 또는 사용[미들웨어](/pages/functions/middleware/)Pages 기능, 당신은 당신의 노동자 스크립트의 구성에주의를 기울여야 합니다. Pages는 정적 자산의 앞에 Pages 기능을 봉사하기 위하여 기본적으로 이고`_routes.json`Pages 이 행동을 사용자 정의 할 수있는 기능 미들웨어.

Workers는 다른 한편으로는 작업자 스크립트 앞에 정적 자산을 제공해야 합니다.[`assets.run_worker_first`](/workers/static-assets/routing/worker-script/#run-your-worker-script-first). 이 옵션은 예를 들어, 정적 자산을 제공하기 전에 인증 체크 또는 로깅 요청을 수행하는 경우 필요합니다.

<WranglerConfig>
  ```json
  {
  	"name": "my-worker",
  	"compatibility_date": "$today",
  	"main": "./dist/worker/index.js",
  	"assets": {
  		"directory": "./dist/client/",
  		"run_worker_first": true
  	}
  }
  ```
</WranglerConfig>

  ```json
  		"mode": "smart"

  ```
</WranglerConfig>
