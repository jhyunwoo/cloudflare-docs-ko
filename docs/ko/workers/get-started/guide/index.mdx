## 1. 새로운 Worker 프로젝트 만들기

터미널 창을 열고 C3를 실행하여 노동자 프로젝트를 만듭니다.[사이트맵`create-cloudflare-cli`)](https://github.com/cloudflare/workers-sdk/tree/main/packages/create-cloudflare)Cloudflare에 새 응용 프로그램을 설정하고 배치하는 데 도움이되는 명령줄 도구입니다.

이제 새로운 프로젝트가 설정되었습니다. 그 프로젝트 폴더로 이동합니다.

```sh
cd my-first-worker
```

<Details header="C3는 어떤 파일을 만들었습니까?">
  프로젝트 디렉토리에서 C3는 다음과 같이 생성됩니다.

  - `wrangler.jsonc`: 당신의[모델 번호: Wrangler](/workers/wrangler/configuration/#sample-wrangler-configuration)구성 파일.
  - `index.js`(주)`/src`): 최소한`'Hello World!'`에서 작성된 노동자[ES 모듈](/workers/reference/migrate-to-module-workers/)구문.
  - `package.json`: 최소 Node 의존성 구성 파일.
  - `package-lock.json`: 참고[`npm`관련 기사`package-lock.json`](https://docs.npmjs.com/cli/v9/configuring-npm/package-lock-json).
  - `node_modules`: 참고[`npm`관련 기사`node_modules`](https://docs.npmjs.com/cli/v7/configuring-npm/folders#node-modules).
</Details>

<Details header="이미 git 저장소에 프로젝트가 있다면?">
  C3 템플릿에서 새로운 프로젝트를 만들뿐만 아니라 C3는 기존 Git 저장소에서 새로운 프로젝트를 만들 수 있습니다. 기존 Git 저장소에서 새로운 프로젝트를 만들려면 터미널을 열고 실행하십시오.

  ```sh
  npm create cloudflare@latest -- --template <SOURCE>
  ```

  `<SOURCE>`다음 중 하나가 될 수 있습니다:

  - `user/repo`(기타)
  - `git@github.com:user/repo`
  - `https://github.com/user/repo`
  - `user/repo/some-template`(보통)
  - `user/repo#canary`(브레이크)
  - `user/repo#1234abcd`(주)
  - `bitbucket:user/repo`(비트 버클)
  - `gitlab:user/repo`(기타)

  기존 템플릿 폴더는 Cloudflare WorkersXQ에 대한 요구 사항을 충족하기 위해 최소한의 다음 파일을 포함해야합니다.

  - `package.json`
  - `wrangler.jsonc` [표본 Wrangler 윤곽을 보십시오](/workers/wrangler/configuration/#sample-wrangler-configuration)
  - `src/`worker 스크립트 referenced 포함`wrangler.jsonc`
</Details>

## 2. Wrangler CLI 개발

C3 설치[모델 번호: Wrangler](/workers/wrangler/install-and-update/), Workers 명령행 인터페이스, 기본적으로 Workers 프로젝트에서. Wrangler는 당신에게[지원하다](/workers/wrangler/commands/#init), [제품정보](/workers/wrangler/commands/#dev)·[계정 만들기](/workers/wrangler/commands/#deploy)Workers 프로젝트.

첫 번째 노동자를 만든 후, 실행[`wrangler dev`](/workers/wrangler/commands/#dev)프로젝트 디렉토리의 명령은 작업자를 개발하기위한 로컬 서버를 시작합니다. 이것은 개발 중에 로컬로 작업자를 미리 볼 수 있습니다.

```sh
npx wrangler dev
```

이전에 WranglerXQXQ를 사용하지 않은 경우 웹 브라우저를 열고 Cloudflare 계정에 로그인할 수 있습니다.

오시는 길[모델 번호: http://localhost:8787](http://localhost:8787)당신의 노동자를 볼 수 있습니다.

<Details header="브라우저 문제?">
  이 단계에서 문제가 있거나 브라우저 인터페이스에 액세스 할 수없는 경우, 참조[`wrangler login`](/workers/wrangler/commands/#login)문서.
</Details>

## 3. 글쓰기 코드

새로운 프로젝트 생성 및 실행으로 코드를 작성하고 편집하기 시작할 수 있습니다.

자주 묻는 질문`src/index.js`파일.`index.js`아래 코드로 변환됩니다:

```js title="Original index.js"
export default {
	async fetch(request, env, ctx) {
		return new Response("Hello World!");
	},
};
```

<Details header="코드 설명">
  이 부호 구획은 몇몇 다른 부속으로 이루어져 있습니다.

  ```js title="Updated index.js" {1}
  export default {
  	async fetch(request, env, ctx) {
  		return new Response("Hello World!");
  	},
  };
  ```

  `export default`정의에 필요한 JavaScript 문법[JavaScript 모듈](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Modules#default_exports_versus_named_exports). 당신의 노동자는 목표의 기본 수출을 가지고, 당신의 노동자가 취급해야 하는 사건에 대응하는 재산과 더불어.

  ```js title="index.js" {2}
  export default {
  	async fetch(request, env, ctx) {
  		return new Response("Hello World!");
  	},
  };
  ```

  이름 \*[`fetch()`회사 소개](/workers/runtime-apis/handlers/fetch/)Worker가 HTTP 요청을 받으면 호출됩니다. 다른 유형의 이벤트에 응답하기 위해 수출 된 객체의 추가 이벤트 핸들러를 정의 할 수 있습니다. 예를 들어, 추가[`scheduled()`회사 소개](/workers/runtime-apis/handlers/scheduled/)Worker invocations에 응답하기[Cron 방아쇠](/workers/configuration/cron-triggers/).

  또한,`fetch`핸들러는 항상 3개의 모수를 통과했습니다:[`request`, `env`·`context`](/workers/runtime-apis/handlers/fetch/).

  ```js title="index.js" {3}
  export default {
  	async fetch(request, env, ctx) {
  		return new Response("Hello World!");
  	},
  };
  ```

  Workers 실행 시간 예상`fetch`핸들러를 돌려`Response`객체 또는 Promise로 해결`Response`객체. 이 예제에서, 당신은 새로운 반환`Response`문자열로`"Hello World!"`.
</Details>

당신의 현재에 있는 내용을 대체하십시오`index.js`아래 내용으로 파일, 텍스트 출력을 변경합니다.

```js title="index.js" {3}
export default {
	async fetch(request, env, ctx) {
		return new Response("Hello Worker!");
	},
};
```

그런 다음 파일을 저장하고 페이지를 다시로드하십시오. 작업자의 출력은 새로운 텍스트로 변경됩니다.

<Details header="눈에 띄는 변화?">
  노동자를 위한 산출이 변화하지 않는 경우에, 확인합니다:

  1. 당신은 변경을 저장`index.js`.
  2. 당신은`wrangler dev`실행.
  3. 당신은 당신의 브라우저를 다시로드.
</Details>

## 4. 프로젝트 배포

Wrangler를 통해 작업자를 배포합니다.`*.workers.dev`하위 도메인 또는[주문 영역](/workers/configuration/routing/custom-domains/).

```sh
npx wrangler deploy
```

하위 도메인 또는 도메인을 구성하지 않은 경우 Wrangler는 게시 프로세스 중에 하나 설정할 수 있습니다.

작업자 미리보기`<YOUR_WORKER>.<YOUR_SUBDOMAIN>.workers.dev`.

<Details header="523 오류가 있습니까?">
  자주 묻는 질문[`523`오류 수정](/support/troubleshooting/http-status-codes/cloudflare-5xx-errors/error-523/)때 당신의`*.workers.dev`처음에 대한 하위 도메인은 분을 기다립니다. 또는 오류가 스스로 해결됩니다.
</Details>
