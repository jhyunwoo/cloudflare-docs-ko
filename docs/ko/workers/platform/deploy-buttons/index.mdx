## Cloudflare 버튼에 배포하는 것은 무엇입니까?

CloudflareXQ 버튼으로 WorkersXQ의 배포를 단순화하여 CloudflareXQ를 구현합니다.

- **Git 저장소를 복제**: Cloudflare는 배포 후 개발을 계속할 수 있는 사용자의 GitHub/GitLab 계정으로 소스 저장소를 복제합니다.
- **프로젝트 구성**: 사용자들은 저장소 이름, 작업자 이름과 같은 주요 세부 사항을 사용자 정의할 수 있으며, 새로 만들어진 Git 저장소에 반영된 사용자 정의를 가진 단일 설정 페이지에 필요한 리소스 이름.
- **빌드 및 배치**: Cloudflare는 응용 프로그램을 사용하여 구축[모델 번호: Workers 회사연혁](/workers/ci-cd/builds)Cloudflare 네트워크에 배포합니다. 필요한 모든 리소스는 자동으로 제공되며 추가 설정 없이 Worker에 바인딩됩니다.

## 자동 자원 제공

당신의 노동자 응용 프로그램은 Cloudflare 리소스를 필요로한다면, 그들은 배포의 일부로 자동으로 제공 될 것입니다. 현재 지원된 리소스는 다음과 같습니다:

- **제품 정보**: [KV 네임스페이스](/kv/), [D1 데이터베이스](/d1/), [R2 물통](/r2/), [Hyperdrive](/hyperdrive/), [Vectorize 데이터베이스](/vectorize/)·[비밀번호](/secrets-store/)
- **회사 소개**: [모델 번호: Durable Objects](/durable-objects/), [모델 번호: Workers AI](/workers-ai/)·[모델 번호: Queues](/queues/)

Cloudflare는 당신의 신청을 위한 자원 필요조건을 결정하기 위하여 당신의 근원 repo의 WranglerXQ 윤곽 파일을 읽을 것입니다. 배포 중 Cloudflare는 필요한 리소스를 제공하고 새로 생성 된 리소스에 적용 가능한 WranglerXQ 구성을 업데이트합니다 (예 : 데이터베이스 ID 및 네임스페이스 ID). 성공적인 배포를 보장하려면 소스 저장소가 리소스 이름, 리소스 ID 및 기타 모든 속성에 대한 기본 값이 포함되어 있는지 확인하십시오.

## 좋은 관행

**Build/Deploy 명령어 구성**: 사용자 정의를 사용하는 경우`build`·`deploy`당신의 스크립트`package.json`(예를 들어, 전체 스택 프레임 워크를 사용하거나 D1 마이그레이션을 실행하는 경우), CloudflareXQ는 자동으로 빌드 및 배포 필드를 감지하고 사전 팝업합니다. 사용자는 배포 설정 중에 사용자 지정 명령을 수정하거나 수락할 수 있습니다.

없음`deploy`스크립트는 지정되어, Cloudflare는 preconfigure`npx wrangler deploy`기본적으로. 없음`build`스크립트는 지정되어, Cloudflare는 이 필드 공백을 남길 것입니다.

**실행 D1 이름 \***: 설정의 일부로 마이그레이션을 실행하고 싶다면, 이것에 지정할 수 있습니다.`package.json`당신의 마이그레이션을 실행하여`deploy`스크립트. 마이그레이션 명령은 reference가 데이터베이스 이름보다 묶어 마이그레이션이 성공할 때 사용자가 소스 저장소의 다른 데이터베이스 이름을 지정할 때 성공해야 합니다. 다음은 스크립트 섹션을 설정할 수있는 방법의 예입니다.`package.json`:

```json
{
	"scripts": {
		"build": "astro build",
		"deploy": "npm run db:migrations:apply && wrangler deploy",
		"db:migrations:apply": "wrangler d1 migrations apply DB_BINDING --remote"
	}
}
```

**바인딩에 대한 설명 제공**: 이 템플릿에 필요한 이유와 같은 바인딩에 대한 추가 정보를 제공하려는 경우, 또는 값을 구성하는 방법에 대한 제안, 당신은 당신의 설명을 제공 할 수 있습니다`package.json`. 이것은 특히 Cloudflare 밖에 값을 찾을 필요가 있는 환경변수 및 비밀을 위해 유용합니다.

연락처`` `code` ``, `**bold**`, `__italics__`·`[links](https://example.com)`지원됩니다.

```json title="package.json"
{
	"name": "my-worker",
	"private": true,
	"cloudflare": {
		"bindings": {
			"API_KEY": {
				"description": "Select your company's [API key](https://example.com/) for connecting to the example service."
			},
			"COOKIE_SIGNING_KEY": {
				"description": "Generate a random string using `openssl rand -hex 32`."
			}
		}
	}
}
```

## 제한 사항

- **모노레포지**: Cloudflare는 완전히 지원 monorepos하지 않습니다
  - 저장소 URL이 하위디렉토리가 포함된 경우, 해당 하위디렉토리 내에서 애플리케이션이 완전히 분리되어야 합니다. 그렇지 않으면 빌드가 실패합니다. Cloudflare는 배포 프로세스의 일부로 만든 새로운 저장소의 뿌리로이 하위 디렉토리를 취급합니다.
  - 또한 여러 Workers 응용 프로그램을 포함하는 모노레포가 있다면 함께 배포되지 않습니다. 각 응용 프로그램에 대한 Cloudflare 버튼에 별도의 배포를 구성해야 합니다. 사용자는 수동으로 각 subdirectory를 위한 명백한 Workers 신청을 창조할 것입니다.
- **Pages 신청**: Cloudflare 버튼만 지원 Workers 응용 프로그램에 배포합니다.
- **비 GitHub/GitLab 저장소**: github.com 이외의 소스 저장소 및 gitlab.com은 지원되지 않습니다. GitHub 및 GitLab의 자체 호스팅 버전도 지원되지 않습니다.
- **개인 저장소**: Repositories는 다른 사람들에게 공개해야합니다. 성공적으로 CloudflareXQ 버튼을 사용하여 배포하십시오.
