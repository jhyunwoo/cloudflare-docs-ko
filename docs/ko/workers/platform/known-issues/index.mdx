QXQX0397XQQ Workers를 사용할 때 어떤 알려진 버그와 문제가 있습니다.

## 노선특성

- 특정 경로 정의 할 때, trailing`/*`당신의 본은 예상대로 행동할 수 없습니다.

두 가지 다른 Workers를 고려, 각 같은 영역에 배치. Worker A는 할당됩니다.`example.com/images/*`경로 및 노동자 B는 주어진`example.com/images*`노선 패턴. 이 곳에서는 다음과 같은 URL이 해결되는 방법은 다음과 같습니다.

```
// (A) example.com/images/*
// (B) example.com/images*

"example.com/images"
// -> B
"example.com/images123"
// -> B
"example.com/images/hello"
// -> B
```

당신은 모든 예제 트리거 Worker B. 이 예제는 예기치 않은 행동을 exemplizes.

하위 도메인에 와일드 카드를 추가하면 다음과 같은 URL이 해결됩니다.

```
// (A) *.example.com/a
// (B) a.example.com/*

"a.example.com/a"
// -> B
```

## 다운로드

- 현재 위치`wrangler dev --remote`, 모든 나가는 요구는 주어집니다`cf-workers-preview-token`Cloudflare가 미리보기 요청으로 인식되는 헤더. 이것은 전체 Cloudflare 네트워크에 적용되므로 다른 Cloudflare 영역에 HTTP 요청을 처리하는 것은 현재 보안상의 이유로 삭제됩니다. workaround를 활성화하려면 다음 코드를 Worker 스크립트에 삽입하십시오.

```js
const request = new Request(url, incomingRequest);
request.headers.delete('cf-workers-preview-token');
return await fetch(request);
```

## CNAME 설정에서 Fetch API

자주 묻는 질문[`fetch()`](/workers/runtime-apis/fetch/)작업자에서 Cloudflare DNS 해결자는 사용됩니다. 지역이 있을 때[부분 (CNAME) 설정](/dns/zone-setups/partial-setup/), 노동자가 해결해야 할 모든 호스트명은 Cloudflare의 DNS 설정에서 전용 DNS 항목을 필요로한다. 그렇지 않으면 Fetch API 호출은 상태 코드로 실패합니다.[530 (1016)](/support/troubleshooting/http-status-codes/cloudflare-1xxx-errors/error-1016/).

QXQX0403XQDN의 누락된 DNS 레코드로 설정

```
// Zone in partial setup: example.com
// DNS records at Authoritative DNS: sub1.example.com, sub2.example.com, ...
// DNS records at Cloudflare DNS: sub1.example.com

"sub1.example.com/"
// -> Can be resolved by Fetch API
"sub2.example.com/"
// -> Cannot be resolved by Fetch API, will lead to 530 status code

```

추가하기`sub2.example.com`Cloudflare DNS에

```
// Zone in partial setup: example.com
// DNS records at Authoritative DNS: sub1.example.com, sub2.example.com, ...
// DNS records at Cloudflare DNS: sub1.example.com, sub2.example.com

"sub1.example.com/"
// -> Can be resolved by Fetch API
"sub2.example.com/"
// -> Can be resolved by Fetch API
```

## IP 주소로 Fetch

Workers 잠수함의 경우, 요청은 IP 주소로 직접 URL로 만들 수 있습니다. 이 제한을 극복하기[귀하의 영역에 A 또는 AAAA 이름 레코드를 추가하십시오.](https://developers.cloudflare.com/dns/manage-dns-records/how-to/create-dns-records/)그리고 그 리소스를 fetch한다.

예를 들어, 영역에서`example.com`유형의 기록`A`이름과 함께`server`및 가치`192.0.2.1`, 그리고 그 후에 사용:

```js
await fetch('http://server.example.com')
```

사용되지 않음:

```js
await fetch('http://192.0.2.1')
```
