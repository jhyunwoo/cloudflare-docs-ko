이 가이드는 시작하기를 통해 알려줍니다.`@cloudflare/vitest-pool-workers`패키지. 테스트의 더 복잡한 예제를 위해`@cloudflare/vitest-pool-workers`, 참조[회사 소개](/workers/testing/vitest-integration/recipes/).

첫째, 그것을 확인:

- 내 계정[호환성 날짜](/workers/configuration/compatibility-dates/)설정`2022-10-31`또는 나중에.
- ES 모듈 형식을 사용하여 작업자 (하지 않은 경우, 참조[ES 모듈 형식으로 마이그레이션](/workers/reference/migrate-to-module-workers/)사이트 맵
- 가장 핫한`@cloudflare/vitest-pool-workers`프로젝트에서 dev Dependencies로 설치

  <PackageManagers pkg="vitest@~3.2.0 @cloudflare/vitest-pool-workers" dev="true" />

  :::참조

  :::

## Vitest 구성 정의

내 계정`vitest.config.ts`파일, 사용`defineWorkersConfig`Workers Vitest 통합을 구성하려면.

당신의 Worker 구성을 사용할 수 있습니다.[Wrangler 설정 파일](/workers/wrangler/configuration/)설정하기`wrangler.configPath`.

```ts title = vitest.config.ts
import { defineWorkersConfig } from "@cloudflare/vitest-pool-workers/config";

export default defineWorkersConfig({
	test: {
		poolOptions: {
			workers: {
				wrangler: { configPath: "./wrangler.jsonc" },
			},
		},
	},
});
```

또한 override 또는 추가 구성을 정의할 수 있습니다.`miniflare`주요. Wrangler config를 통해 설정된 값에 대한 우선이 걸립니다.

예를 들어, 이 구성은 KV 네임스페이스를 추가합니다.`TEST_NAMESPACE`테스트에만 접근하고 수정되었습니다.

```js null {6-8}
export default defineWorkersConfig({
	test: {
		poolOptions: {
			workers: {
				wrangler: { configPath: "./wrangler.jsonc" },
				miniflare: {
					kvNamespaces: ["TEST_NAMESPACE"],
				},
			},
		},
	},
});
```

사용 가능한 Miniflare 옵션의 전체 목록은 참조[미니 플레어`WorkersOptions`API 문서](https://github.com/cloudflare/workers-sdk/tree/main/packages/miniflare#interface-workeroptions).

사용 가능한 구성 옵션의 전체 목록은 참조[제품 설명](/workers/testing/vitest-integration/configuration/).

## 유형 정의

Typescript를 사용하지 않는 경우 이 섹션을 건너뛸 수 있습니다.

먼저 실행해야[`wrangler types`](/workers/wrangler/commands/), 생성[Cloudflare QXWorkers 런타임을 위한 유형](/workers/languages/typescript/)한국어`Env`당신의 노동자의 의무에 근거를 두는 유형.

다음을 추가`tsconfig.json`테스트 폴더에서 추가`"@cloudflare/vitest-pool-workers"`유형 배열에 대한 유형 정의`cloudflare:test`·
출력을 추가해야합니다.`wrangler types`이름 \*`include`QXQX0835XQ QXWorkers 런타임을 사용할 수 있도록 배열하십시오.

<Details header="예제 test/tsconfig.json">
  ```jsonc title="test/tsconfig.json"
  {
  	"extends": "../tsconfig.json",
  	"compilerOptions": {
  		"moduleResolution": "bundler",
  		"types": [
  			"@cloudflare/vitest-pool-workers", //`cloudflare:test` 유형 제공
  		],
  	},
  	"include": [
  		"./**/*.ts",
  		"../src/worker-configuration.d.ts", //`wrangler types`의 산출
  	],
  }
  ```
</Details>

당신은 또한의 유형을 정의해야합니다`env`테스트에 제공된 객체. 이름 \*`env.d.ts`테스트 폴더에 파일, 그리고 선언`ProvidedEnv`확장하여 인터페이스`Env`에 의해 생성되는 공용영역`wrangler types`.

```ts title="test/env.d.ts"
declare module "cloudflare:test" {
	//`import("cloudflare:test").env`
	interface ProvidedEnv extends Env {}
}
```

테스트 바인딩이 Wrangler config의 바인딩과 다릅니다. 여기에서 입력해야 합니다.`ProvidedEnv`.

## 시험 쓰기

우리는이 간단한 노동자를 예로 사용합니다. 404 응답을 반환합니다.`/404`경로 및`"Hello World!"`다른 모든 경로.

<TypeScriptExample filename="src/index.ts">
  ```ts
  export default {
  	async fetch(request, env, ctx): Promise<Response> {
  		if (pathname === "/404") {
  			return new Response("Not found", { status: 404 });
  		}
  		return new Response("Hello World!");
  	},
  } satisfies ExportedHandler<Env>;
  ```
</TypeScriptExample>

### 단위 시험

Worker를 수입함으로써 Unit Test를 작성할 수 있습니다.`fetch`핸들러.

<TypeScriptExample filename="test/unit.spec.ts">
  ```ts
  import {
  	env,
  	createExecutionContext,
  	waitOnExecutionContext,
  } from "cloudflare:test";
  import { describe, it, expect } from "vitest";
  //당신의 노동자를 수입하십시오 그래서 당신은 단위 시험할 수 있습니다
  import worker from "../src";

  //지금, 당신은이 같은 무언가를 할 필요가있어 올바르게 입력
  //`Request`는 `worker.fetch()`XQ에 전달합니다.
  const IncomingRequest = Request<unknown, IncomingRequestCfProperties>;

  describe("Hello World worker", () => {
  	it("responds with Hello World!", async () => {
  		const request = new IncomingRequest("http://example.com/404");
  		//`worker.fetch()`
  		const ctx = createExecutionContext();
  		const response = await worker.fetch(request, env, ctx);
  		//`ctx.waitUntil()`XQXQ가 `ctx.waitUntil()`로 전달되는 모든 QX`Promise`XQ를 기다리십시오
  		await waitOnExecutionContext(ctx);
  		expect(response.status).toBe(404);
  		expect(await response.text()).toBe("Not found");
  	});
  });

  ```
</TypeScriptExample>

### 통합 시험

SELF fetcher를 사용할 수 있습니다.`cloudflare:test`통합 테스트를 작성합니다. 이것은 주요 노동자에서 정의 된 기본 수출에 대한 서비스 바인딩입니다.

<TypeScriptExample filename="test/integration.spec.ts">
  ```ts
  import { SELF } from "cloudflare:test";
  import { describe, it, expect } from "vitest";

  describe("Hello World worker", () => {
  	it("responds with not found and proper status for /404", async () => {
  		const response = await SELF.fetch("http://example.com/404");
  		expect(response.status).toBe(404);
  		expect(await response.text()).toBe("Not found");
  	});
  });

  ```
</TypeScriptExample>

사용 방법`SELF`통합 테스트를 위해 Worker 코드는 테스트 런너와 동일한 컨텍스트에서 실행됩니다. 이것은 당신이 당신의 노동자를 통제하기 위하여 세계적인 모조를 사용할 수 있다는 것을 의미합니다, 또한 당신의 노동자는 Vite에 의해 제공된 subtly 다른 단위 해결책 행동을 이용합니다.
일반적으로 이것은 문제가 아니지만, 가능한 한 생산에 가까운 신선한 환경에서 노동자를 실행하려면 보조 노동자를 사용할 수 있습니다. 더 알아보기[이 예제](https://github.com/cloudflare/workers-sdk/blob/main/fixtures/vitest-pool-workers-examples/basics-integration-auxiliary/vitest.config.ts)보조 Workers를 사용하여 통합 테스트를 설정하는 방법. 그러나, 보조 Workers를 사용하여 옵니다[제한 사항](/workers/testing/vitest-integration/configuration/#workerspooloptions)당신은 알고 있어야한다.
