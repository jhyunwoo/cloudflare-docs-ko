이 가이드는 설정 방법을 보여줍니다[미니 플레어](/workers/testing/miniflare)Workers를 시험하기 위하여. Miniflare는 Workers가 실행되고 시험되는 방법을 완전히 통제할 수 있는 저수준 API입니다.

Miniflare를 사용하려면 Miniflare v3의 최신 버전을 설치해야합니다.

<PackageManagers pkg="miniflare@latest" dev />

이 가이드의 나머지는 개념을 보여줍니다.[`node:test`](https://nodejs.org/api/test.html)테스트 프레임 워크,하지만 어떤 테스트 프레임 워크 사용할 수 있습니다.

Miniflare는 작업자를 실행하기위한 다양한 구성 옵션을 노출하는 저수준 API입니다. 대부분의 경우, 테스트는 사용 가능한 옵션의 하위 세트 만 필요하지만, 참조 할 수 있습니다[가득 차있는 API reference](/workers/testing/miniflare/get-started/#reference)Miniflare에서 가능한 것을 탐험하십시오.

테스트를 작성하기 전에 노동자를 만들 필요가 있습니다. Miniflare는 Cloudflare 플랫폼 primitives를 에뮬레이션하는 저수준 API이기 때문에, 당신의 노동자는 JavaScriptXQ 또는 당신에 기록될 필요가 있을 것입니다[자체 구축 파이프라인 통합](#custom-builds)테스트 설정으로. 다음은 JavaScript 전용 노동자입니다.

```js title="src/index.js"
export default {
	async fetch(request) {
		return new Response(`Hello World`);
	},
};
```

다음, 당신은 초기 테스트 파일을 만들 필요가:

```js {12,13,14,15,16,17,18,19} title="src/index.test.js"
import assert from "node:assert";
import test, { after, before, describe } from "node:test";
import { Miniflare } from "miniflare";

describe("worker", () => {
	/** 이름
* @ 유형 {Miniflare}*/
	let worker;

	before(async () => {
		worker = new Miniflare({
			modules: [
				{
					type: "ESModule",
					path: "src/index.js",
				},
			],
		});
		await worker.ready;
	});

	test("hello world", async () => {
		assert.strictEqual(
			await (await worker.dispatchFetch("http://example.com")).text(),
			"Hello World",
		);
	});

	after(async () => {
		await worker.dispose();
	});
});
```

위의 테스트를 실행할 수 있어야 합니다.`node --test`

위의 테스트 파일의 강조 표시 줄은 JavaScript Worker를 실행하는 Miniflare를 설정하는 방법을 보여줍니다. Miniflare가 설정되면 개별 테스트는 실행 작업자와 응답에 대한 assert에 요청을 보낼 수 있습니다. 이것은 당신의 노동자를 시험하기를 위한 Miniflare를 사용하여의 주요 제한입니다[Vitest 통합](/workers/testing/vitest-integration/)— 당신의 노동자에 대한 모든 접근은`dispatchFetch()`Miniflare API, 당신은 당신의 노동자에게서 개별 기능을 시험할 수 없습니다.

## Bindings로 해석

:::카트로션

Miniflare는 읽지 않습니다[Wrangler의 구성 파일](/workers/wrangler/configuration). 당신의 노동자가 Miniflare API 선택권에서 지정되어야 하는 모든 바인딩.

:::

더 보기`dispatchFetch()`Miniflare에서 API를 사용하면 작업자에게 요청을 보내고 올바른 응답이 반환되었지만 때로는 테스트에서 바인딩과 직접 상호 작용해야합니다. 같은 사용 사례를 위해 Miniflare는[`getBindings()`](/workers/testing/miniflare/get-started/#reference)API. 예를 들어, 테스트에서 환경 변수에 액세스하려면 테스트 파일을 적응`src/index.test.js`다음과 같이:

```diff lang="js" title="src/index.test.js"
...
describe("worker", () => {
	...
	before(async () => {
		worker = new Miniflare({
			...
+			bindings: {
+				FOO: "Hello Bindings",
+			},
		});
		...
	});

	test("text binding", async () => {
		const bindings = await worker.getBindings();
		assert.strictEqual(bindings.FOO, "Hello Bindings");
	});
	...
});
```

KV 및 R2XQ와 같은 로컬 리소스와 상호 작용할 수 있습니다. 예를 들어, KV 네임스페이스와 상호 작용하는 방법은 다음과 같습니다.

```diff lang="js" title="src/index.test.js"
...
describe("worker", () => {
	...
	before(async () => {
		worker = new Miniflare({
			...
+			kvNamespaces: ["KV"],
		});
		...
	});

	test("kv binding", async () => {
		const bindings = await worker.getBindings();
		await bindings.KV.put("key", "value");
		assert.strictEqual(await bindings.KV.get("key"), "value");
	});
	...
});
```

## 더 복잡한 Workers

위의 예는 단일 JavaScript 파일로 구성된 간단한 작업자를 테스트하는 방법을 보여줍니다. 그러나 대부분의 실제 Workers는 그보다 더 복잡합니다. Miniflare는 API를 사용하여 Worker의 모든 constituent 파일 제공:

```js
new Miniflare({
	modules: [
		{
			type: "ESModule",
			path: "src/index.js",
		},
		{
			type: "ESModule",
			path: "src/imported.js",
		},
	],
});
```

이것은 당신의 노동자가 성장함에 따라 약간의 자갈 수 있습니다. 이것을 돕기 위하여, Miniflare는 또한 모듈을 포함하는 자동적으로 파악하기 위하여 단위 도표를 크롤링할 수 있습니다:

```js
new Miniflare({
	scriptPath: "src/index-with-imports.js",
	modules: true,
	modulesRules: [{ type: "ESModule", include: ["**/*.js"] }],
});
```

## 사용자 정의

많은 실제 사례에서 Workers는 일반 JavaScriptXQ로 작성되지 않지만 npm 패키지 및 기타 의존성에서 가져 오는 여러 TypeScriptXQ 파일로 구성되며 빌드 도구에 의해 번들됩니다. Miniflare를 통해 작업자를 테스트하면 테스트 전에이 빌드 도구를 실행해야합니다. 이 빌드가 실행되는 방법은 특정 테스트 프레임 워크에 의존하지만,`node:test`그것은 가능성이`setup()`걸이. 예를 들어, 사용 중인 경우[모델 번호: Wrangler](/workers/wrangler/)당신의 노동자를 구축하고 배포하기 위해, 당신은 살 수`wrangler build`다음과 같은 명령:

```js
before(() => {
	spawnSync("npx wrangler build -c wrangler-build.json", {
		shell: true,
		stdio: "pipe",
	});
});
```
