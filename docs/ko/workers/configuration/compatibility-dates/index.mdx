Cloudflare는 정기적으로 Workers 런타임을 업데이트합니다. 이 업데이트는 전 세계적으로 모든 WorkersXQ에 적용되며 이미 기능을 중지하기 위해 배포 된 작업자가 발생하지 않아야합니다. 때로는 약간의 변화가 뒤로 호환 될 수 있습니다. 특히, 기존 Workers가 의도적으로 의존할 수 있는 runtime API에 버그가 있을 수 있습니다. Cloudflare는 새로운 Workers가 기존 WorkersXQXQ가 배포된 Workers를 방지하기 위해 버그 수정을 계속할 수 있는 버그 수정을 실행합니다.

호환성 날짜 및 플래그는 개발자로서이 실행 시간 변경을 선택합니다.[호환성 깃발](/workers/configuration/compatibility-flags)그들은 기본적으로 활성화된 날짜를 갖게 되며, 지정하여`compatibility_date`당신의 노동자를 위해, 당신은 빨리 이 각종 compatibility flagsXQ의 전부를, 그 날짜를 포함하여 빨리 가능하게 할 수 있습니다.

## 호환성 날짜 설정

프로젝트를 시작할 때 항상 설정해야 합니다.`compatibility_date`현재 날짜에. 당신은 때때로 업데이트해야합니다`compatibility_date`이름 \* 업데이트 할 때, 당신은 참조해야합니다[모델 번호: compatibility flags](/workers/configuration/compatibility-flags)페이지가 변경되었는지, 당신은 당신의 노동자를 시험하는 것을 주의해야 합니다 변화가 당신에게 영향을 미치는지, 필요한대로 코드를 업데이트. 새로운 호환성 날짜는 다음 실행시 효력을 발생합니다.[`npx wrangler deploy`](/workers/wrangler/commands/#deploy)명령.

업데이트 할 필요가 없습니다`compatibility_date`당신이 원하는 경우. Workers 실행 시간은 영원히 오래된 호환성 날짜를 지원할 것입니다. 만약에, 어떤 이유로, Cloudflare는 살아있는 WorkersXQ, CloudflareXQXQ가 적극적으로 영향을 미칠 변화를 만드는 데 필요한 것을 발견한다. 즉, Cloudflare는 모든 경우에 이것을 피하는 것을 목표로한다.

그러나 업데이트 할 필요가 없습니다.`compatibility_date`필드, 두 가지 이유를 위해 그렇게 할 수있는 좋은 연습입니다 :

1. 때때로 새로운 기능은 현재가 있는 Workers에서만 사용할 수 있습니다`compatibility_date`. 최신 기능에 액세스하려면 최신 상태를 유지해야합니다.
2. 일반적으로, 다른 것보다[모델 번호: compatibility flags](/workers/configuration/compatibility-flags)Workers 문서는 현재를 설명할 수 있습니다.`compatibility_date`, 역사적인 행동에 대한 정보를 omitting. 노동자가 오래된 경우`compatibility_date`, 당신은 지속적으로 compatibility flags 페이지를 참조해야 할 것입니다 당신이 사용하고있는 APIs 중 하나를 확인하려면.

#### Wrangler

호환성 날짜는 노동자의에서 놓일 수 있습니다[Wrangler 구성 파일](/workers/wrangler/configuration/).

<WranglerConfig>
  ```jsonc
  {
  	//4 월 5, 2022을 통해 백그라운드 호환 변경으로 전환하십시오.
  	"compatibility_date": "2022-04-05"
  }
  ```
</WranglerConfig>

#### Cloudflare 대시보드를 통해

노동자가 Cloudflare 대시보드를 통해 생성될 때, 겸용성 날짜는 현재 날짜에 자동적으로 놓입니다.

호환성 날짜는 Workers 설정에서 업데이트 될 수 있습니다[Cloudflare dashboard](https://dash.cloudflare.com/).

#### Cloudflare API를 통해

호환성 날짜는 노동자를 사용하여 업로드할 때 설정될 수 있습니다[Workers 스크립트 API](/api/resources/workers/subresources/scripts/methods/update/)또는[Workers 버전 API](/api/resources/workers/subresources/scripts/subresources/versions/methods/create/)요청 몸의`metadata`이름 \*

호환성 날짜가 API를 통해 업로드에 지정되지 않은 경우, 모든 플래그가 효력을 발생하기 전에 가장 오래된 호환성 날짜에 기본값 (2021-11-02). 새로운 Workers를 만들 때 API를 통해 업로드 할 때 현재의 날짜에 호환성 날짜를 설정하는 것이 좋습니다.
