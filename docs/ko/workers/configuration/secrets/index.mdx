## 이름 \*

비밀은 암호화 된 텍스트 값을 작업자에게 첨부 할 수있는 바인딩 유형입니다. 비밀은 API 키와 auth 토큰과 같은 민감한 정보를 저장하는 데 사용됩니다.

Worker 코드를 통해 비밀에 액세스할 수 있습니다:

- 더 보기[`env`이름 \*](/workers/runtime-apis/handlers/fetch/#parameters)당신의 노동자에 전달[`fetch`이벤트 핸들러](/workers/runtime-apis/handlers/fetch/).
- 관련 상품`env`이름 \*[`cloudflare:workers`](/workers/runtime-apis/bindings/#importing-env-as-a-global)코드를 어디에서든지에서 비밀을 접근하십시오.
- [`process.env`](/workers/configuration/environment-variables)Workers에[Node.js 호환성](/workers/runtime-apis/nodejs/)지원하다

## Workers로 비밀 접근

비밀은 Workers에서 다른 어떤 것일 수 있습니다[환경 변수](/workers/configuration/environment-variables/). 예를 들어, 주어진`DB_CONNECTION_STRING`비밀, 당신은 당신의 노동자 코드를 통해 액세스 할 수`env`모수:

```js title="index.js"
import postgres from "postgres";

export default {
	async fetch(request, env, ctx) {
		const sql = postgres(env.DB_CONNECTION_STRING);

		const result = await sql`SELECT * FROM products;`;

		return new Response(JSON.stringify(result), {
			headers: { "Content-Type": "application/json" },
		});
	},
};
```

또한 가져올 수 있습니다`env`이름 \*`cloudflare:workers`요청 핸들러의 외부를 포함한 코드에서 비밀에 액세스하려면:

<TypeScriptExample>
  ```ts
  import { env } from "cloudflare:workers";
  import postgres from "postgres";

  //비밀을 사용하여 최상위에서 데이터베이스 클라이언트를 초기화
  const sql = postgres(env.DB_CONNECTION_STRING);

  export default {
  	async fetch(request: Request): Promise<Response> {
  		const result = await sql`SELECT * FROM products;`;

  		return new Response(JSON.stringify(result), {
  			headers: { "Content-Type": "application/json" },
  		});
  	},
  };
  ```
</TypeScriptExample>

액세스에 대한 자세한 내용은`env`글로벌, 참조[관련 상품`env`글로벌](/workers/runtime-apis/bindings/#importing-env-as-a-global).

:::노트\[Secrets Store (베타)]
이 페이지에 설명 된 비밀은 per-Worker 수준에 정의되고 관리됩니다. 계정 수준의 비밀을 사용하려면, 참조[비밀번호](/secrets-store/). 계정 수준의 비밀은 당신의 노동자에 구성[비밀 저장 바인딩](/secrets-store/integrations/workers/).
:::

## 배포 Workers에 대한 비밀

### 당신의 프로젝트에 비밀을 추가

#### Wrangler

비밀을 통해 추가할 수 있습니다.[`wrangler secret put`](/workers/wrangler/commands/#secret)또는[`wrangler versions secret put`](/workers/wrangler/commands/#versions-secret-put)명령.

`wrangler secret put`Worker의 새로운 버전을 만들고 즉시 배포합니다.

```sh
npx wrangler secret put <KEY>
```

사용 방법[gradual 배포](/workers/configuration/versions-and-deployments/gradual-deployments/), 대신 사용`wrangler versions secret put`명령. 이것은 노동자의 새로운 버전을 만들 것입니다, 그 다음을 사용하여 배포 할 수 있습니다[`wrangler versions deploy`](/workers/wrangler/commands/#versions-deploy).

:::참조
3.73.0의 앞에 Wrangler 버전은 당신이 지정할 것을 요구합니다`--x-versions`플래그.
주요 특징

```sh
npx wrangler versions secret put <KEY>
```

#### dashboard를 통해

dashboard를 통해 비밀을 추가하려면:

1. Cloudflare dashboard에서, 가십시오**Workers & Pages**사이트 맵

   <DashButton url="/?to=/:account/workers-and-pages" />

2. 내 계정**제품정보**, 당신의 노동자를 선정 >**계정 설정**.

3. 이름 \***변수 및 비밀**, 선택**더 보기**.

4. 유형 선택**계정 관리**, 입력**변수 이름**, 그리고 그것의 입력**제품정보**. 이 비밀은 당신의 노동자에 유효하 그러나 가치는 Wrangler 및 dashboard에서 숨겨질 것입니다.

5. (선택) 더 많은 비밀을 추가하려면, 선택**추가 변수**.

6. 제품정보**계정 만들기**당신의 변화를 구현합니다.

### 당신의 프로젝트에서 비밀 삭제

#### Wrangler

비밀을 통해 삭제할 수 있습니다[`wrangler secret delete`](/workers/wrangler/commands/#secret-delete)또는[`wrangler versions secret delete`](/workers/wrangler/commands/#versions-secret-delete)명령.

`wrangler secret delete`Worker의 새로운 버전을 만들고 즉시 배포합니다.

```sh
npx wrangler secret delete <KEY>
```

사용 방법[gradual 배포](/workers/configuration/versions-and-deployments/gradual-deployments/), 대신 사용`wrangler versions secret delete`명령. 이것은 노동자의 새로운 버전을 만들 것입니다, 그 다음을 사용하여 배포 할 수 있습니다[`wrangler versions deploy`](/workers/wrangler/commands/#versions-deploy).

```sh
npx wrangler versions secret delete <KEY>
```

#### dashboard를 통해

dashboard를 통해 노동자 프로젝트에서 비밀을 삭제하려면:

1. Cloudflare dashboard에서, 가십시오**Workers & Pages**사이트 맵

   <DashButton url="/?to=/:account/workers-and-pages" />

2. 내 계정**제품정보**, 당신의 노동자를 선정 >**계정 설정**.

3. 이름 \***변수 및 비밀**, 선택**제품정보**.

4. 내 계정**제품정보**서랍, 선택**사이트맵**삭제하려는 비밀 옆에.

5. 제품정보**계정 만들기**당신의 변화를 구현합니다.

6. (선택 사항) 편집 서랍을 사용하는 대신 비밀에 삭제 아이콘을 클릭 할 수 있습니다.
