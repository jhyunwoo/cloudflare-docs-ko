버전은 작업자에게 변화합니다. Deployments는 트래픽에 배포되는 방법을 구성합니다.

작업자의 독립적으로 변경할 수 있는 변경(버전)을 업로드할 수 있습니다.

![버전 및 배포](~/assets/images/workers/platform/versions-and-deployments/versions-and-deployments.png)

버전 및 배포를 사용하는 것은 유용하다면:

- Workers에 중요한 응용 프로그램을 실행하고 롤링 배포 전략을 사용하여 작업자의 새로운 버전을 배포 할 때 위험을 줄일 수 있습니다.
- 작업자의 새로운 버전을 배포할 때 성능 차이를 모니터링하고 싶습니다.
- 당신은 WorkersXQ를 위해 형성된 CI/CD 파이프라인이 있고 그러나 수동 방출을 삭감하고 싶습니다.

## 이름 \*

버전은 코드의 상태뿐만 아니라 노동자의 구성의 상태에 의해 정의됩니다[Wrangler 구성 파일](/workers/wrangler/configuration/). 버전은 역사적 변화를 추적[번들 코드](/workers/wrangler/bundling/), [정적 자산](/workers/static-assets/)설정 변경[관련 제품](/workers/runtime-apis/bindings/)·[겸용성 날짜와 compatibility flags](/workers/configuration/compatibility-dates/)시간 이상.

버전 또한 버전과 관련된 메타데이터를 추적합니다.: 버전 ID, 버전 생성, 소스 배포, 타임스탬프. 선택적으로, 버전 메시지 및 버전 태그는 버전 업로드에 구성 될 수 있습니다.

:::참조
관련 Workers에 대한 국가 변경[저장 자원](/workers/platform/storage-options/)등[KV](/kv/), [R2](/r2/), [Durable Objects](/durable-objects/)·[D1](/d1/)버전으로 추적되지 않습니다.

## 계정 만들기

배포판은 작업자의 버전(s)을 추적하여 트래픽을 전달합니다. 배포는 노동자의 하나 또는 두 가지 버전으로 구성 할 수 있습니다.

기본적으로 Workers는 트래픽이 1 버전에서 새로 배치 된 버전으로 즉시 이동되는 모든 입력 온스 배포 모델을 지원합니다. 대안으로, 당신은 사용할 수 있습니다[gradual 배포](/workers/configuration/versions-and-deployments/gradual-deployments/)롤링 배포 전략을 만들려면.

배포와 관련된 메타데이터를 추적할 수 있습니다: 배포를 생성하는 사용자, 배포 소스, 타임스탬프 및 버전(s) 배포. 선택적으로, 배포를 만들 때 배포 메시지를 구성할 수 있습니다.

## 버전 및 배포 사용

### 새 버전 만들기

작업자의 버전을 만들 수있는 다른 방법을 검토하고 배포합니다.

#### 새 버전을 업로드하고 즉시 배포

자동으로 트래픽의 100 %에 배치 된 새로운 버전 :

- 변경 사항[`wrangler deploy`](/workers/wrangler/commands/#deploy)Cloudflare 대시보드를 통해
- 변경은 명령으로 배포됩니다.[`npx wrangler deploy`](/workers/wrangler/commands/#deploy)이름 \*[Workers 회사연혁](/workers/ci-cd/builds)
- 변경 사항[Workers 스크립트 업로드 API](/api/resources/workers/subresources/scripts/methods/update/)

#### 새 버전을 업로드하여 배포하거나 나중에 배포

:::참조

3.73.0의 앞에 Wrangler 버전은 당신이 지정할 것을 요구합니다`--x-versions`플래그.

:::

즉시 배포되지 않은 작업자의 새로운 버전을 만들려면, 사용[`wrangler versions upload`](/workers/wrangler/commands/#versions-upload)명령 또는 Cloudflare dashboard를 통해 새로운 버전을 만들**제품 정보**버튼. 당신은 찾을 수 있습니다**제품 정보**아래 옵션은 "Deploy" 버튼 옆에 있습니다.

이 방법으로 만든 버전은 한 번에 배포 될 수 있습니다 또는 점차적으로 사용[`wrangler versions deploy`](/workers/wrangler/commands/#versions-deploy)명령 또는 Cloudflare dashboard를 통해**계정 만들기**탭.

:::참조
사용 방법[Wrangler](/workers/wrangler/), 노동자의 방아쇠로 만든 변화[경로, 도메인](/workers/configuration/routing/)또는[cron 트리거](/workers/configuration/cron-triggers/)명령에 적용해야 합니다.[`wrangler triggers deploy`](/workers/wrangler/commands/#triggers).
:::

:::참조
새 버전은 변경할 때 생성되지 않습니다.[작업자에 연결된 리소스](/workers/runtime-apis/bindings/). 예를 들어, 2 Workers (Worker A 및 Worker B)가 연결되면[서비스 바인딩](/workers/runtime-apis/bindings/service-bindings/), Worker B의 코드를 변경하는 것은 Worker A의 새로운 버전을 만들지 않을 것입니다. Worker B의 코드를 변경하는 것은 Worker B의 새로운 버전을 만들 것입니다. 서비스 바인딩 변경 (예 : 바인딩을 삭제하거나 삭제[환경분야](/workers/wrangler/environments/)Worker A의 포인트는 Worker B의 새로운 버전을 만들 수 없습니다.

## 제한 사항

### 첫 번째 업로드

자주 묻는 질문[사이트맵](/workers/get-started/guide/#1-create-a-new-worker-project)또는[`wrangler deploy`](/workers/wrangler/commands/#deploy)당신이 새로운 Workers 프로젝트를 창조하는 첫번째로. 사용 방법[`wrangler versions upload`](/workers/wrangler/commands/#versions-upload)노동자를 업로드하면 실패합니다.

### 서비스 노동자 syntax

Service worker 문법은 업로드된 버전에 지원되지 않습니다.[`wrangler versions upload`](/workers/wrangler/commands/#versions-upload). ES 모듈 형식을 사용해야 합니다.

더 알아보기[서비스 Workers에서 ES 모듈로 마이그레이션](/workers/reference/migrate-to-module-workers/#advantages-of-migrating)서비스 노동자 형식에서 ES 모듈 형식으로 Workers를 마이그레이션하는 방법을 배울 수 있습니다.

### 튼튼한 목표 마이그레이션

버전 업로드[튼튼한 목표 마이그레이션](/durable-objects/reference/durable-objects-migrations/)지원되지 않습니다. 제품 정보[`wrangler deploy`](/workers/wrangler/commands/#deploy)신청하는 경우[튼튼한 목표 마이그레이션](/durable-objects/reference/durable-objects-migrations/).

앞으로도 지원될 것입니다.
