인바운드 HTTP 요청을 수신하려면 인터넷에 액세스 할 수있는 외부 엔드 포인트에 연결해야합니다.

3 종류의 노선이 있습니다.

- [사용자 정의 도메인](/workers/configuration/routing/custom-domains): 도메인 또는 하위 도메인 경로 (예 :`example.com`또는`shop.example.com`) 노동자가 근원인 Cloudflare 지역 안에.

- [오시는 길](/workers/configuration/routing/routes/): Cloudflare 영역 내에서 설정되는 경로는 원래 서버가 있는 경우, 노동자가 통신할 수 있는 노동자 뒤에 있습니다.

- [`workers.dev`](/workers/configuration/routing/workers-dev/): 아`workers.dev`subdomain 노선은 각 노동자를 위해 자동으로 생성되어 신속하게 시작할 수 있습니다. 당신은 선택할 수 있습니다[기타 제품](/workers/configuration/routing/workers-dev/)이름 \*`workers.dev`하위 도메인.

## 나에게 가장 좋은 것은?

그것은 생산 Workers를 실행하는 것이 좋습니다[Workers 노선 또는 사용자 정의 도메인](/workers/configuration/routing/), 오히려 당신의 것에`workers.dev`하위 도메인. 내 계정`workers.dev`subdomain는 대우됩니다[무료 웹사이트](https://www.cloudflare.com/plans/)개인 또는 취미 프로젝트가 아닌 비즈니스를 위한 것입니다.

Custom Domains는 Worker가 애플리케이션의 Origin 서버인 경우 사용을 권장합니다. 사용자 정의 도메인은 동일한 영역 내에서 호출 할 수 있습니다.`fetch()`, 노선과는 달리.

응용 프로그램의 기원 서버가 Cloudflare에 외부인 경우를 사용하는 경우를 권장합니다. 같은 영역의 대상이 될 수 없습니다`fetch()`전화.
