호환성 깃발은 특정한 특징을 가능하게 합니다. Workers 팀 테스트가 기본적으로 활성화되지 않는 변경 사항을 테스트하거나 코드가 의존하지만 여전히 다른 호환성 변경을 적용 할 수 있도록 변경 사항을 다시 유지해야하는 경우 유용 할 수 있습니다.

호환성 플래그는 종종 기본적으로 활성화되는 날짜를 가지고 있으므로, 지정하여[`compatibility_date`](/workers/configuration/compatibility-dates)당신의 노동자를 위해, 당신은 빨리 이 각종 compatibility flagsXQXQ의 모두를 가능하게 하고, 그 날짜를 포함하여.

## compatibility flags를 놓기

당신은 목록을 제공 할 수 있습니다`compatibility_flags`특정 변경을 활성화하거나 비활성화하는 경우.

#### Wrangler

호환성 깃발은 노동자의 놓일 수 있습니다[Wrangler 구성 파일](/workers/wrangler/configuration/).

이 예제는 특정 플래그를 활성화`formdata_parser_supports_files`설명 된[이름 \*](/workers/configuration/compatibility-flags/#formdata-parsing-supports-file). 지정된 날짜로,`2021-09-14`, 이 특정 플래그는 아직 기본적으로 활성화되지 않았다, 하지만, 그것을 지정하여`compatibility_flags`, 우리는 그것을 어쨌든 가능하게 할 수 있습니다.`compatibility_flags`이전의 기본이 되는 변경도 사용할 수 있습니다.

<WranglerConfig>
  ```jsonc
  {
  	//2021년 9월 14일 이후의 호환성 변경으로 전환합니다.
  	"compatibility_date": "2021-09-14",
  	//또한 FormData API에 대한 곧 수정을 선택합니다.
  	"compatibility_flags": [
  		"formdata_parser_supports_files"
  	]
  }
  ```
</WranglerConfig>

#### Cloudflare 대시보드를 통해

호환성 깃발은 Workers 조정에서 새롭게 할 수 있습니다[Cloudflare dashboard](https://dash.cloudflare.com/).

#### Cloudflare API를 통해

호환성 깃발은 노동자를 사용하여 업로드할 때 놓일 수 있습니다[Workers 스크립트 API](/api/resources/workers/subresources/scripts/methods/update/)또는[Workers 버전 API](/api/resources/workers/subresources/scripts/subresources/versions/methods/create/)요청 몸의`metadata`이름 \*

## Node.js 호환성 깃발

:::참조
[더 보기`nodejs_compat`계정 만들기](/workers/runtime-apis/nodejs/)또한 가능`nodejs_compat_v2`귀하의 호환성 날짜가 2024-09-23 또는 나중에입니다. v2 플래그는 실행 시간 Node.js 호환성을 개선하여 추가 polyfills 및 글로벌 작업자. 그러나이 개선은 번들 크기를 증가시킵니다.

귀하의 호환성 날짜가 2024-09-22 또는 이전이며 v2를 활성화하려면 추가하십시오.`nodejs_compat_v2`더 알아보기`nodejs_compat`플래그.
당신의 겸용성 날짜가 2024-09-23 후에 있는 경우에, 그러나 당신은 당신의 뭉치 크기를 증가시키기 위하여 v2를 비활성화하고 싶은 경우에, 추가하십시오`no_nodejs_compat_v2`더 알아보기`nodejs_compat flag`.
:::

·[성장 subset](/workers/runtime-apis/nodejs/)Node.js APIs는 직접 유효합니다[런타임 API](/workers/runtime-apis/nodejs), 당신의 자신의 부호에 polyfills를 추가할 필요가 없습니다. 작업자에서 이러한 API를 활성화하려면 추가`nodejs_compat`호환성 플래그[Wrangler 구성 파일](/workers/wrangler/configuration/):

<Render file="nodejs_compat" product="workers" />

<WranglerConfig>
  ```jsonc
  {
  	"compatibility_flags": [
  		"nodejs_compat"
  	]
  }
  ```
</WranglerConfig>

추가 Node.js APIs 추가로, 그들은 아래에 사용할 수 있습니다`nodejs_compat`호환성 깃발. 다른 대부분의 compatibility flags와는 달리, 우리는 예상하지 않습니다`nodejs_compat`미래의 날짜에서 기본적으로 활성화됩니다.

Node.js`AsyncLocalStorage`API는 Workers를 위한 특히 유용한 특징입니다. 만 사용할 수`AsyncLocalStorage`API, 사용`nodejs_als`호환성 깃발.

<WranglerConfig>
  ```jsonc
  {
  	"compatibility_flags": [
  		"nodejs_als"
  	]
  }
  ```
</WranglerConfig>
