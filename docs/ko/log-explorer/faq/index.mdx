## 쿼리에 사용할 수 있는 필드(또는 열)는 무엇인가요?

[지원되는 데이터세트](/log-explorer/manage-datasets/#supported-datasets)에 해당하는 [Datasets](/logs/logpush/logpush-job/datasets/)에 나열된 모든 필드는 Log Explorer에서 볼 수 있습니다.

## 내 쿼리가 완료되지 않거나 시간 초과되는 이유는 무엇인가요?

Log Explorer는 쿼리 매개변수가 더 좁은 시간 범위에 집중될 때 가장 잘 동작합니다. 쿼리가 많은 양의 데이터를 반환하는 경우 쿼리 시간 초과가 발생할 수 있습니다. 성능 향상을 위해 쿼리를 더 구체화해 보세요.

## 데이터세트를 활성화한 뒤 쿼리에서 로그가 보이지 않는 이유는 무엇인가요?

Log Explorer는 데이터세트를 활성화한 시점부터 로그 수집을 시작합니다. 데이터세트가 활성화되기 전에 발생한 이벤트에 대한 로그는 표시되지 않습니다. 데이터세트를 활성화한 이후 새로운 이벤트가 생성되었는지 확인한 다음 다시 확인하세요.

## 쿼리에서 오류가 반환되었습니다. 무엇이 잘못되었는지 어떻게 확인하나요?

현재 오류 코드를 개선하기 위해 적극적으로 작업 중입니다. 일반적인 오류를 받았다면 SQL 구문(사용자 지정 SQL 기능을 사용하는 경우)을 확인하고 날짜와 limit를 포함했는지 확인하세요. 그래도 쿼리가 실패하면 시간 초과일 가능성이 높습니다. 필터를 더 구체적으로 조정해 보세요.

## 데이터는 어디에 저장되나요?

데이터는 Cloudflare R2에 저장됩니다. 각 Log Explorer 데이터세트는 Cloudflare D1과 유사하게 고객별 수준에서 저장되며, 이를 통해 고객 데이터가 다른 고객의 데이터와 분리되어 유지됩니다. 앞으로 이 싱글 테넌트 스토리지 모델을 통해 자체 보존 정책을 만들고 데이터를 어느 리전에 저장할지 선택할 수 있는 유연성이 제공될 예정입니다.

## Log Explorer는 Customer Metadata Boundary를 지원하나요?

현재 Log Explorer는 Customer Metadata Boundary를 지원하지 않습니다.

## Log Explorer가 지원할 수 있는 로그 볼륨에 제한이 있나요?

Log Explorer 데이터 플랫폼은 계속해서 확장되고 있습니다. 현재 Log Explorer는 초당 최대 50,000레코드의 로그 수집 속도를 지원합니다. 이보다 더 높은 수준이 필요하다면 담당 계정 팀에 문의하세요.

## Log Explorer는 Logpush와 어떻게 다른가요? 둘 다 필요한가요?

Log Explorer를 사용하면 대시보드 또는 API에서 Cloudflare 로그를 직접 검색하고 분석할 수 있습니다. 반면 [Logpush](/logs/logpush/)는 원시 로그를 타사 SIEM 또는 스토리지 시스템으로 전달합니다. 일반적으로 둘 다 필요하지는 않지만, 일부 고객은 빠른 조사를 위해 Log Explorer를 사용하고 장기 보관 또는 다른 도구와의 통합을 위해 Logpush를 사용합니다.

## Log Explorer의 무료 버전이나 체험판이 있나요?

Log Explorer는 모든 Application Services 또는 Zero Trust 구매에 대해 유료 애드온으로 제공됩니다. 현재 무료 버전은 없습니다.

## Log Explorer 요금은 어떻게 청구되나요?

Log Explorer 요금은 인덱싱되고 저장된 로그의 양을 기가바이트(GB) 단위로 측정하여 산정됩니다. 요금은 Log Explorer에 유지하기로 선택한 로그 데이터 양에 따라 증가합니다. BigQuery와 같은 쿼리 기반 과금 모델과 달리, 요금은 데이터를 얼마나 자주 검색하거나 스캔하는지에 기반하지 않습니다. 로그가 수집되고 저장된 뒤에는 추가 비용 없이 쿼리할 수 있습니다.

## 공격 트래픽의 로그도 Log Explorer 사용량에 포함되나요?

예. 일반적으로 Log Explorer는 공격 트래픽을 포함해 수집되고 저장된 전체 로그 볼륨을 기준으로 과금합니다. 이러한 로그는 보안 사고 조사에 중요한 경우가 많으므로 다른 모든 로그 데이터와 동일하게 처리됩니다.

하지만 Layer 7(L7) DDoS 공격 트래픽에서 생성된 로그는 기본적으로 수집되지 않으므로 Log Explorer 사용량에 포함되지 않습니다.

## Log Explorer는 R2에 데이터를 어떻게 저장하며, 왜 내 R2 버킷에서는 보이지 않나요?

Log Explorer는 내부적으로 Cloudflare Logpush와 R2를 사용해 로그를 스트리밍하고 저장합니다. 기술적 및 성능상의 이유로 데이터는 Cloudflare가 관리하는 내부 고객별 R2 버킷에 저장됩니다. 이 버킷은 데이터를 격리하기 위한 싱글 테넌트 방식이지만, 계정의 R2 인터페이스에서는 보이지 않습니다. 이 스토리지에 대해 별도로 청구되지는 않으며 Log Explorer 사용량에 포함됩니다.

## Custom Dashboards는 R2 Log Explorer 데이터를 기반으로 하나요, 아니면 GraphQL을 기반으로 하나요?

현재 Custom Dashboards는 [GraphQL](/analytics/graphql-api/sampling/)에서 실행됩니다. 시간이 지나면서 로그에서 직접 차트를 구축하는 기능과 같이 두 기능 간의 더 깊은 통합이 포함되도록 발전할 예정입니다.

## Log Explorer 사용량은 어떻게 추적할 수 있나요?

월별 사용량은 Log Explorer 내의 Log Search 및 Manage Datasets 대시보드 섹션 상단에 표시됩니다.

![대시보드의 사용량 표시](~/assets/images/log-explorer/log-explorer-usage.png)

## Log Explorer를 어떻게 끄나요?

Log Explorer를 끄려면 다음을 수행해야 합니다.

1. **추가 요금 발생을 즉시 중단하려면 로그 수집을 중지합니다.** 로그 수집을 중지하려면 계정 수준과 영역 수준에서 활성화된 데이터세트를 모두 비활성화하세요.
2. **갱신을 중지하려면 Log Explorer 구독을 취소합니다.** 구독은 현재 청구 주기가 끝날 때까지 활성 상태로 유지될 수 있습니다.

### 1. 로그 수집 중지

다음 단계를 수행하면 즉시 Log Explorer에 대한 추가 요금 발생이 중단됩니다.

#### 계정 수준 데이터세트 검토 및 비활성화

1. Cloudflare 대시보드에서 계정 수준 **Manage datasets** 페이지로 이동합니다.

   <DashButton url="/?to=/:account/log-explorer/manage-sources" />

2. 더 이상 필요하지 않은 각 데이터세트를 토글로 끕니다. 각 작업을 확인하려면 **Stop ingesting logs**를 선택합니다.

#### 영역 수준 데이터세트 검토 및 비활성화

1. Cloudflare 대시보드에서 영역 수준 **Manage datasets** 페이지로 이동합니다.

   <DashButton url="/?to=/:account/:zone/log-explorer/manage-sources" />

2. 더 이상 필요하지 않은 각 데이터세트를 토글로 끕니다. 각 작업을 확인하려면 **Stop ingesting logs**를 선택합니다.

3. 관련된 모든 영역에 대해 반복합니다.

### 2. Log Explorer 구독 취소

이 작업은 Log Explorer의 갱신을 중지합니다.

1. Cloudflare 대시보드에서 **Billing** 페이지로 이동합니다.

   <DashButton url="/?to=/:account/billing" />

2. **Subscriptions** 탭에서 Log Explorer 구독을 찾아 **Cancel**을 선택합니다.
