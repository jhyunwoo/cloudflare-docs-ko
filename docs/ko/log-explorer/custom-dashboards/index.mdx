맞춤형 대시보드를 사용하면 애플리케이션 보안, 성능, 사용량을 모니터링하기 위한 목적에 맞는 대시보드를 만들 수 있습니다. 이전 사고에 대한 지속적인 모니터링을 위해 모니터를 생성하고, 수상한 활동의 지표를 식별하는 데 활용하며, 시작을 돕는 템플릿에 액세스할 수 있습니다.

:::note
Enterprise 고객은 최대 100개의 대시보드를 생성할 수 있습니다.

Pro 및 Business 플랜 고객은 최대 5개의 대시보드를 생성할 수 있습니다.
:::

대시보드는 주요 메트릭과 분석을 표시하는 시각적 인터페이스를 제공하여 데이터를 효율적으로 모니터링하고 분석할 수 있도록 돕습니다. 서로 다른 대시보드는 서로 다른 목적에 사용됩니다. 예를 들어 보안 대시보드는 공격 시도와 위협을 추적하고, 성능 대시보드는 API 지연 시간과 가동 시간을 모니터링하며, 사용량 대시보드는 트래픽 패턴과 사용자 행동을 분석합니다.

서로 다른 메트릭은 애플리케이션 성능에 대한 인사이트를 제공하는 데 각기 다른 역할을 합니다. 예를 들어 총 HTTP 요청 수는 트래픽 볼륨의 개요를 제공하고, 평균 응답 시간은 애플리케이션 속도를 평가하는 데 도움이 됩니다. 여기에 더해 트래픽 패턴과 사용자 행동 같은 사용량 메트릭은 사용자가 애플리케이션과 어떻게 상호작용하는지에 대한 인사이트를 제공합니다. 이러한 메트릭을 함께 사용하면 추세를 포착하고, 문제를 식별하며, 데이터를 바탕으로 한 합리적인 결정을 내릴 수 있습니다.

## 새 대시보드 만들기

새 대시보드를 만들려면 **Log Explorer** > **Dashboards** 페이지로 이동합니다.

   <DashButton url="/?to=/:account/log-explorer/dashboards" />

대시보드를 만들 때는 두 가지 옵션이 있습니다. 처음부터 직접 만드는 방법과 미리 설계된 템플릿을 사용하는 방법입니다.

- **템플릿**은 자주 사용되는 메트릭과 차트가 포함된 대시보드를 더 빠르게 설정할 수 있는 방법을 제공합니다. 보안 위협, API 성능, 봇 트래픽 모니터링처럼 표준적인 사용 사례에 유용합니다. 템플릿을 사용하면 빠르게 시작할 수 있으면서도 요구 사항에 맞게 수정할 수 있습니다.
- 반면 **처음부터 만드는 대시보드**는 구조를 완전히 제어할 수 있어, 필요에 맞는 정확한 데이터세트, 메트릭, 시각화를 선택할 수 있습니다. 이 접근 방식은 구체적인 모니터링 목표가 있거나 데이터를 매우 세밀하게 맞춤형으로 보고 싶을 때 적합합니다.

어떤 옵션을 선택할지는 미리 정의된 인사이트로 빠르게 설정해야 하는지, 아니면 고유한 분석 요구 사항에 맞는 완전한 맞춤형 대시보드가 필요한지에 따라 달라집니다.

### 처음부터 대시보드 만들기

처음부터 대시보드를 만들 때는 **Create new** 옵션을 선택합니다. 다음 섹션의 지침에 따라 대시보드에 차트를 추가하기 시작할 수 있습니다.

#### 새 차트 만들기

새 차트를 만들려면 **Add chart**를 선택합니다. 차트를 만드는 방법은 두 가지입니다.

- **프롬프트 사용**: `Compare status code ranges over time.` 같은 쿼리를 입력합니다. AI 모델이 가장 적절한 시각화를 결정하고 차트 구성을 생성합니다.
- **차트 사용자 지정**: 차트 유형, 제목, 쿼리할 데이터세트, 메트릭, 필터를 포함한 차트 요소를 수동으로 선택합니다. 이 옵션을 사용하면 차트 구조를 완전히 제어할 수 있습니다.

사용 가능한 차트, 데이터세트, 필드, 메트릭, 필터에 대한 자세한 내용은 다음 섹션을 참고하세요.

##### 차트 유형

사용할 수 있는 차트 유형은 다음과 같습니다.

- **시계열**: 시간에 따른 추세를 표시하여 여러 시리즈를 비교할 수 있게 합니다.
- **범주형**: 서로 다른 시리즈 간 비율을 비교합니다.
- **통계**: 단일 값을 강조하고 델타와 스파크라인을 표시해 빠른 인사이트를 제공합니다.
- **백분율**: 하나의 값을 다른 값에 대한 백분율로 나타냅니다.
- **Top N**: 특정 속성에 대해 가장 높은 순위의 값을 식별합니다.

##### 데이터세트와 메트릭

사용할 데이터세트에 따라 사용할 수 있는 메트릭과 필터가 달라집니다. 예를 들어 HTTP Requests 데이터세트를 사용하는 경우 메트릭으로 **origin response duration**을 선택할 수 있습니다. 그런 다음 해당 메트릭에 대해 총합, 중앙값, 분위수와 같은 원하는 집계 방법을 선택할 수 있습니다. 다음 표는 데이터세트, 필드, 사용 가능한 메트릭을 정리한 것입니다.


| 데이터세트 | 필드 | 정의 | 메트릭 |
|-----------------|-----------------|------------|---------|
| HTTP Requests | Requests | HTTP 프로토콜을 통해 클라이언트가 서버로 보낸 요청 수입니다. | Total |
| | DNS Response Time | DNS 쿼리가 해결되는 데 걸린 시간으로, 요청이 이루어진 시점부터 응답을 받은 시점까지를 측정합니다. | Total, Average, Median, 95th percentile, 99th percentile |
| | Time to First Byte | 요청이 이루어진 시점부터 서버가 응답의 첫 번째 바이트를 반환할 때까지의 시간입니다. | Total, Average, Median, 95th percentile, 99th percentile |
| | Bytes returned to the Client | 요청에 대한 응답으로 서버가 클라이언트에 전송한 데이터 양(바이트)입니다. | Total, Average, Median, 95th percentile, 99th percentile |
| | Number of visits | 웹사이트 또는 애플리케이션에 대한 고유 방문 또는 세션 수입니다. | Total |
| | Origin response duration | 오리진 서버가 요청을 처리하고 응답하는 데 걸린 시간입니다. | Total, Average, Median, 95th percentile, 99th percentile |
| Security Events | Security events | WAF 및 Bot Management와 같은 애플리케이션 보안 제품이 수행한 작업입니다. | Total |

##### 필터

필터 조건을 입력하여 분석 범위를 조정할 수도 있습니다. 이를 통해 가장 관련성이 높은 데이터에 집중할 수 있습니다.

1. **Add filter**를 선택합니다.
2. **field**, **operator**, **value**를 선택합니다. 예를 들어 소스 IP 주소로 이벤트를 필터링하려면 _Source IP_ 필드를 선택하고 _equals_ 연산자를 선택한 뒤 IP 주소를 입력합니다.
3. **Apply**를 선택합니다.

### 템플릿으로 대시보드 만들기

또는 미리 설계된 대시보드 템플릿을 사용해 대시보드를 만들 수도 있습니다. 사용할 수 있는 템플릿은 다음과 같습니다.

- **Bot monitoring**: 웹사이트에 접근하는 자동화된 트래픽을 식별할 수 있습니다.
- **API Security**: 애플리케이션의 API 엔드포인트에 대한 데이터 전송과 예외를 모니터링할 수 있습니다.
- **Account takeover**: 로그인 시도, 유출된 자격 증명 사용, 계정 탈취 공격을 모니터링할 수 있습니다.
- **API Performance**: 애플리케이션의 API 엔드포인트에 대한 타이밍 데이터와 오류율을 볼 수 있습니다.
- **Performance monitoring**: 오리진 서버에서 느린 호스트와 경로를 식별하고, 시간 경과에 따른 time to first byte 메트릭을 볼 수 있습니다.

템플릿 중 하나를 선택한 다음 **Use template**를 선택합니다.

## 대시보드 또는 차트 편집

대시보드를 만든 후 저장된 대시보드를 보려면 **Back to all dashboards**를 선택해 전체 목록에 액세스합니다. 대시보드를 어떤 방식으로 만들었든, 기존 차트를 언제든 편집하고 필요에 따라 새 차트를 추가할 수 있습니다.

## 추가 분석

각 차트에 대해 다음 작업을 수행할 수 있습니다.

- [Security Analytics](/waf/analytics/security-analytics/)에서 관련 트래픽을 검토합니다.
- [Log Search](/log-explorer/log-search/)에서 상세 로그를 탐색합니다.

이렇게 하면 애플리케이션의 보안, 성능, 사용 패턴에 대해 더 깊이 있는 인사이트를 확보할 수 있습니다.
