Cloudflare는 브라우저 렌더링을 통해 만든 모든 요청에 헤더를 자동으로 부착합니다. 이 헤더는 Cloudflare에서 이러한 요청이 온지 확인하기 위해 대상 서버를 쉽게 만듭니다.

## 사용자 중심

기본적으로 User-Agent는 Browser Rendering에 액세스하는 방법에 따라 다릅니다.

| 제품 설명                                                   | 기본 User-Agent                                                                                                     |
| ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| [REST API를](/browser-rendering/rest-api/)               | `Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/119.0.0.0 Safari/537.36` |
| [크롤 엔드포인트](/browser-rendering/rest-api/crawl-endpoint/) | `CloudflareBrowserRenderingCrawler/1.0`                                                                           |
| [Workers 회사 소개](/browser-rendering/workers-bindings/)   | Chrome 버전의 기본 User-Agent                                                                                          |

:::참조
REST API 및 Workers Bindings User-Agent 문자열의 Chrome 버전은 브라우저 렌더링 업데이트로 변경할 수 있습니다. 특정 버전 번호에 의존하지 마십시오.
주요 특징

아래 나열된 헤더와 달리, User-Agent는 사용자 정의할 수 있습니다.`userAgent`당신의 모수[REST API를](/browser-rendering/rest-api/)요청 또는 귀하의[Workers 회사 소개](/browser-rendering/workers-bindings/)구성. User-Agent는 구성이 가능하기 때문에, 대상 서버는 사용자가 사용 중인 문자열에 의존하지 않고 브라우저 렌더링 요청을 식별하기 위해 아래 헤더를 사용해야 합니다.

## 비 구성 헤더

:::참조
뒤에 오는 우두머리는 투명성을 지키고 제거되거나 overridden (에`setExtraHTTPHeaders`예를 들어).
주요 특징

| 기타 제품                         | 이름 \*                                                                                                                   |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `cf-brapi-request-id`         | 브라우저 렌더링 요청의 고유 식별자[REST API를](/browser-rendering/rest-api/)                                                            |
| `cf-brapi-devtools`           | 브라우저 렌더링 요청의 고유 식별자[Workers 회사 소개](/browser-rendering/workers-bindings/)                                                |
| `cf-biso-devtools`            | Cloudflare의 렌더링 인프라에서 시작된 요청을 나타내는 플래그                                                                                  |
| `Signature-agent`             | [봇 공개 키의 위치](https://web-bot-auth.cloudflare-browser-rendering-085.workers.dev)요청을 서명하고 Cloudflare에서 온 확인하는 데 사용되는      |
| `Signature`·`Signature-input` | 디지털 서명, 유효한 요청에 사용, 에 표시된 것과 같이[이 건축 문서](https://datatracker.ietf.org/doc/html/draft-meunier-web-bot-auth-architecture) |

### 웹 봇 Auth 소개

더 보기`Signature`헤더는 인증 방법을 사용합니다.[웹 봇 Auth](/bots/reference/bot-verification/web-bot-auth/). Web Bot Auth는 HTTP 메시지의 암호화 서명을 활용하여 자동화된 봇에서 요청이 제공된다는 것을 확인합니다. Cloudflare 브라우저 렌더링에서 시작된 요청을 확인하려면, 키가 발견된 것을 사용합니다.[이 디렉토리](https://web-bot-auth.cloudflare-browser-rendering-085.workers.dev/.well-known/http-message-signatures-directory)확인하기`Signature`·`Signature-Input`수신 요청에서 헤더에서 발견. 성공적인 검증은 Cloudflare 브라우저 렌더링에서 시작된 요청을 증명하고 transit에 탬퍼되지 않았습니다.

### Bot 탐지

Browser Rendering의 봇 탐지 ID는`128292352`. 자신의 영역을 스캔하려고 시도하고 봇 보호 구성 간섭없이 웹 사이트에 액세스하려면 브라우저 렌더링을 원하면 WAF Skip 규칙을 만들 수 있습니다.[Allowlist 브라우저 렌더링](/browser-rendering/faq/#how-do-i-allowlist-browser-rendering).
