이 페이지는 구성에 대한 일반적인 지도를 제공합니다.`robots.txt`브라우저 렌더링에 액세스 할 계획 웹 사이트 맵.

## Identifying Browser 렌더링 요청

요청은 확인할 수 있습니다.[자동적인 headers](/browser-rendering/reference/automatic-request-headers/)Cloudflare는 붙듭니다:

- `cf-brapi-request-id`— REST API 요청에 대한 고유 식별자
- `Signature-agent`— Cloudflare의 봇 검증 키에 포인터

브라우저 렌더링에는 봇 감지 ID가 있습니다.`128292352`. 이것을 사용하여 브라우저 렌더링 트래픽을 허용하거나 차단하는 WAF 규칙을 만듭니다. 기본 사용자 에이전트 및 기타 식별 정보를 위해, 참조[자동 요청 헤더](/browser-rendering/reference/automatic-request-headers/).

## robots.txt에 대한 모범 사례

잘 구성`robots.txt`해당 이용 후기에 달린 코멘트가 없습니다.

### 사이트 맵

참고 자료를 사이트에 포함`robots.txt`그래서 크롤러는 당신의 URL을 발견할 수 있습니다:

```txt title="robots.txt"
User-agent: *
Allow: /

Sitemap: https://example.com/sitemap.xml
```

여러 사이트 맵을 나열 할 수 있습니다:

```txt title="robots.txt"
User-agent: *
Allow: /

Sitemap: https://example.com/sitemap.xml
Sitemap: https://example.com/blog-sitemap.xml
```

### 크롤 지연 설정

제품 정보`crawl-delay`서버에서 자주 크롤러 요청 페이지를 제어하려면:

```txt title="robots.txt"
User-agent: *
Crawl-delay: 2
Allow: /

Sitemap: https://example.com/sitemap.xml
```

값은 초입니다. ·`crawl-delay`2의 크롤러는 요청 사이에 2 초를 기다립니다.

## 사이트 맵에 대한 모범 사례

사이트를 효율적으로 처리하는 데 도움이되는 사이트 맵을 구성:

```xml title="sitemap.xml"
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://example.com/important-page</loc>
    <lastmod>2025-01-15T00:00:00+00:00</lastmod>
    <priority>1.0</priority>
  </url>
  <url>
    <loc>https://example.com/other-page</loc>
    <lastmod>2025-01-10T00:00:00+00:00</lastmod>
    <priority>0.5</priority>
  </url>
</urlset>
```

| 사이트 맵        | 제품정보              | Recommend                                               |
| ------------ | ----------------- | ------------------------------------------------------- |
| `<loc>`      | 페이지의 URL          | 견적 요청 전체 URL을 사용하십시오.                                   |
| `<lastmod>`  | 마지막 수정일           | 크롤러가 업데이트 된 콘텐츠를 식별하는 데 도움이됩니다. ISO 8601 체재를 사용하십시오.    |
| `<priority>` | 상대적 중요성 (0.0-1.0) | 중요한 페이지에 더 높은 값을 설정합니다. 크롤러는 우선순위 순서에 있는 페이지를 가공할 것입니다. |

### 사이트 맵

다수 사이트 맵을 가진 큰 위치를 위해, sitemap 색인 파일을 사용하십시오. 브라우저 렌더링 사용`depth`배열 된 사이트 맵의 많은 수준을 제어하는 매개 변수는 다음과 같습니다 :

```xml title="sitemap.xml"
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  ...
</urlset>
<sitemapindex xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
   <sitemap>
      <loc>https://www.example.com/sitemap-products.xml</loc>
   </sitemap>
   <sitemap>
      <loc>https://www.example.com/sitemap-blog.xml</loc>
   </sitemap>
</sitemapindex>
```

### 캐싱 헤더

Browser Rendering periodically refetches sitemaps 에 유지 내용 신선한. 사이트맵`Last-Modified`또는`ETag`응답 헤더 그래서 크롤러는 사이트 맵이 마지막 fetch 이후 변경 될 수 있습니다.

### Recommend

- 이름 \*`<lastmod>`모든 URL에서 페이지가 변경되었는지 확인합니다. ISO 8601 체재를 사용하십시오 (예를 들면,`2025-01-15T00:00:00+00:00`).
- 사이트 맵 인덱스 파일을 여러 사이트 맵으로 사용합니다.
- 큰 사이트 맵을 압축`.gz`대역폭을 줄이기 위한 형식.
- 파일 당 50 MB 및 50,000 URL의 사이트 맵을 유지 (표준 사이트 맵 제한).
