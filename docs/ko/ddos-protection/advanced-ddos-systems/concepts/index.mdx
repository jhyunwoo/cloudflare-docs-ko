## 연락처

고급 DDoS 보호는 정교한 DDoS 공격에서 선택한 IP 접두사를 보호합니다. 접두사는 IP 주소 또는 CIDR 형식의 IP 범위 일 수 있습니다. 고급 DDoS 보호에 접두사를 추가해야 하므로 Cloudflare는 수신을 분석할 수 있습니다.<GlossaryTooltip term="data packet">제품정보</GlossaryTooltip>정교한 TCP DDoS 공격에 대한 보호를 제공합니다.

고급 DDoS 보호에 추가 된 접두사는 다음과 같습니다.

- 연락처[Magic Transit에 내장](/magic-transit/how-to/advertise-prefixes/).
- 접두사의 subset[Magic Transit에 내장](/magic-transit/how-to/advertise-prefixes/).

Magic Transit 또는 그 상태가 여전히 표시되지 않은 프리픽 (또는 접두사의 하위 집합)을 추가 할 수 없습니다*계정 관리*. 계정 팀에 연락하여 prefix 승인에 도움을 받으십시오.

## 회사 소개

고급 DDoS 보호 수당은 모든 구성 된 고급 DDoS 보호 규칙을 우회 할 수있는 접두사 목록입니다.

예를 들어, 회사 파트너에 의해 사용 된 접두사를 추가 할 수 있으므로 고급 DDoS 보호에 의해 수행 된 패킷 검사 및 완화 작업에서 면제됩니다.

## 【특전】

규칙은 주어진 고급 DDoS 보호를 구성합니다.[제품정보](/ddos-protection/advanced-ddos-systems/concepts/#scope), 몇몇에 따라[제품정보](/ddos-protection/advanced-ddos-systems/concepts/#rule-settings): 실행 모드, 파열 감도 및 속도 감도.

각 시스템 구성 요소 (SYN 홍수 보호 및 out-of-state TCP 보호) 규칙의 자체 목록이 있으며 적어도 하나의 규칙이 있어야합니다.

### 규칙 설정

각 규칙 유형에는 뒤에 오는 조정이 있습니다: 범위, 형태, 파열 감도 및 비율 감도.

특정 트래픽 패턴으로 인해 거짓 긍정적 또는 규칙의 파열 또는 비율 감도를 조정할 필요가 있습니다.

#### 관련 상품

고급 TCP 보호 규칙은 뒤에 오는 범위의 하나가 있을 수 있습니다:

- **주요사업**: 규칙은 모든 들어오는 패킷에 적용됩니다.
- **(주)**: 규칙은 선택한 지역에 들어오는 패킷에 적용됩니다.
- **데이터 센터**: 규칙은 선택한 Cloudflare 데이터 센터의 수신 패킷에 적용됩니다.

규칙 범위는 당신이 평소보다 더 또는 더 적은 교통이있을 수 있는 위치에 있는 out-of-state 소포를 위한 체계의 포용력을 조정할 수 있습니다, 또는 다른 네트워킹 이유 때문에.

위의 범위 중 하나에 대한 정의 규칙 외에도, 당신은 또한 선택해야합니다[연락처](/ddos-protection/advanced-ddos-systems/concepts/#prefixes)고급 TCP 보호로 보호하고자 합니다.

#### 주요 특징

고급 TCP 보호 시스템은 끊임없이 DDoS 공격을 완화하는 TCP 연결을 배웁니다. 고급 TCP 보호 규칙은 다음 실행 모드 중 하나를 가질 수 있습니다 : 모니터링, 완화 (사용), 또는 비활성화.

- **관련 기사**
  - 이 모드에서 고급 TCP 보호는 패킷에 영향을 미치지 않습니다. 대신, 보호 시스템은 합법적 인 TCP 연결을 배우게되며 mitigated 것이 무엇인지 보여줍니다. Network Analytics를 확인하여 현재 구성에 따라 들어오는 패킷에 대해 고급 TCP 보호 기능을 시각화 할 수 있습니다.<Render file="log-and-monitor-behavior-link" product="ddos-protection" />

- **청구 (Enabled)**
  - 이 모드에서 고급 TCP 보호는 합법적 인 TCP 연결을 배우고 규칙 구성 (burst 및 Rate 감도)을 기반으로 TCP DDoS 공격에 대한 완화 조치를 수행 할 것입니다.[관련 상품](/ddos-protection/advanced-ddos-systems/concepts/#allowlist).

- **지원하다**
  - 이 모드에서는 규칙이 들어오는 패킷을 평가하지 않습니다.

#### Burst 감도

파열 감도는 패킷 비율에 있는 단기 파열에 규칙의 감도입니다:

- 낮은 감도는 패킷 비율에 더 큰 스파이크가 완화 작업을 유발할 수 있음을 의미합니다.
- 높은 감도는 패킷 비율에 더 작은 스파이크가 완화 작업을 유발할 수 있음을 의미합니다.

기본 파열 감도는*한국어*.

#### 비율 감도

비율 감도는 지속적인 소포 비율에 규칙의 감도입니다:

- 낮은 감도는 더 높은 지속적인 소포 비율이 완화 작용을 유발할 수 있다는 것을 의미합니다.
- 높은 감도는 더 낮은 지속적인 소포 비율이 완화 활동을 유발할 수 있다는 것을 의미합니다. 높은 감도는 증가된 보호를 제안합니다, 그러나 당신은 더 거짓 긍정을 얻을지도 모릅니다 (그것은, 합법적인 교통에 속한 양).

기본 비율 감도는 입니다*한국어*.

#### 단면도 감도

:::참조
단면도 감도는 유효합니다[고급 DNS 보호](/ddos-protection/advanced-ddos-systems/overview/advanced-dns-protection/)이름 \*
주요 특징

최근 본 적이 없는 DNS 쿼리에 대한 감도.

- 더 높은 감도 수준은 완화 체계가 더 빨리 mitigating 시작할 것이라는 것을 의미합니다.
- 낮은 감도는 잠재적으로 의심스러운 DNS 쿼리에 대한 더 많은 공차를 제공합니다.

기본 프로파일 감도 및 권장 설정은*이름 \**. 관찰된 공격에 따라 필요한 경우에만 감도를 증가해야 합니다.

## 제품정보

필터 표현은 참고 자료 소스 및 대상 IP 주소 및 포트를 할 수 있습니다. 각 시스템 구성 요소 (SYN 홍수 보호 및 out-of-state TCP 보호) 하나 이상의[【특전】](#rule), 그러나 여과기는 선택적입니다.

각 시스템 구성 요소에는 자체 필터가 있습니다. 각 실행 모드의 필터를 구성할 수 있습니다:

- **Mitigation 필터**: 시스템은 필터 표현과 일치하는 패킷을 드롭합니다.
- **감시 필터**: 시스템은 필터 표현과 일치하는 패킷을 기록합니다.
- **필터 해제**: 시스템은 필터 표현과 일치하는 패킷을 무시합니다.

일치 할 때 필터는 주어진 시스템 구성 요소 (SYN 홍수 보호 또는 정전 TCP 보호)의 모든 구성 규칙에 대한 실행 모드를 변경합니다.

'Cloudflare 대시보드\`에 필터를 생성하는 방법에 대한 지침은 참조[필터 만들기](/ddos-protection/advanced-ddos-systems/how-to/create-filter/). API 예제의 경우, 참조[Common API 호출](/ddos-protection/advanced-ddos-systems/api/tcp-protection/examples/).

### 예제 사용 사례

새 접두사를 위한 모니터 필터를 만들 수 있습니다. 접두사와 일치하기 위해 표현을 사용하여 내장되어 있습니다.

이미 내장된 접두사는 소송 모드에서 하나 이상의 구성 규칙으로 보호될 수 있습니다.

새로운 접두사를 내장할 때, 이 접두사에 대한 모니터링 필터를 구성하고 고급 TCP 보호에 추가합니다.

## 실행 모드 정의

규칙과 필터 구성을 모두 가질 때, 실행 모드는 다음과 같이 결정됩니다.

1. 구성 필터 중 하나에 대한 일치가 있다면 필터의 실행 모드를 사용하십시오. 필터 평가 순서는 다음 순서에서 그들의 형태에 근거를 둡니다:
   1. Mitigation filter (필터와 함께`enabled`모드)
   2. 모니터링 필터 (filter with`monitoring`모드)
   3. 필터 해제 (filter with`disabled`모드)
2. 필터가 일치하지 않으면 기존 규칙에 의해 결정된 실행 모드를 사용하십시오.
3. 규칙 일치가 없다면 고급 TCP 보호가 비활성화됩니다.

## 법적고지

고급 TCP 보호 시스템은 연결 상태에 따라 다른 이유에 대한 완화 조치를 적용합니다. 더 보기**법적고지**표시된 필드**고급 TCP 보호**탭의[네트워크 Analytics](/analytics/network-analytics/)대시보드는 주어진 패킷이 시스템에 의해 떨어졌다는 이유에 더 많은 정보를 포함합니다.

연결 상태는 다음과 같습니다:

- **- 한국어**: SYN 또는 SYN-ACK 패킷은 새로운 연결을 열려고 전송되었습니다.
- **기타**: 3방향 TCP 핸즈크가 완료되었으며 TCP 연결이 열려 있습니다.
- **관련 상품**: FIN 또는 FIN-ACK 패킷은 연결 닫기를 시도해 보았습니다.
- **【특징】**: 닫은 three-way handhake가 완료되었거나 RST 패킷은 연결을 닫았습니다.

완화 이유는 다음과 같습니다 :

| 레아슨            | 이름 \*                                                               |
| -------------- | ------------------------------------------------------------------- |
| **옵션 정보**      | 패킷은 TCP 연결의 현재 상태를 주어지지 않았기 때문에 떨어졌다.                               |
| **자주 묻는 질문**   | 패킷은 패킷 홍수의 가장 가능성이 있다고 결정했기 때문에 패킷 도전.                              |
| **관련 기사**      | Packet는 해결 된 도전에 속하기 때문에 떨어졌다.                                      |
| **찾을 수 없음**    | 패킷은 기존 TCP 연결의 일부가 아니라 새로운 연결을 설정하지 않습니다.                           |
| **자주 묻는 질문**   | 패킷은 속성 (예를 들어, TCP 플래그 또는 순서 번호)가 기존의 연결에 대한 예상값과 일치하지 않기 때문에 떨어졌다. |
| **Already 닫기** | 패킷은 이미 닫히는 연결에 속하기 때문에 떨어졌다.                                        |

Mitigation은 고급 TCP 보호 구성(rule sensitivities, set allowlists and prefixes)을 기반으로 합니다. 보호 시스템은 인터넷 라우팅의 자연 임의성을 수용하기 위해 아웃-of-state 패킷에 약간의 공차를 제공 할 것입니다.
