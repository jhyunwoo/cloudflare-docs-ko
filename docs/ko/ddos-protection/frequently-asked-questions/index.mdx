## DDoS 공격 이벤트란?

Cloudflare의 DDoS 시스템 감지 및 mitigate 공격, 그들은 드롭, 속도 제한, 또는 도전 (적용) 패킷, DNS 쿼리 또는 HTTP 요청, 공격 유형에 따라.

3개의 주요 DDoS 완화 체계가 있습니다:

1. [DDoS 관리 규정](/ddos-protection/managed-rulesets/)

   ·[Network-layer DDoS 관리 규정](/ddos-protection/managed-rulesets/network/)

   ₢ 킹[HTTP DDoS 관리 규정](/ddos-protection/managed-rulesets/http/)

2. [고급 TCP 보호](/ddos-protection/advanced-ddos-systems/overview/advanced-tcp-protection/)

3. [고급 DNS 보호](/ddos-protection/advanced-ddos-systems/overview/advanced-dns-protection/)

DDoS 관리 규정에는 많은 개별 규칙이 포함되어 있습니다. 각 규칙은 DDoS 공격 트래픽을 식별하는 시스템의 파괴를 제공합니다. DDoS 관리 규정이 공격을 식별할 때, 공격 트래픽과 일치하기 위해 실시간 지문을 생성하고, 그 지문을 사용하여 공격을 완화하는 ephemeral mitigation 규칙을 설치합니다.

공격의 시작 시간은 완화 규칙이 설치 될 때입니다. 공격은 규칙과 일치하는 더 많은 트래픽이 없을 때 끝납니다. 단일 DDoS 공격 이벤트입니다.

DDoS 공격은 시작 시간, 종료 시간 및 다음과 같은 추가 공격 메타 데이터가 있습니다.

- 공격 ID
- 공격 벡터
- 기타 규칙
- 총 바이트 및 패킷
- 공격 대상
- Mitigation 활동

이 정보는 팝업에 사용됩니다.[회사연혁](/analytics/network-analytics/understand/main-dashboard/#executive-summary)본문 바로가기[네트워크 Analytics](/analytics/network-analytics/)‘대시보드’

GraphQL API를 통해 검색할 수 있습니다.`dosdAttackAnalyticsGroups`노드.

현재 DDoS 공격 이벤트의 개념은 단지 존재합니다.[Network-layer DDoS 관리 규정](/ddos-protection/managed-rulesets/network/). 다른 시스템에 대한 개별 패킷, 쿼리 또는 HTTP 요청의 그룹화가 없습니다.

## 'Cloudflare'는 "낮고 느린" DDoS 공격에 대해 어떻게 보호합니까?

·[낮은 및 느린 DDoS 공격](https://www.cloudflare.com/learning/ddos/ddos-low-and-slow-attack/)일반적으로 non-volumetric 공격입니다. 공격자는 HTTP 요청의 낮은 볼륨을 보내고 천천히합니다. 이 유형의 공격은 더 적은 검출 가능하고 천천히 배출 리소스를 목표로합니다.

[인기 카테고리](https://www.cloudflare.com/learning/ddos/ddos-attack-tools/slowloris/)공격자가 설정하는 저와 느린 공격의 유형입니다[TCP 연결](/fundamentals/reference/tcp-connections/)대상 서버에는 종종 HTTP 또는 HTTPS 프로토콜을 사용합니다.

Slowloris 공격의 경우 공격자는 incomplete HTTP 헤더 라인을 보내므로 HTTP 요청을 완료하지 않습니다. 서버는 완전한 요청을 기다립니다. 연결이 열립니다. 공격자는 주기적으로 추가 HTTP 헤더 필드 또는 부분 라인을 보내 연결 살아. 이것은 부분 HTTP 헤더를 보내거나 사용해서 달성될 수 있습니다`content-length`실제로 보낸 것보다 더 큰 메시지 몸 크기를 선언하는 헤더.

낮은 공격에 대 한 방어 하는 가장 좋은 연습은 HTTP 역 프록시를 사용 하 여, 같은 'Cloudflare''[사이트맵](/fundamentals/concepts/how-cloudflare-works/)또는[‘WAF’](/waf/)서비스. 역 프록시는 방패로 작동합니다. 이 웹 사이트는 애플 리케이션에 전념. 우리는 정품 앱과 게임을 제공 할 목적으로이 사이트를 만들었습니다. 4AppsApk 최고의 안드로이드 애플 리케이션을위한 무료 APK 파일 다운로드 서비스, 계략. 요청이 'Cloudflare'에 의해 버퍼링되도록 영역을 구성 할 수 있으므로 낮은 공격과 느린 공격을 흡수합니다. 우리의 프록시는 전달하기 전에 전체 HTTP 요청을 기다립니다. 버퍼링 요청을 활성화하려면[바디 버퍼링](/rules/configuration-rules/settings/#request-body-buffering).

요청은 Cloudflare\`에서 제공됩니다.[캐시](/cache/)또는[작업자](/workers/), 적용 가능한 경우. 그렇지 않다면, 그것은 단지 기원에 보내질 것입니다. - 완전히 완료되고 WAF 체크를 통과했습니다. 그래서 공격은 존재하지 않습니다, TCP Slowloris 공격 보호와 유사.

또한, 역 프록시는 일련의 후 타임 아웃 불완전 HTTP 요청[공급 업체](/fundamentals/reference/tcp-connections/#tcp-connections-and-keepalives).

활성화의 최소 임계값이 없습니다. 그러나, 추가 보안을 제공하기 위해, 사용자 정의 방화벽 규칙은 payload 크기에 대한 체크를 확인하고 내용이 예상되는 것과 같이 보이는 것을 보장하기 위해 기본 위생 검사를 수행합니다.

RUDY (R-U-Dead-Yet?) DDoS 공격은 대상 서버에서 느린 공격을 수행하는 데 대한 denial-of-service (DoS) 도구의 또 다른 유형입니다.

기존의 DDoS 공격과 마찬가지로 짧은 기간 동안의 높은 볼륨으로 압도적 인 서버가 RUDY는 몇 가지 연장 된 요청을 만드는 데 중점을 둡니다. 웹 서버를 묶고 합법적 인 트래픽을 사용할 수 없도록 매우 느린 속도로 양식 데이터를 제출하여이 작업을 수행합니다. 이 접근법은 RUDY 공격을 탐지하기 어렵게 만듭니다. 트래픽이 합법적으로 나타나기 때문에 기존의 DDoS 보호 메커니즘을 유발할 요청이있는 서버를 홍수시키지 않습니다.

RUDY는 웹 서버의 Application layer(Layer 7)를 대상으로 하며, 웹 양식 핸들 데이터 제출을 활용합니다. 공격은 한 바이트의 정보를 애플리케이션으로 주사하여 작동합니다.`POST`한 번에 필드를 기다리고 있습니다. 이 프로세스는 애플리케이션 스레드가 의도적으로 양식 제출 완료를 기다리고 서버의 리소스를 효과적으로 배출하고 합법적 인 요청을 처리하는 것을 방지합니다.

더 알아보기[학습 센터](https://www.cloudflare.com/learning/ddos/ddos-attack-tools/r-u-dead-yet-rudy/)RUDY 공격에 대한 자세한 내용은.

## Cloudflare는 SSL/TLS 협상 공격 또는 홍수로 처리합니까?

SSL/TLS는 BEAST, Poodle 및 CRIME와 같은 공격을 기반으로 한 'Cloudflare'의 TLS 설정, 구성 및 요령 제한에 의해 완화됩니다. Cloudflare는 HTTP 역 프록시로 제공하므로 TLS 배기 스타일 공격은 HTTP 요청을 소스 서버로 전달하기 전에 TLS 세션을 종료하여 조정됩니다. TLS 트래픽은 적절한 TLS Handhake를 완료하지 않고 원래 서버로 예상되지 않습니다. 또한 자동화된 DDoS 탐지 및 완화 시스템은 cipher Suite, 패킷 필드, HTTP 요청 속성 및 메타데이터, 원산지 건강, 트래픽 프로파일링, 기계 학습 모델 및 위협 인텔리전스를 활용하여 추가 SSL 기반 공격을 탐지하고 완화합니다.

## 죽음 DDoS 공격의 Ping은 무엇입니까?

죽음의 Ping (PoD) 공격은 다른 컴퓨터 또는 서버에 malformed 또는 oversize 패킷을 전송하는 것을 포함, 동결, 충돌, 또는 재부팅 시스템에 발생할 수 있습니다. 패킷은 인터넷을 통해 전송되는 데이터의 조각이며, 죽음의 Ping은 IP 프로토콜이 최대 65,535 바이트 크기의 패킷을 필요로하는 사실의 장점을 가지고 있습니다. 이 크기보다 더 큰 패킷을 전송함으로써 공격자는 대상의 TCP / IP 스택에서 취약점을 악화시킬 수 있으며 버퍼 오버플로를 발생시키고 시스템 충돌을 포함한 예측 가능한 행동을 선도합니다. 이 유형의 공격은 일반적인 요즘, 대부분의 현대 시스템 및 네트워킹 장비와 같은 anomalies를 취급하기 위해 패치되었습니다.

## LOIC와 HOIC는 무엇입니까?

LOIC는 인기있는 네트워크 스트레스 테스트 및 DoS 공격 응용 프로그램입니다 TCP, UDP 또는 HTTP 요청으로 서버를 홍수 하는 데 사용 되는 서비스 중단. 그것은 단순하고 최소한의 해킹 경험으로 개인에 의해 사용할 수있는 능력에 대해 알려져있다. LOIC는 사용자가 작은 서버를 공격 할 수 있도록 지시 할 수 있으며 서버가 요청의 과부하에서 느리거나 충돌 할 수 있습니다. 그것은 주요 회사와 조직에 대한 공격에서 해커 그룹 Anonymous에 의해 그것의 사용을 위해 2010 주위에 유명했다.

HOIC는 LOIC의 업그레이드로, 그 제한을 극복하기 위해 설계되었으며, 특히 탐지 및 완화 측면에서. 그것은 사용자가 더 강력한 DoS 공격을 실행할 수 있습니다. 여러 웹 사이트에 공격을 동시에 더 높은 볼륨의 요청. HOIC는 또한 방어 메커니즘을 위해 더 어려운 기능을 통합하여 공격 트래픽을 식별하고 완화하기 위해보다 어려운 기능을 통합하므로 트래픽을 mimic 합법적 인 HTTP 트래픽을 허용하는 기술을 사용하여 전통적인 네트워크 보안 도구에 대한 더 도전입니다. HOIC는 다양한 웹 사이트를 동시에 대상으로 할 수있게 해주는 "booster" 스크립트의 사용을 지원하며 광범위한 DoS 공격을 수행하는 도구로 강력한 힘을 크게 늘리고 있습니다.

이 도구와 공격은 네트워크 프로토콜의 다른 측면을 악화하고 불필요한 트래픽으로 압도적 인 대상에 행동, 서비스의 운명을 선도. 남용의 잠재력으로, 그들의 사용은 테스트 목적으로 통제된 환경의 불법 및 윤리적 외부입니다.

## DDoS 보호는 SYN 홍수 공격이 mitigated지 결정하는 방법`dosd`또는 고급 TCP 보호?

DDoS 공격[관리 규칙](/ddos-protection/managed-rulesets/)공격 패킷과 실시간 지문을 생성하는 사이에 공통성을 발견하여 공격을 감지하고 mitigate 공격합니다.

공격이 매우 무작위로 처리되고 DDoS 관리 규칙은 공격 패킷 중 일반적인 패턴을 감지 할 수 없습니다.[고급 TCP 보호](/ddos-protection/advanced-ddos-systems/overview/advanced-tcp-protection/)stateful TCP flowtracking 기능을 사용하여 패킷이 합법적인지 결정합니다. 고급 TCP 보호는 또한 단순한 TCP 기반 공격을 mitigates.

고급 TCP 보호는 필요와 유효한[매직 트레인](/magic-transit/)고객. 제품 정보[스펙트럼](/spectrum/)그리고 우리의 HTTP 서비스는 역 프록시를 사용하여 정교한 랜딩 TCP 기반 DDoS 공격을 완화합니다.

## "Cloudflare"는 특정 포인트 (PoP)를 압도적으로 압도 할 수있는 하이퍼 로컬 DDoS 공격을 처리합니까?

Hyper-localized DDoS 공격은 봇넷 노드의 특정 PoP 또는 데이터 센터를 대상으로 하는 공격으로 그 위치를 압도적으로 파악하고 정전이나 서비스 중단을 유발합니다.

그러나, 'Cloudflare'의 방어 접근은 이러한 공격에 의존하고 지능 교통 공학, 글로벌 애니캐스트 및 실시간, 자율 DDoS 완화의 조합을 사용하여 하이퍼 로컬 DDoS 공격을 처리 할 수 있습니다 - 일시적으로 Presence (PoP)의 특정 포인트의 용량을 초과 할 수 있습니다.

### Global Anycast 네트워크

Anycast는 동일한 IP 주소를 공유하기 위해 여러 서버 (PoPs)를 허용하고 Border Gateway Protocol (BGP) 라우팅 시스템은 사용자 트래픽이 가장 가까운 가장 낮은 노드로 경로를 보장합니다.

#### 회사연혁

한 PoP는 로컬 DDoS 홍수로 압도되거나 제한된 용량의 결과로 BGP 경로 전파가 PoP에서 멀리 이동 트래픽으로 조정할 수 있습니다. Cloudflare는 특정 피어 또는 업스트림으로부터 BGP 발표를 철회하여 더 나은 PoP를 통해 다시 루트로 이동할 수 있습니다. DDoS 트래픽이 여러 지리적 영역에서 시작되기 때문에 Anycast 및 트래픽 엔지니어링은 공격을 전개합니다.[Cloudflare의 전체 용량 Anycast 네트워크](https://www.cloudflare.com/network/)단일 PoP에 부담을 줄입니다.

### 지능형 교통 공학

Cloudflare는 실시간 데이터 및 인텔리전스 시스템을 사용하여 트래픽 라우팅, 로드 밸런싱 및 혼잡 관리에 대한 결정을 내립니다.

#### 회사연혁

특정 PoP가 포화 또는 경험 공격 트래픽이되면, 'Cloudflare'는 트래픽 쉐이핑, 경로 인식 라우팅 및 동적 DNS 응답을 사용하여 대체 경로의 내부 트래픽 엔지니어링 시스템 동적 스티어링 트래픽입니다.

시스템은 CPU 부하, 네트워크 혼잡 및 트래픽 유형을 모니터링하여 다시 루트 또는 스로틀 연결 여부에 대한 스마트 결정을 내릴 수 있습니다.

Layer 7 (application-level) 공격을 위해, Cloudflare는 애플리케이션 서버에 도달하기 전에 또는 속도 제한 트래픽을 해결할 수 있습니다. 이 시나리오는 유지 보수에 대한 특정 PoP를 취할 때 일부 범위와 유사합니다. 트래픽 관리자를 통해 자동으로 수행 할 수 있으며, 필요한 경우 사이트 신뢰성 엔지니어 (SRE).

### 실시간 DDoS 완화

DDoS 관리 규칙 및 고급 DDoS 보호는 독립적으로 모든 단일 서버에서 자율적이고 실행되며 로컬 및 글로벌 조정을 통해 각 서버와 PoP의 탄력성에 기여합니다. 이 시스템은 모든 PoP에서 네트워크 가장자리에 가까운 실행, 의미 감지 및 완화는 신속하게 발생, 종종 눈에 띄는 충격 전에. 트래픽이 하나의 PoP 용량을 초과하는 경우, 완화 규칙은 다른 PoP로 복제됩니다.

- **DDoS 관리 규정**: 실시간 DDoS 공격을 탐지하고 mitigates합니다. 공격을 감지 할 때, 그것은 몇 초 안에 규칙을 배치하여 악의적인 트래픽을 완화합니다.
- **고급 TCP 보호**: 애플리케이션 서버가 눈에 띄는 TCP/IP 동작을 식별하고 삭제합니다.
- **고급 DNS 보호**: DNS 서버가 눈에 띄는 DNS 쿼리 동작을 식별하고 삭제합니다.

## 고급 TCP 보호의 보호 학습 기능은 무엇입니까?

Protected Learning 기능으로[고급 TCP 보호](/ddos-protection/advanced-ddos-systems/overview/advanced-tcp-protection/)인터넷 routing chaos를 극복하는 시스템은 합법적 인 트래픽을 통해 허용하고 가장자리에서 DDoS 공격 차단.

Anycast 및 BGP는 가장 가까운 가장 최적의 데이터 센터로 인터넷 트래픽을 전송하는 데 도움이되는 프로토콜입니다. Occasional 네트워크 이벤트는 인터넷 라우팅의 유지 보수 또는 변경을 위해 오프라인으로 찍은 데이터 센터와 같은 설치 된 연결이 다른 데이터 센터로 다시 시작 될 수 있습니다.

Cloudflare\`는 Protected Learning으로도 알려진 Flow inference 기능이며, 이를 처리하기 위해 특별히 설계되었습니다. TCP 연결이 흐름과 같은 경우, 새로운 데이터 센터로 이동하면, 우리의 시스템은 로컬 플로우 테이블에 나타나지 않는 기존의 연결입니다. 디도스 공격의 일부일 수 있는 알 수없는 연결으로 흐름을 차단하는 대신, 우리의 시스템은 연결이 합법적 인 경우 확인하는 독점적 인 프로세스를 사용합니다. 그것은 acknowledgment (ACK)의 패킷에 도전하여 DDoS 공격의 일부가 아닙니다. 흐름이 우리의 체크를 통과하면, 우리는 중단없이 계속 할 수 있습니다. DDoS 공격에 대한 네트워크 보호를 유지하면서 트래픽의 합법적 인 이동은 긴 실행 연결을 방해하지 않습니다.
