## 무료, Pro 및 비즈니스 계획

'Cloudflare'가 제공하는 DDoS 공격 보호 관리 규칙은 기본적으로 'Cloudflare', IP 애플리케이션이 Spectrum에 내장되어 있으며, Magic Transit에 내장된 IP Prefixes가 활성화됩니다.

일부 상황에서 DDoS 규정에 의해 제공되는 기본 보호는 특정 상황에 따라 미세 조정 될 수 있습니다. 다른 Cloudflare 제품을 사용하여 추가 보호를 구성 할 수도 있습니다.

### 제공된 DDoS 규칙을 조정

"Cloudflare"가 제공하는 한 개 이상의 DDoS 규칙이 합법적 인 트래픽에 영향을 미치는 경우, 이러한 종류의 트래픽에 대한 완화 조치를 수행하지 않도록 조정할 수 있습니다. 자주 묻는 질문[잘못된 긍정적 인 취급](/ddos-protection/managed-rulesets/http/http-overrides/override-examples/#legitimate-traffic-is-incorrectly-identified-as-an-attack-and-causes-a-false-positive)한 개 이상의 DDoS 규칙의 감도 수준을 감소시키고 합법적 인 트래픽을 수신 할 수 있습니다.

### 추가 보호 구성

DDoS 공격에 대한 추가 보호를 구성하려면 관련 Cloudflare 제품 참조[Network-layer DDoS 공격 보호](/ddos-protection/managed-rulesets/network/#related-cloudflare-products)·[HTTP DDoS 공격 보호](/ddos-protection/managed-rulesets/http/#related-cloudflare-products).

## 기업 계획

Cloudflare의 DDoS 보호 시스템은 자동으로 탐지 및 DDoS 공격을 완화합니다. 또한 시스템은 법적인 응용 프로그램, 인터넷 서비스, 또는 악의적 인 클라이언트 응용 프로그램을 통해 의심의 여지없이 들어오는 트래픽을 유발할 수 있습니다. 트래픽이 합법적 인 경우, 완화 조치는 인터넷 속성의 서비스 중단과 정전을 일으킬 수 있습니다.

이 상황을 방지하기 위해, Cloudflare는 다음 단계를 수행 할 것을 권장합니다.

<Steps>
  1. 모든 규칙 작업을 설정[DDoS 공격 보호 관리 규정](/ddos-protection/managed-rulesets/)으로*로그인*.
  2. 표시된 트래픽을 분석합니다.
  3. 개인 관리 규칙의 감도 또는 행동을 조정, 필요한 경우.
  4. Switch 규칙 작업*로그인*기본값으로 다시.
</Steps>

### 자주 묻는 질문

다음 중 하나가 있어야 합니다:

- [Cloudflare에 내장 된 영역](/dns/zone-setups/full-setup/)그러나 업데이트되지 않은 DNS 레코드.
- [Spectrum에 내장된 IP 애플리케이션](/spectrum/get-started/).
- [Magic Transit에 내장 된 IP 접두사](/magic-transit/get-started/).

### 1. 로그에 규칙 작업을 구성

:::참조

더 보기*로그인*행동은 기업 고객에게만 유효합니다.
주요 특징

<Steps>
  1. [HTTP DDoS 공격 보호에 대한 모든 규칙을 구성](/ddos-protection/managed-rulesets/http/http-overrides/configure-dashboard/#access), 자신의 행동을 설정*로그인*.
  2. [Network-layer DDoS 공격 보호에 대한 모든 규칙을 구성](/ddos-protection/managed-rulesets/network/network-overrides/configure-dashboard/#create-a-ddos-override), 작업 설정*로그인*.

API를 사용하는 경우, 모든 관리 규정 규칙의 동작을 설정하기 위해 규칙 수준에서 override를 정의합니다.`log`이 지침에 따라:

- [HTTP DDoS 공격 보호 관리 규정에 대한 override 구성](/ddos-protection/managed-rulesets/http/http-overrides/configure-api/#configure-an-override-for-the-http-ddos-attack-protection-managed-ruleset)
- [Network-layer DDoS 공격 보호 관리 규정에 대한 override 구성](/ddos-protection/managed-rulesets/network/network-overrides/configure-api/#configure-an-override-for-the-network-layer-ddos-attack-protection-managed-ruleset)

### 2. 검토 표백 트래픽

<Steps>
  1. 로그인[분석 대시보드](/ddos-protection/reference/analytics/)(‘대시보드’는 ‘Cloudflare’ 서비스에 따라 달라집니다.).
  2. 필요한 경우 하나 이상의 필터를 적용하고, 합법적인 트래픽을 차단한 규칙을 확인합니다.*로그인*모드가 비활성화되었습니다. 규칙 ID를 입력합니다.
</Steps>

### 3. 관리된 통치 규칙을 주문을 받아서 만드십시오

'Cloudflare 대시보드\` 또는 API를 사용하여 특정 관리 규칙을 식별하고, 감도 또는 행동을 변경할 수 있습니다.

Cloudflare\`\`대시보드를 사용하는 경우 다음을 참조합니다.

- ['대시보드'에서 HTTP DDoS 공격 보호 구성](/ddos-protection/managed-rulesets/http/http-overrides/configure-dashboard/)
- ['대시보드'의 Network-layer DDoS 공격 보호 구성](/ddos-protection/managed-rulesets/network/network-overrides/configure-dashboard/)

API를 사용하는 경우, 참조:

- [API를 통해 HTTP DDoS 공격 보호 구성](/ddos-protection/managed-rulesets/http/http-overrides/configure-api/)
- [API를 통해 Network-layer DDoS 공격 보호 구성](/ddos-protection/managed-rulesets/network/network-overrides/configure-api/)

API를 사용할 때, 당신은 당신이 설정한 규칙을 제거하지 않고 필요한 규칙을 추가해야[단계 1](#1-configure-ruleset-actions-to-log).

### 4. Switch 규칙은 기본적으로 다시 동작합니다.

당신이 한 변화를 다시[단계 1](#1-configure-ruleset-actions-to-log), 각 관리 규칙의 행동을 다시 변경*기본 정보*내 계정**Ruleset 작업**.

또는 API를 사용하는 경우,[중복 제거](/ddos-protection/managed-rulesets/http/http-overrides/configure-api/#configure-an-override-for-the-http-ddos-attack-protection-managed-ruleset)당신은 이전에 각 관리 규칙에 대한 규칙 수준에 형성. 당신은 단지 규칙을 삭제하고 당신이 구성 할 수있는 규칙의 모든 것이되지 않도록 보장[단계 3](#3-customize-managed-ruleset-rules).
