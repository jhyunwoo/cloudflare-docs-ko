## 제품정보

사용자 정의 공급자는 AI Gateway에서 기본적으로 지원되지 않는 AI 제공 업체를 통합 할 수 있습니다. 이 기능은 AI Gateway의 Observability, 캐싱, 속도 제한 및 HTTPS API 엔드포인트가 있는 모든 AI 공급자와 다른 기능을 사용할 수 있습니다.

## 사용 사례

- **내부 AI 모델**: 조직의 자체 호스팅 AI 모델에 연결
- **지역 공급자**: AI 제공업체와 지역별 통합
- **특수 모델**: 표준 공급자를 통해 도메인 별 AI 서비스를 사용할 수 없습니다
- **주문 endpoints**: 자체 AI 인프라에 대한 경로 요청

## 시작하기 전에

### 자주 묻는 질문

- AI Gateway 액세스와 활성 Cloudflare 계정
- 사용자 정의 AI 공급자의 유효한 API 열쇠
- 공급자의 API를 위한 HTTPS 기본 URL

### 인증현황

API endpoints for create, reading, updating, or deleting custom 제공 업체는 인증이 필요합니다. 적절한 권한을 가진 Cloudflare API 토큰을 만들 필요가 있습니다.

API 토큰을 만들려면:

1. 오시는 길[Cloudflare 대시보드 API 토큰 페이지](https://dash.cloudflare.com/?to=:account/api-tokens)
2. 이름 \***토큰 만들기**
3. 제품정보**주문 토큰**그리고 다음 권한을 추가:
   - `AI Gateway - Edit`
4. 이름 \***자주 묻는 질문**그리고 그때**토큰 만들기**
5. 토큰 복사 - 당신은 그것을 사용할 수 있습니다`Authorization: Bearer $CLOUDFLARE_API_TOKEN`기타 제품

## 사용자 정의 공급자 만들기

<Tabs syncKey="dashPlusAPI">
  <TabItem label="사이트맵">
    API를 사용하여 새로운 사용자 정의 제공 업체 만들기:

    1. 내 계정[계정 ID](/fundamentals/account/find-account-and-zone-ids/)계정 태그.

    2. 이름 \*`POST`새로운 사용자 정의 공급자를 만드는 요청:

    ```bash title="Create Custom Provider"
    curl -X POST "https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/ai-gateway/custom-providers" \
      -H "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
      -H "Content-Type: application/json" \
      -d '{
        "name": "My Custom Provider",
        "slug": "some-provider",
        "base_url": "https://api.myprovider.com",
        "description": "Custom AI provider for internal models",
        "enable": true
      }'
    ```

    **필수 필드:**

    - `name`(string): 공급자를 위한 표시 이름
    - `slug`(문자): 유일한 식별자 (하이픈과 관련). 계정 내에서 고유해야합니다.
    - `base_url`(string): 공급자의 API 엔드포인트를 위한 HTTPS URL. 시작하기`https://`.

    **선택적인 분야:**

    - `description`(string): 공급자의 묘사
    - `link`(string): 공급자 문서에 URL

    - `beta`(불린): beta 특징으로 표 (과태:`false`)
    - `curl_example`(string): 공급자를 사용하는 경우 cURL 명령
    - `js_example`(string): 공급자를 사용하는 JavaScript 부호

## AI Gateway와 사용자 정의 제공

사용자 정의 제공 업체를 만들면 AI Gateway를 통해 요청을 두 가지 접근법 중 하나를 사용하여 처리 할 수 있습니다.**통합 API**또는**공급자 별 endpoint**. 어느 접근을 가진 당신의 주문 공급자를 추천할 때, 당신은 slug를 prefix해야 합니다`custom-`.

:::노트\[사용자 지정]
모든 사용자 정의 공급자 slugs는 prefixed해야합니다`custom-`AI Gateway를 통해 요청할 때. 예를 들어, 공급자가 slug가 있다면`some-provider`, 당신은 사용해야 합니다`custom-some-provider`귀하의 요청에.
주요 특징

### URL 라우팅 작동 방법

AI Gateway가 사용자 정의 공급자에 대한 요청을 받으면 공급자의 구성을 결합하여 상류 URL을 구성합니다.`base_url`후 오는 길`custom-{slug}/`게이트웨이 URL에서.

**더 보기`base_url`필드는 root 도메인만 포함해야 합니다.**(또는 제공자의 API의 고정 접두사를 가진 도메인). 모든 API 별 경로 세그먼트 (likes`/v1/chat/completions`) 요청 URL에서 이동, 하지에서`base_url`.

공식은:

```
Gateway URL:   https://gateway.ai.cloudflare.com/v1/{account_id}/{gateway_id}/custom-{slug}/{provider-path}
Upstream URL:  {base_url}/{provider-path}
```

후에 모든 것`custom-{slug}/`요청 URL에 직접 추가됩니다.`base_url`최종 업스트림 URL을 입력합니다. 이 수단`{provider-path}`여러 경로 세그먼트, 쿼리 매개 변수 또는 어떤 경로 구조를 포함할 수 있습니다.

### Unified API와 공급자별 endpoint 사이 선택

|                  | 통합된 API (`/compat`)                    | 공급자 별 endpoint                 |
| ---------------- | -------------------------------------- | ------------------------------ |
| **제품 정보**        | OpenAI 호환 API를 가진 공급자                  | 모든 API 구조와 공급자                 |
| **요청 형식**        | OpenAI를 따르십시오`/chat/completions`스키마    | 공급자의 기본 요청 형식 사용               |
| **경로 제어**        | 관련 제품`/compat/chat/completions`        | 업스트림 경로에 전체 제어                 |
| **공급자를 지정하는 방법** | `model`유형:`custom-{slug}/{model-name}` | URL 경로:`/custom-{slug}/{path}` |

사용 방법**통합 API**사용자 정의 공급자가 OpenAI 호환을 받으면`/chat/completions`요청 형식. 이것은 가장 간단한 옵션이며 OpenAI SDK와 잘 작동합니다.

사용 방법**공급자 별 endpoint**사용자 정의 공급자가 비표준 API 경로 또는 요청 형식을 사용할 때. 이 URL 경로와 요청 몸이 업스트림 공급자로 보내도록 전체 제어를 제공합니다.

### Unified API를 통해

Unified API는 OpenAI 호환 형식을 사용하여 공급자의 채팅 완료 엔드포인트에 요청을 보냅니다. 형식을 사용하여 모델을 지정`custom-{slug}/{model-name}`.

```bash title="Request using custom provider via Unified API"
curl https://gateway.ai.cloudflare.com/v1/{account_id}/{gateway_id}/compat/chat/completions \
  -H "Authorization: Bearer $PROVIDER_API_KEY" \
  -H "cf-aig-authorization: Bearer $CF_AIG_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "custom-some-provider/model-name",
    "messages": [{"role": "user", "content": "Hello!"}]
  }'
```

### 공급 업체 별 endpoint

공급자 별 엔드포인트는 업스트림 경로에 전체 컨트롤을 제공합니다. 후에 모든 것`custom-{slug}/`URL에 부과됩니다`base_url`.

```bash title="Direct provider endpoint"
curl https://gateway.ai.cloudflare.com/v1/{account_id}/{gateway_id}/custom-some-provider/v1/chat/completions \
  -H "Authorization: Bearer $PROVIDER_API_KEY" \
  -H "cf-aig-authorization: Bearer $CF_AIG_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "model-name",
    "messages": [{"role": "user", "content": "Hello!"}]
  }'
```

이름 \*`base_url`이름 \*`https://api.myprovider.com`, 이 요구는 proxied 입니다:`https://api.myprovider.com/v1/chat/completions`

### 이름 \*

다음 예제는 구성하는 방법을 보여줍니다`base_url`다른 유형의 공급자를 위한 요청 URL을 건설하십시오.

#### 예제 1 : OpenAI 호환 공급자 (표준`/v1/`경로)

많은 공급자는 API를 호스팅하는 OpenAI 협약을 따릅니다`{domain}/v1/chat/completions`.

**구성:**

- `slug`: `my-openai-compat`
- `base_url`: `https://api.example-provider.com`

**공급자 별점:**

```bash
curl https://gateway.ai.cloudflare.com/v1/{account_id}/{gateway_id}/custom-my-openai-compat/v1/chat/completions \
  -H "Authorization: Bearer $PROVIDER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "example-model",
    "messages": [{"role": "user", "content": "Hello!"}]
  }'
```

**URL 매핑:**

| 회사연혁       | 제품정보                                                                                                         |
| ---------- | ------------------------------------------------------------------------------------------------------------ |
| 게이트웨이 URL  | `https://gateway.ai.cloudflare.com/v1/{account_id}/{gateway_id}/custom-my-openai-compat/v1/chat/completions` |
| `base_url` | `https://api.example-provider.com`                                                                           |
| 공급자 경로     | `/v1/chat/completions`                                                                                       |
| 업스트림 URL   | `https://api.example-provider.com/v1/chat/completions`                                                       |

이 공급자가 OpenAI-compatible이기 때문에, 당신은 또한 Unified API를 사용할 수 있었습니다:

```bash
curl https://gateway.ai.cloudflare.com/v1/{account_id}/{gateway_id}/compat/chat/completions \
  -H "Authorization: Bearer $PROVIDER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "custom-my-openai-compat/example-model",
    "messages": [{"role": "user", "content": "Hello!"}]
  }'
```

#### 예제 4 : 사용자 정의 기본 URL로 OpenAI SDK를 사용하는 공급자

OpenAI SDK를 사용하여 AI Gateway를 통해 사용자 지정 공급자에 연결할 때, SDK를 설정`base_url`Gateway의 공급자 별 엔드포인트 경로(최대 및 API 버전 포함)에 대한 귀하의 공급자가 기대할 것으로 예상됩니다.

**구성:**

- `slug`: `alt-provider`
- `base_url`: `https://api.alt-provider.com`

**Python (OpenAI SDK):**

```python title="Using OpenAI SDK with a custom provider"
from openai import OpenAI

client = OpenAI(
    api_key="your-provider-api-key",
    base_url="https://gateway.ai.cloudflare.com/v1/{account_id}/{gateway_id}/custom-alt-provider/v1",
    default_headers={
        "cf-aig-authorization": "Bearer {cf_aig_token}",
    },
)

#SDK appends /chat/completions 를 base url 에 자동으로 추가합니다.
#최종 상류 URL: https://api.alt-provider.com/v1/chat/completions
response = client.chat.completions.create(
    model="alt-model-v2",
    messages=[{"role": "user", "content": "Hello!"}],
)
```

**URL 매핑:**

| 회사연혁             | 제품정보                                                                                                     |
| ---------------- | -------------------------------------------------------------------------------------------------------- |
| SDK 지원`base_url` | `https://gateway.ai.cloudflare.com/v1/{account_id}/{gateway_id}/custom-alt-provider/v1`                  |
| SDK 추가           | `/chat/completions`                                                                                      |
| 전체 게이트웨이 URL     | `https://gateway.ai.cloudflare.com/v1/{account_id}/{gateway_id}/custom-alt-provider/v1/chat/completions` |
| 회사 소개`base_url`  | `https://api.alt-provider.com`                                                                           |
| 공급자 경로           | `/v1/chat/completions`                                                                                   |
| 업스트림 URL         | `https://api.alt-provider.com/v1/chat/completions`                                                       |

## 일반적인 오류

### 409 Conflict - 중복 슬러그

```json
{
  "success": false,
  "errors": [
    {
      "code": 1003,
      "message": "A custom provider with this slug already exists",
      "path": ["body", "slug"]
    }
  ]
}
```

각 주문 공급자는 당신의 계정 안에 독특해야 합니다. 다른 슬러그를 선택하거나 기존 공급자를 업데이트하십시오.

### 404 발견되지 않음

```json
{
  "success": false,
  "errors": [
    {
      "code": 1004,
      "message": "Custom Provider not found"
    }
  ]
}
```

지정된 공급자 ID가 존재하지 않거나 접근할 수 없습니다. 공급자 ID 및 인증 자격 증명을 검증합니다.

### 400 Bad Request - 잘못된 base url

```json
{
  "success": false,
  "errors": [
    {
      "code": 1002,
      "message": "base_url must be a valid HTTPS URL starting with https://",
      "path": ["body", "base_url"]
    }
  ]
}
```

더 보기`base_url`필드는 유효한 HTTPS URL이어야한다. HTTP URL은 보안상의 이유로 지원되지 않습니다.

### 404 주문 공급자에 요청을 할 때

업스트림 공급자로부터 404를 받으면 가장 일반적인 원인은 잘못된 경로 매핑입니다. 인증:

1. 내 계정`base_url`공급자의 세트**비밀번호**(예:`https://api.provider.com`) API 경로 세그먼트를 포함하여 오히려.
2. 귀하의 요청 URL은 포함**전체 API 경로**후에`custom-{slug}/`. 예를 들어, 업스트림 엔드포인트가 있다면`https://api.provider.com/api/v2/chat`, 귀하의 게이트웨이 URL이 종료되어야 합니다.`/custom-{slug}/api/v2/chat`.
3. 중복 또는 누락된 경로 세그먼트가 없습니다. 자주 묻는 질문`/v1`모두에서`base_url`그리고 요청 경로, upstream 수신 결과`/v1/v1/chat/completions`.

## 좋은 관행

1. **descriptive slugs 사용**: 명확하게 공급자를 식별하는 slugs를 선택하십시오 (예 :`internal-gpt`, `regional-ai`)
2. **통합 문서**: 사용`curl_example`·`js_example`사용 예제를 제공 하는 필드
3. **자주 묻는 질문**: 시험`enable: false`공급자에게 활동하기 전에
4. **감시자 사용법**: AI Gateway의 분석을 사용하여 사용자 정의 공급자에게 요청을 추적하십시오.
5. **끝점 보안**: 사용자 정의 공급자의 기본 URL이 적절한 인증 및 권한 구현
6. **BYOK 사용**: Store 공급자 API 키 안전하게 사용[로드 중 ...](/ai-gateway/configuration/bring-your-own-keys/)대신 모든 요청에 포함

## 제한 사항

- 사용자 정의 공급자는 Cloudflare 계정에서 공유되지 않습니다

- 공급자 slugs는 각 계정 안에 독특해야 합니다
