이 가이드는 최신 Cloudflare QXQXQXWorkers AIXQ를 사용하는 방법의 개요를 제공합니다 Gateway 바인딩 방법. 당신은 AI 게이트웨이 바인딩을 설정하는 방법을 배울 것이다, 액세스 새로운 방법, 그리고 당신의 WorkersXQ에 통합.

## 1. 당신의 노동자에 AI 바인딩을 추가하십시오

Workers AIXQ에 노동자를 연결하려면 다음을 추가하십시오.[Wrangler 구성 파일](/workers/wrangler/configuration/):

import { WranglerConfig } from "~/components";

<WranglerConfig>
  ```jsonc
  {
  	"ai": {
  		"binding": "AI"
  	}
  }
  ```
</WranglerConfig>

이 구성은 당신의 노동자 부호에서 접근 가능한 AI 바인딩을 설치합니다`env.AI`.

<Render file="wrangler-typegen" product="workers" />

## 2. Workers AIXQ + 출입구를 가진 기본적인 사용법

Workers AI 및 AI 게이트웨이를 사용하여 의도 작업을 수행하려면 다음 코드를 사용할 수 있습니다.

```typescript title="src/index.ts"
const resp = await env.AI.run(
	"@cf/meta/llama-3.1-8b-instruct",
	{
		prompt: "tell me a joke",
	},
	{
		gateway: {
			id: "my-gateway",
		},
	},
);
```

또한 최신 요청 로그 ID에 액세스 할 수 있습니다 :

```typescript
const myLogId = env.AI.aiGatewayLogId;
```

## 3. Gateway Binding 액세스

다음 코드를 사용하여 AI Gateway 바인딩에 액세스 할 수 있습니다.

```typescript
const gateway = env.AI.gateway("my-gateway");
```

Gateway 인스턴스가 있으면 다음 메소드를 사용할 수 있습니다.

### 3.1. `patchLog`: 피드백 보내기

더 보기`patchLog`메소드는 특정 로그 ID에 대한 피드백, 점수 및 메타 데이터를 보낼 수 있습니다. 모든 객체 속성은 선택 사항이므로 매개 변수의 조합을 포함 할 수 있습니다.

```typescript
gateway.patchLog("my-log-id", {
	feedback: 1,
	score: 100,
	metadata: {
		user: "123",
	},
});
```

- **기타 제품**: `Promise<void>`(필수)`await`요청.)
- **예제 사용 사례**: 사용자 피드백 또는 추가 메타데이터로 로그 입력을 업데이트합니다.

### 3.2. `getLog`: 로그 세부 읽기

더 보기`getLog`특정 로그 ID의 세부 정보를 검색합니다. 유형의 객체를 반환합니다.`Promise<AiGatewayLog>`. 이 유형이 누락되면, 당신은 실행해야[`wrangler types`](/workers/languages/typescript/#generate-types).

```typescript
const log = await gateway.getLog("my-log-id");
```

- **기타 제품**: `Promise<AiGatewayLog>`
- **예제 사용 사례**: 디버깅 또는 분석을위한 로그 정보를 검색합니다.

### 3.3. `getUrl`: 게이트웨이 URL 받기

더 보기`getUrl`메소드는 AI Gateway의 기본 URL을 검색할 수 있으며, 공급자에게 특정 엔드포인트를 얻기 위해 선택적으로 지정할 수 있습니다.

```typescript
//기본 게이트웨이 URL 받기
const baseUrl = await gateway.getUrl();
//산출: https://gateway.ai.cloudflare.com/v1/my-account-id/my-gateway/

//공급자 별 URL을 가져옵니다
const openaiUrl = await gateway.getUrl("openai");
//산출: https://gateway.ai.cloudflare.com/v1/my-account-id/my-gateway/openai
```

- **매개 변수**: 옵션`provider`(string 또는`AIGatewayProviders`사이트맵
- **기타 제품**: `Promise<string>`
- **예제 사용 사례**: 직접 API 호출 또는 디버깅 구성에 대한 동적 구성 URL.

#### SDK 통합 예제

더 보기`getUrl`인기있는 AI SDK를 통합하는 방법은 특히 유용합니다.

**OpenAI SDK:**

```typescript
import OpenAI from "openai";

const openai = new OpenAI({
	apiKey: "my api key", //process.env["OPENAI API KEY"의 기본값
	baseURL: await env.AI.gateway("my-gateway").getUrl("openai"),
});
```

**OpenAI를 가진 Vercel AI SDK:**

```typescript
import { createOpenAI } from "@ai-sdk/openai";

const openai = createOpenAI({
	baseURL: await env.AI.gateway("my-gateway").getUrl("openai"),
});
```

**Anthropic을 가진 Vercel AI SDK:**

```typescript
import { createAnthropic } from "@ai-sdk/anthropic";

const anthropic = createAnthropic({
	baseURL: await env.AI.gateway("my-gateway").getUrl("anthropic"),
});
```

### 3.4. `run`: 범용 요청

더 보기`run`방법은 유니버셜 요청을 실행할 수 있습니다. 사용자는 단일 범용 요청 객체 또는 그 배열을 통과 할 수 있습니다. 이 방법은 모든 AI Gateway 공급자를 지원합니다.

더 알아보기[Universal endpoint 문서](/ai-gateway/usage/universal/)유효한 입력에 관하여 세부사항을 위해.

```typescript
const resp = await gateway.run({
	provider: "workers-ai",
	endpoint: "@cf/meta/llama-3.1-8b-instruct",
	headers: {
		authorization: "Bearer my-api-token",
	},
	query: {
		prompt: "tell me a joke",
	},
});
```

- **기타 제품**: `Promise<Response>`
- **예제 사용 사례**: 수행[범용 요청](/ai-gateway/usage/universal/)지원되는 공급자에.

## 이름 \*

이 AI Gateway 바인딩 방법으로, 당신은 지금 할 수 있습니다:

- 피드백 및 업데이트 메타데이터`patchLog`.
- 자주 묻는 질문`getLog`.
- 직접 API 액세스를 위한 Gateway URL을 가져옵니다`getUrl`, 인기있는 AI SDK와 통합하기 쉬운.
- 모든 AI Gateway 공급자에게 보편적인 요청을 실행`run`.

이 방법은 AI 통합을 통해 더 큰 유연성과 제어를 제공하며 Cloudflare QXWorkers 플랫폼에서 더 정교한 응용 프로그램을 구축 할 수 있습니다.
