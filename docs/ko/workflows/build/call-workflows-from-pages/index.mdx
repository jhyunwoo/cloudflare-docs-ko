### 서비스 Bindings

[서비스 바인딩](/workers/runtime-apis/bindings/service-bindings/)다른 노동자 또는 직접 노출 없이 Pages 기능에서 노동자를 부르는 것을 허용하십시오.

이렇게하려면:

1. 직장에서 작업 흐름을 배포
2. Pages 프로젝트에서 작업자에게 서비스 바인딩
3. 묶음을 사용하여 작업자를 원격으로 호출

예를 들어, 노동자가 호출 한 경우`workflows-starter`, 당신은 다음과 같이 Pages 프로젝트에 새로운 서비스 바인딩을 만들 것입니다, 그것을 지키다`service`name은 Workflow의 이름을 다음과 같이 정의합니다.

<WranglerConfig>
  ```jsonc
  {
  	"services": [
  		{
  			"binding": "WORKFLOW_SERVICE",
  			"service": "workflows-starter"
  		}
  	]
  }
  ```
</WranglerConfig>

당신의 노동자는 다른 Workers 또는 PagesXQXQ 함수는 Service Binding에 호출할 수 있습니다.

다음 예제에서, 우리는 특정을 노출`createInstance`우리의 접근법`Payload`그리고 반환[`InstanceStatus`](/workflows/build/workers-api/#instancestatus)Workflows API에서:

<TypeScriptExample filename="index.ts">
  ```ts
  import { WorkerEntrypoint } from "cloudflare:workers";

  interface Env {
  	MY_WORKFLOW: Workflow;
  }

  type Payload = {
  	hello: string;
  };

  export default class WorkflowsService extends WorkerEntrypoint<Env> {
  	//현재 handler가 지원되지 않는 항목은 지원되지 않습니다.
  	async fetch() {
  		return new Response(null, { status: 404 });
  	}

  	async createInstance(payload: Payload) {
  		let instance = await this.env.MY_WORKFLOW.create({
  			params: payload,
  		});

  		return Response.json({
  			id: instance.id,
  			details: await instance.status(),
  		});
  	}
  }
  ```
</TypeScriptExample>

Pages 기능은 다음과 같습니다:

<TypeScriptExample filename="functions/request.ts">
  ```ts
  interface Env {
  	WORKFLOW_SERVICE: Service;
  }

  export const onRequest: PagesFunction<Env> = async (context) => {
  	//이 페이로드는 앱 내에서 또는 프론트엔드에서 아무것도 할 수 있습니다.
  	let payload = { hello: "world" };
  	return context.env.WORKFLOWS_SERVICE.createInstance(payload);
  };
  ```
</TypeScriptExample>

Pages 기능에서 리소스에 대해 자세히 알아 보려면 Cloudflare QXQXQXQXdashboardXQ를 통해 바인딩하는 방법을 포함하여[Pages 기능에 대한 바인딩 문서](/pages/functions/bindings/#service-bindings).

### fetch 사용

:::노트\[서비스 바인딩 vs. fetch]

자주 묻는 질문[서비스 바인딩](/workers/runtime-apis/bindings/service-bindings/)자신의 계정에 노동자를 호출 할 때.

Service Bindings는 작업자에서 공개 엔드포인트를 노출해야 할 필요가 없으며 인증 구성을 요구하지 않으며 직접 작업자에 메소드를 호출 할 수 있으므로 HTTP 요청 및 응답 관리의 오버 헤드를 피하십시오.

:::

서비스 바인딩을 설정하는 대안은 WorkflowsXQ를 사용하여 HTTP를 통해 노동자를 호출하는 것입니다[모델 번호: Workers](/workflows/build/workers-api/#workflow)으로`create`각 수신 HTTP 호출에 대한 새로운 워크 플로우 인스턴스:

<TypeScriptExample filename="index.ts">
  ```ts
  //이것은 당신의 Workflow 정의와 같은 파일에 있습니다.
  export default {
  	async fetch(req: Request, env: Env): Promise<Response> {
  		let instance = await env.MY_WORKFLOW.create({
  			params: payload,
  		});
  		return Response.json({
  			id: instance.id,
  			details: await instance.status(),
  		});
  	},
  };
  ```
</TypeScriptExample>

내 계정[Pages 기능](/pages/functions/get-started/)다음을 만들 수 있습니다`fetch`노동자에게 전화 :

<TypeScriptExample filename="functions/request.ts">
  ```ts
  export const onRequest: PagesFunction<Env> = async (context) => {
  	//다른 코드
  	let payload = { hello: "world" };
  	const instanceStatus = await fetch("https://YOUR_WORKER.workers.dev/", {
  		method: "POST",
  		body: JSON.stringify(payload), //Workflow에 전달하기 위해 Worker의 페이로드를 보내십시오.
  	});

  	return Response.json(instanceStatus);
  };
  ```
</TypeScriptExample>

당신은 또한이 요청을 머리에 공유 비밀을 전달하고 당신의 노동자에 그것을 검증하여 선택할 수 있습니다.
