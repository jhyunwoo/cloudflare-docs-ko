이 가이드에서 GitHub 저장소를 연구하는 AI 에이전트를 구축합니다. "Compare open-source LLM 프로젝트"와 같은 작업을 제공 하 고:

1. 관련 저장소 GitHub 검색
2. 각 것에 대한 Fetch 세부 사항 (스타, 포크, 활동)
3. 분석 및 비교
4. 자주 묻는 질문

각 LLM 통화 및 도구 통화가됩니다.<GlossaryTooltip term="step">한국어</GlossaryTooltip>— 자기 유지, 개별적으로 직장 단위. 어떤 단계가 실패하면, Workflows가 자동으로 표시됩니다. 전체 작업 흐름이 중간 작업 충돌하면 마지막 성공적인 단계에서 다시 시작합니다.

| - 연혁                 | Workflows를 가진 해결책                   |
| -------------------- | ----------------------------------- |
| Long-running 에이전트 루프 | 어떤 중단을 살아가는 튼튼한 실행                  |
| 믿을 수 없는 LLM 및 API 호출 | 자주 묻는 질문                            |
| 인간적인 승인을 위한 대기       | `waitForEvent()`시간 또는 일 동안 일시 중지    |
| 채용공고                 | `step.sleep()`consuming 자원 없이 체크 사이 |

이 가이드는[에이전트 SDK](/agents/)실시간 진행 업데이트를 위한 Workflows와 LLM 통화를 위한 Anthropic SDK. 동일한 패턴은 LLM SDK (OpenAI, Google AI, Mistral 등)에 적용됩니다.

## 2. 도구 정의

LLM은 외부 시스템과 상호 작용할 수 있습니다. 스키마를 정의합니다 (어떤 도구가 받아 들일 수 있음). LLM은 작업에 따라 각 도구를 사용할 때 결정합니다.

<Steps>
  1. 이름 \*`src/tools.ts`두 가지 보완 도구로:

     ```ts title="src/tools.ts"
     export interface SearchReposInput {
     	query: string;
     	limit?: number;
     }

     export interface GetRepoInput {
     	owner: string;
     	repo: string;
     }

     interface GitHubSearchResponse {
     	items: Array<{ full_name: string; stargazers_count: number }>;
     }

     interface GitHubRepoResponse {
     	full_name: string;
     	description: string;
     	stargazers_count: number;
     	forks_count: number;
     	open_issues_count: number;
     	language: string;
     	license: { name: string } | null;
     	updated_at: string;
     }

     export const searchReposTool = {
     	name: "search_repos" as const,
     	description:
     		"Search GitHub repositories by keyword. Returns top results. Use get_repo for details.",
     	input_schema: {
     		type: "object" as const,
     		properties: {
     			query: {
     				type: "string",
     				description: "Search query (e.g., 'typescript orm')",
     			},
     			limit: { type: "number", description: "Max results (default 5)" },
     		},
     		required: ["query"],
     	},
     	run: async (input: SearchReposInput): Promise<string> => {
     		const response = await fetch(
     			`https://api.github.com/search/repositories?q=${encodeURIComponent(input.query)}&sort=stars&per_page=${input.limit ?? 5}`,
     			{
     				headers: {
     					Accept: "application/vnd.github+json",
     					"User-Agent": "DurableAgent/1.0",
     				},
     			},
     		);
     		if (!response.ok) return `Search failed: ${response.status}`;
     		const data = await response.json<GitHubSearchResponse>();
     		return JSON.stringify(
     			data.items.map((r) => ({
     				name: r.full_name,
     				stars: r.stargazers_count,
     			})),
     		);
     	},
     };

     export const getRepoTool = {
     	name: "get_repo" as const,
     	description:
     		"Get detailed info about a GitHub repository including stars, forks, and description.",
     	input_schema: {
     		type: "object" as const,
     		properties: {
     			owner: {
     				type: "string",
     				description: "Repository owner (e.g., 'cloudflare')",
     			},
     			repo: {
     				type: "string",
     				description: "Repository name (e.g., 'workers-sdk')",
     			},
     		},
     		required: ["owner", "repo"],
     	},
     	run: async (input: GetRepoInput): Promise<string> => {
     		const response = await fetch(
     			`https://api.github.com/repos/${input.owner}/${input.repo}`,
     			{
     				headers: {
     					Accept: "application/vnd.github+json",
     					"User-Agent": "DurableAgent/1.0",
     				},
     			},
     		);
     		if (!response.ok) return `Repo not found: ${input.owner}/${input.repo}`;
     		const data = await response.json<GitHubRepoResponse>();
     		return JSON.stringify({
     			name: data.full_name,
     			description: data.description,
     			stars: data.stargazers_count,
     			forks: data.forks_count,
     			issues: data.open_issues_count,
     			language: data.language,
     			license: data.license?.name ?? "None",
     			updated: data.updated_at,
     		});
     	},
     };

     export const tools = [searchReposTool, getRepoTool];
     ```
</Steps>

이 도구는 서로 보완 :`search_repos`저장소를 찾아서`get_repo`특정한 것에 관하여 fetches 세부사항.

## 3. 작업 흐름을 작성

더 보기`AgentWorkflow`Agents SDK에서 클래스는 양방향 에이전트 통신으로 Cloudflare QXWorkflows를 확장합니다. Workflow는 WebSocket 클라이언트로 진행되며 RPC를 통해 Agent 메소드를 호출할 수 있습니다.

- 더 보기[`step`](/workflows/build/workers-api/#step)객체는 내구성을 정의하는 방법을 제공합니다.
- `step.do(name, callback)`코드를 실행하고 결과를 주장합니다. 작업 흐름이 중단되면, 그것은 마지막 성공적인 단계에서 이력서.
- `this.reportProgress()`Agent(비-durable)에 진행된 업데이트를 보냅니다.
- `this.broadcastToClients()`모든 연결된 WebSocket 클라이언트에 메시지를 보냅니다. (비 내구성).

부드러운 소개를 위해, 참조[첫 번째 Workflow 구축](/workflows/get-started/guide/).

이름 \*`src/workflow.ts`:

```ts title="src/workflow.ts"
import { AgentWorkflow } from "agents/workflows";
import type { AgentWorkflowEvent, AgentWorkflowStep } from "agents/workflows";
import Anthropic from "@anthropic-ai/sdk";
import {
	tools,
	searchReposTool,
	getRepoTool,
	type SearchReposInput,
	type GetRepoInput,
} from "./tools";
import type { ResearchAgent } from "./agent";

type Params = { task: string };

export class ResearchWorkflow extends AgentWorkflow<ResearchAgent, Params> {
	async run(event: AgentWorkflowEvent<Params>, step: AgentWorkflowStep) {
		const client = new Anthropic({ apiKey: this.env.ANTHROPIC_API_KEY });

		const messages: Anthropic.MessageParam[] = [
			{ role: "user", content: event.payload.task },
		];

		const toolDefinitions = tools.map(({ run, ...rest }) => rest);

		//튼튼한 대리인 반복 - 각 회전은 checkpointed입니다
		for (let turn = 0; turn < 10; turn++) {
			//에이전트 및 연결 클라이언트의 진행
			await this.reportProgress({
				step: `llm-turn-${turn}`,
				status: "running",
				percent: turn / 10,
				message: `Processing turn ${turn + 1}...`,
			});

			const response = (await step.do(
				`llm-turn-${turn}`,
				{ retries: { limit: 3, delay: "10 seconds", backoff: "exponential" } },
				async () => {
					const msg = await client.messages.create({
						model: "claude-sonnet-4-5-20250929",
						max_tokens: 4096,
						tools: toolDefinitions,
						messages,
					});
					//Workflow 상태에 대해 직렬화
					return JSON.parse(JSON.stringify(msg));
				},
			)) as Anthropic.Message;

			if (!response || !response.content) continue;

			messages.push({ role: "assistant", content: response.content });

			if (response.stop_reason === "end_turn") {
				const textBlock = response.content.find(
					(b): b is Anthropic.TextBlock => b.type === "text",
				);
				const result = {
					status: "complete",
					turns: turn + 1,
					result: textBlock?.text ?? null,
				};

				//보고 완료 (durable)
				await step.reportComplete(result);
				return result;
			}

			const toolResults: Anthropic.ToolResultBlockParam[] = [];

			for (const block of response.content) {
				if (block.type !== "tool_use") continue;

				//고객에 대한 방송 툴 실행
				this.broadcastToClients({
					type: "tool_call",
					tool: block.name,
					turn,
				});

				const result = await step.do(
					`tool-${turn}-${block.id}`,
					{ retries: { limit: 2, delay: "5 seconds" } },
					async () => {
						switch (block.name) {
							case "search_repos":
								return searchReposTool.run(block.input as SearchReposInput);
							case "get_repo":
								return getRepoTool.run(block.input as GetRepoInput);
							default:
								return `Unknown tool: ${block.name}`;
						}
					},
				);

				toolResults.push({
					type: "tool_result",
					tool_use_id: block.id,
					content: result,
				});
			}

			messages.push({ role: "user", content: toolResults });
		}

		return { status: "max_turns_reached", turns: 10 };
	}
}
```

<Details header="왜 LLM 및 도구에 대한 별도의 단계?">
  각 각`step.do()`체크포인트를 만듭니다. 작업 흐름 충돌 또는 노동자 재시작:

  - **LLM 단계 후에**: 응답은 지속됩니다. 이력서에서 LLM 통화를 건너 도구 실행으로 이동합니다.
  - **공구 단계 후에**: 결과가 지속됩니다. 나중에 도구가 실패하면 이전 도구가 다시 실행되지 않습니다.

  이것은 특히 중요합니다:

  - **LLM 통화**: 저렴하고 느리게 반복하지 않아야합니다.
  - **외부 API**: 5 월에는 제한 또는 부작용이 있습니다.
  - **Idempotency는**: 일부 도구 (이메일 전송과 같은) 두 번 실행하지 않아야합니다.
</Details>

## 4. 에이전트 작성

에이전트는 HTTP 요청, WebSocket 연결, Workflow Lifecycle 이벤트를 처리합니다. 작업 흐름 인스턴스를 트리거합니다.`runWorkflow()`콜백을 통해 진행된 업데이트 수신.

이름 \*`src/agent.ts`:

```ts title="src/agent.ts"
import { Agent } from "agents";

type State = {
	currentWorkflow?: string;
	status?: string;
};

export class ResearchAgent extends Agent<Env, State> {
	initialState: State = {};

	//연구 작업을 시작 - HTTP 또는 WebSocket을 통해 호출
	async startResearch(task: string) {
		const instanceId = await this.runWorkflow("RESEARCH_WORKFLOW", { task });
		this.setState({
			...this.state,
			currentWorkflow: instanceId,
			status: "running",
		});
		return { instanceId };
	}

	//워크플로우의 상태 얻기
	async getResearchStatus(instanceId: string) {
		return this.getWorkflow(instanceId);
	}

	//워크플로우가 진행될 때 호출
	async onWorkflowProgress(
		workflowName: string,
		instanceId: string,
		progress: unknown,
	) {
		//모든 연결된 WebSocket 클라이언트에게 방송
		this.broadcast(JSON.stringify({ type: "progress", instanceId, progress }));
	}

	//작업 흐름이 완료되면 호출
	async onWorkflowComplete(
		workflowName: string,
		instanceId: string,
		result?: unknown,
	) {
		this.setState({ ...this.state, status: "complete" });
		this.broadcast(JSON.stringify({ type: "complete", instanceId, result }));
	}

	//워크플로우 오류가 있을 때 호출
	async onWorkflowError(
		workflowName: string,
		instanceId: string,
		error: string,
	) {
		this.setState({ ...this.state, status: "error" });
		this.broadcast(JSON.stringify({ type: "error", instanceId, error }));
	}
}
```

## 6. API 작성

Worker는 작업 흐름 수명주기를 관리하는 에이전트에 대한 요청을 처리합니다. 제품 정보`routeAgentRequest()`WebSocket 연결 및`getAgentByName()`서버 측 RPC 통화를 위해.

기타 제품`src/index.ts`:

```ts title="src/index.ts"
import { getAgentByName, routeAgentRequest } from "agents";

export { ResearchAgent } from "./agent";
export { ResearchWorkflow } from "./workflow";

export default {
	async fetch(request: Request, env: Env): Promise<Response> {
		const url = new URL(request.url);

		///agents/research-agent/{name}에 WebSocket 연결 경로
		const agentResponse = await routeAgentRequest(request, env);
		if (agentResponse) return agentResponse;

		//연구 작업을 시작하는 HTTP API
		if (request.method === "POST" && url.pathname === "/research") {
			const { task, agentId } = await request.json<{
				task: string;
				agentId?: string;
			}>();

			//name 로 에이전트 인스턴스를 가져옵니다 (가 존재하지 않는 경우 생성)
			const agent = await getAgentByName(
				env.ResearchAgent,
				agentId ?? "default",
			);

			//RPC를 통한 연구 작업 흐름 시작
			const result = await agent.startResearch(task);
			return Response.json(result);
		}

		//작업 흐름 상태
		if (url.pathname === "/status") {
			const instanceId = url.searchParams.get("instanceId");
			const agentId = url.searchParams.get("agentId") ?? "default";

			if (!instanceId) {
				return Response.json({ error: "instanceId required" }, { status: 400 });
			}

			const agent = await getAgentByName(env.ResearchAgent, agentId);
			const status = await agent.getResearchStatus(instanceId);

			return Response.json(status);
		}

		return new Response("POST /research with { task } to start", {
			status: 400,
		});
	},
} satisfies ExportedHandler<Env>;
```

## 실시간 클라이언트 통합

WebSocket을 통해 에이전트에 연결하여 실시간 진행 업데이트를 받으십시오. 더 보기`useAgent`Hook은 연결`/agents/{agent-name}/{instance-name}`:

```
/agents/research-agent/default  → ResearchAgent instance "default"
/agents/research-agent/user-123 → ResearchAgent instance "user-123"
```

```tsx
import { useState } from "react";
import { useAgent } from "agents/react";

function ResearchUI({ agentId = "default" }) {
	const [progress, setProgress] = useState(null);

	const { state } = useAgent({
		agent: "research-agent", //연구지도Agent 클래스
		name: agentId, //인스턴스 이름
		onMessage: (message) => {
			const data = JSON.parse(message.data);
			if (data.type === "progress") {
				setProgress(data.progress);
			}
		},
	});

	return (
		<div>
			{progress && (
				<p>
					{progress.message} ({Math.round(progress.percent * 100)}%)
				</p>
			)}
		</div>
	);
}
```

에이전트 클래스 이름은 URL에 대한 kebab-case로 자동 변환됩니다 (`ResearchAgent` → `research-agent`).
