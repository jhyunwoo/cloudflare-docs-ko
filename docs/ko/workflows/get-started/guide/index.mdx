Workflows는 Workers 플랫폼을 사용하여 내구성, 다단계 응용 프로그램을 구축 할 수 있습니다. 워크 플로우는 자동 리트리, 지속 상태, 시간 또는 일 동안 실행, 및 타사 API 사이 좌표.

Workflows를 포스트 처리 파일 업로드 할 수 있습니다[R2 객체 저장](/r2/), Automate 세대의[모델 번호: Workers AI](/workers-ai/)연결하기[모델 번호: Vectorize](/vectorize/)벡터 데이터베이스, 또는 사용자 수명주기 이메일을 트리거[이메일 서비스](/email-routing/).

:::참조
용어 "Durable Execution"는이 프로그래밍 모델을 설명하는 데 널리 사용됩니다.

"Durable"은 외부 상점 또는 직렬화 프로그램 상태에 수동으로 쓰기하지 않고 부적절한 persist 상태에 대한 프로그램의 능력을 설명합니다.
주요 특징

이 가이드에서는 데이터, 일시 중지 및 프로세스 결과를 생성하고 배포합니다.

## 빠른 시작

단계를 건너 뛰고 완료 워크 플로우를 끌어본다면, 이 가이드에 건물이 있습니다.

```sh
npm create cloudflare@latest workflows-starter -- --template "cloudflare/workflows-starter"
```

Cloudflare Workers 또는 코드를 먼저 탐색하고 세부 정보를 나중에 배우려면이 옵션을 사용하십시오.

아래 단계를 따르십시오. 작업 흐름을 처음부터 구축하는 방법을 배우십시오.

<Steps>

  2. 새 프로젝트 디렉토리로 이동:

     ```sh

     ```

     <Details header="C3는 어떤 파일을 만들었습니까?">
       프로젝트 디렉토리에서 C3는 다음과 같이 생성됩니다.

       - `wrangler.jsonc`: 당신의[Wrangler 구성 파일](/workers/wrangler/configuration/#sample-wrangler-configuration).
       - `src/index.ts`: TypeScript에서 작성된 최소 작업자.
       - `package.json`: 최소 Node 의존성 구성 파일.
       - `tsconfig.json`: TypeScript 구성.
     </Details>
</Steps>

## 2. 작업 흐름을 작성

<Steps>
  1. 새 파일 만들기`src/workflow.ts`:

     ```ts title="src/workflow.ts"
     import { WorkflowEntrypoint, WorkflowStep } from "cloudflare:workers";
     import type { WorkflowEvent } from "cloudflare:workers";

     type Params = { name: string };
     type IPResponse = { result: { ipv4_cidrs: string[] } };

     export class MyWorkflow extends WorkflowEntrypoint<Env, Params> {
     	async run(event: WorkflowEvent<Params>, step: WorkflowStep) {
     		const data = await step.do("fetch data", async () => {
     			const response = await fetch("https://api.cloudflare.com/client/v4/ips");
     			return await response.json<IPResponse>();
     		});

     		await step.sleep("pause", "20 seconds");

     		const result = await step.do(
     			"process data",
     			{ retries: { limit: 3, delay: "5 seconds", backoff: "linear" } },
     			async () => {
     				return {
     					name: event.payload.name,
     					ipCount: data.result.ipv4_cidrs.length,
     				};
     			},
     		);

     		return result;
     	}
     }
     ```

     Workflow 확장`WorkflowEntrypoint`그리고 구현`run`방법. 이 코드는 또한 우리의 패스`Params`유형으로[유형 모수](/workflows/build/events-and-parameters/)그래서 우리의 작업 흐름을 트리거 이벤트는 유형입니다.

     더 보기[`step`](/workflows/build/workers-api/#step)객체는 Workflows API의 핵심입니다. 작업 흐름에서 내구성을 정의하는 방법을 제공합니다:

     - `step.do(name, callback)`- 코드를 실행하고 결과를 주장합니다. Workflow가 중단되거나 재향 군인이라면 재 실행 완료 작업보다 마지막 성공적인 단계에서 다시 시작합니다.
     - `step.sleep(name, duration)`- 지속가능성(e.g.,`"10 seconds"`, `"1 hour"`).

     당신은 통과 할 수 있습니다[retry 구성](/workflows/build/sleeping-and-retrying/)으로`step.do()`실패가 처리되는 방법을 사용자 정의합니다. 이름 \*[전체 단계 API](/workflows/build/workers-api/#step)추가 방법`sleepUntil`·`waitForEvent`.

     별도의 단계로 코드를 깰 때, 자신을 묻습니다 : "나는 단지 하나의 부분이 실패하면이 코드를 다시 실행 할 수?" 별도의 단계는 외부 API, 쿼리 데이터베이스, 또는 저장에서 파일을 읽는 것과 같은 작업에 이상적입니다. 나중에 단계가 실패하면 작업 흐름이 이미 fetched 데이터를 사용하여 그 시점에서 다시 시도 할 수 있습니다. 중복 API 통화 또는 데이터베이스 쿼리를 피하십시오.

     Workflow logic을 정의하는 방법에 대한 자세한 내용은 참조[Workflows의 규칙](/workflows/build/rules-of-workflows/).
</Steps>

## 3. 작업 흐름 구성

<Steps>
  1. 기타`wrangler.jsonc`, 당신의 것[Wrangler 구성 파일](/workers/wrangler/configuration/)Workers 프로젝트 및 작업 흐름에 대한 자세한 내용을`workflows`윤곽:

     <WranglerConfig>
       ```json title="wrangler.jsonc"
       {
       	"$schema": "node_modules/wrangler/config-schema.json",
       	"name": "my-workflow",
       	"main": "src/index.ts",
       	"compatibility_date": "$today",
       	"observability": {
       		"enabled": true
       	},
       	"workflows": [
       		{
       			"name": "my-workflow",
       			"binding": "MY_WORKFLOW",
       			"class_name": "MyWorkflow"
       		}
       	]
       }
       ```
     </WranglerConfig>

     더 보기`class_name`당신의 수출한 종류를 일치해야 하고,`binding`코드에 Workflow에 액세스하는 데 사용할 수있는 변수 이름입니다 (like`env.MY_WORKFLOW`).

     액세스 할 수 있습니다.[관련 제품](/workers/runtime-apis/bindings/)(예 :[모델 번호: KV](/kv/), [R2](/r2/), 또는[D1](/d1/))를 통해`this.env`작업 흐름 안에. Workers 내에서 바인딩에 대한 자세한 내용은 참조[바인딩 (env)](/workers/runtime-apis/bindings/).

  2. 지금, 당신의 바인딩을 위한 유형을 생성합니다:

     ```sh
     npx wrangler types
     ```

     이 생성`worker-configuration.d.ts`파일 첨부`Env`다음을 포함하는 유형`MY_WORKFLOW`바인딩.
</Steps>

## 4. API 작성

지금, 당신은 당신의 워크 플로우를 호출 할 수있는 장소가 필요합니다.

<Steps>
  1. 기타 제품`src/index.ts`한국어[회사 소개](/workers/runtime-apis/handlers/fetch/)시작 및 체크 Workflow 인스턴스:

     ```ts title="src/index.ts"
     export { MyWorkflow } from "./workflow";

     export default {
     	async fetch(request: Request, env: Env): Promise<Response> {
     		const url = new URL(request.url);
     		const instanceId = url.searchParams.get("instanceId");

     		if (instanceId) {
     			const instance = await env.MY_WORKFLOW.get(instanceId);
     			return Response.json(await instance.status());
     		}

     		const instance = await env.MY_WORKFLOW.create();
     		return Response.json({ instanceId: instance.id });
     	},
     } satisfies ExportedHandler<Env>;
     ```
</Steps>

## 5. 현지 개발

<Steps>
  1. 로컬 개발 서버 시작:

     ```sh
     npx wrangler dev
     ```

  2. Workflow 인스턴스를 시작하려면 새로운 터미널 창을 열고 실행하십시오.

     ```sh
     curl http://localhost:8787
     ```

     이름 \*`instanceId`자동으로 생성됩니다:

     ```json output
     { "instanceId": "abc-123-def" }
     ```

  3. 반환된 상태 확인`instanceId`:

     ```sh
     curl "http://localhost:8787?instanceId=abc-123-def"
     ```

     Workflow는 단계로 진행됩니다. 대략 20 초 후에 (잠 지속), 그것은 완료될 것입니다.
</Steps>

## 6. 작업 흐름을 배포

<Steps>
  1. 작업 흐름을 배포:

     ```sh
     npx wrangler deploy
     ```

     배포된 URL에 대한 동일한 컬 명령을 사용하여 생산 테스트. 당신은 또한 할 수 있습니다[작업 흐름 인스턴스를 트리거](/workflows/build/trigger-workflows/)Workers, Wrangler, 또는 Cloudflare QXQXQXQXQXQ를 통해 생산에서.

     배포되면 Workflow 인스턴스를 CLI로 검사할 수 있습니다.

     ```sh
     npx wrangler workflows instances describe my-workflow latest
     ```

     출력의`instances describe`쇼:

     - 각 단계의 상태 (교육, 실패, 실행)
     - 단계에 의해 방출되는 어떤 국가
     - 이름 \*`sleep`작업 흐름이 깨질 때 국가
     - 각 단계와 관련한 주의사항
     - 오류, 예외 메시지 포함
</Steps>
