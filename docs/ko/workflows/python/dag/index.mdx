Python Workflows SDK는 정의 방식으로 DAG 워크플로우를 지원합니다.`step.do`정의하는 매개 변수 이름 (단계가 실행되기 전에 완료해야 할 다른 단계).

```python
from workers import Response, WorkflowEntrypoint, WorkerEntrypoint

class PythonWorkflowStarter(WorkflowEntrypoint):
    async def run(self, event, step):
        async def await_step(fn):
            try:
                return await fn()
            except TypeError as e:
                print(f"Successfully caught {type(e).__name__}: {e}")

        await step.sleep('demo sleep', '10 seconds')

        @step.do()
        async def dep_1():
            #기타 제품
            print('executing dep1')
            return 'dep1'

        @step.do()
        async def dep_2():
            #기타 제품
            print('executing dep2')
            return 'dep2'

        @step.do(concurrent=True)
        async def final_step(dep_1, dep_2):
            #기타 제품
            print(f'{dep_1} {dep_2}')

        await await_step(final_step)

class Default(WorkerEntrypoint):
    async def fetch(self, request):
        await self.env.MY_WORKFLOW.create()
        return Response("Hello world!")
```

이 예제에서,`dep_1`·`dep_2`실행하기 전에 concurrently`final_step`그들 둘 다에 달려 있는 ,.

이름 \*`concurrent=True`concurrently 해결 될 수 있습니다. 의존도가 이미 완료되면 건너 뛰고 반환 값이 재사용됩니다.

:::참조

이전 호환성 동작은 명시된 의존성 목록을 지원합니다.`depends=[...]`. 새로운 작업 흐름을 위해, 단계 의존성을 표현하는 매개 변수 이름을 사용합니다.

:::

이 패턴은 다이아몬드 모양의 작업 흐름에 유용합니다. 단계는 동시 실행할 수있는 두 개 이상의 다른 단계에 달려 있습니다.
