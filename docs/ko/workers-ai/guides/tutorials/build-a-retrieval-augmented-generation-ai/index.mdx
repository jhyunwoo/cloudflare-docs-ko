## 4. Cloudflare D1 및 VectorizeXQ를 사용하여 embedding 추가

Embeddings는 Cloudflare AI 프로젝트에서 사용할 수있는 언어 모델에 추가 기능을 추가 할 수 있습니다. 을 통해 수행**모델 번호: Vectorize**, Cloudflare의 벡터 데이타베이스.

Vectorize를 사용하기 시작하려면 새로운 embeddings 인덱스를 만듭니다.`wrangler`. 이 색인은 768 차원을 가진 벡터를 저장하고, 벡터가 서로 유사하다는 것을 결정하는 cosine 유사성을 이용합니다:

```sh
npx wrangler vectorize create vector-index --dimensions=768 --metric=cosine
```

그런 다음 새로운 Vectorize 인덱스에 대한 구성 세부 사항을 추가하십시오.[Wrangler 구성 파일](/workers/wrangler/configuration/):

<WranglerConfig>
  ```jsonc
  {
  	//... 기존의 wrangler 구성
  	"vectorize": [
  		{
  			"binding": "VECTOR_INDEX",
  			"index_name": "vector-index"
  		}
  	]
  }
  ```
</WranglerConfig>

벡터 인덱스는 데이터를 나타내는 데 사용되는 플로팅 포인트 번호인 치수 컬렉션을 저장할 수 있습니다. 벡터 데이터베이스를 쿼리 할 때, 당신은 또한 치수로 쿼리를 변환 할 수 있습니다.**모델 번호: Vectorize**벡터를 저장하는 것을 능률적으로 결정하는 것은 당신의 쿼리와 유사합니다.

## 6. 노트를 만들고 Vectorize

Workers 기능을 확장하여 여러 경로를 처리할 수 있습니다.`hono`Workers를 위한 여정 도서관. 이것은 우리의 데이터베이스에 메모를 추가하기위한 새로운 루트를 만들 수 있습니다. 설치하기`hono`이름 \*`npm`:

<PackageManagers pkg="hono" />

다음, 수입`hono`내 계정`src/index.js`파일. 당신은 또한 업데이트해야합니다`fetch`자주 묻는 질문`hono`:

```js

const app = new Hono();

app.get("/", async (c) => {
	const answer = await c.env.AI.run("@cf/meta/llama-3-8b-instruct", {
		messages: [{ role: "user", content: `What is the square root of 9?` }],
	});

	return c.json(answer);
});

export default app;
```

루트 경로 설정`/`그것은 기능적으로 응용 프로그램의 이전 버전과 동일.

이제 워크플로우를 업데이트하여 데이터베이스에 메모를 추가하고 관련 embeddings를 생성 할 수 있습니다.

이 예제는[`@cf/baai/bge-base-en-v1.5`모델 번호:](/workers-ai/models/bge-base-en-v1.5/)embedding를 창조하기 위하여 사용될 수 있는 ,. Embeddings는 저장되고 retrieved 안쪽에[Vectorize](/vectorize/), Cloudflare의 벡터 데이타베이스. 사용자 쿼리는 Vectorize 내에서 검색에 사용할 수 있도록 embedding로 설정됩니다.

```js
import { WorkflowEntrypoint } from "cloudflare:workers";

export class RAGWorkflow extends WorkflowEntrypoint {
	async run(event, step) {
		const env = this.env;
		const { text } = event.payload;

		const record = await step.do(`create database record`, async () => {
			const query = "INSERT INTO notes (text) VALUES (?) RETURNING *";

			const { results } = await env.DB.prepare(query).bind(text).run();

			const record = results[0];
			if (!record) throw new Error("Failed to create note");
			return record;
		});

		const embedding = await step.do(`generate embedding`, async () => {
			const embeddings = await env.AI.run("@cf/baai/bge-base-en-v1.5", {
				text: text,
			});
			const values = embeddings.data[0];
			if (!values) throw new Error("Failed to generate vector embedding");
			return values;
		});

		await step.do(`insert vector`, async () => {
			return env.VECTOR_INDEX.upsert([
				{
					id: record.id.toString(),
					values: embedding,
				},
			]);
		});
	}
}
```

작업 흐름은 다음과 같은 것들입니다:

1. 자주 묻는 질문`text`모수.
2. 새로운 행을 삽입`notes`D1의 테이블, 및 검색`id`새로운 행의.
3. 변환하기`text`벡터로`embeddings`LLM 바인딩의 모형.
4. 업데이트`id`·`vectors`이름 \*`vector-index`Vectorize에 있는 색인.

이 작업을 수행하면 메모의 새로운 벡터 표현을 만들 수 있습니다.

코드를 완료하려면 사용자가 데이터베이스에 메모를 제출할 수있는 경로를 추가합니다. 이 루트는 JSON 요청 몸을 파싱합니다.`note`매개 변수를 만들고 워크플로의 새로운 인스턴스를 만들고, 매개 변수를 전달합니다.

```js
app.post("/notes", async (c) => {
	const { text } = await c.req.json();
	if (!text) return c.text("Missing text", 400);
	await c.env.RAG_WORKFLOW.create({ params: { text } });
	return c.text("Created note", 201);
});
```

## 7. 주를 검색하는 Vectorize를 쿼리

코드를 완료하려면 루트 경로를 업데이트 할 수 있습니다 (`/`) 질문 Vectorize. 벡터로 쿼리를 변환하고, 다음을 사용합니다.`vector-index`가장 유사한 벡터를 찾는 인덱스.

더 보기`topK`매개변수는 함수에 의해 반환된 벡터의 수를 제한합니다. 예를 들어, 제공`topK`1 의 반환만 반환*가장 유사한*쿼리를 기반으로 벡터. 설치하기`topK`5에 5 가장 유사한 벡터를 반환합니다.

비슷한 벡터의 목록을 제공, 당신은 그 벡터에 따라 저장된 레코드 ID와 일치하는 메모를 검색 할 수 있습니다. 이 경우, 우리는 단지 하나의 메모를 검색하고 있습니다. 그러나 필요한대로 이것을 사용자 정의 할 수 있습니다.

LLM 바인딩을 위한 프롬프트로 그 노트의 텍스트를 삽입할 수 있습니다. 이것은 Retrieval-Augmented Generation 또는 RAG의 기초입니다. LLM에서 생성한 텍스트를 강화하기 위해 LLM 이외의 데이터에서 추가 컨텍스트를 제공합니다.

컨텍스트를 포함하기 위해 프롬프트를 업데이트하고 LLM을 요청할 때 컨텍스트를 사용할 수 있습니다.

```js
import { Hono } from "hono";
const app = new Hono();

//Existing 포스트 경로 ...
//app.post('/notes', async (c) => { ... })

app.get("/", async (c) => {
	const question = c.req.query("text") || "What is the square root of 9?";

	const embeddings = await c.env.AI.run("@cf/baai/bge-base-en-v1.5", {
		text: question,
	});
	const vectors = embeddings.data[0];

	const vectorQuery = await c.env.VECTOR_INDEX.query(vectors, { topK: 1 });
	let vecId;
	if (
		vectorQuery.matches &&
		vectorQuery.matches.length > 0 &&
		vectorQuery.matches[0]
	) {
		vecId = vectorQuery.matches[0].id;
	} else {
		console.log("No matching vector found or vectorQuery.matches is empty");
	}

	let notes = [];
	if (vecId) {
		const query = `SELECT * FROM notes WHERE id = ?`;
		const { results } = await c.env.DB.prepare(query).bind(vecId).run();
		if (results) notes = results.map((vec) => vec.text);
	}

	const contextMessage = notes.length
		? `Context:\n${notes.map((note) => `- ${note}`).join("\n")}`
		: "";

	const systemPrompt = `When answering the question or responding, use the context provided, if it is provided and relevant.`;

	const { response: answer } = await c.env.AI.run(
		"@cf/meta/llama-3-8b-instruct",
		{
			messages: [
				...(notes.length ? [{ role: "system", content: contextMessage }] : []),
				{ role: "system", content: systemPrompt },
				{ role: "user", content: question },
			],
		},
	);

	return c.text(answer);
});

app.onError((err, c) => {
	return c.text(err);
});

export default app;
```

## 8. Anthropic Claude 모형 (선택) 추가

더 큰 문서를 작업 하는 경우, 당신은 Anthropic의 사용 옵션을[Claude 모델](https://claude.ai/)큰 컨텍스트 윈도우가 있고 RAG 워크플로우에 잘 맞습니다.

시작하기`@anthropic-ai/sdk`포장:

<PackageManagers pkg="@anthropic-ai/sdk" />

내 계정`src/index.js`, 당신은 새롭게 할 수 있습니다`GET /`오시는 길`ANTHROPIC_API_KEY`환경 변수. 설정되면 Anthropic SDK를 사용하여 텍스트를 생성 할 수 있습니다. 설정되지 않은 경우 기존 Workers AI 코드로 돌아올 것입니다.

```js
import Anthropic from '@anthropic-ai/sdk';

app.get('/', async (c) => {
  //... 기존 코드
	const systemPrompt = `When answering the question or responding, use the context provided, if it is provided and relevant.`

	let modelUsed = ""
	let response = null

	if (c.env.ANTHROPIC_API_KEY) {
		const anthropic = new Anthropic({
			apiKey: c.env.ANTHROPIC_API_KEY
		})

		const model = "claude-3-5-sonnet-latest"
		modelUsed = model

		const message = await anthropic.messages.create({
			max_tokens: 1024,
			model,
			messages: [
				{ role: 'user', content: question }
			],
			system: [systemPrompt, notes ? contextMessage : ''].join(" ")
		})

		response = {
			response: message.content.map(content => content.text).join("\n")
		}
	} else {
		const model = "@cf/meta/llama-3.1-8b-instruct"
		modelUsed = model

		response = await c.env.AI.run(
			model,
			{
				messages: [
					...(notes.length ? [{ role: 'system', content: contextMessage }] : []),
					{ role: 'system', content: systemPrompt },
					{ role: 'user', content: question }
				]
			}
		)
	}

	if (response) {
		c.header('x-model-used', modelUsed)
		return c.text(response.response)
	} else {
		return c.text("We were unable to generate output", 500)
	}
})
```

마지막으로, 당신은 설정해야합니다`ANTHROPIC_API_KEY`Workers 응용 프로그램에서 환경 변수. 이 작업을 수행 할 수 있습니다.`wrangler secret put`:

```sh
$ npx wrangler secret put ANTHROPIC_API_KEY
```

## 9. 메모 및 벡터 삭제

```js
app.delete("/notes/:id", async (c) => {
	const { id } = c.req.param();

	const query = `DELETE FROM notes WHERE id = ?`;

	await c.env.VECTOR_INDEX.deleteByIds([id]);

	return c.status(204);

```

## 10. (선택) 문자 나누기

텍스트의 큰 조각을 위해, 그것은 더 작은 펑크로 텍스트를 분할하는 것이 좋습니다. LLM을 더 효과적으로 수집 할 수 있습니다 관련 맥락, 텍스트의 큰 조각을 검색하지 않고.

구현하기 위해, 우리는 우리의 프로젝트에 새로운 NPM 패키지를 추가 할 것입니다, \`@langchain/textsplitters':

<PackageManagers pkg="@langchain/textsplitters" />

더 보기`RecursiveCharacterTextSplitter`이 패키지에 의해 제공되는 클래스는 텍스트를 더 작은 펑크로 분할합니다. 그것은 당신의 liking에 주문을 받아서 만들어질 수 있습니다, 그러나 대부분의 경우에 기본 구성은 작동합니다:

```js
import { RecursiveCharacterTextSplitter } from "@langchain/textsplitters";

const text = "Some long piece of text...";

const splitter = new RecursiveCharacterTextSplitter({
	//이들은 chunking 크기를 바꾸기 위하여 주문을 받아서 만들어질 수 있습니다
	//펑크 크기: 1000,
	//펑크 오버랩: 200,
});

const output = await splitter.createDocuments([text]);
console.log(output); //[{ 페이지내용: 'Some long piece of text...'}]
```

이 스플리터를 사용하려면 작업 흐름을 업데이트하여 텍스트를 더 작은 펑크로 분할합니다. 우리는 그런 다음 펑크를 넘어 텍스트의 각 펑크에 대한 워크플로의 나머지를 실행합니다.

```js
export class RAGWorkflow extends WorkflowEntrypoint {
	async run(event, step) {
		const env = this.env;
		const { text } = event.payload;
		let texts = await step.do("split text", async () => {
			const splitter = new RecursiveCharacterTextSplitter();
			const output = await splitter.createDocuments([text]);
			return output.map((doc) => doc.pageContent);
		});

		console.log(
			"RecursiveCharacterTextSplitter generated ${texts.length} chunks",
		);

		for (const index in texts) {
			const text = texts[index];
			const record = await step.do(
				`create database record: ${index}/${texts.length}`,
				async () => {
					const query = "INSERT INTO notes (text) VALUES (?) RETURNING *";

					const { results } = await env.DB.prepare(query).bind(text).run();

					const record = results[0];
					if (!record) throw new Error("Failed to create note");
					return record;
				},
			);

			const embedding = await step.do(
				`generate embedding: ${index}/${texts.length}`,
				async () => {
					const embeddings = await env.AI.run("@cf/baai/bge-base-en-v1.5", {
						text: text,
					});
					const values = embeddings.data[0];
					if (!values) throw new Error("Failed to generate vector embedding");
					return values;
				},
			);

			await step.do(`insert vector: ${index}/${texts.length}`, async () => {
				return env.VECTOR_INDEX.upsert([
					{
						id: record.id.toString(),
						values: embedding,
					},
				]);
			});
		}
	}
}
```

이제 텍스트의 큰 조각이 제출 될 때`/notes`endpoint, 그들은 더 작은 펑크로 나뉩니다, 각 펑크는 작업 흐름에 의해 처리됩니다.
