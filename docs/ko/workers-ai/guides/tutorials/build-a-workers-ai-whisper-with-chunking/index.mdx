이 튜토리얼에서는 다음과 같은 방법을 배울 것입니다:

- **큰 오디오 파일을 Transcribe:**&#xC0AC;용 방법[Whisper-큰-v3-turbo](/workers-ai/models/whisper-large-v3-turbo/)Cloudflare QXWorkers AI의 모델은 자동 음성 인식 (ASR) 또는 번역을 수행 할 수 있습니다.
- **큰 파일 손잡이:**&#xD070; 오디오 파일을 처리하기 위해 작은 펑크로 분할하십시오. 메모리 및 실행 시간 제한을 극복하는 데 도움이됩니다.
- **Cloudflare Workers를 사용하여 배포하십시오:**&#xC11C;버가 없는 환경에서도 확장성, 낮은 latency transcription 파이프라인을 만듭니다.

## 2. Workers AI에 당신의 노동자를 연결하십시오

당신은 Workers AI에 연결하기 위하여 노동자를 위한 AI 바인딩을 창조해야 합니다.[회사 소개](/workers/runtime-apis/bindings/)Workers는 Workers AI, Cloudflare 개발자 플랫폼과 같은 리소스와 상호 작용할 수 있습니다.

Workers AI를 작업자에게 바인딩하려면 Wrangler 구성 파일의 끝에 다음을 추가하십시오.

<WranglerConfig>
  ```jsonc

  	"ai": {
  		"binding": "AI"
  	}
  }
  ```
</WranglerConfig>

당신의 바인딩은 입니다[당신의 노동자 부호에서 유효한](/workers/reference/migrate-to-module-workers/#bindings-in-es-modules-format)에 의해[`env.AI`](/workers/runtime-apis/handlers/fetch/).

## 4. chunking를 가진 큰 오디오 파일 손잡이

본문 바로가기`src/index.ts`다음 통합 코드로 파일. 이 표본은 방법에 설명합니다:

(1) 쿼리 매개 변수에서 오디오 파일 URL을 추출합니다.

(2) 명시적으로 리디렉션을 따르는 동안 오디오 파일을 Fetch합니다.

(3) 작은 펑크로 오디오 파일을 분할 (예 : 1 MB 펑크).

(4) QXQX0060XQ AI 바인딩을 통해 Whisper-large-v3-turbo 모델을 사용하여 각 펑크를 부여합니다.

(5) 일반 텍스트로 집계 된 쓰레기를 반환합니다.

```ts
import { Buffer } from "node:buffer";
import type { Ai } from "workers-ai";

export interface Env {
	AI: Ai;
	//필요한 경우 KV 네임스페이스를 추가하여 성적표를 저장합니다.
	//MY KV NAMESPACE: KVNamespace;
}

/** 이름
* 제공된 URL에서 오디오 파일을 Fetches하고 싱크로 분할합니다.
* 이 기능은 명시적으로 리디렉션을 따릅니다.
* 이름
* @param audioUrl - 오디오 파일의 URL.
* @returns는 ArrayBuffers의 배열은 각각 오디오의 펑크를 나타냅니다.*/
async function getAudioChunks(audioUrl: string): Promise<ArrayBuffer[]> {
	const response = await fetch(audioUrl, { redirect: "follow" });
	if (!response.ok) {
		throw new Error(`Failed to fetch audio: ${response.status}`);
	}
	const arrayBuffer = await response.arrayBuffer();

	//예: 오디오를 1MB 펑크로 분할합니다.
	const chunkSize = 1024 * 1024; //1MB 이상
	const chunks: ArrayBuffer[] = [];
	for (let i = 0; i < arrayBuffer.byteLength; i += chunkSize) {
		const chunk = arrayBuffer.slice(i, i + chunkSize);
		chunks.push(chunk);
	}
	return chunks;
}

/** 이름
* Whisper‐large‐v3‐turbo 모델을 사용하여 단일 오디오 펑크를 변환합니다.
* 함수는 base64 인코딩된 문자열로 오디오 펑크를 변환합니다.
* AI 바인딩을 통해 모형에 보냅니다.
* 이름
* @param chunkBuffer - 오디오 펑크는 ArrayBuffer입니다.
* @param env - Cloudflare AI 바인딩을 포함하여 노동자 환경.
* @returns는 모델의 transcription 텍스트.*/
async function transcribeChunk(
	chunkBuffer: ArrayBuffer,
	env: Env,
): Promise<string> {
	const base64 = Buffer.from(chunkBuffer, "binary").toString("base64");
	const res = await env.AI.run("@cf/openai/whisper-large-v3-turbo", {
		audio: base64,
		//선택적인 모수 (필요한 경우에 조정 및 세트):
		//작업: "transcribe", // 또는 "translate"
		//언어: "en",
		//vad filter: "false",
		//initial prompt: "필요한 경우의 Provide context.",
		//접두사: "Transcription:",
	});
	return res.text; //transcription 결과가 "text" 속성을 포함합니다.
}

/** 이름
* 주요 fetch 핸들러. 그것은 'url' 쿼리 매개 변수를 추출, 오디오를 fetches,
* chunks에서 처리하고 전체 transcription을 반환합니다.*/
export default {
	async fetch(
		request: Request,
		env: Env,
		ctx: ExecutionContext,
	): Promise<Response> {
		//쿼리 매개 변수에서 오디오 URL을 추출합니다.
		const { searchParams } = new URL(request.url);
		const audioUrl = searchParams.get("url");

		if (!audioUrl) {
			return new Response("Missing 'url' query parameter", { status: 400 });
		}

		//오디오 펑크를 가져옵니다.
		const audioChunks: ArrayBuffer[] = await getAudioChunks(audioUrl);
		let fullTranscript = "";

		//각 펑크를 처리하고 전체 성적표를 만듭니다.
		for (const chunk of audioChunks) {
			try {
				const transcript = await transcribeChunk(chunk, env);
				fullTranscript += transcript + "\n";
			} catch (error) {
				fullTranscript += "[Error transcribing chunk]\n";
			}
		}

		return new Response(fullTranscript, {
			headers: { "Content-Type": "text/plain" },
		});
	},
} satisfies ExportedHandler<Env>;
```

## 5. 작업자를 배포

1. **노동자를 로컬로 실행:**

   wrangler의 개발 모드를 사용하여 작업자를 로컬로 테스트하십시오.

```sh
npx wrangler dev
```

브라우저를 열고 이동[모델 번호: http://localhost:8787](http://localhost:8787), 또는 사용 컬:

```sh
curl "http://localhost:8787?url=https://raw.githubusercontent.com/your-username/your-repo/main/your-audio-file.mp3"
```

URL 쿼리 매개 변수를 오디오 파일에 직접 링크로 바꾸십시오. ( GitHub-hosted 파일의 경우, 원시 파일 URL을 사용하십시오.)

2. **노동자를 배포:**

   테스트가 완료되면 Worker를 다음과 같이 배포합니다.

```sh
npx wrangler deploy
```

3. **배포 된 노동자를 테스트 :**

   배포 후, 쿼리 매개 변수로 오디오 URL을 전달하여 작업자를 테스트하십시오.

```sh
curl "https://<your-worker-subdomain>.workers.dev?url=https://raw.githubusercontent.com/your-username/your-repo/main/your-audio-file.mp3"
```

자주 묻는 질문`<your-worker-subdomain>`, `your-username`, `your-repo`·`your-audio-file.mp3`당신의 실제적인 세부사항으로.

성공적인 경우, 노동자는 오디오 파일의 성적을 반환합니다:

```sh
This is the transcript of the audio...
```
