Zero Trust 정책을 사용하면 특정 유형의 멀티 팩터 인증 (MFA) 메소드를 사용하여 사용자가 특정 응용 프로그램에 로그인 할 수 있습니다. 예를 들어, 사용자가 물리적 하드 키로 인증되는 경우 주어진 응용 프로그램에 도달 할 수있는 규칙을 만들 수 있습니다.

이 기능은 다음과 같은 ID 공급자를 사용하는 경우에만 유효합니다:

- 오오타
- Microsoft Entra ID (이전 Azure AD)
- OpenID 연결 (OIDC)
- 사이트맵

응용 프로그램에 MFA 요구 사항을 시행하려면:

1. 내 계정[사이트맵 한국어](https://one.dash.cloudflare.com/), 이동**액세스 제어** > **이름 \***.

2. MFA를 시행하고 싶은 응용 프로그램을 찾기**설정하기**. 대안으로,[새 응용 프로그램 생성](/cloudflare-one/access-controls/applications/http-apps/).

3. 오시는 길**회사연혁**.

4. 응용 프로그램이 이미 ID 요구 사항을 포함 한 정책을 가지고 있다면, 그것을 찾아 선택**설정하기**.

   :::참조
   본 방침은 정체성 선별기를 사용하는 규칙을 포함해야 합니다. 예를 들어, Include 규칙은 사용자를 허용할 수 있습니다.[규칙 그룹](/cloudflare-one/access-controls/policies/groups/), 이메일 도메인, 또는 ID 공급자 그룹.
   주요 특징

5. 정책에 따라 다음 규칙을 추가하십시오:

   | 규칙 유형 | 옵션 정보 | 제품정보                                   |
   | ----- | ----- | -------------------------------------- |
   | 이름 \* | 인증 방법 | `mfa - multiple-factor authentication` |

6. 자주 묻는 질문

:::카ution\[중요]

**사용자가 필요한 MFA 방법을 제시하지 않는 경우 어떻게됩니까?**

사이트맵 액세스는 사용자를 거부 할 것입니다, 그들은 성공적으로 대체 방법으로 ID 공급자에 로그인하는 경우에도.

:::

## JWT에 인증 방법 추가

사용자의 정체성 공급자와 정통할 때, 정체성 공급자는 Cloudflare Access로 사용자 이름을 공유합니다. 사이트맵 접근은 그 값을<GlossaryTooltip term="JSON web token">JSON 웹 토큰 (JWT)</GlossaryTooltip>사용자에 대한 생성.

특정 정체성 공급자는 사용자가 로그인할 수 있도록 멀티 팩터 인증(MFA) 방법을 공유할 수 있습니다. 사이트맵 액세스는 JWT와 힘으로 이러한 값을 추가 할 수 있습니다. 예를 들어, 사용자가 암호와 물리적 하드 키로 인증 된 경우, ID 공급자는 Cloudflare 액세스에 대한 확인을 보낼 수 있습니다.

사이트맵 해당 이용 후기에 달린 코멘트가 없습니다.

사이트맵 오시는 길[RFC 8176년](https://tools.ietf.org/html/rfc8176), 인증 방법 참조 값, 인증 방법을 정의합니다.
