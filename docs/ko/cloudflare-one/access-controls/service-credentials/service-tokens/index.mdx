Cloudflare에 대해 인증하는 서비스 토큰을 사용하여 자동화 시스템을 제공 할 수 있습니다. 1개의 정책. 사이트맵 Access는 Client ID와 Client Secret로 구성된 서비스 토큰을 생성합니다. 자동화 시스템 또는 응용 프로그램은 이러한 값을 사용하여 액세스에 의해 보호 된 응용 프로그램에 도달 할 수 있습니다.

이 섹션은 서비스 토큰을 생성, 갱신, 수정하는 방법을 다룹니다.

## 오시는 길

### 초기 요청

서비스 토큰을 사용하여 액세스 응용 프로그램에 인증하려면 HTTP 요청 헤더에 다음을 추가하십시오.

`CF-Access-Client-Id: <CLIENT_ID>`

`CF-Access-Client-Secret: <CLIENT_SECRET>`

예를 들어,

```sh
curl -H "CF-Access-Client-Id: <CLIENT_ID>" -H "CF-Access-Client-Secret: <CLIENT_SECRET>" https://app.example.com
```

서비스 토큰이 유효하다면 Access는 JWT가 응용 프로그램에 적용하는 것을 생성합니다.[`CF_Authorization`제품 정보](/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/). 이 쿠키를 사용할 수 있습니다.[다음 요청](#subsequent-requests)신청에.

#### 단일 헤더로 인증

단일 HTTP 헤더에서 서비스 토큰을 수락하는 셀프 호스팅 액세스 응용 프로그램을 구성 할 수 있습니다.`CF-Access-Client-Id`·`CF-Access-Client-Secret`머리의 쌍. 이것은 요청에서 하나의 사용자 정의 헤더를 전송하는 SaaS 서비스를 인증하는 데 유용합니다 (예를 들어,`Authorization`헤더).

단일 헤더를 사용하여 인증하려면:

1. 기존의 Access Application 구성을 가져옵니다:

   <APIRequest path="/accounts/{account_id}/access/apps/{app_id}" method="GET" />

2. 더 보기`PUT`서비스 토큰 인증을 사용하려는 헤더의 이름을 요청합니다. 기존 구성을 overwriting하기 위해,`PUT`요청 몸은 이전의 모든 필드를 반환해야`GET`이름 \*

   <APIRequest
     path="/accounts/{account_id}/access/apps/{app_id}"
     method="PUT"
     json={{
      domain: "app.example.com",
      type: "self_hosted",
      read_service_tokens_from_header: "Authorization",
   }}
   />

3. 헤더를 HTTP 요청에 추가합니다. 예를 들어,

   ```sh
   curl -H "Authorization: {\"cf-access-client-id\": \"<CLIENT_ID>\", \"cf-access-client-secret\": \"<CLIENT_SECRET>\"}" https://app.example.com
   ```

### 자주 묻는 질문

당신은 후[신청에 정정](#initial-request)서비스 토큰을 사용하여 결과 추가`CF_Authorization`모든 후속 요청의 헤더에 쿠키:

```sh
curl -H "cookie: CF_Authorization=<CF_AUTHORIZATION_COOKIE>" https://app.example.com
```

익지않는 우두머리를 사용하는 것을 선호하는 경우에, 값을 것과 같이 보내십시오`cf-access-token`:

```sh
curl -H "cf-access-token: <CF_AUTHORIZATION_COOKIE>" https://app.example.com
```

이 쿠키의 모든 요청은 JWT가 만료 될 때까지 성공합니다.

:::참조

귀하의 액세스 응용 프로그램은 서비스 Auth 정책을 가지고 있다면, 다음 요청에 서비스 토큰을 보내야합니다. 응용 프로그램이 적어도 하나의 허용 정책을 가지고있는 경우 JWT 만 사용할 수 있습니다.

## Renew 서비스 토큰

서비스 토큰은 토큰을 만들 때 선택한 토큰 기간에 따라 만료됩니다.

서비스 토큰을 갱신하려면:

1. 내 계정[사이트맵 한국어](https://one.dash.cloudflare.com), 이동**액세스 제어** > **서비스 자격** > **서비스 토큰**.
2. 갱신하고 싶은 토큰을 찾습니다.
3. 1 년 동안 토큰의 수명을 연장하려면, 선택**지원하다**.
4. 토큰의 수명을 1년 이상 연장하려면:
   1. 제품정보**제품정보**.
   2. 새로운 선택**서비스 토큰 기간**.
   3. 제품정보**제품 정보**. 만료일은 선택한 금액으로 연장됩니다.

## 서비스 토큰

토큰이 만료되기 전에 액세스를 취소하려면 토큰을 삭제합니다.

1. 내 계정[사이트맵 한국어](https://one.dash.cloudflare.com), 이동**액세스 제어** > **서비스 자격** > **서비스 토큰**.
2. **이름 \***&#xD1A0;큰을 수정해야 합니다.

삭제 된 서비스 토큰에 의존하는 서비스는 더 이상 애플리케이션에 도달 할 수 없습니다.

:::참조

액세스 응용 프로그램을 편집 할 때, selecting**기존 토큰**기존 세션을 수정하지만 새로운 세션을 시작으로 사용자를 방지하지 않습니다. 클라이언트 ID 및 클라이언트 비밀은 여전히 유효합니다. 그들은 다음 요청에 새로운 토큰을 교환 할 수 있습니다. 접속을 취소하려면 서비스 토큰을 삭제해야 합니다.

## 토큰 만료 알림 설정

서비스 토큰이 만료되기 전에 일주일에 알림을 설정할 수 있습니다.

서비스 토큰 만료 경고를 구성하려면:

1. 내 계정[Cloudflare 대시보드](https://dash.cloudflare.com), 이동**공지사항**사이트 맵
   <DashButton url="/?to=/:account/notifications" />
2. 제품정보**더 보기**.
3. 제품정보*Expiring Access 서비스 토큰*.
4. 경고 및 옵션 설명에 대한 이름을 입력하십시오.
5. (선택) 알림 이메일에 대한 다른 수신자 추가.
6. 제품정보**제품 정보**.
