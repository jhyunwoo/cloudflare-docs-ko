## 자주 묻는 질문

- 이름 \*[회사 소개](/cloudflare-one/integrations/identity-providers/)Cloudflare에서 구성 한국어
- Workday 계정 관리

## 1. Cloudflare One에 SaaS 애플리케이션 추가

1. 내 계정[사이트맵 한국어](https://one.dash.cloudflare.com), 이동**액세스 제어** > **이름 \***.
2. 제품정보**앱 추가** > **SaaS 서비스** > **제품정보**.
3. 제품 정보**제품 설명**, 입력`Workday`그리고 일치하는 textbox를 선택합니다.
4. 인증 프로토콜의 경우, 선택**사이트맵**.
5. 제품정보**앱 추가**.
6. 다음 필드에 기입:
   - **기업 ID**: `http://www.workday.com`
   - **Assertion 소비자 봉사 URL**: `https://<your-environment>.myworkday.com/<your-tenant>/login-saml.flex`생산 계정 또는`https://<your-environment>-impl.myworkday.com/<your-tenant>/login-saml.flex`미리보기 sandbox 계정
   - **이름 ID 체재**: *이름 \**
7. 제출하기**SSO 엔드포인트**, **Access Entity ID 또는 발급자**·**공공 키**.
8. 설정하기[오시는 길](/cloudflare-one/access-controls/policies/)신청하기
9. 신청 저장.

## 2. 메타데이터 파일을 다운로드

1. Cloudflare의 애플리케이션 구성에서 SAML 메타데이터 엔드포인트를 붙여넣기 웹 브라우저에서 하나.
2. URL의 내용을 다운로드하려면 브라우저 별 단계를 따르십시오.`.xml`파일.

## 3. SAML SSO 공급자를 Workday에 추가하십시오.

1. Workday에서**계정 관리** > **관련 기사** > **Tenant Setup 편집 - 보안**.
2. 이름 \***SAML 설치**, 켜기**SAML 인증**.
3. 내 계정**SAML ID 공급자**테이블, 선&#xD0DD;**+**.
4. 다음 필드에 기입:
   - **Identity Provider 이름**: ID 공급자의 원하는 이름 (예를 들면,`Cloudflare Access`)
   - **계정 관리**: Cloudflare One의 Application 구성에서 Entity ID 또는 Issuer 액세스
   - **IdP SSO 서비스 URL**: Cloudflare One의 애플리케이션 구성에서 SSO 엔드포인트
5. 이름 \***x509 인증서**, 메뉴 아이콘 선택 >**X509 공개 키 만들기**.
6. 이름 \***이름 \***, 독특한 이름을 입력 (예를 들어,`access`).
7. 이름 \***인증번호**, Cloudflare에 있는 신청 윤곽에서 공중 열쇠를 풀기.
8. 제품정보**이름 \***.
9. SP-initiated 로그인을 활성화하려면 (당신의 Workday URL로 이동하여 로그인), 다음 필드에 입력:
   - **SP 개시**: 켜기.
   - **서비스 제공자 ID**: `http://www.workday.com`
   - **로그인 SP-initiated 요청**: 턴오프.
10. 이름 \***단일 로그인**, 다음 항목 중 하나 또는 둘 다 추가**리디렉션 URL**그리드. 각 항목에 대해 사용자 그룹이 같은 인증 옵션을 사용하여 로그인, 선택**단일 URL**. 다른 인증 옵션을 사용할 경우, 선택**인증 선택기**.
    - IdP 개시 SSO: 아래에**로그인 Redirect URL**, 입력`<your-team-name>.cloudflareaccess.com`.
    - SP 개시 SSO: 아래**로그인 Redirect URL**, 입력`https://<your-environment>/<your-tenant/login-saml2.htmld`.

## 4. 통합 테스트

:::참조
사용자가 Workday를 잠그는 상황에서 발생하는 경우 사용자는 사용자의 사용자 이름과 암호로 서명하기 위해 Workday가 제공하는 백업 URL을 사용할 수 있습니다.`https://<your-workday-url>/login.flex?redirect=n`.
:::

1. Workday에서[인증 규칙](https://doc.workday.com/admin-guide/en-us/authentication-and-security/authentication/authentication-policies/dan1370796466772.html).
2. 이름 \***인증 조건**, 테스트 사용자에게만 적용할 조건을 추가합니다.
3. 이름 \***허용된 인증 유형**, 선택**제품정보**, 다음**사이트맵**.
4. 제품정보**이름 \***.
5. 다음 단계 완료:
   - **SP-initiated 로그인을 활성화한 경우**: Incognito 브라우저 창을 열고 Workday URL로 이동하여 테스트 사용자의 이메일에 입력하십시오. Cloudflare Access 로그인 화면에 리디렉션하고 정체 공급자와 서명하도록 안내합니다.
   - **SP-initiated 로그인을 활성화하지 않은 경우**: 앱 실행기로 이동`https://<cloudflare-team-name>.cloudflareaccess.com`. 선택**Workday 소개**사이트 맵 Cloudflare Access 로그인 화면에 리디렉션하고 정체 공급자와 서명하도록 안내합니다.
6. 로그인이 성공하면 보안 설정을 추가할 수 있습니다.[사용자 그룹](https://doc.workday.com/admin-guide/en-us/authentication-and-security/configurable-security/security-groups/user-based-security-groups/dan1370796695367.html?toc=2.2.12.0)또는[인증 규칙](https://doc.workday.com/admin-guide/en-us/authentication-and-security/authentication/authentication-policies/dan1370796466772.html)사용자의 다른 그룹에 대한 다른 로그인 규칙을 구성합니다.
