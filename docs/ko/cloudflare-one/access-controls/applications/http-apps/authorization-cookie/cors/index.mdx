Cross-Origin 리소스 공유 ([사이트맵](https://developer.mozilla.org/en-US/docs/Web/HTTP/CORS)) HTTP 헤더를 사용하는 메커니즘은 다른 소스에서 선택한 리소스에 도달하기 위해 하나의 기원 권한을 실행하는 웹 응용 프로그램을 부여하는 것입니다. 웹 응용 프로그램은 도메인, 프로토콜 또는 포트를 포함한 자체에서 다른 기원을 가진 리소스를 요청할 때 크로스 라이진 HTTP 요청을 실행합니다.

액세스에 의해 보호 된 사이트에 도달 할 수있는 CORS 요청의 경우, 요청은 유효해야합니다`CF-Authorization`제품 정보 요청 유형에 따라 추가 구성이 필요할 수 있습니다.

- [간단한 요청](https://developer.mozilla.org/en-US/docs/Web/HTTP/CORS#simple_requests)preflight 요청을 트리거하지 않고 원래에 직접 보내집니다. 구성 지침에 대한 참조[간단한 요청](#allow-simple-requests).

- [사전 요청](https://developer.mozilla.org/en-US/docs/Web/HTTP/CORS#preflighted_requests)브라우저가 실제 요청을 보내기 전에 OPTIONS 요청을 보낼 수 있습니다. OPTIONS 요청은 방법 및 헤더가 원산지로 허용됩니다. 구성 지침에 대한 참조[사전 요청을 허용](#allow-preflighted-requests).

:::카ution\[중요]

- Incognito 모드에서 CORS를 문제 해결하지 마십시오. 이로 인해 액세스 중단이 발생할 수 있습니다.`CF-Authorization`Cross Origin 요청에 타사 쿠키로 차단됩니다.

- Safari, 특정 Safari 13.1에서 고유 한 형식으로 쿠키를 처리합니다. 어떤 경우에는 CORS가 실패할 수 있습니다. Apple은 쿠키 취급에 대한 패치를 해제합니다. Safari 13.1 (15609.1.20.111.8)를 실행할 때 macOS 10.15.4에 영향을 미칩니다.

:::

## 간단한 요청

Access-protected 도메인에 간단한 CORS 요청을 만들고 아직 로그인하지 않은 경우 요청이 반환됩니다.`CORS error`. 이 오류를 해결할 수있는 두 가지 방법이 있습니다 :

- **옵션 1** — [자주 묻는 질문](#authenticate-manually).
- **옵션 2** — [Cloudflare 만들기 인증 토큰을 자동으로 전송하는 Worker](#send-authentication-token-with-cloudflare-worker). 이 방법은 CORS 교환에 관련된 두 사이트가 액세스 뒤에있는 경우에만 작동합니다.

### 수동으로 인증

1. 브라우저에서 대상 도메인을 방문하십시오. 액세스 로그인 페이지를 볼 수 있습니다.
2. 대상 도메인에 로그인하십시오. 이 생성물`CF-Authorization`사이트 맵
3. CORS 요청을 만든 페이지를 새로 고침합니다. 새로 생성 된 쿠키와 함께 요청을 다시 보냅니다.

## 사전 요청을 허용

Access-protected 도메인에 사전 등록 된 크로스 리긴 요청을하면 OPTIONS 요청이 반환됩니다.`403`오류. 이 오류는 도메인에 로그인했는지 여부에 관계없이 발생합니다. 브라우저가 OPTIONS 요청으로 쿠키를 포함하지 않기 때문에 디자인. Cloudflare는 그러므로 CORS 교환을 실패하기 위하여 preflight 요구를 막을 것입니다.

이 오류를 해결할 수있는 세 가지 방법이 있습니다 :

- **옵션 1** — [Bypass OPTIONS 요청으로](#bypass-options-requests-to-origin).
- **옵션 2** — [Cloudflare를 구성하여 OPTIONS 요청에 대응](#configure-response-to-preflight-requests).
- **옵션 3** — [Cloudflare 만들기 인증 토큰을 자동으로 전송하는 Worker](#send-authentication-token-with-cloudflare-worker). 이 방법은 CORS 교환에 관련된 두 사이트가 액세스 뒤에있는 경우에만 작동합니다.

### Bypass OPTIONS 요청으로

Cloudflare를 구성하여 OPTIONS 요청을 원본 서버에 직접 보낼 수 있습니다. OPTIONS 요청에 대한 우회 액세스 :

1. 내 계정[사이트맵 한국어](https://one.dash.cloudflare.com), 이동**액세스 제어** > **이름 \***.
2. OPTIONS 요청을 수신하고 선택할 수있는 기원을 찾습니다**설정하기**.
3. 오시는 길**고급 설정** > **Cross-Origin 자원 공유 (CORS) 설정**.
4. 기타 제품**Bypass 옵션 요청**. 이 응용 프로그램에 대한 모든 기존 CORS 설정을 제거 할 것입니다.

Access JWT에 대한 CORS를 시행하는 것이 중요합니다. - 이 옵션은 원산지 서버에서 CORS 강제로만 사용되어야 합니다.

### preflight 요청에 응답 구성

Cloudflare를 구성할 수 있습니다. OPTIONS 요청은 원산지에 도달하지 않습니다. 사전 교환이 해결되면 브라우저는 인증 쿠키를 포함하는 주요 요청을 보낼 것입니다. (Access-protected 도메인에 로그인해야 함).

Cloudflare가 선불 요청에 응답하는 방법을 구성하려면:

1. 내 계정[사이트맵 한국어](https://one.dash.cloudflare.com), 이동**액세스 제어** > **이름 \***.

2. OPTIONS 요청을 수신하고 선택할 수있는 기원을 찾습니다**설정하기**.

3. 오시는 길**고급 설정** > **Cross-Origin 자원 공유 (CORS) 설정**.

4. 이것들을 구성[CORS 설정](https://developer.mozilla.org/en-US/docs/Web/HTTP/CORS#the_http_response_headers)당신의 근원에 의해 보내지는 응답 헤더에 일치하기 위하여.

   예를 들어, 설정한 경우`api.mysite.com`다음 헤더를 반환하려면:

   ```txt
   headers: {
     'Access-Control-Allow-Origin': 'https://example.com',
     'Access-Control-Allow-Credentials' : true,
     'Access-Control-Allow-Methods': 'GET, OPTIONS',
     'Access-Control-Allow-Headers': 'office',
     'Content-Type': 'application/json',
   }
   ```

   다음으로 이동`api.mysite.com`접근 및 구성**액세스 제어-Allow-Origin**, **액세스 제어-Allow-Credentials**, **액세스 제어-Allow-Methods**·**액세스 제어-Allow-Headers**.
   ![Cloudflare One의 CORS 설정](~/assets/images/cloudflare-one/policies/CORS-settings.png)

5. 제품정보**자주 묻는 질문**.

6. (선택) OPTIONS 요청을 전달하여 구성을 확인할 수 있습니다.`curl`. 예를 들면,

   ```bash
   curl --head --request OPTIONS https://api.mysite.com \
   --header 'origin: https://example.com' \
   --header 'access-control-request-method: GET'
   ```

   다음과 같은 응답을 반환해야:

## Cloudflare Worker로 인증 토큰 전송

Cloudflare 액세스에 의해 보호 된 두 사이트가있는 경우,`example.com`·`api.mysite.com`, 2 사이에 만들어진 요청은 CORS 검사에 따라 달라질 수 있습니다. 로그인 계정`example.com`쿠키를 발행합니다.`example.com`. 사용자의 브라우저 요청시`api.mysite.com`· Cloudflare 접근은 특정한 쿠키를 찾습니다`api.mysite.com`. 사용자가 이미 로그인하지 않은 경우 요청이 실패합니다.`api.mysite.com`.

두 번에 로그를 피하려면 Cloudflare Worker를 만들 수 있습니다.`api.mysite.com`.

기타`/src/index.js`그리고 기존 코드를 삭제하고 다음 예에서 붙여넣기:

```js
//API가 살아가는 호스트명
const originalAPIHostname = "api.mysite.com";

export default {
	async fetch(request, env) {
		//호스트 변경. 요청이 example.com/api/name에 포함된 경우, 새로운 URL은 api.mysite.com/api/name입니다.
		const url = new URL(request.url);
		url.hostname = originalAPIHostname;

		//API가 api.mysite.com/anyname에 있는 경우 (경로를 "api/" 없이),
		//example.com/api/name의 "api/" 부분을 제거

		//url.pathname = url.pathname.substring(4)

		//최고의 연습은 항상 새로운 요청을 구성하는 원래의 요청을 사용합니다.
		//모든 속성을 복제합니다. URL을 적용하면 생성자가 필요합니다.
		//한 번의 요청이 건설되었기 때문에 URL은 immutable입니다.
		const newRequest = new Request(url.toString(), request);

		newRequest.headers.set("cf-access-client-id", env.CF_ACCESS_CLIENT_ID);
		newRequest.headers.set("cf-access-client-secret", env.CF_ACCESS_CLIENT_SECRET);
		try {
			const response = await fetch(newRequest);

			//응답에 복사
			const modifiedResponse = new Response(response.body, response);

			//응답에서 set-cookie를 삭제하므로 기존 쿠키를 무시하지 않습니다.
			modifiedResponse.headers.delete("set-cookie");

			return modifiedResponse;
		} catch (e) {
			return new Response(JSON.stringify({ error: e.message }), {
				status: 500,
			});
		}
	},
};
```

### 5. HTTP 요청 URL 업데이트

수정하기`example.com`모든 요청을 보낼 수있는 응용`example.com/api/`대신에`api.mysite.com`.

HTTP 요청은 이제 두 가지 다른 Access-protected 도메인 사이에 원활하게 작동해야합니다. 사용자가 로그인할 때`example.com`브라우저는 대신 Worker에 요청을 만듭니다.`api.mysite.com`. 노동자는 요청 헤더에 액세스 서비스 토큰을 추가하고 요청을 전달합니다.`api.mysite.com`. 서비스 토큰이 서비스 Auth 정책을 일치하기 때문에 사용자는 더 이상 로그인 할 필요가 없습니다`api.mysite.com`.

## 문제 해결

일반적으로 CORS 문제를 해결 할 때 다음 단계를 권장합니다.

1. 설명된 문제와 HAR 파일을 캡처하고 JS 콘솔 로그 출력을 동시에 기록합니다. HAR 파일은 혼자서 cross-origin 문제 뒤에 이유에 전체 가시성을 제공하지 않습니다.
2. 응용 프로그램이 설정 한 것을 보장합니다.`credentials: 'same-origin'`모든 fetch 또는 XHR 요청에서.
3. 사용중인 경우[Cross-origin 설정](https://developer.mozilla.org/en-US/docs/Web/HTML/Attributes/crossorigin)스크립트 태그에서, 이들은 "use-credentials"로 설정해야합니다.

:::caution\[CORS는 동일한 도메인에 실패]

CORS는 동일한 도메인에서 발생하지 않습니다. 이 오류가 발생하면 요청이 없는 경우`CF-Authorization`사이트 맵
주요 특징
