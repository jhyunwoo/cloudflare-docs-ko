Cloudflare 액세스로 사이트를 보호 할 때 Cloudflare는 요청이 유효한지 확인하기 위해 해당 사이트에 대한 모든 HTTP 요청 바인딩을 확인합니다.`CF_Authorization`제품 정보 요청이 쿠키를 포함하지 않는 경우, 액세스 요청을 차단합니다.

## 액세스 JWTs

더 보기`CF_Authorization`쿠키는 사용자의 정체성을 포함합니다.[JSON 웹 토큰 (JWT)](https://www.cloudflare.com/learning/access-management/token-based-authentication/). Cloudflare는 Cloudflare Access와 구성된 ID 공급자 사이에서 OAUTH 또는 SAML 통합을 통해 이러한 토큰을 안전하게 만듭니다.

접근은 2개의 분리를 생성합니다`CF_Authorization`도메인에 따라 토큰:

- **글로벌 세션 토큰**: 접속할 때 사용자 로그가 생성됩니다. 이 토큰은 쿠키로 저장됩니다.<GlossaryTooltip term="team domain">팀 도메인</GlossaryTooltip>(예:`https://<your-team-name>.cloudflareaccess.com`) 각 응용 프로그램에 로그인 할 필요가 있는 사용자를 방지합니다.

- [**앱 토큰**](/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/application-token/): 사용자가 도달하는 각 응용 프로그램에 대한 생성. 이 토큰은 보호 된 도메인의 쿠키로 저장됩니다 (예를 들어,`https://jira.site.com`)와 사용될지도 모릅니다[자주 묻는 질문](/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/validating-json)당신의 근원에.

### Multi-domain 응용

사이트맵 Access는 단일 도메인을 보호하고 관리 할 수 있습니다.[자체 호스팅 응용](/cloudflare-one/access-controls/applications/http-apps/self-hosted-public-app/). 사용자가 한 도메인에 성공적으로 인증 한 후, 액세스는 자동으로 문제`CF_Authorization`같은 액세스 응용 프로그램에 다른 도메인에 갈 때 쿠키. 이것은 사용자가 다중 도메인 응용 프로그램에 한 번 인증해야합니다.

5개 이하 도메인을 가진 접근 신청을 위해, 접근은 일련의 리디렉션을 통해 모든 것을 위한 쿠키를 전제할 것입니다. 사용자가 그 하위 도메인을 명시적으로 방문하지 않은 경우에도 다른 하위 도메인에서 데이터를 검색 할 수있는 단일 페이지 애플리케이션 (SPAs)을 허용합니다. 쿠키를 설정할 수 없습니다. 와일드 카드드 서브도메인을 위해, 콘크리트 하위도메인을 리디렉션하는 것을 알 수 없습니다. (Wildcarded paths are allowed).

액세스 응용 프로그램이 5 개 이상의 도메인을 가지고 있다면 액세스는 모든 쿠키를 미리 설정하지 않습니다. 쿠키는 사용자가 각 도메인을 방문할 때만 발급됩니다. 이 제한은 사용자 경험에 영향을 미칠 수있는 지연 문제를 방지하는 것입니다.

## 쿠키 설정

사이트맵 액세스는 인증된 사용자에 대한 액세스에 의해 생성 된 브라우저 쿠키에 추가 될 수있는 옵션 보안 설정을 제공합니다.

- [관련사이트](#samesite-attribute)

이 설정을 활성화하려면:

1. 내 계정[사이트맵 한국어](https://one.dash.cloudflare.com), 이동**액세스 제어** > **이름 \***.

2. 구성하고 선택하려는 응용 프로그램을 찾습니다**설정하기**.

5. 제품정보**자주 묻는 질문**.

### SameSite 속성

더 보기[`SameSite`](https://web.dev/samesite-cookies-explained/)쿠키의 정의된 사이트가 브라우저에서 요청한 사이트와 일치하면 쿠키를 제한합니다. 이것에 대한 보호 추가[크로스 사이트 요청 forgery (CSRF)](https://en.wikipedia.org/wiki/Cross-site_request_forgery).

selector 옵션은:

- **이름 \***- 쿠키는 cross-origin 요청을 포함하여 모든 컨텍스트에서 전송됩니다.
- **프로젝트**- 쿠키는 최상위 네비게이션으로 전송되며 제3자 웹사이트에서 시작된 GET 요청으로 전송됩니다.
- **사이트맵**- 쿠키는 제3자 웹사이트에서 시작된 요청과 함께 전송되지 않습니다.

더 알아보기[Mozilla 문서](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie#samesitesamesite-value)더 많은 정보.

:::카트로션

당신이 받는 경우에`ERR_TOO_MANY_REDIRECTS`오류, 확인`SameSite`설정은 없음 또는 Lax로 설정됩니다. 설정하기`SameSite`Strict에 설정은 너무 많은 리디렉션에서 발생할 수 있습니다.

:::

#### SameSite를 사용하지 않을 때

지원되지 않음`SameSite`특정 응용 프로그램의 허가 쿠키에 의존하는 추가 사이트 또는 응용 프로그램이 있다면 제한.

### 사이트맵

더 보기`HttpOnly`flag는 Cross-Site Scripting (XSS) 공격의 likelihood를 줄이기 위해 클라이언트 측 스크립트에 액세스하는 쿠키를 방지하는 쿠키 속성입니다. 이 플래그는 기본적으로 활성화됩니다.

#### HttpOnly를 사용하지 않을 때

지원되지 않음`HttpOnly`이름:

- 비범성 기반 도구에 대한 액세스 응용 프로그램을 사용하고 있습니다 (SSH 또는 RDP와 같은).
- 액세스에 의해 생성 된 사용자의 쿠키에 액세스 할 수있는 소프트웨어가 있습니다.

### 회사 소개

관련 쿠키 (`CF_Binding`)는 사용자가 성공적으로 정정할 때 발행된 선택적인 쿠키입니다. 묶음 쿠키는 사용자의 브라우저에 의해 전송되며 특정 응용 프로그램에 묶음`CF_Authorization`사이트 맵 이 쿠키는 Cloudflare의 네트워크에서 벗겨지며 원래 서버로 전달되지 않습니다.

개인 정보 보호 정책`CF_Authorization`가능한 악의적인 근원에서 쿠키. 요청이 Cloudflare의 네트워크에 도착하면 예상되는 바인딩 쿠키없이 Cloudflare가 거부됩니다.`CF_Authorization`사이트 맵

### 쿠키 경로

Cookie Path Attribute는 애플리케이션의 경로 URL을 추가합니다.`CF_Authorization`제품 정보 사용할 때, 로그인한 사용자`example.com/path1`액세스 권한`example.com/path2`. 비활성화시`CF_Authorization`쿠키는 도메인 및 하위 도메인에만 적용됩니다.

## 브라우저에서 타사 쿠키 허용

기본적으로 일부 브라우저는 개인 브라우징 모드에서 모든 타사 쿠키를 차단합니다.`CF_Authorization`사이트 맵 XHR 요청은 개인 창에서 작동하려면 응용 프로그램을 면제해야합니다.<GlossaryTooltip term="team domain">팀 도메인</GlossaryTooltip>브라우저의 추적 보호 시스템에서.

접근 신청을 위한 제삼자 쿠키를 가능하게 하기 위하여:

<Details header="크롬">
  1. 오시는 길**계정 설정** > **개인정보 및 보안** > **쿠키 및 기타 사이트 데이터**.
  2. 이름 \***항상 쿠키를 사용할 수있는 사이트**, 다음 URL을 추가:
     - 액세스 응용 프로그램의 호스트 이름 (예를 들어,`https://jira.site.com`)
     - `https://<your-team-name>.cloudflareaccess.com`
</Details>

<Details header="스낵 바">
  1. 오시는 길**스낵 바** > **계정 설정** > **제품 정보**.
  2. 옵션 정보**모든 쿠키**.

<Details header="파이어 폭스">

  3. 제품정보**자주 묻는 질문**.
  4. 액세스 응용 프로그램의 URL을 입력 (예를 들어,`https://jira.site.com`) 및 선택**지원하다**.
  5. 이름 \*`https://<your-team-name>.cloudflareaccess.com`선택하기**지원하다**.
