사이트맵 액세스는 정체성 집계 또는 프록시로 행동하여 웹 응용 프로그램을 보안 할 수 있습니다. 기존 ID 공급자 (IdPs), 장치 자세 공급자 및 신호를 사용할 수 있습니다.[다른 규칙](/cloudflare-one/access-controls/policies/#selectors)신청에 로그인할 수 있는 제어.

![사이트맵 액세스는 응용 프로그램에 액세스 권한을 부여하기 전에 사용자의 정체성을 확인합니다.](~/assets/images/cloudflare-one/applications/diagram-saas.jpg)

다음 유형의 웹 응용 프로그램을 보호 할 수 있습니다 :

- [**SaaS 응용**](/cloudflare-one/access-controls/applications/http-apps/saas-apps/)귀하의 팀에 의해 호스팅되지 않습니다. 예시에는 Salesforce 및 Workday가 포함됩니다. SaaS 애플리케이션을 확보하려면 SaaS 애플리케이션의 SSO 구성으로 Cloudflare Access를 통합해야 합니다.

- **셀프 호스팅 응용**당신의 자신의 환경에서 호스트하는 내부 응용 프로그램입니다. Atlassian Suite 또는 애플리케이션과 같은 데이터 센터 버전이 될 수 있습니다. 자체 호스팅 응용 프로그램에 대한 설정 요구 사항은 응용 프로그램이 인터넷에 공개적으로 액세스하거나 개인 네트워크에서 사용자에게 제한되는지 여부에 따라 달라집니다.
  - [**Public hostname 응용 프로그램**](/cloudflare-one/access-controls/applications/http-apps/self-hosted-public-app/)공개 DNS 레코드가있는 웹 응용 프로그램입니다. 인터넷에서 누구나 브라우저에서 URL을 입력하고 Cloudflare Access를 통해 인증하여 응용 프로그램에 액세스 할 수 있습니다. 공공 웹 사이트에 대한 보안 액세스는 Cloudflare DNS[전체 설정](/dns/zone-setups/full-setup/)또는[부분 CNAME 설정](/dns/zone-setups/partial-setup/).
  - [**Private Network 애플리케이션**](/cloudflare-one/access-controls/applications/non-http/self-hosted-private-app/)공개 DNS 레코드가 없습니다, 그들은 공공 인터넷에서 접근 할 수없는 의미. 개인 IP 또는 개인 호스트 이름을 사용하여 연결하려면 Cloudflare Gateway를 통해 사용자의 트래픽이 경로를해야합니다. 선호하는 방법은 사용자의 장치에 WARP 클라이언트를 설치하는 것입니다, 그러나 당신은 또한 장치 소통량을 전달할 수 있었습니다[네트워크 위치](/cloudflare-wan/)또는 같은 Agentless 옵션을 사용하십시오.[PAC 파일](/cloudflare-one/networks/resolvers-and-proxies/proxy-endpoints/)또는[Clientless 웹 고립](/cloudflare-one/remote-browser-isolation/setup/clientless-browser-isolation/).

- [**모형 Context 의정서 (MCP) 서버**](/cloudflare-one/access-controls/ai-controls/)웹 응용 프로그램은 생성 AI 도구를 사용하여 비즈니스 응용 분야에서 데이터를 읽고 작성합니다. 예를 들어 Salesforce는[MCP 서버](https://github.com/salesforcecli/mcp)개발자는 GitHub Copilot 또는 기타 AI 코드 편집기를 사용하여 Salesforce tenant의 리소스와 상호 작용합니다.

- [**Cloudflare 대시보드 SSO**](/fundamentals/manage-members/dashboard-sso/)Cloudflare 대시보드를 위한 SSO 설정을 관리하는 SaaS 애플리케이션의 특수 타입이며, 관리자 편집을 위한 제한된 권한이 있습니다.
