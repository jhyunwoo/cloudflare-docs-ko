## WARP 클라이언트

사용자는 Cloudflare WARP 클라이언트를 장치에서 설치하고 Zero Trust 조직에 등록하여 연결할 수 있습니다. 원격 장치는 사용자의 개인 네트워크에있을 때 응용 프로그램에 연결합니다. 기본적으로, 모든 장치가 귀하의 조직에 등록하면 액세스 정책 또는 게이트웨이 방화벽 규칙에 의해 보호되지 않는 한 개인 경로에 액세스 할 수 있습니다. 응용 프로그램을 보안하려면, 당신은 할 수 있습니다[자체 호스팅 응용 프로그램 생성](/cloudflare-one/access-controls/applications/non-http/self-hosted-private-app/)개인 IP 범위, 포트 범위 및 / 또는 호스트 이름 및 빌드[오시는 길](/cloudflare-one/access-controls/policies/)특정 사용자를 허용하거나 차단합니다.

사용자가 네트워크 내에서 특정 인프라 서버에 액세스하는 방법을 정의하고 싶다면,[인프라 응용](/cloudflare-one/access-controls/applications/non-http/infrastructure-apps/)인프라에 대한 접근. 인프라에 대한 액세스는 사용자가 비-HTTP 애플리케이션에 액세스하는 방법을 통해 제어 및 가시성을 추가합니다.

- 특정 서버에 액세스하고 사용자가 그 서버에 액세스 할 수있는 방법을 정확히 가지고있는 지위에 대한 벌금에 담긴 정책.
- SSH 키를 짧은 라이브 인증서를 사용하여 사용자를 인증합니다.
- SSH 명령은 저장 서비스 또는 SIEM 솔루션으로 로그인합니다.[다운로드](/cloudflare-one/insights/logs/logpush/).

## Clientless 액세스

Clientless 액세스 방법은 WARP 클라이언트를 배포하거나 클라이언트를 설치할 수없는 조직에 적합합니다. Clientless 액세스는 Cloudflare에 도메인을 내장하고 서버가 도달 할 수 있도록 public hostname을 구성해야합니다. 명령 로깅은 지원되지 않습니다.

### 브라우저 렌더링 터미널

Cloudflare의[브라우저 기반 터미널](/cloudflare-one/access-controls/applications/non-http/browser-rendering/)사용자는 SSH, RDP 및 VNC를 어떤 구성없이 연결할 수 있습니다. 사용자가 public hostname URL(예를 들어,`https://ssh.example.com`) 액세스 자격 증명과 로그인, Cloudflare는 브라우저에서 터미널을 렌더링합니다. RDP 연결을 위해 사용자는 Cloudflare Access에 의해 인증된 Windows 사용자 이름과 암호를 사용하여 Windows 서버에 인증해야 합니다.

### 클라이언트 측 cloudflared

사용자는 설치하여 응용 프로그램에 로그인 할 수 있습니다.`cloudflared`장치에서 hostname-specific 명령어를 실행합니다. 더 많은 정보를 원하시면, 참조[Cloudflared 인증](/cloudflare-one/access-controls/applications/non-http/cloudflared-authentication/).
