인프라에 대한 액세스는 사용자가 개별 서버, 클러스터, 또는 데이터베이스에 액세스하는 방법을 통해 과립 제어 할 수 있습니다. Cloudflare Access에 인프라 애플리케이션을 추가함으로써 사용자는 리소스에 정통하고 포트, 프로토콜 및 사용자 이름을 지정하는 방법을 구성할 수 있습니다. 액세스 및 명령 로그는 규제 준수를 보장하고 보안 침해의 경우 사용자 활동의 감사를 허용합니다.

:::참조
현재 인프라에 대한 접근은 지원[사이트맵](/cloudflare-one/networks/connectors/cloudflare-tunnel/use-cases/ssh/ssh-infrastructure-access/). 다른 의정서를 사용하기 위하여,[Self-hosted 개인 응용 프로그램 추가](/cloudflare-one/access-controls/applications/non-http/self-hosted-private-app/). 브라우저 기반 SSH, RDP 또는 VNC를 위해, 참조[브라우저 렌더링 터미널](/cloudflare-one/access-controls/applications/non-http/browser-rendering/).
:::

## 5. 사용자로 연결

사용자는 선호하는 클라이언트 소프트웨어를 사용하여 대상의 IP 주소에 연결합니다. 사용자는 장치에 WARP로 로그인해야하지만 다른 시스템 구성이 필요하지 않습니다. 선택적으로 구성할 수 있습니다.[개인 DNS 해결자](/cloudflare-one/traffic-policies/resolver-policies/)대상의 개인 호스트 이름에 연결을 허용.

### 다른 VNET에 연결

다른 VNETS에 있는 표적에 연결하기 위하여, 사용자는 필요로 할 것입니다[연결된 가상 네트워크를 전환](/cloudflare-one/networks/connectors/cloudflare-tunnel/private-net/cloudflared/tunnel-virtual-networks/#connect-to-a-virtual-network)WARP 클라이언트에서.

:::참조
사용자가 VNET-A의 대상에 연결되고 VNET-B의 대상에 연결해야 할 경우 VNET-A 내에서 대상에 기존의 연결을 차단하지 않습니다. 현재, 연결은 VNETs 사이에서 유지됩니다.

사용자는 사용할 수 있습니다`warp-cli`대상의 목록을 표시할 수 있습니다. WARP 장치에서 터미널을 열고 다음 명령을 실행하십시오.

<Render file="tunnel/warp-cli-target-list" product="cloudflare-one" />

선택적으로 플래그를 추가하여 출력을 필터링 할 수 있습니다. 예를 들면:

```sh
warp-cli target list --attribute hostname=do-target --username root
```

모든 사용 가능한 필터 보기, 유형`warp-cli target list --help`.

## 사용자의 세션

모든 인프라 대상에 대한 사용자의 액세스를 수정하려면, 당신은 할 수 있습니다[Zero Trust에서 사용자 수정](/cloudflare-one/access-controls/access-settings/session-management/#per-user)또는 장치 수정. Cloudflare는 현재 특정 대상의 사용자 세션을 수정하지 않습니다.
