Kandji는 사용자 정의 앱으로 Cloudflare WARP를 배포합니다. Kandji가 사용자 정의 앱을 배포하는 방법 개요의 경우, 참조[지식 베이스](https://support.kandji.io/custom-apps-overview).

## 맥 OS

가장 간단한 배포를 위해 Kandji는 Cloudflare WARP의 사용자 알림을 활성화하고 개인 정보 P참고 자료 정책 제어 ([자료: PPPC](https://support.kandji.io/create-a-privacy-preferences-policy-control-profile)) Full Disk Access가 있습니다.

1. 다운로드[회사 소개](https://github.com/kandji-inc/support/blob/64e0d8c8fa393d0967d2519aea60b5c834754563/Configuration%20Profiles/cloudflare_warp.mobileconfig).

2. 사용자 정의 프로파일 추가 :
   1. 오시는 길**관련 기사** > **새소식** > **Library 아이템 추가** > **주문 단면도**.
   2. 제품정보**추가 및 구성**.

3. 사용자 정의 프로파일 구성 :

   1. 이름 \***이름 \***&#xC0AC;용자 지정 구성 프로파일에 대 한.
   2. 사용자 정의 프로파일을 테스트 Blueprint로 할당하십시오.
   3. 설치하기**장치 가족**으로*한국어*.
   4. 다운로드`cloudflare_warp.mobileconfig`파일 이전 다운로드.
   5. 사용자 정의 프로파일을 저장합니다.

   ![Kandji에 있는 WARP를 위한 주문 단면도 형성](~/assets/images/cloudflare-one/connections/custom-profile.png)

4. 사용자 지정 앱 추가:
   1. 오시는 길**관련 기사** > **새소식** > **Library 아이템 추가** > **주문 앱**.
   2. 제품정보**추가 및 구성**.

5. 사용자 지정 앱 구성:
   1. 사용자 정의 앱 이름.

   2. 프로필에 사용된 동일한 테스트 Blueprint에 사용자 지정 앱을 할당합니다.

   3. 제품정보**감사 및 시행**임명 유형으로.

   4. 제출하기**감사 및 Enforce 스크립트** [이름 \*](#audit-and-enforce-script)그리고 붙여넣기**감사 Script**텍스트 필드.

   5. 최소 앱 버전을 시행하려면 업데이트**ENFORCED 버전**버전 번호와 감사 스크립트의 변수는 (예를 들어,`1.5.207.0`).

      **ENFORCED 버전**을 빈 값(`""`)으로 두면 감사 스크립트는 버전을 확인하지 않고, **Applications** 폴더 안에 Cloudflare WARP 앱이 존재하는지만 확인합니다. 자세한 내용은 스크립트 주석을 참고하세요.

   6. 내 계정**자주 묻는 질문**섹션, 선택**Installer 패키지**.

   7. 이름 \***Installer 패키지**, 업로드`Cloudflare_WARP_<VERSION>.pkg`파일. 이미 설치 패키지가 없다면,[다운로드](/cloudflare-one/team-and-resources/devices/warp/download-warp/#macos).

   8. 제품정보**제품 정보**.

Cloudflare WARP가 설치되었는지 확인하려면 앱을 선택하십시오.**주문 앱**도서관과 전망**주요연혁**탭.

return_installed_app_version() {
    #현재 설치된 앱 버전 반환
    #
    #$1 - 신청의 이름입니다.
    local app_name="$1"
    local installed_version="" #로컬 변수를 초기화

    #애플리케이션 디렉토리의 내부에 앱을 찾습니다.
    #3 단계까지 모든 하위 디렉토리.
    local find_app="$(/usr/bin/find /Applications -maxdepth 3 -name $app_name)"
    local ret="$?"

    #앱이 설치되면 확인
    if [[ "$ret" -eq 0 ]] && [[ -d "$find_app" ]] &&
        [[ "$app_name" == "$(/usr/bin/basename $find_app)" ]]; then
        #이전 명령이 true를 반환하고 반환된 객체는 디렉토리입니다.
        #그리고 우리가 찾고있는 앱 이름은 앱 이름과 동일하다.
        #찾기 명령에 의해 발견.

        #설치된 앱 버전을 얻고 "-"를 "로 대체합니다."
        installed_version=$(/usr/bin/defaults read \
            "$find_app/Contents/Info.plist" CFBundleShortVersionString |
            /usr/bin/sed "s/-/./g")

    else
        installed_version="None"
    fi

    echo "$installed_version"
}

#프로파일 변수는 prefix에 일치하는 프로파일의 배열로 설정됩니다.
#PROFILE PAYLOAD ID PREFIX 변수
profiles=$(/usr/bin/profiles show | grep "$PROFILE_PAYLOAD_ID_PREFIX" | sed 's/.*\ //')

#PROFILE PAYLOAD ID PREFIX가 발견되지 않은 경우, 다음 에이전트가 실행될 때까지 0을 종료합니다.
if [[ ${#profiles[@]} -eq 0 ]]; then

    echo "Waiting until the profile is installed before proceeding ..."
    echo "Will check again at the next Kandji agent check-in ..."

else
    echo "Profile prefix $PROFILE_PAYLOAD_ID_PREFIX present ..."

    #애플리케이션 디렉토리의 내부에 앱을 찾습니다.
    #3 단계까지 모든 하위 디렉토리.
    find_app="$(/usr/bin/find /Applications -maxdepth 3 -name $APP_NAME)"
    ret="$?"

    #앱이 설치되면 확인
    if [[ "$ret" -eq 0 ]] && [[ -d "$find_app" ]] &&
        [[ "$APP_NAME" == "$(/usr/bin/basename $find_app)" ]]; then

        #버전 번호에서 기간을 제거하여 비교를 할 수 있습니다.
        installed_version="$(return_installed_app_version $APP_NAME | /usr/bin/sed 's/\.//g')"

        #버전 번호에서 기간을 제거하여 비교를 할 수 있습니다.
        enforced_version="$(echo $ENFORCED_VERSION | /usr/bin/sed 's/\.//g')"

        #install version이 강제적인 경우를 확인합니다. 그런 다음
        #1번 출구에서 설치 프로세스를 시작합니다.
        if [[ "$installed_version" -lt "$enforced_version" ]]; then

            echo "Installed app version: $installed_version"

            echo "No need to run the installer ..."
            exit 0
        fi

    else
        echo "$APP_NAME was not found in the Applications folder ..."
        echo "Need to install $APP_NAME ..."
        exit 1

    fi

fi

exit 0
