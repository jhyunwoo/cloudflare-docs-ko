## 클라이언트 Orchestration API

WARP 클라이언트는 Cloudflare에 등록 또는 조정 변화 같이 가동을 위한 갱도의 외부 표준 HTTPS 연결을 통해 연결합니다. 이러한 작업을 수행하려면 다음 IP 및 도메인을 허용해야합니다.

<Render file="warp/client-orchestration-ips" product="cloudflare-one" />

아직`zero-trust-client.cloudflareclient.com`·`notifications.cloudflareclient.com`다른 IP 주소로 해결할 수 있습니다, WARP는 상기 나열된 IPs와 해결 된 IP를 overrides. 연결 문제를 방지하려면 위의 IP가 방화벽을 통해 허용된다는 것을 보장합니다.

<Details header="파일 형식 높은 필요조건">
  FedRAMP에서 WARP 배포 높은 환경, 방화벽을 통해 IP 및 도메인의 다른 설정을 허용해야합니다.

  - IPv4 API 엔드포인트:`162.159.213.1`·`172.64.98.1`
  - IPv6 API 엔드포인트:`2606:54c1:11::`·`2a06:98c1:4b::`
  - SNIs:`api.devices.fed.cloudflare.com`·`notifications.devices.fed.cloudflare.com`
</Details>

## 연결 체크

WARP 연결을 설치의 일환으로 클라이언트는 WARP 갱도의 안쪽 그리고 외부에 연결 체크를 실행합니다.

### 외부 갱도

클라이언트는 WARP 갱도의 외부 일반적인 인터넷 연결을 확인하기 위하여 뒤에 오는 목적지에 연결합니다. 이 IP 및 도메인이 방화벽 허용 목록에 있는지 확인하십시오.

- `162.159.197.3`
- `2606:4700:102::3`
- `engage.cloudflareclient.com`: 클라이언트는 항상 IP에 직접 요청을 보낼 것입니다[WARP 진입 IPv4 또는 IPv6 범위](/cloudflare-one/team-and-resources/devices/warp/deployment/firewall/#warp-ingress-ip)(또는 당신[`override_warp_endpoint`](/cloudflare-one/team-and-resources/devices/warp/deployment/mdm-deployment/parameters/#override_warp_endpoint)설정). 요청은 프록시 서버를 사용하지 않습니다.

아직`engage.cloudflareclient.com`다른 IP 주소로 해결할 수 있습니다, WARP는 상기 나열된 IPs와 해결 된 IP를 overrides. 연결 문제를 방지하려면 위의 IP가 방화벽을 통해 허용된다는 것을 보장합니다.

### 안쪽 갱도

WARP 클라이언트는 WARP 갱도의 안쪽에 연결을 확인하기 위하여 뒤에 오는 목적지에 연결합니다:

- `162.159.197.4`
- `2606:4700:102::4`
- `connectivity.cloudflareclient.com`

이 체크는 터널 내부에서 발생하므로 이러한 IP 및 도메인을 방화벽 허용 목록에 추가 할 필요가 없습니다. 그러나 요청이 게이트웨이를 통과했기 때문에 게이트웨이 HTTP 또는 네트워크 정책에 의해 차단되지 않습니다.

## NEL 보고 (선택)

WARP 클라이언트는 우리의 NEL 엔드포인트에 연결을 보고합니다`a.nel.cloudflare.com`. 이것은 기술적으로 작동하지만 제대로 제외되지 않은 경우 우리의 로그에 오류가 발생합니다.

## Latency 통계 (옵션)

WARP 클라이언트는 ICMP 신호를에 생성합니다[WARP 진입 IPs](/cloudflare-one/team-and-resources/devices/warp/deployment/firewall/#warp-ingress-ip)터널 지연 검사를 실행할 때. 이것은 기술적으로 작동하지만 제대로 제외되지 않은 경우 로그에 오류가 발생합니다.

## 시간 동기화 (선택)

WARP 클라이언트는 NTP (으)로 정확한 시간을 동기화하려고 시도`UDP 123`)에[Cloudflare의 시간 서비스](/time-services/ntp/usage/)이름 \*`time.cloudflare.com`. 이것은 기술적으로 작동하지만 제대로 제외되지 않은 경우 우리의 로그에 오류가 발생합니다.

## 방화벽 규칙의 범위

### 필수 범위

조직이 현재 IP 주소, 포트 및 도메인을 통해 인바운드 / 아웃바운드 통신을 허용하지 않으면 예외를 수동으로 추가해야합니다. 플랫폼에 기반한 다음 프로세스에 대한 최소 요구 사항의 규칙:

- 윈도우:`C:\Program Files\Cloudflare\Cloudflare WARP\warp-svc.exe`
- macOS: 다음 지침에 따라 코어 네트워킹 데몬 및 GUI 구성 요소를 모두 명시적으로 허용해야합니다.

  1. 핵심 네트워킹 daemon:`/Applications/Cloudflare WARP.app/Contents/Resources/CloudflareWARP`

     이 바이너리는 번들 ID가 없으며 전체 경로를 통해 허용해야합니다.

  2. GUI 구성 요소는 MDM 또는 방화벽 공급업체의 선호 형식에 따라 다음과 같은 세 가지 식별자 중 하나를 선택합니다.

     `/Applications/Cloudflare WARP.app`(특허)

     `/Applications/Cloudflare WARP.app/Contents/MacOS/Cloudflare WARP`(특허)

     `com.cloudflare.1dot1dot1dot1.macos`(벤더 ID)

  :::카ution\[macOS 15.0에서 15.4]

  macOS Sequoia 버전 15.0에서 15.4로 변경하려면 업데이트해야 합니다.[macOS 방화벽 설정](https://support.apple.com/guide/mac-help/change-firewall-settings-on-mac-mh11783/mac)WARP 클라이언트를 허용하여 장치의 방화벽을 관리합니다. macOS의 버전은 Apple이 방화벽에서 예상치 못한 파손을 해결하기 위해 도입 된 변경 때문에 영향을 미치지 않습니다.

  WARP 클라이언트를 허용하려면 macOS Sequoia 버전 15.0을 통해 15.4의 기능을 수행하고 여전히 원치 않는 수신 트래픽을 차단하고 이러한 단계를 따르십시오.

  1. 다음을 해제[macOS 방화벽 설정](https://support.apple.com/guide/mac-help/change-firewall-settings-on-mac-mh11783/mac):
     - **모든 들어오는 연결을 차단**
     - **자동으로 내장된 소프트웨어를 통해 들어오는 연결을 받을 수 있습니다.**
     - **자동으로 다운로드된 서명 소프트웨어를 허용하여 수신된 연결을 수신**
  2. 추가하기[WARP 데몬 및 GUI 프로세스](#required-scopes)방화벽 예외 목록으로 설정하여*자주 묻는 질문*.
  3. 다른 제한은 트래픽을 수신하는 프로세스에만 예외를 허용합니다.
  4. (선택) 사용자 관리 권한을 부여하지 마십시오. 그렇지 않으면 방화벽 설정 및 예외를 수정할 수 있습니다.
     주요 특징

- 맥 OS:`/Applications/Cloudflare WARP.app`
