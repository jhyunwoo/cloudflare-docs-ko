## WARP를 연결할 수 없습니다

WARP가 붙어 있다면`Disconnected`국가 또는 자주 변경`Connected`·`Disconnected`, 이것은 클라이언트가 Cloudflare의 세계적인 네트워크에 연결을 설치할 수 없다는 것을 나타냅니다.

<div class="medium-img">
  ![WARP 클라이언트 UI의 예는 WARP에 돌릴 수 없을 때](~/assets/images/cloudflare-one/connections/warp-stuck-on-disconnected.png)
</div>

내 계정[WARP 디버그 로그](/cloudflare-one/team-and-resources/devices/warp/troubleshooting/warp-logs/), `daemon.log`일반적으로 다음과 같은 오류 중 하나 이상을 표시합니다.

- Happy Eyeball는 실패합니다:

  ```txt
  ERROR main_loop: warp::warp::happy_eyeballs: Happy eyeballs error Custom { kind: NotConnected, error: "All Happy Eyeballs checks failed" }
  ```

- 다른 많은 체크 밖으로 타이밍:

  ```txt
  ERROR warp::warp::connectivity_check: DNS check failed error=ResolveError { kind: Timeout }
  WARN warp::warp::connectivity_check: Tunnel trace failed request::Error { kind: Request, url: Url { scheme: "https", cannot_be_a_base: false, username: "", password: None, host: Some(Domain("connectivity.cloudflareclient.com")), port: None, path: "/cdn-cgi/trace", query: None, fragment: None }, source: TimedOut }
  ```

이 문제가 발생하는 이유는 다음과 같습니다.

### 제삼자 서비스는 WARP를 막는 입니다

제 3 자 서비스 ( 하드웨어 또는 소프트웨어 방화벽, 라우터, MDM / 그룹 정책 구성 또는 기타 네트워킹 인터페이스와 같은) 연결에서 WARP를 차단하는 장소에 보안 정책을 가질 수 있습니다.

#### 제품정보

제3자 서비스 구성[WARP에 의해 요구되는 IP 주소](/cloudflare-one/team-and-resources/devices/warp/deployment/firewall/).

### 제3자 VPN은 WARP와 인터퍼링

우리가 VPNs에서 WARP와 방해를 보는 가장 일반적인 장소는:

- **교통 여정의 통제:**&#xB0B4; 계정`daemon.log`, 당신은 큰 숫자의 라우팅 테이블 변경을 볼 수 있습니다. 예를 들어,

  ```txt
  DEBUG warp::warp_service: Routes changed:
      Added; Interface: 8; Destination: 10.133.27.201/32; Next hop: 100.64.0.2;
      Added; Interface: 8; Destination: 10.133.27.202/32; Next hop: 100.64.0.2;
  DEBUG warp::warp_service: Routes changed:
      Added; Interface: 8; Destination: 10.133.27.203/32; Next hop: 100.64.0.2;
      Added; Interface: 8; Destination: 10.133.27.204/32; Next hop: 100.64.0.2;
  DEBUG warp::warp_service: Routes changed:
      Added; Interface: 8; Destination: 10.133.27.205/32; Next hop: 100.64.0.2;
  ```

  이것은 제 3 자 VPN이 라우팅 테이블을 제어하기위한 WARP 싸움임을 나타냅니다.

- **DNS의 제어:**&#xB0B4; 계정`daemon.log`, 당신은이 경고에 따라 DNS 변경의 큰 수를 볼 것 이다:

  ```txt
  WARN main_loop: warp::warp_service: Reinforcing DNS settings. Is something else fighting us?
  ```

  daemon은 다른 프로세스가 UDP 및 TCP 소켓에 이미 경계를 가질 수도 있습니다.

  ```txt
  WARN warp::warp: Unable to bind local UDP socket error=Os { code: 48, kind: AddrInUse, message: "Address already in use" } sockaddr=127.0.2.2:53
  WARN warp::warp: Unable to bind local TCP socket error=Os { code: 48, kind: AddrInUse, message: "Address already in use" } sockaddr=127.0.2.2:53
  ```

VPN이 문제의 소스임을 확인하려면, 일시적으로 제거되지 않음 (무선 또는 차단되지 않음) VPN.

#### 제품정보

1. VPN에서 모든 DNS 집행을 비활성화합니다. WARP는 기본 인터페이스에서 기본 및 보조 DNS 서버를 터치하는 마지막 클라이언트이어야합니다.
2. 내 계정[모델 번호: Cloudflare 한국어](https://one.dash.cloudflare.com/), 만들기[분할 터널 규칙](/cloudflare-one/team-and-resources/devices/warp/configure-warp/route-traffic/split-tunnels/)VPN 서버를 제외하고 (예를 들어,)`vpnserver.3rdpartyvpn.example.com`).
3. VPN을 구성하면 내부 리소스에 대한 경로가 포함되어 있습니다. VPN 경로가 경로로 오버랩하지 않도록하십시오.[WARP 갱도에서 포함되는](/cloudflare-one/team-and-resources/devices/warp/configure-warp/route-traffic/split-tunnels/).

더 많은 정보를 원하시면,[- 연혁](/cloudflare-one/team-and-resources/devices/warp/deployment/vpn/)WARP 클라이언트와 함께 VPN을 실행하려면.

### ISP 또는 국가 차단 WARP

일부 국가는 VPN 또는 VPN과 같은 소프트웨어의 사용을 명시적으로 차단하여 트래픽을 암호화합니다. 이 블록은 종종 의도적으로 시행되고 때로는 성공적인 연결을 볼 수 있습니다.

국가가 WARP 트래픽 차단 될 수 있다면 ISP에 문의하십시오.

### (맥/리눅스) 기기의`/etc/resolv.conf`파일에는 잘못된 문자가 있습니다

WARP는 파싱할 수 없습니다`resolv.conf`잘못된 hostname을 포함하는 파일. 내 계정`daemon.log`, 당신은 볼 것이다`unrecognized char`경고:

```txt
WARN main_loop: warp::warp_service: Tunnel connection experienced error error=Custom { kind: Other, error: ProtoError { kind: Msg("unrecognized char:  ") } }
```

#### 제품정보

1. 자주 묻는 질문`/etc/resolv.conf`당신의 장치에 파일.
2. 내 계정`search`지시어와 같은 잘못된 URL 문자를 확인한다.`!@#$%^&*()<>?`.
3. 잘못된 줄을 제거하고 DNS 서비스에 대한 WARP 및 게이트웨이에 의존합니다.

## WARP에 돌리고 더 이상 인터넷을 찾을 수 없습니다

만약 WARP 쇼로`Connected`하지만 당신은 어떤 웹 사이트 또는 내부 리소스에 도달 할 수 없습니다, 이것은 다음 구성 문제 중 하나로 인해 가능성이.

### Gateway 방화벽 정책은 트래픽 차단

misconfigured Gateway 방화벽 정책은 제한되는 일부 또는 모든 사이트에 트래픽에서 발생할 수 있습니다.

#### 제품정보

<Render file="gateway/debugging-policies" product="cloudflare-one" />

### 장치는 설치 된 루트 인증서가 없습니다.

설치 및 신뢰[루트 CA](/cloudflare-one/team-and-resources/devices/user-side-certificates/)Browser Isolation과 같은 고급 보안 기능을 활성화하는 데 필요한 단계입니다.[TLS 해독](/cloudflare-one/traffic-policies/http-policies/tls-decryption/), AV 스캐닝 및 장치 자세.

루트 CA가 장치에 설치되지 않은 경우, 모든 웹 사이트에 위탁되지 않은 인증서 경고를 볼 수 있습니다. 예제 경고 포함`Certificate not trusted`, `Not trusted identity`또는`SSL Error`.

#### 제품정보

[Cloudflare 인증서 설치](/cloudflare-one/team-and-resources/devices/user-side-certificates/manual-deployment/)모든 장치, 또는[자신의 인증서를 업로드](/cloudflare-one/team-and-resources/devices/user-side-certificates/custom-certificate/)Cloudflare에.

:::참조

점점 더 많은 응용 프로그램 ( 브라우저 포함) 자신의 인증서 상점에 의존. 루트 인증서를 보장 할뿐만 아니라 장치 수준에서 신뢰할 수 있습니다, 당신은 또한 필요 할 수 있습니다[개별 응용 프로그램에 인증서 추가](/cloudflare-one/team-and-resources/devices/user-side-certificates/manual-deployment/#add-the-certificate-to-applications). 예를 들어, Linux에서 Firefox를 사용하려면 시스템 및 Firefox에서 인증서를 설치해야합니다.

:::

### 제3자 보안 제품은 Gateway와 interfering

WARP는 게이트웨이에 전송된 트래픽에 TLS 해독을 수행하기 위해 타사 DLP 또는 프록시 서비스를 허용하지 않습니다.

문제를 진단하기 위해, 이동`https://zero-trust-client.cloudflareclient.com/v0/client_config`인증서를 확인하면 HTTPS 트래픽이 서명됩니다. 인증서가 조직 또는 타사 서비스에 의해 발급되면 타사 서비스는 WARP 트래픽에 TLS 해독을 수행하고 우리가 신뢰하지 않는 인증서로 재 서명합니다.

#### 제품정보

타사 보안 제품에서 HTTPS 검사 및 TLS 해독을 비활성화하십시오.[WARP IP 주소](/cloudflare-one/team-and-resources/devices/warp/deployment/firewall/).

### Docker 콘테이너는 DNS 해결책을 실패합니다

WARP를 사용하고 Microsoft 하드웨어의 Docker 컨테이너 내부 CI/CD 파이프라인을 실행하면 egress IP, 컨테이너의`/etc/resolv.conf`파일이 주사될 수 있습니다.[IP 주소를 가진 사용자 정의 nameserver`168.63.129.16`](https://learn.microsoft.com/en-us/azure/virtual-network/what-is-ip-address-168-63-129-16)(Azure 인프라에 따라 다름)
더 보기`168.63.129.16`IP 주소는 Azure VM에만 접근하고 Cloudflare WARP 터널을 통해 경로를 통과 할 때 컨테이너의 트래픽을 발생시킵니다.

#### 제품정보

이 문제를 해결하려면 Azure-specific nameserver IP를 제외해야 합니다.`168.63.129.16`) WARP 갱도를 통해서 노선으로. 더 알아보기[분할 터널](/cloudflare-one/team-and-resources/devices/warp/configure-warp/route-traffic/split-tunnels/#change-split-tunnels-mode)Azure-specific IP를 제외한 지침을 따르십시오.

## 특정 앱 또는 웹 사이트에 연결할 수 없습니다.

아래는 WARP 블록에서 특정 응용 프로그램을로드하는 가장 일반적인 이유입니다.

### TLS Decryption는 활성화되고 app 또는 위치는 증명서를 핀으로 꼿습니다

일부 응용 프로그램은 SSL 검사를 지원하지 않거나 그렇지 않으면[TLS 해독과 호환](/cloudflare-one/traffic-policies/http-policies/tls-decryption/#inspection-limitations). Gateway는[인증서 pinning 수행에 알려진 응용 프로그램의 목록](/cloudflare-one/traffic-policies/application-app-types/#do-not-inspect-applications).

#### 솔루션 (앱이 개인 인증서 저장소가있는 경우)

Firefox, Docker, Python 및 npm와 같은 응용 프로그램은 자신의 인증서 저장소에 의존하고 Cloudflare 루트 인증서는 각각 신뢰할 수 있어야합니다.

더 알아보기[우리의 지시](/cloudflare-one/team-and-resources/devices/user-side-certificates/manual-deployment/#add-the-certificate-to-applications)일반적인 응용 프로그램에 루트 인증서를 추가합니다. 응용 프로그램에 대한 우리의 목록, 인터넷 검색 시도`<app-name> proxy support`또는`<app-name> proxy certificate`.

#### 해결책 (마지막 리조트)

신청에 인증서를 설치할 수 없는 경우, 생성[Inspect 정책 없음](/cloudflare-one/traffic-policies/http-policies/#do-not-inspect)Gateway 검사에서 응용 프로그램을 제외합니다.

### Gateway 방화벽 정책은 앱 또는 사이트 차단

게이트웨이 DNS, 네트워크, 또는 HTTP가 실수로 포트, IP 또는 도메인을 차단할 수 있습니다.

#### 제품정보

### Split Tunnel 설정은 앱 또는 사이트에 대한 misconfigured

일부 응용 프로그램은 내부 또는 WARP 터널의 모든 외부를 흐르는 트래픽을 요구합니다. 예를 들어 AirDrop을 사용하거나 로컬 프린터와 통신하기 위해 트래픽은 터널 밖에서는 안됩니다. Microsoft Teams와 같은 응용 프로그램은 제대로 작동하기 위해 모든 Microsoft Teams 트래픽은 터널 내부 또는 터널 내부에 완전히 있어야합니다.

#### 제품정보

1. 애플리케이션에 필요한 IP 주소 및/또는 도메인을 정의합니다. 일반 인터넷 검색 조건 포함`<app-name> split tunnel list`, `<app-name> allow list`, 또는`<app-name> firewall ips`.
2. 내 계정[모델 번호: Cloudflare 한국어](https://one.dash.cloudflare.com/), 너의 것[분할 터널 설정](/cloudflare-one/team-and-resources/devices/warp/configure-warp/route-traffic/split-tunnels/).
3. 응용 프로그램에 따라 필요한 IP 및 / 또는 도메인의 모든 제외. Microsoft 응용 프로그램을 위해, 우리는 제공합니다[원클릭 액션](/cloudflare-one/team-and-resources/devices/warp/configure-warp/warp-settings/#directly-route-microsoft-365-traffic)모든 Microsoft 365 IP를 제외한다.
