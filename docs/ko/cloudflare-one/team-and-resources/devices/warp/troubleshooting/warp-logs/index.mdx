#### 같은 로그의 여러 버전

더 보기`warp-debugging-info`폴더는 같은 로그의 여러 버전을 포함 할 수 있습니다.`daemon.log`, `daemon.1.log`·`daemon.2.log`. 로그는 매우 오래 얻을 수 있기 때문에, 그들은 매일 회전 또는 특정 크기를 초과 할 때.

- `<logfile>.log`현재 로그입니다. 이것은 거의 항상 로그 당신이 찾고 있어야, 그것은 당신이 하루에 발생 이벤트를 보여줍니다`warp-diag`명령.
- `<logfile>.1.log`이전 날의 이벤트를 보여줍니다.
- `<logfile>.2.log`2 일 전에 이벤트를 보여줍니다.

:::참조

타임스탬프 같은 로그`daemon.log`, 가장 최근의 이벤트는 파일의 끝에 나타납니다.
주요 특징

### 로그 유지 창

각 WARP 로그 파일 (예 :`connection_stats.log`, `dns_stats.log`, `daemon.log`, `boringtun.log`, `daemon_dns.log`, `dex.log`·`captive-portal.log`)는 크기와 나이에 의해 제한됩니다:

- **최대 파일 크기:**&#x31;0 메가바이트
- **최대 파일 연령:**&#x32;4시간
- **로그 당 유지 된 버전의 최대 수:**&#x34; (예를 들면,`daemon.log`, `daemon.1.log`, `daemon.2.log`·`daemon.3.log`)

로그 파일은 최대 96 시간 (4 일)까지 데이터를 포함 할 수 있습니다.`warp-diag`실행되었지만, 로그 활동이 최소한이라면만. 높은 로깅 볼륨 (예를 들어, 반복 오류)를 가진 환경에서, 로그는 더 자주 회전 할 수 있으며 캡처 된 창은 훨씬 단축 될 수 있습니다 (몇 시간 만).

항상 각 로그 파일의 끝에 타임스탬프를 체크하여 진단 아카이브에 의해 덮는 시간 범위를 확인합니다.

:::note\[Linux 로그 동작]

Linux에서 WARP daemon 로그는 시스템 로그에 기록됩니다.`warp-svc`서비스.

최대 로그 레벨을 조정할 필요가 있거나 로그가 무엇인지 필터링하면 WARP를 구성할 수 있습니다.`systemd`단위 파일 사용[`LogLevelMax=`옵션 정보](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html#LogLevelMax=).

Cloudflare WARP는 임명 과정에서 로깅 수준을 구성하는 공식적인 방법을 제공하지 않습니다.

:::
