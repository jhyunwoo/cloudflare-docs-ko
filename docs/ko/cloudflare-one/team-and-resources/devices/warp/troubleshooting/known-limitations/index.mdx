## Windows 서버

WARP 클라이언트는 Windows 서버에서 실행하지 않습니다. 더 알아보기[다운로드](/cloudflare-one/team-and-resources/devices/warp/download-warp/)지원되는 운영 체계의 명부를 위해.

## Windows ARM에 연결되는 WARP

ARM 기반 프로세서가있는 Windows 장치에서 WARP 클라이언트는 때때로 얻을 수 있습니다[연결 상태에 붙어](/cloudflare-one/team-and-resources/devices/warp/troubleshooting/common-issues/#unable-to-connect-warp)WARP에 toggle 때 (첫째로 WARP를 설치할 때와 같은).

이 문제점의 주위에 일하기 위하여, 당신은 일시적으로 WARP 네트워크 접합기를 제거할 수 있습니다:

1. WARP 클라이언트 GUI와 toggle WARP를 떨어져 엽니다.
2. Windows에서 장치 관리자를 엽니 다.
3. 제품정&#xBCF4;**- 연혁** > **숨겨진 장치 표시**.
4. 이름 \***네트워크 어댑터**, 찾기**Cloudflare WARP 공용영역 갱도**선택하기**Uninstall 장치**.
5. 제품정보**이 장치에 대한 드라이브를 제거하려면**, 다음 선택**다운로드**.
6. 토글 WARP 다시.

WARP는 이제 네트워크 어댑터를 다시 설치하고 WARP 클라이언트 GUI는 이제 보여야**연결하기**.

Microsoft는 최근 Microsoft 365 응용 프로그램에 의해 사용되는 IP 주소로 변경되었습니다 (Microsoft Teams와 같은). 고객 사용[직접 경로 Microsoft 365 트래픽](/cloudflare-one/team-and-resources/devices/warp/configure-warp/warp-settings/#directly-route-microsoft-365-traffic)기능은 수동으로 다음 IP를 추가해야합니다.[분할 터널 제외 목록](/cloudflare-one/team-and-resources/devices/warp/configure-warp/route-traffic/split-tunnels/#add-a-route):

- `24.24.24.24/32`

## DoH 모드에서 Windows에서 nslookup

Windows 장치에서[DNS만 모드](/cloudflare-one/team-and-resources/devices/warp/configure-warp/warp-modes/#dns-only-mode), `nslookup`기본적으로 DNS 요청을 보냅니다.[WARP 로컬 DNS 프록시](/cloudflare-one/team-and-resources/devices/warp/configure-warp/route-traffic/warp-architecture/#dns-traffic)IPv6 이상. 그러나 WARP가 IPv4-mapped IPv6 주소를 사용하므로 (실제 IPv6 주소 대신)`nslookup`이 주소 유형과 쿼리가 실패하지 않을 것입니다 :

```txt
C:\Users\JohnDoe>nslookup google.com
Server:  UnKnown
Address:  ::ffff:127.0.2.2

*** UnKnown can't find google.com: No response from server
```

문제를 해결하려면 IPv4 주소를 지정하십시오.[WARP 로컬 DNS 프록시](/cloudflare-one/team-and-resources/devices/warp/configure-warp/route-traffic/warp-architecture/#dns-traffic)당신의 질문에서:

```bash
C:\Users\JohnDoe>nslookup google.com 127.0.2.2
```

대안으로, 사용 PowerShell:

```powershell
Resolve-DnsName -Name google.com
```

## Comcast DNS 서버

WARP를 통해 DNS 트래픽을 예측할 수 없습니다. Comcast가 사용자의 장치에서 직접 보내지 않는 DNS 트래픽을 거부하기 때문입니다.

- IPv4 주소:`75.75.75.75`·`75.75.76.76`
- IPv6 주소:`2001:558:feed::1`·`2001:558:feed::2`

문제점의 주위에 일하기 위하여, 당신은 할 수 있습니다:

- 이름 \*[분할 터널 규칙](/cloudflare-one/team-and-resources/devices/warp/configure-warp/route-traffic/split-tunnels/)WARP에서 위의 IP를 제외합니다.
- 장치 또는 라우터를 구성하여 공용 DNS 서버를 사용합니다.[`1.1.1.1`](https://1.1.1.1/dns/).

## Cox DNS 서버

관련 기사[Comcast DNS 서버](#comcast-dns-servers)위에 나열된 제한, Cox DNS 서버는 WARP egress IPs (또는 Cox IP가 아닌 모든 IP)의 트래픽에 응답하지 않습니다. workaround는 거의 동일합니다. Cox DNS 서버가 개별 최종 사용자에게 특정할 수 있습니다. 당신은 할 수 있습니다:

- 이름 \*[분할 터널 규칙](/cloudflare-one/team-and-resources/devices/warp/configure-warp/route-traffic/split-tunnels/)모든 Cox DNS 서버를 제외한다. 비즈니스 고객을 위해, 참조[COX 문서](https://www.cox.com/business/support/cox-business-dns-and-mail-exchange-hosting-services.html)DNS 서버 IP를 위해. 주거 고객을 위해 로컬 DNS 서버를 확인하십시오. 주거 DNS 서버는 전형적으로 떨어졌습니다`68.105.28.0/24`·`68.105.29.0/24`.
- 장치 또는 라우터를 구성하여 공용 DNS 서버를 사용합니다.[`1.1.1.1`](https://1.1.1.1/dns/).

## Bridged Networking과 Linux에서 Docker

[기타 제품](https://www.docker.com/products/container-runtime/)리눅스에서 WARP에 의해 요구되는 underlying 네트워크 갱도 MTU 변화를 실행하지 않습니다. 이것은 WARP가 주인 기계에 활성화될 때 Docker 콘테이너 안쪽에 연결 문제점을 일으킬 수 있습니다. 예를 들어,`curl -v https://cloudflare.com > /dev/null`기본 교량 네트워크 드라이버를 사용하는 Docker 컨테이너에서 실행하면 실패합니다.

이 문제점의 주위에 일하기 위하여, 리눅스에 도커를 가진 WARP의 사용자는 도커의 네트워크 공용영역에 MTU를 수동으로 재구성할 수 있습니다. 수정할 수 있습니다.`/etc/docker/daemon.json`다음을 포함:

```json
{
	"mtu": 1420
}
```

또는 작업 MTU 값으로 Docker 네트워크 생성:

```sh
docker network create -o "com.docker.network.driver.mtu=1420" my-docker-network
```

MTU 값은 호스트의 기본 인터페이스 마이너스 80 바이트의 MTU로 설정해야합니다 WARP 프로토콜 오버 헤드. 대부분의 MTUs는 1500이므로 1420은 대부분의 사용자에게 작업해야합니다.

## Docker에서 WARP DNS 액세스

WARP는 로컬 DNS 프록시를 실행합니다.`127.0.2.2`·`127.0.2.3`. Docker 컨테이너 내에서 이러한 주소에 액세스할 수 있으며 내부 또는 fallback 도메인을 해결할 수 있습니다. 기본 Docker[교량 네트워크](https://docs.docker.com/engine/network/drivers/bridge/)호스트에서 DNS 설정을 복사하지만, 루프백 DNS 주소를 필터링`127.0.2.2`·`127.0.2.3`, 그래서 컨테이너는 사용할 수 없습니다.

컨테이너로 WARP DNS 해상도를 활성화하려면:

- 지원하다[Docker 네트워크](https://docs.docker.com/engine/network/#user-defined-networks)(권장) : Docker 컨테이너를 허용하여 네트워크 고립을 호스트에서 유지하는 교량 네트워크 드라이버를 사용합니다. 자신의 브리지 네트워크를 만드는 경우, 당신은 또한[MTU를 따르십시오](/cloudflare-one/team-and-resources/devices/warp/troubleshooting/known-limitations/#docker-on-linux-with-bridged-networking).
- 제품 정보[호스트 네트워킹](https://docs.docker.com/engine/network/drivers/host/)(추천되지 않음): 네트워크 고립의 보안 이점을 제거하고 항구 충돌에 지도할지도 모릅니다.

다음 예제는 특별한 호스트를 사용합니다 (`connectivity-check.warp-svc`) 로컬 DNS 프록시에서만 지원되는 Docker 네트워킹 모드를 보여줍니다.

```
# This host is not resolvable by default
❯ docker run --rm alpine nslookup connectivity-check.warp-svc.
```

## Windows 앱 연결 문제

WARP 클라이언트가 국부적으로 기계에 활동적일 때, 사용자는 Windows 365 PC에 연결할 수 없습니다[Windows 앱](https://aka.ms/WindowsApp). 이 문제는 Windows 365에 브라우저 기반 연결에 영향을 미치지 않습니다.

이 문제를 해결하려면 관련 WARP에서 지정된 네트워크를 제외하십시오.[회사소개](/cloudflare-one/team-and-resources/devices/warp/configure-warp/device-profiles/). 필수 네트워크는 아래에 나열됩니다`WindowsVirtualDesktop`서비스 태그[Azure IP 범위 및 서비스 태그 - Public Cloud](https://www.microsoft.com/en-us/download/details.aspx?id=56519)자원 (연구에 대한`"name": "WindowsVirtualDesktop"`).

Microsoft는 이전에 제공 한[PowerShell 스크립트](https://github.com/microsoft/Windows365-PSScripts/tree/main/Windows%20365%20Gateway%20IP%20Lookup)이 네트워크를 검색하기 위해, 하지만 그것은 deprecated 이후. 관련 네트워크는 이제 다음과 같은 하위넷에 통합되어 있으며 관련 WARP 장치 프로파일에서 제외되어야합니다.

```
40.64.144.0/20
51.5.0.0/16
2603:1061:2010::/48
2603:1061:2011::/48
```

## 트래픽 만 모드의 IPv6 DNS 해상도

내 계정[교통 모드](/cloudflare-one/team-and-resources/devices/warp/configure-warp/warp-modes/#traffic-only-mode), IPv6 DNS 서버를 사용하는 장치는 이러한 서버가 WARP 터널에서 수동으로 제외되지 않은 경우 연결 문제를 경험할 수 있습니다.

일반적인 IPv4 DHCP 구성과는 달리 DNS 서버는 종종 자동으로 개인 주소 범위 내에서 떨어지는 반면, IPv6 환경은 일반적으로 적절한 작동을 위해 분할 터널 설정을 통해 DNS 서버 주소의 수동 exclusion을 요구합니다.

DNS 서버가 IPv6 주소를 사용한다면, 수동으로 사용할 수 없습니다.[분할 터널 설정](/cloudflare-one/team-and-resources/devices/warp/configure-warp/route-traffic/split-tunnels/)교통만 하면 제대로 작동할 수 있습니다.

## Ivanti Secure Access (이전 펄스 보안)

Ivanti Secure Access VPN 클라이언트는 Windows Filtering Platform(WFP) 규칙을 설치하여 WARP와 충돌할 수 있습니다.[WARP 로컬 DNS 프록시](/cloudflare-one/team-and-resources/devices/warp/configure-warp/route-traffic/warp-architecture/#dns-traffic)항구에`53`. 이 결과에`Host not found`Ivanti가 비활성화되거나 차단될 때 오류 또는 인터넷 연결의 총 손실.

이 문제를 해결하려면 Ivanti 지원 또는 관리자에게 문의하여 특정 방화벽 규칙 차단 트래픽을 수정하거나 제거하십시오.`127.0.2.2`.

## Microsoft Intune의 Lockdown 모드로 항상 VPN

Microsoft Intune를 사용하여 Android에서 WARP 클라이언트를 배포하는 경우[항상 VPN 및 Lockdown 모드 활성화](https://learn.microsoft.com/en-us/intune/intune-service/configuration/device-restrictions-android-for-work?tabs=aecorporate#fully-managed-dedicated-and-corporate-owned-work-profile-devices-5), Cloudflare 1개의 대리인은 등록하지 않을지도 모릅니다. 이것은 Lockdown 형태가 Cloudflare를 방지하기 때문에 입니다 통합 네트워크에 액세스하여 등록 절차를 완료합니다.

이것은 Google에보고 된 Android OS의 알려진 제한입니다. 기능 요청의 상태를 추적 할 수 있습니다.[Google 문제 추적기](https://issuetracker.google.com/issues/238109298?pli=1).

이 문제를 해결하려면 항상 VPN을 활성화하면서 Lockdown 모드를 비활성화 할 수 있습니다.

1. Intune 프로필에서 비활성화**Lockdown 형태**계속하기**항상 VPN**지원하다
2. 사용 방법[`auto_connect`](/cloudflare-one/team-and-resources/devices/warp/deployment/mdm-deployment/parameters/#auto_connect)·[`switch_locked`](/cloudflare-one/team-and-resources/devices/warp/deployment/mdm-deployment/parameters/#switch_locked)원활한 연결에 대한 관리 구성의 매개 변수.
3. Cloudflare를 실행하는 사용자 One Agent 앱을 통해 한 번 등록을 수동으로 완료합니다.
