기본적으로 Cloudflare Zero Trust는 로컬 확인에 사용되는 일반적인 최상위 도메인을 Gateway 처리 대상에서 제외합니다. 이러한 최상위 도메인은 장치의 기본 인터페이스에 구성된 로컬 DNS resolver가 해석합니다.

로컬 도메인 Fallback 목록에 추가 도메인을 추가하고 Gateway fixr의 장소에서 DNS 서버를 지정할 수 있습니다. WARP 클라이언트는 구성 된 fallback 서버에 직접 요청합니다.

## 제한 사항

로컬 도메인 Fallback은 WARP 클라이언트를 실행하는 장치에만 적용됩니다.

DNS 요청은 Local Domain Fallback bypass fixr에 따라 달라집니다. Gateway DNS 정책 또는 DNS 로깅에 적용되지 않습니다. DNS 쿼리를 사용자 정의 해결자에게 전달하고 게이트웨이 필터링을 적용하려는 경우, 사용[해결사 정책](/cloudflare-one/traffic-policies/resolver-policies/). Local Domain Fallback과 fixr 정책이 동일한 장치로 구성되면 Cloudflare는 클라이언트 측 Local Fallback 규칙을 먼저 적용할 것입니다.

## 내부 IP를 위한 반전 DNS 조회

기본적으로 Warp sends[반전 DNS 쿼리](https://www.cloudflare.com/learning/dns/glossary/reverse-dns/)공용 DNS 서버. 내부 IP 주소와 관련된 도메인 이름을 찾습니다.[로컬 도메인 fallback 항목 추가](#add-a-domain)제품 정보`in-addr.arpa`(IPv4) 및/또는`ip6.arpa`(IPv6) 내부 DNS 서버 IP에 포인트.`in-addr.arpa`·`ip6.arpa`최상위 도메인[reserved](https://www.iana.org/domains/arpa)반전 DNS 쿼리를 위해. 이 도메인에 대한 로컬 도메인 fallback 항목을 추가함으로써 모든 역 DNS 쿼리 (예 :`dig -x 1.1.1.1`) 이제 로컬 DNS 서버를 통해 해결됩니다.
