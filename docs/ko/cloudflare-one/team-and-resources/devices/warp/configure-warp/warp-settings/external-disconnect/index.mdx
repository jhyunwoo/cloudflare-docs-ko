외부 비상 차단 기능은 조직이 Cloudflare의 인프라를 사용하여 WARP 클라이언트의 함대를 원격으로 차단하고 재연결할 수 있습니다. 예를 들어, 이벤트에서[Cloudflare 네트워크 정전](/cloudflare-one/team-and-resources/devices/warp/configure-warp/warp-settings/external-disconnect/#use-cases)Cloudflare의 시스템은 다운 또는 제한이 없는 경우에도 여전히 장치를 관리할 수 있습니다.

외부 비상 사태가 활성화되면 WARP 클라이언트는 주기적으로 고객 호스팅 HTTPS 엔드포인트를 조사합니다. 클라이언트는 새로운 상태로 유효한 JSON 페이로드를 수신하면 연결 상태를 변경합니다. 모든 실패는 성공적으로 국가를 검색합니다 (예 : endpoint unachability, 잘못된 인증서 지문, 또는 improperly Structured payload와 같은) 클라이언트의 상태 변화를 일으킬 수 없습니다.

당신은 대시보드 개시를 가진 조합에 있는 외부 비상사태 차단을 이용할 수 있습니다[모든 장치에 WARP를 분리하십시오](/cloudflare-one/team-and-resources/devices/warp/configure-warp/warp-settings/#disconnect-warp-on-all-devices)설정. 외부 엔드포인트에서 분리된 신호는[자주 묻는 질문](#warp-settings-precedence).

## 사용 사례

외부 비상 사태를 사용하여 단일 지점의 위험 위험을 완화하고 네트워크 중단 중에 비즈니스 연속성을 보장합니다. 사용 사례는 다음과 같습니다:

- **보안 Incident 응답**: 전체 함대를 통해 WARP 터널을 신속하게 종결 할 수있는 능력을 제공합니다.
- **준수 및 감사**: 조직의 자체 인프라에 의해 완전히 분리, 감사 및 제어되는 "emergency stop"기능을 위임하는 민감한 또는 규제 환경에 대한 Fulfills 요구 사항.
- **재해 복구**: WARP 장치가 Cloudflare의 API에 도달 할 수없는 경우 (네트워크 아웃리지, 라우팅 문제 또는 클라이언트 측면 구성), 관리자는 고객 호스팅 엔드포인트를 통해 함대를 강제 차단하는 기능을 유지합니다.

## 외부 endpoint 필요조건

외부 차단 엔드포인트는 Cloudflare의 외부에서 호스팅되는 HTTPS 서버입니다. WARP는 비상 차단 신호를 fetch합니다. 고객은이 엔드포인트를 관리할 책임이 있습니다.

### 엔드포인트 URL

외부 엔드포인트 URL은:

- HTTPS 프로토콜을 사용합니다.
- 호스트로 IPv4 또는 IPv6 주소를 사용하여 도메인이 아닙니다.
- (추천) 공공 IP를 사용하여 장치가 네트워크 위치에 상관없이 최신 상태를 파악할 수 있습니다.

### 응답 payload

WARP 클라이언트는 다음과 같은 형식으로 외부 엔드포인트에서 JSON 응답 페이로드를 기대합니다.

```json
{
  "emergency_disconnect": false | true
}
```

- 이름 \*`emergency_disconnect`설정`true`, 장치는 비상 차단을 시작한다.
- 이름 \*`emergency_disconnect`설정`false`, 장치는 정상 가동을 계속할 것입니다.

### Cipher 스위트

WARP 클라이언트는 TLS 연결을 사용하여 설치합니다[Rustls의](https://github.com/rustls/rustls). HTTPS 엔드포인트가 하나씩 허용되도록[Rustls에 의해 지원되는 cipher 스위트](https://docs.rs/rustls/0.21.10/src/rustls/suites.rs.html#125-143).

## 외부 비상 차단 설정

### 1. 외부 차단 endpoint 생성

External Emergency Disconnect를 구성하려면 글로벌 차단 신호를 제공하는 자체 인프라의 HTTPS 엔드포인트가 필요합니다. WARP 클라이언트는 외부 엔드포인트를 오염시키고 Zero Trust에 업로드한 SHA-256 지문에 대한 TLS/SSL 인증서를 검증합니다. 더 알아보기[외부 endpoint 필요조건](#external-endpoint-requirements)더 많은 정보.

다음 예제는 Docker의 nginx 컨테이너를 사용하여 외부 연결 엔드포인트를 배포하는 방법을 보여줍니다.

1. TLS/SSL 인증서 생성:

   ```sh
   openssl req -x509 -newkey rsa:4096 -sha256 -days 3650 -nodes -keyout key.pem -out cert.pem
   ```

   Distinguished Name (DN) 필드를 작성하는 것이 좋습니다. 조직의 정보 또는 언론에 기입`Enter`기본값을 사용한다.

   명령은 PEM 형식과 개인 키에서 인증서를 출력합니다. 이 파일을 안전한 장소에 저장하십시오.

2. 네트워크에서 HTTPS 서버를 구성하여 이 인증서와 키를 사용합니다.

   a. nginx 구성 파일 만들기`nginx.conf`:

   ```txt title="nginx.conf"
   events {
   	worker_connections  1024;
   }

   http {
   		server {
   				listen              443 ssl;
   				ssl_certificate     /certs/cert.pem;
   				ssl_certificate_key /certs/key.pem;
   				location /status/disconnect {
   						default_type application/json;
   						return 200 '{"emergency_disconnect": false}';
   				}
   		}
   }
   ```

   필요한 경우, 교체`/certs/cert.pem`·`/certs/key.pem`인증서 및 키의 위치.

   b. Docker compose 파일에 nginx 이미지를 추가하십시오:

   ```yml title="docker-compose.yml"
   services:
   	nginx:
   		image: nginx:latest
   		ports:
   			- 3333:443
   		volumes:
   			- ./nginx.conf:/etc/nginx/nginx.conf:ro
   			- ./certs:/certs:ro
   ```

   필요한 경우, 교체`./nginx.conf`·`./certs`nginx 구성 파일 및 인증서의 위치.

   c. 서버 시작:

   ```sh
   docker compose up -d
   ```

3. HTTPS 엔드포인트가 작동하는 테스트하려면 최종 사용자의 장치에서 컬 명령을 실행하십시오. 당신은 통과해야합니다`--insecure`자동 서명 인증서를 사용하므로 옵션.

   ```sh
   curl --insecure https://<server-ip>:3333/status/disconnect
   ```

   ```sh output
   {"emergency_disconnect": false}
   ```

### 4. 외부 비상사태 Disconnect를 시험하십시오

1. WARP가 연결된다는 것을 보증하십시오.

2. 외부 비상사태 Disconnect 특징이 있다는 것을 보증하십시오[관련 기사](#3-turn-on-external-emergency-disconnect).

3. 내 계정[외부 endpoint](#create-an-external-disconnect-endpoint)구성, 변경`emergency_disconnect`으로`true`:
   ```json
   {"emergency_disconnect": true}
   ```

4. 변경 사항을 적용하려면 서버를 다시로드해야합니다. 다시로드[이름 \*`nginx`계정 관리](#create-an-external-disconnect-endpoint):
   ```sh
   docker exec <container-name-or-id> nginx -s reload
   ```

WARP는 형성된 polling 간격에서 자동적으로 끊고, WARP GUI는 전시할 것입니다[`Admin directed disconnect`](/cloudflare-one/team-and-resources/devices/warp/troubleshooting/client-errors/#admin-directed-disconnect). 모든 장치를 재연결하기 위하여, 변화`emergency_disconnect`뒤로`false`.

## 로그인

외부 비상사태 차단 신호는 Cloudflare의 인프라에서 자주적으로, 외부에 방아쇠가 Cloudflare에 의해 기록되지 않습니다. 대시보드 로그는 기능 설정에 대한 변경을 보고합니다 (기능을 켜거나 종료 URL을 변경), 차단 이벤트가 없습니다.

장치에서 현재 긴급 차단 상태를 얻으려면 다음 명령을 실행할 수 있습니다.

```sh
warp-cli settings
```

```sh output
Merged configuration:
(override)	Emergency disconnect: true (issued @ 2025-12-09T13:57:42.597864Z)
```

현재 상태는 또한에서 유효합니다[WARP diagnosic 로그](/cloudflare-one/team-and-resources/devices/warp/troubleshooting/warp-logs/#macoswindowslinux)내 계정`warp-settings.txt`.

### 로컬 클라이언트 재설정

마지막 리조트로서, CLI를 사용하여 개별 장치에 외부 비상 차단을 재설정 할 수 있습니다.

```
warp-cli registration delete
```

이 명령은 클라이언트 등록을 취소하고 로컬 정책을 취소하고 긴급 상태를 삭제합니다. 연결하기 위하여, 당신은 필요로 할 것입니다[외부 비상 차단](#clear-external-emergency-disconnect-state)그리고 그때[재 목록 WARP](/cloudflare-one/team-and-resources/devices/warp/deployment/manual-deployment/)Zero Trust 조직으로.

## WARP 설정 우선

글로벌 차단 설정이 상호 작용하고 다른 WARP 프로필 설정에 영향을 미치는 방법을 알아보세요.

### 글로벌 연결 설정

클라이언트는 Cloudflare 대시보드 둘 다에서 신호를 교차할 것입니다 (via를 통해[모든 장치에 WARP를 분리하십시오](/cloudflare-one/team-and-resources/devices/warp/configure-warp/warp-settings/#disconnect-warp-on-all-devices)) 외부 엔드포인트. 글로벌 단선은 소스가 트리거하면 시행됩니다.

|                           | [모든 장치에 WARP를 분리하십시오](/cloudflare-one/team-and-resources/devices/warp/configure-warp/warp-settings/#disconnect-warp-on-all-devices)이름 \*`On` | [모든 장치에 WARP를 분리하십시오](/cloudflare-one/team-and-resources/devices/warp/configure-warp/warp-settings/#disconnect-warp-on-all-devices)이름 \*`Off` |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| **외부 endpoint 반환`true`**  | 힘 분리                                                                                                                                         | 힘 분리                                                                                                                                          |

### 관리 override

글로벌 단선은 어떤 존재를 명확하게합니다.[관리자 override 코드](#allow-admin-override-codes). 사용자의 유일한 방법은 글로벌 연결 중에 다시 연결됩니다.[관리자 override 코드](#allow-admin-override-codes). 예를 들어, 코드를 사용하여 IT 직원을 제공 할 수 있으므로 글로벌 차단으로 이끌 수있는 사건의 해상도를 테스트 할 수 있습니다. 오버라이드 코드는 오버라이드 타임 아웃이 만료 될 때까지 글로벌 차단에서 특정 사용자 및 장치를 면제합니다.
