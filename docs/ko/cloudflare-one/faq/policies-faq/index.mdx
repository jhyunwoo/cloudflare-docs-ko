## 정책 시행의 순서는 무엇입니까?

Gateway 및 Access 정책은 일반적으로 UI의 정책 테이블에 따라 상단에서 하단으로 트리거합니다. 예외는 Bypass 및 Service Auth 정책을 포함, 이는 액세스 평가 첫 번째. 마찬가지로 Gateway HTTP 정책의 경우, Inspect 및 Isolate 정책은 모든 허용 또는 블록 정책을 준수하지 않습니다. 시행에 대한 자세한 내용을 보려면, 우리의 문서를 참조[오시는 길](/cloudflare-one/access-controls/policies/#order-of-execution)·[Gateway 정책](/cloudflare-one/traffic-policies/order-of-enforcement/).

## **웹 사이트에 L7 방화벽을 우회할 수 있습니까?**

사이트맵 Gateway는 HTTP의 호스트명을 사용합니다.`CONNECT`요청의 목적지를 식별하는 헤더. 사이트를 우회하고 싶은 관리자는[검사하지 마십시오](/cloudflare-one/traffic-policies/http-policies/#do-not-inspect)암호화 및 일반 텍스트 트래픽에서 발생하는 HTTP 검사를 방지하기 위해 정책.

HTTP 트래픽 검사에서 L7 방화벽 결과를 우회하고 로깅은 HTTP 세션에서 비활성화됩니다.

## 두 번째 레벨 하위 도메인 URL로 응용 프로그램을 보안 할 수 있습니까?

예. SSL 인증서가 첫 번째 및 두 번째 레벨 하위 도메인을 다룹니다. 대부분의 인증서는 첫 번째 레벨 하위 도메인을 커버하고 두 번째는 아닙니다. 이것은 대부분의 Cloudflare 인증서에 대한 사실입니다. CF 인증서로 두 번째 레벨 하위 도메인을 커버하기 위해, 생성[고급 인증서](/ssl/edge-certificates/advanced-certificate-manager/manage-certificates/).

Cloudflare의 Wildcard 기반 정책 액세스는 해당 레벨을 커버합니다. 왼쪽 상단 하위 도메인에 와일드 카드 정책을 추가하십시오.

## 어떻게 정책은 HTTP 정책과 함께 작동합니까?

고립 정책, 모든 HTTP 정책과 같은, 단계에 평가됩니다. 사용자가 고립 된 브라우저와 HTTP 정책에 대한 재평가 요청을 할 때. 이 웹 사이트는 귀하가 웹 사이트를 탐색하는 동안 귀하의 경험을 향상시키기 위해 쿠키를 사용합니다.

## 왜 API 또는 CLI 트래픽이 격리되지 않습니까?

고립 정책은 다음과 같은 요청에 적용됩니다.`Accept: text/html*`. 이것은 Browser Isolation 정책을 API와 명령 줄 요청으로 공동 작업을 할 수 있습니다.

## 특정 비표준 포트에 액세스 할 수 있습니까?

이름 \* 사이트맵 액세스는 URL에 추가 된 포트를 포함 할 수있는 정책을 시행 할 수 없습니다. 그러나 Cloudflare 터널을 사용하여 비표준 포트로 트래픽을 포인트 할 수 있습니다. 예를 들어, Jira가 포트에서 사용할 경우`8443`당신의 근원에, 당신은 Cloudflare 갱도를 통해 그 항구에 프록시 소통량을 할 수 있습니다.

## 왜 여전히 게이트웨이 정책에 의해 차단 도메인에 도달 할 수 있습니까?

도메인이 DNS, 네트워크 또는 HTTP 정책에 의해 차단되는 경우:

- **귀하의 정책은 여전히 업데이트됩니다.**&#x43;loudflare는 전 세계 데이터 센터의 새로운 설정을 업데이트합니다. 그것은 propagate에 변화를 위한 대략 60 초가 소요됩니다.

도메인이 DNS 정책에 의해 차단되는 경우에, 그것은 일 수 있습니다:

- **당신의 장치는 다른 DNS 해결자를 사용하고 있습니다.**&#x44;NS 설정에서 다른 DNS 해결자가 있는 경우, 기기는 게이트웨이의 일부가 아닌 해결자에게 IP 주소를 사용할 수 있습니다. 결과적으로 차단하려고 하는 도메인은 여전히 장치에서 접근할 수 있습니다. DNS 설정에서 다른 모든 IP 주소를 제거하고 Gateway의 DNS 해결 IP 주소를 포함해야합니다.

- **귀하의 정책은 DNS 위치에 할당되지 않습니다.**&#xC815;책이 DNS 위치에 할당되지 않은 경우 해당 위치에서 DNS 쿼리를 보내면 Gateway는 정책이 적용되지 않습니다. DNS 위치에 대한 정책을 할당하면 원하는 정책이 해당 위치에서 DNS 쿼리를 보낼 때 적용됩니다.

- **DoH 엔드포인트는 Gateway DNS 위치가 아닙니다.**. 브라우저는 DoH 엔드포인트를 사용할 수 있습니다. 브라우저에서 DoH를 직접 구성하려면 DoH 엔드포인트가 게이트웨이 DNS 위치인지 확인하십시오.

도메인이 네트워크 정책에 의해 차단되는 경우에, 그것은 일 수 있습니다:

- **당신의 브라우저는 기존의 연결을 재사용**. 네트워크 정책은 연결이 열릴 때만 적용됩니다. 브라우저가 네트워크 정책에 의해 차단 될 도메인에 연결되면 게이트웨이는 연결이 닫힐 때까지 요청을 차단하지 않습니다. 도메인을 차단하려면 관련 탭을 닫거나 브라우저를 다시 시작합니다.

## 액세스가 Forbidden 상태 페이지를 반환 할 때 로그인 페이지로?

Access는 상태 코드가있는 Forbidden 페이지를 반환합니다.`401`/`403`사용자가 통과 할 수있는 방법이 없습니다.[- 연혁](/cloudflare-one/access-controls/policies/). Cloudflare가 사용자가 로그인 할 수없는 전체 정책을 결정할 수 있다면 액세스 대신 Forbidden 페이지를 반환합니다.[로그인 페이지](/cloudflare-one/reusable-components/custom-pages/access-login-page/).

예를 들어, 애플리케이션에는 사용자가 있어야 하는 정책이 있습니다.[특정 위치](/cloudflare-one/access-controls/policies/#allow)로그인

관리자로, 당신은이 geolocation 정책을 사용하여 정의 할 수[이름 \*](/cloudflare-one/access-controls/policies/#include)규칙, 사용자가 국가 A 또는 국가 B에서 응용 프로그램에 로그인 할 수 있음을 의미.

또는이 geolocation 정책을 사용하여 정의 할 수 있습니다.[이름 \*](/cloudflare-one/access-controls/policies/#require)규칙, 사용자가 로그인하려면 Country A에 있어야합니다.

C의 사용자가 애플리케이션에 액세스하려고 시도하면 Include 및 Require 시나리오에서 사용자는 Forbidden 페이지를 받게됩니다. Country C는 시나리오에서 정의되지 않았기 때문입니다. 따라서 Cloudflare는 이 사용자가 정책 요구 사항을 충족 할 수 없다는 것을 결정했으며 Forbidden 상태 페이지를 받게됩니다.
