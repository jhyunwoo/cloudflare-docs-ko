Cloudflare를 사용하여 Microsoft Entra ID (이전 Azure Active Directory)를 통합 할 수 있습니다. 사용자 정체성 및 그룹 회원을 기반으로 한 정책 사용자는 Cloudflare에 정통합니다 Entra ID 자격 증명을 사용하여 하나.

## Entra ID를 정체 공급자로 설정

### 1. Entra ID 설정 얻기

다음 Entra ID 값은 통합을 설정해야 합니다.

- 신청 (클라이언트) ID
- 디렉토리 ID
- 고객 비밀

그 값을 검색하려면:

1. 로그인하기[Microsoft Entra 관리자 센터](https://entra.microsoft.com/).

2. 오시는 길**이름 \*** > **Enterprise 응용**.

6. 이름 \***리디렉션 URI**, 선택*웹 사이트*플랫폼은 다음 URL을 입력합니다.


#### UPN 및 이메일

조직의 UPNs가 사용자의 이메일 주소와 일치하지 않는 경우, 이메일에 대한 사용자 정의 청구를 추가해야합니다. 예를 들어, 조직의 이메일 형식이면`user@domain.com`그러나 UPN은`u908080@domain.com`, 이메일 기반 정책을 구성하는 경우 이메일 청구를 작성해야 합니다.

기본적으로 Cloudflare는 Cloudflare에서 생성하고 구성하는 고유의 클레임 이름을 먼저 살펴봅니다. 이메일(예:`email_identifier`) 에서`id_token`JSON 응답. 독특한 클레임 이름을 구성하지 않았다면 Cloudflare는 그런 다음`email`이름 \* 마지막으로, 존재하지 않는 경우, Cloudflare는 UPN 청구를 살펴볼 것입니다.

이메일을 수신하려면`id_token`Microsoft Entra에서 다음을 수행해야합니다.

1. 내 계정[Microsoft Entra 관리자 센터](https://entra.microsoft.com/), 이동**제품 설명** > **앱 등록** > **모든 신청**관련 응용 프로그램을 선택.

2. 이름 \***계정 관리**, 선택**토큰 구성**.

3. 이메일 청구

   ![Entra의 이메일 청구](~/assets/images/cloudflare-one/identity/azure/entra-email-claim.png)

   위의 예에는 UPN 청구 및 이메일 청구가 포함됩니다. 이메일 청구가 Microsoft Entra 구성에서 생성되었기 때문에 Cloudflare는`email`JSON 응답의 키 값 쌍.

4. 이메일이 다른 이름보다 청구되는 경우`email`Cloudflare에 있는 당신의 윤곽을 새롭게 해야 합니다 1개:

   a. 에서[사이트맵 한국어](https://one.dash.cloudflare.com), 이동**통합** > **Identity 공급자** > **Azure 광고** > **제품정보**.

   b. 아래**옵션 구성** > **이메일 청구**, 조직의 이메일 주소를 나타내는 주장의 이름을 입력하십시오.

#### 오브젝트 ID

사용자의 이메일 또는 UPNs가 변경 될 수 있는지 여부에 관계없이 사용자의 객체 ID를 통과 할 수 있습니다 (`oid`) Microsoft Entra에서 Cloudflare 액세스. 객체 ID를 수신하는 Access를 구성하려면, 참조[사용자 정의 OIDC 주장](/cloudflare-one/integrations/identity-providers/generic-oidc/#custom-oidc-claims). 추가 구성이 Microsoft Entra에 필요하지 않습니다.

### Provisioning 속성

Provisioning 속성은 Entra ID가 Cloudflare Access와 동기화되는 사용자 속성을 정의합니다. 프로비저닝 속성을 수정하려면**Attribute 매핑**선택하기**Provision Microsoft Entra ID 사용자**.

이미 구성되지 않은 경우 Cloudflare는 다음 사용자 속성 매핑을 가능하게 권장합니다.

| customappsso 특성                | Entra ID 특성                 | Recommend                               |
| ------------------------------ | --------------------------- | --------------------------------------- |
| `userName`                     | `userPrincipalName`또는`mail` | 견적 요청 Cloudflare One의 이메일 주소와 일치해야 합니다. |
| `emails[type eq "work"].value` | `mail`                      | 견적 요청 Cloudflare One의 이메일 주소와 일치해야 합니다. |
| `name.givenName`               | `givenName`                 | (주)                                     |
| `name.familyName`              | `surname`                   | (주)                                     |

### 그룹 별

#### 인증현황

Entra 그룹에 대한 액세스 및 게이트웨이 정책은 모두 적용됩니다.[그룹 그룹](https://learn.microsoft.com/entra/fundamentals/how-to-manage-groups#add-a-group-to-another-group). 예를 들어, 사용자가 그룹에 속한 경우`US devs`·`US devs`더 넓은 그룹의 일부입니다`Devs`, 사용자는 생성된 모든 정책에 의해 허용되거나 차단될 것입니다`Devs`.

#### SCIM 제공

SCIM 규정을 위해,[배열된 그룹은 지원되지 않습니다](https://learn.microsoft.com/en-us/entra/identity/app-provisioning/how-provisioning-works#assignment-based-scoping). Microsoft Entra ID's SCIM 구현은 Cloudflare에 배열 된 그룹 회원에 대한 정보를 보내지 않습니다. 명시적으로 할당 된 그룹의 직접 회원 만 제공 될 것입니다. 그룹 회원이 올바르게 동기화되도록하려면 Entra ID에서 그룹을 직접 지정하여 프로비저닝을 원하는 그룹에 할당해야 합니다.

Microsoft에서 SCIM 요청이 배열 된 그룹 정보를 포함하지 않기 때문에 Cloudflare 또는 Microsoft는 그룹이 동기화되지 않는 알림을 제공 할 수 있습니다.
