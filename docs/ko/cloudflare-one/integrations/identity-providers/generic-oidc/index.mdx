사이트맵 Access에는 이미 Access에서 설정되지 않는 IdPs를 통합하는 데 도움이되는 일반적인 OpenID Connect (OIDC) 커넥터가 있습니다.

## 1. ID 공급자에 있는 신청을 창조하십시오

1. ID 공급자를 방문하고 클라이언트/앱을 만듭니다.

2. 클라이언트/앱을 만들 때 IdP가 요청할 수 있습니다.**공인 리디렉션 URI**. 다음 URL을 입력하십시오:

   ```txt
   https://<your-team-name>.cloudflareaccess.com/cdn-cgi/access/callback
   ```

   <Render file="find-team-name" product="cloudflare-one" />

3. 이 필드의 내용을 복사:

   - 고객 ID
   - 고객 비밀
   - Auth URL:`authorization_endpoint`IdP의 URL
   - 토큰 URL:`token_endpoint`IdP의 URL
   - 인증서 URL:`jwks_uri`IdP의 엔드포인트는 토큰을 서명하기 위해 IdP 키를 허용

   ID 공급자의 가치를 찾을 수 있습니다.**OIDC 발견 끝점**. 일부 공급자는 "잘 알려진 URL"을 호출합니다.

IdP 그룹에 따라 정책을 구축하려면:

- IdP가 보내는 것을 확신합니다.`groups`이름 \* naming은 정확히 일치해야합니다 (문자 과민성). 다른 모든 값은 OIDC 청구로 전송됩니다.

## 옵션 구성

### 사용자 정의 OIDC 주장

모든 OIDC IdP 통합은 사용자 정의 OIDC 주장의 사용을 지원합니다. 일단 구성되면 액세스는 주장을 추가합니다.[액세스 JWT](/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/application-token/)당신의 근원 서비스에 의하여 소비를 위해. 참고 자료 사용자 정의 OIDC 주장 할 수 있습니다[오시는 길](/cloudflare-one/access-controls/policies/), 사용자 정의 ID 속성을 기반으로 응용 프로그램에 사용자 액세스를 제어하는 방법을 제공. Custom OIDC 클레임은 현재 Gateway 정책에서 지원되지 않습니다.

OIDC를 IdP 통합에 추가하려면:

1. ID 공급자에서 OIDC ID 토큰에 대한 사용자 정의 청구가 포함되어 있는지 확인하십시오.
2. 내 계정[사이트맵 한국어](https://one.dash.cloudflare.com), 이동**통합** > **Identity 공급자**.
3. 이름 \***당신의 ID 공급자**, 당신의 ID 공급자를 찾아내고 선정하십시오**제품정보**.
4. 이름 \***OIDC 클레임**, 사용자 정의 주장의 이름을 입력 (예를 들어,`oid`).
5. 제품정보**제품 정보**.
6. 제품정보**제품정보**사용자 정의 주장이 나타나는 것을 확인합니다.`oidc_fields`. 예를 들면,

   ```json
   	"oidc_fields": {
   		"oid": "54eb1ed2-7150-44e6-bbe4-ead24c132fd4"
   	},
   ```

이제 사용자 정의 청구에 대한 액세스 정책을 구축 할 수 있습니다**OIDC 소개**또는**IdP OIDC 클레임**옵션 정보 사용자 정의 주장은 또한 접근 뒤에 근원에 전달될 것입니다[사이트맵](/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/application-token/#custom-saml-attributes-and-oidc-claims).

#### 이메일 청구

사용자 지정을 지정할 수 있습니다.**이메일 청구**액세스가 사용자 이메일을 식별하는 데 사용할 이름. IdP가 표준을 반환하지 않는 경우에 유용합니다.`email`OIDC ID 토큰 주장.

#### 멀티 레코드 OIDC 주장

사이트맵 액세스는 다중 기록 OIDC 주장에 대한 지원 확장. 이 주장은 밖으로 파고 있으며 개인적으로 참고 자료d 정책. 이 기능은 granular 접근 제한과 애플리케이션의 정확한 사용자 권한화를 가능하게 합니다.

사이트맵 접근은 부분적인 OIDC 요구 가치 참고 자료s 또는 OIDC 범위를 지원하지 않습니다.
