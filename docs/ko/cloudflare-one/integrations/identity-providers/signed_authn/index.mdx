SAML 요청 흐름에서 Cloudflare 서비스 제공업체(SP)로 서비스 제공업체(IdP)로 액세스 기능. 사이트맵 액세스는 IdP에 SAML 요청을 보냅니다. SAML 공급자로부터 업로드한 서명 인증서는 응답을 검증합니다.

일부 경우에 관리자는 SP의 요청이 정해진 것을 확인해야합니다. SP의 요청과 IdP의 응답을 모두 검증함으로써 팀은 SAML 관계에서 작업이 두 방향으로 서명 할 수 있습니다.

사이트맵 액세스는 Signed AuthN 요청의 형태로이 요구 사항을 지원합니다. 활성화되면 Access는 AuthN 세부 사항을 포함하는 HTTP POST 요청에 내장 된 서명을 보냅니다.

## Signed AuthN 요청 설정

Signed AuthN 요청을 설정하려면:

1. Cloudflare에서 하나, 이동**통합** > **Identity 공급자**.

2. 이름 \***당신의 ID 공급자**, 선택**새로운 ID 공급자 추가**.

3. 제품 정보**사이트맵**다음 페이지에.

4. 대화 상자에 필드를 완료합니다.

5. 인증서를 찾기 위해이 URL로 이동:

   ```txt
   https://<your-team-name>.cloudflareaccess.com/cdn-cgi/access/public-cert
   ```

   IdP 검증은 가장 최근의 인증서를 사용합니다. 사이트맵 일상적으로 보안 측정으로 공공 키를 회전합니다.

   사이트맵 Access는 다음과 같은 2 개의 구별 된 이름 필드를 포함하는 인증서를 사용합니다.

   - **Issuer Distinguished 이름** - `CN=cloudflareaccess.com, C=US, ST=Texas, L=Austin, O=Cloudflare`
   - **제목 구별 이름** - `CN=*.cloudflareaccess.com, C=US, ST=Texas, L=Austin, O=Cloudflare`

   대부분의 IdP 구성은 AuthN 서명 검증을 시행하기 위해 3 가지 구성 요소가 필요합니다.

   - **인증서 발급[구분된 이름 (DN)](https://knowledge.digicert.com/generalinformation/INFO1745.html)**
   - **인증서 제목 구분 이름**
   - **공공 인증서**

6. IdP 계정에서, 당신의 허가 도메인을 가진 대체하십시오<GlossaryTooltip term="team domain">팀 도메인</GlossaryTooltip>Cloudflare 액세스에 의해 생성.

   이것은 예 형식입니다:

   ```txt
   https://<your-team-name>.cloudflareaccess.com/cdn-cgi/access/public-cert
   ```
