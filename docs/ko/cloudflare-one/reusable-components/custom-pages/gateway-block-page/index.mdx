Gateway 블록 트래픽이 있을 때[DNS 보호](/cloudflare-one/traffic-policies/dns-policies/#block)또는[HTTP 블록 정책](/cloudflare-one/traffic-policies/http-policies/#block), 사용자의 브라우저에 표시할 블록 페이지를 구성할 수 있습니다. 사용자의 브라우저를 다른 페이지로 리디렉션할 수 있습니다. 모든 블록 정책에 대해 전 세계적으로 이러한 사용자 정의를 적용하거나 per-policy 기반 설정을 override 할 수 있습니다.

## 자주 묻는 질문

차단된 도메인의 URL로 블록 페이지를 표시하려면 조직의 장치가 있어야 합니다.[Cloudflare 인증서](/cloudflare-one/team-and-resources/devices/user-side-certificates/manual-deployment/)설치. 기업 사용자는 또한 할 수 있습니다[자신의 루트 CA 인증서를 배포](/cloudflare-one/team-and-resources/devices/user-side-certificates/custom-certificate/). 인증서를 설치하지 않는 경우, 블록 페이지[제대로 표시되지 않음](#certificate-error).

## 블록 페이지 구성

Gateway는 트래픽이 차단되는 사용자의 브라우저에서 글로벌 블록 페이지를 표시합니다. 기본적으로 Gateway는 모든 DNS 블록 정책을 위한 블록 페이지를 표시할 것입니다. 당신은 할 수[글로벌 설정에 턴](#configure-policy-block-behavior)1인당.

글로벌 블록 페이지를 구성하려면:

1. 내 계정[사이트맵 한국어](https://one.dash.cloudflare.com), 이동**재사용 가능한 부품** > **주문 페이지**.
2. 이름 \***계정 Gateway 블록 페이지**, Gateway는 현재 구획 페이지 조정을 표시합니다. 제품정보**계정 관리**.
3. 자주 묻는 질문[default Gateway 블록 페이지](#use-the-default-block-page)·[URL 리디렉션](#redirect-to-a-block-page), 또는[Custom Gateway 블록 페이지](#customize-the-block-page).
4. 제품정보**제품 정보**.

### 기본 블록 페이지를 사용

당신이 선택할 때**기본 Gateway 블록 페이지**, Gateway는 전시할 것입니다[Cloudflare 호스팅 페이지](https://blocked.teams.cloudflare.com/). Gateway에 의해 차단된 모든 트래픽에 대한 기본 옵션입니다.

### 블록 페이지로 이동

Cloudflare 블록 페이지를 표시하는 대신 게이트웨이를 구성하여`307`(Temporary Redirect) HTTP 응답 코드 및 사용자 정의 URL로 리디렉션.

non-Cloudflare 블록 페이지로 리디렉션하려면:

1. 내 계정[사이트맵 한국어](https://one.dash.cloudflare.com), 이동**재사용 가능한 부품** > **주문 페이지**.
2. 이름 \***계정 Gateway 블록 페이지**, 선택**계정 관리**.
3. 제품 정보**URL 리디렉션**.
4. 차단 된 트래픽을 리디렉션하려면 URL을 입력하십시오.
5. (선택) 켜기**자주 묻는 질문**관련 기사[추가 정책 context](#policy-context)리디렉션 URL에.
6. 제품정보**제품 정보**.

Gateway는 이제 사용자 트래픽이 블록 페이지로 블록 정책을 일치 할 때 사용자 정의 페이지로 리디렉션됩니다.

URL을 리디렉션하는 HTTP 정책을 작성하려면, 참조[Redirect 동작](/cloudflare-one/traffic-policies/http-policies/#redirect).

#### Redirect 선행

리디렉션 URL의 경로와 쿼리는 원래 URL을 통해 선행합니다. 당신은 켜기**자주 묻는 질문**, Gateway는 리디렉션 URL의 끝에 컨텍스트를 추가합니다. 예를 들어, 원래 URL이 있다면`example.com/path/to/page?querystring=X&k=1`그리고 리디렉션 URL은`cloudflare.com/redirect-path?querystring=Y`, Gateway는 요청을 리디렉션합니다:

```txt ins="&cf_user_email=user@example.com"
cloudflare.com/redirect-path?querystring=Y&cf_user_email=user@example.com
```

## 정책 블록 동작 구성

DNS 정보 블록 정책, 당신은 표시 할 각 정책에 대한 블록 페이지를 켜해야합니다. HTTP 블록 정책의 경우 Gateway는 기본적으로 글로벌 블록 페이지를 자동으로 표시합니다. 각 정책의 설정 내에서 모든 정책 유형에 대한 글로벌 블록 페이지 설정을 override 할 수 있습니다.

블록 페이지에 턴하거나 글로벌 블록 페이지 설정을 통해 개별 정책:

## 제한 사항

### 인증서 오류

브라우저에서 보안 위험 경고를 받으면 차단된 페이지를 방문하면 제대로 확인해야 합니다.[인증서 설치](/cloudflare-one/team-and-resources/devices/user-side-certificates/manual-deployment/)그들의 장치에. 인증서가 설치되지 않거나 설치되지 않은 경우, 사용자의 브라우저가 발생할 수 있습니다.

- 표시하기**HTTP 응답 코드: 526**오류 페이지, insecure 업스트림을 나타내는.
- 연결을 닫고 어떤 페이지를 표시하지 못합니다.

문제 해결에 대한 자세한 내용은 참조[문제 해결](/cloudflare-one/faq/troubleshooting/#as-of-february-2-2025-my-end-user-devices-browser-is-returning-a-your-connection-is-not-private-warning).

### 데이터 센터 및 IP 주소 매칭

블록 정책을 일치 HTTP 요청하면 동일한 Cloudflare 데이터 센터에 DNS 쿼리로 도착하지 않는 경우 게이트웨이는 사용자 정의 블록 페이지 대신 기본 블록 페이지를 표시합니다.

이것은 IPv4, IPv6 및 DoH (HTTPS over HTTPS) 및 DoT (DNS over TLS)와 같은 암호화 된 프로토콜을 포함하여 게이트웨이 해결자 엔드 포인트로 보내 DNS 쿼리에 적용됩니다. DNS 쿼리가 해당 HTTP 요청보다 다른 Cloudflare 데이터 센터로 전달되는 경우 (예를 들어, DoH 트래픽이 WARP 터널 외부로 전송되는 경우) 게이트웨이는 두 요청을 correlate하고 사용자 정의 블록 페이지 대신 기본 블록 페이지를 표시 할 수 없습니다.

HTTP 요청이 DNS 요청보다 다른 IP 주소에서 제공되면 게이트웨이는 블록 페이지에서 규칙 ID, 사용자 정의 메시지 또는 다른 필드를 표시 할 수 없습니다. recursive DNS fixr의 소스 IP 주소가 사용자의 IP 주소와 다를 때 발생할 수 있습니다.
