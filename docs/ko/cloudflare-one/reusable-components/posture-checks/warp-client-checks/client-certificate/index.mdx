Client Certificate Device posture 속성은 신뢰할 수 있는 인증서에 의해 서명된 유효한 클라이언트 인증서가 있는지 확인합니다. 신뢰할 수있는 인증서는 Cloudflare에 업로드하고 자세 검사 규칙의 일부로 지정됩니다. 클라이언트 인증서 자세 검사는 Gateway 및 Access 정책을 사용하여 사용자가 관리 된 장치에서 연결되도록 사용할 수 있습니다.

## 자주 묻는 질문

- 귀하의 장치에 대한 클라이언트 인증서를 발급하는 CA. WARP는 인증서 신뢰 체인을 평가하지 않습니다. 발급 인증서가되어야합니다.

  :::note\[고객증을 발급한 서명 인증서]

  후속 검사에서 사용할 인증서를 업로드하면 Cloudflare는 루트와 중간 인증서를 구별하지 않습니다. 실제 서명 인증서를 업로드해야합니다 - 직접 클라이언트 인증서를 서명 한 것.

  다른 인증서를 업로드하면 신뢰 체인에서 더 높은 존재하더라도 (예를 들어, 서명 인증서를 발급 한 루트), 자세 검사가 실패합니다.

  :::

- Cloudflare WARP 클라이언트는 입니다[설치하기](/cloudflare-one/team-and-resources/devices/warp/deployment/)장치에서.

- 클라이언트 인증서는[설치 및 신뢰](#configure-the-client-certificate-check)장치에서.

:::참조

테스트를위한 샘플 루트 CA를 생성하려면, 참조[mTLS 인증서 생성](/cloudflare-one/access-controls/service-credentials/mutual-tls-authentication/#generate-mtls-certificates).
:::

## 클라이언트 인증서 확인 구성

2. 내 계정[사이트맵 한국어](https://one.dash.cloudflare.com), 이동**재사용 가능한 부품** > **자주 묻는 질문**.

3. 오시는 길**WARP 클라이언트 체크**선택하기**자주 묻는 질문**.

4. 제품정보**고객 인증서**.

5. 당신은 다음 정보를 위해 신속한 것입니다:
   1. **이름 \***: 이 장치 자세 검사에 대한 독특한 이름을 입력하십시오.
   2. **운영 체계**: 운영 체제를 선택하십시오.
   3. **OS 위치**: 클라이언트 인증서가 설치되는 위치를 지정합니다.

      <Details header="윈도우">
        - 현지 기계 신뢰점
        - 사용자 신뢰
      </Details>

      <Details header="맥 OS">
        - 시스템 키체인
      </Details>

      <Details header="리눅스">
        - 모델 번호: NSSDB`/etc/pki/nssdb`) - 주문 위치를 검색하려면, 입력
          인증서 및 개인 키에 절대 파일 경로 (s) (예를 들어
          `/usr/local/mycompany/certs/client.pem`·
          `/usr/local/mycompany/certs/client_key.pem`). 인증서 및
          개인 키는 있어야합니다`PEM`파일 형식. 그들은 둘 다에서 일 수 있습니다
          파일 또는 같은 파일.
      </Details>
   4. **인증서 ID**: 서명 인증서의 UUID를 입력합니다.
   5. **이름 \***: (선택 사항) 클라이언트 인증서에서 Common Name (CN)을 확인하려면 선택 문자열을 입력하십시오.`${serial_number}`·`${hostname}`변수 (예를 들면,`${serial_number}_mycompany`). WARP는 정확한, 케이스 과민한 경기를 위해 검색할 것입니다. 일반적인 이름을 지정하지 않으면 WARP는 인증서의 일반적인 이름 필드를 무시합니다.
   6. **확장 키 사용을위한 체크**: (선택 사항) 클라이언트 인증서가 하나 이상의 속성을 설정했는지 확인하십시오. 지원된 값은**고객 인증** (`1.3.6.1.5.5.7.3.2`)와/또는**이름 \*** (`1.3.6.1.5.5.7.3.4`).
   7. **자주 묻는 질문**: (추천) 사용할 때 WARP는 클라이언트 인증서와 관련된 개인 키가 있음을 확인합니다.
   8. **제목 내용**: (선택 사항) 클라이언트 인증서의 제목 대체 이름 (SAN)을 확인하려면 선택 문자열을 입력`${serial_number}`·`${hostname}`변수 (예를 들면,`${serial_number}_mycompany`). WARP는 정확한, 케이스 과민한 경기를 위해 검색할 것입니다. 자세 검사에 여러 SAN을 추가 할 수 있습니다 - 인증서는 확인을 위해 하나의 SAN과 일치해야합니다.

6. 제품정보**제품 정보**.

다음으로 이동**관련 기사** > **로그인** > **Posture 로그**클라이언트 인증서 확인은 예상 결과를 반환합니다.

## 문제 해결

클라이언트 인증서가 제대로 설치되고 신뢰할 경우 다음 명령을 사용할 수 있습니다.

<Tabs>
  <TabItem label="윈도우">
    1. PowerShell 창을 엽니다.
    2. 특정 일반적인 이름을 가진 인증서에 대한 로컬 머신 신뢰 저장소를 검색하려면 다음 명령을 실행하십시오.

    ```powershell
    Get-ChildItem Cert:\LocalMachine\My\ | where{$_.Subject -like "*<COMMON_NAME>*"}
    ```

    3. 특정 일반적인 이름으로 인증서에 대한 사용자 신뢰 저장소를 검색하려면 다음 명령을 실행하십시오.

    ```powershell
    Get-ChildItem Cert:\CurrentUser\My\ | where{$_.Subject -like "*<COMMON_NAME>*"}
    ```
  </TabItem>

  <TabItem label="맥 OS">
    1. 오픈 터미널
    2. 특정 일반적인 이름으로 인증서에 대한 시스템 키체인을 검색하려면 다음 명령을 실행하십시오.

    ```sh
    /usr/bin/security find-certificate -c "<COMMON_NAME>" -p /Library/Keychains/System.keychain
    ```
  </TabItem>

  <TabItem label="리눅스">
    1. 오픈 터미널
    2. NSSDB의 모든 클라이언트 인증서를 나열하려면 다음 명령을 실행하십시오.

    ```sh
    certutil -L -d /etc/pki/nssdb
    ```


    3. 인증서 별명을 사용하여 원하는 인증서를 엽니다. 일반적인 이름은 선에서 나타날 것입니다.`Subject: "CN=123456.mycompany"`.

    ```sh
    certutil -L -d /etc/pki/nssdb -n meow
    ```
