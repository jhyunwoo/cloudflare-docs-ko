Gateway는 애플리케이션 및 앱 유형에 따라 DNS, 네트워크 및 HTTP 정책을 만들 수 있습니다. 사용자의 네트워크에 특정 트래픽을 필터링하기 위해 개별 애플리케이션 또는 그룹을 선택할 수 있습니다.

## 이름 \*

당신이 선택할 때*제품 설명*Gateway 정책 빌더의 선택자,**제품정보**필드는 모든 지원되는 응용 프로그램과 해당 응용 프로그램을 포함합니다. 대안으로, 당신은 사용할 수 있습니다[게이트웨이 API](/api/resources/zero_trust/subresources/gateway/subresources/app_types/methods/list/)응용 프로그램, 앱 유형 및 ID 번호 목록을 fetch합니다.

Cloudflare의 통합 목록 관리 하나, 당신은 사용할 수 있습니다[회사연혁](/cloudflare-one/team-and-resources/app-library/).

## 신청 hostnames

Cloudflare에 의해 분류하는 신청은 기능을 제공하기 위하여 다른 내부와 외부 자원의 수에 자주적으로 의존할지도 모릅니다. 허용 및 블록 게이트웨이 정책의 효과적인 행동을 가능하게하려면 Cloudflare 1개의 별도의 애플리케이션 정의[이름 \*](#hostnames)·[지원 hostnames](#support-hostnames).

### 이름 \*

Hostnames는 응용 프로그램에 코어가 아닌 도메인입니다.[다른 신청에 의해 사용하는](#overlapping-hostnames). 이 도메인은 응용 프로그램을 차단할 때 특별히 차단됩니다. App Library는 이 hostnames를[Hostnames 테이블](/cloudflare-one/team-and-resources/app-library/#overview)신청하기

### 지원 hostname

지원 hostnames는 함수를 순서로 호출할 수 있는 공유 자원입니다. 애플리케이션은 콘텐츠 전달, 애플리케이션 행동, 또는 타사 시스템 통합에 대한 지원 호스트명을 사용할 수 있습니다. 이 호스트명을 차단하면 다른 정책에 대한 예상치 못한 행동이 발생할 수 있습니다. 또한, 이러한 호스트 이름 중 하나에 특정 조치를 취하지 않고 응용 프로그램의 행동에 영향을 미칠 수 있습니다. 예를 들어, 그렇게 가정`file-sharing-service.com`관련 기사`content-delivery.com`. 접근을 허용하는 경우`file-sharing-service.com`그리고 그 관련 하위 도메인은 아니지만`content-delivery.com`, 몇몇의 기능의`file-sharing-service.com`Gateway가 트래픽을 일치할 때 휴식 할 수 있습니다.

효과적인 애플리케이션 행동을 보장하기 위해 Gateway는 허용 정책의 지원 호스트명을 사용합니다. Cloudflare는 명시적으로 이러한 정책의 호스트 이름 연결을 지원하지만 블록 정책의 연결을 차단하지 않습니다. 예를 들어, 많은 Google 애플리케이션 사용`accounts.google.com`인증. Cloudflare에서 높은 제한적인 정책을 가진 1개의 환경,`accounts.google.com`제대로 기능할 것이다 많은 신청을 위해 허용되어야 합니다. 응용 프로그램을 사용하는 경우`accounts.google.com`허용 정책의 지원 호스트 이름에서 Gateway는 모두 허용됩니다.`accounts.google.com`그리고 애플리케이션의 도메인.

## 제품 정보

### Overlapping 호스트 이름

Overlapping hostnames는 Google 또는 Meta와 같은 많은 응용 프로그램을 가진 납품업자를 위해 가장 일반적입니다. 게이트웨이 정책의 Application selector를 사용할 때 게이트웨이에 의해 찍은 행동은 특정 응용 프로그램에 정의됩니다. 게이트웨이는 같은 호스트명을 사용하는 다른 응용 프로그램을 기록하지만, 응용 프로그램이 정책에 의해 일치하지 않는 한 행동을하지 않습니다. 예를 들어 Facebook과 Facebook Messenger 앱 모두 사용`chat-e2ee.facebook.com`이름. Facebook Messenger 앱으로 트래픽을 평가할 때 Gateway는 Facebook Messenger 트래픽에서만 동작하지만 Facebook 및 Facebook Messenger 앱을 모두 로그 할 수 있습니다.

게이트웨이가 원하는 선행으로 트래픽을 평가하기 위해 가장 높은 우선 순위를 가진 가장 구체적인 정책을 주문하십시오.[우선순위](/cloudflare-one/traffic-policies/order-of-enforcement/#priority-within-a-policy-builder).

### 적용을 검사하지 마십시오

Gateway는 TLS decryption과 호환이 되는 그룹 애플리케이션을*검사하지 마십시오*앱 유형. Cloudflare가 호환되는 응용 프로그램을 식별하므로 Gateway는 주기적으로 새로운 응용 프로그램을 추가하기 위해이 응용 프로그램을 업데이트합니다. 게이트웨이는 현재 또는 미래의 호환 트래픽을 방해하지 않습니다.[HTTP 정책을 검사하지 마십시오](/cloudflare-one/traffic-policies/http-policies/#do-not-inspect)전체보기*검사하지 마십시오*앱 유형 선택.

앱 관리[회사연혁](/cloudflare-one/team-and-resources/app-library/), 응용 프로그램을 검사하지 마십시오. 예를 들어 App Library는 그룹*Google 드라이브 (검사하지 않음)*&#xC774;름 \***Google 드라이브**.

:::note\[Install Cloudflare 인증서는 수동으로 TLS 해독을 허용]
Do Not Inspect policy for application 대신 응용 프로그램을 구성할 수 있습니다.[Cloudflare 인증서 신뢰](/cloudflare-one/team-and-resources/devices/user-side-certificates/manual-deployment/#add-the-certificate-to-applications). 이렇게 할 것은 당신의 소통량으로 가시성을 잃지 않고 기능을 할 수 있습니다.

#### Microsoft 365 통합

Microsoft 365 애플리케이션 및 서비스에 대한 성능을 최적화하려면 Microsoft 365 트래픽 통합을 전환하여 TLS 해독을 우회할 수 있습니다. 이것은 만들 것입니다[Inspect 정책 없음](/cloudflare-one/traffic-policies/http-policies/#do-not-inspect)모든 것[Microsoft 365 도메인 및 IP 주소](https://docs.microsoft.com/en-us/microsoft-365/enterprise/microsoft-365-ip-web-service)Microsoft에 의해 지정. 이 정책은 Cloudflare 정보를 사용하여 다른 Microsoft 365 트래픽을 명시적으로 정의하지 않습니다.

Microsoft 365 통합을 켜려면:

1. 내 계정[모델 번호: Cloudflare 한국어](https://one.dash.cloudflare.com/), 이동**교통 정책** > **교통 설정** > **정책 설정**.
2. 내 계정**Microsoft 365 트래픽의 해독**, 선택**공지사항**.
3. 정책을 확인하려면, 선택**공지사항**. 대안으로, 이동**교통 정책** > **HTTP 정책**. Microsoft 365 Auto Generated라는 정책은 목록에서 활성화됩니다.

모든 미래 Microsoft 365 트래픽은 Gateway 로깅 및 필터링을 우회합니다. 이 행동을 비활성화하려면, 끄거나 정책을 삭제합니다.

### 옵션 정보

Terraform 사용자는 앱 유형 목록을 검색 할 수 있습니다.`cloudflare_zero_trust_gateway_app_types_list`데이터 소스. 이로 인해 해당 국가의 ID가 아닌 응용 프로그램의 이름을 가진 Gateway 정책을 만들 수 있습니다. 예를 들면:

```tf
data "cloudflare_zero_trust_gateway_app_types_list" "gateway_apptypes" {
  account_id = var.cloudflare_account_id
}

locals {
  apptypes_map = merge([
    for c in data.cloudflare_zero_trust_gateway_app_types_list.gateway_apptypes.result :
    { (c.name) = c.id }
  ]...)
}

resource "cloudflare_zero_trust_gateway_policy" "zt_block_dns_apps" {
  account_id = var.cloudflare_account_id
  name       = "DNS Blocked apps"
  action     = "block"
  traffic    = "any(app.ids[*] in {${join(" ", [
    local.apptypes_map["Discord"],
    local.apptypes_map["GoToMeeting"],
    local.apptypes_map["Greenhouse"],
    local.apptypes_map["Zelle"],
    local.apptypes_map["Microsoft Visual Studio"]
  ])}})"
}
```
