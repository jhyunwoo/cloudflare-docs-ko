Cloudflare 네트워크 방화벽 규칙은 Cloudflare의 DDoS 완화가 적용됩니다. 두 시스템은 독립적이며, Cloudflare 네트워크 방화벽 내부의 트래픽을 허용하지 않습니다 우리의 DDoS 완화. 트래픽은 여전히 Cloudflare의 시스템을 통해 흐름에 적용 된 DDoS 완화에 의해 차단 될 수 있습니다.

기본적으로 Cloudflare Network Firewall 정책은 규칙에 의해 명시적으로 차단 될 때까지 모든 트래픽을 허용합니다. 정책이 구성되지 않으면 DDoS 완화가 적용된 후 모든 트래픽이 허용됩니다.

## 보안 정책

보안 정책을 구성하기위한 두 가지 옵션이 있습니다.

- 모든 것을 차단하고 특정 필수 트래픽에 대한 규칙을 허용하는 긍정적 인 보안 모델을 강화하십시오.
- 특정 트래픽을 차단하고, 기본적으로 다른 모든 것이 허용됩니다.

트래픽은 구성 된 규칙의 순서에 일치합니다. 트래픽이 활성화 된 규칙에 의해 일치하므로 나중에 규칙에 더 이상 유효하지 않습니다. 무능한 규칙은 완전히 건너 뛸 수 있습니다 - 트래픽은 그들에 대해 평가되지 않습니다. 대시보드에서**교통 정책** > **방화벽 정책**, 규칙 순서는 정상에서 시작하고 규칙의 명부를 아래로 흐릅니다.

예를 들어 규칙 #4에서 모든 TCP 트래픽을 허용하면 모든 TCP 트래픽이 허용됩니다. 규칙 #5 IP 주소에 대한 트래픽 차단`x.x.x.x`확인되지 않습니다.

보안 정책을 구성 할 때 가장 좋은 관행을 위해, 참조[좋은 관행](/cloudflare-network-firewall/best-practices/).

## Packet 필터링 정책 및 Magic Transit endpoint 건강 검사

Cloudflare-sourced 트래픽은 Cloudflare 네트워크 방화벽 규칙에 따라 구성됩니다. 모든 ICMP 트래픽을 차단하면 Cloudflare를 차단합니다.<GlossaryTooltip term="tunnel health-check" link="/magic-transit/reference/tunnel-health-checks/#endpoint-health-checks">endpoint 건강 검사</GlossaryTooltip>. ICMP 트래픽을 막을 때, 당신의 규칙을 첫째로 구획 ICMP 규칙을 적용하기 전에 당신의 접두사 엔드 포인트 IPs에 Cloudflare 공중 IPs에서 sourced 허용하십시오.

Cloudflare의 공중 IPs의 명부를 위해, 참조하십시오[IP 범위](https://www.cloudflare.com/ips/).

## Cloudflare 네트워크 방화벽 단계

트래픽은 두 단계로 처리됩니다: 당신의 관례 규칙에 대하여 첫째로, 그 후에 Cloudflare의 관리한 규칙에 대하여.

### 주문 단계 통치자

Custom phase는 정의하고 제어하는 규칙의 집합입니다. 이 규칙의 표현, 순서 및 행동을 사용자 정의 할 수 있습니다.

Cloudflare Network Firewall은 전신의 순서에 관리 된 정책 전에 사용자 정의 정책을 평가합니다. 따라서 트래픽이 사용자 정의 정책에서 조건을 먼저 충족하면 행동 Cloudflare 네트워크 방화벽이 취합니다.

사용자 정의 규칙에 사용할 수있는 작업은**제품정보**또는**팟캐스트**(로).

### 관리 단계 통치자

관리 단계 규칙은 Cloudflare에 의해 유지되고 제일 연습, 알려진 악의적인 본 및 다른 위협 인텔에 근거를 둔 규칙을 포함합니다.

Cloudflare는 관리되는 단계에 있는 규칙을 위한 실행의 표정 그리고 순서를 유지합니다. 해당 패킷을 매칭할 수 있는 개별 규칙을 설정할 수 있습니다.
