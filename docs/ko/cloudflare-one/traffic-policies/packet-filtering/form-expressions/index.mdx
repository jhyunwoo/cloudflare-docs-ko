규칙은 Cloudflare 규칙 언어를 사용하여 작성됩니다 - 도메인 별 언어 (DSL)는 mimic Wireshark semantics에 예정되어 있습니다. 더 많은 정보를 원하시면, 참조[언어 선택](/ruleset-engine/rules-language/)문서.

간단한 케이스로 시작하려면 소스 IP와 일치하는 방법 아래 검토하십시오. 이 표현에서`ip.src`수신 패킷의 소스 IP 주소를 나타냅니다.`==`"equals":

```txt
ip.src == 192.0.2.0
```

Expressions는 논리 연산자를 통해 여러 항목에 가입하여 더 복잡 할 수 있습니다 (`&&`의미와,`||`의미 OR). 다음 표식 일치 패킷에서`192.0.2.1`TCP 푸시 또는 재설정 플래그 세트가 있습니다.

```txt
ip.src == 192.0.2.1 && (tcp.flags.push || tcp.flags.reset)
```

## 회사연혁

Cloudflare 네트워크 방화벽을 사용하여 건너뛰거나 차단할 수 있습니다.<GlossaryTooltip term="data packet">제품정보</GlossaryTooltip>소스 또는 목적지 IP, 소스 또는 목적지 포트, 프로토콜, 패킷 길이 또는<GlossaryTooltip term="bit field matching">비트 필드 일치</GlossaryTooltip>.

## 제한 사항

표현식 엔진은 CIDR 표기 (IP 주소는 다음과 같습니다.`192.0.2.0/24`), 그러나 curly 버팀대 세트 안쪽에서만. 베어 비교는 예상대로 작동하지 않습니다 :

```txt
ip.src == 192.0.2.0/24  # bad
ip.src in { 192.0.2.0/24 }  # good
```

Expressions는 많은 참여 또는 배열된 항목이 표현될 때 쉽게 접근할 수 있는 복잡성 한계가 있습니다. 다음은 예입니다:

```txt
(tcp.dstport == 1000 || tcp.dstport == 1001) && (tcp.dstport == 1002 || tcp.dstport == 1003) && (tcp.dstport == 1004 || tcp.dstport == 1005) && (tcp.dstport == 1006 || tcp.dstport == 1007) && (tcp.dstport == 1008 || tcp.dstport == 1009) && (tcp.dstport == 1010 || tcp.dstport == 1011) && (tcp.dstport == 1012 || tcp.dstport == 1013) && (tcp.dstport == 1014 || tcp.dstport == 1015) && (tcp.dstport == 1016 || tcp.dstport == 1017)
```

제한이 도달되면 응답은`400`상태 코드 및 오류 메시지`ruleset exceeds complexity constraints`. 여러 규칙을 통해 표현을 분할하고 다시 시도. 각 규칙은 조건의 하위 집합을 처리 할 수 있으며 방화벽은 주문에서 평가합니다.
