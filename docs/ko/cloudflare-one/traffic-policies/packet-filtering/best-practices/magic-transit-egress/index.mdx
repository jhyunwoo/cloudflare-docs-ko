에 대한 제안[미니멀 규칙](/cloudflare-one/traffic-policies/packet-filtering/best-practices/minimal-ruleset)·[확장 규칙](/cloudflare-one/traffic-policies/packet-filtering/best-practices/extended-ruleset)ingress (incoming) 트래픽에 대한 권장 사항입니다. 이 페이지는 egress (outgoing) 트래픽에 필요한 추가 고려사항을 다룹니다.

Cloudflare 네트워크 방화벽은 연결 상태를 추적하지 않습니다 (그것은 "stateful"). 상태의 방화벽은 자동으로 활성 연결에 대한 트래픽을 반환 할 수 있습니다. 예를 들어, 요청 아웃 바운드를 보내면 응답이 허용됩니다. Network Firewall이 stateful이 아니기 때문에, 각 패킷은 - ingress 또는 egress가 아닌 - 규칙에 대해 독립적으로 평가됩니다. 이것은 ingress 블록 규칙을 inadvertently 막 egress 트래픽을 의미한다.

Magic Transit egress 트래픽의 경우 다음을 고려하십시오.

- 네트워크 방화벽 규칙은 Cloudflare를 통해 통과하는 Magic Transit ingress 및 egress 트래픽에 적용됩니다.
- "default drop" catchall 규칙이 있다면 (이전 규칙과 일치하지 않는 모든 트래픽을 차단하는 마지막 규칙) 진입 트래픽을 위해, 당신은 당신의 Magic Transit 접두사에서 소스를 허용하는 이전 규칙을 추가해야합니다 목적지로 목적지**이름 \***&#xC544;웃바운드 egress 트래픽을 허용한다.

  예를 들어, 다음과 같은 경우 기본 드롭 catchall 규칙을 허용하십시오.

  **이름 \***: `ip.src in {<YOUR_MAGIC_TRANSIT_PREFIX>}` <br />
  **- 연혁**: 허용
