모든 방화벽 정책을 보유하고 있는 최상위 컨테이너입니다. 대시보드 또는 [계정 rulesets API](/api/resources/rulesets/methods/list/)를 통해 기존 루트 ruleset을 확인할 수 있습니다. 새로운 Magic Transit 고객이라면 계정에 생성된 루트 ruleset이 없을 수 있습니다. 루트 ruleset 예제를 보려면 [Cloudflare 네트워크 방화벽 Terraform 문서](https://registry.terraform.io/providers/cloudflare/cloudflare/latest/docs/resources/magic_firewall_ruleset)를 검토하세요.

기본적으로 최대 200개의 정책을 만들 수 있습니다. 필요한 경우 더 높은 제한을 요청하려면 계정 팀에 문의하십시오. 정책 내에서 참고 자료에 IP 주소 목록을 작성하는 것이 좋습니다.

## 정책 추가

1. 로그인하기[Cloudflare 대시보드](https://dash.cloudflare.com/)·**사업영역** > **방화벽 정책**.
2. 제품정보**정책 추가**.
3. 새로운 정책에 대한 정보를 작성하십시오. 모든 기존 정책은 IPv4 트래픽에만 적용됩니다. 당신은 사용할 수[관리 IP 목록](/waf/tools/lists/managed-lists/#managed-ip-lists)때 populating**제품정보**.
4. 당신이 할 때, 선택**새 정책 추가**.

## 정책 업데이트

1. 로그인하기[Cloudflare 대시보드](https://dash.cloudflare.com/)·**사업영역** > **방화벽 정책**.
2. 편집하고 세 가지 점을 선택하십시오 >**제품정보**.
3. 변경 사항 및 선택에 대한 정책 업데이트**제품 정보**.

## 기존 정책 삭제

1. 목록에서 삭제하려는 정책을 찾습니다.
2. 행 끝에서, 선택**이름 \***.
3. 제품정보**이름 \***&#xC0AD;제를 다시 확인합니다.

## 사이트맵

아래에서 API를 사용하여 특정 작업을 수행하는 방법을 찾을 수 있습니다.

:::카트로션\[Warning]

이 페이지의 예는 모두 사용`https://api.cloudflare.com/client/v4/accounts/{account_id}/rulesets`끝점. 이 엔드포인트는 처음부터 정책을 작성하고**규칙의 모든 기존 정책을 대체합니다.**.

이미 배포된 규칙이 있다면,`https://api.cloudflare.com/client/v4/accounts/{account_id}/rulesets/{ruleset_id}/rules`대신 종료.

더 알아보기[규칙에 추가](/ruleset-engine/rulesets-api/add-rule/)·[계정 규칙 만들기](/api/resources/rulesets/methods/create/)더 많은 정보.

:::

### 공지사항

건너뛰기 행동은 방화벽이 일치 트래픽을 위해 현재 규칙을 평가하고 효과적으로 그것을 통해 허용한다. 상단에서 하단으로 순서대로 규칙을 평가합니다. 아래 예에서, 건너뛰기 규칙은 블록 규칙 전에 나타나므로 해당 트래픽 (포트`8080`)는 catch-all 블록이 적용되기 전에 허용됩니다.

```bash
curl https://api.cloudflare.com/client/v4/accounts/{account_id}/rulesets \
--header "Authorization: Bearer <API_TOKEN>" \
--header "Content-Type: application/json" \
--data '{
  "name": "Example ruleset",
  "kind": "root",
  "phase": "magic_transit",
  "description": "Example ruleset description",
  "rules": [
    {
      "action": "skip",
      "action_parameters": { "ruleset": "current" },
      "expression": "tcp.dstport in { 8080 } ",
      "description": "Allow port 8080"
    },
    {
      "action": "block",
      "expression": "tcp.dstport in { 1..65535 }",
      "description": "Block all TCP ports"
    }
  ]
}'
```

### 국가 차단

아래 예제는 브라질에서 온 소스 또는 목적지 IP 주소로 모든 패킷을 차단하여 2-letter 국가 코드를 사용하여[ISO 3166-1 알파 2](https://www.iso.org/obp/ui/#search/code/)파일 형식.

```bash
curl https://api.cloudflare.com/client/v4/accounts/{account_id}/rulesets \
--header "Authorization: Bearer <API_TOKEN>" \
--header "Content-Type: application/json" \
--data '{
  "name": "Example ruleset",
  "kind": "root",
  "phase": "magic_transit",
  "description": "Example ruleset description",
  "rules": [
    {
      "action": "block",
      "expression": "ip.src.country == \"BR\"",
      "description": "Block traffic from Brazil"
    }
  ]
}'
```

### IP 목록 사용

Cloudflare 네트워크 방화벽 지원[본문 바로가기](/waf/tools/lists/use-in-expressions/)제품정보`ip.src`·`ip.dst`이름 \* 지원된 목록은:

- `$cf.anonymizer`- 익명 프록시
- `$cf.botnetcc`- Botnet 명령 및 제어 채널
- `$cf.malware`- 악성 코드의 소스
- `$<IP_LIST_NAME>`- 계정 수준 IP 목록의 이름

```bash
curl https://api.cloudflare.com/client/v4/accounts/{account_id}/rulesets \
--header "Authorization: Bearer <API_TOKEN>" \
--header "Content-Type: application/json" \
--data '{
  "name": "Example ruleset",
  "kind": "root",
  "phase": "magic_transit",
  "description": "Example ruleset description",
  "rules": [
    {
      "action": "block",
      "expression": "ip.src in $cf.anonymizer",
      "description": "Block traffic from anonymizer proxies"
    }
  ]
}'
```
