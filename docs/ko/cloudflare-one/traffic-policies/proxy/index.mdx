당신은 앞으로 할 수 있습니다[HTTP: HTTP](/cloudflare-one/traffic-policies/get-started/http/)·[네트워크](/cloudflare-one/traffic-policies/get-started/network/)로그인 및 필터링 게이트웨이에 트래픽. 게이트웨이는 Cloudflare 터널, GRE 터널 또는 IPsec 터널을 통해 연결된 리소스로 구성된 아웃바운드 트래픽 및 트래픽을 프록시 할 수 있습니다. 사용자가 게이트웨이 프록시에 연결하면 게이트웨이가 연결을 수락하고 새로운, 별도의 연결을 설정할 수 있습니다.

Gateway 프록시는 트래픽 및 DNS 모드에서 WARP 클라이언트를 통해 HTTP 및 네트워크 트래픽을 필터링하는 데 필요합니다. WARP 클라이언트를 배치하지 않고 HTTP 트래픽을 프록시하려면 구성할 수 있습니다.[PAC 파일](/cloudflare-one/networks/resolvers-and-proxies/proxy-endpoints/)당신의 장치에.

## 프록시 알고리즘

Gateway는[Happy Eyeballs 알고리즘](https://datatracker.ietf.org/doc/html/rfc6555)뒤에 오는 순서에 있는 프록시 교통에:

1. 사용자의 브라우저는 Gateway를 TCP SYN 세그먼트로 전송하여 TCP 핸싱을 시작합니다.
2. Gateway는 Origin 서버에 SYN 세그먼트를 보냅니다.
3. Origin 서버가 SYN-ACK 세그먼트를 다시 보내면 Gateway는 사용자와 Gateway와 Gateway와 Origin 서버 사이에 별도의 TCP 연결을 설정합니다.
4. Gateway는 사용자가 수신한 필터 트래픽을 검사합니다.
5. 트래픽이 검사를 통과하면 Gateway 프록시 트래픽은 사용자와 Origin 서버간에 양방향으로 전달됩니다.

## 지원된 의정서

Gateway는 TCP, UDP 및 ICMP 트래픽 프록시를 지원합니다.

### TCP 포트

프록시가 활성화되면 Gateway는 항상 TCP 트래픽을 전달합니다.

기본적으로 TCP 연결 시도는 30 초 후에 timeout이고 idle 연결은 8 시간 후에 차단될 것입니다.

### 사이트맵

UDP 프록시는 VoIP와 같은 UDP 트래픽을 전달[내부 DNS 요청](/cloudflare-one/networks/connectors/cloudflare-tunnel/private-net/cloudflared/private-dns/), 및 두꺼운 클라이언트 신청.

HTTP / 3 트래픽을 기록하고 필터링하려면 TLS decryption과 Gateway proxy를 UDP로 전환해야하므로 게이트웨이는 HTTP / 3 트래픽을 HTTP / 2로 강제로 검사 할 수 있습니다. 그렇지 않으면 HTTP / 3 트래픽은 검사를 우회합니다. 더 많은 정보를 원하시면, 참조[HTTP/3 검사](/cloudflare-one/traffic-policies/http-policies/http3/).

### ICMP를<Badge text="Beta" variant="caution" size="small" />

ICMP 프록시는 ICMP 트래픽을 통해 게이트웨이를 통해 개인 네트워크에 도달 할 수 있습니다. 예를 들어, WARP 사용자가 같은 진단 명령을 실행할 수 있습니다.`ping`·`traceroute`내부 서버 IP에.

:::카트로션\[Limitation]
게이트웨이는 ICMP 트래픽을 로그 또는 필터링할 수 없습니다.
주요 특징
