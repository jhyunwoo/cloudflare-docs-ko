다음 정책은 일반적으로 네트워크 트래픽을 확보하는 데 사용됩니다. 네트워크 정책은 정상에서 바닥까지 순서로 평가되며, 첫 번째 일치 정책은 적용됩니다. 더 넓은 블록 정책에 따라 더 구체적인 허용 정책을 배치하십시오.

권장 정책의 기본 설정에 대한 참조[인터넷 트래픽 및 SaaS 앱 보안](/learning-paths/secure-internet-traffic/build-network-policies/recommended-network-policies/).

더 알아보기[네트워크 정책 페이지](/cloudflare-one/traffic-policies/network-policies/)다른 selectors, 연산자 및 작업의 종합 목록.

## 승인된 트래픽만 허용

특정 사이트 또는 응용 프로그램에 대한 사용자 접근 제한[HTTP 정책](/cloudflare-one/traffic-policies/http-policies/). 이 패턴은 두 가지 정책을 사용합니다 : HTTP / HTTPS 트래픽을 허용하는 허용 정책은 블록 정책에 따라 다른 모든 것을 거부합니다. 블록 정책 위의 허용 정책을 배치하기 때문에 매칭 트래픽은 catch-all 블록 적용 전에 허용됩니다.

### 1. HTTP 및 HTTPS 트래픽 허용

    | ------- | ----- | ----------- | ----- | ---- |
    | 검출된 의정서 | 이름 \* | *사이트맵*      | 이름 \* | 지원하다 |

## 모든 포트에서 검사할 때 HTTPS 트래픽 필터

조직이 네트워크 정책과 기본적으로 트래픽을 차단하고 싶다면[모든 포트에서 HTTP 트래픽을 검사](/cloudflare-one/traffic-policies/network-policies/protocol-detection/#inspect-on-all-ports), 당신은 명시적으로 그것을 필터링 HTTP 및 TLS 트래픽을 허용해야합니다.

<Tabs syncKey="dashPlusAPI">
  <TabItem label="모델 번호: 대시보드">
    | 옵션 정보   | 회사연혁  | 제품정보         | 로그인 | - 연혁 |
    | ------- | ----- | ------------ | --- | ---- |
    | 검출된 의정서 | 이름 \* | *사이트맵*       | 또는  | 지원하다 |

  </TabItem>

  <TabItem label="사이트맵">
    <APIRequest
      path="/accounts/{account_id}/gateway/rules"
      method="POST"
      json={{
  	name: "Allow on inspect all ports",
  	description: "Filter HTTPS traffic when using inspect all ports",
  	enabled: true,

## 프록시 엔드포인트 사용자에게 개인 네트워크 액세스를 제한

프록시 엔드포인트를 사용할 때, 기본적으로 프록시 엔드포인트에 추가된 모든 디바이스는 내부 애플리케이션 및 서비스에 접속할 수 있습니다.[Cloudflare 갱도](/cloudflare-one/networks/connectors/cloudflare-tunnel/). 접근을 제한하고 보안의 추가 층을 추가하려면 다음 정책을 작성하십시오.

사용 방법[소스 IP 프록시 엔드포인트](/cloudflare-one/networks/resolvers-and-proxies/proxy-endpoints/#source-ip-endpoint), 특정 소스 IP에서 프록시 엔드포인트를 통해 접속하는 유일한 사용자에게 제한.

## IP 주소

다른 IP 주소를 가진 특정 IP 주소를 지시하는 Override 트래픽.

<Tabs syncKey="dashPlusAPI">
  <TabItem label="모델 번호: 대시보드">
    | 옵션 정보 | 회사연혁  | 제품정보           | 로그인   | - 연혁          |
    | ----- | ----- | -------------- | ----- | ------------- |
    | 대상 IP | 내 계정  | `203.0.113.17` | 이름 \* | 네트워크 Override |
    | 관광 명소 | 이름 \* | `80`           |       |               |

    | IP 등급     | 공급 능력 |
    | --------- | ----- |
    | `1.1.1.1` | `80`  |
  </TabItem>

  <TabItem label="사이트맵">
    <APIRequest
      path="/accounts/{account_id}/gateway/rules"
      method="POST"
      json={{
  	name: "Override example.com with 1.1.1.1",
  	description: "Override a site's IP address with another IP",
  	enabled: true,
  	action: "l4_override",
  	filters: ["l4"],
  	traffic: "net.dst.ip in {203.0.113.17} and net.dst.port == 80",
  	identity: "",
  	device_posture: "",
  	rule_settings: {
  		l4override: {
  			ip: "1.1.1.1",
  			port: 80,
  		},
  		override_host: "",
  		override_ips: null,
  	},
  }}
    />
  </TabItem>
</Tabs>
