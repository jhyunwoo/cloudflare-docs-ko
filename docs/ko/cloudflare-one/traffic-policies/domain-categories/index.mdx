모델 번호: Cloudflare Gateway는 공공 인터넷에서 알려진 잠재적 인 보안 위험뿐만 아니라 특정 카테고리의 콘텐츠를 차단 할 수 있습니다. 도메인은 분류됩니다.[구름 하나](/security-center/cloudforce-one/), Cloudflare의 위협 정보 해결책. 특정 도메인에 대한 범주를 검토하려면, 사용[Cloudflare 레이더](/radar/glossary/#content-categories).

Cloudflare는 보안 위험과 보안 위협을 커버하는 내용 범주 및 보안 범주로 도메인을 분류합니다.

- **관련 분류**: Upstream 공급 업체는 도메인에 대한 콘텐츠 범주를 공급합니다. 이 카테고리는 영역으로 도메인을 구성하는 데 도움이됩니다. 그러나, 우리의 납품업자에 의해 이용된 특정한 기준 및 방법은 공개되지 않을지도 모릅니다.
- **보안 위험**: Cloudflare는 내부 모델을 사용하여 도메인에 대한 보안 위험을 결정합니다. 이 모델은 도메인과 그 명성의 나이를 포함하여 다양한 요소를 분석합니다. 이것은 잠재적으로 위험한 도메인을 식별 할 수 있습니다.
- **보안 위협**: Cloudflare는 내부 데이터 소스, 기계 학습 모델, 상용 피드 및 오픈 소스 위협 인텔의 혼합을 고용하는 악성 도메인을 식별하기 위해.

DNS 또는 HTTP 정책을 생성하여 보안 및 콘텐츠 범주를 차단할 수 있습니다. 귀하의 정책을 구성하면 게이트웨이 로그에 네트워크 활동과 관련된 범주를 검사 할 수 있습니다.

도메인의 categorization로 변경하려면, 참조[관련 항목](/security-center/investigate/change-categorization/). 잠재적으로 위험한 도메인을 투자에 대한 자세한 내용은 참조[위험 경고](/security-center/investigate/investigate-threats/#domain).

:::노트\[Subdomain 카테고리]

카테고리를 할당하지 않은 하위 도메인은 부모 도메인의 범주를 상속합니다. Gateway가 하위 도메인을 분류 할 때 하위 도메인은 자신의 범주 만 수행됩니다. Categorized 하위 도메인은 부모 도메인의 범주를 상속하지 않습니다.

| -------------------- | ------------------------------------------------------------------------------------------------ |

| 스낵 바                 | 원치 않는 청소, 설문 조사 및 광고와 사용자를 대상으로 한 사이트.                                                           |
| 스파이웨어                | 원치 않는 광고를 표시하거나 사용자의 지식없이 사용자 정보를 수집하는 코드를 배포하거나 포함하도록 알려진 사이트.                                  |

## 필터링 옵션

### IP 카테고리를 해결하여 트래픽 필터

보안 또는 콘텐츠 카테고리의 DNS 정책을 만들 때 선택적으로 켜질 수 있습니다.**IP 카테고리를 해결하여 트래픽 필터**정책 설정에서. 설정할 때 게이트웨이는 도메인 이름 이외에 해결된 IP 주소를 기반으로 쿼리를 차단합니다. 이 설정은 블록 된 카테고리의 도메인이 IP 주소를 합법적으로 공유 할 수 있기 때문에 false 긍정적 인 수를 늘릴 수 있습니다.

### 이름 \*`CNAME`도메인 범주

사이트의 범주`CNAME`기록은 그것과 다를 수 있습니다`A`이름 \* 예를 들어,`blog.example.com`개인 블로그에서 분류 될 수 있습니다, 동안`example.com`기술 밑에 분류됩니다. DNS 정책을 제한하려면 루트 도메인의 범주에만 해당합니다.**Ignore CNAME 도메인 카테고리**.

이 설정에 대해`CNAME`도메인 범주는 여전히 게이트웨이에 표시됩니다[다운로드](/cloudflare-one/insights/logs/logpush/)로그아웃

## Categorization 과정

Cloudflare의 도메인 categorization 엔진은 다음과 같은 여러 데이터 소스로 시작합니다.

1. Cloudflare의 세계적인 네트워크를 사용하여 독점적인 자료.

2. 제3자 정보 피드. Cloudflare는 Avira와 Zvelo와 같은 30 개 이상의 오픈 소스 정보 피드 및 프리미엄 상업 피드에서 데이터를 사용합니다.

그런 다음 초기 categorization는 다음과 같이 세련됩니다.

3. 기계 학습 모델. DGA 도메인, DNS 터널링 및 피싱 감지 모델 분석 패턴 및 행동을 포함한 알고리즘은 새로운 진화 위협을 탐지합니다.

4. 커뮤니티 피드백. 검토 과정을 통해 Cloudflare는 우리의 내부 모형 및 위협 분석가 둘 다에 의하여 의견을 평가합니다. 이것은 우리의 분류가 현재와 정확한 위협 인텔리전스를 반영한다는 것을 보증합니다.

## 옵션 정보

Terraform 사용자는 범주 목록을 검색 할 수 있습니다.`cloudflare_zero_trust_gateway_categories_list`데이터 소스. 이 문서는 미국 ID가 아닌 범주의 이름을 가진 Gateway 정책을 만들 수 있습니다. 예를 들면:

```tf
data "cloudflare_zero_trust_gateway_categories_list" "categories" {
  account_id = var.cloudflare_account_id
}

locals {
  main_categories_map = {
    for idx, c in data.cloudflare_zero_trust_gateway_categories_list.categories.result :
    c.name => c.id
  }

  subcategories_map = merge(flatten([
    for idx, c in data.cloudflare_zero_trust_gateway_categories_list.categories.result : {
      for k, v in coalesce(c.subcategories, []) :
      v.name => v.id
    }
  ])...)
}

resource "cloudflare_zero_trust_gateway_policy" "zt_block_dns_tech_categories" {
  account_id = var.cloudflare_account_id
  name       = "DNS Blocked"
  action     = "block"
  traffic    = "any(dns.content_category[*] in {${join(" ", [
    local.main_categories_map["Technology"],
    local.subcategories_map["APIs"],
    local.subcategories_map["Artificial Intelligence"],
    local.subcategories_map["Content Servers"],
    local.subcategories_map["Translator"]
  ])}})"
}
```
