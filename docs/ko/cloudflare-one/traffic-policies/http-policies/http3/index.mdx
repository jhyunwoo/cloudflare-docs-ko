Gateway는 UDP에서 QUIC 프로토콜을 사용하는 HTTP / 3 트래픽 검사를 지원합니다.

Gateway는 HTTP 정책을 HTTP/3 트래픽에 마지막으로 적용합니다. 더 많은 정보를 원하시면, 참조[법의학](/cloudflare-one/traffic-policies/order-of-enforcement/#http3-traffic).

## HTTP/3 검사를 켜십시오

HTTPS 트래픽을 검사하기 전에, 당신은 배포해야[사용자 측 증명서](/cloudflare-one/team-and-resources/devices/user-side-certificates/)당신의 장치 및 켜기[TLS 해독](/cloudflare-one/traffic-policies/http-policies/tls-decryption/). HTTP/3 트래픽을 검사하기 위해, 당신은 또한 켜야 합니다[Gateway 프록시](/cloudflare-one/traffic-policies/proxy/)UDP의 경우

UDP 및 TLS 해독을위한 게이트웨이 프록시를 켜려면 :

1. 내 계정[모델 번호: Cloudflare 한국어](https://one.dash.cloudflare.com), 이동**교통 정책** > **교통 설정**.
2. 내 계정**프록시 및 검사**, 켜기**Secure Web Gateway를 프록시 트래픽으로 허용**.
3. 제품정보**TCP 포트**·**사이트맵**.
4. 기타 제품**TLS 해독**.

### 적용 제한

Gateway는 Mozilla Firefox 및 Microsoft Edge의 HTTP/3 트래픽을 HTTP/3 프록시 연결을 설정하여 확인할 수 있습니다. Gateway는 HTTP / 3 연결, 해독 및 트래픽을 검사하고 HTTP / 2에서 대상 서버에 연결됩니다. Gateway는 cURL과 같은 다른 HTTP 응용 프로그램을 검사 할 수 있습니다.

UDP 프록시 및 TLS 해독 모두 Cloudflare에서 설정된 경우 하나, Google Chrome은 모든 HTTP / 3 연결을 취소하고 HTTP / 2로 다시 구합니다. HTTP 정책을 시행 할 수 있습니다. UDP 프록시 또는 TLS 해독 중 하나가 꺼지면 Chrome의 HTTP / 3 트래픽은 검사를 우회합니다.

## 검사에서 HTTP / 3 트래픽 면제

HTTP / 3 트래픽이 클라이언트에서 소스로 엔드 투 엔드 암호화를 요구하면 여전히 게이트웨이 프록시를 사용하여 만들 수 있습니다.[HTTP 정책을 검사하지 마십시오](/cloudflare-one/traffic-policies/http-policies/#do-not-inspect)원하는 트래픽을 일치합니다. Do Not Inspect 정책을 사용하면 HTTP / 3 트래픽이 프록시 성능과 엔드 투 엔드 암호화를 우회하여 게이트웨이의 TLS 해독 및 검사를 유지할 수 있습니다.

## 힘 HTTP/2 소통량

UDP 프록시를 켜지 않고 HTTP 트래픽에 게이트웨이 정책을 적용하려면 HTTP / 2 트래픽 도달 게이트웨이 만 보장하기 위해 사용자의 브라우저에서 QUIC을 해제해야합니다.
