HTTP 정책은 웹 사이트, IP 주소 및 파일 유형과 같은 모든 HTTP 및 HTTPS 요청 및 블록, 허용, 또는 특정 요소를 제한 할 수 있습니다. HTTP 정책은 레이어 7에서 모든 TCP (및[선택적으로 UDP](/cloudflare-one/traffic-policies/get-started/http/#1-connect-to-gateway)) 교통. 기본적으로 Gateway는 포트에 HTTP 트래픽을 검사합니다.`80`그리고,[TLS 해독](/cloudflare-one/traffic-policies/http-policies/tls-decryption/)켜, 포트에 HTTPS 트래픽`443`. Gateway를 구성할 수도 있습니다.[모든 포트에서 HTTP / HTTPS 트래픽을 검사](/cloudflare-one/traffic-policies/network-policies/protocol-detection/#inspect-on-all-ports).

HTTP 정책은 다음과 같습니다.**- 연혁**또한 정책의 범위를 결정하는 논리 표현. 표현을 만들기 위해, 당신은 선택할 필요가**옵션 정보**한국어**회사연혁**, 값 또는 값의 범위를 입력**제품정보**이름 \* 사용 가능**이름 \***·**또는**여러 조건을 평가하는 논리 연산자.

## 관련 기사

HTTP 정책의 행동은 주어진 요소 (도메인, IP 주소, 파일 유형 등)로 무엇을 선택할 수 있습니다. 당신은 정책 당 하나의 작업을 할당 할 수 있습니다.

Redirect 동작을 통해 지정된 HTTP 요청을 다른 URL로 리디렉션할 수 있습니다. 예를 들어, 사용자가 SaaS 앱의 공개 웹 페이지로 검색하면 자체 호스팅 인스턴스, 단일 서명 페이지 또는 내부 정책 페이지로 리디렉션할 수 있습니다.

블록 액션과 블록 페이지로 URL을 리디렉션하려면, 참조[블록 페이지로 이동](/cloudflare-one/reusable-components/custom-pages/gateway-block-page/#redirect-to-a-block-page).

#### 정책 설정

내 계정**정책 URL 리디렉션**, 일치하는 요청을 리디렉션하는 URL을 정의할 수 있습니다. 리디렉션 URL은 경로와 쿼리를 포함 할 수 있습니다. 예를 들어, 리디렉션할 수 있습니다.`example.com`으로`cloudflare.com/path/to/page?querystring=x`.

<Render file="gateway/policy-context" product="cloudflare-one" />

당신은 켜기**자주 묻는 질문**, Gateway는 원래 경로 및 쿼리 문자열을 리디렉션 URL에 추가합니다. 리디렉션 URL의 경로와 쿼리는 원래 URL을 통해 선행합니다. 예를 들어, 원래 URL이 있다면`example.com/path/to/page?querystring=X`그리고 리디렉션 URL은`cloudflare.com/redirect-path?querystring=Y`, Gateway는 요청을 리디렉션합니다:

```txt "cloudflare.com/redirect-path" "?querystring=Y"
cloudflare.com/redirect-path/path/to/page?querystring=Y
```

모든 옵션을 설정할 때 Gateway는 원래 경로와 쿼리 문자열을 보존할 것이며, 리디렉션 URL의 끝에 정책 컨텍스트를 추가합니다. 예를 들어, 원래 URL이 있다면`example.com/path/to/page?querystring=X&k=1`그리고 리디렉션 URL은`cloudflare.com/redirect-path?querystring=Y`, Gateway는 요청을 리디렉션합니다:

```txt "cloudflare.com/redirect-path" "?querystring=Y" ins="&cf_user_email=user@example.com"
cloudflare.com/redirect-path/path/to/page?querystring=Y&k=1&cf_user_email=user@example.com
```

주어진 호스트 이름, 응용 프로그램, 또는 앱 유형에 대한 정책을 검사하지 마십시오, HTTP 요청을 로그 또는 차단 할 수있는 능력을 잃을 것입니다, DLP 정책을 적용하고 AV 스캔을 수행.

HTTPS 암호화 내에서 포함 된 정보는 전체 요청 URL과 같은 게이트웨이 검사를 우회하면 볼 수 없습니다. 그러나 여전히 적용 할 수 있습니다.[네트워크 정책](/cloudflare-one/traffic-policies/network-policies/)이 교통에. 더 많은 정보를 원하시면, 참조[TLS 해독](/cloudflare-one/traffic-policies/http-policies/tls-decryption/).

:::

검사에서 특정 요소를 우회하지 마십시오. HTTPS 트래픽을 해독하고 검사하는 게이트웨이를 방지하려면 TLS 헤더의 Server Name Indicator (SNI)에 대한 정책이 일치해야합니다. 브라우저에서 Do Not Inspect 사이트에 액세스 할 때 브라우저가 표시 될 수 있습니다.**당신의 연결은 개인이 아닙니다**연결하기 위해 진행할 수 있는 경고. Do Not Inspect 정책을 필요로 할 수있는 응용 프로그램에 대한 자세한 내용은 참조[TLS 해독 제한](/cloudflare-one/traffic-policies/http-policies/tls-decryption/#inspection-limitations).

모든 Inspect 규칙은 먼저 평가되지 않습니다, 어떤 허용 또는 블록 규칙 전에, 검사가 발생하면 결정. 더 많은 정보를 원하시면, 참조[법의학](/cloudflare-one/traffic-policies/order-of-enforcement/#http-policies).
