Zero Trust 기업 계획에 추가 기능으로만 사용할 수 있습니다.
주요 특징

전용 egress IP는 조직에서 트래픽을 허용하는 데 사용할 수있는 정적 IP 주소입니다. 이 IP는 귀하의 계정에 고유하며 Cloudflare의 네트워크를 통해 다른 고객 여정 트래픽에 사용되지 않습니다. 각 전용 egress IP는 특정 Cloudflare 데이터 센터에 할당된 IPv4 주소와 IPv6 범위로 구성됩니다. 최소 Cloudflare는 두 가지 다른 도시에 데이터 센터에 대응하는 두 개의 전용 egress IPs로 계정을 제공 할 것입니다.

계정은 추가 전용 IP를 가질 수 있습니다. 추가 전용 egress IP를 요청하려면 서비스 창을 예약하려면 계정 팀에 문의하십시오.

## IP를 켜십시오

전용 egress IP를 통해 트래픽을 라우팅하려면:

1. 개인 IP를 얻기 위해 계정 팀에 문의하십시오.
2. 내 계정[모델 번호: Cloudflare 한국어](https://one.dash.cloudflare.com), 이동**교통 정책** > **교통 설정**.
3. 기타 제품**Secure Web Gateway를 프록시 트래픽으로 허용**.
4. 제품정보**TCP 포트**.
5. (선택 사항) 선택**사이트맵**. 이것은 HTTP / 3 트래픽을 전용 IP로 egress 할 수 있습니다.

전용 egress IP는 이제 게이트웨이에 의해 모든 네트워크 및 HTTP 트래픽에 대해 켜집니다. 선택적으로 트래픽의 하위 설정을위한 전용 egress IP를 켜려면, 참조[egress 정책](/cloudflare-one/traffic-policies/egress-policies/).

## IP를 검증

기기가 올바른 전용 egress IP를 사용하는 경우 확인하려면:

1. WARP 클라이언트를 통해 장치가 Zero Trust 조직에 연결된다는 것을 검증하십시오.
2. 장치의 소스 IPv4 주소 결정`https://ipv4.icanhazip.com/`.
3. 장치의 소스 IPv6 주소 결정`https://ipv6.icanhazip.com/`.
4. 소스 IPv4 및 IPv6 주소가 전용 IP와 일치하도록 검증합니다.

다른 소스에 대해 테스트 할 때 IPv4 또는 IPv6 주소를 볼 수 있습니다. 게이트웨이에는 연결이 IPv4 또는 IPv6 이상인지 여부에 대한 제어가 없습니다. 일부 소스는 IPv4에서만 사용할 수 있으며 다른 사람들은 IPv6에서만 사용할 수 있습니다. 프로토콜 모두 지원될 때, 결정은 클라이언트 장치에 운영 체계와 브라우저에 의해 합니다. 예를 들어 Windows는 기본적으로[이익 IPv6](https://learn.microsoft.com/troubleshoot/windows-server/networking/configure-ipv6-in-windows)IPv4 이상.

## IP 정보

### 자신의 IP 주소를 가져옵니다 (BYOIP)

엔터프라이즈 사용자는 전용 IP로 자신의 권한을 보호하는 IPv4 및 IPv6 주소를 사용할 수 있습니다. 게이트웨이는 자체 IPv4 및 IPv6 주소를 제공합니다. IPv6 범위를 얻으려면, 참조[인터넷 번호에 대한 미국 등록 (ARIN)](https://www.arin.net/resources/guide/ipv6/first_request/)또는[유럽, 중동 및 중앙 아시아 지역 인터넷 등록 (RIPE NCC)](https://www.ripe.net/manage-ips-and-asns/ipv6/request-ipv6/).

IP 주소를 내장한 후 IP 주소가 생성될 때 나타납니다.[egress 정책](/cloudflare-one/traffic-policies/egress-policies/)그리고 선택**전용 egress IPs (Cloudflare 또는 BYOIP) 사용**으로[egress 방법](/cloudflare-one/traffic-policies/egress-policies/#egress-methods). BYOIP 전용 egress IPs는 지원하지 않습니다[IP 위치](#ip-geolocation).

더 많은 정보를 원하시면, 참조[Cloudflare 단추](/byoip/)또는 계정 팀에 문의.

## 제한 사항

### Concurrent 연결

조직에 할당 된 각 전용 IP는 대상 IP 및 대상 포트 당 40,000 동시 연결을 지원합니다. 전용 IP 및 소스 포트의 각 조합에 대한 여러 가지 원산지를 구성할 수 있습니다.

### 지원된 교통

전용 egress IPs는 적용되지 않습니다 :

- Gateway를 통해 해결된 DNS 쿼리
- Cloudflare 갱도를 통해 Zero Trust에 연결된 개인적인 네트워크
- Zero Trust에 연결된 개인 네트워크를 위해 중단되는 교통[Cloudflare 대만](/cloudflare-wan/)
- ICMP 교통 (와 같은)`ping`)

이 기원은 전용 IP 대신 기본 공유 IP를 볼 것입니다. 이것은 Cloudflare가 근원 IP 보다는 다른 식별자에 의하여 이 근원에 교통을 거를 수 있기 때문에 입니다.

### 교통 탄력

트래픽 탄력을 향상시키기 위해 전용 IP를 다른 Cloudflare 데이터 센터 위치에 할당하십시오. 같은 도시에서 여러 IP를 가지고 있다면 그 도시 내에서 다른 데이터 센터를 선택하십시오. 더 많은 정보를 원하시면 계정 팀에 문의하십시오.

### IP 위치

귀하의 egress 트래픽은 도시로 선정될 것입니다.[egress 정책](/cloudflare-one/traffic-policies/egress-policies/). 트래픽이 egress 정책과 일치하지 않는 경우, IP geolocation 기본값은 사용자에 가장 가까운 전용 egress 위치. 우리는 당신이 창조하는 것을 추천합니다[모든 egress 정책](/cloudflare-one/traffic-policies/egress-policies/#catch-all-policy)전용 egress IPs가 계정에 할당되기 전에. IP geolocation이 업데이트되었는지 확인하려면 지원된 데이터베이스 중 하나에서 전용 egress IP를 확인하십시오.

### Egress 위치

사용자의 물리적 egress 위치는 연결이 IPv4 또는 IPv6 이상인지 여부에 따라 달라질 수 있습니다.

| 프로젝트    | Cloudflare에 의해 예상되는 목적지 | 물리적 egress 위치           | IP 위치              |
| ------- | ----------------------- | ----------------------- | ------------------ |
| IPv4 지원 | 이름 \*                   | 전용 egress IP를 가진 데이터 센터 | 전용 egress IP 위치 일치 |
| IPv4 지원 | 이름 \*                   | 로컬 연결 데이터 센터            | 전용 egress IP 위치 일치 |
| IPv6를   | 이름 \*                   | 로컬 연결 데이터 센터            | 전용 egress IP 위치 일치 |
| IPv6를   | 이름 \*                   | 로컬 연결 데이터 센터            | 전용 egress IP 위치 일치 |

#### IPv4 지원

특정 위치에서 물리적으로 진입하려면 트래픽은 IPv4를 통해 Cloudflare에 proxied해야합니다. 최종 사용자는 가장 가까운 Cloudflare 데이터 센터에 연결하지만, Cloudflare는 내부로 트래픽을 우회하여 전용 위치에서 설정[egress 정책](/cloudflare-one/traffic-policies/egress-policies/). 그러므로, 사용자의 WARP 클라이언트 p참고 자료s에서 보이는 연결된 자료 센터는 그들의 실제적인 선거 위치에 일치하지 않을지도 모릅니다.

우리는 사용자가 Cloudflare에 의해 proxied 도메인을 방문 할 때 더 나은 IPv4 성능을 제공 할 수 있습니다 (또한 알려진[오렌지 클라우드](/dns/proxy-status/)도메인). 이 시나리오에서 IPv4 트래픽은 여전히 전용 위치에서 egress에 나타나는 동안 네트워크에서 가장 수행 된 데이터 센터에서 물리적으로 egress합니다.

예를 들어 로스 앤젤레스의 1 차 전용 egress IP와 뉴욕의 2 차 전용 egress IP가 있습니다. Las Vegas의 사용자는 연결된 데이터 센터로 Las Vegas를 볼 수 있습니다. 그들은 Cloudflare에 의해 발음되지 않는 사이트에 갈 경우 ([회색 clouded](/dns/proxy-status/#dns-only-records))와 같은`espn.com`, 그들은 로스 앤젤레스 (또는 어느 도시가 일치 선거 정책에 있음)에서 선거한다. 오렌지 클라우드 사이트로 가는 경우`cloudflare.com`, 그들은 라스 베이거스에서 물리적으로 진입하지만 로스 앤젤레스를 IP 위치로 사용합니다.

:::note\[IPv4 및 IPv6 동작]
IPv4 주소는 제한되어 있으므로 Cloudflare는 전용 IPv4 주소가 제공되는 데이터 센터에 물리적으로 트래픽을 경로를해야합니다. IPv6에는 거의 무제한 주소 공간이 있습니다. Cloudflare는 모든 지리적으로 모든 데이터 센터에서 IPv6 범위를 할당할 수 있습니다. 이것은 IPv6 트래픽이 로컬로 진입 할 수 있지만 여전히 구성 된 지리적 위치에서 기인하게 나타납니다.
주요 특징

#### IPv6를

IPv4와 달리 IPv6를 통해 트래픽은 연결된 데이터 센터에서 물리적으로 egress하지만 전용 IP 위치 중 하나와 함께 논리적으로 egress됩니다. IPv6가 더 많은 주소 공간을 사용할 수 있기 때문에 Cloudflare를 허용하여 모든 데이터 센터에 IPv6 범위를 할당 할 수 있습니다. 각 계정은 /64 IPv6 범위를받습니다. 이 접근 방식을 위한 충분한 공간을 제공합니다.

위의 예에서, 라스 베이거스 사용자는 라스 베이거스에서 물리적으로 egress하지만 트래픽은 로스 앤젤레스에 IP 위치합니다. 이 수단:

| 사이트 맵       | 제품정보                                                   |
| ----------- | ------------------------------------------------------ |
| 육체적인 egress | 사용자의 가장 가까운 Cloudflare 데이터 센터 (라스베가스)                  |
| IP 위치       | egress 정책 (Los Angeles)에서 구성된 전용 egress IP 위치          |
| 로그인         | IP 위치 변경 (Los Angeles) 심지어 물리적 선거가 다른 위치에서 (Las Vegas) |

## 자주 묻는 질문 (FAQ)

### 여러 데이터 센터에 동일한 egress IP 주소를 제공 할 수 있습니까?

없음, egress IP는 단일 데이터 센터로 제한됩니다.

### 단일 egress IP를 통해 그들의 가장 가까운 데이터 센터에서 다른 위치에서 내 사용자를 할 수 있습니까?

없음, 트래픽은 egress IP가 규정 된 데이터 센터에서만 egress 할 것입니다. 사용자가 멀리 떨어져 있는 위치에 있는 경우에, 우리는 다른 자료 센터의 맞은 자료 센터에 다수 egress IPs를 보존하고 그들의 가장 가까운 자료 센터에 당신의 사용자에게 규정하는 것을 추천합니다.

### 전용 egress IP를 사용하여 트래픽을 통해 발음[PAC 파일](/cloudflare-one/networks/resolvers-and-proxies/proxy-endpoints/)?

예, 사용자들은 IP 주소를 통해 egress할 것입니다.

### 전용 egress IP를 사용할 때 어떤 일이 발생합니까?[Cloudflare 브라우저 고립](/cloudflare-one/remote-browser-isolation/)?

원격 브라우저 세션이 로드되는 가장 가까운 데이터 센터에 연결됩니다. 원격 브라우저는 제공된 egress IP를 가진 데이터 센터를 통해 egress 할 것입니다.

### 전용 egress IPs 작업 수행[Cloudflare 중국 네트워크](/china-network/)?

아니요, Gateway는 중국 네트워크의 전용 egress IP를 지원하지 않습니다.
