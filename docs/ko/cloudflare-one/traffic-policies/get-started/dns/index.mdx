Secure Web Gateway를 사용하면 DNS 트래픽을 검사 할 수 있습니다 - 장치가 같은 도메인 이름을 번역 할 수 있습니다`example.com`IP 주소로 - 웹 사이트 사용자가 방문 할 수있는 제어. 모든 연결이 DNS 조회로 시작되기 때문에, DNS 필터링 블록은 연결의 초기 단계에서 위협을 위협합니다. 장치가 목적지에 도달하기 전에. DNS 정책을 사용하여 악성 도메인, 피싱 사이트 또는 전체 콘텐츠 범주를 차단합니다.

:::참조
DNS 쿼리 및 조직에 대한 기타 트래픽을 필터링하는 더 자세한 가이드를 위해, 참조[인터넷 트래픽 및 SaaS 앱 보안](/learning-paths/secure-internet-traffic/concepts/)구현 가이드.
주요 특징

## 1. Gateway에 연결

개별 기기에서 DNS 쿼리를 필터링할 수 있습니다(예: 직원 노트북) 또는 전체 네트워크 위치(예: 사무실 라우터). 당신의 배포와 일치하는 옵션을 선택합니다.

### 연결 장치

노트북 또는 전화와 같은 개별 장치에서 DNS 요청을 필터링하려면:

1. [WARP 클라이언트 설치](/cloudflare-one/team-and-resources/devices/warp/download-warp/)당신의 장치에. WARP는 Cloudflare를 통해 장치의 DNS 쿼리를 통과하는 경량 대리인이므로 게이트웨이를 검사하고 필터링 할 수 있습니다.
2. [WARP 클라이언트를 따르십시오](/cloudflare-one/team-and-resources/devices/warp/deployment/manual-deployment/)당신의 조직에서<GlossaryTooltip term="team name">Zero Trust 인스턴스</GlossaryTooltip>\[^1]. 이 WARP는 게이트웨이 정책을 시행합니다.
3. (선택) 표시하려면[사용자 정의 블록 페이지](/cloudflare-one/reusable-components/custom-pages/gateway-block-page/)요청이 차단될 때 일반적인 브라우저 오류 대신,[Cloudflare 루트 인증서 설치](/cloudflare-one/team-and-resources/devices/user-side-certificates/)당신의 장치에.

### DNS 위치 연결

각 장치에 소프트웨어를 설치하지 않고 사무실 또는 데이터 센터와 같은 네트워크 위치에서 DNS 요청을 필터링하려면:

1. [위치 추가](/cloudflare-one/networks/resolvers-and-proxies/dns/locations/)당신의 Cloudflare에 1개의 조정. DNS 위치는 필터로 원하는 DNS 쿼리가 있는 네트워크(Office와 같은)를 나타냅니다.
2. 라우터, 브라우저 또는 OS에서, 위치 설정 UI에 표시된 Cloudflare 주소로 포인트로 DNS 서버 설정을 변경합니다. 게이트웨이를 통해 그 네트워크에서 모든 DNS 쿼리를 전달합니다.

:::참조

Gateway는 프로토콜에 따라 쿼리가 제공되는지 확인하는 다른 방법을 사용합니다.

- **IPv4 쿼리**— Gateway는 네트워크의 소스 IP 주소에 근거한 위치에 쿼리를 일치합니다. 이름 \***네트워크** > **해결사 및 Proxies** > **DNS 위치**, 확인**소스 IPv4 주소**보호하려는 네트워크의 공공 IP를 일치합니다.
- **IPv6, TLS (DOT) 이상 DNS, 또는 HTTPS (DOH) 쿼리**— 이 프로토콜은 소스 IP를 손상시킬 수 있기 때문에 게이트웨이는 각 위치에 할당된 고유의 DNS 전달 주소를 사용하여 쿼리에 해당합니다. 귀하의 해결자가 적절한 운송 주소로 구성되었는지 확인합니다.

## 4. 옵션 추가 정책

첫 번째 정책이 활성화되면, 참조[일반적인 DNS 정책](/cloudflare-one/traffic-policies/dns-policies/common-policies)다른 정책에 대해 추가 할 수 있습니다. 일반적인 추가는 특정 콘텐츠 카테고리 차단 ( 소셜 미디어 또는 스트리밍과 같은), 검색 엔진에 SafeSearch를 활성화하고, DNS 쿼리를 제한하기 때문에 장치가 승인 한 해결자를 사용할 수 있습니다.
