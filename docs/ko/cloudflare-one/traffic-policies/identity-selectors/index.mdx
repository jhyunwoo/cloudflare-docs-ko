Cloudflare로 한, 사용자 정체 수준으로 아웃바운드 트래픽을 필터링하는 Secure Web Gateway 정책을 만들 수 있습니다. 이를 위해서는 설정된 DNS, HTTP 또는 네트워크 정책을 구축할 수 있습니다.[ID 기반 선택자](#identity-based-selectors). 이 선별기는 Zero Trust WARP 클라이언트를 안으로 배치하는 것을 요구합니다[교통 및 DNS 모드](/cloudflare-one/team-and-resources/devices/warp/configure-warp/warp-modes/).

또한 추가 신호를 기반으로 아웃바운드 트래픽을 필터링 할 수도 있습니다.[장치 자세 검사](/cloudflare-one/reusable-components/posture-checks/).

## Gateway 정체 체크

게이트웨이는 사용자가 로그인하거나 다시 입력할 때 정체성을 확인합니다. 사용자의 식별을 확인하고 일정한 간격으로 재입력이 필요합니다.[WARP 클라이언트 세션 기간 시행](/cloudflare-one/team-and-resources/devices/warp/configure-warp/warp-sessions/).

사용 안 함[SCIM 규정을 지원하는 IdP](#automatic-scim-idp-updates), 게이트웨이는 사용자가 Zero Trust 인스턴스에 의존할 때까지 IdP 그룹에서 사용자를 추가하거나 제거할 때 감지하지 않습니다. 사용자는 두 가지 방법이 있습니다:

- Access-protected 응용 프로그램에서 로그 아웃하고 다시 로그인하십시오.
- WARP 클라이언트에서 세션을 다시 유지**이름 \*** > **계정 정보** > **관련 제품** [^1]. 이 브라우저 창을 열고 사용자를 로그인합니다.

[^1]: 에서 WARP 버전 2026.1 이전, 선택**모델: P참고 자료s** > **계좌정보** > **재 인증 세션**.

Gateway가 정책을 평가할 때 사용할 수 있는 ID를 보시려면, 확인[사용자 등록](/cloudflare-one/team-and-resources/users/users/).

### 자동 SCIM IdP 업데이트

Gateway는 Cross-domain Identity Management (SCIM) 프로비저닝 시스템 구성 IdPs에 대한 사용자 이름, 제목 및 그룹 회원의 변경을 자동으로 감지합니다. 더 많은 정보를 원하시면, 참조[SCIM 제공](/cloudflare-one/team-and-resources/users/scim/).

:::note\[Gateway 그룹 vs. 액세스 규칙 그룹]

Gateway에서**사용자 그룹**IdP에서 그룹을 나타냅니다 (예를 들어, Okta 그룹). Gateway는 현재 DNS, HTTP 및 네트워크 정책을 적용하지 않습니다.[액세스 규칙 그룹](/cloudflare-one/access-controls/policies/groups/). 액세스 규칙 그룹이 장치 위치 또는 IP 주소와 같은 IdP를 통해 사용할 수없는 기준을 포함하기 때문에입니다.

:::
