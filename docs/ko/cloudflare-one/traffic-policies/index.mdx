모든 조직은 사용자가 인터넷에 도달 할 수있는 방법을 필요로한다 - 악성 사이트 차단, 위험 응용 프로그램을 제한, 그리고 어떻게 트래픽이 기업 네트워크를 종료하는. 보안 체크 포인트 세트로 교통 정책의 생각, 각을 통해 허용되기 전에 트래픽의 다른 층을 검사.

모델 번호: Cloudflare 게이트웨이[보안 웹 게이트웨이](https://www.cloudflare.com/learning/access-management/what-is-a-secure-web-gateway/)(사용자와 인터넷을 통해 보안 규칙을 시행하는 클라우드 서비스), 조직의 인터넷 트래픽을 검사하고 필터링하는 정책을 설정할 수 있습니다. 웹 사이트, 응용 프로그램 및 서비스에 대한 트래픽 정책 제어는 액세스 할 수 있습니다. 그리고 트래픽이 네트워크를 떠난 방법.

Gateway는 네트워크 트래픽이 다른 레이어에서 검사 될 수 있기 때문에 여러 정책 유형을 지원합니다. - 원시 패킷에서 전체 HTTP 요청까지. 각 정책 유형은 특정 층에서 당신을 통제합니다:

<Details header="Packet 필터링">
  **[Packet 필터링](/cloudflare-one/traffic-policies/packet-filtering/network-firewall-overview/)**&#xC18C;스 IP 주소 또는 프로토콜과 같은 속성에 근거를 둔 원료 네트워크 패킷 및 블록 트래픽을 검사합니다. 사용자가 누구인지 알 필요가 없습니다.

  다른 정책에 도달하기 전에 원치 않는 트래픽을 삭제하는 패킷 필터링을 사용합니다.
</Details>

<Details header="DNS 정책">
  **[DNS 정책](/cloudflare-one/traffic-policies/dns-policies/)**&#xBAA8;든 DNS 쿼리를 확인 사용자 만들기. 쿼리가 정책 규칙에 일치 할 때 게이트웨이는 해결에서 도메인을 차단 할 수 있습니다 - 도메인 이름은 IP 주소로 번역되지 않기 때문에 사이트가로드되지 않습니다.

  DNS 정책은 연결의 초기 단계에 행동하며, 모든 콘텐츠는 fetched. 이것은 가장 빠른 정책 유형을 배치하고 가장 넓은 범위를 만듭니다. 더 많은 정보[DNS 필터링](https://www.cloudflare.com/learning/access-management/what-is-dns-filtering/)Cloudflare 학습 센터를 참조하십시오.

  DNS 정책을 사용하여 악성 도메인을 차단하고 콘텐츠 범주를 제한하거나로드에서 전체 사이트를 방지합니다. 완전한 위협 보호를 위해, HTTP 정책을 가진 쌍 DNS 정책 — DNS 구획은 나쁜 도메인을, 그러나 HTTP는 허용한 교통에서 숨겨지은 위협을 붙잡습니다.
</Details>

<Details header="네트워크 정책">
  **[네트워크 정책](/cloudflare-one/traffic-policies/network-policies/)**&#xAC1C;별 TCP, UDP 및 GRE 패킷을 검사합니다. 그들은 IP 주소, 포트, 프로토콜 및 암호화 된 연결 (Server Name Indication, 또는 SNI)의 시작에 전송 된 서버 이름에 일치 할 수 있습니다.

  SSH 및 RDP와 같은 특정 포트 또는 비 HTTP 서비스에 대한 액세스를 차단하는 네트워크 정책을 사용합니다.
</Details>

<Details header="HTTP 정책">
  **[HTTP 정책](/cloudflare-one/traffic-policies/http-policies/)**&#x55;RL, 헤더, 업로드 또는 다운로드 파일을 포함한 웹 요청의 전체 내용을 검사합니다. 게이트웨이는 HTTPS 트래픽을 해독하므로 DNS 및 네트워크 정책을 볼 수 있습니다.

  특정 URL을 차단하는 HTTP 정책을 사용하여 민감한 데이터에 대한 스캔 파일 업로드, 다운로드에 악성 코드 차단, 사용자가 로그인 할 수있는 제어 - 예를 들어, 귀하의 회사 Google Workspace 계정을 허용하지만 개인 Gmail을 차단.
</Details>

<Details header="Egress 정책">
  **[Egress 정책](/cloudflare-one/traffic-policies/egress-policies/)**&#xD2B8;래픽이 조직에 속한 고정 IP 주소를 할당하여 네트워크를 어떻게 나타낸지 제어합니다. 제3자 서비스는 해당 IP를 인식할 수 있습니다.

  IP 주소의 알려진 목록에서 트래픽을 허용하는 파트너 또는 서비스에 연결하는 egress 정책을 사용합니다.
</Details>

<Details header="Resolver 정책">
  **[Resolver 정책](/cloudflare-one/traffic-policies/resolver-policies/)**&#xAE30;본 Cloudflare 해결사 대신 특정 DNS 서버에 DNS 쿼리를 보냅니다.

  Cloudflare One을 통해 연결된 내부 네트워크에서 개인 호스트 이름을 해결하는 해결사 정책을 사용하여 준수를 위해 자신의 DNS 서버에 대한 경로 쿼리, 또는 내부 리소스에 도달합니다.
</Details>

:::참조
정책을 작성하거나 편집할 때, 해당 정책이 Cloudflare의 모든 데이터 센터 전반에 업데이트되기까지 최대 60초가 걸릴 수 있습니다.

## 모델 번호: 시작하기

각 정책 유형의 경우, 이 작업 흐름을 따르십시오:

1. 보호하려는 장치 또는 네트워크를 연결하십시오.
2. Gateway가 기기에서 트래픽을 수신하는 것을 확인합니다.
3. 권장 보안 정책을 설정 — 예를 들어, 모든 블록[보안 위협 범주](/cloudflare-one/traffic-policies/domain-categories/#security-categories)DNS 정책.
4. 조직의 필요에 따라 특정 정책을 추가하십시오.

예를 들어, WARP 클라이언트 (단계 1)를 사용하여 장치 등록을 시작할 수 있습니다. 게이트웨이 로그 (단계 2)에 DNS 쿼리가 나타나는 것을 확인합니다. 그러면 모든 보안 위험 범주 (단계 3)를 차단하는 DNS 정책을 만듭니다.

step-by-step 설정 가이드의 경우, 참조[DNS 보호](/cloudflare-one/traffic-policies/get-started/dns/), [회사연혁](/cloudflare-one/traffic-policies/get-started/network/)·[HTTP: HTTP](/cloudflare-one/traffic-policies/get-started/http/)정책.

### 정책 유형 선택

올바른 정책 유형은 필터로 원하는 트래픽에 따라 다릅니다.

| 이름 \*                    | 정책 유형                           | 이름 \*                                       |
| ------------------------ | ------------------------------- | ------------------------------------------- |
| URL로 웹 사이트 차단            | HTTP: HTTP                      | 전체 URL 경로 검사, 그냥 도메인                        |
| 블록 도메인 (모든 페이지)          | DNS 보호                          | 해결에서 도메인을 방지                                |
| 블록 비-HTTP 트래픽 (SSH, RDP) | 회사연혁                            | 포트에 TCP/UDP 패킷 검사                           |
| 블록 맬웨어 및 위협              | DNS 보&#xD638;*·*&#x48;TTP: HTTP | DNS 블록 알려진 나쁜 도메인. HTTP는 허용 된 트래픽에서 위협을 잡아. |
| 정적 egress IPs 할당         | 팟캐스트                            | 제3자 서비스를 확인하자                               |
| 다른 정책 실행 전에 드롭 트래픽       | Packet 필터링                      | user context 없이 패킷 속성에 의해 차단                |
| DNS를 사용자 정의 네임서버에 경로     | 관련 제품                           | 기본 Cloudflare 결산                            |
