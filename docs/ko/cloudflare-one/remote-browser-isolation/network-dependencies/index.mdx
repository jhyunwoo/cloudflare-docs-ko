조직이 방화벽 또는 기타 정책을 사용하여 인터넷 트래픽을 제한하려면 브라우저 고립을 허용하는 몇 가지 변화를 만들 필요가 있습니다.

## Remoting 클라이언트

고립된 페이지는 remoting 클라이언트에 의해 봉사됩니다. 이 클라이언트는 HTTPS와 WebRTC를 통해 Cloudflare의 네트워크에 통신합니다.

### Remoting Client (서비스)

리모팅 클라이언트는 정적 자산과 API 엔드포인트를 제공합니다. 기능에 브라우저 고립을 위해, 당신은 허용해야 합니다:

- HTTPS 교통`*.browser.run`항구에`443`

#### Clientless 웹 고립

Clientless Web Isolation를 통해 연결되는 사용자는 Cloudflare Access에 연결해야 합니다. 액세스에 연결하려면 다음을 허용해야합니다.

- HTTPS 교통`https://<team-name>.cloudflareaccess.com`항구에`443`

### WebRTC 채널

Browser Isolation는 로컬 브라우저와 원격 브라우저 사이에 낮은 수준의 통신을위한 WebRTC를 사용합니다.

WebRTC 트래픽을 전달하려면 클라이언트가 다음 IP 주소에 연결할 수 있어야합니다.

| IP 범위                                                                  | 항구 범위         | 프로젝트 |
| ---------------------------------------------------------------------- | ------------- | ---- |
| IPv4:`162.159.201.10 - 162.159.201.255` <br />IPv6:`2606:4700:f2::/48` | 10000 - 59999 | 사이트맵 |

각 원격 브라우저 인스턴스는 무작위로 포트를 할당하고 사용자가 종종 변경하고 통지없이 변경 될 수있는 포트입니다.

:::참조

WebRTC 트래픽은 로컬 브라우저 HTTP/HTTPS 프록시 설정에서 프록시를 통해 흐름하지 않습니다. 연결 장치는 WebRTC IP 범위에 직접 연결할 수 있어야합니다.
