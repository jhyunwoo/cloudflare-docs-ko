## 5. 사용자로 연결

최종 사용자는 지정된 범위의 IP 주소를 방문함으로써 네트워크에 HTTP 또는 TCP 기반 서비스를 도달 할 수 있습니다.

IP 대신 개인 호스트명을 사용하여 서비스에 도달 할 수 있도록, 참조[개인 DNS](/cloudflare-one/networks/connectors/cloudflare-tunnel/private-net/cloudflared/private-dns/).

### 문제 해결

#### 장치 구성

기기가 제대로 구성되는지 확인하려면 사용자가 방문 할 수 있습니다.`https://help.teams.cloudflare.com/`그것을 지키는:

- 페이지 반환**당신의 네트워크는 완전히 보호됩니다**.
- 내 계정**HTTP 필터링**, 모두**사이트맵**·**Gateway 프록시**지원하다
- 더 보기**팀 이름**터널을 생성한 Zero Trust 조직과 일치합니다.

#### Router 구성

장치의 로컬 IP 주소를 확인하고 개인 네트워크의 IP / CIDR 범위 내에서 떨어지지 않도록하십시오. 예를 들어 일부 홈 라우터는 DHCP 할당을 만들 것입니다.`10.0.0.0/24`범위, 어느 overlaps와`10.0.0.0/8`대부분의 기업 개인 네트워크에 의해 사용되는 범위. 사용자의 홈 네트워크가 터널의 경로와 동일한 IP 주소를 공유 할 때, 장치가 응용 프로그램에 연결할 수 없습니다.

IP 분쟁을 해결하려면 다음을 할 수 있습니다.

- 사용자의 라우터를 재구성하여 비 overlapping IP 범위를 사용합니다. 호환 라우터는 일반적으로 사용`192.168.1.0/24`, `192.168.0.0/24`또는`172.16.0.0/24`.
- 분할 터널 설정에서 IP 범위를 꽉 쥔 다음`10.0.0.0/24`범위. 개인 네트워크가 어떤 호스트가 없는 경우에만 작동합니다.`10.0.0.0/24`.
- 개인 네트워크의 IP / CIDR을 변경하여 집 네트워크에 의해 일반적으로 사용되는 범위로 오버랩하지 않습니다.
