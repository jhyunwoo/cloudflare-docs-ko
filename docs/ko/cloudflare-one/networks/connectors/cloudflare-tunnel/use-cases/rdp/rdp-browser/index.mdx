사용자는 RDP 클라이언트 또는 RDP 서버에 연결할 수 있습니다[WARP 클라이언트](/cloudflare-one/team-and-resources/devices/warp/)그들의 장치에. 브라우저 기반 RDP 레버리지[Cloudflare 갱도](/cloudflare-one/networks/connectors/cloudflare-tunnel/)RDP 서버에서 Cloudflare의 글로벌 네트워크에 안전한 아웃바운드 전용 연결을 만듭니다. 설정은 실행`cloudflared`RDP 서버에서 daemon (또는 개인 네트워크 내에서 다른 호스트 기계) 및 공공 호스트 이름에 RDP 트래픽을 라우팅.

사용자에게 두 가지 방법이 있습니다.[브라우저에서 RDP 서버에 도달](#4-connect-as-a-user):

- **앱 실행기 (추천)**: 사용자는 로그인할 수 있습니다.[앱 실행기](/cloudflare-one/access-controls/access-settings/app-launcher/)Cloudflare 액세스 자격으로 브라우저에서 Windows 기계에 RDP 연결을 시작합니다. 사용자는 Windows 사용자 이름과 암호를 사용하여 Windows 기계에 인증됩니다. Cloudflare는 Windows 서버에서 모든 자격 증명을 관리하지 않습니다.
- **직접 URL**: 사용자가 Windows 서버에 직접 이동할 수도 있습니다.`https://<app-domain>/rdp/<vnet-id>/<target-ip>/<port>`, 어디`vnet-id`이름 \*<GlossaryTooltip term="Virtual network">가상 네트워크</GlossaryTooltip>Cloudflare 터널 경로에 할당. 인증 흐름은 App Launcher와 동일합니다. 첫 번째 사용자는 Cloudflare Access에 로그인하고 Windows 기계에 인증하는 Windows 자격 증명을 사용하십시오.

브라우저 기반 RDP는 함께 사용할 수 있습니다[WARP에 여정](/cloudflare-one/networks/connectors/cloudflare-tunnel/use-cases/rdp/rdp-warp-to-tunnel/)서버에 연결하는 여러 가지 방법이 있습니다. 각 연결 방법을 구성할 때 동일한 Cloudflare 터널을 재사용할 수 있습니다.

## 3. DNS 레코드 생성

브라우저를 통해 RDP 대상 (즉, Windows 기계)을 만들려면 필요할 것입니다.[Cloudflare DNS 레코드](/dns/manage-dns-records/how-to/create-dns-records/)도메인 및 하위 도메인의 경우 사용자가 연결됩니다. 이 도메인은 액세스 응용 프로그램을 통해 사용자에게 사용할 수있는 대상에 액세스하는 데 사용됩니다 (단계 참조 4).

예를 들어, 사용자가 대상에 연결하는 경우`rdp.example.com`, [DNS 레코드 생성](/dns/manage-dns-records/how-to/create-dns-records/#create-dns-records)제품 정보`rdp.example.com`. 당신은 창조할 수 있습니다`A`, `AAAA`, 또는`CNAME`자료:

<Details header="이름 *" open={false}>
  뒤에 오는 DNS 기록은 당신의 공중 subdomain를 점합니다 (`rdp`) IPv4 주소로[Class E 주소 공간](https://datatracker.ietf.org/doc/html/rfc5735).

  - **제품정보**: *·*
  - **이름 \***: `rdp`
  - **IPv4 주소**: `240.0.0.0`
  - **프록시 상태**: 에
</Details>

<Details header="AAAA 기록" open={false}>
  뒤에 오는 DNS 기록은 당신의 공중 subdomain를 점합니다 (`rdp`) IPv6에[discard 주소 범위](https://www.rfc-editor.org/rfc/rfc6666.html):

  - **제품정보**: *AAAA 소개*
  - **이름 \***: `rdp`
  - **IPv6 주소**: `100::`
  - **프록시 상태**: 에
</Details>

<Details header="CNAME 기록" open={false}>
  다음 것`CNAME`공개 subdomain을 기록하십시오 (`rdp`) 완전히 자격이 된 도메인 이름에.

  - **제품정보**: *이름 \**
  - **이름 \***: `rdp`
  - **제품정보**: `www.rdp.example.com`
  - **프록시 상태**: 에

  이름 \***제품정보**필드는 단계 2로 구성된 RDP 대상과 관련이 없습니다.
</Details>

DNS 레코드는 활성 대상 IP 주소 또는 호스트 이름에 점이 필요하지 않습니다. DNS 레코드는 유효해야합니다. Cloudflare의 RDP 프록시는 올바른 RDP 대상에 여정을 처리합니다.

## 6. 사용자로 연결

RDP에 Windows 기계에 연결하기:

1. 브라우저를 열고 App Launcher URL로 이동:

   ```text
   https://<your-team-name>.cloudflareaccess.com
   ```

   기타 제품`<your-team-name>`Zero Trust로<GlossaryTooltip term="team name">팀 이름</GlossaryTooltip>.

2. 정체성 공급자에 로그인할 수 있는 프롬프트를 따르십시오.

   인증되면 App Launcher는 사용자가 사용할 수있는 응용 프로그램을 보여주는 타일을 표시합니다. 브라우저 기반 RDP를 통해 Windows 서버 (targets)도 타일로 나타날 것입니다. 다중 액세스 응용 프로그램을 통해 대상이 도달하면 대상은 액세스 응용 프로그램에 타일이있을 것입니다.

3. 연결하려는 대상을 선택하십시오.

   App Launcher 타일은 양식의 URL을 실행합니다.`https://<app-domain>/rdp/<vnet-id>/<target-ip>/<port>`. 이 URL에 직접 탐색할 수도 있습니다.

   :::노트\[Virtual network ID]
   `vnet-id`이름 \*[가상 네트워크](/cloudflare-one/networks/connectors/cloudflare-tunnel/private-net/cloudflared/tunnel-virtual-networks/)(VNET) RDP 대상은 Cloudflare 터널 구성에 할당됩니다. Cloudflare 터널을 통해 대상을 래핑 할 때 VNET을 지정하지 않았다면, 대상은 기본적으로 VNET에 자동으로 추가됩니다.

   모든 VNETs 및 ID 목록을 fetch하려면`GET`요청하기[가상 네트워크](/api/resources/zero_trust/subresources/networks/subresources/virtual_networks/methods/list/)끝점. 기본 VNET은 매개 변수가 있습니다.`"is_default_network": true`.
   :::

4. 연결하려는 포트를 선택합니다. 항구 선택 스크린은 접근 신청이 다수 항구 (예를 들면, 항구에 RDP 소통량을 허용하는 경우에만 나타납니다`3389`그리고 항구`65321`).

5. (선택) 브라우저 설정에서 액세스 응용 프로그램을 클립보드에 액세스 할 수 있습니다. Clipboard 액세스는 주제입니다.[정책 제한](#configure-clipboard-controls)관리자에 의해 구성.

6. Windows 사용자 이름과 암호를 입력하십시오. 사용자 이름을 포맷하는 방법에 대한 자세한 내용은, 참조[사용자 식별자 형식](#user-identifier-formats).

이제 원격 Windows 데스크톱에 액세스 할 수 있습니다.

## 클립보드 컨트롤

클립보드 컨트롤은 사용자가 로컬 머신과 브라우저 기반 RDP 세션 사이에 텍스트를 복사하거나 붙여 줄 수 있는지 제한 할 수 있습니다. 해당 이용 후기에 달린 코멘트가 없습니다. 여러 정책을 작성하여 다른 클립보드 권한을 구성할 수 있습니다.

### 기본 동작

- **새로운 정책**: 클립보드 액세스는 기본적으로 거부됩니다. 클립보드 작업을 명시적으로 허용해야합니다.
- **연락처**: 브라우저 기반 RDP에 대한 액세스 응용 프로그램은이 기능 이전에 생성 된 전체 클립 보드 액세스를 유지하여 백워드 호환성을 보존합니다.

### 옵션 설정

각 접근 정책을 위해, 당신은 뒤에 오는 클립보드 통제 선택권의 하나를 선택할 수 있습니다:

| 설치하기                  | 이름 \*                                                    |
| --------------------- | -------------------------------------------------------- |
| *원격 RDP 세션에 클라이언트 허용* | 사용자는 로컬 클라이언트에서 브라우저 기반 RDP 세션으로 텍스트를 복사하고 붙여넣을 수 있습니다.  |
| *클라이언트에 원격 RDP 세션 허용* | 사용자는 브라우저 기반 RDP 세션에서 로컬 클라이언트에 복사 및 붙여넣을 수 있습니다.        |
| *두 방향 허용*             | 사용자는 브라우저 기반 RDP 세션과 로컬 클라이언트 사이의 텍스트를 복사하고 붙여넣을 수 있습니다. |
| *이름 \**               | 사용자는 브라우저 기반 RDP 세션과 로컬 클라이언트 사이의 텍스트를 복사하고 붙여넣을 수 없습니다. |

사용자가 제한 클립보드 동작을 시도할 때, 클립보드 콘텐츠는 해당 동작이 허용되지 않는 메시지로 대체됩니다.

### 사용자 식별자 형식

브라우저 기반 RDP는 다음과 같은 로그인 자격 증명을 사용하여 Windows 기계에 연결합니다.

#### 보안 계정 관리자 (SAM)

SAM-formatted 사용자 식별자는 공간없이 지원됩니다.

예제:

- `DOMAIN\username`
- `DOMAIN\username with spaces`
- `.\username`
- `.\username with spaces`
- `username`
- `username with spaces`

<Details header="문자 제한" open={true}>
  도메인을 지정하는 식별자`DOMAIN\username`, 도메인의 최대 20 문자와 사용자의 15 문자를 가질 수 있습니다.

  도메인없이 식별자 등`.\username`, 기본 도메인을 사용합니다. 사용자 이름은 최대 20 문자를 가질 수 있습니다.
</Details>

#### 사용자명(UPN)

UPN-formatted 사용자 식별자는 공백, 견적없이 지원됩니다.

예제:

- `"username with spaces"@domain.org`
- `username with spaces@domain.org`
- `username@domain.org`

:::참조
Cloudflare는 RDP 대상에서 사용자 식별자를 구성하지 않습니다. 인증에 사용되는 모든 사용자 식별자는 서버에 사전 구성해야 합니다.
주요 특징

#### 마이크로 소프트 엔트라 ID

Microsoft Entra ID 도메인에 바인딩되는 사용자 식별자는 사용자 이름을 입력해야 합니다.`AzureAD\user@example.com`또는`AzureAD\user`·`AzureAD\`prefix는 case-insensitive입니다.
로그인 흐름은 Microsoft Entra ID-bound 사용자 이름을 사용할 때 약간 다릅니다.

1. 위의 형식 중 하나에 사용자 이름을 입력하십시오.
2. 사용자 이름을 입력하면 비밀번호 상자가 사라지고 RDP 연결이 시작됩니다.
3. RDP 서버는 RDP 서버에 액세스 권한을 부여하기 전에 암호를 신속하게합니다.

## Known 제한

- **TLS 인증서 검증**: Cloudflare는 TLS를 사용하여 RDP 대상에 연결하지만 원산지 TLS 인증서를 확인하지 않습니다.
- **WARP 인증**: 브라우저 기반 RDP 트래픽이 WARP 클라이언트를 통해 이동하지 않기 때문에 사용자는 사용할 수 없습니다.[WARP 세션 정체성](/cloudflare-one/team-and-resources/devices/warp/configure-warp/warp-sessions/#configure-warp-sessions-in-access)인증하기
- **RDP 이상 오디오**: 사용자는 마이크와 스피커를 원격 기계와 상호 작용할 수 없습니다.
- **클립보드 크기 제한**: 로컬 머신과 브라우저 기반 RDP 세션 사이에 복사된 데이터는 500 KB를 초과할 수 없습니다.
- **Clipboard 데이터 유형**: 클립보드 컨트롤만 지원 텍스트 데이터. 이미지 및 파일 클립보드 전송은 지원되지 않습니다.
- **파일 전송**: 사용자는 원격 기계 및 vice versa에 그들의 국부적으로 기계에서 파일을 이동할 수 없습니다.
- **로컬 프린터로 인쇄**: 사용자는 브라우저 기반 RDP 세션에서 로컬 네트워크의 프린터로 정보를 인쇄할 수 없습니다.
- **Entra-joined 계정의 네트워크 수준 인증**: 브라우저 기반 RDP는 PKU2U 인증을 지원하지 않습니다.[네트워크 수준 인증 (NLA)](https://learn.microsoft.com/en-us/windows-server/remote/remote-desktop-services/remotepc/remote-desktop-allow-access#why-allow-connections-only-with-network-level-authentication)Entra-joined 계정으로. Entra-joined 계정에 연결하면 원격 Windows 기계에서 NLA의 집행을 해제해야합니다. NLA를 비활성화 할 수 있습니다**계정 설정** > **시스템** > **원격 데스크톱**, 또는 로컬 그룹 정책 편집기를 사용하여 비활성화**Network Level Authentication을 사용하여 원격 연결을 위한 사용자 인증**.
