## 8. 사용자로 연결

사용자는 장치에서 WARP 클라이언트에 로그인되어 있기 때문에 대상에 연결할 SSH 클라이언트를 사용할 수 있습니다. 대상이 특정 가상 네트워크 안에 있는 경우 WARP 클라이언트가 있다는 것을 보증합니다.[가상 네트워크에 연결](/cloudflare-one/networks/connectors/cloudflare-tunnel/private-net/cloudflared/tunnel-virtual-networks/#connect-to-a-virtual-network)연결하기 전에. 사용자는 장치에서 SSH 구성을 수정할 필요가 없습니다. 예를 들면, 맨끝에서 SSH에:

```sh
ssh <username>@<target IP>
```

인프라에 대한 접근도 지원`scp`, `sftp`·`rsync`명령. 더 알아보기[Known 제한](#known-limitations)지원되지 않은 SSH 명령 및 기능 목록.

사용자 연결에 대한 자세한 내용을 보려면, 참조[인프라 문서](/cloudflare-one/access-controls/applications/non-http/infrastructure-apps/#4-connect-as-a-user).

## SSH 명령 로그

SSH 명령 로그는 실제 SSH 명령을 포함하고 사용자가 대상에 ran. Cloudflare에 SSH 로그를 저장하고 대시보드에서 로그를 다운로드 할 수 있습니다.[다운로드](#download-encrypted-ssh-logs)고객이 제공 한 공공 키를 사용하여 암호화되며 Cloudflare에 볼 수 없습니다. 다운로드 가능한 SSH 로그의 납품은 제일 노력입니다; 보장된 납품을 위해, 기업 고객은 할 수 있습니다[Logpush 작업 구성](#export-ssh-logs-with-logpush)SSH 로그를 저장 목적지에 보냅니다. ## Known 제한

### SSH 특징

- 국부적으로와 먼 항구 운송

1. [귀하의 액세스 정책 확인](#1-review-access-policies)사용자가 대상에 액세스 할 수 있습니다.

### 1. 리뷰 액세스 정책

Cloudflare는 SSH와 연결하여 서버가 나타납니다.[이름 \*](/cloudflare-one/networks/connectors/cloudflare-tunnel/use-cases/ssh/ssh-infrastructure-access/#4-add-a-target).

당신은 당신의 목표에 대한 액세스 정책을 만들려고 안내했다[substep 9 단계 5: 인프라 응용 프로그램 추가](#5-add-an-infrastructure-application).

터널의 상태를 확인하려면:

1. 내 계정[사이트맵 한국어](https://one.dash.cloudflare.com/), 이동**네트워크** > **오시는 길**.

3. 터널 이름을 복사합니다.

4. 오시는 길**네트워크** > **연결관** > **사이트맵 연락처**터널 이름으로 검색합니다.

### 3. 서버에서 사용자 존재 확인

UNIX 서버에서 사용자의 존재를 확인하려면, 실행`id <USERNAME>`서버의 명령은 사용자의 존재를 확인한다. 사용자 이름이 존재하지 않는 경우, 서버에 사용자를 추가해야합니다.

사용자가 서버에 존재하는 경우, 벌레`sshd_config`다음 단계의 파일.

### 4. 디버그`sshd_config`파일 misconfiguration

#### 예를 들어 설정과 테스트

다음 단계는 문제 해결 요법을 통해 걸어갈 것입니다. 당신은 일시적으로 기존의 교체 할 것`sshd_config`지정된 예로 파일하여 구성 문제를 룰 수 있습니다. 계속하기 전에, 신중하게[리뷰 및 비교 모두 파일](#review-your-sshd_config-file-for-misconfigurations)어떤 분쟁 해결 지침을 식별합니다.

:::caution\[서버에 접속할 수 있음]

이러한 문제 해결 단계는 현재 SSH 세션이 기존 구성에 의존하지 않기 때문에 SSH 서버에서 잠겨있을 수 있습니다.[예제 파일](#review-your-sshd_config-file-for-misconfigurations). 최대 caution로 Proceed.

:::

1. 현재 백업`sshd_config`파일.

   ```sh
   mv /etc/ssh/sshd_config /etc/ssh/sshd_config.bak
   ```

2. 새로운 기능`sshd_config`파일.

   ```sh
   vi /etc/ssh/sshd_config
   ```

3. 삽입 모드를 입력하여`i`키보드의 열쇠.

4. 과거에[예제 파일](#review-your-sshd_config-file-for-misconfigurations).

5. 탈출을 눌러 삽입 모드를 종료 (`esc`) 열쇠.

6. 이름 \*`:x`저장 및 출구.

7. [관련 상품](#reload-your-ssh-server)SSH 서버.

   :::caution\[시작하지 않음]
   당신의 시작`sshd`서비스는 현재 SSH 연결의 종료에서 발생합니다. SSH 세션을 종료하지 않도록 재시작 대신 다시로드하십시오.
