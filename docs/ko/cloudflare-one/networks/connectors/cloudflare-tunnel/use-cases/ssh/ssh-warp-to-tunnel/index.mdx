## 1. SSH 서버 만들기

이 예제는 Google Cloud Platform (GCP) 가상 머신 (VM)에서 SSH 서버를 설정하는 방법을 통해 걸지만 SSH 연결을 지원하는 모든 기계를 사용할 수 있습니다. 이미 구성된 SSH 서버가 있다면, 당신은 건너 뛸 수 있습니다.[단계 2](#2-connect-the-server-to-cloudflare).

### 1.1 SSH 키 쌍 만들기

VM 인스턴스를 만들기 전에 SSH 키 쌍을 만들 필요가 있습니다.

1. 터미널을 열고 다음 명령을 입력하십시오.

   ```sh
   ssh-keygen -t rsa -f ~/.ssh/gcp_ssh -C <username in GCP>
   ```

2. 전달될 때 passphrase를 입력하십시오. 두 번 입력해야합니다.

   두 파일이 생성됩니다 :`gcp_ssh`개인 키를 포함, 그리고`gcp_ssh.pub`공개 키가 포함되어 있습니다.

3. 명령줄에서 입력:

   ```sh
   cat ~/.ssh/gcp_ssh.pub
   ```

4. 출력을 복사합니다. GCP에서 VM 인스턴스를 만들 때 사용됩니다.

### 1.2 GCP에서 VM 인스턴스 생성

이제 SSH 키 쌍이 생성되어 VM 인스턴스를 만들 수 있습니다.

1. 내 계정[Google 클라우드 콘솔](https://console.cloud.google.com/), [새 프로젝트 만들기](https://developers.google.com/workspace/guides/create-project).
2. 오시는 길**Compute 엔진** > **VM 인스턴스**.
3. 제품정보**인스턴스 생성**.
4. VM 인스턴스 이름, 예를 들어`ssh-server`.
5. 기타 제품**고급 옵션** > **보안 보안** > **자주 묻는 질문**.
6. 이름 \***수동으로 생성 된 SSH 키 추가**, 선택**상품 추가**당신이 창조한 대중적인 열쇠를 풀기.
7. 제품정보**이름 \***.
8. VM 인스턴스가 실행되면, 옆에 드롭다운을 엽니다.**사이트맵**선택하기*본문 바로가기*.

## 3. hostname 경로 사용

호스트 이름 경로는 SSH에 직접 허용`ssh.internal.local`정적 IP 경로 관리 없이. SSH 서버가 알 수없는 경우 Hostname 경로는 특히 유용합니다 또는 클라우드 공급자가 제공하는 동적 인프라와 같은 ephemeral IP 주소.

<Details header="hostame 라우팅 작품">
  Cloudflare 터널의 hostname 루트를 만들 때:

  1. SSH를 개인 별명으로 (예를 들면,`ssh user@ssh.internal.local`).
  2. Gateway는 호스트명을 해결합니다.<GlossaryTooltip term="initial resolved IP">초기 해결 IP</GlossaryTooltip>CGNAT 범위에서.
  3. WARP 터널을 통해 교통 경로 Cloudflare.
  4. Gateway 네트워크 정책은 연결을 평가합니다.
  5. Cloudflared 프록시는 SSH 서버의 개인 IP에 연결됩니다.
</Details>

개인 DNS 해설자가 없거나 SSH를 IP 주소로 옮길 경우[단계 4](#4-optional-use-ip-routes).

## 6. 사용자로 연결

터널 경로와 사용자 장치를 설정하면 사용자는 이제 SSH 기계에 연결할 수 있습니다. SSH 서버가 SSH 키가 필요하면 SSH 명령에 키가 포함되어 있어야 합니다.

```sh
ssh -i ~/.ssh/gcp_ssh <username>@ssh.internal.local
```

WARP 클라이언트는 Zero Trust 조직에 연결되어야 합니다. 사용자가 만든 게이트웨이 네트워크 정책을 일치하면 연결할 수 있습니다.

### 문제 해결

연결할 수 없는 경우, 다음을 확인합니다:

1. **DNS 해상도 확인**- WARP 장치에서, 당신은 성공적으로 개인적인 hostname을 해결할 수 있다는 것을 확인하십시오:

   ```sh
   nslookup ssh.internal.local
   ```

   ```sh output
   Server:		127.0.2.2
   Address:	127.0.2.2#53

   Non-authoritative answer:
   Name:	ssh.internal.local
   Address: 100.80.200.48
   ```

   자주 묻는 질문[WARP의 DNS 프록시](/cloudflare-one/team-and-resources/devices/warp/configure-warp/route-traffic/warp-architecture/#dns-traffic)게이트웨이를 반환<GlossaryTooltip term="initial resolved IP">초기 해결 IP</GlossaryTooltip>. 쿼리가 다른 IP를 해결하거나 반환하지 못하면, 확인[지역 도메인 Fallback](/cloudflare-one/team-and-resources/devices/warp/configure-warp/route-traffic/local-domains/)구성 및[Gateway 해결사 정책](/cloudflare-one/traffic-policies/resolver-policies/).

2. **Gateway 로그 확인**- 리뷰[Gateway 네트워크 로그](/cloudflare-one/insights/logs/gateway-logs/)연결이 정책에 의해 차단되는 경우 볼 수 있습니다.

3. **터널 상태를 검증**- 터널이 건강하고 연결되도록 확인[터널 상태](/cloudflare-one/networks/connectors/cloudflare-tunnel/monitor-tunnels/).

4. **초기 해결 IP에 대한 연결성 테스트**- SSH 서버에 연결하면, 장치가 연결해야 합니다.<GlossaryTooltip term="initial resolved IP">초기 해결 IP</GlossaryTooltip>:

   ```sh
   ssh -v <username>@ssh.internal.local
   ```

   ```sh output
   ...
   Authenticated to ssh.internal.local ([100.80.200.48]:22) using "publickey".
   ...
   ```

   IP에 연결되는 선을 찾습니다`100.64.0.0/10`범위. 요청이 실패하면 초기 해결 IP를 확인합니다.[WARP 터널을 통해 경로](/cloudflare-one/team-and-resources/devices/warp/configure-warp/route-traffic/split-tunnels/). 당신은 또한 당신의 검사할 수 있습니다[터널 로그](/cloudflare-one/networks/connectors/cloudflare-tunnel/monitor-tunnels/logs/)요청이 서버의 개인 IP로 routing임을 확인합니다.
