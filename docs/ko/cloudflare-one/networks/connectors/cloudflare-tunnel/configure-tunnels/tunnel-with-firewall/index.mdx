모든 진입 트래픽을 차단하여 Cloudflare 터널을 사용하여 긍정적 인 보안 모델을 구현할 수 있으며 egress 트래픽 만 허용`cloudflared`. 당신의 갱도 윤곽에서 지정된 서비스는 외부 세계에 드러낼 것입니다.

## 항구 항구

아래의 매개 변수는 방화벽 내부의 egress 트래픽을 구성할 수 있습니다.

방화벽 유형을 구성하는 방법:

- 방화벽이 도메인 기반 규칙 (FQDN 수당)을 지원한다면 아래 나열된 호스트 이름에 아웃바운드 연결을 허용할 수 있습니다.
- 방화벽이 IP 기반 규칙을 필요로 하는 경우, 각 도메인의 모든 목록 IP 주소로 아웃바운드 연결을 허용한다.

공급 능력`7844`TCP 및 UDP 프로토콜 모두 허용됩니다 (for`http2`·`quic`).

### 터널 작업에 필요한

`cloudflared`포트에 Cloudflare의 글로벌 네트워크에 연결`7844`. Cloudflare를 사용하기 위하여 터널, 방화벽은 포트에 다음 목적지에 아웃바운드 연결을 허용해야합니다`7844`(UDP를 사용하려면`quic`프로토콜 또는 TCP를 사용하는 경우`http2`프로토콜).

## 방화벽 구성

### 클라우드 VM 방화벽

클라우드 공급자의 가상 머신 (VM) 인스턴스에서 서비스를 호스팅하는 경우 모든 진입 트래픽을 차단하고 egress 트래픽을 허용하는 인스턴스 레벨 방화벽 규칙을 설정할 수 있습니다. 예를 들어, Google Cloud Platform (GCP)에서 모든 진입 규칙을 삭제할 수 있습니다. GCP의 방화벽 denies ingress 트래픽이 명시된 규칙과 일치하지 않는 것이기 때문입니다.

### OS 방화벽

대안으로, 당신은 운영 체제 (OS) 레벨 방화벽 규칙을 사용하여 모든 진입 트래픽을 차단하고 유일한 egress 트래픽을 허용 할 수 있습니다. 예를 들어, 서버가 Linux에서 실행하면 사용할 수 있습니다.`iptables`방화벽 규칙을 설정하려면:

1. 현재 방화벽 규칙을 확인하십시오.

   ```sh
   sudo iptables -L
   ```

2. 지원하다`localhost`스스로 소통하기.

   ```sh
   sudo iptables -A INPUT -i lo -j ACCEPT
   ```

3. 이미 연결 및 관련 트래픽을 설정할 수 있습니다.

   ```sh
   sudo iptables -A INPUT -m conntrack --ctstate RELATED,ESTABLISHED -j ACCEPT
   ```

4. 새로운 SSH 연결을 허용.

   ```sh
   sudo iptables -A INPUT -p tcp --dport ssh -j ACCEPT
   ```

5. 다른 진입 트래픽을 드롭합니다.
   :::카트로션\[Warning]

   뒤에 오는 명령에 아주 주의하십시오. 현재 SSH 연결을 보존하지 않았거나 새로운 SSH 연결을 허용하지 않았다면, SSH가 다시 시스템에 다시 로그 아웃 할 수 없습니다.
   주요 특징

   ```sh
   sudo iptables -A INPUT -j DROP
   ```

6. 방화벽 규칙을 설정한 후, 이 명령을 사용하여 현재 확인`iptables`설정:

   ```sh
   sudo iptables -L
   ```

7. 터널을 실행하고 모든 구성 된 서비스는 터널을 통해 외부 세계에 접근 할 수 있지만 서버의 외부 IP 주소를 통해하지 않습니다.

8. 기본적으로, 규칙을 통해 추가`iptables`명령은 메모리에만 저장되며 재부팅에 persist하지 않습니다. Linux 배포에 따라 방화벽 규칙을 저장하고 다시로드하는 다양한 방법이 있습니다. 예를 들어, Debian에서 사용할 수 있습니다.[`iptables-persistent`](https://packages.debian.org/sid/iptables-persistent)포장:

   ```sh
   sudo apt install iptables-persistent
   sudo netfilter-persistent save
   ```

### PowerShell로 테스트

Windows에서 PowerShell 명령을 사용할 수 있습니다.`dig`없습니다.

DNS를 테스트하려면:

```powershell
Resolve-DnsName -Name _v2-origintunneld._tcp.argotunnel.com SRV
```

```txt output

----                                     ----   ---   -------    ----------                     -------- ------ ----

_v2-origintunneld._tcp.argotunnel.com       SRV    112   Answer     region1.v2.argotunnel.com         1        1      7844
```
