Cloudflare로 게이트웨이, HTTPS(DoH) 요청을 통해 DNS를 필터링할 수 있습니다.[DNS 위치](/cloudflare-one/networks/resolvers-and-proxies/dns/locations/)또는 귀하의 장치에 WARP 클라이언트를 설치하지 않고 사용자에 의해.

위치 기반 정책은 DNS 요청을 보내야합니다.[위치별 DoH 엔드포인트](#filter-doh-requests-by-location), 정체성 기반 정책은 그 요청이 포함되어야합니다.[사용자 별 DoH 토큰](#filter-doh-requests-by-user).

## 위치별 필터 DoH 요청

위치 기반 정책은 DNS 쿼리를 고유하게 보낼 것을 요구합니다.<GlossaryTooltip term="DoH subdomain">DoH 엔드포인트</GlossaryTooltip>위치 지정:

```txt
https://<YOUR_DOH_SUBDOMAIN>.cloudflare-gateway.com/dns-query
```

### 자주 묻는 질문

위치 찾기<GlossaryTooltip term="DoH subdomain">DoH 하위 도메인</GlossaryTooltip>.

### DoH에 대한 브라우저 구성

브라우저는 HTTPS(DoH) 엔드포인트에서 DNS를 사용할 수 있습니다. 브라우저에서 DoH를 직접 구성하려면 DoH 엔드포인트로 게이트웨이 DNS 위치를 선택해야 합니다. 그렇지 않으면 DNS 필터링은 브라우저에서 발생하지 않습니다.

<Render file="gateway/doh-instructions" product="cloudflare-one" />

DNS 쿼리는 이제 필터링 게이트웨이로 전송됩니다. 이러한 요청을 필터링하려면 DNS 정책을 사용하여[**DNS 위치**](/cloudflare-one/networks/resolvers-and-proxies/dns/locations/)옵션 정보

### 일반 DoH endpoint 사용

일반 Cloudflare DoH 엔드포인트에 DoH 요청을 보낼 수 있습니다.`dns.cloudflare-gateway.com`. 요청의 위치를 지정하려면, header 이름을 포함`cf-dns-location`위치의 DoH 하위 도메인의 값으로. 예를 들면:

```http
GET /dns-query?name=example.com&type=A HTTP/2
Host: dns.cloudflare-gateway.com
cf-dns-location: 9y65g5srsm
Accept: application/dns-message
```

## 사용자별 필터 DoH 요청

사용자 정체성을 기반으로 DoH 쿼리를 필터링하려면 각 쿼리는 사용자 별 인증 토큰을 포함해야합니다. 사용자 당 여러 장치가 있고 장치별 정책을 적용하려는 경우, 각 장치에서 다른 이메일으로 지도해야 합니다.

현재 인증 토큰은 API를 통해 생성될 수 있습니다. 이것을 실행할 수 있습니다.[상호 작용하는 Python 스크립트](/cloudflare-one/static/authenticated-doh.py)설정 절차를 자동화하거나 아래의 단계를 따르십시오.

### 1. 계정의 서비스 토큰 만들기

각 Cloudflare 계정은 하나의 활성 액세스 만 가능합니다.[서비스 토큰](/cloudflare-one/access-controls/service-credentials/service-tokens/)한 번에 HTTPS (DoH)에 DNS에 대한 허가.

```bash
curl "https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/access/service_tokens" \
--header "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
--header "Content-Type: application/json" \
--data '{"name":"ACME Corporation service token"}'
```

서비스 토큰 저장`client_id`, `client_secret`·`id`.

### 2. 서비스 토큰을 위한 Enable DoH 기능

```bash
curl --request PUT \
"https://api.cloudflare.com/client/v4/accounts/$ACCOUNT_ID/access/organizations/doh/$SERVICE_TOKEN_ID" \
--header "Authorization: Bearer $CLOUDFLARE_API_TOKEN"
```

당신이 얻을 경우`access.api.error.service_token_not_found`오류, 확인`$SERVICE_TOKEN_ID`값은`id`그리고 아니`client_id`.

:::참조

### 4. 사용자를 위한 DoH 토큰 생성

사용자를 위한 DoH 토큰을 요청하여 서비스 토큰을 사용하여<GlossaryTooltip term="team domain">팀 도메인</GlossaryTooltip>.

```bash
curl "https://<TEAM_NAME>.cloudflareaccess.com/cdn-cgi/access/doh-token?account-id=<ACCOUNT_ID>&user-id=<USER_ID>&auth-domain=<TEAM_NAME>.cloudflareaccess.com" \
--header "Cf-Access-Client-Id: <CLIENT_ID>" \
--header "Cf-Access-Client-Secret: <CLIENT_SECRET>"
```

### 5. 정정된 DoH 조회를 보내십시오

해결자에게 DoH 쿼리 보내기`https://<ACCOUNT_ID>.cloudflare-gateway.com/dns-query`, 사용자의 DoH 토큰을 포함 하 여 확인`CF-Authorization`헤더.

```bash
curl --silent "https://<ACCOUNT_ID>.cloudflare-gateway.com/dns-query?name=example.com" \
--header "accept: application/dns-json" \
--header "CF-Authorization: <USER_DOH_TOKEN>" | jq
```

사이트가 차단되고 당신은 켜져있다면[블록 페이지](/cloudflare-one/reusable-components/custom-pages/gateway-block-page/#configure-policy-block-behavior)정책의 경우 쿼리가 반환됩니다.`162.159.36.12`( 게이트웨이 블록 페이지의 IP 주소). 블록 페이지가 비활성화되면 응답이됩니다.`0.0.0.0`.
