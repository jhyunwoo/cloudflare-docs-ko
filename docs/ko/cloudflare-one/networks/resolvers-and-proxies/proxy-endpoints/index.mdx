주요 특징

Proxy endpoints는 클라이언트를 장치에 설치하지 않고 Gateway 정책을 적용 할 수 있습니다. 설정하기[Proxy Auto-Configuration (PAC) 파일](#what-is-a-pac-file)브라우저 수준에서, 당신은 필터링 및 정책 시행을위한 게이트웨이를 통해 트래픽을 통과 할 수 있습니다. Cloudflare는 프록시 엔드포인트의 두 가지 유형 구성을 지원합니다.[승인 endpoints](#authorization-endpoint)·[소스 IP 프록시 엔드포인트](#source-ip-endpoint).

:::참조
최고의 경험과 가장 깊은 가시성을 위해 Cloudflare는 사용하기 좋습니다[WARP 클라이언트](/cloudflare-one/team-and-resources/devices/warp/). 장치 클라이언트를 설치할 때 프록시 엔드포인트를 사용하여 환경에 견딜 수 없습니다.
주요 특징

### 프록시 엔드포인트를 사용할 때

Proxy endpoints는 WARP 클라이언트를 배치하는 환경에 적합하지 않습니다. 일반적인 사용 사례:

- **가상 데스크톱 (VDI)**: 사용자는 가상 머신으로 로그인하고 인터넷에 도달하기 위해 브라우저를 사용합니다.
- **규정 준수**: 법적으로 또는 기술적으로 Endpoint에 소프트웨어를 설치하지 않는 환경.
- **Legacy SWG 마이그레이션**: PAC 파일을 사용하는 Legacy Secure Web Gateways에서 전환하는 조직.

### PAC 파일이란?

<GlossaryDefinition term="PAC file" prepend="A PAC file is " />

최종 사용자는 웹 사이트를 방문 할 때 브라우저는 게이트웨이에 의해 필터링 할 계정과 관련된 Cloudflare 프록시 서버에 요청을 보냅니다. PAC 파일은 모든 요청에 대한 브라우저에 의해 평가되며 트래픽이 프록시를 통해 이동하거나 직접 연결해야 할지 결정합니다. Gateway 정보[각 유형의 HTTP 트래픽을 필터링 할 수 없습니다](#traffic-limitations)PAC 파일을 사용하여 proxied.

PAC 파일은 몇 가지 이점을 제공합니다 :

- **통합 관리**: 개별 기기를 재구성하지 않고 한 위치에 있는 routing 규칙
- **가동 가능한 routing**: 다른 프록시 또는 도메인, IP 범위 또는 프로토콜을 기반으로 한 직접 연결에 대한 경로 다른 트래픽 유형
- **짐 밸런싱**: 자동 장애를 가진 다수 프록시 서버의 맞은 트래픽

:::참조
PAC 파일은 사용자 상호 작용을 요구합니다. Authorization endpoints는 사용자가 로그인해야 합니다.[사이트맵 오시는 길](/cloudflare-one/access-controls/policies/). PAC 파일은 현재 사용자 이름/암호, mTLS 또는 Kerberos 허가를 지원하지 않습니다. 추가 인증 방법에 대한 지원은 향후 출시 예정입니다.
주요 특징

### 프록시 엔드포인트의 종류

사이트맵 하나의 제공 두 가지 유형의 프록시 엔드 포인트, 각각의 다른 권한 방법.

프록시 엔드포인트를 만들면 입력할 수 없습니다. 다른 권한이 있는 경우, 새로운 프록시 엔드포인트를 생성해야 합니다.

#### 인증 endpoint<Badge text="Beta" variant="caution" />

Authorization endpoints 사용[사이트맵 오시는 길](/cloudflare-one/access-controls/policies/)Zero Trust 승인 제공 사용자는 정체성 공급자를 통해 인증하고 프록시 엔드포인트를 사용할 수 있기 전에 액세스 정책을 통과해야합니다.

승인 종료를 사용할 때:

- 사용자 수준의 인증 및 ID 기반 정책이 필요합니다.
- 프록시 트래픽과 특정 사용자를 연결하고 싶습니다.
- 조직은 ID 공급자를 통해 로그인해야 합니다 (Okta, Microsoft Entra ID 또는 Google Workspace와 같은)
- 프록시에 접속할 수 있는 granular 컨트롤이 필요합니다.

#### 근원 IP 엔드포인트

IP 엔드포인트는 IP 주소를 기반으로 트래픽을 승인합니다. 사전 구성 IP 주소 만 트래픽은 프록시 엔드포인트를 사용할 수 있습니다.

소스 IP 엔드포인트를 사용할 때:

- 사무실 또는 네트워크 위치의 고정 세트가 있습니다.
- 사용자 인증 없이 간단한 설정
- 귀하의 장치 공유 일반적인 egress IP 주소
- 당신은 개별 사용자를 식별 할 필요가 없습니다

## 2. PAC 파일을 만듭니다

PAC 파일은 JavaScript에 기록된 텍스트 파일이며, 이는 프록시 서버에 리디렉션해야 합니다. Cloudflare 대시보드에 PAC 파일을 만들거나 자신의 사용자 정의 PAC 파일을 작성할 수 있습니다.

:::가격
PAC 파일을 만들기위한 상세한 지침 및 예시, 참조[PAC 파일 모범 사례](/cloudflare-one/networks/resolvers-and-proxies/proxy-endpoints/best-practices/).
:::

### 호스팅 PAC 파일 만들기<Badge text="Beta" variant="caution" />

Cloudflare One에서 PAC 파일을 만들 때 Cloudflare는 공개적으로 접근 가능한 노동자에 호스트합니다. Hosted PAC 파일은 Cloudflare의 글로벌 네트워크를 통해 자동으로 배포됩니다.

호스팅 PAC 파일을 만들려면:

1. 내 계정[사이트맵 한국어](https://one.dash.cloudflare.com/), 이동**네트워크** > **해결사 및 Proxies**.

2. 제품정보**프록시 엔드포인트**.

3. [프록시 엔드포인트 만들기](#1-create-a-proxy-endpoint)또는 기존 하나를 선택, 다음 선택**제품정보**.

4. 제품정보**PAC 파일 추가**.

5. PAC 파일을 구성:

   내 계정**PAC 파일 세부 정보**:

   1. 이름 \***기본 정보**이름과 선택적인 묘사를 포함하여.
   2. (선택 사항) 사용자 지정**URL 슬러그**기억에 남는 URL 경로 만들기. 슬러그는 생성 후 변경할 수 없습니다.
   3. 내 계정**PAC 파일 구성**, 선택**Browse PAC 파일 구성 템플릿**템플릿을 선택하여 사용자 정의할 수 있습니다. 사용 가능한 템플릿은 Okta 및 Azure입니다. 템플릿을 선택한 후,**PAC 파일 JavaScript**선택된 템플릿과 대화할 수 있습니다.
   4. 네트워크 요구 사항에 맞게 JavaScript를 수정합니다.

   내 계정**설정 설명서**:

   1. 브라우저를 선택하십시오.
   2. Cloudflare의 지시를 따르십시오 장치를 구성하는 것.

6. 제품정보**이름 \***.

호스팅 된 PAC 파일 URL은 다음과 같습니다.

```txt
https://pac.cloudflare-gateway.com/<account-id>/<slug>
```

위치:

- `<account-id>`이름 \*[Cloudflare 계정 ID](/fundamentals/account/find-account-and-zone-ids/)
- `<slug>`지정된 사용자 정의 경로입니다 (또는 사용자 지정하지 않는 경우 자동 생성 값)

#### PAC 파일 제한

Cloudflare-hosted PAC 파일은 다음과 같은 제한이 있습니다.

- **최대 파일 크기**: PAC 파일 당 256 KB
- **계정 당 최대 PAC 파일**: 50 (비엔터프라이즈 계획) 또는 1,000 (기업 계획)
- **새소식**: 글로벌 네트워크에서 몇 초 안에 PAC 파일 propagate로 변경

#### 충돌 행위

PAC 파일은 성능과 신뢰성을 위해 전 세계적으로 캐시됩니다.

- 브라우저 및 운영 체제는 PAC 파일을 로컬로 캐시할 수 있습니다.
- PAC 파일을 자동으로 호스팅하는 업데이트는 캐시를 유효
- 클라이언트가 새 버전을 fetch 할 필요가 있다면, 클라이언트 구성에 따라 브라우저 캐시 또는 다시 시작 브라우저를 삭제해야 할 수 있습니다.

### 자체 호스팅 PAC 파일

내부 웹 서버와 같은 자체 인프라에서 PAC 파일을 호스트 할 수도 있습니다.[Cloudflare Workers](/workers/). Self-hosting은 호스팅 환경에 대한 완전한 제어를 제공하지만 가용성 및 배포를 관리해야합니다.

### 프록시 엔드포인트 제한

각 계정은 프록시 엔드포인트의 최대 번호가 있습니다.

- **Non-Enterprise 계획**: 50 프록시 엔드포인트
- **Enterprise 계획**: 500 프록시 엔드포인트

## 3. 장치 구성

### 3a. Cloudflare 인증서 설치

프록시 엔드포인트로 Gateway HTTP 정책을 사용하려면 반드시 해야 합니다.[Cloudflare 인증서 설치](/cloudflare-one/team-and-resources/devices/user-side-certificates/)당신의 장치에. Gateway는 HTTPS 트래픽을 검사하고 특정 도메인을 차단하거나 게이트웨이 블록 페이지를 표시합니다.

### 3b. PAC 파일을 사용하는 브라우저 구성

모든 주요 브라우저는 PAC 파일을 지원합니다. 개별 브라우저를 구성하거나 장치에서 모든 브라우저에 적용하는 시스템 설정을 구성할 수 있습니다. 여러 기기는 프록시 엔드포인트 설정에 포함 된 소스 IP 주소만큼 동일한 PAC 파일을 호출 할 수 있습니다.

## 4. HTTP 정책을 테스트

구성을 테스트하려면,[HTTP 정책](/cloudflare-one/traffic-policies/http-policies/)테스트 도메인을 차단합니다. 브라우저에서 차단 된 도메인을 방문 할 때 게이트웨이 블록 페이지를 참조하십시오.

이제 프록시 엔드포인트 선택기를 사용할 수 있습니다.[네트워크](/cloudflare-one/traffic-policies/network-policies/#proxy-endpoint)·[HTTP: HTTP](/cloudflare-one/traffic-policies/http-policies/#proxy-endpoint)PAC 파일을 통해 트래픽을 필터링하는 정책.

## 제한 사항

### 인증 endpoint 제한

사용 방법[승인 endpoints](#authorization-endpoint), 뒤에 오는 제한의 인식일 수 있습니다.

#### 도메인 우회 및 인증서 pinning

PAC 파일로 검사하지 않을 도메인을 우회해야합니다. Gateway는 여전히 적용됩니다[Inspect (DNI) 정책](/cloudflare-one/traffic-policies/http-policies/#do-not-inspect)인증 엔드포인트를 사용할 때, 이것은 인증서 핀닝 오류를 우회하지 않습니다.

#### Plaintext HTTP 트래픽

Authorization endpoints는 트래픽이 구성되지 않는 일반 텍스트 HTTP 트래픽을 지원하지 않습니다[오시는 길](/cloudflare-one/access-controls/applications/http-apps/self-hosted-public-app/)또는 PAC 파일로 우회.

#### 브라우저 고립

오시는 길[HTTP 격리 정책](/cloudflare-one/traffic-policies/http-policies/#isolate)현재 베타 기간 동안 승인 종료점을 지원하지 않습니다.

#### Referer 헤더 트래픽

같은 소스 IP에서 사용자에 로그인 최근 기록 된 도메인을 일치하는 참조 HTTP 헤더와 트래픽은 다음 비 ID 이메일 주소와 함께 허용됩니다 :

```txt
auth-proxy-non-identity@<your-team-name>.cloudflareaccess.com
```

이름 \*`<your-team-name>`이름 \*[팀 이름](/cloudflare-one/faq/getting-started-faq/#what-is-a-team-domainteam-name).

브라우저가 사용자 인증을 확인하기 위해 사용되는 ID 쿠키를 사용하여 HTTP 하위 요청을 태그하지 않기 때문에 발생합니다. 이것은 프록시 기반 Secure Web Gateways의 업계 표준 행동입니다.

이 트래픽을 필터링하려면 두 가지 옵션이 있습니다.

- 설정하기[HTTP 정책](/cloudflare-one/traffic-policies/http-policies/)블록 또는 모든 트래픽 일치 허용`auth-proxy-non-identity@<your-team-name>.cloudflareaccess.com`이메일 주소
- 특정 소스 IP에 비 필수 트래픽을 제한하려면, 생성[네트워크 정책](/cloudflare-one/traffic-policies/network-policies/)소스 IP와 프록시 엔드포인트 모두 일치합니다.

### 교통 제한

프록시 엔드포인트의 각 유형은 다음과 같은 기능을 지원합니다:

| 제품 정보                                                                      | 근원 IP 엔드포인트 | 인증 endpoint |
| -------------------------------------------------------------------------- | ----------- | ----------- |
| **HTTP/HTTPS 트래픽**                                                         | ✅[^1]       | ✅[^2]       |
| **비-HTTP TCP 트래픽**                                                         | ✅           | —           |
| **UDP 트래픽**                                                                | —           | —           |
| **[웹 사이트](/cloudflare-one/traffic-policies/http-policies/http3/)**         | —           | —           |
| **[Identity 기반 정책](/cloudflare-one/traffic-policies/identity-selectors/)** | —           | ✅           |
| **mTLS 인증**                                                                | —           | —           |
| **[행복한 아이볼](https://datatracker.ietf.org/doc/html/rfc6555)**               | —           | —           |
| **브라우저 HTTPS 자동 업그레이드**                                                    | —[^3]       | —[^3]       |

[^1]: 제품 정보[소스 IP 엔드포인트](#source-ip-endpoint)일반 텍스트 HTTP (non-HTTPS) 소스에 액세스하려면 구성[셀프 호스팅 액세스 애플리케이션](/cloudflare-one/access-controls/applications/http-apps/self-hosted-public-app/). 이것은 사용자가 접근 정책을 통해 보안을 유지하면서 HTTP 리소스에 액세스 할 수 있습니다.

[^2]: 일반 텍스트 HTTP (non-HTTPS) 소스에 액세스하려면[승인 endpoints](#authorization-endpoint), 참조[Plaintext HTTP 트래픽](#plaintext-http-traffic).

[^3]: 프록시 엔드포인트는 브라우저가 HTTPS로 HTTP 요청을 자동으로 업그레이드 할 때 HTTPS를 지원하지 않습니다 (Chrome의 자동 HTTPS 업그레이드와 같은). 자동 업그레이드된 사이트와 연결 문제가 발생하면 브라우저 설정에서 자동 HTTPS 업그레이드를 비활성화하거나 예외로 사이트를 구성할 수 있습니다.

### Gateway DNS 및 해결자 정책

오시는 길[DNS 보호](/cloudflare-one/traffic-policies/dns-policies/)·[해결사](/cloudflare-one/traffic-policies/resolver-policies/)정책은 항상 장치 구성에 관계없이 PAC 파일과 함께 트래픽에 적용됩니다.
