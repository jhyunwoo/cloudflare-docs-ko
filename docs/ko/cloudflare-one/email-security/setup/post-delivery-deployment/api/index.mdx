API 배포를 선택할 때, 이메일 메시지는 이미 사용자의 inbox에 도달 한 후 이메일 보안에 도달합니다.

그런 다음 이메일 공급자와 통합을 통해 이메일 보안을 할 수 있습니다.[자동 모드 메시지](/cloudflare-one/email-security/settings/auto-moves/)조직의 정책을 기반으로 합니다.

![API 배포로, 사용자가 도달 한 후 이메일 보안의 이메일 필터를 통해 메시지 여행.](~/assets/email-security/M365_API_Deployment_Graph.png)

## 이름 \*

API 배포를 선택할 때 다음 혜택을 얻을 수 있습니다:

- 메일 플로우 작업에 어떤 변화없이 복잡한 이메일 아키텍처에 대한 쉬운 보호.
- Microsoft 365에 대한 Agentless 배포.

## 제한 사항

그러나 API 배포에는 다음과 같은 단점이 있습니다.

- 이메일 보안은 Microsoft의 Graph API에 의존하고, 정전은 inbox에 있는 메시지 거주 시간을 증가할 것입니다.
- 귀하의 이메일 공급자는 이메일 보안에서 throttle API 요청을 할 수 있습니다.
- 이메일 보안은 메일 박스에 대한 열람 및 쓰기가 필요합니다.
- 귀하의 이메일 공급자로부터 API 지원 필요 (일반적으로 지원되지 않음).
- 탐지 비율은 다수 해결책이 존재하는 경우에 더 낮을지도 모릅니다.
- 메시지는 수정 또는 quarantined 할 수 없습니다.
