1. 배포 경로 선택: 이메일 보안 제공 두 배포 모드,[포스트 기쁨](/cloudflare-one/email-security/setup/post-delivery-deployment/)API와 BCC/Journaling를 위해[사전 배달](/cloudflare-one/email-security/setup/pre-delivery-deployment/)MX/Inline를 위해.

## 1. 배포 선택

### 포스트 기쁨 배포

포스트 배달 배포를 선택할 때 Cloudflare는 이메일을 스캔**후에**그들은 사용자의 inbox에 도달.

Microsoft 365 사용자 인 경우이 작업을 통해 수행됩니다.[Microsoft의 그래프 API](/cloudflare-one/email-security/setup/post-delivery-deployment/api/m365-api/)또는[연구분야](/cloudflare-one/email-security/setup/post-delivery-deployment/bcc-journaling/journaling-setup/m365-journaling/).

당신이라면[Google 작업 공간](/cloudflare-one/email-security/setup/post-delivery-deployment/bcc-journaling/bcc-setup/gmail-bcc-setup/gmail-bcc-setup/)또는[Microsoft 교환](/cloudflare-one/email-security/setup/post-delivery-deployment/bcc-journaling/bcc-setup/bcc-microsoft-exchange/)사용자, 이것은 BCC를 통해 수행됩니다.

#### 왜 당신은 포스트 배달 배포를 고려해야

Post-delivery 배포는 시간 효율적인, 그것은 MX 변경을 포함하지 않기 때문에. Post-delivery 배포는 메일 흐름을 방해하지 않습니다. Post-delivery 배포를 사용하면[자동 모드 이벤트](/cloudflare-one/email-security/settings/auto-moves/)하드 또는 소프트 삭제 메시지 및 동기화[이름 \*](/cloudflare-one/email-security/directories/)Microsoft Graph API 또는 Google Workspace를 사용할 때.

:::참조
언제 당신은 포스트 배달 배포를 선택:

- 위협이 제거됩니다**후에**메시지는 inbox에 전달되었습니다.
- API 범위 또는 BCC/Journaling 규칙 윤곽을 요구합니다.
- Auto-move는 통합을 연결하면 BCC/Journaling에서만 가능합니다.
  주요 특징

### 사전 납품 배포

사전 배달 배포를 선택할 때 Cloudflare는 이메일을 스캔**이전 다음**그들은 사용자의 inbox에 도달. Cloudflare에 MX 레코드 포인트.

#### 왜 사전 배달 배포를 고려해야

Pre-delivery 배포는 가장 높은 수준의 보호를 제공합니다. 그것은 시행[텍스트 애드온](/cloudflare-one/email-security/settings/detection-settings/configure-text-add-ons/)또는 납품에 다시 쓰기 링크.

Pre-delivery 블록은 transit에서 위협을 차단하고 사용자가 이메일을 조회하기 전에 배너 또는 텍스트를 추가합니다.

:::참조
pre-delivery 배포를 선택할 때:

- MX 레코드를 편집하거나 커넥터를 만듭니다.
- 통합을 통해 자동화된 이벤트를 사용할 수 있습니다.
- 사이트맵[IP 정보](/cloudflare-one/email-security/setup/pre-delivery-deployment/egress-ips/)downstream 메일 서버에서 허용됩니다.
  주요 특징

더 알아보기[회사연혁](/cloudflare-one/email-security/reference/dispositions-and-attributes/#dispositions)dispositions에 대해 더 알아보기.

## 3. 임의 레지스트리 설정

이름 \*[비즈니스 이메일 손상 (BEC)](https://www.cloudflare.com/en-gb/learning/email-security/business-email-compromise-bec/)목표 임원 또는 금융 역할. 당신은 자격이 될 가능성이있는 역할의 주소를 추가해야합니다. 더 알아보기[회원 등록](/cloudflare-one/email-security/settings/detection-settings/impersonation-registry/)사용자를 impersonation Regisy에 추가하는 방법을 배우기 위해.

임의 레지스트리에 포함 할 수있는 역할은 다음과 같습니다.

- C 스위트
- 금융 역할
- 사이트맵
- IT 도움말
- 이름 \*

역할 변경으로 분기별로 임의 레지스트리를 검토해야합니다.

## 4. 메시지 제출

제출은 이메일의 처분으로 변경됩니다.**후에**초기 스캔. Cloudflare의 내장 피드백 루프는 false Positives/negatives를 수정합니다.**·**&#xAC10;지 모델을 훈련하여 더 똑똑한 시간을 얻을 수 있습니다. 더 알아보기[자주 묻는 질문](/cloudflare-one/email-security/submissions/#submit-messages-for-review)자주 묻는 질문

### 메시지를 reclassify 할 수 있습니다

[보안 팀](/cloudflare-one/email-security/submissions/team-submissions/)·[최종 사용자](/cloudflare-one/email-security/submissions/user-submissions/)제출을 수행 할 수 있습니다.

### 왜 메시지를 제출해야 하나요?

제출은 다음과 같이 중요합니다.

- **그들은 모델 정확도 향상**: 모든 검증 된 제출은 Cloudflare의 기계 학습을 가르치며 새로운 루어, 언어, 인프라 및 자비 패턴을 인식합니다.
- **그들은 경고 피로를 감소**: 사용자가 실제로 대시보드에서 소음을 절단하는 조직에 tailors 탐지를 원하는 Suspicious 또는 스팸 이메일 수정.
- **그들은 치료 루프를 닫습니다.**: 분해가 Malicious로 업그레이드되면 Cloudflare는 모든 inbox (Graph API 또는 Google Workspace API 통합)에서 해당 이메일을 자동으로 제거합니다.
- **그들은 당신이 어떤 제출에 촬영 활동을 기록 할 수 있습니다**: 각 제출은 원본, 요청 및 최종 분해에 대한 제출 ID, 세부 사항을 표시합니다. 더 알아보기[자주 묻는 질문](/cloudflare-one/email-security/submissions/#submit-messages-for-review)제출에 대해 더 알아보기.

제출의 대부분을 만들기 위해:

1. 매주 제출을 검토합니다.
2. 모든 MX/Inline 배포와 관련된 통합이 있습니다. 통합을 연결하면 매번 EML을 업로드 할 필요가 없습니다. Cloudflare는 귀하의 이메일 메시지 사본을받을 API를 사용할 수 있습니다.
3. 어떤 증가에 투자[사용자 제출](/cloudflare-one/email-security/investigation/search-email/#user-submissions)(사용자는 필터를 우회하는 phish를 발견 할 수 있습니다) 귀하의 정책을 분석하는 것을 확인합니다.

제출의 올바른 사용은 이메일 보안이 더 적은 수동 조정으로 더 강한 보호를 제공합니다.
