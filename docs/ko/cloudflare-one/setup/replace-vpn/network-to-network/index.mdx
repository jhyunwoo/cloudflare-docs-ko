각 네트워크에 두 개의 별도의 개인 네트워크를 연결하여 Cloudflare를 통해 두 방향으로 트래픽을 전송하고 수신할 수 있습니다. 사무실 위치, 데이터 센터, 또는 클라우드 환경을 연결해야 할 때 유용합니다. 예를 들면, 1개의 사무실에 있는 직원은 다른 사무실에 있는 파일 서버, 인쇄 기계, 또는 내부 신청에 접근할 수 있었습니다.

다른 연결 시나리오를 탐구하려면, 참조[VPN 설정](/cloudflare-one/setup/replace-vpn/).

이 가이드는 동일한 단계를 따릅니다**시작하기**경험에서[사이트맵 1개의 대시보드](https://one.dash.cloudflare.com).

## 어떻게 작동합니까?

[WARP 연결관](/cloudflare-one/networks/connectors/cloudflare-tunnel/private-net/warp-connector/) <InlineBadge preset="beta" />각 네트워크에서 단일 Linux 기기에 설치하는 네트워크 커넥터입니다. 그 장치는 전체 네트워크에 대한 트래픽을 처리 : Cloudflare에 아웃바운드 트래픽을 보내고 인바운드 트래픽을 수신 한 다음 네트워크에서 올바른 장치에 전달합니다. 이 때문에, 네트워크에 다른 장치는 어떤 소프트웨어를 설치할 필요가 없습니다.

## 자주 묻는 질문

- Cloudflare 계정으로 Zero Trust 조직. 이 설정하지 않은 경우, 참조[시작하기](/cloudflare-one/setup/).
- Linux 장치 또는 가상 머신은 첫 번째 개인 네트워크에 있습니다. 이것은 당신이 당신의 첫번째 WARP 연결관을 설치하는 곳에 입니다.
- 별도의 개인 네트워크에서 두 번째 Linux 장치 또는 가상 머신. 이것은 당신이 당신의 두번째 WARP 연결관을 설치하는 곳에 입니다.

:::참조
사이트맵 커넥터는 현재 Linux 전용입니다. 요구 사항 및 제한에 대한 자세한 내용은 참조[WARP 연결관](/cloudflare-one/networks/connectors/cloudflare-tunnel/private-net/warp-connector/).
:::

## 단계 1: 네트워크 세그먼트 정의

네트워크 세그먼트는 연결하려는 개인 네트워크의 IP 범위를 식별합니다. 세그먼트를 정의할 때 대시보드는 WARP 커넥터 구성을 생성하고 Cloudflare를 어떻게 네트워크에 도달하는 경로를 설정합니다. 다음 단계에 커넥터를 설치하고 실행합니다.

1. 내 계정[사이트맵 한국어](https://one.dash.cloudflare.com), 선택**시작하기**탭.
2. 제품 정보**클라이언트 기반 또는 사이트로 VPN 교체**, 선택**시작하기**.
3. 제품 정보**네트워크**, 선택**계속하기**.
4. 에 의해**사설망 간 교통**스크린, 선택**계속하기**.
5. 첫 번째 네트워크 세그먼트의 IP 범위를 입력 (예를 들어,`10.0.0.0/24`).
6. 이 네트워크 세그먼트의 이름을 입력 (예를 들어,`office-a`).
7. 제품정보**계속하기**.

:::참조
네트워크의 IP 범위가 확실하지 않은 경우 라우터 또는 네트워크 설정을 확인하십시오.

## 단계 2: 첫번째 연결관을 배치하십시오

첫번째 네트워크 세그먼트에 있는 리눅스 장치에 WARP 연결관을 설치하십시오. 대시보드는 운영 체제에 특정 명령을 생성합니다.

1. 드롭다운에서 장치의 운영 체제를 선택하십시오.

2. Linux 기기에서 대시보드에 표시된 명령을 복사하고 실행합니다. 대시보드는 명령의 세 세트를 제공합니다:
   1. **WARP 설치**: 패키지 저장소를 설정하고 설치`cloudflare-warp`패키지.
   2. **IP 전달**: 네트워크간의 트래픽을 전달할 수 있습니다.
   3. **토큰을 가진 WARP 연결관을 실행하십시오**: Cloudflare 계정을 가진 연결관을 등록하고 그것을 연결합니다.

3. 연결관 배치 후에, 대시보드는 당신의 네트워크 세그먼트가 활동적입니다.

4. 제품정보**계속하기**.

## 단계 3: 두 번째 세그먼트 정의

동일한 프로세스를 반복[단계 1](#step-1-define-a-network-segment)두 번째 네트워크. IP 범위는 첫 번째 세그먼트로 오버랩하지 않아야합니다. 각 네트워크는 고유한 범위를 필요로 합니다 그래서 Cloudflare는 정확한 목적지 (예를 들면,`10.0.1.0/24`당신의 첫번째 세그먼트가 인 경우에`10.0.0.0/24`).

## 단계 4: Deploy 두번째 연결관

동일한 프로세스를 반복[단계 2](#step-2-deploy-first-connector)두 번째 네트워크 세그먼트의 Linux 장치에서. 연결관 배치 후에, 대시보드는 당신의 네트워크 세그먼트가 활동적입니다.

## 단계 5: 앞으로 장치 소통량

WARP 커넥터가 네트워크의 라우터에 설치되면 (기본 게이트웨이 역할을하는 장치), 네트워크의 다른 장치가 자동으로 트래픽을 전송합니다. 추가 구성이 필요 없으며, 이 단계를 건너뛸 수 있습니다.

WARP 커넥터가 다른 장치에 설치되면 네트워크의 다른 장치가 정적 경로를 필요로하므로 WARP 커넥터 장치에 크로스 네트워크 트래픽을 전송하는 것을 알고 있습니다. 이 경로없이, 장치는 다른 네트워크에 대한 트래픽을 전송하는 곳을 모른다, 연결은 작동하지 않습니다. 대시보드는 시스템의 OS-specific 명령어를 제공하여 트래픽을 전달합니다.

1. 구성하려는 장치의 운영 체제를 선택하십시오.
2. 터널을 선택하여 교통을 우회합니다.
3. 대상 장치에 생성된 명령을 복사하고 실행합니다.
4. 필요에 따라 추가 장치를 반복하거나 선택**계속하기**마지막 단계로 진행하십시오.

routing 옵션에 대한 자세한 내용은 참조[두 개 이상의 개인 네트워크를 연결](/cloudflare-one/networks/connectors/cloudflare-tunnel/private-net/warp-connector/site-to-site/#4-route-traffic-from-subnet-to-warp-connector).

## 6 단계 : 연결 확인

대시보드는 당신의 연결관이 반대 네트워크 세그먼트에 있는 장치를 도달할 수 있다는 것을 확인합니다. 둘 다 네트워크에 장치는 이제 Cloudflare를 통해 통신할 수 있습니다.

연결성을 확인하려면 반대 네트워크에 장치를 도달하십시오 (예를 들어,`ping 10.0.1.100`첫번째 네트워크에 장치에서).

## 다음 단계

연결 확인 후, 정책 및 액세스 제어와 연결된 네트워크를 확보 고려:

- **Gateway 정책 설정**: 기본적으로 네트워크 세그먼트 사이의 모든 트래픽은 제한없이 Cloudflare를 통해 흐릅니다. Gateway 정책은 네트워크간에 스캔, 필터 및 로그 트래픽을 할 수 있습니다. 더 많은 정보를 원하시면, 참조[DNS 정책](/cloudflare-one/traffic-policies/dns-policies/), [네트워크 정책](/cloudflare-one/traffic-policies/network-policies/)·[HTTP 정책](/cloudflare-one/traffic-policies/http-policies/).
- **오시는 길**: 특정 서비스에 대한 제한 또는 ID 기반 규칙과 연결된 네트워크에 호스트. 더 많은 정보를 원하시면, 참조[개인 IP 또는 호스트 이름 보안](/cloudflare-one/access-controls/applications/non-http/self-hosted-private-app/).
- **장치 프로필 만들기**: 사용자 장치에서 Cloudflare를 통해 커넥터 경로에 대한 제어. 더 많은 정보를 원하시면, 참조[두 개 이상의 개인 네트워크를 연결](/cloudflare-one/networks/connectors/cloudflare-tunnel/private-net/warp-connector/site-to-site/).
- **Zero Trust에 더 많은 것을 탐험하십시오**: 커넥터, 정책 및 경로 검토[사이트맵 1개의 대시보드](https://one.dash.cloudflare.com).

정책 설계 및 장치 자세 검사에 대한 심층적 인지도, 참조[VPN 학습 경로 변경](/learning-paths/replace-vpn/concepts/).

- [문제 해결 터널](/cloudflare-one/networks/connectors/cloudflare-tunnel/troubleshoot-tunnels/): 터널 연결 및 라우팅 문제를 진단합니다.
