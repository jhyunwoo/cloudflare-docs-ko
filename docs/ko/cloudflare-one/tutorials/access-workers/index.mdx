이 튜토리얼은 사용하는 방법을 다룹니다.[사이트맵 작업자](/workers/)사용자 지정 HTTP 헤더를 트래픽에 추가, 그리고 그 사용자 지정 헤더를 보낼 방법 당신의 근원 서비스에 의해 보호[사이트맵 오시는 길](/cloudflare-one/access-controls/policies/).

일부 응용 프로그램 및 네트워킹 구현은 Zero Trust 프록시를 통해 이동하는 트래픽을 구현하기 어려울 수있는 원산지로 전달 될 특정 사용자 정의 헤더를 요구합니다. Worker를 구성할 수 있습니다.[사용자 인증 헤더](/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/)오시는 길

***

## 시작하기 전에

- Cloudflare 액세스로 소스 서버 보안

## 시작하기 전에

1. 내 계정[Cloudflare 대시보드](https://dash.cloudflare.com/), 이동**Workers 및 Pages**사이트 맵

   <DashButton url="/?to=/:account/workers-and-pages" />

2. 첫 번째 노동자라면, 선택**회사 소개**. 그렇지 않으면, 선택**회사연혁**, 다음 선택**회사 소개**.

3. Worker에 대한 identifiable 이름을 입력한 다음 선택**계정 만들기**.

4. 제품정보**비밀번호**.

5. 다음 노동자를 입력:

<TypeScriptExample>
  ```ts title="Worker with custom HTTP headers"
  export default {
  	async fetch(request, env, ctx): Promise<Response> {
  		const { headers } = request;
  		const cfaccessemail = headers.get("cf-access-authenticated-user-email");

  		const requestWithID = new Request(request);
  		requestWithID.headers.set("company-user-id", cfaccessemail);

  		return fetch(requestWithID);
  	},
  } satisfies ExportedHandler<Env>;
  ```
</TypeScriptExample>

6. 제품정보**저장 및 배포**.

당신의 노동자는 지금 당신의 접근 보호한 근원 서비스에 주문 우두머리를 보낼 준비가 준비되어 있습니다.

## 당신의 hostname에 노동자를 적용하십시오

1. 당신이 만든 노동자를 선택, 다음 이동**트리거**.
2. 내 계정**오시는 길**, 선택**경로 추가**.
3. 당신의 근원을 위한 hostname 그리고 지역을, 그 후에 선정하십시오**경로 추가**.

Worker는 정의된 경로와 일치하는 요청으로 사용자 정의 헤더를 삽입합니다. 예를 들면:

```http title="Example custom header" {4,5}
"Accept": "text/html,application/xhtml+xml,application/xml;q=0.9,image/avif,image/webp,image/apng,*/*;q=0.8,application/signed-exchange;v=b3;q=0.7",
    "Accept-Encoding": "gzip",
    "Accept-Language": "en-US,en;q=0.9",
    "Cf-Access-Authenticated-User-Email": "user@example.com",
    "Company-User-Id": "user@example.com",
    "Connection": "keep-alive"
```
