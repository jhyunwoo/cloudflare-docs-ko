이 튜토리얼은 Single-sign-on (SSO) 기능 확장을 통해 수행됩니다.[사이트맵 오시는 길](/cloudflare-one/access-controls/policies/)serverless 컴퓨팅 플랫폼과 함께[Cloudflare Workers](/workers/). 구체적으로, 이 가이드는 Cloudflare Access 인증 이벤트에서 추가 정보를 포함하기 위해 보안 된 원산지에 전송 된 요청을 수정하는 방법을 설명합니다.

**완료 시간:**&#x34;5 분

## 인증 흐름

[사이트맵 오시는 길](/cloudflare-one/access-controls/policies/)사용자가 응용 프로그램에 연결하기 전에 사용자의 정체성을 검증하는 인증 프록시입니다. 아래 다이어그램에 표시된 것처럼, Access inserts a[사이트맵](/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/application-token/)요청으로, 그런 다음[견적 요청](/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/validating-json/#validate-jwts)Origin 서버에 의해.

![Access 애플리케이션에 대한 표준 인증 흐름](~/assets/images/cloudflare-one/applications/access-standard-flow.png)

Cloudflare Worker를 사용하여 추가 HTTP 헤더를 요청할 수 있습니다. 이 예제에서, 우리는 추가합니다[장치 posture 속성](/cloudflare-one/reusable-components/posture-checks/#enforce-device-posture) `firewall_activated`·`disk_encrypted`, 그러나 Cloudflare Access가 인증 이벤트에서 수집 한 속성을 포함 할 수 있습니다.

![확장 인증 흐름은 추가 요청 헤더를 전달하기 위해 노동자를 사용합니다.](~/assets/images/cloudflare-one/applications/access-extended-flow-serverless.png)

## 이름 \*

이 접근법은 다음과 같습니다:

- **보안 강화:**&#xC778;증 이벤트에서 추가 정보를 통합함으로써 더 강력한 보안 조치를 구현할 수 있습니다. 예를 들어, 장치 준수에 따라 액세스 권한을 시행하기 위해 장치 자세 데이터를 사용할 수 있습니다.
- **사용자 경험 향상:**&#xC0AC;용자 속성을 기반으로 맞춤 콘텐츠 또는 기능을 통해 사용자 경험을 개인화 할 수 있습니다. 예를 들어, 사용자의 역할 또는 위치에 따라 다른 콘텐츠를 표시 할 수 있습니다.
- **개발 단순화:**&#x43;loudflare Workers를 사용함으로써 Cloudflare Access 구성을 쉽게 확장할 수 있습니다.

## 시작하기 전에

- 추가하기[자체 호스팅 응용](/cloudflare-one/access-controls/applications/http-apps/self-hosted-public-app/)Cloudflare 액세스.
- 이름 \*[Disk 암호화](/cloudflare-one/reusable-components/posture-checks/warp-client-checks/disk-encryption/)·[비밀번호](/cloudflare-one/reusable-components/posture-checks/warp-client-checks/firewall/)장치 자세 검사.
- 설치하기[사이트맵](/workers/wrangler/install-and-update/)당신의 국부적으로 기계에.

## 1. 노동자 만들기

1. 새로운 Workers 프로젝트 만들기:

   <PackageManagers type="create" pkg="cloudflare@latest" args={"device-posture-worker"} />

   <Render
     file="c3-post-run-steps"
     product="workers"
     params={{
     		category: "hello-world",
     		type: "Worker only",
     		lang: "JavaScript",
     	}}
   />

2. 프로젝트 디렉토리로 변경:

   ```sh
   $ cd device-posture-worker
   ```

3. 다음 코드를 복사`src/index.js`. 교체해야 합니다`<your-team-name>`Zero Trust로<GlossaryTooltip term="team name">팀 이름</GlossaryTooltip>.

   ```js title="index.js"
   import { parse } from "cookie";
   export default {
   	async fetch(request, env, ctx) {
   		//쿠키의 이름
   		const COOKIE_NAME = "CF_Authorization";
   		const CF_GET_IDENTITY =
   			"https://<your-team-name>.cloudflareaccess.com/cdn-cgi/access/get-identity";
   		const cookie = parse(request.headers.get("Cookie") || "");
   		if (cookie[COOKIE_NAME] != null) {
   			try {
   				let id = await (await fetch(CF_GET_IDENTITY, request)).json();
   				let diskEncryptionStatus = false;
   				let firewallStatus = false;

   				for (const checkId in id.devicePosture) {
   					const check = id.devicePosture[checkId];
   					if (check.type === "disk_encryption") {
   						console.log(check.type);
   						diskEncryptionStatus = check.success;
   					}
   					if (check.type === "firewall") {
   						console.log(check.type);
   						firewallStatus = check.success;
   						break;
   					}
   				}
   				//clone 요청 (즉시) 및 새로운 헤더 설정의 자세 값을 삽입
   				let newRequest = await new Request(request);
   				newRequest.headers.set(
   					"Cf-Access-Firewall-Activated",
   					firewallStatus,
   				);
   				newRequest.headers.set("Cf-Access-Disk-Encrypted", firewallStatus);

   				//관련 링크
   				return await fetch(newRequest);
   			} catch (e) {
   				console.log(e);
   				return await fetch(request);
   			}
   		}
   		return await fetch(request);
   	},
   };
   ```

## 4. 노동자를 배포

```sh
npx wrangler deploy
```
