## Cloudflare 구성 오시는 길

MongoDB 배포에 연결할 수 있는 Cloudflare Access의 규칙을 구축할 수 있습니다. 사이트맵 액세스 규칙은 호스트 이름 주위에 내장; 심지어이 배포는 SSH에 액세스 할 수 있지만, 리소스는 Cloudflare에서 호스트 이름으로 표시됩니다. 예를 들어, 웹 사이트가있는 경우`app.com`Cloudflare 계정에서 안전한 규칙을 구축 할 수 있습니다.`mongodb.app.com`.

1. 내 계정[사이트맵 한국어](https://one.dash.cloudflare.com/), 이동**액세스 제어** > **이름 \***.

2. 제품정보**앱 추가**.

3. 제품정보**셀프 호스팅**.

4. 신청에 대한 이름 입력.

5. 제품정보**공공 hostname 추가**그리고 사용자가 배포에 연결되는 하위 도메인을 입력합니다 (예를 들어,`mongodb.app.com`).

6. 더 보기[오시는 길](/cloudflare-one/access-controls/policies/)배포에 도달 할 수있는 제어. 조직 내에서 누구나 연결하거나 연결할 수 있는 정책을 구축할 수 있습니다. 정체 공급자 그룹과 같은 신호를 기반으로 한 더 많은 과립 정책을 구축할 수 있습니다.[multifactor 방법](/cloudflare-one/tutorials/okta-u2f/), 또는[이름 \*](/cloudflare-one/access-controls/policies/groups/).

7. 자주 묻는 질문[자체 호스팅 응용 프로그램 생성 단계](/cloudflare-one/access-controls/applications/http-apps/self-hosted-public-app/)앱을 게시합니다.

## Kubernetes 배포 구성

SSH에 접근하려면 Kubernetes 배포는 MongoDB 독립 서비스와 SSH 프록시 서비스를 모두 관리해야 합니다. 아래 구성은 포트 27017에서 사용할 수있는 데이터베이스 서비스 1 복제뿐만 아니라 포트 22에서 SSH 프록시를 배치합니다.

<Details header="StatefulSet 구성">
  ```yaml
  apiVersion: apps/v1
  kind: StatefulSet
  metadata:
    name: mongodb-standalone
    namespace: mongodb
  spec:
    serviceName: database
    replicas: 1
    selector:
      matchLabels:
        app: database
    template:
      metadata:
        labels:
          app: database
          selector: mongodb-standalone
      spec:
        containers:
          - name: mongodb-standalone
            image: mongo
            command: ["mongod"]
            args: ["--config=/config/mongod.conf"]
            ports:
              - containerPort: 27017
                protocol: TCP
                name: mongod
            volumeMounts:
              - name: mongodb-conf
                mountPath: /config
                readOnly: true
              - name: mongodb-data
                mountPath: /data/db
              - name: tls
                mountPath: /etc/tls
              - name: mongodb-socket
                mountPath: /socket
          - name: ssh-proxy
            image: ubuntu:20.04
            command: ["/scripts/entrypoint.sh"]
            ports:
              - containerPort: 22
                protocol: TCP
                name: ssh-port
            volumeMounts:
              - name: mongodb-socket
                mountPath: /socket
              - name: scripts
                mountPath: /scripts
                readOnly: true
              - name: ssh-authorized-keys
                mountPath: /config/ssh
                readOnly: true
            resources:
              requests:
                cpu: 20m
                memory: 32Mi
        volumes:
          - name: mongodb-socket
            emptyDir: {}
          - name: mongodb-conf
            configMap:
              name: mongodb-standalone
              items:
                - key: mongod.conf
                  path: mongod.conf
          - name: tls
            secret:
              secretName: tls
          - name: mongodb-data
            persistentVolumeClaim:
              claimName: mongodb-standalone
          - name: scripts
            configMap:
              name: scripts
              items:
                - key: entrypoint.sh
                  path: entrypoint.sh
                  mode: 0744
          - name: ssh-authorized-keys
            configMap:
              name: ssh-proxy-config
              items:
                - key: authorized_keys
                  path: authorized_keys
                  mode: 0400
  ```
</Details>

해당 서비스 정의는 컨테이너의 포트 및 대상 포트를 지정해야합니다 (이 경우, 데이터베이스 서비스 및 SSH 프록시 서비스).

<Details header="서비스 정의">
  ```yaml
  apiVersion: v1
  kind: Service
  metadata:
    name: database
    namespace: mongodb
    labels:
      app: database
  spec:
    clusterIP: None
    selector:
      app: database
    ports:
      - protocol: TCP
        port: 27017
        targetPort: 27017
  ---
  apiVersion: v1
  kind: Service
  metadata:
    name: ssh-proxy
    namespace: mongodb
    labels:
      app: database
  spec:
    selector:
      app: database
    ports:
      - protocol: TCP
        port: 22
        targetPort: 22
  ```
</Details>

MongoDB pod 및 SSH 점프 호스트는 빈 디렉토리 볼륨에 유닉스 소켓을 공유합니다. 더 보기`entrypoint.sh`점프 호스트에 의해 실행, 아래 예제, OpenSSH 서버를 시작합니다.

```bash
#!/bin/sh
export TZ=America/Chicago
ln -snf /usr/share/zoneinfo/$TZ /etc/localtime && echo $TZ > /etc/timezone
apt-get update -y && apt-get install -y openssh-server
mkdir /root/.ssh
cp /config/ssh/authorized_keys /root/.ssh/authorized_keys
chmod 400 /root/.ssh/authorized_keys
service ssh start
while true;
do sleep 30;
done;
```

### Cloudflare 구성 관련 제품

아래 구성은 단일 복제를 실행합니다.`cloudflared`MongoDB 및 SSH 프록시 서비스와 함께 진입 지점으로.`cloudflared`SSH 프록시 서비스에 프록시 트래픽. 더 보기`cloudflared`인스턴스는 다른 네임스페이스에서 자체 배포로 실행되며, 네트워크 정책이 허용되면 쿠버네티스 노드의 모든 서비스에 진입합니다.

## 고객의 연결

배포되면 실행할 수 있습니다.`cloudflared`MongoDB 배포에 연결하는 클라이언트 측에. SSH 구성 파일에 다음 줄을 추가하면 호스트 이름과 세부 사항과 예를 교체합니다. 더 보기`--destination`값은 이전에 형성된 SSH 프록시 서비스의 URL과 일치해야 합니다.

```bash
Host mongodb
  ProxyCommand /usr/local/bin/cloudflared access ssh --hostname mongodb.widgetcorp.tech --destination ssh-proxy.mongodb.svc.cluster.local:22
  LocalForward 27000 /socket/mongodb-27017.sock
  User root
  IdentityFile /Users/username/.ssh/id_rsa
```

한 번의 단계입니다. SSH 연결을 배포 할 때,`cloudflared`브라우저 창을 실행하고 인증하기 위해 프롬프트합니다. 인증되면 유효한 세션이 있으면 연결됩니다. 터널이 설치되면 모든 요청을`localhost:27000`당신의 기계에 전달될 것입니다`/socket/mongodb-27017.sock`SSH 프록시 컨테이너에.

MongoDB Compass를 설정할 수 있습니다.`localhost:27000`.
