Cloudflare Access를 사용하여 Zero Trust 규칙을 GitLab의 자체 호스팅 인스턴스에 추가할 수 있습니다. Cloudflare와 결합 터널, 사용자는 HTTP 및 SSH를 통해 연결하고 팀의 정체성 공급자와 정통 할 수 있습니다.

**이 walkthrough는 방법을 포함합니다:**

- GitLab의 인스턴스 배포
- 그 인스턴스에 모든 인바운드 연결을 잠금하고 Cloudflare 터널을 사용하여 Cloudflare에 아웃바운드 연결을 설정
- Cloudflare와 정책 구축 GitLab에 도달 할 수있는 제어 액세스
- Cloudflare를 통해 HTTP 및 SSH에 연결

**완료 시간:**

1시간

## GitLab 배포

이 섹션은 DigitalOcean에서 GitLab 배포를 통해 도보. 이미 GitLab을 배포 한 경우이 섹션을 건너뛸 수 있습니다.

RAM 및 6 CPU의 16 GB의 드롭 스테이션을 만듭니다. 500명의 사용자를 지원할 수 있어야 합니다.[GitLab의 리소스 권장 사항](https://docs.gitlab.com/ee/install/requirements.html).

![비밀번호](~/assets/images/cloudflare-one/zero-trust-security/gitlab/create-droplet.png)

GitLab은 인터넷에 노출되는 외부 IP를 제공합니다 (지금). 초기 구성을 위한 외부 IP를 사용하여 배포된 서버에 연결해야 합니다. IP로 연결할 수 있습니다.[SSH 키 추가](https://www.digitalocean.com/community/tutorials/how-to-set-up-ssh-keys--2)DigitalOcean 계정으로.

이 예제는 macOS 기계를 사용하여 Droplet을 구성합니다. DigitalOcean에서 기계에 할당 된 IP 주소를 복사하십시오.

![기계 IP](~/assets/images/cloudflare-one/zero-trust-security/gitlab/show-ip.png)

## Zero Trust 규칙을 가진 Securing GitLab

### Zero Trust 정책 구축

Cloudflare Access를 사용하여 Zero Trust 규칙을 구축하여 GitLab (HTTP)의 웹 응용 프로그램에 연결할 수 있으며 SSH에 연결할 수 있습니다.

사용자가 액세스에 의해 보호 된 사이트에 요청을 할 때, 그 요청은 Cloudflare의 네트워크 먼저 히트. 액세스는 다음 사용자가 응용 프로그램에 도달 할 수 있는지 확인 할 수 있습니다. Cloudflare 터널과 통합되면 Zero Trust 아키텍처는 다음과 같습니다.

![GitLab 서비스](~/assets/images/cloudflare-one/zero-trust-security/gitlab/teams-diagram.png)

애플리케이션에 도달 할 수있는 사람들을 결정하기 위해 Cloudflare Access는 Okta, Microsoft Entra ID 또는 Google과 같은 정체성 공급자와 통합하여 문에서 확인되는 ID 카드를 발급합니다. VPN은 사용자가 개인 네트워크에 무료 범위를 허용하지만 누군가가 활성화 된 규칙을 구축하고 액세스는 모든 요청에 대한 정체성 검사를 시행합니다 (및 구성 된 모든 과립성에서).

GitLab의 경우, 두 개의 정책을 구축하여 시작합니다. 사용자는 몇 가지 방법으로 GitLab에 연결됩니다. 웹 앱과 SSH 이상. 각각의 하위 도메인을 확보하는 정책을 작성합니다. 첫째, 웹 앱.

### Cloudflare에 연결

이제 Cloudflare 터널을 사용하여 GitLab을 Cloudflare에 연결할 수 있습니다.

1. 다음 명령을 실행하여 새로운 터널을 만듭니다.

```sh
cloudflared tunnel create gitlab
```

`cloudflared`이 터널의 고유 ID를 생성합니다. 예를 들어`6ff42ae2-765d-4adf-8112-31c55c1551ef`. SSH와 HTTP 트래픽을 모두 사용할 수 있습니다.

2. Cloudflare 터널을 두 목적지로 프록시 트래픽을 구성해야 합니다. 아래 구성은 웹 앱과 DNS 레코드를 위해 생성되는 DNS 레코드에 대한 트래픽을 우회합니다.

구성 파일을 편집 할 수있는 선택의 텍스트 편집기를 사용합니다. 예를 들어,`Vi`.

```sh
vim ~/.cloudflared/config.yml
```

3. 교통을 제공하는 터널을 구성합니다.

```yml
tunnel: 6ff42ae2-765d-4adf-8112-31c55c1551ef
credentials-file: /root/.cloudflared/6ff42ae2-765d-4adf-8112-31c55c1551ef.json

ingress:
  - hostname: gitlab.widgetcorp.tech
    service: http://localhost:80
  - hostname: gitlab-ssh.widgetcorp.tech
    service: ssh://localhost:22
  #Catch-all 규칙은 트래픽이 어떤 일치하지 않는 경우 404로 만 응답합니다.
  #이전 규칙
  - service: http_status:404
```

![공유하기](~/assets/images/cloudflare-one/zero-trust-security/gitlab/config-file.png)

4. 구성 파일이 다음과 같이 올바르게 설정되도록 테스트 할 수 있습니다.

```sh
cloudflared tunnel ingress validate
```

`cloudflared`터널을 표시해야합니다. 터널을 실행할 수 있습니다.

```sh
cloudflared tunnel run
```

![터널 실행](~/assets/images/cloudflare-one/zero-trust-security/gitlab/tunnel-run.png)

:::참조

이 명령은 실행되어야한다.`systemd`장기 사용을 위한 서비스; 그것이 종결되면, GitLab는 사용할 수 없습니다.

### SSH 구성

SSH 이상 푸시 및 풀 코드하려면 설치해야합니다.`cloudflared`클라이언트 기계 뿐 아니라. 이 예제는 macOS 노트북을 사용합니다. macOS에서 설치할 수 있습니다.`cloudflared`다음 명령으로.

```sh
brew install cloudflared
```

설치해야 하는 이유`cloudflared`, 당신은 어떤 독특한 방법으로 SSH 명령을 포장 할 필요가 없습니다. 대신 SSH 구성 파일에 한 번의 변경을해야합니다.

```sh
vim /Users/samrhea/.ssh/config
```

다음 값을 입력; 교체`gitlab-ssh.widgetcorp.tech`만든 호스트 이름과 함께.

```txt
Host gitlab-ssh.widgetcorp.tech
  ProxyCommand /usr/local/bin/cloudflared access ssh --hostname %h
```

이제 SSH 흐름을 테스트할 수 있습니다.

```sh
git clone git@gitlab-ssh.widgetcorp.tech:samrhea/demo
```

`cloudflared`이 웹 사이트는 애플 리케이션에 전념. 우리는 정품 앱과 게임을 제공 할 목적으로이 사이트를 만들었습니다. 4AppsApk 최고의 안드로이드 애플 리케이션을위한 무료 APK 파일 다운로드 서비스, 계략.

## 로그아웃

허용하고 차단 된 이벤트의 로그도 볼 수 있습니다. 자주 묻는 질문`Access`페이지의`Logs`Zero Trust에 있는 단면도.

## 문제 해결

Git Large File Storage (LFS)를 사용하는 경우 Git LFS가 자동으로 지원되지 않습니다.`cloudflared`. Cloudflare Access에 의해 보호 된 저장소에 액세스하려면, 실행하여 수동으로 인증해야합니다 :

```sh
cloudflared access login <your-git-access-url>
```

기타 제품`<your-git-access-url>`Cloudflare 액세스 보호 URL.
