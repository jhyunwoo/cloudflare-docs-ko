Cloudflare는 추가 구성 또는 하드웨어를 필요로하지 않고 모든 도메인에서 IPv6를 활성화합니다 (당신의 호스트가 IPv6 지원을 제공합니다).

IPv6 호환성이 켜지면 Cloudflare 자동 생성[`AAAA`DNS 레코드](/dns/manage-dns-records/reference/dns-record-types/#a-and-aaaa)IPv6 클라이언트를 연결할 수 있습니다. 다른 한편, IPv6 호환성이 꺼지면 Cloudflare는 자동으로 생성하고 광고하지 않습니다.`AAAA`영역의 DNS. 클라이언트 소프트웨어는 IPv4 또는 IPv6를 사용하여 두 가지 방법을 지원하는 호스트 이름에 연결 여부를 결정합니다.

제품 정보[DNS 레코드](/dns/proxy-status/)IPv6 및 IPv4 근원 주소를 모두 가지고 있는 Cloudflare는 당신의 근원 서버에 연결할 때 IPv4 주소를 선호할 것입니다.

## Enable IPv6 호환성

기본적으로 IPv6 호환성은 도메인에 켜져 있으며 모든 도메인 및 하위 도메인에 적용됩니다.[DNS 레코드](/dns/proxy-status/).

:::참조
Cloudflare에 가입하면[Cloudflare 호스팅 파트너](http://www.cloudflare.com/hosting-partners)또는 사용[부분 설정](/dns/zone-setups/partial-setup/), IPv6 호환성은 apex 도메인에 적용되지 않습니다.

## IPv6 호환성 사용

원래 웹 서버가 IPv4 포맷 된 IP 주소를 이해한다면, non-Enterprise 고객은해야합니다[지원하다**Pseudo의 IPv4**](/network/pseudo-ipv4/).

또는 엔터프라이즈 계정이있는 고객은 Cloudflare의 IPv6 호환성을 비활성화 할 수 있습니다.

  </TabItem>

:::참조

IPv6가 비활성화되면 도메인은 여전히 IPv6 트래픽을받을 수 있습니다 (예를 들어 Tor 네트워크를 통해). 완전히 모든 IPv6 트래픽을 비활성화하려면:

- 공지사항[**회사소개**](/network/onion-routing/).
- 지원하다[WAF 사용자 정의 규칙](/waf/custom-rules/create-dashboard/)관련 기사`0:0:0:0:0:0:0:0/0`상태 사용`ip.src in {::/0}`.
- 더 보기`and cf.worker.upstream_zone == ""`Workers subrequests를 막기 위하여 위에 규칙에. Workers subrequests는 IPv6 주소를 사용하며 요청이 Worker 스크립트에서 제공되지 않습니다. 더 많은 정보를 원하시면, 참조[`cf.worker.upstream_zone`](/ruleset-engine/rules-language/fields/reference/cf.worker.upstream_zone/)관련 문서

:::
