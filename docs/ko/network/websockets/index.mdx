Cloudflare는 추가 윤곽 없이 proxied WebSocket 연결을 지원합니다.

## 이름 \*

WebSockets는 클라이언트와 Origin 서버 사이에 지속적으로 연결됩니다. WebSockets 연결 안쪽에 클라이언트와 근원은 세션을 설치하지 않고 데이터를 다시 통과할 수 있습니다. WebSockets 연결에서 데이터를 빠르게 교환합니다. WebSockets는 종종 실시간 채팅 및 게임과 같은 응용 프로그램에 사용됩니다.

## 요청 및 대역폭 측정

WebSocket 연결의 성격을 감안하면 요청과 대역폭 사용 측면에서 전형적인 HTTP 트래픽과 다를 수 있습니다. 엔터프라이즈 고객이라면 Cloudflare 측정 요청 및 대역폭을 정확하게 견적하는 것이 중요합니다.

Cloudflare는 다음 방법으로 단일 WebSocket 연결을 측정합니다.

- **제품정보**: Cloudflare는 HTTP 요청으로 WebSocket 연결 당 초기 업그레이드 요청만 인식합니다. WebSocket 연결을 통해 양방향 메시지 스트림을 보낼 수 있지만 단일 긴 수명 HTTP 요청으로 계산됩니다.

- **대역폭**: Cloudflare는 클라이언트에게 Cloudflare에서 보내진 자료 이동을 측정합니다. 이것은 일반적으로 Cloudflare 뒤에 WebSocket 서버에서 WebSocket 클라이언트가 대역폭 사용으로 계산되는 것을 의미합니다.

WebSocket 연결이 닫히면 웹소켓 사용을 통해 집계된 WebSocket 사용을 볼 수 있습니다.[트래픽 분석](/analytics/account-and-zone-analytics/zone-analytics/#traffic)·[GraphQL 분석 API](/analytics/graphql-api/)·[HTTP 요청 로그](/logs/logpush/logpush-job/datasets/zone/http_requests/).

## 기술 노트

Cloudflare가 글로벌 네트워크에 새로운 코드를 출시 할 때 WebSockets 연결을 종료하는 서버를 다시 시작할 수 있습니다.

### 좋은 관행

- 지원하다[관련 기사](https://developer.mozilla.org/en-US/docs/Web/API/WebSockets_API/Writing_WebSocket_servers#pings_and_pongs_the_heartbeat_of_websockets).
- 검토 및 제거 또는 클라이언트의 기원 및 / 또는에 타임 아웃 설정.

최소한의 도구로 단일 URL에 대한 문제점을 재현할 수 있습니다.
