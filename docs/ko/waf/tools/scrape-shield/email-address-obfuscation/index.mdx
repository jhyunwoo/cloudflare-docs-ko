Cloudflare Email Address Obfuscation을 활성화함으로써 웹 페이지의 이메일 주소는 봇에서 숨겨지어 인간에게 볼 수 있습니다. 사실, 방문자를위한 웹 사이트에 눈에 띄는 변화가 없습니다.

## 이름 \*

이메일 수확기 및 기타 봇은 이메일 주소를 찾는 인터넷을 통해 스팸 대상 수신자에게 추가 할 수 있습니다. 원치 않는 이메일의 증가량에 이 추세 결과.

웹 관리자는 이메일 주소를 작성하여이에 대해 보호하기 위해 clever로 올랐습니다.`help [at] cloudflare [dot] com`또는 이메일 주소의 임베디드 이미지를 사용하여. 그러나 이메일 주소를 클릭하여 자동적으로 이메일을 보내주십시오. Cloudflare Email Address Obfuscation을 활성화함으로써 웹 페이지의 이메일 주소는 봇에서 (숨겨진) 을 차단하고 인간에게 눈에 띄는 것을 계속합니다. 사실, 방문자를위한 웹 사이트에 눈에 띄는 변화가 없습니다.

## 어떻게 작동합니까?

Email Address Obfuscation이 활성화되면 Cloudflare는 링크와 같은 HTML에서 눈에 보이는 이메일 주소를 대체합니다.`[email protected]`. 방문자가이 obfuscated 형식을 볼 경우, 그들은 실제 이메일 주소를 공개 할 수있는 링크를 클릭 할 수 있습니다. 이 접근법은 실제 사용자에게 접근할 수 있는 동안 이메일 주소를 스크랩에서 봇을 방지합니다.

## 손상된 이메일에서 Cloudflare 방지

특정 이메일 주소를 손상으로부터 Cloudflare를 방지하려면 다음을 할 수 있습니다.

- 페이지 HTML 코드에 다음 의견 추가:

  ```html
  <!--이메일 off-->contact@example.com<!--/이메일 off-->
  ```

- AJAX 통화용 JSON 형식의 이메일 주소를 반환하면 웹 서버가 콘텐츠 유형을 반환합니다.`application/json`.

- 이메일 장애 기능 비활성화[구성 규칙](/rules/configuration-rules/)특정 엔드포인트에 적용할 수 있습니다.

***

## 이메일 obfuscation

예기치 않은 웹 사이트 행동을 방지하려면 이메일 주소가 잘못되지 않습니다.

- 어떤 HTML 태그 속성, 제외`href`의 속성`a`태그.
- 다른 HTML 태그:
  - `<script></script>`
  - `<noscript></noscript>`
  - `<textarea></textarea>`
  - `<xmp></xmp>`
  - `<head></head>`
- MIME 유형이 없는 페이지`text/html`또는`application/xhtml+xml`.

:::주\[주]

- 이메일 의무는 다음과 같은 경우에 적용되지 않습니다:
  - 당신은 사용`Cache-Control: no-transform`헤더.
  - HTML/JavaScript 코드는 특별히 추가됩니다.[작업자](/workers/).
- Email Obfuscation은 HTML 페이지가 포함될 때 예상대로 작동하지 않을 수 있습니다.`<template></template>`태그.

:::
