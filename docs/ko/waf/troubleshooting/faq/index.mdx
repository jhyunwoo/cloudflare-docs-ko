## 일반 질문

### 왜 보안 이벤트가 Cloudflare IP 주소가 다른 필드가 클라이언트 세부 사항과 일치합니까?

Cloudflare Worker를 통해 요청이 진행될 때 발생합니다.

이 경우 Cloudflare는 IP 주소를 포함하여 클라이언트 세부 사항을 고려하여 보안 설정을 트리거합니다. 그러나 표시된 IP[보안 이벤트](/waf/analytics/security-events/)Cloudflare IP 주소가 될 것입니다.

### 특정 문자를 표현할 필요가 있습니까?

네, 특정 문자를 표현할 수 있습니다. 정확한 escaping은 문자열 문법에 따라 달라집니다.

- 원시 문자열 구문을 사용하는 경우 (예를 들어,`r#"this is a string"#`), 정규 표현식의 특별한 의미를 가지고있는 문자를 탈출해야합니다.
- 인용 문자열 구문을 사용하는 경우 (예를 들어,`"this is a string"`), 당신은 특별한 문자를 escaping와 같은 추가 escaping를 실행할 필요가 있습니다`"`·`\`이름 \*`\"`·`\\`, 리터 문자열과 일반 표현에서 모두.

문자열 구문 및 escaping에 대한 자세한 내용은 참조[문자열 값과 일반 표현](/ruleset-engine/rules-language/values/#string-values-and-regular-expressions).

### 왜 정규식 패턴이 작동하지 않습니까?

정규 표현식을 사용하는 경우, 같은 도구로 테스트하는 것이 좋습니다.[정규 표현 101](https://regex101.com/?flavor=rust\&regex=)또는[Rustexp의 장점](https://rustexp.lpil.uk).

### 왜 예외를 만들지 못했을 때 몇 가지 규칙이 있습니까?

당신은[SSL/TLS 인증서](/ssl/)Cloudflare에 의해 관리되는, 매번 인증서는 발행되거나 갱신됩니다,[도메인 관리 검증 (DCV)](/ssl/edge-certificates/changing-dcv-method/dcv-flow/)자주 묻는 질문 인증서가 있을 때`pending_validation`국가 및 장소에서 유효한 DCV 토큰, 몇몇 Cloudflare 안전 특징[주문 규칙](/waf/custom-rules/)·[관리 규칙](/waf/managed-rules/)특정 DCV 경로에 자동으로 비활성화됩니다 (예를 들어,`/.well-known/pki-validation/`·`/.well-known/acme-challenge/`).

이 자동적인 우회는 안으로 나타나지 않습니다[제품 정보](/rules/trace-request/)결과.

### 왜 차단되었습니까?

Cloudflare는 안전할 수 없는 활동을 감지할 때 요청을 차단할 수 있습니다. 일반적인 이유는 다음과 같습니다 :

- 악성 트래픽, DDoS 공격, 기타 위협에 대한 보안 보호.
- 짧은 시간에 과도한 요청 (한도 제한).
- Bot-like 또는 자동화된 트래픽.
- IP 주소는 공공 블록리스트에 나열되어 있습니다.[프로젝트 꿀 냄비](https://projecthoneypot.org/).

사이트 방문자:

- 사이트 소유자에게 블록이 발생했을 때, Cloudflare Ray ID가 오류 페이지의 하단에 표시됩니다.
- 의심스러운 입력 또는 자동화된 스크립트를 피하십시오.
- 당신의 IP 명성을 검사하십시오[프로젝트 꿀 냄비](https://projecthoneypot.org/).

사이트 소유자 인 경우 :

- 보안 설정은 접근성을 준수합니다.
- Cloudflare 대시보드에서 차단된 요청을 모니터링 합니다.
- Allowlist 신뢰할 수있는 IP 또는 미세 톤 WAF / 봇 규칙은 거짓 긍정을 줄이기 위해.

:::참조
ISP 수준 블록은 Cloudflare 또는 사이트 소유자 보안 제한과 구별됩니다. 자주 묻는 질문[Cloudflare IP 주소 차단](/support/troubleshooting/general-troubleshooting/potential-isp-blocking/).
:::

## 로그아웃

### WAF는 어떻게 알려진 봇에서 트래픽을 처리합니까?

#### 잠재적으로 봇 차단에 대한 주의

사용자 정의 규칙을 만들 때*제품정보*, *비동기 도전*, *관리 도전*, 또는*대화 도전*행동, 당신은 unintentionally는 알려진 봇에서 트래픽을 차단 할 수 있습니다. 특히, 이것은 URI, 경로, 호스트, ASN, 또는 국가를 기반으로 완화 작업을 수행 할 때 검색 엔진 최적화 (SEO) 및 웹 사이트 모니터링에 영향을 줄 수 있습니다.

더 알아보기[문서 작성](/cloudflare-challenges/troubleshooting/#allowlist-traffic-from-mitigation-actions)더 많은 정보.

#### 현재 검색

[Cloudflare 레이더](https://radar.cloudflare.com/verified-bots)이름 \***제품 설명**WAF가 현재 감지하는 알려진 봇. 트래픽이 이 봇과 다른 사람이 나열되지 않을 때,`cf.client.bot`필드 설정`true`.

확인하기 위해 친절한 봇을 제출하려면[**검증된 봇**](https://radar.cloudflare.com/traffic/verified-bots)Cloudflare 레이더의 페이지와 선택**봇 추가**.

확인된 봇에 대한 자세한 내용은 참조[로그아웃](/bots/concepts/bot/).

:::참조

알려진 봇과 검증된 기능 차이는 없습니다. 그러나 알려진 봇 필드 (`cf.client.bot`)는 모든 고객을 위해 유효합니다, 확인한 bots 분야 (`cf.bot_management.verified_bot`)는 기업 고객을 위해 유효합니다.
