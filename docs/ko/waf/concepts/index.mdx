웹 애플리케이션 방화벽 또는 WAF는 웹 앱과 인터넷 사이에 방패를 만듭니다. 이 방패는 많은 일반적인 공격을 완화할 수 있습니다. 더 철저한 정의를 위해, 참조[Web Application 방화벽 설명](https://www.cloudflare.com/learning/ddos/glossary/web-application-firewall-waf/)학습 센터에서.

## 규칙 및 규칙

·[으로](/ruleset-engine/about/rules/)필터를 정의하고 필터와 일치하는 수신 요청에 수행 할 작업.

·[이름 \*](/ruleset-engine/about/rulesets/)Cloudflare 글로벌 네트워크의 트래픽에 적용 할 수있는 규칙의 주문 세트입니다.

## 주요 성분

Cloudflare WAF는 다음을 포함합니다:

- [관리 규칙](/waf/managed-rules/)(예를 들어,[Cloudflare 관리되는 통치자](/waf/managed-rules/reference/cloudflare-managed-ruleset/)) Cloudflare에 의해 생성 된 서명 기반 규칙은 알려진 공격에 대한 즉각적인 보호를 제공합니다.
- [교통 감지](/waf/detections/)(예를 들어, 봇 점수 및 공격 점수)는 metadata와 함께 요청을 풍부하게합니다.
- 사용자 정의 규칙은 다음과 같습니다.[주문 규칙](/waf/custom-rules/)·<GlossaryTooltip term="rate limiting" link="/waf/rate-limiting-rules/">비율 제한 규칙</GlossaryTooltip>.

## 탐지 versus mitigation

Cloudflare WAF의 두 가지 주요 역할은 다음과 같습니다.

- **제품정보**: 한 개 이상의 요청을 실행[교통 감지](/waf/detections/)악성 또는 잠재적으로 악의적 인 활동을 찾을 수 있습니다. 활성화된 탐지의 점수는 유효합니다[보안 Analytics](/waf/analytics/security-analytics/)대시보드, 보안 자세를 분석하고 가장 적합한 완화 규칙을 결정할 수 있습니다.

- **법적고지**: 블록, 도전, 또는 다른 완화 기능을 통해 throttles 요청[주문 규칙](/waf/custom-rules/), [관리 규칙](/waf/managed-rules/)·[비율 제한 규칙](/waf/rate-limiting-rules/). 트래픽을 완화하는 규칙은 해당 표현의 트래픽 검사에서 해당 표현의 점수를 포함 할 수 있습니다.

:::카트로션\[Warning]
트래픽 감지는 들어오는 트래픽에 대한 완화 조치를 적용하지 않습니다. 탐지는 공격 완화 전략을 정의하는 데 사용할 수있는 신호를 제공합니다.
주요 특징

### 사용 가능한 교통 감지

WAF는 현재 들어오는 요청에 보안 위협을 찾는 다음 탐지를 제공합니다.

- [**공격 점수**](/waf/detections/attack-score/): 알려진 공격 변형 및 악의적 인 페이로드를 확인합니다. 1 ( 악의적으로)에서 99 ( 악의적으로)의 규모에 대한 점수 트래픽.
- [**새소식**](/waf/detections/leaked-credentials/): data breaches에서 이전에 유출된 credentials (usernames and passwords)에 대한 수신 요청을 스캔합니다.
- [**맛있는 업로드**](/waf/detections/malicious-uploads/): 업로드된 파일과 같은 스캔 콘텐츠 객체, 악성코드와 같은 악성코드.
- [**AI 보안 앱**](/waf/detections/ai-security-for-apps/): 대외국어 모델(LLMs)에 의해 구동되는 서비스를 보호합니다.
- [**봇 점수**](/bots/concepts/bot-score/): 1 (봇처럼)에서 99 (인간처럼) 규모에 대한 트래픽 점수.

Cloudflare 대시보드의 트래픽 감지를 활성화하려면 보안으로 이동**계정 설정**사이트 맵

## 규칙 실행 순서

Cloudflare는 수신 요청을 처리 할 때 다른 유형의 규칙을 평가합니다. 규칙 실행 순서는 다음과 같습니다:

1. [IP 액세스 규칙](/waf/tools/ip-access-rules/)
2. [방화벽 규칙](/firewall/cf-firewall-rules/)(대략)
3. [주문 규칙](/waf/custom-rules/)
4. [비율 제한 규칙](/waf/rate-limiting-rules/)
5. [관리 규칙](/waf/managed-rules/)
6. [사이트맵 비율 제한](/waf/reference/legacy/old-rate-limiting/)(이전 버전, 분해)

규칙은 순서로 평가됩니다. 규칙에 대한 일치가 있다면[용어 정의](/ruleset-engine/rules-language/actions/), 규칙 평가는 중지하고 행동은 즉시 실행됩니다. 비 종료 작업 규칙 (예 :*로그인*)는 평가되고 실행되는 것과 같은 규칙을 방지하지 않을 것입니다. 규칙이 평가되는 방법에 대한 자세한 내용은 참조[규칙 평가](/ruleset-engine/about/rules/#rule-evaluation)Ruleset Engine 문서에서.

각 WAF 기능이 실행되는 단계에 대한 자세한 내용은 참조[WAF 단계](/waf/reference/phases/).
