몇 가지 일반적인 비율 제한 구성 문제 방지 적절한 요청 일치:

- **규칙 패턴의 HTTP 또는 HTTPS 프로토콜 계획 포함**(예 :`https://example.com/*`). HTTP 또는 HTTPS 트래픽 만 일치하는 규칙을 제한하려면 요청 일치의 배열을 사용하십시오. 예를 들어,`"schemes": [ "HTTPS" ]`.
- **트레일 슬래시 문자를 잊어 (droping slash character)`/`)**· Cloudflare 제한 비율은 홈페이지에 대한 요청을 치료합니다 (예 :`example.com`·`example.com/`) 동등으로, 그러나 다른 어떤 경로 (와 같은`example.com/path/`·`example.com/path`). 요청 경로와 트레일 슬래시없이, 와일드 카드 일치 (예를 들어,`example.com/path*`).
- **쿼리 문자열 또는 앵커 포함**(예 :`example.com/path?foo=bar`또는`example.com/path#section1`). 같은 규칙`example.com/path`요청을 일치`example.com/path?foo=bar`.
- **속도 제한을 덮고[IP 접근 규칙](/waf/tools/ip-access-rules/)**.
- **항구 번호를 포함하여**(예 :`example.com:8443/api/`). 제한 속도는 규칙 내에서 포트 번호를 고려하지 않습니다. URL에서 포트 번호를 제거하여 요금 제한 규칙이 예상대로 트리거합니다.

## Common API 오류

다음과 같은 일반적인 오류는 configuring rate limiting Rule을 통해 방지할 수 있습니다.[Cloudflare API를](/api/resources/rate_limits/methods/create/):

- `Decoding is not yet implemented`– 귀하의 요청이 누락 된 표시`Content-Type: application/json`헤더. 문제를 해결하기 위해 API 요청에 헤더를 추가하십시오.
- `Ratelimit.api.not_entitled`– 기업 고객은 규칙을 추가하기 전에 계정 팀에 연락해야합니다.

:::참조
더 보기`origin_traffic`매개변수는 Enterprise 계획에서만 설정할 수 있습니다. 설치하기`"origin_traffic" = false`Free, Pro 또는 Business Domain의 규칙은 자동으로 변환됩니다.`"origin_traffic" = true`.
:::
