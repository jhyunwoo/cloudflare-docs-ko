기본적으로 WAF 관리 규칙은 Cloudflare 대시보드를 통해 완전히 관리되며 대부분의 웹 사이트 및 웹 애플리케이션과 호환됩니다. 그러나, 거짓 긍정과 거짓 부정적인 발생할 수 있습니다:

- **False 긍정적**: Legitimate 요청 감지 및 악의로 필터링.
- **부정 행위**: 맛있는 요청은 필터링되지 않습니다.

## 문제 해결 false 긍정적

의심스러운 내용의 정의는 각 웹 사이트에 적용됩니다. 예를 들어, 웹 사이트에 게시 된 PHP 코드는 일반적으로 의심스러운입니다. 그러나 웹 사이트는 코드가 얼마나 가르치고 방문자로부터 PHP 코드 제출이 필요할 수 있습니다. 이 상황에서, 당신은 정상적인 웹 사이트 운영을 방해하기 때문에이 웹 사이트의 관련 관리 규칙을 비활성화해야합니다.

가짜 긍정적 인 테스트하려면 WAF 관리 규칙을 설정하십시오.*관련 기사*모드. 이 모드는 도전적이지 않고 가능한 공격에 대한 응답을 기록하거나 수신 요청을 차단할 수 있습니다. 또한, Security Events를 검토[샘플 로그](/waf/analytics/security-events/#sampled-logs)거짓 긍정적 인 규칙을 결정하기 위해.

거짓 긍정을 발견한다면, 몇몇 잠재적인 해결책이 있습니다:

- **클라이언트의 IP 주소 추가[IP 액세스 규칙](/waf/tools/ip-access-rules/)수당 :**&#xBE0C;라우저 또는 클라이언트가 같은 IP 주소에서 방문하면 권장됩니다.
- **해당 관리 규칙(s) 비활성화**: 막거나 도전적인 거짓 긍정을 멈추고, 전반적인 사이트 보안을 감소시킵니다. 규칙 ID에 의해 차단 된 요청`981176`OWASP 규칙을 나타냅니다. 문제를 해결하기 위해 OWASP 감도를 결정합니다.
- **Bypass WAF는 방화벽 규칙과 규칙을 관리했습니다.** [방화벽 규칙 만들기](/firewall/cf-dashboard/create-edit-delete-rules/#create-a-firewall-rule)이름 \**비밀번호*매개 변수의 특정 조합에 대한 WAF 관리 규칙을 비활성화하는 작업. 예를 들어,[bypass 관리 규칙](/firewall/cf-firewall-rules/actions/)특정 URL 및 특정 IP 주소 또는 사용자 에이전트에 대 한.
- **(추천하지 않음) WAF는 URL에 트래픽에 대한 규칙을 관리 :**&#xD2B9;정 URL 엔드포인트에 보안을 낮춥니다. 를 통해 구성[페이지 규칙](/rules/page-rules/).

추가 가이드라인은 다음과 같습니다:

- 특정 규칙이 false 긍정적 인 경우, 규칙을 설정**주요 특징**으로*사용 방법*오히려 돌기 보다는*이름 \**&#xC804;체 규칙**이름 \***.
- 웹 사이트의 관리자 섹션과 거짓 긍정적 인 경우, 생성[페이지 규칙](/rules/page-rules/)으로**Disable 보안**사이트 리소스의 관리자 섹션에 대한 — 예를 들어,`example.com/admin`.

## 거짓 부정 행위

false 부정을 식별하려면 웹 서버에서 HTTP 로그를 검토하십시오. 잘못된 부정을 줄이기 위해, 다음 체크리스트를 사용합니다:

- WAF 관리 규칙은**보안 보안** > **사이트맵** > **관리 규칙**?

- WAF 관리 규칙을 통해 비활성화[페이지 규칙](/rules/page-rules/)?

- 모든 관리 규칙이 기본적으로 활성화되어 있으므로 개별 관리 규칙 기본 작업을 검토하십시오.
  - 예를 들어 Cloudflare는 기본으로 빈 사용자 에이전트와 요청할 수 있습니다. 빈 사용자 에이전트와 요청을 차단하려면 규칙을 변경**주요 특징**으로*제품정보*.
  - 또 다른 예: unmitigated SQL injection attacks를 차단하려는 경우 관련 SQLi 규칙을 활성화하고 설정*제품정보*이름 \***Cloudflare 스페셜**그룹.

- Cloudflare를 통해 HTTP 트래픽을 제공 하는 DNS 레코드?

- 방화벽 규칙[관련 기사](/firewall/cf-firewall-rules/actions/#supported-actions)관리 규칙?

- 허용된 국가, ASN, IP 범위, 또는 IP 주소[IP 접근 규칙](/waf/tools/ip-access-rules/)또는[방화벽 규칙](/firewall/cf-firewall-rules/)공격 트래픽 일치?

- Cloudflare 보호를 우회하기 위하여 당신의 근원 IP 주소를 직접 도달하는 악의적인 교통입니까? 모든 트래픽을 차단[Cloudflare의 IP 주소](/fundamentals/concepts/cloudflare-ip-addresses/)웹 서버에서.
