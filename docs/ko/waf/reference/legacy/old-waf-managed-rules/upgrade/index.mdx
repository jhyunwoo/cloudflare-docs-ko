2022-05-04에서 Cloudflare가 업그레이드를 시작했습니다.[WAF 관리 규칙의 이전 버전](/waf/reference/legacy/old-waf-managed-rules/)새 소식[WAF 관리 규칙](/waf/managed-rules/), 자격이 된 영역의 첫 번째 세트를 허용한다. 현재 모든 영역은 파트너 계정을 포함한 WAF 관리 규칙으로 업그레이드 할 수 있습니다.

Cloudflare는 WAF 관리 규칙의 새로운 버전에 점차적으로 격상됩니다. Cloudflare 대시보드 또는 API를 통해 영역에 대한 업그레이드 프로세스를 수동으로 시작할 수 있습니다.**업그레이드가 불가능합니다.**— 새로운 WAF 관리 규칙으로 업그레이드하면 이전 버전으로 돌아갈 수 없습니다.

오래된 대시보드를 사용하는 경우 업그레이드가 완료되면 규칙이 다른 사용자 인터페이스를 사용하여 표시됩니다.**보안 보안** > **사이트맵** > **관리 규칙**탭. 사용중인 경우[새로운 보안 대시보드](/security/), 당신의 격상된 규칙은에서 보일 것입니다**보안 보안** > **보안 규칙**.

또한 WAF 관리 규칙 API는 일단 당신이 격상시키는 것을 중지할 것입니다.

:::caution\[조정안내]

**WAF 관리 규칙의 이전 버전과 관련된 API 및 Terraform 리소스가 나타났습니다.**&#xB354; 보기[WAF 관리 규칙의 이전 버전을 관리하기위한 API](#api-changes)2025-06-15 이후 더 이상 지원되지 않습니다. 동일한 적용[Terraform 자원](#terraform-changes)WAF 관리 규칙의 이전 버전과 관련. 어떤 문제를 피하기 위해 구성을 마이그레이션해야합니다.

더 알아보기[가능한 업그레이드 오류](#possible-upgrade-errors)당신이 업그레이딩 문제를 가지고 있다면.

:::

## 주요 혜택

WAF 관리 규칙의 새로운 버전은 이전 버전의 다음 혜택을 제공합니다:

- **새로운 매칭 엔진**– WAF 관리 규칙은 더 빠른 관리 규칙 배포를 허용하는 Ruleset Engine에 의해 구동되며 스케일링 문제없이 더 많은 트래픽을 확인할 수 있습니다. 규칙은 WAF 사용자 정의 규칙과 같은 다른 Cloudflare 보안 제품에 사용되는 동일한 구문을 따릅니다.

- **업데이트된 관리된 Rulesets**– Cloudflare OWASP Core Ruleset은 WAF의 관리 규칙 세트 중 하나이며, OWASP Core Ruleset (v3.x)의 최신 버전을 기반으로합니다.<GlossaryTooltip term="paranoia level">paranoia 수준</GlossaryTooltip>WAF 관리 규칙 (2.x)에서 사용되는 버전과 비교하여 거짓 긍정적 인 비율을 향상시킵니다. 당신은 또한 감도 점수에 대한 더 많은 제어가, 얼마나 많은 각 규칙이 점수에 기여하고 트리거 된 요청의 총 점수는.

- **더 나은 규칙과 구성**– 단일 클릭으로 Deploy Managed Rulesets를 즉시 보호할 수 있습니다. 전체 규칙의 행동을 강화하거나 단일 규칙을 사용자 정의합니다. 주어진 소프트웨어 또는 공격 벡터에 적용 가능한 규칙을 조정할 수있는 특정 태그와 함께 모든 규칙에 대한 overrides를 적용합니다. 다음과 같은 구성을 배포할 수 있습니다:
  - 모든 영역에서 Cloudflare 관리 규칙 세트 배포.
  - 포함되지 않는 모든 트래픽에 Cloudflare OWASP Core Ruleset 배포`/api/*`길에서.
  - 내 IP에서 오는 트래픽에 대한 내 계정의 관리 규칙을 비활성화합니다.

WAF 관리 규칙의 이점에 대한 자세한 내용은, 참조[블로그 게시물](https://blog.cloudflare.com/new-cloudflare-waf/).

## 향상 충격

당신은 URI 기반 WAF overrides가없는 모든 영역을 업그레이드 할 수 있습니다. 동일한 보호는 새로운 WAF로 이동하면 지역에 적용됩니다.

WAF 관리 규칙의 이전 버전에서 대부분의 구성 설정은 새로운 버전으로 업그레이드되지만 OWASP ModSecurity Core Rule Set에서 정의 된 일부 특정 구성은 손실 될 것입니다. 필요한 경우 새로운 WAF 관리 규칙에 이러한 구성을 생성해야합니다.

API 사용자의 경우 WAF 관리 규칙의 이전 버전을 관리하기위한 API는 업그레이드 한 번 작동 중지합니다. 새로운 WAF 관리 규칙을 관리하기 위해 Rulesets API를 사용해야합니다.

### 업그레이드 될 구성

업그레이드 프로세스는 WAF 관리 규칙의 다음과 같은 설정을 위해 해당 구성을 만들 것입니다:

- 방화벽 규칙*비밀번호* > *WAF 관리 규칙*.
- 페이지 규칙과 구성*Disable 보안*.
- 페이지 규칙과 구성*웹 응용 프로그램 방화벽: 끄기*또는*웹 애플리케이션 방화벽: On*.

OWASP 규칙 설정은 부분적으로 업그레이드됩니다. 자세한 내용은 다음 섹션을 참조하십시오.

### 업그레이드 과정에서 손실되는 구성

업그레이드 프로세스는 부분적으로 WAF 관리 규칙의 이전 버전에서 사용할 수있는 OWASP ModSecurity Core Rule 세트의 설정을 마이그레이션합니다.

다음 OWASP 설정은 마이그레이션됩니다:

- **IR 정보**: 한국어[오래된 감도 값](/waf/reference/legacy/old-waf-managed-rules/#owasp-modsecurity-core-rule-set)다음으로 마이그레이션 될 것입니다[paranoia 수준](/waf/managed-rules/reference/owasp-core-ruleset/concepts/#paranoia-level)(PL) 및[점수 임계 값](/waf/managed-rules/reference/owasp-core-ruleset/concepts/#score-threshold)새로운 OWASP 규칙의 조합:

  | 오래된 감도 | 새로운 OWASP에 PL | 새로운 OWASP의 점수 임계값 |
  | ------ | ------------- | ----------------- |
  | 사이트맵   | 공장 투어         | 중간 – 40 이상        |
  | 한국어    | 공장 투어         | 높은 - 25 이상        |
  | 이름 \*  | 공장 투어         | 중간 – 40 이상        |
  | 기본 정보  | 공장 투어         | 중간 – 40 이상        |

- **- 연혁**: 이전 OWASP 규칙의 행동은 새로운 OWASP 관리 규칙에서 거의 직접 맵핑을 가지고 있습니다.*관련 기사*행동은 migrated*로그인*.

다음 OWASP 설정은**아니다.**&#x32; 버전의 규칙 사이에 직접적인 equivalence가 없기 때문에 마이그레이션 :

- OWASP 그룹 오버라이드
- OWASP 규칙 overrides

이러한 설정을 교체하려면 Cloudflare OWASP Core Ruleset을 WAF Managed Ruleset을 귀하의 필요에 따라 다시 구성해야하며, 어떤 태그/rule overrides를 지정해야 합니다. 새로운 OWASP Core Ruleset 구성에 대한 자세한 내용은 참조[Cloudflare OWASP 핵심 통치자](/waf/managed-rules/reference/owasp-core-ruleset/).

### 업그레이드에서 당신을 방지하는 구성

지역이 있는 경우[URI 기반 WAF overrides](/api/resources/firewall/subresources/waf/subresources/overrides/methods/list/)(API를 통해 사용 가능), WAF 관리 규칙으로 업그레이드 할 수있는 옵션이 없습니다. WAF 관리 규칙으로 업그레이드하려면:

1. 기존의 URI 기반 WAF overrides 삭제[WAF 오버라이드 삭제](/api/resources/firewall/subresources/waf/subresources/overrides/methods/delete/)가동.
2. 아래 설명된 업그레이드 프로세스를 따르십시오.

### Cloudflare 대시보드 변경

업그레이드 프로세스가 완료되면 Cloudflare 대시보드는 규칙을 표시합니다.

- 오래된 대시보드:**보안 보안** > **사이트맵** > **관리 규칙**탭 (다른 사용자 인터페이스 사용)
- 새로운 대시보드:**보안 보안** > **보안 규칙**

오래된 WAF 관리 규칙과는 달리, WAF를 가능하게 하기 위하여 더 이상 세계적인 온/오프 조정이 없습니다. 대신 각 관리 규정을 개별적으로 배포합니다.

WAF 관리 규칙을 Cloudflare 대시보드에 배포하는 방법에 대한 자세한 내용은 참조[WAF를 대시보드에 배포](/waf/managed-rules/deploy-zone-dashboard/).

### API 변경

업그레이드가 완료되면 WAF 관리 규칙과 상호 작용하는 API**일 중지**. 이 APIs는 다음과 같습니다:

- [WAF 패키지](/api/resources/firewall/subresources/waf/subresources/packages/methods/list/)
- [WAF 규칙 그룹](/api/resources/firewall/subresources/waf/subresources/packages/subresources/groups/methods/list/)
- [WAF 규칙](/api/resources/firewall/subresources/waf/subresources/packages/subresources/rules/methods/list/)

:::카트로션
위에 명시된 WAF 관리 규칙 API를 사용하여 어떤 통합이 있는 경우, 새로운 WAF 관리 규칙을 업그레이드하기 전에 업데이트해야 합니다.
주요 특징

WAF 관리 규칙을 사용하려면[규칙 세트 API](/ruleset-engine/managed-rulesets/). API를 통해 WAF 관리 규칙을 배치하는 방법에 대한 자세한 내용은 참조[API를 통해 WAF 관리 규칙 배포 (zone)](/waf/managed-rules/deploy-api/).

### Terraform 변경

업그레이드가 완료되면 WAF 관리 규칙을 구성하기위한 다음 Terraform 리소스**일 중지**:

- [`cloudflare_waf_package`](https://registry.terraform.io/providers/cloudflare/cloudflare/3.35.0/docs/resources/waf_package)
- [`cloudflare_waf_group`](https://registry.terraform.io/providers/cloudflare/cloudflare/3.35.0/docs/resources/waf_group)
- [`cloudflare_waf_rule`](https://registry.terraform.io/providers/cloudflare/cloudflare/3.35.0/docs/resources/waf_rule)

이 리소스는 Terraform Cloudflare 공급자에서 3.35 버전까지만 지원되었습니다. 버전 4.x[더 이상 이러한 리소스 지원](https://registry.terraform.io/providers/cloudflare/cloudflare/latest/docs/guides/version-4-upgrade#resources-1).

새로운 WAF 관리 규칙의 구성을 Terraform을 사용하여 관리하려면 사용해야합니다.[`cloudflare_ruleset`](https://registry.terraform.io/providers/cloudflare/cloudflare/latest/docs/resources/ruleset)자료실

## 업그레이드 시작

WAF 대시보드 또는 API를 통해 WAF 업그레이드를 시작할 수 있습니다.

### 대시보드 사용

1. 로그인하기[Cloudflare 대시보드](https://dash.cloudflare.com/), 귀하의 계정과 영역을 선택.

2. A) 오래된 대시보드를 사용하는 경우:

   - 오시는 길**보안 보안** > **사이트맵** > **관리 규칙**탭.

   B) 사용중인 경우[새로운 보안 대시보드](/security/):

   1. 오시는 길**보안 규칙**사이트 맵

      <DashButton url="/?to=/:account/:zone/security/security-rules" />

   2. 제품정보**관리 규칙을 업그레이드하려면**.

   만약 당신이 기업 고객인 경우에, 대시보드는 뒤에 오는 기치 보여줄 것입니다:

   ![Enterprise 고객에게 표시된 업그레이드 배너.](~/assets/images/waf/reference/waf-migration-ent-banner.png)

   전문 / 비즈니스 고객 인 경우 대시보드는 다음과 같은 배너를 보여줍니다.

   ![Pro/Business 고객에 표시된 업그레이드 배너.](~/assets/images/waf/reference/waf-migration-biz-banner.png)

3. 업그레이드 배너에서, 선택**리뷰 구성**. 이 배너는 해당 영역에서만 표시됩니다.

4. 제안된 WAF 윤곽을 검토하십시오. 구성을 조정할 수 있습니다.[WAF 관리 규칙 구성 편집](/waf/managed-rules/deploy-zone-dashboard/#configure-a-managed-ruleset)또는 창조[옵션 정보](/waf/managed-rules/waf-exceptions/)규칙 또는 특정 규칙의 실행을 건너뛰기 위해.

5. 검토 할 때, 선택**계정 만들기**새로운 WAF 관리 규칙 구성을 배포합니다.

   전문 / 비즈니스 고객이라면 Cloudflare는 새로운 WAF 구성을 배포하고 이전 WAF 버전을 비활성화합니다. 업그레이드 프로세스는 몇 분이 걸릴 수 있습니다.

   기업 고객이라면 두 WAF 구현이 동시에 활성화됩니다.**계정 만들기**, 그래서 당신은 당신의 새로운 윤곽을 유효하게 할 수 있습니다. 추가 지침에 대한 다음 섹션에서 단계를 참조하십시오.

#### 새로운 WAF 구성을 검증하고 업그레이드 완료 (Enterprise customers only)

새로운 WAF 구성을 WAF 구현을 모두 배치 한 후 엔터프라이즈 고객이라면 동시에 활성화됩니다. 이 단계에서 (통합 유효 모드), 당신은 WAF 관리 규칙 Cloudflare 대시보드에서 두 가지 구현에 액세스 할 수 있습니다, 당신은 업그레이드 배너를 표시 할 때까지. 새로운 WAF 관리 규칙은 이전 버전 전에 실행됩니다.

1. 현재 검증 모드를 사용하여 새로운 WAF 구성의 동작을 확인합니다.[보안 이벤트](/waf/analytics/security-events/). 자세한 내용은 참조[보안 이벤트에서 새로운 WAF 행동 분석](#analyzing-the-new-waf-behavior-in-security-events).

2. WAFs와 구성을 검토 할 때, 선택**업데이트**업그레이드 배너에서 다음 선택**이전 버전 오프**. 이 가동은 향상을 완료하고 이전 WAF 버전을 비활성화합니다.

업그레이드가 완료되면 대시보드는 업그레이드 된 규칙을 모두 보여줍니다.

- 오래된 대시보드:**보안 보안** > **사이트맵** > **관리 규칙**이름 \*
- 새로운 대시보드:**보안 보안** > **보안 규칙**

업그레이드가 완료되면 대시보드를 새로 고침하십시오.

:::참조
업그레이드 프로세스는 1 시간까지 걸릴 수 있습니다. 이 기간 동안 WAF 관리 규칙의 두 버전에서 보안 이벤트를 관찰 할 수 있습니다.

## 보안 이벤트에서 새로운 WAF 행동 분석

### 기업 고객

기업 고객이라면,**유효 모드**WAF 업그레이드 프로세스의 새로운 WAF 관리 규칙 구성의 동작을 확인. Cloudflare는 새로운 WAF 구성을 배포한 후 검증 모드를 활성화합니다. 이 모드에서 이전 WAF 버전은 여전히 활성화되므로 업그레이드 과정에서 새로운 구성의 동작을 검증할 수 있습니다. 새로운 WAF 관리 규칙은 이전 버전 전에 실행됩니다.

오시는 길[샘플 로그](/waf/analytics/security-events/#sampled-logs)검증 모드에서 보안 이벤트에서 다음을 확인하십시오:

- 이전 WAF 버전에 의해 처리되는 새로운 WAF에 의해 허용되는 모든 요청을 찾습니다 (예를 들어, 도전 또는 블록 액션에 의해). 이 일이 발생하면, 쓰기를 고려[방화벽 규칙](/firewall/cf-dashboard/create-edit-delete-rules/#create-a-firewall-rule)또는[WAF 사용자 정의 규칙](/waf/custom-rules/create-dashboard/)이전에 확인된 요청을 처리하기 위해.

- 새로운 WAF에 의해 차단 된 합법적 인 요청을 찾습니다. 이 상황에서 WAF 관리 규칙을 편집하여 이러한 요청을 차단하고 수행 된 행동을 변경하거나 규칙을 비활성화합니다. 더 많은 정보를 원하시면, 참조[관리 규칙 구성](/waf/managed-rules/deploy-zone-dashboard/#configure-a-managed-ruleset).

### 사업/Professional 고객을 위해

비즈니스 및 전문 고객은 새로운 WAF 관리 규칙으로 업그레이드 한 후 새로운 WAF 동작을 확인할 수 있다는 것을 의미하는 검증 모드에 액세스 할 수 없습니다.

업그레이드를 따르는 날, 체크[샘플 로그](/waf/analytics/security-events/#sampled-logs)WAF 관리 규정에 의해 차단되는 합법적 인 요청을 찾는 보안 이벤트. 부정확하게 차단된 요청을 식별하면 해당 WAF 규칙 동작을 로그에 조정합니다. 관리 규칙의 행동을 변경하는 방법에 대한 자세한 내용은 참조[관리 규칙의 개별 규칙 구성](/waf/managed-rules/deploy-zone-dashboard/#configure-individual-rules-of-a-managed-ruleset).

또한, 차단된 요청을 확인합니다. 이 상황에서, 만들기를 고려[방화벽 규칙](/firewall/cf-dashboard/create-edit-delete-rules/#create-a-firewall-rule)또는[WAF 사용자 정의 규칙](/waf/custom-rules/create-dashboard/)이 요청을 차단합니다.

#### 설정 바꾸기`cf-terraforming`

당신은 사용할 수 있습니다[`cf-terraforming`](https://github.com/cloudflare/cf-terraforming)새로운 WAF 관리 규칙 구성에 대한 Terraform 구성을 생성하는 도구 업그레이드 후. 그런 다음 Terraform 상태로 새로운 리소스를 가져옵니다.

오래된 WAF를 교체하기위한 권장 단계는 새로운 WAF 관리 규칙에 대한 새로운 규칙 기반 구성과 Terraform의 규칙 구성을 다음과 같습니다.

1. 다음 명령을 실행하여 영역의 모든 규칙 구성을 생성합니다.

   ```sh null {3,6}
   cf-terraforming generate --zone <ZONE_ID> --resource-type "cloudflare_ruleset"
   ```

   ```txt output
   resource "cloudflare_ruleset" "terraform_managed_resource_3c0b456bc2aa443089c5f40f45f51b31" {
     kind    = "zone"
     name    = "default"
     phase   = "http_request_firewall_managed"
     zone_id = "<ZONE_ID>"
     rules {
       [...]
     }
     [...]
   }
   [...]
   ```

2. 이전 명령은 다른 Cloudflare 제품에 대한 추가 규칙 구성을 반환 할 수도 있습니다.[Ruleset 엔진](/ruleset-engine/). WAF 관리 규칙 구성을 찾고 있기 때문에 Terraform 리소스 만 유지하십시오.`http_request_firewall_managed`단계 및 저장 그것 에 a`.tf`구성 파일. 다음 단계에 전체 리소스 이름을 필요로합니다.

3. 구매하기`cloudflare_ruleset`이전에 Terraform state로 확인된 리소스`terraform import`명령. 예를 들면:

   ```sh
   terraform import cloudflare_ruleset.terraform_managed_resource_3c0b456bc2aa443089c5f40f45f51b31 zone/<ZONE_ID>/3c0b456bc2aa443089c5f40f45f51b31
   ```

   ```txt output
    cloudflare_ruleset.terraform_managed_resource_3c0b456bc2aa443089c5f40f45f51b31: Importing from ID "zone/<ZONE_ID>/3c0b456bc2aa443089c5f40f45f51b31"...
    cloudflare_ruleset.terraform_managed_resource_3c0b456bc2aa443089c5f40f45f51b31: Import prepared!
      Prepared cloudflare_ruleset for import
    cloudflare_ruleset.terraform_managed_resource_3c0b456bc2aa443089c5f40f45f51b31: Refreshing state... [id=3c0b456bc2aa443089c5f40f45f51b31]

    Import successful!

    The resources that were imported are shown above. These resources are now in
    your Terraform state and will henceforth be managed by Terraform.
   ```

4. 지원하다`terraform plan`Terraform이 이제 새로운 상태를 확인합니다.`cloudflare_ruleset`다른 기존 리소스 외에도 Terraform이 이미 관리했습니다. 예를 들면:

   ```sh
   terraform plan
   ```

   ```txt output

   cloudflare_ruleset.terraform_managed_resource_3c0b456bc2aa443089c5f40f45f51b31: Refreshing state... [id=3c0b456bc2aa443089c5f40f45f51b31]
   [...]
   cloudflare_waf_package.my_package: Refreshing state... [id=14a2524fd75c419f8d273116815b6349]
   cloudflare_waf_group.my_group: Refreshing state... [id=0580eb5d92e344ddb2374979f74c3ddf]
   [...]
   ```

5. 이전 버전의 WAF 관리 규칙과 관련된 모든 상태를 제거하십시오.

   :::카트로션
   WAF 패키지, 그룹 및 Terraform 상태의 규칙을 제거해야 합니다.`.tf`문제를 방지하기 위해 구성 파일.
   주요 특징

   1. 다음 명령을 실행하여 WAF 관리 규칙의 이전 버전과 관련된 모든 리소스를 찾을 수 있습니다.

      ```sh
      terraform state list | grep -E '^cloudflare_waf_(package|group|rule)\.'
      ```

      ```txt output
      cloudflare_waf_package.my_package
      cloudflare_waf_group.my_group
      ```

   2. 시작하기`terraform state rm ...`건조한 실행 모드에서 명령은 어떤 변경을 수행하지 않고 그 리소스를 제거의 영향을 이해합니다.

      ```sh
      terraform state rm -dry-run cloudflare_waf_package.my_package cloudflare_waf_group.my_group
      ```

      ```txt output
      Would remove cloudflare_waf_package.my_package
      Would remove cloudflare_waf_group.my_group
      ```

   3. 충격이 정확하면 동일한 명령을 실행합니다.`-dry-run`실제로 Terraform 국가의 리소스를 제거하는 매개 변수 :

      ```sh
      terraform state rm cloudflare_waf_package.my_package cloudflare_waf_group.my_group
      ```

      ```txt output
      Removed cloudflare_waf_package.my_package
      Removed cloudflare_waf_group.my_group
      Successfully removed 2 resource instance(s).
      ```

6. WAF 패키지, 그룹 및 Terraform 상태의 규칙 리소스 제거 후 삭제`cloudflare_waf_package`, `cloudflare_waf_group`·`cloudflare_waf_rule`계정 관리`.tf`구성 파일.

7. 지원하다`terraform plan`구성 파일에서 삭제 된 리소스는 더 이상 나타납니다. 당신은 어떤 말썽도 없다.

   ```sh
   terraform plan
   ```

   ```txt output
   cloudflare_ruleset.terraform_managed_resource_3c0b456bc2aa443089c5f40f45f51b31: Refreshing state... [id=3c0b456bc2aa443089c5f40f45f51b31]
   [...]

   No changes. Your infrastructure matches the configuration.

   Terraform has compared your real infrastructure against your configuration and found no differences, so no changes are needed.
   ```

## 최종 알림

의 개념<GlossaryTooltip term="paranoia level">paranoia 수준</GlossaryTooltip>WAF 관리 규칙에서 사용되는 OWASP 버전 (2.x)에 존재하지 않았다. OWASP 가이드 권고를 기반으로 WAF 마이그레이션 프로세스는 Cloudflare OWASP Coreset의 paranoia 수준을 설정합니다.*공장 투어*.

WAF 관리 규칙의 새로운 버전을 비활성화 할 수 없습니다[페이지 규칙](/rules/page-rules/), 이후*웹 응용 프로그램 방화벽: 끄기*페이지 규칙의 설정은 WAF 관리 규칙의 이전 버전에만 적용됩니다. 새로운 WAF 관리 규칙을 비활성화하려면[옵션 정보](/waf/managed-rules/waf-exceptions/)(또한 건너뛰기 규칙).
