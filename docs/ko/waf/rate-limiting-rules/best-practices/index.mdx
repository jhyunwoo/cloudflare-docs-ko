다음과 같은 섹션은 일반적인 사용 사례에 대한 구성을 제한하는 전형적인 비율을 포함합니다. 제공된 예 규칙을 결합하고 자신의 시나리오에 조정할 수 있습니다.

제한 속도의 주요 사용 사례는 다음과 같습니다.

## granular 접근 제한을 위해

### 사용자 에이전트

일반적인 사용 사례는 개별 사용자 에이전트에 의해 수행 된 요청의 비율을 제한하는 것입니다. 다음 예제 규칙은 모바일 앱을 사용하여 최대 100 요청을 10 분 동안 수행 할 수 있습니다. 데스크탑 브라우저의 속도를 제한하는 별도의 규칙을 만들 수도 있습니다.

| 설치하기         | 제품정보                             |
| ------------ | -------------------------------- |
| 일치 기준        | 사용자 에이전트 동일`MobileApp`           |
| 패스워드         | `http.user_agent eq "MobileApp"` |
| 계산 특성        | IP 정보                            |
| 비율 (요구 / 기간) | 100 요청 / 10 분                    |
| - 연혁         | 관리 도전                            |

### 단일의 제한 재사용`cf_clearance`제품 정보

방문자가 성공적으로 관리 된 도전을 통과 한 후, Cloudflare는 문제`cf_clearance`쿠키는 검증된 것으로 식별합니다. 그러나 악성 행위자는 재사용하거나 단일 유효성을 공유하려고 할 수 있습니다.`cf_clearance`여러 요청 또는 장치에서 부가적인 문제를 우회할 수 있습니다.

이 비율 제한 규칙은 많은 요청이 동일한 방법으로 할 수 있는지 제한하여 이러한 학대를 완화하는 데 도움이됩니다.`cf_clearance`정의된 기간 안에 값. Legitimate Human users will keep unaffected, 자동화 또는 단일 정리 토큰을 사용하여 재플레이된 요청은 임계값이 초과되면 차단됩니다.

| 설치하기         | 제품정보                                   |
| ------------ | -------------------------------------- |
| 일치 기준        | URI 경로 동등`/checkout`                   |
| 패스워드         | `http.request.uri.path eq "/checkout"` |
| 계산 특성        | 쿠키 (`cf_clearance`)                    |
| 비율 (요구 / 기간) | 100 요청 / 10 분                          |
| - 연혁         | 제품정보                                   |

### 특정 IP 주소 또는 ASNs 허용

리소스에 액세스 할 때 또 다른 사용 사례는 제한 규칙에서 IP 주소 또는 Autonomous System Numbers (ASNs)를 제외하고는 제외됩니다.

다음 예제 규칙은 동일한 IP 주소에서 분당 최대 10 요청을 허용합니다.`GET`요청사항`/status`, 방문자의 IP 주소가 포함되지 않는 한`partner_ips` [IP 목록](/waf/tools/lists/custom-lists/#ip-lists).

| 설치하기         | 제품정보                                                                                                 |
| ------------ | ---------------------------------------------------------------------------------------------------- |
| 일치 기준        | URI 경로 동등`/status`및 요청 방법 동등`GET`IP 소스 주소는 목록에 없습니다`partner_ips`                                     |
| 패스워드         | `http.request.uri.path eq "/status" and http.request.method eq "GET" and not ip.src in $partner_ips` |
| 계산 특성        | IP 정보                                                                                                |
| 비율 (요구 / 기간) | 10 요청 / 1 분                                                                                          |
| - 연혁         | 관리 도전                                                                                                |

### 참고로 제한

일부 응용 프로그램은 다른 소스에 의해 시작된 요청을받습니다 (예를 들어, 타사 페이지에 링크 된 광고에 의해 사용). quotas를 관리하거나 indirect DDoS 공격을 방지하기 위해 개별 참조 페이지에 의해 생성 된 요청 수를 제한 할 수 있습니다.

| 설치하기         | 제품정보                                                                  |
| ------------ | --------------------------------------------------------------------- |
| 일치 기준        | URI 경로 동등`/status`및 요청 방법 동등`GET`                                     |
| 패스워드         | `http.request.uri.path eq "/status" and http.request.method eq "GET"` |
| 계산 특성        | 헤더 (`Referer`) [^1]                                                   |
| 비율 (요구 / 기간) | 100 요청 / 10 분                                                         |
| - 연혁         | 제품정보                                                                  |

[^1]: HTTP 헤더 이름은 "referrer".

*이 예제 규칙은 고급 비율 제한이 필요합니다.*

### 대상 호스트의 제한

SaaS 애플리케이션 또는 고객 사용[SaaS를 위한 Cloudflare SSL](/cloudflare-for-platforms/cloudflare-for-saas/)같은 영역에서 수천 개의 호스트가있을 수 있습니다, 이는 호스트의 실제적인 당 개별 규칙을 만드는. 이를 극복하기 위해 호스트를 사용하는 제한 규칙을 만들 수 있습니다.

다음 예제 규칙은 요청에 대한 비율을 추적합니다.`/login`각 호스트의 끝점:

| 설치하기         | 제품정보                                                                 |
| ------------ | -------------------------------------------------------------------- |
| 일치 기준        | URI 경로 동등`/login`및 요청 방법 동등`GET`                                     |
| 패스워드         | `http.request.uri.path eq "/login" and http.request.method eq "GET"` |
| 계산 특성        | IP 및 호스트                                                             |
| 비율 (요구 / 기간) | 10 요청 / 10 분                                                         |
| - 연혁         | 제품정보                                                                 |

*이 예제 규칙은 고급 비율 제한이 필요합니다.*

## credential에 대하여 보호

제한 속도의 전형적인 사용 사례는 다음과 같은 공격에 대한 로그인 엔드 포인트를 보호하는 것입니다.[품질 관리](https://www.cloudflare.com/learning/bots/what-is-credential-stuffing/). 다음 예제는 클라이언트가 너무 많은 요청을 처리하기 위해 penalties 증가 규칙을 제한하는 세 가지 다른 비율을 포함합니다.

**규칙 #1**

| 설치하기         | 제품정보                                                                                                      |
| ------------ | --------------------------------------------------------------------------------------------------------- |
| 일치 기준        | Hostname 동등`example.com`URI 경로 동등`/login`및 요청 방법 동등`POST`                                                 |
| 패스워드         | `http.host eq "example.com" and http.request.uri.path eq "/login" and http.request.method eq "POST"`      |
| 계산 특성        | IP 정보                                                                                                     |
| 주문 카운터       | URI 경로 동등`/login`및 방법 동등`POST`응답 코드는 (401, 403)                                                           |
| 표창식          | `http.request.uri.path eq "/login" and http.request.method eq "POST" and http.response.code in {401 403}` |
| 비율 (요구 / 기간) | 4 요청 / 1 분                                                                                                |
| - 연혁         | 관리 도전                                                                                                     |

**규칙 #2**

| 설치하기         | 제품정보                                                                                                      |
| ------------ | --------------------------------------------------------------------------------------------------------- |
| 일치 기준        | Hostname 동등`example.com`URI 경로 동등`/login`및 요청 방법 동등`POST`                                                 |
| 패스워드         | `http.host eq "example.com" and http.request.uri.path eq "/login" and http.request.method eq "POST"`      |
| 계산 특성        | IP 정보                                                                                                     |
| 주문 카운터       | URI 경로 동등`/login`및 요청 방법 동등`POST`응답 상태 코드는 (401, 403)                                                     |
| 표창식          | `http.request.uri.path eq "/login" and http.request.method eq "POST" and http.response.code in {401 403}` |
| 비율 (요구 / 기간) | 10 요청 / 10 분                                                                                              |
| - 연혁         | 관리 도전                                                                                                     |

**규칙 #3**

| 설치하기         | 제품정보                                                                                                      |
| ------------ | --------------------------------------------------------------------------------------------------------- |
| 일치 기준        | 호스트 동등`example.com`                                                                                       |
| 패스워드         | `http.host eq "example.com"`                                                                              |
| 계산 특성        | IP 정보                                                                                                     |
| 주문 카운터       | URI 경로 동등`/login`및 요청 방법 동등`POST`응답 상태 코드는 (401, 403)                                                     |
| 표창식          | `http.request.uri.path eq "/login" and http.request.method eq "POST" and http.response.code in {401 403}` |
| 비율 (요구 / 기간) | 20 요청 / 1 시간                                                                                              |
| - 연혁         | 1 일 동안 블록                                                                                                 |

*이 예제 규칙은 비즈니스 계획 또는 위에 필요합니다.*

규칙 #1는 분 당 최대 4 개의 요청을 허용하므로 관리 된 도전이 트리거됩니다. 이 구성은 합법적 인 고객이 암호를 기억하는 데 몇 가지 시도를 허용합니다. 자동화 된 배우가 여러 요청을 만드는 경우, 클라이언트는 해결되지 않은 관리 도전에 의해 차단 될 것입니다. 다른 한편으로 인간이 얻고 규칙 #1의 비율 제한에 도달 할 때 도전을 통과하면 규칙 #2은 다음 10 분 동안 10 요청을 허용하는 보호의 다음 수준을 제공 할 것입니다. 이 두 번째 임계값을 초과하는 클라이언트의 경우, 규칙 #3 (가장 심한)은 1 일 동안 클라이언트를 차단합니다.

이 세 가지 규칙은 규칙 표현과 분리 된 세 가지 규칙이 있습니다 (또한 완화 표현으로도 알려져 있음). 별도의 계산식을 구성할 때, 해당 표준은 동작이 트리거될 때만 사용됩니다. 계산 식에서 HTTP 응답 상태 코드 및 HTTP 응답 헤더에 따라 조건을 포함 할 수 있습니다. 따라서 백엔드 논리로 제한 비율을 통합합니다.

두 가지 다른 표현을 가진 것을 결정할 수 있습니다. - 계산 표현과 규칙 / 완화 표현 - 정의 :

1. 비율을 계산하는 데 사용되는 요청.
2. 요청은 실제로 행동했습니다.

예를 들어, 규칙 #3은 고려 비율을 계산합니다.`POST`이름 \*`/login`즉,`401`또는`403`HTTP 상태 코드. 그러나, 비율 한계가 초과될 때, Cloudflare 구획 각 요구에`example.com`동일한 IP로 생성된 호스트. 더 많은 정보를 계산하기 위해, 참조[요금 계산](/waf/rate-limiting-rules/request-rate/#example-b).

:::note\[추가 보호 구성]

로그인 엔드포인트는 일반적으로 보호됩니다.[노출된 credentials의 사용](/waf/managed-rules/check-for-exposed-credentials/)·[봇 남용](/bots/).
:::

## 작업의 수 제한

클라이언트가 수행한 작업 수를 제한하는 비율을 사용할 수 있습니다. 이 보호를 제공하는 정확한 규칙은 당신의 신청에 달려 있을 것입니다. 다음 예제 주소[콘텐츠 스크랩](https://www.cloudflare.com/learning/bots/what-is-content-scraping/)쿼리 문자열 매개 변수 또는 JSON body를 통해.

### 내용 스크랩 방지 (Query 문자열을 통해)

이 예에서 클라이언트는 다른 쿼리 문자열 매개 변수를 사용하여 전자 상거래 웹 사이트에서 (가격 및 바구니에 추가)을 찾는 것과 같은 작업을 수행합니다. 예를 들어, 클라이언트가 보낸 전형적인 요청은 다음과 같습니다.

```txt
GET https://store.com/merchant?action=lookup_price&product_id=215
Cookie: session_id=12345
```

귀하의 보안 팀은 클라이언트가 봇을 방지하기 위해 가격을 볼 수 시간의 제한을 설정하려는 것이 좋습니다. Cloudflare Bot Management를 포함 할 수 있습니다. 상점 전체 카탈로그를 스크랩에서.

**규칙 #1**

| 설치하기         | 제품정보                                                                                             |
| ------------ | ------------------------------------------------------------------------------------------------ |
| 일치 기준        | URI 경로 동등`/merchant`URI 쿼리 문자열 포함`action=lookup_price`                                           |
| 패스워드         | `http.request.uri.path eq "/merchant" and http.request.uri.query contains "action=lookup_price"` |
| 계산 특성        | IP 정보                                                                                            |
| 비율 (요구 / 기간) | 10 요청 / 2 분                                                                                      |
| - 연혁         | 관리 도전                                                                                            |

**규칙 #2**

| 설치하기         | 제품정보                                                                                             |
| ------------ | ------------------------------------------------------------------------------------------------ |
| 일치 기준        | URI 경로 동등`/merchant`URI 쿼리 문자열 포함`action=lookup_price`                                           |
| 패스워드         | `http.request.uri.path eq "/merchant" and http.request.uri.query contains "action=lookup_price"` |
| 계산 특성        | IP 정보                                                                                            |
| 비율 (요구 / 기간) | 20 요청 / 5 분                                                                                      |
| - 연혁         | 제품정보                                                                                             |

이 두 가지 비율 제한 규칙 일치 요청은 선택한 동작을 수행 (가격, 이 예에서) 사용`IP`계산 특성으로. 자주 묻는 질문[이름 \*`/login`이름 \*](#protecting-against-credential-stuffing), 두 가지 규칙은 영구적 인 경우 false 긍정적을 줄일 수 있습니다 (하지만 합법적 인) 방문자.

특정한 모습을 제한하기`product_id`쿼리 문자열 매개 변수를 통해 특정 쿼리 매개 변수를 계산 특성으로 추가 할 수 있으므로 클라이언트에 관계없이 모든 요청을 기준으로 계산됩니다. 다음과 같은 예 규칙은 각 표의 수를 제한합니다.`product_id`10 초에서 50 요청.

| 설치하기         | 제품정보                                   |
| ------------ | -------------------------------------- |
| 일치 기준        | URI 경로 동등`/merchant`                   |
| 패스워드         | `http.request.uri.path eq "/merchant"` |
| 계산 특성        | 질문 (`product_id`)                      |
| 비율 (요구 / 기간) | 50 요청 / 10 초                           |
| - 연혁         | 제품정보                                   |

*이 예제 규칙은 고급 비율 제한이 필요합니다.*

신청 처리 예약 및 예약을 보호하기 위해 제한 규칙의 동일한 패턴을 따를 수 있습니다.

### 스크랩 방지 (몸을 통해)

JSON 형식으로 요청 본문을 통해 작업 및 매개 변수를 처리하는 응용 프로그램을 고려하십시오. 예를 들어,`lookup_price`가동은 다음과 같이 보일 수 있었습니다:

```txt
POST https://api.store.com/merchant
Cookie: session_id=12345

Body:
{
  "action": "lookup_price",
  "product_id": 215
}
```

이 시나리오에서는 개별 세션에서 작업의 수를 제한하는 규칙을 작성할 수 있습니다.

| 설치하기         | 제품정보                                                                                                             |
| ------------ | ---------------------------------------------------------------------------------------------------------------- |
| 일치 기준        | URI 경로 동등`/merchant`JSON 문자열`action`이름 \*`lookup_price`                                                          |
| 패스워드         | `http.request.uri.path eq "/merchant" and lookup_json_string(http.request.body.raw, "action") eq "lookup_price"` |
| 계산 특성        | 쿠키 (`session_id`)                                                                                                |
| 비율 (요구 / 기간) | 10 요청 / 2 분                                                                                                      |
| - 연혁         | 관리 도전                                                                                                            |

*이 예제 규칙은 고급 비율 제한 및 페이로드 검사를 요구합니다.*

또한 각의 보기 수를 제한할 수 있습니다.`product_id`클라이언트가 다음과 같은 규칙을 배포함으로써 요청을 작성에 관계없이:

| 설치하기         | 제품정보                                                                                                             |
| ------------ | ---------------------------------------------------------------------------------------------------------------- |
| 일치 기준        | URI 경로 동등`/merchant`JSON 필드`action`이름 \*`lookup_price`                                                           |
| 패스워드         | `http.request.uri.path eq "/merchant" and lookup_json_string(http.request.body.raw, "action") eq "lookup_price"` |
| 계산 특성        | JSON 필드 (`product_id`)                                                                                           |
| 비율 (요구 / 기간) | 50 요청 / 10 초                                                                                                     |
| - 연혁         | 제품정보                                                                                                             |

*이 예제 규칙은 고급 비율 제한 및 페이로드 검사를 요구합니다.*

:::참조

요청 몸이 JSON이 아닌 경우, 사용할 수 있습니다.[`http.request.body.raw`](/ruleset-engine/rules-language/fields/reference/http.request.body.raw/)필드와 정규 표현식 (along with a[`matches`회사연혁](/ruleset-engine/rules-language/operators/#comparison-operators)) 동일한 목표를 달성하기 위해.

### bots의 제한 요청

봇에서 트래픽을 식별하는 일반적인 접근은 큰 볼륨을 유발하는 제한 요청을 평가하는 것입니다.`403`또는`404`Origin 서버의 응답 상태 코드. 일반적으로 스크랩 응용 분야에서 자동화 된 활동을 나타냅니다.

이 상황에서 다음과 같은 규칙을 구성 할 수 있습니다.

| 설치하기         | 제품정보                              |
| ------------ | --------------------------------- |
| 일치 기준        | Hostname 동등`example.com`          |
| 패스워드         | `http.host eq "example.com"`      |
| 계산 특성        | IP 정보                             |
| 주문 카운터       | 응답 상태 코드는 (401, 403)              |
| 표창식          | `http.response.code in {401 403}` |
| 비율 (요구 / 기간) | 5 요청 / 3 분                        |
| - 연혁         | 관리 도전                             |

*이 예제 규칙은 비즈니스 계획 또는 위에 필요합니다.*

자동화된 소스에 의해 수행된 작업의 속도를 제어하려면, 사용 속도 제한 규칙과 함께 고려[Bot 관리](/bots/get-started/bot-management/). Bot 관리로, 당신은 사용할 수 있습니다[봇 점수](/bots/concepts/bot-score/)해당 표준의 일부로 자동화 또는 자동화된 트래픽에만 적용할 수 있습니다. 예를 들어, 최대 점수(또는 임계값)을 사용할 수 있습니다.`30`자동화된 교통 및`10`자동화된 트래픽.

귀하의 애플리케이션이 쿠키를 사용하여 세션을 추적하는 경우, 쿠키를 사용하여 속도 제한 컨텍스트를 설정할 수 있습니다. (즉, 계산 특성으로 사용). 쿠키에 대한 특성 제한 비율을 설정함으로써 규칙은 다른 IP 주소에서 요청을 함께 그룹하지만 분산 된 공격을 수행하는 봇 네트워크로 처리 할 때 일반적인 시나리오 인 동일한 세션에 속합니다.

**규칙 #1**

| 설치하기         | 제품정보                                                                                |
| ------------ | ----------------------------------------------------------------------------------- |
| 일치 기준        | Bot 점수 30 이하 및 URI 쿼리 문자열 포함`action=delete`                                         |
| 패스워드         | `cf.bot_management.score lt 30 and http.request.uri.query contains "action=delete"` |
| 계산 특성        | 쿠키 (`session_id`)                                                                   |
| 비율 (요구 / 기간) | 10 요청 / 1 분                                                                         |
| - 연혁         | 관리 도전                                                                               |

**규칙 #2**

| 설치하기         | 제품정보                                                                                |
| ------------ | ----------------------------------------------------------------------------------- |
| 일치 기준        | Bot 점수 10 이하 및 URI 쿼리 문자열 포함`action=delete`                                         |
| 패스워드         | `cf.bot_management.score lt 10 and http.request.uri.query contains "action=delete"` |
| 계산 특성        | 쿠키 (`session_id`)                                                                   |
| 비율 (요구 / 기간) | 20 요청 / 5 분                                                                         |
| - 연혁         | 제품정보                                                                                |

*이 예제 규칙은 고급 비율 제한 및 Bot 관리가 필요합니다.*

응용 프로그램이 세션 쿠키를 사용하지 않는 경우, 당신은 사용할 수 있습니다[JA3 지문](/bots/additional-configurations/ja3-ja4-fingerprint/)개별 고객을 식별합니다. JA3 지문은 고객과 함께 사용할 수있는 독특한 식별자입니다.[Bot 관리](/bots/get-started/bot-management/)Cloudflare는 동일한 클라이언트에서 오는 요청을 식별 할 수 있습니다. 모든 고객은 자동 또는 아닙니다.

| 설치하기         | 제품정보                                                                     |
| ------------ | ------------------------------------------------------------------------ |
| 일치 기준        | URI 경로 동등`/merchant`그리고 Bot 점수 10 이하                                     |
| 패스워드         | `http.request.uri.path eq "/merchant" and cf.bot_management.score lt 10` |
| 계산 특성        | JA3 지문                                                                   |
| 비율 (요구 / 기간) | 10 요청 / 1 분                                                              |
| - 연혁         | 관리 도전                                                                    |

*이 예제 규칙은 고급 비율 제한 및 Bot 관리가 필요합니다.*

## REST API 보호

APIs는 API 요청이 비싸기 때문에 신청 백엔드에 뜻깊은 긴장을 둘 수 있습니다. 이 요청은 복잡한 작업을 필요로 할 수도 있습니다 (데이터 처리 및 대형 데이터 조회와 같은) 학대, 결국 원래 서버를 가져올 수 있습니다.

### Volumetric 공격 방지

고급 비율 제한은 많은 유형의 부피 측정 공격을 완화할 수 있으며 DDoS 공격, 대량 할당 및 데이터 압축과 같은 공격을 완화 할 수 있습니다.

자주 묻는 질문`POST`작업. 정통 트래픽을 위해, 당신은 사용할 수 있습니다[API 디스커버리](/api-shield/security/api-discovery/)endpoint 당 요청에 적합한 비율을 식별하고 다음과 같은 비율 제한 규칙을 만듭니다.

| 설치하기         | 제품정보                                                                      |
| ------------ | ------------------------------------------------------------------------- |
| 일치 기준        | URI 경로 동등`/endpoint1`및 요청 방법 동등`POST`                                     |
| 패스워드         | `http.request.uri.path eq "/endpoint1" and http.request.method eq "POST"` |
| 계산 특성        | 헤더 (`x-api-key`)                                                          |
| 비율 (요구 / 기간) | API Discovery에 의해 제안하거나 과거 트래픽 분석에 의해 평가.                                 |
| - 연혁         | 제품정보                                                                      |

*이 예제 규칙은 고급 비율 제한이 필요합니다. API Discovery는 추가 라이센스가 필요합니다.*

계산 특성은 헤더, 키, 토큰, 쿠키, 쿼리 매개 변수 또는 JSON 몸 필드가 될 수 있습니다. 일부 API는 JSON 몸의 일부로 세션 ID 또는 사용자 ID를 포함합니다. 추가 정보에 대한 다음 섹션에 참조 :

- 고유 식별자가 URI 경로에 있다면, 참조[비밀번호](#protect-resources).
- 고유 식별자가 JSON 몸에 있다면, 참조[스크랩 방지 (몸을 통해)](#prevent-content-scraping-via-body).

### 비밀번호

`GET`요청은 응용 프로그램에 과도한 변형을 만들거나 대역폭과 같은 비용 자원에 영향을 미칠 수 있습니다. 예를 들어, 클라이언트가 특정 URL에 액세스하여 파일을 다운로드 할 수있는 대용량 저장 파일 (예 : 이미지)와 함께 응용 프로그램을 고려 :

```txt
GET https://api.store.com/files/<FILE_ID>
Header: x-api-key=9375
```

당신은 아마도 학대를 피하기 위해 다운로드 수를 제한하고 싶지만, 당신은 각 파일에 대한 개별 규칙을 작성하고 싶지 않다, 데이터 저장의 크기를 부여. 이 경우 다음과 같은 규칙을 쓸 수 있습니다.

| 설치하기         | 제품정보                                                              |
| ------------ | ----------------------------------------------------------------- |
| 일치 기준        | Hostname 동등`api.example.com`및 요청 방법 동등`GET`                       |
| 패스워드         | `http.host eq "api.example.com" and http.request.method eq "GET"` |
| 계산 특성        | 오시는 길                                                             |
| 비율 (요구 / 기간) | API Discovery에 의해 제안하거나 과거 트래픽 분석에 의해 평가.                         |
| - 연혁         | 제품정보                                                              |

*이 예제 규칙은 고급 비율 제한이 필요합니다.*

규칙은 10 분마다 10 다운로드의 한계를 정의합니다.`https://api.store.com/files/*`. 규칙 특성으로 Path를 사용하여 새로운 규칙을 작성하는 것을 피하십시오. 매번 다른 새로운 업로드 파일이 있습니다.`<FILE_ID>`. 이 규칙으로, 비율은 소스 IP 또는 세션 식별자에 관계없이 모든 요청에 따라 계산됩니다.

경로도 결합할 수 있습니다.`x-api-key`헤더 (또는 IP, 키 또는 토큰이없는 경우)는 특정 클라이언트가 식별 한 것과 같이 최대 다운로드 수를 설정하기 위해`x-api-key`, 주어진 파일로 만들 수 있습니다:

| 설치하기         | 제품정보                                                              |
| ------------ | ----------------------------------------------------------------- |
| 일치 기준        | Hostname 동등`api.store.com`및 요청 방법 동등`GET`                         |
| 패스워드         | `http.host eq "api.example.com" and http.request.method eq "GET"` |
| 계산 특성        | 경로 및 헤더 (`x-api-key`)                                             |
| 비율 (요구 / 기간) | API Discovery에 의해 제안하거나 과거 트래픽 분석에 의해 평가.                         |
| - 연혁         | 제품정보                                                              |

*이 예제 규칙은 고급 비율 제한이 필요합니다.*

## GraphQL API 보호

GraphQL API를 위한 서버 과부하를 방지하는 것은 RESTful APIs를 위한 과부하 방지에서 다를 수 있습니다. GraphQL에 내장 된 응용 프로그램에 의해 만들어진 가장 큰 도전 중 하나는 단일 경로가 서버에 모든 쿼리를 관리하고, 모든 요청은 일반적으로`POST`가동. HTTP 방식과 URI 경로에 따라 다른 API 사용 사례에 대한 다른 비율 제한을 방지합니다.

그러나 RESTful API와 같은 방법 및 경로를 사용하는 대신, 요청의 목적은 일반적으로 클라이언트가 fetch 또는 mutate로 원하는 데이터에 대한 정보가 있는 신체에 내장되어 있습니다.[GraphQL의 용어](https://graphql.org/learn/queries/)서버 측 데이터 수정)의 경우, 작업 수행에 필요한 추가 데이터와 함께.

서버 과부하를 방지하려면 다음과 같은 접근법을 고려하십시오.

1. 특정 사용자가 같은 GraphQL 작동 이름을 호출 할 수있는 시간을 제한합니다.
2. 지정된 사용자가 요청할 수 있는 쿼리의 총계를 제한합니다.
3. 개별 요청의 쿼리 복잡성을 제한하십시오.

다음 예제는 영화에 대한 리뷰를 수락하는 응용 프로그램을 기반으로합니다. GraphQL 요청은 다음과 같습니다.

```txt
POST https://moviereviews.example.com/graphql
Cookie: session_id=12345

Body:
{
  "data": {
    "createReview": {
      "stars": 5,
      "commentary": "This is a great movie!"
    }
  }
}
```

### 작업의 수 제한

행동의 비율을 제한하려면 다음 규칙을 사용할 수 있습니다.

| 설치하기         | 제품정보                                                                                    |
| ------------ | --------------------------------------------------------------------------------------- |
| 일치 기준        | URI 경로 동등`/graphql`본문내용 바로가기`createReview`                                              |
| 패스워드         | `http.request.uri.path eq "/graphql" and http.request.body.raw contains "createReview"` |
| 계산 특성        | 쿠키 (`session_id`)                                                                       |
| 비율 (요구 / 기간) | 5 요청 / 1 시간                                                                             |
| - 연혁         | 제품정보                                                                                    |

*이 예제 규칙은 고급 비율 제한 및 페이로드 검사를 요구합니다.*

### 쿼리의 총계를 제한합니다.

GraphQL 요청을 처리하는 데 필요한 복잡성은 크게 다를 수 있습니다. API는 단일 엔드포인트를 사용하고 있기 때문에 각 요청의 복잡성을 파악하기 어렵습니다.

자원 배기에서 기원 서버를 보호하기 위해, 오히려 요청의 수를 제한하는 것보다 시간 동안 단일 클라이언트를 처리하는 데 필요한 복잡성의 양을 제한해야합니다. 사이트맵 Rate Limiting을 사용하면 규칙을 만들 수 있습니다.[시간에 따른 복잡성](/waf/rate-limiting-rules/request-rate/#complexity-based-rate-limiting)복잡성 예산 또는 제한에 도달 한 후 이후의 요청을 차단합니다.

이 유형의 비율 제한은 요청의 복잡성에 따라 서버 점수가 모든 봉사 요청을 요구합니다. 또한 서버는 HTTP 헤더로 응답에 이 점수를 추가해야합니다. 그런 다음 속도 제한 메커니즘은 해당 특정 클라이언트의 예산을 업데이트하는이 정보를 사용합니다.

예를 들어, 다음 규칙은 시간 당 1,000의 전체 복잡성 예산을 정의합니다.

| 설치하기     | 제품정보                                  |
| -------- | ------------------------------------- |
| 일치 기준    | URI 경로 포함`/graphql`                   |
| 패스워드     | `http.request.uri.path eq "/graphql"` |
| 계산 특성    | 쿠키 (`session_id`)                     |
| 기간별 점수   | 1,000                                 |
| 기간 :     | 1시간                                   |
| 응답 헤더 이름 | `score`                               |
| - 연혁     | 제품정보                                  |

*이 예제 규칙은 고급 비율 제한 및 페이로드 검사를 요구합니다.*

원래 서버가 요청을 처리 할 때, 그것은 추가`score`HTTP 헤더가 얼마나 많은 일을 나타내는 값과 응답에 대한 기본은 처리하기 위해 수행되었다 — 예를 들어,`100`. 다음 시간에 동일한 클라이언트는 추가 예산까지 요청을 수행 할 수 있습니다`900`. 이 예산이 초과되면, 나중에 요청은 타임 아웃이 만료 될 때까지 차단됩니다.

### 개별 쿼리의 복잡성 제한

API Shield 고객은 GraphQL 악성 쿼리 보호를 사용하여 GraphQL API를 보호합니다. GraphQL 악의적 인 쿼리 보호는 GraphQL 트래픽을 스캔하여 원본을 과부하하고 서비스 거부 결과를 얻을 수 있습니다. GraphQL 쿼리의 깊이와 크기를 제한하는 규칙을 구축 할 수 있습니다 의심의 여지없이 큰 또는 복잡한 쿼리를 차단하기 위해.

더 알아보기[API Shield 문서](https://developers.cloudflare.com/api-shield/security/graphql-protection/)GraphQL 악성 쿼리 보호에 대한 자세한 내용은.
