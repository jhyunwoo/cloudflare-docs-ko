사용 방법[규칙 세트 API](/ruleset-engine/rulesets-api/)영역 수준에서 API를 통해 제한 규칙을 만들려면.

규칙을 제한하는 비율은 규칙 세트 엔진에 의해 취급되는 일정한 규칙과 유사합니다, 그러나 추가를 포함합니다`ratelimit`제한 설정과 객체. 더 알아보기[비율 제한 모수](/waf/rate-limiting-rules/parameters/)이 분야에 대한 자세한 정보와 그 매개 변수.

제한 규칙을 배포해야 합니다.`http_ratelimit` [단계 항목 점 규칙](/ruleset-engine/about/rulesets/#entry-point-ruleset).

제한 규칙은 규칙 목록의 끝에서 나타납니다.

Terraform을 사용하는 경우, 참조[Terraform을 사용하여 제한 규칙 구성](/terraform/additional-configurations/rate-limiting-rules/).

### 예제 A - 요청 속성을 기반으로 한 비율 제한

이 예제는 제한 규칙을 추가합니다.`http_ratelimit`ID를 가진 지역을 위한 단계 입장 점 통치자`$ZONE_ID`. 단계 항목 포인트 규칙 이미 존재, ID`$RULESET_ID`.

<APIRequest
  path="/zones/{zone_id}/rulesets/{ruleset_id}/rules"
  method="POST"
  json={{
  	description: "My rate limiting rule",
  	expression: '(http.request.uri.path matches "^/api/")',
  	action: "block",
  	ratelimit: {
  		characteristics: [
  			"cf.colo.id",
  			"ip.src",
  			'http.request.headers["x-api-key"]',
  		],
  		period: 60,
  		requests_per_period: 100,
  		mitigation_timeout: 600,
  	},
  }}
  roles={false}
/>

### 예제 B - 사용자 정의 응답 제한 속도

이 예제는 제한 규칙을 추가합니다.`http_ratelimit`ID를 가진 지역을 위한 단계 입장 점 통치자`$ZONE_ID`. 단계 항목 포인트 규칙 이미 존재, ID`$RULESET_ID`.

새로운 규칙은 정의[주문 응답](/waf/rate-limiting-rules/create-zone-dashboard/#configure-a-custom-response-for-blocked-requests)요청은 제한율로 인해 차단됩니다.

<APIRequest
  path="/zones/{zone_id}/rulesets/{ruleset_id}/rules"
  method="POST"
  json={{
  	description: "My rate limiting rule",
  	expression: '(http.request.uri.path matches "^/api/")',
  	action: "block",
  	action_parameters: {
  		response: {
  			status_code: 403,
  			content: "You have been rate limited.",
  			content_type: "text/plain",
  		},
  	},
  	ratelimit: {
  		characteristics: [
  			"cf.colo.id",
  			"ip.src",
  			'http.request.headers["x-api-key"]',
  		],
  		period: 60,
  		requests_per_period: 100,
  		mitigation_timeout: 600,
  	},
  }}
  code={{
  	mark: [{ range: "9-13" }],
  }}
  roles={false}
/>

### 예 C - 캐시 된 자산을 무시하는 비율

이 예제는 제한 규칙을 추가합니다.`http_ratelimit`ID를 가진 지역을 위한 단계 입장 점 통치자`$ZONE_ID`. 단계 항목 포인트 규칙 이미 존재, ID`$RULESET_ID`.

새로운 규칙은 비율을 계산 할 때 캐시 된 자산에 대한 요청을 고려하지 않습니다 (`"requests_to_origin": true`).

### 예 D - 복잡성 기반 비율 제한 규칙

:::참조
[복잡한 비율 제한](/waf/rate-limiting-rules/request-rate/#complexity-based-rate-limiting)Advanced Rate Limiting으로 Enterprise 고객에게만 사용할 수 있습니다.
주요 특징

이 예제는 제한 규칙을 추가합니다.`http_ratelimit`ID를 가진 지역을 위한 단계 입장 점 통치자`$ZONE_ID`. 단계 항목 포인트 규칙 이미 존재, ID`$RULESET_ID`.

새로운 규칙은 복잡한 비율 제한 규칙입니다.`my-score`HTTP 응답 헤더는 클라이언트의 전체 복잡성 점수를 계산하기 위해 계정으로. 총 점수를 가진 카운터는 제한 규칙의 계산 표현에 대한 일치가있을 때 업데이트됩니다 (이 경우 규칙 표현과 동일합니다.`counting_expression`빈 문자열입니다. 이 총 점수가 더 큰 경우`400`기간 중`60`초 (1 분), 나중에 클라이언트 요청은 기간 동안 차단됩니다`600`초 (10 분).

<APIRequest
  path="/zones/{zone_id}/rulesets/{ruleset_id}/rules"
  method="POST"
  json={{
  	description: "My complexity-based rate limiting rule",
  	expression: '(http.request.uri.path wildcard "/graphql/*")',
  	action: "block",
  	ratelimit: {
  		characteristics: ["cf.colo.id", 'http.request.headers["x-api-key"]'],
  		score_response_header_name: "my-score",
  		score_per_period: 400,
  		period: 60,
  		mitigation_timeout: 600,
  		counting_expression: "",
  	},
  }}
  code={{
  	mark: [{ range: "13-14" }],
  }}
  roles={false}
/>
