## 2. WAF 공격 점수에 근거를 둔 주문 규칙을 창조하십시오

:::참조
WAF 공격 점수는 비즈니스 고객에게만 사용할 수 있습니다 (단일 필드에 제한 된 액세스) 및 엔터프라이즈 고객 (전체 액세스).
주요 특징

[WAF 공격 점수](/waf/detections/attack-score/)Cloudflare의 관리 규칙을 보완하는 기계 학습 층이며, 추가 보호 기능을 제공합니다.[SQL 주입](https://www.cloudflare.com/learning/security/threats/sql-injection/)(SQLi),[크로스 사이트 스크립트](https://www.cloudflare.com/learning/security/threats/cross-site-scripting/)(XSS), 그리고 많은[원격 코드 실행](https://www.cloudflare.com/learning/security/what-is-remote-code-execution/)(RCE) 공격. 그것은 규칙 우회 및 잠재적으로 새로운, 발견되지 않은 공격을 식별하는 데 도움이됩니다.

엔터프라이즈 고객이 있다면 다음을 수행하십시오.

<Steps>
  1. WAF 공격 점수에 액세스하려면 계정 팀에 도달하십시오.

  2. [사용자 정의 규칙 만들기](/waf/custom-rules/create-dashboard/)사용 방법<GlossaryTooltip term="attack score">공격 점수</GlossaryTooltip>유형:
     - **수신 요청 일치**:

       | 제품정보      | 회사연혁     | 제품정보 |
       | --------- | -------- | ---- |
       | WAF 공격 점수 | 더 적은 보다는 | `20` |

     - **자주 묻는 질문**: 블록
</Steps>

비즈니스 계획에 있다면, 위에서 언급 한대로 사용자 정의 규칙을 만들지만 사용[WAF 공격 점수 클래스](/waf/detections/attack-score/#available-scores)대신 필드. 예를 들어 다음과 같은 규칙 표현을 사용할 수 있습니다.`WAF Attack Score Class equals Attack`.

## 3. bot 점수를 기반으로 사용자 정의 규칙 만들기

:::참조
Bot 점수는 기업 고객에게만 유효합니다[Bot 관리](/bots/get-started/bot-management/). Pro 및 Business 계획의 고객은 가능할 수 있습니다.[슈퍼 Bot 전투 모드](/bots/get-started/super-bot-fight-mode/)대신.
주요 특징

고객 접근[Bot 관리](/bots/get-started/bot-management/)자동화된 트래픽을 차단할 수 있습니다 (예를 들면, from[봇 스크랩 온라인 콘텐츠](https://www.cloudflare.com/learning/bots/what-is-content-scraping/)) 봇 점수로 사용자 정의 규칙을 사용하여 응용 프로그램을 타격에서이 트래픽을 방지합니다.

[사용자 정의 규칙 만들기](/waf/custom-rules/create-dashboard/)사용 방법<GlossaryTooltip term="bot score">봇 점수</GlossaryTooltip>·<GlossaryTooltip term="verified bot">인증 봇</GlossaryTooltip>분야:

- **수신 요청 일치**:

  | 제품정보 | 회사연혁     | 제품정보  | 로그인   |
  | ---- | -------- | ----- | ----- |
  | 봇 점수 | 더 적은 보다는 | `20`  | 이름 \* |
  | 인증 봇 | 이름 \*    | 이름 \* |       |

- **자주 묻는 질문**: 관리 도전

악성 봇에 대한 기본 보호의 더 포괄적 인 예를 들어, 참조[나쁜 봇 도전](/waf/custom-rules/use-cases/challenge-bad-bots/#general-protection).

봇 관련 분야에 대한 자세한 내용은 표현에서 사용할 수 있습니다.[Bot 관리 변수](/bots/reference/bot-management-variables/).

Cloudflare Managed Ruleset 및 규칙을 배포하면 공격 점수와 봇 점수를 기반으로 한 실질적인 보호를 달성하고 false 긍정적 인 가능성을 제한합니다.

## 4. 선택 사항 - Cloudflare OWASP Core Ruleset 배포

Cloudflare Managed Ruleset 및 공격 점수를 구성하면 배포할 수 있습니다.[Cloudflare OWASP 핵심 통치자](/waf/managed-rules/reference/owasp-core-ruleset/). 이 관리되는 통치자는 OWASP ModSecurity 핵심 규칙 세트의 Cloudflare의 구현입니다. Cloudflare 관리 규칙 세트를 사용하여 공격 범위는 SQLi 및 XSS와 같은 일반적인 공격 벡터를 감지하여 크게 오버랩.

:::카트로션
Cloudflare OWASP Core Ruleset은 가짜 긍정적이며 Cloudflare Managed Ruleset 및 WAF 공격 점수의 상단에 추가 할 때만 마진 혜택을 제공합니다. 이 관리 규칙을 배포하기로 결정하면 트래픽에 기반한 설정을 모니터링하고 조정해야합니다.
주요 특징

    <Steps>

         <DashButton url="/?to=/:account/:zone/security/settings" />

      2. (선택) 필터 로**웹 애플리케이션 악용**.

      3. 기타 제품**OWASP 핵심**.<br />기본 설정으로 Cloudflare OWASP Core Ruleset을 배포합니다. paranoia level =*공장 투어*점수 임계값 =*중간 - 40 이상*.
    </Steps>
  </TabItem>

      2. 이름 \***관리 규칙**, 선택**계정 만들기**Cloudflare OWASP 핵심 규칙 세트 옆에.<br />기본 설정으로 규칙을 배포합니다: paranoia level =*공장 투어*점수 임계값 =*중간 - 40 이상*.
    </Steps>
  </TabItem>

<Details header="Ruleset 구성">
  Cloudflare Managed Ruleset과는 달리 Cloudflare OWASP Core Ruleset은 점수 기반입니다. 특정 파라노아 수준을 선택 (레벨은 다를 수 있음)*공장 투어*으로*공장 투어*, 어디*공장 투어*가장 낮은 수준), 이는 규칙의 더 큰 그룹을 증가시킬 수. 구성 작업을 수행 할 때 결정되는 점수 임계값을 선택합니다. 높은 점수 임계값을 가진 낮은 paranoia는 보통 몇몇 거짓 긍정적으로 지도합니다. OWASP Core Ruleset이 평가되는 방법의 예를 들어, 참조[OWASP 평가 예](/waf/managed-rules/reference/owasp-core-ruleset/example/).

  이 전략 중 하나를 따라 필요한 규칙을 구성하십시오.

  - 엄격한 설정에서 시작 (paranoia level =*공장 투어*, 점수 임계값 =*낮음 - 60 이상*). 점수 임계 값과 파라노아 레벨을 줄이면 들어오는 트래픽의 좋은 거짓 긍정 / true 긍정적 인 속도를 얻을 수 있습니다.
  - 대안으로, 더 많은 허용 구성에서 시작 (paranoia level =*공장 투어*, 점수 임계값 =*높은 - 25 이상*) 그리고 당신의 보호를 조정하기 위하여 모수를 둘 다 증가시키고, 거짓 긍정적의 저 수를 지키는 시도.

  Cloudflare OWASP Core Ruleset 구성에 대한 자세한 정보는 대시보드에 참조하세요.[대시보드 구성](/waf/managed-rules/reference/owasp-core-ruleset/configure-dashboard/#ruleset-level-configuration).
</Details>

## 5. 보안 대시보드s의 트래픽 검토

:::참조
무료 계획의 사용자는 보안 이벤트에 액세스해야합니다.
주요 특징

WAF 구성을 설정 한 후 다음 대시보드s를 사용하여 현재 설정에 영향을받는 트래픽을 검토하십시오.

- 제품 정보[보안 Analytics](/waf/analytics/security-analytics/)WAF 완화 대책에 영향을받지 않는 트래픽을 포함한 모든 트래픽을 탐험하십시오. 모든 데이터 제공[교통 감지](/waf/concepts/#available-traffic-detections)이 대시보드에서 사용할 수 있습니다.
- 제품 정보[보안 이벤트](/waf/analytics/security-events/)Cloudflare 보안 제품에 대한 자세한 정보를 얻을 수 있습니다.

Enterprise 고객은 HTTP 요청 및 보안 이벤트에 대한 데이터를 얻을 수 있습니다.[Cloudflare 로그](/logs/).

## 6. 선택 - 다음 단계

이전 섹션에서 정보를 기반으로 WAF를 구성하면 응용 프로그램에 가능한 위협에 대한 강력한 기본 보호를해야합니다.

특정 사용 사례에 대한 추가 보호를 얻기 위해 다음 권장 사항을 탐색 할 수 있습니다.

### 특정 IP 주소 허용

사용자 정의 규칙 만들기[수당에 IP 주소에서 트래픽을 허용](/waf/custom-rules/use-cases/allow-traffic-from-ips-in-allowlist/).

### 특정 국가 차단

사용자 정의 규칙 만들기[특정 국가에서 트래픽 차단](/waf/custom-rules/use-cases/block-traffic-from-specific-countries/).

### 가격 제한

제한 규칙을 만들기[로그인 endpoint에 제한 비율 적용](/waf/rate-limiting-rules/use-cases/#example-1).

### credential 채우기 공격 방지

제품 정보[누출 검출](/waf/detections/leaked-credentials/)관련 기사<GlossaryTooltip term="credential stuffing" link="https://www.cloudflare.com/learning/bots/what-is-credential-stuffing/">품질 관리</GlossaryTooltip>당신의 신청에 공격.

### 악성코드를 앱으로 업로드하는 행위

:::참조
유료 애드온으로 엔터프라이즈 고객에게 제공.
주요 특징

[WAF 콘텐츠 스캔 사용](/waf/detections/malicious-uploads/get-started/)귀하의 응용 프로그램에 업로드 된 콘텐츠를 스캔하여 악의적인 콘텐츠를 검색합니다.

### API에 대한 추가 보안 받기

:::참조
기업 고객에게 유효한.
주요 특징

Cloudflare는 SQL 주입 공격과 같은 새로운 알려진 응용 공격 및 악용에서 API를 보호합니다. API-specific 보안 제품은 API 검색 및 인증 관리와 같은 API의 고유한 위험에 대한 보호를 확장합니다.

Cloudflare의 API 보안 기능에 대한 자세한 내용은 참조[Cloudflare API Shield](/api-shield/).
