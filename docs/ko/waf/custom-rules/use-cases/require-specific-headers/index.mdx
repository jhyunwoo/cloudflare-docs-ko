특정 HTTP 요청 헤더의 존재에 따라 많은 조직의 자격 트래픽. 규칙 언어 사용[HTTP 요청 헤더 필드](/ruleset-engine/rules-language/fields/reference/?field-category=Headers\&search-term=http.request)특정 헤더를 가진 대상 요청에.

## 예 1 : HTTP 헤더의 존재가 필요합니다.

이 예제 사용자 정의 규칙은[`http.request.headers.names`](/ruleset-engine/rules-language/fields/reference/http.request.headers.names/)필드는 존재를 찾습니다`X-CSRF-Token`헤더. 더 보기[`lower()`](/ruleset-engine/rules-language/functions/#lower)변환 함수는 header name을 lowcase로 변환하여 표현은 case-insensitive입니다.

언제까지`X-CSRF-Token`헤더가 누락되어 Cloudflare는 요청을 차단합니다.

- **패스워드**: `not any(lower(http.request.headers.names[*])[*] eq "x-csrf-token") and (http.request.full_uri eq "https://www.example.com/somepath")`
- **- 연혁**: *제품정보*

## 예 2: HTTP 헤더를 특정 값으로 요구합니다.

이 예제 사용자 정의 규칙은[`http.request.headers`](/ruleset-engine/rules-language/fields/reference/http.request.headers/)필드는 존재를 찾습니다`X-Example-Header`헤더와 값을 얻는다 (모든 경우). 언제까지`X-Example-Header`헤더가 누락되거나 값이 없습니다.`example-value`, Cloudflare는 요구를 막습니다.

- **패스워드**: `not any(http.request.headers["x-example-header"][*] eq "example-value") and (http.request.uri.path eq "/somepath")`
- **- 연혁**: *제품정보*

키에서`http.request.headers`HTTP 헤더 이름과 일치하는 필드는 더 낮은 케이스에 있습니다.

이 예제에서 헤더 이름은 case-insensitive이지만 헤더 값은 case-sensitive입니다.
