토큰 인증은 문서, 파일 및 미디어에 대한 액세스를 제한 할 수 있습니다. 등록하지 않고 사용자를 선택하십시오. 이것은 leeching 및 unauthorized 공유에서 지불 / 제한 된 콘텐츠를 보호합니다.

토큰 인증을 구성하는 두 가지 옵션이 있습니다. Cloudflare Workers 또는 사용자 정의 규칙을 통해.

## 선택권 1: Cloudflare Workers를 사용하여 형성하십시오

다음 Cloudflare Workers 리소스에 대한 참조 토큰 인증의 두 가지 다른 구현:

- 더 보기[로그인 요청](/workers/examples/signing-requests/)예.
- 더 보기[머리에 Auth](/workers/examples/auth-with-headers/)템플릿.

시작하기에 Workers에, 참조[한국어](/workers/get-started/quickstarts/).

:::참조

제공된 코드[로그인 요청](/workers/examples/signing-requests/)예제와 호환`is_timed_hmac_valid_v0()`안으로 사용하는 기능[옵션 2](#option-2-configure-using-custom-rules). 정의 규칙을 사용하여 example Worker 스크립트에 의해 서명된 요청을 확인할 수 있음을 의미합니다.
주요 특징

## 옵션 2 : 사용자 정의 규칙을 사용하여 구성

규칙 언어 사용[`is_timed_hmac_valid_v0()`](/ruleset-engine/rules-language/functions/#hmac-validation)HMAC 검증 함수는 사용자 정의 규칙 표현의 해시 기반 메시지 인증 코드 (HMAC) 토큰을 검증합니다.

:::참조
오시는 길`is_timed_hmac_valid_v0()`HMAC 검증 기능은 Cloudflare Pro, Business 또는 Enterprise 플랜을 요구합니다.
주요 특징

토큰 인증을 검증하려면[사용자 정의 규칙 만들기](/waf/custom-rules/create-dashboard/)자주 묻는 질문`is_timed_hmac_valid_v0()`규칙 표현의 기능. 같은 작업을 사용할 수 있습니다.*제품정보*.

### 예제 규칙

이 예제는 특정 호스트 이름과 URL 경로에 HMAC 키 검증을 통과하지 않는 방문자를 차단하는 규칙을 설명합니다. 토큰 인증에 필요한 세부 사항:

- HMAC 생성 및 검증을위한 비밀 키 (예를 들어,`mysecrettoken`)
- 인증하려는 경로 (예를 들어,`downloads.example.com/images/cat.jpg`)
- 토큰을 포함하는 쿼리 문자열 매개 변수의 이름 (예를 들어,`verify`)
- 초의 토큰 수명 (예를 들어, 3 시간 = 10,800 초)

다음 예 URL을 고려:

```txt
downloads.example.com/images/cat.jpg?verify=1484063787-9JQB8vP1z0yc5DEBnH6JGWM3mBmvIeMrnnxFi3WtJLE%3D
```

위치:

- `/images/cat.jpg`HMAC 메시지는 자산에 대한 경로를 나타냅니다.
- `?verify=`HMAC 토큰이 발행되었을 때 자산과 타임 스탬프 사이의 분리기입니다.
- `1484063787`토큰이 발행될 때 타임스탬프를 나타내며, 초 단위로 표현됩니다.
- `9JQB8vP1z0yc5DEBnH6JGWM3mBmvIeMrnnxFi3WtJLE%3D`Base64 인코딩된 MAC입니다.

:::카트로션
선택할 때`flags`관련 기사`is_timed_hmac_valid_v0()`, 당신은 Base64 인코딩 된 MAC 값을 인코딩 URL을 인코딩해야합니다. 더 많은 정보를 원하시면, 참조[HMAC 검증](/ruleset-engine/rules-language/functions/#hmac-validation).
:::

사용자 정의 규칙의 표현은 다음과 같습니다 :

```txt
(http.host eq "downloads.example.com" and not is_timed_hmac_valid_v0("mysecrettoken", http.request.uri, 10800, http.request.timestamp.sec, 8))
```

이 예의 사용자 정의 규칙의 구성 요소 (이전 예 URL 사용) 포함:

- 토큰 비밀 키 =`mysecrettoken`
- 토큰 수명 =`10800`(10,800 초 = 3 시간)
- `http.request.uri` = `/images/cat.jpg?verify=1484063787-9JQB8vP1z0yc5DEBnH6JGWM3mBmvIeMrnnxFi3WtJLE%3D`
- `http.request.timestamp.sec` = `1484071925`(예를 들어)
- 분리기 길이:`len("?verify=")` = `8`

더 보기[`is_timed_hmac_valid_v0()`](/ruleset-engine/rules-language/functions/#hmac-validation)함수는 생성된 MAC의 값을 비교합니다`mysecrettoken`비밀 키 값에 인코딩 된`http.request.uri`.

MAC 값 일치와 토큰이 아직 만료되지 않은 경우 다음 공식에 따라:

```txt
http.request.timestamp.sec < (<TIMESTAMP_ISSUED> + 10800)
```

그런 다음 토큰은 유효하며`is_timed_hmac_valid_v0()`기능 반환`true`.

## HMAC 토큰 생성

다음 예제는 이전 섹션에서 설명 된 사용자 정의 규칙을 사용하여 검증된 경로에 대한 소스 서버에서 토큰을 생성 할 수있는 방법을 보여줍니다.

<Tabs>
  <TabItem label="사이트맵" icon="seti:python">
    ```python
    import hmac
    import base64
    import time
    import urllib.parse
    from hashlib import sha256

    message = "/images/cat.jpg"
    secret = "mysecrettoken"
    separator = "verify"
    timestamp = str(int(time.time()))
    digest = hmac.new((secret).encode('utf8'), "{}{}".format(message, timestamp).encode('utf8'), sha256)
    token = urllib.parse.quote_plus(base64.b64encode(digest.digest()))
    print("{}={}-{}".format(separator, timestamp, token))
    ```
  </TabItem>

  <TabItem label="사이트맵" icon="seti:python">
    ```python
    import hmac
    import base64
    import time
    import urllib
    from hashlib import sha256

    message = "/images/cat.jpg"
    secret = "mysecrettoken"
    separator = "verify"
    timestamp = str(int(time.time()))
    digest = hmac.new(secret, message + timestamp, sha256)
    param = urllib.urlencode({separator: '%s-%s' % (timestamp, base64.b64encode(digest.digest()))})
    print(param)
    ```
  </TabItem>

  <TabItem label="PHP를" icon="seti:php">
    ```php
    <?php
    $message = "/images/cat.jpg";
    $secret = "mysecrettoken";
    $separator = "verify";
    $timestamp = time();
    $token = urlencode(base64_encode(hash_hmac("sha256", $message . $timestamp, $secret, true)));
    echo("{$separator}={$timestamp}-{$token}");
    ```
  </TabItem>

## 같은 비밀을 사용하여 여러 경로를 보호합니다.

여러 URI 경로를 보호하기 위해 동일한 비밀 키를 사용할 수 있습니다.

이것은 이전 예에서 설명된다, 어디`http.request.uri`으로 전달[`MessageMAC`](/ruleset-engine/rules-language/functions/#messagemac)validation 함수에 인수.

이름 \*`http.request.uri`자산에 대한 경로와 그 값은 각 요청에 대한 추출, 검증 함수는 모든 요청 URI를 평가`downloads.example.com`같은 비밀 키를 사용하여.

여러 경로를 인증하는 동일한 비밀 키를 사용할 수 있는 동안 HMAC 토큰을 생성해야 합니다.

## 단일 서명으로 전체 URI 경로 접두사를 보호합니다.

단 하나 HMAC 서명을 가진 전체 고정 길이 URI 경로 접두사를 보호할 수 있습니다 (또한 동일한 비밀을 사용할 것입니다). 이를 달성하기 위해 URI 경로 접두사 (전체 URI 경로 상응) 및 원본 쿼리 문자열을[`MessageMAC`](/ruleset-engine/rules-language/functions/#messagemac)인수에 대한[`is_timed_hmac_valid_v0()`](/ruleset-engine/rules-language/functions/#hmac-validation)기능.

사용 방법[`substring()`](/ruleset-engine/rules-language/functions/#substring)전체 URI 경로에서 접두사를 얻는 기능.

다음 예에서, URI 경로 접두사 단일 HMAC 서명을 요구하는 것은 항상 51 문자 길이입니다 (`x`캐릭터 위너):

```txt
/case-studies/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx/
```

이 경우, 길이 51의 다른 URI 경로 접두사에 대한 다른 HMAC 서명을 사용할 필요가 있습니다.

HMAC 유효성 검사에 실패한 경우, 당신은 다음과 같은 사용자 정의 규칙을 만들 수 있습니다:

<Example>
  규칙 표현:

  ```txt
    (http.host eq "downloads.example.com" and starts_with(http.request.uri.path, "/case-studies") and not is_timed_hmac_valid_v0("mysecrettoken", concat(substring(http.request.uri.path, 0, 51), "?", http.request.uri.query), 10800, http.request.timestamp.sec, 1))
  ```

  활동 :

  - 제품정보
</Example>

유효한 수신 요청의 예 URI 경로:

```txt
/case-studies/12345678-90ab-4cde-f012-3456789abcde/foobar-report.pdf?1755877101-5WOroVcDINdl2%2BQZxZFHJcJ6l%2Fep4HGIrX3DtSXzWO0%3D
/case-studies/12345678-90ab-4cde-f012-3456789abcde/acme-corp.pdf?1755877101-5WOroVcDINdl2%2BQZxZFHJcJ6l%2Fep4HGIrX3DtSXzWO0%3D
/case-studies/768bf477-22d5-4545-857d-b155510119ff/another-company-report.pdf?1755878057-jeMS5S1F3MIgxvL61UmiX4vODiWtuLfcPV6q%2B0Y3Rig%3D
```

첫 번째 두 URI 경로는 동일한 HMAC 서명을 사용할 수 있기 때문에 동일한 51-character 접두사 (`/case-studies/12345678-90ab-4cde-f012-3456789abcde/`) 그것은 사용자 정의 규칙에 의해 검증됩니다.

세 번째 URI 경로는 접두사는 서로 다른 HMAC 서명을 필요로한다.
