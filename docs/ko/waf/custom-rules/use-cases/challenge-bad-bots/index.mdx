Cloudflare의 Bot 관리 기능은 요청이 봇에서 시작되는 것과 같은 점수를 나타냅니다.

:::참조
오시는 길[Bot 관리](/bots/plans/bm-subscription/)Cloudflare Enterprise 플랜을 사용하여 Bot Management를 사용할 수 있습니다.
주요 특징

Bot 점수는 1에서 99까지 배열합니다. 낮은 점수는 스크립트, API 서비스 또는 자동화된 에이전트에서 요청이 제공됩니다. 높은 점수는 인간이 표준 데스크탑 또는 모바일 웹 브라우저에서 요청을 발행한다는 것을 나타냅니다.

이 예제는 다음과 같습니다.

- [`cf.bot_management.score`](/ruleset-engine/rules-language/fields/reference/cf.bot_management.score/)bots에서 대상 요청
- [`cf.bot_management.verified_bot`](/ruleset-engine/rules-language/fields/reference/cf.bot_management.verified_bot/)자주 묻는 질문[잘 알려진 봇](https://radar.cloudflare.com/verified-bots)
- [`cf.bot_management.ja3_hash`](/ruleset-engine/rules-language/fields/reference/cf.bot_management.ja3_hash/)특정[JA3 지문](/bots/additional-configurations/ja3-ja4-fingerprint/)

## 제안된 규칙

제일 결과를 위해:

- 제품 정보[봇 분석](/bots/bot-analytics/#enterprise-bot-management)규칙을 적용하기 전에 교통에 대해 알아보세요.
- 작은 시작과 시간이 지남에 봇 임계 값을 증가.

당신의 규칙은 또한 다를 수 있습니다[사이트 맵](/bots/get-started/bot-management/)그리고 거짓 긍정을 위한 당신의 포용력.

### 일반 보호

뒤에 오는 3개의 주문 규칙은 악의적인 bots에 대하여 기본 보호를 제공합니다:

**규칙 1:**

- **패스워드**: `(cf.bot_management.verified_bot)`
- **- 연혁**: *건너뛰기:*
  - *모든 나머지 사용자 정의 규칙*

**규칙 2:**

- **패스워드**: `(cf.bot_management.score eq 1)`
- **- 연혁**: *제품정보*

**규칙 3:**

- **패스워드**: `(cf.bot_management.score gt 1 and cf.bot_management.score lt 30)`
- **- 연혁**: *관리 도전*

### 브라우저, API 및 모바일 트래픽에 대한 특정 보호

#### 브라우저 엔드포인트를 보호

요청이 확실히 자동화 될 때 (score of 1) 또는 자동화 될 가능성이 (scores 2 통해 29) 그리고*아니다.*&#xC54C;려진 좋은 봇 목록에서 Cloudflare는 요청을 차단합니다.

- **패스워드**: `(cf.bot_management.score lt 30 and not cf.bot_management.verified_bot)`
- **- 연혁**: *제품정보*

#### API 트래픽

Bot Management가 자동화된 사용자를 감지하므로 명시적으로 허용해야 합니다.**이름 \***&#xC790;동화된 트래픽⁠ —[API를](https://www.cloudflare.com/learning/security/api/what-is-an-api/)그리고 파트너 APIs.

이 예제는 브라우저 전용 규칙과 동일한 보호를 제공하지만 자동화 된 트래픽을 API로 허용합니다.

- **패스워드**: `(cf.bot_management.score lt 30 and not cf.bot_management.verified_bot and not starts_with(http.request.uri.path, "/api"))`
- **- 연혁**: *제품정보*

#### 모바일 트래픽 조정

Bot Management는 모바일 트래픽에 더 민감 할 수 있으므로 합법적 인 요청을 차단하기 위해 추가 논리에 추가 할 수 있습니다.

모바일 응용 프로그램에서 요청을 처리하는 경우 잠재적으로 특정 상황에 따라 허용 할 수 있습니다.[JA3 지문](/bots/additional-configurations/ja3-ja4-fingerprint/).

- **패스워드**: `(cf.bot_management.ja3_hash eq "df669e7ea913f1ac0c0cce9a201a2ec1")`
- **- 연혁**: *건너뛰기:*
  - *모든 나머지 사용자 정의 규칙*

그렇지 않으면 모바일 트래픽의 낮은 임계값을 설정할 수 있습니다. 다음과 같은 규칙은 확실히 자동화 된 모바일 트래픽을 차단하고 자동화 된 트래픽을 해결합니다.

**규칙 1:**

- **패스워드**: `(cf.bot_management.score lt 2 and http.user_agent contains "App_Name 2.0")`
- **- 연혁**: *제품정보*

**규칙 2:**

- **패스워드**: `(cf.bot_management.score lt 30 and http.user_agent contains "App_Name 2.0")`
- **- 연혁**: *관리 도전*

#### 다른 규칙을 결합

도메인이 모바일, 브라우저 및 API 트래픽을 처리하는 경우 다음 순서에서 이러한 예 규칙을 준비하고 싶습니다.

- 관련 기사[API 트래픽](#exempt-api-traffic)
- 규칙(s)[모바일 트래픽](#adjust-for-mobile-traffic)
- 관련 기사[비밀번호](#protect-browser-endpoints)

### 정체되는 자원 보호

정적 자원은 기본적으로 보호됩니다.`cf.bot_management.score`이름 \*

정적 자원을 제외하고는`not (cf.bot_management.static_resource)`당신의 규칙 표현. 자주 묻는 질문[정체되는 자원 보호](/bots/additional-configurations/static-resources/).

### 자주 묻는 질문

거기에서, 당신은 특정 요청 경로에 따라 사용자 정의 규칙을 사용자 정의 할 수 있습니다 (`/login`또는`/signup`), 일반적인 교통 본, 또는 다른 많은 특성.

자주 묻는 질문[봇 분석](/bots/bot-analytics/#enterprise-bot-management)·[보안 이벤트](/waf/analytics/security-events/)규칙이 더 많은 튜닝을 필요로하는지 확인하십시오.
