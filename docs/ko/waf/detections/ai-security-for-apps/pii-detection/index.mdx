AI Security for Apps (이전 Firewall for AI)는 LLM 프롬프트에서 개인 식별 정보 (PII)를 탐지 할 수 있습니다. PII 탐지에 대한 두 가지 접근이 있으며, 층 보호에 대해 함께 사용할 수 있습니다.

- [Fuzzy 탐지 (AI 전원)](#fuzzy-pii-detection)- AI Security for Apps는 AI 모델을 사용하여 일반적인 PII 유형의 신속한 콘텐츠를 식별합니다. 이 접근법은 자연 언어 또는 예기치 않은 형식으로 표시될 때 PII를 붙잡습니다.
- [정확한 탐지 (regex)](#exact-pii-detection-regex)— 당신은 WAF 주문 규칙을 원시 요청 몸에 정규 표현식으로 작성합니다. 이 접근법은 알려진, 예측 가능한 형식으로 조직 별 식별자에 이상적입니다.

## Fuzzy PII 탐지

AI Security for Apps가 활성화되면 요청이 도착합니다.`cf-llm`labeled endpoint, 그것은 PII에 대한 프롬프트를 스캔하고 두 개의 필드를 팝업 :

- **LLM PII 검출** ([`cf.llm.prompt.pii_detected`][1]) — `true`PII가 발견 된 경우.
- **LLM PII 카테고리** ([`cf.llm.prompt.pii_categories`][2]) — 특정 PII 유형의 배열은 찾아냈습니다.

[1]: /ruleset-engine/rules-language/fields/reference/cf.llm.prompt.pii_detected/

[2]: /ruleset-engine/rules-language/fields/reference/cf.llm.prompt.pii_categories/

탐지는 근거를 둡니다[사이트맵](https://microsoft.github.io/presidio/supported_entities/), 데이터 보호 및 de-identification SDK. 더 알아보기[`cf.llm.prompt.pii_categories`분야 참고 자료](/ruleset-engine/rules-language/fields/reference/cf.llm.prompt.pii_categories/)인정된 범주의 전체 목록입니다.

:::노트\[접속 PII]
앱 PII 탐지를 위한 AI Security는 수신된 요청에만 실행합니다. LLM 응답에 있는 PII를 검출할 필요가 있는 경우에, 당신은 사용할 수 있습니다[민감한 데이터 탐지](/waf/managed-rules/reference/sensitive-data-detection/)신용 카드 번호, 사회 보안 번호 및 API 키와 같은 패턴에 대한 응답 바디를 스캔합니다. 민감한 데이터 탐지 로그 일치하지만 응답을 차단하지 않습니다. Layered 가시성을 위한 request-side 규칙과 함께 사용하십시오.

### 거짓 긍정을 줄이기 위해 특정

더 보기`cf.llm.prompt.pii_detected`필드 반환`true`어떤 PII 범주가 감지 될 때 - 같은 넓은 범주를 포함`PERSON`, `DATE_TIME`·`LOCATION`종종 정상 대화에서 나타납니다. 이 분야에 근거를 둔 차단은 대부분의 신청을 위한 높은 거짓 positive 비율을 일으킬 것입니다.

대신, 규칙을 구축`cf.llm.prompt.pii_categories`그리고 목록은 당신의 사용 케이스에 대한 중요 한 범주. 예를 들어, 고객 지원 chatbot은 신용 카드 번호와 SSN을 차단해야하지만 안전하게 사람 이름과 날짜를 무시할 수 있습니다. 카테고리의 가장 좁은 세트로 시작, 모니터 일치[보안 Analytics](/waf/analytics/security-analytics/), 그리고 필요만 확장하십시오.

### 예제 규칙 - fuzzy 탐지

#### PII를 포함하는 어떤 요구든지 차단하십시오

- **수신 요청 일치**:

  | 제품정보       | 회사연혁  | 제품정보 |
  | ---------- | ----- | ---- |
  | LLM PII 검출 | 이름 \* | 한국어  |

  편집자를 사용할 때 표현:<br />
  `(cf.llm.prompt.pii_detected)`

- **- 연혁**: *제품정보*

#### 블록 전용 PII 범주

- **수신 요청 일치**:

  | 제품정보         | 회사연혁 | 제품정보          |
  | ------------ | ---- | ------------- |
  | LLM PII 카테고리 | 로그인  | `Credit Card` |

  편집자를 사용할 때 표현:<br />
  `(any(cf.llm.prompt.pii_categories[*] in {"CREDIT_CARD"}))`

- **- 연혁**: *제품정보*

#### 이메일 주소로 이동하지만 신용 카드 및 SSN을 차단

두 가지 만들기[주문 규칙](/waf/custom-rules/create-dashboard/):

1. 행동 규칙*제품정보*그리고 다음과 같은 표현:<br />
   `(any(cf.llm.prompt.pii_categories[*] in {"CREDIT_CARD" "US_SSN"}))`

2. 행동 규칙*로그인*그리고 다음과 같은 표현:<br />
   `(any(cf.llm.prompt.pii_categories[*] in {"EMAIL_ADDRESS"}))`

## 정확한 PII 탐지 (regex)

당신이 감지해야하는 경우**사용자 정의 PII 형식**내부 직원 ID, 환자 기록 번호 또는 독점 계정 식별자와 같은 조직에 특정 - WAF를 만들 수 있습니다[주문 규칙](/waf/custom-rules/)익지않는 몸에 regex 경기를 사용하여 ([`http.request.body.raw`](/ruleset-engine/rules-language/fields/reference/http.request.body.raw/)분야).

이 접근법은 AI 모델이 기본적으로 인식되지 않는 형식을 덮음으로써 퓨지 감지를 보완합니다.

### 예: 직원 ID를 감지

다음 예에서 조직은 형식의 직원 ID를 사용합니다.`EMP-`정확히 6 자리에 따라 (예를 들어,`EMP-482910`).

[사용자 정의 규칙 만들기](/waf/custom-rules/create-dashboard/)뒤에 오는 윤곽으로:

- **수신 요청 일치**:

  | 제품정보      | 회사연혁     | 제품정보           |
  | --------- | -------- | -------------- |
  | 익지않는 요구 몸 | 경기 regex | `EMP-[0-9]{6}` |

  편집자를 사용할 때 표현:<br />
  `(http.request.body.raw matches "EMP-[0-9]{6}")`

- **- 연혁**: *제품정보*

- **응답 유형으로**: 사용자 정의 JSON

- **응답 몸**: `{ "error": "Request blocked: employee ID detected in prompt." }`

<Details header="특정 endpoint에 범위">
  LLM 엔드포인트에만 규칙을 제한하려면 경로 상태와 결합하십시오.

  | 제품정보      | 회사연혁     | 제품정보           | 로그인   |
  | --------- | -------- | -------------- | ----- |
  | URI 경로    | 이름 \*    | `/api/chat`    | 이름 \* |
  | 익지않는 요구 몸 | 경기 regex | `EMP-[0-9]{6}` |       |

  편집자를 사용할 때 표현:<br />
  `(http.request.uri.path eq "/api/chat" and http.request.body.raw matches "EMP-[0-9]{6}")`
</Details>

### 더 많은 regex 예제

| 관례 PII 유형        | 예제 형식               | Regex 패턴                   |
| ---------------- | ------------------- | -------------------------- |
| 직원 ID            | `EMP-482910`        | `EMP-[0-9]{6}`             |
| 환자 기록 번호         | `PAT/2024/00391`    | `PAT/[0-9]{4}/[0-9]{5}`    |
| 내부 계정 ID         | `ACCT-XX-99999`     | `ACCT-[A-Z]{2}-[0-9]{5}`   |
| 사용자 정의 API 키 접두사 | `sk_live_abc123...` | `sk_live_[a-zA-Z0-9]{20,}` |

### regex 규칙에 대한 고려

- **사이트맵 계획 요구 사항.**&#x52;egex 운영자 (`matches`·`~`)는 사업 또는 기업 계획을 요구합니다.
- **몸 크기 한계.**&#xB354; 보기`http.request.body.raw`필드는 요청 신체의 제한된 부분을 검사합니다. 정확한 제한[숙박 플랜](/ruleset-engine/rules-language/fields/reference/http.request.body.raw/).
- **JSON 페이로드.**&#x52;aw body는 전체 JSON 구조를 포함합니다. 이력서는 JSON 문자열 내부에 배열 된 사실에 대해 계정해야합니다.
- **공연.**&#x43;omplex regex 패턴은 규칙 평가 시간에 영향을 미칠 수 있습니다. 가능한 한 특정 패턴을 유지.

## 두 가지 접근법

당신은 층으로 막힌 보호를 위해 함께 fuzzy와 정확한 탐지를 이용할 수 있습니다:

`(cf.llm.prompt.pii_detected or http.request.body.raw matches "EMP-[0-9]{6}")`

이 규칙은 AI 모델 중 하나가 어떤 내장 PII 카테고리 또는 regex가 사용자 정의 식별 형식을 일치시킵니다.
