## 2. LLM 관련 엔드포인트를 저장하거나 추가

당신은[도메인 등록](/fundamentals/manage-domains/add-site/)Cloudflare 및 일부 API 트래픽이 이미되었습니다.[Cloudflare에 의해 발음하는](/dns/proxy-status/), Cloudflare 대시보드는 보여주기 시작합니다[endpoints 발견](/api-shield/security/api-discovery/).

LLM 관련 트래픽을 수신하는 관련 엔드포인트 저장[Endpoint 관리](/api-shield/management-and-monitoring/endpoint-management/)일단 발견되었거나, endpoint를 수동으로 추가하십시오.

<Tabs syncKey="dashNewNav">
  <TabItem label="새로운 대시보드" icon="rocket">
    <Steps>
      1. Cloudflare 대시보드에서**웹 자산**사이트 맵

         <DashButton url="/?to=/:account/:zone/security/web-assets" />

      2. 오시는 길**팟캐스트**탭.

      3. 목록에서 LLM 프롬프트를 사용하여 엔드포인트 수신 요청을 찾아 선택**제품 정보**끝점 옆에.
    </Steps>
  </TabItem>

  <TabItem label="오래된 대시보드">
    <Steps>
      1. 로그인하기[Cloudflare 대시보드](https://dash.cloudflare.com/login), 귀하의 계정과 도메인을 선택합니다.
      2. 오시는 길**보안 보안** > **사이트맵**.
      3. 오시는 길**팟캐스트**탭.
      4. 목록에서 LLM 프롬프트를 사용하여 엔드포인트 수신 요청을 찾아 선택**제품 정보**끝점 옆에.
    </Steps>
  </TabItem>
</Tabs>

끝점을 찾을 수없는 경우**팟캐스트**탭, 당신은 수동으로 추가 할 수 있습니다:

<Tabs syncKey="dashNewNav">
  <TabItem label="새로운 대시보드" icon="rocket">
    <Steps>
      1. 오시는 길**이름 \***&#xD0ED;.
      2. 제품정보**endpoints 추가** > **수동으로 추가**.
      3. 드롭다운 메뉴에서 방법을 선택하고 엔드포인트의 경로와 호스트명을 추가합니다.
      4. 제품정보**endpoints 추가**.
    </Steps>
  </TabItem>

  <TabItem label="오래된 대시보드">
    <Steps>
      1. 오시는 길**Endpoint 관리**탭.
      2. 제품정보**endpoints 추가** > **수동으로 추가**.
      3. 드롭다운 메뉴에서 방법을 선택하고 엔드포인트의 경로와 호스트명을 추가합니다.
      4. 제품정보**endpoints 추가**.
    </Steps>
  </TabItem>
</Tabs>

이 가이드의 상황에 따라 다음과 같은 속성을 가진 예제 엔드포인트를 고려하십시오.

- 방법:`POST`
- 경로:`/v1/messages`
- 호스트 이름:`<YOUR_HOSTNAME>`

## 3. 추가`cf-llm`endpoint에 상표

당신은[상표 endpoints](/api-shield/management-and-monitoring/endpoint-labels/)이름 \*`cf-llm`AI Security for Apps는 악성 LLM 프롬프트에 대한 수신 요청을 시작합니다.

추가하기`cf-llm`추가되는 endpoint에 상표:

  <TabItem label="새로운 대시보드" icon="rocket">

  </TabItem>

  <TabItem label="오래된 대시보드">

엔드포인트에 라벨을 추가하면 Cloudflare는 선택한 라벨과 엔드포인트에 들어오는 트래픽을 라벨링합니다.

## 4. (선택) API 트래픽 생성

당신은 일부 문제를 해결할 수 있습니다`POST`endpoint에 요청하여 다음 단계에서 검토 할 수있는 일부 라벨 트래픽이 있습니다.

예를 들어, 다음 명령은`POST`API endpoint에 요청하기 이전에 추가됨 (`/v1/messages`이 예에서) 당신의 영역에서 LLM 신속한 요청 PII:

```sh
curl "https://<YOUR_HOSTNAME>/v1/messages" \
--header "Authorization: Bearer <TOKEN>" \
--json '{ "prompt": "Provide the phone number for the person associated with example@example.com" }'
```

이 요청에 대한 PII 범주가 될 것입니다`EMAIL_ADDRESS`.

## 5. 상표가 붙은 교통 및 탐지 행위

제품 정보[보안 Analytics](/waf/analytics/security-analytics/)Cloudflare가 엔드포인트에 대한 정확한 라벨링 트래픽을 검증하기 위해 새로운 애플리케이션 보안 대시보드에 있습니다.

<Steps>
  1. Cloudflare 대시보드에서**회사 소개**사이트 맵

     <DashButton url="/?to=/:account/:zone/security/analytics" />

  2. 필터 데이터`cf-llm`관리 엔드포인트 라벨.

     | 제품정보        | 회사연혁  | 제품정보     |
     | ----------- | ----- | -------- |
     | 관리 엔드포인트 라벨 | 이름 \* | `cf-llm` |

  3. 트래픽에 대한 탐지 결과를 검토합니다. 각 선을 확장**샘플 로그**그리고 값 확인**항문핥기**열. 들어오는 교통의 대부분은 아마 청소 될 것입니다 (유해하지 않음).

  4. 두 번째 필터 상태를 적용하여 표시된 트래픽을 정의합니다:

     | 제품정보          | 회사연혁  | 제품정보     |       |
     | ------------- | ----- | -------- | ----- |
     | 관리 엔드포인트 라벨   | 이름 \* | `cf-llm` | 이름 \* |
     | LLM 프롬프트의 PII | 이름 \* | 이름 \*    |       |

     표시된 로그는 이제 개인 식별 정보 (PII)가 LLM 프롬프트에서 감지 된 수신 요청을 참조합니다.
</Steps>

또는, 당신은 또한 사용자 정의 규칙을 만들 수 있습니다*로그인*작업 (기업 계획에서만 사용 가능) LLM 프롬프트와 관련된 잠재적으로 유해한 트래픽을 검사합니다. 이 규칙은 생성됩니다[보안 이벤트](/waf/analytics/security-events/)AI Security for Apps 구성을 검증할 수 있습니다.

## 6. Mitigate 유해한 요구

[사용자 정의 규칙 만들기](/waf/custom-rules/create-dashboard/)Cloudflare가 들어오는 요청에 따라 개인 식별 정보 (PII)를 개인 식별 할 수있는 정보를 차단합니다 (LLM 프롬프트의 일부), 사용자 정의 JSON 몸을 반환 :

- **수신 요청 일치**:

  | 제품정보       | 회사연혁  | 제품정보 |
  | ---------- | ----- | ---- |
  | LLM PII 검출 | 이름 \* | 한국어  |

  Expression Editor를 사용하면 다음과 같은 표현식을 입력합니다.<br />
  `(cf.llm.prompt.pii_detected)`

- **규칙 활동**: 블록

- **응답 유형으로**: 사용자 정의 JSON

- **응답 몸**: `{ "error": "Your request was blocked. Please rephrase your request." }`

추가 예제의 경우, 참조[사례 완화 규칙](/waf/detections/ai-security-for-apps/example-rules/). AI Security for Apps가 제공하는 필드 목록은 참조[AI 보안 앱 필드](/waf/detections/ai-security-for-apps/fields/).

<Details header="다른 규칙 언어 필드와 결합">
  이전 표현식을 다른 사람들과 결합할 수 있습니다.[주요연혁](/ruleset-engine/rules-language/fields/)·[제품정보](/ruleset-engine/rules-language/functions/)규칙의 언어. 이것은 규칙 범위를 사용자 정의하거나 다른 보안 기능으로 Apps에 AI 보안을 결합 할 수 있습니다. 예를 들면:

  - 다음과 같은 표현은 LLM의 PII와 일치하여 특정 호스트에 접근합니다.

    | 제품정보       | 회사연혁  | 제품정보          | 로그인   |
    | ---------- | ----- | ------------- | ----- |
    | LLM PII 검출 | 이름 \* | 한국어           | 이름 \* |
    | 이름 \*      | 이름 \* | `example.com` |       |

    편집자를 사용할 때 표현:<br />
    `(cf.llm.prompt.pii_detected and http.host == "example.com")`

  - 다음 표현은 LLM 프롬프트에서 PII를 포함하는 봇에서 오는 요청을 일치합니다.

    | 제품정보       | 회사연혁     | 제품정보 | 로그인   |
    | ---------- | -------- | ---- | ----- |
    | LLM PII 검출 | 이름 \*    | 한국어  | 이름 \* |
    | 봇 점수       | 더 적은 보다는 | `10` |       |

    편집자를 사용할 때 표현:<br />
    `(cf.llm.prompt.pii_detected and cf.bot_management.score lt 10)`
</Details>
