누출된 자격[교통 감지](/waf/detections/)credentials (usernames and passwords)에 대한 수신 요청을 이전에 유출[자료 breaches](https://www.cloudflare.com/learning/security/what-is-a-data-breach/).

:::참조
현재 사용중인 경우[노출된 Credentials 체크](/waf/managed-rules/check-for-exposed-credentials/)(이전 구현) 및 credentials 검출을 누출하기 위해 업그레이드하려는, 참조[손상된 credentials 탐지에 향상](/waf/managed-rules/check-for-exposed-credentials/upgrade-to-leaked-credentials-detection/).
:::

## 어떻게 작동합니까?

일단 활성화되면, 누출된 credentials 탐지는 일반적인 웹 앱과 당신이 구성하는 어떤 주문 탐지 위치든지에서 알려진 입증 본을 위한 들어오는 HTTP 요구를 검사할 것입니다.

Cloudflare가 요청에서 인증 자격 증명을 감지하면 그 자격 증명은 알려진 누출 된 자격 증명 목록에 대해 검사됩니다. 자격 증명 목록은 다음과 같습니다.

- 더 보기[파종 된 (HIBP)](https://haveibeenpwned.com)일치하는 암호 dataset (암호 만)
- Cloudflare 수집 자격 증명 (사용자 이름)

Cloudflare는 기존의[유출된 자격 분야](#leaked-credentials-fields)스캔 결과에 근거합니다. 이 결과를 확인할 수 있습니다.[보안 Analytics](/waf/analytics/security-analytics/)대시보드, 규칙 표현의이 필드를 사용 ([주문 규칙](/waf/custom-rules/)또는[비율 제한 규칙](/waf/rate-limiting-rules/)) 당신의 최종 사용자에 의해 손상된 credentials의 사용법에 대하여 당신의 신청을 보호하고, 또한 누출된 credential 공격에 대하여. Cloudflare는 공격자가 수행되기 때문에 누출 된 자격 증명을 감지 할 수 있습니다.[품질 관리](https://www.cloudflare.com/learning/bots/what-is-credential-stuffing/)공격 또는 합법적 인 최종 사용자는 이전에 유출 된 암호를 재사용하기 때문입니다.

또한, 누출된 credentials 탐지는 제공합니다[회사연혁](/rules/transform/managed-transforms/reference/#add-leaked-credentials-checks-header)그것은 추가`Exposed-Credential-Check`필드가 누출 된 값으로 요청 헤더. 예를 들어, 사용자 이름과 암호 모두 이전에 누출 된 경우, 헤더 값은`1`; 암호만 유출된 경우에, 가치는 일 것입니다`4`.

웹 애플리케이션에서 사용되는 일반적인 접근법은 도난 범죄의 사용을 감지하고 상황에 대한 최종 사용자를 경고하고 암호를 업데이트하도록 요청합니다. 소스 서버에서 수신된 관리 헤더를 기반으로 할 수 있습니다.

:::참조
Cloudflare는 저장하지 않습니다, 로그, 또는 누출 된 자격 검사를 수행 할 때 일반 텍스트 최종 사용자 암호를 유지합니다. 암호는 해시, 암호화 표현으로 변환, 그리고 다음 누출 된 자격의 데이터베이스에 비해.

## 기본 스캔 위치

누출된 자격 탐지에는 다음과 같은 잘 알려진 웹 응용 프로그램에 대한 HTTP 요청에 대한 자격 증명을 식별하기위한 규칙이 포함되어 있습니다.

- 박사후
- 프로젝트
- 팟캐스트
- 마젠토
- 뚱 베어
- 사이트 맵
- Microsoft 교환 OWA

또한 스캔에는 일반적인 웹 인증 패턴에 대한 일반적인 규칙이 포함되어 있습니다.

구성할 수 있습니다.[사용자 정의 감지 위치](#custom-detection-locations)웹 애플리케이션에 사용되는 특정 인증 메커니즘을 지정합니다. 사용자 정의 감지 위치는 Cloudflare WAF 웹 응용 프로그램의 HTTP 요청에 대한 사용자 및 암호를 찾을 수 있습니다.

## 주문 감지 위치

:::참조
기업 고객에게만 유효한.
주요 특징

때로는 웹 응용 프로그램의 특정 케이스에 대한 HTTP 요청에 대한 자격 증명을 찾을 수있는 위치를 지정 할 수 있습니다.

예를 들어, HTTP의 JSON 몸이 웹 응용 프로그램에서 다음과 같이 보이는 사용자를 인증하는 경우:

```json
{ "user": "<username>", "secret": "<password>" }
```

다음과 같은 설정으로 사용자 정의 감지 위치를 구성 할 수 있습니다.

- 사용자 이름:<br />
  `lookup_json_string(http.request.body.raw, "user")`
- 비밀번호:<br />
  `lookup_json_string(http.request.body.raw, "secret")`

사용자 지정 탐지 위치를 지정할 때, 사용자 지정 필드의 위치만 필요합니다.

다음 표에는 다른 요청 유형에 대한 예 탐지 위치가 포함됩니다.

| 주문 유형        | 사용자 이름 위치 / 비밀번호 위치                                                                                              |
| ------------ | ---------------------------------------------------------------------------------------------------------------- |
| JSON 몸       | `lookup_json_string(http.request.body.raw, "user")`<br />`lookup_json_string(http.request.body.raw, "secret")`   |
| URL 인코딩 양식   | `url_decode(http.request.body.form["user"][0])`<br />`url_decode(http.request.body.form["secret"][0])`           |
| Multipart 형태 | `url_decode(http.request.body.multipart["user"][0])`<br />`url_decode(http.request.body.multipart["secret"][0])` |

사용자 정의 감지 위치를 지정하는 Expressions는 다음과 같은 필드와 기능을 포함 할 수 있습니다.

- 분야:
  - [`http.request.body.form`](/ruleset-engine/rules-language/fields/reference/http.request.body.form/)
  - [`http.request.body.multipart`](/ruleset-engine/rules-language/fields/reference/http.request.body.multipart/)
  - [`http.request.body.raw`](/ruleset-engine/rules-language/fields/reference/http.request.body.raw/)
  - [`http.request.headers`](/ruleset-engine/rules-language/fields/reference/http.request.headers/)
  - [`http.request.uri.args`](/ruleset-engine/rules-language/fields/reference/http.request.uri.args/)
  - [`http.request.uri.query`](/ruleset-engine/rules-language/fields/reference/http.request.uri.query/)
- 기능:
  - [`lookup_json_string()`](/ruleset-engine/rules-language/functions/#lookup_json_string)
  - [`url_decode()`](/ruleset-engine/rules-language/functions/#url_decode)

사용자 정의 감지 위치에 대한 지침, 참조[시작하기](/waf/detections/leaked-credentials/get-started/#4-optional-configure-a-custom-detection-location).
