많은 웹 응용 프로그램은 고통<GlossaryTooltip term="credential stuffing" link="https://www.cloudflare.com/learning/bots/what-is-credential-stuffing/">품질 관리</GlossaryTooltip>최근 과거 공격. 이러한 공격에는 데이터베이스에서 사용자 이름 / 암호 쌍을 사용하여 많은 로그인 시도가 있습니다.<GlossaryTooltip term="leaked credentials">노출된 자격</GlossaryTooltip>.

Cloudflare는 Cloudflare Web Application Firewall (WAF)를 사용하여 노출된 자격 증명을 위한 자동화된 검사를 제공합니다.

<Render file="leaked-credentials-recommend-detection" product="waf" />

WAF는 이 체크를 위한 2개의 기계장치를 제공합니다:

- 더 보기[노출된 Credentials 체크 관리되는 통치자](/waf/managed-rules/reference/exposed-credentials-check/)인기있는 CMS 응용 프로그램에 대한 사전 정의 규칙이 포함되어 있습니다. 주어진 영역에 대한 이 규칙을 활성화하면 즉시 이러한 잘 알려진 응용 프로그램에 노출 된 자격 증명을 확인 할 수 있습니다. 관리된 규칙은 모든 유료 계획에 사용할 수 있습니다.

- 할 수있는 능력[사용자 정의 규칙](#exposed-credentials-checks-in-custom-rules)귀하의 기준에 따라 노출된 자격 증명을 확인하는 계정 수준. 이 구성 옵션은 유료 애드온으로 엔터프라이즈 고객에게 사용할 수 있습니다.

Cloudflare는 정기적인 기초에 노출된 자격 검사 기능을 지원하는 노출된 자격 증명의 데이터베이스를 업데이트합니다.

명확한 텍스트의 사용자 이름과 암호 자격은 Cloudflare 네트워크를 결코 떠나지 않습니다. WAF는 이전에 노출된 자격 증명이 있는 경우, 사용자 이름과 암호의 익명화 된 버전을 사용합니다. Cloudflare는 다음과 같은 접근 방식을 따릅니다.*₢ 킹*-Anonymity mathematical 속성은 다음과 같은 블로그 게시물에 설명 :[k-Anonymity로 유출된 비밀번호 검증](https://blog.cloudflare.com/validating-leaked-passwords-with-k-anonymity/).

## 자주 묻는 질문

WAF는 노출된 credentials를 검출할 때 뒤에 오는 행동의 하나 할 수 있습니다:

- **Exposed-Credential-Check 헤더**: 노출된 자격으로 HTTP 요청에 새로운 HTTP 헤더를 추가합니다. 원래의 응용 프로그램은 암호 재설정을 강제 할 수 있습니다, 두 요소 인증 과정을 시작, 또는 다른 작업을 수행. 추가된 HTTP 헤더의 이름은`Exposed-Credential-Check`그 값은`1`. 행동 이름은`Rewrite`내 계정[보안 이벤트](/waf/analytics/security-events/).

  :::참조
  헤더 이름은 사용할 때와 동일합니다.[유출된 Credentials 체크 Header 추가](/rules/transform/managed-transforms/reference/#add-leaked-credentials-checks-header)관리형 변환, 헤더는 관리형 변환을 사용할 때 다른 값을 가질 수 있습니다 (from`1`으로`4`), 당신의 Cloudflare 계획에 따라서.
  주요 특징

- **비동기 도전**: 노출된 credentials를 가진 HTTP 요청을 만드는 클라이언트에게 비동기적인 도전을 선물합니다.

- **관리 도전**: 인간 시대의 수명이 인터넷을 통해 CAPTCHA를 해결하는 데 도움이됩니다. 요청의 특성에 따라 Cloudflare는 특정 기준에 따라 적절한 유형의 도전을 동적으로 선택할 수 있습니다.

- **제품정보**: 노출된 credentials를 포함하는 블록 HTTP 요청.

- **로그인**: Enterprise 플랜에서만 가능합니다. Cloudflare 로그에 노출된 credentials와 로그 요청. 더 심한 행동에 투입하기 전에 규칙을 검증하는 것이 좋습니다.

- **대화 도전**: 노출된 자격으로 HTTP 요청을 만드는 클라이언트에 대한 대화형 도전을 제시합니다.

Exposed Credentials Check Managed Ruleset의 규칙에 대한 기본 동작은*Exposed-Credential-Check 헤더*(이름)`rewrite`API에서).

Cloudflare는 다음과 같은 작업을 사용하는 것이 좋습니다.*Exposed-Credential-Check 헤더*(이름)`rewrite`API에서) 그리고*로그인* (`log`).

## Exposed credentials는 주문 규칙에 확인합니다

:::참조
사용자 정의 규칙에 노출 된 자격 검사는 API를 통해 만 사용할 수 있으며 유료 애드온으로 엔터프라이즈 고객에게 사용할 수있는 계정 수준 WAF를 요구합니다.
주요 특징

더 알아보기[노출된 Credentials 체크 관리되는 통치자](/waf/managed-rules/reference/exposed-credentials-check/), 당신은 또한 안으로 드러낸 credentials를 검사할 수 있습니다[주문 규칙](/waf/custom-rules/). 1개의 일반적인 사용 케이스는 당신의 신청의 최종 사용자 입증 endpoints에 주문 규칙을 드러내는 것입니다 드러내는 credentials를 검사하기 위하여. 노출된 자격 증명을 확인하는 규칙은 제한 규칙 전에 실행됩니다.

사용자 정의 규칙에 노출 된 자격 증명을 확인하려면 계정 수준에서 규칙 정의에 노출 된 자격 검사를 포함하고 HTTP 요청에서 사용자 이름과 암호 값을 얻는 방법을 지정합니다. 더 많은 정보를 원하시면, 참조[노출된 credentials를 위한 주문 규칙을 창조하십시오](/waf/managed-rules/check-for-exposed-credentials/configure-api/#create-a-custom-rule-checking-for-exposed-credentials).
