주요 특징

Cloudflare Sensitive Data Detection 관리 규정은 소스 서버에 의해 생성 된 데이터 누출을 식별하는 데 도움이됩니다. 이 규칙은 다음과 같은 일반적인 민감한 데이터의 패턴을 찾고 응답의 몸에 달려있다 :

- [개인 식별 정보](https://www.cloudflare.com/learning/privacy/what-is-pii/)(PII) — 예를 들어, 여권 번호.
- 금융 정보 — 예를 들어, 신용 카드 번호.
- secrets — 예를 들면, API 열쇠.

Cloudflare Sensitive Data Detection을 켜는 것은 응답 경로 밖에 발생하므로 추가 대기 시간을 제공하지 않습니다. 이런 이유로 규칙은 항상 배포됩니다.*로그인*행동 (당신은 이미 전송 된 응답을 차단 할 수 없습니다), 당신의 기원 서버를 떠나 민감한 데이터에 대한 가시성을 제공.

:::참조
Cloudflare Sensitive Data Detection 관리 규정에 대한 몇 가지 규칙은 기본적으로 비활성화되어 가짜 긍정적 및 많은 수의 로그 이벤트를 방지합니다. 응용 프로그램에 관련된 PII 및 민감한 데이터를 검토하고 다음 섹션의 지침에 따라 관리 규칙에 적절한 규칙을 켜야합니다.
주요 특징

## 추가 알림

Cloudflare Sensitive Data Detection은 방문자에게 전송되는 모든 응답을 확인할 수 있습니다 (사용자 지정 필터 표현에 따라 정의된 경우), 캐시 및 응답에서 응답을 포함하여[사이트맵](/workers/).

탐지는 텍스트, HTML, JSON 및 XML 콘텐츠를 최대 1MB까지 처리합니다.

현재 Cloudflare Sensitive Data Detection은 지원하지 않습니다.[일치하는 페이로드 로깅](/waf/managed-rules/payload-logging/).

## 대시보드 구성

여러 수준에서 Cloudflare Sensitive Data Detection 규정을 구성할 수 있습니다.

- [규칙 설정 수준](#ruleset-level-configuration)
- [태그 수준](#tag-level-configuration)
- [규칙 수준](#rule-level-configuration)

더 특정 구성 (rule 및 태그 수준) 보다 더 큰 우선 순위 보다 적은 특정 구성 (ruleset 레벨). 더 알아보기[관리된 규칙을 무시](/ruleset-engine/managed-rulesets/override-managed-ruleset/)더 많은 정보를 위한 Ruleset Engine 문서에.

### Ruleset-level 구성

Cloudflare 대시보드에서 다음 Cloudflare Sensitive Data Detection 설정을 구성할 수 있습니다.

- **관련 상품**: 범위의 사용자 정의 필터 표현을 정의할 때 Cloudflare Sensitive Data Detection Ruleet은 들어오는 요청의 하위 집합에만 적용됩니다. 기본적으로 대시보드에 배포된 관리된 규칙은 모든 수신 트래픽에 적용됩니다.

당신은[Cloudflare 민감한 데이터 탐지 규칙을 배치](#deploy-in-the-dashboard), 대시보드에서 그것을 구성하는 뒤에:

## 검색 결과

Cloudflare Sensitive Data Detection에 의해 검출되는 모든 데이터 누출을 확인하려면 다음을 수행 할 수 있습니다.

- 자주 묻는 질문[보안 이벤트](/waf/analytics/security-events/)관리 규정에 의해 생성 된 모든 이벤트에 대한.
- 설정하기[WAF 경고](/waf/reference/alerts/)WAF 이벤트의 모든 스파이크 알림 Advanced Security Events Alert의 경우 엔터프라이즈 플랜에 하나 이상의 도메인을 필터링할 수 있습니다.`Data Loss Protection`Sensitive Data Detection에 대한 특정 경고를 수신하는 서비스.
