[Core Web Vitals](https://www.cloudflare.com/learning/performance/what-are-core-web-vitals/)는 사용자 경험을 포착하기 위해 Google이 설계한 상위 수준 지표입니다. 세 가지 핵심 Core Web Vitals 지표가 측정됩니다: Largest Contentful Paint, First Input Delay, Cumulative Layout Shift. 이 각 지표는 Google이 설계한 업계 표준 방법론과 테스트를 바탕으로 Good, Needs Improvement, Poor 중 하나의 등급이 자동으로 부여됩니다. Page load time 통계는 First Paint와 First Contentful Paint로 보완됩니다.

:::note


현재 Core Web Vitals는 Chromium 기반 브라우저에서만 지원되며, Safari와 Firefox 지원은 곧 제공될 예정입니다.


:::

## Core Web Vitals 접근하기

Core Web Vitals를 사용하면 웹사이트를 탐색하는 동안 사용자 경험에 영향을 주는 웹 페이지 요소를 시각적인 형태로 쉽게 찾아낼 수 있습니다.
Core Web Vitals에 접근하려면 다음과 같이 하세요.

1. Cloudflare 대시보드에서 **Web Analytics** 페이지로 이동합니다.

   <DashButton url="/?to=/:account/web-analytics" />

2. 웹사이트를 선택한 다음 **Core Web Vitals**를 선택합니다.

### Core Web Vitals 지표

Core Web Vitals는 사용자 경험에 영향을 주는 특정 기능에 대한 정보를 담은 세 가지 주요 섹션으로 나뉩니다.

- [Largest Contentful Paint (LCP)](https://web.dev/optimize-lcp/): 사용자가 체감하는 로딩 속도를 측정합니다. 페이지의 주요 콘텐츠가 로드되는 데 얼마나 걸리는지를 반환합니다.
- [Interaction to Next Paint (INP)](https://web.dev/inp/): 사용자 인터페이스의 반응성을 측정합니다. 즉 클릭이나 키 입력 같은 사용자 상호작용에 웹사이트가 얼마나 빠르게 반응하는지를 봅니다.
- [Cumulative Layout Shift (CLS)](https://web.dev/optimize-cls/): 시각적 안정성을 측정합니다. 즉 다양한 요소가 화면에 로드될 때 페이지 레이아웃이 얼마나 흔들리는지를 봅니다.

이 각 지표는 사용자 경험에 미치는 영향을 나타내며, Web Analytics가 이를 수치화하고 등급화합니다.

Cloudflare Web Analytics는 Core Web Vitals에서 URL, Browser, Operating System, Country, Element 기준으로 데이터를 필터링할 수 있게 하여 상호작용형 탐색 기능을 제공합니다.

### Debug view

각 그래프 아래의 Debug View 섹션에는 각 지표에 부정적인 영향을 주는 상위 다섯 개 요소가 표시됩니다. 데이터 표에 나타난 요소를 선택하면 더 많은 세부 정보를 볼 수 있습니다.

LCP, INP, CLS 각 표는 해당 요소들의 75번째 백분위(P75) 성능도 한눈에 보여 줍니다. 표의 각 행을 선택하면 요소를 확장해 P50, P90, P99 지표를 포함한 더 많은 정보에 접근할 수 있습니다.

이 숫자들은 한 요소가 페이지 내 다른 요소와 비교해 상대적으로 어떤 성능을 보이는지를 뜻합니다. 예를 들어 어떤 요소가 로드되기까지 3,900ms가 걸렸고 75백분위에 속한다면, 이는 페이지의 75% 요소보다 더 느리게 로드된다는 의미입니다.

## 수집되는 정보

Web Analytics는 자체 경량 JavaScript beacon을 사용해 Vitals Explorer가 사용하는 정보를 수집합니다. 사용량 지표를 수집하기 위해 쿠키나 `localStorage` 같은 클라이언트 측 상태는 사용하지 않습니다. 또한 Vitals Explorer는 IP 주소, User Agent 문자열 또는 기타 데이터를 사용해 개인을 식별(fingerprinting)하지 않습니다.

### 모든 Core Web Vitals 지표에 공통으로 수집되는 데이터

#### Element

DOM 노드를 나타내는 CSS selector입니다. 이 문자열을 이용해 브라우저 개발자 콘솔에서 `document.querySelector(<element_name>)`를 실행하면 어떤 DOM 노드가 점수/값에 부정적인 영향을 미치는지 확인할 수 있습니다.

#### Path

Core Web Vitals가 수집된 시점의 URL path입니다.

#### Value

각 Core Web Vitals에 대한 [지표 값](https://web.dev/cls/#layout-shift-score)입니다. 이 값은 LCP 또는 INP의 경우 밀리초 단위이며, CLS의 경우 점수입니다.

### Largest Contentful Paint에 대해 추가로 수집되는 데이터

#### URL

출처 URL입니다(예: 이미지, 텍스트, 웹 폰트).

#### Size

원본 객체의 바이트 단위 크기입니다.

### Cumulative Layout Shift에 대해 추가로 수집되는 데이터

Layout information은 width, height, x축 위치, y축 위치, left, right, top, bottom을 포함하는 JSON 값입니다. 이 값들은 페이지에서 발생하는 layout shift를 나타냅니다.

#### CurrentRect

페이지 이동이 발생한 뒤, 가장 큰 면적을 가진 DOM 요소의 layout 정보를 캡처합니다. 이 JSON 값은 **Debug View** 섹션에서 **Current**로 표시됩니다. 접근하려면 **Cumulative Layout Shifts (CLS)** 그래프 > **Debug View**로 이동한 뒤, 해당 표에서 어떤 요소든 선택해 **Layout Shifts** 섹션으로 들어가면 됩니다. সেখানে **Current**가 표시됩니다.

#### PreviousRect

페이지 이동이 발생하기 전, 가장 큰 면적을 가진 DOM 요소의 layout 정보를 캡처합니다. 이 JSON 값은 **Debug View** 섹션에서 **Previous**로 표시됩니다. 접근하려면 **Cumulative Layout Shifts (CLS)** 그래프 > **Debug View**로 이동한 뒤, 해당 표에서 어떤 요소든 선택해 **Layout Shifts** 섹션으로 들어가면 됩니다. সেখানে **Previous**가 표시됩니다.
