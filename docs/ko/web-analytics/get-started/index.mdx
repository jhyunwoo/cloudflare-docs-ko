## Cloudflare를 통해 프록시되지 않는 사이트

1. Cloudflare 대시보드에서 **Web Analytics** 페이지로 이동합니다.

   <DashButton url="/?to=/:account/web-analytics" />

2. **Add a site**를 선택합니다.
3. **Set up hostname**에 웹사이트의 호스트명을 입력합니다.
4. 입력한 호스트명을 선택할 수 있도록 나타나는 메시지 상자를 선택한 다음 **Done**을 선택합니다.
5. **Manage site**에서 JS 스니펫을 복사합니다. 이곳은 나중에 방금 추가한 호스트명을 수정할 수 있는 곳이기도 합니다.
6. (선택 사항) **View Analytics sites**를 선택해 Web Analytics 인터페이스로 돌아갑니다. Web Analytics 웹사이트 설정을 계속하려면 계속 읽으세요.
7. 웹사이트의 HTML 페이지 어디에서든 closing body tag 바로 앞에 JS 스니펫을 추가합니다.

이제 웹사이트에 Web Analytics 설정이 완료되었지만, 데이터가 표시되기까지 몇 분 정도 걸릴 수 있습니다.

Web Analytics에서 **Add a site**를 선택해 추적하려는 모든 웹사이트에 대해 3~7단계를 반복하세요. **Web Analytics Sites**에서 각 웹사이트 카드 안의 **Manage site**를 선택하면 언제든지 사이트의 Web Analytics 설정을 조정할 수 있습니다.

추적 가능한 사이트 수에 대한 자세한 내용은 [Limits](/web-analytics/limits/)를 참고하세요.

## Cloudflare를 통해 프록시되는 사이트

<Render file="web-analytics-proxied-setup" product="web-analytics" />

이제 웹사이트는 기본적으로 활성화되어 있는 자동 설정을 통해 Web Analytics를 사용하고 있습니다.

언제든지 **Manage Site**로 이동해 자동 설정을 다음 중 하나로 변경할 수 있습니다.

- **Enable, excluding visitor data in the EU** - EU 방문자에게는 JS Snippet이 삽입되지 않습니다.
- **Enable with JS Snippet installation** - JS Snippet을 수동으로 설치해야 합니다.
- **Disable** - JS Snippet 삽입이 비활성화되며 더 이상 삽입되지 않습니다.

Web Analytics로 추적하려는 모든 웹사이트에 대해 이 단계를 반복하세요. 이전에 Browser Insights를 사용했던 Cloudflare 프록시 사이트에는 Web Analytics가 기본적으로 활성화됩니다. **Manage site**를 선택하면 언제든지 사이트의 Web Analytics 설정을 조정할 수 있습니다.

추적 가능한 사이트 수에 대한 자세한 내용은 [Limits](/web-analytics/limits/)를 참고하세요.

Web Analytics로 어떤 사이트나 페이지를 추적할지 구성하는 방법에 대한 자세한 내용은 [Rules](/web-analytics/configuration-options/rules/)를 참고하세요.

:::caution[Important]

`Cache-Control` 헤더가 `public, no-transform`으로 설정되어 있으면 Cloudflare 프록시는 웹사이트의 원본 payload를 수정할 수 없습니다. 따라서 Beacon 스크립트가 사이트에 자동으로 삽입되지 않으며, Web Analytics가 동작하지 않습니다. 자세한 내용은 [Origin cache control](/cache/concepts/cache-control/)을 참고하세요.

:::
