**Dynamic steering**은 헬스 모니터 데이터를 사용해 주어진 Cloudflare 리전 또는 데이터 센터에 대해 가장 빠른 풀을 식별합니다.

Dynamic steering은 RTT의 지수 가중 이동 평균(EWMA)을 기반으로 RTT 프로필을 생성하여 가장 빠른 풀을 결정합니다. 특정 리전이나 코로케이션 센터에서 풀에 대한 최신 RTT 데이터가 없으면, Cloudflare는 장애 조치 순서에 따라 풀로 트래픽을 보냅니다.

RTT 값은 헬스 프로브 요청이 이루어질 때마다 수집되며, 엔드포인트가 모니터 요청에 응답한 결과를 기준으로 합니다. 요청이 들어오면 Cloudflare는 RTT 데이터를 검사하고 이를 사용해 RTT 값 순으로 풀을 정렬합니다.

풀에 대해 Dynamic steering을 처음 활성화할 때는 Cloudflare가 해당 풀의 RTT 프로필을 구축하는 동안 변경 사항이 적용되기까지 10분 정도 기다리세요.

TCP 헬스 모니터의 경우, 클라우드 제공업체의 에지 위치에서 TCP를 종료하고 있다면 계산된 지연 시간이 엔드포인트까지의 실제 지연 시간을 반영하지 못할 수 있습니다.

아래 다이어그램은 동부 북미, 유럽, 호주 세 리전 중 EWMA가 가장 낮은 풀로 Cloudflare가 트래픽을 어떻게 라우팅하는지 보여줍니다. 이 경우 RTT가 가장 낮기 때문에 ENAM 풀이 선택됩니다.

:::note

Dynamic steering이 기대한 대로 동작하도록 하려면 [Health Monitor Region](/load-balancing/monitors/#health-monitor-regions)을 **All Regions**로 설정해야 합니다.
Enterprise 전용인 **All Data Centers** 옵션도 유효한 대안입니다.

:::
