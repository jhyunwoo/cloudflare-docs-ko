**Geo steering**은 특정 국가, 리전 또는 Enterprise 고객에 한해 데이터 센터에 연결된 풀로 트래픽을 보냅니다.

이 옵션은 사이트 방문자가 자신과 가장 가까운 엔드포인트에 접근하게 하여 페이지 로딩 성능을 개선하고자 할 때 특히 유용합니다.

:::note
사용자 지정 로드 밸런싱 규칙은 Geo steering과 호환되지 않습니다. 따라서 Geo 스티어링된 Load Balancer에 사용자 지정 규칙을 적용하면 기대한 대로 동작하지 않습니다.
:::

## 풀 할당

같은 영역에 여러 풀을 할당할 수 있으며, 로드 밸런서는 이를 장애 조치 순서대로 사용합니다. 데이터 센터, 국가, 리전 중 명시적으로 정의하지 않은 옵션은 모두 기본 풀과 장애 조치 구성을 사용하도록 폴백됩니다.

### 리전 스티어링

Cloudflare에는 전 세계를 아우르는 [13 geographic regions](/load-balancing/reference/region-mapping-api/#list-of-load-balancer-regions)가 있습니다. 클라이언트의 리전은 해당 클라이언트의 DNS 쿼리에 응답한 Cloudflare 데이터 센터의 리전에 따라 결정됩니다.

:::caution

리전에 풀을 추가하면, **Geo steering** 구성에서 제거하기 전까지는 [이 풀을 삭제](/load-balancing/pools/create-pool/#delete-a-pool)할 수 없습니다. 다른 **Traffic Steering** 방식으로 변경해도 이 구성은 자동으로 제거되지 않습니다.
:::

<Tabs syncKey="dashPlusAPI"> <TabItem label="Dashboard">

[로드 밸런서를 생성하거나 편집](/load-balancing/load-balancers/create-load-balancer/)할 때:

1. **Traffic steering** 단계로 이동합니다.
2. **Geo steering**을 선택합니다.
3. **Region**에서 리전을 선택한 다음 **Add Region**을 선택합니다.
4. **Edit**를 선택합니다.
5. 풀을 선택한 다음 **Add Pool**을 선택합니다.
6. 여러 풀을 추가하는 경우 원하는 failback 순서로 다시 정렬합니다.
7. 필요한 경우 리전을 더 추가합니다.

</TabItem> <TabItem label="API">

[Update Load Balancers](/api/resources/load_balancers/methods/update/) 명령의 `regions_pool` 속성을 사용해 리전 배열을 지정합니다. 각 리전은 [적절한 리전 코드](/load-balancing/reference/region-mapping-api/#list-of-load-balancer-regions)와 함께, 해당 리전에서 사용할 엔드포인트 목록으로 지정합니다.

아래 예시에서 `WNAM`과 `ENAM`은 각각 북미 서부 해안과 동부 해안을 나타냅니다.

```json title="Request"
// PUT /zones/:zone_id/load_balancers
{
	"description": "Load Balancer for www.example.com",
	"name": "www.example.com",
	"ttl": 30,
	"proxied": true,
	"fallback_pool": "ff02c959d17f7bb2b1184a202e3c0af7",
	"default_pools": [
		"17b5962d775c646f3f9725cbc7a53df4",
		"ff02c959d17f7bb2b1184a202e3c0af7"
	],
	"region_pools": {
		"WNAM": [
			"17b5962d775c646f3f9725cbc7a53df4",
			"ff02c959d17f7bb2b1184a202e3c0af7"
		],
		"ENAM": [
			"17b5962d775c646f3f9725cbc7a53df4",
			"ff02c959d17f7bb2b1184a202e3c0af7"
		],
		"EEU": [
			"ff02c959d17f7bb2b1184a202e3c0af7",
			"17b5962d775c646f3f9725cbc7a53df4"
		]
	}
}
```

`WNAM`만 정의하면 동부 해안에서 오는 트래픽은 `default_pools`로 라우팅됩니다. 각 위치의 클라이언트를 사용해 이를 테스트할 수 있습니다.

</TabItem> </Tabs>

### 국가 스티어링

<Tabs syncKey="dashPlusAPI"> <TabItem label="Dashboard">

[로드 밸런서를 생성하거나 편집](/load-balancing/load-balancers/create-load-balancer/)할 때:

1. **Traffic steering** 단계에 도달할 때까지 [create a load balancer procedure](/load-balancing/load-balancers/create-load-balancer/#create-a-load-balancer)를 따릅니다.
2. **Geo steering**을 선택합니다.
3. **Country**에서 국가를 선택한 다음 **Add Region**을 선택합니다.
4. **Edit**를 선택합니다.
5. 풀을 선택한 다음 **Add Pool**을 선택합니다.
6. 여러 풀을 추가하는 경우 원하는 failback 순서로 다시 정렬합니다.
7. 필요한 경우 국가를 더 추가합니다.

</TabItem> <TabItem label="API">

[API](/api/resources/load_balancers/methods/create/)를 통해 로드 밸런서를 생성할 때 `country_pools` 객체를 포함해 국가를 풀 ID 목록(장애 조치 우선순위 순)과 매핑합니다.

국가 코드 목록을 가져오려면 [Region API](/load-balancing/reference/region-mapping-api/)를 사용하세요.

명시적으로 정의하지 않은 국가는 먼저 해당 `region_pool` 매핑(있는 경우)을 사용하도록 폴백한 다음, 연결된 기본 풀을 사용합니다.

</TabItem> </Tabs>

### PoP 스티어링

[API](/api/resources/load_balancers/methods/create/)를 통해 로드 밸런서를 생성할 때 `pop_pools` 객체를 포함해 Cloudflare 데이터 센터를 풀 ID 목록(장애 조치 우선순위 순)과 매핑합니다.

데이터 센터 식별자를 찾는 데 도움이 필요하면 [이 커뮤니티 스레드](https://community.cloudflare.com/t/is-there-a-way-to-retrieve-cloudflare-pops-list-and-locations-programmatically/234643)를 참조하세요.

명시적으로 정의하지 않은 데이터 센터는 먼저 해당 `country_pool`, 그다음 `region_pool` 매핑(있는 경우), 마지막으로 연결된 기본 풀을 사용하도록 폴백됩니다.

:::note
PoP steering은 Enterprise 고객만 사용할 수 있으며 API를 통해서만 접근할 수 있습니다.
:::

### 장애 조치 동작

같은 리전에 풀이 하나뿐이고 그 풀이 사용 불가능하면 fallback pool이 사용됩니다.
같은 리전에 여러 풀이 있으면 풀 순서가 그대로 존중됩니다. 예를 들어 첫 번째 풀이 사용 불가능하면 두 번째 풀이 사용됩니다.
