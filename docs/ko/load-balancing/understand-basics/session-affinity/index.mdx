## 유형

세션 어피니티는 `"none"` 또는 `""`(기본값)로 지정하지 않는 한, 로드 밸런서가 사용할 세션 어피니티 유형을 지정합니다.

### Cloudflare 쿠키만 사용

프록시된 로드 밸런서로 첫 요청이 들어오면, 요청이 전달될 엔드포인트 정보를 인코딩한 쿠키가 생성됩니다. 이후 같은 클라이언트가 같은 로드 밸런서로 보내는 후속 요청은, 쿠키의 유효 기간 동안 그리고 해당 엔드포인트가 정상 상태인 한 쿠키에 인코딩된 엔드포인트로 전송됩니다. 쿠키가 만료되었거나 엔드포인트가 비정상 상태이면 새 엔드포인트를 계산해 사용합니다.

### Cloudflare 쿠키 및 Client IP 폴백

이 방식은 `cookie`와 비슷하게 동작하지만, 초기 엔드포인트 선택이 안정적으로 유지되며 클라이언트의 IP 주소를 기반으로 결정됩니다.

### HTTP 헤더 기준

프록시된 로드 밸런서로 첫 요청이 들어오면, 구성된 HTTP 헤더를 기반으로 세션 키가 생성됩니다. 세션 키는 로드 밸런서 세션 상태 동안 요청이 어떤 엔드포인트로 전달될지 저장하는 데 사용되는 요청 헤더를 인코딩합니다. 이후 동일한 헤더를 가진 로드 밸런서 요청은, 세션이 유지되는 동안 그리고 해당 엔드포인트가 정상 상태인 한 같은 엔드포인트로 전송됩니다. 세션이 `session_affinity_ttl` 초 동안 유휴 상태였거나 엔드포인트가 비정상 상태이면 새 엔드포인트를 계산해 사용합니다.

:::note

[Sticky Zero-Downtime Failover](/load-balancing/understand-basics/session-affinity/#zero-downtime-failover)는 HTTP 헤더 기반 세션 어피니티에서는 지원되지 않습니다.

:::

#### 헤더 사용 방식 제어

기본적으로 HTTP 헤더 기반 세션 어피니티에 대해 구성한 HTTP 헤더 중 적어도 하나는 로드 밸런서로 전송되는 요청에 존재해야 헤더 기반 세션이 생성됩니다. 클라이언트가 요청에 HTTP 헤더를 추가하거나 제거했고 이미 세션을 설정한 상태라면, 이후 요청에서 새로 발견된 HTTP 헤더를 기준으로 새 세션이 생성되며, 해당 헤더가 구성에 지정되어 있는 경우에 한합니다.

세션을 생성하려면 구성한 모든 HTTP 헤더가 요청에 존재해야 하도록 하려면, Cloudflare API를 통해 `session_affinity_attributes.require_all_headers`를 `true`로 설정하거나, 로드 밸런서를 편집할 때 Cloudflare 대시보드에서 `Require all headers`를 `enabled`로 전환하세요.

## Cloudflare 대시보드에서 세션 어피니티 활성화

[로드 밸런서를 생성하거나 편집](/load-balancing/load-balancers/create-load-balancer/)할 때 **Hostname** 단계에서 Session Affinity를 활성화합니다.

Session Affinity를 활성화하면 다음 옵션 중 하나를 선택합니다.

- **By Cloudflare cookie only**: 연결된 엔드포인트를 추적하기 위해 `__cflb` 쿠키를 설정합니다.
- **By Cloudflare cookie and Client IP fallback**: `__cflb` 쿠키를 설정하지만, 세션 어피니티 쿠키가 제공되지 않으면 클라이언트 IP 주소도 사용합니다.
- **By HTTP header**.

:::caution[중요]

Session Affinity는 [DNS-only mode (gray cloud)](/load-balancing/understand-basics/proxy-modes/)에서 지원되지 않습니다. 대신 [DNS persistence](/load-balancing/additional-options/dns-persistence/)를 사용할 수 있습니다.

:::

## Cloudflare API로 세션 어피니티 활성화

세션 어피니티는 로드 밸런서의 속성이며, 다음 엔드포인트로 설정할 수 있습니다.

- [Create a load balancer](/api/resources/load_balancers/methods/create/)
- [Edit a load balancer](/api/resources/load_balancers/methods/update/)

`session_affinity`, `session_affinity_ttl`, `session_affinity_attributes` 파라미터를 사용하여 세션 어피니티 동작을 사용자 지정할 수 있습니다.

HTTP 헤더 기반 세션 어피니티를 활성화하려면 `session_affinity` 값을 `header`로 설정하고, HTTP 헤더 이름을 `session_affinity_attributes.headers`에 추가합니다.

문맥 속 API 명령에 대한 자세한 내용은 [Create a load balancer with the API](/load-balancing/load-balancers/create-load-balancer/)를 참조하세요.

## 엔드포인트 드레인

엔드포인트 드레인을 사용하면 활성 고객에게 영향을 주지 않고 엔드포인트의 트래픽을 모두 제거하거나 배출할 수 있습니다. 엔드포인트 드레인에 대한 자세한 내용은 [Performing planned maintenance](/load-balancing/additional-options/planned-maintenance/#gradual-rotation)를 참조하세요.

:::caution[중요]

엔드포인트 드레인은 [DNS-only mode (gray cloud)](/load-balancing/understand-basics/proxy-modes/)의 로드 밸런서에서는 지원되지 않습니다.

:::

## 무중단 장애 조치

Zero-Downtime Failover는 일시적인 네트워크 문제 발생 시 풀 내부의 엔드포인트로 자동으로 트래픽을 보냅니다. 이를 통해 활성 헬스 모니터 사이에서 문제가 발생할 때 사용자에게 표시되는 오류를 줄일 수 있습니다.

다음 세 가지 옵션 중 하나를 활성화할 수 있습니다.

- **None**: 장애 조치가 수행되지 않으며 사용자에게 오류가 표시될 수 있습니다.
- **Temporary**: 원래 고정되어 있던 엔드포인트를 다시 사용할 수 있을 때까지 다른 엔드포인트로 트래픽이 전송됩니다.
- **Sticky**: 세션 어피니티 쿠키가 업데이트되며, 이후 요청은 필요에 따라 새 엔드포인트로 전송됩니다.

:::note

[Sticky Zero-Downtime Failover](/load-balancing/understand-basics/session-affinity/#zero-downtime-failover)는 HTTP 헤더 기반 세션 어피니티에서는 지원되지 않습니다.

:::
