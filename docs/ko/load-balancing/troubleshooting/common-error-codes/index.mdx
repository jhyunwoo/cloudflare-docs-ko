Cloudflare Load Balancing API는 각 pool과 endpoint에 전역 health 정보를 추가합니다. 또한 Cloudflare 네트워크가 더 넓은 범위에서 무엇을 보고 있는지 확인할 수 있게 해 줍니다. Cloudflare는 quorum 시스템을 사용하여 pool과 endpoint의 health 상태를 결정합니다. Quorum은 한 지역에서 health monitor 요청을 실행하는 PoP들의 결과를 바탕으로 하며, 다수의 결과가 사용됩니다.

실패를 문제 해결할 때는 Cloudflare Load Balancing에 프로그래밍 방식으로 접근할 수 있는 Cloudflare API를 사용하세요. Health Monitor Events와 Load Balancer Monitors 경로는 Load Balancing 이벤트 로그에 접근하고 Cloudflare monitor를 다시 구성하는 데 매우 유용한 도구입니다.

List Health Monitor Events 명령을 사용하면 Cloudflare API를 통해 데이터 센터별 endpoint health 세부 정보를 확인할 수 있습니다.

```txt
GET user/load_balancing_analytics/events
```

health monitor 요청이 실패하면, 이 세부 정보에는 그 원인이 포함됩니다.

일반적인 문제 원인과 해결 방법은 아래와 같습니다.

***

## TCP connection failed

### 원인

health monitor 요청이 endpoint와의 TCP 연결을 수립하지 못했습니다.

### 해결 방법

일반적으로 Cloudflare와 endpoint 사이의 네트워크 장애가 발생했거나, 방화벽이 연결을 허용하지 않을 때 이런 문제가 발생합니다. 네트워크 및 방화벽 설정이 Load Balancing 트래픽을 방해하지 않는지 확인하세요.

***

## HTTP timeout occurred

### 원인

endpoint가 설정된 제한 시간 안에 HTTP 응답을 반환하지 못했습니다. 예를 들어 timeout을 1초 또는 2초처럼 매우 낮게 설정했을 때 이런 일이 발생할 수 있습니다.

### 해결 방법

endpoint가 응답할 수 있도록 HTTP 응답 timeout 값을 늘리는 것을 권장합니다.

***

## Response code mismatch error

### 원인

Cloudflare가 HTTP 상태 코드를 수신했지만, 그 값이 Cloudflare monitor 구성의 `expected_codes` 속성에 정의된 값과 일치하지 않습니다.

### 해결 방법

응답 코드는 `expected_codes`와 일치해야 합니다. List Monitors API 명령을 사용해 값이 올바른지 확인하세요.

### 다른 원인

HTTP 연결을 사용하도록 monitor를 구성했는데 endpoint가 HTTPS로 리디렉션하는 경우에도 이 문제가 발생할 수 있습니다. 이 경우 응답 코드는 보통 301, 302 또는 303입니다.

### 해결 방법

Cloudflare monitor 구성을 HTTPS 사용으로 변경하거나, 올바른 상태 코드를 확인할 수 있도록 `follow_redirect` 값을 `true`로 설정하세요.

***

## Response body mismatch error

### 원인

endpoint가 반환한 응답 본문에 monitor에서 구성한 `expected_body` 값이 포함되어 있지 않습니다(대소문자 구분 없음).

Cloudflare는 응답의 처음 10 KB만 읽습니다. 더 큰 응답을 반환하고 `expected_body`가 처음 10 KB 안에 없으면 health monitor 요청은 실패합니다.

### 해결 방법

`expected_body`가 응답 본문의 처음 10 KB 안에 있도록 하세요.

***

## TLS untrusted certificate error

### 원인

인증서가 공용 Certificate Authority(CA)에서 신뢰되지 않습니다.

### 해결 방법

self-signed 인증서를 사용 중이라면, 공용으로 신뢰되는 인증서를 사용하거나 monitor의 `allow_insecure` 속성을 `true`로 설정하는 것을 권장합니다.

***

## TLS name mismatch error

### 원인

health monitor(클라이언트)가 서버 인증서에 있는 이름과 요청 hostname을 일치시키지 못했습니다.

### 해결 방법

List Monitors 명령으로 Cloudflare monitor에 설정된 `header` 값이 올바른지 확인하고, 필요한 변경은 Update Monitors 명령으로 적용하세요.

***

## TLS protocol error

### 원인

이 오류는 오래된 TLS 버전을 사용 중이거나 endpoint가 HTTPS용으로 구성되어 있지 않을 때 발생할 수 있습니다.

### 해결 방법

endpoint가 TLS 1.0 이상을 지원하고 HTTPS용으로 구성되어 있는지 확인하세요.

***

## TLS unrecognized name error

### 원인

서버가 클라이언트가 제공한 이름을 인식하지 못했습니다. host header가 설정되어 있으면 Cloudflare는 초기 TLS handshake에서 이를 ServerName으로 설정합니다. 설정되어 있지 않으면 ServerName을 보내지 않으며, 이 때문에 이 오류가 발생할 수 있습니다.

### 해결 방법

monitor 객체에 host header를 설정하세요.

***

## No route to host error

### 원인

IP 주소에 Cloudflare 네트워크에서 도달할 수 없습니다. 일반적인 원인은 ISP 또는 호스팅 제공업체 네트워크 문제(예: BGP 수준) 또는 IP 자체가 존재하지 않는 경우입니다.

### 해결 방법

IP가 정확한지 확인하고, 정확하다면 ISP 또는 호스팅 제공업체의 네트워크 문제가 있는지 점검하세요.

***

## Exceeded quota error

### 원인

플랜에 포함된 수보다 더 많은 객체(monitors, pools, endpoints)를 생성하려고 하면 이 오류를 받게 됩니다.

대시보드를 사용하는 경우 추가 객체를 만들 수 없습니다.

**Cloudflare API**를 사용하는 경우에는 오류 메시지가 반환됩니다.

### 해결 방법

* 더 많은 객체(load balancers, pools, endpoints, monitors)를 생성해야 하는 Enterprise 고객은 account team에 문의해 이 문제를 상의해야 합니다.
* Self-service 고객은 더 많은 endpoints가 포함된 Load Balancing 구독으로 업그레이드해 용량을 늘릴 수 있습니다.

***

## TCP Timeout

### 원인

데이터 전송이 확인되지 않았고, 데이터 재전송도 성공하지 못했습니다.

### 해결 방법

handshake에 대한 SYN-ACK가 endpoint에서 실제로 발생하는지 확인하고 [Cloudflare Support](/support/contacting-cloudflare-support/)에 문의하세요.

***

## TLS Handshake Failure

### 원인

브라우저와 웹 서버 간 연결이 안전하지 않음을 나타냅니다.

### 해결 방법

Wi-Fi 네트워크를 변경하거나 유선 네트워크에 연결하고, 네트워크 연결이 안정적인지 확인하세요.

***

## Network Unreachable

### 원인

네트워크를 사용할 수 없어 Cloudflare가 endpoint에 연결할 수 없습니다. 이는 일반적으로 네트워크 문제 또는 잘못된 IP 때문에 발생합니다.

### 해결 방법

Cloudflare Load Balancer 구성에서 endpoint에 입력한 IP 또는 endpoint hostname에 대해 DNS가 반환하는 IP를 확인하세요.

***

## HTTP Invalid Response

### 원인

보통 HTTP 502 오류 또는 bad gateway가 원인입니다.

### 해결 방법

endpoint가 요청에 응답하는지, 그리고 어떤 애플리케이션도 비정상 종료되었거나 과부하 상태가 아닌지 확인하세요.

***

## DNS Unknown Host

### 원인

endpoint hostname이 존재하지 않습니다.

### 해결 방법

endpoint가 IP 주소로 확인되는지 점검하세요.

***

## Connection Reset by Peer

### 원인

클라이언트가 endpoint에서 데이터를 수신하는 동안 네트워크 오류가 발생했습니다.

### 해결 방법

endpoint에 많은 트래픽이 몰리고 있거나 오류가 발생했는지 확인하세요.

***

## Monitor Config Error

### 원인

monitor 구성에 오류가 있어 pool endpoint에 대해 검사가 실행되지 않습니다.

### 해결 방법

monitor 구성이 endpoint에 예상되는 요청과 일치하는지 검토하세요.

***

## DNS Internal

### 원인

endpoint의 hostname이 내부 IP 주소 또는 orange-clouded IP 주소로 확인됩니다. 이 경우 pool endpoint에 대해 검사가 실행되지 않습니다.

### 해결 방법

Cloudflare는 Cloudflare를 통해 프록시되는 endpoint hostname의 사용을 허용하지 않습니다.

***

## Load Balancing Not Enabled

### 원인

account 또는 zone에 대해 Load Balancing이 활성화되어 있지 않습니다.

### 해결 방법

Enterprise 고객은 Cloudflare Account Team에 문의하세요. Free, Pro, Business 고객은 [Load Balancing 활성화](/load-balancing/get-started/enable-load-balancing/)를 진행해야 합니다.

***

## Validation failed error

### 원인

Load Balancer endpoint를 구성하는 동안 host header 값을 설정하려고 하면 이 오류를 받게 됩니다.

### 해결 방법

Cloudflare는 이제 구성된 [endpoint host headers](/load-balancing/additional-options/override-http-host-headers/)를 account와 연결된 zone의 직속 하위 도메인인 정규화된 도메인 이름(FQDN)으로 제한합니다. 예를 들어 이 host header는 Load Balancer 자체와 동일한 zone에 속하지만, pool은 여러 Load Balancer에서 함께 사용할 수 있습니다.

***

## Object referenced by other objects

### 원인

Load Balancer의 [geo steering](/load-balancing/understand-basics/traffic-steering/steering-policies/geo-steering/) 지역에서 참조 중인 pool을 삭제하려고 하면 이 오류가 발생합니다.

### 해결 방법

Load Balancer의 geo steering 구성에서 해당 pool을 제거하세요. Load Balancer가 더 이상 geo steering을 사용하지 않는다면, 먼저 [geo steering을 다시 활성화](/load-balancing/understand-basics/traffic-steering/steering-policies/geo-steering/)한 다음 pool을 제거해야 합니다.

***

## Other Failure

### 원인

위에 언급된 다른 실패 유형으로 분류할 수 없는 경우입니다.

### 해결 방법

[Cloudflare Support](/support/contacting-cloudflare-support/)에 문의하세요.
