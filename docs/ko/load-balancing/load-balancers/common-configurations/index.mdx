다음 섹션을 참고하여 자주 사용되는 로드 밸런서 구성을 어떻게 구현할 수 있는지 이해해 보세요.

이 페이지는 Cloudflare [Load Balancing components](/load-balancing/understand-basics/load-balancing-components/)와 각 구성 요소를 생성하고 수정하는 방법을 이미 이해하고 있다고 가정합니다.

<div id="active---passive-failover" />

## Active - Passive Failover

**active-passive failover**는 활성 풀의 엔드포인트로 트래픽을 보내다가 실패 임계값(구성 가능)에 도달하면, 그 시점에 로드 밸런서가 수동(passive) 풀로 트래픽을 전환합니다.

이 설정은 서비스 중단 없이 운영할 수 있게 하고 계획된 장애에도 도움이 되지만, 전체 트래픽 속도는 다소 느려질 수 있습니다.

**active-passive failover**로 로드 밸런서를 설정하려면 다음과 같이 하세요.

1. 두 개의 풀(`primary`와 `secondary`)로 로드 밸런서를 생성합니다.
2. 풀 목록에서 다음 순서로 배치합니다.
   1. `primary`
   2. `secondary`
3. **Traffic Steering**에서 [**Off**](/load-balancing/understand-basics/traffic-steering/steering-policies/standard-options/#off---failover)를 선택합니다.

이 구성을 사용하면 `primary`의 사용 가능한 엔드포인트 수가 **Health Threshold**에 지정한 값보다 적어질 때까지 모든 트래픽이 `primary`로 전달됩니다. 그 이후에만 로드 밸런서가 `secondary`로 트래픽을 보냅니다.

모든 풀이 다운으로 표시되는 경우 Cloudflare는 **fallback pool**을 사용합니다. fallback pool은 엔드포인트로 트래픽을 성공적으로 보내기 위한 최후의 수단입니다. fallback pool은 마지막 수단이므로 해당 풀의 상태는 헬스 판단에 반영되지 않으며, Cloudflare는 상태를 **No Health**로 보고합니다. fallback pool은 API 또는 Cloudflare 대시보드에서 선택할 수 있습니다. fallback pool을 다루는 방법에 대한 자세한 내용은 [Pool-level steering](/load-balancing/understand-basics/traffic-steering/steering-policies/)을 참고하세요.

## Active - Active Failover

**active-active failover**는 같은 풀 안의 엔드포인트들로 트래픽을 분산하다가 풀이 실패 임계값(구성 가능)에 도달하면, 그 시점에 로드 밸런서가 **fallback pool**로 트래픽을 다시 보냅니다.

이 설정은 전체 요청 속도를 높여 주지만, 계획된 장애나 예기치 않은 장애에는 더 취약합니다.

**active-active failover**로 로드 밸런서를 설정하려면 다음 중 하나를 선택하세요.

* 여러 엔드포인트(`endpoint-1`, `endpoint-2`)를 가진 단일 풀(`primary`)로 로드 밸런서를 생성하고, 각 엔드포인트에 동일한 [**Weight**](/load-balancing/understand-basics/traffic-steering/origin-level-steering/#weights)를 설정합니다.
* 두 개의 풀(`primary`, `secondary`)로 로드 밸런서를 생성하고, [**Traffic Steering**](/load-balancing/understand-basics/traffic-steering/steering-policies/)에는 **Off**를 제외한 아무 옵션이나 선택합니다.

:::note


서버 페일오버와 일반적인 구성에 대한 추가 배경 정보는 [our Learning Center](https://www.cloudflare.com/learning/performance/what-is-server-failover/)를 참고하세요.


:::
