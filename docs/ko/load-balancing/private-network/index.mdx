Private Network Load Balancing을 사용하면 데이터 센터 내부 서버 간([endpoint steering](/load-balancing/understand-basics/traffic-steering/origin-level-steering/)) 및 프라이빗 애플리케이션 간의 트래픽을 로드 밸런싱할 수 있습니다. 이를 통해 하드웨어 어플라이언스의 필요성을 줄이고 인프라를 클라우드로 마이그레이션하는 데 도움이 되며, 탄력적인 확장성과 향상된 안정성 같은 이점을 제공합니다.

Private Network Load Balancing은 엔드포인트 값으로 퍼블릭 IP뿐 아니라 가상 IP와 프라이빗 IP도 지원합니다.

:::note

이 페이지는 Cloudflare Load Balancing 솔루션이 어떻게 동작하는지에 어느 정도 익숙하다고 가정합니다. 입문용 개요는 [Load Balancing components](/load-balancing/understand-basics/load-balancing-components/)를 참고하세요.
:::

## 오프램프

오프램프는 Cloudflare가 퍼블릭하게 공개되지 않은 네트워크에 직접적이고 안전하게 연결할 수 있도록 해줍니다.

트래픽 스티어링 결정이나 페일오버 메커니즘은 풀과 엔드포인트의 상태 정보에 의존하므로, 가상 IP 또는 프라이빗 IP를 로드 밸런서의 엔드포인트로 직접 입력할 수 있으면 기존 헬스 모니터링을 더 효과적으로 활용할 수 있습니다.

### Tunnel

현재 프라이빗 IP 오리진에 연결하려면 Cloudflare load balancer에는 연결된 [virtual network (VNet)](/cloudflare-one/networks/connectors/cloudflare-tunnel/private-net/cloudflared/tunnel-virtual-networks/)이 포함된 [Cloudflare tunnel](/cloudflare-one/networks/connectors/cloudflare-tunnel/)이 필요합니다. [published application route](/cloudflare-one/networks/connectors/cloudflare-tunnel/routing-to-tunnel/public-load-balancers)를 사용해 엔드포인트에 연결하는 경우에는 VNet이 필요하지 않습니다.

엔드포인트와 virtual network(VNet) 터널 연결이 구성되면 Cloudflare는 터널 상태뿐 아니라 해당 가상 IP 또는 프라이빗 IP 대상의 상태도 판단할 수 있습니다.

자세한 가이드는 [Set up Private Network Load Balancing for Public traffic to Tunnel](/load-balancing/private-network/public-to-tunnel/)을 참고하세요.

<div id="cloudflare-wan" />

### Cloudflare WAN

Private Network Load Balancing은 GRE, IPSec, CNI 터널과 같은 Cloudflare WAN(이전 Magic WAN) 터널에 대한 오프램프 트래픽도 지원합니다. 자세한 내용은 [Set up Private Network Load Balancing with Cloudflare WAN](/load-balancing/private-network/cloudflare-wan/)을 참고하세요.

## 온램프

반대로 Private Network Load Balancing 온램프는 최종 사용자 요청과 Cloudflare 네트워크 사이의 안전한 경로를 뜻합니다. Cloudflare Load Balancing은 [CDN](/cache/), [Spectrum](/spectrum/), [WARP](/cloudflare-one/team-and-resources/devices/warp/), [Cloudflare WAN](/cloudflare-wan/)에서 들어오는 트래픽을 지원하며, 이 트래픽을 로드 밸런서로 전달한 뒤 임의의 오프램프(CDN/CNI/IPSec/GRE/Tunnel) 뒤에 있는 엔드포인트로 내보낼 수 있습니다. 트래픽은 어떤 온램프/오프램프 조합으로든 유입 및 유출될 수 있습니다.

:::note
[Spectrum](/spectrum/)을 온램프로 사용하고 [Cloudflare WAN](/load-balancing/private-network/#cloudflare-wan)을 오프램프로 사용할 때는 Spectrum의 [proxy protocol](/spectrum/how-to/enable-proxy-protocol/) 설정이 지원되지 않습니다.
:::

## 사용 사례

- **퍼블릭 인터넷에서 시작되어 프라이빗/내부 서비스로 향하는 요청**: [Cloudflare Tunnel](/cloudflare-one/networks/connectors/cloudflare-tunnel/)을 사용해 인터넷에서 들어오는 요청을 회계 시스템이나 생산 자동화 시스템 같은 내부 IP 기반 서비스로 라우팅할 수 있습니다.

- **지능적인 트래픽 라우팅**: 프라이빗 트래픽에 대한 페일오버를 활용하고, 단순히 터널의 상태만 모니터링하는 대신 이러한 IP 대상의 상태를 직접 모니터링할 수 있습니다.

- **비표준 포트에서 애플리케이션 호스팅**: 비표준 포트를 사용하는 프라이빗 IP 주소의 애플리케이션으로 트래픽을 쉽게 지정하고 라우팅할 수 있으므로, 기존 인프라 변경 없이도 더 유연한 서비스 구성이 가능합니다.

- **Public 및 Private Load Balancer**: Public LB는 인터넷 트래픽을 프라이빗 IP 주소로 전달할 수 있어 WAF, API Shield 같은 모든 L7 제품을 지원합니다. Private LB는 프라이빗 네트워크에서 시작된 트래픽을 프라이빗 IP 주소로 전달하며 WARP 또는 Cloudflare WAN 같은 온램프가 필요합니다.
