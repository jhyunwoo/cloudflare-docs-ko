Load Balancing 규칙에서 지원하는 필드는 Cloudflare가 로드 밸런서를 통과하는 트래픽을 프록시하는지 여부에 따라 달라집니다.

잘못된 필드 집합을 사용하면 예상치 못한 동작이 발생할 수 있습니다. 최상의 결과를 얻으려면 트래픽의 [proxy status](/load-balancing/understand-basics/proxy-modes/)에 맞는 필드를 사용하세요.

또한 일부 Load Balancing 규칙 필드는 [Load Balancing 표현식](/load-balancing/additional-options/load-balancing-rules/expressions/#working-with-expressions)에 설명된 것처럼 Expression Builder에서 사용할 수 있지만, 다른 필드는 API 또는 [Expression Editor](/load-balancing/additional-options/load-balancing-rules/expressions/#expression-editor)를 통해 수동으로만 구성할 수 있습니다.

## Expression Builder 필드 세트

[Expression Builder](/load-balancing/additional-options/load-balancing-rules/expressions/#expression-builder)에서 사용할 수 있는 필드가 어떻게 그룹화되어 있는지 이해하려면 다음 표를 참고하세요.

| 필드 세트 | Expression Builder의 섹션 | 설명 |
| --------- | ------------------------- | ---- |
| [프록시 여부와 관계없이 지원되는 필드](#fields-supported-regardless-of-proxy) | `BOTH` | 로드 밸런서의 proxy status와 관계없이 항상 접근할 수 있는 값입니다. |
| [프록시 전용 필드](#proxied-only-fields) | `PROXIED ONLY` | 로드 밸런서가 프록시될 때만 접근할 수 있는 값입니다. |
| [비프록시 전용 필드](#unproxied-only-fields) | `NON-PROXIED ONLY` | 로드 밸런서가 프록시되지 않을 때만 접근할 수 있는 값입니다(DNS-only 트래픽). |

				</p>

				</p>
				<p>
					<strong>사용 중단 경고:</strong> 향후에는 프록시되지 않은 요청에서 이 필드가 항상 클라이언트 리졸버 IP 주소로 설정될 예정입니다. ECS 존재 여부를 확인하고 ECS IP를 사용하려면 각각{" "}
					<a href="#field-dns-rr-opt-client">

					</a>

					<a href="#field-dns-rr-opt-client-addr">

					</a>
					필드를 참고하세요.
				</p>
				<p>
					예시 값:
					<br />
					<code class="InlineCode">1.2.3.4</code>
				</p>
			</td>
		</tr>

				<p>

## 연산자 및 그룹 기호

- **비교 연산자**는 표현식에 정의된 값이 실제 HTTP 요청 값과 어떤 관계여야 표현식이 true를 반환하는지 지정합니다.

- **논리 연산자**는 두 표현식을 결합해 하나의 복합 표현식을 만들고, 우선순위에 따라 표현식을 어떻게 평가할지 결정합니다.

- **그룹 기호**는 표현식을 정리하고, 연산자 우선순위를 강제하며, 표현식을 중첩할 수 있게 해줍니다.

예시와 사용법은 Rules language 문서의 [연산자 및 그룹 기호](/ruleset-engine/rules-language/operators/)를 참고하세요.
