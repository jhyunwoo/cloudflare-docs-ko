애플리케이션 설정을 변경하거나 새 자산을 추가할 때는 보통 한 번에 하나의 엔드포인트에서 변경을 적용하는 것이 좋습니다. 엔드포인트별로 순차 진행하면 변경에 따른 위험을 줄이고 더 일관된 사용자 경험을 보장할 수 있습니다.

엔드포인트를 점진적으로 순환 대상에서 제외하려면(세션 기반 로드 밸런싱에서 중요함) 로드 밸런서에서 [endpoint drain을 활성화](#gradual-rotation)하세요. 이 옵션은 [proxied load balancer(orange-clouded)](/load-balancing/understand-basics/proxy-modes/)에서만 사용할 수 있습니다.

엔드포인트에서 즉시 트래픽을 우회시키려면 [풀 또는 모니터 설정을 조정](#immediate-rotation)하세요.

:::note


엔드포인트가 비정상 상태가 되는 것을 막기 위해 트래픽을 다른 곳으로 우회하려는 목적이라면 [Load Shedding](/load-balancing/additional-options/load-shedding/)을 대신 사용하세요.


:::

## 시작 전에

엔드포인트를 비활성화하기 전에, 영향을 받는 모든 로드 밸런서와 풀의 설정을 검토하세요.

풀이 **Health Threshold** 아래로 떨어지면 **Unhealthy**로 간주되며, 로드 밸런서 설정과 steering policy에 따라 로드 밸런서가 해당 풀로부터 트래픽을 다른 곳으로 라우팅하기 시작할 수 있습니다.

## 점진적 순환 제외

:::note


Endpoint drain은 [proxied load balancer(orange-clouded)](/load-balancing/understand-basics/proxy-modes/)에서만 사용할 수 있습니다.


:::

[세션 기반 로드 밸런싱](/load-balancing/understand-basics/session-affinity/)에서는 특정 최종 사용자의 모든 요청을 특정 엔드포인트로 보내는 것이 중요합니다. 그렇지 않으면 장바구니 항목과 같은 사용자 세션 정보가 손실되어 비즈니스에 부정적인 결과를 초래할 수 있습니다.

세션 연속성을 유지하면서 엔드포인트를 순환 대상에서 제거하려면 로드 밸런서에 **Endpoint drain**을 설정하세요.

1. 새 로드 밸런서 또는 기존 로드 밸런서에서 **Hostname** 단계로 이동합니다.
2. **Session Affinity**가 활성화되어 있는지 확인합니다.
3. **Endpoint drain duration**에 초 단위 시간을 입력합니다. 이 값이 **Session TTL** 값보다 작으면 기존 세션에 영향을 주게 됩니다.
   ![Endpoint drain이 포함된 session affinity 구성 예시](~/assets/images/load-balancing/session-affinity-3.png)
4. 로드 밸런서 변경 사항을 저장합니다.
5. **Manage Pools**를 클릭합니다.
6. 엔드포인트를 비활성화합니다. 로드 밸런서가 해당 엔드포인트에서 세션을 점진적으로 비우기 시작합니다.
7. 로드 밸런서에서 풀을 펼쳐 비활성화된 엔드포인트를 찾습니다. 예상 **Drain Time**이 카운트다운되는 것을 볼 수 있습니다.
   ![로드 밸런서 drain 진행 중을 보여주는 예시](~/assets/images/load-balancing/session-affinity-4.png)
8. drain 상태가 **Complete**가 되면 더 이상 해당 엔드포인트에 연결이 남아 있지 않습니다.
   ![로드 밸런서 drain 완료를 보여주는 예시](~/assets/images/load-balancing/session-affinity-5.png)
9. 필요한 유지 관리 또는 업그레이드를 수행합니다.
10. 엔드포인트를 다시 서비스에 투입하려면 다시 활성화합니다.

## 즉시 순환 제외

엔드포인트에서 트래픽을 즉시 우회시키려면 다음을 수행하세요.

1. 다음 중 하나를 수행합니다.
   * 엔드포인트의 [모니터](/load-balancing/monitors/)에서 **Response Body** 또는 **Response Code**에 잘못된 값을 넣는 등, 해당 엔드포인트가 헬스 모니터 요청에 실패하도록 모니터 설정을 업데이트합니다.
   * 풀에서 엔드포인트를 비활성화합니다.
   * 풀에서 [endpoint weight](/load-balancing/understand-basics/traffic-steering/origin-level-steering/#weights)를 `0`으로 설정합니다(단, 동일한 엔드포인트가 여러 풀에 포함되어 있으면 여전히 트래픽이 도달할 수 있습니다).
2. [Load Balancing Analytics](/load-balancing/reference/load-balancing-analytics/)를 모니터링하여 어떤 요청도 해당 풀에 도달하지 않는지 확인합니다.
   * [DNS-only load balancing(gray-clouded)](/load-balancing/understand-basics/proxy-modes/)을 사용 중이라면 DNS 리졸버 캐시 때문에 변경 사항 반영이 지연될 수 있습니다.
3. 필요한 유지 관리 또는 업그레이드를 수행합니다.
4. **1단계**에서 적용한 변경을 되돌립니다.
