이 튜토리얼은 Cloudflare의 글로벌 트래픽 관리를 활용하는 방법을 소개하는 입문용 예제입니다.

다음 섹션에서는 [active-passive failover](/load-balancing/load-balancers/common-configurations/#active---passive-failover) 로드 밸런서를 설정하는 과정을 안내합니다. 이때 [Cloudflare Pages](/pages/)를 <GlossaryTooltip term="endpoint" link="/load-balancing/understand-basics/load-balancing-components/#endpoints">엔드포인트</GlossaryTooltip> 중 하나로 사용하며, Load Balancing 대시보드 워크플로우와 중요한 필드 값, 트러블슈팅 포인트도 함께 설명합니다.

<div id="use-cases" />

## 사용 사례

이 구성은 프로덕션 웹사이트나 애플리케이션을 Pages로 마이그레이션하는 경우, 또는 기본 오리진이 다운되었을 때를 대비한 백업이나 맞춤형 웹 페이지를 두고 싶은 경우에 유용합니다.

## 시작하기 전에

다음을 확인하세요.

- Cloudflare [Load Balancing components](/load-balancing/understand-basics/load-balancing-components/)에 익숙해야 합니다.
- 도메인을 소유하고 있으며 Cloudflare를 [primary DNS provider](/dns/zone-setups/full-setup/)로 사용해야 합니다.
- Cloudflare Pages로 [웹사이트 또는 애플리케이션을 배포](/pages/get-started/git-integration/)해 두어야 합니다.
- 계정에서 [Load Balancing을 활성화](/load-balancing/get-started/enable-load-balancing/)해 두어야 합니다.

## 헬스 모니터 생성

**Create Load Balancer** 워크플로우 안에서 모든 구성 요소를 만들 수도 있지만, **Manage Monitors**와 **Manage Pools** 섹션을 별도로 사용하면 각 구성 요소의 설정을 로드 밸런서로 묶기 전에 더 쉽게 테스트하고 문제를 해결할 수 있습니다.

모니터는 엔드포인트를 정상 또는 비정상으로 판단하는 기준을 정의합니다. 먼저 다음과 같이 모니터를 설정하세요.

1. Cloudflare 대시보드에서 **Load Balancing** 페이지로 이동합니다.

   <DashButton url="/?to=/:account/load-balancing" />

2. **Monitors** 탭을 선택한 다음 **Create monitor**를 선택합니다.
3. 모니터에 설명적인 이름을 지정하고, 나머지 필드가 다음과 같이 채워져 있는지 확인합니다.

| Field | Value |
| ----- | ----- |
| Type  | HTTP  |
| Path  | /     |
| Port  | 80    |

4. **Advanced health check settings**에서 기본값을 유지하고 **Follow Redirects** 옵션을 활성화합니다.

   Cloudflare Pages 같은 서비스를 사용할 때는, 헬스 모니터 요청뿐 아니라 방문자 요청도 목적지에 도달하기 전에 리디렉션될 수 있습니다. 이 옵션을 활성화하면 실제로는 단지 리디렉션(`301` 코드 등)되었을 뿐인데도 모니터가 엔드포인트를 비정상으로 보고하는 일을 방지할 수 있습니다.

:::note[팁]

정의한 파라미터를 기준으로 모니터 이름을 지을 수 있습니다. 예: `HTTP - 200 - Follow Redirects`

이렇게 하면 나중에 이 모니터를 다른 엔드포인트에도 연결할 때 어떤 기준을 사용하는지 쉽게 기억할 수 있습니다.
:::

5. **Save**를 선택해 확인합니다.

## 풀 생성

풀은 헬스 모니터 요청과 방문자 요청이 어디로 전달될지를 담고 있는 정보입니다.

위에서 언급한 [사용 사례](#use-cases)를 지원하고, 프로덕션 웹사이트용 오리진 서버가 하나이며 Cloudflare Pages 인스턴스용 오리진도 하나라고 가정하면, 각각 엔드포인트 하나를 가진 두 개의 풀을 만드세요.

:::caution[중요]

[Cloudflare Pages](/pages/)를 가리키는 엔드포인트는 올바르게 해석되도록 프로젝트 도메인(`<project>.pages.dev`)을 **host header**에 반드시 입력해야 합니다. 올바른 설정에 대한 참조 표는 아래 8단계에서 확인할 수 있습니다.

host header를 추가하지 않으면 모니터에서는 [response code mismatch error](/load-balancing/troubleshooting/common-error-codes/#response-code-mismatch-error)가 발생하고, 방문자 측에서는 로드 밸런서가 비정상 모니터 상태에도 불구하고 활성화된 경우 [Error 1000: DNS points to prohibited IP](/support/troubleshooting/http-status-codes/cloudflare-1xxx-errors/error-1000/)가 발생합니다.
:::

1. Cloudflare 대시보드에서 **Load Balancing** 페이지로 이동합니다.

   <DashButton url="/?to=/:account/load-balancing" />

2. **Pools** 탭을 선택한 다음 **Create monitor**를 선택합니다.

3. 첫 번째 풀에서는 다음 필드를 먼저 입력합니다.

- 풀 이름(고유해야 함). 예시: `primary`
- 이름을 보충 설명할 설명. 예시: `production website`

4. [**Endpoint Steering**](/load-balancing/understand-basics/traffic-steering/origin-level-steering/) 선택은 그대로 둡니다. 각 풀에는 엔드포인트가 하나뿐이므로 이 경우에는 이 스티어링 방식이 영향을 주지 않습니다.

5. 다음 정보를 사용해 오리진 서버를 엔드포인트로 추가합니다.

- 엔드포인트 이름(고유해야 함). 예시: `my-website`.
- 엔드포인트 IP 주소 또는 호스트명.

  :::caution

  아래 8단계 예시처럼 Cloudflare를 엔드포인트로 사용할 때는 Cloudflare anycast IP 주소 중 하나를 지정하지 마세요. 이 IP는 언제든 변경될 수 있으므로, 대신 호스트명을 사용해야 합니다.
  :::

- 엔드포인트 [weight](/load-balancing/understand-basics/traffic-steering/origin-level-steering/#weights)는 `1`로 설정할 수 있습니다. 각 풀에 엔드포인트가 하나뿐이므로 이 경우 엔드포인트 weight는 차이를 만들지 않습니다.
- **Add host header**를 선택해 [hostname](/load-balancing/additional-options/override-http-host-headers/)을 추가합니다.

  :::caution

  프로덕션 웹사이트가 Cloudflare Pages 같은 플랫폼에 호스팅되어 있고, 기본 서브도메인(`example.pages.dev`)을 사용한 뒤 [custom domain](/pages/configuration/custom-domains)(`my-app.com`)을 구성한 경우에는 헬스 모니터 요청이 실패하지 않도록 host header를 추가해야 합니다.
  :::

6. 다음 정보로 첫 번째 풀 구성을 마무리합니다.

- **Health Threshold**는 `1`로 둡니다. 각 풀에 엔드포인트가 하나뿐이므로 이 필드에서 가능한 값은 이것뿐입니다.
- 이전 단계에서 구성한 **Monitor**를 선택합니다.
- Cloudflare가 어떤 [위치](/load-balancing/monitors/#health-monitor-regions)에서 주기적으로 모니터 요청을 보내 엔드포인트 상태를 테스트할지 선택하기 위해 **Health Check Regions**를 선택합니다.

7. **Save**를 선택합니다.

8. 두 번째 풀도 같은 과정을 반복하되 다음 값을 사용합니다.

| Field | Value |
| -------------------------- | ----------------------------------------- |
| Pool name | `secondary` |
| Description | `Pages version` |
| Endpoint steering | `<default>` |
| Endpoint name | `my-pages-website` |
| Endpoint address | `<your custom domain or Pages subdomain>` |
| Weight | `1` |
| Host (**Add host header**) | `<your custom domain or Pages subdomain>` |
| Health threshold | `1` |
| Monitor | `<monitor defined on previous step>` |
| Health check regions | `<select region of your choice>` |

## 엔드포인트 상태 확인

로드 밸런서를 설정하기 전에 다음을 확인하세요.

1. Cloudflare 대시보드에서 **Load Balancing** 페이지로 이동합니다.

   <DashButton url="/?to=/:account/load-balancing" />

1. **Pools** 탭으로 이동합니다.
1. 목록에서 생성한 풀을 찾아 상태가 `Healthy`인지 확인합니다. 페이지를 새로 고쳐야 할 수도 있습니다.
1. 각 풀 항목을 펼쳐 그 안의 엔드포인트 상태도 `Healthy`인지 확인합니다.

기본 원리는 프로덕션 웹사이트와 Cloudflare Pages 프로젝트가 모두 실제로 서비스 중이고 브라우저에서 직접 접근 가능하다면, 모니터도 HTTP 응답으로 `200` 코드를 받아야 한다는 것입니다.

풀이나 모니터 설정이 위 지침을 따랐는지 다시 확인하세요. 그래도 문제가 있다면 [Troubleshooting](/load-balancing/troubleshooting/common-error-codes/) 또는 [FAQ](/load-balancing/troubleshooting/load-balancing-faq/#why-is-my-endpoint-or-pool-considered-unhealthy)를 참고하세요.

## 로드 밸런서 생성

엔드포인트와 모니터가 올바르게 설정되어 있고 예상한 상태를 반환하는 것을 확인한 뒤 로드 밸런서를 생성합니다.

1. Cloudflare 대시보드에서 **Load Balancing** 페이지로 이동합니다.

   <DashButton url="/?to=/:account/load-balancing" />

2. **Create load balancer**를 선택합니다.

3. **Hostname** 페이지에서 다음을 구성한 뒤 **Next**를 선택합니다.
   - **Hostname**을 입력합니다. 이것은 로드 밸런서가 제공되는 DNS 이름입니다. 예를 들어 지금은 `lb` 같은 임시 호스트명(전체 값은 `lb.<your_domain>`)을 사용할 수 있습니다.
   - 주황색 구름 아이콘을 전환해 [proxy mode](/load-balancing/understand-basics/proxy-modes/)를 업데이트합니다. 이 설정은 트래픽이 어떻게 라우팅되고 어떤 IP 주소가 광고되는지에 영향을 줍니다.
   - [session affinity](/load-balancing/understand-basics/session-affinity/)와 [adaptive routing](/load-balancing/understand-basics/adaptive-routing/)에 대한 원하는 옵션을 선택합니다.

4. **Add a Pool** 페이지에서 다음을 구성한 뒤 **Next**를 선택합니다.
   - 이전에 만든 첫 번째 풀을 선택하고 **Add Pool**을 선택합니다.
   - 두 번째 풀도 같은 방식으로 추가하고 필요하면 순서를 바꿉니다. 이 튜토리얼에서는 프로덕션 웹사이트 풀이 첫 번째(`primary`), Cloudflare Pages 풀이 두 번째(`secondary`)가 됩니다.
   - 필요하면 [**Fallback Pool**](/load-balancing/understand-basics/health-details/#fallback-pools)을 업데이트합니다. 이 튜토리얼에서는 이를 보조 풀인 secondary로 그대로 두어도 됩니다.

5. **Monitors** 페이지에서 풀에 연결된 모니터와 예상 상태를 검토한 뒤 **Next**를 선택합니다.

6. **Traffic Steering** 페이지에서 **Off**가 선택되어 있는지 확인합니다. 이렇게 하면 로드 밸런서는 **Add a Pool** 섹션(위 3단계)에서 정한 순서를 따르게 되어 [Active - Passive Failover](/load-balancing/load-balancers/common-configurations/#active---passive-failover) 구성이 됩니다.

7. 이 튜토리얼에서는 [**Custom Rules**](/load-balancing/additional-options/load-balancing-rules/) 옵션을 비워 둡니다.

8. **Review** 페이지에서 구성을 검토한 뒤 **Save as Draft**를 선택합니다.

정의한 호스트명으로 `LB` 타입의 DNS 레코드가 [**DNS** > **Records**](https://dash.cloudflare.com/?to=/:account/:zone/dns/records)에 생성되고, 이에 대응하는 로드 밸런서가 [**Load Balancing**](https://dash.cloudflare.com/?to=/:account/load-balancing)에 추가됩니다.

## 선택 사항 - 테스트 호스트명에 배포

로드 밸런서에 임시 호스트명을 사용했다면, 아래 단계에 따라 배포하고 테스트하세요.

1. Cloudflare 대시보드에서 **Load Balancing** 페이지로 이동합니다.

   <DashButton url="/?to=/:account/load-balancing" />

2. **Load Balancers** 목록에서 테스트 호스트명(`lb` 등)으로 생성한 로드 밸런서를 찾아 활성화합니다.
3. 브라우저에서 임시 호스트명(`lb.example.com`)에 요청을 보냅니다. 기본 오리진 서버에 호스팅된 웹사이트나 애플리케이션이 보여야 합니다.
4. **Manage Load Balancers** 목록으로 돌아가 테스트용 로드 밸런서를 펼친 뒤 기본 풀을 비활성화합니다.
5. 브라우저의 새 시크릿 창에서 임시 호스트명에 다시 요청을 보냅니다. 이번에는 보조 오리진 서버에 호스팅된 웹사이트나 애플리케이션이 보여야 합니다.

   문제가 있다면 풀, 모니터, 로드 밸런서 구성이 위 지침을 따랐는지 다시 확인하세요. 필요하면 [Troubleshooting](/load-balancing/troubleshooting/common-error-codes/) 또는 [FAQ](/load-balancing/troubleshooting/load-balancing-faq/)도 참고하세요.

:::caution[중요]

모든 것이 제대로 작동하는 것을 확인한 후에는 로드 밸런서 안의 풀을 다시 활성화해야 합니다.
:::

## 프로덕션 트래픽을 로드 밸런서로 라우팅

이제 로드 밸런서를 설정하고 동작을 확인했으므로, 실제 도메인 또는 서브도메인에 로드 밸런서를 연결할 수 있습니다.

1. 프로덕션 호스트명에 올바른 [priority order](/load-balancing/load-balancers/dns-records/#priority-order)의 DNS 레코드가 있고, [SSL/TLS certificate](/load-balancing/load-balancers/dns-records/#ssltls-coverage)의 적용 범위 안에 있는지 확인합니다.

   Enterprise 계정이라면 애플리케이션의 제외 경로도 검토하세요. 예를 들어 `/admin` 경로로 향하는 요청은 로드 밸런서가 분산하지 않길 원할 수 있습니다. 이런 예외가 있다면 [Origin rule](/rules/origin-rules/features/#dns-record)을 설정하세요.

2. 기존 로드 밸런서의 **Hostname**을 수정해 프로덕션 트래픽을 받도록 구성합니다.
