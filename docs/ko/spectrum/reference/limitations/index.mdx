다음 제한 사항은 Spectrum이 지원하는 여러 프로토콜에 적용됩니다.

## HTTPS

현재 HTTPS 애플리케이션은 HTTP/3를 지원하지 않습니다.

## UDP

현재 Cloudflare는 UDP 패킷의 패킷 단편화를 지원하지 않습니다. 패킷이 단편화되면 Cloudflare의 엣지에서 폐기됩니다. 또한 UDP Spectrum 애플리케이션은 Magic Transit, BYOIP, Spectrum, Bindings에서 지원되지 않습니다.

## Minecraft

Minecraft Java Edition은 지원되지만 Minecraft Bedrock Edition은 지원되지 않습니다.

## Universal SSL

[Universal SSL](/ssl/edge-certificates/universal-ssl/)은 Cloudflare Spectrum과 호환되지 않습니다. 대신 [고급 인증서](/ssl/edge-certificates/advanced-certificate-manager/) 또는 [사용자 지정 인증서](/ssl/edge-certificates/custom-certificates/)를 사용하세요.

## Private Network Load Balancing

[Spectrum](/load-balancing/private-network/#on-ramps)을 온램프로 사용하고 [Cloudflare WAN](/load-balancing/private-network/#cloudflare-wan)을 오프램프로 사용하는 경우, Spectrum의 [프록시 프로토콜](/spectrum/how-to/enable-proxy-protocol/) 설정은 지원되지 않습니다.

## Cloudflare Tunnel

Spectrum을 [Cloudflare Tunnel](/cloudflare-one/networks/connectors/cloudflare-tunnel/)과 통합하는 것은 **HTTP/HTTPS** 애플리케이션에 대해서만 지원됩니다. 이는 Spectrum이 Tunnel 서비스에 도달하기 위해 요청을 [Layer 7 CDN 제품](/spectrum/reference/layer-7-analytics/#the-overlap-layer-7-traffic-being-proxied-through-spectrum)을 통해 업스트림으로 전달해야 하기 때문입니다.

Spectrum에서 Cloudflare Tunnel을 통해 트래픽을 올바르게 라우팅하려면 다음이 필요합니다.

1. Spectrum 애플리케이션의 유형을 **HTTP** 또는 **HTTPS**로 구성합니다.
2. Spectrum 애플리케이션의 origin을, 이미 Cloudflare Tunnel을 통해 [트래픽을 라우팅하고 있는](/cloudflare-one/networks/connectors/cloudflare-tunnel/routing-to-tunnel/) 호스트 이름으로 지정합니다. 예를 들어 [DNS 레코드](/cloudflare-one/networks/connectors/cloudflare-tunnel/routing-to-tunnel/dns/) 또는 [Cloudflare Load Balancer](/cloudflare-one/networks/connectors/cloudflare-tunnel/routing-to-tunnel/public-load-balancers/)를 통해서입니다.

Cloudflare Tunnel origin과 함께 다른 유형의 Spectrum 애플리케이션(예: TCP)을 사용하는 것은 지원되지 않습니다. 또한 Spectrum 애플리케이션의 origin을 Tunnel의 하위 도메인(`<UUID>.cfargotunnel.com`)으로 직접 지정하는 것도 올바른 구성이 아니며 동작하지 않습니다.

## 포트 수신 구성

기본적으로 Spectrum은 모든 포트에서 수신하도록 구성되어 있어 보안 감사 담당자에게 우려를 줄 수 있습니다. 그러나 Spectrum은 Cloudflare 내에서 명시적으로 구성된 엣지 포트에서 들어오는 연결만 프록시한다는 점을 이해하는 것이 중요합니다.

Spectrum IP의 임의 포트에 대해 TCP 핸드셰이크가 시작되면, 핸드셰이크는 항상 완료됩니다. 해당 포트에 대해 Spectrum 애플리케이션이 구성되어 있다면 연결은 origin으로 프록시됩니다. 구성된 애플리케이션이 없다면 연결은 즉시 종료되며 origin 연결은 열리지 않습니다.

Spectrum은 해당 포트에 대해 Spectrum 애플리케이션이 구성된 경우에만 origin으로 트래픽을 프록시합니다.
