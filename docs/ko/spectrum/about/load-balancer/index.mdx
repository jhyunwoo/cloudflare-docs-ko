Spectrum을 Cloudflare [Load Balancing](/load-balancing/)과 함께 구성하면 TCP 헬스 체크, 장애 조치, 트래픽 스티어링을 제공하여 Spectrum 애플리케이션의 복원력을 높일 수 있습니다.

Cloudflare Load Balancing의 작동 방식 개요는 [Load Balancing components](/load-balancing/understand-basics/load-balancing-components/)를 참고하세요. 설정 방법은 [Spectrum 애플리케이션에 load balancing 추가](/load-balancing/additional-options/spectrum/)를 참고하세요.

## TCP 헬스 체크

Cloudflare load balancer를 구성하면 HTTP 및 HTTPS 프로빙 기능에 더해, 어느 TCP 포트든 연결 수락 여부를 검사하도록 프로브할 수 있습니다.

헬스 체크는 load balancer에서 선택 사항입니다. 하지만 헬스 체크가 없으면 load balancer는 첫 번째 풀의 모든 엔드포인트로 트래픽을 분산합니다. 헬스 체크를 활성화하면 오류 상태에 들어간 호스트는 트래픽을 받지 않아 가동 시간을 유지할 수 있습니다. 이를 통해 호스트 풀 내부 또는 여러 풀 사이에서 지능형 장애 조치를 활성화할 수 있습니다.

아래 예시는 30초마다 새로 고침되는 포트 2408에서 실행 중인 애플리케이션에 대한 TCP 헬스 체크 구성입니다. TCP 헬스 체크는 대시보드 또는 Cloudflare API를 통해 구성할 수 있습니다.

## 트래픽 스티어링

모든 트래픽 스티어링 정책은 Spectrum을 통한 전송 계층 load balancing에서 사용할 수 있습니다. 사용 가능한 [global traffic steering](/load-balancing/understand-basics/traffic-steering/steering-policies/) 및 [endpoint steering](/load-balancing/understand-basics/traffic-steering/origin-level-steering/) 옵션에 대해 자세히 알아보려면 Load Balancing 문서를 참고하세요.

## 가중치

[Endpoint weights](/load-balancing/understand-basics/traffic-steering/origin-level-steering/#weights)를 사용하면 용량이 다른 엔드포인트를 운영하거나 기타 이유로 호스트 간 트래픽을 분할할 수 있습니다.

load balancer 풀 안에서 구성한 가중치는 Spectrum을 통한 load balancing에도 그대로 적용됩니다.
