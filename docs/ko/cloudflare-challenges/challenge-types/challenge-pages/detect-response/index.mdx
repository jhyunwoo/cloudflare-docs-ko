요청이 원래 예상 응답 대신 'Cloudflare' 챌린지 페이지를 만났을 때, 챌린지 페이지 응답 (챌린지 페이지 유형의 무시)에는`cf-mitigated`헤더 현재 및 설정`challenge`. 이 우두머리는 fetch/XHR 요청을 만들 때 응답이 도전된지 검출하기 위하여 레버리지될 수 있습니다. 이 헤더는 응답이 챌린지인지 여부를 확인하는 신뢰할 수있는 방법을 제공합니다. 웹 응용 프로그램을 사용하면 결과에 따라 적절한 조치를 취할 수 있습니다. 예를 들어, 백엔드의 응답에 직면 한 프런트 엔드 응용 프로그램은이 헤더 값의 존재를 확인하고 예상치 못한 사건을 처리 할 수 있습니다.

:::참조
요청된 자원 유형에 관계없이, 도전의 내용 유형은 일 것입니다`text/html`.
:::

제품정보`cf-mitigated`헤더,`challenge`유효 값입니다. header는 모든 도전 페이지 유형에 대한 설정입니다.

설명하기 위해, 여기에는 사용 방법을 설명하는 JavaScript 코드 스니펫입니다`cf-mitigated`응답이 도전했는지를 감지하는 헤더 :

```js
fetch("/my-api-endpoint").then((response) => {
	if (response.headers.get("cf-mitigated") === "challenge") {
		//핸들 도전된 응답
	} else {
		//자주 묻는 질문
	}
});
```
