API Shield Routing을 사용하면 기존 zone 및 DNS 구성과 다른 경로와 호스트를 가진 여러 백엔드 서비스로 요청을 라우팅하는, 통합된 외부 노출 API를 만들 수 있습니다.

:::note

**Source Endpoint**는 API Shield가 Endpoint Management에서 관리하는 엔드포인트를 의미합니다. **Target Endpoint**는 Routing 기능이 요청을 실제로 전달하는 최종 목적지를 의미합니다.
:::

## 프로세스

경로를 만들기 전에 [스키마 업로드](/api-shield/security/schema-validation/#add-validation-by-uploading-a-schema), [API Discovery](/api-shield/security/api-discovery/), 또는 [수동 추가](/api-shield/management-and-monitoring/#add-endpoints-manually) 같은 기존 방식으로 Source Endpoints를 Endpoint Management에 추가해야 합니다.

경로를 만들려면 Source Endpoint의 operation ID가 필요합니다. dashboard에서 operation ID를 찾으려면 다음 단계를 따르세요.

Source Endpoints를 Endpoint Management에 추가한 뒤에는, 아래 단계에 따라 특정 operation ID에 대한 경로를 만들고 검증할 수 있습니다.

### 경로 만들기

<Tabs syncKey="dashNewNav">
    <TabItem label="New dashboard" icon="rocket">
        <Steps>
            1. In the Cloudflare dashboard, go to the **Web Assets** page.

                <DashButton url="/?to=/:account/:zone/security/web-assets" />
            2. In **Endpoints**, select an existing endpoint and expand its details.
            3. Under **Routing**, select **Create route**.
            4. Enter the target URL or IP address to route your endpoint to.
            5. Select **Deploy route**.
        </Steps>
    </TabItem>
    <TabItem label="Old dashboard">
        <Steps>
            1. Log in to the [Cloudflare dashboard](https://dash.cloudflare.com/), and select your account and domain.
            2. Go to **Security** > **API Shield**.
            3. In **Endpoint Management**, select an existing endpoint and expand its details.
            4. Under **Routing**, select **Create route**.
            5. Enter the target URL or IP address to route your endpoint to.
            6. Select **Deploy route**.
        </Steps>
    </TabItem>

</Tabs>

:::note
path variables가 있다면 순서를 바꿀 수 있습니다. 예를 들어 `/api/{var1}/users/{var2}`를 `/{var2}/users/{var1}`로 라우팅할 수 있습니다. 변수에 해당하지 않는 경로 세그먼트는 추가하거나 완전히 생략할 수도 있습니다.
:::

기존 경로에서 **Edit route**를 선택하면 경로를 편집하거나 삭제할 수도 있습니다.

### 경로 검증하기

Source Endpoint로 요청을 보내면, Target Endpoint를 직접 호출했을 때와 동일한 방식으로 백엔드 서비스의 내용을 볼 수 있어야 합니다.

API Shield가 예상과 다른 결과를 반환한다면 Source Endpoint의 호스트, 메서드, 경로를 확인하고 Route를 검증해 Target Endpoint 값이 올바른지 확인하세요.

:::note

Route 변경 사항이 Cloudflare 네트워크 전체에 동기화되기까지 최대 5분이 걸릴 수 있습니다.
:::

## 제공 대상

API Shield Routing은 현재 open beta 상태이며 API Shield를 구독한 Enterprise 고객만 사용할 수 있습니다. API Shield를 구매하지 않은 Enterprise 고객은 [API Shield as a non-contract service](https://dash.cloudflare.com/?to=/:account/:zone/security/api-shield)를 Cloudflare dashboard에서 미리 보거나 계정 팀에 문의할 수 있습니다.

## 제한 사항

동일한 zone으로 향하는 경로인 경우 Target Endpoint를 Worker로 라우팅할 수 없습니다.

요청의 메서드는 변경할 수 없습니다. 예를 들어 `GET` Source Endpoint는 항상 Target Endpoint에 `GET` 요청을 전송합니다.

Source Endpoint에 있는 모든 변수를 Target Endpoint에서도 사용해야 합니다. 예를 들어 `/api/{var1}/users/{var2}`를 `/api/users/{var2}`로 라우팅하는 것은 허용되지 않으며, Source Endpoint에는 `{var1}`가 있지만 Target Endpoint에는 없기 때문에 오류가 발생합니다.
