API Shield의 Endpoint Management를 사용해 <GlossaryTooltip term="API endpoint">API endpoints</GlossaryTooltip>를 저장하고, 업데이트하고, 성능 메트릭을 모니터링함으로써 엔드포인트의 상태를 추적하세요.

**Add endpoints**를 사용하면 고객이 [API Discovery](/api-shield/security/api-discovery/)에서 직접 엔드포인트를 저장하거나 메서드, 경로, 호스트 기준으로 수동 추가할 수 있습니다.

이렇게 하면 지정한 엔드포인트가 관리 대상 엔드포인트 목록에 추가됩니다. 저장된 엔드포인트 목록은 **Endpoint Management** 페이지에서 확인할 수 있습니다.

Cloudflare는 엔드포인트를 저장하는 즉시 해당 엔드포인트의 [성능 데이터](/api-shield/management-and-monitoring/#endpoint-analysis)를 수집하기 시작합니다.

:::note
엔드포인트가 [Cloudflare Workers](/workers/)를 사용하고 있다면 metrics 데이터는 채워지지 않습니다.
:::

### API Discovery에서 엔드포인트 추가

Discovery에서 API 엔드포인트를 추가하는 방법은 두 가지가 있습니다.

#### Endpoints 탭에서 추가

{/* prettier-ignore-start */}

<Tabs syncKey="dashNewNav">
  <TabItem label="New dashboard" icon="rocket">
    <Steps>
      1. From **Endpoints**, go to **Add endpoints** > **Select from Discovery** tab.
      2. Select the discovered endpoints you would like to add.
      3. Select **Add endpoints**.
    </Steps>
  </TabItem>
  <TabItem label="Old dashboard">
    <Steps>
      1. From **Endpoint Management**, select **Add endpoints** > **Select from Discovery** tab.
      2. Select the discovered endpoints you would like to add.
      3. Select **Add endpoints**.
    </Steps>
  </TabItem>
</Tabs>

{/* prettier-ignore-end */}

#### Discovery 탭에서 추가

{/* prettier-ignore-start */}

<Tabs syncKey="dashNewNav">
  <TabItem label="New dashboard" icon="rocket">

      2. Select the discovered endpoints you would like to add.
      3. Select **Save selected endpoints**.
    </Steps>
  </TabItem>
  <TabItem label="Old dashboard">

### Schema validation에서 엔드포인트 추가

{/* prettier-ignore-start */}

<Tabs syncKey="dashNewNav">
  <TabItem label="New dashboard" icon="rocket">
    <Steps>
      1. From **Web assets**, go to the **Endpoints** tab.
      2. Select **Add endpoints** > **Upload Schema**.
      3. Upload a schema file.
      4. Select **Add schema and endpoints**.
    </Steps>
  </TabItem>
  <TabItem label="Old dashboard">
    <Steps>
      1. Add a schema by [configuring Schema validation](/api-shield/security/schema-validation/).
      2. On **Review schema endpoints**, save new endpoints to endpoint management by checking the box.
      3. Select **Save as draft** or **Save and Deploy**. Endpoints will be saved regardless of whether the schema is saved as a draft or published.
    </Steps>
  </TabItem>
</Tabs>

{/* prettier-ignore-end */}

API Shield는 동일한 호스트, 메서드, 경로를 가진 중복 엔드포인트를 찾습니다. 중복 엔드포인트는 endpoint management에 저장되지 않습니다.

:::note
**Save new endpoints to endpoint management**를 해제하면 엔드포인트는 추가되지 않습니다.
:::

### 엔드포인트 수동 추가

{/* prettier-ignore-start */}

<Tabs syncKey="dashNewNav">
  <TabItem label="New dashboard" icon="rocket">
    <Steps>
      1. From **Web assets**, go to the **Endpoints** tab.
      2. Select **Add endpoints** > **Manually add**.
      3. Choose the method from the dropdown menu and add the path and hostname for the endpoint.
      4. Select **Add endpoints**.
    </Steps>
  </TabItem>
  <TabItem label="Old dashboard">
    <Steps>
      1. From Endpoint Management, select **Add endpoints** > **Manually add**.
      2. Choose the method from the dropdown menu and add the path and hostname for the endpoint.
      3. Select **Add endpoints**.
    </Steps>
  </TabItem>
</Tabs>

{/* prettier-ignore-end */}

:::note
여러 체크박스를 선택하면 Discovery에서 여러 엔드포인트를 개별로가 아니라 한 번에 추가할 수 있습니다.
:::

엔드포인트를 수동으로 추가할 때는 경로나 호스트의 변수 필드를 중괄호로 감싸 지정할 수 있습니다. 예: `/api/user/{var1}/details` 또는 `{hostVar1}.example.com`.

Cloudflare는 다음 형식의 hostname variables를 지원합니다.

```txt

{hostVar1}.example.com

foo.{hostVar1}.example.com

{hostVar2}.{hostVar1}.example.com
```

Hostname variables는 도메인 필드 전체를 구성해야 하며, 필드 내 다른 텍스트와 함께 사용할 수 없습니다.

다음 형식은 지원되지 않습니다.

```txt

foo-{hostVar1}.example.com
```

Cloudflare가 API Shield에서 변수를 사용하는 방식에 대한 자세한 내용은 [API Discovery](/api-shield/security/api-discovery/)의 예시를 참고하세요.

### 엔드포인트 수동 삭제

엔드포인트는 하나씩 또는 일괄로 삭제할 수 있습니다.

{/* prettier-ignore-start */}

<Tabs syncKey="dashNewNav">
  <TabItem label="New dashboard" icon="rocket">
    <Steps>
      1. From **Web assets**, go to the **Endpoints** tab.
      2. Select the checkboxes for the endpoints that you want to delete.
      3. Select **Delete endpoints**.
    </Steps>
  </TabItem>
  <TabItem label="Old dashboard">
    <Steps>
      1. From Endpoint Management, select the checkboxes for the endpoints that you want to delete.
      2. Select **Delete endpoints**.
    </Steps>
  </TabItem>
</Tabs>

{/* prettier-ignore-end */}

:::caution
Endpoint Management에서 엔드포인트를 삭제하면 Cloudflare는 관련된 모든 성능 및 분석 데이터 추적을 즉시 중단합니다. 해당 엔드포인트의 기존 이력 메트릭은 영구적으로 제거되며 복구할 수 없습니다. 나중에 이 엔드포인트를 다시 저장하면, 메트릭 추적은 다시 저장된 시점부터 재개됩니다.
:::

## Endpoint Analysis

저장된 각 엔드포인트에 대해 고객은 다음을 확인할 수 있습니다.

- **Request count**: 일정 기간 동안 해당 엔드포인트로 들어온 총 요청 수입니다.
- **Rate limiting recommendation**: 10분 기준 권장치입니다. 이 값은 요청 수에 따라 결정됩니다.
- **Latency**: 평균 origin 응답 시간(ms)입니다. 방문자가 요청을 보낸 시점부터 origin에서 응답을 돌려받는 시점까지 걸리는 시간을 보여줍니다.
- **Error rate** vs. overall traffic: 4xx, 5xx 및 그 합계로 그룹화됩니다.
- **Response size**: 요청에 대해 반환된 평균 응답 크기(바이트)입니다.
- **Labels**: 엔드포인트에 현재 할당된 [labels](/api-shield/management-and-monitoring/endpoint-labels/)입니다.
- **[Authentication status](/api-shield/security/authentication-posture/)**: 이 엔드포인트의 성공한 요청에서 관찰된 [session identifiers](/api-shield/get-started/#session-identifiers)의 분포입니다.
- **Sequences**: 해당 엔드포인트가 포함된 [Sequence Analytics](/api-shield/security/sequence-analytics/) 시퀀스 수입니다.

:::note

분석을 보는 고객은 상세 metrics 보기를 최근 24시간과 7일 사이에서 전환할 수 있습니다.
:::

Cloudflare API를 통해 Endpoint Management와 상호작용할 수 있습니다. 자세한 내용은 [Endpoint Management’s API documentation](/api/resources/api_gateway/subresources/discovery/subresources/operations/methods/list/)를 참고하세요.

## Sensitive Data Detection

Sensitive data는 다양한 개인 식별 정보와 금융 데이터를 포함합니다. Cloudflare는 일반적인 데이터 유출 위협에 대응하기 위해 이 ruleset을 만들었으며, WAF는 origin의 HTTP 응답 본문에서 이러한 데이터를 검색할 수 있습니다.

zone이 [Sensitive Data Detection managed ruleset](/waf/managed-rules/reference/sensitive-data-detection/)도 함께 구독 중이라면, API Shield는 Endpoint Management에 등록된 API 엔드포인트 응답 본문에서 민감한 데이터가 발견되었음을 사용자에게 알려줍니다.

Sensitive Data Detection은 Advanced application security 요금제를 사용하는 Enterprise 고객에게 제공됩니다.

zone에서 Sensitive Data Detection이 활성화되면, API Shield는 지난 7일간의 WAF firewall events를 조회하고, 엔드포인트에 민감한 응답이 매치된 경우 Endpoint Management 테이블 행에 알림 아이콘을 표시합니다.

Endpoint Management 테이블 행을 펼쳐 자세히 보면 발견된 민감 데이터의 유형을 표시합니다. **Explore Events**를 선택하면 Security Events에서 매치된 이벤트를 볼 수 있습니다.

zone에서 Sensitive Data Detection이 활성화된 뒤에는 [Sensitive Data Detection ruleset을 탐색](https://dash.cloudflare.com/?to=/:account/:zone/security/data/ruleset/e22d83c647c64a3eae91b71b499d988e/rules)할 수 있습니다. Sensitive Data Detection이 활성화되어 있지 않으면 이 링크는 동작하지 않습니다.

## 제한 사항

지연 시간 같은 일부 성능 메트릭은 요청이 origin 서버로 직접 전달되지 못하도록 하는 방식으로 Cloudflare 서비스에 의해 처리될 때 지원되지 않습니다.

이 제한은 특히 다음과 같은 경우에 관찰됩니다.

- URL 경로에서 Cloudflare Worker가 실행 중인 경우
- [Waiting Room](/waiting-room/)처럼 Workers 위에 구축된 다른 제품이 애플리케이션에서 활성화된 경우

이러한 시나리오에서는 시스템이 origin 응답 시간을 정확히 측정할 수 없으며, 해당 메트릭은 dashboard에 채워지지 않습니다.
