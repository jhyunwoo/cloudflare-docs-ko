## 2025-02-17

**자동 적용되는 새 위험 레이블**

이제 API Shield가 누락된 스키마와 성능 이상 징후(오류율, 지연 시간, 응답 본문 크기의 급증)로 인한 위험이 있는 엔드포인트에 자동으로 레이블을 지정합니다.

## 2025-01-16

**API Authentication Posture**

세션 식별자가 구성된 zone에서는 고객이 [Endpoints](/api-shield/management-and-monitoring/) 내부에서 엔드포인트별 인증 세부 정보를 확인할 수 있습니다.

## 2024-12-19

**자동 적용되는 엔드포인트 위험 레이블**

이제 API Shield가 인증 상태와 민감 데이터 탐지를 바탕으로 엔드포인트에 자동으로 위험 레이블을 지정합니다.

## 2024-11-04

**Endpoint labels**

고객은 이제 [Endpoint labeling service](/api-shield/management-and-monitoring/endpoint-labels/)를 사용해 사용 사례와 사용자 지정 레이블별로 엔드포인트를 정리하여, 쉽게 참조하고 향후 머신 러닝(ML) 모델 학습에도 활용할 수 있습니다.

## 2024-10-18

**Custom Rules에서 API Shield 필드 사용**

이제 고객은 [custom rules](/waf/custom-rules/)에서 API Shield 제품 기능 필드를 사용할 수 있으며, [JWT validation](/api-shield/security/jwt-validation/), [session identifiers](/api-shield/get-started/#session-identifiers), [Schema validation](/api-shield/security/schema-validation/) 같은 기능을 참조할 수 있습니다.

## 2024-09-25

**Schema validation 2.0용 Fallthrough rule**

이제 고객은 Schema validation 2.0으로 보호되는 스키마에 나열된 엔드포인트와 일치하지 않는 요청을 차단하거나 기록하기 위해 [Fallthrough Action](/api-shield/security/schema-validation/#add-validation-by-adding-a-fallthrough-rule)을 활성화할 수 있습니다.

## 2024-08-28

**Endpoint management 및 Schema validation 용량 증가**

Endpoint management와 Schema validation이 이제 저장 및 검증된 API 엔드포인트를 최대 10,000개까지 지원합니다.

## 2024-07-08

**API Discovery의 hostname variables**

이제 고객은 [API Discovery](/api-shield/security/api-discovery/)가 동일한 메서드와 경로를 가진 유사한 서브도메인을 함께 그룹화하는 시점을 확인할 수 있어, vanity domain이나 서브도메인을 많이 공유하는 API를 더 쉽게 발견하고 관리할 수 있습니다.

## 2024-07-02

**API Routing으로 API 요청 라우팅**

이제 고객은 [API Routing](/api-shield/management-and-monitoring/api-routing/)을 통해 요청을 서로 다른 백엔드 서비스로 라우팅하여, 원래는 분리되어 있는 시스템 전반에 분산된 API 앞에 통합된 진입점을 만들 수 있습니다.

## 2024-05-13

**Advanced Rate Limiting, Transform Rules, 세션 ID에서 JWT claims 사용**

이제 고객은 [JSON Web Tokens(클레임으로 알려진 필드)](/api-shield/security/jwt-validation/transform-rules/#enhance-transform-rules-with-jwt-claims) 내부 값을 [API Shield의 session identifiers](/api-shield/get-started/#session-identifiers)로 사용하고, [Advanced Rate Limiting](/waf/rate-limiting-rules/)에서 값을 카운트하며, [Transform Rules](/rules/transform/)에서 유용한 정보를 전달할 수 있습니다.

## 2024-04-30

**Cloudflare dashboard에서 Sequence mitigation 규칙 빌드**

이제 고객은 [Cloudflare dashboard](https://dash.cloudflare.com/)의 API Shield 섹션에 있는 새 사용자 인터페이스에서 [Sequence mitigation](/api-shield/security/sequence-mitigation/) 규칙을 만들 수 있습니다.

## 2024-02-23

**Endpoint management에서 hostname variables 지원**

이제 고객은 호스트명에 변수가 포함된 엔드포인트를 [Endpoint management](/api-shield/management-and-monitoring/)에 저장할 수 있습니다. Hostname variables는 모든 제품 기능에서 지원됩니다.
