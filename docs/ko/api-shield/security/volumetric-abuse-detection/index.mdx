Cloudflare Volumetric Abuse Detection은 적응형 rate limiting 시스템을 설정하는 데 도움을 줍니다.

Cloudflare는 개별 엔드포인트에 대한 사용자 트래픽을 기준으로 엔드포인트 남용을 탐지합니다.

예를 들어, API는 `/reset-password` 엔드포인트와 `/login` 엔드포인트에서 서로 다른 수준의 트래픽을 볼 수 있습니다. 또한 `/login` 엔드포인트는 성공적인 마케팅 캠페인 이후 평소보다 훨씬 많은 트래픽을 볼 수도 있습니다.

이 두 시나리오는 전통적인 rate limiting의 한계를 보여 줍니다. 엔드포인트마다 트래픽이 다를 뿐 아니라, 동일한 엔드포인트라도 시간에 따라 트래픽이 달라질 수 있습니다. Volumetric Abuse Detection은 비지도 학습을 사용해 API마다 별도의 기준선을 만들고, 사용자 행동 변화에 더 잘 적응함으로써 이러한 문제를 해결합니다.

Volumetric Abuse Detection rate limits는 세션 단위로 생성됩니다. IP 주소 기반의 전통적인 rate limit과 달리, Volumetric Abuse Detection rate limits는 API 트래픽이 증가할 때 오탐에 덜 취약합니다.

Volumetric Abuse Detection rate limits는 명백한 대량 남용을 방지하면서 오탐을 최소화하기 위한 방법입니다. 전반적인 악성 bot 트래픽을 방지하려는 경우에는 Cloudflare의 [Bot solutions](/bots/)를 참고하세요.

## 프로세스

Volumetric Abuse Detection은 API의 개별 세션 트래픽 통계를 분석해 엔드포인트별, 세션별 rate limit을 권장합니다.

엔드포인트에 접근하는 위치는 다음과 같습니다.

Old dashboard: **Security** > **API Shield** > **Endpoint Management**

New dashboard: **Security** > **Web Assets** > **Endpoints**

트래픽 패턴이 변경되면 권장치는 계속 업데이트됩니다.

### 요구 사항

Volumetric Abuse Detection은 엔드포인트에 대해 충분하고 통계적으로 안전한 트래픽 데이터를 수집한 뒤에만 rate limit threshold를 생성합니다. 발견된 엔드포인트에 권장치가 없다면, 트래픽이 필요한 기준을 충족하지 못했을 가능성이 큽니다.

threshold는 지난 7일(또는 최초 발견 이후) 동안 다음 조건을 모두 만족한 엔드포인트에 대해서만 제안됩니다.

- 엔드포인트는 충분한 유효 트래픽([API Discovery](/api-shield/security/api-discovery/#requirements) 기준을 충족하는 트래픽)을 받아야 합니다. 간헐적이거나 불규칙한 트래픽은 제안을 방해할 수 있습니다.
- 엔드포인트는 지난 7일 동안 어느 한 24시간 구간에서 최소 50개의 서로 다른 세션에 의해 접근되어야 합니다.
- 요청 헤더나 쿠키에서 사용할 수 있는 authorization token 같은 <GlossaryTooltip term="session identifier" link="/api-shield/get-started/#to-set-up-session-identifiers">Session identifiers</GlossaryTooltip>가 구성되어 있어야 Cloudflare가 개별 세션을 정확히 탐지하고 필요한 세션별 rate 분석을 수행할 수 있습니다.

session identifier를 추가한 뒤에는 Cloudflare dashboard의 엔드포인트에 rate limit recommendations가 나타나기까지 24시간을 기다리세요.

### Rate limiting recommendation 계산

rate limit recommendations가 **Endpoints**에 나타나면 엔드포인트 행을 선택해 추천값에 대한 더 자세한 정보를 볼 수 있습니다. 전체 권장 rate limit 값과 함께 p99, p90, p50 rate limit 값도 표시됩니다.

권장 rate limit 값은 하루 동안 계속 계산되며, API의 트래픽 프로필이 유사하다면 새 계산 결과가 기존 권장치와 같을 수도 있습니다. 재계산 시에는 최근 24시간 동안 발생한 요청을 봅니다.

Cloudflare는 API 세션 전반의 요청률 분포 변동성까지 분석에 포함하므로, 전체 rate limit recommendation을 선택하는 것을 권장합니다. 단일 p-value를 선택하면 이상치 수가 많을 때 오탐이 발생할 수 있습니다.

:::note[p-values]

p-values는 트래픽 중 몇 퍼센트가 그 값 아래에 들어오는지를 나타냅니다. 예를 들어 p90 값이 `83`이면, 세션의 90%는 10분 동안 최대 요청률이 83 미만이었다는 뜻입니다.
:::

**Endpoints**에서 추천값에 대한 신뢰도와 지난 7일 동안 관찰된 고유 세션 수를 검토할 수 있습니다. 일반적으로 고유 세션 수가 적고 사용자 행동의 변동성이 큰 엔드포인트는 신뢰도 점수가 낮습니다.

신뢰도가 낮은 rate limit이라도 API 남용을 방지하는 데 여전히 도움이 될 수 있습니다. 추천값의 신뢰도 때문에 적용이 망설여진다면, 우선 규칙을 `log` 모드로 시작하고 오탐이 있는지 관찰하는 것을 권장합니다.

## 제한 사항

session identifiers가 구성되어 있으면 API Shield는 항상 recommendations를 계산합니다. 세션 기반 rate limits를 활성화하려면 [Advanced Rate Limiting](/waf/rate-limiting-rules/#availability)을 구독하세요.

## 제공 대상

Volumetric Abuse Detection은 Enterprise 고객만 사용할 수 있습니다. 이 제품에 관심 있는 Enterprise 고객이라면 계정 팀에 문의하세요.
