Use the [Cloudflare GraphQL API](/analytics/graphql-api/getting-started/) to gather data about your GraphQL API’s current usage and configure Cloudflare’s GraphQL malicious query protection to log or block malicious queries.

## 소개

query size는 쿼리 안의 terminal fields(leaf)의 수로 정의되고, query depth는 leaf가 존재하는 가장 깊은 수준으로 정의됩니다. 예를 들어 아래 쿼리의 size는 `4 (terminalField[1-4] all contribute to this counter)`로 보고되고, depth는 `3 (terminalField3 and terminalField4 are at depth level 3)`로 보고됩니다.

```graphql title="GraphQL query"
{
	terminalField1
	nonTerminalField1(filter: 123) {
		terminalField2
		nonTerminalField2 {
			terminalField3
			terminalField4
		}
	}
}
```

## GraphQL 통계 수집

Cloudflare GraphQL API의 새 `apiGatewayGraphqlQueryAnalyticsGroups` 노드를 사용하면 `apiGatewayGraphqlQuerySize`와 `apiGatewayGraphqlQueryDepth` 차원을 조회할 수 있습니다.

```graphql graphql-api-explorer title="GraphQL query"
query ApiGatewayGraphqlQueryAnalytics(
	$zoneTag: string
	$start: Time
	$end: Time
) {
	viewer {
		zones(filter: { zoneTag: $zoneTag }) {
			apiGatewayGraphqlQueryAnalyticsGroups(
				limit: 100
				orderBy: [
					apiGatewayGraphqlQuerySize_DESC
					apiGatewayGraphqlQueryDepth_DESC
				]
				filter: { datetime_geq: $start, datetime_leq: $end }
			) {
				count
				dimensions {
					apiGatewayGraphqlQuerySize
					apiGatewayGraphqlQueryDepth
				}
			}
		}
	}
}
```

위 쿼리로 다음과 같은 응답을 얻을 수 있습니다.

```json title="Response"
{
	"data": {
		"viewer": {
			"zones": [
				{
					"apiGatewayGraphqlQueryAnalyticsGroups": [
						{
							"count": 10,
							"dimensions": {
								"apiGatewayGraphqlQueryDepth": 1,
								"apiGatewayGraphqlQuerySize": 11
							}
						},
						{
							"count": 10,
							"dimensions": {
								"apiGatewayGraphqlQueryDepth": 1,
								"apiGatewayGraphqlQuerySize": 2
							}
						}
					]
				}
			]
		}
	},
	"errors": null
}
```

이 응답 예시에서 Cloudflare는 선택한 기간 동안 depth 1, size 11인 요청 10건과 depth 1, size 2인 요청 10건을 관찰했습니다.

## GraphQL 통계 분석

응답을 사용해 각 속성의 percentile을 계산하고 허용할 threshold를 정할 수 있습니다. 예를 들어 query size나 depth에 대해 `1.5 * p99` 같은 간단한 휴리스틱을 사용할 수 있습니다.

다음은 위 GraphQL API 응답 출력(JSON 파일 기준)을 받아 query size와 depth의 p-level을 보고하는 간단한 Python 스크립트입니다.

```python title="Python script"
#!/usr/bin/env python3

import json
import numpy as np
import argparse

parser = argparse.ArgumentParser()
parser.add_argument("--response", help="apiGatewayGraphqlQueryAnalyticsGroups 노드를 포함한 API JSON 응답 파일 경로", required=True)
args = parser.parse_args()
with open(args.response) as f:
    query_sizes = np.array([], dtype=np.uint16)
    query_depths = np.array([], dtype=np.uint8)
    data = json.load(f)['data']['viewer']['zones'][0]['apiGatewayGraphqlQueryAnalyticsGroups']
    for datapoint in data:
        query_sizes = np.append(query_sizes, [datapoint['dimensions']['apiGatewayGraphqlQuerySize']] * datapoint['count'])
        query_depths = np.append(query_depths, [datapoint['dimensions']['apiGatewayGraphqlQueryDepth']] * datapoint['count'])

    quantiles = [0.99, 0.95, 0.75, 0.5]
    print('\n'.join([f"Query size {int(q * 100)}th percentile is {v}" for q, v in zip(quantiles, np.quantile(query_sizes, quantiles))]))
    print('\n'.join([f"Query depth {int(q * 100)}th percentile is {v}" for q, v in zip(quantiles, np.quantile(query_depths, quantiles))]))
```

위 쿼리를 사용하면 다음과 같은 출력을 얻습니다.

```json title="Example output"
./calculator.py --response=response.json
Query size 99th percentile is 11.0
Query size 95th percentile is 11.0
Query size 75th percentile is 11.0
Query size 50th percentile is 6.5
Query depth 99th percentile is 1.0
Query depth 95th percentile is 1.0
Query depth 75th percentile is 1.0
Query depth 50th percentile is 1.0
```

## 들어오는 GraphQL 쿼리에 제한 설정

API Shield 고객은 이제 custom rules에서 세 가지 새 필드를 사용할 수 있습니다.

- `cf.api_gateway.graphql.query_size`: GraphQL 쿼리의 크기를 설명합니다.
- `cf.api_gateway.graphql.query_depth`: GraphQL 쿼리의 깊이를 설명합니다.
- `cf.api_gateway.graphql.parsed_successfully`: Cloudflare가 쿼리를 파싱할 수 있었는지 여부를 설명합니다. 현재는 best-effort parsing을 수행하므로 일부 유효한 쿼리는 파싱하지 못할 수 있습니다. 따라서 GraphQL 보안 규칙을 배포할 때는 반드시 custom rules에 `and cf.api_gateway.graphql.parsed_successfully` 필터를 사용해야 합니다.
  <br />

예를 들어 다음 규칙을 API 또는 dashboard를 통해 배포하면, 깊게 중첩되어 있고 30개 이상의 필드를 요청하는 쿼리를 차단할 수 있습니다.

```txt wrap
(cf.api_gateway.graphql.query_size > 30 and cf.api_gateway.graphql.query_depth > 7 and cf.api_gateway.graphql.parsed_successfully)
```

:::note

GraphQL 파싱을 어떤 엔드포인트에서 실행할지 직접 구성할 수는 없습니다. 요청은 `/graphql`로 끝나는 경로를 대상으로 할 때 파싱됩니다.

:::
