다음 Page Rule로 APO를 제어할 수 있습니다. Page Rule을 통해 캐싱을 변경한 경우, 변경 사항이 적용되려면 캐시를 비워야 합니다.

:::caution

[Cache Rules](/cache/how-to/cache-rules/)는 구성 유연성이 더 뛰어나므로, APO 제어에는 Page Rule 대신 Cache Rules 사용을 고려하세요.
:::

* **Cache Level: Bypass** — APO는 응답 헤더가 `cf-apo-via: origin,page-rules`인 페이지를 우회합니다.

* **Cache Level: Ignore Query String** — APO는 캐시에서 제공할 때 모든 쿼리 문자열을 무시합니다.

* **Cache Level: Cache Everything** — APO는 모든 쿼리 문자열이 포함된 페이지를 캐시합니다.

  :::caution

  WordPress 플러그인을 통한 자동 페이지 purge는 쿼리 문자열이 없는 페이지들만 정리하며, 캐시된 모든 페이지를 정리하지는 않습니다. 요청 헤더가 `cache-control: no-cache`인 경우에도 캐시된 응답이 반환됩니다.

  :::

* **Bypass Cache on Cookie (Business and Enterprise plans only)** — APO는 기본 목록에 더해 사용자 지정 bypass 쿠키를 적용합니다.

* **Edge Cache TTL** — APO는 30일 대신 사용자 지정 Edge TTL을 적용합니다. 이 Page Rule은 CAPTCHA나 nonce를 생성할 수 있는 페이지에 유용합니다.

* **Browser Cache TTL** — APO는 사용자 지정 Browser TTL을 적용합니다.

* `CDN-Cache-Control` 및 `Cloudflare-CDN-Cache-Control` — 사용자가 Page Rule 없이도 캐시 TTL을 세밀하게 제어할 수 있게 해줍니다. `CDN-Cache-Control` 및 `Cloudflare-CDN-Cache-Control` 헤더에 대한 자세한 내용은 [CDN-Cache-Control](/cache/concepts/cache-control/)을 참고하세요.
