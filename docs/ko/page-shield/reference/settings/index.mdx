## endpoint를 보고

사용할 때, Page Shield의 클라이언트 측 리소스 모니터링은<GlossaryTooltip term="content security policy (CSP)">콘텐츠 보안 정책 (CSP)</GlossaryTooltip> [HTTP 헤더만](/page-shield/reference/csp-header/)응용 프로그램에서 실행되는 모든 스크립트에 대한 정보를 수집합니다.

기본적으로, 보고서는 Cloudflare-owned endpoint로 보내집니다.

```txt
https://csp-reporting.cloudflare.com/cdn-cgi/script_monitor/report?<QUERY_STRING>
```

유료 애드온을 가진 기업 고객은 CSP 보고서가 동일한 호스트 이름으로 보내지는 보고서를 변경할 수 있습니다.

```txt
<YOUR-HOSTNAME>/cdn-cgi/script-monitor/report?<QUERY_STRING>
```

### CSP 보고서에 대한 동일한 호스트명을 사용하기위한 필수 사항

CSP 보고를 위한 동일한 hostname을 사용하여 다른 Cloudflare 제품과 방해할 수 있습니다. 이 옵션을 선택하기 전에, 당신의 Cloudflare 윤곽이 다음과 같이 따릅니다:

- 제한 규칙 없음`cdn-cgi/*`URL 경로
- 사용자 정의 규칙은 일치하지 않습니다`cdn-cgi/*`URL 경로

## 연결 표적 세부사항

연결 대상이 Cloudflare로 보고되면 URI는 세션 ID와 같은 민감한 데이터를 포함할 수 있습니다.

기본적으로 Page Shield는 악성 위협 인텔리전스 피드에 대한 도메인을 확인할 수 있습니다. Page Shield를 사용하면 도메인 페이지에서 만든 연결을 분석 할 때 전체 URI를 사용할 수 있습니다. URI에 존재하는 모든 민감한 데이터는 명확한 텍스트에 기록되며 연결 모니터 대시보드에 액세스 할 수 있습니다.

## 클라이언트 측 리소스 모니터링

Page Shield의 클라이언트 측 리소스 모니터링을 끄면 영역에서 실행되는 스크립트에 가시성을 잃고 도메인의 페이지에서 만든 아웃바운드 연결 및 HTTP 트래픽에서 감지 된 쿠키.

클라이언트 측 자원 감시를 끄는:

      2. (선택) 필터 로**고객 측 남용**.

      3. 이름 \***연속 스크립트 모니터링**, toggle를 설정**이름 \***.
    </Steps>
  </TabItem>

  <TabItem label="'대시보드'">
    <Steps>
      1. 로그인하기[‘Cloudflare’ ‘대시보드’](https://dash.cloudflare.com/), 귀하의 계정과 도메인을 선택합니다.
