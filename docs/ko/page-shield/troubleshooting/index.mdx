## Cloudflare는 활성화 후 클라이언트 측 리소스를 표시하지 않습니다.

Cloudflare는 모든 단일 페이지 보기에서 데이터를 수집하지 않습니다. 대신 정보를 효율적으로 수집하는 샘플링 접근법을 사용합니다. 이 도메인은 더 낮은 트래픽을 가진 도메인이 초기 보고서를 생성하기 위해 더 오래 걸릴 수 있음을 의미합니다. 이 도메인은 충분한 샘플을 축적 할 수있는 더 많은 페이지보기를 필요로합니다. 보고 프로세스를 가속화하기 위해, 당신은 적극적으로 당신의 응용 프로그램에 트래픽을 생성하는 것이 좋습니다[클라이언트 측 리소스 모니터링 활성화](/page-shield/get-started/). 이것은 더 빠른 보고 발생을 지도하는 더 많은 자료로 Cloudflare를 제공할 것입니다.

## 대시보드는 인식하지 않는 스크립트와 연결을 보여줍니다

Scripts 종종 참고 자료 다른 스크립트는 응용 프로그램 밖에서.

그러나 자원 모니터링에 예기치 않은 스크립트를 볼 경우 대시보드, 악의적 활동의 징후를 확인합니다.

## Content Security Policy (CSP)와 관련된 브라우저 개발자 도구에서 경고를 얻습니다.

Cloudflare는<GlossaryTooltip term="content security policy (CSP)">콘텐츠 보안 정책 (CSP)</GlossaryTooltip>여러분의 응용 프로그램에 실행되는 모든 스크립트 목록을 수집하는 보고서 전용 지침.

일부 브라우저 디스플레이 스크립트는 개발자 도구의 콘솔 팬에 경고로보고됩니다. 예를 들면:

```txt
[Report Only] Refused to execute inline script because it violates
the following Content Security Policy directive: "script-src 'none'".

Either the 'unsafe-inline' keyword, a hash ('sha256-RFWPLDbv2BY+rCkDzsE+0fr8ylGr2R2faWMhq4lfEQc='), or a nonce ('nonce-...')
is required to enable inline execution.
```

이러한 경고를 안전하게 무시할 수 있습니다. Cloudflare와 관련되어 있기 때문에 로드된 스크립트를 감지해야합니다. 더 많은 정보를 원하시면, 참조[Page Shield가 작동하는 방법](/page-shield/how-it-works/).

## 도메인에 대한 정책 위반 보고서를 얻을 수 있습니다 I allowlisted

CSP의 정책 위반[보고서-only 지시어](/page-shield/reference/csp-header/)리디렉션 또는 리디렉션 HTTP 상태 코드를 고려하지 마십시오. 이것은[디자이너](https://www.w3.org/TR/CSP3/#create-violation-for-request)보안상의 이유로.

일부 타사 서비스는 허용 정책이 리디렉션을 수행 할 수 있습니다. 그런 서비스의 예는 Google Ads입니다.[CSP 정책과 잘 작동하지 않습니다.](https://support.google.com/adsense/thread/102839782?hl=en\&msgid=103611259).

예를 들어, 추가하면`adservice.google.com`도메인을 허용 정책, 당신은 다른 도메인으로 리디렉션하기 때문에이 도메인에 대한 정책 위반 보고서를 얻을 수 (당신의 허용 정책에 제시되지 않음). 이 경우, 위반 보고서는 여전히 원래 도메인을 언급하고, 일부 혼란을 일으킬 수있는 리디렉션 대상의 도메인이 아닙니다.

이 문제를 해결하려고, 귀하의 허용 정책에 리디렉션 대상의 도메인을 추가. 리디렉션으로 인해 여러 도메인을 추가 할 수 있습니다.
