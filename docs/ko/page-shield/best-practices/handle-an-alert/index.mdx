당신이 받은 경우[고객 서비스](/page-shield/alerts/alert-types/), 때로는 스크립트의 성격을 확인하기 위해 몇 가지 수동 조사를 수행해야합니다. 이 페이지에 제공된 지도를 조사에 대한 시작점으로 사용하십시오.

## 1. 경고를 유발하는 것을 이해하십시오.

자주 묻는 질문[검출 시스템](/page-shield/how-it-works/malicious-script-detection/)경고를 트리거했다. ‘Cloudflare’ ‘대시보드’에 직접 보내지는 알림에 링크가 제공됩니다. 대안으로, 다음을 수행:

<Steps>
  {/* prettier-ignore-start */}

  1. 클라이언트 측 자원 페이지로 이동:

     <Tabs syncKey="dashNewNav">
       <TabItem label="새로운 ‘대시보드’" icon="rocket">
         1. 'Cloudflare'에서 '대시보드'로 이동**웹 자산**사이트 맵

            <DashButton url="/?to=/:account/:zone/security/web-assets" />

         2. 선택하기**고객 서비스**탭.
       </TabItem>

       <TabItem label="'대시보드'">
         1. 로그인하기[‘Cloudflare’ ‘대시보드’](https://dash.cloudflare.com/), 귀하의 계정과 도메인을 선택합니다.
         2. 오시는 길**보안 보안** > **페이지 방패**.
       </TabItem>
     </Tabs>

  2. 제품정보**스크립트**또는**연결하기**당신이받은 경고에 언급 된 리소스에 대한 검색.

  3. 제품정보**이름 \***&#xD655;인된 리소스 옆에. 아래 예 스크린 샷은 악성 스크립트 리소스를 보여줍니다.

     ![Dialog 상자는 악성 스크립트의 세부 사항을 보여줍니다.](~/assets/images/page-shield/handle-alert-malicious-script-example.png)

  {/* prettier-ignore-end */}
</Steps>

세부 사항 페이지는 검출 시스템이 경고를 유발하는 것을 지정합니다. 다음 필드의 값을 확인:

- **맛있는 코드**
- **맛있는 URL**
- **좋은 도메인**

다른 검출 메커니즘은 동시에 악성 스크립트를 고려할 수 있습니다. 이것은 거짓 긍정이 아닌 검출의 likelihood를 증가시킵니다.

## 2. 리소스가 감지 된 페이지를 찾습니다.

잠재적 악성 스크립트에 대한 경고를받은 경우:

<Steps>
  1. 스크립트를 로딩하거나 연결을 수행하는 웹 사이트의 페이지에 Navigate. 브라우저를 열고 URL 중 하나를 탐색**페이지 URL**필드 (스크립트 세부 대화 상자에서 표시).

  2. 브라우저의 개발자 도구를 열고 스크립트가 로드되고 있는지 확인합니다. 개발자 도구에서 이것을 확인할 수 있습니다.**회사연혁**스크립트 이름, URL 또는 hostname을 검색하는 탭.
</Steps>

잠재적으로 악의적인 연결에 대한 경고를받은 경우:

<Steps>
  1. 웹 사이트의 페이지로 이동하여 경고를 유발하는 연결이 이루어집니다. 브라우저를 열고 지정된 URL 중 하나에 이동**페이지 URL**필드 (연결 세부 사항 대화 상자에서 표시).

  2. 브라우저의 개발자 도구를 열고 연결이 만들어져 있는지 확인합니다. 개발자 도구에서 이것을 확인할 수 있습니다.**회사연혁**탭, 연결의 대상 이름 검색.
</Steps>

스크립트 또는 연결을 찾을 경우, 이것은 스크립트가로드됩니다 (또는 연결이 설치됩니다) 모든 웹 사이트 방문자를위한 - 진행[단계 3](#3-check-the-script-reputation).

스크립트가로드되거나 연결되는 것을 찾을 수없는 경우 다음 중 하나를 의미 할 수 있습니다.

- 스크립트가 로드되고 있습니다 (또는 연결이 만들어집니다) 방문자의 브라우저 확장.
- 현재 상태는 스크립트를로드하지 않거나 연결을 만들 것입니다. 복잡한 응용 프로그램은 스크립트를로드하고 상태에 따라 연결을 설정할 수 있습니다.
- 올바른 지리적 위치 (또는 유사한 상태)에 있지 않습니다.
- 공격자는 스크립트를로드하거나 특정 브라우저 / 서명자와 방문자의 비율에 대한 연결을 만드는 것입니다.

이 경우, 아래의 단계 이외에, 가장 좋은 방법은:

- 안전한 가상 환경에서, 온라인 검색 도구를 사용하고 주어진 리소스를 검색하십시오. 검색 결과 및 리소스 메타데이터, 예를 들어 도메인 등록 세부 사항;
- 의심스러운 경우, 자원에 대한 응용 코드베이스를 스캔하고 발견되면, 목적을 명확하게합니다.

## 3. 스크립트 명성을 확인

Cloudflare가 리소스의 도메인을 "맛있는 도메인"이라고 생각하면 도메인이 좋은 평판이 없다는 것입니다. 도메인은 악성코드를 호스팅하거나 피싱 공격에 사용됩니다. 일반적으로 도메인 / 호스트 이름을 검토하는 것은 왜 경고를받은지 이해하는 것이 충분합니다. Cloudflare\`와 같은 도구를 사용할 수 있습니다.[보안 센터 Investigate](https://dash.cloudflare.com/?to=/:account/security-center/investigate)이 검증을 돕는 플랫폼.

Cloudflare의 내부 시스템은 "맛있는 코드", 외부 도구를 포함하는 스크립트를 분류하면 페이지 방패에서 얻을 수있는 감지를 확인 할 수 없습니다. 기계 학습 (ML) 모델은 'Cloudflare'-specific 기술입니다.

'Cloudflare'의 분류는 거짓 긍정적이며 계정 팀에 문의하여 페이지 방패의 밑면 기술을 향상시킬 수 있습니다.

## 4. (선택) 스크립트 내용 분석

다음 분석의 일부를 수행하기 위해 가상 머신을 사용할 수 있습니다.

<Steps>
  1. 스크립트 URL을 열고 스크립트 소스 코드를 가져옵니다. 스크립트가 obfuscated 또는 인코딩된 경우, 이것은 스크립트가 악화되는 표시일 수 있습니다.
  2. 모든 hostnames 또는 IP 주소를 위한 스크립트 소스 코드를 스캔합니다.
  3. 각 호스트 이름 또는 IP 주소를 확인하려면 'Cloudflare'의 Security Center Investigate 플랫폼을 사용하여 위협 정보 및 / 또는 Compromise의 잠재적 인 지표를 온라인으로 검색하십시오.
</Steps>

***

## 이름 \*

악성 리소스 경고를 트리거 한 리소스:

- 당신의 신청에서 적극적으로 현재
- 악의적 인 호스트 또는 IP 주소로로드되거나 악의적 인 코드가 있습니다.
- 악명 높은 호스트 이름 또는 IP 주소는 소스 코드에, 이는 obfuscated / 인코딩 될 수있다

이 지표가 지속적인 활성 타협의 서명이 될 수 있기 때문에 더 조사해야합니다.
