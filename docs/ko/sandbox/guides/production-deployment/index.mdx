:::note\[ 미리보기 URL에만 필수]
사용자 정의 도메인 설정은 ONLY 당신이 사용 하는 경우 필요`exposePort()`sandboxes에서 서비스를 노출. 애플리케이션이 포트를 노출하지 않으면 배포할 수 있습니다.`.workers.dev`이 윤곽 없이.
주요 특징

Sandbox SDK 애플리케이션을 미리 보기 URL 지원으로 제작합니다. 미리보기 URL은 와일드 카드 DNS 라우팅이 필요하므로 각 노출 포트의 고유한 하위 도메인을 생성합니다.`https://8080-abc123.yourdomain.com`.

더 보기`.workers.dev`도메인은 Wildcard subdomains를 지원하지 않습니다, 그래서 미리 URL을 사용하는 생산 배포는 사용자 정의 도메인이 필요합니다.

:::Cution\[TLS를 위한 Subdomain 깊이 사정]
작업자가 하위 도메인에서 실행되는 경우 (예를 들어,`sandbox.yourdomain.com`), 미리보기 URL은 두 번째 레벨 와일드 카드가`*.sandbox.yourdomain.com`. Cloudflare의 보편적인 SSL은 첫번째 수준 wildcards를 포함합니다 (`*.yourdomain.com`), 그래서 당신은 증명서 덮음을 필요로 합니다`*.sandbox.yourdomain.com`. 그것 없이, 미리보기 URL은 TLS Handhake 오류로 실패합니다.

당신은 세 가지 옵션이 있습니다 :

- **apex 도메인에 배포** (`yourdomain.com`) 그래서 미리 URL은 첫 번째 수준에 머물 (`*.yourdomain.com`), 보편적인 SSL은 자동적으로 덮습니다. 이것은 가장 간단한 옵션입니다.
- **제품 정보[고급 인증서 관리자](/ssl/edge-certificates/advanced-certificate-manager/)**($ 10 / 월) 인증서를 제공`*.sandbox.yourdomain.com`Cloudflare dashboard를 통해.
- **사용자 정의 인증서 업로드**같은 공급자에서[암호화하자](https://letsencrypt.org/)(무료). 와일드카드 인증서 생성`*.sandbox.yourdomain.com`DNS-01 도전을 사용하여 Cloudflare dashboardXQ를 통해 업로드**SSL/TLS > Edge 인증서 >[주문 증명서](/ssl/edge-certificates/custom-certificates/)**. 만료되기 전에 갱신해야 합니다.
  주요 특징

## 자주 묻는 질문

- 활성 Cloudflare 영역 도메인
- 사용중인 작업자`exposePort()`
- [Wrangler 클립](/workers/wrangler/install-and-update/)설치하기

## 설치하기

### Wildcard DNS 레코드 만들기

Cloudflare dashboard에서 도메인으로 이동하고 A 레코드를 만듭니다.

- **제품정보**: 아
- **이름 \***: \* (wildcard)
- **IPv4 주소**: 192.0.2.0
- **프록시 상태**: Proxied (오렌지 클라우드)

Cloudflare의 프록시를 통해 모든 하위 도메인 경로. IP 주소`192.0.2.0`Cloudflare가 발음될 때 문서 주소 (RFC 5737)입니다.

### Worker 노선 구성

Wrangler 구성에 와일드 카드 경로 추가:

<WranglerConfig>
  ```jsonc
  {
  	"$schema": "./node_modules/wrangler/config-schema.json",
  	"name": "my-sandbox-app",
  	"main": "src/index.ts",
  	"compatibility_date": "$today",
  	"routes": [
  		{
  			"pattern": "*.yourdomain.com/*",
  			"zone_name": "yourdomain.com"
  		}
  	]
  }
  ```
</WranglerConfig>

기타 제품`yourdomain.com`당신의 실제적인 도메인으로. 이 모든 하위 도메인 요청을 작업자에게 전달하고 Cloudflare를 활성화하여 SSL 인증서를 자동으로 제공합니다.

### 계정 만들기

작업자를 배포:

```sh
npx wrangler deploy
```

## 계정 만들기

URL을 미리 테스트:

```typescript
//요청에서 hostname 추출
const { hostname } = new URL(request.url);

const sandbox = getSandbox(env.Sandbox, 'test-sandbox');
await sandbox.startProcess('python -m http.server 8080');
const exposed = await sandbox.exposePort(8080, { hostname });

console.log(exposed.url);
//모델 번호: https://8080-test-sandbox.yourdomain.com
```

브라우저의 URL을 방문하여 서비스에 액세스할 수 있습니다.

## 문제 해결

- **CustomDomain필수**: 작업자가 배포되지 않습니다.`.workers.dev`그리고 와일드카드 DNS 레코드와 경로가 올바르게 구성된다.
- **SSL/TLS 오류**: 인증 규정에 대한 몇 분을 기다립니다. DNS 레코드를 검증하고 SSL/TLS 모드는 dashboard에서 "Full"또는 "Full (strict)"로 설정됩니다. 작업자가 하위 도메인에 있다면 (예를 들어,`sandbox.yourdomain.com`), 보편적인 SSL은 두번째 수준 wildcard를 커버하지 않습니다`*.sandbox.yourdomain.com`— 보기[TLS 주의](#subdomain-depth-matters-for-tls)옵션에 대한이 페이지 상단에.
- **재해하지 않는 미리보기 URL**: 와일드카드 DNS 레코드가 존재하고 proxied를 확인합니다. DNS 전파를 위해 30-60 초를 기다립니다.
- **액세스하지 않는 포트**: 서비스 바인딩을 보장합니다.`0.0.0.0`(없음)`localhost`·`proxyToSandbox()`작업자의 fetch 핸들러에서 먼저 호출됩니다.

자세한 문제 해결, 참조[Workers 라우팅 문서](/workers/configuration/routing/).
