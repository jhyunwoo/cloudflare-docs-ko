기본 런타임 이미지를 확장하여 자체 패키지, 도구 및 구성으로 sandbox 컨테이너 이미지를 사용자 정의합니다.

## Base 이미지

Sandbox SDK는 여러 Ubuntu 기반 이미지 변형을 제공합니다. 사용 사례에 맞는 것을 선택:

| 이름 \*  | 태그 suffix   | 사용 사례                                  |
| ------ | ----------- | -------------------------------------- |
| 기본 정보  | (없음)        | JavaScript/TypeScript 작업대를 위한 Lean 이미지 |
| Python | `-python`   | 데이터 과학, ML, Python 코드 실행               |
| 오픈코드   | `-opencode` | OpenCode CLI와 AI 코딩 에이전트               |

```dockerfile
# Default - lean, no Python
FROM docker.io/cloudflare/sandbox:0.7.0

# Python - includes Python 3.11 + data science packages
FROM docker.io/cloudflare/sandbox:0.7.0-python

# OpenCode - includes OpenCode CLI for AI coding
FROM docker.io/cloudflare/sandbox:0.7.0-opencode
```

:::caution\[Version 동기화 필요]
항상 Docker 이미지 버전과 npm 패키지 버전과 일치합니다. 당신이 사용 하는 경우`@cloudflare/sandbox@0.7.0`, 사용`docker.io/cloudflare/sandbox:0.7.0`(또는 변형) 기본 이미지로.

**왜 이 문제**: SDK는 자동으로 시작에 버전 호환성을 확인합니다. Mis matching version은 끊기거나 예기치 않은 기능을 일으킬 수 있습니다. 버전이 일치하지 않으면 로그에 경고가 표시됩니다.

이름 \*[버전 호환성](/sandbox/concepts/sandboxes/#version-compatibility)문제 해결 버전 mismatch 경고.
주요 특징

### 기본 이미지

기본 이미지는 JavaScript 및 TypeScript 워크로드에 최적화되어 있습니다.

- 우분투 22.04 LTS 기지
- Node.js 20 LTS 와 npm
- 분 1.x (JavaScript/TypeScript 런타임)
- 시스템 유틸리티 : 컬, wget, git, jq, zip, unzip, 파일, procps, ca-certificates

### Python 이미지

더 보기`-python`변형은 기본 이미지에서 모든 것을 포함합니다 :

- Python 3.11 핍과 venv
- 사전 설치된 패키지: matplotlib, numpy, pandas, ipython

### OpenCode 이미지

더 보기`-opencode`변형은 기본 이미지에서 모든 것을 포함합니다 :

- [OpenCode 클립](https://opencode.ai)AI-powered 코딩 에이전트

## 사용자 정의 이미지 만들기

이름 \*`Dockerfile`프로젝트 루트:

```dockerfile title="Dockerfile"
FROM docker.io/cloudflare/sandbox:0.7.0-python

# Install additional Python packages
RUN pip install --no-cache-dir \
    scikit-learn==1.3.0 \
    tensorflow==2.13.0 \
    transformers==4.30.0

# Install Node.js packages globally
RUN npm install -g typescript ts-node prettier

# Install system packages
RUN apt-get update && apt-get install -y \
    postgresql-client \
    redis-tools \
    && rm -rf /var/lib/apt/lists/*
```

(주)`wrangler.jsonc`reference 당신의 Dockerfile에:

```jsonc title="wrangler.jsonc"
{
	"containers": [
		{
			"class_name": "Sandbox",
			"image": "./Dockerfile",
		},
	],
}
```

당신이 실행할 때`wrangler dev`또는`wrangler deploy`, Wrangler는 자동적으로 도커 이미지를 건설하고 Cloudflare의 콘테이너 레지스트리에 그것을 밀어냅니다. 당신은 수동으로 이미지를 구축하거나 게시 할 필요가 없습니다.

## arbitrary 기본 이미지 사용

독립 바이너리를 사용하여 Docker 이미지에 sandbox 기능을 추가 할 수 있습니다. 이 접근 방식을 사용하면 Cloudflare 기본 이미지에 따라 기존 이미지를 사용할 수 있습니다.

```dockerfile title="Dockerfile"
FROM your-custom-image:tag

# Copy the sandbox binary from the official image
COPY --from=docker.io/cloudflare/sandbox:0.7.0 /container-server/sandbox /sandbox

ENTRYPOINT ["/sandbox"]
```

더 보기`/sandbox`Binary는 SDK 통신을 가능하게 하는 HTTP API 서버를 시작합니다. 당신은 선택적으로 자신의 시작 명령을 실행할 수 있습니다:

```dockerfile title="Dockerfile"
FROM node:20-slim

COPY --from=docker.io/cloudflare/sandbox:0.7.0 /container-server/sandbox /sandbox

# Copy your application
COPY . /app
WORKDIR /app

ENTRYPOINT ["/sandbox"]
CMD ["node", "server.js"]
```

사용 방법`CMD`, sandbox 바이너리는 적절한 신호 전달과 어린이 프로세스로 명령을 실행합니다.

## 사용자 정의 시작 스크립트

더 복잡한 시작 순서에 대 한, 사용자 정의 시작 스크립트를 만들:

```dockerfile title="Dockerfile"
FROM docker.io/cloudflare/sandbox:0.7.0-python

COPY my-app.js /workspace/my-app.js
COPY startup.sh /workspace/startup.sh
RUN chmod +x /workspace/startup.sh

CMD ["/workspace/startup.sh"]
```

기본 이미지는 이미 올바른 설정`ENTRYPOINT`, 그래서 당신은 단지 제공해야`CMD`. sandbox 바이너리는 HTTP API 서버를 시작, 그 후 당신의 스파게`CMD`적절한 신호 전달을 가진 아이 과정으로.

```bash title="startup.sh"
#!/bin/bash

#배경에서 서비스 시작
node /workspace/my-app.js &

#추가 서비스
redis-server --daemonize yes
until redis-cli ping; do sleep 1; done

#스크립트 실행을 유지 (샌드 박스 바이너리 API 서버를 처리)
wait
```

:::note\[Legacy 스타트업 스크립트]
기존의 시작 스크립트가 있는 경우`exec bun /container-server/dist/index.js`, 그들은 backwards 겸용성을 위해 계속할 것입니다. 그러나, 우리는 새로운 접근법으로 마이그레이션하는 것이 좋습니다.`CMD`당신의 시작 스크립트. 과도하지 마십시오`ENTRYPOINT`기본 이미지를 확장 할 때.
