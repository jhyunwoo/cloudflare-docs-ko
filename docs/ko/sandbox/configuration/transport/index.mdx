Sandbox SDK가 전송 모드를 사용하여 컨테이너와 통신하는 방법을 구성합니다.

## 제품정보

Sandbox SDK는 튼튼한 개체와 컨테이너 사이의 통신을위한 두 개의 운송 모드를 지원합니다.

- **HTTP 수송**(과태) - 각 SDK 작업은 컨테이너에 별도의 HTTP 요청을 만듭니다.
- **WebSocket 운송**- 모든 SDK 작업은 단일 지속성 WebSocket 연결을 통해 다중화됩니다.

## WebSocket 운송을 사용할 때

작업자 또는 튼튼한 개체가 요청당 많은 SDK 작업을 할 때 WebSocket 수송을 사용하십시오. 이것은 타격을 피합니다[subrequest 제한](/workers/platform/limits/#subrequests).

### 구독 제한

Cloudflare Workers는 컨테이너 API 통화를 포함하여 외부 서비스에 요청을 할 때 적용하는 보조 제한이 있습니다.

- **Workers 무료**: 50 요청 당 하위 요청
- **Workers 유료**: 요청당 1,000개의 하위 요청

HTTP 수송 (과태)로, 각 SDK 가동 (`exec()`, `readFile()`, `writeFile()`, 등)는 1개의 subrequest를 소모합니다. 단일 요청에 많은 샌드 박스 작업을 수행하는 응용 프로그램은 이러한 제한을 명중 할 수 있습니다.

### WebSocket 운송이 도움이 되는 방법

WebSocket 운송은 컨테이너에 단일 지속적 연결을 설정하고 모든 SDK 작업을 여러 번 설정합니다. WebSocket 업그레이드는 다음과 같습니다.**1개의 subrequest**몇 가지 작업에 관계없이 나중에 수행됩니다.

**HTTP 수송과 예 (4 subrequests):**

```typescript
await sandbox.exec("python setup.py");
await sandbox.writeFile("/app/config.json", config);
await sandbox.exec("python process.py");
const result = await sandbox.readFile("/app/output.txt");
```

**WebSocket 수송과 같은 코드 (1 subrequest):**

```typescript
//Identical code - 수송은 환경변수를 통해 형성됩니다
await sandbox.exec("python setup.py");
await sandbox.writeFile("/app/config.json", config);
await sandbox.exec("python process.py");
const result = await sandbox.readFile("/app/output.txt");
```

## 제품 설명

설정하기`SANDBOX_TRANSPORT`작업자의 구성에서 환경 변수. SDK는 Worker 환경 바인딩 (컨테이너 내부에서 아닙니다)에서 이것을 읽습니다.

### HTTP 수송 (과태)

HTTP 수송은 기본이며 추가 구성이 필요하지 않습니다.

### WebSocket 운송

WebSocket 전송 활성화`SANDBOX_TRANSPORT`당신의 노동자의`vars`:

<WranglerConfig>
  ```jsonc
  {
  	"name": "my-sandbox-worker",
  	"main": "src/index.ts",
  	"compatibility_date": "$today",
  	"vars": {
  		"SANDBOX_TRANSPORT": "websocket"
  	},
  	"containers": [
  		{
  			"class_name": "Sandbox",
  			"image": "./Dockerfile",
  		},
  	],
  	"durable_objects": {
  		"bindings": [
  			{
  				"class_name": "Sandbox",
  				"name": "Sandbox",
  			},
  		],
  	},
  }
  ```
</WranglerConfig>

앱 코드 변경이 필요하지 않습니다. SDK는 모든 작업을 위해 구성된 수송을 자동으로 사용합니다.

## 운송 행동

### 연결 수명주기

**HTTP 수송:**

- 각 SDK 작업에 대한 새로운 HTTP 요청 생성
- 지속적인 연결 없음
- 각 요구는 무소속하고 무정합니다

**WebSocket 수송:**

- 첫번째 SDK 가동에 WebSocket 연결 설치
- 모든 후속 작업에 대한 지속적인 연결 유지
- 연결은 sandbox 잠이거나 evicted 때 닫힙니다
- 연결이 떨어지면 자동으로 다시 연결

### 고객지원

모두 지원 스트리밍 운영 (like)`exec()`실시간 출력):

- **HTTP 수송**- Server-Sent 이벤트 사용 (SSE)
- **WebSocket 운송**- WebSocket 스트리밍 메시지 사용

귀하의 코드는 전송 모드에 관계없이 동일합니다.

### 오류 처리

둘 다 수송은 동일한 과실 취급 행동을 제공합니다. SDK는 exponential 백오프와 함께 일시적인 오류(503 응답과 동일)에 자동으로 표시됩니다.

WebSocket-specific 행동:

- 연결 실패 방아쇠 자동 재연결
- 투명하게 WebSocket 차단을 처리하는 SDK
- In-flight 가동은 재연결 도중 잃지 않습니다

## 수송 선택

| 채용정보                       | 교통수단      |
| -------------------------- | --------- |
| 요청당 많은 SDK 운영              | 웹소켓       |
| Workers 또는 Durable Objects | 웹소켓       |
| 접근 제한 제한                   | 웹소켓       |
| 단순, infrequent sandbox 사용  | HTTP (과태) |
| 개별 요청을 디버깅 또는 검사           | HTTP (과태) |

:::note\[기본은 대부분의 사용 사례에 충분하다]
HTTP 수송은 대부분의 신청을 위해 잘 작동합니다. WebSocket 운송으로 전환하면 하위 퀘스트 제한을 타격하거나 요청당 많은 빠른 샌드박스 작업을 수행 할 수 있습니다.

## Migration 가이드

수송 사이 전환은 부호 변화를 요구합니다.

### HTTP에서 WebSocket로 전환

더 보기`SANDBOX_TRANSPORT`내 계정`wrangler.jsonc`:

<WranglerConfig>
  ```jsonc
  {
  	"vars": {
  		"SANDBOX_TRANSPORT": "websocket"
  	},
  }
  ```
</WranglerConfig>

다음 배포:

```bash
npx wrangler deploy
```

### WebSocket에서 HTTP로 전환

제거하기`SANDBOX_TRANSPORT`변수 (또는 그것을 설정`"http"`):

<WranglerConfig>
  ```jsonc
  {
  	"vars": {
  		//SANDBOX TRANSPORT를 제거하거나 "http"로 설정
  	},
  }
  ```
</WranglerConfig>
