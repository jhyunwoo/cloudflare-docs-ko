Cloudflare Realtime TURN 서비스는 바이트의 진입 및 egress 사용을 계산합니다. TURN 분석 API를 사용하여 실시간 및 과거 데이터에 액세스할 수 있습니다. 한 번에 TURN 사용 데이터를 볼 수 있습니다.

Cloudflare TURN 분석은 GraphQL API에서만 가능합니다.

:::note\[API 토큰 권한]

Realtime GraphQL API에 쿼리를 만들기 위해 API 토큰에 "Account Analytics" 권한이 필요합니다.
주요 특징

:::참조

이름 \*[그래프QL API](/analytics/graphql-api/)GraphQL 클라이언트를 설정하는 방법에 대한 자세한 내용은. 아래 예제는 동일한 GraphQL 엔드포인트를 사용합니다.`https://api.cloudflare.com/client/v4/graphql`.
:::

## 유효한 미터 및 차원

TURN 분석은 다양한 방법으로 쿼리 및 집계 할 수있는 풍부한 데이터를 제공합니다.

### 미터

다음 메트릭을 쿼리 할 수 있습니다.

- **egress바이트**: TURN 서버에서 클라이언트로 보낸 총 바이트
- **관련 기사**: TURN 서버에 의해 수신된 총 바이트
- **동시 연결**: 동시 연결 평균 수

이 메트릭스 지원 집계`sum`·`avg`기능.

### 크기 (mm)

다음 크기로 데이터를 깰 수 있습니다:

- **시간 집계**: `datetime`, `datetimeMinute`, `datetimeFiveMinutes`, `datetimeFifteenMinutes`, `datetimeHour`
- **Geographic의 특징**: `datacenterCity`, `datacenterCountry`, `datacenterRegion`(Cloudflare 데이터 센터 위치)
- **이름 \***: `keyId`, `customIdentifier`, `username`

### 필터링

TURN 분석에서 데이터를 필터링 할 수 있습니다:

- 일정 범위
- TURN 키 ID
- TURN 사용
- 사용자 정의 식별자

:::참조

[사용자 정의 식별자](/realtime/turn/replacing-existing/#tag-users-with-custom-identifiers)시스템에 다른 사용자에 대 한 사용의 유용 합니다.

:::

## GraphQL 클라이언트

GraphQL은 자체 문서화 프로토콜입니다. GraphQL 클라이언트를 사용하여 스키마 및 사용 가능한 필드를 탐험 할 수 있습니다. 인기 옵션 포함:

- **[사이트맵](https://altairgraphql.dev/)**: schema 문서 탐색기가있는 GraphQL 클라이언트
- **[그래피QL](https://github.com/graphql/graphiql)**: 오리지널 GraphQL IDE
- **[포스트맨](https://www.postman.com/)**: schema introspection과 GraphQL 쿼리 지원

전체 스키마를 탐험하려면 클라이언트를 구성하여 연결`https://api.cloudflare.com/client/v4/graphql`API 자격으로. 더 알아보기[GraphQL 스키마를 탐험](/analytics/graphql-api/getting-started/explore-graphql-schema/)상세 설명.

## 유용한 TURN 분석 쿼리

다음은 일반적인 usecases에 대한 몇 가지 예 쿼리입니다. 당신은 당신의 사용 케이스를 적응시키고 분석 자료에 다른 보기를 얻을 수 있습니다.

### 한 번에 데이터 사용과 동시 연결

이 포괄적 인 쿼리는 동시 여러 미터를 검색하는 방법을 보여줍니다. 동시 연결, egress 및 5 분 간격의 진입 바이트. 이것은 dashboardS를 건축하고 순간 사용법을 감시하기를 위해 유용합니다.

```graphql
query concurrentConnections {
	viewer {
		accounts(filter: { accountTag: $accountId }) {
			callsTurnUsageAdaptiveGroups(
				limit: 10000
				filter: { date_geq: $dateFrom, date_leq: $dateTo }
			) {
				dimensions {
					datetimeFiveMinutes
				}
				avg {
					concurrentConnectionsFiveMinutes
				}
				sum {
					egressBytes
					ingressBytes
				}
			}
		}
	}
}
```

분석에 따라 다른 시간 집계 간격을 선택할 수 있습니다.

- **`datetimeMinute`**: 1분 간격 (최대 과립)
- **`datetimeFiveMinutes`**: 5 분 간격 (dashboards를 위해 추천하는)
- **`datetimeFifteenMinutes`**: 15분 간격
- **`datetimeHour`**: 시간 간격 (장기적인 추세를 위해 최상)
