RealtimeKit SDK를 통해 회의에 참여하기 전에, 귀하의 백엔드는 그 회의를 사용하여 참가자로 추가해야합니다[Participant API 추가](/api/resources/realtime_kit/subresources/meetings/methods/add_participant/)·
RealtimeKit에서, a**이름 \***&#xD2B9;정 회의에 참여할 수 있는 사용자를 나타냅니다.

학생을 교실에 등록 할 때이 생각할 수 있습니다. 회의는 교실이며 참가자를 추가하는 것은 그들이 참석할 수 있도록 사용자가 등록하는 방법입니다.

당신은 참가자를 추가 할 때, 당신은 또한 그것을 선택합니다[기타 제품](/realtime/realtimekit/concepts/preset/)신청하기 사전 설정은 역할, 권한 및 정의
그 참가자의 회의 경험.

### 참여 토큰

회의에 참여할 때[참가자 추가](/api/resources/realtime_kit/subresources/meetings/methods/add_participant/)API 엔드 포인트, 그것은 반환:

- 참여자`id`회의 내에서이 참가자를 식별합니다.
- 인증 받기`token`그 참가자를 위해.

당신의 백엔드는 당신의 frontend 신청에 유효합니다. 사용자가 회의에 참여하도록 선택할 때, frontend는 RealtimeKit SDK에 토큰을 전달합니다.

RealtimeKit는 토큰을 사용하여 참가자를 인증하고 회의 및 참가자가 참여하는 것을 결정합니다. 유효한 인증 토큰 없이,
SDK는 그 참가자를 대신하여 회의에 참여할 수 없습니다. 참가자는 유효한 인증 토큰을 가지고 있으며, 참가자는 한 번에 동일한 회의의 여러 라이브 세션에 참여할 수 있습니다.

### 토큰 유효성 및 새로 고침

참가자 인증 토큰은 시간이 지남에 따라 만료됩니다. 토큰이 만료되면 회의에서 동일한 사용자에게 새로운 참가자를 만들 필요가 없습니다.

대신, 귀하의 백엔드가 호출 할 수 있습니다[개인 정보 보호 정책](/api/resources/realtime_kit/subresources/meetings/methods/refresh_participant_token/)API 엔드포인트.
이 엔드포인트는 기존 참가자 레코드에 대한 새로운 인증 토큰을 발행하고, 참가자와 같은 세부 정보를 유지`id`그리고 같은 미리 설치.

### 사용자 정의 participant 식별자

participant를 추가할 때, 당신은 선택적으로 custom participant 식별자를 제공할 수 있습니다, 것과 같이 불린`custom_participant_id`. 이 가치는 당신의 사용을 위해 순전히 입니다.
RealtimeKit 저장하고 API에서 반환하지만 액세스 제어를 사용하지 않습니다. 응용 프로그램의 사용자를 RealtimeKit participant로 맵핑 할 수 있습니다.
RealtimeKit 세션 데이터, 이벤트 또는 시스템의 사용자 정보와 분석.

numeric user id 또는 UUID와 같은 자신의 시스템에서 안정적인 내부 식별자를 사용합니다.
