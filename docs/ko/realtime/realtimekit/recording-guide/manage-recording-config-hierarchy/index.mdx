이 문서는 overview의 사전 구조로 시스템 내에서 레코딩 구성을 관리합니다. 그것은 다양한 구성 수준이 상호 작용하고 설정 우선 순위를 설명합니다. 레코딩 구성은 세 가지 다른 수준에서 정의 할 수 있습니다.

- [미팅 API 시작](/api/resources/realtime_kit/subresources/recordings/methods/start_recordings/)
- [미팅 API 만들기](/api/resources/realtime_kit/subresources/meetings/methods/create/)
- 연락처[Cloudflare RealtimeKit 대시보드](https://dash.cloudflare.com/?to=/:account/realtime/kit)

## 기록적인 윤곽을 이해하십시오

녹음 구성의 선행을 컴파일하려면 다음 세부 사항으로 delve에 중요합니다. 이 이해는 API와 개발자 포털을 통해 여러 구성을 처리할 때 중요합니다.

| 이름 \* | 사이트맵                                                                                         | 이름 \*                                                                             |
| ----- | -------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 1     | [녹화 시작 API](/api/resources/realtime_kit/subresources/recordings/methods/start_recordings/)설정 | 시스템에 가장 높은 우선 순위. 여기에 정의 된 모든 설정은 다른 구성에 대해 우선 순위를 부여합니다.                         |
| 2     | [미팅 API 만들기](/api/resources/realtime_kit/subresources/meetings/methods/create/)설정            | 시스템의 우선 순위의 두 번째 수준. 여기에 설정 supersede Org Level config 하지만 미팅 API 구성을 녹화 시작 하지.   |
| 3     | Dashboard를 통해 지정                                                                             | 시스템에 가장 낮은 우선 순위. 여기서 정의된 설정은 미팅 API 구성을 기록하고 미팅 API 구성을 작성하여 overridden이 될 것입니다. |

## 보기 Scenario

행동의 선행 순서를 설명하려면 다음과 같은 회의의 시나리오를 고려하십시오.

1. Org 수준 Config는 Cloudflare R2 물통에서 저장될 기록이라고 지정합니다.

2. H264 코덱을 사용하여 AWS S3 스토리지 버킷에 저장된 미팅 API 세트 레코딩을 만듭니다.

3. 회의 API를 녹화 시작하면 VP8 코덱을 사용하여 GCS 버킷에서 레코딩을 저장할 수 있습니다.

이 시나리오에서 회의 API를 기록하는 시작은 Meeting API Config 및 Org Level Config을 만들기에 대해 전진합니다.
그 결과, 회의의 녹음은 다른 수준에서 기본 설정에 관계없이 VP8 코덱을 사용하여 GCS 버킷에 저장됩니다.
