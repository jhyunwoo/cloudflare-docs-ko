Cloudflare의 제한 및 타임아웃 이해 Realtime은 애플리케이션의 성능과 신뢰성을 최적화하는 데 중요합니다. 이 섹션은 Cloudflare를 통합 할 때 키 제약 및 행동을 개요 앱으로 실시간.

## 무료 다운로드

- 각 계정은 Cloudflare에서 클라이언트에게 1,000GB/month의 데이터 전송을 무료로 가져옵니다.
- 클라이언트에서 Cloudflare에 데이터 전송은 항상 무료입니다.

## 제한 사항

- **API 세션 당 실시간**: 각 세션당 초당 최대 50개의 API 호출을 할 수 있습니다. 앱 기반에 제한이 없습니다. 다만 세션.

- **API 통화 당 트랙**: 최대 64개의 트랙이 단일 API 호출에 추가될 수 있습니다. 세션에 더 많은 트랙을 추가해야하는 경우 여러 API 호출에서 배포해야합니다.

- **세션 당 트랙**: 세션이 포함될 수 있는 트랙 수에 대한 상한 제한이 없습니다. 실제 제한은 연결의 대역폭과 Cloudflare에서 관리됩니다.

## Inactivity 운동

- **연락처**: 트랙은 자동으로 타임 아웃과 쓰레기 수거 후 30 초의 inactivity, 여기서 inactivity는 Cloudflare에 의해 수신되는 미디어 패킷으로 정의됩니다. 이 메커니즘은 트랙을 사용하는 모든 세션에서 자원 및 세션 정리의 효율적인 사용을 보장합니다.

## PeerConnection 요구 사항

- **세션 상태**: 세션에 대한 모든 작업 (예를 들어, 당기기 또는 푸시 트랙), PeerConnection 상태는해야합니다`connected`. 가동은 밖으로 타이밍의 앞에 이 국가를 기다리는 5 초 동안 막을 것입니다. 이것은 단지 활성 및 viable 세션이 미디어 전송에 종사한다는 것을 보장합니다.

## Connectivity 문제 처리

- **인터넷 연결 고려 사항**: 클라이언트와 CloudflareXQ 사이의 인터넷 연결 손실에 대한 잠재적 인 주소가 있어야합니다. 감지 및 재연결 전략을 구현하는 것은 세션 연속성을 유지하기 위해 권장됩니다. 이것은 연결 상태를 모니터링하기 위해 periodic 'heartbeat' 신호를 수신 할 수 있습니다. 연결 문제를 감지하면 자동으로 연결하고 새로운 세션을 수립하려고합니다. 세션 및 트랙은 타이밍 아웃 전에 30 초 동안 재사용 할 수 있으며 연결 시도를위한 간단한 창을 제공합니다.

이러한 제한에 대한 접착과 타임 아웃 행동을 이해하는 데 도움이 될 것입니다 당신의 응용 프로그램은 원활한 사용자 경험을 제공하면서 응답 및 안정 유지.

## 지원된 Codecs

Cloudflare Realtime은 다음과 같은 코덱을 지원합니다:

### 지원되는 영상 코덱

- **사이트맵**
- **사이트맵**
- **사이트맵**
- **사이트맵**
- **AV1의**

### 지원되는 오디오 코덱

- **오푸스**
- **G.711 PCM (A-law)**
- **G.711 PCM (μ-law)**

외부 48kHz PCM 지원을 위해[WebSocket 어댑터](/realtime/sfu/media-transport-adapters/websocket-adapter/)
:::
