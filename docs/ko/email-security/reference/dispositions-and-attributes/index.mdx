이메일 보안은 주어진 이메일 메시지, 도메인, URL, 또는 패킷이 일부인지 결정하는 다양한 요인을 사용합니다.<GlossaryTooltip term="phishing">피싱</GlossaryTooltip>공지사항 이 작은 패턴 평가는 자연에서 동적이며 — 많은 경우 — 단일 패턴은 최종 verdict를 결정하지 않습니다.

이 패턴에 따라 이메일 보안 추가`X-Headers`우리의 체계를 통과하는 각 이메일 메시지에.

## 회사연혁

이메일 보안을 통해 흐르는 모든 트래픽은 특정 메시지의 우리의 평가를 나타내는 최종 처분을받습니다. 각 메시지는 하나의 파기 헤더를 수신하므로 조직은 다른 메시지 유형에 명확하고 특정 작업을 수행 할 수 있습니다.

disposition 값을 사용할 수 있습니다.[당신의 quarantine 정책을 창조하십시오](/email-security/email-configuration/domains-and-routing/domains/)또는[auto-retract 설정](/email-security/email-configuration/retract-settings/).

### 사용 가능한 값

| 관련 제품                             | 이름 \*                                                                                              | Recommend                             |
| --------------------------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------- |
| `MALICIOUS`                       | 트래픽은 여러 피싱 버릴 트리거, 나쁜 행동에 대한 임계값을 충족, 활성 캠페인과 관련.                                                  | 제품정보                                  |
| `SUSPICIOUS`                      | 피싱 캠페인과 관련된 교통 (그리고 우리의 자동화 시스템에 의해 더 분석 아래).                                                      | 이 메시지를 내부적으로 평가하기 위해 연구.              |
| `SPOOF`                           | 이메일 인증 정책(SPF, DKIM, DMARC) 또는 mismatching을 가진 피싱 캠페인과 관련된 트래픽`Envelope From`·`Header From`가치.     | 투자 후 블록 (삼자 메일 서비스에 의해 트리거 될 수 있습니다). |
| `UCE`(Unsolicited Commercial 이메일) | 비 맛있는 상업 캠페인과 관련된 교통.                                                                              | 기존 스팸 quarantine 폴더로 경로.              |
| `BULK`(대시보드 전용)                   | 뉴스 레터 또는 마케팅 캠페인과 관련된 트래픽. 더 알아보기[연락처](https://en.wikipedia.org/wiki/Graymail_%28email%29)더 많은 정보. | 모니터 또는 태그                             |

### Header 구조

이메일 보안이 이메일 메시지에 disposition 헤더를 추가하면 헤더가 다음 형식과 일치합니다.

```txt
X-Area1Security-Disposition: [Value]
```

이메일 주소`SPAM`태그가 될 것입니다`UCE`(Unsolicited commercial email) 그들의 헤더에:

```txt
X-Area1Security-Disposition: UCE
```

## 관련 기사

이메일 보안을 통해 흐르는 트래픽은 하나 이상의 수신**관련 기사**특정 조건이 충족된다는 것을 나타냅니다.

### 사용 가능한 값

| 사이트 맵                                   | 지원하다                                                                                                                                                       |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CUSTOM_BLOCK_LIST`                     | 이 메시지는 사용자 정의 블록 목록에 정의 된 값을 일치합니다.                                                                                                                        |
| `NEW_DOMAIN_SENDER=<REGISTRATION_DATE>` | 새로 등록 된 도메인에서 메일에 알림. yyyyy-MM-dd HH로 포맷: mm:ss ZZZ.                                                                                                       |
| `NEW_DOMAIN_LINK=<REGISTRATION_DATE>`   | 새로 등록 된 도메인에 지적 링크와 메일에 경고. yyyyy-MM-dd HH로 포맷: mm:ss ZZZ.                                                                                                 |
| `ENCRYPTED`                             | 이메일 메시지가 암호화됩니다.                                                                                                                                           |
| `EXECUTABLE`                            | 이메일 메시지는 executable 파일이 포함되어 있습니다.                                                                                                                         |
| `BEC`                                   | 이메일 주소가 포함 된 표시[비즈니스 이메일 손상 (BEC)](/email-security/email-configuration/enhanced-detections/business-email-compromise/)이름 \* 관련 기사`MALICIOUS`또는`SPOOF`관련 기사 |

### Header 구조

이메일 보안이 이메일 메시지에 disposition 헤더를 추가하면 헤더는 다음과 같은 형식과 일치합니다.

```txt
X-Area1Security-Attribute: [Value]
X-Area1Security-Attribute: [Value2]
```
