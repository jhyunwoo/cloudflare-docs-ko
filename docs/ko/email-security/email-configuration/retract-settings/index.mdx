당신이 사용할 때[API 설정](/email-security/deployment/api/)이메일 보안을 위해 수신자의 메일 박스에 도달하여 메일을 방지할 수 없습니다.

그러나 - 그래서 당신은 또한 가지고[연구분야](/email-security/deployment/api/setup/#journaling-setup), [BCC 소개](/email-security/deployment/api/setup/#bcc-setup)또는[MS 그래프](/email-security/deployment/api/setup/office365-graph-api/)set up message retraction to take post-delivery action against suspicious message. 이러한 retractions는 Microsoft 365 및 Google Workspaces (Gmail)과 API 통합을 통해 발생합니다.

## Retraction 옵션

retraction를 설정하면 수동으로 메시지를 retract하거나 특정한 일치하는 메시지를 이동하기 위해 자동 retraction을 설정할 수 있습니다.<GlossaryTooltip term="disposition">관련 기사</GlossaryTooltip>사용자의 mailbox 내에서 특정 폴더에. 또한 Post Delivery Response 및 Phish Submission Response를 활성화하여 이메일 보안에 의해 수집 된 새로운 정보에 대해 이전에 전달 된 메시지를 재평가 할 수 있습니다. 이전에 전달 된 이메일은 이제이 새로운 일치<GlossaryTooltip term="phishing">피싱</GlossaryTooltip>관련 기사

더 알아보기[사이트맵](/email-security/deployment/api/setup/gsuite-bcc-setup/add-retraction/)·[사무실 365](/email-security/email-configuration/retract-settings/office365-retraction/)이 옵션에 대한 자세한 내용은 가이드.

## Retraction 미터

retraction 설정은 이 기능에 대한 메트릭에 액세스 할 수 있습니다. 로그인 후[이메일 보안 대시보드](https://horizon.area1security.com), 검색**관련 기사**카드. retractions의 미터는 다음과 같은 정보를 포함합니다:

- **총 회귀**: 재생의 총 양을 표시합니다.
- **지원하다**: 메시지 이메일 보안의 비율을 표시하고 성공적으로 추적 할 수 있었다.
- **뚱 베어**: 메시지 이메일 보안의 비율이 성공적으로 수행 할 수 없었다. 실패를 위한 이유:
  - 사용자가 이미 삭제되거나 junk로 메시지를 표시, 수동 또는 mailbox 필터를 통해.
  - retracted 메시지의 특정 사본은 mailbox로 존재하지 않을 수있는 배포 목록 주소로 보내졌으므로 retraction이 실패합니다. 그 배포 목록의 각 구성원에게 보낸 메시지의 별도 사본은 철회됩니다.
  - Retraction는 더 이상 권한이 없습니다.
- **자주 묻는 질문**: 시간에 메시지의 상태에 대한 참조는 철회되었습니다. 자동화된 재전송을 위해, 이메일 보안은 가능한 한 빨리 재전송을 수행하기 위한 것입니다 그래서 사용자는 메시지를 보거나 열 수 없습니다. 수동 반사는 나중에 발생할 수 있습니다, 그래서 메시지는 이미 읽을 가능성이 더.
- **자동/수동**: 자동 / 수동 모드를 통해 다시 추적 된 메시지의 비율을 참조하십시오.

제품정보**자주 묻는 질문**선택된 시간 간격을 위한 철회된 이메일을 위한 검색을 실행할 것입니다.
