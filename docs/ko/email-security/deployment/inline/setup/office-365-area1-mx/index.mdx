## 4. 메시지 처리

Office 365 (O365) 이메일 quarantine 또는 이메일 보안이 선호되는 조합을 사용하는 시나리오가있을 수 있습니다. 다음은 O365 quarantine을 사용하는 모범 사례입니다.[으로 disposition](/email-security/reference/dispositions-and-attributes/):

| 관련 제품        | - 연혁                                                                                                                                                                                                                                                                                                     |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `MALICIOUS`  | 항상 quarantined해야합니다. 사용자가 알림을 필요로 하는 경우, 관리자가 메시지를 공개해야 합니다. 사용자는 결코 자기 중급에 능력이 없다.`MALICIOUS`관리자의 승인없이 이메일. 이메일은 몸과 제목이 있어야합니다.                                                                                                                                                                         |
| `SUSPICIOUS` | 보장되지 않습니다. 이메일은 몸과 제목 태그가 있어야하며 사용자의 inbox 또는 junk 메일 폴더에 전달됩니다. 이점 고객은 사용해야 합니다[`URL defang`](/email-security/email-configuration/email-policies/link-actions/)이 disposition로, 모든 기업 고객은 항상 가능하게 합니다[이메일 링크 고립](/email-security/email-configuration/email-policies/link-actions/#email-link-isolation). |
| `SPAM`       | 항상 quarantined해야합니다. 사용자가 알림을 필요로 하는 경우, 그들은 또는 관리자 승인이 이메일 해제를 요구할 수 없습니다. 이메일은 제목이어야한다.                                                                                                                                                                                                                |
| `BULK`       | 보장되지 않습니다. 이메일은 태그가 있어야하며 inbox 또는 junk mail 폴더에 전달되어야 합니다.                                                                                                                                                                                                                                              |
| `SPOOF`      | 이름 \*`SPOOF`감지는 깨끗하고 잘 관리됩니다.[이용 약관](/email-security/email-configuration/lists/), 이메일은 항상 quarantined이어야한다. 만약에`SPOOF`감지는 깨끗하지 않습니다, 그들은 같은 치료해야`SPAM`당신이 가지고 있는 경우에 분해[향상된 탐지](/email-security/email-configuration/enhanced-detections/)구성. 그렇지 않은 경우`SPOOF`검출은 대우되어야 합니다`BULK`. 이메일은 몸과 제목이 있어야합니다.    |

Office 365 (O365)에는 다양한 옵션뿐만 아니라 제한 사항도 있습니다. 더 알아보기[Office 365 사용 사례](/email-security/deployment/inline/setup/office-365-area1-mx/use-cases/)더 많은 정보.

이메일 보안 대시보드에는[관리 quarantine](/email-security/email-configuration/admin-quarantine/), 그리고 당신은 또한 사용자 quarantine가 필요할 때 사무실 365 quarantine를 사용할 수 있습니다. 많은 quarantine 옵션이 있지만, 다음은 Office 365의 기본 사용 사례입니다.[예제 자습서](/email-security/deployment/inline/setup/office-365-area1-mx/use-cases/)덮개를 의지하십시오:

- **사용 케이스 1**: Office 365 junk 이메일 폴더 및 Admin Quarantine에 이메일 보내기 (추천)
- **사용 사례 2**: junk 이메일 폴더 및 사용자 관리 quarantine에 이메일을 전달하십시오 (이 사용 사례는 해당`MALICIOUS`이메일 보안 대시보드 내에서 quarantined
- **사용 케이스 3**: junk 이메일 및 관리 quarantine에 이메일 전달
- **사용 케이스 4**: 사용자 관리 quarantine 및 관리 quarantine에 이메일 전달
- **사용 케이스 5**: 사용자 junk 이메일 폴더 및 관리 quarantine에 이메일 전달

## 6 실행`Enable-OrganizationCustomization`(필수)

다음 단계는 이전에 Office 365 인스턴스를 사용자 정의하지 않은 경우에만 필요합니다. 이전 단계에서이 cmdlet을 실행하는 메시지를 수신하면 구성을 진행하기 위해 작업을 수행해야합니다. 이 변화는 효력을 가지고 가기 위하여 24 시간 오래 걸릴지도 모릅니다.

1. PowerShell을 관리자로 실행하고 다음 명령을 실행합니다. 이름 \*`Yes`신속한 경우:

```powershell
Install-Module ExchangeOnlineManagement
```

![PowerShell의 설치 모듈 명령을 실행](~/assets/images/email-security/deployment/inline-setup/o365-area1-mx/step1-install-module.png)

:::참조
이 모듈은 Microsoft 모듈입니다.
주요 특징

2. 정책 변경을 실행하고 Office 365 인스턴스에 연결하려면 다음 명령을 실행하십시오.

   ```powershell
   set-executionpolicy remotesigned
   ```

   정책 변경을 실행하고 싶다면 다음 명령을 실행하십시오.

   ```powershell
   Import-Module ExchangeOnlineManagement
   ```

   마지막으로 Office 365 인스턴스에 대해 인증된 다음을 실행합니다.

   ```powershell
   Connect-ExchangeOnline
   ```

   ![정책 변경을 실행하려면 명령을 실행](~/assets/images/email-security/deployment/inline-setup/o365-area1-mx/step2-set-executionpolicy.png)

3. 더 보기`Connect-ExchangeOnline`cmdlet는 로그인 할 수 있습니다. Office 365 관리자 계정으로 로그인하십시오. 일단 인증되면 PowerShell 프롬프트로 반환됩니다.

   ![Office 365 관리자 계정으로 로그인](~/assets/images/email-security/deployment/inline-setup/o365-area1-mx/step3-connect-exchange.png)

4. 당신은 그것을 확인할 수 있습니다`OrganizationCustomization`명령을 실행하여 활성화된다:

```powershell
Get-OrganizationConfig | FL isDehydrated
```

![get-organizationconfig 명령어 실행](~/assets/images/email-security/deployment/inline-setup/o365-area1-mx/step4-get-organizationconfig.png)

결과가 있다면`false`, `OrganizationCustomization`이미 활성화되고 더 많은 작업이 필요하지 않습니다. 사실, 당신은 그것을 활성화해야합니다:

```powershell
Enable-OrganizationCustomization
```

![이전 결과가 true 인 경우 조직 사용자 정의 모드를 활성화하십시오.](~/assets/images/email-security/deployment/inline-setup/o365-area1-mx/step4-enable-organizationcustomization.png)
