Dummy Sitekeys와 secret key를 사용하여 자동화된 테스트 제품군과 방해할 수 있는 실질적인 도전을 트리거하지 않고 Turnstile 구현을 테스트할 수 있습니다.

자동 테스트 스위트 (Selenium, Cypress, 또는 Playwright와 같은)는 Turnstile에 의해 봇으로 검출됩니다.

- Turnstile 블록 자동 브라우저가 실패하는 테스트
- 도전 변이로 인한 예측 가능한 시험 결과
- 양식 제출 테스트와 방해
- Difficulty 테스트 완전한 사용자 흐름

Dummy key는 예측 가능한 제어 응답을 제공하여 자동화된 테스트 도구를 사용합니다.

## 사이트 맵

| 사이트맵                       | 채용 정보        | Widget 유형 | 사용 사례                  |
| -------------------------- | ------------ | --------- | ---------------------- |
| `1x00000000000000000000AA` | 항상 패스        | 옵션 정보     | 성공적인 양식 제출             |
| `2x00000000000000000000AB` | 항상 실패        | 옵션 정보     | 시험 오류 처리 및 재시험 논리      |
| `1x00000000000000000000BB` | 항상 패스        | 옵션 정보     | invisible 위젯 성공 흐름 테스트 |
| `2x00000000000000000000BB` | 항상 실패        | 옵션 정보     | invisible 위젯 오류 처리     |
| `3x00000000000000000000FF` | 힘 상호 작용하는 도전 | 옵션 정보     | 테스트 사용자 상호 작용 시나리오     |

## 비밀 키 테스트

서버 측 유효성 검사를 위한 이 비밀 열쇠를 사용하십시오:

| 비밀 키                                  | 채용 정보                       | 사용 사례                 |
| ------------------------------------- | --------------------------- | --------------------- |
| `1x0000000000000000000000000000000AA` | 항상 유효한 패스                   | 성공적인 토큰 유효성 검사        |
| `2x0000000000000000000000000000000AA` | 항상 유효한 실패                   | Test validation 오류 처리 |
| `3x0000000000000000000000000000000AA` | "token already sent" 오류를 반환 | duplicate 토큰 처리       |

## - 연혁

### 지역 개발

어떤 도메인에서 키 작업을 테스트:

- `localhost`
- `127.0.0.1`
- `0.0.0.0`
- 모든 개발 도메인

Cloudflare는 생산에서 사용되는 사이트 키가 로컬 도메인을 허용하지 않는 것이 좋습니다 (`localhost`또는`127.0.0.1`), 그러나 사용자는 밑에 허용한 도메인의 명부에 국부적으로 도메인을 추가하기 위하여 선택할 수 있습니다[Hostname 관리](/turnstile/additional-configuration/hostname-management/). 더미 positionkeys는 어떤 도메인에서, 다음을 포함하여 사용될 수 있습니다`localhost`.

### 고객 측 테스트

테스트 사이트키로 생산 Sitekey를 교체하십시오.

```html
<!--개발/테스트-->
<div class="cf-turnstile" data-sitekey="1x00000000000000000000AA"></div>

<!--제품정보-->
<div class="cf-turnstile" data-sitekey="your-real-sitekey"></div>
```

### 서버 측 테스트

테스트 비밀 키로 생산 비밀 키를 교체합니다.

```js
//환경 기반 구성
const SECRET_KEY = process.env.NODE_ENV === 'production' 
  ? process.env.TURNSTILE_SECRET_KEY 
  : '1x0000000000000000000000000000000AA';

//유효성 검사
const validation = await validateTurnstile(token, SECRET_KEY);
```

### 환경 설정

다른 환경을 위한 다른 열쇠를 설치하십시오.

```shell

#.env.개발
TURNSTILE_SITEKEY=1x00000000000000000000AA
TURNSTILE_SECRET_KEY=1x0000000000000000000000000000000AA

#다운로드
TURNSTILE_SITEKEY=2x00000000000000000000AB
TURNSTILE_SECRET_KEY=2x0000000000000000000000000000000AA

#.env. 생산
TURNSTILE_SITEKEY=your-real-sitekey
TURNSTILE_SECRET_KEY=your-real-secret-key
```

## Dummy 토큰 행동

### 토큰 생성

테스트 sitekeys는 더미 토큰을 생성합니다:`XXXX.DUMMY.TOKEN.XXXX`

### 토큰 검증

- 비밀 키를 테스트 : 더미 토큰 만 받아 실제 토큰을 거부합니다.
- 생산 비밀 열쇠: 진짜 토큰만, reject dummy 토큰만 받아들입니다.

:::참조
생산 비밀 키는 더미 토큰을 거부합니다. 테스트 목적으로 dummy secret key를 사용해야 합니다.
주요 특징

### 유효성 응답

```json title="Success response"
{
  "success": true,
  "challenge_ts": "2022-02-28T15:14:30.096Z",
  "hostname": "localhost",
  "error-codes": [],
  "action": "test",
  "cdata": "test-data"
}
```

```json title="Failure response"
{
  "success": false,
  "error-codes": ["invalid-input-response"]
}

```

```json title="Token already redeemed"
{
  "success": false,
  "error-codes": ["timeout-or-duplicate"]
}
```

| `1x00000000000000000000AA` | `1x0000000000000000000000000000000AA` | 이 조합은 항상 성공적인 유효성 검사에서 발생합니다.              |
| `2x00000000000000000000AB` | `2x0000000000000000000000000000000AA` | 이 조합은 항상 실패합니다.                            |
