Turnstile가 문제가 발생할 수 있는 인스턴스가 있습니다.`error-callback`.

이러한 문제는 네트워크 연결 문제 및 브라우저 호환성 문제에서 구성 오류 및 도전 실패에 이르기까지 다양 할 수 있습니다.

오류가 발생하면 적절한 오류 처리를 구현하면 방문자가 도움이되는 피드백을 받고 응용 프로그램을 일시적으로 복구 할 수 있습니다.

더 알아보기[오류 코드](/turnstile/troubleshooting/client-side-errors/error-codes/)특정 오류 조건을 해결하는 문제 해결 지침.

## 오류 처리

더 보기`error-callback`명시적으로 렌더링 위젯과 옵션`data-error-callback`implicit 렌더링에 대한 속성은 JavaScript 콜백을 제공하여 잠재적 인 오류를 처리합니다.

이 콜백 메커니즘은 오류가 방문자에게 제시되는 방법에 대한 완전한 제어를 제공하고 응용 프로그램의 필요에 맞게 맞춤 복구 전략을 구현 할 수 있습니다.

<Tabs>
  <TabItem label="오류 콜백과 Explicit 렌더링">
    ```js wrap
    turnstile.render('#my-widget', {
      sitekey: 'your-sitekey',
      'error-callback': function(errorCode) {
        console.error('Turnstile error occurred:', errorCode);
        handleTurnstileError(errorCode);
        return true; //오류 처리 표시
      }
    });
    ```
  </TabItem>

  <TabItem label="Implicit 렌더링 오류 콜백">
    ```html wrap title="HTML"
    <div class="cf-turnstile" 
         data-sitekey="your-sitekey" 
         data-error-callback="onTurnstileError"></div>
    ```
  </TabItem>
</Tabs>

오류 콜백을 지정하는 것은 선택적이지만 생산 응용 프로그램에 권장됩니다. 오류 콜백이 설정되지 않으면, Turnstile는 오류에 JavaScript 예외를 던지고 페이지의 기능을 혼란시키고 가난한 사용자 경험을 만들 수 있습니다. 오류 콜백을 제공함으로써 이러한 예외를 잡고 처리 할 수 있습니다.

오류 콜백이 비-falsy 결과로 반환되면 Turnstile는 오류를 처리하고 추가 오류 로깅을 수행하지 않을 것이라고 가정합니다. 오류 콜백이 falsy 결과를 반환하면 (포함`undefined`), Turnstile는 개발 도중 벌레잡기를 위해 유용할 수 있는 오류 부호를 포함하는 JavaScript 콘솔에 경고를 기록할 것입니다.

오류 콜백은 첫 번째 매개 변수로 오류 코드를 검색합니다. 이 오류 코드는 첫 번째 세 자리가 오류 가족을 나타냅니다 (설정 문제, 네트워크 문제 또는 도전 실패와 같은) 구조화 된 형식을 따르고 나머지 자리는 그 가족 내에서 정확한 오류를 지정합니다.

```js wrap
function handleTurnstileError(errorCode) {
  const errorFamily = Math.floor(errorCode / 1000);
  
  switch(errorFamily) {
    case 100:
      showMessage('Please refresh the page and try again.');
      break;
    case 110:
      showMessage('Configuration error. Please contact support.');
      break;
    case 300:
    case 600:
      showMessage('Security check failed. Please try refreshing or using a different browser.');
      break;
    default:
      showMessage('An unexpected error occurred. Please try again.');
  }
}
```

## 관련 기사

기본적으로 Turnstile는 사용자가 개입하지 않고 일시적인 네트워크 문제 또는 임시 서비스 중단을 처리하는 데 도움이되는 문제를 해결하는 데 자동으로 의존합니다.

이 자동적인 retry 기계장치는을 위해 유용합니다[모바일 방문자](/turnstile/get-started/mobile-implementation/)네트워크의 연결이나 방문자가 가끔의 안정성 문제로 경험할 수 있습니다.

retries로 인해 이후의 실패가 관찰되면 오류 콜백은 동일한 underlying 문제에 대해 여러 번 호출 할 수 있습니다. 오류 처리 코드는 중복 오류 메시지를 표시하거나 반복적으로 동일한 복구 작업을 수행 할 수있는이 가능성을 고려해야합니다.

```js wrap
let retryCount = 0;

turnstile.render('#my-widget', {
  sitekey: 'your-sitekey',
  'error-callback': function(errorCode) {
    retryCount++;
    
    if (retryCount <= 2) {
      console.log(`Turnstile retry attempt ${retryCount}`);
      return false; //Turnstile를 다시 처리하자
    } else {
      showPersistentErrorMessage(errorCode);
      return true; //우리는 여기에서 그것을 취급할 것입니다
    }
  }
});
```

retry 행동을 retry 값 설정하여 조정할 수 있습니다.`never`기본값 대신`auto`. 이것은 Turnstile에서 자동적으로 구호하고, 때에 당신을 통제하고 회복 시도가 하는 방법을 주기 위하여 결과할 것입니다. 방문자를 확인하는 문제 또는 오류가 있으면 위젯이 재발하지 않으며 수동 동작을 취할 때까지 해당 실패 상태에 남아있을 것입니다.

```js wrap
turnstile.render('#my-widget', {
  sitekey: 'your-sitekey',
  retry: 'never',
  'error-callback': function(errorCode) {
    //모든 retry 논리를 제어
    setTimeout(() => {
      turnstile.reset('#my-widget');
    }, 3000);
  }
});
```

전화 번호`turnstile.reset()`관련 기사`error-callback`retry를 수동으로 트리거합니다. 이 접근법은 Exponential backoff, retrying, 또는 특정 오류가 발생하기 전에 사용자 확인과 같은 사용자 정의 재량 논리를 구현하려는 경우 유용합니다.

Turnstile를 위한 화물 사이 간격은 형성될 수 있습니다`retry-interval`옵션, 방문자의 전형적인 네트워크 조건을 위해 리트리 타이밍을 최적화 할 수 있습니다. 더 긴 간격은 더 느리고 또는 더 적은 믿을 수 있는 연결에 방문자를 위해 더 적합할지도 모릅니다, 더 짧은 간격은 전형적으로 안정되어 있는 연결을 가진 환경에서 잘 작동합니다.

```js wrap
turnstile.render('#my-widget', {
  sitekey: 'your-sitekey',
  retry: 'auto',
  'retry-interval': 8000, //retries 사이 8 초를 기다리십시오
  'error-callback': handleError
});
```

## 관련 링크

방문자가 합리적인 시간대 내에서 상호 작용하는 도전에 참여하지 않으면 타임 아웃 콜백 기능은 트리거됩니다. 이 타임아웃 메커니즘은 잘못된 상태로 남아있는 상황에서 문제를 방지하고 방문자가 작업이 필요할 때 피드백을받습니다.

예를 들어, Turnstile 위젯이 완료하는 데 몇 분이 필요할 수있는 형태로 구현되는 시나리오에서 위젯 내에서 상호 작용하는 도전은 확장 된 기간 동안 삭제 된 경우 발생됩니다. 방문자는 양식 필드를 채우고 Turnstile 도전을 내려다 볼 수 있으며 만료되거나 잘못된 토큰으로 양식을 제출하려고 시도 할 수있는 상황에 중점을 둡니다.

그런 경우,`timeout-callback`위젯의 활성화, 위젯을 활성화하여 필요한대로 재설정하고 적절한 지침을 제공합니다. 이 콜백은 Turnstile 위젯을 강조하면서 사용자 친화적 인 타임 아웃 핸들링을 구현하거나 알림을 표시하거나 자동으로 문제를 상쾌하게 할 수 있습니다.

```js wrap
turnstile.render('#my-widget', {
  sitekey: 'your-sitekey',
  callback: function(token) {
    console.log('Challenge completed successfully');
  },
  'timeout-callback': function() {
    console.log('Challenge timed out - user action required');
    document.getElementById('challenge-notice').textContent = 
      'Please complete the security check above to continue.';
    
    //선택적으로 위젯을 강조
    document.getElementById('my-widget').style.border = '2px solid orange';
  },
  'expired-callback': function() {
    console.log('Token expired - challenge needs refresh');
    document.getElementById('challenge-notice').textContent = 
      'Security check expired. Please try again.';
  }
});
```
