데이터 속성 또는 JavaScript 렌더링 매개 변수를 사용하여 Turnstile 위젯의 외관, 행동 및 기능을 구성하십시오.

## Rendering 방법

Turnstile 위젯은 implicit 또는 명시된 렌더링을 사용하여 구현할 수 있습니다.

<Tabs>
  <TabItem label="Implicit 연출">
    Implicit 렌더링 자동적으로 요소에 대한 HTML을 스캔`cf-turnstile`클래스와 렌더링 위젯 때 페이지로드. 간단한 구현, 정적 웹 사이트 또는 위젯을 원하는 경우 페이지로드에서 즉시 나타납니다.

    **어떻게 작동합니까?**

    <Steps>
      1. Turnstile 스크립트를 페이지에 추가합니다.
      2. 이름 \*`<div class="cf-turnstile" data-sitekey="your-key"></div>`이름 \*
      3. Widgets는 페이지를 로드할 때 자동으로 렌더링됩니다.
      4. 위젯 구성`data-*`HTML 요소에 속성.
    </Steps>

    ```html title="Example" wrap
    	<script src="https://challenges.cloudflare.com/turnstile/v0/api.js" async defer></script>
    	<div class="cf-turnstile" data-sitekey="<YOUR-SITE-KEY>" data-theme="light"></div>
    ```
  </TabItem>

  <TabItem label="Explicit 렌더링">
    Explicit 렌더링을 통해 프로그래밍 가능한 컨트롤을 제공 할 때 위젯이 JavaScript 기능을 사용하여 생성되는 방법. 동적 웹 사이트 및 단일 페이지 응용 프로그램 (SPAs)에 가장 잘 사용됩니다. 위젯 생성의 타이밍을 제어 할 필요가 있거나 방문자 상호 작용을 기반으로 한 상태 렌더링 또는 다른 구성으로 여러 위젯에 사용됩니다.

    **어떻게 작동합니까?**

    <Steps>
      1. Turnstile 스크립트 추가`?render=explicit`모수.
      2. 컨테이너 요소 만들기 ( 없이)`cf-turnstile`수업).
      3. 이름 \*`turnstile.render()`위젯을 만들려면 기능.
      4. JavaScript 객체 매개 변수를 사용하여 위젯 구성.
    </Steps>

    ```html title="Example" wrap
    	<script src="https://challenges.cloudflare.com/turnstile/v0/api.js?render=explicit" defer></script>
    	<div id="my-widget"></div>
    	
    	<script>
    	window.onload = function() {
    		turnstile.render('#my-widget', {
    			sitekey: '<YOUR-SITE-KEY>',
    			theme: 'light',
    			callback: function(token) {
    				console.log('Success:', token);
    			}
    		});
    	};
    	</script>
    ```
  </TabItem>
</Tabs>

## Widget 크기

Turnstile 위젯은 관리 또는 비 상호 작용 모드를 사용할 때 두 가지 다른 고정 크기 또는 유연한 폭 크기를 가질 수 있습니다.

| 크기 (mm) | 폭 (mm)          | 고도:        | 사용 사례                  |
| ------- | --------------- | ---------- | ---------------------- |
| 일반 정보   | 300px의          | 65px, 65px | 표준 구현                  |
| 제품정보    | 100% (분: 300px) | 65px, 65px | 책임감 있는 디자인             |
| 기본 정보   | 150px의          | 140px ·    | Space-constrained 레이아웃 |

- `normal`: 기본 크기는 대부분의 데스크톱 및 모바일 레이아웃에 잘 작동합니다. 웹 사이트 또는 양식에 수평 공간을 적절하게하는 경우 이것을 사용하십시오.
- `flexible`: 최소한의 사용성을 유지하면서 컨테이너 너비에 자동 적응합니다. 모든 화면 크기에서 작업해야하는 반응형 디자인에 이것을 사용하십시오.
- `compact`: 모바일 인터페이스, 사이드바, 또는 수평 공간이 제한되는 공간에 이상적입니다. 소형 위젯은 작은 폭을 수용하기 위해 정상보다 키가 높다.

:::참조
Widget 크기는 관리 및 비동기 모드에만 적용됩니다. 보이지 않는 위젯은 크기 구성에 관계없이 시각적 발자국이 없습니다.
주요 특징



## 테마 옵션

웹 사이트의 디자인과 일치하는 위젯의 시각적 외관을 사용자 정의합니다.

- `auto`(과태): 자동으로 방문자의 시스템 테마 p참고 자료 일치. Auto는 방문자의 p참고 자료s를 존중하고 최고의 접근성 경험을 제공합니다.
- `light`: 밝은 색상과 명확한 대조를 가진 가벼운 주제. 빛 테마는 밝은 배경에 베스트를 작동하고 읽기를위한 높은 대비를 제공합니다.
- `dark`: 어두운 인터페이스에 최적화 된 다크 테마. 어두운 테마는 어두운 인터페이스, 게임 사이트, 또는 어두운 색 구성 요소와 응용 프로그램에 이상적입니다.

## 외관 형태

위젯이 외관 모드를 사용하여 방문자에 볼 때 제어.

- `always`(과태): 위젯은 항상 페이지 부하에서 볼 수 있습니다. 이것은 당신이 방문자를 원하는 가장 구현을위한 최고의 옵션으로 즉시 보안 검증이 장소에 명확한 시각적 피드백을 제공합니다.
- `execute`: 도전이 시작된 후 위젯만 볼 수 있습니다. 이것은 방문자가 양식을 작성하거나 제출 버튼을 선택할 때뿐만 아니라 위젯 외관의 타이밍을 제어 할 때 유용합니다.
- `interaction-only`: 위젯은 방문자 상호 작용이 요구되고 가장 깨끗한 방문자 경험을 제공합니다. 대부분의 방문객은 위젯을 볼 수 없지만 의심스러운 봇은 대화 형 도전에 직면 할 것입니다.

:::참조
외관 모드는 눈에 보이는 위젯 유형에만 영향을 미칩니다 (Managed 및 Non-Interactive). 보이지 않는 위젯은 외관 설정에 관계없이 표시되지 않습니다.
주요 특징

<Tabs>
  <TabItem label="Implicit 연출">
    ```html title="Always visible (default)" wrap

    ```

    ```html title="Visible only after challenge begins" wrap
    	<div class="cf-turnstile" data-sitekey="<YOUR-SITE-KEY>" data-appearance="execute"></div>
    ```

    ```html title="Visible only when interaction is needed" wrap
    	<div class="cf-turnstile" data-sitekey="<YOUR-SITE-KEY>" data-appearance="interaction-only"></div>
    ```

  <TabItem label="Explicit 렌더링">

    ```js title="Always visible (default)" wrap
    	turnstile.render('#widget-container', {
    ```

## 실행 모드

도전이 실행되고 토큰이 생성될 때 제어합니다.

- `render`(과태): 도전은 호출 후 자동으로 실행`render()`기능 및 위젯로드로 즉시 보호를 제공합니다. 챌린지는 페이지로드가 진행되는 동안 배경에서 실행되며, 방문자가 데이터를 제출할 때 토큰이 준비됩니다.
- `execute`: 도전은 호출 후 실행`turnstile.execute()`함수는 별도로 작동하며, 인증이 발생할 때 정확한 제어를 제공합니다. 이 옵션은 다중 단계 형태, 조건 검증, 또는 방문자가 데이터를 제출하려고 시도 할 때까지 도전을 무시 할 때 유용합니다. 이 페이지로드 성능과 방문자 경험을 향상 시킬 수 있습니다.

  **일반적인 시나리오**

  - 다중 단계 형태: 최종 단계에서만 검증을 실행하십시오.
  - 조건 보호: 특정 기준을 충족하는 방문자 만 확인합니다.
  - 성능 최적화 : 초기 페이지로드 시간을 줄이기 위해 Defer 검증.
  - 사용자 트리거 검증: 방문자는 수동으로 검증 과정을 시작합니다.


## 언어 설정

위젯 인터페이스에 대한 언어를 설정합니다.

- `auto`(과태): 방문자의 브라우저 언어 p참고 자료를 사용합니다.
- 특정한 언어 부호: ISO 639-1 2 맨끝 부호와 같은`es`, `fr`, `de`.
- 언어 및 지역 : 지역 변종을위한 복합 코드 등`en-US`, `es-MX`, `pt-BR`.

:::주\[주]

- 설정할 때`auto`, Turnstile는 브라우저 설정에서 방문자의 선호 언어를 자동으로 감지합니다.
- 요청된 언어가 지원되지 않는 경우, Turnstile는 영어로 돌아갑니다.
- 언어는 로드 메시지, 오류 상태 및 접근성 라벨을 포함한 모든 방문자 직면 텍스트에 영향을줍니다.
- 특정 언어를 설정할 수 있습니다 방문자 경험에 대한 국제 관객.

## Callback 설정

콜백과 위젯 이벤트 핸들.

- `callback`: 도전이 성공적으로 완료되면 Triggered.
- `error-callback`: 오류가 발생했을 때 Triggered.
- `expired-callback`: 토큰이 만료될 때 Triggered (timeout).
- `timeout-callback`: 대화 형 도전이 시작될 때 Triggered.

성공 콜백은 Siteverify API를 사용하여 서버에서 검증되어야하는 토큰을받습니다. 토큰은 단일 사용이며 300초 후에 만료됩니다.

<Tabs>
  <TabItem label="Implicit 연출">
    ```html wrap
    	<div class="cf-turnstile"
    		data-sitekey="<YOUR-SITE-KEY>"
    		data-callback="onSuccess"
    		data-error-callback="onError"
    		data-expired-callback="onExpired"
    		data-timeout-callback="onTimeout"></div>
    	<script>
    	function onSuccess(token) {
    	console.log('Challenge Success:', token);
    	}
    	function onError(errorCode) {
    	console.log('Challenge Error:', errorCode);
    	}
    	function onExpired() {
    	console.log('Token expired');
    	}
    	function onTimeout() {
    	console.log('Challenge timed out');
    	}
    	</script>
    ```
  </TabItem>

  <TabItem label="Explicit 렌더링">
    ```js wrap
    	turnstile.render('#widget-container', {
    		sitekey: '<YOUR-SITE-KEY>',
    		callback: function(token) {
    			console.log('Challenge Success:', token);
    		},
    		'error-callback': function(errorCode) {
    			console.log('Challenge Error:', errorCode);
    		},
    		'expired-callback': function() {
    			console.log('Token expired');
    		},
    		'timeout-callback': function() {
    			console.log('Challenge timed out');
    		}
    	});
    ```
  </TabItem>
</Tabs>

### 좋은 관행

- 항상 토큰을 처리하고 양식 제출 또는 다음 단계로 진행하기 위해 성공 콜백을 구현합니다.
- 우아한 오류 처리 및 방문자 피드백에 대한 오류 콜백을 사용합니다.
- 실패하기 전에 문제를 새로 고침하기 위해 만료 된 토큰을 모니터링합니다.
- 문제 해결을 통해 방문자를 안내하는 핸들 타임 아웃.

## 고급 구성 옵션

### Retry 행동

Turnstile가 실패한 문제를 제어합니다.

- `auto`(과태): 자동적으로 retries 실패한 도전. Auto retry는 임시 네트워크 문제 또는 처리 오류에서 자동으로 복구하여 더 나은 방문자 경험을 제공합니다.
- `never`: 자동 리트리를 비활성화합니다. 이것은 수동 개입을 요구하고 사용자 정의 재량 논리가 필요한 응용 프로그램에 오류 처리에 대한 전체 제어를 제공합니다.
- `retry-interval`: 리트리 시도 사이의 시간을 제어 (과태: 8000ms) 빠른 복구와 서버 부하 사이의 균형을 잡아.

```html title="Auto retry (default)" wrap
<div class="cf-turnstile" data-sitekey="<YOUR-SITE-KEY>"></div>
```

```html title="Disable retry" wrap
<div class="cf-turnstile" data-sitekey="<YOUR-SITE-KEY>" data-retry="never"></div>
```

```html title="Custom retry interval (8000ms default)"
<div class="cf-turnstile" data-sitekey="<YOUR-SITE-KEY>" data-retry-interval="0000"></div>
```

### 새로 고침

Turnstile는 토큰 만료 및 대화형 타임아웃을 처리하는 방법을 제어합니다.

- `refresh-expired`: 토큰이 만료될 때 동작을 제어합니다 (`auto`, `manual`, `never`).
- `refresh-timeout`: 상호 작용하는 도전 시간 (timeout) 때 행동 제어`auto`, `manual`, `never`).

#### 이름 \*

- `auto`새로 고침은 원활한 방문자 경험을 제공하지만 더 많은 리소스를 사용합니다.
- `manual`새로 고침은 방문자 컨트롤을 제공하지만 조치를 취해야합니다.
- `never`새로 고침하려면 응용 프로그램을해야합니다.

다른 전략은 방문자 경험 요구 사항에 따라 토큰 expiration versus Interactive timeout에 사용할 수 있습니다.

```html title="Auto refresh expired tokens (default)" wrap
<div class="cf-turnstile" data-sitekey="<YOUR-SITE-KEY>"></div>
```

```html title="Manual refresh" wrap
<div class="cf-turnstile" data-sitekey="<YOUR-SITE-KEY>" data-refresh-expired="manual"></div>

```

```html title="Auto refresh timeouts (default for Managed mode)"
<div class="cf-turnstile" data-sitekey="<YOUR-SITE-KEY>" data-refresh-timeout="auto"></div>
```

### 주문 데이터

사용자 정의 식별자 및 데이터 추가.

- `action`: 분석 및 차별화에 대한 사용자 정의 식별자 (최대 32 자).
- `cData`: 유효 기간 동안 반환되는 사용자 정의 페이로드 데이터 (최대 255 자).

#### 사용 사례

- Action Tracking: 로그인, 가입, 연락처 양식 등을 구별합니다. 관련 기사
- 방문자 컨텍스트: 방문자 ID, 세션 정보, 기타 컨텍스트 데이터를 전달합니다.
- A/B 테스트: 다른 위젯 구성 또는 페이지 변형을 추적.
- Fraud detection: 위험 평가에 대한 추가 상황에 포함.

:::카트로션
둘 다 활동과 cData 필드는 알파벳 문자, 밑줄 ( ) 및 hyphens (-)를 받아들입니다.
주요 특징

```html title="Add custom action identifier" wrap
<div class="cf-turnstile" data-sitekey="<YOUR-SITE-KEY>" data-action="login"></div>
```

```html title="Add custom data payload" wrap
<div class="cf-turnstile" data-sitekey="<YOUR-SITE-KEY>" data-cdata="user-cdata"></div>
```

### Form 통합

Turnstile가 HTML 형태로 통합하는 방법을 구성합니다.

활성화되면 Turnstile는 자동으로 숨겨져`<input>`인증 토큰의 요소. 이것은 다른 양식 데이터와 함께 제출됩니다, 서버 측 검증을 바로 만들기.

- `response-field`: 토큰으로 숨겨진 양식 필드를 만들지 여부를 결정합니다 (`default: true`)
- `response-field-name`: 숨겨진 형태 필드에 대한 사용자 정의 이름 (`default: cf-turnstile-response`)

#### 이름 \*

- 자동 형태 통합은 토큰이 추가 JavaScript를 필요로 할 때 포함된다는 것을 의미합니다.
- 사용자 정의 필드 이름은 기존 양식 필드와 충돌을 방지하는 데 도움이됩니다.
- Disabled 응답 필드는 복잡한 형태 시나리오에 대한 토큰 처리에 대한 전체 제어를 제공합니다.

```html title="Custom response field name" wrap
<div class="cf-turnstile" data-sitekey="<YOUR-SITE-KEY>" data-response-field-name="turnstile-token"></div>
```

```html title="Disable response field" wrap
<div class="cf-turnstile" data-sitekey="<YOUR-SITE-KEY>" data-response-field="false"></div>
```
