이 튜토리얼은 Cloudflare Turnstile,[웹 애플리케이션 방화벽 (WAF)](/waf/)·[Bot 관리](/bots/get-started/bot-management/)기존 인증 시스템으로. 이 조합은 자동화된 공격과 악성 로그인 시도를 포함하여 다양한 위협에 대한 강력한 방어를 만듭니다.

## 제품정보

WAF 및 Bot 관리를 사용하려면 사이트가 Cloudflare를 통해 DNS 포인팅을해야합니다. 그러나 Turnstile는 Cloudflare의 네트워크에 있지 않는 사람들을 포함하여 어떤 위치에 독립적으로 사용될 수 있습니다. 이 튜토리얼은 Cloudflare의 네트워크에 있지 않은 경우 Turnstile에 초점을 맞추고 있습니다.

WAF, Bot 관리 및 Turnstile는 신청의 다른 층에 운영해서 잘 작동합니다:

- WAF는 네트워크 신호를 기반으로 악의적인 트래픽을 필터링합니다.
- Bot Management는 자동화된 위협을 식별하고 mitigate를 분석합니다.
- Turnstile는 클라이언트 측과 브라우저 신호를 검사하여 인간의 사용자와 봇과 구별합니다.

서버 측 (WAF 및 Bot 관리) 및 클라이언트 측 (Turnstile) 안전 측정을 결합함으로써, 당신은 공격자에 대한 어려운 보호 시스템을 창조하기 위하여 방어의 다수 층을 결합할 수 있습니다.

## 시작하기 전에

- WAF 및 Bot 관리에 액세스하여 Cloudflare 계정이 있어야 합니다.
- 기존 JavaScript/TypeScript 기반 경로 처리 인증.

이 튜토리얼은 일반 HTML에서 작성된 간단한 로그인 양식을 사용하여 Turnstile를 응용 프로그램에 통합하는 방법을 설명합니다. 백엔드에서 TypeScript에서 작성된 인증 경로가 로그인 요청을 처리합니다. 당신은 당신의 선택의 언어로 이것을 대체 할 수 있습니다. 언어 또는 프레임 워크가 외부 HTTP 요청을 할 수 있기 때문에[Turnstile의 API](/api/resources/turnstile/subresources/widgets/methods/create/), 당신은 당신의 신청에 Turnstile를 통합할 수 있습니다.

## Cloudflare Turnstile 설치

Turnstile는 Cloudflare의 네트워크에 있는지 여부에 관계없이 모든 사이트에서 사용할 수 있습니다.

<Steps>
  1. Cloudflare 대시보드에서**사이트맵**사이트 맵

     <DashButton url="/?to=/:account/turnstile" />
  2. 제품정보**위젯 추가**자주 묻는 질문
  3. Turnstile 구성에 도메인을 추가하십시오.
  4. 제품정보**이름 \***.
</Steps>

Turnstile는 브라우저와 클라이언트 측 신호를 분석하여 보안의 추가 레이어를 추가하여 WAF 및 Bot 관리에서 수행 한 서버 측 체크를 보완합니다.

### 기존의 통관 쿠키를 사용하는 옵션

사이트가 Cloudflare에 있다면, 기존의 옵션을 사용할 수 있습니다.[회사 소개](/cloudflare-challenges/concepts/clearance/#pre-clearance-support-in-turnstile)Turnstile의 설정. 이 통합은 Turnstile가 사용자가 도전을 받아야 할지 여부의 결정에 따라 정리 쿠키를 사용할 수 있습니다. 이 통합은 선택적이지만 이미 WAF 및 Bot 관리를 사용하는 경우 권장됩니다.

## 애플리케이션에 Turnstile 통합

Turnstile를 응용 프로그램에 구현하는 두 가지 구성 요소가 있습니다. Turnstile 위젯과 서버 측 검증 논리.

### 로그인 양식에 Turnstile 위젯 추가

기존 로그인 양식에 Turnstile 위젯 추가:

```html
<form id="login-form">
	<input type="text" id="username" placeholder="Username" required />
	<input type="password" id="password" placeholder="Password" required />
	<div class="cf-turnstile" data-sitekey="<YOUR-SITE-KEY>"></div>
	<button type="submit">Log in</button>
</form>

<script
	src="https://challenges.cloudflare.com/turnstile/v0/api.js"
	async
	defer
></script>
```

기타 제품`<YOUR-SITE-KEY>`실제 Turnstile 사이트 키로.

## 로그인 요청 처리

기존 인증 경로에서 Turnstile 유효성을 추가하십시오.

```typescript
async function validateTurnstileToken(
	ip: string,
	token: string,
	secret: string,
): Promise<boolean> {
	const response = await fetch(
		"https://challenges.cloudflare.com/turnstile/v0/siteverify",
		{
			method: "POST",
			headers: { "Content-Type": "application/json" },
			body: JSON.stringify({ ip, secret, response: token }),
		},
	);

	const outcome = await response.json();
	return outcome.success;
}

//TypeScript 경로 핸들러입니다.
//다른 구현으로 이것을 대체 할 수 있습니다.
//당신의 언어 또는 프레임 워크를 기반으로
export async function onRequestPost(context) {
	const { request, env } = context;
	const { username, password, token } = await request.json();

	//유효한 Turnstile 토큰
	const secretKey = env.TURNSTILE_SECRET_KEY;
	const ip = request.headers.get("CF-Connecting-IP");
	const turnstileValid = await validateTurnstileToken(ip, token, secretKey);
	if (!turnstileValid) {
		//오류 메시지로 로그인 페이지로 돌아가기
		return Response.redirect("/login", 302, {
			headers: {
				Location: "/login?error=invalid-turnstile-token",
			},
		});
	}

	//기존 인증 로직을 수행
	const isValidLogin = await checkCredentials(username, password);

	if (isValidLogin) {
		return new Response(JSON.stringify({ message: "Login successful" }), {
			status: 200,
			headers: { "Content-Type": "application/json" },
		});
	} else {
		return new Response(JSON.stringify({ error: "Invalid credentials" }), {
			status: 401,
			headers: { "Content-Type": "application/json" },
		});
	}
}
```

## 제품정보

배포 후 통합을 테스트하고 싶습니다. 봇 점수가 낮기 때문에, 아마 도전을받지 않습니다. 그러나, 당신은 도전 페이지로 리디렉션을 강제로 추가 규칙을 추가 할 수 있습니다. 이 작업을 할 수있는 몇 가지 옵션:

1. 항상 도전 페이지에 IP 주소를 전달하는 WAF 규칙을 추가하십시오.
2. 쿼리 매개 변수의 존재를 확인하는 WAF 규칙을 추가하십시오.`?challenge=true`.

## 좋은 관행

1. 항상 자격 증명을 확인하기 전에 서버 측에 Turnstile 토큰을 검증합니다.
2. Turnstile 비밀 키와 같은 민감한 정보를 저장하는 환경 변수를 사용합니다.
3. 잠재적 보안 문제를 모니터링하기 위해 적절한 오류 처리 및 로깅을 구현합니다.

Turnstile와 WAF와 Bot 관리를 결합함으로써, 당신은 네트워크 층에서 당신의 신청을 확보하는 체계를 창조할 수 있고, 또한 클라이언트 측 신호를 사용하여 보호의 여분 층을 제공하. 이 접근법은 사용자의 로그인 시스템에 대한 공격을 자동화하는 악의적인 행위자보다 훨씬 어렵습니다.
