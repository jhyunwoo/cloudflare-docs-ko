이 페이지에서 최적화하려는 소스 이미지를 정의하고 관리하는 방법을 배울 수 있습니다.

## 허용된 근원에서만 소스 이미지를 허용하십시오

소스 이미지를 제한할 수 있습니다.**법적고지**, 정의된 목록에서 소스 이미지에만 변환을 적용합니다.

기본적으로 허용된 소스가 설정됩니다.**법적고지**. Cloudflare는 항상 당신의 변환이 봉사하는 동일한 지역에서 근원 이미지를 허용할 것입니다.

소스 이미지로 변환을 요청하면**법적고지**, 그 후에 이미지는 거절될 것입니다. 예를 들어, 영역에서 변환하는 경우`a.com`그리고 추가적인 근원을 정의하지 마십시오.`a.com/image.png`소스 이미지로 사용할 수 있지만`b.com/image.png`오류를 반환합니다.

새로운 기원을 정의하려면:

1. 이름 \***이름 \***, 선택**이름 \***.
2. 이름 \***이름 \***, 소스 이미지의 도메인을 지정합니다. 유효한 웹 URL만 허용됩니다.

![Cloudflare 대시보드](~/assets/images/images/add-origin.png)

루트 도메인을 추가하면 하위 도메인은 허용되지 않습니다. 다른 단어에서, 당신이 추가하는 경우`b.com`, 다음 소스 이미지에서`media.b.com`거절될 것입니다.

개별 subdomains를 지원하려면, 다음과 같은 추가 원산지를 정의하십시오.`media.b.com`. 만 추가하면`media.b.com`그리고 루트 도메인이 아니라, 루트 도메인의 소스 이미지 (`b.com`) 및 기타 하위 도메인 (`cdn.b.com`)는 거절될 것입니다.

모든 하위 도메인을 지원하려면`*`루트 도메인의 시작에 wildcard. 예를 들어,`*.b.com`root 도메인의 소스 이미지를 수락합니다 (like)`b.com/image.png`) 또한 subdomains에서 (like`media.b.com/image.png`또는`cdn.b.com/image.png`).

3. 선택적으로, 당신은 지정할 수 있습니다**오시는 길**소스 이미지를 위해. 경로가 지정되지 않은 경우, 이 도메인의 모든 경로에서 소스 이미지가 허용됩니다.

Cloudflare는 정의된 경로가 소스 경로의 시작 부분에 있는지 확인합니다. 정의된 경로가 경로의 시작 부분에 존재하지 않으면 소스 이미지가 거부됩니다.

예를 들어, 도메인을 정의하는 경우`b.com`및 경로`/themes`, 다음`b.com/themes/image.png`접수 가능`b.com/media/themes/image.png`거절될 것입니다.

4. 제품정보**더 보기**. 당신의 기원은 이제 허용 된 기원의 목록에 나타납니다.
5. 제품정보**제품 정보**. 이 변화는 즉시 효력을 가지고 갈 것입니다.

설정할 때**법적고지**, 소스 이미지의 초기 URL 만 체크됩니다. 어떤 리디렉션, 귀하의 영역을 떠나는 URL을 포함, 다음 될 것입니다, 그리고 결과 이미지는 변환됩니다.
