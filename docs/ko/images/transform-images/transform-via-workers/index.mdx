Cloudflare Workers를 사용하여 사용자 정의 URL 구성으로 변환하여 모든 이미지 요청에 강력한 프로그래밍 제어를 제공합니다.

다음은 유연성 Workers의 몇 가지 예입니다.

- **사용자 정의 URL 계획 사용**. 이미지 URL에 있는 화소 차원을 지정하는 대신, 사용 preset 이름과 같은`thumbnail`·`large`.
- **원본 이미지의 실제 위치를 숨기기**. 외부 S3 버킷 또는 URL에 대한 정보를 탐색하지 않고 서버에 숨겨진 폴더에 이미지를 저장할 수 있습니다.
- **콘텐츠 협상**. 이것은 이미지 크기, 체재 및 질을 동적인 네트워크의 장치 그리고 상태에 근거를 둔 적응시키는 것이 유용합니다.

resizing 특징은 접근됩니다[옵션 정보](/workers/runtime-apis/request/#the-cf-property-requestinitcfproperties)한국어`fetch()` [노동자 내부의 subrequest](/workers/runtime-apis/fetch/).

:::참조

Cloudflare를 사용할 수 있습니다. SVGs를 sanitize 이미지하지만 크기를 줄 수 없습니다.

:::

## 작업자 구성

CloudflareQX대시보드XQ의 WorkersXQXQXQ 섹션에서 새로운 스크립트를 만듭니다. Worker 스크립트를 사용하여 자산을 제공하는 데 전념하는 경로`/images/*`또는`/assets/*`. 지원되는 이미지 체재만 resize 일 수 있습니다. 다른 유형의 리소스 (CSS, HTML)을 변경하려면 오류가 발생합니다.

:::카트로션\[Warning]

전체 영역에 대한 이미지 조정 작업자를 설정하지 마십시오 (`/*`). 이 모든 비 이미지 요청을 차단하고 웹 사이트를 액세스 할 수 있습니다.

:::

작업자가 직접 호출하는 이미지에 의해 발생하는 요청 루프를 피하기 위해 원래의 경로 (unresize) 이미지로 분리 된 경로에 의해 처리하는 것이 가장 좋습니다. 예를 들어, 이미지 저장`example.com/originals/`디렉토리 및 핸들 resizing 통해`example.com/thumbnails/*`이미지가 닿는 경로`/originals/`디렉토리. 소스 이미지가 Worker에 의해 처리되는 위치에 저장되면 무한한 루프를 만들기에서 Worker를 방지해야합니다.

### 요청 루프 방지

재조정 및 최적화를 수행하려면, Worker는 원본을 태워야 할 수 있어야합니다, 당신의 Origin 서버에서 크기 이미지. 이미지가 서버에 저장되는 경로로 Worker overlaps에 의해 처리되는 경로가 있다면, 자체에서 이미지를 요청하기 위해 노력하는 Worker가 무한한 루프를 일으킬 수 있습니다.

당신은 특정 요청이 원래 서버로 직접 이동합니다. 언제까지`image-resizing`문자열은 현재`Via`헤더, 그것은 다른 노동자에서 오는 요청이며 원래 서버로 지시해야합니다 :

```js
export default {
	async fetch(request) {
		//이 요청이 이미지 재조합 작업자에서 오는 경우,
		//그것을 다시 resizing에 의하여 무한한 반복을 일으키는 원인이 하십시오:
		if (/image-resizing/.test(request.headers.get("via"))) {
			return fetch(request);
		}

		//이제 당신은 안전하게 여기에 이미지를 resizing 할 수 있습니다
	},
};
```

## 대시보드

:::주\[주]

이미지 변환은 Workers 대시보드 편집기의 미리보기에서 시뮬레이션되지 않습니다.

:::

Worker 편집기의 스크립트 미리보기는 무시합니다.`fetch()`옵션, 항상 크기가 아닌 이미지를 fetch합니다. Worker 스크립트를 배포해야 하는 이미지 변환의 효과를 볼 수 있으며 편집기 밖에 사용할 수 있습니다.

## 오류 처리

이미지가 재사이즈될 수 없을 때 — 예를 들어, 이미지가 존재하지 않았기 때문에, 재조정 매개 변수가 무효했다 — 응답은 오류를 나타내는 HTTP 상태 (예를 들어,`400`, `404`, 또는`502`).

기본적으로 오류가 브라우저에 전달되지만 오류를 처리하는 방법을 결정할 수 있습니다. 예를 들어, 브라우저를 원래로 리디렉션할 수 있습니다. 대신 크기가 작습니다.

```js
const response = await fetch(imageURL, options);

if (response.ok || response.redirected) {
	//fetch()는 상태 304에 대응할 수 있습니다.
	return response;
} else {
	return Response.redirect(imageURL, 307);
}
```

서버의 원본 이미지가 매우 크다면, 이미지가 너무 많은 대역폭, 메모리 또는 틈 페이지 레이아웃을 사용할 수 있는 매우 큰 이미지로 돌아가기 보다는 전혀 실패하지 않을 수 있습니다.

당신은 또한 placeholder 이미지와 실패한 이미지를 대체할 수 있습니다:

```js
const response = await fetch(imageURL, options);
if (response.ok || response.redirected) {
	return response;
} else {
	//서버에서 URL로 변경
	return fetch("https://img.example.com/blank-placeholder.png");
}
```

## 예제 worker

감사합니다.[작업자 설정](/workers/get-started/guide/)에 의해`https://example.com/image-resizing`URL을 처리하기`https://example.com/image-resizing?width=80&image=https://example.com/uploads/avatar1.jpg`:

```js
/** 이름
* Fetch 및 로그 요청
* @param {Request} 요청*/
export default {
	async fetch(request) {
		//Parse 요청 URL 쿼리 문자열에 액세스
		let url = new URL(request.url);

		//Cloudflare-specific 옵션은 cf 객체에 있습니다.
		let options = { cf: { image: {} } };

		//쿼리 문자열에서 복사 매개 변수를 요청 옵션.
		//다양한 매개 변수를 구현할 수 있습니다.
		if (url.searchParams.has("fit"))
			options.cf.image.fit = url.searchParams.get("fit");
		if (url.searchParams.has("width"))
			options.cf.image.width = parseInt(url.searchParams.get("width"), 10);
		if (url.searchParams.has("height"))
			options.cf.image.height = parseInt(url.searchParams.get("height"), 10);
		if (url.searchParams.has("quality"))
			options.cf.image.quality = parseInt(url.searchParams.get("quality"), 10);

		//당신의 노동자는 자동적인 체재 교섭을 책임집니다. 수락 헤더를 확인합니다.
		const accept = request.headers.get("Accept");
		if (/image\/avif/.test(accept)) {
			options.cf.image.format = "avif";
		} else if (/image\/webp/.test(accept)) {
			options.cf.image.format = "webp";
		}

		//원래의 URL을 가져옵니다 (전체 크기) 크기를 이미지.
		//여기에서 URL을 조정할 수 있습니다, 예를 들어, 서버의 고정 주소로 미리 설정,
		//그래서 사용자 접근 가능한 URL은 더 짧고 깨끗합니다.
		const imageURL = url.searchParams.get("image");
		if (!imageURL)
			return new Response('Missing "image" value', { status: 400 });

		try {
			//TODO: 검증 논리를 사용자 정의
			const { hostname, pathname } = new URL(imageURL);

			//선택적으로 JPEG, PNG, GIF 또는 WebP 파일 확장자와 URL 만 허용
			//https://developers.cloudflare.com/images/url-format#supported-formats-and-limitations를 보십시오
			if (!/\.(jpe?g|png|gif|webp)$/i.test(pathname)) {
				return new Response("Disallowed file extension", { status: 400 });
			}

			//데모: "example.com" 이미지만 허용
			if (hostname !== "example.com") {
				return new Response('Must use "example.com" source images', {
					status: 403,
				});
			}
		} catch (err) {
			return new Response('Invalid "image" value', { status: 400 });
		}

		//요청 헤더를 통과하는 요청을 작성
		const imageRequest = new Request(imageURL, {
			headers: request.headers,
		});

		//resizing 선택권을 가진 반환 fetch ()는 크기를 가진 응답을 통과할 것입니다.
		return fetch(imageRequest, options);
	},
};
```

이미지를 재생할 때, 먼저 스크립트를 배포하십시오. 대시보드의 온라인 편집기에서 반응하지 않습니다.

## 공지사항`cacheKey`

크기 이미지는 항상 캐시됩니다. 그들은 전체 크기의 소스 이미지의 URL에 대한 캐시 항목 아래의 추가 변형으로 캐시됩니다`fetch`구독하기 다른 많은 Workers 또는 많은 외부 URL을 사용하는 것에 대해 걱정하지 마십시오. 크기가 큰 이미지의 캐싱에 영향을 미치지 않으며 크기를 조정 할 필요가 없습니다.

당신이 사용하는 경우`cacheKey`여러 소스 URL의 캐시를 unify하는 fetch 옵션은 어떤 재조합 옵션을 포함하지 않습니다`cacheKey`. 그렇게 해서 캐시를 파고 캐싱 성능이 어울립니다. 더 보기`cacheKey`참고 자료는 전체 크기의 소스 이미지 URL만, 크기의 버전이 아닙니다.
