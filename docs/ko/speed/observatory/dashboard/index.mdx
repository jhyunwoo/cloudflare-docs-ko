Observatory 개요 대시보드는 지난 7일 동안 영역의 성능을 한눈에 보여줍니다. 합성 모니터링, 실제 사용자 데이터, Cloudflare의 분석을 결합하여 성능 병목을 빠르게 식별하고 실행 가능한 권장 사항을 받을 수 있도록 도와줍니다.

## 제안

**Suggestions** 패널은 성능을 개선하기 위해 적용할 수 있는 맞춤형 최적화를 강조해서 보여줍니다. 예시는 다음과 같습니다.

- Polish로 Largest Contentful Paint(LCP) 줄이기
- Argo Smart Routing으로 Time to First Byte(TTFB) 줄이기

이러한 권장 사항은 사이트에서 관찰된 성능에 따라 달라집니다.

제안을 선택하면 더 자세한 정보가 펼쳐집니다.

- **표시되는 이유**: 감지된 성능 문제를 설명합니다.
- **취할 수 있는 조치**: 수행할 수 있는 권장 조치를 나열합니다.

## Core Web Vitals

대시보드는 75백분위수(p75) 값으로 **Core Web Vitals**를 통합해 보여줍니다. 이 메트릭은 실제 사용자 경험을 반영합니다.

- **Largest Contentful Paint (LCP)**: 페이지의 주요 콘텐츠가 얼마나 빨리 표시되는지를 나타냅니다.
- **Interaction to Next Paint (INP)**: 사용자 상호작용에 사이트가 얼마나 빠르게 반응하는지를 나타냅니다.
- **Cumulative Layout Shift (CLS)**: 페이지 레이아웃이 시각적으로 얼마나 안정적인지를 나타냅니다.

실제 사용자 데이터가 충분하지 않으면 메트릭이 **데이터 없음**으로 표시될 수 있습니다.

## 네트워크 성능

**Network Performance** 섹션은 지연이 발생하는 위치를 파악하는 데 도움이 되는 타이밍 데이터를 보여줍니다.

- **Time to First Byte (TTFB)**: 초기 요청과 응답의 첫 바이트를 받는 시점 사이의 시간을 측정합니다.
- **Time to Last Byte (TTLB) Breakdown**: 응답 단계별 분석을 제공합니다.

    - DNS 확인 시간
    - TCP 연결 시간
    - 서버의 요청 처리 시간
    - 응답 전송 시간

이 분석을 통해 지연이 DNS, 연결 설정, 서버 처리, 응답 전달 중 어디에서 발생하는지 확인할 수 있습니다.

## HTTP 트래픽

**HTTP Traffic** 섹션은 Cloudflare와 원본 서버 사이에서 트래픽이 어떻게 처리되는지 보여줍니다.

- **Served by**: Cloudflare에서 제공된 요청과 원본 서버에서 제공된 요청의 비율
- **4xx errors**: Cloudflare 엣지와 원본 서버 기준으로 나뉜 클라이언트 오류
- **5xx errors**: Cloudflare 엣지와 원본 서버 기준으로 나뉜 서버 오류

이 보기를 통해 문제의 원인이 Cloudflare 측인지 원본 측인지 구분할 수 있습니다.

## 합성 모니터링

**Synthetic Monitoring** 표는 사이트의 자동 테스트 결과를 보여줍니다. 각 행에는 다음 정보가 포함됩니다.

- **테스트한 URL**
- **마지막 테스트 실행**
- **반복 횟수**(예약 실행된 경우)
- **점수**(Pass/Fail)

합성 모니터링을 사용하면 실제 사용자 모니터링(RUM)을 보완하면서 일관된 조건에서 사이트 가용성과 성능을 선제적으로 테스트할 수 있습니다.

## 대시보드 사용하기

Speed 개요 대시보드를 사용해 다음 작업을 수행하세요.

- 실행 가능한 최적화를 위해 **Suggestions** 검토
- 좋은 사용자 경험을 보장하기 위해 **Core Web Vitals** 추적
- 지연 병목을 찾기 위해 **Network Performance** 분석
- **HTTP Traffic** 인사이트로 오류 진단
- **Synthetic Monitoring** 결과로 사이트 신뢰성 확인
