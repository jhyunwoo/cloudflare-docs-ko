아래에서 가장 자주 묻는 질문에 대한 답변을 확인할 수 있습니다. 찾고 있는 답변이 없다면 [커뮤니티 페이지](https://community.cloudflare.com/c/website-application-performance/88)를 참고해 더 많은 리소스를 살펴보세요.

## 테스트가 로드되기까지 얼마나 걸리나요?

약 25초에서 1분 이상까지 다양할 수 있습니다. Speed 탭을 열어 둔 상태라면 테스트는 계속 실행됩니다. 떠났다가 다시 돌아와도 테스트 결과를 계속 확인할 수 있습니다.

## 테스트하는 URL에서 쿼리 파라미터나 앵커가 지원되나요?

아니요. 현재 테스트한 URL에 추가된 쿼리 파라미터나 앵커는 모두 제거됩니다.

예를 들어 `https://example.com/blog/?utm_medium=social#title` URL을 사용하면 Observatory는 `?utm_medium=social` 쿼리 파라미터와 `#title` 앵커를 모두 버립니다. 실제로 테스트되는 URL은 `https://example.com/blog/`입니다.

## 웹사이트 분석을 다시 실행할 때 `403` 응답이 나옵니다. 왜 그런가요?

WAF 사용자 지정 규칙을 확인하여 Observatory가 사이트에 요청하는 트래픽을 차단하고 있지 않은지 확인하세요.

## Observatory 지도에서 실제 사용자 모니터링(RUM) 데이터가 보이지 않는 이유는 무엇인가요?

Observatory 지도에서 실제 사용자 모니터링(RUM) 데이터가 보이지 않는 데에는 여러 이유가 있습니다.

- RUM 데이터 채우기에 필요한 시간: RUM 데이터베이스를 채우는 데는 시간이 걸립니다. 즉, 새로 활성화한 RUM은 즉시 데이터를 제공하지 않을 수 있으므로, 지도에 RUM 데이터가 나타나기까지 일정 시간이 필요할 수 있습니다.

- 점진적 샘플링: RUM 데이터는 점진적으로 샘플링되므로 모든 요청이 캡처되지는 않습니다. 일부 요청은 샘플링 과정에서 제외될 수 있어 지도에 불완전하거나 누락된 데이터 포인트가 생길 수 있습니다.

- 광고 차단기의 영향: RUM 데이터 수집은 실제 사용자 브라우저에서 실행되는 서드파티 JavaScript에 의존합니다. 그러나 광고 차단기나 유사한 브라우저 확장 프로그램이 이 스크립트를 막아 RUM 데이터 수집이 되지 않을 수 있으며, 그 결과 지도에 표시되는 분석의 완전성이 떨어질 수 있습니다.

- 환경에서 RUM 기능이 활성화되고 구성되어 있어야 합니다. 켜져 있지 않거나 설정이 완료되지 않았다면 RUM 데이터가 표시되지 않을 수 있습니다.

## Observatory에서 RUM 분석과 트래픽 분석 사이에 차이가 생기는 이유는 무엇인가요?

Observatory에서 실제 사용자 모니터링(RUM) 분석과 트래픽 분석 사이에 차이가 발생하는 이유는 다음과 같습니다.

- 광고 차단기의 영향: 앞선 항목과 마찬가지로 광고 차단기로 인해 RUM 데이터 수집이 방해받아 데이터가 누락될 수 있습니다. 반면 트래픽 분석은 일반적으로 서버 측 데이터 수집에 의존하므로 RUM만큼 광고 차단기의 영향을 받지 않을 수 있습니다.

- RUM의 점진적 샘플링: RUM 데이터는 점진적 샘플링을 통해 수집되므로 모든 사용자 요청이 캡처되지는 않습니다. 이 샘플링 방식 때문에 모든 서버 요청을 기록하는 전통적인 트래픽 분석과 비교했을 때 약간의 차이가 발생할 수 있습니다.

## Observatory 테스트 결과 페이지에서 활성화한 실제 사용자 모니터링(RUM)을 비활성화하려면 어떻게 하나요?

RUM을 활성화하면 계정 수준에서 해당 hostname에 대한 Web Analytics 구성 항목이 생성됩니다.

RUM을 비활성화하려면 다음 단계를 따르세요.

1. Cloudflare 대시보드에서 **Web Analytics** 페이지로 이동합니다.

   <DashButton url="/?to=/:account/web-analytics" />

2. RUM을 비활성화하려는 hostname에 대해 **Manage Site**를 선택합니다.
3. **Delete**를 선택합니다.
