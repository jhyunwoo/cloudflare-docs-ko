0-RTT(Zero Round Trip Time) 연결 재개는 이전에 이미 웹사이트에 연결한 적이 있는 클라이언트의 성능을 개선하여, 재방문 사용자의 지연 시간을 줄여 줍니다. 이 기능은 애플리케이션을 자주 방문하거나 모바일 네트워크를 통해 접속하는 사용자에게 특히 유용합니다.

Cloudflare는 GET, HEAD, OPTIONS 요청에 대해 0-RTT를 지원하므로 이러한 유형의 요청에 더 빠르게 응답할 수 있습니다. POST 요청은 0-RTT를 지원하지 않는다는 점에 유의하세요.

0-RTT 표준에 따라, Cloudflare는 0-RTT 요청에 `Early-Data: 1` 헤더를 추가합니다. 이를 통해 오리진 서버는 어떤 요청이 0-RTT 재개를 사용했는지 식별할 수 있습니다. 고객은 오리진으로 연결되는 모든 0-RTT 요청에서 `Early-Data: 1` 헤더를 확인할 수 있어야 합니다.

0-RTT의 작동 방식과 잠재적인 제한 사항을 포함한 자세한 내용은 [블로그 게시물](https://blog.cloudflare.com/even-faster-connection-establishment-with-quic-0-rtt-resumption/)을 참고하세요.

## 0-RTT 연결 재개 활성화

기본적으로 0-RTT 연결 재개는 Cloudflare 애플리케이션에서 활성화되어 있지 않습니다.

<Tabs syncKey="dashPlusAPI"> <TabItem label="Dashboard">

대시보드에서 0-RTT 연결 재개를 활성화하려면 다음을 수행하세요.

1. Cloudflare 대시보드에서 **Speed** > **Settings** 페이지로 이동합니다.

   <DashButton url="/?to=/:account/:zone/speed/optimization" />

2. **Protocol Optimization** 탭으로 이동한 다음 **0-RTT Connection Resumption** 아래의 토글을 **On**으로 전환합니다.

</TabItem> <TabItem label="API">

API로 0-RTT 연결 재개 설정을 조정하려면 URI 경로에서 설정 이름을 `0rtt`로 지정하고, `value` 파라미터를 `"on"` 또는 `"off"`로 설정한 [`PATCH`](/api/resources/zones/subresources/settings/methods/edit/) 요청을 보내세요.

</TabItem> </Tabs>

:::note
0-RTT 연결 재개는 클라이언트와 Cloudflare 사이에서만 설정됩니다. 오리진 서버까지 확장되지는 않습니다.
:::
