## 요구 사항

Speed Brain은 다음 조건에서 동작합니다.

- Cloudflare에서 Speed Brain 기능이 활성화되어 있어야 합니다.
- 웹 페이지 방문자의 브라우저가 Chromium 기반 브라우저 121 이상이어야 합니다.
- 미리 가져오기 대상 웹 페이지가 캐시 대상이어야 합니다.
- 미리 가져오기 대상 페이지가 Worker를 호출하지 않아야 합니다.

## Speed Brain이란?

Speed Brain의 전반적인 목표는 사용자가 실제로 이동하기 전에 웹페이지를 브라우저에 다운로드해 두는 것입니다.

Cloudflare는 [Speculation Rules API](https://developer.mozilla.org/en-US/docs/Web/API/Speculation_Rules_API)를 활용해 브라우저가 미래 탐색을 미리 가져올지 고려하도록 지시함으로써 웹 페이지 성능을 향상합니다. Speed Brain은 웹사이트에서 처음 방문하는 첫 페이지의 로드 시간은 개선하지 않지만, 같은 사이트에서 이후 탐색하는 웹 페이지의 로드 시간은 개선할 수 있습니다.

브라우저가 이동할 가능성이 높다고 판단하는 페이지를 미리 가져옴으로써, Speed Brain은 [Largest Content Paint](https://web.dev/articles/lcp) (LCP), [Time to First Byte](https://web.dev/articles/ttfb) (TTFB), 그리고 전반적인 페이지 로드 시간을 개선할 수 있습니다.

## Speed Brain 작동 방식

Cloudflare의 Speed Brain 기능이 활성화되면 웹 페이지 응답에 `Speculation-Rules`라는 HTTP 헤더가 추가됩니다. 이 헤더의 값은 사전 정의된 Speculation-Rules 구성을 호스팅하는 URL입니다. 이 구성은 브라우저가 `conservative` [eagerness](https://developer.chrome.com/docs/web-platform/prerender-pages#eagerness)로 미래 탐색을 미리 가져올지 고려하도록 지시합니다.

구성 예시는 다음과 같습니다.

```json
{
	"prefetch": [
		{
			"source": "document",
			"where": {
				"and": [{ "href_matches": "/*", "relative_to": "document" }]
			},
			"eagerness": "conservative"
		}
	]
}
```

이 구성은 브라우저가 미래 탐색에 대해 미리 가져오기 요청을 시작하도록 지시합니다. 이러한 미리 가져오기 요청에는 `sec-purpose: prefetch` HTTP 요청 헤더가 포함됩니다. 성공하지 못한 미리 가져오기 요청은 `503` 상태 코드로 응답합니다. 성공한 미리 가져오기 요청은 `200` 상태 코드로 응답합니다.

## Speed Brain 테스트

Speed Brain이 활성화되어 있는지 테스트하려면 웹 페이지의 HTTP 응답 헤더에 `Speculation-Rules` 헤더가 포함되어 있는지 확인할 수 있습니다. 다만 Speed Brain의 베타 단계에서는 이 동작이 100% 일관적이지 않을 수 있습니다.

브라우저가 실제로 미리 가져오기 요청을 보내는지 테스트하려면 Chrome DevTools의 **Network** 탭을 엽니다. 그런 다음 Speed Brain이 활성화된 웹페이지의 링크를 마우스로 누르세요. 이 동작은 미리 가져오기 요청을 시작해야 하며, 그 요청은 **Network** 탭에 표시됩니다. 다만 브라우저가 미리 가져오기를 시작하지 않기로 결정할 수 있는 이유는 여러 가지가 있습니다. 자세한 내용은 [Chrome Limits guide](https://developer.chrome.com/docs/web-platform/prerender-pages#chrome-limits)를 참고하세요. Speculation-Rules 디버깅에 대한 일반적인 정보는 [Chrome Speculation Debugging guide](https://developer.chrome.com/docs/devtools/application/debugging-speculation-rules)를 참고하세요.

## RUM 통합

Speed Brain은 Web Analytics 및 Real User Measurements (RUM)와 통합되도록 설계되었습니다. 이 통합을 통해 Cloudflare 대시보드의 Web Analytics 인터페이스 안에서 Speed Brain이 웹 성능에 미치는 영향을 이해할 수 있습니다.

RUM을 활성화하지 않고도 Speed Brain을 사용할 수는 있지만, 이 기능이 웹 페이지 성능에 어떤 영향을 주는지는 확인할 수 없습니다. RUM 설정 방법에 대한 자세한 내용은 [Web Analytics & RUM](/web-analytics/) 문서를 참고하세요.

## Speed Brain 활성화 및 비활성화

Speed Brain은 Cloudflare 대시보드의 **Speed** 탭과 API에서 사용할 수 있습니다.

<Tabs syncKey="dashPlusAPI"> <TabItem label="대시보드">

대시보드에서 **Speed Brain**을 활성화하거나 비활성화하려면 다음 단계를 따르세요.

1. Cloudflare 대시보드에서 **Speed** > **Settings** 페이지로 이동합니다.

   <DashButton url="/?to=/:account/:zone/speed/optimization" />

2. **Content Optimization**으로 이동합니다.
3. **Speed Brain** 토글을 **On** 또는 **Off**로 전환합니다.

</TabItem> <TabItem label="API">

다음 `PATCH` 요청으로 Speed Brain을 활성화할 수 있습니다.

<APIRequest
  path="/zones/{zone_id}/settings/speed_brain"
  method="PATCH"
  json={{
    value: "on"
  }}
/>

Speed Brain을 비활성화하려면 `value`를 `"off"`로 설정하세요.

</TabItem> <TabItem label="Terraform">

Terraform을 사용해 Speed Brain을 구성할 수도 있습니다. 자세한 내용은 [Terraform documentation](https://registry.terraform.io/providers/cloudflare/cloudflare/latest/docs)의 `cloudflare_zone_settings_override` 리소스를 참고하세요.

</TabItem> </Tabs>

## 주의 사항

- 미리 가져오기 응답이 브라우저에 실제로 렌더링된다는 보장이 없기 때문에, Speed Brain은 [안전하지 않은 미리 가져오기](https://developer.mozilla.org/en-US/docs/Web/API/Speculation_Rules_API#unsafe_prefetching) 위험을 최소화하기 위한 두 가지 보호 장치를 포함합니다.

  - Speed Brain은 Workers가 실행되는 경로에서는 미리 가져오기를 수행하지 않습니다. 이 보호 장치가 없으면 미리 가져오기 요청이 Worker 로직을 의도치 않게 실행할 수 있고, 그 로직이 들어오는 요청을 일반 요청(즉, prefetch가 아닌 요청)으로 가정할 수 있습니다. 예를 들어 Worker에서 페이지 조회 수 카운터를 증가시키는 경우가 있습니다. 페이지가 실제로 브라우저에 렌더링되지 않았다면 페이지 조회 수는 증가하면 안 됩니다.

  - 미리 가져오기 요청은 절대 오리진 서버에 도달하지 않습니다. 미리 가져오기 요청은 Cloudflare 캐시에 저장된 콘텐츠만 제공합니다. 콘텐츠가 캐시에 없다면 미리 가져오기 요청은 오리진 서버로 계속 진행되지 않습니다. 이 보호 장치가 없으면 미리 가져오기 응답이 브라우저에 렌더링되지 않았더라도 오리진 서버 상태가 변경될 수 있습니다. 예를 들어 로그아웃 URL에 대한 prefetch `GET` 요청이 서버의 로그아웃 동작을 의도치 않게 실행할 수 있습니다.

- 오리진 서버 응답에 `Speculation-Rules` 헤더가 포함되어 있으면, Cloudflare는 이를 덮어쓰지 않습니다.

- Speed Brain은 `strict-dynamic` 또는 `nonce-{hash}` 속성을 사용하는 제한적인 [Content Security Policy](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/script-src) 구성과 함께 작동하지 않습니다.

- 현재 Speed Brain은 `pages.dev`를 사용하거나 이에 의존하는 웹사이트와 호환되지 않습니다.
