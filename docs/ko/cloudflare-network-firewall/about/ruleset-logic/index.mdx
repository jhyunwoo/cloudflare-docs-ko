Cloudflare Network Firewall (이전 Magic Firewall) 규칙은 Cloudflare의 DDoS 완화가 적용된 후 수행됩니다. 두 시스템은 독립적이며, Cloudflare 네트워크 방화벽 내부의 트래픽을 허용하는 것은 우리의 DDoS 완화 내에서 허용되지 않습니다. 교통은 여전히 Cloudflare의 시스템을 통해 흐름에 적용된 DDoS 완화에 의해 차단 될 수 있습니다.

기본적으로 Cloudflare Network Firewall은 규칙에 의해 명시적으로 차단 될 때까지 모든 트래픽을 허용합니다. 규칙이 구성되지 않은 경우, 모든 트래픽은 Cloudflare의 DDoS 완화가 적용된 후 허용됩니다.

## 보안 정책

보안 정책을 구성하기위한 두 가지 옵션이 있습니다.

- 긍정적 인 보안 모델을 강화하고 필요한 트래픽을 허용하고 다른 모든 것을 차단합니다.
- 특정 트래픽을 차단하고, 기본적으로 다른 모든 것이 허용됩니다.

트래픽은 구성 된 규칙의 순서에 일치합니다. 교통이 활성화 된 규칙에 의해 일치하기 때문에 나중에 규칙에 대해 더 이상 유효하지 않으며 트래픽은 장애인 규칙을 통과합니다. 대시보드에서**Cloudflare 네트워크 방화벽**, 규칙 순서는 정상에서 시작하고 규칙의 명부를 아래로 흐릅니다.

예를 들어 규칙 #4에서 모든 TCP 트래픽을 허용하면 모든 TCP 트래픽이 허용됩니다. 규칙 #5 IP 주소에 대한 트래픽 차단`x.x.x.x`확인되지 않습니다.

보안 정책을 구성 할 때 가장 좋은 관행을 위해, 참조[좋은 관행](/cloudflare-network-firewall/best-practices/).

## Cloudflare 네트워크 방화벽 규칙 및 Magic Transit endpoint 건강 검사

Cloudflare-sourced 트래픽은 Cloudflare 네트워크 방화벽 규칙에 따라 구성됩니다. ICMP 트래픽을 차단하면 Cloudflare를 차단합니다.<GlossaryTooltip term="tunnel health-check" link="/magic-transit/reference/tunnel-health-checks/#endpoint-health-checks">endpoint 건강 검사</GlossaryTooltip>. ICMP 트래픽을 막을 때, 당신의 규칙을 첫째로 구획 ICMP 규칙을 적용하기 전에 당신의 접두사 엔드 포인트 IPs에 Cloudflare 공중 IPs에서 sourced 허용하십시오.

Cloudflare의 공개 IP 목록은 참조[IP 범위](https://www.cloudflare.com/ips/).

## Cloudflare 네트워크 방화벽 단계

Cloudflare 네트워크 방화벽은 두 단계의 트래픽을 처리합니다. 첫 번째 단계에서 Cloudflare 네트워크 방화벽은 사용자 정의 단계에서 규칙에 대한 패킷을 일치시킵니다. 두 번째 단계에서 Cloudflare 네트워크 방화벽은 관리 단계의 규칙에 대한 패킷을 일치시킵니다.

### 주문 단계 통치자

Cloudflare Network Firewall Custom phase는 사용자에 의해 정의된 규칙의 집합입니다. 그 규칙의 표현, 순서 및 행동은 사용자에 의해 사용자 정의 할 수 있습니다.

또한, 사용자는 관리 단계의 규칙의 동작을 무시하기 위해이 사용자 정의 단계에서 규칙을 추가 할 수 있습니다.

### 관리 단계 통치자

관리 단계 규칙은 Cloudflare에 의해 업데이트되고 유지되고, Cloudflare는 제일 연습, 알려진 악의적인 본 및 다른 기준에 근거를 둔 이 규칙을 창조합니다.

Cloudflare는 관리 단계의 규칙에 대한 실행의 표현과 순서를 유지합니다. 이름 \*
활성화, 비활성화, 또는 일치하는 패킷을 로그로 만들 수 있습니다.
