이름 \*[관리 규칙](/ruleset-engine/managed-rulesets/)Cloudflare에 의해 유지되는 규칙을 신속하게 배포할 수 있으며, 규칙이 활성화되는 제어 Cloudflare Network Firewall (이전 Magic Firewall)을 사용할 수 있습니다.

:::주\[주:]

Cloudflare Network Firewall을 사용하여 관리 된 규칙을 사용하기 전에 먼저 관리 된 규칙을 사용할 수 있어야합니다. 접근을 위한 계정 팀에 연락하십시오.

:::

규칙을 활성화하거나 비활성화하려면 속성이 overridden을 지정할 수 있습니다. overrides는 관리 단계, 루트 종류 통치자에서 발생합니다. 현재 루트 규칙에는 하나의 규칙만 가질 수 있지만, 단일 규칙은 여러 배의 중복을 포함 할 수 있습니다.

규칙을 활성화하기위한 여러 가지 옵션이 있습니다.

- 개인 규칙을 선택하고 활성화하십시오.
- 범주에 의해 활성화하여 여러 규칙을 활성화`magic-transit-phase`.
- 전체 규칙을 사용.

## 사이트맵

### 1. 관리된 단계 관리한 종류 통치자를 창조하십시오

관리 규칙을 만들려면 먼저 다음과 같은 요청을 빌드해야합니다.

- `managed_ruleset_id`: 당신이 가능한 규칙을 포함하는 관리 된 단계 관리 된 종류의 규칙의 ID.
- `managed_rule_id`: 가능한 규칙의 ID.

또한, 당신은 override를 원하는 속성이 필요합니다. 중복할 수 있는 속성은 다음과 같습니다:

- `enabled`: 이 값은 설정할 수 있습니다.`true`또는`false`. 설정할 때`true`, 규칙은 패킷을 일치하고 행동이 overridden하지 않는 경우 규칙의 기본 동작을 적용합니다. 설정할 때`false`, 규칙은 비활성화하고 어떤 패킷과 일치하지 않습니다.
- `action`: 값은 설정할 수 있습니다.`log`그래서 규칙은 규칙의 기본 동작을 적용 대신 로그를 생성합니다.

더 보기`enabled`·`action`규칙의 속성은 관리 된 단계 관리 된 종류 규칙에 설정되어 있습니다. 관리 단계의 모든 규칙은 현재 기본적으로 비활성화됩니다.

아래의 예에는 Managed Phase Managed Kind Ruleet의 요청이 포함되어 있습니다.

```bash title="Example request - Create a Managed phase Managed Kind ruleset"
curl https://api.cloudflare.com/client/v4/accounts/{account_id}/rulesets
--header "Authorization: Bearer <API_TOKEN>" \
--header "Content-Type: application/json" \
--data '{
  "name": "execute ruleset",
  "description": "Ruleset containing execute rules",
  "kind": "root",
  "phase": "magic_transit_managed",
  "rules": [
    {
      "expression": "true",
      "action": "execute",
      "description": "Enable one rule ",
      "action_parameters": {
        "id": "<MANAGED_RULESET_ID>",
        "version": "latest",
        "overrides": {
          "rules": [
            {
              "id": "<MANAGED_RULE_ID>",
              "enabled": true,
              "action": "log"
            }
          ]
        }
      }
    }
  ]
}'
```

### 2. 관리된 단계에 의하여 처리되는 종류 통치자를 깁으십시오

루트 종류 규칙 만 포함 한 규칙을 확인하려면 규칙을 패치하여 새로운 관리 규칙을 활성화합니다.

이전 단계의 예에서 건물, 아래의 예는 범주를 활성화하여 여러 규칙 대신 하나의 규칙을 선택합니다. 범주에 설정 될 것 이다`log`규칙이 로그를 생성 할 수 있음을 의미하지만 패킷을 받아 들일 수 없습니다.

```bash title="Example request - Patch a Managed phase Managed kind ruleset"
curl --request PATCH \
https://api.cloudflare.com/client/v4/accounts/{account_id}/rulesets/{root_kind_ruleset}/rules/{root_kind_rule} \
--header "Authorization: Bearer <API_TOKEN>" \
--header "Content-Type: application/json" \
--data '{
  "expression": "true",
  "action": "execute",
  "action_parameters": {
    "id": "<MANAGED_RULESET_ID>",
    "version": "latest",
    "overrides": {
      "rules": [
        {
          "id": "<MANAGED_RULE_ID>",
          "enabled": true
        }
      ],
      "categories": [
        {
          "category": "simple",
          "enabled": true,
          "action": "log"
        }
      ]
    }
  }
}'
```

### 3. 모든 규칙 사용

완전한 규칙을 활성화하거나 모든 규칙을 활성화하려면 아래의 요청을 보내주십시오.

```bash title="Example request to enable all rules"
curl --request PATCH \
https://api.cloudflare.com/client/v4/accounts/{account_id}{account_id}/rulesets/{root_kind_ruleset}/rules/{root_kind_rule} \
--header "Authorization: Bearer <API_TOKEN>" \
--header "Content-Type: application/json" \
--data '{
  "expression": "true",
  "action": "execute",
  "action_parameters": {
    "id": "<MANAGED_RULESET_ID>",
    "version": "latest",
    "overrides": {
      "enabled": true
    }
  }
}'
```

### 4. 규칙 삭제

규칙을 삭제하려면, 참조[규칙을 삭제](/ruleset-engine/rulesets-api/delete-rule/).

## Cloudflare 대시보드

대시보드를 사용하여 관리되는 규칙을 사용할 수 있습니다.

1. Cloudflare 대시보드에서[방화벽 정책](https://dash.cloudflare.com/?to=/:account/network-security/magic_firewall/managed)사이트 맵
2. 내 계정**관련 규칙**탭, 선택**Deploy 관리 규칙**.
3. 페이지를 새로 고침하고 귀하의 계정에 사용할 Cloudflare에 의해 구성 된 규칙을 보여줍니다. 당신이 원하는 규칙을 선택하십시오**계정 관리**. 당신이 원하는 규칙이 표시되지 않는 경우, 모든 네트워크 방화벽 관리 규칙 목록을 얻기 위해 계정 관리자에 문의하십시오.
4. 이름 \***Ruleset 구성**, 구성**Ruleset 작업**드롭다운 메뉴에서. Cloudflare는이 설정을 변경하는 것이 좋습니다.**로그인**규칙이 행동을 결정하기 전에 트래픽에 미치는 영향을 평가하기 위해. 더 많은 정보를 원하시면, 참조[관리된 규칙을 무시](/ruleset-engine/managed-rulesets/override-managed-ruleset/).
5. 아직 아래**Ruleset 구성**, 선택*이름 \**&#x64;ropdown-menu에서**Ruleset 상태**. 이 규칙에 있는 모든 규칙의 기본 상태에 override를 적용할 것입니다.
6. 제품정보**제품 정보**Network Firewall Managed Ruleet을 배포하기 위해 규칙 레벨 오버라이드가 없습니다.

### 규칙 레벨 오버라이드 추가

규칙 레벨 오버라이드를 적용하면 관리 규칙의 행동을 사용자 정의 할 수 있습니다. Cloudflare의 규칙 구성에 대한 권장 사항을 구현하면 규칙이 설정됩니다.**로그인**활동 및**이름 \***&#xC774;름 \*

다른 한편, 이전 단계에서 Cloudflare의 권장 사항을 적용하지 않았다면, 규칙은 적용된 모든 기본으로 구현됩니다.

대시보드에 규칙 수준 overrides를 추가하려면:

1. Cloudflare 대시보드에서[방화벽 정책](https://dash.cloudflare.com/?to=/:account/network-security/magic_firewall/managed)사이트 맵
2. 내 계정**관련 규칙**탭, 네트워크 방화벽 관리 규칙을 찾아 규칙을 추가하고 선택**계정 관리**.
3. 제품정보**검색 규칙**.
4. 변경해야 할 규칙에서, 선&#xD0DD;**- 연혁**드롭다운에서 동작을 변경하거나, toggle을 사용하거나 규칙을 활성화합니다.
5. 제품정보**이름 \***.
6. 제품정보**제품 정보**.

Cloudflare 대시보드는 이제 당신이 설정 한 규칙 레벨 오버라이드를 보여줍니다.

### Network Firewall 관리 규정

1. Cloudflare 대시보드에서[방화벽 정책](https://dash.cloudflare.com/?to=/:account/network-security/magic_firewall/managed)사이트 맵
2. 내 계정**관련 규칙**탭, 네트워크 방화벽 관리 규칙을 찾아 삭제하고 선택**계정 관리**.
3. 제품정보**설치하기**.

Cloudflare Network Firewall 관리 규정은 이제 삭제됩니다.
