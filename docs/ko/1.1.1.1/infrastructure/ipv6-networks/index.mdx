네트워크 인프라가 IPv6 전용 네트워크로 전환되는 중이지만, 제공업체는 여전히 IPv4 주소를 지원해야 합니다. 듀얼 스택 네트워크는 모든 노드가 IPv4와 IPv6 연결 기능을 모두 갖추고 있어, IPv4 패킷과 IPv6 패킷을 모두 이해할 수 있는 네트워크를 말합니다.

1.1.1.1은 DNS64를 지원합니다. DNS64는 AAAA 레코드가 없을 때 A 레코드로부터 AAAA 레코드를 합성하는 메커니즘입니다. DNS64를 사용하면 DNS 리졸버가 IPv4 응답으로부터 IPv6 주소를 합성하도록 구성할 수 있습니다.

:::note

IPv6 전용 네트워크를 관리하거나 사용 중인 경우에만 DNS64를 활성화해야 합니다. 리졸버는 IPv6 주소를 합성할 수 있지만, DNSSEC를 사용하는 도메인에 대해서는 해당 레코드의 서명을 합성할 수 없으므로, 서명을 다시 검증할 수 있는 DNS 클라이언트는 서명이 없는 이 추가 레코드를 거부하게 됩니다.

좋은 절충안은 클라이언트와 리졸버 사이에서 DNS over TLS 또는 DNS over HTTPS와 같은 안전한 프로토콜을 사용해 변조를 방지하는 것입니다.

:::

## DNS64 구성

DNS64는 이미 NAT64를 지원하는 네트워크를 위한 기능입니다. NAT64를 보유한 네트워크 운영자라면 다음 IP 주소로 업데이트하여 DNS64 지원을 시험해 볼 수 있습니다.

```txt
2606:4700:4700::64
2606:4700:4700::6400
```

일부 장치는 IPv6 주소의 여덟 부분 각각을 별도 필드로 입력하도록 하며, `::`와 같은 IPv6 축약 표기법을 허용하지 않습니다. 이런 필드에는 다음 값을 입력하세요.

```txt
2606:4700:4700:0:0:0:0:64
2606:4700:4700:0:0:0:0:6400
```

## DNS64 테스트

구성을 마친 뒤, IPv4 전용 주소에 접속해 실제로 도달할 수 있는지 확인하세요. 예를 들어 [https://ipv4.google.com](https://ipv4.google.com)을 방문해 볼 수 있습니다.

[http://test-ipv6.com/](http://test-ipv6.com/)에 접속해 IPv6 주소가 감지되는지 테스트하세요. `10/10`을 받으면 IPv6가 올바르게 구성된 것입니다.
