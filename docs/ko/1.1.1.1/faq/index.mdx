아래에서 가장 자주 받는 질문에 대한 답변을 확인할 수 있습니다. 찾는 답변이 없다면 [커뮤니티 페이지](https://community.cloudflare.com/)에서 더 많은 자료를 살펴보세요.

## 1.1.1.1이란 무엇인가요?

1.1.1.1은 Cloudflare의 빠르고 안전한 DNS 리졸버입니다. `cloudflare.com`과 같은 애플리케이션에 접속하려고 하면, 컴퓨터는 해당 애플리케이션을 불러오기 위해 어느 서버에 연결해야 하는지 알아야 합니다. 컴퓨터는 이름을 주소로 변환하는 방법을 스스로 알지 못하므로, 이를 대신 수행해 줄 특수한 서버에 요청합니다.

이 특수한 서버를 DNS 재귀 리졸버라고 합니다. 리졸버의 역할은 `cloudflare.com`에 대한 `2400:cb00:2048:1::c629:d7a2` 같은 주소를 찾아 요청한 컴퓨터에 돌려주는 것입니다.

컴퓨터는 IP 주소로 식별되는 특정 DNS 리졸버와 통신하도록 구성됩니다. 보통 가정용 또는 무선 인터넷에서는 ISP(예: Comcast 또는 AT\&T)가 이 구성을 관리하고, 회사 인터넷에 연결되어 있다면 네트워크 관리자가 이를 관리합니다. 사용자가 직접 컴퓨터가 통신할 DNS 리졸버를 변경할 수도 있습니다.

## 내 컴퓨터 / 스마트폰 / 태블릿이 1.1.1.1에 연결되어 있는지 어떻게 확인하나요?

[1.1.1.1/help](https://one.one.one.one/help)를 방문하여 시스템이 1.1.1.1에 연결되어 있고 제대로 작동하는지 확인하세요.

## DNS 리졸버는 무엇을 하나요?

DNS 리졸버는 인터넷의 주소록과 같습니다. 이름을 주소로 변환하여 브라우저가 목적지까지 가는 방법을 파악할 수 있게 해줍니다. DNS 리졸버는 위에서부터 역방향으로 따라 내려가며 사용자가 찾는 웹사이트를 찾아냅니다.

모든 리졸버는 도메인 이름 끝에 보이지 않게 붙는 `.`를 찾는 방법을 알고 있습니다(예: `cloudflare.com.`). 전 세계에는 `.` 파일을 호스팅하는 [수백 개의 루트 서버](http://www.root-servers.org/)가 있으며, 리졸버에는 이 서버들의 [IP 주소가 하드코딩](http://www.internic.net/domain/named.root)되어 있습니다. Cloudflare는 [ISC와의 파트너십](https://blog.cloudflare.com/f-root/)을 통해 전 세계 모든 서버에서 [해당 파일](http://www.internic.net/domain/root.zone)을 직접 호스팅하고 있습니다.

리졸버는 루트 서버 중 하나에 체인의 다음 고리, 즉 최상위 도메인(TLD, top-level domain) 또는 도메인 접미사를 어디에서 찾을 수 있는지 묻습니다. TLD의 예로는 `.com` 또는 `.org`가 있습니다. 다행히 루트 서버는 모든 TLD 서버의 위치를 저장하고 있으므로, DNS 리졸버가 다음에 어떤 IP 주소로 질의해야 하는지 알려줄 수 있습니다.

그다음 리졸버는 TLD 서버에 자신이 찾는 도메인을 어디에서 찾을 수 있는지 묻습니다. 예를 들어 리졸버는 `.com`에 `cloudflare.com`을 어디에서 찾을 수 있는지 질의할 수 있습니다. TLD는 해당 TLD를 사용하는 모든 도메인의 위치가 담긴 파일을 호스팅합니다.

리졸버가 최종 IP 주소를 얻으면, 그 답을 요청한 컴퓨터에 반환합니다.

이 전체 시스템을 [도메인 이름 시스템(DNS)](https://www.cloudflare.com/learning/dns/what-is-dns/)이라고 합니다. 이 시스템에는 정보를 호스팅하는 서버([authoritative DNS](https://www.cloudflare.com/learning/dns/dns-server-types/))와 정보를 찾는 서버(DNS 리졸버)가 포함됩니다.

## 1.1.1.1은 ANY를 지원하나요?

Cloudflare는 ANY 질의가 정상적인 사용보다 DNS 시스템에 대한 대규모 볼류메트릭 공격을 지속시키는 데 더 자주 사용되기 때문에 2015년에 [ANY 질의 지원을 중단](https://blog.cloudflare.com/deprecating-dns-any-meta-query-type/)했습니다. 1.1.1.1은 `qtype==ANY` 요청을 받으면 `NOTIMPL`을 반환합니다.

## 1.1.1.1은 DNSSEC와 어떻게 동작하나요?

1.1.1.1은 DNSSEC 검증 리졸버입니다. 1.1.1.1은 모든 질의에 `DO` (`DNSSEC OK`) 비트를 설정해, authoritative 서버가 가능할 경우 서명된 응답을 보내 달라는 뜻을 전달합니다. 1.1.1.1은 [지원되는 DNSKEY 서명 알고리즘](/1.1.1.1/encryption/dnskey/)에 명시된 서명 알고리즘을 지원합니다.

## 1.1.1.1은 EDNS Client Subnet 헤더를 보내나요?

1.1.1.1은 프라이버시 중심 리졸버이므로 클라이언트 IP 정보를 전송하지 않으며, authoritative 서버에 <GlossaryTooltip term="EDNS Client Subnet (ECS)">EDNS Client Subnet (ECS)</GlossaryTooltip> 헤더도 보내지 않습니다. 유일한 예외는 교차 제공자 디버깅을 돕기 위한 Akamai 디버그 도메인 `whoami.ds.akahelp.net` 하나뿐입니다. 하지만 Cloudflare는 `akamaihd.net`과 같은 Akamai의 운영 도메인에는 ECS를 전송하지 않습니다.

## 1.1.1.1은 IPv6를 지원하나요?

1.1.1.1은 IPv6를 완전히 지원합니다.

## Purge Cache란 무엇인가요?

1.1.1.1의 Purge Cache 도구를 사용하면 도메인 이름에 대한 1.1.1.1의 DNS 캐시를 새로 고칠 수 있습니다. 특정 도메인 이름의 캐시를 새로 고치려면 [Purge Cache 페이지](https://one.one.one.one/purge-cache/)를 방문하세요.

## Query name minimization이란 무엇인가요?

Cloudflare는 authoritative DNS 서버에 최소한의 query name만 전송하여 프라이버시 유출을 줄입니다. 예를 들어 클라이언트가 `foo.bar.example.com`을 조회하면, 1.1.1.1이 `.com`에 공개하는 정보는 example.com을 누가 책임지는지만 알기 원한다는 사실뿐이며, zone 내부 구조는 숨겨진 상태로 유지됩니다.

## Root hints란 무엇인가요?

지연 시간을 줄이고, 질의의 프라이버시 유출을 줄이며, DNS 시스템의 부하를 낮추기 위해 1.1.1.1은 [로컬에 호스팅된 root zone 파일](https://blog.cloudflare.com/f-root/)을 upstream으로 사용합니다.

## 1.1.1.1이 사용하는 IP를 allowlist에 추가할 수 있나요?

Authoritative DNS 제공자는 1.1.1.1이 upstream DNS 제공자에 질의할 때 사용하는 IP를 allowlist에 추가하고 싶을 수 있습니다. allowlist에 추가해야 하는 IP의 전체 목록은 [https://www.cloudflare.com/ips/](https://www.cloudflare.com/ips/)에서 확인할 수 있습니다.
