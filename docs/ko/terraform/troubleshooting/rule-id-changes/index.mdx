제품 정보[`cloudflare_ruleset`](https://registry.terraform.io/providers/cloudflare/cloudflare/latest/docs/resources/ruleset)리소스, Cloudflare 공급자는 규칙을 삭제하고 Terraform 구성의 규칙을 수정할 때 새로운 것을 만들 수 있습니다. API가 Cloudflare 구성의 기존 규칙과 새로운 Terraform 구성에서 규칙을 일치 할 수 없기 때문에 발생합니다. Terraform 설정에서 규칙을 수정하고 변경 사항을 적용하면 Cloudflare 계정 또는 영역에서 다른 규칙 ID와 새로운 규칙을 만들 수 있습니다.

이 행동은 모든 자동화 또는 모니터링 시스템에 영향을 미칠 수 있습니다. 규칙 수정 사이에 immutable 규칙 ID를 갖는 것을 재구성 할 수 있습니다.

## 수정 사이에 동일한 규칙 ID를 유지하는 방법

Terraform을 통해 규칙을 변경할 때 기존 규칙 ID를 유지하려면 추가하십시오.`ref`각 규칙에 필드.

더 보기`ref`필드는 규칙에 각 규칙에 고유해야합니다 사용자 정의 외부 식별자입니다. 당신이 제공 할 때`ref`값, 공급자는 기존 규칙과 함께 업데이트 된 Terraform 구성의 규칙과 일치합니다.`ref`외부 식별자 및 규칙 ID는 보존됩니다.

`ref`값에는 최소 길이의 문자열 데이터 유형이 있습니다. 예를 들어,`my_ref`.

설정하면`ref`규칙의 필드, 변화`ref`필드 값은 Terraform이 새로운 규칙을 만들 것입니다.

## `cf-terraforming`고객지원`ref`필드 값

기본적으로 규칙을 만들 때, 그`ref`값은 규칙 ID와 동일합니다. 설정할 수 있습니다.`ref`Cloudflare API를 통해 값.

당신은[기존 CloudflareXQ 구성 가져 오기](/terraform/advanced-topics/import-cloudflare-resources/)이름 \*[`cf-terraforming`](https://github.com/cloudflare/cf-terraforming), 생성 된 Terraform 구성이 있습니다`ref`각 규칙의 값, 규칙 ID와 같은 값.

Terraform 구성과 규칙의 구성을 수동으로 만든 경우`ref`필드, 추가`ref`각 규칙에 필드 그래서 각 규칙 수정은 새로운 규칙 ID를 생성하지 않습니다.
