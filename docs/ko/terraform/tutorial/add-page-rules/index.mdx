내 계정[HTTPS 설정 구성](/terraform/tutorial/configure-https-settings/)튜토리얼, 모든 들어오는 요청에 적용되는 영역 설정`example.com`. 이 튜토리얼에서는 이러한 설정을 사용하여 예외를 추가합니다.[페이지 규칙](/rules/page-rules/).

특정하게, 당신은 렌더링하고 캐시 할 수없는 URL에 대한 보안 수준을 증가합니다 :`https://www.example.com/expensive-db-call`. 또한, 이 페이지를 호스트하기 위해 이전 URL에서 리디렉션을 추가합니다.

## 1. 페이지 규칙 설정 만들기

새로운 지점을 만들고 구성을 추가합니다.

```bash
git checkout -b step5-pagerule
```

페이지 규칙은 특정 URL 패턴의 영역 설정을 무시합니다. 두 페이지 규칙을 추가하여`main.tf`:

```hcl
# Increase security for expensive database operations
resource "cloudflare_page_rule" "expensive_endpoint_security" {
  zone_id  = var.zone_id
  target   = "${var.domain}/expensive-db-call"
  priority = 1

  actions = {
    security_level = "under_attack"
  }
}

# Redirect old URLs to new location
resource "cloudflare_page_rule" "legacy_redirect" {
  zone_id  = var.zone_id
  target   = "${var.domain}/old-location.php"
  priority = 2

  actions = {
    forwarding_url = {
      url         = "https://www.${var.domain}/expensive-db-call"
      status_code = 301
    }
  }
}
```

첫 번째 규칙은 데이터베이스 엔드포인트의 "Under Attack"모드에 보안을 증가시킵니다. 두 번째 규칙은 301 영구 리디렉션과 오래된 URL을 리디렉션합니다.

## 2. 미리보기 및 변경 적용:

```sh
terraform plan
terraform apply
```

## 3. 변화를 검증:

리디렉션 기능을 테스트:

```bash
curl -I https://example.com/old-location.php
```

예상된 산출:

```bash output
HTTP/1.1 301 Moved Permanently
Location: https://example.com/expensive-db-call
```

증가 된 보안을 테스트 (잠금 모드는 도전 페이지를 반환):

```bash
curl -I https://example.com/expensive-db-call
```

예상된 산출:

```bash output
HTTP/1.1 503 Service Temporarily Unavailable
```

503 응답은 아래 공격 모드가 활성화되어 DDoS 공격에 대한 보호를 허용하기 전에 도전 페이지로 방문자를 제시합니다.

## 4. 변경 및 합병:

```bash
git add main.tf
git commit -m "Step 5 - Add two Page Rules"
git push
```

전화는 예상대로 작동합니다. 첫 번째 경우, Cloudflare 글로벌 네트워크는 대응`301`새로운 위치에 브라우저를 리디렉션. 두 번째 경우, Cloudflare 글로벌 네트워크는 처음에 응답`503`, 아래 공격 모드와 일관성.
