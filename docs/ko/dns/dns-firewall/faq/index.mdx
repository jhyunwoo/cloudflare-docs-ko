Cloudflare DNS Firewall에 대한 자주 묻는 질문의 답변을 참고하세요.

## DNS Firewall은 어떤 백엔드 네임서버에 업스트림 쿼리를 보낼지 어떻게 선택하나요?

DNS Firewall은 고객의 여러 네임서버 사이를 번갈아 사용하며, 느린 네임서버보다 더 빠른 업스트림 네임서버로 쿼리를 보낼 가능성이 높아지도록 설계된 알고리즘을 사용합니다.

## DNS Firewall은 오래된 객체를 얼마나 오래 캐시하나요?

DNS Firewall은 할당된 메모리에 따라 캐시 보존 기간을 설정합니다.

충분한 메모리가 할당되어 있는 한, Cloudflare는 TTL이 만료되더라도 캐시에서 항목을 강제로 삭제하지 않습니다. 이 기능 덕분에 네임서버가 오프라인일 때도 Cloudflare가 캐시에서 오래된 객체를 제공할 수 있습니다.

## DNS Firewall은 SERVFAIL을 캐시하나요?

예. 캐싱 목적상 `SERVFAIL`도 다른 음수 응답과 동일하게 처리됩니다. 기본 TTL은 30초입니다. [API](/api/resources/dns_firewall/methods/edit/)를 사용해 다른 `negative_cache_ttl` 값을 설정할 수 있습니다.

## DNS Firewall은 EDNS Client Subnet(ECS)을 지원하나요?

예. DNS 제공자는 종종 클라이언트 IP를 기준으로 지리적으로 다른 DNS 응답을 제공하기 때문에, <GlossaryTooltip term="EDNS Client Subnet (ECS)">EDNS Client Subnet (ECS)</GlossaryTooltip>([RFC 7871](https://www.rfc-editor.org/rfc/rfc7871.html))을 통해 클라이언트 IP를 확인하고자 합니다. EDNS Client Subnet이 활성화되면 DNS Firewall은 DNS 쿼리와 함께 클라이언트 IP 서브넷을 업스트림 네임서버로 전달합니다.

EDNS가 활성화되면 DNS Firewall은 클라이언트 IP 서브넷을 기준으로 지리적으로 올바른 응답을 캐시에서 제공합니다. 이를 위해 DNS Firewall은 캐시를 분할합니다. 예를 들면 다음과 같습니다.

1. resolver가 클라이언트 `192.0.2.0/24`에 대한 응답을 찾고 있다고 알립니다.
2. DNS Firewall은 응답을 얻기 위해 해당 요청을 업스트림 네임서버로 프록시합니다.
3. DNS Firewall은 업스트림 네임서버의 응답을 캐시하지만, 해당 `/24`에 대해서만 캐시합니다.
4. 이후 `203.0.113.0/24`가 동일한 DNS 질문을 하면 응답은 다시 캐시가 아니라 업스트림 네임서버에서 반환됩니다.

:::note

EDNS는 DNS 캐시의 효율성을 제한합니다.

:::

일부 resolver는 EDNS 데이터를 전혀 보내지 않을 수 있습니다. [API](/api/resources/dns_firewall/methods/edit/)를 통해 `ecs_fallback` 매개변수를 `true`로 설정하면, 들어오는 DNS 쿼리에 EDNS 데이터가 없을 때만 DNS Firewall이 resolver의 IP 서브넷을 대신 전달합니다.

## DNS Firewall은 음수 응답을 캐시하나요?

예. 기본 TTL은 30초입니다. [API](/api/resources/dns_firewall/methods/edit/)를 통해 `negative_cache_ttl`을 설정할 수 있습니다. 이 값은 `REFUSED`, `NXDOMAIN`, `SERVFAIL` 상태의 응답 TTL에 영향을 줍니다.

## 네임서버 호스트명의 PTR 레코드는 어떻게 설정하나요?

네임서버 호스트명을 가리키는 DNS Firewall 클러스터 IP의 PTR 레코드를 설정하려면 다음 API 엔드포인트를 사용하세요.

- [Show DNS Firewall Cluster Reverse DNS](/api/resources/dns_firewall/subresources/reverse_dns/methods/get/)
- [Update DNS Firewall Cluster Reverse DNS](/api/resources/dns_firewall/subresources/reverse_dns/methods/edit/)
