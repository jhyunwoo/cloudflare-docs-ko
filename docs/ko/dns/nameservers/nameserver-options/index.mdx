아래 섹션에서는 다양한 Cloudflare 네임서버 옵션을 설명합니다. 이 옵션들의 제공 여부는 요금제에 따라 다릅니다. 또한 Cloudflare Registrar에서 도메인을 구매했다면, 해당 도메인은 이미 Cloudflare 네임서버를 사용 중이며 [계속 유지해야 합니다](/registrar/faq/#can-i-change-my-nameservers).

## 할당 방식

[기본(primary, full)](/dns/zone-setups/full-setup/) 또는 [보조](/dns/zone-setups/zone-transfers/cloudflare-as-secondary/) DNS 설정으로 도메인을 추가하면 Cloudflare가 자동으로 네임서버를 할당합니다.

기본 할당 방식은 [표준 네임서버](/dns/nameservers/#standard-nameservers)를 사용하고, 같은 계정 내 모든 영역에서 네임서버 이름이 최대한 일관되게 유지되도록 하는 것입니다. 다만 충돌이 발생하면 같은 계정 내 도메인이라도 서로 다른 네임서버 이름이 할당될 수 있습니다.

:::caution
도메인 탈취를 방지하기 위해 이제 Cloudflare에 해당 영역을 만들기 전에 등록기관에서 Cloudflare 네임서버를 미리 설정할 수 없습니다. 네임서버를 미리 설정한 뒤 도메인을 추가하면, 도메인에는 새로운 네임서버 쌍이 할당됩니다.
:::

이 네임서버 할당은 변경할 수 없습니다. 하지만 구독 유형에 따라 더 나은 네임서버 일관성을 위한 다른 옵션을 사용할 수 있습니다.

### 네임서버 일관성

새 영역을 추가할 때 기대할 수 있는 일관성 수준은 구성된 네임서버 유형에 따라 달라집니다.

- [표준 네임서버](/dns/nameservers/#standard-nameservers)의 경우, 같은 영역이 다른 Cloudflare 계정에 추가되는 것만으로도 충돌이 발생할 수 있으므로, 새 영역이 기존 영역과 다른 네임서버 이름을 받을 가능성이 높습니다.

- [계정 사용자 지정 네임서버](/dns/nameservers/custom-nameservers/account-custom-nameservers/)를 사용하면 충돌은 부모 영역과 자식 영역 사이에서만 발생하므로, 새 영역 간 일관된 할당 가능성이 더 높습니다.

- [테넌트 사용자 지정 네임서버](/dns/nameservers/custom-nameservers/tenant-custom-nameservers/) 또는 [Foundation DNS 고급 네임서버](/dns/foundation-dns/advanced-nameservers/#nameservers-hosting-and-assignment)를 사용하면 동일한 이름의 두 영역이 서로 다른 계정에 추가되어도 충돌이 생길 수 있습니다. 하지만 이 기능들에 대한 접근이 더 제한적이므로, 새 영역이 기존 영역과 다른 네임서버 이름을 받을 가능성은 더 낮습니다.

### DNS 영역 기본값

Enterprise 계정이라면 [자체 DNS 영역 기본값](/dns/additional-options/dns-zone-defaults/)을 구성하여 새 영역을 계정에 추가할 때 Cloudflare가 네임서버를 할당하는 방식을 변경할 수도 있습니다.

- **Standard nameservers randomized**: 일관성을 시도하는 대신, Cloudflare가 도메인을 계정에 추가할 때마다 무작위 네임서버 이름 쌍을 할당합니다.
- **Advanced nameservers**: 기본 방식과 동일하게 같은 계정 내 여러 영역에서 네임서버 이름을 최대한 일관되게 유지하려고 시도하지만, 특정 [Foundation DNS 네임서버](/dns/foundation-dns/advanced-nameservers/)를 사용합니다.
- **Account custom nameservers**: Cloudflare가 계정에 미리 구성된 [계정 사용자 지정 네임서버](/dns/nameservers/custom-nameservers/account-custom-nameservers/) 세트를 자동으로 할당합니다. 이 방식에서는 **Set 1**을 먼저 시도하고, 충돌이 있으면 나머지 세트를 오름차순으로 순환합니다.

:::caution

## Multi-provider DNS

Multi-provider DNS는 [기본 설정(full)](/dns/zone-setups/full-setup/)을 사용하는 영역에서는 선택적 설정이며, [보조 설정](/dns/zone-setups/zone-transfers/cloudflare-as-secondary/)을 사용하는 영역에서는 기본적으로 강제되는 동작입니다.

기본 영역에서 multi-provider DNS를 활성화하면 다음과 같은 일이 발생합니다.

* Cloudflare는 더 이상 영역 apex에 만든 `NS` 레코드를 무시하지 않습니다. 아래 예시를 참고하세요.

  <Example>

  | Type | Name | Nameserver         |
  | ---- | ---- | ------------------ |
  | `NS` | `@`  | `ns1.external.com` |

  </Example>

이것은 영역 apex에 대해 `NS` 레코드를 요청하는 DNS 쿼리에 대한 응답에 Cloudflare 네임서버와 다른 DNS 공급자의 네임서버가 모두 포함된다는 뜻입니다.

* Cloudflare는 등록기관에 나열된 [네임서버](/dns/nameservers/update-nameservers/)에 다른 DNS 공급자의 네임서버가 포함되어 있더라도 기본 영역(full setup)을 활성화합니다.

:::caution

이 옵션을 선택하고 영역에서 DNSSEC도 사용하려면 [multi-signer DNSSEC](/dns/dnssec/multi-signer-dnssec/)를 반드시 구성하세요.

:::

## Nameserver TTL

Cloudflare 네임서버(표준 또는 고급)와 사용자 지정 네임서버 모두에서 `NS` 레코드 time-to-live(TTL)은 **DNS Records** 페이지의 **DNS record options** 아래 설정으로 제어됩니다.

:::note[Foundation DNS]
**DNS record options**는 [Foundation DNS](/dns/foundation-dns/)의 일부입니다. Enterprise 고객인데 Cloudflare 대시보드에 **Nameserver TTL**이 보이지 않는다면 계정 팀에 문의하세요.
:::

기본 TTL은 24시간(86,400초)이지만 필요에 따라 더 낮출 수 있습니다. 예를 들어 네임서버를 변경하거나 영역을 마이그레이션할 때는 짧은 TTL이 유용할 수 있습니다. 허용 값 범위는 30초에서 86,400초입니다.

이 설정은 [DNS 영역 기본값](/dns/additional-options/dns-zone-defaults/)으로도 구성할 수 있으므로, 계정에서 새로 생성되는 영역은 자동으로 지정한 값으로 시작하게 됩니다.
