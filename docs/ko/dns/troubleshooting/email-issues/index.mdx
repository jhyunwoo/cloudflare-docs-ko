메일 전송 또는 수신에 문제가 있다면 다음 문제 해결 단계를 따라 보세요.

## 레코드가 올바른가요?

유효한 DNS 레코드 내용이 있는지 메일 관리자 또는 메일 제공업체와 확인하세요.

## DNS 레코드가 누락되었나요?

도메인의 DNS 레코드가 올바른지 메일 관리자에게 확인해 달라고 요청하세요. 레코드를 추가하거나 편집하는 데 도움이 필요하면 [Cloudflare에서 DNS 레코드 관리](/dns/manage-dns-records/how-to/create-dns-records)에 대한 가이드를 참고하세요.

## NS 레코드가 구성되어 있나요?

NS 레코드는 호스트명의 관리 권한을 다른 DNS 제공업체에 위임하는 데 사용됩니다(자세한 내용은 [Delegate a subdomain (outgoing)](/dns/manage-dns-records/how-to/subdomains-outside-cloudflare/#delegate-a-subdomain-outgoing) 참고). Cloudflare 대시보드의 DNS 탭에 NS 레코드가 구성되어 있다면, 그것이 의도된 설정인지 그리고 충돌을 일으키고 있지 않은지 확인하세요.

## CNAME Flattening이 활성화되어 있나요?

Cloudflare DNS 설정에서 [Flatten all CNAMEs](/dns/cname-flattening/set-up-cname-flattening/)로 설정하면, 모든 `CNAME` 레코드에 대한 쿼리는 `A` 레코드로 flatten되며 `CNAME` 레코드는 반환되지 않습니다.

또한 쿼리된 네임서버가 `CNAME` 레코드를 반환하지 않는 경우(일부 네임서버는 TXT 레코드를 반환할 수 있음), ***Flatten all CNAMEs***가 활성화되어 있으면 아무것도 반환되지 않을 수 있습니다. ***Flatten at the root***로 변경하면 `CNAME` 레코드가 반환되지 않는 문제를 해결할 수 있습니다.

## 계정에 Cloudflare Spectrum이 활성화되어 있나요?

[Cloudflare Spectrum](/spectrum/reference/configuration-options#smtp)이 활성화되고 이메일 트래픽을 Cloudflare를 통해 프록시하도록 구성되지 않은 한, Cloudflare는 포트 25(SMTP)의 트래픽을 프록시하지 않습니다. Spectrum이 활성화되어 있지 않다면 이메일 트래픽(SMTP)은 실제로 Cloudflare를 통과하지 않고, Cloudflare는 단지 DNS만 해석합니다. 따라서 이메일 트래픽 전송에 사용되는 모든 DNS 레코드는 Cloudflare 네트워크를 우회하도록 DNS-only여야 합니다. 자세한 내용은 [Cloudflare 프록시와 호환되는 서브도메인 식별](/dns/proxy-status/)을 확인하세요.

## 메일 제공업체에 지원 요청

DNS 레코드를 편집한 직후에도 이메일이 작동하지 않는다면, 문제 해결에 필요한 데이터를 Cloudflare 지원팀에 제공할 수 있도록 메일 관리자 또는 메일 제공업체에 추가 지원을 요청하세요.

## dc-######### 서브도메인

`dc-#####` 서브도메인은 `SRV` 또는 `MX` 레코드가 Cloudflare [proxy](/dns/proxy-status/)로 설정된 도메인으로 해석될 때 발생하는 충돌을 해결하기 위해 추가됩니다.

따라서 Cloudflare는 원본 IP 주소로 해석되는 `dc-#####` DNS 레코드를 생성합니다. `dc-#####` 레코드는 `MX` 또는 `SRV` 레코드 트래픽이 프록시되지 않고(직접 원본 IP로 해석됨), 그 외 다른 트래픽에는 Cloudflare 프록시가 계속 동작하도록 보장합니다.

예를 들어 Cloudflare를 사용하기 전 메일용 DNS 레코드가 다음과 같다고 가정해 보겠습니다.

`example.com MX example.com` `example.com A 192.0.2.1`

Cloudflare 사용 후 `A` 레코드를 프록시하면, Cloudflare는 다음 예처럼 Cloudflare IP를 포함한 DNS 응답을 제공합니다(`203.0.113.1`).

`example.com MX example.com` `example.com A 203.0.113.1`

메일 트래픽을 Cloudflare로 프록시하면 메일 서비스가 중단되므로, Cloudflare는 이 상황을 감지하고 `dc-#####` 레코드를 생성합니다.

`example.com MX dc-1234abcd.example.com` `dc-1234abcd.example.com A 192.0.2.1` `example.com A 203.0.113.1`

`dc-######` 레코드는 다음 방법 중 하나로만 제거할 수 있습니다.

* 도메인에서 메일을 수신하지 않는다면 `MX` 레코드를 삭제합니다.
* 도메인에서 메일을 수신한다면 `MX` 레코드가 Cloudflare에서 프록시되지 않는 메일 서브도메인의 별도 `A` 레코드로 해석되도록 업데이트합니다.

`example.com MX mail.example.com` `mail.example.com A 192.0.2.1` `example.com A 203.0.113.1`

:::caution

메일 서버가 웹 서버와 같은 IP에 있다면, MX 레코드가 origin IP 주소를 노출하게 됩니다.
:::
