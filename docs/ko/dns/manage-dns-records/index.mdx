DNS 레코드는 도메인에 대한 정보를 담고 있으며, 웹사이트나 애플리케이션을 방문자 및 다른 웹 서비스가 사용할 수 있도록 만드는 데 사용됩니다.

각 DNS 레코드는 서로 다른 유형에 속하며, 각 유형은 서로 다른 목적을 가집니다. DNS 레코드의 여러 유형에 대한 배경 설명은 [Learning Center](https://www.cloudflare.com/learning/dns/dns-records/)를 참고하세요. 특정 유형에 대한 참조 정보를 빠르게 찾으려면 [DNS record types](/dns/manage-dns-records/reference/dns-record-types/)를 참고하세요.

[도메인 이름을 얻기 위해](/fundamentals/manage-domains/#get-a-domain-name) 사용한 공급자와 [웹사이트 또는 애플리케이션을 호스팅하는](/fundamentals/manage-domains/#host-your-domain) 방식에 따라, DNS 레코드가 자동으로 생성되어 있는 경우가 일반적입니다. [설정 방식](/dns/zone-setups/)에 따라 Cloudflare를 사용해 DNS 레코드를 관리할 수 있습니다.

## DNS 레코드 표

Cloudflare에서 레코드를 관리할 때는 아래에 설명된 일반적인 레코드 필드 외에도 [Proxy status](/dns/proxy-status/) 및 [CNAME flattening](/dns/cname-flattening/) 옵션을 볼 수 있습니다. 이는 Cloudflare가 제공하는 고유 기능입니다.

<Details header="레코드 필드">
- **Type**: 레코드의 목적을 정의합니다. 레코드 유형마다 해당 `Content` 필드에 필요한 정보가 다릅니다.
- **Name**: 레코드가 해석하는 리소스를 식별합니다. 레코드의 목적에 따라 이 필드에 추가해야 하는 값도 달라집니다.
- **Content**: 레코드 유형에 따라 레코드의 핵심 값을 담습니다.
- **TTL**: 각 레코드가 DNS 확인자에 의해 얼마나 오래 캐시되는지를 제어합니다.
</Details>

<Details header="예시">

<Example>
**example.com**의 DNS 관리:

| Type | Name    | Content      | Proxy status | TTL    |
| ---- | ------- | ------------ | ------------ | ------ |
| A    | `blog`  | `192.0.2.1`  | Proxied      | Auto   |

이 예시에서 `A` 유형의 IP 주소 해석 레코드는 `blog.example.com` 서브도메인에 해당하는 리소스가 IPv4 주소 `192.0.2.1`에서 도달 가능하다는 것을 나타냅니다.

또한 이 레코드는 <GlossaryTooltip term="proxy status" link="/dns/proxy-status/">proxied</GlossaryTooltip> 상태이므로, Cloudflare가 DNS 확인자가 이 정보를 얼마나 오래 캐시해야 하는지 자동으로 결정합니다.
</Example>

</Details>

## DNS 레코드 수량 제한

단일 <GlossaryTooltip term="DNS zone">zone</GlossaryTooltip>에서 생성할 수 있는 레코드 수에는 제한이 있습니다.

- `2024-09-01 00:00:00 UTC` 이전에 생성된 Free zone: 1,000
- `2024-09-01 00:00:00 UTC` 이후에 생성된 Free zone: 200
- Pro: 3,500
- Business: 3,500
- Enterprise: 3,500

:::note[더 많은 DNS 레코드가 필요한 경우]

Enterprise 고객이 더 많은 DNS 레코드가 필요하다면 계정 팀에 문의하세요. Cloudflare는 단일 zone에서 수백만 개의 DNS 레코드를 지원할 수 있습니다.

:::
