**Time to Live (TTL)**는 [DNS 레코드](/dns/manage-dns-records/how-to/create-dns-records/)의 필드로, 각 레코드가 얼마나 오래 캐시되는지와 그 결과 레코드 업데이트가 최종 사용자에게 도달하는 데 얼마나 걸리는지를 제어합니다.

더 긴 TTL은 캐시된 결과가 사용될 가능성을 높여 [DNS 조회](https://www.cloudflare.com/learning/dns/what-is-dns/) 속도를 높여 주지만, 동시에 레코드 업데이트가 적용되는 데 더 오래 걸리게 만듭니다.

## Proxied 레코드

기본적으로 모든 <GlossaryTooltip term="proxy status" link="/dns/proxy-status/">proxied 레코드</GlossaryTooltip>의 TTL은 **Auto**이며 300초로 설정됩니다. 이 값은 편집할 수 없습니다.

[IP 주소 해석에 사용되는 레코드](/dns/manage-dns-records/reference/dns-record-types/#ip-address-resolution)만 프록시할 수 있으므로, 이 설정은 재귀 확인자가 할당된 [anycast IP 주소](/fundamentals/concepts/cloudflare-ip-addresses/)의 잠재적 변경 사항을 300초(5분) 이상 캐시하지 않도록 해 빠르게 반영되게 합니다.

:::note
로컬 DNS 캐시가 갱신되는 데 더 오래 걸릴 수 있으므로, 실제로 레코드 변경을 체감하기까지는 5분보다 더 오래 걸릴 수 있습니다.
:::

## Unproxied 레코드

**DNS only** 레코드의 경우 TTL을 **30초**(Enterprise) 또는 **60초**(비 Enterprise)에서 **1일** 사이로 선택할 수 있습니다.

**Auto** TTL은 300초(5분)로 설정됩니다.

## Nameserver TTL

[Nameserver TTL](/dns/nameservers/nameserver-options/#nameserver-ttl)은 별도의 기능이며 Cloudflare 네임서버와 사용자 지정 네임서버에만 영향을 줍니다. DNS 레코드 표의 다른 [NS 레코드](/dns/manage-dns-records/reference/dns-record-types/#ns)에 대한 TTL은 해당 레코드의 TTL 필드로 제어됩니다.
