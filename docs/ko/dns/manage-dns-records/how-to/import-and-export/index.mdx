## 레코드 가져오기

### 제한 사항

- <Render file="zone-file-size-limit" product="dns" />
- API rate limit은 사용자당 분당 3회 요청입니다.

### zone file 형식 지정

도메인에 대한 [BIND zone file](https://en.wikipedia.org/wiki/Zone_file)을 만드세요. 도움이 필요하면 [서드파티 도구](https://pgl.yoyo.org/as/bind-zone-file-creator.php)를 사용할 수 있습니다.

특정 레코드 유형(예: `CNAME`, `DNAME`, `MX`, `NS`, `PTR`, `SRV`)을 사용하는 경우, 해당 레코드의 **content**에는 반드시 후행 마침표가 붙은 완전한 정규 도메인 이름(`example.com.`처럼)이 들어 있어야 합니다. 자세한 내용은 [RFC 1035](https://www.rfc-editor.org/rfc/rfc1035#section-5.1) 또는 [Stack Exchange 게시물](https://superuser.com/questions/348282/fqdn-format-in-bind-zone#348284)을 참고하세요.

## DNS 레코드 속성

zone file을 내보내거나 가져올 때 Cloudflare는 [RFC 1035 section 5](https://datatracker.ietf.org/doc/html/rfc1035#section-5-1)에 따라, 각 레코드 뒤에 `;` 문자를 사용한 인라인 댓글 형태로 속성을 덧붙이며 [comments and tags](/dns/manage-dns-records/reference/record-attributes/)를 다음 구조로 포맷합니다.

| 조합           | 설명                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **태그만 있는 경우**         | 태그 이름에는 [제한된 문자 집합](/dns/manage-dns-records/reference/record-attributes/#tags)만 사용할 수 있습니다.<br/><br/>또한 태그 값에 `"`, `=`, `,`, `\`가 포함되면 반드시 큰따옴표(`"`)로 감싸야 합니다. 큰따옴표로 감싼 태그 값은 JSON 문자열로 표현되므로, 값 안의 다른 따옴표는 `\"`로 이스케이프할 수 있습니다.<br/><br/>값이 비어 있는 태그는 `my-tag-name:""`, `my-tag-name:`, 또는 `my-tag-name`처럼 표현할 수 있습니다. |
| **댓글만 있는 경우**    | 댓글은 문자에 대한 [제약이 더 적기 때문에](/dns/manage-dns-records/reference/record-attributes/#comments) 원문 그대로 포함됩니다.<br/><br/>댓글 안에 `cf_tags=` 문자열이 포함되어 있으면, 줄 끝에 추가로 ` cf_tags=`를 넣어야 합니다.                                                                                                                                                                                                    |
| **댓글과 태그가 모두 있는 경우**  | zone file의 댓글은 위 설명처럼 ; `<comment>` cf_tags=`<tags>`` 형식이 됩니다. `cf_tags=` 앞에 공백 문자가 추가된다는 점에 유의하세요.                                                                                                                                                                                                                                                                                                                                                |
| **어느 속성도 없는 경우** | zone file의 댓글은 비어 있거나 완전히 생략될 수 있습니다. 또한 zone file에서 레코드 바로 뒤에 오지 않는 댓글은 무시됩니다.                                                                                                                                                                                                                                                                                                                                              |

```txt title="예시 zone file"
; Only tags
a.example.com.  60  IN  A   1.1.1.1 ;   cf_tags=awesome
b.example.com.  60  IN  A   1.1.1.1 ;   cf_tags=tag1,tag2:value2,tag3:"value,with,commas",tag4:"value with \"escaped\" quotation marks"

; Only a comment
c.example.com.  60  IN  A   1.1.1.1 ; just a comment without tags
d.example.com.  60  IN  A   1.1.1.1 ; this comment contains cf_tags= as text cf_tags=

; Comments and tags
e.example.com.  60  IN  A   1.1.1.1 ; simple example cf_tags=important,ticket:THIS-12345
f.example.com.  60  IN  A   1.1.1.1 ; this is the comment cf_tags=tag1:value1,tag2:value2,tag-without-value,another-tag-without-value,tag-with-quoted-value:"because of the comma, quotes are needed"

; Neither attribute
g.example.com.  60  IN  A   1.1.1.1
```

### 예약된 cf- 태그

내보내기와 가져오기에서 `cf-`로 시작하는 특수 태그는 특정 Cloudflare 구성을 제어할 수 있게 해 줍니다. 내보낼 때는 zone 내 각 레코드의 현재 구성을 반영하도록 이 태그가 자동으로 추가됩니다.

```txt title="cf- 태그가 있는 레코드 예시"
;; CNAME Records
a.cloudflaredocs.com.	1	IN	CNAME	example.com. ; cf_tags=test:1,cf-flatten-cname
b.cloudflaredocs.com.	1	IN	CNAME	example.com. ; cf_tags=cf-proxied:false
c.cloudflaredocs.com.	1	IN	CNAME	example.com. ; cf_tags=tag-without-value,cf-proxied:true
```

#### cf-proxied

내보낼 때 [proxied DNS records](/dns/proxy-status/)에는 `cf-proxied:true` 태그가 포함되고, DNS-only 레코드에는 `cf-proxied:false`가 설정됩니다.

zone file을 가져올 때는 `cf-proxied` 태그의 값이 레코드를 프록시할지 결정할 때 우선 적용됩니다. 즉:

- 태그가 존재하면, 대시보드에서 **Proxy imported DNS records**가 선택되어 있는지와 무관하게, 또는 API에서 `proxied` 매개변수가 일반적으로 `true` 또는 `false`로 설정되어 있는지와 무관하게, 해당 값이 우선 적용됩니다.
- 태그가 없으면 프록시 상태는 일반 가져오기 옵션으로 되돌아가며, 즉 대시보드에서 **Proxy imported DNS records**가 선택되었는지 여부 또는 API에서 `proxied` 매개변수에 `true`/`false`가 설정되었는지를 따릅니다.

#### cf-flatten-cname

유료 zone에서 [Per-record CNAME flattening](/dns/cname-flattening/set-up-cname-flattening/#per-record)을 사용하려면, zone file에서 평탄화된 각 CNAME 레코드 옆에 `cf-flatten-cname` 태그를 추가하세요. 내보낼 때는 zone에 설정된 레코드 구성을 반영하도록 이 태그가 자동으로 추가됩니다.

## DNS zone file 지시문

DNS zone file은 리소스 레코드(RR) 외에도 지시문을 사용해 구성할 수 있습니다. 지시문은 `$`로 시작하며 표준화되어 있습니다. `$ORIGIN`과 `$INCLUDE`는 [RFC 1035](https://www.rfc-editor.org/rfc/rfc1035#section-5.1)에, `$TTL`은 [RFC 2308](https://www.rfc-editor.org/rfc/rfc2308)에 정의되어 있습니다. 또한 BIND는 [비표준](https://bind9.readthedocs.io/en/latest/chapter3.html#bind-primary-file-extension-the-generate-directive) `$GENERATE` 지시문을 제공합니다.

Cloudflare는 `$ORIGIN`, `$TTL`, `$GENERATE` 지시문을 지원합니다.

`$INCLUDE`는 지원되지 않습니다. zone file에 `$INCLUDE` 지시문이 포함되어 있으면 Cloudflare는 `$INCLUDE directive not allowed` 파싱 오류를 반환합니다.
