## 참조

### DNS 해석

부분 영역(<GlossaryTooltip term="CNAME setup" link="/dns/zone-setups/partial-setup/">CNAME 설정</GlossaryTooltip>)에서는 Cloudflare가 [DNS 레코드를 기본 영역(전체 설정)과 다르게 해석](/dns/zone-setups/partial-setup/dns-resolution/)합니다.

### CNAME Flattening

CNAME 설정(부분)에서는 프록시할 호스트명이 CNAME 레코드를 통해 Cloudflare를 가리켜야 합니다. [영역 apex에는 CNAME 레코드를 둘 수 없기](https://datatracker.ietf.org/doc/html/rfc1912#section-2.4) 때문에(`example.com`), authoritative DNS 공급자가 [CNAME Flattening](https://blog.cloudflare.com/introducing-cname-flattening-rfc-compliant-cnames-at-a-domains-root/)을 지원하는 경우에만 영역 apex를 Cloudflare로 프록시할 수 있습니다.

authoritative DNS 공급자가 CNAME Flattening을 지원하지 않는다면 `.htaccess` 파일 등을 사용해 트래픽을 Cloudflare로 프록시되는 서브도메인으로 리디렉션하세요. 또는 [정적 IP 또는 BYOIP](/fundamentals/concepts/cloudflare-ip-addresses/#customize-cloudflare-ip-addresses)을 사용할 수도 있습니다.

### DDoS 보호

DNS 인프라를 대상으로 하는 공격에 대한 [DDoS 보호](/ddos-protection/)는 [기본 설정(전체)](/dns/zone-setups/full-setup/) 도메인에서만 사용할 수 있습니다. CNAME 설정(부분) 도메인은 Cloudflare authoritative 네임서버를 사용하지 않기 때문입니다.

### 도메인 소유권

Enterprise 고객은 [zone hold](/fundamentals/account/account-security/zone-holds/)를 사용해 다른 Cloudflare 계정에 이미 활성화된 영역을 조직 내 다른 팀이 추가하지 못하게 할 수 있습니다. CNAME 설정(부분)의 경우 동일한 영역이 여러 계정에 추가되면, 마지막으로 설정을 완료한 계정이 소유권을 갖습니다.
