부모 zone이 [primary setup (full)](/dns/zone-setups/full-setup/)[^1]을 사용하는 경우, 자식 zone을 설정하는 절차는 서브도메인이 이미 부모 도메인 안에 존재하는지 여부에 따라 달라집니다.

:::note


Cloudflare 부모 zone이 secondary setup에 있는 경우에도 아래 단계는 유사합니다. 차이점은 필요한 DNS 레코드 조정 작업을 외부 primary DNS 제공자에서 수행한다는 점뿐입니다.


:::

## 서브도메인이 아직 존재하지 않는 경우

부모 zone에 아직 서브도메인을 포괄하는 DNS 레코드가 없다면:

1. 서브도메인을 새 zone으로 Cloudflare 계정에 추가합니다. 부모 zone이 있는 동일 계정일 수도 있고 다른 계정일 수도 있습니다.

2. [full](/dns/zone-setups/full-setup/setup/) 또는 [secondary](/dns/zone-setups/zone-transfers/cloudflare-as-secondary/setup/) setup에 맞게 구성을 완료합니다.

3. 서브도메인의 네임서버 이름을 확인합니다. 이는 새로 만든 자식 zone의 [**DNS Records**](https://dash.cloudflare.com/?to=/:account/:zone/dns/records) 페이지에서 찾을 수 있으며, 부모 zone에서 사용하는 네임서버와는 **다릅니다**.

4. 부모 zone의 [**DNS Records**](https://dash.cloudflare.com/?to=/:account/:zone/dns/records) 페이지에서 위임하려는 서브도메인에 대해 `NS` 레코드 두 개를 [추가](/dns/manage-dns-records/how-to/create-dns-records/)합니다.

   예를 들어 `www.example.com`을 위임한다면 `example.com`에 다음과 같은 레코드를 추가할 수 있습니다.

   | **Type** | **Name** | **Content**               |
   | -------- | -------- | ------------------------- |
   | `NS`     | www      | john.ns.cloudflare.com    |
   | `NS`     | www      | melinda.ns.cloudflare.com |

5. 몇 분 후 자식 zone이 활성 상태가 됩니다.

6. 자식 zone에 필요한 다양한 DNS 레코드를 생성합니다.

7. (선택 사항) 자식 zone에서 [DNSSEC](/dns/zone-setups/subdomain-setup/dnssec/)를 [활성화](/dns/zone-setups/subdomain-setup/dnssec/)합니다.

## 서브도메인이 이미 존재하는 경우

부모 zone에 이미 서브도메인을 포괄하는 DNS 레코드를 만든 상태라면:

1. 서브도메인을 새 zone으로 Cloudflare 계정에 추가합니다. 부모 zone이 있는 동일 계정일 수도 있고 다른 계정일 수도 있습니다.

2. [full](/dns/zone-setups/full-setup/setup/) 또는 [secondary](/dns/zone-setups/zone-transfers/cloudflare-as-secondary/setup/) setup에 맞게 구성을 완료합니다.

3. 자식 zone 안에 서브도메인과 관련된 모든 DNS 레코드가 있는지 확인합니다. 여기에는 위임된 서브도메인보다 더 깊은 모든 DNS 레코드도 포함됩니다. 예를 들어 `www.example.com`을 위임한다면 `api.www.example.com`에 대한 레코드도 옮겨야 합니다.

   :::note
   자식 zone이 primary setup(full)에 있다면 부모 zone에서 레코드를 [내보낸](/dns/manage-dns-records/how-to/import-and-export/#export-records) 뒤 불필요한 항목을 삭제하고, 새 zone에 해당 레코드를 [가져오는](/dns/manage-dns-records/how-to/import-and-export/#import-records) 방법을 고려하세요.
   :::

4. 부모 zone이 Cloudflare에 있다면 자식 zone에 필요할 수 있는 설정([WAF 사용자 지정 규칙](/waf/custom-rules/), [Rules](/rules/), [Workers](/workers/) 등)을 옮겨야 합니다.

5. 자식 zone에서 자식 서브도메인과 더 깊은 모든 서브도메인(있는 경우)을 포괄하는 [고급 SSL 인증서](/ssl/edge-certificates/advanced-certificate-manager/)를 주문합니다.

6. 서브도메인의 네임서버 이름을 확인합니다. 이는 새로 만든 자식 zone의 [**DNS Records**](https://dash.cloudflare.com/?to=/:account/:zone/dns/records) 페이지에서 찾을 수 있으며, 부모 zone에서 사용하는 네임서버와는 **다릅니다**.

   :::note
   부모 zone이 Cloudflare에 있다면 아래 7단계와 9단계는 API로 수행할 수도 있습니다. [Batch DNS records](/api/resources/dns/subresources/records/methods/batch/) 엔드포인트를 사용해 하나의 요청 안에서 DNS 레코드를 삭제하고 생성 또는 업데이트하세요. 자세한 내용은 [일괄 레코드 변경](/dns/manage-dns-records/how-to/batch-record-changes/)을 참고하세요.
   :::

7. 부모 zone의 [**DNS Records**](https://dash.cloudflare.com/?to=/:account/:zone/dns/records) 페이지에서 서브도메인의 기존 주소 레코드(`A/AAAA`)를 `NS` 레코드로 바꿉니다. 주소 레코드가 하나뿐이라면 기존 레코드를 수정하고 새 `NS` 레코드를 하나 추가합니다. 주소 레코드가 여러 개라면 그중 두 개를 `NS` 레코드로 변경합니다.

   예를 들어 `www.example.com` 서브도메인을 위임하려면 부모 zone `example.com`의 업데이트된 레코드에는 다음과 같은 `NS` 레코드가 포함되어야 합니다.

   | **Type** | **Name** | **Content**            |
   | -------- | -------- | ---------------------- |
   | `NS`     | www      | john.ns.cloudflare.com |
   | `NS`     | www      | adam.ns.cloudflare.com |

   이 예시에서 `john.ns.cloudflare.com`과 `adam.ns.cloudflare.com`은 6단계에서 확인한 서브도메인 네임서버를 나타냅니다.

8. 공용 resolver([1.1.1.1](https://1.1.1.1/purge-cache/) 및 [8.8.8.8](https://developers.google.com/speed/public-dns/cache))에서 서브도메인의 주소 레코드를 플러시합니다.

9. 부모 zone의 [**DNS Records**](https://dash.cloudflare.com/?to=/:account/:zone/dns/records) 페이지에서 7단계에서 만든 `NS` 레코드를 제외하고, 위임된 서브도메인 아래에 남아 있는 모든 레코드를 [삭제](/dns/manage-dns-records/how-to/create-dns-records/#delete-dns-records)합니다.

   또한 위임된 서브도메인보다 더 깊은 모든 DNS 레코드도 삭제합니다. 예를 들어 `www.example.com`을 위임하는 경우 `api.www.example.com` 레코드는 새 자식 zone에만 존재해야 합니다.

10. 짧은 시간이 지나면 자식 zone이 활성 상태가 되어야 합니다.

11. (선택 사항) 자식 zone에서 [DNSSEC](/dns/zone-setups/subdomain-setup/dnssec/)를 활성화합니다.

[^1]: 즉, Cloudflare가 Authoritative DNS 제공자라는 의미입니다.
