부모 zone이 [CNAME setup (partial)](/dns/zone-setups/partial-setup/)[^2]을 사용하는 경우, 자식 zone을 설정하는 절차는 서브도메인이 이미 부모 도메인 안에 존재하는지에 따라 달라집니다.

## 서브도메인이 아직 존재하지 않는 경우

부모 zone에 아직 서브도메인을 포괄하는 DNS 레코드가 없다면:

<Tabs> <TabItem label="하위 zone이 full 또는 secondary">

1. 서브도메인을 새 zone으로 Cloudflare 계정에 추가합니다. 부모 zone이 있는 동일 계정일 수도 있고 다른 계정일 수도 있습니다.
2. [full](/dns/zone-setups/full-setup/setup/) 또는 [secondary](/dns/zone-setups/zone-transfers/cloudflare-as-secondary/setup/) setup에 맞게 구성을 완료합니다.
3. 자식 zone에 DNS 레코드를 생성한 후, 외부 DNS 제공자에서 Cloudflare 네임서버를 `NS` 레코드로 추가합니다.
4. 잠시 후 자식 zone이 활성 상태가 되어야 합니다.

</TabItem> <TabItem label="하위 zone이 partial">

1. 서브도메인을 새 zone으로 Cloudflare 계정에 추가합니다. 부모 zone이 있는 동일 계정일 수도 있고 다른 계정일 수도 있습니다.
2. zone 요금제로 Business 또는 Enterprise를 선택하고 필요에 맞게 온보딩 흐름을 완료합니다.
3. [Overview 페이지](https://dash.cloudflare.com/?to=/:account/:zone)에서 **Convert to CNAME DNS Setup**을 선택합니다.
4. 자식 zone에 필요한 [DNS 레코드](/dns/manage-dns-records/how-to/create-dns-records/)를 모두 생성했는지 확인합니다.
5. [**DNS Records**](https://dash.cloudflare.com/?to=/:account/:zone/dns/records) 페이지에서 **Verification TXT Record**를 확인하고 authoritative DNS 제공자에 추가합니다.


<Details header="검증 레코드 예시">

`sub.example.com`에 대한 검증 레코드는 다음과 같을 수 있습니다.

| Type | Name                                | Content             |
| ---- | ----------------------------------- | ------------------- |
| TXT  | `cloudflare-verify.sub.example.com` | 966215192-518620144 |

authoritative DNS 제공자가 도메인을 자동으로 DNS 레코드 `name` 필드에 덧붙이는 경우에는 레코드 이름에 `cloudflare-verify`만 입력해야 합니다. 그렇지 않으면 `cloudflare-verify.sub.example.com.sub.example.com`처럼 잘못된 레코드 이름이 생길 수 있습니다.

레코드를 만든 후에는 이 [Dig Web Interface 링크](https://digwebinterface.com/?type=TXT\&ns=auth\&nameservers=)를 사용해 `cloudflare-verify.<YOUR DOMAIN>`을 검색(`dig`)하여 정상 동작하는지 검증할 수 있습니다.


</Details>

이 레코드는 서브도메인이 Cloudflare에서 CNAME setup(partial)으로 활성 상태인 동안 계속 유지되어야 합니다.

6. 잠시 후 자식 zone이 활성 상태가 되어야 합니다.
7. authoritative DNS 제공자에서, 추가한 서브도메인과 Cloudflare를 통해 프록시하려는 더 깊은 서브도메인 레코드에 대해 `{your-hostname}.cdn.cloudflare.net`을 가리키는 `CNAME` 레코드를 추가합니다.


<Details header="authoritative DNS 제공자의 CNAME 레코드 예시">

`sub.example.com`의 `CNAME` 레코드는 다음과 같습니다.

```txt
sub.example.com CNAME sub.example.com.cdn.cloudflare.net
```


</Details>

</TabItem> </Tabs>

## 서브도메인이 이미 존재하는 경우

부모 zone에 이미 서브도메인을 포괄하는 DNS 레코드를 만든 상태라면:

<Tabs> <TabItem label="하위 zone이 full 또는 secondary">

1. 서브도메인을 새 zone으로 Cloudflare 계정에 추가합니다. 부모 zone이 있는 동일 계정일 수도 있고 다른 계정일 수도 있습니다.

2. [full](/dns/zone-setups/full-setup/setup/) 또는 [secondary](/dns/zone-setups/zone-transfers/cloudflare-as-secondary/setup/) setup에 맞게 구성을 완료합니다.

3. 자식 zone에서 서브도메인과 관련된 모든 DNS 레코드를 [다시 생성](/dns/manage-dns-records/how-to/create-dns-records/)합니다. 여기에는 위임된 서브도메인보다 더 깊은 모든 DNS 레코드도 포함됩니다. 즉 `www.example.com`을 위임한다면 `api.www.example.com`에 대한 레코드도 옮겨야 합니다.

   :::note
   자식 zone이 primary setup(full)에 있다면 부모 zone에서 레코드를 [내보낸](/dns/manage-dns-records/how-to/import-and-export/#export-records) 뒤 불필요한 항목을 삭제하고, 새 zone에 해당 레코드를 [가져오는](/dns/manage-dns-records/how-to/import-and-export/#import-records) 방법을 고려하세요.
   :::

4. 자식 zone에 필요할 수 있는 설정([WAF 사용자 지정 규칙](/waf/custom-rules/), [Rules](/rules/), [Workers](/workers/) 등)을 반드시 옮깁니다.

5. 자식 zone에서 자식 서브도메인과 그보다 더 깊은 모든 서브도메인을 포괄하는 [고급 SSL 인증서](/ssl/edge-certificates/advanced-certificate-manager/)를 주문합니다.

6. 서브도메인의 Cloudflare 네임서버를 확인하고, 외부 DNS 제공자에서 이를 `NS` 레코드로 추가합니다.

7. 잠시 후 자식 zone이 활성 상태가 되어야 합니다.

8. 부모 zone의 [**DNS Records**](https://dash.cloudflare.com/?to=/:account/:zone/dns/records) 페이지에서, 해당 서브도메인 또는 더 깊은 서브도메인을 참조하는 모든 `A`, `AAAA`, `CNAME` 레코드를 [삭제](/dns/manage-dns-records/how-to/create-dns-records/#delete-dns-records)합니다.

</TabItem> <TabItem label="하위 zone이 partial">

1. 서브도메인을 새 zone으로 Cloudflare 계정에 추가합니다. 부모 zone이 있는 동일 계정일 수도 있고 다른 계정일 수도 있습니다.

2. zone 요금제로 Business 또는 Enterprise를 선택하고 필요에 맞게 온보딩 흐름을 완료합니다.

3. [Overview 페이지](https://dash.cloudflare.com/?to=/:account/:zone)에서 **Convert to CNAME DNS Setup**을 선택합니다.

4. 자식 zone에서 서브도메인과 관련된 모든 DNS 레코드를 [다시 생성](/dns/manage-dns-records/how-to/create-dns-records/)합니다. 여기에는 zone을 만들 때 사용한 서브도메인보다 더 깊은 모든 DNS 레코드가 포함됩니다. 예를 들어 `www.example.com`용 zone을 만들었다면 `api.www.example.com`에 대한 레코드도 옮겨야 합니다.

   :::note
   Cloudflare는 부모 zone에서 레코드를 [내보낸](/dns/manage-dns-records/how-to/import-and-export/#export-records) 뒤 불필요한 항목을 삭제하고, 새 zone에 해당 레코드를 [가져오는](/dns/manage-dns-records/how-to/import-and-export/#import-records) 방법을 권장합니다.
   :::

5. 자식 zone에 필요할 수 있는 설정([WAF 사용자 지정 규칙](/waf/custom-rules/), [Rules](/rules/), [Workers](/workers/) 등)을 반드시 옮깁니다.

6. 자식 zone에서 자식 서브도메인과 그보다 더 깊은 모든 서브도메인을 포괄하는 [고급 SSL 인증서](/ssl/edge-certificates/advanced-certificate-manager/)를 주문합니다.

7. [**DNS Records**](https://dash.cloudflare.com/?to=/:account/:zone/dns/records) 페이지에서 **Verification TXT Record**를 확인하고 authoritative DNS 제공자에 추가합니다.
