처음에 Cloudflare에서 [부분 영역(CNAME 설정)](/dns/zone-setups/partial-setup/)으로 설정했다면, 나중에 [보조 설정](/dns/zone-setups/zone-transfers/cloudflare-as-secondary/)으로 전환할 수 있습니다.

<Render file="conversion-subdomain-setup-callout" product="dns" />

이 페이지는 [내보내기 및 가져오기](/dns/manage-dns-records/how-to/import-and-export/)와 API 호출을 사용해 이 전환을 수행하는 방법을 안내합니다.

## 시작하기 전에

다음 사항을 고려했는지 확인하세요.

- 보조 영역에서 트래픽을 프록시하려면 기본적으로 활성화되어 있지 않은 설정이 필요합니다. 자세한 내용은 [Secondary DNS override](/dns/zone-setups/zone-transfers/cloudflare-as-secondary/proxy-traffic/)를 참고하세요. 아래 단계에는 이 설정을 활성화하는 과정이 포함되어 있습니다.
- [인바운드 영역 전송에서의 DNSSEC](/dns/zone-setups/zone-transfers/cloudflare-as-secondary/dnssec-for-secondary/)에는 여러 옵션이 있습니다. DNSSEC를 사용할 계획이라면 어떤 옵션으로 구성할지 미리 정하고, 다른 DNS 공급자들이 해당 구성을 지원하는지도 확인하세요.
- [고급 인증서](/ssl/edge-certificates/advanced-certificate-manager/manage-certificates/)를 주문하거나 [사용자 지정 인증서](/ssl/edge-certificates/custom-certificates/uploading/)를 업로드해 SSL/TLS를 미리 준비할 수 있습니다. 모든 프록시 호스트명을 인증서가 포괄하는지, 그리고 [SSL 인증서 상태](https://dash.cloudflare.com/?to=/:account/:zone/ssl-tls/edge-certificates)가 **Active**인지 확인해야 합니다.

## 1. 영역 파일 준비

1. CNAME 설정(부분)과 함께 사용하던 authoritative DNS 공급자에서 영역 파일을 내보냅니다.
2. 영역 파일을 편집하여 `cdn.cloudflare.net` 접미사가 포함된 항목을 모두 제거합니다.

- `CNAME` 대상이 레코드가 생성된 동일한 호스트명에 Cloudflare 접미사만 붙이는 형태라면, 이를 Cloudflare 부분 영역의 레코드로 대체합니다.

<Details header="예시">

authoritative DNS 공급자의 원본 레코드:

| Type    | Name              | Content                              |
| ------- | ----------------- | ------------------------------------ |
| `CNAME` | `www.example.com` | `www.example.com.cdn.cloudflare.net` |

Cloudflare 부분 영역의 레코드:

| Type | Name              | Content  |
| ---- | ----------------- | -------- |
| `A`  | `www.example.com` | `<IPv4>` |
| `A`  | `www.example.com` | `<IPv4>` |

영역 파일에서 최종적으로 조정된 레코드:

| Type | Name              | Content  |
| ---- | ----------------- | -------- |
| `A`  | `www.example.com` | `<IPv4>` |
| `A`  | `www.example.com` | `<IPv4>` |

</Details>

- `CNAME` 레코드가 다른 호스트명을 가리킨다면, 이 레코드는 유지하되 `cdn.cloudflare.net` 접미사만 제거하고, Cloudflare 부분 영역의 레코드도 함께 가져옵니다.

<Details header="예시">

authoritative DNS 공급자의 원본 레코드:

| Type    | Name              | Content                                         |
| ------- | ----------------- | ----------------------------------------------- |
| `CNAME` | `www.example.com` | `other-hostname.example.com.cdn.cloudflare.net` |

Cloudflare 부분 영역(CNAME 설정)의 레코드:

| Type | Name                         | Content  |
| ---- | ---------------------------- | -------- |
| `A`  | `other-hostname.example.com` | `<IPv4>` |
| `A`  | `other-hostname.example.com` | `<IPv4>` |

영역 파일에서 최종적으로 조정된 레코드:

| Type    | Name                         | Content                      |
| ------- | ---------------------------- | ---------------------------- |
| `CNAME` | `www.example.com`            | `other-hostname.example.com` |
| `A`     | `other-hostname.example.com` | `<IPv4>`                     |
| `A`     | `other-hostname.example.com` | `<IPv4>`                     |

</Details>

## 2. Cloudflare 영역 구성

1. [Import DNS Records 엔드포인트](/api/resources/dns/subresources/records/methods/import/)를 사용해 적절히 [형식이 맞춰진 영역 파일](/dns/manage-dns-records/how-to/import-and-export/#format-your-zone-file)을 부분 영역으로 가져옵니다.

   <Render file="zone-file-size-limit" product="dns" /> 기존에 이미 프록시된 레코드는 가져오기 작업으로 덮어쓰지 않습니다.

2. [Update DNS Settings 엔드포인트](/api/resources/dns/subresources/settings/subresources/zone/methods/edit/)에서 `secondary_overrides`를 `true`로 설정해 Secondary DNS Override를 활성화합니다.

:::caution

이 단계는 전환 후에도 Cloudflare가 레코드의 프록시 상태를 유지하기 위해 꼭 필요합니다.
:::

3. [Edit Zone 엔드포인트](/api/resources/zones/methods/edit/)에서 `type`을 `secondary`로 설정해 영역 유형을 전환합니다.

   전환이 정상적으로 되었는지는 새로 할당된 보조 네임서버에 질의해 확인할 수 있습니다. 네임서버는 [**DNS Records**](https://dash.cloudflare.com/?to=/:account/:zone/dns/records) 페이지에서 확인할 수 있으며 `ns0123.secondary.cloudflare.com`과 같은 형식입니다.

```bash
# ns0123 부분을 실제 Cloudflare 네임서버로 바꾸세요
dig example.com @ns0123.secondary.cloudflare.com
```

4. 등록기관에서 [네임서버를 업데이트](/dns/nameservers/update-nameservers/)하여 Cloudflare 네임서버를 가리키도록 합니다.

이전 `NS` 레코드의 TTL이 만료되고 해당 정보가 리졸버 캐시에서 제거되면, 영역은 Cloudflare에 정상적으로 위임됩니다. DNS 레코드를 계속 업데이트하려면 다음 단계에서 [영역 전송](/dns/zone-setups/zone-transfers/)을 구성해야 합니다.

## 3. 영역 전송 구성

1. 기본 DNS 공급자에서 `cdn.cloudflare.net`에 대한 모든 참조를 제거합니다. 이를 위해 [1단계](#1-영역-파일-준비)에서 준비한 동일한 영역 파일을 기본 영역에 가져올 수 있습니다.

:::caution

`cdn.cloudflare.net`을 계속 참조하는 DNS 레코드가 남아 있으면, 해당 호스트명에 대한 HTTP 트래픽이 끊어집니다.
:::

2. 기본 공급자에서 아웃바운드 영역 전송을 활성화하고 Cloudflare 계정에 피어 DNS 서버를 생성합니다.

<Render file="create-peer-server" product="dns" />

3. Cloudflare 영역을 방금 만든 피어 DNS 서버에 연결합니다.

<Tabs syncKey="dashPlusAPI"> <TabItem label="대시보드">

1. Cloudflare 대시보드에서 **DNS Settings** 페이지로 이동합니다.

   <DashButton url="/?to=/:account/:zone/dns/settings" />

2. **DNS Zone Transfers** 아래에서 **Manage linked peers**를 선택합니다.
3. **Zone refresh** 값을 선택합니다. 이 값은 기본 DNS 서버에서 영역 업데이트를 확인하는 주기를 초 단위로 제어합니다.
   :::caution
   Cloudflare는 기본 공급자가 제공하는 SOA 레코드의 REFRESH 값을 사용하지 않습니다. 대신 Cloudflare의 보조 영역에서 설정한 zone refresh 값으로 기본 영역의 SOA serial을 얼마나 자주 확인할지 결정합니다.
   :::
4. 앞에서 만든 피어 서버를 선택합니다. 필요한 경우 하나의 영역에 여러 피어 서버를 연결할 수 있습니다.
5. 확인을 위해 **Save**를 선택합니다.

</TabItem> <TabItem label="API">

[Update Secondary Zone Configuration 엔드포인트](/api/resources/dns/subresources/zone_transfers/subresources/peers/methods/update/)를 사용해 Cloudflare 영역을 피어 DNS 서버에 연결합니다.

</TabItem> </Tabs>

4. [**DNS Settings**](https://dash.cloudflare.com/?to=/:account/:zone/dns/settings) 페이지에서 연결된 피어가 **DNS Zone Transfers** 아래에 표시되는지 확인하고 **Initiate zone transfer**를 선택합니다. 또는 [Force AXFR 엔드포인트](/api/resources/dns/subresources/zone_transfers/subresources/force_axfr/methods/create/)를 사용할 수 있습니다.
