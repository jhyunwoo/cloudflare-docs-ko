Cloudflare DNS는 다양한 [설정 방식](/dns/zone-setups/)으로 사용할 수 있습니다. 이러한 설정이 무엇인지 개괄적으로 이해하고 특정 DNS 용어를 소개받으려면 [Concepts](/dns/concepts/)를 참고하세요.

가장 일반적인 설정(full)에서는 [도메인을 추가](/fundamentals/manage-domains/add-site/)하고, [DNS 레코드를 가져온 다음](/dns/manage-dns-records/), [네임서버를 업데이트](/dns/nameservers/update-nameservers/)하여 Cloudflare를 기본 권한 DNS 제공업체로 만듭니다.

:::note
[네임서버를 업데이트](/dns/nameservers/update-nameservers/)하기 전에 반드시 [DNS 레코드를 검토](/dns/zone-setups/full-setup/setup/#review-dns-records)하세요. 올바른 DNS 레코드를 설정하지 않은 채 도메인을 Cloudflare에서 활성화하면 도메인에 접속할 수 없을 수 있습니다.
:::

설정을 완료하면 다음이 가능합니다.

- Cloudflare 대시보드 또는 API를 통해 [DNS 레코드를 관리](/dns/manage-dns-records/how-to/create-dns-records/)합니다. 이를 통해 웹사이트의 apex 도메인(`example.com`)이나 특정 서브도메인(`blog.example.com`)에서 어떤 리소스를 제공할지 제어하고, 다른 구성도 제어할 수 있습니다.

- Cloudflare는 여러분의 호스트 이름에 대한 [모든 DNS 쿼리에 응답](/fundamentals/concepts/how-cloudflare-works/)하며, DNS 레코드는 [Cloudflare 글로벌 네트워크](https://www.cloudflare.com/network/) 전반에 전파되어 도메인을 더 빠르게 만듭니다.

## 리소스

다음 링크는 중요한 개념을 소개하며, 웹사이트나 애플리케이션을 Cloudflare에 올려두는 동안 필요할 수 있는 작업을 안내합니다.

- [DNS records](/dns/manage-dns-records/): DNS 레코드는 도메인에 대한 정보를 담고 있으며, 웹사이트나 애플리케이션을 방문자 및 다른 웹 서비스에 노출하는 데 사용됩니다.

- [Nameservers](/dns/nameservers/): Cloudflare DNS 맥락에서 네임서버는 권한 네임서버를 뜻합니다. 어떤 네임서버가 `example.com`에 대해 권한을 가진다는 것은, 사용자가 `example.com`에 접속하려 할 때 DNS 리졸버가 이 네임서버의 응답을 신뢰한다는 의미입니다.

- [Proxy status](/dns/proxy-status/): 프록시 상태는 A, AAAA, CNAME 레코드에 대해 들어오는 HTTP/S 요청을 Cloudflare가 어떻게 처리할지에 영향을 줍니다. 레코드가 프록시되면 Cloudflare는 [애니캐스트 IP](/fundamentals/concepts/cloudflare-ip-addresses/)로 응답하고, 이를 통해 [cache](/cache/)/[CDN](https://www.cloudflare.com/learning/cdn/what-is-a-cdn/), [DDoS protection](/ddos-protection/), [WAF](/waf/), 그리고 [그 밖의 기능](/directory/?product-group=Application+performance%2CApplication+security)으로 HTTP/S 트래픽을 가속하고 보호합니다.
