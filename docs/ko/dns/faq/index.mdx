## Cloudflare 제공 항목

### Cloudflare는 무료 DNS(도메인 네임서버) 제공업체인가요?

예. Cloudflare는 모든 요금제의 고객에게 [무료 DNS 서비스](https://www.cloudflare.com/dns)를 제공합니다. 다음 사항을 참고하세요.

- Cloudflare를 사용하기 위해 호스팅 제공업체를 바꿀 필요는 없습니다.
- 등록기관을 옮길 필요도 없습니다. 등록기관에서 해야 하는 유일한 변경은 권한 네임서버를 Cloudflare 네임서버로 가리키게 하는 것입니다.

### Cloudflare는 DNS 쿼리에 대해 비용을 청구하거나 제한하나요?

Cloudflare는 DNS 쿼리를 제한하거나 상한을 두지 않지만, 가격은 요금제 수준에 따라 달라집니다.

Free, Pro, Business 요금제 고객에게는 DNS 쿼리에 대해 비용을 청구하지 않습니다. Enterprise 요금제 고객의 경우, Cloudflare는 월간 DNS 쿼리 수를 가격 산정 입력값으로 사용하여 맞춤 견적을 생성합니다.

### Cloudflare는 도메인 마스킹을 제공하나요?

아니요. Cloudflare는 도메인 마스킹이나 DNS 리디렉션 서비스를 제공하지 않습니다(호스팅 제공업체는 제공할 수 있습니다). 대신 [Bulk Redirects](/rules/url-forwarding/bulk-redirects/)를 통한 URL 전달 기능을 제공합니다.

### 서브도메인을 Cloudflare에 직접 추가할 수 있나요?

예. Enterprise 고객은 [subdomain support](/dns/zone-setups/subdomain-setup/)를 통해 서브도메인을 Cloudflare에 직접 추가할 수 있습니다.

### Cloudflare는 EDNS0(extension mechanisms for DNS)를 지원하나요?

예. EDNS0는 최신 DNS 구현의 핵심 구성 요소이며 Cloudflare 모든 고객에게 활성화되어 있습니다. EDNS0는 DNS Resolver(재귀 DNS 제공업체)가 더 큰 메시지 크기와 DNSSEC를 지원하는지 신호로 알릴 수 있게 해줍니다.

EDNS0는 [DNS 확장](http://en.wikipedia.org/wiki/Extension_mechanisms_for_DNS)을 위한 최초의 승인된 메커니즘 집합이며, 원래 [RFC 2671](https://www.rfc-editor.org/rfc/rfc2671.html)로 발표되었습니다.

## 네임서버

### Cloudflare 네임서버는 어디에서 찾을 수 있나요?

**DNS Records** 페이지에서 **Cloudflare Nameservers** 카드를 찾으세요.

<DashButton url="/?to=/:account/:zone/dns/records" />

또한 특정 Cloudflare 네임서버와 연결된 IP 주소는 dig 명령이나 [whatsmydns.net](https://www.whatsmydns.net/) 같은 온라인 타사 DNS 조회 도구를 통해 확인할 수 있습니다.

```sh
dig kate.ns.cloudflare.com
```

```sh output
kate.ns.cloudflare.com.    68675    IN    A    173.245.58.124.
```

### Cloudflare를 가리키도록 네임서버는 어디에서 변경하나요?

도메인을 등록한 등록기관에서 변경합니다. 등록기관은 호스팅 제공업체와 같을 수도 있고 다를 수도 있습니다. 자세한 맥락은 [Update nameservers](/dns/nameservers/update-nameservers/)를 참고하세요.

도메인의 등록기관이 어디인지 모른다면 WHOIS 검색이 도움이 됩니다. 예를 들어 [ICANN Lookup](https://lookup.icann.org/)을 사용할 수 있습니다.

:::caution

일부 국가 코드 TLD는 ICANN Lookup에서 지원되지 않을 수 있습니다. 이런 경우에는 다른 WHOIS 검색 도구를 사용하세요.
:::

### 왜 `(mydomain) stopped using Cloudflare's nameservers`라는 이메일을 받았나요?

Cloudflare가 DNS를 호스팅하는 도메인에 대해, Cloudflare는 해당 도메인이 DNS 해석에 Cloudflare 네임서버를 사용하는지 계속 확인합니다. Cloudflare 네임서버가 사용되지 않으면 [domain status](/dns/zone-setups/reference/domain-status/)가 **Active**에서 **Moved**로 바뀌고 고객에게 이메일이 전송됩니다.

이것이 중요한 이유는 도메인이 [충분히 오랜 기간](/dns/zone-setups/reference/domain-status/) **Moved** 상태에 있으면 Cloudflare에서 삭제되기 때문입니다.

## DNS 레코드

### Cloudflare는 도메인이 가질 수 있는 DNS 레코드 수를 제한하나요?

예. 모든 고객은 만들 수 있는 DNS 레코드 수에 제한이 있습니다.

- Free: 200
- Pro: 3,500
- Business: 3,500
- Enterprise: 3,500

2024-09-01 00:00:00 UTC 이전에 생성된 Free Zone은 제한이 1,000으로 늘어납니다.

:::note[더 많은 DNS 레코드가 필요한 경우]
Enterprise 고객이고 더 많은 DNS 레코드가 필요하다면 계정 팀에 문의하세요. Cloudflare는 하나의 Zone에서 수백만 개의 DNS 레코드를 지원할 수 있습니다.
:::

### 제가 만든 DNS 변경 사항이 전파되기까지 얼마나 걸리나요?

기본적으로 Cloudflare Zone 파일에 가한 모든 변경이나 추가는 전 세계에 5분 이내, 보통은 훨씬 더 빠르게 반영됩니다.

이전에 설정된 [DNS 레코드](/dns/manage-dns-records/how-to/create-dns-records/)의 TTL(Time-to-Live)에 따라, 이전 데이터가 TTL이 만료될 때까지 캐시에 남아 있을 수 있습니다. 프록시된 레코드는 5분("Automatic") 후 만료되지만, 프록시되지 않은 레코드의 TTL은 사용자 지정할 수 있습니다.

TTL이 큰 레코드에 대한 변경이 예상된다면, 변경이 가능한 한 빨리 적용되도록 미리 TTL을 줄이는 것이 합리적일 수 있습니다.

### 왜 Cloudflare DNS 서버에 `ANY` 쿼리를 할 수 없나요?

`ANY` 쿼리는 특별하며 자주 오해됩니다. 보통 DNS 이름에 존재하는 모든 레코드 유형을 얻기 위해 사용되지만, 실제로 반환되는 것은 재귀 리졸버의 캐시에 있는 임의의 유형일 뿐입니다. 이 때문에 디버깅에 사용할 때 혼란이 생길 수 있습니다.

CNAME flattening과 같은 Cloudflare의 많은 고급 DNS 기능 때문에 `ANY` 쿼리에 올바른 답변을 제공하는 것은 복잡하며 때로는 불가능하기도 합니다. 예를 들어 DNS 레코드가 동적으로 생겼다 사라지거나 원격에 저장되어 있으면 모든 결과를 동시에 가져오는 것이 부담스럽거나 불가능할 수 있습니다.

자세한 내용은 [Deprecating the DNS ANY meta-query type](https://blog.cloudflare.com/deprecating-dns-any-meta-query-type/)을 참고하세요. `ANY` 차단 결정은 DNS Firewall 고객에게는 영향을 주지 않습니다.

### 내 도메인의 DNS 응답에 Cloudflare의 A 또는 AAAA 레코드 / IP 주소가 나타나는 이유는 무엇인가요?

Cloudflare를 통해 프록시되는 DNS 레코드의 경우, DNS 쿼리에는 원래 서버 IP 주소 대신 Cloudflare의 IP 주소가 반환됩니다. 이를 통해 Cloudflare는 웹사이트에 대한 모든 요청을 최적화하고 캐시하며 보호할 수 있습니다.
