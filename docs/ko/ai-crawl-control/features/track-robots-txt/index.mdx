AI Crawl Control의 **Robots.txt** 탭은 여러 호스트 이름에 걸쳐 AI 크롤러가 <GlossaryTooltip term="robots.txt">`robots.txt`</GlossaryTooltip> 파일과 어떻게 상호작용하는지에 대한 인사이트를 제공합니다. 요청 패턴을 모니터링하고, 파일 가용성을 확인하며, 지시 사항을 위반하는 크롤러를 식별할 수 있습니다.

robots.txt 인사이트에 접근하려면 다음 단계를 따르세요.

1. [Cloudflare 대시보드](https://dash.cloudflare.com/)에 로그인한 다음 계정과 도메인을 선택합니다.
2. **AI Crawl Control**로 이동합니다.

   <DashButton url="/?to=/:account/:zone/ai" />

3. **Robots.txt** 탭으로 이동합니다.

## Managed robots.txt 상태 확인

탭 상단의 상태 카드는 Cloudflare가 `robots.txt` 파일을 관리하고 있는지 보여줍니다.

활성화되면 Cloudflare는 학습에 사용되는 일반적인 AI 크롤러를 차단하는 지시 사항을 포함하고, `robots.txt`에 [Content Signals Policy](/bots/additional-configurations/managed-robots-txt/#content-signals-policy)를 포함합니다. Cloudflare가 `robots.txt` 파일을 관리하는 방식에 대한 자세한 내용은 [Managed `robots.txt`](/bots/additional-configurations/managed-robots-txt/)를 참고하세요.

## robots.txt 요청 데이터 필터링

탭 상단에서 필터를 적용하여 robots.txt 요청 분석 범위를 좁힐 수 있습니다.

- 특정 크롤러 이름(예: Googlebot 또는 특정 AI 봇)으로 필터링합니다.
- 크롤러를 운영하는 주체별로 필터링하여 직접적인 라이선스 기회 또는 기존 계약을 이해합니다.
- 일반적인 사용 사례(예: AI 학습, 일반 검색, AI assistant)별로 필터링합니다.
- 과거 분석을 위한 사용자 지정 기간을 선택합니다.

모든 표와 메트릭의 값은 필터에 따라 업데이트됩니다.

## robots.txt 가용성 모니터링

**Availability** 표는 선택한 기간 동안 호스트 이름별 `robots.txt` 파일의 과거 요청 빈도와 상태를 보여줍니다.

| 열 | 설명 |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Path | 요청된 특정 호스트 이름의 `robots.txt` 파일입니다. 경로는 요청이 많은 순서부터 적은 순서로 나열됩니다. |
| Requests | 이 경로에 대해 발생한 총 요청 수입니다. 요청은 다음과 같이 구분됩니다.<br/>- **Successful:** 400 미만의 HTTP 상태 코드(**200 OK** 및 리디렉션 포함)<br/>- **Unsuccessful:** 400 이상의 HTTP 상태 코드 |
| Status | `robots.txt` 파일을 핑한 결과의 HTTP 상태 코드입니다. |
| Content Signals | `robots.txt` 파일에 AI 학습, 검색 또는 AI 입력에서의 사용을 위한 지시 사항인 [Content Signals](https://contentsignals.org/)가 포함되어 있는지 보여주는 표시기입니다. |

이 표에서 다음과 같은 조치를 취할 수 있습니다.

- 실패한 요청 수가 많은지 모니터링합니다. 이는 크롤러가 `robots.txt` 파일에 접근하는 데 어려움을 겪고 있음을 시사합니다.
  - **Status**가 `404 Not Found`이면 명확한 지시 사항을 제공하기 위해 `robots.txt` 파일을 생성합니다.
  - 파일이 존재한다면, 접근을 차단하고 있을 수 있는 상위 WAF 규칙이나 다른 보안 설정을 확인합니다.
- **Content Signals** 열이 신호가 누락되었음을 나타내면 이를 `robots.txt` 파일에 추가합니다. [Content Signals](https://contentsignals.org/) 지침을 따르거나 [Managed `robots.txt`](/bots/additional-configurations/managed-robots-txt/)를 활성화하여 Cloudflare가 이를 대신 관리하도록 할 수 있습니다.

## robots.txt 위반 추적

**Violations** 표는 `robots.txt` 파일에서 명시적으로 허용되지 않은 경로를 요청한 AI 크롤러를 식별합니다. 이를 통해 규정을 준수하지 않는 크롤러를 식별하고 적절한 조치를 취할 수 있습니다.

:::note[위반 계산 방식]

Violations 표는 **현재** `robots.txt` 지시 사항과 과거 크롤러 요청 간의 불일치를 식별합니다. 위반은 실시간으로 기록되지 않으므로, 최근에 추가하거나 변경한 규칙 때문에 과거에는 정상적이었던 요청이 위반으로 표시될 수 있습니다.

예를 들어 새 `Disallow` 규칙을 추가하면, 해당 경로에 대한 모든 과거 요청이 요청 당시에는 위반이 아니었더라도 위반으로 표시됩니다.
:::

| 열 | 설명 |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Crawler | `robots.txt` 지시 사항을 위반한 봇의 이름입니다. 크롤러 운영자는 크롤러 이름 바로 아래에 표시됩니다. |
| Path | 크롤러가 접근을 시도한 특정 URL 또는 경로로, `robots.txt` 파일에서 허용되지 않은 항목입니다. |
| Directive | 해당 경로에 대한 접근을 금지한 `robots.txt` 파일의 정확한 줄입니다. |
| Violations | 선택한 기간 동안 허용되지 않은 경로/지시 사항 쌍에 대해 발생한 HTTP 요청 수입니다. |

`robots.txt` 지시 사항을 위반하는 크롤러를 식별하면 몇 가지 선택지가 있습니다.

- [**Crawlers** 탭](/ai-crawl-control/features/manage-ai-crawlers/)으로 이동하여 규정을 준수하지 않는 크롤러를 영구적으로 차단합니다.
- [Cloudflare WAF](/waf/)를 사용해 위반 크롤러에 대한 경로별 보안 규칙을 생성합니다.
- [Redirect Rules](/rules/url-forwarding/)를 사용해 위반 크롤러를 사이트의 적절한 영역으로 유도합니다.
