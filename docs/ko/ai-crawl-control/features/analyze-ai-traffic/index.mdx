AI Crawl Control 메트릭은 AI 크롤러가 웹사이트([Cloudflare 영역](/fundamentals/concepts/accounts-and-zones/#zones))와 어떻게 상호작용하는지에 대한 인사이트를 제공합니다.

AI Crawl Control 메트릭을 보려면 다음 단계를 따르세요.

1. [Cloudflare 대시보드](https://dash.cloudflare.com/)에 로그인한 다음 계정과 도메인을 선택합니다.
2. **AI Crawl Control**로 이동합니다.

   <DashButton url="/?to=/:account/:zone/ai" />

의미 있는 정보는 **Overview**, **Crawlers**, **Metrics** 탭 전반에서 확인할 수 있습니다.

## Overview 탭 보기

**Overview** 탭은 AI 크롤러 활동의 스냅샷을 제공합니다.

| 구성 요소 | 할 수 있는 일 |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **요약 정보** | 총 요청량, 요청량 변화, 가장 일반적인 상태 코드, 가장 인기 있는 경로, 대량 트래픽 크롤러 활동을 검토합니다. |
| **Managed robots.txt 상태** | 영역에서 [Cloudflare managed robots.txt](/bots/additional-configurations/managed-robots-txt/)가 활성화되어 있는지 확인합니다. |
| **추세 차트가 포함된 메트릭** | 총 요청, 허용된 요청, 실패한 요청, 총 리퍼럴(유료 요금제만)을 모니터링합니다. |
| **운영자별로 그룹화된 크롤러** | 허용된 요청, 리퍼럴(유료 요금제만), 활동 변화율을 기준으로 회사(OpenAI, Microsoft, Google, ByteDance, Anthropic, Meta)별로 정리된 크롤러를 탐색합니다. 크롤러나 운영자를 선택하면 **Crawlers** 탭에서 상세히 볼 수 있습니다. |
| **필터** | 날짜 범위, 크롤러, 운영자, 호스트 이름, 경로로 보기를 사용자 지정합니다. 모든 메트릭은 동적으로 업데이트됩니다. |

## Crawlers 탭 보기

**Crawlers** 탭은 개별 AI 크롤러에 대한 세부 정보를 제공하며 **Block** 또는 **Allow** 제어를 설정할 수 있게 합니다.

| 열 | 설명 |
| ----------------- | -------------------------------------------------------------------------------- |
| **크롤러** | AI 크롤러의 이름입니다. |
| **운영자** | 해당 크롤러를 운영하는 회사입니다. |
| **데이터 전송량** | 이 크롤러 요청이 소비한 총 대역폭입니다. KB, MB 또는 GB 형식으로 표시됩니다. |
| **요청 수** | 이 크롤러에서 발생한 총 요청 수입니다. |
| **작업** | 현재 접근 제어 설정(Allow 또는 Block)입니다. |

크롤러 접근 관리에 대한 자세한 내용은 [AI 크롤러 관리](/ai-crawl-control/features/manage-ai-crawlers/)를 참고하세요.

## Metrics 탭 보기

**Metrics** 탭은 AI 크롤러가 웹사이트와 어떻게 상호작용하는지 이해하는 데 도움이 되는 세부 분석과 차트를 제공합니다.

### 시간 경과에 따른 요청

선택한 기간 동안의 크롤러 활동 패턴을 시각화합니다. 보기 선택기를 사용해 메트릭 간 전환이 가능합니다.

| 보기 | 설명 |
| -------------------- | --------------------------------------------------------------------------------- |
| **전체 요청** | 차단된 응답과 오류 응답을 포함한 총 요청입니다. |
| **허용된 요청** | 성공적인 응답(status 200-299)을 받은 요청입니다. |
| **데이터 전송량** | 시간 경과에 따른 허용 요청의 대역폭 사용량으로, KB, MB 또는 GB 형식으로 표시됩니다. |

데이터는 다음과 같은 다양한 차원으로 그룹화할 수 있습니다.

| 차원 | 설명 |
| ------------ | ---------------------------------------------------------------------------------------- |
| **Crawler** | 개별 AI 크롤러(예: GPTBot, ClaudeBot, Bytespider)의 활동을 추적합니다. |
| **Category** | 목적 또는 유형별로 크롤러를 분석합니다. |
| **Operator** | 어떤 회사(OpenAI, Anthropic, ByteDance 등)가 사이트를 크롤링하는지 파악합니다. |
| **Host** | 여러 하위 도메인 전반의 활동을 세분화합니다. |

:::note
데이터 전송량 보기는 `edgeResponseBytes`를 표시합니다. 일부 크롤러는 요청하는 콘텐츠에 따라 다른 크롤러보다 요청당 데이터 전송량이 더 높게 보일 수 있습니다.
:::

### 상태 코드 분포

**Status code distribution** 차트는 시간 경과에 따른 AI 크롤러 요청의 HTTP 응답 코드를 보여줍니다.

- **2xx** — 성공한 응답
- **3xx** — 리디렉션
- **4xx** — 클라이언트 오류(403 차단 및 402 결제 필요 포함)
- **5xx** — 서버 오류

이 차트를 사용하면 오류 코드 분포와 리디렉션 양을 포함해 사이트가 AI 크롤러에 어떻게 응답하는지의 패턴을 파악할 수 있습니다.

### 상위 리퍼러

:::note
이 기능은 유료 요금제 고객에게 제공됩니다.
:::

리퍼러 분석으로 트래픽 소스를 식별해 AI 운영자의 발견 패턴과 콘텐츠 인기도를 이해합니다.

| 보기 | 설명 |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------- |
| **Referral sources** | 사이트로 AI 기반 리퍼럴 트래픽을 보내는 상위 도메인(예: `chatgpt.com`, `perplexity.ai`)입니다. |
| **Destination patterns** | AI 기반 리퍼럴 트래픽을 가장 많이 받는 사이트 영역을 패턴별로 그룹화해 보여줍니다(예: `/blog/*`, `/api/*`). |

상위 리퍼러 섹션의 탭을 사용해 보기 간 전환할 수 있습니다.

### 시간 경과에 따른 리퍼럴

선택한 기간 동안의 리퍼럴 트래픽 추세를 추적합니다. 다음 기준으로 그룹화할 수 있습니다.

| 차원 | 설명 |
| ------------ | -------------------------------------------------------------------------- |
| **Operator** | 회사(OpenAI, Anthropic 등)별 리퍼럴을 표시하는 누적 영역 차트입니다. |
| **Source** | 트래픽을 유도하는 상위 리퍼럴 URL입니다. |
| **Total** | 집계된 전체 리퍼럴 양입니다. |

### 가장 인기 있는 경로

**Most popular paths** 표는 사이트에서 AI 크롤러가 가장 자주 요청하는 페이지를 보여줍니다.

| 열 | 설명 |
| -------------------- | --------------------------------------------------------- |
| **경로** | 요청된 페이지 경로입니다. |
| **호스트 이름** | 요청된 페이지의 호스트 이름입니다. |
| **리퍼럴** | AI 플랫폼에서 이 경로로 유입된 리퍼럴 방문 수입니다. |
| **허용된 요청** | 이 경로에 대한 성공한 요청 수입니다. |

경로별 크롤러 세부 내역을 보려면 상위 레벨 필터를 사용하세요.

#### 패턴 그룹화로 사이트 영역 분석

**Patterns** 탭을 선택하면 요청이 URI 패턴(예: `/blog/*`, `/api/v1/*`, `/docs/*`)별로 그룹화되어 표시됩니다. 이를 통해 AI 크롤러가 사이트의 어떤 영역을 가장 많이 대상으로 삼는지 빠르게 파악할 수 있습니다.

패턴 그룹화는 개별 경로를 사이트 영역으로 집계합니다.

- 패턴은 최대 2단계 깊이까지 포함합니다(예: `/api/*`, `/api/v1/*`).
- 루트 패턴 `/*`는 사이트 전체의 총 트래픽을 보여줍니다.
- 패턴은 호스트 이름 간에 집계되지 않습니다.
- 단일 경로 패턴은 와일드카드 없이 표시됩니다(예: `sitemap.xml/*`가 아니라 `sitemap.xml`).

추가 탭은 다음과 같습니다.

- **All** — 콘텐츠와 미디어 요청을 합쳐서 표시합니다(패턴이 아닌 개별 경로).
- **Content** — HTML, JSON 및 텍스트 콘텐츠입니다.
- **Media** — 이미지, 동영상 및 기타 미디어 파일입니다.

## 데이터 필터링 및 내보내기

필터 바를 사용해 여러 기준으로 분석 범위를 좁힐 수 있습니다.

| 필터 | 설명 |
| -------------- | ----------------------------------------- |
| **Date range** | 분석할 기간을 선택합니다. |
| **Crawler** | 특정 AI 크롤러로 필터링합니다. |
| **Operator** | 특정 회사로 필터링합니다. |
| **Hostname** | 특정 하위 도메인으로 필터링합니다. |
| **Path** | 특정 URL 경로 또는 패턴으로 필터링합니다. |

복잡한 분석을 위해 여러 필터를 조합할 수 있습니다. 모든 메트릭과 차트는 필터 선택에 따라 동적으로 업데이트됩니다.

데이터를 내보내려면 **Download CSV** 또는 **Download image**를 선택합니다. 다운로드에는 적용된 모든 필터와 그룹화가 포함됩니다.

## 크롤러별 드릴다운

**Crawlers** 탭에는 각 크롤러에 대한 작업 메뉴가 있으며 다음 옵션이 제공됩니다.

| 작업 | 설명 |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------- |
| **메트릭 보기** | **Metrics** 탭을 선택한 크롤러로 필터링합니다. |
| **Cloudflare Radar에서 보기** | Cloudflare Radar에서 각 검증된 크롤러에 대한 추가 정보를 확인합니다. |
| **Security Analytics에서 보기** | 탐지 ID 기준으로 Security Analytics를 필터링합니다([Bot Management](/bots/get-started/bot-management/) 고객). |
| **사용자 에이전트 복사** | [WAF 사용자 지정 규칙](/waf/custom-rules/), [Redirect Rules](/rules/url-forwarding/), 또는 robots.txt 파일에서 사용하기 위해 사용자 에이전트 문자열을 복사합니다. |
| **탐지 ID 복사** | [WAF 사용자 지정 규칙](/waf/custom-rules/)에서 사용하기 위해 탐지 ID를 복사합니다([Bot Management](/bots/get-started/bot-management/) 고객). |

## 프로그래밍 방식 접근

AI Crawl Control 분석에 프로그래밍 방식으로 접근하려면 [GraphQL Analytics API](/ai-crawl-control/reference/graphql-api/)를 사용하세요. 이 API는 탐지 ID, 리퍼러 데이터, 데이터 전송 메트릭을 포함해 대시보드에서 사용할 수 있는 동일한 데이터에 접근할 수 있게 해 줍니다.
