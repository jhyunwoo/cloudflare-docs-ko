모든 호스트 이름에 대해 상호 전송 계층 보안(mTLS)을 활성화할 수 있습니다. 자세한 내용은 [클라이언트 인증서 개요](/ssl/client-certificates/)를 참고하세요.

Cloudflare 대시보드에서 호스트에 대해 mTLS를 활성화하려면:

1. Cloudflare 대시보드에서 **Client Certificates** 페이지로 이동합니다.

   <DashButton url="/?to=/:account/:zone/ssl-tls/client-certificates" />

2. **Client Certificates** 카드의 **Hosts** 섹션에서 **Edit**를 선택합니다.
3. 현재 도메인 내 호스트 이름을 입력합니다.
:::note
도메인(`example.com`)은 자동으로 덧붙여집니다. 즉, `abc.example.com`에 대해 mTLS를 활성화하려면 `abc`만 입력하면 됩니다.
:::
4. **Save**를 선택하여 확인합니다.

## 사용 중인 CA

[클라이언트 인증서 개요](/ssl/client-certificates/#how-it-works)에서 설명한 것처럼 Cloudflare는 계정 수준에 설정된 CA를 기준으로 클라이언트 인증서를 검증합니다. 즉, 동일한 Cloudflare 계정 아래에 있고 해당 호스트에 대해 mTLS를 활성화한 경우, 이러한 인증서는 여러 zone/domain(`example.com`)에 걸쳐 검증에 사용될 수 있습니다.

:::note[자체 CA 사용]
Cloudflare 관리형 CA 대신 자체 CA를 사용해야 한다면 [BYOCA](/ssl/client-certificates/byo-ca/)를 참고하세요. 이는 Enterprise 계정에서 사용할 수 있는 API 전용 옵션이며, 이 경우 인증서와 호스트 이름 연결은 **대시보드에 표시되지 않습니다**.
:::

## 다음 단계

호스트에 대해 mTLS를 활성화한 후에는 다음을 수행할 수 있습니다.

- WAF 사용자 지정 규칙으로 mTLS를 강제합니다. 대시보드에서 **Create mTLS Rule**을 선택하여 템플릿을 사용하거나, 자세한 안내는 [Cloudflare에서의 mTLS 학습 경로](/learning-paths/mtls/mtls-app-security/#3-validate-the-client-certificate-in-the-waf)를 참고하세요.
- [API Shield](/api-shield/security/mtls/configure/)로 mTLS를 강제합니다. mTLS를 사용하기 위해 API Shield가 **필수는 아니지만**, 많은 팀이 API 보호를 위해 mTLS를 사용합니다.
