Cloudflare는 가능한 한 넓은 범위의 user agent(브라우저, API 클라이언트 등)에 대한 호환성을 제공하려고 합니다. 하지만 구체적으로 지원되는 클라이언트 집합은 SSL/TLS 인증서 유형, 방문자의 [browser version](#non-sni-support), 그리고 인증서를 발급하는 [certificate authority (CA)](/ssl/reference/certificate-authorities/)에 따라 달라질 수 있습니다.

## Universal SSL

Cloudflare Universal SSL은 TLS 프로토콜의 [Server Name Indication (SNI)](https://www.cloudflare.com/learning/ssl/what-is-sni/) 확장을 사용하는 브라우저와 API 클라이언트만 지원합니다.

또한 Free 요금제 영역의 Universal SSL은 Elliptic Curve Digital Signature Algorithm(ECDSA)을 지원하는 브라우저와만 호환됩니다.

유료 요금제는 추가 호환성을 제공하며 RSA 알고리즘도 지원합니다.

## 기타 인증서 유형

Cloudflare SSL/TLS 상품, 제공 가능한 알고리즘, 그리고 각 CA의 브라우저 호환성에 대한 자세한 목록은 [Certificate authorities](/ssl/reference/certificate-authorities/)를 참고하세요.

## Non-SNI 지원

[SNI extensions](https://www.cloudflare.com/learning/ssl/what-is-sni/)는 2003년에 TLS 프로토콜로 표준화되었지만, 일부 브라우저와 운영 체제는 TLS 1.1이 출시된 뒤에야 이 확장을 구현했습니다(모바일 브라우저는 2011년). 방문자가 2011년 이후 업데이트되지 않은 장치를 사용한다면 SNI를 지원하지 않을 수 있습니다.

Non-SNI 요청을 지원하려면 다음을 사용할 수 있습니다.

* [사용자 지정 인증서를 업로드](/ssl/edge-certificates/custom-certificates/uploading/#upload-a-custom-certificate)하고 해당 client support 값으로 `Legacy`를 지정합니다.

  `Legacy` 사용자 지정 인증서는 [BYOIP](/byoip/)와 호환되지 않으며, [Universal SSL](/ssl/edge-certificates/universal-ssl/) 또는 [advanced certificates](/ssl/edge-certificates/advanced-certificate-manager/)와 달리 Cloudflare는 [custom certificates](/ssl/edge-certificates/custom-certificates/)의 발급 및 갱신을 관리하지 않는다는 점에 유의하세요.

* (BYOIP 고객 전용) Enterprise 고객은 자체 IP prefix를 Cloudflare 네트워크로 가져오고 [address map에서 non-SNI handshake에 사용할 기본 SNI를 지정](/byoip/address-maps/setup/#non-sni-support)할 수 있습니다.

* (유료 요금제 전용) [Cloudflare Support에 문의](/support/contacting-cloudflare-support/)하여 영역에 대한 non-SNI IP 세트를 요청합니다.

## HTTPS 레코드

[HTTPS Service (HTTPS) records](/dns/manage-dns-records/reference/dns-record-types/#svcb-and-https)를 사용하면 초기 평문 HTTP 연결 없이도 클라이언트에 서버 연결 방식 정보를 미리 제공할 수 있습니다.

도메인에 [HTTP/2 또는 HTTP/3가 활성화](/speed/optimization/protocol/)되어 있고, [프록시된 DNS 레코드](/dns/proxy-status/)를 사용하며, [Universal SSL](/ssl/edge-certificates/universal-ssl/)도 사용 중이라면 Cloudflare는 클라이언트에게 서버 연결 방법을 알리기 위해 HTTPS 레코드를 즉시 생성합니다.

:::caution
HTTP/2와 HTTP/3 구성 모두 Cloudflare가 제공하는 SSL/TLS 인증서를 요구합니다. 따라서 예를 들어 Universal SSL을 비활성화하면 이 동작에 영향을 줄 수 있습니다.
:::

## OCSP와 HTTP 버전

Cloudflare의 OCSP 구현은 평문 HTTP 연결에서 기본적으로 HTTP/1.1을 사용합니다.

HTTPS 연결의 경우 클라이언트는 서버가 TLS ALPN(Application-Layer Protocol Negotiation) 확장을 통해 HTTP/2를 지원하면 자동으로 HTTP/2 사용을 시도합니다. 서버가 HTTP/2를 지원하지 않거나 사용할 수 없으면 HTTP/1.1로 폴백합니다.
