[TLS 1.0과 TLS 1.1](/ssl/reference/protocols/)은 알려진 취약점 때문에 정보를 보호하기에 충분하지 않습니다. 특히 Cloudflare 고객에게 PCI의 주요 영향은 TLS 1.0과 TLS 1.1이 결제 카드 관련 트래픽을 보호하기에 충분하지 않다는 점입니다.

PCI 표준은 TLS 1.2 이상 사용을 권장합니다. 권장되는 cipher suite 목록은 [Compliance standards](/ssl/edge-certificates/additional-options/cipher-suites/compliance-status/)를 참고하세요.

Cloudflare는 또한 TLS 1.0 및 1.1에 대해 [알려진 취약점에 대한 완화책](#known-vulnerabilities-mitigations)을 구현합니다.

## Minimum TLS Version을 1.2로 설정

Cloudflare 도메인이 TLS 1.2 이상 프로토콜만 허용하도록 구성하려면 다음을 수행하세요.

1. Cloudflare dashboard에서 **Edge Certificates** 페이지로 이동합니다.

   <DashButton url="/?to=/:account/:zone/ssl-tls/edge-certificates" />

2. **Minimum TLS Version**에서 **TLS 1.2** 이상을 선택합니다.

이 설정과 다른 구성 옵션에 대한 자세한 내용은 [Minimum TLS version](/ssl/edge-certificates/additional-options/minimum-tls/)을 참고하세요.

## 알려진 취약점 완화

Cloudflare는 TLS 1.2 이전 버전에 대해 알려진 취약점에 대한 여러 완화책을 수행합니다. 예를 들어 Cloudflare는 다음을 지원하지 않습니다.

* TLS에서의 헤더 압축
* SPDY 3.1에서의 헤더 압축
* RC4
* SSL 3.0
* 클라이언트와의 재협상
* DHE ciphersuites
* Export-grade ciphers

Cloudflare의 완화책은 다음 공격들로부터 보호합니다.

* CRIME
* BREACH
* POODLE
* RC4 Cryptographic Weaknesses
* SSL Renegotiation Attack
* Protocol Downgrade Attacks
* FREAK
* LogJam
* TLS 1.1 및 1.2에서는 3DES가 완전히 비활성화되며, TLS 1.0에 대해서는 Cloudflare가 완화책을 구현합니다.

Cloudflare는 다음에 대한 추가 완화책도 제공합니다.

* Heartbleed
* Lucky Thirteen
* CCS injection vulnerability

Cloudflare는 이러한 취약점에 대해 모든 서버에 패치를 적용했습니다. 또한 [Cloudflare Web Application Firewall](/waf/)에는 Heartbleed와 ShellShock를 포함해 여러 취약점을 완화하는 managed rule이 있습니다.

### Return of Bleichenbacher's Oracle Threat (ROBOT)

Cloudflare를 사용하는 동안 ROBOT의 존재를 지적하는 보안 스캔은 false positive입니다. Cloudflare는 패딩을 실시간으로 검사하고, 패딩이 잘못된 경우 임의의 session key로 교체합니다.

### Sweet32 (CVE-2016-2183)

Sweet32는 Transport Layer Security(TLS) 프로토콜에서 Triple DES(3DES) 암호화 알고리즘을 사용하는 방식의 취약점입니다. 현재 Sweet32는 proof of concept 공격이며, 실제 환경에서 알려진 사례는 없습니다. Cloudflare는 TLS 1.0에 대해 다음 방식으로 이 취약점을 수동 완화했습니다.

* 공격자는 단일 TLS 세션에서 32GB의 데이터를 수집해야 합니다.
* Cloudflare는 32GB의 데이터가 수집되기 훨씬 전에 영향받는 3DES cipher에 대해 새로운 TLS 1.0 세션 키를 강제로 적용합니다.
