Google Chrome과 Mozilla는 Entrust의 root CA에서 발급된 인증서를 더 이상 신뢰하지 않겠다고 발표했습니다.

Entrust는 Cloudflare가 사용하는 [certificate authorities](/ssl/reference/certificate-authorities/) 범위에 포함되지 않으므로, 이 변경은 주로 Entrust가 발급한 [custom certificates](/ssl/edge-certificates/custom-certificates/)를 업로드하는 고객에게만 영향을 줄 수 있습니다.

## 결정 사항

**2024년 11월 12일 이후** 발급된 새 Entrust 인증서는 기본적으로 Chrome에서 신뢰되지 않습니다. 그리고 **2024년 12월 1일 이후** 발급된 새 Entrust 인증서는 기본적으로 Mozilla에서 신뢰되지 않습니다.

불신 대상이 될 전체 루트 목록은 발표문([Chrome](https://security.googleblog.com/2024/06/sustaining-digital-certificate-security.html), [Mozilla](https://groups.google.com/a/mozilla.org/g/dev-security-policy/c/jCvkhBjg9Yw?pli=1))을 참고하세요.

## Entrust의 대응

고객이 문제를 겪지 않도록 Entrust는 Chrome과 Mozilla 모두에서 신뢰되는 다른 certificate authority인 SSL.com과 협력했습니다.

즉, Entrust 인증서는 SSL.com 루트를 사용해 발급됩니다.

## Cloudflare 관리형 인증서

Cloudflare도 [SSL.com과 협력](/ssl/reference/certificate-authorities/)하고 있으므로, custom certificate를 업로드하는 방식에서 Cloudflare 관리형 인증서를 사용하는 방식으로 전환할 수 있습니다. 이 변경은 다음과 같은 장점을 제공합니다.

* [Advanced certificates](/ssl/edge-certificates/advanced-certificate-manager/)를 사용해 더 많은 제어와 유연성을 확보하면서 자동 갱신의 이점도 누릴 수 있습니다.
* [Total TLS](/ssl/edge-certificates/additional-options/total-tls/)를 활성화해 [프록시된 호스트명](/dns/proxy-status/)에 대한 인증서를 자동 발급할 수 있습니다.
* [Delegated DCV](/ssl/edge-certificates/changing-dcv-method/methods/delegated-dcv/)를 사용해 [partial (CNAME) setup](/dns/zone-setups/partial-setup/) 영역의 인증서 갱신 시 수동 작업을 줄일 수 있습니다.
* SaaS 제공업체라면 custom hostname을 [생성](/api/resources/custom_hostnames/methods/create/)하거나 [편집](/api/resources/custom_hostnames/methods/edit/)할 때 SSL.com을 certificate authority로 지정함으로써 고객에게도 자동 갱신의 이점을 확장할 수 있습니다(API 전용).
