활성화된 SSL/TLS 인증서가 있더라도 방문자는 여전히 안전하지 않은 HTTP 연결로 리소스에 접근할 수 있습니다.

이 트래픽은 HTTPS로 리디렉션하고, 이미지 같은 다른 리소스도 HTTPS로 로드되도록 하는 것이 가장 좋습니다.

## 사전 요구 사항

HTTPS 연결 강제를 시도하기 전에 애플리케이션에 활성 [edge certificate](/ssl/get-started/#choose-an-edge-certificate)가 있는지 확인하세요. 그렇지 않으면 방문자는 애플리케이션에 전혀 접근할 수 없습니다.

또한 [SSL encryption mode](/ssl/origin-configuration/ssl-modes/)가 **Off**로 설정되어 있지 않은지 확인하세요. 그렇지 않으면 Cloudflare가 모든 방문자 연결을 자동으로 HTTP로 리디렉션합니다.

## 1. 기존 리디렉션 평가

방문자가 [리디렉션 루프](/ssl/troubleshooting/too-many-redirects/)에 빠지지 않도록 오리진 서버와 Cloudflare 대시보드 내의 기존 리디렉션을 검토하세요.

일반적으로 오리진 서버에서의 리디렉션은 피하는 것이 좋습니다. 잊어버리기 쉽고 애플리케이션 성능도 저하시키기 때문입니다. 요청이 오리진에 도달하기 전에 Cloudflare가 리디렉션하는 편이 훨씬 빠릅니다.

Cloudflare 내의 리디렉션이 `http`로 시작하는 URL로 트래픽을 전달하지 않는지 확인하세요.

## 2. HTTP URL 다시 쓰기

애플리케이션에 HTTP URL에 대한 링크나 참조가 포함되어 있으면, 방문자는 HTTPS 페이지에 접근할 때 [혼합 콘텐츠 오류](/ssl/troubleshooting/mixed-content-errors/)를 볼 수 있습니다.

이 문제를 방지하려면 [Automatic HTTPS Rewrites](/ssl/edge-certificates/additional-options/automatic-https-rewrites/)를 활성화하고, 여전히 오리진 서버로 도달하는 HTTP 요청이 무엇인지 주의 깊게 살펴보세요.

## 3. 트래픽을 HTTPS로 리디렉션

전체 애플리케이션이 HTTPS 트래픽을 지원할 수 있다면 [Always Use HTTPS](/ssl/edge-certificates/additional-options/always-use-https/#encrypt-all-visitor-traffic)를 활성화하세요.

애플리케이션의 일부만 HTTPS 트래픽을 지원한다면 **Always Use HTTPS**를 활성화하지 말고, [single redirect](/rules/url-forwarding/single-redirects/)를 사용하여 HTTPS로의 리디렉션을 선택적으로 수행하세요. 예시는 [관리자 영역 요청을 HTTPS로 리디렉션](/rules/url-forwarding/examples/redirect-admin-https/)을 참고하세요.
