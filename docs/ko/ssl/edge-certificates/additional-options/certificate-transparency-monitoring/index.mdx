Certificate Transparency (CT) Monitoring은 공개 베타 상태의 [opt-in](#opt-in-and-out) 기능으로, 도메인에 대해 발급된 모든 SSL/TLS 인증서를 다시 확인할 수 있게 함으로써 보안을 강화하는 것을 목표로 합니다.

CT Monitoring 알림은 Cloudflare의 [backup certificates](/ssl/edge-certificates/backup-certificates/)를 포함한 Cloudflare 내부 프로세스뿐 아니라, 모니터링 중인 도메인을 포함하는 인증서가 [Certificate Authority (CA)](/ssl/concepts/#certificate-authority-ca)에 의해 발급되어 공개 CT 로그에 추가될 때마다 트리거됩니다. 동작 방식에 대한 자세한 내용은 [소개 블로그 게시물](https://blog.cloudflare.com/introducing-certificate-transparency-and-nimbus/)을 참고하세요.

:::caution[고려해야 할 사항]

- 도메인 또는 하위 도메인에 대해 인증서를 자동 발급하는 Cloudflare 또는 기타 서비스를 사용하고 있다면 이 역시 CT Monitoring 이메일을 트리거할 수 있습니다.
- 도메인이 공유 인증서에 포함되어 있다면, 도메인과 함께 <GlossaryTooltip term="Subject Alternative Names (SANs)">subject alternative names (SANs)</GlossaryTooltip>로 포함된 다른 도메인이나 하위 도메인 때문에 알림을 받을 수 있습니다. 이런 경우 [Certificate Search](https://crt.sh/) 같은 도구로 더 많은 정보를 확인할 수 있습니다.
- CT Monitoring은 피싱 시도를 감지하지 않습니다. 예를 들어 `cloudflare.com`에 대해서는 `cloudf1are.com` 또는 `cloud-flare.com`에 대한 인증서가 발급되어도 알림이 발생하지 않습니다.

:::

## Opt in 및 Opt out

알림은 기본적으로 비활성화되어 있습니다. 알림을 받으려면 [**Edge Certificates**](https://dash.cloudflare.com/?to=/:account/:zone/ssl-tls/edge-certificates#ct-alerting-card) 페이지로 이동하여 **Certificate Transparency Monitoring**을 활성화하세요. Business 또는 Enterprise 영역이라면 **Add Email**을 선택합니다.

알림 수신을 중지하려면 **Certificate Transparency Monitoring**을 비활성화하거나 기능 카드에서 이메일을 제거하세요.

## 주의해서 봐야 하는 이메일

대부분의 인증서 알림은 정상적인 알림입니다. Cloudflare는 도메인 인증서가 로그에 나타날 때마다 알림을 보냅니다. 인증서는 만료되며 다시 발급되어야 하므로, 발급 이메일을 받는 것은 완전히 정상입니다. 이메일에 도메인과 합리적인 소유권 정보, 인증서 정보가 포함되어 있다면 **별도의 조치는 필요하지 않습니다**.

또한 인증서가 Cloudflare를 통해 발급되었는지도 확인해야 합니다. Cloudflare는 인증서를 제공하기 위해 [여러 CA](/ssl/reference/certificate-authorities/)와 협력합니다.
추가 조치가 필요 없는 Cloudflare 발급 인증서와 백업 인증서를 모두 확인하려면 대시보드의 [Edge Certificates 페이지](https://dash.cloudflare.com/?to=/:account/:zone/ssl-tls/edge-certificates)를 확인하세요.

다음과 같이 명백히 이상한 점이 있을 때는 조치를 취해야 합니다.

- 인증서 발급자를 알아보지 못하는 경우
  :::note

  Cloudflare는 백업 인증서를 프로비저닝하므로, 현재 사이트에 활성 사용 중이 아닌 인증서가 표시될 수 있습니다. [Edge Certificates 페이지](https://dash.cloudflare.com/?to=/:account/:zone/ssl-tls/edge-certificates)에는 사이트에 대해 요청된 모든 인증서가 표시됩니다.
  :::

- 최근 웹사이트 문제를 발견한 경우

## 조치 방법

### 옵션 1: 인증 기관에 연락

악성 인증서를 폐기할 수 있는 것은 Certificate Authority뿐입니다. 도메인에 대해 부정하게 발급된 인증서라고 판단되면 이메일의 **Issuer**로 표시된 Certificate Authority에 연락하세요.

- [GlobalSign support](https://support.globalsign.com/)
- [GoDaddy support](https://www.godaddy.com/contact-us?sp_hp=B)
- [Google Trust Services support](https://pki.goog/faq/)
- [IdenTrust support](https://www.identrust.com/support/support-team)
- [Let's Encrypt support](https://letsencrypt.org/contact/)
- [Sectigo support](https://sectigo.com/support)
- [SSL.com support](https://www.ssl.com/submit-a-ticket/)

### 옵션 2: 도메인 등록기관에 연락

도메인 등록기관은 잠재적으로 악성인 도메인을 **정지**시킬 수 있습니다. 예를 들어 악성 도메인이 GoDaddy를 통해 등록된 것으로 보이면 GoDaddy 지원팀에 문의해 도움을 받을 수 있는지 확인하세요. 다른 등록기관도 마찬가지입니다.

### 옵션 3: 다른 방식으로 대응

악성 인증서에 대응하는 다른 방법도 있습니다. 사이트 공지를 통해 방문자에게 경고하거나 브라우저 제작사(Chrome의 Google 등)에 해당 도메인을 차단해 달라고 요청할 수 있습니다.

누군가 온라인에서 당신을 사칭하려 한다면 반드시 조치를 취해야 합니다. 하지만 이를 식별하는 것은 보통 어렵기 때문에 신중해야 합니다. **대부분의 인증서는 악성이 아닙니다. 문제가 있다고 판단되는 경우에만 조치를 취하세요.**

## HTTP Public Key Pinning

Certificate Transparency Monitoring은 HTTP Public Key Pinning(HPKP)과 동일한 문제를 해결하지만, [기술적 문제는 더 적습니다](https://scotthelme.co.uk/im-giving-up-on-hpkp/).

Cloudflare는 HPKP를 제공하거나 지원하지 않으며 Universal SSL과 함께 사용하는 것도 권장하지 않습니다.
