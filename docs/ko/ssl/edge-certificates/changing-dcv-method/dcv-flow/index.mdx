[Universal](/ssl/edge-certificates/universal-ssl/), [Advanced](/ssl/edge-certificates/advanced-certificate-manager/), 그리고 [Custom hostname](/cloudflare-for-platforms/cloudflare-for-saas/security/certificate-management/) 인증서를 발급받기 위해 Cloudflare는 여러 공개 신뢰 [인증 기관(CA)](/ssl/reference/certificate-authorities/)과 협력합니다.

그러나 CA에 인증서 발급 또는 갱신을 요청할 때마다 요청자는 해당 도메인을 제어하고 있음을 증명해야 합니다. 이때 DCV 프로세스가 수행되며, 일반적으로 표준 URL 경로(`/.well-known/pki-validation`)에 HTTP 토큰을 배치하거나 권한 있는 DNS 제공자에 TXT 레코드를 배치하는 방식으로 증명을 제공합니다.

## DCV 프로세스에서 Cloudflare의 위치

위에서 언급한 사용 사례에는 이 과정에 세 가지 당사자가 참여합니다.

- 인증서가 발급되는 웹사이트 또는 애플리케이션
- 요청자(Cloudflare)
- 요청을 처리하는 CA

## 프로세스 단계

요약하면, Cloudflare가 CA에 인증서 발급 또는 갱신을 요청한 뒤 다음 다섯 단계가 성공해야 합니다.

1. Cloudflare가 CA로부터 DCV 토큰을 받습니다.
2. Cloudflare가 토큰을 사용자를 대신해 배치하거나([전체 DNS 설정](/dns/zone-setups/full-setup/), [위임된 DCV](/ssl/edge-certificates/changing-dcv-method/methods/delegated-dcv/)), 사용자가 직접 배치할 수 있도록 토큰을 제공합니다.
3. Cloudflare가 토큰 존재 여부를 확인하기 위해 검증 URL을 폴링합니다.
4. Cloudflare가 여러 DNS 리졸버를 통해 토큰이 배치된 것을 확인하면, CA에도 이를 확인하도록 요청합니다.
5. CA가 토큰 배치를 확인하면 인증서가 발급됩니다. 확인할 수 없으면 인증서는 발급되지 않으며 토큰도 더 이상 유효하지 않습니다.

## 고려해야 할 사항

- 검증 URL을 방해하는 설정(예: 방화벽 차단, 잘못 구성된 DNSSEC)은 인증서 발급 또는 갱신에 문제를 일으킬 수 있습니다. [문제 해결 가이드](/ssl/edge-certificates/changing-dcv-method/troubleshooting/)를 참고하세요.

### DCV 토큰

DCV 토큰은 Cloudflare가 아니라 CA가 생성하고 제어합니다. 작동 방식에 대한 보다 자세한 기술 사양은 [RFC 8555](https://www.rfc-editor.org/rfc/rfc8555#section-7.1.5)에서 확인할 수 있습니다.

- [프로세스 단계](#프로세스-단계)의 5단계에서 언급했듯이, DCV 토큰은 검증 실패가 발생하면 변경됩니다. 예를 들어 DNSSEC 문제로 DCV 검사가 실패하면 인증서 주문은 더 이상 유효하지 않으며 Cloudflare는 새 인증서 요청을 다시 시작해야 합니다. 토큰은 재사용할 수 없으므로 새 토큰이 필요합니다.

- DCV 토큰에는 [유효 기간](/ssl/edge-certificates/changing-dcv-method/validation-backoff-schedule/)도 있습니다. DCV를 수동으로 처리하는 경우, 인증서가 갱신 시점에 들어가면 가능한 한 빨리 토큰을 배치하는 것이 좋습니다. 그렇지 않으면 토큰이 만료되어 새 토큰이 필요할 수 있습니다.
