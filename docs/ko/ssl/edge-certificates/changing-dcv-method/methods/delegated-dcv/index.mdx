위임된 DCV는 [부분 DNS 설정](/dns/zone-setups/partial-setup/)을 사용하는 영역, 즉 권한 있는 DNS를 Cloudflare가 제공하지 않는 영역이 DCV 프로세스를 Cloudflare에 위임할 수 있게 해줍니다.

DCV 위임을 사용하려면 모든 이후 인증서 주문을 Cloudflare가 자동 갱신할 수 있도록 해 주는 일회성 레코드를 배치해야 하며, 이렇게 하면 갱신 시점에 수동 개입이 필요하지 않습니다.

:::note

DCV 위임은 Universal 인증서에서는 동작하지 않으며 [Advanced certificate](/ssl/edge-certificates/advanced-certificate-manager/)를 사용해야 합니다.
:::

## 사용해야 하는 경우

다음 조건이 모두 참이면 위임된 DCV를 사용해야 합니다.

- 영역이 [부분 DNS 설정](/dns/zone-setups/partial-setup/)을 사용 중입니다.
- Cloudflare가 이미 [자동으로 DCV를 수행](/ssl/edge-certificates/changing-dcv-method/)하고 있지 않습니다.
- 영역이 [Advanced certificate](/ssl/edge-certificates/advanced-certificate-manager/)를 사용 중입니다.
- 인증 기관이 Google Trust Services, SSL.com 또는 Let's Encrypt 중 하나입니다.

### 유의할 사항

[발표 블로그 게시물](https://blog.cloudflare.com/introducing-dcv-delegation/)에서 설명하듯 현재는 한 번에 하나의 제공자에게만 DCV를 위임할 수 있습니다. 이는 다음을 의미합니다.

- 동일한 호스트 이름에 대해 [오리진 서버](/ssl/concepts/#origin-certificate)용 공개 신뢰 인증서를 함께 발급하고 있다면 더 이상 그렇게 할 수 없습니다. 대신 [Cloudflare origin CA certificates](/ssl/origin-configuration/origin-ca/)를 사용할 수 있습니다.

- 영역이 여러 CDN 제공자를 사용하고 있다면 다른 [방법](/ssl/edge-certificates/changing-dcv-method/methods/)을 사용하는 것이 좋을 수 있습니다. Cloudflare에 DCV 위임이 구성되면 Cloudflare만 사용자를 대신해 DCV를 수행할 수 있고 외부 CDN 제공자는 그렇게 할 수 없게 되기 때문입니다.

## 설정

위임된 DCV를 설정하려면 다음을 수행하세요.

1. 영역에 대해 [Advanced certificate](/ssl/edge-certificates/advanced-certificate-manager/manage-certificates/)를 주문하고 **Certificate validation method**로 `TXT`를 선택합니다.
2. [**Edge Certificates**](https://dash.cloudflare.com/?to=/:account/:zone/ssl-tls/edge-certificates) 페이지에서 **DCV Delegation for Partial Zones**로 이동합니다.
3. Cloudflare 검증 URL을 복사합니다.
4. 권한 있는 DNS 제공자에서 다음 사항을 고려하여 `CNAME` 레코드를 생성합니다.

- 인증서가 apex 도메인과 와일드카드만 포함한다면 apex 도메인에 대한 단일 `CNAME` 레코드만 만들면 됩니다. 직접적인 하위 도메인도 함께 포함됩니다.

<Example>

```txt
_acme-challenge.example.com CNAME example.com.<COPIED_VALIDATION_URL>.
```

</Example>

- 인증서가 이름이 명시된 서브도메인도 포함한다면, 권한 있는 DNS 제공자에 각 특정 서브도메인마다 `CNAME` 레코드를 하나씩 추가해야 합니다.

<Example>

예를 들어 `example.com`, `*.example.com`, `sub.example.com`을 포함하는 인증서라면 다음 레코드가 필요합니다.

```txt
_acme-challenge.example.com CNAME example.com.<COPIED_VALIDATION_URL>.
_acme-challenge.sub.example.com CNAME sub.example.com.<COPIED_VALIDATION_URL>.
```

</Example>

<Render file="dcv-conflicting-records" product="ssl" />

`CNAME` 레코드가 배치되면, 영역이 Cloudflare에서 [active](/dns/zone-setups/reference/domain-status/) 상태인 한, 고급 인증서에서 DCV 위임 레코드가 있는 모든 호스트 이름에 대해 Cloudflare가 TXT DCV 토큰을 추가합니다.

DCV는 정기적으로 수행되므로, 권한 있는 DNS 제공자에서 `CNAME` 레코드를 제거하지 마세요. 제거하면 Cloudflare가 사용자를 대신해 DCV를 수행할 수 없게 되어 인증서가 발급되지 않습니다.

## 추가 세부 사항

### 테스트

`dig` 명령으로 테스트할 경우, 인증서가 발급 대기 상태일 때만 배치된 토큰을 볼 수 있어야 합니다.

이는 Cloudflare가 필요할 때 토큰을 배치하고 이후 정리하기 때문입니다.

```sh
dig TXT +noadditional +noquestion +nocomments +nocmd +nostats _acme-challenge.example.com. @1.1.1.1

_acme-challenge.example.com. 3600    IN    CNAME    example.com.<COPIED_VALIDATION_URL>
```

### 갱신

인증서 갱신 시점에 호스트 이름에 접근할 수 없게 되면, 위임된 DCV를 통한 자동 갱신은 수행될 수 없습니다. 현재 해석되지 않는 호스트 이름에 대한 인증서를 갱신해야 한다면 [changing DCV method API endpoint](/api/resources/ssl/subresources/verification/methods/edit/)에 PATCH 요청을 보내고 방법을 TXT로 변경하여 [TXT DCV 방법](/ssl/edge-certificates/changing-dcv-method/methods/txt/)에 따라 수동 갱신을 진행할 수 있습니다.

호스트 이름이 다시 해석 가능해지면 [위임된 DCV](/ssl/edge-certificates/changing-dcv-method/methods/delegated-dcv/)는 예상대로 다시 작동합니다.

### 이동된 도메인

[영역을 다른 계정으로 이동](/fundamentals/manage-domains/move-domain/)하면 권한 있는 DNS 제공자에 있는 `CNAME` 레코드를 새 검증 URL로 업데이트해야 합니다.
