다양한 Authenticated Origin Pulls 설정에서 사용하는 인증서를 관리하는 방법은 아래 섹션을 참고하세요.

---

## 만료된 인증서

Cloudflare는 관련 인증서에 대해 Cloudflare API로 삭제 요청([Delete a zone-level certificate](/api/resources/origin_tls_client_auth/subresources/zone_certificates/methods/delete/) 또는 [Delete a hostname-level certificate](/api/resources/origin_tls_client_auth/subresources/hostname_certificates/methods/delete/))을 보내지 않는 한 만료된 클라이언트 인증서를 삭제하지 않습니다. 오리진이 유효한 클라이언트 인증서만 허용하도록 설정되어 있다면, 인증서가 만료되면 요청을 차단하게 됩니다.

AOP 인증서가 만료되기 30일 전과 14일 전에 경고를 받도록 [notifications](/notifications/notification-available/#ssltls)를 설정해 두세요.

---

## 특수 목적 인증서 사용

zone 수준과 hostname 수준에서 서로 다른 클라이언트 인증서를 동시에 적용하려면 zone-level 인증서와 per-hostname 커스텀 인증서를 함께 사용할 수 있습니다.

먼저 인증서를 사용해 [zone-level pulls](/ssl/origin-configuration/authenticated-origin-pull/set-up/zone-level/)를 설정합니다. 그런 다음 [개별 hostnames](/ssl/origin-configuration/authenticated-origin-pull/set-up/per-hostname/)에 대해 여러 개의 특수 목적 인증서를 업로드합니다. per-hostname 인증서는 더 구체적이므로 zone 인증서보다 우선합니다.

---

## 다운타임 없이 인증서 교체

:::caution[자동 삭제 없음]
Cloudflare는 관련 인증서에 대해 Cloudflare API로 삭제 요청([Delete a zone-level certificate](/api/resources/origin_tls_client_auth/subresources/zone_certificates/methods/delete/) 또는 [Delete a hostname-level certificate](/api/resources/origin_tls_client_auth/subresources/hostname_certificates/methods/delete/))을 보내지 않는 한 만료된 클라이언트 인증서를 삭제하지 않습니다.
:::

### Per-hostname

1. [새 인증서를 업로드](/api/resources/origin_tls_client_auth/subresources/hostname_certificates/methods/create/)합니다.
2. [인증서 목록을 조회](/api/resources/origin_tls_client_auth/subresources/hostname_certificates/methods/list/)하고 업로드한 인증서의 ID를 확인합니다.
3. [특정 hostname에 대해 Authenticated Origin Pulls를 활성화](/api/resources/origin_tls_client_auth/subresources/hostnames/methods/update/)하면서, 2단계에서 얻은 ID로 사용할 인증서를 지정합니다.

<APIRequest
	path="/zones/{zone_id}/origin_tls_client_auth/hostnames"
	method="PUT"
	json={{
		"config": [
			{
				"enabled": true,
				"hostname": "<HOSTNAME>",
				"cert_id": "<CERT_ID>"
			}
		]
	}}
/>

:::note
두 인증서를 모두 유지하면 API에는 둘 다 `active`로 표시되지만, 가장 최근에 배포된 인증서가 실제로 활성화되어 사용됩니다.
:::

### Zone-level

1. [새 인증서를 업로드](/api/resources/origin_tls_client_auth/subresources/zone_certificates/methods/create/)합니다.
2. [새 인증서가 Active 상태인지 확인](/api/resources/origin_tls_client_auth/subresources/zone_certificates/methods/get/)합니다.
3. 새 인증서가 활성화되면 [이전 인증서를 삭제](/api/resources/origin_tls_client_auth/subresources/zone_certificates/methods/delete/)합니다.

:::note
두 인증서를 모두 유지하면 API에는 둘 다 `active`로 표시되지만, 가장 최근에 배포된 인증서가 실제로 활성화되어 사용됩니다.
:::
