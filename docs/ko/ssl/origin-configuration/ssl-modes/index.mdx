## 사용 가능한 암호화 모드

[Automatic SSL/TLS](#automatic-ssltls-default)는 SSL/TLS Recommender를 위해 개발된 프로브를 기반으로 웹사이트에 가장 안전하고 보안성이 높은 암호화 모드를 판단합니다. 웹사이트에 더 안전한 옵션이 있다면(오리진 인증서나 기능을 기준으로) Automatic SSL/TLS가 이를 찾아 도메인에 적용합니다. 다른 옵션인 [Custom SSL/TLS](#custom-ssltls)는 오늘날의 암호화 모드 설정과 정확히 동일하게 동작합니다.

:::note
새로운 [Automated SSL/TLS feature](#automatic-ssltls-default)를 점진적으로 출시하고 있습니다.

아직 zone이 마이그레이션되지 않았다면 대시보드에서는 [Custom SSL/TLS](#custom-ssltls) 옵션만 볼 수 있습니다.
:::

다양한 암호화 모드가 캐시에 어떤 영향을 주는지는 [Impact of SSL setting on cache behavior](/cache/how-to/cache-keys/#impact-of-ssl-settings-on-cache-behavior) 섹션을 참고하세요.

### Automatic SSL/TLS (default)

Automatic SSL/TLS는 SSL/TLS Recommender가 개발한 고급 방식을 활용해 웹사이트에 가장 안전한 암호화 모드를 선택합니다. Recommender는 Cloudflare에서 신뢰할 수 있는 봇으로 인식되는 Cloudflare-SSLDetector user agent를 사용해 사이트를 크롤링하며, 정확성을 위해 `robots.txt` 규칙(해당 user agent를 명시적으로 대상으로 하는 규칙 제외)을 우회합니다. 이후 오리진 서버에서 HTTP와 HTTPS 모두로 콘텐츠를 다운로드하고, content similarity 알고리즘을 적용해 일관성을 평가합니다. 현재 SSL/TLS 암호화 모드를 이해하고 오리진의 인증서 및 기능을 평가함으로써 Recommender는 도메인에 대해 가장 높은 보안을 유지하도록 설정을 자동 조정할 수 있습니다.

:::note
Automatic SSL/TLS는 설정을 더 낮은 보안 수준의 암호화 모드로 바꾸지 않습니다. 예를 들어 오리진 인증서가 만료되더라도 암호화 모드는 **Full (strict)**에서 **Full**로 바뀌지 않습니다. 오리진 SSL/TLS 구성이 항상 유효하도록 직접 관리해야 합니다.
:::

자동 업그레이드는 점진적으로 적용됩니다. Automatic SSL/TLS는 우선 전체 트래픽의 1%만 새 모드로 업그레이드하면서 시작합니다. 문제가 없으면 10% 단위로 증가시켜 최종적으로 100% 트래픽이 권장 모드를 사용하게 됩니다. 이 과정에서 오리진 연결 실패가 발생하면 Cloudflare는 업그레이드를 중단하고 즉시 트래픽을 이전 모드로 롤백한 뒤 실패를 기록합니다. 100% 트래픽이 TLS 관련 오류 없이 성공적으로 업그레이드되면 도메인의 SSL/TLS 설정이 영구적으로 업데이트됩니다.

Flexible → Full/Strict 전환은 오리진 scheme 변경(HTTP → HTTPS)으로 cache key가 달라지므로 더 신중하게 처리됩니다. 이 경우 cache warm-up을 허용하기 위해 전환 속도가 더 느려질 수 있으며, 이후 정상적인 증가 단계로 복귀합니다.

#### Additional details

- **스캔 주기**: 자동 스캔은 현재 대략 한 달에 한 번 실행되며, 경우에 따라(예: 설정 변경이나 업그레이드) 더 자주 일어날 수 있습니다. 다음 조건이면 스캔이 중단됩니다.
  - 사이트가 이미 가장 안전한 모드(예: **Full (strict)**)를 사용 중인 경우
  - auto mode에서 **Custom SSL/TLS**로 전환한 경우

- **업그레이드 전 오류 점검**: 서비스 중단을 방지하기 위해 Cloudflare는 zone의 암호화 모드를 업그레이드하기 전에 `5XX` 오류(`502`, `503` 등)를 점검하고, HTTP와 HTTPS 콘텐츠가 일관적인지도 평가합니다.

- **업그레이드 알림**: Cloudflare는 어떤 zone이 업그레이드되었는지를 정리한 주간 digest 이메일을 발송합니다. 현재 이 이메일은 Super Admin에게만 전송됩니다.

#### 단일 zone 옵트아웃

API를 통해 특정 zone을 옵트아웃하려면 grace period 만료일 이전 또는 당일에 아래 API 호출을 수행할 수 있습니다.

<APIRequest
	path="/zones/{zone_id}/settings/{setting_id}"
	method="PATCH"
	json={{
		value: "custom",
	}}
	parameters={{
		setting_id: "ssl_automatic_mode",
	}}
/>

#### 여러 zone 옵트아웃

여러 zone을 옵트아웃하려면:

1. 다음 권한을 가진 API token을 생성합니다.
   - `Zone - Zone - Read`
   - `Zone - Zone Settings - Read`
   - `Zone - Zone Settings - Edit`
2. zone 목록을 가져오기 위해 [`GET` request](/api/resources/zones/methods/list/)를 수행합니다(`account.id`로 필터링 가능).

   ```bash "account.id=<ACCOUNT_ID>"
   curl 'https://api.cloudflare.com/client/v4/zones?account.id=<ACCOUNT_ID>' \
   --header 'Authorization: Bearer <CF_API_TOKEN>' \
   --header 'Content-Type: application/json'
   ```

3. 각 zone ID를 줄바꿈으로 구분해 `zones.txt` 같은 파일에 저장합니다.
4. `opt-out-multiple-zones.sh`용 bash 스크립트를 만들고 아래 내용을 추가합니다. `zones.txt`를 같은 디렉터리에 두거나 경로를 수정하세요.

   ```bash title="opt-out-multiple-zones.sh"
   for zoneID in $(cat zone.txt); do
     printf "Opting out ${zoneID}:\n"

     curl --request PATCH \
   		--url https://api.cloudflare.com/client/v4/zones/$zoneID/settings/ssl_automatic_mode \
   		--header 'Authorization: Bearer <CF_API_TOKEN>' \
   		--header 'Content-Type: application/json' \
   		--data '{"value":"custom"}'

     printf "\n\n"
   done
   ```

5. 명령줄에서 다음을 실행합니다.

   ```bash
   bash opt-out-multiple-zones.sh
   ```
