:::caution[중요]

HSM 제조사 문서를 꼼꼼히 검토하고 키 서버에 대한 접근을 적절히 제한하세요.

:::

PKCS#11 토큰을 시작하려면 개인 키, PIN, 토큰 레이블로 초기화해야 합니다. 이를 수행하는 방법은 각 하드웨어 장치마다 다르므로 공급업체가 제공하는 지침을 따라야 합니다. 또한 공유 객체 파일(`.so`)인 `module`의 경로도 찾아야 합니다. 장치를 초기화한 후에는 다음 명령으로 토큰 레이블을 확인할 수 있습니다.

```sh
pkcs11-tool --module <module path> --list-token-slots
```

가져왔거나 생성한 개인 키의 레이블도 확인해야 합니다. 다음 명령을 실행하고 `Private Key Object`를 찾으세요.

```bash
pkcs11-tool --module <module path> --pin <pin> \
    --list-token-slots --login --list-objects
```

이제 구성 파일의 `private_key_stores` 섹션에 추가하여 PKCS#11 토큰을 Keyless 서버와 함께 사용하는 데 필요한 모든 정보를 갖추었습니다. Keyless가 접근할 수 있어야 하는 키 쌍은 [PKCS#11 URI](https://tools.ietf.org/html/rfc7512) 형식을 사용해 구성 파일에 지정할 수 있습니다.

## PKCS#11 URI

PKCS#11 URI는 세미콜론으로 구분된 속성 값 쌍으로 이루어진 경로 구성 요소와, 선택적으로 뒤따르는 쿼리로 구성됩니다. 일반적인 형식은 다음과 같습니다.

```txt
pkcs11:path-component[?query-component]
```

URI 경로 구성 요소에는 리소스를 식별하는 속성이 들어 있습니다. 쿼리 구성 요소에는 경로 구성 요소가 식별한 리소스를 가져오는 데 필요한 몇 가지 속성이 포함될 수 있습니다. 경로 구성 요소의 속성은 `;` 문자로 구분되고, 쿼리 구성 요소의 속성은 `&` 문자로 구분됩니다. 모든 속성은 URL 인코딩됩니다.

Keyless는 다음 세 가지 속성을 지정해야 합니다.

- **Module**: PKCS#11 모듈 라이브러리를 찾기 위해 `module-path`를 사용합니다.
- **Token**: `serial`, `slot-id`, 또는 `token`을 사용해 PKCS#11 토큰을 지정합니다.
- **Slot**: `id` 또는 `object`를 사용해 PKCS#11 키 쌍을 지정합니다.

일부 모듈의 경우 모듈에 너무 많은 세션이 열리는 것을 방지하기 위해 `max-sessions` 쿼리 속성이 필요합니다. 상황에 따라 `pin-value` 같은 추가 속성도 필요할 수 있습니다. 자세한 내용은 사용하는 PKCS#11 모듈 문서를 참조하세요.

## 예시

다음은 여러 모듈에 저장된 키에 대한 PKCS#11 URI 예시입니다.

```txt
private_key_stores:
- uri: pkcs11:token=SoftHSM2%20RSA%20Token;id=%03?module-path=/usr/lib64/libsofthsm2.so&pin-value=1234
- uri: pkcs11:token=accelerator;object=thaleskey?module-path=/opt/nfast/toolkits/pkcs11/libcknfast.so
- uri: pkcs11:token=YubiKey%20PIV;id=%00?module-path=/usr/lib64/libykcs11.so&pin-value=123456&max-sessions=1
- uri: pkcs11:token=elab2parN;id=%04?module-path=/usr/lib/libCryptoki2_64.so&pin-value=crypto1
```

## 제한 사항

현재는 한 번에 하나의 PKCS#11 모듈만 사용할 수 있으므로, 키가 여러 HSM에 분산되어 있다면 [p11-glue를 사용해 하나의 모듈을 통해 접근을 통합](https://p11-glue.github.io/p11-glue/)하는 것을 권장합니다.
