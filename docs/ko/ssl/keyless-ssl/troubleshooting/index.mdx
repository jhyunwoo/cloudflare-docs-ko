## 로그 확인

로그를 확인하려면 다음과 비슷한 명령을 사용하세요.

- systemd: `sudo journalctl -f -u gokeyless`
- upstart/sysvinit: `sudo tail -f /var/log/gokeyless.log`

## 디버그 로깅 활성화

디버그 로깅을 활성화하려면 다음과 비슷한 명령을 사용하세요.

```sh
cd /etc/keyless
sudo -u keyless gokeyless --loglevel 0
```

## 브라우저가 연결을 시도한 뒤 TLS 연결 실패를 보고하는 경우

1. 키 서버가 네트워크 외부에서 접근 가능한지(tcp/2407) 확인합니다.
2. 패킷 캡처를 제공합니다.
   `sudo tcpdump -nni <interface> -s 0 -w keyless-$(date +%s).pcap port 2407`

## 클라이언트가 연결되지만 즉시 중단되는 경우

`gokeyless`를 디버그 로깅으로 실행했을 때 다음과 같은 로그가 보인다면,

```txt
[DEBUG] connection 162.158.57.220:37490: reading half closed by client
[DEBUG] connection 162.158.57.220:37490: server closing connection
[DEBUG] connection 162.158.57.220:37490 removed
[DEBUG] spawning new connection: 162.158.57.220:37862
[DEBUG] connection 162.158.57.220:37862: reading half closed by client
[DEBUG] connection 162.158.57.220:37862: server closing connection
[DEBUG] connection 162.158.57.220:37862 removed
```

이 로그는 키 서버가 적절한 서버 인증서 또는 `.PEM` 파일을 사용하지 않아, 인증서 교환 후 클라이언트가 연결을 중단하고 있음을 의미할 가능성이 높습니다. 인증서는 keyless CA가 서명한 것이어야 하며, SAN에는 keyless 서버의 호스트명이 포함되어야 합니다. 다음은 `11aa40b4a5db06d4889e48e2f.example.com`에 위치한 keyless 서버의 유효한 예시입니다(Subject Alternative Name 및 Authority Key Identifier 참고).

```bash
openssl x509 -in server.pem -noout -text -certopt no_subject,no_header,no_version,no_serial,no_signame,no_validity,no_subject,no_issuer,no_pubkey,no_sigdump,no_aux | sed -e 's/^        //'
```

## gokeyless 바이너리가 CA 파일을 로드하지 못하는 경우

서버에 설치된 모든 키와 인증서의 권한이 올바른지 확인하세요.

## Keyless가 예상하지 못한 호스트에 영향을 주는 경우

해당 호스트에만 적용되는 인증서를 제공하거나, Cloudflare 대시보드의 **SSL/TLS** 앱에서 인증서 우선순위를 변경해야 합니다.

## Windows의 키 서버

Cloudflare는 현재 [Cloudflare 패키지 저장소](https://pkg.cloudflare.com/)에서 지원하는 GNU/Linux 배포판에 대해서만 패키지를 제공합니다.

하지만 키 서버는 오픈 소스이므로 직접 바이너리를 빌드하고 배포해볼 수 있습니다. 다만 Windows에서 실행하는 구성은 지원되지 않으므로, Cloudflare가 도움을 줄 수 없는 문제가 발생할 수 있습니다.

## 키 서버의 다중 도메인 지원

동일한 키 서버를 여러 도메인에 사용할 수 있습니다.

다만 이 경우 `gokeyless.yaml` 파일에 새 도메인의 호스트명과 Zone ID를 추가해야 합니다.
