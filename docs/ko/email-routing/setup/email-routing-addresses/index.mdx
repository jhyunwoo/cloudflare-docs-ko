이메일 규칙은 사용자 지정 이메일 주소와 대상 주소의 쌍, 또는 이메일 노동자와 사용자 지정 이메일 주소입니다. 이것은 당신이 당신의 선호한 inbox에 이메일을 경로, 또는 이메일 Workers를 통해 논리를 적용할 수 있습니다 당신의 이메일에 일어나는 것을 결정하기 전에. 특정한 공급자에서 특정한 우편물 inboxes에 이메일을 전달하는 다수 주문 주소가 있을 수 있습니다.

## 주문 주소

1. Cloudflare 대시보드에서, 가십시오**이메일 Routing**사이트 맵

   <DashButton url="/?to=/:account/:zone/email/routing" />

2. 제품정보**여정 규칙**.

3. 제품정보**자주 묻는 질문**.

4. 내 계정**주문 주소**, 사용하려는 사용자 정의 이메일 주소를 입력하십시오 (예를 들어,`my-new-email`).

5. 내 계&#xC815;**- 연혁**드롭다운 메뉴, 이 이메일 규칙이 수행해야하는 것을 선택하십시오. 더 알아보기[이메일 규칙](#email-rule-actions)더 많은 정보.

6. 내 계정**여행 정보**, 이메일 주소를 선택하거나 이메일을 원하는 이메일 노동자를 선택 — 예를 들어,`your-name@gmail.com`. 당신은 이미 확인 된 목적지 주소를 선택할 수 있습니다. 새로운 목적지 주소를 추가하려면, 참조[대상 주소](#destination-addresses).

:::참조

같은 사용자 정의 주소와 연결된 하나의 대상 주소를 가지고 있다면, 이메일 Routing은 가장 최근 규칙 만 처리됩니다. 이것은 사용자 정의 주소와 목적지 주소의 가장 최근 쌍 만 의미 (rule) 당신의 전달 된 이메일을 받게됩니다. 이를 피하기 위해, 같은 사용자 정의 주소로 하나의 목적지 주소를 연결하지 마십시오.
주요 특징

### 이메일 규칙

이메일 규칙을 만들 때, 당신은 지정해&#xC57C;**- 연혁**:

- *자주 묻는 질문*: 이메일은 목적지 주소로 이동합니다. 이것은 기본 동작입니다.
- *작업자에게 보내기*: 이메일은 논리로 처리됩니다.[이메일 Worker](/email-routing/email-workers).
- *팟캐스트*: 삭제 이메일은 routing없이 사용자 정의 주소로 보내. 이메일 주소를 확인하려면 유용할 수 있습니다.

:::참조

스팸을 방지하기 위해 모든 이메일 규칙은 사용자에 의해 검증 될 때까지 자동으로 비활성화됩니다.

:::

### 이메일 규칙을 비활성화

1. Cloudflare 대시보드에서, 가십시오**이메일 Routing**사이트 맵

   <DashButton url="/?to=/:account/:zone/email/routing" />

2. 제품정보**여정 규칙**.

3. 내 계정**주문 주소**, 당신이 일시 중지하고 싶은 이메일 규칙을 식별, 상태 버튼을 toggle**지원하다**.

귀하의 이메일 규칙이 비활성화되었습니다. 대상 주소 또는 이메일 노동자에 이메일을 전달하지 않습니다. 이메일을 다시 전달하려면 이메일 규칙 상태 버튼을 toggle**지원하다**.

### 사용자 정의 주소

1. 로그인하기[Cloudflare 대시보드](https://dash.cloudflare.com/)계정 및 도메인을 선택하십시오.
2. 오시는 길**이름 \*** > **이메일 Routing** > **오시는 길**.
3. 내 계정**주문 주소**, 편집하고 싶은 이메일 규칙을 확인하고, 선택**제품정보**.
4. 이 주문 주소에 적합한 변경을 만드십시오.

## Catch-all 주소

이 기능을 활성화할 때, 이메일 Routing은 지정된 도메인에 유효한 이메일 주소의 변형을 잡을 것입니다. 예를 들어, 이메일 규칙을 작성하면`info@example.com`사고방식`ifno@example.com`, 이메일은 아직도 당신이 가지고 있는 경우에 제대로 취급될 것입니다**Catch-all 주소**지원하다

Catch-all 주소를 활성화하려면:

1. 로그인하기[Cloudflare 대시보드](https://dash.cloudflare.com/)계정 및 도메인을 선택하십시오.
2. 오시는 길**이름 \*** > **이메일 Routing** > **오시는 길**.
3. 이름 \***Catch-all 주소**, 그래서 그것 쇼로**지원하다**.
4. 내 계&#xC815;**- 연혁**드롭다운 메뉴, 이러한 이메일과 무엇을 할 수 있습니다. 더 알아보기[이메일 규칙](#email-rule-actions)더 많은 정보.
5. 제품정보**제품 정보**.

## 뚱 베어

이메일 Routing 지원 subaddressing, also known as plus addressing, 정의 된[RFC 5233년](https://www.rfc-editor.org/rfc/rfc5233). 이것은 "+" 분리기를 사용하여 임의 세부 정보로 사용자 정의 주소를 부여 할 수 있습니다.

당신은 subaddressing을 활성화 할 수 있습니다**이름 \*** > **이메일 Routing** > **계정 설정**.

일단 활성화되면 사용자 정의 주소의 모든 하위 범주를 사용할 수 있습니다. 예를 들어, 이메일을 보내면`user+detail@example.com`그것은에 의해 캡처됩니다`user@example.com`주문 주소. 더 보기`+detail`일부는 이메일 루팅에 의해 무시되지만 로그에서 처리 체인에서 다음 캡처 할 수 있습니다,[이메일 Worker](/email-routing/email-workers/)또는[회사 소개](https://github.com/cloudflare/agents/tree/main/examples/email-agent).

주문 주소`user+detail@example.com`이미 존재, 그것은 전신을 걸릴 것입니다`user@example.com`. 이것은 기존의 라우팅 규칙을 끊는 것을 방지하고 특정 규칙에 의해 캡처 할 수있는 특정 하위 범주를 허용합니다.

## 대상 주소

이 섹션은 목적지 주소를 관리 할 수 있습니다. 그것은 이미 확인 된 모든 이메일 주소를 나열, 뿐만 아니라 이메일 주소 공개 검증. 인증 이메일을 보내거나 대상 주소를 삭제할 수 있습니다.

대상 주소는 계정 수준에서 공유되며 계정의 다른 도메인과 재사용 할 수 있습니다. 이 같은 목적지 주소는 귀하의 계정에 다른 도메인에 사용할 수 있습니다.

스팸을 방지하려면, 이메일 규칙은 대상 주소가 확인 된 후 활성화되지 않습니다. Cloudflare는 대상 주소에 지정된 검증 이메일을 보냅니다**주문 주소**. 당신은 선택해야**연락처**해당 이메일은 대상 주소를 활성화합니다.

:::참조

목적지 주소를 자동으로 삭제하는 모든 이메일 규칙을 사용할 수 있습니다.

:::
