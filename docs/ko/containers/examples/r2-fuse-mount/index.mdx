FUSE (Filesystem in Userspace)를 사용하면 마운트 할 수 있습니다.[R2 물통](/r2/)컨테이너 안에 파일시스템으로. 응용 프로그램은 객체 저장 API보다 표준 파일 시스템 운영을 사용하여 R2와 상호 작용할 수 있습니다.

일반적인 사용 사례:

- **부트 스트랩 컨테이너 자산**- 샌드박스 및 에이전트 환경에 대한 데이터셋, 모델 또는 의존성
- **Persisting 사용자 상태**- 다운로드 관리 없이 저장 및 액세스 사용자 구성 또는 애플리케이션 상태
- **큰 정적 파일**- 컨테이너 이미지를 bloating하거나 파일 다운로드
- **파일 편집**- 컨테이너 내에서 코드 또는 구성을 만들고 예를 들어 편집을 저장합니다.

:::note\[정보]

오브젝트 저장은 POSIX 호환 파일 시스템이 아니며 로컬 저장소입니다. FUSE 마운트는 익숙한 인터페이스를 제공하지만, 기본 SSD와 같은 성능을 기대하지 않아야합니다.

이 거래가 허용되는 일반적인 사용 사례는 공유 자산, 부트 스트랩을 읽을 수 있습니다.[이름 \*](/agents/)또는[회사 소개](/sandbox/)초기 데이터로, 사용자 상태의 지속 및 Filesystem API를 필요로 하는 애플리케이션은 아니지만 고성능 I/O가 필요하지 않습니다.

:::

## 설치 물통

R2 버킷을 탑재하려면 Dockerfile에서 FUSE 어댑터를 설치하고 컨테이너 시작에서 실행할 수 있습니다.

이 예제는[인기 카테고리](https://github.com/tigrisdata/tigrisfs)R2를 포함하여 S3-compatible 저장을 지원하는 ,:

<Details header="파일 형식">
  ```dockerfile
  FROM alpine:3.20

  # Install FUSE and dependencies
  RUN apk add --no-cache \ 
      --repository http://dl-cdn.alpinelinux.org/alpine/v3.20/main \
      ca-certificates fuse curl bash

  # Install tigrisfs
  RUN ARCH=$(uname -m) && \
      if [ "$ARCH" = "x86_64" ]; then ARCH="amd64"; fi && \
      if [ "$ARCH" = "aarch64" ]; then ARCH="arm64"; fi && \
      VERSION=$(curl -s https://api.github.com/repos/tigrisdata/tigrisfs/releases/latest | grep -o '"tag_name": "[^"]*' | cut -d'"' -f4) && \
      curl -L "https://github.com/tigrisdata/tigrisfs/releases/download/${VERSION}/tigrisfs_${VERSION#v}_linux_${ARCH}.tar.gz" -o /tmp/tigrisfs.tar.gz && \
      tar -xzf /tmp/tigrisfs.tar.gz -C /usr/local/bin/ && \
      rm /tmp/tigrisfs.tar.gz && \
      chmod +x /usr/local/bin/tigrisfs

  # Create startup script that mounts bucket and runs a command
  RUN printf '#!/bin/sh\n\
      set -e\n\
      \n\
      mkdir -p /mnt/r2\n\
      \n\
      R2_ENDPOINT="https://${R2_ACCOUNT_ID}.r2.cloudflarestorage.com"\n\
      echo "Mounting bucket ${R2_BUCKET_NAME}..."\n\
      /usr/local/bin/tigrisfs --endpoint "${R2_ENDPOINT}" -f "${R2_BUCKET_NAME}" /mnt/r2 &\n\
      sleep 3\n\
      \n\
      echo "Contents of mounted bucket:"\n\
      ls -lah /mnt/r2\n\
      ' > /startup.sh && chmod +x /startup.sh

  EXPOSE 8080
  CMD ["/startup.sh"]
  ```
</Details>

시작 스크립트는 마운트 포인트를 생성, 물통을 마운트하기 위해 배경에 tigrisfs를 시작, 다음 마운트 디렉토리 내용을 나열합니다.

### 컨테이너에 credentials 통과

당신의 콘테이너 필요[R2 자격](/r2/api/tokens/)환경 변수로 전달된 구성. 상점 자격[작업자 비밀](/workers/configuration/secrets/), 그때 그들을 통과`envVars`이름:

<TypeScriptExample filename="src/index.ts">
  ```ts
  import { Container, getContainer } from "@cloudflare/containers";

  interface Env {
    FUSEDemo: DurableObjectNamespace<FUSEDemo>;
    AWS_ACCESS_KEY_ID: string;
    AWS_SECRET_ACCESS_KEY: string;
    R2_BUCKET_NAME: string;
    R2_ACCOUNT_ID: string;
  }

  export class FUSEDemo extends Container<Env> {
    defaultPort = 8080;
    sleepAfter = "10m";
    envVars = {
      AWS_ACCESS_KEY_ID: this.env.AWS_ACCESS_KEY_ID,
      AWS_SECRET_ACCESS_KEY: this.env.AWS_SECRET_ACCESS_KEY,
      R2_BUCKET_NAME: this.env.R2_BUCKET_NAME,
      R2_ACCOUNT_ID: this.env.R2_ACCOUNT_ID,
    };
  }
  ```
</TypeScriptExample>

더 보기`AWS_ACCESS_KEY_ID`·`AWS_SECRET_ACCESS_KEY`비밀로 저장되어야한다.`R2_BUCKET_NAME`·`R2_ACCOUNT_ID`변수로 설정할 수 있습니다.`wrangler.jsonc`:

:::note\[R2 AWS API 키 변경]
너에게`AWS_ACCESS_KEY_ID`·`AWS_SECRET_ACCESS_KEY`, [R2 대시보드](https://dash.cloudflare.com/?to=/:account/r2/overview)새로운 R2 액세스 API 키 생성. 생성 된 사용`Access Key ID`이름 \*`AWS_ACCESS_KEY_ID`·`Secret Access Key`이름 \*`AWS_SECRET_ACCESS_KEY`.
:::

```json
{
  "vars": {
    "R2_BUCKET_NAME": "my-bucket",
    "R2_ACCOUNT_ID": "your-account-id"
  }
}
```

### 다른 S3-compatible 저장 공급자

AWS S3 및 Google Cloud Storage를 포함한 다른 S3- 호환 스토리지 제공 업체는 R2와 같은 접근 방식을 사용하여 장착 될 수 있습니다. 적절한 엔드포인트 URL과 스토리지 공급자에 대한 액세스 자격 증명을 제공해야합니다.

## 설치 물통 prefixes

물통 안에 특정한 접두사 (subdirectory)를 거치기 위하여, 대부분의 신관 접합기는 전체 물통을 거치하고 그 후에 산 내의 접두사 경로에 접근해야 합니다.

tigrisfs로, 물통을 마운트하고 파일 시스템 경로를 통해 접두사에 액세스하십시오.

```dockerfile
RUN printf '#!/bin/sh\n\
    set -e\n\
    \n\
    mkdir -p /mnt/r2\n\
    \n\
    R2_ENDPOINT="https://${R2_ACCOUNT_ID}.r2.cloudflarestorage.com"\n\
    /usr/local/bin/tigrisfs --endpoint "${R2_ENDPOINT}" -f "${R2_BUCKET_NAME}" /mnt/r2 &\n\
    sleep 3\n\
    \n\
    echo "Accessing prefix: ${BUCKET_PREFIX}"\n\
    ls -lah "/mnt/r2/${BUCKET_PREFIX}"\n\
    ' > /startup.sh && chmod +x /startup.sh
```

신청은 다음에서 읽을 수 있습니다`/mnt/r2/${BUCKET_PREFIX}`접두사의 밑에 파일만 접근하기 위하여. 패스워드`BUCKET_PREFIX`다른 R2 구성과 함께 환경 변수.

## 장착 버킷으로 읽기 전용

거치된 물통에 쓰기에서 신청을 방지하기 위하여, 추가하십시오`-o ro`read-only로 filesystem을 마운트하는 flag:

```dockerfile
RUN printf '#!/bin/sh\n\
    set -e\n\
    \n\
    mkdir -p /mnt/r2\n\
    \n\
    R2_ENDPOINT="https://${R2_ACCOUNT_ID}.r2.cloudflarestorage.com"\n\
    /usr/local/bin/tigrisfs --endpoint "${R2_ENDPOINT}" -o ro -f "${R2_BUCKET_NAME}" /mnt/r2 &\n\
    sleep 3\n\
    \n\
    ls -lah /mnt/r2\n\
    ' > /startup.sh && chmod +x /startup.sh
```

이것은 당신이 신청만 읽는 자료를 지키는 공유 자산 또는 윤곽 파일을 위해 유용합니다.
