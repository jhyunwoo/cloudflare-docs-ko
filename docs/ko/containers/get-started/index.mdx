## 첫 번째 컨테이너 배포

다음 명령을 실행하고 시작 템플릿에서 컨테이너로 새로운 작업자를 배치:

<PackageManagers type="create" pkg="cloudflare@latest" args={"--template=cloudflare/templates/containers-template"} />

작업자 또는 컨테이너 코드로 코드 변경을 배포하려면 다음 명령을 사용하여 실행할 수 있습니다.[Wrangler 클립](/workers/wrangler/):

<PackageManagers type="exec" pkg="wrangler" args="deploy" />

당신이 실행할 때`wrangler deploy`, 다음 일이 발생:

- Wrangler는 Docker를 사용하여 컨테이너 이미지를 만듭니다.
- Wrangler는 이미지를 이미지에 밀어[컨테이너 이미지 Registry](/containers/platform-details/image-management/)그것은
  Cloudflare 계정과 통합.
- Wrangler는 당신의 노동자를 배치하고, Cloudflare의 네트워크는 당신의 콘테이너의 산란한 인스턴스에 준비되어 있을 것입니다

빌드 및 푸시는 일반적으로 첫 번째 배포에 가장 오래 걸립니다. 자주 묻는 질문
더 빠르기 때문에[재사용된 이미지 층](https://docs.docker.com/build/cache/).

:::참조
처음에 노동자를 배치 한 후, 당신은 때까지 몇 분을 기다릴 필요가
요청을 받을 준비가 되어 있습니다. Workers와는 달리, 콘테이너는 제공될 몇 분이 걸립니다.
이 시간 동안 요청은 노동자에게 보내지만 컨테이너에 호출은 오류가 발생합니다.

### 컨테이너에 요청하기

지금, 당신의 노동자를 위한 URL을 엽니다. 같은 것을 보면`https://hello-containers.YOUR_ACCOUNT_NAME.workers.dev`.

경로를 요청하면`/container/1`또는`/container/2`, 특정한 콘테이너에 당신의 노동자 노선 요구.
각각의 다른 경로 "/container/" 독특한 컨테이너로 경로.

자주 묻는 질문`/lb`, 당신은 무작위로 선택된 3개의 콘테이너 중 하나에 balanace 요구를 적재할 것입니다.

각 요청의 출력을 읽을 때이 행동을 확인할 수 있습니다.

## 각 콘테이너는 그것의 자신의 튼튼한 목표에 의해 역행됩니다

수신 요청은 처음 Worker에 의해 처리되며 컨테이너를 사용하도록 통과했습니다.[튼튼한 목표](/durable-objects)·
보일러 플레이트 코드를 단순화하고 줄이기 위해 Cloudflare는[`Container`한국어](https://github.com/cloudflare/containers)의 일부`@cloudflare/containers`NPM 패키지.

컨테이너를 사용하려면 Durable ObjectsXQ와 익숙하지 마십시오. 그러나 도움이 될 수 있습니다.
기본을 이해하기 위해.

각 튼튼한 개체는 개별 컨테이너 인스턴스와 함께 실행되며 시작을 관리하고 중지합니다.
포트를 통해 컨테이너와 상호 작용할 수 있습니다. 컨테이너는 Worker 인스턴스 근처에 실행될 것입니다.
그들을 요청, 하지만 반드시. 더 알아보기["위치 선택"](/containers/platform-details/#how-are-locations-are-selected)상세 정보

간단한 앱에서, 튼튼한 개체는 컨테이너와 프록시 요청을 부팅 할 수 있습니다.

더 복잡한 앱에서 컨테이너 사용 가능한 Durable Objects를 사용하면 개별 상태 컨테이너에 대한 요청을 처리 할 수 있습니다.
인스턴스, 컨테이너 수명주기를 관리, 사용자 정의 시작 명령 및 환경 변수에 전달, Hooks 실행
컨테이너 상태 변경 및 더.

이름 \*[튼튼한 개체 컨테이너 방법 문서](/durable-objects/api/container/)그리고
[`Container`클래스 저장소](https://github.com/cloudflare/containers)더 많은 정보.

내 계정[Wrangler 구성 파일](/workers/wrangler/configuration/)당신의 노동자와 당신의 콘테이너 둘 다를 위한 윤곽을 정의하십시오:

<WranglerConfig>
  ```jsonc
  {
  	"containers": [
  		{
  			"max_instances": 10,
  			"class_name": "MyContainer",
  			"image": "./Dockerfile"
  		}
  	],
  	"durable_objects": {
  		"bindings": [
  			{
  				"name": "MY_CONTAINER",
  				"class_name": "MyContainer"
  			}
  		]
  	},
  	"migrations": [
  		{
  			"tag": "v1",

  				"MyContainer"
  			]
  		}
  	]
  }
  ```
</WranglerConfig>

이 구성에 대한 중요한 점:

- `image`Dockerfile 또는 Dockerfile을 포함하는 디렉토리로 이동합니다.
- `class_name`\* 필수[튼튼한 개체 클래스 이름](/durable-objects/api/base/).
- `max_instances`컨테이너 인스턴스를 동시에 실행하는 최대 수를 선언합니다.
  그것은 실행됩니다.
- 튼튼한 개체는 사용해야 합니다[`new_sqlite_classes`](/durable-objects/best-practices/access-durable-objects-storage/#create-sqlite-backed-durable-object-class)아니다.`new_classes`.

### 컨테이너 이미지

컨테이너 이미지는 실행할 수 있어야 합니다.`linux/amd64`건축, 하지만 그 옆에, 몇 가지 제한이 있다.

예를 들어 방금 배포 된 경우 8080 포트 요청에 응답하는 간단한 Golang 서버입니다.
이름 \*`MESSAGE`Worker와[자동 생성
환경 변수](/containers/platform-details/#environment-variables) `CLOUDFLARE_DEPLOYMENT_ID.`

```go
func handler(w http.ResponseWriter, r *http.Request) {
	message := os.Getenv("MESSAGE")
	instanceId := os.Getenv("CLOUDFLARE_DEPLOYMENT_ID")

	fmt.Fprintf(w, "Hi, I'm a container and this is my message: %s, and my instance ID is: %s", message, instanceId)
}
```

:::참조
예를 배치 한 후, 다른 이미지를 배포하기 위해, 당신은 자신의 하나와 함께 제공 된 이미지를 대체 할 수 있습니다.
주요 특징

### 작업자 코드

#### 컨테이너 구성

첫 번째 주`MyContainer`어떤 확장[`Container`](https://github.com/cloudflare/containers)종류:

```js
export class MyContainer extends Container {
  defaultPort = 8080;
  sleepAfter = '10s';
  envVars = {
    MESSAGE: 'I was passed in via the container class!',
  };

  override onStart() {
    console.log('Container successfully started');
  }

  override onStop() {
    console.log('Container successfully shut down');
  }

  override onError(error: unknown) {
    console.log('Container error:', error);
  }
}
```

이것은 콘테이너를 위한 기본적인 윤곽을 정의합니다:

- `defaultPort`포트 설정`fetch`·`containerFetch`방법은 컨테이너와 통신 할 수 있습니다. 또한 블록
  컨테이너가 이 포트를 듣는 때까지 요청.
- `sleepAfter`콘테이너를 위한 timeout를 일정한 시간 동안 idle이기 후에 잠그기 위하여 놓으십시오.
- `envVars`시작할 때 컨테이너로 전달되는 환경 변수를 설정합니다.
- `onStart`, `onStop`·`onError`컨테이너가 시작될 때 실행되는 걸이, 정지, 또는 과실, 각각.

이름 \*[컨테이너 종류 문서](/containers/container-package)더 많은 세부 사항 및 구성 옵션.

#### 컨테이너로의 여정

요청이 Cloudflare를 입력하면 작업자의[`fetch`회사 소개](/workers/runtime-apis/handlers/fetch/)뚱 베어 이것은 들어오는 요청을 처리하는 코드입니다. 예제 코드의 fetch 핸들러, 두 가지 방법으로 컨테이너를 발사, 다른 경로:

- 자주 묻는 질문`/container/`새로운 컨테이너에 대한 요청을 전달
  각 경로. 이것은 새로운 컨테이너 인스턴스를 회전함으로써 이루어집니다. 주의사항
  새로운 경로에 대한 첫 번째 요청은 나중에 요청보다 더 오래 걸립니다, 이것은
  새로운 컨테이너가 부팅되기 때문에.

  ```js
  if (pathname.startsWith("/container")) {
  	const container = env.MY_CONTAINER.getByName(pathname);
  	return await container.fetch(request);
  }
  ```

- 자주 묻는 질문`/lb`몇몇 콘테이너의 맞은편에 균형 요구를 적재할 것입니다.
  이것은 간단한 사용`getRandom`helper 메서드, 임의의 ID를 선택
  설정 번호에서 (이 경우 3), 그 컨테이너 인스턴스에 경로. routing 또는 load balancing logic과 함께 이것을 교체 할 수 있습니다.

  ```js
  if (pathname.startsWith("/lb")) {
  	const container = await getRandom(env.MY_CONTAINER, 3);
  	return await container.fetch(request);
  }
  ```

컨테이너를 사용하는 여러 가지 방법을 허용합니다.

- 당신은 단순히 많은 stateless와 교환할 수 있는 콘테이너에 요구에 보낼 것을 원하면,
  당신은 균형을 적재해야 합니다.
- 만약 당신이 stateful 서비스 또는 개별적으로 주소가 필요 하는 경우
  컨테이너, 특정 컨테이너 인스턴스를 요청해야 합니다.
- 부족한 작업을 실행하는 경우, 컨테이너를 통해 미세 곡물 제어를 원
  lifecycle, container entrypoint 또는 env vars를 매개 변수화하려는, 또는
  여러 컨테이너 통화를 함께 체인을 원하면 특정 요청을 요청해야합니다.
  컨테이너 인스턴스.

:::참조
현재 많은 교환 가능한 컨테이너 인스턴스 중 하나에 대한 라우팅 요청이 수행됩니다.
이름 \*`getRandom`도움.

이것은 임시입니다 — 우리는 대기 시간 인식 자동 확장 및로드 밸런싱에 대한 기본 지원을 추가 할 계획.
