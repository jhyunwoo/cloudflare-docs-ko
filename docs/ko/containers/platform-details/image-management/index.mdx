## 중 이미지를 밀어`wrangler deploy`

현재 위치`wrangler deploy`, 당신이 설정한 경우`image`내 계정[Wrangler 구성](/workers/wrangler/configuration/#containers)Dockerfile에 대한 경로로 Wrangler는 Docker를 사용하여 컨테이너 이미지를 로컬로 구축하고 Cloudflare에 의해 레지스트리 실행으로 밀어줍니다.
Cloudflare 계정과 통합되어[R2](/r2/). 모든 인증은 자동으로 처리됩니다.
Cloudflare 둘 다 누르고 이미지를 당기기.

Dockerfile에 대한 경로를 제공합니다:

<WranglerConfig>
  ```json
  {
  	"containers": {
  		"image": "./Dockerfile"
  		// ...rest of config...
  	}
  }
  ```
</WranglerConfig>

작업자 배치`wrangler deploy`. 다른 이미지 관리는 필요하지 않습니다.

이후 배포에, Wrangler는 공간과 시간을 절약하는 변경 된 이미지 레이어를 밀어 것입니다.

:::참조
Docker 또는 Docker 호환 CLI 도구는 Wrangler를 실행하고 이미지를 밀어야 합니다.
아래 설명된 것과 같이 미리 만들어진 이미지를 사용하는 경우이 필요하지 않습니다.
주요 특징

## pre-built 컨테이너 이미지 사용

현재, 우리는 Cloudflare 관리 레지스트리에 저장된 이미지를 지원합니다`registry.cloudflare.com`·[아마존 ECR](https://aws.amazon.com/ecr/)·
추가 외부 등록에 대한 지원은 곧 출시됩니다.

다른 레지스트리 공급자로부터 사전 제작 된 이미지를 사용하려면 먼저 로컬에 존재하는 것을 확인합니다.
Cloudflare 등록:

```
docker pull <public-image>
docker tag <public-image> <image>:<tag>
```

Wrangler는 QXQX0141XQQ Registry에 이미지를 밀어주는 명령을 제공합니다:

<PackageManagers type="exec" pkg="wrangler" args="containers push <image>:<tag>" />

또는, 당신은 사용할 수 있습니다`-p`플래그와`wrangler containers build`한 단계에 이미지를 밀어 :

<PackageManagers type="exec" pkg="wrangler" args="containers build -p -t <tag> ." />

Wrangler 설정에서 다음 사용할 수있는 이미지 레지스트리 URI를 출력합니다.

<WranglerConfig>
  ```json
  {
  	"containers": {
  		"image": "registry.cloudflare.com/your-account-id/your-image:tag"
  		// ...rest of config...
  	}
  }
  ```
</WranglerConfig>

### Amazon ECR 컨테이너 이미지 사용

컨테이너 이미지 저장[아마존 ECR](https://aws.amazon.com/ecr/), 당신은 credentials를 가진 ECR 레지스트리 도메인을 구성해야 할 것입니다.
이 자격은 저장됩니다[비밀번호](/secrets-store)이름 \*`containers`범위.
컨테이너를 준비할 때, 이러한 자격 증명은 이미지를 끌어낼 수있는 ephemeral 토큰을 생성하는 데 사용됩니다.
우리는 현재 공개 ECR 이미지를 지원하지 않습니다.
ECR에 필요한 자격 증명을 생성하려면 읽기 전용 정책으로 IAM 사용자를 만들 필요가 있습니다.
다음 예제는 AWS 계정의 모든 이미지 저장소에 액세스 권한을 부여`123456789012`내 계정`us-east-1`.

```json
{
	"Version": "2012-10-17",
	"Statement": [
		{
			"Action": ["ecr:GetAuthorizationToken"],
			"Effect": "Allow",
			"Resource": "*"
		},
		{
			"Effect": "Allow",
			"Action": [
				"ecr:BatchCheckLayerAvailability",
				"ecr:GetDownloadUrlForLayer",
				"ecr:BatchGetImage"
			],
			// arn:${Partition}:ecr:${Region}:${Account}:repository/${Repository-name}
			"Resource": [
				"arn:aws:ecr:us-east-1:123456789012:repository/*"
				// "arn:aws:ecr:us-east-1:123456789012:repository/example-repo"
			]
		}
	]
}
```

IAM 사용자의 자격 증명을 사용할 수 있습니다.[Wrangler의 레지스트리 구성](/workers/wrangler/commands/#containers-registries)·
Wrangler는 이미 존재하지 않는 경우에 비밀 상점을 창조하고, 그 후에 당신의 비밀을 창조할 것입니다.

<PackageManagers type="exec" pkg="wrangler" args="containers registries configure 123456789012.dkr.ecr.us-east-1.amazonaws.com --aws-access-key-id=AKIAIOSFODNN7EXAMPLE" />

설정되면 wrangler config에서 ECR 이미지를 사용할 수 있습니다.

:::참조
우리는 ECR 이미지를 캐시하지 않습니다. 우리는 prewarm에 이미지를 당기고 콘테이너를 시작합니다. AWS ECR의 egress 수수료가 부과될 수 있습니다.

앞으로 R2에서 이미지 캐싱을 추가할 계획입니다.
주요 특징

<WranglerConfig>
  ```json
  {
  	"containers": {
  		"image": "123456789012.dkr.ecr.us-east-1.amazonaws.com/example-repo:tag"
  		// ...rest of config...
  	}
  }
  ```
</WranglerConfig>

:::참조
현재, Cloudflare Vite-plugin은 지역 개발의 레지스트리 링크를 지원하지 않습니다.`wrangler dev`·
workaround로, 사용하는 최소 Dockerfile을 만들 수 있습니다.`FROM <registry-link>`. 확인`EXPOSE`로컬 dev의 포트뿐만 아니라.

## CI와 이미지를 밀어

연속 통합 환경에서 내장 된 이미지를 사용하려면 설치`wrangler`다음 것
하나를 사용하여 이미지를 밀어`wrangler containers build`이름 \*`--push`깃발, 또는
사용 방법`wrangler containers push`명령.

## 등록 제한

이미지는 구성 가능한 디스크로 크기로 제한됩니다.[인스턴스 유형](/containers/platform-details/limits/#instance-types)콘테이너를 위해.

이미지 삭제`wrangler containers images delete`공간을 해방하기 위하여, 그러나 반전
삭제 된 이미지를 사용하는 이전 버전에 노동자는 오류가 발생합니다.
