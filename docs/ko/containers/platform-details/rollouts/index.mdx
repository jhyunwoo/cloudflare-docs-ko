## 롤아웃 작업

당신이 실행할 때`wrangler deploy`, 노동자 부호는 즉시 업데이트되고 콘테이너
인스턴스는 롤링 배포 전략을 사용하여 업데이트됩니다. 기본 롤아웃 구성은 두 단계이며,
인스턴스의 첫 번째 단계 업데이트 10 % 및 두 번째 단계는 나머지 90 %를 업데이트합니다.
Wrangler config 파일에서 설정할 수 있습니다.[`rollout_step_percentage`](/workers/wrangler/configuration#containers)호텔 위치

변경을 배포할 때도 구성할 수 있습니다.[`rollout_active_grace_period`](/workers/wrangler/configuration#containers), 이는 최소한이다
Active container 인스턴스가 롤아웃 중에 업데이트할 수 있는 수의 초가 될 수 있습니다.
그 시점에서 컨테이너가 전송됩니다.`SIGTERM`, 여전히 우아하게 폐쇄하는 15 분이 있습니다.
인스턴스가 15 분 이내에 멈추지 않는 경우 강제로 중지됩니다.`SIGKILL`신호.
컨테이너 인스턴스가 중지되기 전에 발생해야 할 정리가 있다면 15 분 동안 수행해야합니다.

일단 중지되면, 인스턴스는 업데이트 된 코드를 실행하는 새로운 인스턴스로 대체됩니다. 요청은 컨테이너가 다시 시작되는 동안 걸 수 있습니다.

다음은 5 분의 은혜 기간을 설정하는 예 구성이며, 첫 번째 단계 업데이트 10 %의 인스턴스와 두 번째 단계 업데이트 100 %의 인스턴스 :

<WranglerConfig>
  ```jsonc
  {
  	"containers": [
  		{
  			"max_instances": 10,
  			"class_name": "MyContainer",
  			"image": "./Dockerfile",
  			"rollout_active_grace_period": 300,
  			"rollout_step_percentage": [
  				10,
  				100
  			]
  		}
  	],
  	"durable_objects": {
  		"bindings": [
  			{
  				"name": "MY_CONTAINER",
  				"class_name": "MyContainer"
  			}
  		]
  	},
  	"migrations": [
  		{
  			"tag": "v1",
  			"new_sqlite_classes": [
  				"MyContainer"
  			]
  		}
  	]
  }
  ```
</WranglerConfig>

## Immediate 롤아웃

한 단계에 컨테이너 인스턴스의 100 %를 롤하는 One-off 배포를 수행해야하는 경우 다음과 같이 배포 할 수 있습니다.

<PackageManagers pkg="wrangler" type="exec" args="deploy --containers-rollout=immediate" />

주의사항`rollout_active_grace_period`, 형성된 경우에, 아직도 적용합니다.
