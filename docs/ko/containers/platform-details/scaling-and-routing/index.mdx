### Scaling container 인스턴스와`get()`

:::참조
이 섹션에서는 helpers를 사용합니다.[컨테이너 패키지](/containers/container-package).
:::

현재 컨테이너는 고유 ID로 컨테이너를 얻기 위해 수동으로 확장됩니다.
컨테이너 시작 컨테이너를 얻는 것은 자동으로 시작되지 않습니다.

```typescript
//가져오기 및 시작 두 컨테이너 인스턴스
const containerOne = getContainer(
	env.MY_CONTAINER,
	idOne,
).startAndWaitForPorts();

const containerTwo = getContainer(
	env.MY_CONTAINER,
	idTwo,
).startAndWaitForPorts();
```

각 인스턴스가 실행될 때까지`sleepAfter`시간이 발생하거나 수동으로 중지 될 때까지.

이 행동은 컨테이너 인스턴스의 수명주기에 명시된 컨트롤을 원할 때 매우 유용합니다.
예를 들어, 특정 사용자에 대한 컨테이너 백엔드 인스턴스를 회전하거나 간단히 할 수 있습니다.
AI-generated 코드를 격리하는 코드 sandbox를 실행하거나 짧은 작업 일괄 작업을 실행할 수 있습니다.

#### 더 보기`getRandom`helper 기능

그러나 때때로 컨테이너의 여러 인스턴스를 실행하고 쉽게 경로 요청을 할 수 있습니다.

현재,이를 달성하는 가장 좋은 방법은 다음과 같습니다.*이름 \** `getRandom`helper 기능:

```javascript
import { Container, getRandom } from "@cloudflare/containers";

const INSTANCE_COUNT = 3;

class Backend extends Container {
	defaultPort = 8080;
	sleepAfter = "2h";
}

export default {
	async fetch(request: Request, env: Env): Promise<Response> {
		//참고 : "getRandom"은 가까운 미래에 지연으로 대체됩니다.
		const containerInstance = getRandom(env.BACKEND, INSTANCE_COUNT)
		return containerInstance.fetch(request);
	},
};
```

getRandom 함수는 여러 stateless 컨테이너 인스턴스로 경로를 멈출 수 있는 Stopgap 솔루션으로 제공됩니다.
각 요청과 경로에 대한 N 인스턴스 중 하나를 무작위로 선택합니다. 불행히도, 그것은 두 가지 주요 단점이 있습니다 :

- 사용자가 경로에 고정된 인스턴스를 설정해야 합니다.
- 위치와 관계없이 각 인스턴스를 무작위로 선택합니다.

우리는 가까운 미래에 내장 자동화 및 라우팅 기능을 가진 이러한 문제를 해결 계획.

### Autoscaling 및 라우팅 (출시)

:::참조
이 공개되지 않은 기능입니다. 변경 될 수 있습니다.
주요 특징

컨테이너에 자동 확장을 설정할 수 있습니다.`autoscale`콘테이너 종류에 재산:

```javascript
class MyBackend extends Container {
	autoscale = true;
	defaultPort = 8080;
}
```

이 플랫폼은 들어오는 트래픽 및 리소스 사용 (메모리, CPU)을 기반으로 자동으로 스케일 인스턴스를 확장합니다.

컨테이너 인스턴스는 로컬 트래픽을 제공하기 위해 자동으로 시작되며 더 이상 필요하지 않을 때 중지됩니다.

올바른 인스턴스에 대한 요청을 경로로, 당신은 사용할 것이다`getContainer()`컨테이너 인스턴스를 얻는 helper 함수, 그 후에
그것에 통행 요구:

```javascript
export default {
	async fetch(request, env) {
		return getContainer(env.MY_BACKEND).fetch(request);
	},
};
```

이것은 컨테이너의 가장 가까운 준비 인스턴스에 트래픽을 보낼 것입니다. 컨테이너가 과부하되거나 아직 출시되지 않은 경우,
요청은 잠재적으로 더 먼 콘테이너로 갈 것입니다. 콘테이너 readiness는 자동적으로 근거한 결정될 수 있습니다
자원 사용에, 또한 custom readiness checks에 configurable 일 것입니다.

Autoscaling and latency-aware routing will be available in the near future, and will be documented in more details when released.
그때까지, 당신은 사용할 수 있습니다`getRandom`여러 컨테이너 인스턴스에 대한 요청을 경로를 돕는 기능.
